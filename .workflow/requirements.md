# 요구사항 — Rawdoc 에디터 코어 기술 검증

작성일: 2026-09-07
사이클 성격: **기술 리스크 검증 스파이크** (제품 기능 개발이 아님)

> 이 문서가 파이프라인의 입력물이다. 여기 없는 것은 만들지 않는다.
> 상위 배경은 `docs/research.html` (2026-08-29, rev.2) 에 있다.

## 1. 문제

Notion 계열 도구는 `##` 를 입력하는 즉시 블록으로 변환해 마크다운 원문을 없앤다.
Rawdoc 은 원문을 남기는 것을 핵심 주장으로 삼는다.

현재 `docs/prototype.html` 은 `textarea` + 오버레이로 원문 보존을 구현해 두었다.
그러나 다음 단계인 **옵시디언식 라이브 프리뷰**(커서가 있는 줄만 원문, 나머지는 렌더링)는
textarea 구조에서 원리적으로 불가능하다 — textarea 는 내부 텍스트를 부분적으로 다르게 그릴 수 없다.
(`docs/research.html` 8장)

따라서 에디터 코어를 CodeMirror 6 으로 교체해야 하는데, 여기에 되돌리기 비싼 리스크가 하나 있다:

**CM6 decoration 으로 마크다운 기호를 숨겼다 보였다 하는 동작과 한글 IME 조합 상태가 겹치면
커서가 튀거나 글자가 중복 입력되기 쉽다.** 나중에 발견하면 아키텍처를 되돌려야 하는 종류다.

지금은 이 리스크를 아무도 확인하지 않은 상태이고, 확인 없이 본 구현에 들어가면
"뒤늦은 대규모 리팩터링" 이 그대로 재현된다.

## 2. 사용자

| 구분 | 내용 |
| --- | --- |
| 제품의 최종 사용자 | 소규모 개발팀 (5~10명) 비공개 베타 — **이번 사이클의 대상이 아니다** |
| 이번 사이클의 사용자 | 개발자 본인 1명 (검증 수행자) |
| 사용 환경 | 데스크톱 Chrome / 안드로이드 Chrome / 안드로이드 Capacitor WebView |
| 입력기 | 한글 IME (데스크톱 MS IME, 모바일 삼성·구글 키보드) |

## 3. 범위

### 만든다

- [ ] `spike/` 디렉터리에 CodeMirror 6 기반 최소 에디터 화면 1개
- [ ] 라이브 프리뷰 — **인라인 요소(굵게·기울임·링크·인라인코드) + 블록(표·코드블록) 위젯 치환까지 전부**
- [ ] Capacitor 로 위 화면을 안드로이드 앱으로 감싸 실행
- [ ] Playwright 테스트 환경 및 입력 시나리오 테스트
- [ ] 3개 환경별 검증 결과 기록 문서

### 만들지 않는다 (명시적 제외)

- [ ] 고급 렌더링 — KaTeX 수식, Mermaid, PlantUML, 발표 모드
- [ ] 과금·결제·좌석 관리·플랜 구분
- [ ] 실시간 동기화 — Yjs, Durable Object, y-partyserver
- [ ] 로그인·계정·인증 (OAuth/JWT)
- [ ] 백엔드 일체 — Cloudflare Workers, D1, R2
- [ ] 데이터 영속화 — IndexedDB 포함. 이번 스파이크는 새로고침하면 초기화돼도 된다
- [ ] 댓글, 페이지 목록, 다중 문서, `.md` 내보내기
- [ ] `src/` 의 기존 Vite 스캐폴드 교체 — 손대지 않는다
- [ ] iOS / Safari 대응
- [ ] Play 스토어 등록

## 4. 성공 기준

아래 4개가 **전부 참**이고 결과가 문서로 남으면 이번 사이클은 끝이다.

- [ ] **조합 안정성** — 한글을 연속 입력하는 동안 decoration 재계산이 일어나도 커서가 튀지 않고 글자가 중복 입력되지 않는다
- [ ] **기호 토글 시 조합 유지** — `**굵게**` 처럼 커서 이동으로 기호가 숨겨지거나 드러나는 순간에 한글을 입력 중이어도 조합이 깨지지 않는다
- [ ] **블록 위젯 커서 출입** — 표·코드블록 위젯에 방향키로 진입/이탈할 때 원문이 정확히 복원되고 그 안에서 한글 입력이 동작한다
- [ ] **3개 환경 동일** — 데스크톱 Chrome / 안드로이드 Chrome / 안드로이드 Capacitor WebView 에서 위 셋이 모두 같은 결과를 낸다

판정은 **사람이 직접 타이핑해서** 한다. 자동 테스트는 보조 수단이다 (6장 참조).

## 5. 제약

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 실행 환경 | 데스크톱 Chrome, 안드로이드 Chrome, 안드로이드 Capacitor WebView | 사용자 지정 |
| 언어/런타임 | Node.js, Vite 7, React 19, CodeMirror 6 | 기존 프로젝트 구성 + `docs/research.html` 6장 |
| 성능 요구 | 수치 기준 없음. 한글 연속 입력 시 체감 지연이 없을 것 | 검증 조건에서 파생 |
| 데이터 보관 | 이번 사이클은 저장 없음(메모리). 프로젝트 1차 저장 방침은 브라우저 IndexedDB | 사용자 지정 |
| 배포 방식 | 배포 없음. 안드로이드는 USB 설치 또는 에뮬레이터 실행만 | 스파이크 성격 |
| 검증 기기 | **미정 (가정: 실기기 우선, 불가하면 Android Studio AVD)** | 6장 미해결 질문 |

## 6. 미해결 질문

- [ ] **안드로이드 검증 수단** — 실기기(USB 디버깅) 인가 에뮬레이터인가. 실기기가 IME 동작을 정확히 보여주지만 준비 여부가 확인되지 않음. **가정: 실기기 우선**. B-005 착수 시 확정한다
- [ ] **블록 위젯 진입 UX** — 위젯에 방향키로 진입시킬지, 클릭으로만 진입시킬지, 진입하면 원문 전체를 펼칠지 해당 셀만 펼칠지. B-003 계획 시 확정한다
- [ ] **Playwright 의 한글 IME 재현 범위** — CDP 로 composition 이벤트를 어디까지 재현할 수 있는지 미확인. 재현 불가로 판명되면 자동 테스트는 "decoration 계산 로직" 만 덮고 IME 판정은 전량 사람 확인으로 간다. B-004 에서 확인한다
- [ ] **`docs/research.html` 8장과의 의도적 불일치** — 그 문서는 1차에서 인라인만 라이브 프리뷰하고 표·코드블록은 원문으로 두라고 권했다. 이번 사이클은 블록까지 검증 대상에 넣었으므로 난이도와 실패 확률이 그 권고보다 높다. 이는 "가장 위험한 것을 먼저 확인한다" 는 스파이크 목적에 따른 의도적 선택이다
