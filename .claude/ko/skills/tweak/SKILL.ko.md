# tweak

메인이 직접 한다. 에이전트를 띄우지 않는다. 고치기 → 사용자가 `npm run dev` 로 확인 → 다시 고치기 → 커밋의 짧은 순환이 목적이다

규칙 근거: `CLAUDE.md` "Direction" 3 에 이 스킬 예외가 있다 (사용자 지시 2026-09-23: "디자인 명세 구현안하고 빠르게 수정한 뒤 그냥 증거로 간단하게 노트 남기는 모드", 범위 "작은 동작까지", 노트는 `specs/tweaks.md`)

## 1. tweak 인가

**범위 안** — 바로 고친다

- 보이는 것: 색, 간격, 크기, 정렬, 글꼴, 아이콘, 그림자, 모션, 겹침 순서
- UI 문구: 라벨, 툴팁, 알림 문장
- 이미 있는 것의 작은 동작: 버튼 옮기기, 메뉴 항목 순서, 호버·포커스·눌림 표시, 어느 기존 요소가 포커스를 받는지, 기존 컨트롤 보이기·숨기기

**범위 밖** — 멈추고 `write-spec` 으로

- 데이터, 저장, 동기화, 서버(`worker/`), 마이그레이션, Yjs 경로
- 새 화면, 대화상자, 메뉴, 커맨드, 단축키
- 새 의존성
- `CLAUDE.md` 불변조건에 닿는 것
- 명세의 **동작** 수용 기준이 말하는 것을 바꾸는 것 (`e2e/F-xxx` 동작 테스트가 선택자가 아니라 기대값을 바꿔야 하는 경우)

경계에 걸리면 어느 쪽으로 봤는지와 이유를 한 줄 말하고 진행한다. 사용자가 아니라고 하면 그때 바꾼다

tweak 안에서도 불변조건은 그대로다: 제품명·색 hex 는 `brand.config.ts` 밖에 쓰지 않고, 색은 `color-mix()` 로 파생하고, decoration 은 문서 내용을 바꾸지 않는다

## 2. 순환

1. 코드를 찾는다(클래스 이름, UI 문자열, 컴포넌트를 `Grep`). 바꾸려는 값·문자열을 `specs/design.md`·`specs/ia.md` 에서 확인한다
2. 고친다. 맞는 토큰이 `tokens.css` 에 있으면 그걸 쓴다. 다시 쓸 값일 때만 토큰을 새로 만든다
3. 무엇을 바꿨고 어디를 보면 되는지 사용자에게 말한다. dev 서버는 보통 이미 떠 있다(`npm run dev`). 없으면 백그라운드로 띄운다. 눈으로 보는 판단은 사용자 몫이다 — 요청이 없으면 스크린샷·측정에 매달리지 않는다
4. 사용자가 만족할 때까지 2~3 반복

## 3. 커밋 전 확인

"How we work" 대로 가볍게 — TDD 없음, 시각 e2e 추가 없음

- `npx eslint <바꾼 파일>`
- 바꾸거나 지운 클래스 이름·선택자·UI 문자열을 `e2e/` 에서 `Grep` 한다. 쓰는 테스트가 있으면 한 번 돌리고(`npm run e2e:one -- "<제목>|<제목>"`) **선택자만** 고친다. 동작 기대값이 깨지면 tweak 이 아니었던 것이다 — 멈춘다(1)
- `specs/design.md`·`specs/ia.md` 의 값·문자열이 바뀌었으면 같은 커밋에서 그 줄을 고친다. 사용자 요청이 곧 승인이고, 노트에 그렇게 적는다

## 4. 노트 — `specs/tweaks.md`

표 맨 위(최신이 위)에 한 줄 추가

```
| 2026-09-23 | 사이드바 행 간격 6px → 4px | 사용자: "사이드바가 너무 헐렁함" | F-153, design.md 4.2 |
```

- 무엇을: 값이 있으면 전 → 후
- 왜: 사용자 말을 인용. 이유를 말하지 않았으면 `사용자 요청`
- 관련: 그 화면을 다루는 명세, 함께 고친 명세 문서 줄. 없으면 `—`
- 커밋 해시 칸은 두지 않는다 — `git log -- specs/tweaks.md` 로 찾는다

## 5. 커밋

- 커밋 하나 = tweak 요청 하나 (같은 화면의 관련 수정 여러 개는 함께). 파일: 바꾼 코드 + `specs/tweaks.md` + (3) 의 `design.md`·`ia.md` 줄
- 경로를 명시한다: `git add -- <경로>` 다음 `git commit … -- <경로>`
- 제목: `{무엇을 바꿨는지} (tweak)`. 본문: 무엇을 확인했는지 한 줄(eslint, 어떤 e2e)
- `git push`
