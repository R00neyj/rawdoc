# polish-korean

영어판 `.claude/skills/polish-korean/SKILL.md` 가 원본이다. 이 파일은 사람용 스냅샷이고 자동으로 따라가지 않는다.

근거: im-not-ai (https://github.com/epoko77-ai/im-not-ai, `skills/humanize-korean/references/`). 사용자 지시 2026-10-05: "윤문 스킬 만들고 체인지로그는 항상 스킬 참조하도록 해줘".

## 1. 언제 쓰나

- **`content/changelog.md` 항목은 매번.** 항목을 쓴 뒤 커밋 전에 새로 넣은 줄에 이 과정을 돌린다(`deploy` 스킬)
- 요청이 있을 때: 사용법 글, README, `cli/README.md`, 도움말 문구. `specs/**`, `CLAUDE*.md`, 코드 주석, 테스트 고정값은 사용자가 지목할 때만

## 2. 네 가지 원칙

1. **뜻은 움직이지 않는다.** 사실·숫자·버전·고유명사·원인·조건은 그대로
2. **국소적으로.** 3장 패턴에 걸리는 문장만 고친다. 멀쩡한 문장은 그대로
3. **말투와 형식 유지.** 공개 글은 합니다체. 헤딩, 굵은 꼬리표, 표, 목록 개수·순서, 파일이 형식으로 쓰는 `—` 구분은 둔다
4. **과윤문 금지.** 파일당 바뀐 줄 5~30%. 30% 를 넘으면 멈추고 고친 곳마다 패턴이 있는지 확인. 문학적으로 꾸미지 않는다

## 3. 고칠 패턴

| 묶음 | 찾을 것 | 고치는 법 |
| --- | --- | --- |
| 번역투 | `~를 통해`, `~에 대해/관해`, `~에 있어서`, `~에 의해` 피동, `~되어지다`, `-에서의/-에로의`, `~로부터` | `~로`, 목적격, 능동, 단순 피동, 절로 풀기 |
| 무생물 주어 + 사역 | "모드는 ~하게 합니다", "기능이 ~를 가능하게 합니다" | 사람이나 장소를 주어로: "~에서는 ~할 수 있습니다" |
| 긴 관형구 | 명사 앞에 3어절 넘게 쌓인 꾸밈 | 두 문장으로 나눔 |
| 늘어진 문장 | 쉼표나 `~고 ~며` 로 3절 넘게 이음 | 나눔. 항목 개수는 그대로 |
| 명사화 | "저장을 시도합니다", "실행이 됩니다" | 동사로: "저장하려고 합니다", "실행할 수 있습니다" |
| 형식명사 | `~것입니다`, `~할 필요가 있다`, `~점`, `~바` | 바로 말함 |
| 분열문 | "핵심은 ~이다", "가장 쓸모 있는 쓰임은 ~이다" | 주어-서술어로: "~할 때 가장 쓸모 있습니다" |
| AI 관용구 | "결론적으로", "주목할 만하다", "시사하는 바", "단순한 A가 아닌 B", "A를 넘어", "순간" | 지우거나 구체적 사실로 |
| 완곡 중첩 | "~할 수 있을 것으로 보입니다" | 같은 세기의 완곡 하나로 |
| 정도부사 | "매우", "정말", "특히 자주", 동의어 겹침 | 지우거나 구체적 이유로 |
| `-들` | 무정물·추상명사에 붙은 것 | 지움 |
| 문두 접속사 | "또한/따라서/즉/나아가" 연속 | 지우거나 합침 |
| 같은 어미 반복 | 같은 종결어미 4문장 넘게 연속 | 몇 개만 바꿈 |
| 장식 | 형식이 아니라 강조용으로 쓴 굵게·따옴표·대시 | 강조를 뺌 |

## 4. 절대 바꾸지 않는 것

- 프론트매터 키·값(체인지로그 `updated:` 는 여기가 아니라 `deploy` 스킬이 맞춘다)
- 헤딩 — 링크 대상일 수 있음. 체인지로그의 `## YYYY-MM-DD` 묶음
- 백틱 안의 모든 것: 명령, 코드, `가져오기` 같은 UI 문자열. 링크 주소, `[[위키링크]]` 예시, 코드블록, 콜아웃 문법
- 숫자, 단위, 버전, 표의 열, 항목·문단의 개수와 순서

## 5. 체인지로그만의 것

- 한 줄은 사용자가 이제 할 수 있는 것이나 더는 틀어지지 않는 것을 말한다(`specs/features/F-273.md` 3장). 구현 이야기는 사용자가 보는 것으로 바꾼다 — "폴백", "자리를 먼저 잡아 두어" 같은 내부 말은 뺀다. 사실은 바꾸지 않는다
- 한 줄에 변화 하나. 늘어진 문장을 나눠도 같은 줄 안에서 문장만 늘고 줄은 늘지 않는다

## 6. 커밋 전 확인

- 코드 표기·숫자·헤딩 그대로인지: `git show HEAD:<파일>` 과 작업 파일에 `` grep -o '`[^`]*`\|[0-9][0-9.,]*\|^#.*' `` 를 돌려 정렬해 비교. 일부러 사실을 더한 파일(예: 릴리스를 따라잡는 사용법 글)은 헤딩과 프론트매터만 본다
- `npx vitest run tests/site` (사용법 글을 고쳤으면 `tests/src/lib/userCssGuide.test.ts tests/worker/guideLimits.test.ts` 도)
