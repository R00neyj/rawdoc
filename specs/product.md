# Rawdoc 전체 기능명세

작성일: 2026-09-13
상태: **초안 — 사람 승인 전.** 9장 결정됨 표 참고 (2026-09-13~15). 7장 M2 기능 목록은 2026-09-15 승인. 남은 미결은 Q6 문서 크기 상한, Q14 제품명·메인 컬러

> 이 문서가 구현의 상위 원본이다. 여기 없는 기능은 만들지 않는다
> 작은 명세(`specs/features/F-xxx.md`)는 이 문서의 기능 ID 하나를 풀어 쓴 것이다

## 1. 제품 정의

소규모 개발팀용 원문 보존형 마크다운 협업 에디터

- **핵심 주장:** 입력한 마크다운 기호가 변환되지 않고 남는다. `.md` 로 내보내면 사용자가 친 원문과 바이트가 같다
- **편집 화면:** 옵시디언식 라이브 프리뷰 — 커서가 있는 줄(블록)은 원문, 나머지는 렌더링된 모습
- **차별화 축** (`docs/research.html` 5장):
  1. 한국어 — UI, 문서, 지원
  2. 데이터 위치 — 국내 리전 또는 자체 호스팅
  3. 댓글 앵커 정확도 — 줄 번호가 아니라 텍스트 내용에 붙는 앵커
- **직접 경쟁:** HackMD, HedgeDoc. 원문 보존 자체는 신규 컨셉이 아니다 (`docs/research.html` 1·2장)

## 3. 단계 구성

| 단계 | 목표 | 끝나면 되는 것 |
| --- | --- | --- |
| **M1** | 로컬 단일 사용자 에디터 | 브라우저 하나에서 여러 문서를 라이브 프리뷰로 쓰고, 새로고침해도 남고, `.md` 로 뽑거나 들여올 수 있다. 앱으로 설치해 오프라인에서도 같은 기능을 쓴다 |
| M2 | 백엔드와 계정 | 로그인하고, 문서가 서버에 저장되어 다른 기기에서 열린다 |
| M3 | 실시간 협업 | 같은 문서를 여러 명이 동시에 편집하고 서로의 접속·커서가 보인다 |
| M4 | 댓글 | 텍스트 내용에 붙는 댓글을 달고 해결·삭제할 수 있다 |
| M5 | 이미지 서버 저장 | ~~이미지를 서버에 올려 다른 기기·공유 링크에서도 보인다~~ → 2026-09-15 M2 F-209 로 당김 (Q34). 로컬 첨부는 M1 (F-156~F-158) |

- 단계는 순서대로 진행한다. 앞 단계가 끝나기 전에 다음 단계의 의존성을 설치하지 않는다
- 예외 (2026-09-15, Q31): M1 우클릭 명세(F-167~F-170)를 남긴 채 M2 를 먼저 진행한다
- 작은 명세로 쪼갤 대상은 M1 과 M2 (7장). M3 이후는 방향만 적고, 착수 시점에 이 문서를 먼저 고친다

## 5. M1 데이터 모델

```
Document
  id         string   // 생성 시 발급, 변하지 않음
  title      string   // 비면 "제목 없는 문서"
  content    string   // 마크다운 원문 그대로 (줄은 lineEnding 으로 이음)
  lineEnding "crlf" | "lf"  // 새 문서는 "crlf". 가져온 파일은 원래 형식 (Q9)
  createdAt  number   // epoch ms
  updatedAt  number   // epoch ms

Attachment (2026-09-14, F-156)
  id         string   // 소문자 16진수 16자. 원문 src 는 attachments/{id}.{ext}
  mime, ext  string   // png·jpg·gif·webp 만
  size       number   // 바이트, 5MB 이하
  width, height number
  createdAt  number
  blob       Blob     // 원본 바이트 그대로
```

- 편집 중인 문서의 원본은 CM6 `EditorState` 다. IndexedDB 기록은 **`EditorState` → 저장소 단방향 스냅샷**이며, 편집 중에 저장소나 React 상태에서 에디터로 역방향 동기화하지 않는다
- 저장소에서 에디터로 읽는 것은 문서를 여는 시점 1회뿐이다
- 스키마 버전을 DB 에 기록한다. M2 이관 때 필요하다
