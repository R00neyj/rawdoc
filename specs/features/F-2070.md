### 5.2 `src/app/liveNotices.ts` — 판정 세 가지

```ts
import type { Store } from '../types'
import type { DocMeta } from './docMeta'
import type { StopReason } from './liveDoc'

export type LiveStopNoticeBranch = 'read-only-revoked' | 'read-only-signed-out' | 'revoked' | 'gone' | 'signed-out'

export function isOwnServerDoc(storeKind: Store['kind'], currentDoc: Pick<DocMeta, 'role'> | null, sharedDoc: object | null): boolean
export function disconnectedNoticeMessage(readOnlySession: boolean, persistBroken: boolean | undefined): string
export function liveStopNoticeBranch(reason: StopReason | null, readOnlySession: boolean): LiveStopNoticeBranch | null
```

규칙(지금 식 그대로):
- `isOwnServerDoc`: `storeKind === 'server'` 이고 `isSharedDoc(currentDoc)` 가 거짓이고 `sharedDoc` 이 없을 때만 참. `currentDoc` 이 `null` 이어도 참이다(`isSharedDoc(null)` 은 거짓 — 지금 식 그대로, 관찰 2)
- `disconnectedNoticeMessage`: 읽기 전용 세션이면 `READ_ONLY_LIVE_NOTICE.disconnected`, 아니고 `persistBroken` 이 참이면 `LIVE_NOTICE.disconnectedVolatile`, 그 밖(`false`·`undefined`)은 `LIVE_NOTICE.disconnected`. 읽기 전용이 영속보다 먼저다
- `liveStopNoticeBranch`: 지금 `if` 사슬의 순서 그대로 — 읽기 전용 + `revoked` → `'read-only-revoked'`, 읽기 전용 + `signed-out` → `'read-only-signed-out'`, `revoked` → `'revoked'`, `not-found`·`deleted` → `'gone'`(읽기 전용 여부 무관), `signed-out` → `'signed-out'`, 그 밖(`forbidden`·`read-only`·`null`) → `null`

호출 자리(훅 안, 바뀌는 줄은 이것뿐이다):
- N1 effect 와 `revoked` 갈래의 `const ownDoc = store.kind === 'server' && !isSharedDoc(currentDoc) && !sharedDoc` 두 줄 → `const ownDoc = isOwnServerDoc(store.kind, currentDoc, sharedDoc)`
- N5 갈래의 `const message = readOnlySession ? … : …` 여러 줄(5줄) → `const message = disconnectedNoticeMessage(readOnlySession, liveSession?.persistBroken)` 한 줄. 이 갈래 안에서는 `liveSession` 이 늘 있다(`snap` 이 있어야 들어온다) — 식 결과가 지금과 같다
- `const reason = snap.stopReason` → `const branch = liveStopNoticeBranch(snap.stopReason, readOnlySession)`. 뒤따르는 다섯 조건(`readOnlySession && reason === 'revoked'` … `reason === 'signed-out'`)을 `branch === '…'` 로 바꾼다. 갈래 **본문과 주석·순서는 그대로**다. 마지막 한 줄짜리 `} else if (reason === 'signed-out') showSaveAsNewNotice(…)` 도 조건만 바뀐다

## 11. 열린 질문 (모두 기본값 — 기본값대로)

### Q1. 온라인 재시작 effect(`restartsOnOnline`)를 옮기나 — **기본값: App 에 남긴다**

- 이유: 이 effect 는 `setDocSession` 으로 세션을 새로 시작하고 `setOpenDoc(null)` 을 부른다. `handleResumeFailed`·`restartDocSession`·렌더 중 블록 b~d 와 같은 세션 핵이고, F-2059 4장 첫 행("`setOpenDoc` 10곳 — 단계 4 세션 핵")이 단계 4 로 미룬 경로다. 옮기면 훅이 `DocSession` 전체 타입을 알아야 하는데, 이 타입은 F-2059 2.3 이 단계 4 몫으로 정했다
- 다른 쪽(옮긴다 — 로드맵 이름 "오프라인 보기" 를 넓게 읽음): App 이 약 16줄 더 준다. 대신 옵션에 `docPath`·`setDocSession`·`setOpenDoc` 이 더해지고, `DocSession` 을 App 밖으로 export 하거나 훅에 같은 모양을 다시 적어야 한다. 이 조각이 4장 불변식 경로에 닿게 되어 `--repeat 3` 과 사람 확인이 붙는다

### Q2. 다른 탭·다른 곳 삭제 알림 effect 를 옮기나 — **기본값: App 에 남긴다**

- 이유: 훅 호출 자리(≈736)로 끌어올리면 이 effect 의 실행 자리가 약 750줄 위로 움직여, 같은 커밋에서 알림을 띄울 수 있는 `useDocLock`·`useTabSync`(`onNotice`)·`useE2ee`·금고 이관 판정 effect 보다 먼저 돈다. `pushNotice` 는 같은 등급이면 나중 것이 이기므로 겹칠 때 남는 알림이 바뀔 수 있다. 그 effect 가 읽는 `deletedElsewhereId` 는 App 에 남는 블록 h 가 되돌린다(F-2059 3.3)
- 다른 쪽(옮긴다): App 이 약 12줄 더 주고 `새 문서로 저장` 알림의 쓰임이 한 파일에 모인다. 대신 옵션에 `deletedElsewhereId`·`deletedElsewhereSourceRef` 가 더해지고 위 실행 순서 차이를 따로 확인해야 한다

### Q3. `liveNotices.ts` 로 무엇까지 떼나 — **기본값: 세 함수(5.2)**

- 이유: 세 함수는 조건식·문구 선택을 그대로 바꿔 끼울 수 있고, 호출 자리의 좁히기가 깨지지 않는다. 다른 판정(N5·N6 띄우기/걷기, N7 seq 판정)을 `'show' | 'dismiss' | null` 로 떼면 `ids.disconnected`·`shown` 의 `null` 좁히기가 함수 밖으로 나가 `!` 단언이나 본문 수정이 생긴다(F-2068 탐침의 `TS2345` 와 같은 종류) — "옮기기만" 을 넘는다
- 다른 쪽(더 뗀다): 단위 테스트가 N5·N6·N7 수명까지 덮지만 A5 의 빨강·초록 줄이 약 두 배가 된다
- 다른 쪽(`isOwnServerDoc` 하나만): 줄 변경이 가장 적지만, 지금 e2e 가 없는 N5′·N5v·N10 갈래 선택을 단위로 보지 못한다

### Q4. `--repeat 3` 을 두나 — **기본값: 두지 않는다 (4.6)**

- 이유: F-2059 4장의 어느 행도 이 조각을 가리키지 않고, 개요 4장 머리는 `--repeat 3` 을 불변식 조각에만 쓰는 예외로 정했다. 로드맵 행도 F-2070 에는 `verify:full` 만 적었다(F-2072~F-2074 에만 "4장 `--repeat 3`")
- 다른 쪽(둔다): `npm run e2e:one -- e2e/liveDoc.spec.js e2e/offlineDoc.spec.js e2e/liveResume.spec.js --workers 2 --repeat 3` 을 A4 에 더한다. `liveDoc` F-305 E15 가 10초 기다림을 포함해 약 3분이 더 든다

### Q5. `isOfflineView` 를 App 에 두나 — **기본값: App 에 두고 위로 올린다 (2.2)**

- 이유: 읽는 곳이 App 세 곳, 훅 한 곳이다. F-2069 의 `docScreenId` 와 같은 처리(같은 파일 안 이동)다
- 다른 쪽(훅이 `docPath` 를 받아 계산해 반환): 옵션이 `isOfflineView` 대신 `docPath` 가 되고 반환이 둘이 된다. 동작은 같다. App 의 `restartsOnOnline`·`isReadOnlyDoc`·`useDocSaver` 가 알림 훅의 반환값을 읽게 된다

### Q6. e2e 묶음에 둘째 명령(`F-2030 A12|F-2042 A3|F-2056 A3|F-407 E13`)을 더하나 — **기본값: 더한다 (8장)**

- 이유: L5 가 N2 자리에 뜨는 갈래(`isOwnServerDoc` 호출), 훅 반환 `showSaveAsNewNotice` 를 App 에 남는 삭제 알림이 부르는 두 갈래(bootMerge·다른 탭), 이 탭 금고 옮기기에서 N3 이 뜨지 않는 것은 로드맵 행 파일이 보지 않는다. 로드맵 행에서 빼는 것이 아니라 더하는 것이라 개요와 부딪치지 않는다(F-2066 Q2·F-2068 Q7 과 같은 판단). `verify:full` 이 어차피 전부 돌리지만, A4 는 조각 커밋 전 빠른 판정이다
- 다른 쪽(로드맵 행 그대로): 네 경로를 `verify:full` 에서만 본다

### 관찰 (이 조각은 고치지 않는다 — F-2059 7장 성격, 판정은 사용자)

1. **절 머리 주석이 `N1~N6` 이다.** 실제로는 N1~N10·L5·문서 묶음까지 다룬다. 3.6 은 옮긴 주석을 그대로 가져가라고 하므로 고치지 않는다. 새 호출 주석(5.3)은 `N1~N10` 으로 적는다
2. **`currentDoc` 이 `null` 이어도 "내 서버 문서" 로 본다.** `isSharedDoc(null)` 이 거짓이라, 목록에 아직 없는 문서(해시로 바로 연 공유 문서 등)가 동기화 뒤 4403 이면 N2 대신 L5 가 뜨거나 `recheckAccount()` 가 불릴 수 있다. 코드를 읽어 판단했고 실행해 보지 않았다. U6 이 지금 식을 그대로 고정한다
3. **N6 은 띄우기에만 "읽기 전용이 아님" 조건이 있고 걷기에는 없다.** 편집 세션에서 띄운 N6 은 뒤 세션이 읽기 전용이어도 `tooLarge` 가 거짓이면 걷힌다. 의도와 맞는 것으로 보이나 기록만 한다
4. **경계 — 옆 조각과 대조 필요:** N3 갈래 안의 F-407 7.4 금고 전환 몇 줄(`refreshDocFromServer` → `fresh?.e2ee` → `restartDocSession()`)은 이 effect 안에 있어 이 조각이 옮긴다. F-2073(금고 옮기기) 명세가 같은 줄을 자기 목록에 넣었으면 main 이 이 조각 쪽으로 정리한다. 이 갈래를 보는 e2e 는 없다
5. **경계 — 옆 조각과 대조 필요:** 구역 바로 아래 `liveRoomDoc` 사이드바 `updatedAt` effect(`liveChangedAtRef` 포함, F-305 10.1·F-2041·F-2056)와 `liveEditorOption`(편집기 `live` 넘김값, F-2059 3.4 목록)은 F-2059 5.4 표 어느 행에도 이름이 없다. 이 조각은 옮기지 않는다. F-2072(편집기 연동) 또는 단계 4(세션 핵) 중 어디로 갈지 main 이 F-2072 명세와 대조한다
