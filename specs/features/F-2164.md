## 2. 계약 (`splitOff.ts`)
```ts
export type SplitOnInput = { tabsBar: boolean; publicView: boolean; shares: boolean; help: boolean; trash: boolean }
export function splitOn(i: SplitOnInput): boolean                       // tabsBar 이고 나머지 넷이 모두 거짓
export function restoreSplit(s: SplitState, exists: (key: string) => boolean, lookup: (key: string) => TabMeta | undefined): SplitState
export function shownSplit(s: SplitState, on: boolean): SplitState      // on 이면 s, 아니면 { layout: 'single', ratios: [], focus: 0, panes: [s.panes[s.focus]] } — 칸 객체는 같은 것
export function withFocusTabs(s: SplitState, tabs: DocTabsState): SplitState   // panes[focus] 의 tabs·active 만 바꿈, 비어도 칸을 닫지 않음
export function splitUnitPanes(s: SplitState, currentDocId: string | null, drained: boolean): PaneDoc[] // drained 면 [{ docId: currentDocId }], 아니면 F-2163 unitPanes
```
- **`tabsBar`** = 탭이 창 위 줄 모드(`standalone && !narrow && !phone`, `useDocTabs` 가 `bar` 를 돌려주는 조건). 그래서 1024px 미만(`NARROW_QUERY`)·휴대폰 폭·브라우저 탭은 모두 꺼짐. 셋째~다섯째 = App `publicRoute !== null`·`sharesOpen`·`helpOpen`·`trashOpen`(S-5·S-6·S-7·S-10)
- 끄지 않는 화면: 홈·S-4 공유·S-8 지도는 F-2163 `hidden`(편집기 유지) 그대로. S-11 로컬 파일도 F-2159 6장 목록 밖이라 홈과 같게 둔다
- `restoreSplit` = 칸마다 `syncTabMeta(restoreTabs(칸, exists), lookup)` 뒤 `prunePanes`. 부팅·다시 켜기가 같은 함수를 쓴다
- `withFocusTabs` 가 빈 칸을 닫지 않는 이유: `storeTabs`(꺼진 곳의 저장)와 뜻을 맞춰, 빈 칸은 다시 켤 때 `restoreSplit` 의 `prunePanes` 가 한 번에 닫는다(F-2162 5장)

## 3. 복원 (결론 1, 흐름 6 "다시 엶")
- `useDocTabs` 복원 effect 의 읽기를 `parseStoredTabs` → `parseStoredSplit(getPref('md.docTabs',''), scope, getPref('md.viewMode'))` → `restoreSplit(…, 목록 ids, metaLookup)` 로 바꾼다. 문턱(`enabled && ready`, 범위마다 한 번)·`freshStart` 판정은 그대로, 대상만 `panes[focus]`: freshStart 이고 포커스 칸 활성 ≠ `currentDocId` 면 그 활성으로 `navigate`, 주소가 문서를 가리키면 `routeOpen(s, 그 문서, 있으면 'preview' 없으면 'pinned', 칸 자리 순서(포커스 먼저), null)`
- 나머지 칸은 활성 탭만 묶음이 생겨 내용을 연다(F-2163 `unitPanes`). 칸 key 는 새로 만든다. 복원 뒤 App 보기 방식 = `panes[focus].viewMode`(F-2163 3장 포커스 바뀜 경로 그대로). `ratios` 는 저장값(`parseStoredSplit` 이 0.2~0.8 로만 자름), 화면 값은 6장
- 부팅 때 꺼져 있으면(좁은 창·전용 화면 주소) 복원은 `enabled` 가 참이 될 때 위 그대로 돈다(지금 문턱). 전용 화면 주소로 부팅해도 `enabled` 면 복원은 하고 그리기만 꺼진다

## 4. 꺼짐 동안 (결론 2, 흐름 6 "1024px 미만", 결정 11)
- **메모리의 `SplitState` 는 그대로 들고, 탭 조작은 포커스 칸에만**: 따라가기 effect 는 `routeOpen` 대신 `withFocusTabs(s, openTabCapped(panes[focus], entry, mode, paneTabLimit(s, focus)))`, 탭 닫기·고정·옮기기도 `withFocusTabs`. 저장은 `storeTabs(raw, scope, panes[focus])`(나머지 `split` 보존). 휴대폰 탭(`phone`)·전용 화면의 창 탭 줄은 포커스 칸 탭을 보인다. 1024px 미만 비휴대폰은 지금처럼 탭 effect 가 모두 멈춘다
- 꺼진 동안 나누기·칸 닫기 항목은 숨기고(`splitAction` 을 부르지 않음), `Alt+Shift+D`·`Ctrl+Shift+W`·`Ctrl+1~4` 는 가로채지 않는다
- **다시 켜질 때**(꺼짐→켜짐 렌더): 메모리 값에 `restoreSplit`, 그다음 `currentDocId` 가 있으면 3장과 같은 `routeOpen`(좁은 창에서 고른 문서가 다른 칸에만 있으면 그 칸이 포커스). 저장소를 다시 읽지 않는다 — 꺼진 동안 다른 브라우저 탭이 쓴 거울이 배치를 흔들지 않게. 비율 저장값은 꺼짐 동안 안 바뀌어 넓히면 원래 값

## 5. 내리기 순서·본문 유실 방지 (결론 3)
- 막힘(코드로 확인): 묶음보다 편집기가 먼저 내려가면 대기 중이던 저장이 `host.getText` → `''` 로 **빈 본문을 저장**한다(`runSave` 가 저장 순간 읽음). 묶음이 먼저 빠지면 `docId` 리셋 effect 가 dirty 를 버려 마지막 입력을 잃는다. 그래서 순서는 ① 꺼짐 감지 렌더: 칸·묶음은 그대로 두고 포커스 칸 말고 `hidden`(F-2163 3장) ② `flushAll()`(F-2163 칸 닫기와 같은 통로)을 기다림 — 진행 중 저장(`savingRef`)도 이때 끝남 ③ 그 사이 다시 켜지지 않았으면(꺼짐 세대 번호 비교) `drained = true` → `splitUnitPanes` 가 `[{ docId: currentDocId }]` 가 돼 나머지 묶음이 슬롯에서 빠지고(연결·방 Doc 내림, F-2160 8장) 같은 커밋에 그 칸 편집기도 내려간다
- `flushAll` 이 `false` 여도 ③ 으로 간다 — 지금 문서 전환(`beforeLeaveDoc` 결과 무시)과 같고, 실패는 저장 오류 띠가 이미 알린다. 켜지는 렌더에서 `drained` 는 곧바로 거짓, 부팅 첫 값은 `!on`(비울 묶음이 없음). 이 비우기는 `enabled` 문턱 밖에서 돈다(좁은 창은 `enabled` 가 거짓이 되는 바로 그때 비워야 한다)
- S-6·S-7·S-10 진입은 이미 `await beforeLeaveDoc()` 뒤 상태를 바꾸므로 ② 가 곧바로 끝난다. **S-5 는 App `handlePublicHashChange` 가 flush 없이 `setPublicRoute` 해 편집기가 먼저 내려간다** → `bootPhase === 'ready'` 이고 새 경로가 공개 보기면 `await beforeLeaveDoc()` 뒤, 주소가 그새 바뀌었으면(`useHashRouting` `hashAtEntry` 선례) 그만두고, 아니면 `setPublicRoute`. 1칸에도 같은 위험이라 칸 수와 무관하게 적용
- 같은 문서가 포커스 칸과 내려가는 칸에 함께 있으면 묶음은 남고(포커스 칸) 그 칸 편집기만 `paneSources.remove`(F-2163 6장)

## 6. 창 크기와 비율 (결론 4)
- 켜짐/꺼짐은 창 폭(`NARROW_QUERY`) 하나로 정한다 — 칸 영역(사이드바·오른쪽 패널을 뺀 폭)이 560px 보다 좁아도 끄지 않고 `clampRatios(…, size)` 가 그 축을 0.5 로 둔다(F-2162 4장 그대로)
- `SplitPanes` 는 ResizeObserver 크기마다 `clampRatios(layout, 저장 ratios, 크기)` 로 그리고 **저장값은 바꾸지 않는다**(F-2163 3장). 추가: 너비나 높이가 0 인 관찰(`hidden`·꺼짐 중)은 버리고 마지막 크기를 쓴다 — 0 이면 하한 > 상한이라 모든 경계가 0.5 로 튄다. 꺼짐이면 `shownSplit(s, false)` 한 칸만 그리고, 그 칸의 문서는 `currentDocId`(좁은 창에서 탭이 안 따라가도 화면은 고른 문서), 칸 key 는 같은 칸 객체라 `carryPaneKeys` 가 옛 key 를 줘 **포커스 칸 편집기를 다시 만들지 않는다**(실행 취소 유지)
