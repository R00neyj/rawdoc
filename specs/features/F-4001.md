# F-4001 콘텐츠 보안 정책(CSP) — 경로별 정책·위반 보고·단계 전환

작성일: 2026-10-06
상태: 승인(2026-10-06, 사용자 'ㄱㄱ' — 열린 질문 Q1~Q3 모두 기본값 확정, 구현은 1단계 Report-Only 까지). 보안(`F-4NNN`)이고 비인증 쓰기 라우트·서비스 워커 캐시 머리 문제가 들어 있어 250줄을 넘는다
범위: 앱·공개 페이지·로그인·랜딩·사이트 페이지·정적 자산 응답에 CSP 를 얹는다. 위반 보고 엔드포인트, Report-Only → enforce 단계. 화면 없음, `src/app/App.tsx` 안 건드림

## 정해진 것 (사용자, 바꾸지 않는다)
1. 위반 보고는 자체 Worker 엔드포인트로 모은다. 외부 보고 서비스 없음
2. `style-src` 는 `'unsafe-inline'` 허용, `script-src` 만 엄격. 스타일 nonce 없음
3. 랜딩(`/`·`/welcome`)의 서버 생성 인라인 `<script>` 는 요청마다 nonce. 해시·외부 파일 분리 없음
4. Report-Only 로 먼저 내보내고 위반을 본 뒤 enforce
5. 경로별로 정책을 달리한다

**이미 들어간 것:** 커밋 `eb904f2` 의 `worker/securityHeaders.ts` `withSecurityHeaders` 가 Worker 를 거치는 응답에 `X-Frame-Options: DENY`·`X-Content-Type-Options: nosniff`·`Referrer-Policy`(`/p/` 는 `no-referrer`)·`Content-Security-Policy: frame-ancestors 'none'` 을 붙인다. 이 변경은 명세 없이 들어갔다 — 이 명세가 그 사후 근거이고, 세 머리는 그대로 두고 그 위에 얹는다

## 2. 계약 — `src/lib/cspPolicy.ts`

Worker 는 `src/lib/**` 만 import 한다(architecture 6장), `vite.config.ts` 도 이 파일을 읽는다 — 그래서 `worker/` 가 아니라 여기 둔다. `node:` import 없음

```ts
export type CspKind = 'app' | 'landing' | 'login' | 'site' | 'api'
export type CspMode = 'report-only' | 'enforce'
export const CSP_MODE: CspMode = 'report-only'      // 단계 전환은 이 한 줄 + _headers (7장)
export const CSP_REPORT_PATH = '/api/csp-report'
export const BOOT_PAINT_SHA256 = 'c/oJtoDfQLhIQbvu8wTNg+mYvbePh/eI3OCN8P6lJsQ='  // r1
export function buildCsp(kind: Exclude<CspKind, 'api'>, opts: { nonce?: string; origin?: string }): string
export function cspHeaders(kind: CspKind, mode: CspMode, opts: { nonce?: string; origin?: string }): Record<string, string>
export function staticHeaderLines(mode: CspMode): string[]   // _headers `/*` 묶음의 머리 줄들
export function createCspNonce(): string                       // crypto.getRandomValues 16바이트 → base64
export function cspRevisionSource(): string                    // `${CSP_MODE}\n${buildCsp('app', { origin: 'https://rawdoc.app' })}`
```

- `BOOT_PAINT_SHA256` 는 손으로 적은 상수다. Worker 의 머리 함수가 동기라 `crypto.subtle` 비동기 계산을 피한다. `bootPaint.ts` 를 바꾸는 명세(예: F-2092 검사기 버전 올림 — 스크립트에 숫자가 박힌다)는 이 상수도 바꾼다 — U2 가 잡는다
- `origin` 은 요청 URL 의 출처. `connect-src` 의 소켓 출처는 그 스킴을 `https:`→`wss:`, `http:`→`ws:` 로 바꾼 것(로컬 `dev:worker` 8790 도 맞는다). CSP3 는 `'self'` 가 같은 호스트 `wss:` 를 덮지만 Safari 의 예전 동작이 확인되지 않아 적어 둔다

### 3.2 정책 전문

`{WS}` = 2장의 소켓 출처, `{N}` = 요청마다 새 nonce, `{BOOT}` = `BOOT_PAINT_SHA256`

| 종류 | 정책 | 결정 근거 |
| --- | --- | --- |
| `app` | `default-src 'self'; script-src 'self' 'sha256-{BOOT}'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' {WS}; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; report-uri /api/csp-report` | 인라인은 부팅 스크립트 하나뿐이고 빌드 상수라 해시(r1). nonce 는 r11·r12 로 불가. eval 불필요(r2). `blob:` 첨부·`data:` CSS(r4). 외부 연결 없음(r3). 앱 폼은 모두 `preventDefault` |

- `worker-src`·`manifest-src`·`media-src`·`connect-src`(app 밖)는 `default-src 'self'` 를 따른다 — 적지 않는다. SW 등록(`/sw.js`)·매니페스트(`/manifest.webmanifest`)·`push-sw.js` 모두 같은 출처
- `'report-sample'` 은 넣지 않는다 — 보고에 코드 조각이 실려 오지 않게
- GitHub 프록시의 `PROXY_CSP`·다운로드 응답의 `default-src 'none'; sandbox`(`worker/githubImages.ts`)는 그대로 둔다

### 3.3 머리 묶음 (`cspHeaders`, `staticHeaderLines`)

| 모드 | `Content-Security-Policy` | `Content-Security-Policy-Report-Only` |
| --- | --- | --- |
| `report-only` | `frame-ancestors 'none'` (지금 것) | 3.2 정책 |
| `enforce` | 3.2 정책 | 없음 |

- `api` 는 모드와 상관없이 `Content-Security-Policy: frame-ancestors 'none'` 하나. 응답에 이미 CSP 가 있으면(프록시) **같은 객체를 그대로** 돌려준다 — 지금 규칙
- `api` 밖 종류는 응답에 이미 있는 두 CSP 머리를 **지우고** 다시 쓴다. r10 때문에 `ASSETS.fetch` 응답에는 `_headers` 의 `site` 정책이 먼저 붙어 오기 때문이다
- `/p/*` 의 `Referrer-Policy` 는 있든 없든 `no-referrer` 로 **덮어쓴다**. 나머지 세 머리는 지금처럼 없을 때만
- `public/_headers` 의 `/*` 묶음 = `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, 그리고 위 표의 `site` 줄. `Referrer-Policy` 는 넣지 않는다 — `/*` 가 `ASSETS.fetch('/')` 로 만든 `/p/` 응답에도 붙어 `no-referrer` 와 부딪히고, 브라우저 기본값이 이미 `strict-origin-when-cross-origin` 이다. 이 묶음이 r9 의 빈틈(사이트 페이지·자산·`sw.js` 에 프레임 차단 없음)도 메운다

### 3.4 nonce 와 `csp-rev`

- `worker/index.ts` `fetch` 가 요청마다 `createCspNonce()` 를 한 번 부르고 `handleRequest` 와 `withSecurityHeaders` 둘에 넘긴다. `handleRequest` 는 랜딩 두 분기(`/welcome`, `/` 의 `landing`)에서 `renderWelcomePage({ path, nonce })` 로 쓴다. 다른 종류에선 버린다(16바이트 난수, 비용 무시)
- `renderWelcomePage` 의 `nonce` 는 선택 인자다. 주면 r7 의 실행 인라인 스크립트에만 `nonce="{N}"`. JSON-LD·`src` 스크립트에는 붙이지 않는다. 안 주면 지금 HTML 그대로 — `e2e/helpers.js` `mockLanding`·`mockWelcome` 이 고치지 않고 지난다
- 계약: `withSecurityHeaders(response: Response, request: Request, nonce: string): Response`
- **`csp-rev`:** `vite.config.ts` `brandHtmlPlugin` 이 `<meta name="csp-rev" content="{cspRevisionSource() 의 sha256 hex 앞 8자}">` 를 `head` 에 넣는다(`node:crypto`). 이유: r11 — 모드나 앱 정책만 바꾼 배포는 `index.html` 바이트가 같아 precache revision 이 그대로이고, 설치·SW 사용자는 옛 머리를 계속 쓴다. meta 가 바뀌면 revision 이 바뀌어 새 SW 가 받아 온다(적용은 앱의 기존 업데이트 안내 또는 모든 창을 닫은 뒤)
- 사이트 페이지에는 넣지 않는다 — SW 가 precache 해 옛 머리가 남아도 스크립트가 없어 깨질 것이 없다

## 4. 위반 보고 — `POST /api/csp-report`

### 4.1 형식: `report-uri` 만
`application/csp-report` 한 건씩(r13 에서 실제 확인). `report-to`(Reporting API, `application/reports+json`, 묶음·지연 전송)는 쓰지 않는다 — Chrome 은 `report-to` 가 있으면 `report-uri` 를 무시하는데 그 전송의 `Origin`·자격 증명 동작을 확인하지 못했다(Q2)

### 4.2 처리 순서 (`worker/index.ts` 가 `/ws/` 처럼 Origin 검사·라우트 표 **앞**에서 `handleCspReport` 로 넘긴다 → `runWriteGate` 를 거치지 않는다)

1. `POST` 아니면 405 `method_not_allowed`
2. `Origin` 이 **있고** `isAllowedOrigin` 이 거짓이면 403 `forbidden_origin`. **없으면 통과** — 브라우저·버전에 따라 빠질 수 있고, 세션·쿠키를 쓰지 않는 라우트라 CSRF 대상이 아니다. 남의 사이트가 보내는 가짜 보고는 같은 출처 `Origin` 을 달 수 없다
3. `Content-Type` 이 `application/csp-report` 나 `application/json` 으로 시작하지 않으면 415 `unsupported_media_type`
4. 본문 상한 **8,192바이트** — `worker/docs.ts` `readJsonLimited` 로 읽는다. 넘으면 413 `too_large`, JSON 아니면 400 `invalid_json`. r13 보고 한 건은 정책 문자열을 품어 1KB 안팎
5. `WRITE_LIMITER.limit({ key: 'csp:' + (CF-Connecting-IP ?? 'unknown') })` 가 `success: false` 면 **204**(저장 안 함). 바인딩이 없거나 던지면 통과(`runWriteGate` 와 같은 태도). IP 는 키로만 쓰고 저장하지 않는다
6. 정규화(4.3) 결과가 `null` 이면 204
7. 같은 격리(isolate)에서 같은 키를 60초 안에 이미 썼으면 204 — 깨진 정책이 페이지 열 때마다 D1 쓰기를 부르지 않게. 기억은 500개를 넘으면 비운다
8. D1 upsert(4.4) 후 204. D1 오류는 `console.error` 후 204

응답 본문 없음. 세션을 읽지 않는다

### 4.3 정규화 `normalizeCspReport(body: unknown, origin: string): CspReportRow | null` (순수)

개인 정보·링크 토큰이 남지 않게 **분류값만** 남긴다. URL 경로·쿼리·`referrer`·`original-policy`·`script-sample` 은 버린다

| 칸 | 규칙 |
| --- | --- |
| `page` | `document-uri` 가 다른 출처거나 못 읽으면 `null`(버림). 경로 `/`→`root`, `/welcome`→`welcome`, `/login`→`login`, `/p/` 로 시작→`public`(**토큰은 남지 않는다**), `/guides`·`/guides/…`·`/changelog`·`/help`·`/privacy`·`/terms`→`site`, 나머지→`other` |
| `directive` | `effective-directive`, 없으면 `violated-directive` 의 첫 낱말. `[a-z-]` 1~40자가 아니면 `null` |
| `blocked` | `inline`·`eval`·`wasm-eval`·`trusted-types-policy`·`trusted-types-sink` 는 그대로. `data`·`data:…`→`data`, `blob`·`blob:…`→`blob`. 같은 출처 URL→`self`(경로 버림 — `/pub/docs/{token}/…` 가 들어올 수 있다). `*-extension:` 스킴→`{스킴}:`. 그 밖 `http(s)`·`ws(s)` URL→출처(`scheme://host[:port]`). 빈 값→`''`, 나머지→`other`. 200자 자름 |
| `source` | `source-file` 이 같은 출처이고 경로가 `/assets/{파일}`·`/sw.js`·`/push-sw.js`·`/workbox-{…}.js` 면 그 경로(쿼리 버림), 다른 같은 출처 경로→`self`. 확장 스킴·외부 출처는 `blocked` 와 같은 규칙. 없으면 `''` |
| `line` | `line-number` 가 0 이상 10,000,000 이하 정수면 그 값, 아니면 0 |
| `mode` | `disposition` 이 `enforce`·`report` 가 아니면 `null` |

### 4.4 저장 — D1 `csp_reports`

D1 을 고른 이유: `wrangler.jsonc` 에 `observability`(Workers Logs)가 없어 `console` 로그는 `wrangler tail` 로 **살아 있는 동안만** 보인다. 승격 판단(7장)에 며칠치 집계가 필요하다

```sql
CREATE TABLE csp_reports (
  page TEXT NOT NULL, directive TEXT NOT NULL, blocked TEXT NOT NULL,
  source TEXT NOT NULL, line INTEGER NOT NULL, mode TEXT NOT NULL,
  count INTEGER NOT NULL DEFAULT 1, first_at INTEGER NOT NULL, last_at INTEGER NOT NULL,
  PRIMARY KEY (page, directive, blocked, source, line, mode)
);
```

- 같은 키면 `count + 1`, `last_at` 갱신(밀리초). 새 키는 표가 **1,000행 미만일 때만** 넣는다 — 그 요청은 204 로 버린다
- 보존 **30일**: 매일 Cron(`scheduled` 의 매일 분기)에 `cleanupCspReports(env, now)` 를 `waitUntil(runQuietly(…))` 로 하나 더 — `last_at < now − 30일` 삭제
- 사람·IP·UA·URL 을 저장하지 않으므로 개인정보 처리방침은 바꾸지 않는다
- 보는 법(새 스크립트 없음): `npx wrangler d1 execute md-editor-db --remote --command "SELECT page, directive, blocked, source, line, mode, count, datetime(last_at/1000,'unixepoch') AS last FROM csp_reports ORDER BY last_at DESC LIMIT 100"`
- 배포: 원격 D1 마이그레이션(`0024`)을 코드보다 먼저 (deploy 스킬)

## 9. 열린 질문

### Q1. 앱 부팅 인라인 스크립트를 해시로 허용하나 — **기본값: 해시(`'sha256-…'`)**
- 사용자 지시의 "해시·외부 파일 분리 없음" 은 랜딩·로그인 대상이었고, 앱에는 인라인 스크립트가 없다고 알고 계셨다(r1 로 있음). nonce 는 앱 응답이 SW 에 머리째 캐시돼 불가(r11)
- 해시인 이유: 스크립트가 빌드 상수라 값이 고정되고, 첫 칠 전에 돌아야 하는 머리 스크립트(F-2015)라 요청을 하나 늘리지 않는다
- 다른 쪽(`/boot-paint.js` 외부 파일)을 고르면: 상수·U2 가 없어지고 `script-src 'self'` 만 남는다. 대신 `vite.config.ts` `bootPaintPlugin` 이 파일을 내고 precache 에 들어가며, 첫 방문 첫 칠 전에 왕복이 하나 는다(F-2015 의 "튀지 않음" 목표와 부딪힐 수 있음)

### Q2. `report-to` 를 함께 쓰나 — **기본값: `report-uri` 만**
- 이유: `report-uri` 는 Chrome 154 에서 형식·`Origin` 까지 확인했다(r13). `report-to` 를 넣으면 Chrome 이 `report-uri` 를 버리는데 그 전송은 확인하지 못했다
- 다른 쪽을 고르면: `Reporting-Endpoints` 머리(Worker 응답만 — `_headers` 는 절대 주소를 요청마다 못 만든다)와 `application/reports+json` 배열 파싱이 더해지고, 4.2 의 2번을 실제 전송으로 다시 확인해야 한다

### Q3. 승격(7장)을 F-4001 의 두 번째 커밋으로 두나 — **기본값: 따로 커밋 `CSP 강제 전환 (F-4001 2단계)`**
- `CLAUDE.md` "한 F 를 여러 커밋으로 나누지 않는다" 의 예외가 필요하다. 승격은 7일 관찰 뒤라 구현 커밋에 넣을 수 없다
- 다른 쪽을 고르면: 승격을 새 번호(예: F-4002, 두 줄 명세)로 떼어 규칙을 지킨다. 명세 하나가 더 생긴다

## 10. 가정으로 둔 것 (Report-Only 1단계가 확인한다)

- (a) 제공자 인증 흐름의 리다이렉트가 `accounts.google.com`·`github.com` 밖으로 나가지 않는다. 브라우저가 `form-action` 을 리다이렉트에도 적용하는지·다른 호스트를 거치는지는 확인하지 않았다 — H1 로그인 행과 4.4 조회의 `login`/`form-action` 행으로 본다. 나오면 그 출처를 `login` 정책에 더한다
- (b) Firefox·Safari 도 `report-uri` 를 `application/csp-report`(또는 `application/json`)로 보낸다. 확인한 것은 Chrome 뿐
- (c) `api` 종류를 `frame-ancestors 'none'` 그대로 둔다 — `default-src 'none'` 이 첨부 그림을 새 탭에서 여는 동작을 바꾸는지 확인하지 않았다. 바꾸지 않는 쪽이 안전하다고 봤다
- (d) 운영 자산 워커도 r10(miniflare 가 묶은 같은 원본)처럼 `env.ASSETS.fetch` 응답에 `_headers` 를 붙인다 — H2 가 확인한다. 붙지 않아도 3.3 은 덮어쓰기라 결과가 같다
- (e) 데모 편집기(`welcome-demo.js`)가 `blob:` 그림을 쓰는지는 보지 않았다 — `landing` 의 `img-src` 를 앱과 같게 열어 두었다
