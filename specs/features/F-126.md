## 2. 데이터

```
Folder
  id         string       // crypto.randomUUID()
  name       string       // 비면 "새 폴더"
  parentId   string|null  // null = 최상위. 최상위 폴더만 하위 폴더를 가진다 (2단계)
  createdAt  number
  updatedAt  number

Document (추가 필드)
  folderId   string|null  // null = 폴더 밖(최상위)
```

- 깊이: 최상위 폴더(1단계) → 하위 폴더(2단계) → 문서. 하위 폴더 안에 폴더를 만들 수 없다
- 기존 문서에는 `folderId` 가 없다. 읽을 때 `null` 로 취급하고 일괄 다시 쓰지 않는다
- 이름 중복 허용

## 3. 저장소

- DB `md-docs` **버전 2**. `upgrade` 에서 `oldVersion < 1` 이면 기존대로 `docs`·`meta` 생성, `oldVersion < 2` 이면 `folders`(keyPath `id`) 생성. `meta` 의 스키마 버전을 2 로 기록. 기존 `docs` 는 건드리지 않는다

추가 인터페이스 (`memoryStore` 도 같은 모양)

```js
store.listFolders()                          // Promise<Folder[]>
store.createFolder({ name, parentId })       // parentId 가 최상위 폴더가 아니면(없거나 그 자신이 하위 폴더) reject
store.renameFolder(id, name)                 // updatedAt 갱신
store.moveFolder(id, parentId)               // 결과 깊이가 2단계를 넘으면 reject (하위 폴더를 가진 폴더는 다른 폴더 안으로 못 감, 자기 자신 안으로 못 감)
store.removeFolder(id)                       // 한 트랜잭션: 안의 문서 folderId 와 하위 폴더 parentId 를 지운 폴더의 parentId 로 바꾸고 폴더 삭제
store.moveDoc(id, folderId)                  // folderId 만 바꾼다. updatedAt 은 바꾸지 않는다 (편집이 아니므로 최근 수정순을 흔들지 않는다)
store.create({ title, content, lineEnding, folderId })   // folderId 생략 시 null
```

- 문서를 지운 폴더로 옮겨 없는 `folderId` 를 가진 문서가 생기면(다른 탭 동시 조작 등) 목록에서 최상위에 보인다 (`folderTree.js` 가 처리)

## 4. `folderTree.js`

- `buildTree({ folders, docs }) → Node[]`
  - 같은 부모 안 순서: 폴더 먼저(이름 `localeCompare(b, 'ko')` 오름차순), 그 다음 문서(`updatedAt` 내림차순 — I6 은 폴더 안에서도 적용)
  - 부모가 없는 폴더·문서는 최상위로
- `canMoveFolder({ folders, id, parentId }) → boolean`, `canCreateFolder({ folders, parentId }) → boolean`
- `ancestorsOfDoc({ folders, doc }) → folderId[]` (문서를 열 때 펼칠 폴더)

## 5. 화면 (ia.md 2장 B·3.17)

### 5.1 사이드바
```
문서
[＋ 새 문서] [＋ 새 폴더]
[↥ 가져오기]

▾ 기획               ⋯
   ▸ 회의록          ⋯
     API 초안         ⋯
▸ 개인               ⋯
  협업 규칙           ⋯
```
- 폴더 행: `▸`(닫힘) / `▾`(열림) + 이름. 행 클릭으로 펼침 전환. `aria-expanded`
- 목록은 `role="tree"`, 항목 `role="treeitem"`. 들여쓰기 한 단계 14px
- 펼침 상태는 `md.openFolders`(폴더 id JSON 배열)에 저장. 새로 만든 폴더는 열린 상태. 문서를 열면(선택·해시·새 문서·가져오기) 그 문서의 조상 폴더를 연다
- 기존 문서 항목의 `×` 는 `⋯` 메뉴로 바꾼다. 마우스 오버·키보드 포커스 시 표시 (기존 `×` 규칙과 같음)

### 5.2 `⋯` 메뉴
| 대상 | 항목 |
| --- | --- |
| 최상위 폴더 | `새 문서`, `하위 폴더`, `이름 변경`, `삭제` |
| 하위 폴더 | `새 문서`, `이름 변경`, `삭제` |
| 문서 | `폴더로 이동…`, `삭제` |

- 메뉴는 앱이 그린다 (라이브러리 없음). 방향키로 항목 이동, Enter 실행, Esc·바깥 클릭으로 닫고 포커스를 `⋯` 로 되돌린다

### 5.3 동작
- `＋ 새 문서`: **현재 문서가 속한 폴더** 안에 만든다 (없으면 최상위). 메뉴의 `새 문서` 는 그 폴더 안에. 이후 흐름은 ia.md 3.3
- `가져오기`: 현재 문서가 속한 폴더 안에 만든다
- `＋ 새 폴더`: 최상위에 `새 폴더` 로 만들고 그 행을 이름 입력 상태로 바꾼다. `하위 폴더` 도 같다
- 이름 입력: 행 안 `<input>`. Enter·포커스 잃음 = 확정, Esc = 입력 전 이름 유지. 비우면 `새 폴더`
- 폴더 삭제: D-1 을 폴더 문구로 — `"{이름}" 폴더를 삭제할까요? 안의 문서와 하위 폴더는 한 단계 위로 옮겨집니다.` / `삭제` `취소`. 문서는 지워지지 않는다
- 문서 삭제: 기존 D-1 그대로 (메뉴에서 연다)
- `폴더로 이동…`: D-3 대화상자. 제목 `폴더로 이동`, 선택지 `최상위` + 모든 폴더(하위 폴더는 들여써 표시) 라디오 목록, 현재 위치 선택된 상태, `이동` `취소`
- 끌어놓기(HTML Drag and Drop): 문서 → 폴더 행·최상위 빈 영역, 폴더 → 최상위 폴더 행·최상위 빈 영역. 놓을 수 없는 대상(깊이 초과, 자기 자신)은 강조하지 않고 놓아도 아무 일 없음. 놓을 수 있는 대상은 `--accent-soft` 배경
- 끌어놓기는 마우스 전용이고, 키보드로는 메뉴의 `폴더로 이동…` 을 쓴다. 폴더의 키보드 이동은 M1 에서 제공하지 않는다
- 해시 URL 은 바꾸지 않는다 (`#/d/{id}`)
- S-2(문서 0개)에서도 폴더는 사이드바에 보인다
