### 3.1 공개 모양

- 이름·인자 순서는 F-3003·F-3006·F-3007 이 그대로 부르는 계약이다. 내부 도우미(HKDF, base64url, 이어 붙이기)는 export 하지 않는다
- `nowMs` 를 인자로 받는 이유: 시계를 테스트에서 고정한다(`Date.now()` 를 안에서 부르지 않는다)
- `PushOutcome` 은 F-3001 3.8 분류의 이름이다: `sent` = 2xx(부르는 쪽이 `fail_count` 를 0 으로, 하루 지났으면 `last_ok_at`), `gone` = 구독이 없다(지운다), `transient` = 이번만 건너뜀(아무것도 안 쓴다), `rejected` = 그 밖 거절(`fail_count` +1, 3 이면 지운다 — F-3006)

### 3.2 VAPID 키 (`importVapidKey`)

- 입력은 비밀 값 `VAPID_PRIVATE_JWK` 의 문자열 그대로(F-3001 3.8). `undefined`·빈 문자열·JSON 아님·`kty !== 'EC'`·`crv !== 'P-256'`·`d`·`x`·`y` 중 하나라도 없거나 base64url 로 풀어 32 B 가 아님·`importKey` 거절(m4) → **`null`**. 던지지 않는다 — `null` 이면 부르는 쪽이 "푸시 꺼짐"(503·경로 0, F-3001 3.3)으로 다룬다
- 가져올 때 JWK 의 `ext`·`key_ops`·`alg` 는 무시하고 `{ kty, crv, d, x, y }` 만 넘긴다(m3 — 스크립트가 어떤 모양으로 만들든 받는다). 비밀 키는 `extractable: false`, 용도 `['sign']`
- `publicKey` = base64url(`0x04 ‖ x ‖ y`), 패딩 없음, 87자(m3). 이 값이 F-3003 `GET /api/push/key` 의 `publicKey` 이고 `Authorization` 의 `k=` 다

### 3.3 VAPID JWT·`Authorization` (`vapidJwt`, `createVapidAuth`)

- JWT = `base64url(머리) . base64url(내용) . base64url(서명)`, 패딩 없음
  - 머리는 정확히 `{"typ":"JWT","alg":"ES256"}`(이 순서, 공백 없음)
  - 내용은 키 셋 `aud`·`exp`·`sub` 만. `aud` = 인자 그대로, `exp` = `floor(nowMs / 1000) + VAPID_JWT_TTL_SEC`(43,200 — 12시간, RFC 8292 의 24시간 이하), `sub` = 인자 그대로
  - 서명 = `ECDSA`/`SHA-256` 으로 `머리.내용` 의 UTF-8 바이트에 서명한 64 B(r‖s) — 변환 없이 그대로(m5)
- `audience` 는 `pushAudience(endpoint)` — 그 주소의 `origin`(스킴+호스트+기본 아닌 포트). 허용 목록 밖·URL 아님이면 `null`
- `subject` 는 부르는 쪽이 **`new URL(BETTER_AUTH_URL).origin`** 을 넘긴다(F-3001 3.8 — 제품명·주소 문자열을 코드에 새로 쓰지 않는다). 이 함수는 `subject` 를 검사하지 않는다(10장 Q1)
- `createVapidAuth(keys, subject)` 가 돌려준 `header(audience, nowMs)` = `vapid t={JWT}, k={publicKey}`. **출처(`audience`)마다 JWT 하나를 기억**했다가, `nowMs / 1000 ≥ exp − VAPID_JWT_REFRESH_SEC` 가 되면 새로 만든다. 그 전에는 같은 문자열을 돌려준다. 기억은 그 객체 안에만 있다 — DO 인스턴스에 오래 두는 것은 F-3006, Worker 요청은 요청마다 새로 만든다(서명 0.08 ms, m2)

### 3.4 받는 쪽 키와 암호화 (`readPushKeys`, `encryptPushPayload`)

- `readPushKeys`: 두 문자열을 base64url 로 푼다. 알파벳 `A-Z a-z 0-9 - _` 만, 끝의 `=` 패딩은 허용(브라우저마다 `toJSON()` 모양이 다를 수 있다 — 확인 안 함). `p256dh` 는 65 B 이고 첫 바이트 `0x04`, `auth` 는 16 B. 그리고 `p256dh` 를 `importKey('raw', …, { name: 'ECDH', namedCurve: 'P-256' })` 해 보아 거절되면(m6) `null`. 그래서 **비동기**다. F-3003 이 `PUT /api/push/subscription` 검사에 이 함수를 그대로 쓴다(`null` → 400 `invalid`)
- `encryptPushPayload(plaintext, keys, seed?)` — RFC 8291 3.4 절차 그대로. 결과 = 머리 86 B(`salt` 16 B ‖ 레코드 크기 `4096` 빅 엔디언 4 B ‖ `idlen` = 65 ‖ 보내는 쪽 공개 키 65 B) ‖ AES-128-GCM(`plaintext ‖ 0x02`) 암호문(태그 16 B 포함)
  - **레코드 하나, 채움(padding) 없음** — 구분 바이트 `0x02` 하나만. 길이 = 86 + 평문 + 17
  - `seed` 가 없으면 부를 때마다 새 `salt`(`crypto.getRandomValues`, 16 B)와 새 ECDH P-256 키 쌍을 만든다. **`seed` 는 테스트 전용**(W1 에서 RFC 부록 A 값을 넣는다) — 운영 코드는 넘기지 않는다
  - 평문이 `PUSH_RECORD_SIZE − 17`(4,079 B)을 넘으면 던진다(레코드 하나에 안 들어간다). 실제 입력은 `encodePushPayload` 가 3,000 B 로 막는다(4.3)

### 3.5 허용 목록 (`isAllowedPushEndpoint`)

참인 조건 전부:
- 길이 1 ~ `PUSH_ENDPOINT_MAX_CHARS`(1,024)
- `new URL` 로 풀리고 `protocol === 'https:'`, `username`·`password` 빔, `port` 빔(기본 443)
- `hostname` 이 `PUSH_SERVICE_HOSTS` 의 한 항목과 같거나, 항목이 `.` 으로 시작하면 그 접미사로 끝나면서 앞에 한 글자 이상 있다

```ts
export const PUSH_SERVICE_HOSTS = [
  'fcm.googleapis.com',               // Chrome·안드로이드·삼성 인터넷·Opera
  'updates.push.services.mozilla.com', // Firefox
  '.push.apple.com',                  // Safari·iOS (web.push.apple.com 등)
  '.notify.windows.com',              // Edge (wns2-….notify.windows.com)
] as const
```

- F-3001 3.8 은 Apple 을 `web.push.apple.com` 하나로 적었다. 이 명세는 **`.push.apple.com` 접미사**로 넓힌다 — Apple 이 웹 푸시 문서에서 엔드포인트를 막는 서버에 `*.push.apple.com` 을 허용하라고 안내한다(일반 지식, **이번에 문서를 받아 확인하지 않았다**). 목록 전체의 확인은 10장 Q2
- `pushTopic(docId)` = `docId` 에서 `-` 를 뺀 문자열. 결과가 `/^[A-Za-z0-9_-]{1,32}$/` 가 아니면 `null`(RFC 8030 5.4 — `Topic` 은 base64url 알파벳 32자 이하). UUID 는 32자 16진수라 통과한다

### 3.6 요청과 응답 (`buildPushRequest`, `classifyPushStatus`, `sendPush`)

`buildPushRequest` 가 만드는 요청(계약 — F-3001 3.8):

| 항목 | 값 |
| --- | --- |
| 주소 | `target.endpoint` 그대로 |
| `method` | `POST` |
| `redirect` | `manual` — 허용 목록 밖으로 끌려가지 않게(SSRF, F-3001 3.8) |
| `TTL` | `String(PUSH_TTL_SEC)` = `86400` |
| `Content-Encoding` | `aes128gcm` |
| `Content-Type` | `application/octet-stream` |
| `Urgency` | `normal` |
| `Authorization` | `vapid.header(pushAudience(endpoint), nowMs)` |
| `Topic` | `topic` 인자가 있고 `/^[A-Za-z0-9_-]{1,32}$/` 일 때만. 없거나 틀리면 머리를 넣지 않는다 |
| 몸통 | `encryptPushPayload(encodePushPayload(payload), keys)` |

- 요청을 못 만들 때: 허용 목록 밖·`readPushKeys` 가 `null` → `{ outcome: 'gone' }`(그 구독은 다시 돼도 못 쓴다 — 지운다), `encodePushPayload` 가 `null` → `{ outcome: 'transient' }`(우리 쪽 문제라 구독을 벌하지 않는다)
- `Content-Length` 는 넣지 않는다(`fetch` 가 넣는다)

`classifyPushStatus(status)` — 순서대로 먼저 맞는 것:

| 입력 | 결과 | 까닭 |
| --- | --- | --- |
| `null`(네트워크 오류·시간 초과) | `transient` | |
| 200~299 (FCM·Mozilla·Apple 은 `201`) | `sent` | |
| 404, 410 | `gone` | 구독 없음·만료 |
| 429, 500~599 | `transient` | 다시 보내지 않는다(F-3001 3.1) |
| 그 밖 (3xx, 400, 401, 403, 413 등 모든 나머지) | `rejected` | 401·403 = VAPID 어긋남, 400·413 = 모양, 3xx = `redirect: 'manual'` 로 따라가지 않은 전환 |

`sendPush` = `buildPushRequest` → 못 만들면 그 결과(`status: null`) / 만들었으면 `fetchImpl(url, { ...init, signal: AbortSignal.timeout(PUSH_SEND_TIMEOUT_MS) })` → 던지면(네트워크·시간 초과) `{ transient, null }`, 응답이 오면 `{ classifyPushStatus(res.status), res.status }`. 응답 몸통은 읽지 않는다. `fetchImpl` 기본값은 전역 `fetch`. **던지지 않는다**(암호화 실패 포함 — 키가 `readPushKeys` 를 통과했는데도 실패하면 `transient`)

### 4.1 타입과 상수


F-3001 2.5 의 서버 쪽 상수를 **전부 여기서 export** 한다(값은 F-3001 2.5 그대로): `PUSH_BATCH_MS = 180_000`, `PUSH_PRESENCE_FRESH_MS = 90_000`, `PUSH_STALE_MS = 3_600_000`, `PUSH_TTL_SEC = 86_400`, `PUSH_SENDS_PER_RUN_MAX = 40`, `PUSH_SUBSCRIPTIONS_PER_USER_MAX = 5`, `PUSH_PAYLOAD_MAX_BYTES = 3_000`, `PUSH_EXCERPT_CHARS = 80`, `PUSH_SHARE_DEDUPE_MS = 600_000`, `PUSH_QUOTA_RATIO = 0.9`, `PUSH_QUOTA_REPEAT_MS = 604_800_000`, `VAPID_JWT_TTL_SEC = 43_200`. 클라이언트 쪽 `PUSH_SYNC_INTERVAL_MS` 는 F-2110 의 `src/app/pushClient.ts` 에 둔다(F-3001 2.5)

- 이 명세가 쓰지 않는 상수까지 지금 두는 이유: 뒤 명세 다섯(F-3003·F-3005~F-3008)이 **이 파일을 고치지 않고 import 만** 하게 — `docRoomCore.ts` 처럼 여러 명세가 한 파일을 차례로 고치는 겹침을 하나 줄인다. 값 자체는 단위 테스트로 못 박지 않는다(쓰는 명세의 행동 테스트가 판정한다)

### 4.2 모양 검사 (`readPushPayload`, `safePushUrl`)

- `readPushPayload` 가 `null` 이 아닌 조건 전부: 일반 객체, 키가 정확히 `v`·`title`·`body`·`tag`·`url` 다섯, `v === 1`, `title`·`body`·`url` 이 문자열, `title` 이 빈 문자열이 아님, `tag` 가 `/^(doc|share):[0-9A-Za-z-]{1,64}$/` 이거나 `quota`·`test`
- `url` 은 검사로 떨어뜨리지 않고 **`safePushUrl` 로 바꿔 끼운 값**을 돌려준다(F-3001 4.4 "아니면 `/` 로")
- `safePushUrl(url)`: 문자열이고 `/` 로 시작하며 `new URL(url, 'https://x.invalid').origin === 'https://x.invalid'` 이면 그대로, 아니면 `'/'`. `URL` 이 던지면 `'/'`. m7 이 이 규칙으로 `//`·`/\`·탭 끼운 주소를 걸러냄을 확인했다. 기준 출처 `https://x.invalid` 는 판정용 자리표시다(예약된 `.invalid` — 실제로 어디에도 가지 않는다)
- `FALLBACK_NOTIFICATION` = `{ title: '새 알림', body: '', tag: 'fallback', url: '/' }`(F-3001 5.1 마지막 행). F-3004 서비스 워커가 풀기·검사 실패 때 띄운다

### 4.3 직렬화 (`encodePushPayload`)

- `JSON.stringify` 를 UTF-8 로. 바이트가 `PUSH_PAYLOAD_MAX_BYTES`(3,000) 이하면 그대로
- 넘으면 `body` 만 줄인다: 코드 포인트 단위로 앞에서부터 가장 긴 머리 + `…` 로 바꿔 3,000 B 안에 드는 것. `body` 를 비워도(`…` 도 없이) 넘으면 `null`
- 실제로 넘는 입력은 문구 규칙(5장)상 나오지 않는다(m8 나쁜 경우 813 B) — 방어선이다

## 10. 열린 질문

### Q1. VAPID `sub` 가 `http://localhost:8790` 일 때 — **기본값: 검사하지 않고 그대로 넣는다**

- `sub` 는 부르는 쪽이 `BETTER_AUTH_URL` 의 `origin` 을 넘긴다. 운영은 `https://…` 라 RFC 8292(`mailto:` 또는 `https:`)에 맞다. 로컬 `npm run dev:worker` 는 `http://localhost:8790` 이다
- 기본값의 이유: RFC 8292 는 SHOULD 다. FCM 은 로컬 개발 `sub` 를 문제 삼지 않는다고 알려져 있다(**확인 안 함**). 로컬에서 Chrome 으로 테스트 알림을 보는 길을 막지 않는다
- 다른 안: `https:` 가 아니면 `importVapidKey` 를 부른 쪽이 푸시를 끈다(503). 로컬에서 푸시를 전혀 못 본다. 또는 `sub` 전용 비밀 값을 하나 더 둔다 — 새 설정 키와 배포 단계가 는다

### Q2. 허용 목록 네 항목 — **기본값: 3.5 표(Apple·Windows 는 접미사)**

- F-3001 3.8 은 "F-3003 이 착수 때 각 브라우저 문서로 다시 확인한다" 고 적었는데, 목록 상수는 이 명세가 만든다. **이 명세를 쓰며 브라우저 문서를 받아 확인하지 않았다**(이 환경에서 웹 문서를 받지 않았다)
- 기본값: 목록은 3.5 대로 구현하고, F-2110 까지 들어간 뒤 사람 확인(Chrome·Firefox·Edge·Safari 각각 켜기)에서 `이 브라우저의 푸시 서비스는 지원하지 않습니다.`(P6)가 뜨는 브라우저가 있으면 그 `endpoint` 호스트를 보고 이 상수를 고치는 작은 명세(또는 F-3003 에 한 행)를 낸다
- 다른 안: 구현 전에 사람이 네 브라우저에서 `PushSubscription.endpoint` 를 한 번씩 찍어 호스트를 적어 준다 — 이 명세 3.5 가 확정값이 된다

### Q3. 3xx 응답 — **기본값: 따라가지 않고 `rejected`**

- 이유: `endpoint` 는 클라이언트가 준 주소다. 전환을 따라가면 허용 목록 검사가 무의미해진다(F-3001 3.8 SSRF). 알려진 푸시 서비스는 푸시 요청에 전환을 쓰지 않는다(가정)
- 다른 안: 전환 대상이 허용 목록 안이면 한 번 따라간다 — 코드가 늘고 테스트가 하나 는다. 필요한 서비스가 나오면 그때

### Q4. 보내기 시간 초과 10초 — **기본값: `PUSH_SEND_TIMEOUT_MS = 10_000`, 넘으면 `transient`**

- 이유: 초대 `PUT` 의 `waitUntil` 은 응답 뒤 30초까지 돈다(Workers 일반 지식, 확인 안 함). 기기 5대를 병렬로 보내도 10초 안에 끝나야 남는다. DO 알람(F-3006)은 40건을 보내므로 병렬로 보내야 한다 — 그 방식은 F-3006 이 정한다
- 다른 안: 시간 초과 없음 — 푸시 서비스가 멎으면 알람·`waitUntil` 이 끝까지 붙잡힌다

### Q5. `PushCommentKind` 와 `docComments` 의 알림 종류 — **기본값: 이 명세는 따로 정의, 합치기는 F-3005 가**

- 이유: F-3005 가 `comment` 를 `docComments.ts` 에 더하기 전이다. 지금 합치면 `docComments.ts` 를 이 명세가 고쳐야 하고 F-3005·F-2111 과 겹친다
- 다른 안: 이 명세가 `docComments.ts` 의 종류 타입에 `comment` 를 먼저 더한다 — 그러면 `readNotificationsResponse`·`isNotificationItem` 과 어긋나는 기간이 생긴다(서버가 아직 `comment` 를 안 보내니 해는 없지만 타입이 거짓말을 한다)

### Q6. 평문 채움(padding) — **기본값: 없음**

- RFC 8291 은 채움을 허용한다(길이로 내용을 짐작하지 못하게). 푸시 서비스는 암호문 길이를 본다 — 제목·발췌 길이의 대략이 드러난다
- 이유: F-3001 3.9 가 푸시 서비스가 "주소·크기·시각" 을 본다고 이미 적었고, 채우면 모든 푸시가 커진다(4,096 B 로 채우면 푸시 서비스·기기 데이터가 5배 안팎). 다른 안: 256 B 단위로 올려 채운다 — `encryptPushPayload` 에 한 단계, W1 은 `seed` 에 채움 0 을 넣어 그대로
