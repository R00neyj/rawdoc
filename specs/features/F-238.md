# F-238 공개 공유 링크 OG 메타 동적 생성

작성일: 2026-09-17
상태: 사용자 "SEO 최적화 할거 뭐있지?" → 공개 공유 링크의 카카오톡·슬랙 등 미리보기가 전부 제네릭 태그(브랜드명만)로 뜨는 문제 확인 후 논의. 원인: 공유 URL이 해시(`#/p/{token}`) 기반이라 서버가 토큰을 볼 수 없음 → 경로 기반(`/p/{token}`)으로 바꿔야 서버사이드 주입이 가능하다는 설명에 사용자 "ㄱㄱ"로 승인. 명세 초안 작성 후 사용자 승인 완료(2026-09-17)
근거: F-210(단일 문서 공유, `#/p/{token}`), F-211(폴더 공개 보기, `#/p/f/{token}`), 커밋 `49b5a20`(og:title 등 정적 브랜드 태그 최초 도입)
전제: 공유 링크는 항상 루트에서 새로 발급된다(`ShareMenu.tsx`·`FolderMenu.tsx` 어디서도 발급 시 문서 id 를 hash 에 넣지 않음) — 그러므로 이번 경로 스킴은 `/p/:token`·`/p/f/:token` 두 가지만 있으면 되고, 폴더 안 특정 문서로의 딥링크(`#/p/f/{token}/{docId}`)는 계속 해시 하위 이동으로만 존재한다(App.tsx 기존 동작, 변경 없음)

## 2. 범위

- 새로 발급하는 공유 링크만 경로 기반으로 바뀐다. 이미 배포된 `#/p/{token}`·`#/p/f/{token}` 해시 링크는 계속 그대로 열린다(서버는 해시를 보지 못하므로 지금처럼 정적 `index.html` 을 그대로 받고, 클라이언트 해시 라우팅이 기존과 동일하게 처리 — 무변경)
- 서버사이드로 바꾸는 태그는 `og:title`·`og:description`·`twitter:title`·`twitter:description` 네 개뿐. `og:image`·`twitter:image`·`og:url`·`theme-color` 등 나머지는 건드리지 않는다(다른 작업 진행 중 — §1 표 참고)
- 폴더 하위 특정 문서 딥링크(`/p/f/{token}/{docId}` 형태)는 만들지 않는다 — §전제 참고. `worker/publicPage.ts` 는 `/p/f/:token` 뒤에 추가 세그먼트가 있으면 매치 실패로 처리해(`null`) 기존 정적 폴백으로 넘긴다
- 사이트맵·robots.txt 는 별도 작업(제외)
- 이번 변경은 표시(응답 HTML 의 메타 태그)만 바꾼다. 문서 원문·DB 데이터는 절대 변경하지 않는다

## 3. `worker/publicPage.ts` 동작

```ts
export async function renderPublicPage(request: Request, env: Env, pathname: string): Promise<Response | null>
```

- 경로 매칭: `^/p/([^/]+)$` → 문서 토큰, `^/p/f/([^/]+)$` → 폴더 토큰. 둘 다 아니면 `null`
- 토큰 조회: `isValidToken` 통과 + `share_links` 에서 `token=? AND revoked_at IS NULL` + `target_type` 일치하는 행이 있어야 진행. 없으면 `null`(`links.ts` 의 기존 조회 패턴·쿼리 재사용, `handlePublicGetDoc`/`handlePublicGetFolder` 와 동일 SQL이면 됨 — 새 함수로 중복 작성해도 되고 `links.ts` 에서 export 해 재사용해도 됨, 구현 자유)
- 문서(`target_type='doc'`): `docs` 테이블에서 `title`, `content` 조회
  - `title = \`${doc.title} · ${brand.name}\``
  - `description = excerpt(stripComments(doc.content))` — 없으면(빈 문자열) `SITE_DESCRIPTION` 폴백
  - `excerpt(text)`: 개행·연속 공백을 단일 스페이스로 접고 앞뒤 trim → 100자 초과 시 100자로 자르고 말줄임표(`…`) 추가. 마크다운 기호(`#`, `*` 등) 제거는 하지 않는다(범위 밖)
- 폴더(`target_type='folder'`): `folders` 테이블에서 `name` 조회
  - `title = \`${folder.name} · ${brand.name}\``
  - `description = SITE_DESCRIPTION`(폴더는 발췌 대상이 없다 — 문서 목록을 순회해 만들지 않는다)
- 대상 행 자체가 없으면(삭제된 문서/폴더인데 링크만 남은 경우) `null`
- 유효하면: `const base = await env.ASSETS.fetch(request)` 로 기본 `index.html` 을 받아(`not_found_handling: single-page-application` 이 이미 200 을 준다) 텍스트를 읽고, 아래 `injectMeta` 로 4개 태그의 `content` 값만 치환해 새 `Response` 를 만든다
  - 응답 헤더: `content-type: text/html; charset=utf-8`, `X-Robots-Tag: noindex`(F-210 `pubResponse` 와 동일 정책 — 검색 색인은 계속 막는다), 나머지는 `base` 헤더 유지
- 어떤 단계든 예외가 나면 잡아서 `null` 반환(실제 페이지 로딩을 절대 깨뜨리면 안 된다) — 상위(`worker/index.ts`)에서도 다시 try/catch 하지 않고 이 함수가 항상 안전하게 끝나도록 만든다

`injectMeta(html, { title, description })`:
- 태그별로 `property="og:title"`/`property="og:description"`/`name="twitter:title"`/`name="twitter:description"` 를 가진 `<meta ... content="...">` 만 정확히 골라 `content` 값을 치환한다(다른 태그를 오염시키지 않도록 속성 매칭 필수, 단순 문자열 치환 금지)
- 치환 값은 HTML 속성 이스케이프 필수(`&` `<` `>` `"` ) — 문서 제목·본문은 사용자 입력이라 그대로 넣으면 속성이 깨지거나 인젝션 가능. 로컬 `escapeHtml` 헬퍼를 이 파일 안에 작게 둔다(다른 곳의 `md.utils.escapeHtml` 재사용 안 함 — 워커 번들에 markdown-it 끌어들이지 않는다)

## 5. 클라이언트 라우팅 (`hashRoute.ts`·`App.tsx`)

- `parsePathRoute('/p/abc')` → `{type:'public', token:'abc'}`, `parsePathRoute('/p/f/abc')` → `{type:'publicFolder', token:'abc'}`, 그 외(`/`, `/p/`, `/p/f/`, `/p/a/b` 등) → `{type:'none'}`
- `App.tsx` 초기 `publicRoute` state: 경로가 먼저 매치되면 그걸 쓰고, 아니면 지금처럼 해시를 본다. 이후 동작(해시 변경 리스너, 폴더 안 문서 선택 시 해시 push 등)은 전부 기존 그대로 — 진입 판정 한 곳만 바뀐다
