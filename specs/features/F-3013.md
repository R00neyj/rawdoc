## 사용자가 이미 정한 것 (2026-10-04 grill, 바꾸지 않는다)

1. 가져오기(당기기)와 푸시를 한 번에 낸다
2. GitHub App 설치 + 사용자 인증(OAuth 흐름). 권한은 저장소 Contents 읽기·쓰기 + Metadata 읽기만. 로그인용 OAuth App(F-2033)과 별개 — Google 로그인 사용자도 연결한다. GitHub 호출은 Worker 만, 갱신 토큰은 D1 에 암호화
3. 문서 하나 ↔ 저장소·브랜치·경로의 파일 하나. 폴더 통째 없음
4. 시작 위치 둘: 사이드바 가져오기 메뉴 `GitHub에서 가져오기…`(연결된 새 문서), 문서 메뉴 `GitHub에 연결…`(경로에 파일이 없으면 첫 푸시가 만든다)
5. 다시 당기면 **지금 본문 vs 원격 본문 둘만** 비교해 덩어리를 골라 합친다(마지막 동기화 본문은 저장하지 않음). 도구는 `@codemirror/merge` 6.12.2 `unifiedMergeView` — 새 의존성은 이것 하나
6. 커밋 메시지는 사용자가 적는다. 원격 sha 가 마지막 동기화 때와 다르면 푸시를 막고 당겨 합치게 한다. 올리는 것은 `.md` + 새로 넣은 `attachments/`(`.md` 와 같은 폴더). 당겨 온 그림은 다시 올리지 않는다. `.md` 바이트는 `.md` 내보내기(F-112)와 같다
7. 당기기·푸시는 문서 주인만(주인 토큰). 편집자는 연결 상태만 본다. 합친 결과는 Yjs 로 퍼진다
8. 횟수 제한은 지금 무제한. D1 설정 행에 "월 N회(비우면 무제한)"·"기능 끄기", 배포 없이 관리 스크립트로 바꾼다. 남용 방지는 `WRITE_LIMITER`
9. 그림: 본문 글자는 그대로. 당길 때 저장소 그림을 받아 WebP 로 바꿔 R2 첨부로 두고 "문서+경로 → 첨부" 를 기록. SVG·5MB 초과·변환 실패는 볼 때마다 Worker 가 주인 토큰으로 받아 준다(프록시). 보기 링크·공개 링크 방문자에게도 보이되 본문에 있는 경로만, 권한 확인은 첨부와 같게
10. 이미지 문법은 F-2127. 이 개요는 그 6장 확장 지점(`src/lib/imageMarkdown.ts` `ResolveImagePath`)에 꽂는 쪽만

## 1. 범위

### 1.1 하는 것
- GitHub 계정 연결·해제(설정 `계정` 탭), 저장소·브랜치·파일 고르기, 연결된 새 문서 가져오기, 기존 문서 연결, 당기기 + 덩어리 합치기, 푸시(커밋 1개), 저장소 그림 받아 넣기·프록시, 연결 상태 표시, 월 횟수·끄기 관리 도구

## 3. 서버

### 3.1 비밀 값과 설정 (Q3 기본값)

| 이름 | 종류 | 값 |
| --- | --- | --- |
| `GITHUB_APP_CLIENT_ID` | `vars` (커밋, 운영 값) | 운영 앱 Client ID. 로컬은 `.dev.vars` 가 덮는다(F-2033 측정 i) |
| `GITHUB_APP_SLUG` | `vars` | 설치 주소 `https://github.com/apps/{slug}/installations/new` 용 |
| `GITHUB_APP_CLIENT_SECRET` | `secrets.required` | 앱 client secret |
| `GITHUB_TOKEN_KEY` | `secrets.required` | 토큰 암호 키, 32바이트 난수 base64 |

- 로그인용 `GITHUB_CLIENT_ID`·`GITHUB_CLIENT_SECRET` 과 이름이 겹치지 않게 `GITHUB_APP_` 접두
- `secrets.required` 에 넣는 이유: 로컬 `dev:worker` 로 실제 앱을 돌려 봐야 한다(외부 API 를 아무도 안 돌려 봤다). 목록 밖이면 wrangler 가 `.dev.vars` 값을 버린다(F-3003 m5). 대가는 비밀 값 없이는 배포가 실패한다는 것 — 7장 1번이 먼저 넣는다
- 슬러그는 제품명과 같을 수 있다. `vars.BETTER_AUTH_URL` 처럼 설정 값이지 코드·UI 문자열이 아니다. GitHub 요청 `User-Agent` 는 `brand.config.ts` 의 이름을 import 해 만든다

### 3.2 토큰 암호화
- AES-256-GCM(WebCrypto). 키 = `GITHUB_TOKEN_KEY` base64 를 `importKey('raw')`. 저장 글자 `v1.{iv base64url 12B}.{암호문+태그 base64url}`, iv 는 매번 새 난수
- AAD = `github:{user_id}:{access|refresh}` — 행·칸을 바꿔 끼우면 풀리지 않는다
- 풀기 실패(키 바뀜·깨짐)는 "다시 연결 필요" 와 같게 다룬다(`refresh_expires_at = 0`). 키를 바꾸면 모든 사용자가 다시 연결한다 — 키 교체 절차는 두지 않는다
- 비용 0.079ms/회(m4). 브라우저·로그에 토큰을 내보내지 않는다

### 3.3 연결 흐름과 토큰 갱신
1. `GET /api/github/connect?return=` (로그인 필수) → 쿠키 `gh_oauth`(HttpOnly, Secure — `http://localhost` 만 빼고, SameSite=Lax, Path=`/api/github/`, Max-Age 600)에 `state`·PKCE `verifier`·`return` 을 담고 `https://github.com/login/oauth/authorize?client_id&redirect_uri&state&code_challenge&code_challenge_method=S256` 로 302. `return` 검사는 `loginReturn` 그대로
2. `GET /api/github/callback?code&state` → `state` 와 쿠키 대조, 같은 세션 사용자, `POST https://github.com/login/oauth/access_token`(client_id·secret·code·verifier·redirect_uri) → `GET /user` 로 `id`·`login` → `github_accounts` UPSERT. 다른 Rawdoc 계정이 이미 그 `github_id` 를 쓰면 저장하지 않고 `error=github_taken`
3. `GET /user/installations` 가 0개면 `https://github.com/apps/{slug}/installations/new?state=` 로 302, 있으면 `return` 으로 302 + 해시에 `github=connected`
4. `GET /api/github/setup?installation_id&setup_action&state` (Setup URL, 설치·저장소 바꾸기 뒤) → `return` 으로 302
- 오류는 `return` 해시에 `github_error={code}` — 코드: `denied`(사용자가 거절)·`state`·`github_taken`·`exchange_failed`·`disabled`
- **갱신**: 호출 전 `access_expires_at - now < 5분` 이면 갱신. 같은 사용자 요청 둘이 동시에 갱신하면 하나는 `bad_refresh_token`(g2). 규칙: 갱신 결과는 `token_rev` 조건부 UPDATE 로 쓰고, `bad_refresh_token` 을 받으면 행을 다시 읽어 `token_rev` 가 올랐으면 새 토큰을 쓰고, 그대로면 `refresh_expires_at = 0`(다시 연결 필요). GitHub 가 401 을 주면 한 번만 갱신 후 재시도
- 해제 `DELETE /api/github/account` → g7 로 grant 폐기(실패해도 진행) → 행 삭제. 연결(`github_links`)은 남는다 — 다시 연결하면 그대로 쓴다

- GET 이 아닌 `/api/github/*`·`/api/docs/:id/github*` 는 기존 쓰기 관문(`WRITE_LIMITER` 분당 120 포함)을 그대로 탄다. 그래서 횟수가 드는 파일 읽기도 `POST`
- **`content` 는 클라이언트가 만든다**: `.md` 바이트는 편집기 `getText(lineEnding)`(내보내기와 같은 함수) + `remote_bom` 이면 BOM. 서버는 크기(`MAX_CONTENT_BYTES` + 3)만 본다. 주인 자신의 저장소에 주인 권한으로 쓰는 것이라 서버가 DO 를 깨워 다시 읽지 않는다
- **그림 blob 은 클라이언트가 base64 로 만들어 한 장씩 보낸다**: Worker 안 base64 는 CPU 를 쓰고(m3), 한 호출에 몰면 외부 하위 요청 50(w1)에 닿는다. Worker 는 본문을 그대로 흘려보낸다(`request.body` → `fetch`). 한 번 푸시의 새 그림은 50장까지(2차 한도 g3, 분당 80)
- `sha`·`bom` 을 클라이언트가 알려 주는 것은 믿는다 — 거짓이어도 주인이 자기 저장소를 덮을 수 있을 뿐이고, 푸시는 GitHub 의 실제 sha 와 다시 대조한다
- 푸시 순서: ref `GET` → 머리 커밋의 경로 sha 가 `remote_sha` 와 같은지(`remote_sha` NULL 이면 파일이 없어야) → 아니면 409 → `.md` blob → tree(`base_tree` + `.md` + `images` 를 `{md 폴더}/attachments/{name}`) → commit(부모 = 머리) → ref `PATCH`(빨리감기만). 422 면 409 `github_conflict`. 성공하면 `remote_sha` = 새 `.md` blob sha. 호출 6번 + 갱신 0~1
- GitHub 오류 대응: 한도(g3) → 503 `github_rate_limited` + `retryAfter`; 브랜치 보호·권한 → 403 `github_forbidden`; 저장소·경로 없음 → 404 `github_not_found`; 토큰 → 409 `github_reconnect`

### 3.5 경로 규칙 — `src/lib/githubPath.ts` (순수, 서버·클라이언트 공용)
- `resolveRepoPath(mdPath, url): string | null` — F-2127 2.2 셋째 줄이 넘기는 `url` 원문을 받는다. `?`·`#` 뒤를 떼고 `%XX` 를 한 번 푼다(실패 → null). 스킴·`//`·`\`·제어 문자·빈 글자 → null. `/` 로 시작하면 저장소 맨 위 기준, 아니면 `mdPath` 의 폴더 기준. `.`·`..` 를 정리하고 맨 위 위로 올라가면 null
- `repoImagePaths(content, mdPath): Set<string>` — 본문의 `![…](url)` 와 `<img … src="url">` 를 넓게 훑어 `resolveRepoPath` 결과를 모은다. 그리는 조건(F-2127 4.1, 줄에 혼자인 최상위 이미지)보다 넓다 — 허용 목록이 넓어져도 주인이 본문에 적은 경로뿐이다
- `.md` 경로 검사: 위 규칙 + `.md`·`.markdown` 로 끝남 + 1,024자 이하

### 3.6 금고 문서
- 연결 대상이 아니다. `PUT /api/docs/:id/github` 는 `e2ee_key` 가 있으면 409 `e2ee`. 연결된 문서를 금고로 옮기면 `handleSetDocE2ee` 가 409 `github_linked`(본문이 평문으로 나가는 통로가 생기므로)

### 3.7 그림 받아 넣기 (사용자 결정 9)
- WebP 변환은 Workers 에 캔버스가 없어 **브라우저에서** 한다(기존 `toWebp`). 흐름: `pull` 응답 `imageSources`(서버가 본문 그림 경로의 폴더마다 Contents 폴더 목록 1번으로 sha·size 를 얻음, 폴더 20개까지) → 클라이언트가 대응이 없거나 `blob_sha` 가 다른 것만 → `raw` 로 받기 → 시그니처가 png·jpg·gif·webp 이고 5MB 이하만 `toWebp` → 기존 `PUT /api/attachments/{id}.{ext}`(서버 재검사·계정 300MB 그대로) → `PUT …/github/images`. 한 번에 50장
- SVG·5MB 초과·변환·올리기 실패는 대응 없이 둔다 → 3.8 프록시로 보인다
- `raw` 는 Contents `raw` 형식을 흘려보낸다. 20,000,000 B 넘으면 413

- 리졸버(`ResolveImagePath`): 연결된 문서면 `resolveRepoPath(link.path, url)` → 대응이 있으면 `{ id, ext }`, 없으면 `{ repoPath }`. 연결이 없으면 지금처럼 null. 리졸버에 필요한 `path`·`images` 는 로그인 문서는 `GET /api/docs/:id/github`(편집자 포함), 보기 권한·공개 링크는 공유·공개 문서 응답에 새 칸 `github?: { path, images }` 로 받는다(저장소 이름은 넣지 않는다)
- **프록시 응답** (계약):
  - 검사 순서: 문서 권한(공개는 첨부와 같은 링크 판정) → 연결 있음 → `path ∈ repoImagePaths(docs.content, link.path)`(D1 스냅숏 기준, 첨부 검사와 같은 출처) → 대응이 있으면 R2 첨부를 `attachmentResponse` 로 → 없으면 `enabled` 이고 주인 연결이 살아 있을 때만 GitHub `raw` 를 받는다. 어느 단계든 실패는 404
  - 형식 판정은 서버가: `sniffImage` 가 맞으면 그 MIME, 아니면 경로가 `.svg` 이고 앞 1KB 에 `<svg` 가 있을 때만 `image/svg+xml`, 그 밖 404. 10,000,000 B 넘으면 404
  - 머리: `Content-Type`(서버 판정), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`, `Cross-Origin-Resource-Policy: same-origin`, `Content-Disposition: inline`, `Cache-Control: private, max-age=300`
  - `..`·절대 경로·다른 저장소는 3.5 에서 이미 null — 저장소는 늘 연결의 `repo`·`branch` 로만 고정된다
  - Workers Cache API 에 `repo_id`·`branch`·`path` 열쇠로 300초 둔다(권한 검사는 캐시 앞). 인기 공개 문서가 주인의 5,000/시간(g3)을 다 쓰지 않게

### 3.9 횟수와 끄기
- `enabled = 0` → `status`·`DELETE account` 만 되고 나머지 503 `github_disabled`. 프록시는 GitHub 로 가지 않는다(대응된 R2 그림은 계속 보인다)
- 횟수가 드는 것: `file`·`pull`·`push` 각 1(3.4 표). **성공한 뒤** `github_usage` UPSERT +1. 시작 전에 `count >= monthly_limit` 면 429 `github_quota` `{ limit, resetAt }`(다음 달 1일 UTC). 동시 요청으로 한두 번 넘는 것은 받아들인다
- 설정 행은 요청마다 1행 읽기

## 4. 클라이언트

### 4.1 진입점

| 자리 | 지금 | 바뀜 | 조건 |
| --- | --- | --- | --- |
| 사이드바 `가져오기` 버튼(펼침·레일) | 파일 창 | 메뉴: `.md 파일…` / `GitHub에서 가져오기…` | 로그인 + `status.enabled`. 아니면 지금처럼 바로 파일 창 |
| 문서 `⋯`·우클릭 메뉴 | 고정·이동·삭제 | `GitHub에 연결…` 추가(연결돼 있으면 `GitHub 연결 정보…`) | 주인 + 일반 문서 + `enabled` |
| 상단바 | — | 연결된 문서에 `GitHub` 메뉴 버튼: 주인 `당기기…`·`푸시…`·`GitHub에서 보기`·`연결 해제…`, 편집자 `GitHub에서 보기` + 상태 줄 | 연결된 문서 |
| 설정 `계정` 탭 | — | `GitHub` 묶음: `GitHub 연결` / `{login} 연결됨`·`연결 해제`, 이번 달 사용 | 로그인 + `enabled` |
| 명령 팔레트 | — | `GitHub에서 가져오기…`·`이 문서 GitHub에 당기기…`·`이 문서 GitHub에 푸시…` | 위와 같은 조건 |

- `status` 를 못 받으면(가짜 서버에 라우트 없음 포함) 꺼진 것으로 본다 — 기존 e2e 가 그대로 지난다
- 연결 안 된 상태에서 `GitHub에서 가져오기…`·`GitHub에 연결…` 를 누르면 대화상자 안에 `GitHub 연결` 버튼 → `/api/github/connect?return={지금 해시}` 로 이동. 돌아오면 해시 `github=connected` 를 보고 그 대화상자를 다시 연다

### 4.2 고르기 대화상자 (가져오기·연결 공용)
- 저장소(`canWrite` 없는 것은 회색) → 브랜치(기본 브랜치 미리 고름) → 폴더 탐색, `.md`·`.markdown` 만. 목록에 원하는 저장소가 없을 때 `저장소 추가…` = 설치 주소 새 탭
- 가져오기: 파일 → `file` → `decodeMarkdown`(F-114 규칙: UTF-8 아니면 거부, BOM 기억, 섞인 줄바꿈은 CRLF 로 + 알림) → 기존 `POST /api/docs`(제목 = 확장자 뗀 파일 이름, 최상위, `lineEnding` = 판정값) → `PUT /api/docs/:id/github`(`sha`, `bom`) → 문서 열기 → 그림 받아 넣기(3.7)
- 연결: 기존 파일을 고르거나 폴더 + 파일 이름(기본 `toFileName(제목)`)을 적는다. 파일이 이미 있으면 `sha: null` 로 연결하고 곧바로 당기기 대화상자를 연다 — 비교 전까지 푸시는 409 로 막힌다
- 원격 파일이 `MAX_CONTENT_BYTES`(1,000,000 B)를 넘으면 거부. GitHub `size` 로 먼저 거른다

### 4.3 당기기와 합치기 — 적용 경로 (반드시 결론)

**결정: 주인 브라우저의 편집기에 트랜잭션 하나로 넣는다.** 서버가 DO 에 쓰지 않는다

| | 클라이언트 트랜잭션 (택함) | 서버 → DO `writeText`(F-308 경로) |
| --- | --- | --- |
| 원본 규칙 | 편집기 `Y.Doc` → `y-codemirror.next` → 공유 `Y.Text` → DO. 평소 타자와 같은 길 | 같은 `Y.Text` 에 쓰지만 `baseVersion` 이 다르면 `conflict` — 누가 한 글자만 쳐도 실패 |
| 되돌리기 | `Y.UndoManager`(yBinding)가 추적 — `Ctrl+Z` 한 번 | 원격 갱신이라 주인도 못 되돌림 |
| IME | 대화상자가 모달이라 주인 편집기는 조합 중이 아님. 다른 사람에게는 원격 갱신이라 기존 조합 중 보류 규칙 그대로 | 같음 |
| 합치기 화면 | 어차피 브라우저 | 결과를 다시 서버로 보내야 함 |

- 합치기 편집기는 본 편집기와 별개인 CM6 `EditorView`(Yjs 없음). **문서 = 지금 본문(LF), `original` = 원격 본문(LF)**. `mergeControls` 함수로 버튼 글자를 정한다: accept → `내 것 유지`, reject → `GitHub 것으로`. `diffConfig: { timeout: 1000 }`(`scanLimit` 생략 = 끔 — m2, 기본값이면 큰 문서가 덩어리 하나가 된다). `collapseUnchanged: { margin: 3, minSize: 4 }`. 사용자가 손으로 고쳐도 된다
- 고르지 않은 덩어리는 **내 것**(Q1)
- `적용`: 대화상자를 연 때의 본문과 지금 본문이 다르면(그사이 다른 사람이 고침) 적용하지 않고 `그사이 본문이 바뀌어 다시 비교합니다` 와 함께 지금 본문으로 다시 비교한다(원격은 다시 받지 않음). 같으면 연 때 본문 → 결과의 차이를 `userEvent: 'input.github'` 트랜잭션 하나로 → `synced`(`sha`, `bom`)
- 차이가 없으면 대화상자 없이 `synced` 만 하고 `GitHub 파일과 같습니다`
- 적용은 실시간 연결이 `synced` 일 때만(`liveStatusOf`). 아니면 `온라인일 때 당길 수 있습니다`
- 줄바꿈: 비교는 LF 로. 원격과 문서 `lineEnding` 이 다르면 대화상자에 한 줄 `줄바꿈이 다릅니다 (GitHub {LF|CRLF}, 이 문서 {LF|CRLF}). 푸시하면 이 문서 형식으로 올라갑니다`. 문서 `lineEnding` 은 바꾸지 않는다
- 덮기 전 사본(F-282)은 만들지 않는다 — 고른 결과이고 `Ctrl+Z` 가 된다
- `@codemirror/merge` 는 이 대화상자 파일에서만 import 하고 **대화상자를 지연 로드**(`import()`)한다. 증가분이 7.6KB gzip(m1)으로 작지만 쓰는 사람이 연결된 문서 주인뿐이다. precache 에는 조각 하나가 더 들어간다

### 4.4 푸시
- 대화상자: 커밋 메시지(빈 글자면 `푸시` 꺼짐, 1,000자), 대상 `{repo} · {branch} · {path}`, 새 그림 수
- 순서: 본문 `attachments/{id}.{ext}` 참조 → `push-plan` → `missing` 만 첨부를 받아 base64 → `blobs` 한 장씩 → `push`. 409 `github_conflict` 면 `GitHub 파일이 바뀌었습니다. 당겨서 합친 뒤 푸시하세요` + `당기기…` 버튼
- 당겨 온 그림(상대 경로)은 `attachments/` 형식이 아니라 자연히 올라가지 않는다

### Q1. 고르지 않은 덩어리 — **기본값: 내 것(지금 본문)**
- 이유: 아무것도 안 누르고 `적용` 해도 잃는 글자가 없다. 합치기 편집기 문서 = 지금 본문이라 `unifiedMergeView` 의 기본 동작과도 맞는다
- 다른 안(GitHub 것): 문서 = 원격, `original` = 지금 본문으로 뒤집고 버튼 뜻도 뒤집는다. "당기면 원격이 들어온다" 는 기대에는 맞지만 주인이 놓친 덩어리의 로컬 글이 사라진다

### Q2. 원격 BOM — **기본값: 있으면 푸시 때 다시 붙인다**
- 이유: 저장소 파일의 첫 3바이트가 푸시마다 바뀌면 git 차이에 잡힌다. 사용자 결정 6 "내보내기와 같은 바이트" 에서 BOM 하나만 다르다
- 다른 안: 내보내기와 똑같이 BOM 없음 — `remote_bom` 칸이 필요 없고, BOM 이 있던 파일은 첫 푸시에 BOM 이 빠진다

### Q3. 비밀 값 배치 — **기본값: secret 둘은 `secrets.required`, id·slug 는 `vars`**
- 이유: 로컬에서 실제 앱을 돌려야 하는 기능이다(3.1)
- 다른 안(VAPID 식, F-3003): 넷 다 목록 밖 + 없으면 기능 꺼짐 — 배포는 안 막히지만 `dev:worker` 에서 GitHub 를 못 돌린다. U12 는 그대로

### Q4. 연결 해제 때 그림 대응 — **기본값: 지운다**
- 이유: 대응을 풀려면 연결의 `path` 가 필요하다. 남기면 "연결 없는 대응" 상태를 따로 다뤄야 한다. 첨부는 다음 날 정리된다
- 다른 안: 연결 행에 `detached_at` 을 두고 대응·그림을 남긴다 — 연결을 끊어도 그림이 보이지만 표·정리 규칙이 늘어난다

### Q5. 월 횟수에 드는 것 — **기본값: 가져오기·당기기·푸시 각 1회**
- 다른 안: 푸시만 센다(HackMD 식 "동기화 횟수" 가 무엇을 세는지는 확인하지 못했다) — 당기기 남용은 `WRITE_LIMITER` 만 막는다

### Q6. 연결 상태를 누가 보나 — **기본값: 주인·편집자. 보기 권한·공개 방문자는 못 본다**
- 이유: 저장소 이름이 비공개 정보일 수 있다. 보기·공개 쪽은 그림 경로 풀기에 필요한 `path`·`images` 만 받는다(3.8)
- 다른 안: 보기 권한에도 상태 줄을 보인다

### 기본값으로 정한 것 (승인 시 확정)
1. 처음엔 꺼진 채 배포, 마지막 명세 뒤 켠다 (2장)
2. 합친 결과는 주인 편집기 트랜잭션 하나 (4.3)
3. 푸시 `.md`·그림 blob 은 클라이언트가 만들고 Worker 는 흘려보낸다 (3.4)
4. `diffConfig: { timeout: 1000 }` (m2)
5. 저장소 그림은 내보내기 zip 에 넣지 않는다 (3.8 ③)
6. 프록시 300초 캐시·10MB 상한, 받아 넣기 50장, 푸시 새 그림 50장
7. 이미 있는 파일에 연결하면 곧바로 당기기 (4.2)
