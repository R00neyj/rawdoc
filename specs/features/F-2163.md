## 2. 계약 (`paneRules.ts`)
```ts
export function routeOpen(s: SplitState, entry: DocTab, mode: OpenMode, order: readonly number[], prefer: number | null, max = MAX_TABS): { split: SplitState; capped: boolean }
export function unitPanes(s: SplitState, currentDocId: string | null): PaneDoc[]
export function carryPaneKeys(prev: SplitState, prevKeys: readonly string[], next: SplitState, fresh: () => string): string[]
export type SplitAction = { kind: 'split'; next: SplitState } | { kind: 'notice'; message: string } | null
export function splitAction(s: SplitState, pane: number, dir: SplitDir | 'cycle', tab: DocTab): SplitAction
export function docReadOnly(i: { roleReadOnly: boolean; claimReadOnly: boolean; deleted: boolean; liveStopped: boolean; offlineView: boolean; converting: boolean; liveReadOnly: boolean }): boolean
export function openE2eeIds(units: readonly { docId: string | null; meta: DocMeta | null }[]): string[]
```
- **`routeOpen`(흐름 3)**: 문서가 있는 칸(탭 어디든)을 고르는 순서 ① `prefer` 칸 ② 포커스 칸 ③ 다른 칸 중 `order`(최근 포커스가 앞)에서 먼저 나오는 칸 ④ 없으면 포커스 칸. 고른 칸에 `openTabCapped(칸, entry, mode, paneTabLimit(s, 칸))`, `focus` = 그 칸. 지금 `useDocTabs` 의 단일 탭 경로는 칸 하나일 때 이 함수와 같은 결과
- **`unitPanes`**(F-2160 `panes` 입력): 칸 활성 문서들. `currentDocId` 가 그 안에 없고 null 이 아니면 서로 다른 문서가 4 미만일 때 끝에 붙이고, 4면 포커스 칸 자리를 바꾼다 — `selectDoc` 이 `currentDocId` 를 먼저 바꾸고 칸은 effect 에서 따라오므로 그 한 렌더 동안 남은 칸의 묶음이 빠졌다 다시 생기지(편집기 다시 만들기) 않게. 칸 닫기 직후 닫힌 문서도 이 덧붙이기로 이동이 끝날 때까지 남는다
- **`carryPaneKeys`**: React key 가 칸을 따라가게. 같은 객체 → 옛 키, 그다음 남은 새 객체가 하나이고 안 쓰인 옛 키가 하나면 그 키(`setPaneTabs`·`viewMode` 바꾸기), 나머지는 `fresh()`(나누기의 새 칸). F-2162 전이는 칸 객체를 그대로 옮긴다(`splitLayout.ts` 확인)
- **`splitAction`**: `totalTabs(s) >= MAX_TABS` → 알림 `TABS_FULL`, `panes.length === MAX_PANES` → `화면은 4칸까지 나눌 수 있습니다.`, `splitPane`/`cycleSplit` 결과가 null → `null`(항목 숨김), 그 밖 `split`. 메뉴·팔레트 항목은 결과가 `null` 이 아닐 때만 보인다(4칸이면 보이고 누르면 알림)
- `docReadOnly` = 지금 App `isReadOnlyDoc` 식의 OR 그대로(App 도 이것으로 바꾼다). `openE2eeIds` = `meta?.e2ee === 'open'` 이고 `docId` 가 있는 묶음 id

## 3. 칸 그리기·칸마다 값 (결론 1)
- `SplitPanes` 는 `showEditor` 자리에서 `DocumentArea` 하나를 대신한다. 칸 1개면 지금 DOM 그대로(창 위 탭 줄, 상단바 아래 본문). 2개 이상이면 창 위 탭 줄이 없어지고 상단바 아래 `.split-panes[data-layout]` 격자, 칸마다 `.split-pane[data-pane-number="1~4"][data-focused]` 맨 위에 그 칸 `DocTabBar`, 아래 `DocumentArea`. 칸 번호 = `paneForNumber` 의 역. 칸 크기는 `clampRatios(layout, ratios, 칸 영역 크기)`(ResizeObserver, 저장 값은 안 바꿈)
- 칸 key = `carryPaneKeys` 결과 — 닫기·나누기로 칸 자리가 바뀌어도 남은 칸의 편집기는 다시 만들지 않는다. 문서 값은 `unit = unitFor(pane.active)`(F-2160 4장)
- **칸마다 사는 값(`SplitPanes` 안)**: 편집기 handle·`viewerRef`·`contentAreaRef`, 보기 HTML 사본, 보드 표시 사본, `viewMode`(= `SplitState` 칸 값). **창에 하나인 App 값은 포커스 칸 것을 가리킨다**: `usePaneHost` 가 포커스 칸의 handle 을 App `setEditorRefs` 로, `viewerRef`·`contentAreaRef` 를 App ref 로 매 커밋 게시. 포커스 아닌 칸은 포커스를 잃을 때의 `viewerHtml`·보드 여부를 사본으로 그리고, `kanban`·찾기·레일·FAB·Outline 은 포커스 칸만(`focused` 거짓). 댓글 강조는 모든 칸 — 포커스 아닌 칸은 그 묶음으로 `computeCommentAccess` 가 `none` 이 아닐 때 자기 handle 에 `comments.attach`(`onLayout` 무시, `onActivate` = 그 칸 포커스)
- 칸마다 `onDocChange` → `unitFor(칸 문서).saver.notifyChange()`(F-2161 7장 ④), 글자 수·커서 정보는 포커스 칸만. 읽기 전용은 칸마다 `docReadOnly`(그 묶음 값)
- **보기 방식(F-2159 Q2)**: `changeViewMode` 는 포커스 칸 `viewMode` 에 쓰고 `md.viewMode` 도 쓴다(지금 그대로). 포커스가 바뀌면 App 은 상태만 맞추고 `scrollAnchorRef` 를 비우며, 새 칸이 `view` 면 그 칸 편집기 본문으로 `viewerHtml` 을 다시 만든다(다른 칸에서 같은 문서를 고쳤을 수 있다). 보드/원문 고르기는 지금 탭 전환처럼 문서 기본값으로
- 숨기기: 2칸 이상에서 홈(`currentDocId` null)·공유·지도 화면이면 `SplitPanes` 를 언마운트하지 않고 `hidden`(편집기·실행 취소 유지 — `DocumentArea` `hidden` 선례). 분할이 꺼진 폭(탭 `bar` 가 null)이면 포커스 칸 말고는 `hidden`. 묶음 내리기는 F-2164

## 4. 포커스·열기 (흐름 3·4)
- 불변: **포커스 칸 활성 탭 = `currentDocId`**(이동 중 한 렌더 제외). 포커스 바꾸기는 대상 칸 활성 문서가 `currentDocId` 와 같으면 곧바로, 다르면 `selectDoc(그 문서)` 를 부르고 `prefer` = 그 칸으로 `routeOpen` 이 바꾼다(창 UI 와 편집기 게시가 엇갈리지 않게)
- 입구: 칸 안 `pointerdown`·`focusin`(캡처) = 그 칸, `Ctrl+1~4`(`e.code` `Digit1~4`, `paneForNumber`, 없는 번호는 아무 일 없음) = 그 칸 + 편집기(보기면 보기 영역) 포커스, 칸 탭 줄의 탭 클릭 = 그 칸에서 그 탭. `currentDocId` 가 밖에서 바뀌면(사이드바·위키링크·검색·팔레트·달력·백링크·지도·뒤로 가기·새 문서) `routeOpen(…, chooseOpenMode 결과, 최근 포커스 순서, prefer)`, `capped` 면 `TABS_FULL_REPLACED`. 최근 포커스 순서는 칸 key 로 들고 자리로 바꿔 넘긴다
- 이 창에서 지운 문서 탭은 모든 칸에서 닫고(빈 칸은 `setPaneTabs` 가 닫음), 제목 동기화도 모든 칸. `Ctrl+Tab`·`Ctrl+W`·`＋`·탭 고정은 포커스 칸에. 저장은 `storeSplit`(복원은 F-2164 전까지 지금 `parseStoredTabs` 거울 — 다시 열면 포커스 칸 하나)

## 5. 나누기·닫기 (흐름 2·5)
|입구|동작|
|---|---|
|탭 `⋯`·우클릭 `오른쪽에 분할`/`아래에 분할`|`splitAction(s, 그 칸, dir, 그 탭)`|
|팔레트 `오른쪽에 분할`/`아래에 분할`(`pane.splitRight`·`pane.splitDown`)|포커스 칸·활성 탭으로 같은 함수|
|`Alt+Shift+D`(`e.code === 'KeyD'`, `altKey` 조기 반환보다 앞)|`'cycle'`, 결과 `null`(grid)도 4칸 알림|
|탭 메뉴·팔레트 `칸 닫기`(`pane.close`, 단축키 표시 `Ctrl+Shift+W`), `Ctrl+Shift+W`|2칸 이상일 때만 보이고·가로챈다. `closePane(s, 칸)`, 그 칸 탭은 확인 없이 닫힘|
|칸 마지막 탭 `×`·`Ctrl+W`|`setPaneTabs` 가 칸을 닫음|
- 나누기는 `focusEditorRef.current = true` 뒤 상태를 바꿔 새 칸 편집기가 포커스를 받는다. 새 칸 문서가 지금 문서면 `currentDocId` 는 그대로
- **칸이나 탭을 닫아 어느 칸에서도 활성이 아니게 되는 문서가 있으면 `beforeLeaveDoc()`(= `flushAll`)를 기다린 뒤 상태를 바꾼다**(F-2160 8장 "빠지기 전 flush"). 닫은 뒤 포커스 칸 활성이 `currentDocId` 와 다르면 `selectDoc`. 키 셋 모두 대화상자 안·`isComposing` 이면 무시, 탭 `bar` 모드(설치 앱 넓은 화면)에서만

## 6. F-2161 배선 (결론 2)
- `usePaneHost` 가 `createPaneSources()` 하나(① ). `SplitPanes` 는 묶음에 `liveEditorOption` 이 없을 때만 `Editor paneSources` 를 넘긴다. `Editor` layout effect: `prepare(docId)` → 결과를 `paneSource` 로 `createEditor` → `add(docId, handle)`, 정리에서 `remove` 뒤 `destroy`(②). 같은 칸 다시 만들기는 늘 묶음 `remountNonce`(문서 다시 읽기)라 그 문서 칸이 한 커밋에 모두 내려가 원본이 버려지고 새 본문으로 다시 시작 — 다시 읽기의 뜻 그대로. 경로가 바뀌면 `restart` 가 `openDoc` 을 null 로 해 그 문서 칸 편집기가 모두 내려간다(⑥ 따로 할 일 없음)
- `host.getText(docId, le)` = 원본이 있으면 `sourceText`, 없으면 그 문서 칸 편집기(포커스 칸 먼저) `getText`, 없으면 `''`. `getComments(docId)` = 원본이 있으면 F-2161 5장 식, 없으면 지금처럼 포커스 문서 local 일 때 `localCommentRecords()`(③). `useDocComments` 는 `paneSources.source(docId)` 가 있으면 되살리기를 건너뛴다(⑤). 커서 자리는 `RemoteCursorsView` 가 편집기 포커스로 `claim` 하므로 배선 없음

## 7. 모든 묶음에 보안·지워짐·알림 (결론 3)
- **금고 잠그기**: `useE2eeMigrate` 의 `setOpenDoc` 옵션 → `paneUnits: () => readonly DocUnit[]`. `flush` 단계는 `openE2eeIds` 가 비어 있지 않으면 `flushAll`, `unmount` 단계는 그 묶음마다 `setOpenDoc(null)`(칸 편집기·보기 사본이 같이 내려감), `e2eeUnmountedDocId` 는 포커스 문서가 그 안일 때만
- **지워짐**: App `deletedElsewhereId` → `deletedElsewhereIds: Set`. `applyResyncResult`·`bootFlow.ts` 는 `currentDocIdRef` 대신 모든 칸 활성 문서에서 `removedIds` 를 넣고, 금고 경로 바뀜 재시작도 그 묶음마다 `restartAfterFlush`. 지우는 때는 문서가 모든 칸에서 빠질 때(포커스 이동으로는 안 지움). 오류 알림은 그 문서가 포커스가 될 때 한 번(`새 문서로 저장` 이 포커스 문서에 묶이므로)
- **알림 N1~N10**: 창에 하나라 포커스 묶음 기준 그대로, 단 한 번 판정을 문서별로 — `seq` ref 는 `docId:seq` 집합, 방 Doc ref 는 `WeakSet`, N8 병합 수는 `WeakMap<Y.Doc, number>`. 포커스를 오가도 다시 뜨거나 삼켜지지 않는다. 편집권(`useDocClaim`)·4403 보기 전환은 F-2160 에서 이미 묶음마다
