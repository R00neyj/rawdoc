# F-255 사이드바 여러 항목 선택·우클릭 메뉴

작성일: 2026-09-18
상태: 사용자 지시(2026-09-18 "우클릭으로 ... 옵션창 바로 열수 있도록 / 여러항목 선택 가능 / 여러 항목 선택 후 삭제, 혹은 폴더 로 드래그 드랍, 밖으로 드래그 드랍, 새 폴더로 넣기"). 사용자 승인 후 구현 완료 — `4b597f5` 로 반영(2026-09-20 상태 표기 정정, 구현 자체는 그 이전에 끝나 있었음)
근거: `specs/features/F-143.md`(사이드바 행·아이콘), `F-172.md` 2.2(메뉴 나타남·사라짐 전환), `F-132`·`F-170`·`F-174`(폴더 메뉴 항목), `specs/ia.md` 4장

## 1. 범위

### 지금
- 행마다 `...` 버튼(`FolderMenu`)을 눌러야 메뉴가 열린다. 우클릭은 브라우저 기본 메뉴가 뜬다
- 선택이라는 상태가 없다. 문서 클릭 = 열기뿐이고, 드래그는 **한 항목씩**만 된다(`Dragged = { type, id } | null`, `Sidebar.tsx` 39행)
- 여러 문서를 옮기려면 하나씩 끌어야 한다

### 한다
- 사이드바 행 **우클릭으로 그 행의 메뉴를 연다**(지금 `...` 로 열리는 것과 같은 항목). 브라우저 기본 메뉴는 막는다
- 여러 항목을 선택할 수 있게 한다 (`Ctrl`/`Cmd`+클릭 = 하나씩 더하기·빼기, `Shift`+클릭 = 화면에 보이는 순서로 범위)
- 선택이 2개 이상일 때 할 수 있는 것: **삭제**, **폴더로 드래그**, **밖(최상위)으로 드래그**, **새 폴더로 넣기**
- 선택은 눈에 보이게 표시한다(행 배경). 선택 개수는 드래그 중 커서 옆에 개수로 보인다

### 하지 않는다
- 체크박스 UI — 마우스 우선. 키보드 전용 선택(방향키 이동·`Ctrl+A`)은 이번 범위 밖
- 폴더 삭제 시 하위 처리 방식 변경 — `store.removeFolder(id, mode)` 의 지금 규칙을 그대로 쓴다(사용자가 따로 요청한 "상위로 옮길지/전부 삭제할지" 는 별도 명세)
- 복사·잘라내기·붙여넣기, 실행 취소
- 여러 항목 한꺼번에 이름 변경·공유·고정
- 모바일 길게 누르기(long-press)로 메뉴 열기 — 데스크톱 브라우저 기준(CLAUDE.md 진행 방침 1)

## 2. 결정

| 논점 | 결정 | 이유 |
| --- | --- | --- |
| 클릭의 뜻 | **일반 클릭은 지금 그대로**(문서=열기, 폴더=펼치기). 그 항목이 단독 선택도 된다 | 기존 동작을 바꾸면 매 클릭이 낯설어진다 |
| 선택 해제 | 빈 곳 클릭, `Esc`, 사이드바 밖 클릭 | 흔한 규칙 |
| 섞인 선택 | 문서·폴더를 **섞어 고를 수 있다** | 옮길 때 섞여 있는 게 보통이다 |
| 선택 밖 우클릭 | 그 항목만 선택하고 메뉴를 연다 | 의도치 않은 여러 개 삭제를 막는다 |
| 선택 안 우클릭 | 선택을 유지한 채 **여러 항목 메뉴**를 연다 | |
| 여러 항목 메뉴 항목 | `삭제`, `새 폴더로 넣기`, `최상위로 옮기기` 만. 단일 전용(이름 변경·공유·고정·새 문서)은 **숨긴다** | 여러 개에 뜻이 안 통하는 항목을 회색으로 남기지 않는다 |
| 드래그 | 선택된 항목 하나를 끌면 **선택 전체**가 움직인다. 선택 밖 항목을 끌면 그것만(지금 그대로) | |
| 폴더를 제 자손에 넣기 | 그 폴더만 빼고 나머지를 옮긴다. 알림으로 몇 개를 건너뛰었는지 알린다 | `canMoveFolder`(`lib/folderTree`)가 이미 판정한다 |
| 새 폴더로 넣기 | 선택한 것들의 **공통 부모** 아래 폴더를 만들고 옮긴 뒤, 이름을 인라인 편집 상태로 연다 | 이름부터 묻는 대화상자보다 빠르다 |
| 삭제 확인 | 지금 대화상자를 그대로 쓰되 문구에 개수를 넣는다 | |

## 3. 요구사항

### 3.1 선택 상태

`src/app/sidebarSelection.ts` (신규)에 순수 함수로 둔다 — 화면 없이 단위 테스트한다

- 상태: `{ ids: string[]; anchorId: string | null }`. `id` 는 문서·폴더 공용이고 종류는 별도로 들고 다니지 않는다(`{ kind: 'doc' | 'folder'; id: string }` 한 쌍으로 담는다)
- `toggle(sel, item)` — `Ctrl`/`Cmd`+클릭. 이미 있으면 빼고 없으면 더한다. `anchor` 는 방금 누른 것
- `extend(sel, item, visibleOrder)` — `Shift`+클릭. `anchor` 부터 `item` 까지 **화면에 보이는 순서**(접힌 폴더 안은 제외)로 채운다. `anchor` 가 없으면 단독 선택
- `replace(sel, item)` — 일반 클릭
- `clear(sel)`
- 목록에서 사라진 `id`(삭제·이동 후)는 선택에서 빠진다 — `prune(sel, visibleIds)`

### 3.2 우클릭

- `FolderRow`·`DocRow`·`PinnedRow` 의 행(`.tree-row`)에 `onContextMenu` 를 단다. `preventDefault()` 로 브라우저 메뉴를 막는다
- `FolderMenu` 가 **바깥에서 열림·위치를 받을 수 있게** 한다: `open`·`onOpenChange`·`anchorPoint?: { x: number; y: number }`. 값을 안 주면 지금처럼 자기 버튼 기준으로 연다
- 메뉴가 화면 오른쪽·아래로 넘치면 안쪽으로 당긴다
- 이름 편집 중(`isEditing`)인 행은 우클릭해도 메뉴를 열지 않는다 — 텍스트 편집 기본 메뉴가 필요하다

### 3.3 여러 항목 작업

- **삭제**: 문서는 `store.removeDoc`, 폴더는 `store.removeFolder(id, mode)` 를 순서대로. 하나가 실패해도 나머지를 계속하고, 끝나고 실패 개수를 알림으로 알린다
- **최상위로 옮기기 / 폴더로 드래그**: 문서는 `moveDoc(id, folderId)`, 폴더는 `moveFolder(id, parentId)`. `canMoveFolder` 가 막는 것은 건너뛴다
- **새 폴더로 넣기**: `createFolder({ name: '새 폴더', parentId: 공통부모 })` → 선택 항목 이동 → `onStartRename(새 폴더 id)`
- 선택 안에 부모 폴더와 그 자식이 같이 있으면 **부모만 옮긴다**(자식은 따라간다) — 같은 이동을 두 번 하지 않는다

### 3.4 화면

- 선택된 행: `.tree-row--selected`. 색은 `specs/design.md` 토큰으로만. 새 색을 만들지 않는다
- 드래그 중 2개 이상이면 기본 드래그 이미지 대신 개수 배지(`3개 항목`)
- 여러 항목 선택 중에는 행의 `...` 버튼을 눌러도 **여러 항목 메뉴**가 열린다(우클릭과 같은 메뉴)
