## 2. 상태 조회 — `useGithubStatus`

```ts
export function useGithubStatus(o: { account: AccountState; bootPhase: 'booting' | 'ready'; storeKind: Store['kind'] }):
  { status: GithubStatus | null; on: boolean; refresh: () => Promise<GithubStatus | null> }
```

- **켜짐(`on`)** = `account.state === 'in'` && `storeKind === 'server'` && `status?.enabled === true`. 응답이 200 이 아니거나 JSON 이 아니거나 모양이 틀리면 `status = null` → 꺼짐(F-3013 4.1 마지막 줄)
- 메모리에만 둔다. 저장소에 쓰지 않는다. 계정 id 가 바뀌거나 `in` 이 아니게 되면 `null` 로 비운다
- **다시 읽는 때 (이것뿐)**: ① `bootPhase === 'ready'` 이고 계정 id 가 처음 정해졌을 때 ② 설정 `계정` 탭이 보일 때(`onShown`, 푸시 묶음과 같은 자리) ③ D-18 을 열 때 ④ 돌아오기 질의를 처리할 때(5장) ⑤ `DELETE /api/github/account` 204 뒤 ⑥ 어느 GitHub 호출이든 `github_disabled`·`github_reconnect` 를 받았을 때 ⑦ `visibilitychange` 로 보이게 됐고 마지막 성공 조회가 **10분** 넘었을 때
- 동시에 여러 번 불리면 진행 중인 요청 하나를 같이 기다린다
- F-3018 관리 도구로 켜면 ①(새로고침)이나 ⑦에서 보인다. 끄면 ③·⑥·⑦ 중 먼저 오는 때 숨는다 — 그 사이 누른 동작은 503 `github_disabled` 문구를 받는다

### 3.2 `githubUi.ts` (순수)

```ts
export const GITHUB_RESUME_KEY = 'md.githubResume'      // sessionStorage. 제품명 없음
export const GITHUB_RESUME_TTL_MS = 1_800_000
export const GITHUB_LINK_FRESH_MS = 60_000
export function parseGithubStatus(raw: unknown): GithubStatus | null
export function githubDocRole(doc: { role?: 'owner' | 'edit' | 'view'; e2ee?: unknown } | null): 'owner' | 'editor' | null
export function githubConnectUrl(hash: string): string          // '/api/github/connect?return=' + encodeURIComponent(hash || '#/')
export function readGithubReturn(search: string): { kind: 'connected' } | { kind: 'error'; code: string } | null
export function urlWithoutGithubParams(pathname: string, search: string, hash: string): string
export function resumeMarker(r: { kind: 'import' } | { kind: 'link'; docId: string }, userId: string, now: number): string
export function decideGithubResume(raw: string | null, userId: string, now: number): { kind: 'import' } | { kind: 'link'; docId: string } | null
export function githubErrorMessage(r: { status: number; error: string | null; body: unknown }): string
export function githubConnectErrorMessage(code: string): string
export function githubDocTitle(path: string): string
export function decodeGithubContent(content: string): Uint8Array   // atob 실패면 던진다
export function branchChoices(branches: readonly string[], defaultBranch: string): string[]
export function linkTargetPath(dir: string, name: string): string | null
```

- `githubDocRole`: `e2ee` 가 있으면 null. `role` 이 없거나 `'owner'` → `owner`, `'edit'` → `editor`, `'view'` → null
- `readGithubReturn`: `github=connected` 가 있으면 connected, 아니면 `github_error` 값이 있으면 error, 둘 다 없으면 null
- `urlWithoutGithubParams`: 질의에서 `github`·`github_error` 둘만 빼고 나머지(`app=1` 등)·순서·해시는 그대로. 남는 게 없으면 `?` 도 없다
- `decideGithubResume`: JSON 이 아니거나, `userId` 가 다르거나, `now - at >= GITHUB_RESUME_TTL_MS` 면 null. 부르는 쪽은 결과와 상관없이 키를 지운다
- `githubDocTitle`: 마지막 세그먼트에서 끝의 `.md`·`.markdown`(대소문자 무시)를 뗀다. 빈 글자면 `제목 없는 문서`(r2 와 같은 값)
- `branchChoices`: `defaultBranch` 가 목록에 없으면 맨 앞에 끼운다. 있으면 그 자리 그대로
- `linkTargetPath`: `name` 앞뒤 공백을 자르고, `/` 가 있거나 빈 글자면 null. `dir` 이 빈 글자면 `name`, 아니면 `{dir}/{name}`. 결과가 `isRepoMdPath` 아니면 null

### 4.2 연결 캐시 (상단바·문서 메뉴 이름)
- 켜짐이고 지금 문서의 `githubDocRole` 이 null 이 아니면 문서를 열 때 `getDocGithub` 한 번. 결과(`GithubLink` 또는 404 = 없음)를 문서 id 별로 메모리에 두고 `GITHUB_LINK_FRESH_MS` 안에 다시 열면 그대로 쓴다. 그 밖 오류는 "모름" — 상단바 버튼 없음, 다음 열 때 다시 읽는다
- PUT 200·DELETE 204 뒤 그 값으로 바로 바꾼다
- 문서 `⋯` 항목 이름: 캐시가 "연결됨"이면 `GitHub 연결 정보…`, 그 밖(없음·모름)이면 `GitHub에 연결…`. 어느 쪽을 눌러도 D-18 은 먼저 `GET` 으로 확인해 연결 정보 또는 고르기를 보인다(Q3)

- **가져오기**: 파일 줄을 고르면 `가져오기` 가 켜진다. 4.4

- 초점: 열 때 첫 조작 칸(연결 안내면 `GitHub 연결`, 고르기면 `저장소`, 연결 정보면 `닫기`). 닫으면 연 자리로(`Dialog` 기본)

### 4.4 새 문서 가져오기 — `runGithubImport` (반드시 결론)

순서가 결정이다. 의존(`postFile`·`create`·`flushOutbox`·`hasPendingChanges`·`putLink`·`remove`·`open`·`notify`)을 받아 결과 `'opened-existing' | 'imported' | 'failed'` 를 돌려준다

1. 고른 줄의 `size > MAX_CONTENT_BYTES + 3` → `GitHub 파일이 너무 큽니다 (최대 1MB)`, 호출 0(횟수 안 듦)
2. `postGithubFile` (횟수 1). 실패 → 문구, 끝
3. **`linkedDocId` 가 있으면 만들지 않는다** — 그 문서를 열고 `이미 이 GitHub 파일에 연결된 문서를 열었습니다`. 결과 `opened-existing`

## 5. 계정 연결로 떠났다 돌아오기 (반드시 결론)

**떠날 때** (D-18·설정의 `GitHub 연결`): ① `docSaverFlushRef.current()` ② D-18 에서 눌렀으면 sessionStorage `GITHUB_RESUME_KEY` 에 `resumeMarker({ kind: 'import' } 또는 { kind: 'link', docId }, userId, now)`. 설정에서 눌렀으면 표지 없음 ③ `location.assign(githubConnectUrl(location.hash))`

**돌아왔을 때** (`useGithubFlow` 첫 효과, 한 번):
1. `readGithubReturn(location.search)` 가 null 이면 끝(표지도 건드리지 않는다)
2. **곧바로** `replaceAppEntry(urlWithoutGithubParams(pathname, search, hash))` — 계정 확인을 기다리지 않는다. 새로고침·뒤로가기로 같은 알림이 다시 뜨지 않게
3. connected → 알림 `GitHub에 연결했습니다`. error → `githubConnectErrorMessage(code)` 오류 알림
4. 계정이 `in` 이 된 뒤 2장 ④ 조회, 그다음 표지를 읽고 지운다. connected 이고 `decideGithubResume` 가 값을 주면 그 모양의 D-18 을 연다(`link` 는 그 문서가 아직 내 목록에 있을 때만). error 면 열지 않는다

`githubConnectErrorMessage`: `denied` `GitHub 연결을 취소했습니다`, `state` `GitHub 연결이 중간에 끊겼습니다. 다시 해 주세요`, `github_taken` `이 GitHub 계정은 이미 다른 계정에 연결돼 있습니다`, `disabled` `지금은 GitHub 기능을 쓸 수 없습니다`, `exchange_failed`·그 밖 `GitHub에 연결하지 못했습니다. 잠시 뒤에 다시 해 주세요`

`githubErrorMessage` (본문 `error` 기준, 없으면 상태 코드): `github_disabled`·`github_reconnect`·`github_quota`(`{N}` = `limit`, `{M}` = `resetAt` 의 UTC 월)·`github_rate_limited`·`too_large`·`e2ee` 는 ia 6장 문구 그대로. 새 문구: `github_forbidden` `GitHub에서 이 저장소에 쓸 수 없습니다`, `github_not_found` `GitHub에서 찾지 못했습니다. 저장소·브랜치·경로를 확인해 주세요`, `github_target_taken` `이 GitHub 파일은 이미 다른 문서에 연결돼 있습니다`, `account_blocked` 는 `ACCOUNT_BLOCKED_MESSAGE`, `rate_limited` `요청이 많아 잠시 뒤에 다시 해 주세요`, 그 밖·네트워크·`github_unavailable` `GitHub에 연결하지 못했습니다. 잠시 뒤에 다시 해 주세요`

## 11. 열린 질문

### Q1. 가져오기 중간 실패(만든 뒤 연결 실패) — **기본값: 만든 문서를 지운다**
- 이유: 사용자가 원한 것은 "연결된 새 문서"다. 연결 없는 사본이 남으면 다시 가져올 때 같은 내용 문서가 하나 더 생긴다. 내용은 GitHub 에 그대로 있어 잃는 것이 없다
- 다른 안: 남기고 열어 `GitHub에 연결…` 로 잇게 한다 — 지우기 호출이 없지만 4.4 ②에 "연결 안 된 사본" 안내 문구와 중복 처리가 는다

### Q2. `저장소 추가…` 주소 — **기본값: `status` 에 `installUrl` 을 더한다 (`worker/githubAuth.ts` 몇 줄)**
- 이유: slug 는 서버 `vars` 에만 있다(r4). 응답 하나에 붙이면 왕복이 늘지 않는다
- 다른 안 ①: 새 라우트 `GET /api/github/install` → 302 — 서버 라우트 표·쓰기 관문 판정이 는다. ②: 이 항목을 빼고 F-3014 의 "설치 0개면 설치 화면" 만 쓴다 — 서버를 안 건드리지만 저장소를 나중에 더할 길이 GitHub 설정 화면뿐이다

### Q3. 문서 `⋯` 이름을 무엇으로 정하나 — **기본값: 이번 세션 연결 캐시(4.2)**
- 이유: 목록 응답(`GET /api/docs`)에는 연결 여부가 없다. 서버를 안 건드리고, 눌렀을 때 D-18 이 `GET` 으로 바로잡는다
- 다른 안: F-3015 에 목록 응답 `githubLinked` 칸을 더한다 — 이름이 늘 맞지만 서버 목록 쿼리·캐시 모양(`CachedDoc`)이 바뀐다
