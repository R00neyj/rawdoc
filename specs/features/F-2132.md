## 2. 폴더 값 — id 또는 경로

**2.1 받는 곳.** 폴더를 가리키는 옵션은 모두 경로도 받는다**: `new --folder`, `mv --folder`, `mkdir --parent`, `ls --folder`, `find --folder`. 위치 인자로 받는 폴더 id(`rmdir <폴더id>`)는 **id 만** — 되돌릴 수 없는 명령이고, 옵션 값과 위치 인자를 가르는 규칙 하나로 설명이 끝난다. `args.ts` 는 값을 해석하지 않고 그대로 넘긴다(필드 이름 `folder`·`folderId`·`parent` 그대로 — 기존 `args.test.ts` 를 깨지 않게)

### 2.2 해석 규칙 — `cli/src/folderRef.ts` (계약)

```ts
export function isFolderId(value: string): boolean   // UUID 형식(worker/validate.ts UUID_RE 와 같은 식)
export type FolderRefResult =
  | { kind: 'found'; id: string }
  | { kind: 'not_found' }
  | { kind: 'ambiguous'; ids: string[] }
export function resolveFolderPath(value: string, folders: FolderLike[]): FolderRefResult
```

1. **UUID 형식이면 id** 로 그대로 쓴다 — `GET /v1/folders` 를 부르지 않는다. 폴더 id 는 늘 UUID(R4)라 이름과 겹칠 일이 없고, 지금 id 를 주는 호출의 요청 수가 그대로다. 내 폴더가 아닌 UUID 는 지금처럼 서버가 400 으로 거절한다(2.4 안내)
2. 아니면 **경로**: 앞뒤의 `/` 들을 떼고, 입력과 각 폴더의 경로(`folderPathOf` 이름을 `/` 로 이은 것, R10) 를 둘 다 `normalize('NFC')` 해 **문자열 전체가 같은** 폴더를 모은다. 대소문자 구분, 조각마다 공백을 떼지 않는다
   - 조각으로 나누지 않고 경로 문자열 전체를 비교하므로 이름에 `/` 가 든 폴더도 그 표기 그대로 찾힌다. 그 결과 `a/b`(이름) 와 `a` 안의 `b` 가 둘 다 맞으면 3 의 여럿이다. 맨 아래 이름만 주는 줄임은 받지 않는다(Q1)
3. 0개 → `not_found`, 2개 이상 → `ambiguous`(ids 는 `folders` 순서), 1개 → `found`
4. `--folder /`·빈 값은 2 에서 빈 문자열이 되어 `not_found` 다. 맨 위는 지금처럼 `--folder` 를 빼거나 `--root` 로 — `/` 를 맨 위로 받으면 Git Bash 에서 `C:/Program Files/Git/` 이 되어(R7) 같은 명령이 셸마다 다르게 돈다

### 2.3 요청

경로 값이면 `main.ts` 가 명령 함수를 부르기 전에 `GET /v1/folders` 한 번으로 풀고(실패하면 그 오류로 끝, 쓰기 없음), `commands.createDoc`·`moveDoc`·`mkdir` 에는 지금처럼 id 를 넘긴다. `ls`/`find --folder <경로>` 는 `--path` 가 있든 없든 폴더 목록을 **한 번만** 받아 요청 2회(`/v1/folders`·`/v1/docs`)

### 2.4 오류 (종료 코드 2, 표준 출력 비움, 쓰기 요청 없음)

| `error` | 언제 | 문구 (`{값}` 은 `stripControlChars`) |
| --- | --- | --- |
| `folder_not_found` | 2.2 의 `not_found` | `폴더를 찾을 수 없습니다: {값}. {cli} folders 로 폴더 id 와 경로를 확인하세요.` |
| `folder_ambiguous` | 2.2 의 `ambiguous` | `경로가 같은 폴더가 {n}개입니다: {값} ({id1}, {id2}…). 폴더 id 로 지정하세요.` |
| `invalid`(기존) | 서버 400 이고 `field` 가 `folderId`·`parentId` | 기존 문구 뒤에 ` {cli} folders 로 폴더 id 와 경로를 확인하세요.` |

- `folder_not_found` 이고 값이 `/^[A-Za-z]:\//` 로 시작하면 한 문장을 더 붙인다: ` / 로 시작하는 값은 Git Bash 가 Windows 경로로 바꿉니다. 앞의 / 를 빼고 다시 실행하세요.` (R7). `--json` 오류 줄은 기존 `{error, status: null, message}` 에 `folder: {값}`(원문), `folder_ambiguous` 는 `folderIds: string[]` 를 더한다
- 종료 코드를 4(찾을 수 없음)가 아니라 2 로 둔 이유: 지금 같은 입력(`new --folder 수업자료/…`)이 서버 `invalid` 로 2 를 낸다. 스크립트가 보는 번호가 바뀌지 않는다

## 3. `put` 줄바꿈 안내 (쓰기)

- **막지 않고 알린다.** 서버가 이미 문서 방식에 맞춰 저장한다(R1). 로컬 파일은 고치지 않는다 — 서버와 같은 바이트가 필요하면 `get -o`. `new` 는 파일 방식으로 문서가 생겨 해당 없음
- 조건(모두): 원문 파일·표준 입력을 올렸다, 해독한 글자에 줄바꿈이 하나 이상 있다(R3), 해독 결과의 `lineEnding` ≠ **PUT 응답**의 `lineEnding`(R2). 추가 요청 없음. PUT 성공 뒤 `emitDecodeNotices` 안내들 다음에 표준 오류 한 줄, 실패하면 없음, `--json` 이어도 찍는다. 문구(`putPreview.ts`, `{파일}`·`{서버}` 는 `LF`/`CRLF`, `{label}` 은 기존 `labelOf`) — 쓰기: `"{label}" 줄바꿈({파일})이 서버 문서({서버})와 달라 서버 문서에 맞춰 저장했습니다.` / 미리 보기: 끝만 `저장됩니다.`

## 4. `put --dry-run`

### 4.1 인자

- `RunCommand` `put` 에 `dryRun: boolean`. `--dry-run` 이면 `--base-version`·`--force` 를 **빼도 된다**(쓰지 않으니 덮어쓰기 보호가 필요 없다). 둘 다 주거나 원문도 `--title` 도 없으면 지금과 같은 사용법 오류
- 원칙: **`--dry-run` 은 쓰기만 뺀 `put` 이다** — 파일 읽기·해독·안내, 판정, 오류와 종료 코드가 같다

### 4.2 동작

- 요청: `GET /v1/docs/:id` 1회. PUT 없음. GET 은 쓰기 한도에 세지 않는다(F-2119 근거). 확인하지 않는 것(README 에 한 줄): 쓰기 권한(보기 권한 공유 문서도 GET 은 된다), 크기·용량, 쓰기 횟수 한도
- 비교는 서버가 실제 저장할 모양으로: 저장될 본문 = `fromEditorText(toEditorText(파일 글자), 서버 lineEnding)`(R1 과 같은 식)
- 판 번호: `--base-version` 을 줬고 서버 `version` 과 다르고 제목이나 본문이 바뀌면 **`conflict`** — 서버 409 와 같은 조건(R2), 같은 오류 객체(`currentVersion` = 서버 version), 종료 5, 표준 출력 비움. 바뀌는 줄을 보려면 `--base-version` 없이 다시 `--dry-run`- 줄 요약 — `putPreview.ts` 순수 함수. 두 글자를 `toEditorText` 한 뒤 `\n` 으로 나눈 줄 배열(끝 빈 문자열도 한 줄로 둔다)을 비교:
  - `linesAdded` = 새 줄 중 옛 줄 개수표에서 지울 수 없는 줄 수, `linesRemoved` = 옛 개수표에 남은 줄 수(줄 → 개수 Map, 순서 무시). 순서만 바뀐 줄은 세지 않는다 — 전체 diff 가 아니라 크기 감을 주는 요약이고, 1 MB 에서 10 ms 안쪽(R8)
  - `firstChangedLine` = 앞에서부터 처음 다른 줄의 번호(1부터, 저장될 본문 기준). 본문이 같으면 `null`
- 바뀌는 것이 없으면(제목·본문 모두) 표준 오류에 `바뀌는 내용이 없습니다.`, 종료 0. 3장 안내는 미리 보기 문구로, 결과 출력 전에

### 4.3 출력 (계약)

```ts
export type PutPreview = {
  dryRun: true
  id: string
  version: number                         // 서버의 지금 판
  lineEnding: 'crlf' | 'lf'               // 서버 문서 = 저장될 방식
  fileLineEnding: 'crlf' | 'lf' | null    // 원문 없음·줄바꿈 없음이면 null
  titleChanged: boolean
  contentChanged: boolean                 // 저장될 본문 !== 서버 본문
  linesAdded: number
  linesRemoved: number
  firstChangedLine: number | null
}
```

- `--json`: 이 객체 한 줄. 사람용: `dryRun` 을 뺀 키를 이 순서로 `{키}\t{값}\n`(F-2119 5.3 `info` 와 같은 방식), `null` 은 `-`, 불리언은 `true`/`false`. 원문 없이 `--title` 만이면 `contentChanged: false`, 줄 수 0, `firstChangedLine: null`

## 5. 도움말 — `cli/src/help.ts`

### 5.1 `help <명령>`

`args.ts` 에서만 별칭으로 처리하고 `COMMAND_NAMES` 에 넣지 않는다 — `RunCommand` 와 `--help` 의 명령 줄·순서 테스트(F-2050 C13·F-2118 A8·F-2119 A9)를 건드리지 않는다. `help` → `{ kind: 'help', command: null }`, `help <명령>` → `{ kind: 'help', command }` (출력은 `<명령> --help` 와 바이트까지 같다), `help <모르는 이름>` → 사용법 오류 `알 수 없는 명령입니다: {이름}`(명령 없음, 힌트 줄 없음), `help` 뒤 인자 2개 이상 → 사용법 오류 `help 뒤에는 명령 이름 하나만 줍니다.`

### 5.2 전체 도움말

꼬리 줄 맨 앞(Windows PowerShell 줄 위)에 `명령별 옵션은 {cli} help <명령> 또는 {cli} <명령> --help 로 봅니다.` 마지막 줄(syntax 안내, F-2118 A8)은 그대로. `COMMAND_DESCRIPTIONS.put` → `문서를 고칩니다 (get 으로 받은 판 번호 --base-version 필요, --dry-run 은 미리 보기. 자세히: put --help)`. 나머지 한 줄 설명은 그대로

### 5.3 명령별 상세 — 옵션이 있는 명령 모두

옵션이 없는 `logout`·`whoami`·`info`·`folders`·`upload`·`link`·`syntax` 는 한 줄 설명만(F-2118 A9 그대로). 아래 각 블록은 `ls`·`put` 의 지금 모양처럼 빈 줄로 시작한다. `{cli}` 는 `brand.cliName`, `{경로안내}` 는 `폴더 경로는 {cli} folders 가 보여 주는 모양(예: 수업자료/1주차)입니다.`

```
login   사용: {cli} login [--force] [--with-token] [--no-browser]
```

## 6. 위키링크 안내

`put --help`·`mv --help` 의 줄(5.3)과 `syntax` 출력: `위키링크` 그룹 끝(기존 `cliNote` 다음 문단)에 `제목을 바꾸면 옛 제목으로 건 위키링크는 자동으로 고쳐지지 않아 끊깁니다. 폴더를 붙인 링크는 문서를 다른 폴더로 옮겨도 끊길 수 있습니다.` `--json` 은 그 그룹의 `note` 끝에 공백 하나를 두고 붙인다(모양 그대로). 이 문장은 `cli/src/syntax.ts` 상수로 둔다 — `src/lib/markdownSyntax.ts` 의 `cliNote` 를 고치면 `cli/` 만이라는 결정 3 의 테두리를 넘는다(Q2). 늘어나는 길이 약 75자 → 약 1,655자로 상한 2,000자 안(R8)

## 7. `cli/README.md`

- 명령 표: `ls`·`find` 의 `--folder <id>` → `--folder <id\|경로>`, `new` 행 `[--folder <id\|경로>]`, `mv` 행 `(--folder <id\|경로>\|--root)`, `mkdir` 행 `[--parent <id\|경로>]`, `put` 행 끝에 ` [--dry-run]` 과 설명 `--dry-run 은 쓰지 않고 바뀌는 줄 수·줄바꿈 방식만 보여 줍니다(쓰기 권한·용량은 확인하지 않음)`
- 표 아래 문장에 더함: `폴더 경로는 folders 가 보여 주는 모양(수업자료/1주차)이고, 같은 경로의 폴더가 여럿이면 id 로 지정해야 합니다. 명령별 옵션은 help <명령> 으로 봅니다.` `## 원문 보존` 첫 문단 끝에: `put 한 파일의 줄바꿈이 서버 문서와 다르면 서버 문서 방식으로 저장되고 표준 오류에 안내가 뜹니다. 로컬 파일은 바뀌지 않습니다.`
