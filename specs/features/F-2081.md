## 2. 옮기는 것

모든 컴포넌트는 F-2076 3.1 규칙을 따른다 — **파일 하나에 `export default` 컴포넌트 하나와 `export type {이름}Props` 하나**, 훅·`useState`·`useEffect`·Context 없음, props 로만 받는다. 모듈 내부 상수·함수는 export 하지 않는다. JSX 는 **글자 그대로** 옮긴다(F-2059 3.6 — DOM 순서·`className`·`data-*`·`aria-*`·`hidden`·`inert`·`key`·주석 포함). 들여쓰기만 바뀐다.

### Q1. 특성 e2e C1 을 두나 — **기본값: 둔다(1개)**

- 다른 쪽(두지 않는다): e2e 파일을 건드리지 않는다. 대신 이 컨테이너의 구현 검증에서 폴더 입력은 확인되지 않고 PC `verify:full`(A10)까지 기다린다. 소유 표에서 `e2e/appSplit.spec.js` 가 빠지고 A6 이 없어진다

### Q3. `DocumentArea` 가 `showEditor` 를 prop 으로 받나 — **기본값: 받는다**

- 이유: `wikiPreviewEnabled`·`commentAvailable` 을 글자 그대로 옮기려면 그 이름이 있어야 한다(F-2059 3.6 — 빨강·초록을 늘리지 않는다). 컴포넌트 안에서는 늘 `true` 라 뜻은 없다
- 다른 쪽(받지 않고 두 계산에서 `showEditor &&` 를 지운다): prop 하나가 준다. 대신 두 계산 줄이 빨강·초록이 되고, `DocumentArea` 를 다른 조건으로 그리게 되면 조건이 조용히 빠진다

### Q4. `mapDialogScope` 를 `AppScreens` 로 옮기나 — **기본값: App 에 남긴다**

- 이유: F-2076 2.2 가 옮기는 렌더 계산을 "`DocumentArea` 만 쓰는 것" 으로 정했다. `searchDialogScope` 와 짝 주석(`// 지도 인덱스 재사용 범위 — 같은 방식`)으로 붙어 있어 떼면 주석 뜻이 흐려진다
- 다른 쪽(옮긴다): App 이 2줄 더 준다. `AppScreens` 가 `store`·`mapIndexScope` 를 더 받는다(`account` 는 이미 받는다)

### Q5. `CommentRailPanel.tsx` 의 "App 이 .content-area 의 --comment-rail-extra 로 넣는다" 주석을 고치나 — **기본값: 고치지 않는다**

- 이유: F-2059 3.6 은 `App.tsx` 표기가 든 줄만 고친다. 이 줄은 "App" 이라는 역할 이름이고, `commentRailExtra` 상태는 여전히 App 이 갖는다(`DocumentArea` 는 받아서 `style` 에 넣을 뿐)
- 다른 쪽(`DocumentArea` 로 고친다): 소유 표에 `CommentRailPanel.tsx` 가 더해지고 A8 에 빨강·초록 한 줄씩

### 관찰 (이 조각은 고치지 않는다)

1. `LiveSnapshot` type import 는 HEAD 에서 이미 안 쓰인다(2.7). 저장소 ESLint 가 대문자 이름을 `varsIgnorePattern` 으로 넘겨 잡지 못한다 — 같은 이유로 **안 쓰는 컴포넌트 import 도 lint 가 못 잡는다.** 뒤 조각(F-2082)도 `tsc --noUnusedLocals` 로 확인하는 편이 낫다
2. `scrollElement={editorRef.current?.view.scrollDOM ?? null}` 은 실제로는 `CommentPanelPresence` 가 렌더 중 자식 함수를 부를 때 읽힌다 — 규칙이 못 볼 뿐 렌더 중 ref 읽기다. 동작은 지금과 같고 옮기기만 하므로 그대로 둔다

기본값으로 정한 것(승인 시 확정): 2장 경계·props 목록·App 에 남는 것, 5장 계약(파일 모양·필수 필드·호출 표기), 6장 U1~U12, 7.2 C1, 8장 e2e 세 명령, Q1~Q5.
