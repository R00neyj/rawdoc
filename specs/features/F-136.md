## 3. 수정 항목

### 3.1 빈 상태 `새 문서` 버튼 (high)
- 현재: `EmptyState` 가 `onClick={onCreateDoc}` 로 연결되어 클릭 이벤트 객체가 `folderId` 로 넘어가고, IndexedDB 가 `DataCloneError` 를 내 문서가 만들어지지 않는다
- 수정: 이벤트 객체가 인자로 넘어가지 않게 연결한다 (`() => onCreateDoc()`). 같은 패턴으로 `onCreateDoc`·`onCreateFolder` 등 인자를 받는 핸들러가 `onClick` 에 직접 연결된 곳이 있으면 모두 고친다
- 저장소 `create` 는 `folderId` 가 `null` 또는 문자열이 아니면 오류를 던진다 (테스트)

### 3.2 문서는 폴더 행·최상위 영역에만 놓기 (medium)
- 현재: 문서를 다른 문서 행에 끌어놓으면 `onMoveDoc(id, 대상 문서 id)` 가 불리고 저장소도 검사하지 않아, 폴더 id 자리에 문서 id 가 저장된다
- 수정
  - `Sidebar.jsx` `canDropOn`: 문서를 끌 때 대상이 폴더 행이거나 최상위 빈 영역일 때만 참 (F-126 5장)
  - 저장소 `moveDoc(id, folderId)`: `folderId` 가 `null` 이 아니고 존재하는 폴더가 아니면 오류를 던지고 아무것도 바꾸지 않는다. `create` 도 같은 검사
- 테스트: 존재하지 않는 폴더 id·문서 id 로 `moveDoc`·`create` → 거부, 문서 그대로

### 3.3 IndexedDB 업그레이드가 다른 창에 막힐 때 (medium)
- 현재: `openDB` 에 `blocked`·`blocking` 처리가 없다. 옛 버전 창이 연결을 쥐고 있으면 새 창이 부팅 화면에서 끝없이 기다린다
- 수정
  - **새 버전 창 (`blocked`)**: 부팅 화면에 문구 `다른 창에서 이 앱이 열려 있습니다. 그 창을 닫거나 새로 고치면 계속됩니다.` 를 보이고 계속 기다린다. 막힘이 풀려 열리면 평소처럼 진행
  - **옛 버전 창 (`blocking`)**: 먼저 저장 대기 중인 내용을 저장 시도한 뒤 연결을 닫고, 알림 막대에 `새 버전이 다른 창에서 열렸습니다. 이 창을 새로 고쳐 주세요.` 와 `새로 고침` 버튼을 띄운다. 연결을 닫은 뒤의 저장 시도는 기존 저장 실패 처리를 따른다
  - 문구는 이 명세가 정한 것이다 (`specs/ia.md` 6장에 없음 — 최종 보고에서 확인 요청)
- 테스트: `fake-indexeddb` 가 이미 테스트에 쓰이고 있으면 v1 연결을 연 채로 v2 열기 → `blocked` 콜백 호출, v1 쪽 `blocking` 콜백 호출 확인. 없으면 콜백 연결을 단위 수준으로 확인하고 못 한 부분을 보고
