## 1. 계약 — 공개 변수와 공식 훅

### 1.1 계약이 뜻하는 것

- **약속하는 것:** 1.2 의 공개 변수 51개가 `tokens.css` 의 `:root` 에 같은 이름·같은 뜻으로 있다. 1.4 의 뼈대 훅 17개와 1.5 의 본문 훅 11개가 같은 요소에 붙어 있다. 1.5 의 **권장 선택자**로 쓴 규칙은 앱 규칙과 특정도가 같거나 높다 — 사용자 CSS 가 나중에 오므로(2.1) 이긴다
- **약속하지 않는 것:** 그 밖의 클래스·속성·DOM 구조·비공개 변수. tweak 으로 언제든 바뀐다. 이것들을 쓴 스니펫이 업데이트로 깨져도 알리지 않는다
- **계약을 바꾸는 절차:** 공개 변수·훅을 없애거나 이름을 바꾸려면 명세가 필요하다(tweak 불가). 그 명세는 체인지로그에 `사용자 CSS:` 로 시작하는 줄을 남기고 안내 글(5.7)을 고친다. **더하는 것**은 명세 안에서 한 줄로 된다
- 사용자가 요청한 "BEM 이 잘 안 지켜진다" 에 대한 답: 613개 클래스를 고치지 않는다. 대신 사용자에게 알려 줄 28개만 따로 안정 이름을 주고 단위 테스트로 묶는다(1.6). 클래스 전면 정리는 tweak 이 이름을 자주 바꾸는 한 다시 무너지고, 그 비용이 사용자 CSS 가 얻는 것보다 크다

### 1.3 테마·설정과의 관계 — 어떤 선택자로 써야 이기나

`tokens.css` 는 화이트 값을 `:root` (0,1,0) 에, 세피아·다크를 `:root[data-theme='…']` (0,2,0) 에, 글자 크기·서체·들여쓰기를 `:root[data-font-size]` 등 (0,2,0) 에 둔다. 사용자 시트는 늘 뒤에 온다(2.1). 그래서:

| 쓰고 싶은 것 | 권장 선택자 | 이유 |
| --- | --- | --- |
| 모든 테마·인쇄·HTML 내보내기에 | `:root:root` | (0,2,0) 이라 테마·설정 블록과 동률, 뒤에 와서 이긴다 (M6). `:root` 만 쓰면 (0,1,0) 이라 세피아·다크·`작게`·`크게` 에서 진다. `:root[data-theme]` 는 인쇄 중(`printDoc` 이 `data-theme` 를 뗀다)과 HTML 내보내기(`<html>` 에 속성 없음)에서 안 맞는다 |
| 한 테마에만 | `:root[data-theme='white']` / `'sepia'` / `'dark'` | 부팅 스크립트가 해석한 값을 늘 넣는다(`시스템` 이어도 `white`/`dark`). 인쇄·HTML 내보내기는 화이트 값으로 나가므로 테마별 규칙은 거기 안 들어간다 |
| 설정값에 따라 | `:root[data-heading-font='sans']` `[data-body-font='serif']` `[data-font-size='small'\|'large']` `[data-indent='2']` | 지금 있는 속성. 계약에 넣는다 (1.4 끝) |

- **설정과 겹치는 공개 변수**(`--md-font-size`, `--font-display`, `--font-body`)를 `:root:root` 로 덮으면 그 설정(`글자 크기`·`제목 서체`·`본문 서체`)은 효과가 없어진다. 막지 않고 안내 글에 적는다
- 템플릿 CSS(5.3)는 이 표 순서대로 "공통 → 테마별" 블록을 둔다. 같은 특정도에서는 사용자 시트 안에서도 뒤가 이기기 때문이다

### 1.4 화면 뼈대 훅 17개 — 새 `data-ui` 속성

- **이름 규칙:** 속성 이름은 `data-ui`, 값은 영어 소문자 명사 kebab-case. 제품명을 쓰지 않는다. 한 요소에 값 하나
- **앱 CSS·JS 는 `[data-ui]` 를 선택자로 쓰지 않는다.** 사용자 전용 창구다 — 앱이 쓰면 앱 사정으로 특정도·의미가 바뀐다 (1.6 U4). e2e 는 써도 된다
- 기존 클래스를 약속하지 않고 새 속성을 붙이는 이유: 클래스는 tweak 이 이름을 바꾸고(사용자 지적), 앱 CSS 가 같은 클래스로 특정도를 올려 가며 쓴다. 전용 속성은 앱이 안 쓰므로 이름이 흔들릴 이유가 없다

### 1.5 본문 훅 11개 — 지금 클래스를 약속한다

본문은 새 속성을 붙이지 않고 **지금 있는 클래스를 권장 선택자와 함께 약속한다.** 이유:
- 보기 모드 HTML 은 markdown-it 출력이라 HTML 내보내기·인쇄·위키링크 미리보기가 같은 `.markdown-body` 마크업을 쓴다. 여기 속성을 박으면 내보낸 파일 모양이 바뀌고 `toHtmlDoc.test.ts` 가 흔들린다. `.markdown-body` 는 GitHub 관례라 사용자가 이미 안다(Q21 초안도 이 이름을 창구로 적었다)
- 편집 모드는 CM6 줄 decoration 클래스(`md-h1` 등)가 이미 뜻 이름이라 tweak 이 바꿀 일이 드물다. 그래도 바꾸지 못하게 테스트로 묶는다 (1.6 U2)

## 2. 주입 방식과 순서

### 2.1 스니펫마다 시트 하나, `document.adoptedStyleSheets` 맨 뒤

- 켠 스니펫마다 `CSSStyleSheet` 하나를 만들어 `document.adoptedStyleSheets` **맨 뒤**에 목록 순서대로 넣는다. `<style>` 요소를 쓰지 않는다
- **왜 adoptedStyleSheets 인가:** 문서 시트(`<link>`·`<style>`) 전부보다 뒤에 온다 (M5). 지도·수식처럼 나중에 읽히는 청크 CSS 는 Vite 가 `<head>` 에 붙이는데, `<head>` 안 `<style>` 로 넣으면 그보다 앞서 같은 특정도에서 진다. CM6 는 document 에는 `<style>` 을 `<head>` 맨 앞에 넣으므로(style-mod) adoptedStyleSheets 와 겹치지 않는다
- **왜 스니펫마다 하나인가:** 한 스니펫의 닫히지 않은 `{` 가 합친 문자열에서는 뒤 스니펫까지 삼킨다. 시트를 나누면 오류가 그 스니펫 안에 갇힌다
- 순서는 목록 순서(5.1) = 만든 순서. 뒤 스니펫이 같은 특정도에서 이긴다
- **원문을 그대로 적용하지 않는다.** 언제나 3.1 의 검사를 거친 결과(이하 "컴파일 결과")만 시트에 넣는다

### 2.2 `@layer` 를 쓰지 않는다

- 앱 CSS 를 `@layer app` 으로 감싸면 사용자 규칙이 특정도와 상관없이 이겨 편하지만, **층 없는 CM6 기본 테마(style-mod 가 넣는 `<style>`)가 층에 들어간 앱의 CM6 덮어쓰기를 전부 이긴다** — 층 없는 규칙이 층 있는 규칙을 이기는 캐스케이드 규칙 때문이다. 편집기 모양이 무너진다
- 사용자 CSS 를 층에 넣으면 층 없는 앱 CSS 에 전부 진다
- 그래서 둘 다 층 없이, 순서(2.1)와 권장 선택자(1.3~1.5)로 이기게 한다. 사용자가 자기 스니펫 안에서 `@layer` 를 쓰는 것은 막지 않는다(그 규칙은 앱 규칙에 진다고 안내 글에 적는다)

### 2.3 첫 칠 전에 적용 — 부팅 스크립트

- `BOOT_PAINT_SCRIPT`(F-2015)가 테마 다음에 **컴파일 결과를 localStorage 에서 읽어 adoptedStyleSheets 에 넣는다.** 스켈레톤(`boot.css` 가 `--paper` 등을 쓴다)부터 사용자 색으로 칠해져 깜빡이지 않는다. 비용은 상한에서 중앙값 4.3ms (M7)
- 부팅 스크립트는 원문을 검사하지 않는다 — 앱이 저장해 둔 컴파일 결과(4.2 `md.userCssBoot`)만 쓴다. 그 결과에 박힌 **검사기 버전**이 스크립트에 박힌 버전과 다르면 적용하지 않는다(앱이 다시 컴파일한 뒤 적용 — 업데이트 직후 한 번 늦게 칠해진다)
- 어느 쪽 스니펫을 쓰나: `md.account` 가 비었으면 로컬 슬롯, 있으면 그 `id` 와 `md.userCssBoot.account.userId` 가 같을 때만 계정 슬롯. 다르면 아무것도 적용하지 않는다
- 적용하지 않는 경우: 주소에 `safe` 질의 인자(3.3), 해시가 `#/p/` 로 시작(공개 보기, 2.4)
- 시트 생성자는 `document.defaultView.CSSStyleSheet` 로 얻는다 — F-2015 4.3 "다섯 전역만" 규칙을 지키고, `bootPaint.test.ts` 의 가짜 `document` 로 시험할 수 있다. 가짜에 `defaultView`·`location.search` 가 없어도 예외 없이 건너뛴다
- 앱이 부팅 시트를 이어받는다: 앱 모듈이 뜨면 부팅 스크립트가 넣은 시트를 빼고 자기 것으로 바꾼다. 이어받는 방법(기본값: 부팅 스크립트가 만든 시트 배열을 `window` 의 제품명 없는 이름 하나에 걸어 둔다)은 F-2095 가 정한다. **같은 스니펫이 두 번 적용되는 순간이 없어야 한다**
- 적용 상태를 `<html data-user-css="on|off|safe">` 로 남긴다 (`off` = 켠 스니펫 0개). 적용할 때마다 `data-user-css-rev` 를 1 올린다 — 2.5 의 다시 읽기 신호. `data-user-css-rev` 는 비공개다

### 2.5 편집기·지도 — 다시 재기와 CSS 가 닿지 않는 곳

- **CM6 편집기:** 줄 높이·글자 크기가 바뀌면 CM6 높이 표가 낡는다. `<html data-user-css-rev>` 가 바뀌면 `view.requestMeasure()` 를 부른다 (`fontRemeasure.ts` 와 같은 모양의 ViewPlugin, F-2098)
- **3D 지도:** 캔버스는 CSS 가 닿지 않는다. `MapScene.tsx` 는 프로브 요소로 `--panel` `--ink` `--ink-2` `--muted` `--rule` `--accent` `--map-group-1~8` 을 **읽어서** 칠한다. 지금은 `data-theme` 가 바뀔 때만 다시 읽으므로 `data-user-css-rev` 도 지켜보게 한다(F-2098). 노드 크기·간선 굵기 등 그 밖은 사용자 CSS 로 바꿀 수 없다
- **지도 색 형식:** `parseCssColor` 가 hex·`rgb()`·`color(srgb …)` 만 받아 `oklch()`·`lab()`·`display-p3`·`color-mix(in oklch…)` 은 지도에서 `FALLBACK` 이 된다 (M8). 기본값: F-2098 에서 못 읽은 색을 1×1 2D 캔버스에 칠해 sRGB 로 바꿔 읽는다 (9장 Q5)
- **IME:** 원격에서 온 변경(4.4 서버 동기화, 2.6 다른 탭)은 편집기가 한글 조합 중이면 적용을 미루고 `compositionend` 에 적용한다. 레이아웃이 조합 중에 바뀌지 않게 하는 것으로, "조합 중 원격 갱신 금지" 불변식과 같은 취지다. D-16 에서 사용자가 직접 치는 변경은 편집기 조합과 겹치지 않으므로 바로 적용한다

### 2.6 탭 사이

- 같은 브라우저의 다른 탭은 localStorage `storage` 이벤트(4.2 키 셋)로 알아채고 다시 적용한다. 새 채널을 만들지 않는다

## 3. 안전

### 3.1 외부 요청 차단 — 컴파일 규칙

`specs/product.md` Q11 "CSS 도 `url()` 외부 요청은 막는다" 를 따른다. 이유: (1) 남이 건넨 "예쁜 테마" 를 붙여 넣으면 `@font-face unicode-range`·속성 선택자 + 외부 `url()` 로 내가 쓰는 글자·화면 내용을 밖으로 흘릴 수 있다, (2) 오프라인 약속(F-116, 외부 CDN 금지), (3) HTML 내보내기 파일은 인터넷 없이 열려야 한다(F-280).

**문자열 정규식으로 거르지 않는다.** 이스케이프(`\75 rl(`)·`image-set("…")` 문자열 인자 같은 우회가 있다 (M3·M4). 브라우저 파서가 한 번 정규화한 결과를 판정한다:

1. 원문을 `new CSSStyleSheet().replaceSync()` 로 파싱한다 — `@import` 는 여기서 사라진다 (M2)
2. `cssRules` 를 중첩까지 걸으며 **허용 규칙 종류**만 남긴다: 스타일 규칙(중첩 포함), `@media`, `@supports`, `@container`, `@layer`(블록·선언), `@keyframes`, `@font-face`, `@page`, `@starting-style`, `@scope`. **나머지는 통째로 뺀다** — `@property`(초깃값에 `url()`), `@counter-style`(`symbols` 에 이미지), `@namespace`, `@font-feature-values`, `@font-palette-values`, 그리고 앞으로 생길 모르는 종류
3. 선언마다 판정한다 (순수 함수, 3.1 끝):
   - 일반 속성: 정규화된 값에 `url(` 이 있고 그 인자가 `data:` 나 `#` 으로 시작하지 않으면 **그 선언을 뺀다**. `image-set(` 은 정규화 뒤 `url(` 로 들어오므로 같은 규칙에 걸린다
   - 사용자 정의 속성(`--*`): 값(소문자)에 `url(`·`image-set(`·`src(`·`\` 중 하나라도 있으면 **그 선언을 뺀다** — 이 값은 정규화되지 않고(M4) `var()` 로 어디든 들어가 요청을 일으키기 때문이다
   - `@font-face`: `src` 가 `data:` 와 `local()` 만이 아니면 **그 규칙을 뺀다**
4. 남은 규칙들의 `cssText` 를 이은 것이 컴파일 결과다. 뺀 선언·규칙 수와 원문의 `@import` 수(주석을 뺀 원문에서 센다)를 함께 돌려준다 — D-16 이 보여 준다 (5.2)

- 판정 규칙(3번)은 `src/lib/userCssPolicy.ts` 의 **순수 함수**로 둔다(값 문자열·속성 이름·규칙 종류 이름만 받는다). node 단위 테스트로 판정한다. CSSOM 을 걷는 얇은 부분(`src/app/userCssCompile.ts`)은 브라우저에서만 돌아 e2e 1개로 판정한다 — "외부 주소를 가리키는 스니펫을 켜도 그 주소로 요청이 나가지 않는다" (Playwright `request` 이벤트, M4 의 두 경우 포함)
- **검사기 버전** 상수를 둔다. 규칙을 고칠 때마다 올린다. 저장된 컴파일 결과의 버전이 다르면 부팅 적용을 건너뛰고 앱이 다시 컴파일한다 (2.3)
- 설치된 글꼴은 `font-family: '나눔명조'` 처럼 이름으로 쓸 수 있다 — `url()` 이 필요 없다. 안내 글에 적는다

### 3.2 CSP 로 막지 않는 이유

- 지금 앱 응답에 CSP 가 없다 (M9). CSP(`img-src`·`font-src`·`style-src`)를 걸면 3.1 없이도 막히지만, 첫 칠 스크립트(인라인)·브랜드 `<style>` 주입·`data:`/`blob:` 이미지·KaTeX·Mermaid 인라인 스타일·OAuth 흐름을 모두 다시 따져야 하는 별도 작업이다. **이 개요에서는 도입하지 않는다.** 따로 명세가 생기면 3.1 은 이중 방어로 남긴다

### 3.3 안전 모드 — 앱을 못 쓰게 만든 CSS 에서 빠져나오기

`* { display: none }` 한 줄이면 설정 대화상자도 안 보인다. 빠져나오는 길은 **주소**로 둔다 — CSS 가 가릴 수 없는 유일한 입구다.

- **`/?safe`** 로 열면(질의 인자 `safe` 가 있으면, 값 무관) 부팅 스크립트와 앱이 사용자 CSS 를 적용하지 않는다. 저장된 스니펫·켜짐 상태는 **그대로 둔다**
- 서비스 워커가 있으면 `/?safe` 도 `index.html` 로 풀린다(`navigateFallbackDenylist` 에 안 걸린다). 서비스 워커가 없을 때는 워커가 `/` 를 쿠키로 가르는데(`rootTarget`), 앱을 써 본 브라우저는 쿠키가 있어 앱이 열린다. 안내 글에는 "안 열리면 `/?app=1&safe`" 를 함께 적는다
- 안전 모드일 때: `<html data-user-css="safe">`, 알림 띠 N-1 `사용자 CSS 를 끄고 열었습니다.` + 버튼 `다시 켜기`(주소에서 `safe` 를 빼고 해시는 둔 채 다시 읽기). 설정 `사용자 CSS` 탭 맨 위에도 같은 뜻의 한 줄(5.8). 그 창에서 스니펫을 켜고 고쳐도 **적용하지 않는다** — 저장만 한다
- 단축키로 끄는 길은 두지 않는다 (9장 Q6)

### 3.4 크기·개수 제한

| 항목 | 상한 | 근거 |
| --- | --- | --- |
| 스니펫 수 | 50 | 상한에서 부팅 4.3ms (M7). 목록 UI 가 스크롤 한 번 안에 든다 |
| 원문 합계 | **262,144 바이트(256KiB, UTF-8)** — 켜짐 여부와 무관하게 모든 스니펫 합 | localStorage 에 원문(로컬·계정 두 슬롯) + 컴파일 결과가 함께 산다. 최악 약 1MB. Chrome localStorage 한도는 출처당 약 5M 문자로 알려져 있다(**이 프로젝트에서 재지 않았다** — F-2095 가 상한 자료로 `setItem` 이 던지지 않는지 e2e 안에서 확인한다). 상한 부팅 비용은 M7 |
| 이름 | 1~60자, 앞뒤 공백 없음, 제어 문자 없음 | 목록 한 줄 |

- 상한을 넘기는 저장은 막고 문구를 보인다(5.8). 붙여 넣기로 넘으면 그 입력을 받지 않는다(원래 글 그대로)
- 상수는 `src/lib/userCssPolicy.ts` 에 두고 클라이언트·서버가 함께 쓴다(worker 는 `src/lib/**` 순수 함수를 import 할 수 있다, architecture.md 6장)

### 3.5 서버 검증

- 서버는 CSS 를 **해석하지 않는다.** 모양·크기만 본다 — 서버가 CSS 를 남에게 내보내는 길이 없고(2.4), 적용 전 검사는 클라이언트가 늘 한다(2.1)
- 요청 본문 상한 `2 × 262,144 + 16,384 = 540,672` 바이트 — JSON 문자열 이스케이프로 최악 두 배(`e2eeKeys.ts` 의 `MAX_KEYS_BODY_BYTES` 와 같은 논리) + 이름·id 여유
- `PUT` 은 비`GET` `/api/*` 라 `writeGate` 가 자동으로 건다 — 분당 120(`WRITE_LIMITER`), 하루 5,000(`DAILY_WRITE_LIMIT`). 클라이언트는 치는 동안 2초 디바운스로 보내 분당 30회를 넘지 않는다(4.4)
- 사용량 누계(`content_bytes`·`doc_count`)에는 넣지 않는다 — 문서가 아니고 따로 상한이 있다

### 3.6 불변식과의 관계

- **색 hex·제품명 금지(CLAUDE.md)는 앱 소스 규칙이다. 사용자 CSS 는 사용자 데이터라 해당하지 않는다.** 사용자는 hex 를 써도 된다
- 단, **앱이 만드는 문자열은 여전히 해당한다.** 템플릿 CSS 생성 코드(5.3)는 hex 를 소스에 쓰지 않는다 — 기본값은 실행 시 `tokens.css` 원문에서 읽어 넣는다. 안내 글 예시는 `var()`·`color-mix()`·CSS 색 이름만 쓴다
- 저장소 식별자: 새 localStorage 키 셋(4.2)은 `md.` 접두사, 제품명 없음. D1 표 이름 `user_css`
- CLAUDE.md 에 불변식 한 줄을 더할 것을 제안한다 (8장): "사용자 CSS 는 주인의 브라우저(와 주인이 내보낸 파일) 밖으로 나가지 않고, 외부 자원을 부르지 못하게 검사한 결과만 적용한다"

## 4. 저장·동기화

### 4.1 자료 모양

```ts
export type UserCssSnippet = {
  id: string        // 소문자 16진 16자, 만들 때 한 번 정한다
  name: string      // 1~60자
  css: string       // 사용자가 쓴 원문 그대로 (컴파일 결과가 아니다)
  enabled: boolean
  updatedAt: number // ms
}
```

- 목록 순서가 적용 순서다(2.1). 새 스니펫은 끝에 붙는다
- 서버·로컬 모두 **원문**을 저장한다. 컴파일 결과는 기기마다 만든다(검사기 버전이 기기마다 다를 수 있다)

### 4.2 로컬 저장 — localStorage 키 셋

IndexedDB 가 아니라 localStorage 인 이유: 부팅 스크립트가 첫 칠 전에 **동기로** 읽어야 한다(2.3). IndexedDB 는 비동기라 첫 칠에 못 댄다.

| 키 | 값 (JSON) | 쓰는 곳 |
| --- | --- | --- |
| `md.userCss` | `{ "snippets": UserCssSnippet[] }` — **로그아웃 상태의 스니펫** | 앱(`prefs.ts` 경유) |
| `md.userCssAccount` | `{ "userId", "rev", "snippets", "pending": { "upserts": string[], "deletes": string[] }, "mergedLocal": boolean, "fetchedAt": number }` — 계정 스니펫의 캐시와 아직 못 보낸 변경 | 앱 |
| `md.userCssBoot` | `{ "v": 검사기버전, "local": string[], "account": { "userId", "sheets": string[] } \| null }` — 켠 스니펫의 **컴파일 결과**를 목록 순서로 | 앱이 쓰고 **부팅 스크립트도 읽는다** |

- `md.account`(이미 있음)는 부팅 스크립트가 슬롯을 고르는 데 새로 읽는다 (2.3)
- 쓸 때마다 `md.userCssBoot` 도 같은 틱에 고친다. 원문과 컴파일 결과가 어긋나는 창을 두지 않는다

### 4.3 서버 — D1 표 하나, 계정당 한 줄

금고 키 묶음(`e2ee_keys`, F-401)과 같은 모양으로 한다 — 계정당 한 줄, 서버는 모양·크기만 보고, `rev` 조건부 쓰기로 충돌을 가린다.

```sql
CREATE TABLE user_css (
  user_id TEXT PRIMARY KEY REFERENCES users(id),
  snippets TEXT NOT NULL,     -- UserCssSnippet[] JSON
  rev INTEGER NOT NULL,       -- 1 부터, 쓸 때마다 +1
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

| 요청 | 응답 |
| --- | --- |
| `GET /api/user-css` (`If-None-Match` 선택) | 200 `{ snippets, rev }` + `ETag: "{rev}"`. 행이 없으면 200 `{ snippets: [], rev: 0 }`. `If-None-Match` 가 같으면 304 |
| `PUT /api/user-css` `{ snippets, baseRev }` | 200 `{ rev }` / 409 `{ error: 'conflict', rev }` / 413 `{ error: 'too_large', limit: 262144 }` / 400 `{ error: 'invalid', field }` |

- 마이그레이션 `migrations/0017_user_css.sql`. **원격 D1 마이그레이션은 이 표를 읽는 클라이언트 코드(F-2099)보다 먼저 배포한다** (CLAUDE.md 배포 규칙)
- 행 하나 방식(스니펫마다 행이 아니라)을 고른 이유: 전체가 256KiB 로 작고, 순서가 뜻을 가지며(2.1), 선례(`e2ee_keys`)가 이미 같은 모양이라 핸들러·테스트를 거의 그대로 따른다. 대가는 두 기기가 동시에 다른 스니펫을 고치면 409 가 나는 것 — 4.4 의 다시 얹기로 푼다

### 4.4 동기화 규칙 (로그인 상태)

- **받기:** 부팅 뒤 계정이 확인되고 온라인이면 한 번, 탭이 다시 보일 때(`visibilitychange`) 마지막 받기(`fetchedAt`)가 10분 넘었으면 한 번, 로그인 직후 병합(4.5) 때. `If-None-Match` 로 바뀌지 않았으면 304
- **보내기:** 스니펫을 고치면 로컬(계정 슬롯)에 바로 쓰고 `pending` 에 id 를 적는다. 마지막 변경 2초 뒤, D-16 을 닫을 때, `online` 이벤트 때 `PUT`. 성공하면 `pending` 을 비우고 `rev` 를 갱신
- **409 충돌:** 서버 최신을 `GET` 해 그 위에 `pending` 을 다시 얹는다 — `upserts` 의 id 는 로컬 스니펫으로 바꾸거나(없으면 끝에 붙이고), `deletes` 의 id 는 뺀다. 그 결과를 새 `rev` 로 다시 `PUT`. 세 번 연달아 409 면 멈추고 탭에 오류 줄(5.8). 다시 얹기는 순수 함수로 두고 단위 테스트로 판정한다
- 결과적으로 **스니펫 단위 "이 기기가 건드린 것이 이긴다"** 다. 두 기기가 같은 스니펫을 동시에 고치면 나중에 보낸 쪽이 남는다. 되돌리기 수단은 두지 않는다
- 받은 스니펫은 컴파일한 뒤 적용한다(2.1). 조합 중이면 미룬다(2.5)

### 4.5 로그인·로그아웃·계정 바뀜

- **처음 로그인(이 브라우저에서 그 계정으로 `mergedLocal` 이 아직 거짓):** 서버 목록을 받고, 로컬 슬롯의 스니펫 중 **이름과 원문이 둘 다 같은 것이 서버에 없는 것**을 끝에 붙인다. 붙이는 스니펫의 id 는 새로 만들고, 서버에 같은 이름이 이미 있으면 이름을 `{이름} (이 브라우저)` 로 바꾼다(60자를 넘으면 앞을 줄인다). 켜짐 상태는 그대로. `PUT` 성공 뒤 `mergedLocal = true`. 로컬 문서를 첫 로그인 때 전부 올리는 Q33 과 같은 방향이다
- 로컬 슬롯은 병합 뒤에도 **지우지 않는다** — 로그아웃하면 다시 쓴다
- **로그아웃:** 계정 슬롯을 지우지 않는다(원격 문서 캐시가 `userId` 로 남는 것과 같다). 로그아웃 뒤 다시 읽을 때 부팅 스크립트는 `md.account` 가 비었으므로 로컬 슬롯을 적용한다 (2.3)
- **다른 계정으로 로그인:** 계정 슬롯의 `userId` 가 다르면 통째로 버리고(아직 못 보낸 `pending` 포함) 새로 받는다. 그 계정에 대해 처음이면 위 병합을 한다

### 4.6 금고(E2EE) 대상이 아니다

- 금고는 문서 본문·첨부를 암호화한다(F-400). 사용자 CSS 는 문서가 아니고, 서버는 크기 검사만 하면 된다. 평문으로 저장한다
- 안내 글에 "사용자 CSS 는 금고에 들어가지 않는다 — 비밀을 적지 말라" 를 한 줄 적는다

### 4.7 계정 삭제

- `worker/account.ts` 의 삭제 batch 에 `DELETE FROM user_css WHERE user_id = ?1` 을 `users` 행보다 먼저 더한다 (`REFERENCES users(id)`). D-15 요약 문구는 바꾸지 않는다

### 4.8 고르지 않은 대안 — 스니펫을 문서로

"최상위 `CSS` 폴더의 문서 = 스니펫"(새 문서 템플릿 F-2037 의 `템플릿` 폴더 방식)은 동기화·오프라인·CLI 를 공짜로 얻지만 고르지 않았다:
- 마크다운 편집기가 CSS 를 마크다운으로 읽는다 — `#id {` 줄이 제목이 되고 `*` 가 목록이 된다. 코드블록으로 감싸게 하면 추출 규칙이 또 생긴다
- 문서라서 사이드바·검색·지도·공유·폴더 초대에 섞인다. 폴더를 초대하면 CSS 문서가 남에게 가 사용자 결정 3 과 부딪친다
- 켜짐 상태를 둘 곳이 문서 밖에 또 필요하다
- 부팅 스크립트가 IndexedDB 를 동기로 읽을 수 없어 첫 칠 적용(2.3)이 안 된다

## 5. 화면·내보내기·인쇄·안내

### 5.1 설정 대화상자 `사용자 CSS` 탭

- 탭 순서: `화면` · `편집기` · **`사용자 CSS`** · `데이터` · `금고` · `계정`. `SettingsTabId` 에 `'css'` 를 더하고 `SettingsTabAvailability.css` 는 **선택**(`e2ee` 와 같이) — 빠지면 거짓. 로컬 앱·로그인 앱에서 준다. 공개 보기(S-5)는 주지 않는다
- 위에서 아래로:
  1. 안전 모드일 때만: `안전 모드 — 이 창에서는 사용자 CSS 를 적용하지 않습니다.`
  2. 설명: `직접 쓴 CSS 로 앱 모양을 바꿉니다. 켠 스니펫은 HTML 내보내기와 인쇄에도 들어갑니다.` + 링크 `사용자 CSS 사용법`(`/guides/custom-css`, 새 탭)
  3. 저장 위치 한 줄: 로그아웃 `이 브라우저에만 저장됩니다. 로그인하면 계정에 저장해 다른 기기에서도 씁니다.` / 로그인 `계정에 저장해 로그인한 기기 모두에 적용합니다.`
  4. 스니펫 목록 — 한 줄에 켜기 체크박스(`input type=checkbox`, 접근성 이름 = 스니펫 이름) · 이름 · `편집` 버튼 · `삭제` 버튼. 비었으면 `스니펫이 없습니다.`
  5. 버튼 `새 스니펫` · `템플릿으로 시작`
  6. 동기화 오류가 있을 때만 오류 줄 (5.8)
- 켜기·끄기는 누르는 즉시 적용·저장(F-290 "저장 버튼 없음" 규칙)
- `새 스니펫`: 이름 `스니펫 {n}`(쓰이지 않은 가장 작은 양의 정수), 원문 빈 문자열, 켜짐, 목록 끝 → 바로 D-16 을 연다
- `삭제`: D-1 과 같은 확인 대화상자 `"{이름}" 스니펫을 삭제할까요? 되돌릴 수 없습니다.` / `삭제` `취소`, 기본 포커스 `취소`
- 탭 키보드는 F-290 규칙 그대로(방향키 순환 등)

### 5.2 D-16 `CSS 편집` 대화상자

- 설정 대화상자 **위에** 연다(D-15 가 설정 위에 뜨는 선례). 크기 `xwide`(720px)
- 항목: `이름` 입력(최대 60자) · `CSS` 여러 줄 입력(`textarea`, `--font-mono`, `spellcheck=false`, `autocapitalize=off`) · 상태 줄 · `닫기`
- **적용:** 입력이 멈추고 400ms 뒤 컴파일·적용(켜진 스니펫일 때). 로컬 저장도 그때. 서버는 4.4
- **상태 줄:** 켜짐이면 `규칙 {n}개 적용 중`(컴파일 결과의 최상위 규칙 수), 꺼짐이면 `꺼져 있어 적용하지 않습니다`. 3.1 에서 뺀 것이 있으면 한 줄 더: `외부 파일을 부르는 부분 {n}곳을 빼고 적용했습니다.`
- CSS 문법 오류는 알리지 않는다 — 브라우저 파서가 오류 규칙을 조용히 버리므로 알 길이 없다. 규칙 수가 기대보다 적은 것으로 짐작하게 한다
- `Tab` 은 포커스를 옮긴다(들여쓰기를 넣지 않는다). 편집기 수준 입력은 9장 Q1
- 닫으면 포커스는 그 스니펫 줄의 `편집` 버튼으로 돌아간다(새 스니펫이면 그 줄)
- 모달이라 뒤 화면이 흐리지만 변경은 바로 적용되므로 대화상자 주변·닫은 뒤 모습으로 확인한다. 비모달 옆 패널은 9장 Q2

### 5.3 템플릿 CSS — "어떤 클래스를 수정해야 할지 다 알려 줘야" 에 대한 답

사용자 말의 "템플릿css" 를 **공개 변수·훅을 전부 주석과 함께 늘어놓은 시작용 스니펫**으로 읽었다 (F-2037 의 새 문서 템플릿과 무관).

- `템플릿으로 시작` 버튼이 스니펫 하나를 만든다: 이름 `템플릿`(있으면 `템플릿 2`…), **켜짐**, 원문 = 템플릿 CSS. 모든 선언이 주석이라 켜 둬도 아무것도 바뀌지 않고, 주석을 푸는 순간 적용된다
- 템플릿 CSS 는 `userCssContract.ts` 의 순수 함수 `buildTemplateCss(tokensCss: string): string` 이 만든다. `tokensCss` 인자로 `tokens.css` 원문을 받아 **지금 기본값을 주석에 채운다** — 소스에 hex 를 쓰지 않고(3.6), 계약과 템플릿이 따로 놀지 않는다. (vitest 는 `?raw` 를 빈 문자열로 읽으므로 인자로 받는다 — `exportHtmlCss.test.ts` 머리 주석의 실측)
- 모양(순서 고정):
  1. 머리 주석: 안내 글 주소, 권장 선택자 규칙 세 줄(1.3), "약속 밖 클래스는 업데이트로 바뀔 수 있다", 안전 모드 `/?safe`
  2. `:root:root { … }` — 공개 변수 51개를 묶음별로, 한 줄에 `/* --paper: {기본값}; */ /* {label} */`
  3. `:root[data-theme='dark'] { … }` — 다크에서 값이 다른 공개 변수만, 같은 모양
  4. 뼈대 훅 17개 — `/* :root [data-ui="sidebar"] { } */ /* {label} */`
  5. 본문 훅 11개 — 편집·보기 권장 선택자 한 쌍씩
- 크기: 약 6KB 로 예상한다(재지 않았다. 상한 256KiB 에 비해 작다는 판단만 한다)
- 단위 테스트: 결과에 공개 변수 51개·훅 28개 이름이 전부 들어 있다, hex 가 `tokensCss` 에서 온 것뿐이다(빈 `tokensCss` 를 주면 hex 가 0개)

### 5.4 HTML 내보내기

- 내보낸 `.html` 의 `<style>` 에 `EXPORT_CSS`(+수식이면 `MATH_EXPORT_CSS`) **뒤에** 켠 스니펫의 컴파일 결과를 목록 순서대로 잇는다. `escapeStyleClose` 를 그대로 거친다. 스니펫마다 `/* {이름} */` 한 줄을 앞에 둔다
- 무엇이 들어가나: **지금 적용 중인 것 전부** — 켠 스니펫 전부, 안전 모드면 0개. 내보낼 때 고르는 UI 는 두지 않는다 (9장 Q3)
- 내보낸 파일은 `<html>` 에 `data-theme` 가 없고 `<body class="public-view">` 다. 그래서 `:root:root` 와 `.markdown-body` 권장 선택자는 먹고, 테마별(`[data-theme='dark']`)·뼈대 훅 규칙은 안 먹는다. 안내 글에 적는다
- 컴파일 결과를 쓰므로 외부 `url()` 이 파일에 들어가지 않는다 — F-280 의 "인터넷 없이 열린다" 가 유지된다
- 조립은 순수 함수로(`toHtmlDoc.ts` 쪽 인자 추가) 단위 테스트한다. e2e 를 새로 두지 않는다

### 5.5 인쇄(PDF)

- 인쇄는 같은 페이지에서 `window.print()` 를 부르므로(F-279) adoptedStyleSheets 가 **따로 손대지 않아도 들어간다** (M5 에서 인쇄 매체 적용 확인)
- 인쇄 중 `printDoc` 이 `data-theme` 를 떼고 `data-printing="1"` 을 붙인다. 인쇄 전용 규칙은 `@media print { … }` 또는 `:root[data-printing] …`, 인쇄 영역은 `[data-ui="print"]` 로 쓴다. `@page` 도 허용 규칙이라(3.1) 여백·용지를 바꿀 수 있다 — `print.css` 의 `@page { size: A4; margin: 20mm }` 보다 뒤라 이긴다
- 코드 변경은 인쇄 영역에 `data-ui="print"` 를 붙이는 것뿐(F-2093). 인쇄 결과는 사람 확인

### 5.6 책임 경계

- 앱이 책임지는 것: 1장 계약이 지켜진다, 3.1 검사가 외부 요청을 막는다, `/?safe` 가 언제나 사용자 CSS 없이 연다, 스니펫을 다 끄면 사용자 CSS 가 없던 때와 같은 화면이다
- 사용자가 책임지는 것: 약속 밖 클래스를 쓴 규칙이 업데이트로 깨지는 것, 인쇄·HTML 레이아웃을 깨뜨리는 규칙(예: `[data-ui="print"]` 를 숨김), 설정과 겹치는 변수를 덮어 설정이 안 먹는 것(1.3), 접근성 대비를 낮추는 색
- 사용자 CSS 가 켜져 있을 때 들어온 버그 제보는 먼저 `/?safe` 로 재현되는지 본다 — 안내 글·도움말에 적는다

### 5.7 안내 글과 도움말

- **공개 안내 글** `content/guides/custom-css.md`(`/guides/custom-css`, 제목 `사용자 CSS 로 모양 바꾸기`). 담는 것: 스니펫 만들기·켜기, `템플릿으로 시작`, 권장 선택자 규칙(1.3), **공개 변수 51개 표**(이름·설명), **훅 28개 표**(선택자·설명), 테마별 쓰기, 인쇄·HTML 에서 먹는 것과 안 먹는 것(5.4·5.5), 외부 파일 차단과 설치 글꼴 쓰기(3.1), 안전 모드(3.3), 약속 밖 클래스 경고(1.1), 금고 아님(4.6), 상한(3.4)

### Q2. D-16 을 모달로 둘 것인가 — **기본값: 모달 (`Dialog.tsx`, 설정 위)**

모달은 포커스 가두기·복귀 규칙이 이미 있다. 대신 뒤 화면이 흐려 바뀐 모습을 닫고 봐야 한다. 비모달 옆 패널(화면 오른쪽 고정, 뒤 화면을 그대로 둠)을 고르면 새 레이아웃 자리·포커스 규칙·휴대폰 폭 처리를 새로 정해야 하고 F-2096 이 두 배쯤 커진다

### Q3. HTML 내보내기에 넣을 스니펫을 고르게 할 것인가 — **기본값: 고르지 않는다, 적용 중인 것 전부**

사용자 결정 3 을 가장 단순하게 따른다. 스니펫마다 `내보내기에 넣기` 표시를 두면 목록 줄에 칸이 하나 늘고 `UserCssSnippet` 에 필드가 하나 는다(서버 모양도 바뀐다) — 나중에 더하면 이전 자료는 "넣기" 로 읽으면 된다

### Q4. 공개 보기(S-5)를 내 브라우저에서 열 때 내 CSS 를 적용할 것인가 — **기본값: 적용하지 않는다**

### Q5. 지도가 못 읽는 색 형식을 바꿔 읽을 것인가 — **기본값: 바꾼다 (F-2098)**

`oklch()` 등은 요즘 CSS 에서 흔하고, 그대로 두면 지도만 기본색으로 칠해져 버그로 보인다 (M8). 1×1 2D 캔버스에 칠해 픽셀을 읽는 변환은 `MapScene.tsx` 안에 갇힌다. 바꾸지 않는 쪽을 고르면 안내 글에 "지도 색은 hex·`rgb()`·`hsl()`·색 이름·`color-mix(in srgb …)` 로 쓰라" 를 적고 F-2098 이 관찰 속성만 더한다

### Q6. 사용자 CSS 를 끄는 단축키를 둘 것인가 — **기본값: 두지 않는다**

CSS 가 화면을 가려도 단축키는 먹지만, 끄는 상태를 어디 저장할지(이번 창만? 영구?)와 겹치지 않는 조합 찾기가 필요하다. `/?safe` 가 같은 일을 한다. 두는 쪽을 고르면 ia.md 5장 키보드 표 한 줄과 F-2052 단축키 판 항목이 늘고, 단축키 카탈로그 개수 테스트를 고쳐야 한다

### Q7. 안내 글의 변수·훅 표를 빌드 때 생성할 것인가 — **기본값: 손으로 쓰고 테스트로 대조**

`content/guides/*.md` 는 지금 모두 손으로 쓴 원본이고 `site/` 빌드가 자리 표시(`{{…}}`)를 금지한다(`site/guard.ts` `PLACEHOLDER_RE`). 생성하는 쪽을 고르면 사이트 빌드에 새 삽입 단계가 생기고 F-270 계열 명세를 고쳐야 한다. 대조 테스트만으로 빠짐은 잡힌다

### Q8. 스니펫 순서를 바꾸는 UI 를 둘 것인가 — **기본값: 두지 않는다, 만든 순서**

순서가 캐스케이드를 가르므로(2.1) 필요해질 수 있다. 두면 목록 줄에 `위로`·`아래로` 두 버튼과 키보드 규칙이 는다. 자료 모양은 이미 배열이라 서버는 안 바뀐다

### Q9. 뼈대 훅 17개를 줄일 것인가 — **기본값: 17개 그대로**

사용자는 "스무여 개" 라고 했고, 본문 11개를 합치면 28개다. `menu`·`notice`·`home` 을 빼면 25개가 된다. 빼는 것은 F-2093 표에서 줄을 지우는 것뿐이고, 나중에 더하는 것은 계약 추가(1.1, 명세 안 한 줄)라 싸다

### 기본값으로 정한 것 (승인 시 확정)

1. 뼈대 훅은 **새 `data-ui` 속성**, 본문 훅은 **지금 클래스 + 권장 선택자**. 앱은 `data-ui` 를 선택자로 쓰지 않는다 — 1.4·1.5
2. 공개 변수 **51개**, 새 변수 없음. 비공개 27개 — 1.2
3. 권장 선택자 `:root:root`(공통)·`:root[data-theme='…']`(테마별) — 1.3
4. 계약은 `userCssContract.ts` 한 파일 + 단위 테스트 U1~U5 — 1.6
5. **`adoptedStyleSheets` 맨 뒤, 스니펫마다 시트 하나, `@layer` 없음** — 2.1·2.2
6. **부팅 스크립트가 컴파일 결과를 첫 칠 전에 적용**, 검사기 버전이 다르면 건너뜀 — 2.3
7. 공개 보기 S-5 와 서식 있는 복사에는 적용하지 않음 — 2.4
8. **외부 요청은 CSSOM 정규화 뒤 판정으로 막는다** (정규식 아님). 사용자 정의 속성은 `url(`·`image-set(`·`src(`·`\` 가 있으면 뺀다 — 3.1
9. CSP 는 도입하지 않음 — 3.2
10. **안전 모드는 `/?safe`** — 3.3
11. 상한 50개·256KiB·이름 60자 — 3.4
12. 로컬은 localStorage 키 셋, 서버는 `user_css` 표 **계정당 한 줄 + `rev`** — 4.2·4.3
13. 동기화는 스니펫 단위 "이 기기가 건드린 것이 이긴다", 409 는 다시 얹기 세 번 — 4.4
14. 첫 로그인 때 로컬 스니펫을 계정에 붙이고, 로컬 슬롯은 지우지 않음 — 4.5
15. 금고 대상 아님 — 4.6
16. HTML 내보내기는 적용 중인 스니펫 전부, 인쇄는 저절로 — 5.4·5.5
17. 템플릿 CSS 는 계약 모듈에서 생성, 기본값은 실행 시 `tokens.css` 원문에서 — 5.3
