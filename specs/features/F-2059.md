## 3. 공통 규칙 (자식 명세는 이 절 번호를 인용한다)

모든 조각은 3.1~3.8 을 지킨다. 자식 명세의 "함정 표" 는 3.1~3.5 각각에 대해 "그 조각에 해당하는 이름과 처리" 를 한 줄씩 적는다. 해당 없으면 `해당 없음` 과 그 이유를 적는다.

### 3.1 함수 끌어올림

지금 `App()` 안 함수 선언 130개는 끌어올려져서, 아래에 정의된 함수를 위에서 부른다. 예: `changeViewMode` 는 공개 보기 조기 반환 바로 위에 정의되지만 훨씬 위의 `useDocComments({ … })` 인자로 넘어가고, `closePalette`·`openPaletteFrom` 은 우클릭 메뉴 절보다 위에, `runE2eeReset`·`handlePrintDoc`·`openSearch`·`saveCurrentAsNewDoc` 는 그보다 위의 최신값 effect 에서 읽힌다.

훅이 돌려주는 값은 `const` 라 끌어올려지지 않는다. 규칙:

- **렌더 중에 평가되는 참조**(다른 훅의 인자, deps 배열, `useMemo` 본문, 렌더 중 조정 블록, 조기 반환 위의 계산)가 훅 반환값을 가리키면, 그 참조는 훅 호출보다 **아래**에 있어야 한다. 위에 있으면 첫 렌더에서 TDZ 로 죽는다
- **이벤트 핸들러·effect 본문 안의 참조**는 실행이 렌더 뒤라 위에 있어도 된다 (지금도 `openPaletteFrom` 이 이렇게 `setContextMenu` 를 부른다)
- 둘 다 안 되면(훅 호출을 올리면 훅 인자가 아직 정의 전) **ref 로 우회**한다 — `openWikiLinkRef`·`commitTitleRef` 와 같은 "ref + 인자 없는 effect 대입" 모양
- 거꾸로, **훅이 받는 인자**가 App 의 `const`(예: `useCallback` 결과)이면 그 선언이 훅 호출보다 위에 있어야 한다. `function` 선언은 끌어올려지므로 어디 있어도 된다
- 자식 명세는 옮기는 이름마다 "App 안 참조 위치가 렌더 중인가 / 핸들러 안인가" 를 표로 적는다. `grep -n "\b이름\b" src/app/App.tsx` 로 전부 찾는다

### 3.2 최신값 effect 와 ref 대입

인자 없는 `useEffect` 는 매 커밋 선언 순서대로 돈다. 훅 안 effect 는 **훅을 부른 자리**에서 돈다. 지금 App 의 인자 없는 최신값 effect 6개:

| # | 대입하는 ref | 읽는 곳 |
| --- | --- | --- |
| ① | `commentsRef` | 우클릭 메뉴·`Ctrl+Alt+M`·해시 이동 |
| ② | `docSaverFlushRef`·`notifyChangeRef`·`notifyCommentsChangeRef`·`openDocIdRef`·`openDocLineEndingRef`·`e2eeResetStepRef`·`printDocRef`·`printDisabledRef`·`openSearchRef`·`openPaletteRef`·`toggleShortcutsRef`·`toggleCommentsRef`·`bootPhaseRef` | 단축키·저장·금고 잠그기·인쇄 |
| ③ | `docsRef`·`currentDocIdRef`·`docPathRef`·`liveSessionRef`·`liveEverSyncedRef`·`liveTitleDocIdRef`·`saveCurrentAsNewDocRef`·`foldersRef`·`sharedDocRef`·`sharesOpenRef`·`helpOpenRef`·`mapRouteRef`·`dropBlockedRef`·`imageDropBlockedRef`·`readOnlyDocRef`·`narrowRef`·`sidebarOpenRef`·`sidebarCollapsedRef` | `hashchange`·가져오기·금고·끌어놓기 |
| ④ | `runImportFilesRef`·`openOrImportLaunchedFilesRef`·`previewImportFolderRef` | OS 파일 열기·폴더 끌어놓기 |
| ⑤ | `openWikiLinkRef` | 편집기·보기의 위키링크 (3.4) |
| ⑥ | `commitTitleRef` | 제목 위젯 (3.4) |

규칙:

- **읽는 방식을 보존한다.** 지금 클로저로 읽던 값은 훅 인자로(매 렌더 새로), ref 로 읽던 값은 ref 로. 클로저를 ref 로 바꾸거나 그 반대로 바꾸지 않는다 — 한 커밋 안 값이 보이는 시점이 달라진다
- ref 는 **선언·대입·읽기가 모두 한 조각 안에 들어올 때만** 그 훅으로 옮긴다. 하나라도 App 에 남으면 선언과 대입은 App 에 두고 훅에는 ref 객체를 인자로 넘긴다
- ref 를 훅으로 옮기면 그 대입 effect 는 훅 호출 자리에서 돈다. **같은 커밋 안에서 그 ref 를 읽는 App 의 effect 보다 먼저 돌아야 하면** 훅 호출을 그 effect 보다 위에 둔다. 자식 명세는 옮기는 ref 마다 "같은 커밋에 읽는 effect" 를 적고, 없으면 `없음(이벤트 때만 읽음)` 이라 적는다
- `useLayoutEffect` 는 모든 `useEffect` 보다 먼저 돈다. 대입을 layout 에서 passive 로(또는 반대로) 옮기지 않는다

- 훅으로 옮긴 블록도 **다른 블록과의 순서(a→h)를 유지**한다. 순서는 훅 호출 자리로 정해지므로, 자식 명세는 옮긴 뒤 a~h 의 순서를 다시 적어 같은지 보인다
- 조건과 setter 호출 순서를 한 글자도 바꾸지 않는다. ESLint `react-hooks/set-state-in-render` 가 새 파일에서도 0 이어야 한다

### 3.4 Editor 마운트 클로저

`Editor.tsx` 는 `useLayoutEffect(…, [])` 로 **마운트 때 한 번** `createEditor` 에 넘김값을 건넨다. 그 뒤 바뀐 함수는 편집기에 닿지 않는다. 마운트 때 잡히는 넘김값:

`onDocChange`(`handleDocChange`), `onSelectionChange`(`handleSelectionChange`), `onOpenWikiLink`(`handleOpenWikiLink`), `onImageFiles`(`handleImageFiles`), `resolveAttachment`, `onTitleChange`(`handleTitleChange`), `onTitleCommit`(`handleTitleCommit`), `wikiContext`, `live`(`liveEditorOption`), `text`·`viewMode`·`readOnly`·`title`·`titleReadOnly`·`docId`·`autoFocus`

규칙:

- 위 함수를 훅으로 옮기면 **안정성 모양을 그대로** 둔다. 지금 `useCallback(…, [])` 이고 안에서 ref 를 읽으면 옮긴 뒤에도 `useCallback(…, [])` + 같은 ref 를 읽는다. deps 배열을 바꾸지 않는다
- 새 핸들러를 편집기에 넘겨야 하면 "ref + 인자 없는 effect 대입 + `useCallback([])` 껍데기" 모양만 쓴다 (`openWikiLinkRef`·`commitTitleRef` 선례)
- 판정: 문서 A 를 연 채 앱 상태를 바꾼 뒤 그 핸들러를 부르는 동작이 최신 상태를 쓰는지 — 조각별 e2e 묶음에 이 모양의 테스트가 있으면 그것으로, 없으면 5.2 특성 테스트로

### 3.5 공개 보기 조기 반환

`if (publicRoute) return <PublicView …/>` 위에서 **모든 훅이 매 렌더 호출**된다. 그 아래에서 계산하는 `isEmpty`·`showEditor`·`commentAvailable`·`showToolbar`·`topBar` 등은 공개 보기 렌더에서 초기화되지 않는다.

- 새 훅 호출은 전부 조기 반환보다 위에 둔다. 조기 반환 아래 값을 훅 인자로 쓰지 않는다
- 인자 없는 최신값 effect 는 공개 보기 렌더에서도 돈다. 그 안에서 조기 반환 아래 `const` 를 읽으면 TDZ 로 죽는다 — 리뷰 A1 선례(`toggleCommentsRef` 대입이 `isEmpty` 대신 `currentDocId` 로 판정하는 이유). 옮긴 effect 도 같은 제약을 따른다
- 판정: `e2e/publicView.spec.js` 를 **모든 조각의 e2e 묶음에 넣는다** (6장). 공개 보기 렌더에서 죽으면 이 파일이 잡는다

### 3.6 옮기기만 했다는 판정

- **이동 확인:** 조각 커밋 뒤 main 이 `git show --color-moved=plain --color-moved-ws=allow-indentation-change <sha>` 로 본다. 옮긴 줄은 이동 색(옛 줄 굵은 자홍, 새 줄 굵은 청록)으로, 실제로 바뀐 줄은 빨강·초록으로 나온다 — 다른 파일로 옮기고 들여쓰기가 바뀐 경우도 잡는 것을 2026-09-28 git 2.52 로 확인했다. **빨강·초록 줄은 import, 훅 호출, 훅의 인자·반환 틀, `x` → `options.x` 같은 이름 연결, 3.1 의 ref 우회뿐이어야 한다.** 구현자는 보고에 빨강·초록 줄 수와 그 분류를 적는다
- UI 문자열·`className`·`data-*`·`aria-*`·설정 키(`md.*`)·`console.error` 태그는 바이트 그대로
- 옮긴 코드 안 주석은 그대로 가져간다. 옮기며 3줄 이상 주석 덩어리를 만나면(`CLAUDE.md` Code comments — 정리가 먼저 끝나므로 없을 것으로 본다) 그 자리에서 줄인다. 이 경우만 주석 변경을 허용한다
- 옮긴 이름을 가리키는 **다른 파일 주석의 `App.tsx` 언급**(예: `e2e/publicView.spec.js` 의 "App.tsx 의 hashchange 핸들러")은 그 조각이 새 파일 이름으로 고친다. `grep -rn "App.tsx" src e2e` 로 찾고, 옮긴 이름이 들어 있는 줄만 고친다

### 5.3 동결 운영

1. main 이 조각 구현자에게 "마무리" 를 보내 보고를 받는다
2. 조각이 수용 기준을 다 통과했으면 **조각을 먼저 커밋**하고, 긴급 수정은 옮긴 뒤 자리(새 파일)에 한다
3. 통과하지 못했으면 조각을 버린다 — 동결 덕에 소유 파일에 다른 작업이 없으므로 main 이 `git restore -- <그 조각 소유 파일>` 과 새 파일 삭제로 되돌린다. `git stash`·경로 없는 `git checkout` 은 쓰지 않는다(`CLAUDE.md`). 긴급 수정을 커밋한 뒤 **그 조각 명세를 새 코드 기준으로 다시 확인**(옮길 이름 목록·3.1~3.5 표)하고 다시 띄운다
4. 긴급 수정 커밋의 본문에 "F-2059 동결 중 긴급 수정" 을 적는다

**동결 시작 전 조건:** 단계 1 시작 전에 주석 일괄 정리 커밋과 팔레트 버그 수정 2건(잠긴 금고 문서 모드 명령 숨김, 팔레트 `삽입: 표` 칸 편집 진입)이 커밋돼 있어야 한다. 아니면 F-2060 을 띄우지 않는다.

### 5.5 명세·커밋 순서

- 자식 명세 하나 = 명세 커밋 하나, 구현 하나 = 구현 커밋 하나 (`CLAUDE.md` Commit granularity). 구현 커밋 제목은 `{구역} 을 {파일} 로 옮김 (F-20xx)`
- **조각은 전부 순서대로만 구현한다.** 모두 `App.tsx` 를 건드려 병렬이 없다
- 자식 명세는 옮길 이름 목록이 앞 조각에 따라 바뀌므로 **바로 앞 조각이 커밋된 뒤에 쓴다.** 단계 1 의 세 조각은 서로 다른 절만 옮겨 이름이 겹치지 않으므로 한꺼번에 써도 된다
- 자식 명세에 남는 결정이 없으면(`CLAUDE.md` Rules for main) 명세 커밋 뒤 바로 `ship-feature` 로 넘어간다
