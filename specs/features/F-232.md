# F-232 시작 화면 홈, 설정에서 마지막 문서 토글

작성일: 2026-09-15
상태: 사용자 승인(2026-09-15 "이대로 구현"). F-231 커밋 뒤 착수(둘 다 App.tsx 를 건드려 순서대로) (2026-09-15 사용자 "처음 열면 홈화면으로, 설정에서 마지막 문서로 토글 가능하게")
근거: `specs/features/F-111.md`(부팅·`resolveInitialDoc`), `specs/ia.md` 4.3(빈 상태 S-2), F-141(설정 대화상자)

## 1. 범위

### 문제
지금은 앱을 열 때마다(해시가 특정 문서를 안 가리키면) `md.lastDocId` 문서를 자동으로 연다. 사용자는 매번 마지막 문서로 바로 들어가지 말고 **홈 화면**에서 시작하고 싶어 함. 단, 마지막 문서 자동 열기를 원하는 사람도 있을 수 있어 설정에서 고를 수 있게 한다

### 한다
- 해시가 특정 대상을 안 가리킬 때(`#/`, 빈 해시) 기본은 **홈 화면** — 문서를 자동으로 열지 않는다
- 홈 화면은 기존 빈 상태(S-2, `EmptyState`)를 재사용한다. 문서가 0개면 지금 문구 `문서가 없습니다.` 그대로, 1개 이상이면 `문서를 선택하거나 새로 만드세요.`(사이드바 목록에서 고르거나 아래 버튼으로)
- 설정 대화상자에 새 항목 **"시작 화면"**: `홈`(기본) · `마지막 문서`. `마지막 문서` 를 고르면 지금까지의 동작(부팅 때 `md.lastDocId` 문서를 자동으로 연다) 그대로
- 사이드바 머리 줄의 로고+제품명(`SidebarHead` `brand-group`)을 누르면 지금 열려 있는 문서를 벗어나 홈으로(해시 `#/`). 좁은 창 상단바 쪽 로고도 같다
- 해시가 특정 문서(`#/d/{id}`)·공유받은 문서(`#/s/…`)·공개 링크(`#/p/…`)를 가리키면 설정과 무관하게 지금처럼 그 대상을 연다(변경 없음)

### 하지 않는다
- 홈 화면에 최근 문서 카드·검색 등 새 대시보드 UI — 이번엔 기존 빈 상태 재사용까지만
- 서버 저장소(F-207)·공유 화면(F-130)의 분기 로직 변경 — 해시가 있으면 그대로 그 흐름
- 새 탭/새 창을 여는 단축키·메뉴 추가 — 지금 있는 진입 방식(브라우저 탭)만 대상

## 3. 요구사항

### 3.1 부팅 분기 (`App.tsx`, F-111 3.1 대체)
- 해시가 `doc`(특정 문서)·`shared`·`public` 등 구체적 대상을 가리키면 지금 그대로(설정 무관)
- 해시가 없거나 `#/` 면:
  - `getPref('md.startScreen', 'home')` 이 `'last'` 면 지금처럼 `resolveInitialDoc({ hashDocId: null, lastDocId, docs })` 로 자동으로 연다
  - 아니면(기본 `'home'`) 문서를 자동으로 열지 않는다 — `currentDocId = null`, 해시 `#/` 로 둔다(교체하지 않아도 되면 그대로)
- 최초 실행 안내 문서 생성(F-111 3.1의 3번)은 그대로 — 문서 0개일 때 안내 문서를 만드는 것과 "자동으로 여는가" 는 별개. 안내 문서가 막 만들어졌어도 `startScreen` 이 홈이면 열지 않고 목록에만 보인다
- 문서 0개면 지금처럼 해시 `#/`(이미 홈과 같은 화면이라 추가 분기 없음)

### 3.2 홈 화면 표시 조건 (`App.tsx`, `EmptyState.tsx`)
- 지금 `isEmpty = docs.length === 0` 로 `EmptyState` 를 그리던 조건을 `currentDocId === null`(부팅 완료 후, 공유 화면이 아닐 때) 로 바꾼다
- `EmptyState` 에 `hasDocs={docs.length > 0}` 전달 → 문구만 분기, 버튼(`새 문서`·`가져오기`)은 그대로 — 문서가 있어도 새로 만들거나 가져올 수 있어야 하니 그대로 둔다
- 상단바 제목 입력·모드 전환·내보내기 등 "문서가 열려 있어야 하는" 조작은 지금 `isEmpty` 조건이 하던 대로 비활성(조건식만 이름 바꿈, 동작은 F-111 3.6·기존 로직 유지)

### 3.3 로고 → 홈 (`SidebarHead.tsx`, `App.tsx`)
- `brand-group` 을 `<button type="button">` 으로 바꾼다(지금 `<span>`). 좁은 창에서 사이드바가 접혀 있어도(`topbar` variant) 항상 보임(F-216 규칙과 같게 — 이미 `hidden={rail}` 인 `sidebar` variant 만 접힘에서 숨는다, 그대로 유지)
- 누르면: `beforeLeaveDoc()` 대기 → `setSharedDoc(null)`(공유 화면 보고 있었으면 벗어난다) → `currentDocId = null` → `replaceHashUrl(null)`(해시 `#/`)
- 이미 홈이면(문서 미선택) 눌러도 조용히 아무 일 없음(같은 상태로 다시 이동)
- 포커스·호버 모양은 다른 상단바 아이콘 버튼과 통일 — `--transition-fast` 색 전환(F-149 규칙 그대로), 별도 팝 모션 없음

### 3.4 설정 대화상자 (`SettingsDialog.tsx`)
- "글자 크기" 아래 새 Segment "시작 화면": `홈`(기본)·`마지막 문서`
- 고르면 즉시 `setPref('md.startScreen', value)` — 저장은 다음에 앱을 열 때부터 적용(지금 화면을 강제로 바꾸지 않는다)
- 공개 읽기전용 화면(F-230, `showEditorSettings` 와 같은 조건 분기 필요 없음 — 이 항목은 로그인/로컬 앱 전용, `PublicView` 는 애초에 이 설정 대화상자를 문서 하나만 보여주는 용도로 쓰고 목록·홈 개념이 없다) → **`PublicView` 쪽 `SettingsDialog` 호출에는 이 Segment 를 안 준다**(`startScreen` prop 자체를 옵셔널로 두고 없으면 항목을 안 그린다, F-230 의 `showEditorSettings` 패턴과 같음)

### 3.5 움직임 줄이기 · 접근성
- 새 애니메이션 없음(빈 상태 재사용, 로고는 색 전환만)
- 로고 버튼 `aria-label="{brand.name} 홈으로"`, 키보드 포커스·Enter 로 동작

## 5. 기존 e2e 영향

`openApp`(대부분의 e2e 가 쓰는 공용 부팅 헬퍼)은 지금 `page.goto('/')` 직후 에디터가 바로 보이는 것을 전제한다. 기본값이 홈으로 바뀌면 이 전제가 깨져 다른 기능을 검증하는 수백 개 테스트가 전부 실패한다. 이 명세 범위에서 다른 기능 e2e 는 손대지 않는다 — 대신 `openApp` 자체가 `page.addInitScript` 로 `md.startScreen='last'` 를 미리 넣어(F-141 A2 가 이미 쓰는 `setPrefBeforeLoad` 와 같은 방식) 지금처럼 문서가 자동으로 열리게 한다. 진짜 기본값(홈)을 확인하는 테스트만 새 `openAppHome` 을 쓴다(A2 등)
