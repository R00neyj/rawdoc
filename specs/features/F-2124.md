## 2. 색 변수

### 2.1 값 — 개요 2.1 표 그대로

`tokens.css` 첫 `:root` 의 `--md-highlight-bg` 선언 바로 뒤, `/* 서체 */` 앞에 둔다. 주석은 한 줄(코드 주석 규칙): `/* 코드 구문 색 — 콜아웃 색에 --ink 15% 를 섞어 코드 바탕 대비를 올린다 (F-2122 2장) */`

```css
--code-keyword: color-mix(in srgb, var(--callout-danger) 85%, var(--ink));
--code-string: color-mix(in srgb, var(--callout-note) 85%, var(--ink));
--code-comment: color-mix(in srgb, var(--ink-2) 50%, var(--muted));
--code-number: color-mix(in srgb, var(--callout-tip) 85%, var(--ink));
--code-function: color-mix(in srgb, var(--callout-example) 85%, var(--ink));
--code-type: color-mix(in srgb, var(--callout-warning) 85%, var(--ink));
--code-property: color-mix(in srgb, var(--callout-question) 85%, var(--ink));
--code-tag: color-mix(in srgb, var(--callout-success) 85%, var(--ink));
```

- 이름·순서·식이 계약이다. 이 순서가 `PUBLIC_VARS`·템플릿·안내 글 표의 순서다
- 테마 블록에 다시 적지 않는다(개요 2.1). 그래서 템플릿 CSS 의 다크 묶음에 코드 변수는 나오지 않는다 — U6 `다크 블록 선언 이름` 이 그대로 통과한다

### 2.2 대비 테스트 — `tokens.test.ts`

새 `describe('코드 구문 색 (F-2124)')` 하나. 기존 도우미(`extractBlock`·`THEMES`·`contrastRatio`)를 쓰고 아래 셋을 시험한다.

| # | 시험 | 판정 |
| --- | --- | --- |
| T1 | 8개 이름이 고정 사본 순서대로 첫 `:root` 에 있고, 값이 모두 `color-mix(in srgb, var(--a) N%, var(--b))` 꼴이며 `#` 이 없다 | 정규식 |
| T2 | 세피아·다크 블록(주석 지운 원문)에 `--code-` 선언이 없다 | 정규식 |
| T3 | 세 테마 × 8개 × 바탕 `--rule-2`·`--paper` 가 `contrastRatio` ≥ **4.5** | 48칸 |

- **식 풀기 규칙(T3):** `var(--x)` 는 그 테마 토큰에서 hex 가 나올 때까지 따라간다(`--callout-note` → `--link` 두 단계 — `resolveDeep` 와 같은 일). `color-mix(in srgb, A P%, B)` 는 채널마다 `round(A×P/100 + B×(1−P/100))`. 풀리지 않으면(`''`) 테스트가 실패해야 한다 — 조용히 건너뛰면 식을 바꾼 사람이 대비를 잃어도 녹색이 된다
- 문턱이 4.5 인 이유: 개요가 정한 것은 "AA 이상" 이고 4.76 은 현재 값이다. 4.76 을 문턱으로 박으면 콜아웃 색을 한 단계 고치는 tweak 마다 이 테스트가 먼저 빨개진다
- `--paper` 를 바탕에 넣는 이유: 원문 모드 펜스 줄(바탕 없음)과 D-16 편집기(`.user-css-editor` `background: var(--paper)`, 5장)가 이 바탕 위에 칠한다. `--panel` 은 코드 글자가 그 위에 직접 놓이는 곳이 없어 넣지 않는다

## 3. `src/styles/codeHighlight.css`

```css
.code-keyword { color: var(--code-keyword); }
.code-string { color: var(--code-string); }
.code-comment { color: var(--code-comment); }
.code-number { color: var(--code-number); }
.code-function { color: var(--code-function); }
.code-type { color: var(--code-type); }
.code-property { color: var(--code-property); }
.code-tag { color: var(--code-tag); }
```

- 클래스 이름 8개는 개요 1.3 표의 `클래스` 열 그대로다. F-2123 `CODE_TOKEN_KINDS`(`keyword` `string` `comment` `number` `function` `type` `property` `tag`)에 `code-` 를 붙인 것과 같다
- 파일 머리 주석 한 줄만 둔다: `/* 코드블록 구문 색 — 클래스는 F-2122 1.3, 색은 tokens.css --code-* */`. 그 밖의 선언(굵기·기울임·바탕)은 없다(개요 1.3 "색만")
- **`tests/src/styles/codeHighlight.test.ts`:** 파일을 `readFileSync` 로 읽어 주석을 지우고 규칙을 뽑는다. ① 규칙이 정확히 8개이고 선택자 집합이 고정 사본 `['keyword','string','comment','number','function','type','property','tag']` 의 `.code-{종류}` 와 같다 ② 각 규칙의 선언이 `color: var(--code-{같은 종류})` 하나뿐이다 ③ 쓴 `--code-*` 이름이 모두 `tokens.css` 첫 `:root` 에 있다 ④ `#` hex 0개. 고정 사본을 F-2123 모듈에서 import 하지 않는 것은 개요 6장대로 — 어느 쪽이 먼저 들어와도 빨개지지 않게
- `EXPORT_CSS` 에 이 파일이 들었는지는 vitest 가 `?raw` 를 빈 문자열로 바꿔(`exportHtmlCss.ts` `buildKatexFontFaceInline` 주석) 단위로 볼 수 없다. F-2126 의 E3(개요 A13 — 내려받은 파일에 `.code-keyword` 규칙)이 판정한다. 이 명세 구현자는 `npm run build` 뒤 `dist/assets/index-*.css` 에 `.code-keyword` 가 있는지 grep 한 결과를 보고에 적는다

## 4. 사용자 CSS 계약과 안내 글

### 4.1 `userCssContract.ts`

- `PublicVarGroup` 에 `'코드'` 를 `'본문'` 과 `'콜아웃'` 사이에 넣는다(아홉 값)
- `PUBLIC_VARS` 의 `--md-highlight-bg` 행 바로 뒤에 2.1 순서로 8행. 묶음 `'코드'`, 라벨은 개요 5.1 표 문자열 그대로(`코드 키워드 — if·return·import 등` … `코드 HTML·XML·JSX 태그 이름`). 공개 변수 51 → 59
- `CONTENT_HOOKS` 는 바꾸지 않는다 — `code-*` 클래스는 약속하지 않는다(사용자 결정, 개요 Q3)
- `buildTemplateCss` 는 바꾸지 않는다. 결과 템플릿에 `/* ── 코드 ── */` 묶음이 `본문` 뒤에 생기고, 기본값 줄은 `/* --code-keyword: color-mix(in srgb, var(--callout-danger) 85%, var(--ink)); */` 꼴이 된다

### 4.2 `content/guides/custom-css.md`

**① `## 약속된 변수` 표** — `| 본문 | … |` 행과 `| 콜아웃 | … |` 행 사이에 한 행:

```md
| 코드 | `--code-keyword` 키워드 · `--code-string` 문자열 · `--code-comment` 주석 · `--code-number` 숫자·값 · `--code-function` 함수 · `--code-type` 타입 · `--code-property` 속성 · `--code-tag` 태그 |
```

**② 같은 절 끝 글머리 목록** — 기존 두 줄(`--md-font-size`… / 지도 캔버스…) 뒤에 셋째 줄:

```md
- `코드` 묶음은 코드블록 안 구문 색이고, `CSS 편집` 창의 글자 색도 이 변수를 따릅니다. 구문 색을 끄려면 `:root:root`에서 여덟 변수를 모두 `currentColor`로 둡니다
```

- 개요 5.3 의 문장(`--code-* 를 currentColor 로`)을 쓰지 않는 이유: M2 — `--code-` 가 공개 변수가 아니라 `userCssGuide.test.ts` 가 실패한다. 와일드카드 대신 "여덟 변수" 로 쓴다. 테스트는 고치지 않는다
- 언어 목록은 이 글에 넣지 않는다 — 개요 5.3 대로 도움말 `## 마크다운 문법` 캡션(F-2126)이 목록의 자리다
- 프론트매터 `updated:` 를 구현한 날(`YYYY-MM-DD`)로. `summary` 는 그대로
- **이 두 곳은 사용자에게 공개되는 글 본문이다.** 구현 뒤 커밋 전에 메인이 `polish-korean` 스킬을 거친다. 윤문이 문장을 바꿔도 `--code-*` 이름 8개는 백틱으로 남아야 하고 와일드카드(`--code-*`)는 쓰면 안 된다(M2)
- **배포 순서:** 이 글은 "코드블록 안 구문 색" 을 말하지만 실제로 칠하는 것은 F-2125·F-2126 이다. 네 하위 명세가 다 들어오기 전에는 `deploy` 로 밀지 않는다(메인 몫)
