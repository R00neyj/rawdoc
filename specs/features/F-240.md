# F-240 코드블록 — 클릭 진입 회귀 수정, 언어 + 복사 버튼

작성일: 2026-09-18
상태: 사용자 승인 대기 (2026-09-18 사용자 "옵시디언 처럼 코드블럭 우측 상단에 언어 + 복사버튼 있어야함", "코드블럭 바로 포커스 안되서 수정불가능함", "읽기 전용 링크 공유 페이지에서는 복사버튼 있는데 그거 그대로 가져와도 될듯")
근거: `specs/features/F-106.md`(블록 위젯 2.3 클릭 진입·A4), `F-146.md` 3.1(여백 클릭 포커스 해제)·3.2(포커스 없으면 항상 위젯), `F-210.md` 2.5(공개 보기 코드 복사 버튼)

## 1. 범위

### 문제

**(가) 코드블록을 마우스로 클릭해도 편집에 들어가지 못한다 (F-106 A4 회귀).** 윗줄을 클릭한 뒤 방향키로 내려가야만 고칠 수 있다.

2026-09-18 실측으로 원인을 확정했다:

1. 코드블록 위젯 `wrap` 의 `mousedown`(`blocks.ts` `enterOnClick`)은 정상 동작한다 — `preventDefault()` 가 걸리고 `view.dispatch({selection})` 까지 간다
2. 그 dispatch 로 위젯이 원문으로 풀리면서, **클릭한 `<span class="md-codeblock-line">` 이 DOM 트리에서 떨어진다**(`isConnected === false`)
3. 같은 mousedown 이 계속 버블링해 `view.scrollDOM` 의 여백 클릭 가드(`createEditor.ts` `attachMarginClickGuard`, F-146 3.1)에 닿는다. 가드는 `event.target.closest('.cm-content, .cm-gutters')` 로 "여백인가" 를 판정하는데, 떨어진 노드에는 조상이 없어 `closest` 가 `null` 이다 → **여백 클릭으로 오판해 `blur()` 한다**
4. 포커스가 사라지면 F-146 3.2 규칙(`hasFocus === false` 면 겹침을 무시하고 항상 위젯)에 따라 코드블록이 **다시 위젯이 된다**. 커서는 비활성 위젯 DOM 안에 남아 이어지는 키 입력이 사라진다

실측 로그(브라우저): `bub:mousedown:dp=true` → `scroller-bub: connected=false closestContent=false active=(body)`

**(나) 편집 화면 코드블록에는 복사 버튼이 없다.** 공개 읽기 전용 화면(F-210 2.5)에는 이미 있다. 언어(정보 문자열)는 지금도 오른쪽 위에 글자로만 보인다.

### 한다
- 여백 클릭 가드가 **이벤트 경로**로 판정하게 고쳐 (가) 를 없앤다. 코드블록 어느 줄을 클릭하든 그 줄에 커서가 놓이고 바로 고칠 수 있다
- 편집 화면 코드블록 위젯 오른쪽 위에 **언어 + 복사 버튼**을 둔다. 언어는 지금처럼 정보 문자열의 **첫 단어만**, 복사 버튼은 F-210 의 것을 그대로 쓴다(같은 아이콘·같은 1.5초 체크 되돌림·같은 문구)
- 복사 버튼은 코드블록 **원문(펜스 줄 제외, 본문 줄만)** 을 클립보드에 넣는다
- 복사 버튼을 눌러도 **편집 진입은 일어나지 않는다**(버튼만 눌린다)
- 공개 보기(F-210)와 편집 화면이 같은 버튼 만들기 코드·같은 CSS 를 쓰도록 공용으로 뺀다

### 하지 않는다
- 구문 강조 (F-106 2.1 그대로 안 한다)
- 언어 바꾸기 UI, 언어 자동 감지 — 정보 문자열을 **표시만** 한다
- 표 위젯·이미지 위젯에 복사 버튼 추가
- 보기 모드(F-123 `Viewer`, `codeCopy` 옵션)의 현재 동작 변경 — 코드만 공용으로 옮기고 결과 DOM·CSS 는 같아야 한다
- 코드블록 줄 번호, 접기/펼치기

## 3. 요구사항

### 3.1 여백 클릭 가드 (`createEditor.ts`)

`attachMarginClickGuard` 는 지금 클릭 시점의 `event.target` 이 어디에 붙어 있는지로 여백을 판정한다. 핸들러가 도는 동안 DOM 이 바뀌면(위젯이 풀리면) 판정이 뒤집힌다.

- 판정을 `event.composedPath()` 로 바꾼다 — 경로는 이벤트가 **디스패치될 때 확정**되므로 그 뒤 DOM 이 바뀌어도 그대로다
- 경로 안에 `.cm-content` 또는 `.cm-gutters` 가 있으면 여백이 아니다 → 아무것도 하지 않는다
- 경로에 없으면 지금처럼 `preventDefault()` + `activeElement.blur()` (F-146 3.1 유지)
- `composedPath()` 는 `EventTarget[]` 이라 `Element` 가 아닌 항목(`document`·`window`)이 섞인다 — `instanceof Element` 로 거른 뒤 `matches`/`closest` 로 본다

### 3.2 코드블록 머리줄 (`blocks.ts`, `preview.css`)

- `md-codeblock-inner` 안 맨 위에 머리줄 `<div class="md-codeblock-head">` 을 둔다. 오른쪽 정렬, 언어 다음 복사 버튼 순
- 언어: 지금 `.md-codeblock-lang` 그대로(`--muted` 11px, `--font-sans`). **정보 문자열의 첫 단어만** 쓴다 — ` ```js title="a.js" ` 같은 경우 `js` 만. 정보 문자열이 비면 언어 칸을 만들지 않는다(버튼만)
- 복사 버튼: `createCodeCopyButton(() => 본문)`. 위치는 지금 `.code-copy-btn` 의 `position:absolute; top:8px; right:8px` 를 그대로 쓴다(머리줄은 자리만 비워 준다 — `pre` 의 `padding-top` 과 겹치지 않게)
- 버튼은 위젯의 클릭 진입과 충돌하면 안 된다: `btn.addEventListener('mousedown', (e) => e.stopPropagation())` 로 `enterOnClick` 에 닿지 않게 한다(`imageWidget.ts` 와 같은 방식). `click` 은 그대로 동작한다
- 언어 글자를 클릭한 경우는 지금처럼 편집 진입(= 코드블록 시작 위치)이다 — 버튼만 예외다
- `CodeWidget.eq` 의 `key` 에는 이미 `info`·`lines` 가 들어 있어 머리줄 재사용 판정은 그대로 맞다

### 3.3 복사 대상 (`blocks.ts`)

- 위젯이 들고 있는 `lines` 의 `text` 를 `\n` 으로 이어 붙인 문자열. **펜스 줄(```` ``` ````)과 정보 문자열은 넣지 않는다**
- 줄 끝 공백·빈 줄은 원문 그대로 둔다(원문 보존, 제품 불변조건)
- 문서의 줄 끝(CRLF/LF)과 무관하게 `\n` 으로 넣는다 — 클립보드 텍스트는 원문 파일이 아니다

### 3.4 공용 복사 버튼 (`src/lib/codeCopyButton.ts`)

- `Viewer.tsx` 의 `buildCopyButton` 을 그대로 옮긴다. 문구 `코드 복사`·`복사하지 못했습니다`, 성공 시 1.5초 체크 아이콘, `navigator.clipboard` 가 없을 때를 대비한 `try/catch` 전부 유지
- `Viewer` 는 이 함수를 쓰고 결과 DOM 이 지금과 같아야 한다(F-210 A6 가 그대로 통과)
- `src/editor/**` 가 `src/viewer/**` 를 import 하지 않는다(`specs/architecture.md` 1장) — 그래서 `src/lib/` 에 둔다

### 3.5 접근성
- 버튼 `aria-label="코드 복사"`, `title` 같음 (F-210 과 동일)
- 언어 글자는 읽어 줄 필요가 없다 — 지금처럼 `<span>` 글자 그대로 둔다(추가 ARIA 없음)
