## 2. 범위

### 한다

- 상태바 `?` 버튼, `Ctrl/Cmd+Shift+/`, 팔레트 `단축키 보기` — 세 진입점
- 메인 열 안, 편집 영역과 상태바 사이에 끼는 판
- 22개 항목 카탈로그(맥 21개), 묶음 6개
- 사용 감지와 브라우저별 기록
- 판에서만 맥 표기
- 카탈로그 ↔ 우클릭 메뉴·팔레트 키 문자열 일치 검사
- 도움말 한 줄

### 하지 않는다

- 단축키 바꾸기(재지정), 사용 기록 초기화, 서버 동기화
- 기존 툴팁·메뉴·팔레트 표기를 맥 기호로 바꾸기(결정 8)
- 기존 키 정의를 카탈로그에서 만들어 쓰도록 옮기기(결정 6·11). 카탈로그는 **표시와 감지만** 한다
- 판 열림 상태 저장(새로고침하면 닫힌다)
- 상태바가 없는 화면(S-2 빈 상태·S-4·S-5·S-6·S-7·S-8)의 판 (12장 Q1)
- `Ctrl+/`(HTML 주석 토글)의 처리 — 목록에 넣지 않고 바꾸지도 않는다 (12장 Q5, 14장 C1)

## 3. 카탈로그 — `src/app/shortcutCatalog.ts`

### 3.1 계약

```ts
export type ShortcutGroup = '서식' | '편집' | '찾기' | '이동' | '표' | '댓글'
export const SHORTCUT_GROUPS: readonly ShortcutGroup[] // 위 순서 그대로. 판의 묶음 순서다

// 감지 범위 (4.4). 여러 개면 하나라도 맞으면 된다
export type ShortcutScope = 'body' | 'cell' | 'editor' | 'comment' | 'app' | 'doc'

export type KeyChord = {
  mod?: boolean    // Ctrl(맥 ⌘). 감지에서는 ctrlKey || metaKey
  shift?: boolean
  alt?: boolean
  // 글자·기호 키는 KeyboardEvent.code('KeyB', 'Slash'), 이름 있는 키는 KeyboardEvent.key('Tab', 'Enter', 'Escape', 'F3', 'F10', 'ArrowUp', 'ArrowDown', 'ContextMenu')
  key: string
}

export type ShortcutEntry = {
  id: string                          // /^[a-z][a-z0-9]*\.[a-z][a-zA-Z0-9]*$/, 겹치지 않는다
  label: string                       // 판에 보이는 이름 (3.2 표의 문자열 그대로)
  group: ShortcutGroup
  keys: readonly KeyChord[]           // 판에 보이는 순서. keys[0] 이 대표 — 메뉴·팔레트 일치 검사가 이것과 비교한다
  macKeys?: readonly KeyChord[]       // 맥에서 다를 때만. 없으면 keys
  then?: KeyChord                     // 두 번째 키(순서 입력). 'nav.leaveEditor' 하나만 쓴다
  scopes: readonly ShortcutScope[]
  hideOnMac?: true                    // 맥에서는 판·N 에서 뺀다
}

export const SHORTCUT_CATALOG: readonly ShortcutEntry[]

export function isMacPlatform(platform: string | undefined | null): boolean
export function formatChord(chord: KeyChord, mac: boolean): string
export function formatEntryKeys(entry: ShortcutEntry, mac: boolean): string[] // 칸마다 한 문자열. then 이 있으면 '{첫 키} 다음 {둘째 키}' 한 문자열
export function visibleShortcuts(mac: boolean): ShortcutEntry[]               // hideOnMac 을 거른 목록, 카탈로그 순서
```

### 4.2 상태바 배치 규칙

- 지금 `.statusbar` 는 `justify-content: space-between` 이다. 자식이 둘(정보·저장 상태)이면 저장 상태가 오른쪽 끝에 가지만, **셋 이상이면 가운데 자식이 가운데로 뜬다** — 지금도 `금고 열림` 이 보이면 저장 상태가 가운데에 선다(14장 C2)
- 이 명세 뒤 규칙: **정보는 왼쪽, 나머지(저장 상태 · 폴백 표시 · `금고 열림` · `?`)는 이 순서로 오른쪽 끝에 붙어 선다.** 사이 간격은 지금 `.statusbar` 의 `gap`(12px). 방법은 구현이 정한다
- 터치 전용 기기(`@media (hover: none) and (pointer: coarse)`)에서는 `.statusbar-shortcuts` 를 `display: none`. **이 미디어 쿼리 조합은 지금 앱에 한 번도 쓰인 적이 없다** — 있는 것은 `(pointer: coarse)` 둘(`app.css` 목차 버튼·사이드바 토글)뿐이다. 새 규칙이다 (결정 10)

### 4.3 판이 보이는 화면

**판은 상태바에 매인다.** 상태바를 그리는 조건(`App.tsx` 의 `!sharedDoc && !mapRoute && showEditor`, `showEditor = bootPhase === 'ready' && currentDocId !== null`)이 참이고 판 열림 상태가 참일 때만 그린다

| --- | --- | --- |
| S-1 편집 화면(편집·원문·보기 모드 모두) | 있다 | 있다 |
| S-2 빈 상태·홈 | 없다 (`currentDocId === null`) | 없다 (12장 Q1) |
| S-3 부팅 중 | 없다 | 없다 |
| S-4 공유 링크 | 없다 (`!sharedDoc`) | 없다 |

### 4.4 감지 범위 — `scopesFor`

관찰자는 `keydown` 의 `e.target` 과 문서 상태 두 값으로 범위 집합을 만든다. 순수 함수로 두기 위해 DOM 대신 아래 모양을 받는다

```ts
export type TargetProbe = { matches(selector: string): boolean; closest(selector: string): unknown } | null
export type DocProbe = { dialogOpen: boolean; statusBar: boolean }
export function scopesFor(target: TargetProbe, doc: DocProbe): Set<ShortcutScope>
```

| 범위 | 참인 조건 | 근거 |
| --- | --- | --- |
| `body` | 대상이 `.cm-content` **그 요소 자체**이고 `.md-table-cell-editing` 안이 아니다 | CM6 는 `contentDOM` 에 포커스를 둬 keydown 대상이 `.cm-content` 다. 제목 칸(`textarea.doc-title`, `docTitle.ts`)은 본문 `.cm-content` **안의 위젯**이라 `closest` 로 판정하면 섞인다 — 그래서 "그 요소 자체" |
| `cell` | 대상이 `.cm-content` 이고 `.md-table-cell-editing` 안이다 | 칸 하위 편집기는 편집 중인 `td.md-table-cell-editing`(`tableWidget.ts` `startEdit`) 안에 자기 `.cm-editor` 를 둔다 |
| `editor` | `body` 이거나, 대상이 `.cm-panels` 안이고 `.md-table-cell-editing` 안이 아니다 | `searchKeymap`·`Mod-h` 의 scope `editor search-panel` 과 같다 |
| `comment` | 대상이 `.comment-composer-input, .comment-reply-input` | 두 `MentionField` 의 `className` |
| `app` | `dialogOpen` 이 거짓 | `Ctrl+P`·`Ctrl+Shift+F` 의 `document.querySelector('dialog[open]')` 규칙. 팔레트·검색이 **자기 대화상자 위에서** 다시 눌리는 경우(입력칸 전체 선택)는 기록하지 않는다 — 이미 한 번 연 것이라 잃는 것이 없다 |
| `doc` | `app` 이고 `statusBar` 가 참 | 4.3. `statusBar` 는 `document.querySelector('.statusbar') !== null` |

- 대상이 `Element` 가 아니면(`window`·`document`) `app`·`doc` 만 판정한다
- `dialogOpen`·`statusBar` 는 keydown 마다 `querySelector` 한 번씩이다. F-287 3.4 가 같은 질의를 keydown 마다 부르는 근거("DOM 질의 한 번은 keydown 당 비용이 없다")를 그대로 쓴다

### 4.5 키 맞추기 — `matchShortcut`

```ts
export type KeyEventLike = {
  key: string; code: string; ctrlKey: boolean; metaKey: boolean; shiftKey: boolean; altKey: boolean
  isComposing: boolean; keyCode: number; timeStamp: number
}
export type MatchState = { escapeAt: number | null }   // 'body' 에서 본 마지막 Escape 시각
export function matchShortcut(
  ev: KeyEventLike, scopes: ReadonlySet<ShortcutScope>, state: MatchState, mac: boolean,
): { id: string | null; state: MatchState }
```

규칙

1. `isComposing` 이 참이거나 `keyCode === 229` 면 **아무것도 기록하지 않고 상태도 바꾸지 않는다.** `tableWidget.ts` `cellKeydown` 과 같은 판정이다(`view.composing` 은 한 틱 늦다, F-161 3.2). 조합 중 키는 한글 입력의 일부이지 명령이 아니다. 미뤄 두는 재계산이 없으므로 `CLAUDE.md` IME 불변조건("조합 중 미룬 재계산은 끝날 때 따라잡는다")의 대상이 아니다
2. 수정키(`Control`·`Shift`·`Alt`·`Meta`) 자체의 keydown 은 건너뛴다(상태도 그대로)
3. 수정키는 **정확히** 맞아야 한다. `mod` 는 `ctrlKey || metaKey`, 나머지는 각 플래그. 코드에 없는 수정키가 더 눌리면 맞지 않는다(`Ctrl+Shift+Alt+B` 는 `format.bold` 가 아니다). 맥·윈도우 구분 없이 `Ctrl`·`⌘` 둘 다 받는다 — 앱 전역 리스너들(`Ctrl+P`·`Ctrl+Shift+F`·`Ctrl+Alt+M`)과 같다
4. 키 이름: `KeyChord.key` 가 `Key*`·`Slash` 모양이면 `ev.code` 와, 그 밖이면 `ev.key` 와 비교한다. `Shift` 를 누르면 `e.key` 가 `'?'`·`'B'` 로 바뀌기 때문이다 — **실측**: Chrome 에서 `Ctrl+Shift+/` 는 `key: '?'`, `code: 'Slash'` 로 온다(13.1 m1)
5. `Esc 다음 Tab`: `body` 에서 `Escape` 를 보면 `escapeAt = timeStamp`. 다음 키가 `body` 의 `Tab`/`Shift+Tab` 이고 `timeStamp - escapeAt <= 2000` 이면 `nav.leaveEditor` 이고 **`edit.indent` 가 아니다.** 그 밖의 키가 오면 `escapeAt = null`. 2000 은 CM6 `tabFocusMode = Date.now() + 2000` 과 같은 값이고, CM6 도 `Escape`·수정키가 아닌 키가 오면 이 모드를 끈다(`InputState.keydown`)
6. 맥에서 `hideOnMac` 항목은 맞추지 않는다. 맥에서는 `macKeys` 가 있으면 그것으로 맞춘다(`edit.redo` 는 맥에서 `⇧⌘Z` 만)
7. 한 keydown 은 **최대 한 항목.** 카탈로그 순서로 처음 맞은 것. 같은 키가 범위로 갈린다 — `Tab` 은 `body` 면 `edit.indent`, `cell` 이면 `table.nextCell`; `Esc` 는 `cell` 이면 `table.exit`
8. `e.repeat` 는 따로 보지 않는다(이미 기록된 id 는 아무 일도 없다)

### 4.6 관찰자 — `useShortcutUsage.ts`

| 항목 | 결정 |
| --- | --- |
| 리스너 | `window.addEventListener('keydown', …, { capture: true })` **하나.** `App` 이 `publicRoute` 가 아닐 때 부른다 |
| 왜 캡처인가 | 칸 하위 편집기(`cellKeydown` 의 `consume` → `stopPropagation`), 댓글 입력(`Escape` 에서 `stopPropagation`), CM6 바인딩의 `stopPropagation` 이 버블 단계 `window` 리스너에 닿기 전에 멈춘다. 캡처 단계의 `window` 는 어느 대상보다 먼저 받으므로 이것들에 막히지 않는다 |
| **절대 하지 않는 것** | `preventDefault`·`stopPropagation`·`stopImmediatePropagation` 을 부르지 않는다. 포커스를 옮기지 않는다. 예외를 밖으로 내지 않는다(판정 전체를 `try` 로 감싸 삼킨다 — 관찰 실패가 입력을 막으면 안 된다) |
| 기록 | 맞은 id 가 **아직 집합에 없을 때만** React 상태를 바꾸고 localStorage 에 쓴다. 쓰기 횟수는 브라우저 평생 최대 22번이다 |
| 쓰기 방식 | 쓸 때마다 `md.shortcutsUsed` 를 **다시 읽어** 합친 뒤 쓴다 — 다른 탭이 그 사이에 더한 id 를 지우지 않게 |
| 처음 읽기 | 훅이 처음 돌 때 한 번 `parseUsed(getPref('md.shortcutsUsed', ''))` |
| 다른 탭의 기록 | `storage` 이벤트를 듣지 않는다. 판을 다시 열 때 반영하지도 않는다 — 같은 탭에서 쓴 것만 즉시 보인다. 다음 새로고침에 합쳐진다 (12장 Q10) |
| 내보내는 값 | `used: ReadonlySet<string>` |

### 4.7 저장 — `md.shortcutsUsed`

| 항목 | 값 |
| --- | --- |
| 키 | `md.shortcutsUsed` (`md.` 접두사, 제품명 없음 — `CLAUDE.md` 불변조건) |
| 값 | 카탈로그 id 의 JSON 배열. **카탈로그 순서로 정렬**해 쓴다(같은 집합이면 같은 문자열) |

| 차단·시크릿 창 | `prefs.ts` 가 예외를 삼킨다. 그 탭 안에서는 메모리 집합으로 표시가 되고 새로고침하면 사라진다 |

- 파일 소유는 `prefs.ts` 의 `PrefMap` 에 `'md.shortcutsUsed': string`, `ALLOWED_KEYS` 에 같은 키 (결정 7)

| 포커스가 판 안일 때 `Esc` | 닫는다. `preventDefault` + `stopPropagation` — 좁은 창에서 겹쳐 열린 사이드바를 같은 `Esc` 로 함께 닫지 않는다(`Esc` 한 번 = 한 층, `ia.md` 5장 위키링크 미리보기 규칙과 같다) | `?` 버튼으로 |
| 포커스가 판 밖일 때 `Esc` | **판은 그대로.** 본문의 `Esc`(찾기 패널 닫기·`Esc 다음 Tab`·칸 나가기)를 뺏지 않는다 | — |
| 닫힐 때 포커스가 판 안에 있었는데 판이 사라지는 모든 경우(`Ctrl+Shift+/` 포함) | — | `?` 버튼으로. 사라진 요소에 포커스가 남아 `body` 로 떨어지지 않게 |

- 판 안 포커스 순서: `닫기` → 몸(스크롤 영역). DOM 순서가 편집 영역 → 판 → 상태바라서 편집기에서 `Esc 다음 Tab` 으로 나오면 판을 지나 `?` 에 닿는다

### 5.4 레이아웃

- 자리: `.main-column` 안, 편집기 `.content-area` **바로 뒤**, `<StatusBar>` **바로 앞.** `.content-area` 가 `flex: 1; min-height: 0` 이라 판이 끼면 편집 영역이 그만큼 줄어든다(덮지 않는다, 결정 3)
- 판 폭 = 메인 열 폭. 댓글 레일은 `.content-area` **안** 오른쪽 자식이라(`App.tsx` `CommentRailPanel`, `app.css` `.comment-rail`) 판이 열리면 레일도 판 높이만큼 짧아진다 — 레일은 오른쪽에 그대로다
- 높이: 내용 높이, **상한 기본값 `min(320px, 40vh)`**, 넘치면 `.shortcut-panel-body` 안에서 세로 스크롤. `flex: none`
  - 근거(추산, 실측 아님): 행 22 + 묶음 제목 6 = 28줄, 한 줄 약 24px. 메인 열 800px(3열)이면 10줄 ≈ 240px + 머리 줄 ≈ 276px 로 상한 안. 601px 창(2열)이면 14줄 ≈ 336px + 머리 줄 → 상한에 걸려 스크롤. 768px 높이 노트북 화면(뷰포트 약 650px)에서 40vh ≈ 260px 면 편집 영역이 650 − 52(상단바) − 26(상태바) − 260 ≈ 312px 남는다. 값은 사람 확인(10.3)
- 윗선: 1px `--rule`. 바탕 `--panel`(편집 영역과 같은 면), 그림자 없음 — `design.md` 4장 "그림자는 겹쳐 뜨는 것에만". 판은 겹치지 않는다
- 여닫힘 전환: `design.md` 4장 "나타나고 사라지는 … 도 전환으로" 를 따른다. 방법·시간은 구현이 정하고 `prefers-reduced-motion` 이면 전환 없음

| 창 폭 | 모습 |
| --- | --- |
| ≥1024px | 사이드바 오른쪽 메인 열 전체 폭. 레일이 열려 있으면 레일이 판 위에서 끝난다 |
| 601~1023px | 사이드바는 겹침이라 메인 열 = 창 폭. 댓글은 `.comment-sheet` 오른쪽 서랍(`@media (min-width: 601px)` 규칙, `position: absolute; top: 0; bottom: 0` of `.content-area`)이라 **판 위까지만** 내려온다 — 겹치지 않는다 |
| ≤600px (마우스 쓰는 좁은 데스크톱 창) | 같은 판, 대개 1~2열에 스크롤. `.comment-sheet` 아래 판(60dvh)은 `.content-area` 바닥 기준이라 역시 판 위에 선다 |
| 터치 전용 기기 | `?` 버튼이 없다. 팔레트 명령은 남는다(12장 Q3) |

### 5.5 열 때 커서 줄 보이기

- 판이 열려 편집 영역이 줄면 CM6 는 스스로 스크롤하지 않는다. 커서 줄이 새 바닥 아래로 숨을 수 있다(결정 3 이 거절한 "가려짐" 이 다른 모양으로 돌아온다)
- 규칙: **판을 열기 직전에 본문 커서(주 선택의 `head`)가 편집 영역에 보였으면, 판이 자리를 잡은 뒤에도 보이게 한다** — `EditorView.scrollIntoView(head, { y: 'nearest' })` 한 번. 사용자가 다른 곳으로 스크롤해 커서가 원래 안 보였으면 건드리지 않는다. 보기 모드(`viewMode === 'view'`)는 커서가 없어 건너뛴다
- 판을 닫을 때는 하지 않는다(편집 영역이 넓어져 가려질 일이 없다)

### 13.2 가정으로 남긴 것

- **G1** Windows Chrome·Windows OS 가 `Ctrl+Shift+/` 를 가로채지 않는다 — 합성 입력으로는 브라우저 가속기를 판정할 수 없다(H1)
- **G2** macOS 에서 `⇧⌘/` 가 도움말 메뉴 검색에 걸린다 — 널리 알려진 관례일 뿐 이 PC 에서 확인 못 함(H1, Q2)
- **G3** 맥 Chrome 에서 `Shift+F10` 이 `contextmenu` 를 만들지 않는다 → `hideOnMac`. 확인 못 함(H6)
- **G4** 맥에서 `⌘H`(바꾸기)가 페이지에 닿는다 — "Google Chrome 가리기" 메뉴 키와 같아 뺏길 수 있다. 확인 못 함(H6). 뺏기면 `find.replace` 에 `hideOnMac` 을 거는 것이 맞지만 **그 전에 기존 기능(F-261) 자체가 맥에서 안 되는 것**이라 별도 문제다
- **G5** 관찰자 비용이 무시할 만하다 — keydown 마다 `closest`·`matches` 몇 번 + 22항목 비교 + `querySelector` 두 번. 재지 않았다
- **G6** 판 높이 추산(5.4)의 한 줄 24px·열 폭 220px 는 추산이다. 렌더해 재지 않았다
- **G7** `Shift+F10` 을 누르면 Chrome 이 `keydown`(`key: 'F10'`)을 먼저 보낸다 — 윈도우 실기 미확인(H7)
