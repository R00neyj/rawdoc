| | 항목 수 | 크기(Workbox 표기) | gzip 추정 전송량 | 그중 woff2 |
| --- | --- | --- | --- | --- |
| 지금 | 106 | 13,546.50 KiB | 8,381,145B | 25개 5,843,204B |
| 변경안(3장) | **100** | **8,288.77 KiB** | **2,858,331B** | KaTeX 19개만 |

- 지금 구조에서는 첫 방문 뒤 서비스 워커가 설치되며 25개 woff2 를 전부 받는다. 운영 서버는 `/assets/*` 에 `Cache-Control: public, max-age=31536000, immutable` 을 준다(2026-09-26 `curl -I` 로 확인). 해시 붙은 precache 항목은 `revision: null` 이라 Workbox 가 `cache: 'default'` 로 받는다(`PrecacheController.js` `cacheMode`) — 페이지가 이미 받은 서체는 HTTP 캐시에서 나오고, **나머지(홈에서 안 쓴 Noto 700 한글 1MB 등)는 새로 받는다.** 즉 지금 첫 방문 서체 전송량은 결국 약 5.8MB 다
- 서체 CSS 가 커진다: `dist/assets/index-*.css` brotli 15,310B → 32,660B(+17,350B, woff 대체 줄 제거 후. 제거 전 34,570B). gzip 로는 17,410B → 81,431B. 운영은 CSS 를 `Content-Encoding: br` 로 준다(2026-09-26 `curl` 확인) — 그래서 실제 증가는 약 17KB 다. `@font-face` 가 6개 → 341개(Pretendard 92 + Noto 124×2 + D2Coding 1)로 늘어난 탓이다
- `@fontsource` CSS 는 각 조각에 `url(….woff) format('woff')` 대체를 함께 적는다. 그대로 두면 Vite 가 쓰지 않는 `.woff` 246개(약 8.6MB)를 `dist/assets/` 에 더 낸다(`dist` 38,374,240B → 대체 줄을 빼면 29,800,829B). 브라우저는 woff2 를 먼저 쓰므로 받지 않지만 배포 업로드·파일 수만 늘린다 — 3.2 에서 뺀다

**precache 에 조각을 넣으면 줄지 않는다 (계산, `unicode-range` 를 파싱해 파일 크기를 더했다)**

| 방식 | precache 서체 바이트 |
| --- | --- |
| 지금(통파일 4개 + 작은 것) | 5,843,204B |
| 조각을 전부 precache | Pretendard 2,957,724 + Noto 400 3,275,836 + Noto 700 3,400,608 + D2Coding 1,485,508 ≈ **11.1MB** — 지금보다 크다 |
| 자주 쓰는 한글(KS X 1001 완성형 2,350자) + ASCII 가 걸리는 조각만 precache | Pretendard 92개 중 **84개**(2,774,960B), Noto 400 124개 중 85개(2,106,388B), Noto 700 85개(2,201,624B) — Google 분할은 자주 쓰는 글자를 여러 조각에 흩어 두어 "일부만 미리" 가 거의 전부가 된다 |

## 3. 서체 불러오기

### 3.1 `src/main.tsx` — import 계약

지금의 5줄(`pretendardvariable.css`, `noto-serif-kr/korean-400.css`·`latin-400.css`·`korean-700.css`·`latin-700.css`)을 아래 3줄로 바꾼다. 순서는 지금처럼 `./styles/tokens.css` 앞이다.

```ts
import 'pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css'
import '@fontsource/noto-serif-kr/400.css'
import '@fontsource/noto-serif-kr/700.css'
```

- family 이름은 그대로 `Pretendard Variable`·`Noto Serif KR` 이라 `--font-sans`·`--font-serif` 토큰과 `specs/design.md` 2.4 는 바뀌지 않는다
- Pretendard README 가 안내하는 것은 CDN 주소지만, 그 주소의 경로(`dist/web/variable/pretendardvariable-dynamic-subset.css`)가 npm 패키지 안 경로와 같다. 같은 파일을 빌드에 넣어 자체 호스팅한다(D5). README 의 "가변 다이나믹 서브셋" 절이 family 이름을 `"Pretendard Variable"` 로 적는다
- `400.css`·`700.css` 에는 `cyrillic`·`vietnamese`·`latin-ext` 조각도 들어 있다. 그 글자가 화면에 없으면 받지 않으므로 그대로 둔다(빼면 CSS 가 조금 줄지만 그 글자가 나올 때 폴백이 된다)
- Noto 700 이 기본 제목 서체(D6 기본 세리프), 400 은 본문 세리프(D8)·빈 상태 문구용이다. 400 을 설정이 세리프일 때만 싣는 방식은 쓰지 않는다 — CSS 를 설정에 따라 나눠 싣는 장치가 새로 필요하고, 조각은 쓰지 않으면 어차피 받지 않는다

### 3.2 `@fontsource` woff 대체 줄 빼기 — 빌드 규칙

- `vite.config.ts` 에 Vite 플러그인 하나를 둔다. 이름 `strip-fontsource-woff`, `enforce: 'pre'`
- 규칙: 모듈 id 가 `@fontsource/noto-serif-kr/` 아래 `.css` 이면, `src` 안의 `url(….woff) format('woff')` 항목(앞의 쉼표 포함)을 지운다. woff2 항목은 그대로 둔다
- 결과: `dist/assets/` 에 `noto-serif-kr-*.woff` 가 0개. KaTeX 의 `.woff`·`.ttf`(지금도 있는 24+20개)는 이 명세 범위 밖이라 그대로 둔다
- 이유: 0.2 — 쓰지 않는 파일 246개·약 8.6MB 가 배포에 실린다. woff2 를 못 쓰는 브라우저는 이 앱의 대상이 아니다(React 19·CM6 가 이미 그보다 새 브라우저를 요구한다)
- 스크래치에서 이 규칙을 정규식 한 줄 `transform` 으로 돌려 `.woff` 가 사라지고 서체가 정상 적용되는 것을 확인했다(0.2·0.3 변경안 수치가 이 빌드다)

### 3.3 D2Coding

- `src/styles/tokens.css` 의 `@font-face` 는 바꾸지 않는다(Q2 기본값). precache 에서만 빠진다(4장)
- 결과: 첫 방문에 여전히 1,485,508B 를 받는다(0.1 — 홈 화면 `.sidebar h2` 부터 쓴다). 두 번째 방문부터는 `fonts` 캐시에서 나온다

## 4. 서비스 워커 — `vite.config.ts` `VitePWA({ workbox })`

### 4.1 계약

```ts
globPatterns: ['**/*.{js,css,html,png,svg,webmanifest}', 'assets/KaTeX_*.woff2'],
runtimeCaching: [
  {
    // 같은 출처 /assets/*.woff2 — precache 에 없는 서체 조각
    urlPattern: /* 같은 출처 && pathname 이 '/assets/' 로 시작 && '.woff2' 로 끝남 */,
    handler: 'CacheFirst',
    options: {
      cacheName: 'fonts',
      expiration: { maxEntries: 400 },
      cacheableResponse: { statuses: [200] },
    },
  },
],
```

- `cacheName: 'fonts'` — 제품명을 넣지 않는다(불변조건: 저장소 식별자). Workbox `expiration` 이 쓰는 IndexedDB 이름도 `workbox-expiration` 이라 제품명이 없다
- `maxEntries: 400` — 이 빌드가 낼 수 있는 서체 조각은 Pretendard 92 + Noto 248 + D2Coding 1 = 341개다. 한 사람이 전부 써도 넘지 않고, 배포가 바뀌어 옛 해시 파일이 쌓이면 오래된 것부터 지운다. `maxAgeSeconds` 는 두지 않는다 — 파일명에 해시가 있어 내용이 바뀌면 이름이 바뀐다
- precache 경로가 먼저 등록되므로(generateSW 기본) KaTeX woff2 는 precache 에서 나오고 이 규칙에 닿지 않는다
- `maximumFileSizeToCacheInBytes: 3 * 1024 * 1024` 값은 그대로 둔다. 주석만 바꾼다 — 지금 주석의 이유(PretendardVariable.woff2)가 사라지고, 가장 큰 precache 파일은 이제 `createEditor-*.js` 1,704,690B 다(2026-09-26 빌드). Workbox 기본 2MiB 로 되돌리면 이 청크가 조금만 커져도 precache 에서 **조용히 빠져** 오프라인이 깨진다
- `globPatterns` 위 주석 `서체(woff2)까지 precache 한다 (specs/features/F-116.md)` 는 `서체는 KaTeX 만 precache 하고 나머지는 쓸 때 받아 fonts 캐시에 둔다 (F-2040)` 로 바꾼다
- `registerType: 'prompt'`·`injectRegister: false`·`clientsClaim` 없음(F-117)은 건드리지 않는다

### 4.2 오프라인 정책 (Q1 기본값)

- 온라인에서 한 번이라도 그린 글자의 조각은 오프라인에서도 나온다(0.3 ②)
- **오프라인에서 처음 보는 글자는 폴백 서체로 보인다**(0.3 ③). 폴백 순서는 지금 토큰 그대로 — 산세리프 `system-ui, sans-serif`, 세리프 `serif`, 고정폭 `'Pretendard Variable', monospace`. 글자가 빠지거나 네모(□)가 되지는 않는다 — 시스템 한글 서체가 그린다
- 받아들이는 이유: 오프라인에서 새 글자를 쓰는 경우는 드물고(이미 쓴 문서는 온라인에서 한 번 열었을 때 조각이 들어온다), 대가로 첫 방문 서체가 5.8MB → 2.1MB 가 된다. 폴백이어도 내용은 그대로 읽고 쓸 수 있다(불변조건: 장식은 내용을 바꾸지 않는다와 같은 성격 — 서체는 표시만 바꾼다)
- **첫 방문(서비스 워커가 아직 페이지를 제어하지 않는 방문)에 받은 조각은 `fonts` 캐시에 들어가지 않는다.** 제어는 다음 방문부터다(F-117 `registerType: 'prompt'`, `clientsClaim` 없음 — 0.3 ① 에서 새로고침 뒤에야 `controller` 가 생겼다). 그 조각들은 브라우저 HTTP 캐시(운영 `immutable`, 1년)에 남는다. 이 명세는 `clientsClaim` 을 켜지 않는다 — F-117 업데이트 흐름을 건드리게 된다
- 오프라인에서 `error` 가 된 조각은 온라인으로 돌아와도 **그 페이지에서는 다시 받지 않을 수 있다**(FontFace 상태가 `error` 에 머묾 — 0.3 ③ 에서 `error` 로 남는 것까지만 확인). 새로고침하면 다시 받는다. 이것을 위한 장치는 두지 않는다

## 5. 서체가 늦게 올 때

### 5.1 깜빡임 — `font-display`

- 세 서체 모두 `swap` 이다(Pretendard 92개·Noto 248개 `@font-face` 전부 `font-display: swap`, D2Coding `tokens.css` 도 `swap` — 파일에서 확인). 지금과 같다
- 조각 방식에서 달라지는 점: 지금은 서체 하나가 통째로 늦게 오고 한 번에 바뀐다. 이제는 **조각마다 따로 도착하므로, 한 줄 안에서 어떤 글자는 Pretendard, 어떤 글자는 시스템 서체인 채로 잠깐 보일 수 있다.** 대신 조각이 작아(문서 한 편에 Pretendard 12조각 평균 약 26KB) 바뀌는 시간이 짧다 — 30KB/s 에서 문서 한 편 산세리프 전부가 약 10초, 지금은 Pretendard 한 파일만 약 67초
- 레이아웃 흔들림: 폴백 → 웹 서체로 바뀌면 글자 폭이 달라 줄바꿈 위치가 바뀌고 문단 높이가 변한다. 지금도 있는 현상이고, 이 명세는 폴백 서체 치수 맞춤(`size-adjust`·`ascent-override` 로 만든 폴백 `@font-face`)을 넣지 않는다(Q4)

### 5.2 편집기 다시 재기 — `src/editor/fontRemeasure.ts`

- 근거: CM6 `EditorView` 는 만들 때 `document.fonts.ready` 에 **한 번** 걸어 다시 잰다(`@codemirror/view` 6.43.11 `EditorView` 생성자). 통파일일 때는 서체가 부팅 무렵 한 번에 들어와 이것으로 충분했다. 조각 방식에서는 **스크롤로 새 부분이 보이거나 새 글자를 칠 때마다 새 조각이 늦게 도착한다** — 그 뒤 줄 높이가 바뀌어도 CM6 는 다음 갱신·스크롤 때까지 모른다(높이 지도가 낡아 클릭 위치·스크롤 위치가 잠깐 어긋날 수 있다)
- 규칙: 편집기 뷰가 살아 있는 동안 `document.fonts` 의 `loadingdone` 이벤트마다 `view.requestMeasure()` 를 부른다. 뷰가 없어지면 듣기를 푼다. `document.fonts` 가 없는 환경(Vitest `node`)에서는 아무것도 하지 않는다
- `requestMeasure()` 로 충분한 이유: `ViewState.measure` 는 콘텐츠 DOM 높이가 지난번과 다르면(`contentDOMHeight != domRect.height`) 보이는 줄 높이를 다시 잰다 — 서체 교체로 줄바꿈이 바뀌면 이 높이가 바뀐다
- 내보낼 것(계약): `export const fontRemeasure: Extension`. `createEditor.ts` 의 `extensions` 에 넣는다. 표 칸 하위 편집기(`tableWidget.ts`)에는 넣지 않는다 — 칸 높이는 위젯 DOM 이 정하고 바깥 편집기가 다시 잰다
- 선례: `src/lib/mathRender.ts` `requestRemeasureOnFontsReady`(KaTeX 서체 도착 뒤 한 번 다시 재기)
- 단위 테스트는 두지 않는다(DOM 이벤트 연결뿐이다. `node` 환경에 `document` 가 없다). 사람 확인 H3 으로 본다

### 5.3 인쇄 — `src/app/printDoc.ts`

- 지금 `printDoc` 은 인쇄용 DOM 을 붙이고 이미지·Mermaid 를 채운 뒤 `document.fonts.ready` 를 기다린다
- 조각 방식에서는 인쇄용 본문에 **처음 나온 글자의 조각 받기가 레이아웃 때 시작**된다. `document.fonts.ready` 는 부른 시점의 "진행 중인 받기" 에 대한 약속이라, 레이아웃 전에 부르면 곧바로 풀려 폴백 글자로 인쇄될 수 있다
- 규칙: `document.fonts.ready` 를 읽기 **직전에** 인쇄용 루트의 레이아웃을 강제로 한 번 읽는다(예: 높이 값 하나 읽기). 그래야 조각 받기가 먼저 시작되고 `ready` 가 그것을 기다린다. 나머지 순서는 그대로
- 오프라인에서 처음 보는 글자는 인쇄에서도 폴백이다(4.2)

## 12. 열린 질문

### Q1 오프라인 정책 — **사람 결정 필요** (제품 문장을 바꾼다)

| 안 | 첫 방문 서체 | precache 서체 | 오프라인에서 처음 보는 글자 |
| --- | --- | --- | --- |
| **A. 런타임 캐시만 (기본값)** | 문서 한 편 2.07MB | KaTeX 256KB | 폴백 서체 |
| B. 조각 전부 precache | 페이지 2.07MB + SW 가 나머지 조각 ≈ 11.1MB | ≈ 11.1MB | 제 서체 |
| C. 자주 쓰는 한글 조각만 precache | 거의 B 와 같음 | Pretendard 84/92조각 등 ≈ 8.6MB | 대부분 제 서체 |
| D. A + 설치한 PWA(standalone)에서만 나중에 나머지 조각을 천천히 받아 둠 | 웹 A 와 같음. 설치 사용자는 나중에 ≈ 11MB 를 더 받는다 | A 와 같음 | 설치 사용자는 받아 둔 뒤 제 서체 |

- 기본값 A 인 이유: 0.2 — B·C 는 지금(5.8MB)보다 많이 받는다. 목적이 받는 양 줄이기다
- 다른 안을 고르면: B·C 는 이 명세의 목적과 반대라 명세를 다시 써야 한다. D 는 "받아 둘 조건·시점·진행 표시" 가 새로 필요해 별도 명세(M2)로 뺀다 — 이 명세는 A 로 가고 D 를 뒤에 얹을 수 있다

### Q2 D2Coding 을 직접 쪼갤지 — **사람 결정 필요** (도구·라이선스)

- 사실: 변경안에서 남은 서체 바이트의 72%(1,485,508B / 2,073,096B)가 D2Coding 통파일이고, 앱 첫 화면부터 받는다(0.1)
- 스크래치 측정(fontTools 4.62.1 `subset`, 힌팅 유지, woff2): Pretendard 의 92개 `unicode-range` 로 D2Coding 을 자르면 92조각 합 1,133,140B + 그 범위 밖 글자 6,971개(한자 등) 919,488B. **ASCII 만 쓰면 7조각 105,440B, `zettelkasten.md` 의 모든 글자면 17조각 260,580B.** Latin 만 따로 자르면 13,696B
- 라이선스: D2Coding 원본 저장소 `naver/d2-coding-font` 의 `OFL.txt` 첫 줄이 "with Reserved Font Name D2Coding" 이다(2026-09-26 확인). OFL 1.1 3항은 수정판(Modified Version)이 예약 이름을 쓰지 못하게 한다. **잘라 낸 파일이 수정판인지, 그렇다면 family 이름·파일 내부 이름을 바꿔야 하는지는 확인하지 못했다** — 사람 판단이 필요하다. Pretendard·Noto 조각은 저작자·배포처가 직접 만든 것이라 이 문제가 없다

| 안 | 첫 방문 문서 한 편(추정) | 필요한 것 |
| --- | --- | --- |
| **a. 통파일 유지, precache 에서만 뺌 (기본값)** | 2.07MB | 없음 |
| b. 조각을 한 번 만들어 저장소에 넣음(Python fontTools 로 사람이 한 번 실행, 결과 woff2 약 93개 + CSS 를 커밋) | 약 0.85MB | 조각 생성 절차 문서, 저장소 바이너리 약 2MB, 라이선스 판단(이름 바꾸기 포함 가능) |
| c. 빌드 때 자르는 npm 개발 의존성(예: `subset-font`, harfbuzz wasm) | 약 0.85MB | 새 의존성 — 비교표와 사람 결정 필요(CLAUDE.md), 빌드 시간 증가(스크래치 fontTools 로 92조각 만드는 데 10분 넘게 걸렸다) |
| d. 고정폭 한글을 포기하고 D2Coding 을 Latin 조각만 싣기 | 약 0.6MB | design.md D3·D5 결정을 뒤집는다(원문 모드 표 정렬이 깨진다, design.md 2.3) — 권하지 않음 |

- 기본값 a 인 이유: 새 의존성·라이선스 판단 없이 지금 바로 받는 양을 63% 줄인다. b 가 가장 효과가 크므로 **사람이 라이선스를 판단한 뒤 별도 명세로** 하는 것을 권한다
- b·c 를 고르면: 이 명세의 3.3·1장 표에 `tokens.css` 가 들어오고 A5 상한이 1,000,000B 로 내려간다

### Q3 서체 CSS 가 커지는 것 (기본값: 받아들인다)

- 사실: 첫 화면을 막는 `index-*.css` 가 brotli 로 약 17KB 늘어난다(30KB/s 에서 약 0.6초)
- 기본값 받아들임: 줄어드는 서체 양(문서 한 편 약 3.5MB)에 비해 작다
- 다른 안: 서체 `@font-face` 를 별도 CSS 로 떼어 비동기로 싣기 — 그 사이 모든 글자가 폴백으로 그려지고 전체가 한 번 더 바뀐다. 이득(17KB)보다 깜빡임이 커서 권하지 않는다

### Q4 `font-display` (기본값: `swap` 유지)

- `optional` 로 바꾸면 느린 망에서 첫 방문은 시스템 서체로 고정되고 깜빡임·출렁임이 없다. 대신 조각 방식에서는 **나중에 도착한 조각이 그 페이지에서 끝내 적용되지 않아** 새로 친 글자만 시스템 서체로 남는다(한 문단에 서체가 섞인 채 고정). 편집기에서 받아들이기 어렵다
- 폴백 치수 맞춤(`size-adjust`·`ascent-override` 폴백 `@font-face`)은 출렁임을 줄이지만, 시스템 한글 서체가 OS 마다 달라 값을 하나로 정할 수 없다. 넣지 않는다
- 다른 안을 고르면 5.1·H2 가 바뀐다

### Q5 홈 사이드바 제목 `문서` 의 고정폭 (기본값: 그대로)

- 이것 때문에 홈 화면만 봐도 D2Coding 1.49MB 를 받는다(0.1). 그러나 문서를 열면 `.md-mark`·줄 번호가 어차피 고정폭이라, 바꿔도 문서를 여는 사람에게는 줄지 않는다
- Q2 가 a 로 남을 때만 의미가 있다. 바꾼다면 모양 변경이라 `tweak` 로 따로 한다

### Q6 `fonts` 캐시 상한 400 (기본값)

- 조각 341개 + 배포 한두 번의 옛 파일 여유. 서체 패키지를 올려 해시가 모두 바뀌면 새 조각이 쌓이며 옛 조각은 오래된 순으로 지워진다. 더 낮추면 한 사람이 많은 글자를 쓸 때 쓰던 조각이 지워져 오프라인에서 폴백이 늘어난다

### Q7 KaTeX 서체를 precache 에 남기기 (기본값: 남김)

- 19개 약 256KB. 빼면 오프라인에서 처음 보는 수식의 괄호·적분 기호 크기가 틀어진다(KaTeX 는 서체 치수에 기대 배치한다). 빼면 A1 기대가 "woff2 0개" 로 바뀐다
