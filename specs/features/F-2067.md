판정용으로 지금 동작을 적어 둔다.

| 동작 | 지금 |
| --- | --- |

| 폴더 삭제 요청 | 폴더 안 문서·하위 폴더가 없으면 `empty: true`(대화상자 버튼 `취소`·`삭제` 둘), 있으면 `false`(`취소`·`위로 옮기기`·`전부 삭제`) → `closeSidebarIfNarrow()` |
| 문서 삭제 확인 | `store.remove` → **지금 `docs` 에서 그 문서를 뺀 목록**을 `setDocs`(다시 읽지 않는다) → 대화상자 닫기. 지운 문서가 열린 문서면 남은 목록 첫 문서(없으면 `null`)를 열고, 있으면 `md.lastDocId` 저장, 주소는 `replaceState`(`#/d/{id}` 또는 `#/`) |

| 여러 항목 삭제 | 대화상자를 먼저 닫고, 항목마다 문서는 `remove`, 폴더는 `removeFolder(…, 'move-up')` — 실패는 센다. 끝나면 목록 다시 읽기, 열린 문서가 사라졌으면 홈, 실패가 있으면 error `{n}개를 삭제하지 못했습니다.` |

| 폴더 이름 바꾸기 | `store.renameFolder` → 그 폴더만 교체. 실패는 조용히 |
| 고정·해제 | `store.setPinned` → 그 문서의 `pinnedAt` 만 교체(`updatedAt`·순서 불변). 실패는 조용히 |

```ts

export type UseFolderActionsOptions = {
  store: Store

  folders: Folder[]
  currentDocId: string | null
  bulkDeleteItems: SelectionItem[] | null

  setFolders: Dispatch<SetStateAction<Folder[]>>
  setCurrentDocId: Dispatch<SetStateAction<string | null>>

  confirmDelete: (target: DeleteTarget | null, mode?: FolderDeleteMode) => Promise<void>
```

## 11. 열린 질문 (모두 기본값, 사람 결정 필요 없음)

### Q1. 대화상자 상태 세 개(`deleteTarget`·`bulkDeleteItems`·`moveDocTarget`)를 훅으로 옮기나 — **기본값: App 에 둔다 (2.2)**

- 이유: `useSidebarLayout` 인자가 렌더 중에 셋을 읽고(≈1569), 이 훅은 `useSidebarLayout` 반환값을 인자로 받는다. 상태를 훅에 두면 두 훅이 서로를 먼저 필요로 한다. 셋은 최신값 effect ③ 과 JSX 도 읽는다
- 다른 쪽(훅이 상태를 갖고 `useSidebarLayout` 보다 위에서 호출): `closeSidebarIfNarrow`·`addOpenFolders` 를 ref + 인자 없는 effect 로 우회해야 하고(F-2059 3.1 마지막 수단), 새 effect 가 생기며, 훅 호출이 Ⓐ 자리에서 2,000줄 넘게 위로 간다 — 3.8 "옮긴 절 자리" 를 어긴다. 줄 감소는 상태 선언 5줄만큼 늘어난다

### Q2. `replaceHashUrl` 을 어떻게 넘기나 — **기본값: 옵션 (2.3)**

- 이유: App 모듈 상단 함수이고 App 안 17곳에서 쓴다. 훅이 `App.tsx` 에서 import 하면 순환 import 가 된다. F-2059 2.3 은 이 함수를 F-2071 몫으로 정했다 — 지금 새 모듈로 빼면 F-2071 의 일을 앞당긴다
- 다른 쪽(지금 `hashNav.ts` 등으로 옮기고 훅이 import): 옵션이 하나 줄지만 이 조각이 F-2071 소유 파일을 만들거나 App 의 다른 16곳 import 를 바꾸게 된다 — 이동 아닌 줄이 늘어난다

### Q3. 안에 React 훅이 없는데 `use` 이름을 쓰나 — **기본값: `useFolderActions` (F-2059 2.3 계약)**

- 이유: 개요가 파일·훅 이름을 계약으로 정했고 "바꿔야 하면 개요를 먼저 고친다" 고 했다. Q1 기본값 때문에 안에 `useState` 가 없을 뿐, 뒤 조각(예: 목록 다시 읽기 정리)이 상태·effect 를 더할 여지가 남는다. `use` 이름이라 조건부 호출을 막는 lint 도 그대로 걸린다
- 다른 쪽(`createFolderActions` 팩토리, F-2065 `createExportActions` 선례): 이름이 실제 모양과 맞지만 개요 2.3·5.4 표와 `architecture.md` 줄을 먼저 고쳐야 한다

### Q4. `handleMoveFolder`·`handleMoveDoc` 을 반환하나 — **기본값: 반환하지 않는다 (5.1)**

- 이유: App 에 쓰는 곳이 없다(훅 안 `handleBulkMove`·`confirmMoveDoc` 만). 반환에 넣으면 구조 분해 줄만 늘고 읽는 곳이 없다
- 다른 쪽(반환): 뒤 조각이 필요할 때 옵션 변경 없이 쓸 수 있지만, 지금은 쓰지 않는 이름이 App 에 생긴다

### Q5. e2e 묶음에 `listView`·`paletteApp`·`listReuse` 를 더하나 — **기본값: 더한다 (8장)**

- 이유: 폴더 삭제 세 갈래·폴더 만들기를 보는 테스트가 `listView.spec.js`(F-242·F-246·F-247)에만 있고, 팔레트 문서 삭제는 `paletteApp.spec.js` F-2054 A4, 서버 저장소 경로의 이동·고정·다른 탭 삭제는 `listReuse.spec.js` 에 있다. 6장 행의 파일을 빼는 것이 아니라 더하는 것이라 개요와 부딪치지 않는다(F-2066 Q2 와 같은 판단)
- 다른 쪽(6장 행 그대로): 폴더 삭제 `위로 옮기기`·`전부 삭제` 와 폴더 만들기를 번들 안에서 아무것도 보지 않는다

### 관찰 (이 조각은 고치지 않는다 — F-2059 7장 성격, 판정은 사용자)

1. **문서 하나 삭제와 여러 항목·폴더 삭제가 열린 문서를 다르게 처리한다.** `confirmDelete` 문서 갈래는 남은 첫 문서를 열고 `md.lastDocId` 를 저장하며 목록을 다시 읽지 않는다(`docs` 클로저에서 뺀다, `keepLiveTitle` 없음). 폴더 갈래·`confirmBulkDelete` 는 목록을 다시 읽고 열린 문서가 사라지면 홈으로 가며 `md.lastDocId` 를 건드리지 않는다. 개요 D1 표는 셋을 같은 행("replace")에 두었지만 가는 곳이 다르다
2. **문서 하나·폴더 삭제 실패는 알림이 없다.** `confirmDelete` 에 `try` 가 없어 `store.remove`·`removeFolder` 가 throw 하면 대화상자가 열린 채 남고 처리되지 않은 거부가 된다(`ConfirmDeleteDialog` 는 `onConfirm` 결과를 기다리지 않는다). `confirmBulkDelete` 는 같은 실패를 세어 `{n}개를 삭제하지 못했습니다.` 를 띄운다
3. **`handleMoveFolder` 의 `quiet = false` 갈래는 닿지 않는다.** 유일한 호출처 `handleBulkMove` 가 늘 `true` 를 넘긴다 — `Sidebar` 에 단일 폴더 이동 prop 이 없다(근거). 코드는 그대로 옮긴다

기본값으로 정한 것(승인 시 확정): 훅 이름·파일(F-2059 2.3), 옵션 16개·반환 14개 이름 = 지금 App 변수 이름(5.1), 대화상자 상태 App 에 둠(Q1), `replaceHashUrl` 옵션(Q2), 호출 자리 Ⓐ·5.3 표기, e2e 파일 하나에 C1~C5, 묶음 파일 3개 추가(Q5).
