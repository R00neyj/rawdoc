# F-174 사이드바 항목 우클릭으로 `⋯` 메뉴 열기

작성일: 2026-09-15
상태: **접음 (superseded, 2026-09-23).** `specs/features/F-255.md`(사이드바 여러 항목 선택·우클릭 메뉴, `4b597f5`)가 행 우클릭으로 메뉴 열기를 함께 구현해 대신한다. 이전 상태: 초안 — 사람 승인 대기. 사용자 요청(2026-09-15) "좌측 사이드바에서도 우클릭시 기존 호버 > ...메뉴 바로 열리게". 우클릭 명세 묶음(F-167~F-170)에 더함. F-167~F-170 과 파일이 겹치지 않아 순서와 무관하게 먼저 해도 된다
근거: F-126 5.2(`⋯` 메뉴), F-132 4장(고정 항목), F-211 2.4·F-212 2.5(서버 저장소 폴더 항목), F-143 3.6(행 전체 호버), F-172(메뉴 전환), F-170 2장(Shift+우클릭·조합 중 규칙)

## 1. 파일 소유

| 파일 | 변경 |
| --- | --- |
| `src/app/FolderMenu.tsx` | 바깥에서 메뉴를 열 수 있게 (부분 Edit) |
| `src/app/Sidebar.tsx` | `FolderRow`·`DocRow`·`PinnedRow` 행의 `contextmenu` 처리 (부분 Edit) |
| `e2e/sidebarContextMenu.spec.js` | 신규. `F-174 A*` |

- 새 의존성 없음. 메뉴 항목·모양·위치는 바꾸지 않는다

## 2. 요구사항

### 2.1 여는 곳
- 대상 행: 트리 폴더 행(이름 입력 중 아님), 트리 문서 행, `고정됨` 묶음 행. 행 `.tree-row` 안 어디를 우클릭해도(토글·글자·빈 곳·`⋯` 버튼) 그 행의 `⋯` 메뉴를 연다
- `contextmenu` 기본 동작을 막아 브라우저 메뉴는 뜨지 않는다
- 그대로 브라우저 기본 메뉴: `공유받음` 묶음 행(`⋯` 메뉴 없음, F-212 2.4), 폴더 이름 입력란, 사이드바 빈 영역·머리·버튼, 접힌 레일
- **Shift+우클릭**은 앱 메뉴를 열지 않고 브라우저 기본 메뉴 (F-170 2장과 같음)
- 키보드 메뉴 키·Shift+F10 으로 행 안 버튼에 온 `contextmenu` 도 같은 메뉴를 연다

### 2.2 메뉴
- `⋯` 버튼을 누른 것과 똑같이 연다: 같은 항목(서버 저장소 폴더의 링크·초대 항목 포함), 같은 자리(`⋯` 버튼 아래, 우클릭 좌표를 따르지 않음), 같은 전환(F-172), 열리면 첫 항목 포커스
- 열린 동안 그 행 `⋯` 버튼이 보인다(`aria-expanded="true"`, 기존 규칙)
- 이미 열린 메뉴의 행을 다시 우클릭하면 열린 채 둔다(닫지 않음)
- 다른 행 메뉴가 열려 있으면 그 메뉴는 닫히고 새 행 메뉴가 열린다. 한 번에 하나만 열린다
- 닫기·키보드·실행 뒤 포커스는 기존 규칙 그대로(Esc 면 `⋯` 버튼으로)
- 우클릭은 문서를 열거나 폴더를 펼치지 않는다. 끌어놓기를 시작하지 않는다

## 3. 수용 기준

| # | 확인 | 방법 | 기대 |
| --- | --- | --- | --- |
| A1 | 문서 행 | 트리 문서 글자 우클릭 | 그 행 `⋯` 메뉴 열림(`고정`·`폴더로 이동…`·`삭제`), 첫 항목 포커스, `contextmenu` `defaultPrevented` true, 현재 문서 안 바뀜 |
| A2 | 폴더·고정 행 | 폴더 행 빈 곳 우클릭 / `고정됨` 행 우클릭 | 각 행 메뉴 열림, 폴더 펼침 상태 안 바뀜 |
| A3 | 같은 자리 | 같은 행을 `⋯` 클릭으로 열었을 때와 우클릭으로 열었을 때 `.item-menu-list` 위치 비교 | 같음(±1px) |
