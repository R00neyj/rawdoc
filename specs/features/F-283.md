## 1. 범위

### 문제

툴바·우클릭 메뉴의 `하이라이트` 명령(`src/editor/formatCommands.ts` 107행 `toggleHighlight = toggleWrap('==')`)은 `==글자==` 를 넣지만, **어느 모드에서도 하이라이트로 보이지 않는다.** 2026-09-20 코드로 확인한 현재 동작:

| 모드 | 지금 보이는 것 | 이유 |
| --- | --- | --- |
| 편집(라이브) | `==글자==` 글자 그대로. 기호 색도 없고 배경도 없다 | `@lezer/markdown` 에 `==` 를 읽는 노드가 없다. 실측: `==강조==` 를 파싱하면 `Paragraph` 아래 자식 노드가 하나도 생기지 않는다(`**굵게**` 는 `StrongEmphasis`+`EmphasisMark` 가 생긴다). 노드가 없으니 `highlight.ts` 의 `md-mark` 색도, `preview/inline.ts` 의 기호 숨김도 걸리지 않는다 |
| 원문 | `==글자==` 글자 그대로, 색 없음 | 위와 같다 |
| 보기 | `==글자==` 글자 그대로 | 실측: `md.render('==강조==')` → `<p>==강조==</p>`. `renderMarkdown.ts` 에 `==` 규칙이 없고 `markdown-it-mark` 도 설치돼 있지 않다 |

`F-167.md` 2장은 "편집·보기 모드에서 하이라이트 색칠… 은 하지 않는다(지금처럼 글자 그대로 보인다)" 로 정해 두었다. **이 명세가 하이라이트에 한해 그 결정을 바꾼다** (수식 `$`·주석 `%%` 는 그대로 둔다 — 3.4. **수식은 2026-09-21 F-291 이 렌더하게 됐다**)

### 한다
- `renderMarkdown` 에 하이라이트 인라인 규칙을 직접 넣어 보기 모드·공유 화면·공개 보기에서 `<mark>` 로 렌더한다
- 편집(라이브) 모드에서 `==` 를 숨기고 배경색만 보이게 한다. 커서·선택이 그 줄에 있으면 기호가 드러난다
- 원문 모드에서 `==` 를 다른 마크다운 기호와 같은 강조색(`md-mark`)으로 칠한다. 배경은 주지 않는다
- 하이라이트 배경색 토큰을 `tokens.css` 에 더한다. 세 테마(화이트·세피아·다크) 모두 값이 나온다

### 하지 않는다
- **새 의존성.** `markdown-it-mark` 를 설치하지 않는다 (`CLAUDE.md` "새 의존성은 명세에 적힌 것만"). markdown-it 이 이미 갖고 있는 구분자(delimiter) 기계를 그대로 쓴다 — 3.1
- 수식(`$…$`)·각주(`[^1]`)·주석(`%%…%%`) 렌더. `%%` 는 `F-214` 가 내보내기·공유에서 지우는 것으로 끝이고, 화면 표시는 그대로 글자다
- `formatCommands.ts` 손대기. `toggleHighlight`·`clearFormatting` 은 지금 동작 그대로 맞다 (3.3 에서 짝 규칙만 맞춘다)
- 하이라이트 색 고르기(여러 색 하이라이트), 하이라이트 단축키 추가
- `.txt` 평문·PDF·HTML 내보내기에서의 하이라이트 처리 — F-278·F-279·F-280 (6장)

## 3. 문법 규칙

### 3.1 보기 모드 — markdown-it 인라인 규칙을 직접 만든다

`renderMarkdown.ts` 의 기존 커스텀 규칙 4개(작업목록·콜아웃·이미지블록·위키링크)는 모두 **core 규칙**(`md.core.ruler`)으로 토큰 배열을 훑는다. 하이라이트는 그 방식을 쓰지 않고 **인라인 규칙**(`md.inline.ruler` + `md.inline.ruler2`)으로 넣는다. 이유:

- 위키링크식(core 규칙에서 `text` 자식만 훑기)으로 하면 `==a **b** c==` 처럼 **다른 인라인 서식을 건너뛰는 하이라이트를 못 만든다.** 여는 `==` 와 닫는 `==` 가 서로 다른 `text` 자식에 들어가기 때문이다. 억지로 이으면 `<strong>` 과 `<mark>` 가 서로 엇갈리게 닫히는 잘못된 HTML 이 나온다
- markdown-it 은 `~~취소선~~` 을 구분자(delimiter) 방식으로 처리한다(`node_modules/markdown-it/dist/markdown-it.mjs` 2804~2883행 `strikethrough_tokenize`/`postProcess`). 같은 기계(`state.scanDelims`·`state.delimiters`·`state.tokens_meta`)를 쓰면 중첩·플랭킹·인라인코드 제외가 **공짜로 맞는다.** 타입도 이미 있다(`markdown-it.d.mts` 의 `StateInline.delimiters`·`scanDelims`, `ParserInline.ruler2`)

구현 모양(취소선 규칙을 `~`(126) → `=`(61), `s_open/s_close` → `mark_open/mark_close`, `markup: '~~'` → `'=='` 로 옮겨 적은 것):

```ts
md.inline.ruler.before('emphasis', 'highlight', tokenize)      // len >= 2, 홀수 1개는 text 로 남긴다
md.inline.ruler2.before('emphasis', 'highlight', postProcess)  // 짝 맞은 토큰을 mark_open/mark_close 로 바꾼다
```

- `state.scanDelims(state.pos, true)` — 둘째 인자 `true` 는 낱말 가운데(`a==b==c`)도 허용한다는 뜻이다. 취소선과 같다
- `mark_open`/`mark_close` 는 `tag: 'mark'`, `nesting: 1`/`-1`, `markup: '=='`, `content: ''`. **renderer 규칙을 따로 두지 않는다** — markdown-it 기본 `renderToken` 이 `<mark>…</mark>` 를 그린다 (위키링크가 `wikilink_span_open` 을 기본 렌더러에 맡기는 것과 같다)
- `md` 인스턴스는 모듈 안 기존 것 하나를 그대로 쓴다. 새 인스턴스를 만들지 않는다

### 3.2 무엇이 하이라이트인가 (보기 모드 판정)

| 입력 | 결과 | 근거 |
| --- | --- | --- |
| `==글자==` | `<mark>글자</mark>` | 기본 |
| `` `==글자==` `` , 코드블록 안 `==글자==` | 글자 그대로 | 인라인 규칙은 `code_inline`·`fence` 안을 애초에 지나지 않는다(실측: `` `~~a~~` `` → `<code>~~a~~</code>`) |
| `== 글자==` | 글자 그대로 | CommonMark 플랭킹 규칙 — 여는 기호 뒤 공백이면 열지 않는다(실측: `~~ a~~` → `~~ a~~`) |
| `==a **b** c==` | `<mark>a <strong>b</strong> c</mark>` | 구분자 방식이라 중첩이 맞는다(실측: `~~b **c** d~~` → `<s>b <strong>c</strong> d</s>`) |
| `===셋===` | `=<mark>셋</mark>=` | 홀수 1개는 `text` 로 남는다(실측: `~~~셋~~~` → `~<s>셋</s>~`). 취소선과 같은 결과이므로 예외를 두지 않는다 |
| `====a====` | `<mark><mark>a</mark></mark>` | 취소선(`~~~~a~~~~` → `<s><s>a</s></s>`)과 같다. 알려진 동작으로만 적는다 |
| 문단 다음 줄의 `===` | `<h1>` (지금과 같다) | setext 제목은 블록 단계에서 이미 처리돼 인라인 규칙이 보지 않는다(실측 확인) |
| 여는 `==` 와 닫는 `==` 사이에 줄바꿈 | 글자 그대로 (하이라이트 아님) | **3.2.1** |

#### 3.2.1 줄바꿈을 넘지 않는다

markdown-it 의 구분자 기계는 기본적으로 **한 문단 안이면 줄을 넘어 짝을 맞춘다**(실측: `~~a\n b~~` → `<s>a\nb</s>`). 하이라이트는 그렇게 두지 않고 **줄을 넘으면 짝이 아니게** 막는다. 이유:

- 편집 모드 decoration 은 줄을 넘는 `Decoration.replace` 를 만들 수 없다. CM6 가 "Decorations that replace line breaks may not be specified via plugins" 를 던진다 (`src/editor/preview/inline.ts` 19~27행 `pushHide` 주석). 줄을 넘는 하이라이트를 보기 모드만 인정하면 **두 모드가 서로 다른 글을 보여 준다**
- `clearFormatting`(F-167 4장)의 `==…==` 짝 찾기도 줄 단위다. 셋을 같은 규칙으로 맞춘다

막는 방법: `postProcess` 에서 짝이 맞은 뒤, 여는 토큰과 닫는 토큰 사이에 `softbreak`·`hardbreak` 토큰이 하나라도 있으면 **바꾸지 않고 그대로 둔다**(토큰이 `text` 로 남아 `==` 가 글자로 보인다). 구분자에 원문 위치를 따로 달지 않아도 되는 방법이라 `Delimiter` 타입을 건드리지 않는다

### 3.3 편집·원문 모드 판정 — 줄 안 짝 찾기

편집 모드는 구문 트리에 노드가 없으므로(1장) 위키링크(`F-131`)와 같이 **줄 글자를 직접 훑는다.** 그 찾기를 `src/lib/highlightSyntax.ts` 로 뗀다

```ts
export type HighlightMatch = { from: number; to: number; innerFrom: number; innerTo: number }
export function findHighlights(lineText: unknown): HighlightMatch[]
```

- 왼쪽부터 `==` 를 찾고, 그 뒤에서 가장 가까운 `==` 를 닫는 기호로 삼는다. 찾으면 그 뒤부터 다시 센다 — `formatCommands.ts` 의 `findMarkerPairs`(180~209행)와 같은 규칙이다
- 안쪽이 비면(`====`) 짝으로 보지 않는다. 여는 `==` 바로 뒤가 공백이면 짝으로 보지 않는다 (3.2 플랭킹과 맞춘다)
- 세 개 이상 이어진 `=` 는 `findMarkerPairs` 와 같이 왼쪽부터 2개씩 끊는다. 보기 모드(3.2 `===셋===`)와 결과가 한 글자 어긋날 수 있다 — 8장 M3
- **`formatCommands.ts` 의 `findMarkerPairs` 를 이 함수로 바꾸지 않는다.** 그 파일은 F-167 소유이고 `%%`·`$` 까지 함께 쓰는 함수라 이번 범위 밖이다 (8장 M3)

### 3.4 다른 문법과의 경계
- 대상이 아닌 자리: 인라인코드·펜스 코드블록·표(편집 모드 표 칸은 아래 에디터가 따로 있다)·프론트매터. 편집 모드는 `wikiLinks.ts` 가 내보내는 `isOpaquePosition(state, pos)`(`OPAQUE_NODE = FencedCode·InlineCode·Table·Frontmatter`)를 그대로 재사용한다
- 수식 `$…$`·주석 `%%…%%` 는 이 명세가 손대지 않는다. 주석은 지금처럼 글자 그대로고, **수식 렌더는 F-291 이 맡았다**(2026-09-21)
- `docs/` 의 프로토타입·조사 문서는 근거일 뿐 이 명세가 따르는 기준이 아니다. 문법 기준은 Obsidian 의 `==하이라이트==`(`F-167` 근거에 적힌 https://obsidian.md/help/syntax)이지만, **실제로 따르는 것은 "markdown-it 이 `~~취소선~~` 을 처리하는 방식 + 줄바꿈 금지"** 다(3.1·3.2.1). Obsidian 자체 파서의 경계 사례(`===`, 낱말 가운데, 중첩)를 문서로 확인하지 못했고, 확인하지 못한 것을 기준으로 적지 않는다

## 4. 편집·원문 모드 표시

`src/editor/preview/highlightMark.ts` 가 확장 **두 개**를 내보낸다. 계산 함수는 DOM 없이 `EditorState` 만으로 동작하고 `ViewPlugin` 은 `view.visibleRanges` 로 부르기만 한다 (`F-104` 2.1 구조 그대로)

```ts
export function buildHighlightMarks(state, ranges, hasFocus?): Range<Decoration>[]   // 편집(라이브)
export function buildHighlightSymbols(state, ranges): Range<Decoration>[]            // 편집·원문 공통, 기호 색만
export function highlightMarkPreview(): Extension   // livePreview() 안
export function highlightMarkStyle(): Extension     // previewCompartment 밖, 항상 켬
```

### 4.1 편집(라이브) 모드 — `highlightMarkPreview()`
- 짝이 맞은 `==…==` 의 **안쪽 글자**에 `Decoration.mark({ class: 'md-highlight' })` 를 붙인다. 커서가 닿든 안 닿든 **배경은 항상 보인다**(Obsidian 과 같다. 커서가 들어올 때마다 배경이 깜빡이지 않게)
- 여는·닫는 `==` 는 **커서·선택이 그 줄에 없을 때만** `Decoration.replace({})` 로 숨긴다. 판정 단위는 **줄**(`activeLines`, `F-104` 2.2) — 같은 줄의 `**굵게**` 기호와 함께 드러나고 함께 숨는다
- 줄바꿈을 포함한 replace 는 만들지 않는다(3.2.1 에서 애초에 짝이 안 된다. `pushHide` 와 같은 방어는 그대로 둔다)
- IME 규칙은 다른 프리뷰 확장과 같다(`F-104` 2.3·`F-134` 3.1·3.8): `isForced` 면 무조건 재계산, 문서·선택·뷰포트·구문 트리 변화가 없으면 건너뛰고, 조합 중이면 건너뛰되 문서가 바뀌었으면 decoration 위치만 따라간다(`mapDecorationsOnHold`)

### 4.2 원문 모드 — `highlightMarkStyle()`
- 여는·닫는 `==` 에 `Decoration.mark({ class: 'md-mark' })` 만 붙인다. **새 클래스를 만들지 않는다** — `md-mark` 는 이미 `app.css` 2116행에서 강조색(`--accent`)+고정폭을 주는 마크다운 기호 클래스다(`F-107` 2.1)
- `previewCompartment` 밖(`createEditor.ts`, `fenceLinePreview()` 옆)에 두어 **편집·원문 모드 모두** 켠다. 편집 모드에서는 4.1 의 숨김이 겹쳐 보이지 않다가, 커서가 줄에 오면 강조색 기호로 드러난다 — 다른 기호와 같은 모양이 된다
- **원문 모드에는 배경(`md-highlight`)을 주지 않는다.** 원문 모드는 서체·크기만 따르고 요소 모양은 바꾸지 않는다(`F-152` 2.2)

## 5. 색·시각

구체적 색값은 이 명세가 정하지 않는다. 토큰 이름과 파생 방식만 정하고 **실제 눈으로 보는 판정은 사람 확인으로 넘긴다**(`CLAUDE.md` "디자인은 TDD 하지 않는다")

| 토큰 | 자리 | 기본으로 제안하는 파생 |
| --- | --- | --- |
| `--md-highlight-bg` | `tokens.css` `:root`(화이트) | `color-mix(in srgb, var(--callout-question) 22%, transparent)` |

- `--callout-question` 을 고른 이유: 형광펜의 노랑·호박색에 가장 가깝고, **세 테마 모두 값이 이미 있다**(`tokens.css` 화이트 `#855a00`, 세피아는 화이트 상속, 다크는 `#d9a441` 로 따로). 새 hex 를 어디에도 적지 않는다(`CLAUDE.md` 불변조건). 다른 후보는 `--accent` 파생이지만 강조색은 마크다운 기호의 색이라 하이라이트와 뜻이 겹친다 — 8장 M1
- 투명도(`…% , transparent`)로 만들어 **글자색을 건드리지 않는다.** `color: inherit` 로 두면 세 테마의 `--ink` 대비가 그대로 유지된다
- 테마별 값이 따로 필요하면 `:root[data-theme='dark']` 블록에서 이 토큰만 다시 정의한다. `--callout-question` 이 테마마다 달라 기본 제안으로는 다시 정의하지 않아도 된다
- `tokens.test.ts` 의 대비 검산에는 넣지 않는다. 그 테스트는 불투명 hex 만 검산하고 `color-mix()` 는 건너뛴다(`tokens.test.ts` 30~38행 `resolve`) — 투명 배경 대비는 사람이 본다
- 편집 모드(`preview.css`)와 보기 모드(`markdown.css`)가 **같은 토큰**을 쓴다. 보기 모드 선택자는 다른 요소와 같게 `:is(.app-shell, .public-view) .markdown-body mark` — 공유 화면(F-130)·공개 보기(F-210)도 같이 받는다
- 모서리·좌우 여백은 주지 않는 것을 기본으로 한다(배경만). 넣을지는 사람이 보고 정한다
- 글자 선택 바탕(`--selection-bg`)과 겹쳤을 때 구분되는지는 사람 확인 항목이다

### 6.2 `F-278.md` 4.6 예외가 필요 없어진다

F-278 4.6 은 "`renderMarkdown` 에 `==` 를 해석하는 규칙이 없으니 **평문 변환에서만** `text` 토큰의 `==글자==` 를 `글자` 로 바꾼다" 로 정했다. 이 명세가 들어가면 `==글자==` 는 더 이상 `text` 토큰이 아니라 `mark_open` + `text` + `mark_close` 가 된다 → **4.6 의 정규식은 영영 맞지 않는 죽은 코드가 된다**

**어느 것이 먼저 들어가도 깨지지 않는 이유**

| 순서 | 무슨 일이 나는가 |
| --- | --- |
| F-278 → F-283 (계획) | 6.2 대로 `toPlainText` 를 고친다. F-278 A2 가 계속 통과하는지 A16 으로 확인한다 |

즉 **평문 결과는 두 순서 모두 같다.** 순서를 정하는 이유는 결과가 아니라 파일 충돌(6.1)이다
