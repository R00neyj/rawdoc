## 2. 결정

1. **신호는 `data-user-css-rev` 하나만 본다**(개요 2.5). F-2095 는 DOM 의 사용자 시트가 실제로 바뀔 때만 올린다(F-2095 6장 경계) — 이어받기·모드만 바뀐 적용에는 다시 재지 않는다. 구독 함수(`subscribeUserCss`)를 쓰지 않는 까닭: 적용보다 먼저 불릴 수 있고, `src/editor` 가 `src/app` 을 import 하게 된다
2. **이름은 `src/lib/userCssContract.ts` 로 옮긴다.** 의존 방향이 `editor → lib` 만이라(architecture 174행) 편집기 모듈이 `bootPaint.ts` 를 읽을 수 없다. `bootPaint.ts` 가 재export 해 `userCssApply.ts`·기존 테스트의 import 는 그대로 둔다. 같은 문자열을 두 곳에 쓰지 않는다
3. **D-16 편집기에도 넣는다.** D-16 은 사용자 CSS 를 막지 않고(개요 2.4 "모든 대화상자"), 400ms 자동 저장으로 **대화상자가 열린 채** 적용된다. 줄 높이를 시험하는 사람이 바로 그 편집기를 보고 있다. 표 칸 하위 편집기(`tableWidget.ts`)에는 넣지 않는다 — F-2040 5.2 와 같은 까닭(바깥 편집기가 다시 잰다)
4. **캔버스 변환은 `cssColor.ts` 에 둔다**(개요는 `MapScene.tsx` 안). 2D 문맥을 인자로 받으므로 모듈은 여전히 DOM 을 만들지 않고 node 단위 테스트가 가짜 문맥으로 판정한다. `MapScene.tsx` 에 export 를 늘리면 `hasWebGL2` 처럼 react-refresh 예외 주석이 또 붙는다
5. **조합 확인은 하지 않는다.** 원격 적용은 F-2095 가 조합이 끝날 때까지 미루고(개요 2.5 IME 줄), D-16 저장은 `view.composing` 이면 미룬다. `requestMeasure` 는 문서·장식을 바꾸지 않는 레이아웃 읽기라 `fontRemeasure` 도 조합을 보지 않는다

## 3. 편집기 — `userCssRemeasure`

- `fontRemeasure` 와 같은 모양의 `ViewPlugin`. 만들 때 `document.documentElement` 에 `MutationObserver` 를 `{ attributes: true, attributeFilter: [USER_CSS_REV_ATTR] }` 로 걸고, 콜백마다 `view.requestMeasure()` 한 번. `destroy` 에서 `disconnect`
- `document` 나 `MutationObserver` 가 없으면 빈 플러그인(`fontRemeasure` 의 `document.fonts` 확인과 같은 자리)
- 한 태스크에 rev 가 여러 번 올라도 `MutationObserver` 가 묶어 한 번 부르고, `requestMeasure` 도 다음 프레임에 한 번 잰다 — 따로 모으지 않는다

## 4. 지도 — `MapScene.tsx`

- `buildScene` 의 `MutationObserver` `attributeFilter` 를 `['data-theme', USER_CSS_REV_ATTR]` 로. 콜백은 그대로(`applyColors()` + `requestDraw()`). `--ease-out` 은 지금처럼 만들 때 한 번만 읽는다(개요 2.5 "그 밖은 바꿀 수 없다")
- `readToken`: `parseCssColor(계산값)` 이 `null` 일 때만 `colorViaCanvas`, 문맥이 없으면 `FALLBACK`. 문맥은 `buildScene` 마다 1×1 캔버스 하나를 처음 필요할 때 `getContext('2d', { willReadFrequently: true })` 로 만들어 돌려쓴다(`null` 이면 그 장면 동안 다시 만들지 않는다). hex·`rgb()` 만 쓰는 기본 테마에서는 캔버스를 만들지 않는다
- **`colorViaCanvas(ctx, css)` 규칙:** `clearRect(0,0,1,1)` → `fillStyle = css` → `fillRect(0,0,1,1)` → `getImageData(0,0,1,1).data` 넷을 255 로 나눠 돌려준다. 지우기가 먼저인 까닭: 반투명 색이 앞 픽셀과 섞인다. `css` 는 늘 `getComputedStyle` 계산값이라 유효한 색이다 — 무효 문자열 판정은 하지 않는다
- 정밀도는 8비트(M3). 지금 `rgb()` 경로와 같다
