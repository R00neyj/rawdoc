# F-246 `새 폴더` 직후 Enter 로 폴더가 두 개 생기는 문제

작성일: 2026-09-18
상태: 사용자 승인 (2026-09-18 "ㅇㅇ 수정 ㄱㄱ"). F-242 구현 중 발견돼 그때는 범위 밖이라 테스트에서 우회만 했다
근거: `specs/features/F-126.md` 5.3(폴더 만들기·이름 편집), `F-143.md` 3.3(레일 `새 폴더`)

## 1. 범위

### 문제
사이드바 `새 폴더` 를 누른 직후 곧바로 Enter 를 치면 **폴더가 두 개 생긴다**. 재현율은 40~90%(F-242 구현 중 실측).

원인은 `src/app/Sidebar.tsx` `handleCreateFolder`:

```ts
async function handleCreateFolder(parentId: string | null) {
  const folder = await onCreateFolder(parentId)   // ← 저장소 왕복을 기다린다
  if (folder) startRename(folder.id, folder.name) // ← 여기서야 editingId 가 선다
}
```

`startRename` → `setEditingId` → 리렌더 → `useEffect` 가 `editingInputRef.current.focus()` 를 부르기까지 **포커스는 방금 누른 `새 폴더` 버튼에 그대로 남아 있다.** 그 사이 Enter 를 치면 브라우저가 포커스된 버튼을 다시 눌러(native click) `handleCreateFolder` 가 한 번 더 돈다.

폴더를 만들고 반사적으로 이름을 치는 것이 자연스러운 동작이라 실사용에서 충분히 걸린다. 기존 e2e 는 폴더 **개수**를 검증하지 않아 이 버그로 실패하지 않았지만, 잠재적 플레이키 원인이기도 하다.

### 한다
- `새 폴더` 를 누른 뒤 이름 입력 칸이 뜨기 전에 Enter·Space·재클릭이 들어와도 **폴더는 하나만 생긴다**
- 사이드바 목록 버튼과 레일 버튼(`handleRailCreateFolder`), 폴더 우클릭 메뉴의 `하위 폴더 만들기`(`onCreateFolder(node.id)`) 모두 같게 막는다
- 막는 동안에도 화면이 멈춘 것처럼 보이지 않게 한다(짧은 시간이라 별도 표시는 두지 않는다 — 아래 3.2)

### 하지 않는다
- `새 문서`·`가져오기` 버튼의 같은 성격 중복 클릭 — 문서는 만든 뒤 에디터로 포커스가 옮겨가고 중복으로 생겨도 되돌리기 쉬워 이번 범위 밖으로 둔다. 필요하면 별도 명세
- 폴더 만들기 흐름(이름 즉시 편집, 기본 이름 `새 폴더`) 변경
- 저장소 쪽 중복 방지(같은 이름 폴더 금지 등) — 원인은 UI 포커스 타이밍이지 저장소가 아니다
- 대기 표시(스피너)·버튼 잠금 모양 추가

## 3. 요구사항

### 3.1 재진입 가드 (`Sidebar.tsx`)
- `useRef<boolean>` 로 "폴더 만드는 중" 을 들고, `handleCreateFolder` 진입 때 이미 참이면 **아무것도 하지 않고 바로 돌아간다**
- `onCreateFolder` 가 끝나고 `startRename` 까지 마친 뒤 가드를 푼다. 실패(예외·`null` 반환)해도 반드시 푼다(`try/finally`)
- 상태(`useState`)가 아니라 ref 를 쓴다 — React 상태 갱신은 비동기라 연속 입력 사이에 반영이 늦을 수 있다
- 레일 버튼(`handleRailCreateFolder`)은 `onToggleCollapse()` 뒤 같은 `handleCreateFolder` 를 부르므로 가드가 그대로 적용된다

### 3.2 화면
- 가드가 걸려 있는 시간은 저장소 왕복 한 번(서버 저장소도 캐시에 먼저 쓰고 즉시 resolve, F-207 2.3)이라 사람이 느낄 만큼 길지 않다 — **버튼을 `disabled` 로 바꾸거나 표시를 더하지 않는다**
- 두 번째 Enter 는 조용히 무시된다(알림 없음)
