# F-245 한글 입력 중 목록 줄 엔터가 두 번 넘어가는 문제

작성일: 2026-09-18
상태: 사용자 승인 대기 (2026-09-18 사용자 "ul태그 ( - ) 생성에 오류 — 테스트 적고 엔터로 다음줄 넘기면 두번 줄넘김되서 … 띄우고 `- 여기` 위치에 써짐")
근거: `specs/features/F-103.md` 3.2(조합 종료 재계산), `F-104.md` 2.3(IME 보류 규칙), CLAUDE.md 불변조건("IME 조합 중 재계산을 보류하면, 조합 종료 시 밀린 재계산을 반드시 따라잡는다"), `.workflow/tasks/T-004/verify.md` 6.5·7장

## 1. 범위

### 문제
목록 항목(`- 테스트`)을 치고 그 줄 끝에서 엔터를 치면 **줄이 두 번 넘어간다**. 사용자가 본 결과:

```
- 테스트
(빈 줄)
- |        ← 커서
```

기대:

```
- 테스트
- |
```

2026-09-18 실측으로 조건을 좁혔다:

| 경로 | 결과 |
| --- | --- |
| 합성 키 입력(IME 없이 `- 테스트` → Enter) | **정상** — `- 테스트\n- X`. 줄 끝 공백 1·2개, 체크박스(`- [ ]`), 중첩 목록도 전부 정상 |
| CDP `Input.imeSetComposition` 으로 한글을 조합해 넣은 뒤 Enter | **이상** — `- 테스트\r\nX\r\n`. 목록 이어쓰기(`- `)가 안 붙고, 문서 끝에 개행이 하나 더 남는다 |

즉 **한글 IME 조합을 거친 목록 줄에서만** 엔터 처리가 어긋난다. 조합을 거치지 않으면 `insertNewlineContinueMarkdown`(`@codemirror/lang-markdown` 의 `markdownKeymap`, `createEditor.ts` 285행 `markdown()` 이 싣는다)이 정상 동작한다.

CDP 재현은 실제 IME 와 완전히 같지는 않다(`cm-composing` 클래스가 붙지 않았다) — 그래서 사용자가 본 "빈 줄 + `- ` 는 붙음" 과 실측한 "`- ` 안 붙음 + 개행 하나 더" 가 세부에서 다르다. **둘 다 같은 뿌리(조합 경로에서 Enter 가 두 번 반영되거나 키맵을 건너뛴다)로 보고 조사한다.**

### 한다
- 한글(및 다른 IME) 조합으로 친 목록 항목 줄 끝에서 엔터를 쳤을 때, 조합 없이 친 경우와 **같은 결과**가 되게 한다
  - `- 항목` → 다음 줄 `- `
  - `1. 항목` → 다음 줄 `2. `
  - `- [ ] 항목` → 다음 줄 `- [ ] `
  - 중첩 목록은 같은 들여쓰기 유지
- 빈 목록 항목에서 엔터를 치면 지금처럼 목록을 끝낸다(기호를 지우고 빈 줄) — 조합 경로에서도 같아야 한다
- 원인을 먼저 특정하고(아래 3.1), 고친 뒤 회귀 테스트를 남긴다

### 하지 않는다
- 목록 이어쓰기 규칙 자체를 새로 만들기 — `insertNewlineContinueMarkdown` 동작을 그대로 두고, 조합 경로에서 그것이 제대로 불리게만 한다
- 조합 중 재계산 보류 규칙(F-104 2.3) 변경 — 불변조건이다. 보류를 없애는 방식으로 고치지 않는다
- 다른 키(Backspace·Tab 등)의 조합 중 동작 손대기
- 목록 기호 자동 정렬·번호 다시 매기기

## 3. 요구사항

### 3.1 원인 조사 (구현 전 단계)

고치기 전에 다음을 확인해 보고에 적는다:

1. 조합 중/조합 직후 Enter 가 **몇 번** CM6 트랜잭션으로 들어오는가 (`EditorView.updateListener` 로 `tr.isUserEvent('input')`·`docChanged` 를 찍어 본다)
2. `insertNewlineContinueMarkdown` 이 그때 **불리는가, 건너뛰어지는가** (`markdownKeymap` 보다 먼저 `Prec.high(keymap.of(shortcutKeymap))`·`defaultKeymap` 중 누가 Enter 를 먹는지)
3. `compositionCatchup` 의 `setTimeout(0)` dispatch 가 Enter 트랜잭션과 겹쳐 들어오는지
4. `view.composing` 이 Enter keydown 시점에 무엇인지(`.workflow/architecture.md` 3장: compositionstart 시점의 `view.composing` 은 false 다)

### 3.2 고치기
- 조사 결과에 맞는 최소 수정. "Enter 를 한 번만, 목록 이어쓰기 키맵을 거쳐 처리한다" 가 목표다
- 조합 보류·따라잡기 규칙(CLAUDE.md 불변조건)은 유지한다. 따라잡기 신호가 문서를 바꾸는 일이 있어선 안 된다(지금 `forceRecalc` 는 effect 뿐이라 문서를 안 바꾼다 — 그 성질을 유지한다)

### 3.3 테스트 방법
- 실제 한글 IME 는 자동 판정 대상이 아니다(CLAUDE.md "구현 담당 서브에이전트 규칙"). 대신 **CDP `Input.imeSetComposition`** 으로 조합을 흉내내 e2e 로 고정한다:
  ```js
  const cdp = await page.context().newCDPSession(page)
  await cdp.send('Input.imeSetComposition', { text: '테스트', selectionStart: 3, selectionEnd: 3 })
  ```
- 이 방법이 실제 IME 와 다른 점(위 1장)을 테스트 파일 주석에 한 줄로 남긴다
- 실제 한글 IME 확인은 `specs/human-checks.md` 로 올린다
