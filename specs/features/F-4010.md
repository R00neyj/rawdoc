# F-4010 OAuth 로그인 이어가기·동의·오류 화면

작성일: 2026-10-16
상태: 승인 2026-10-16(사용자 "ㄱㄱ" — F-4008 결정·흐름 그림 `specs/wireframes/remote-mcp-flow.html`·동의 화면의 `휴지통으로 보내기`·`돌아갈 곳` 줄 포함). F-4008 6장 로드맵의 둘째 자식. 플러그인 설정·표·`AUTH_ROUTES` 는 F-4009, 여기는 사람이 보는 세 화면과 그 사이의 이어 붙이기만. 전부 worker 단위(`loginRoutes.test.ts` U35 처럼 `worker.fetch` 한 바퀴), e2e 없음(6장)

## 근거 (`@better-auth/oauth-provider` 1.7.10 tarball·HEAD, 이름으로 찾는다)
- `authorizeEndpoint`: 세션이 없거나 `prompt=login`·`create`·`max_age` 초과면 `{loginPage}?{서명 질의}`, 동의가 없으면 `{consentPage}?{서명 질의}` 로 보낸다(`redirectWithPromptCode`). 서명 질의 = 원래 authorize 질의 + `exp`(기본 600초)·`ba_iat`·`ba_param`(서명한 이름들)·`sig`
- 등록 안 된 `client_id`·`redirect_uri` 등은 `getErrorURL` → `onAPIError.errorURL`(우리 `'/login'`) 에 `?error=…&error_description=…` 로 간다. 코드: `invalid_client`·`client_disabled`·`unauthorized_client`·`invalid_redirect`·`unsupported_response_type`·`unsupported_prompt_select_account`·`invalid_request`·`invalid_target`·`request_not_supported`·`request_uri_not_supported`·`invalid_request_uri`. better-auth 콜백이 같은 주소로 보내는 코드(`state_*`·`invalid_callback_request`·`internal_server_error`)와 겹치지 않는다
- 이어가기: 플러그인 before 훅이 본문 `oauth_query` 를 `verifyOAuthQueryParams`(패키지가 내보냄)로 검사하고 `/sign-in/social` 이면 상태 쿠키 `serverContext` 에 싣는다. 콜백이 세션 쿠키를 심으면 after 훅이 그 질의로 authorize 를 다시 돌려 동의 화면이나 `redirect_uri?code&state&iss` 로 302. 요청이 `Sec-Fetch-Mode: navigate`(또는 `Accept: text/html`)가 아니면 302 대신 JSON — 테스트는 콜백에 이 머리를 단다
- 동의 엔드포인트 `POST /oauth2/consent {accept, oauth_query}` 는 거부면 `access_denied`+`state`+`iss` 주소, 허용이면 authorize 결과 주소를 `{redirect:true,url}` 로 준다. authorize 는 `ctx.request` 가 없으면 401 이라 `auth.api.*` 직접 호출로는 안 되고 `getAuth(env).handler` 에 안쪽 `Request` 를 넘겨야 한다. 앱 이름은 `api.getOAuthClientPublic({query:{client_id}})` 의 `client_name`
- 상태 쿠키는 `xchacha20` 암호문 hex 라 평문의 2배+. 계산(스크래치): 보통 질의(state 43자)면 서명 질의 636자, 쿠키 값은 오류 주소에 서명 질의를 실으면 2,730B·안 실으면 1,456B. 서명 질의 849자에서 3,582B → 4,096B 한도 때문에 3장 두 상한
- `worker/securityHeaders.ts` 는 `/login` 만 `login` CSP, 그 밖 경로는 `site`. `login` 의 `form-action` 은 제출 뒤 303 이 가는 제공자 두 출처를 이미 담는다(F-4001 가정 a) — 동의 폼의 303 은 앱의 `redirect_uri` 로 간다

## 2. 계약
```ts
export function clientLabel(client: { name: string | null; redirectUris: string[] }, redirectUri?: string): { name: string; host: string }
export function signedOAuthQuery(search: string): string | null   // sig·ba_param 과 ba_param 에 적힌 이름만, 없으면 null
export function consentRedirectAllowed(url: string, signedQuery: string): boolean
export function consentFormTarget(redirectUri: string | null): string | null
```
- `clientLabel`: host = `redirectUri`(없으면 `redirectUris[0]`)의 `URL.host`(포트 포함), 못 읽으면 `''`. name = 제어문자를 공백으로 바꾸고 trim 한 `name` 의 앞 64 코드포인트, 비면 host
- `consentRedirectAllowed`: 서명 질의의 `redirect_uri` 와 같거나 그 뒤에 `?`·`&` 가 이어지는 주소, 또는 `/login?`·`/oauth/consent?` 로 시작하는 주소만 참
- `consentFormTarget`: `https:`·`http:` 면 `URL.origin`, 그 밖 스킴(앱 전용, 예 `cursor:`)이면 `{스킴}:`, `javascript:`·`data:`·`blob:`·`file:`·못 읽음은 `null`

## 3. `/login` 이어가기 (흐름 1 → A2)
- **OAuth 갈래** = `signedOAuthQuery(url.search)` 가 문자열. 판정 순서: ① 갈래가 아니고 `error` 가 `OAUTH_PRE_REDIRECT_ERRORS` 면 302 `/oauth/error?error={code}` — 세션 판정보다 앞(지금은 세션이 있으면 오류를 버리고 앱으로 간다) ② 갈래면 `verifyOAuthQueryParams(q, env.BETTER_AUTH_SECRET)` 거짓·1,700자 초과 → 302 `/oauth/error?error=request_expired` ③ 갈래면 **세션이 있어도** 페이지를 그린다 — 플러그인은 다시 로그인이 필요할 때만 이리 보낸다 ④ 나머지는 지금 그대로
- 갈래 페이지: `return` 은 읽지 않고(다른 출처 복귀 주소가 끼어들 자리가 없다) 숨은 칸 `oauth_query` 에 q, 제목 아래 안내 줄 `앱 연결을 계속하려면 로그인하세요. 로그인하면 연결을 허용할지 묻는 화면으로 넘어갑니다.`(`login-reauth` 모양). 오류 줄은 지금 표 그대로
- `POST /api/login`: 칸 `oauth_query` 가 있으면 ②와 같은 검사(실패 303 `/oauth/error?error=request_expired`) 뒤 `signInSocial` 본문에 `oauth_query` 를 더한다. `callbackURL` 은 `/?app=1`, `errorCallbackURL` 은 q 가 850자 이하면 `/login?{q}`(실패해도 이어가기가 남는다), 넘으면 `/login`. 850·1,700 은 구현 때 잰 상태 쿠키(q 포함 ≈4q, 미포함 ≈2q)가 4,096B 아래인 값(2026-10-16, 900·1,800 에서 하향)
- 개발 우회(`DEV_AUTH_EMAIL`)는 세션이 없어 이 흐름을 지나지 못한다. 고치지 않는다

## 4. 동의 화면
- `GET /oauth/consent`(GET·HEAD 밖 405): q 무효 → 302 `/oauth/error?error=request_expired` · 세션 없음 → 302 `/login?{q}` · 클라이언트 조회 실패 → 302 `/oauth/error?error=invalid_client` · 그 밖 200, `Cache-Control: private, no-store`, `noindex`
- 문구(`specs/ia.md` 6장 표에 더한다): `<title>앱 연결 · {제품명}</title>`, h1 `{앱 이름} 앱이 {제품명} 계정에 접근하려고 합니다` / `{email} 계정` / `할 수 있는 일` 아래 목록 `문서·폴더 목록과 본문 읽기 (공유받은 문서 포함)`·`문서·폴더 만들기·고치기·옮기기`·`문서·폴더를 휴지통으로 보내기` / `돌아갈 곳: {host}` / `금고 문서는 열 수 없습니다. 연결은 설정 › 연결된 앱에서 끊을 수 있습니다.` / 버튼 `허용`(`name="accept" value="yes"`) `거부`(`value="no"`). `{앱 이름}`·`{host}` 는 `clientLabel(…, redirect_uri)`, 모든 값은 HTML 이스케이프
- 폼 `method="post" action="/api/oauth/consent"`, 숨은 칸 `oauth_query`. CSP 는 `login` + `formTarget = consentFormTarget(질의 redirect_uri)` — 서명이 틀린 주소면 폼이 없는 오류로 가니 넓혀도 쓸 곳이 없다
- `POST /api/oauth/consent`: `/api/` 라 Origin 관문을 지난다(교차 사이트 자동 제출로 남의 앱에 동의시키는 공격을 막는 자리). `isWriteRoute` 거짓(문서 쓰기가 아니다). 크기·형식은 `handleLoginStart` 와 같은 4,096B·form-urlencoded, 어긋나거나 `accept` 가 `yes`·`no` 밖이면 303 `/oauth/error?error=invalid_request` · q 무효 303 `…request_expired` · 안쪽 `Request`(`{BETTER_AUTH_URL}/api/auth/oauth2/consent`, 들어온 `Cookie`·`Origin`, JSON `{accept, oauth_query}`, `Accept: application/json`)를 `getAuth(env).handler` 로 → 200 이고 `consentRedirectAllowed` 면 303 그 주소, 401 이면 303 `/login?{q}`, 그 밖 `console.error` + 303 `/oauth/error?error=server_error`

## 5. 오류 화면 `GET /oauth/error`
- 400, 스크립트 없음, `login` CSP. `<title>앱 연결 · {제품명}</title>`, h1 `앱을 연결하지 못했습니다`, 문구 한 줄(`role="alert"`), 링크 `{제품명} 열기` → `/?app=1`. `error` 값은 화면에 넣지 않는다(F-2033 6.2)
- `invalid_client`·`client_disabled`·`unauthorized_client`: `연결하려는 앱을 찾을 수 없습니다. 앱에서 연결을 처음부터 다시 시작해 주세요.` · `invalid_redirect`: `앱이 알려 준 돌아갈 주소가 등록된 주소와 달라 연결을 멈췄습니다. 안전을 위해 앱으로 돌려보내지 않았습니다.` · `request_expired`: `연결 요청 시간이 지났습니다. 앱에서 연결을 다시 시작해 주세요.` · 그 밖·없음: `연결 요청을 처리하지 못했습니다. 앱에서 연결을 다시 시작해 주세요.`

## 9. 열린 질문
- Q1 플러그인 오류를 `/login` 이 `/oauth/error` 로 넘긴다(기본). 다른 안: `onAPIError.errorURL` 을 `/oauth/error` 로 바꾸고 거기서 `state_*` 를 `/login` 으로 넘김 — F-2033 설정(F-4009 소유 `authServer.ts`)이 바뀌고 better-auth 가 기본 오류 코드를 늘릴 때마다 목록을 따라가야 한다. 기본안의 빈틈: 제공자가 그대로 넘긴 `invalid_client` 같은 코드(우리 설정 오류일 때뿐)가 일반 로그인에서 오면 앱 연결 오류 화면이 뜬다
