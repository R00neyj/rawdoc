## 2. 알림함
- 행 문구: `accessRequestPushPayload` 의 제목 + `.` / 둘째 줄 본문 — 예 `a@x.com님이 문서 편집 권한을 요청했습니다.` / `"기획안"`
- 누르면 F-2116 처럼 그 행을 읽음으로, 알림함 닫고 `#/shares`. 이미 S-6 이면 해시가 그대로라 아래 `accessRequestKey` 가 새로 부르게 한다
- `accessRequestKey(items)` (순수, `notificationsApi.ts`): `access_request` 항목 id 를 정렬해 `,` 로 이은 문자열. 폴링이 새 요청을 가져오면 키가 바뀌어, S-6 을 열어 둔 소유자의 목록이 다시 불린다
- 안 읽은 배지: 종류 구분 없이 이미 센다 — 바꾸지 않는다

## 3. S-6 `권한 요청` 묶음
- 자리: 두 묶음 **위**. 요청이 0개면 묶음 자체를 그리지 않는다(머리 `권한 요청 {N}`). 빈 상태 판정은 세 목록이 모두 비었을 때
- 행 `shares-request-row`: 대상 이름 버튼(기존 `onOpenTarget`), 배지 `문서`/`폴더`, 요청자 `{이름} · {이메일}`(이름이 비면 이메일만), 권한 배지 `보기`/`편집`, 날짜 `YYYY-MM-DD`, 버튼 `승인`(`shares-request-approve`)·`거절`(`shares-request-reject`, 위험색). 보내는 동안 그 행 두 버튼 비활성
- 승인 200 → 행 빼고 목록 다시 부름(새 초대가 `초대한 사람` 에 보이게), 알림 `{이메일}에게 {보기|편집} 권한을 주었습니다.`
- 거절 204 → 행 빼기, 알림 `요청을 거절했습니다.` 확인 대화상자 없음(메시지 없는 요청이고 요청자는 7일 뒤 다시 보낼 수 있다)
- 404 → 행 빼기, 알림 `이미 처리됐거나 사라진 요청입니다.` 그 밖 실패 → 행 유지, 오류 알림 `요청을 처리하지 못했습니다. 연결을 확인한 뒤 다시 시도해 주세요.`
- `sharesApi`: `POST /api/access-requests/{id}/approve`·`/reject`, 결과 `'ok' | 'gone' | 'failed'`
