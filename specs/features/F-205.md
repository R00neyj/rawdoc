## 2. 요구사항

### 2.1 D1 `migrations/0001_users.sql`
```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  email TEXT NOT NULL UNIQUE,
  created_at INTEGER NOT NULL
);
```
- `email` 은 소문자로 저장·비교. `id` 는 `crypto.randomUUID()`

### 2.2 `worker/auth.ts`
- `getUser(request, env): Promise<{ id, email } | null>`
  1. `Cf-Access-Jwt-Assertion` 헤더(없으면 `CF_Authorization` 쿠키) 읽기
  2. `{ACCESS_TEAM_DOMAIN}/cdn-cgi/access/certs` 의 JWKS 로 RS256 서명 검증 (`crypto.subtle.importKey('jwk')` + `verify('RSASSA-PKCS1-v1_5')`). JWKS 는 모듈 변수에 1시간 캐시, `kid` 가 없으면 한 번 다시 받는다
  3. `iss === ACCESS_TEAM_DOMAIN`, `aud` 에 `ACCESS_AUD` 포함, `exp` 가 지금보다 뒤, `email` 문자열
  4. 통과하면 `users` 에서 이메일로 찾고 없으면 만든다 (`INSERT ... ON CONFLICT(email) DO NOTHING` 후 SELECT)
- **로컬 개발 우회**: `env.DEV_AUTH_EMAIL` 이 있고 요청 호스트가 `localhost` 또는 `127.0.0.1` 일 때만 그 이메일을 로그인 사용자로 본다. `DEV_AUTH_EMAIL` 은 `.dev.vars` 에만 두고 `wrangler.jsonc` 에 쓰지 않는다
- `ACCESS_TEAM_DOMAIN`·`ACCESS_AUD` 가 비었고 우회 조건도 아니면 항상 null (설정 전 배포가 열리지 않게)
- 검증 실패 이유는 응답에 넣지 않는다
- 이후 명세가 쓰는 `requireUser(request, env)`: null 이면 `401 {"error":"unauthenticated"}` 응답을 던지는 형태로 둔다

### 2.3 라우트
| 요청 | 응답 |
| --- | --- |
| `GET /api/me` | 로그인: `200 {"id","email"}`. 아니면 `401 {"error":"unauthenticated"}` |
| `GET /api/login?return={해시}` | 로그인이면 `302 Location: /{해시}`. `return` 은 `#/` 로 시작할 때만 쓰고 아니면 `/` (열린 리다이렉트 방지). 로그인이 아니면 401 (Access 앱 설정 전) |

- Access 앱은 `rawdoc.app/api` 경로를 보호한다 (2026-09-15 도메인 변경)(메인이 H64 에서 만든다). 로그인 안 한 사람이 `/api/login` 을 주소창으로 열면 Access 가 일회용 코드 화면을 보여 주고, 통과하면 Worker 가 앱으로 되돌린다
- 로그인 없이 쓰는 공개 API 는 `/api` 밖 접두사를 쓴다 (F-210 에서 `/pub/*`)

### 2.4 `src/app/account.ts`
- `fetchAccount(): Promise<{ state: 'in', id, email } | { state: 'out' } | { state: 'offline' }>`
  - `fetch('/api/me', { redirect: 'manual', credentials: 'same-origin' })`
  - `200` → `in`. `401`·`403`·`response.type === 'opaqueredirect'` → `out` (Access 가 리다이렉트를 줄지 401 을 줄지 문서에 없어 둘 다 처리)
  - 네트워크 오류(`TypeError`)·5xx → `offline`
- `loginUrl(hash)` → `/api/login?return={encodeURIComponent(hash)}`, `logoutUrl()` → `/cdn-cgi/access/logout`
- 마지막 `in` 결과를 `md.account` (`{"id","email"}` JSON)에 저장, `out` 이면 지운다. `offline` 이면 저장값을 쓴다

### 2.5 계정 메뉴 (상단바)
- 상단바 오른쪽 끝, `.md 내보내기` 오른쪽. 아이콘 버튼 `IconAccount` + 툴팁 `계정` (F-142 모양). 메뉴 여닫기·키보드는 공유 메뉴(F-130)와 같다
- 메뉴 항목
  - `out`: `로그인` (IconLogin) → 저장 대기 입력 먼저 저장 후 `location.href = loginUrl(location.hash)`
  - `in`: 첫 줄 이메일(선택 불가 글자), `로그아웃` (IconLogout) → 저장 후 `location.href = logoutUrl()`
  - `offline` + 저장값: 이메일 + 글자 `오프라인` (흐린 글자)
- 로그인 여부는 이번 명세에서 문서 저장에 영향을 주지 않는다 (서버 저장은 F-207)
- 앱 시작 때 1회, 창이 `online` 이벤트를 받을 때 1회 조회
