# F-2141 칸반 보드에서 칸·카드 고치기

작성일: 2026-10-14
상태: 승인 대기. 개요 F-2138 1장(IME·원격)과 사용자 흐름 1절 "다음 행동" 셋. 칸 추가·이름 바꾸기, 카드 추가·글자 고치기·체크. 구현 담당 `feature-implementer`. `App.tsx` 변경 없음

## 근거 (2026-10-14 HEAD, 이름으로 찾는다)
- `src/editor/remoteGate.ts` `connectRemote` 의 조합 판정은 `view.compositionStarted || isCellCompositionStarted(view) || isFrontmatterCompositionStarted(view)`, 살아 있음은 `compositionAlive(view)`(`view.dom` 안 포커스), 따라잡기는 `view.dom` 캡처 `compositionend` → `flushIfIdle`. 보드 입력칸은 `view.dom` 밖이라 셋 다 못 본다
- 하위 편집기 조합을 주 view 에 알리는 선례: `tableWidget.ts` `isCellCompositionStarted`, `frontmatterEdit.ts` `isFrontmatterCompositionStarted`(주 view 를 키로 한 `WeakMap`)
- `tests/src/editor/remoteGate.test.ts` `fakeView` 테스트가 `view.dom` 리스너를 `['+compositionend', '+keydown', '-compositionend', '-keydown']` 로 못 박는다(509행)
- `src/editor/yBinding.ts` `undoLocal`·`redoLocal` 은 `StateCommand` 라 편집기 포커스 없이 `view` 로 부를 수 있다. `undoGroup.ts` `nextUndoGroup` 은 `input.type`·`delete` 만 이어 붙이므로 다른 `userEvent` 는 따로 한 단계다

## 2. 계약
```ts
// boardComposition.ts — 주 view 하나에 보드 하나
export function setBoardComposing(view: EditorView, root: HTMLElement | null, composing: boolean): void // false 로 바뀔 때 끝 구독자를 부른다
export function isBoardCompositionStarted(view: EditorView | null | undefined): boolean
export function boardCompositionAlive(view: EditorView): boolean // root 안 포커스 + 창 앞 + 보임
export function onBoardCompositionEnd(view: EditorView, fn: () => void): () => void
// useKanbanView 결과에 더한다
applyKanban(change: KanbanChange | KanbanChange[] | null, userEvent: `kanban.${'add' | 'edit' | 'move' | 'toggle' | 'flag'}`): boolean
```
- `connectRemote`: 판정에 `|| isBoardCompositionStarted(view)`, 살아 있음 `compositionAlive(view) || boardCompositionAlive(view)`, `onBoardCompositionEnd` 로 `nextTick(flushIfIdle)` 을 걸고 `detach` 때 푼다. `view.dom` 리스너는 늘리지 않는다
- `applyKanban`: `null`·읽기 전용이면 `false`. 아니면 `view.dispatch({ changes, userEvent })` 한 번 — 변경 하나가 트랜잭션 하나, 되돌리기 한 단계

## 3. 동작
- **카드 추가**: 칸 아래 `.kanban-add-card` `카드 추가` → 그 자리에 `.kanban-card-input`(이름 `새 카드`, 자리 표시 `카드 내용`). `Enter` → `addCardChange`, 입력칸은 빈 채 남아 다음 카드를 받는다. `Esc` 는 닫기, blur 는 글자가 있으면 넣고 닫기
- **칸 추가**: 칸 줄 오른쪽 끝 `.kanban-add-lane` `칸 추가` → `addLaneChange(NEW_LANE_TITLE)` 를 바로 쓰고 새 칸 이름 입력칸을 연다(글자 전체 선택)
- **칸 이름**: `.kanban-lane-title` 클릭·`Enter` → `.kanban-lane-input`(이름 `칸 이름`). `Enter`·blur → `renameLaneChange`, `Esc` 취소
- **카드 글자**: 카드 더블클릭·카드에 포커스하고 `Enter`·`F2` → `.kanban-card-input`(이름 `카드 내용`, 첫 줄 글자만). `Enter`·blur → `editCardChange`, `Esc` 취소. 하위 줄은 보드에서 고치지 않는다
- **체크**: 체크 칸이 켜진다. 누르면 `toggleCardChange`
- 끝낸 뒤 포커스: 고치기·이름은 그 카드·칸 머리로, 칸 추가 이름을 끝내면 새 칸의 `카드 추가` 로
- **되돌리기**: `.kanban-board` 에서 입력칸 밖 `Ctrl/Cmd+Z` → `undoLocal`, `Ctrl+Y`·`Ctrl/Cmd+Shift+Z` → `redoLocal`(편집기 키맵과 같은 키)
- **자리 추적**: 입력칸을 연 순간의 카드 `from`·칸 `headingFrom` 을 `onChanges` 마다 `changes.mapPos(pos, 1, MapMode.TrackDel)` 로 옮긴다. 지워지면(`null`) 입력칸을 닫고 알림 `다른 곳에서 지워져 고치지 못했습니다.`(정보). 쓸 때는 옮긴 위치로 지금 원문을 다시 읽어 칸·카드 번호를 찾는다
- **IME**: 입력칸 `compositionstart` → `setBoardComposing(view, 보드 root, true)`, `compositionend` → `false`. `Enter` 는 `isComposing`·`keyCode 229` 면 무시. 조합 중 보드가 다시 그려져도 입력칸 요소와 값은 그대로(키 = 추적 중인 위치의 처음 값)
- 읽기 전용 문서(`isReadOnlyDoc`)에는 `카드 추가`·`칸 추가`가 없고 이름·글자 입력칸이 열리지 않으며 체크 칸은 `disabled`
