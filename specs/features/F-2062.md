## 4. 함정 표 (F-2059 3.1~3.5)

| 절 | 이 조각에서 | 처리 |
| --- | --- | --- |
| 3.1 끌어올림 | 훅 인자: `publicRoute`(state, ≈437), ref 12개(≈576~1543), `showNotice`(`const useCallback`, ≈720). 훅 호출 자리(≈2450) 보다 **모두 위**다. 훅은 반환값이 없어 아래에서 참조되는 것도 없다 | 해당 없음 — 호출 자리를 옮기지 않는다 |
| 3.2 최신값 effect | 옮기는 ref 없음. 훅은 ref 를 **이벤트 때만** 읽는다 — 같은 커밋에 읽는 effect: 전부 `없음(이벤트 때만 읽음)`. 읽는 방식 보존: `publicRoute`·`showNotice` 는 지금처럼 클로저(= 훅 인자, deps 에), 나머지는 ref | 대입 effect ①②③ 은 건드리지 않는다 |
| 3.3 렌더 중 조정 | 여섯 절에 없음 | 해당 없음. a~h 순서 불변 |
| 3.4 Editor 마운트 클로저 | 여섯 절은 `createEditor` 넘김값이 아니다. `editorRef.current?.view` 는 키를 누를 때 읽는다 | 해당 없음 |
| 3.5 공개 보기 조기 반환 | 훅 호출(≈2450)은 조기 반환(≈5367)보다 위. 훅은 조기 반환 아래 `const` 를 읽지 않는다. `Ctrl+F` effect 도 2026-09-28 버그 수정 뒤 `publicRoute` 면 등록하지 않는다(아래 Q1 덧붙임) | C3 로 고정 (7.2) |

**deps — 이 조각에서 유일하게 모양이 바뀌는 줄.** ref 를 훅 인자로 받으면 `react-hooks/exhaustive-deps` 가 경고한다(근거 "ESLint 실측"). F-2059 3.7 은 경고 0 과 새 `eslint-disable` 금지다. 그래서 **각 effect 의 deps = 지금 deps + 그 effect 가 읽는 ref 객체**로 적는다. ref 객체는 App 의 `useRef` 결과라 렌더마다 같은 값이다 → effect 가 다시 도는 때(등록·해제 시점)는 지금과 같다.

| effect | 지금 deps | 옮긴 뒤 deps(ref 객체 추가, 순서 자유) |
| --- | --- | --- |
| Ctrl+F | `[publicRoute]` (2026-09-28 수정) | `[publicRoute, editorRef]` |
| Ctrl+P | `[publicRoute]` | `[publicRoute, sharedDocRef, bootPhaseRef, selectPaletteQueryRef, openPaletteRef]` |
| Ctrl+Shift+F | `[publicRoute]` | `[publicRoute, selectSearchQueryRef, openSearchRef]` |
| Ctrl+Alt+M | `[publicRoute, showNotice]` | `[publicRoute, showNotice, bootPhaseRef, commentsRef, editorRef]` |
| Ctrl+M | `[publicRoute]` | `[publicRoute, sharedDocRef, mapRouteRef, toggleCommentsRef]` |
| Ctrl+Shift+/ | `[publicRoute]` | `[publicRoute, bootPhaseRef, currentDocIdRef, sharedDocRef, mapRouteRef, toggleShortcutsRef]` |

- 훅은 옵션을 **맨 위에서 구조 분해**해 effect 본문이 `options.x` 가 아니라 지금 이름 그대로 `x` 를 읽게 한다 — 옮긴 줄이 이동 색으로 남고(3.6), deps 에 지금과 같은 이름이 선다
- 옵션 객체 자체나 새로 만든 객체·함수를 deps 에 넣지 않는다 — App 이 매 렌더 새 옵션 객체를 넘기므로 매 커밋 다시 등록된다(창 리스너 순서가 바뀐다)

## 5. 시그니처 (계약)

### 5.1 `src/app/globalShortcuts.ts`

```ts
import type { KeyEventLike } from './shortcutUsage'

export function isFindKey(e: KeyEventLike): boolean            // Ctrl/Cmd+F
export function isPaletteKey(e: KeyEventLike): boolean         // Ctrl/Cmd+P
export function isSearchDialogKey(e: KeyEventLike): boolean    // Ctrl/Cmd+Shift+F
export function isAddCommentKey(e: KeyEventLike): boolean      // Ctrl/Cmd+Alt+M
export function isToggleCommentsKey(e: KeyEventLike): boolean  // Ctrl+M (맥도 Control)
export function isShortcutsPanelKey(e: KeyEventLike): boolean  // Ctrl/Cmd+Shift+/
```

규칙 — 지금 핸들러의 앞머리 조건식을 **그대로** 옮긴다. 판정 근거가 무엇이었는지(F-2059 Q3 "혼용 그대로"):

| 함수 | 수식키 | 글쇠 | `isComposing` |
| --- | --- | --- | --- |
| `isFindKey` | `ctrlKey \|\| metaKey`, `!shiftKey`, `!altKey` | `key.toLowerCase() === 'f'` | 보지 않는다 |
| `isPaletteKey` | 같음 | `key.toLowerCase() === 'p'` | 보지 않는다 |
| `isSearchDialogKey` | `ctrlKey \|\| metaKey`, `shiftKey`, `!altKey` | `key.toLowerCase() === 'f'` | 보지 않는다 |
| `isAddCommentKey` | `ctrlKey \|\| metaKey`, `altKey`, `!shiftKey` | `code === 'KeyM'` | `true` 면 `false` |
| `isToggleCommentsKey` | `ctrlKey`, `!metaKey`, `!altKey`, `!shiftKey` | `code === 'KeyM'` | `true` 면 `false` |
| `isShortcutsPanelKey` | `ctrlKey \|\| metaKey`, `shiftKey`, `!altKey` | `code === 'Slash'` | `true` 면 `false` |

- **`keyCode` 229 는 보지 않는다.** `matchShortcut`(F-2052)은 229 도 조합으로 보지만 App 핸들러는 `isComposing` 만 본다 — 옮기기만 하므로 그대로. 차이는 U5·U6 이 고정한다
- **`isComposing` 을 함수 안으로 넣어도 동작이 같은 이유:** 지금 세 핸들러는 키 판정 → (`Ctrl+Alt+M` 은 부팅·대화상자 판정) → `isComposing` 순이지만, `isComposing` 앞의 판정은 모두 부수효과 없는 `return` 이다. `preventDefault` 는 전부 그 뒤다. 그러니 `isComposing` 을 키 판정과 한 함수로 묶어 앞당겨도 어느 키에서도 결과가 같다
- **맥:** 여섯 함수는 플랫폼을 인자로 받지 않는다 — 지금 핸들러가 `isMac` 을 읽지 않는다. `mod` 단축키 다섯 개는 `metaKey`(⌘)도 참, `Ctrl+M` 만 `metaKey` 가 있으면 거짓(⌘M 은 창 최소화, tweak 2026-09-28)
- `KeyboardEvent` 는 `KeyEventLike` 에 그대로 대입된다(근거 "타입 실측") — 훅은 `e` 를 그대로 넘긴다. 필드를 골라 새 객체를 만들지 않는다
- 파일 머리에 한 줄 주석(`// 전역 단축키 키 판정 — DOM 없는 순수 함수 (F-2062, F-2059 Q3)`). 함수마다 주석을 달지 않는다 — 이름이 말한다

### 5.2 `src/app/useGlobalShortcuts.ts`

```ts
import type { RefObject } from 'react'
import type { EditorHandle } from '../editor/Editor'
import type { NoticeWithAction } from './NoticeBar'
import type { UseDocCommentsResult } from './useDocComments'

export type UseGlobalShortcutsOptions = {
  publicRoute: object | null
  showNotice: (input: NoticeWithAction, options?: { sticky?: boolean }) => number
  editorRef: RefObject<EditorHandle | null>
  commentsRef: RefObject<UseDocCommentsResult>
  bootPhaseRef: RefObject<'booting' | 'ready'>
  currentDocIdRef: RefObject<string | null>
  sharedDocRef: RefObject<object | null>
  mapRouteRef: RefObject<object | null>
  openPaletteRef: RefObject<() => void>
  selectPaletteQueryRef: RefObject<() => void>
  openSearchRef: RefObject<() => void>
  selectSearchQueryRef: RefObject<() => void>
  toggleCommentsRef: RefObject<(() => void) | null>
  toggleShortcutsRef: RefObject<() => void>
}

export function useGlobalShortcuts(options: UseGlobalShortcutsOptions): void
```

- `publicRoute`·`sharedDocRef`·`mapRouteRef` 을 `object | null` 로 받는 이유: 핸들러는 참/거짓만 보고, `PublicRoute` 는 App 지역 타입이라 import 하면 순환이 된다(F-2071 이 `hashNav.ts` 로 옮길 때까지). `ShareDoc`·지도 경로 타입도 쓸 일이 없다
- `publicRoute` 는 **값 그대로** 넘긴다(불리언으로 바꾸지 않는다) — 지금 deps 가 객체 동일성으로 다시 도는 것(공개 보기 사이 이동 때 다시 등록)을 그대로 둔다
- `commentsRef`·`editorRef`·`showNotice` 의 실제 타입은 구현 때 App 선언과 맞춰 좁혀도 된다(대입만 되면 계약 위반 아님). **옵션 이름은 바꾸지 않는다** — 지금 App 변수 이름과 같아 호출이 `{ publicRoute, showNotice, editorRef, … }` 단축 표기 한 벌로 끝난다
- 반환값 없음. F-2059 2.1 "반환은 객체" 는 돌려줄 값이 있는 훅의 규칙이다 — 이 훅은 리스너만 단다
- 훅 안 effect 여섯 개는 **지금 순서 그대로**: Ctrl+F → Ctrl+P → Ctrl+Shift+F → Ctrl+Alt+M → Ctrl+M(캡처, `addEventListener(…, true)`·`removeEventListener(…, true)` 그대로) → Ctrl+Shift+/. 모두 `window` 에, 버블 5 + 캡처 1. 핸들러 본문의 첫 키 판정 줄들만 `if (!isXxxKey(e)) return` 한 줄로 바뀐다
- `Ctrl+M` 의 `e.stopPropagation()`(`stopImmediatePropagation` 아님)과 그 옆 주석 그대로

### 5.3 App 의 호출 자리

- 여섯 절이 있던 자리 — 좁은 창 Esc·바깥 클릭 effect 바로 아래, "문서를 열 때 저장소 본문을 1회 읽어" 절 바로 위 (F-2059 3.8). 호출 위에 한 줄 주석 `// ----- 전역 단축키 6개 — 순서·단계 그대로 (F-2062) -----`
- 이 자리가 지키는 순서 세 가지:
  1. **`useShortcutUsage` 보다 뒤** — 관찰자 캡처 리스너(≈1553)가 `Ctrl+M` 캡처 리스너보다 먼저 `window` 에 달린다. `Ctrl+M` 의 `stopPropagation` 은 같은 `window` 의 다른 리스너를 막지 않지만, 순서는 지금과 같게 둔다
  2. **다른 App effect 와의 상대 순서** — 커스텀 훅 안 effect 는 훅을 부른 자리에서 선언 순서대로 돈다. 여섯 effect 가 한 자리에 모여 있었으므로 그 자리에서 부르면 창 리스너 등록 순서가 바이트 단위로 같다
  3. **공개 보기 조기 반환보다 앞** — 모든 렌더에서 불린다

- 다른 쪽(ref 들을 훅 안 `useRef` 로 받아 옮기기): 3.2 위반 — 대입이 App 에 남는다

### Q3. `isComposing` 을 순수 함수에 넣나 — **기본값: 넣는다 (5.1)**

- 이유: F-2059 4장이 `isComposing: true` 갈래를 단위 테스트로 요구한다. 5.1 에 적은 대로 앞당겨도 결과가 같다
- 다른 쪽(키 판정만 떼고 `isComposing` 줄은 핸들러에 둔다): 이동 줄이 3줄 늘지만 조합 갈래는 e2e(합성 이벤트)로만 볼 수 있다

기본값으로 정한 것(승인 시 확정): 함수 이름 6개(5.1), 옵션 이름 = 지금 App 변수 이름(5.2), `object | null` 타입 넓힘, 반환값 없음, e2e 파일 하나에 C1~C3.
