### 3.2 사이드바 구성 (펼침)
- 2026-09-14 **F-151 로 변경**: 머리 줄 토글과 검색 버튼은 상단바 제품명 옆으로 옮겼고 사이드바 머리 줄·레일 펴기·검색은 없앴다. 3.2~3.5 의 해당 부분은 F-151 이 우선한다. 넓은 창에서는 다시 **F-159 가 우선**한다 (사이드바 전체 높이 머리 줄, 레일 검색 버튼, 너비 조절)

위에서 아래 순서

1. **머리 줄**: 왼쪽 끝에 접기 버튼(`IconPanelClose`, 아이콘만, `aria-label`·툴팁 `사이드바 접기`, `aria-expanded="true"`, `aria-controls` = 사이드바 id)
2. **동작 버튼**: `새 문서` · `새 폴더` · `가져오기` · `검색` — 각각 아이콘 + 글자, 한 줄에 하나
3. **고정됨** (고정 문서가 있을 때만): 섹션 제목 앞에 `IconPin` 14px. 각 고정 문서 행 맨 앞(트리의 토글 자리)에 `IconPin` 16px `--muted`
4. **문서**: 섹션 제목 `문서` 는 트리 바로 위로 옮긴다 (지금은 동작 버튼 위에 있다)
5. 트리
6. 맨 아래: `앱 설치`(조건 그대로) · `설정` — 아이콘 + 글자

### 3.3 사이드바 접기 (아이콘 레일, 창 너비 1024px 이상)
- 접으면 사이드바가 폭 `--sidebar-rail-w`(48px) 레일이 된다. 레일에는 아이콘만(툴팁·`aria-label` 은 글자와 같은 문구)
  - 위: 펴기(`IconPanelOpen`, `사이드바 펴기`, `aria-expanded="false"`) · 새 문서 · 새 폴더 · 가져오기 · 검색
  - 아래: 앱 설치(조건 그대로) · 설정
  - 고정됨·문서 트리는 숨긴다
- 펼침·접힘 전환은 폭 전환 `--transition-fast`. 움직임 줄이기면 즉시. 편집 영역은 남은 폭에서 지금 규칙대로 가운데 정렬
- 상태는 `md.sidebar`(`expanded` 기본 / `collapsed`)에 저장하고 다음 실행에도 쓴다
- 레일에서 `새 폴더`: 사이드바를 펼친 뒤 폴더를 만들고 이름 변경 입력을 시작한다 (이름 입력 칸이 트리에 있으므로). `새 문서`·`가져오기`·`설정` 은 접힌 채로 동작한다
- 접기·펴기 후 포커스는 반대쪽 토글 버튼으로 옮긴다

### 3.4 좁은 창 (1024px 미만, `specs/ia.md` 3.11 수정)
- 상단바 `☰` 를 `IconPanelOpen` 아이콘 버튼으로 바꾼다 (`aria-label`·툴팁 `사이드바 열기`). 겹쳐 여는 동작·닫히는 조건은 그대로
- 겹쳐 열린 사이드바는 레일이 아니라 펼친 모양(3.2). 머리 줄 버튼은 `IconPanelClose` `사이드바 닫기` 로 겹친 사이드바를 닫는다
- 좁은 창에서는 `md.sidebar` 를 쓰지 않고 바꾸지도 않는다. 넓히면 저장된 상태로 돌아간다

### 3.5 검색 버튼 (로직 없음)
- 펼침: `검색` 아이콘 + 글자, 글자 오른쪽에 `준비 중`(11px `--muted`). 레일: 아이콘, 툴팁 `검색 — 준비 중`
- `aria-disabled="true"` (포커스는 받는다). 눌러도 아무 동작 없음. 비활성 모양은 `--muted` 글자, 호버 바탕 없음
- 검색 로직·입력창·단축키는 만들지 않는다 (`specs/product.md` 4.5 "검색" 은 여전히 M1 범위 밖, 버튼 자리만)

### 3.6 목록 행 모양 (트리·고정됨·동작 버튼 공통)
- **호버·현재 표시는 행 전체**: 들여쓰기 영역·토글·글자·`⋯` 버튼을 포함한 한 줄 전체에 바탕을 칠한다. 글자 버튼에만 따로 바탕을 칠하지 않는다
  - 호버: 바탕 `--rule-2`
  - 현재 문서: 행 전체 바탕 `--panel` + 1px `--rule` 테두리, 글자 `--ink` 600 (지금 글자 버튼에 있던 모양을 행으로 옮김). 호버해도 현재 모양 유지
  - 끌어놓기 강조(`--accent-soft`)는 행 전체 그대로
- **좌우 여백**: 행 안쪽 왼쪽 6px(들여쓰기와 별도로 더함), 오른쪽 4px. 토글·아이콘과 글자 사이 6px. 글자 칸 자체 여백은 상하좌우 4px(2026-09-16 사용자 "패딩만 수정" — 이전 위아래 7px). 행 높이는 지금과 같게 유지
- 동작 버튼·`앱 설치`·`설정` 도 같은 행 모양(호버 바탕, 좌우 여백)
- F-142 3.5 가이드 선은 새 여백 기준으로 토글 가운데에 다시 맞추고, **호버·현재 행 바탕 위에 보인다**(가려지지 않음)
- 행 전체가 누르는 영역이 되지는 않는다: 토글·글자·`⋯` 는 각자 버튼 그대로 (누르는 동작 바꾸지 않음)

### 3.8 편집 영역이 갇힌 느낌 제거 (2026-09-14 추가)

- 수정

  - 편집(편집·원문 모드), 보기 모드, 빈 상태, 공유 화면(S-4) 모두 같은 규칙

- 주의 (회귀 위험): CM6 줄 번호 거터 위치, 블록 위젯 아래 줄 클릭 위치(F-124 A2d), 표 `+` 버튼 clamp 기준(F-140 3.1 — 편집 영역 끝이 넓어짐), 커서 위치 계산. 스크롤 영역을 바꾸는 방식은 구현에서 정하되 CM6 `EditorView` 의 스크롤 요소(`.cm-scroller`)가 스크롤을 맡는 구조를 깨면 멈추고 보고

### 3.9 F-142 확인에서 나온 결함 (2026-09-14 추가)
- 근거: F-140~F-142 통합 브라우저 확인 결과
- **폴더 토글 아이콘 축소**: `.tree-toggle`(flex) 안의 16px svg 가 계산 크기 10×16px 로 줄어든다. flex 항목 축소 때문으로 추정. 앱의 모든 아이콘 svg(상단바·사이드바·메뉴·레일·토글)가 flex 안에서 줄어들지 않게 한다 (예: 아이콘 svg 에 `flex: none`)
- **가이드 선이 안 보인다는 보고**: 코드(`.tree-group::before`)는 있으나 확인 에이전트가 선을 보지 못했다. 3.6 작업 때 `::before` 의 계산 크기(폭 1px, 높이 > 0)와 화면 표시를 실측하고, 안 보이면 원인(바탕 대비, 쌓임 순서, 위치 계산)을 고친다. 선 색이 `--paper` 위에서 너무 흐리면 `--rule` 대신 `--muted` 계열 토큰으로 바꾸고 보고
