## 3. README (`cli/README.md`)
- 명령 표: `rm <id> --yes` → `문서를 휴지통으로 옮깁니다(웹에서 {N}일 안에 복원)`, `rmdir <id> --yes [--all]` → `폴더를 지웁니다. 안의 것은 위 폴더로 옮기고, \`--all\` 이면 하위 폴더도 지우고 문서는 휴지통으로 옮깁니다`. README 는 글이라 숫자 `30` 을 적는다
- "지우기와 옮기기" 첫 줄을 둘로: `` `rm`·`rmdir` 은 `--yes` 를 붙여야 실행됩니다. 묻지 않고 곧바로 지웁니다. `` / `` `rm` 과 `rmdir --all` 이 지운 문서는 휴지통으로 갑니다. 웹의 휴지통에서 30일 안에 복원할 수 있고, 그 뒤 영구히 지워집니다. 복원·영구 삭제·비우기는 웹에서만 합니다. 휴지통의 문서는 `ls`·`find`·`search` 에 나오지 않고 `get` 은 찾을 수 없다(종료 코드 4)고 멈춥니다. ``
- "한도에 걸리면" `doc_quota_exceeded` 줄 끝 문장 → `휴지통의 문서도 저장 공간과 문서 수에 세므로, 지운 뒤 웹의 휴지통에서 영구 삭제하거나 비워야 공간이 납니다.`

## 8. 열린 질문
### Q1. `rm`·`rmdir` 의 `--yes` 요구 — **기본값: 그대로 요구한다**
- 이유: 앱의 지우기 확인 대화상자도 그대로 둔다(F-3021 결정 6). 휴지통은 실수 복구용이고, 문서가 목록에서 사라지고 방이 닫히는 즉시 효과는 같다. 이미 `--yes` 를 붙인 스크립트는 그대로 돈다
- 다른 안(요구하지 않음): `args.ts` 두 `case` 에서 `yes` 검사를 빼고 옵션은 받아만 둔다, E1·E2·H3 삭제, `main.test.ts` C10 의 `rm d1`·`rmdir f1 --all` 이 요청을 보내는 쪽으로 바뀜, README "지우기와 옮기기" 첫 줄 수정. `rmdir`(move-up)만 남기면 두 명령 규칙이 갈린다
