## 2. 요구사항

### 2.1 한도
- 계정(`owner_id`)별 `attachments.size` 합계 **314,572,800 바이트(300MB)**. 상수 하나 `ATTACHMENT_QUOTA_BYTES` (worker)
- 공유 문서에 편집자가 올린 이미지는 올린 사람(`owner_id`) 합계에 들어간다
- 로그인 안 한 로컬 저장소(IndexedDB)에는 한도 없음(브라우저 저장 공간 규칙 F-118 그대로)

### 2.2 서버
- `PUT /api/attachments/:idext`: 같은 id 가 이미 있으면 지금처럼 200(한도 검사 전). 새 첨부면 크기 검사 뒤 `SELECT COALESCE(SUM(size),0)` 로 합계를 구해 `합계 + 새 크기 > 한도` 면 R2·D1 에 쓰지 않고 **507** `{ error: 'quota_exceeded', used, limit }`
- `GET /api/usage` (로그인 필요): `{ used, limit }` 바이트

### 2.3 클라이언트 사전 검사
- `serverStore.putAttachment`: 캐시에 넣기 전에 `fetchUsage()` 로 `used` 를 받고, 캐시의 올리지 않은(`uploaded: false`) 첨부 크기 합을 더해 `+ 새 크기 > limit` 면 `QuotaExceededError`(이름 `quota_exceeded`) 를 던진다. 조회 실패(오프라인 등)면 검사를 건너뛴다(서버가 최종 판정)
- `attachImages`: 이 오류면 `이미지 저장 공간(300MB)이 가득 찼습니다. 문서에서 지운 이미지는 하루 뒤 정리됩니다.` (`error`), 블록을 넣지 않는다. 그 외 저장 실패 문구는 그대로

### 2.4 보낼 목록에서 507
- 오프라인에서 넣은 이미지가 나중에 507 이면: 그 올리기 항목을 보낼 목록에서 빼고 2.3 문구로 `error` 알림(한 번 보내기 회차에 한 번). 원문·캐시는 그대로(이 기기에서는 보이고 다른 기기에서는 `이미지를 찾을 수 없습니다`)

### 2.5 계정 메뉴
- 로그인 상태에서 메뉴를 열 때마다 `fetchUsage()`. 이메일 줄 아래 `이미지 {사용량} / 300MB` 한 줄, 12px `--muted`, 메뉴 항목 아님(`role="none"`, 포커스 안 받음)
- 사용량 표기: 10MB 미만은 소수 1자리(`0.3MB`), 이상은 정수(`120MB`). 1MB = 1,048,576 바이트
- 90% 이상이면 글자색 `--danger`
- 조회 실패·오프라인이면 줄을 숨긴다
