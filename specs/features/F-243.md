작성일: 2026-09-18

## 1. 범위

### 문제
공유 상태를 **대상 하나씩 열어봐야만** 알 수 있다. 읽기 전용 링크는 문서·폴더의 `공유` 메뉴를 열어야 보이고(`ShareMenu`), 초대한 사람은 그 대상의 초대 대화상자(`InviteDialog`)를 열어야 보인다. "지금 무엇을 누구에게 공유하고 있나", "어떤 걸 링크로 배포했나" 를 한눈에 볼 방법이 없다. 링크를 만들어 두고 잊으면 계속 열려 있다.

### 한다
- **공유 관리 페이지**(`#/shares`) — 내가 공유 중인 것을 한 화면에 모은다
  - 읽기 전용 링크(문서·폴더, F-210·F-211)
  - 초대한 사람(문서·폴더, 이메일 + 보기/편집, F-212)
- 각 줄에서 바로: 링크 **복사**, 링크 **해제**, 초대 **내보내기**(권한 삭제)
- 대상 이름을 누르면 그 문서·폴더로 이동
- 계정 메뉴(`API 토큰` 위)에 `공유 관리` 항목
- 공유 중인 것이 없으면 빈 상태 문구
- 서버 저장소(로그인 상태)에서만 쓴다. 로컬 저장소에는 공유 개념이 없다

### 하지 않는다
- 새 공유 만들기 — 만드는 곳은 지금대로 문서·폴더의 `공유`·`초대` 메뉴
- 권한(보기/편집) **바꾸기** — 이번엔 보기와 해제만. 바꾸려면 기존 초대 대화상자
- 링크 조회수·마지막 열람 시각 기록
- 공유받은(내가 받은) 문서 목록 — 그건 사이드바 `공유받음` 묶음이 이미 한다
- 만료 기한·비밀번호 걸린 링크
- 로컬 저장소 모드 지원

## 3. 요구사항

### 3.1 서버 (`worker/shares.ts`)

`GET /api/shares` — 로그인 필요(`requireUser`). 응답:

```json
{
  "links": [
    { "token": "…", "targetType": "doc", "targetId": "…", "targetName": "회의록", "createdAt": 1758… }
  ],
  "grants": [
    { "targetType": "folder", "targetId": "…", "targetName": "업무", "email": "a@b.com", "role": "edit", "createdAt": 1758… }
  ]
}
```

- `links`: `share_links` 에서 `owner_id = 나`, **`revoked_at IS NULL`** 인 것만. `created_at` 내림차순
- `grants`: `grants` 에서 `owner_id = 나`. `created_at` 내림차순
- `targetName`: `target_type` 이 `doc` 면 `docs.title`, `folder` 면 `folders.name`. **대상이 이미 지워졌으면 그 줄을 빼고 보낸다**(고아 링크·권한은 목록에 안 보인다 — 지우는 건 이 명세 밖)
- 쿼리는 `target_type` 별로 `JOIN` 두 번(문서·폴더) 정도로 끝낸다. 대상마다 한 번씩 조회하지 않는다
- 해제·삭제는 **기존 엔드포인트를 그대로 쓴다** — `DELETE /api/docs/:id/link`, `DELETE /api/folders/:id/link`, `DELETE /api/docs/:id/grants/:email`, `DELETE /api/folders/:id/grants/:email`. 새로 만들지 않는다

### 3.2 클라이언트 API (`src/app/sharesApi.ts`)
- `listShares(): Promise<{ links: ShareLinkRow[]; grants: ShareGrantRow[] }>`
- 오류 분류·`credentials: 'same-origin'` 은 `linkApi.ts` 와 같은 방식. 401 은 `unauthorized` 로 구분해 로그인 안내를 띄울 수 있게 한다

### 3.3 화면 (`SharesPage.tsx`)
- 전체 화면(편집기 자리를 대신 차지). 상단 제목 `공유 관리`, 오른쪽에 `닫기`(홈으로)
- 두 묶음을 세로로: **읽기 전용 링크**, **초대한 사람**. 각 묶음 제목 옆에 개수
- 링크 줄: 대상 이름(버튼 — 누르면 그 문서·폴더로 이동) · 종류 배지(`문서`/`폴더`) · 만든 날짜(`YYYY-MM-DD`) · `링크 복사` · `해제`(`danger`)
  - 링크 주소는 `/p/{token}`·`/p/f/{token}` (F-238 5장 경로 기반). 화면에는 전체 URL 을 회색 글자로 한 줄 말줄임해 보여준다
- 초대 줄: 대상 이름(버튼) · 종류 배지 · 이메일 · 권한 배지(`보기`/`편집`) · 초대한 날짜 · `내보내기`(`danger`)
- `해제`·`내보내기` 는 확인 없이 바로 실행하고, 성공하면 그 줄만 목록에서 뺀다. 실패하면 error 알림 `공유를 해제하지 못했습니다.`
- 빈 상태: 두 묶음 다 비면 `공유 중인 문서와 폴더가 없습니다.` 한 줄. 한쪽만 비면 그 묶음 자리에 `없음`
- 불러오는 중에는 목록 자리에 `불러오는 중…`
- 로그인 안 한 상태로 `#/shares` 에 들어오면 `로그인이 필요합니다.` 와 로그인 버튼(계정 메뉴 로그인과 같은 경로)
- 좁은 창에서는 한 줄이 두 줄로 접힌다(대상·날짜 윗줄, 동작 아랫줄)

### 3.4 라우팅 (`hashRoute.ts`, `App.tsx`)
- `#/shares` → `{ type: 'shares' }`. 다른 패턴보다 **뒤에** 검사한다(`#/s/…` 공유 조각과 헷갈리지 않게 정확히 `#/shares` 만)
- 들어갈 때: `beforeLeaveDoc()` 대기 → `sharedDoc` 해제 → `currentDocId = null` → 해시 `#/shares`
- 나올 때(`닫기`·로고): 홈(`#/`, F-232 3.3 경로 재사용)
- 대상 이름을 누르면: 문서면 `#/d/{id}` 로 열고, 폴더면 홈으로 가면서 사이드바에서 그 폴더를 펼친다(F-232 `addOpenFolders` 재사용)
- 페이지에 들어올 때마다 `listShares()` 를 새로 부른다(캐시하지 않는다)

### 3.5 계정 메뉴 (`AccountMenu.tsx`)
- `account.state === 'in'` 일 때만, `API 토큰` **위**에 `공유 관리`
- 누르면 메뉴를 닫고 `#/shares` 로 간다. `onBeforeNavigate()` 는 로그인·로그아웃과 달리 부르지 않는다(같은 앱 안 이동이라 `beforeLeaveDoc` 은 App 쪽 라우팅이 처리한다)
- 아이콘은 `icons.tsx` 에 있는 공유 계열 아이콘을 쓴다(없으면 `IconLink` 로 추가)
