## 2. 무엇을 들이나

- 패키지: `gsap` 3.15.0(npm). `ScrollTrigger` 는 같은 패키지의 `gsap/ScrollTrigger` 경로다. 다른 패키지는 들이지 않는다
- 넣는 곳: 랜딩 번들 `assets/welcome-demo.js` 하나. 엔트리는 지금처럼 `src/welcome/demo.ts`(F-239 2.1)
- **CDN 금지.** `worker/welcomePage.ts` 가 내는 HTML 의 모든 `<script src>` 는 같은 출처 경로(`/` 로 시작)다. `cdn.jsdelivr.net`·`unpkg.com`·`cdnjs` 같은 주소를 쓰지 않는다(design.md 2.3 과 같은 이유 — 자체 호스팅, 외부 요청 없음). W1 이 본다
- 들이는 이유(사용자 결정 1): 핀 고정 + 스크롤 스크럽(되감기 포함) + 여러 장면 타임라인을 직접 구현하는 것보다 검증된 도구가 낫다고 사용자가 판단했다. 직접 구현 추천은 기각됐다
- 비교표를 다시 싣지 않는다 — 결정은 사용자가 했고, 이 명세의 일은 그 결정의 경계를 정하는 것이다

GSAP 은 오픈소스 라이선스(OSI 승인)가 아니다. 그래서 GSAP 코드를 저장소에 복사하거나 `cli/` 처럼 다시 배포하는 패키지에 넣지 않는다(3.2 경계가 같이 막는다).

### 3.2 import 경계 (계약)

- **gsap 을 import 해도 되는 곳은 `src/welcome/` 안뿐이다.** `src/` 의 나머지, `worker/`, `site/`, `cli/` 는 `gsap`·`gsap/…` 를 import 하지 않는다(정적 `import`, `export … from`, 동적 `import()` 모두)
- `src/welcome/` 안에서도 허용하는 경로는 둘이다

```ts
import { gsap } from 'gsap'
import { ScrollTrigger } from 'gsap/ScrollTrigger'
```

  `gsap/all`·`gsap/dist/*`·다른 플러그인(`gsap/SplitText` 등)은 쓰지 않는다. 다른 플러그인을 쓰고 싶으면 이 명세의 허용 목록을 고친다(10장 Q3)
- **gsap 을 (직접이든 `src/welcome/` 안 상대 경로를 거쳐서든) 끌어오는 `src/welcome/` 모듈은 `src/welcome/` 밖에서 import 하지 않는다.** 밖에서 `src/welcome/` 을 부를 수 있는 것은 gsap 과 닿지 않는 순수 모듈뿐이다 — 지금 작업 트리에서 `worker/welcomePage.ts` 가 `src/welcome/storyDoc.ts`(문자열 데이터 + `brand.config`)를 import 하는 것이 이 경우다. 이유: `worker/` 가 gsap 에 닿으면 wrangler 가 워커 번들에 gsap 을 넣고, 앱 코드가 닿으면 공유 청크(`createEditor-*.js` 등)로 새어 앱 사용자 전부가 받는다
- `src/welcome/` 은 `src/app/` 등 앱 모듈을 import 해도 된다(지금 `createEditor`·CSS `?inline` 을 그렇게 받는다). 방향은 한쪽뿐이다
- 확인 방법: 단위 테스트 `src/welcome/gsapBoundary.test.ts`(8.1). 빌드 산출물 검사는 수용 기준 A3(사람/에이전트가 명령으로)

### 3.3 저작권 주석 보존 — `vite.config.ts`

- 최상위에 `esbuild: { legalComments: 'eof' }` 를 둔다. 결과: `/*! … */`·`@license` 주석이 각 청크 끝으로 모인다
- 비용: `welcome-demo.js` +865 B, 앱 JS 전체 +2,817 B(0장 m5). 한 번 모든 청크의 해시가 바뀌어 기존 사용자 precache 가 한 번 새로 받는다 — 배포 한 번의 비용이다
- 랜딩 번들에만 거는 방법은 찾지 못했다 — Rollup `output.banner` 는 esbuild 압축이 지웠다(m5)

## 4. 캐시·precache

### 4.1 `welcome-demo.js` 는 매번 다시 확인한다 — `public/_headers`

`/assets/*` 규칙 **아래에** 다음 규칙을 더한다. `!` 줄이 없으면 값이 이어 붙어 immutable 이 남는다(0장 m9).

```
/assets/welcome-demo.js
  ! Cache-Control
  Cache-Control: no-cache
```

- 이유(m8): 랜딩 HTML 은 `no-store` 인데 `welcome-demo.js` 는 이름이 고정인 채 1년 immutable 이다. 스토리 연출은 HTML 의 마크업(`.story`·`#story-editor` 등)과 JS 가 서로 맞아야 도는데, 배포 뒤 돌아온 방문자는 새 HTML + 옛 JS 를 받는다. 옛 JS 가 부르는 옛 해시 `createEditor-*.js` 는 새 배포에 없어 모듈 로드가 실패한다 — 방문자는 5.1 의 정적 상태만 본다. 연출을 tweak 로 자주 고칠 것이라 이 어긋남이 매 배포마다 생긴다
- `no-cache` 는 매번 서버에 묻지만 바뀌지 않았으면 `304` 로 끝난다(ETag 가 이미 나간다, m8). 해시 청크(`createEditor-*.js` 등)는 immutable 그대로다
- 이 문제는 GSAP 이전부터 있던 것이다(F-239 이후). 여기서 같이 고치는 이유는 이 명세의 연출 반복이 그것을 매 배포 드러나게 만들기 때문이다. 따로 떼어 "명세 밖 버그 수정" 으로 먼저 커밋해도 된다(main 판단)

### 4.2 앱 precache 에서 뺀다 — `vite.config.ts` `workbox.globIgnores`

`globIgnores: ['og-image.png']` → `['og-image.png', 'assets/welcome-demo.js']`

- 이유: 서비스 워커가 제어하는 브라우저는 랜딩을 보지 않는다. `/` 탐색은 `navigateFallback: 'index.html'` 로 앱이 뜨고(F-271 6장), `/welcome` 은 denylist 라 네트워크로 가서 `301` → `/` 가 되고 그 `/` 가 다시 앱이다. 그러니 precache 된 `welcome-demo.js` 는 쓰일 일이 없다
- 효과(m6): gsap 을 넣은 뒤에도 앱 사용자 precache 는 **지금보다 286,404 B 줄어든다**(빼지 않으면 +114,071 B). 연출 코드가 커져도 앱 사용자에게는 0 이다
- 부수 효과: m7 의 `revision:null` 문제(고정 이름 파일이 precache 에서 갱신되지 않을 수 있음)도 사라진다
- 서비스 워커가 있는 브라우저에서 드물게 랜딩이 떠도(강제 새로고침 등) `welcome-demo.js` 는 네트워크에서 온다 — 오프라인 랜딩은 원래 목표가 아니다

## 5. 가드레일 — 연출이 무엇이든 지킬 것

연출(장면·타이밍·문구)은 명세 밖이지만, 아래는 연출을 어떻게 고쳐도 성립해야 한다. 각 줄의 판정은 8장 테스트다.

### 5.1 JS 없이도 완성 텍스트 (F-239 2.1 마지막 불릿 유지)

- 워커가 내는 HTML 에 **모든 구간 제목·장면 설명·예시 문서·터미널 줄·CTA 가 완성된 글자로** 들어 있고, CSS 만으로(스크립트 없이) 보인다. `visibility: hidden`·`opacity: 0`·`display: none`·`clip-path`·`color: transparent` 로 글을 숨기는 규칙은 **JS 가 붙인 클래스·인라인 스타일 아래에서만** 효력이 있어야 한다. 지금 작업 트리의 `.story.is-live …` 규칙과 구간 제목 타이핑(스크립트가 화면 진입 때 글자를 `visibility: hidden` 으로 나눠 치는 방식)이 이 규칙을 따른다
- 구간 제목 타이핑(사용자 결정 7): "등장 전에 숨긴다" 의 숨김은 스크립트가 한다. 이미 보이던 글자가 지워졌다 다시 써지는 모양은 연출 판단(사람 확인 H3)
- `welcome-demo.js` 가 **받아지지 않거나 실행 중 예외로 멈춰도** 5.1 첫 불릿 상태가 보인다. 그래서 스토리를 숨기거나 겹치는 클래스(`is-live`)는 편집기 마운트와 스크롤 연결이 끝난 뒤에 붙이거나, 준비 중 예외가 나면 떼어 정적 상태로 돌아가야 한다(순서는 구현 판단 — 판정은 E4)
- 크롤러용 사실 확인: 기존 `worker/welcomePage.test.ts` A2(헤드라인 두 줄, `## 회의록`, `다음 회의는 **금요일 오후 2시**입니다` 가 태그를 벗긴 HTML 에 있음)는 그대로 통과해야 한다. 예시 문서를 바꾸면 A2 의 두 문자열도 연출과 같이 바꾼다 — 그때는 "마크다운 기호가 원문 그대로 HTML 에 있다" 는 A2 의 취지(`#`·`*` 가 문자열째 존재)를 유지한다

### 5.2 움직임 줄이기

- `prefers-reduced-motion: reduce` 면 **핀 고정·스크럽·타이핑을 하지 않는다.** ScrollTrigger 로 핀을 만들지 않으므로 `.pin-spacer`(ScrollTrigger 가 핀에 씌우는 요소 클래스, `ScrollTrigger.js` 에서 확인)가 문서에 없다. 스토리 구간에 `is-live` 가 붙지 않는다
- 각 장면은 완성 상태로 문서 흐름대로 읽힌다(사용자 결정 8). 실제 편집기를 띄우는지는 연출 판단 — 띄우면 그 편집기도 완성 문서를 담는다
- design.md 4장 "움직임 줄이기" 행(전환 없음, 반복 움직임 포함)의 랜딩 적용이다

### 5.3 색·이름 불변조건

- 무대 다크 색은 `src/styles/tokens.css` `:root[data-theme='dark']` 값의 **사본 한 벌**을 `worker/pageTokens.ts` 에만 둔다(`PAGE_DARK_VARS`). 랜딩 흰 색 사본 `PAGE_TOKENS_CSS` 와 같은 선례(F-2033 6.3). `worker/welcomePage.ts`·`src/welcome/*` 에 색 hex 를 새로 쓰지 않는다. 브랜드색은 `brand.config.ts` 에서 읽고 파생은 `color-mix()`
- 제품명은 `brand.config.ts` 에서만 읽는다(F-239 A5 와 같은 규칙). 터미널 장면의 CLI 명령 이름도 `brand.cliName` 에서 읽는다 — 10장 Q5
- 페이지 전체에 `data-theme` 을 켜고 끄는 방식이면(작업 트리 `story.ts` 가 그렇게 한다), 스토리를 벗어나거나 페이지를 떠날 때 원래 값(없음)으로 돌아간다. 랜딩에는 앱 설정 저장소가 없으므로 이 값은 localStorage 에 쓰지 않는다

### 5.4 포지셔닝 문구

- F-239 §0 의 "실시간 협업·동시 편집·댓글 앵커 문구를 쓰지 않는다" 는 **낡았다** — 셋 다 배포됐다(F-307 접속자 표시·원격 커서 `4ef0ba4`, F-504 댓글 앵커·위치 따라가기 `afc811c`, F-503 `00a1e01`, 모두 `origin/deploy` 조상. 2026-09-27 `git merge-base --is-ancestor` 확인). 장면 ③·④ 는 이 기능을 보여준다. 고칠 문장은 11장
- 아직 없는 것은 쓰지 않는다: **"MCP"**(로컬 MCP 는 다음 명세, product.md Q44), 국내 리전. CLI 명령은 실제 있는 것만(`new`·`put` — `cli/src/args.ts` 에 있음)
- 장면 ③ 의 두 번째 커서는 편집기 위에 그린 흉내이고 실제 접속이 아니다(사용자 결정 4). 랜딩이 서버에 연결하거나 Yjs 방에 들어가지 않는다 — 랜딩 페이지 JS 가 `/ws/*`·`/api/*` 로 요청을 보내지 않는다(E6)

### 5.5 조기 판정·CTA 무변경 (F-271 4장)

- `<head>` 맨 위 조기 판정 인라인 스크립트(`earlyScript`), CTA 스크립트(`ctaScript`), `data-cta="enter"`·`data-cta="login"` 링크, `.cookie-escape` 는 이 명세와 연출이 건드리지 않는다. GSAP 초기화는 이 스크립트들보다 뒤(`<script type="module">`)에 돈다. 조기 판정이 `reload()` 하는 경우 GSAP 은 받기 전에 페이지를 떠난다
- `e2e/landing.spec.js` 기존 6개(F-271 A6~A11)가 그대로 통과한다

### 5.6 좁은 창 가로 넘침 없음

- 창 폭 390px 에서 랜딩을 위에서 끝까지 스크롤하는 동안 `document.documentElement.scrollWidth` 가 창 폭을 넘지 않는다. 핀 고정·겹침(사용자 결정 8)·SVG 위키 지도·터미널 줄 모두 포함(E3)

### 5.7 크기 예산

- `dist/assets/welcome-demo.js` 는 **460,000 B 이하**(압축 전). 지금 GSAP 포함 400,475 B + 주석 865 B(m1·m5)에 연출 코드 몫 약 58KB 를 더한 값이다. 넘으면 무엇이 들어왔는지 보고 이 수치를 명세에서 고친다(10장 Q6)
- 앱 산출물에 gsap 이 없다: `dist/assets/` 중 `welcome-demo.js` 를 뺀 `.js` 에 문자열 `GreenSock` 이 0회(A3). 3.3 의 `legalComments` 때문에 gsap 이 앱 청크로 새면 이 주석이 따라 나오므로, 이 문자열이 새는 것을 잡는 표지가 된다

## 6. 상태·오류·접근성

- 스크롤 스토리 무대의 편집기는 연출 장치다. 방문자가 조작할 수 있게 둘지(`inert` 여부)는 연출 판단. 다만 **키보드 사용자가 스토리 구간을 Tab 으로 지나갈 수 있어야 한다** — 무대가 포커스를 가두지 않는다(사람 확인 H4)
- 스토리 텍스트(장면 설명)는 스크린리더가 읽을 수 있는 실제 텍스트다(5.1 의 정적 HTML 이 그대로 DOM 에 남는다). 편집기 캔버스 안 연출에만 기대는 정보(예: `.md` 바이트 수)는 정적 HTML 에도 같은 뜻의 문장이 있다
- 창 크기가 바뀌면 ScrollTrigger 가 다시 잰다(ScrollTrigger 기본 동작). 웹 서체가 늦게 와 높이가 바뀌는 경우 `document.fonts.ready` 뒤 한 번 다시 잰다(작업 트리 `story.ts` 가 이미 그렇게 한다). 판정은 사람 확인 H2
- 오류 표시는 두지 않는다 — 5.1 의 정적 상태가 곧 대체 화면이다. 콘솔 오류는 E4 가 허용한다(모듈 로드 실패는 브라우저가 찍는다)

## 10. 열린 질문 (모두 기본값이 있다 — 기본값대로 간다)

### Q1 라이선스 주석을 남길지 (기본값: 남긴다, `legalComments: 'eof'`)

- 라이선스 III 의 "Remove or alter any proprietary notices" 가 압축 빌드에서 주석이 빠지는 것까지 뜻하는지는 문안만으로 분명하지 않다. 남기는 쪽이 비용(앱 +2,817 B)보다 안전하다
- 다른 쪽(남기지 않음)을 고르면: `vite.config.ts` 는 4.2 한 줄만 바뀌고 A3 의 `standard-license` 확인과 5.7 의 표지 설명이 빠진다. 대신 GSAP 고지를 랜딩 꼬리 등 다른 곳에 적을지 사람이 정해야 한다
- **사람이 한 번 읽어 볼 것을 권한다** — 판단의 근거가 법률 문안 해석이다

### Q2 버전 고정 방식 (기본값: 정확히 `3.15.0`)

- 라이선스 VI(Amendments)가 새 문안은 새 버전부터 적용된다고 적는다. `^3.15.0` 이면 `npm update`·lockfile 재생성 때 문안이 바뀐 버전이 모르게 들어올 수 있다. 저장소의 다른 의존성은 `^` 를 쓰지만 gsap 만 예외로 둔다
- `^` 를 고르면: B4 를 "3.15.0 이상 4 미만" 으로 바꾸고, 올릴 때마다 라이선스 페이지 날짜를 확인하는 절차를 `deploy` 스킬 등에 따로 둬야 한다

### Q3 허용 플러그인 (기본값: `ScrollTrigger` 하나)

- 3.15.0 에는 `SplitText`·`ScrambleTextPlugin`·`DrawSVGPlugin` 등이 무료로 들어 있다. 연출 중 쓰고 싶어질 수 있다(예: 위키 지도 선 그리기에 `DrawSVGPlugin`)
- 기본값 이유: 크기(5.7)와 "의존성 경계" 를 한 곳에서 보게 하려고. 늘리려면 이 명세 3.2 허용 목록과 B2 를 고치는 한 줄 수정이면 된다(명세 수정 → 사람 승인)
- 다른 쪽(같은 패키지 안이면 자유)을 고르면: B2 가 `gsap/` 아래 아무 경로나 허용하되 `gsap/all`·`gsap/dist/*` 만 막고, 5.7 예산이 유일한 제동이 된다

### Q4 경계 검사를 무엇으로 (기본값: 단위 테스트 `gsapBoundary.test.ts`)

- ESLint `no-restricted-imports` 는 편집 중에 바로 알려 주지만, 파일 단위 `eslint-disable` 로 꺼질 수 있고 B3 같은 간접 도달은 못 본다. `npm run review` 의 금지 패턴은 바뀐 줄만 본다
- ESLint 를 고르면: `eslint.config.js` 가 소유 표에 들어가고, B3 는 여전히 테스트로 남는다

### Q5 터미널 장면의 명령어 이름 (기본값: `brand.cliName` 에서 읽는다 — 이미 그렇게 돼 있음)

- `brand.config.ts` 에 `cliName: 'rawdoc'`(F-2021 8장)이 있고, 작업 트리 `src/welcome/storyDoc.ts` 가 `const cli = brand.cliName` 으로 명령 이름을 만든다(확인함). 명령어 문자열도 리터럴로 쓰지 않는다
- 다른 쪽(리터럴 `rawdoc`)은 고르지 않는다 — 불변조건 문장과 겹치고, 이미 필드가 있다

### Q6 크기 예산 460,000 B (기본값)

- 근거는 5.7. 목표치가 아니라 "뭔가 크게 딸려 들어왔다" 를 잡는 상한이다. 연출이 예산을 넘기면 원인을 보고한 뒤 이 값을 고친다
- 예산을 두지 않으면: A5 가 "바이트 보고" 로만 남는다

### Q7 gsap 을 동적 import 로 늦출지 (기본값: 정적 import)

- 움직임 줄이기 방문자(5.2)는 gsap 이 필요 없다. 동적 `import('gsap')` 로 나누면 그들은 약 45KB(gzip)를 아낀다
- 기본값 이유: 사용자 결정 1 이 "랜딩 번들에 넣는다" 이고, 나누면 해시 이름 청크가 하나 더 생겨 4.2 의 `globIgnores` 도 그 청크를 따라 넓혀야 한다. 편집기 청크(gzip 약 505KB)를 이미 받는 페이지라 이득이 작다
- 동적 import 를 고르면: B1~B3 는 그대로, 4.2 에 gsap 청크 패턴을 더하고, A3·A5 의 대상 파일이 둘이 된다
