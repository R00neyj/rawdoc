## 2. 판정
```ts
export type ExternalChange = 'none' | 'reload' | 'conflict' | 'missing'
export function decideExternalChange(i: { known: number; current: number | null; dirty: boolean }): ExternalChange
export function readDiskStamp(handle: FileSystemFileHandle): Promise<number | null | 'unknown'> // NotFoundError → null, 그 밖 실패 → 'unknown'
```
- `current === null` → `missing`(dirty 무관). `current === known` → `none`. 다르면(작아져도) `dirty` 면 `conflict`, 아니면 `reload`. `'unknown'` 은 판정하지 않고 넘어간다(이번 계기 무시)
- **쓰기 직전** — 마운트 때 `setBeforeWrite(guard)`. 띠가 떠 있으면 읽지 않고 거짓. 아니면 `readDiskStamp(session.handle)` → `decideExternalChange({ known: session.lastModified, current, dirty: true })` → `none`·`'unknown'` 이면 참, `conflict`·`missing` 이면 띠를 띄우고 거짓(쓸 때는 늘 dirty 라 `reload` 는 없다). 인자 `session` 만 보므로 언마운트 뒤 불려도 판정은 같고 띠만 못 띄운다. **언마운트 때 `setBeforeWrite(null)` 하지 않는다** — 진행 중 쓰기 루프가 가드 없이 쓰는 틈을 막는다. 다음 마운트가 덮어쓴다
- **창 `focus`, `visibilitychange` 로 보일 때** — 판정 하나만 진행(겹친 계기는 버림). 먼저 `await flush()` — 진행 중 쓰기가 `lastModified` 를 갱신하기 전에 읽으면 거짓 충돌이 난다(대기 쓰기는 가드를 거쳐 그 자리에서 쓰인다). 그다음 최신 세션으로 `readDiskStamp` → `decideExternalChange({ known: session.lastModified, current, dirty: hasUnwritten })`. 결과가 띠 상태를 늘 새로 정한다: `none` → 띠 걷음(되살아난 파일이면 다음 입력부터 자동 저장), `reload` → 3장, `conflict`·`missing` → 그 띠
- 폴링 없음. 여는 순간은 판정하지 않는다(방금 읽었다). 띠는 `session.key` 가 바뀌면(다른 파일) 걷는다
## 3. 동작
- **`reload`**(내 변경 없음): `getFile()` → `decodeMarkdown` → `remount({ text, lineEnding, hadBom, lastModified })` → 알림(info) `다른 프로그램에서 바뀐 내용을 불러왔습니다.`, 섞인 줄바꿈이면 대신 `다른 프로그램에서 바뀐 내용을 불러왔습니다. 줄바꿈 형식이 섞여 있어 저장하면 CRLF 로 통일됩니다.`. 새 마운트라 커서는 문서 처음·스크롤 맨 위·실행 취소 기록 없음, 보기 모드는 그대로(이 화면 보기 모드면 `Viewer` 도 새 본문). 위치 보존은 하지 않는다
- 다시 읽기 중 `NotFoundError` → `missing` 띠. UTF-8 아님 → 편집기 그대로, F-2154 3장 not-utf8 알림 + `conflict` 띠(파일이 내 화면과 다르므로 덮어쓰기·가져오기를 고르게)
- 재마운트는 버튼 누름·창 포커스 때만 일어나 조합 중일 수 없다. 열린 `Y.Doc` 에 쓰지 않는다(F-2154 1장)
- **띠** `.local-file-banner`(`role="alert"`, `.local-file-head` 바로 아래, 문구 + `.local-file-banner-actions` 버튼). 닫기 `×` 없음 — 고르거나 다음 판정으로만 걷힌다
| 띠 | 문구 | 버튼 → 동작 |
| --- | --- | --- |
| `conflict` | `다른 프로그램이 이 파일을 바꿨습니다.` | `다시 불러오기` → 위 다시 읽기(내 변경 버림, 알림 없음) · `내 내용으로 덮어쓰기` → `canWrite` 거짓이면 먼저 `grantWrite()`(누름 = 사용자 동작), 그 뒤 `canWrite` 면 `saveNow({ skipGuard: true })`, 참이면 띠 걷음 · `` `${brand.name} 문서로 가져오기` `` → `importToDoc()` |
| `missing` | `파일을 찾을 수 없습니다. 옮겨졌거나 지워졌습니다.` | `` `${brand.name} 문서로 가져오기` `` → `importToDoc()` · `.md 내보내기` → `downloadBlob(new Blob([encodeMarkdown(readText(), { hadBom })]), session.name)` |
- `내 내용으로 덮어쓰기` 뒤 `lastModified`: `saveNow` 가 쓰기 끝에 `getFile().lastModified` 를 세션에 넣는다(F-2155 3장) → 다음 판정의 `known`. `saveNow` 가 거짓이면 띠 그대로(실패 알림은 F-2155)
- **띠 동안**: 자동 저장·`Ctrl+S` 는 가드가 거짓이라 쓰지 않는다(Ctrl+S 는 무동작, 내보내기도 안 뜸). 입력은 된다. 상태 글자는 `useLocalFile` 의 `status` 대신 `저장 멈춤`·error 점(`입력 중…` 이 계속 떠 있으면 거짓말). 떠나기는 F-2155 4장 그대로 — 마지막 쓰기가 가드에 걸려 sticky 알림 + `.md 내보내기`, `beforeunload` 는 `hasUnwritten`
- **`missing` 은 쓰지 않는다**: 없어진 handle 에 `createWritable()` 로 파일을 되살리지 않는다. 사용자가 파일을 되돌려 놓으면 다음 판정에서 걷힌다
