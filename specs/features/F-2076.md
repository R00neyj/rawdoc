## 2. 경계 — 훅·컴포넌트 몇 개로, 무엇을 받는가

### 2.1 원칙

1. **상태·effect·핸들러는 훅으로, JSX 는 상태 없는 컴포넌트로.** 컴포넌트는 훅을 부르지 않는다(3.1). 컴포넌트 안으로 `useState` 를 옮기면 그 상태가 컴포넌트 마운트와 함께 초기화돼 동작이 바뀐다 — 예: 댓글 버튼 자리 `floatingCommentAnchor` 는 지금 App state 라 문서 화면을 떠났다 돌아와도 남는다
2. **props 이름은 App 변수 이름과 같다.** 옮긴 JSX 가 같은 이름을 읽어 `--color-moved` 에서 이동색으로 남는다(F-2059 3.6). 호출 표기는 9장 Q3
3. **React Context 는 쓰지 않는다.** 이유:
   - 리렌더 비용이 줄지 않는다. `React.memo` 가 0건이고 React Compiler 도 없어, App 이 다시 그려지면 자식은 props 가 같아도 다시 그려진다. Context 값을 App 에서 매 렌더 새 객체로 만들면 모든 소비자가 역시 다시 그려진다. 값을 `useMemo` 로 묶으려면 deps 가 수십 개라 옮기기가 아니게 된다
   - 데이터 흐름이 숨는다. props 는 `tsc` 가 빠진 이름을 잡고, 컴포넌트 함수를 직접 불러 엘리먼트 트리를 검사하는 단위 테스트(`EmptyState.test.tsx` 선례)가 그대로 된다. Context 소비자는 Provider 없이 불리면 기본값을 읽어 테스트가 어렵다
   - 이미 있는 두 Context(`CommentCommandContext`·`MentionSourceContext`)는 `DocumentArea` 안으로 JSX 그대로 옮겨 간다
4. **훅 반환값은 지금처럼 구조 분해한다.** 훅 반환 객체를 통째로 컴포넌트에 넘기는 "묶음 props" 는 쓰지 않는다 — 지금 구조 분해된 이름(예: `useAppearancePrefs` 반환 26개)을 다시 묶으면 App 쪽 참조가 `x.y` 로 바뀌어 옮기기가 아니게 된다

## 3. 단계 4 규칙 (F-2059 3.1~3.8 에 더한다)

### 3.1 컴포넌트 규칙

- 컴포넌트 파일은 **컴포넌트 하나(`export default`)와 `export type` 만** 내보낸다. 함수·상수를 함께 export 하면 `react-refresh/only-export-components` 오류다(스크래치패드 실측). 모듈 내부 함수·상수(`clampFabY`·`NO_PEERS`·`const MapPage = lazy(…)`)는 export 하지 않고 둔다
- 컴포넌트는 **훅을 부르지 않는다.** 그래서 `EmptyState.test.tsx` 처럼 컴포넌트 함수를 직접 불러 엘리먼트 트리를 검사할 수 있다(jsdom 없이, F-2059 전제 7)
- 렌더 중 ref 의 `.current` 를 읽는 JSX(`<Editor autoFocus={focusTitleRef.current ? 'title' : focusEditorRef.current}>`, `<CommentRailPanel scrollElement={editorRef.current?.view.scrollDOM ?? null}>`)는 **컴포넌트 파일에서 `react-hooks/refs` 오류**다(실측). 처리는 9장 Q4
- DOM 순서·`className`·`data-*`·`aria-*`·`hidden`·`inert`·`key` 는 바이트 그대로(F-2059 3.6)
- 컴포넌트 안 조건 렌더(`{showEditor && …}` 류)는 옮긴 JSX 그대로다. `AppScreens` 의 다섯 갈래 우선순위(공유 보기 > 공유 관리 > 도움말 > 지도 > 홈)는 단위 테스트로 고정한다(5.1)

### 3.2 훅 호출 자리 — 흩어진 구역을 모을 때

F-2059 3.8 "옮긴 절이 있던 자리에서 부른다" 는 그대로다. 한 훅이 여러 자리의 코드를 모으면(팔레트 ≈1244·≈2006·≈3077·≈3163·≈3209, 문서 이동 ≈2606~≈3443) **effect 를 가진 덩어리의 자리**에서 부른다. 자식 명세는 모으는 덩어리마다 "사이에 낀 effect 목록" 을 적고, effect 가 없는 덩어리(함수·`useMemo`·파생값)만 자리를 옮긴다.

- 문서 이동 훅: 안의 effect 는 최신값 effect ⑤(`openWikiLinkRef`) 하나다. 호출 자리를 `createNewDoc` 자리(≈2606)로 정하면 ⑤ 가 `useSharesPage`(≈2720)의 effect 보다 먼저 돈다. ⑤ 는 ref 대입뿐이고 `useSharesPage` 는 그 ref 를 읽지 않는다(`grep`) — F-2082 가 이 판정을 다시 확인한다
- 팔레트 조립 훅: effect 없음. 단축키 판 훅: effect 하나(판이 자리를 잡은 뒤 커서 스크롤) — 지금 자리(≈3153)에서 부른다

## 9. 열린 질문 / 사람 결정 필요

### Q1. D1 판정 — **결정(2026-09-28, 사용자): 7장 안 그대로**

- 이유: 도달 가능한 칸만 버그로 보면 고칠 곳이 둘이고, 나머지는 판정만으로 F-2082 를 옮기기로 끝낼 수 있다
- 다른 쪽(✗ 칸을 모두 `createNewDoc` 과 같게 맞춘다): 규칙이 하나라 읽기 쉽다. 대신 닿지 않는 코드에 줄이 늘고, F-2082 전에 `App.tsx` 수정 커밋이 하나 더 필요하다

### Q2. 목표 줄 수 — **결정(2026-09-28, 사용자): 약 1,270(범위 1,220~1,350)을 단계 4 의 끝으로 받아들인다**

- 이유: 전제 3(F-2059 2.2 를 그대로)이 App 에 약 700줄을 못 박는다(1.3). 이 틀 안에서 더 줄이려면 넘김값만 옮기는 껍데기 컴포넌트가 늘어난다
- 다른 쪽(단계 4b 를 더해 약 970): 추가 자식 하나. 대상과 어림 — 목록 다시 읽기 허브(`applyResyncResult`·`resyncFromStore`·`resyncFromCache`·`listRefresher`·`listSource`) → `useDocListSync` 약 −90, 잠금·탭 동기화(`handleLockReacquired`·`useDocLock`·`handleClaimRegained`·`claimDocId`·`useTabSync`) → `useDocClaims` 약 −60, 저장소 영속화·새 버전 알림 → `useAppLifecycleNotices` 약 −40, 자동 저장 콜백(`handleDocSaved`·`handleSaveError`) 약 −35, `<Sidebar>` 넘김값 → `AppSidebar` 약 −46, 동기화 구독 약 −5. **F-2059 2.2 를 고쳐야 한다**(`resyncFromStore`·`keepLiveTitle` 를 허브 목록에서 뺀다) — 전제 3 을 바꾸는 것이라 사용자 결정이다

### Q3. 컴포넌트 넘김 표기 — **기본값: 한 줄에 여러 이름을 담는 펼침 `<X {...{ a, b, c }} />`**

- 이유: 훅 호출의 "한 줄 여러 이름"(F-2066~F-2074)과 같은 모양이다. props 이름 = App 변수 이름이라 가능하다. `DocumentArea`(약 50개)가 약 6줄이 된다
- 다른 쪽(`a={a}` 한 줄에 하나): JSX 관례대로 읽힌다. 대신 컴포넌트 다섯의 넘김이 약 190줄이라 단계 4 감소가 약 170줄 준다(App 약 1,440)
- 알아 둘 것: JSX 펼침은 `tsc` 가 **빠진 필수 prop** 은 잡지만 **남는 이름**은 잡지 않는다. 자식 명세는 props 타입의 모든 필드를 필수로 둬 빠짐을 막는다

### Q4. 컴파일러 진단 중 동작을 바꾸지 않고는 못 푸는 것 — **결정(2026-09-28, 사용자): (a) 표에 적은 자리만 `eslint-disable-next-line react-hooks/refs` + 한 줄 이유를 허용**

해당 자리(3.3 표): 렌더 중 ref 를 **함수·훅에 넘기는** 것(`createExportActions` 인자, `listRefresher` 초기화, `listSource` 안 `liveChangedAtRef`)과 렌더 중 ref 를 **읽는** 것(`canInsertTemplate`, `<Editor autoFocus>`, `<CommentRailPanel scrollElement>`), `tabIdRef.current` 두 곳.

| 안 | 내용 | 바뀌는 것 |
| --- | --- | --- |
| (a) 기본 | 위 자리만 끄기 한 줄. `tabIdRef` 는 (b)로 푼다 — `newTabId()` 값을 `useState` 초기값으로 한 번 만들고 ref 는 그 값으로 만든다. 탭 id 는 페이지 수명 동안 바뀌지 않아 동작이 같다 | F-2059 3.7 에 예외 한 줄(8장). 끄기 줄 수는 F-2080·F-2078·F-2081 명세가 셀 때 최대 8 |
| (b) 상태로 바꾼다 | `canInsertTemplate` 는 `editorHandle !== null`, 포커스 요청은 state, `scrollElement` 는 `editorHandle?.view.scrollDOM` | 렌더 시점 값이 달라질 수 있다(D16). 포커스 요청 플래그를 state 로 바꾸면 전환마다 렌더가 한 번 는다 — 옮기기가 아니다 |
| (c) App 에 남겨 컴파일러가 계속 포기하게 둔다 | 해당 계산을 App 에 두고 값만 넘긴다 | 원인 구문을 몰라 언제 깨질지 모른다. F-2081 뒤 App 이 분석되면 그때 오류가 된다 |

- 이유(기본값): 이 코드는 지금 App 안에서 규칙 밖에 있을 뿐 동작은 검증돼 있다. (b)는 D16 처럼 판정이 따로 필요한 차이를 만든다
- 판정 뒤 F-2080 명세가 자리별로 처리를 확정한다

### Q6. 계정 상태를 `useAccountStatus` 로 옮기나 — **기본값: 옮긴다(F-2079)**

- 이유: F-2059 2.2 허브 목록에 `applyAccountFlags`·`recheckAccount` 가 없다. 계정 상태·ref 8개·effect 4개가 한 덩어리로 약 −80
