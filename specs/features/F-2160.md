## 2. 계약 (`docUnit.ts`)
```ts
export const MAX_DOC_UNITS = 4                     // = F-2162 MAX_PANES. 서로 import 하지 않는다
export type PaneDoc = { docId: string | null }     // 칸의 활성 문서. 이번엔 [{ docId: currentDocId }] 하나
export function docUnitIds(panes: readonly PaneDoc[]): string[]   // 칸 순서, null 빼고 중복 제거, 앞 4개
export function assignDocSlots(prev: readonly (string | null)[], ids: readonly string[]): (string | null)[]
export function saverBlocked(i: { docId: string | null; openDocId: string | null; path: DocPathKind | null; claimReadOnly: boolean; deletedElsewhereId: string | null }): boolean
export function openLoadOf(i: { docId: string | null; path: DocPathKind | null; notFoundBeforeSync: boolean; everLive: boolean; forbiddenClose: boolean }): 'store' | 'server-first' | null
export function unitLocked(meta: DocMeta | null, openDocId: string | null): boolean
export type DocUnitHost = { getText: (docId: string, le: LineEnding) => string; getComments: (docId: string) => CommentRecord[] | null; onSaved: (doc: Doc) => void; onSaveError: (docId: string, error: unknown) => void }
// ↑ App 이 매 커밋 채우는 ref. 렌더 중에 읽지 않는다. getText 는 그 문서를 띄운 칸 편집기(없으면 ''), getComments 는 포커스 문서 local 경로만(그 밖 null)

// useTabSync.ts 가 내보낸다
```

- `assignDocSlots`: 길이는 늘 4. 남는 id 는 제자리, 빠진 id 자리를 먼저 비우고 새 id 를 **가장 앞 빈 자리**에. 그래서 칸 하나에서 문서를 바꾸면 늘 슬롯 0 — 지금 훅 인스턴스 하나가 docId 만 바뀌는 것과 같다(세션·저장 리셋 규칙 그대로)
- `saverBlocked` = 지금 App `blocked` 식을 문서 기준으로: `deletedElsewhereId === docId` ∨ `claimReadOnly` ∨ 경로 `realtime`·`offline-view` ∨ `openDocId !== docId`. `openLoadOf` = `useEditorSync` `openLoad` 식 그대로(`everLive` = `everLiveIds.has(docId)`). `unitLocked` = `meta?.e2ee === 'locked' && openDocId !== meta.id`. `loading` = 기존 `isDocLoading` 에 묶음 값

## 3. 문서마다 묶음 (결론 1)
- `useDocUnits(panes: PaneDoc[], shared, hostRef)` → `{ units: DocUnit[]; unitFor(id: string | null): DocUnit; flushAll(): Promise<boolean> }`. 안에서 `useDocUnit` 을 **슬롯마다 한 번씩 4번 고정으로** 부른다(훅 규칙상 반복문 금지 — 네 줄). 슬롯 표는 `assignDocSlots` 결과를 렌더 중 상태 맞추기로 든다. 빈 슬롯(`null`)은 기존 null 처리로 방 Doc·소켓·타이머·채널 메시지 0
- `unitFor(null)` 은 첫 빈 슬롯 묶음(문서 없음 상태 — 지금 홈 화면과 같은 값). `flushAll` = 모든 묶음 `saver.flush` 를 기다려 전부 `true` 일 때만 `true`. App 의 `docSaverFlushRef` 는 `flushAll` 을 가리킨다(이번엔 묶음이 하나라 지금과 같다)
- `shared` = 지금 세 훅이 App 에서 받는 창 값 그대로: `store`·`docs`·`setDocs`·`sharedDoc`·`forbiddenDocIds`·`setForbiddenDocIds`·`accountBlocked`·`bootPhase`·`convertingDocId`·`deletedElsewhereId`·`e2eeStatus`·`yjsStoreRef`·`createdHereRef`·`liveChangedAtRef`·`focusEditorRef`·`claimHub`·`focusDocId`·`setStats`. `everLiveIds` 는 슬롯이 아니라 `useDocUnits` 에 하나(문서가 슬롯을 옮겨도 "이 페이지에서 실시간으로 연 적 있음" 이 남아야 한다)
- `useDocUnit` 순서: `useDocSession` → `useDocClaim(hub, claimId)` → `useLiveRoomDoc` → 본문 1회 읽기 → `useDocSaver`. `claimId` = App 553행 식을 문서마다(`(store.kind === 'idb' \|\| docPath === 'e2ee') && !sharedDoc && !DEV_YSYNC ? docId : null`). 편집권을 되찾으면 묶음이 `store.get(docId)` 로 `reload`(잠긴 금고면 안 함 — 지금 `handleClaimRegained` 그대로)
- `setStats` 는 `docId === focusDocId` 일 때만 부른다(렌더 중 호출이라 ref 가 아니라 직접 받는다). 저장 콜백은 `hostRef` 로 — `useDocSaver` 가 이미 ref 로 감싸 effect·비동기에서만 부른다
- App 순서: `useTabSync`(채널) → `useE2ee` → `useDocUnits` → `const focus = unitFor(currentDocId)` 로 지금 이름(`docSession`·`docPath`·`isRealtime`·`liveSession`·`openDoc`·`docSaver`·`claimReadOnly`…)을 그대로 풀어 쓴다 → 나머지 소비자. `isReadOnlyDoc`·`docLoading`·`commentsMountKey` 는 `focus` 값으로
- **`currentDocId` 이름·뜻·`useDocNavigation`·창에 하나인 40개 파일은 그대로**(F-2159 4장)

## 4. 칸마다 경계 (결론 2)
- 칸마다 = 편집기(`editorRef`·`editorHandle`·`setEditorRefs`), `viewMode`, 보기 HTML(`viewerHtml`·`viewerDocId`·`viewerRef`)·`useViewFind`, `useKanbanView`, 제목 입력, `useDocTabs` 스크롤·커서 기억, 글자 수 `stats`, 떠 있는 댓글 버튼. **이번엔 늘리지 않는다** — App 에 하나씩 있는 지금 값이 곧 "포커스 칸 = 유일한 칸" 이다. 칸 컴포넌트는 `DocumentArea` 이고 문서 값은 `unit` prop 하나로만 받는다(F-2163 이 칸마다 `unitFor(pane.docId)` 를 넘긴다)
- `panes` 는 App 한 줄 `const panes = [{ docId: currentDocId }]`(길이 1 고정). 묶음은 칸 상태를 `hostRef` 와 `focusEditorRef` 밖으로 읽지 않는다 — 칸이 늘어도 묶음 파일이 안 바뀌게
- `host.getText` 는 이번엔 `docId === currentDocId ? editorRef.current?.getText(le) ?? '' : ''`. 창 안 원본(F-2161)이 생기면 F-2163 이 여기서 원본 `Y.Text` 를 읽게 바꾼다

## 6. 단위 테스트 (결론 3, 모두 문서 둘)
- U1 `docUnitIds`: 칸 `a·b·a·null` → `['a','b']`, 빈 목록·`null` 하나 → `[]`. U2 `assignDocSlots`: `[a,∅,∅,∅]`+`[b]` → `[b,∅,∅,∅]`(칸 하나 전환은 슬롯 0) / `[a,b,∅,∅]`+`[b,c]` → `[c,b,∅,∅]`(b 제자리) / `[a,b,∅,∅]`+`[b,a]` → 그대로 / `+[]` → 모두 ∅
- U3 `saverBlocked`: `deletedElsewhereId:'a'` 는 a 만 막고 b 는 안 막음, a 의 `claimReadOnly` 는 b 와 무관, `realtime`·`offline-view`·`openDocId` 다름은 막음. U4 `openLoadOf`: `everLive` a 의 `fallback` → `server-first`, 같은 때 b `fallback` → `store`, `realtime`(4404 아님) → `null`, `docId` null → `null`
- U5 `unitLocked`: 잠긴 a·`openDocId` null → 참, 잠긴 a·이미 열린 a → 거짓, 금고 아닌 b → 거짓. U6 `openedSession`(`useDocSession.ts`): 같은 직전 세션에서 idb 문서 a → `path 'local'`, 서버 금고 문서 b → `'e2ee'`, 서버 owner 문서 → `null`(판정 대기), 두 결과의 `docId` 가 섞이지 않고 `seq` 는 각자 +1
- U7 `reduceClaim`: 같은 탭이 d1·d2 를 쥔 두 상태에 다른 탭(더 이른 `since`)의 d1 `claim-hold` → d1 `yielded`, d2 `null`
