## 3. 훅 — `src/viewer/useCodeHighlight.ts`

### 3.1 계약

```ts
export const HIGHLIGHT_WAIT_MS = 3000
export function useCodeHighlight(html: string): string
export function highlightHtmlWhenReady(html: string, waitMs?: number): Promise<string>  // waitMs 기본 HIGHLIGHT_WAIT_MS
```

`waitMs` 는 개요 4.1 시그니처에 더한 선택 인자다(테스트가 짧게 준다). 호출부는 넘기지 않는다.

### 3.2 규칙

**모듈 경계.** 이 파일은 `react` 와 `../lib/codeLang` 만 정적으로 import 한다. `codeHighlight.ts`·`codeParsers.ts` 는 `import()` 로 받고, 받은 모듈을 모듈 변수에 둬 다음부터 동기로 쓴다. 이유: 이 파일은 `App.tsx` 를 거쳐 메인 청크에 든다 — 정적 import 하면 개요 A2(`index` 에 `highlightTree` 0건)가 깨진다. 엔진 모듈 `import()` 자체가 실패하면 그 탭에서 다시 부르지 않는다(1.4 와 같은 규칙).

**공통 — 언어 없는 html.** `codeLangIdsInHtml(html)` 이 빈 배열이면 두 함수 모두 받은 문자열을 **그대로**(같은 값) 내고 아무것도 import 하지 않는다. 코드블록이 없거나 언어 없는 문서는 지금과 바이트·동작이 같다.

**`highlightHtmlWhenReady`** — 절대 거부하지 않는다.
1. 엔진 두 모듈과 그 html 의 언어마다 `loadCodeGrammar` 를 기다린다. 각 로드의 거부는 `null` 로 본다
2. 이 기다림 전체를 `waitMs` 와 겨룬다. 시간이 다 되면 기다리지 않고 3으로 간다. 진행 중인 로드는 버리지 않는다 — 끝나면 모듈 캐시에 남아 다음 호출·보기 화면이 쓴다
3. 엔진이 있으면 `highlightHtmlCodeBlocks(html, id => loadedCodeGrammar(id)?.parser ?? null)` 결과를, 엔진이 없거나 이 단계가 던지면 받은 html 을 낸다

상한 3,000ms 근거: 문법 청크는 precache 에 들어 있어(개요 M1, `globPatterns` `**/*.js`) 보통 디스크에서 바로 온다. 상한은 서비스 워커 설치 전 첫 방문에서 네트워크가 멈춘 경우에만 걸린다 — 그때 인쇄·내려받기가 끝없이 멈추는 대신 3초 뒤 못 받은 블록만 단색으로 낸다. 알림은 띄우지 않는다(글자는 다 있고 색만 빠진다).

**`useCodeHighlight`** — 기다림 상한 없음(화면은 나중에 다시 칠하면 된다).
- 반환값은 `[html, 갱신 번호]` 를 의존으로 한 `useMemo`: 엔진 모듈이 이미 있으면 위 3단계의 동기 칠하기 결과, 없으면 받은 html. 문법이 다 있으면 첫 렌더부터 칠한다(깜빡임 없음)
- `[html]` 의존 effect: 엔진이 없거나 html 의 언어 중 `loadedCodeGrammar` 가 `null` 인 것이 있으면 엔진과 그 언어들을 불러온다. 끝난 뒤 **새로 불러와진 것(엔진 또는 문법 하나라도)이 있을 때만** 갱신 번호를 올려 다시 그린다. 실패한 언어는 `loadCodeGrammar` 가 바로 `null` 을 내므로 다시 그리지 않는다 — 다시 그림이 반복되지 않는 근거다
- 언마운트나 html 변경 뒤에 끝난 로드는 갱신 번호를 올리지 않는다(취소 플래그)
- 다시 그리면 `Viewer` 의 `[html]` effect 가 다시 돈다 — 첨부 이미지 다시 채우기·mermaid 다시 그리기·머리줄 다시 감싸기. 언어당 그 탭에서 한 번이고 개요 4.1 이 받아들인 비용이다(사람 확인 H1)

**안전.** 칠한 html 은 `Viewer` 가 `dangerouslySetInnerHTML` 로 넣는다. 코드 글자 이스케이프는 `highlightHtmlCodeBlocks` 계약(개요 1.4, F-2123 A5)에 기댄다 — 이 파일에서 문자열을 더 만들지 않는다.

## 5. 문법 캡션 (`markdownSyntax.ts`)

`코드블록` 항목에 `caption` 을 단다. 문자열(ia.md 6장 표에 넣을 값):

| 개념 | 화면 문구 |
| --- | --- |
| 도움말·`syntax` 코드블록 캡션 (F-2126) | `` 언어 자리에 `ts`·`py`·`sh`처럼 적으면 편집·원문·보기 모드와 인쇄·HTML 파일에서 구문에 색이 입혀집니다. 원문은 바뀌지 않습니다. 색을 입히는 언어: JavaScript·TypeScript·CSS·HTML·XML·JSON·YAML·Python·SQL·Shell. `` |

- 목록 부분은 손으로 적지 않고 `HIGHLIGHT_LANG_LABELS.join('·')` 으로 만든다(개요 5.3 R5). `markdownSyntax.ts` 가 `./codeLang` 을 import 하게 된다 — `cli/` 번들과 `site/` 빌드가 이 파일을 거쳐 `codeLang.ts` 를 함께 묶는다. 그래서 **`codeLang.ts` 는 F-2123 뒤에도 정적 import 가 없는 순수 모듈이어야 한다**(F-2123 에 넘기는 조건, 개요 1.4 "동기, 메인 청크" 와 같은 뜻)
- 원문 예시 `` ```js\ncode\n``` `` 는 그대로(Q1). `showResult` 기본이라 도움말 결과 예시에 칠한 블록이 나오지만 `code` 는 변수 이름이라 색이 없다
- 공개 사이트 `/help` 에도 캡션 글이 나간다(같은 원본). 사이트 코드블록은 칠하지 않지만(개요 4.2) 캡션은 앱 화면을 설명하는 문장이라 맞는 말이다
- `syntax` 출력 1,817자(근거) — `syntax.test.ts` A5 그대로 통과

## 10. 열린 질문

### Q1. 도움말 코드블록 예시를 색이 보이는 코드로 바꿀 것인가 — 기본값: 그대로

지금 예시 `` ```js\ncode\n``` `` 는 결과 예시에 색이 하나도 안 나온다(`code` 는 변수 이름). 바꾸면(예: `` ```js\nconst a = 'code'\n``` ``) 캡션 바로 위에서 키워드·문자열 색을 볼 수 있다.

- 기본값 이유: 문법 예시는 "펜스 + 언어 자리" 를 보이는 것이 목적이고, 바꾸면 `helpDoc.test.ts` 원문 목록·공개 사이트 `/help`·명령줄 `syntax` 출력이 함께 바뀐다(이 명세의 소유 밖 테스트 하나가 늘어난다)
- 다른 쪽을 고르면: `markdownSyntax.ts` `코드블록` `source` 한 줄과 `tests/src/app/helpDoc.test.ts` 원문 목록 한 줄을 고친다(소유 표에 그 테스트 추가). 명령줄 출력이 몇 글자 늘지만 2,000자 상한 안
