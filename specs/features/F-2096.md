## 2. 결정

1. **탭은 로그아웃 상태에서만 보인다** — 조건은 `userCssAccountId(account) === null`(F-2095 결정 4 의 `in`→id, `offline`→저장 id, `out`→없음). 로그인했는데 계정 슬롯이 없으면 아무것도 적용하지 않는 것이 F-2095 Q1 이라, 이때 로컬 슬롯을 고치게 하면 저장만 되고 화면이 안 바뀐다. 계정 슬롯을 쓰는 길은 F-2099 가 만들므로 로그인 상태 탭(저장 위치 `계정에 저장해…` 줄, 오류 줄 포함)도 F-2099 가 연다 — **F-2096·F-2099 는 같은 배포**(F-2095 Q1 그대로)
2. **`lang-css` 는 정적 import.** M1 — 동적 import 로 줄어드는 바이트가 없다. 앱 첫 청크 변화 없음, `createEditor` 청크 약 +6.4KB gzip
3. **D-16 편집기는 CM6** — 확장은 4.1 목록만. `Tab` 은 포커스 이동(개요 5.2, `indentWithTab` 을 안 넣는다). `Mod-/` 는 `defaultKeymap` 의 `toggleComment` — F-2093 템플릿 줄 모양의 전제
4. **자동 완성은 넣지 않는다**(개요 5.9) — 열린 질문 Q1
5. **저장·적용 시점** = 문서나 이름이 마지막으로 바뀌고 400ms 뒤(개요 5.2), 그리고 D-16 을 닫을 때. 한 번에 `saveLocalSnippets` 한 번 — 원문 저장·부팅 값·`notifyUserCssChanged('self')` 가 같은 호출이라 적용은 F-2095 가 한다
6. **IME:** 400ms 가 찼을 때 `view.composing` 이면 저장하지 않고, 그 뷰의 `compositionend` 에서 400ms 를 다시 건다. 조합 중인 글자를 저장해 스타일을 바꾸면 조합 중 레이아웃이 흔들린다 — "조합 중 원격 갱신 금지" 불변식과 같은 취지. D-16 뷰에는 미뤄 둔 재계산(decoration)이 없어 따라잡을 것은 저장 하나뿐이다. 닫을 때는 조합 여부와 무관하게 그때 문서로 저장한다(닫히면 조합도 끝난다)
7. **읽고-고치고-쓰기는 한 틱에.** 켜기·삭제·새로 만들기·D-16 저장 모두 `readUserCssSources().local` 을 그때 읽어 id 로 고친 목록을 저장한다. 다른 탭 변경을 덮지 않는다. D-16 은 열 때 원문을 한 번 읽고 다른 탭 변경을 따라가지 않는다 — 저장하면 그 스니펫은 D-16 내용이 이긴다. **저장 때 그 id 가 목록에 없으면**(다른 탭이 지움) 저장하지 않고 D-16 을 닫는다
8. **크기 상한은 입력을 막는다**(개요 3.4 "붙여 넣기로 넘으면 받지 않는다"). 다른 스니펫 원문 바이트 합(`otherBytes`, 열 때 계산) + 새 문서 바이트가 262,144 를 넘는 **문서 변경 트랜잭션은 거른다**(CM `EditorState.transactionFilter`) → 문서 그대로, 크기 상한 문구
9. **템플릿 원문은 동적 import**(F-2093 7.4) — 정적이면 `tokens.css` 원문 11.9KB 가 첫 청크에 든다

## 3. `사용자 CSS` 탭

### 3.1 자리

- 순서 `화면`·`편집기`·**`사용자 CSS`**·`데이터`·`금고`·`계정`(`TAB_ORDER`). 라벨 `사용자 CSS`
- F-2096 에서 로컬 앱(로그아웃)의 탭은 최대 5개(`계정` 은 로그인·저장 계정일 때만이라 `사용자 CSS` 와 같이 안 나온다). 키보드는 F-290 그대로

### 3.2 내용 (위에서 아래, 개요 5.1 순서)

1. `data-user-css` 가 `safe` 일 때만(F-2095 5장 — 그릴 때 `document.documentElement` 에서 읽는다): `안전 모드 — 이 창에서는 사용자 CSS 를 적용하지 않습니다.`
2. 설명 + 링크 `사용자 CSS 사용법` → `USER_CSS_GUIDE_PATH`, `target="_blank" rel="noopener noreferrer"`
3. 저장 위치 `이 브라우저에만 저장됩니다. 로그인하면 계정에 저장해 다른 기기에서도 씁니다.`
4. 목록 `ul.user-css-list[aria-label="스니펫"]`, 줄 `li.user-css-row` — `<label>` 안 `input[type=checkbox]` + 이름(한 줄, 넘치면 말줄임) · `편집` · `삭제`(`dialog-btn`). 비었으면 `스니펫이 없습니다.`
5. `새 스니펫` · `템플릿으로 시작`
6. 저장 오류 줄 `p.user-css-error[role=alert]` — 마지막 저장이 실패했을 때만, 다음 성공 저장이나 탭을 다시 그릴 때 지운다
- `.dialog-field` 를 쓰지 않는다 — F-290 A4 가 설정 라벨을 세는 선택자다
- 탭은 `subscribeUserCss` 와 `storage`(key `md.userCss`·`null`)에서 목록을 다시 읽는다

### 3.3 동작

| 조작 | 결과 |
| --- | --- |
| 체크박스 | 그 스니펫 `enabled` 뒤집고 `updatedAt` 갱신, 바로 저장(F-290 "저장 버튼 없음") |
| `새 스니펫` | `{ id: 새 id, name: 스니펫 {n}, css: '', enabled: true }` 를 끝에 저장 → 성공하면 그 줄 `편집` 버튼에 포커스 → D-16 열기. 복귀 대상이 그 버튼이 된다(`Dialog` 는 열 때 `activeElement` 를 잡는다) |

## 4. D-16 `CSS 편집`

### 4.1 편집기 (`createUserCssEditor`)

확장 — 이 목록만:
`history()`, `drawSelection()`, `indentOnInput()`, `bracketMatching()`, `closeBrackets()`, `syntaxHighlighting(classHighlighter)`, `new LanguageSupport(cssLanguage)`(자동 완성 없음 — `css()` 대신), `EditorView.lineWrapping`, `EditorView.contentAttributes.of({ spellcheck: 'false', autocapitalize: 'off', autocorrect: 'off', 'aria-labelledby': 'user-css-edit-css-label' })`, `keymap.of([...closeBracketsKeymap, ...defaultKeymap, ...historyKeymap])`, 크기 거르기(결정 8), 변경 알림(`onDocChange`)

- 줄 번호·접기·검색·Yjs·마크다운 확장은 넣지 않는다. 문서 편집기(`createEditor.ts`)와 공유하는 코드가 없다
- `Escape`: 선택이 있으면 `simplifySelection` 이 먼저 먹어 선택만 풀리고(M3) 두 번째 `Escape` 가 D-16 을 닫는다. 받아들인다(문서 편집기와 같다)
- 색: `classHighlighter` 의 `tok-*` 클래스에 `app.css` 가 토큰 색을 준다 — `.user-css-editor .tok-comment`(`--code-comment`), `.tok-propertyName`(`--code-property`), `.tok-variableName`(`--accent`), `.tok-string`·`.tok-literal`(`--code-string`), `.tok-number`(`--code-number`), `.tok-keyword`·`.tok-atom`(`--code-keyword`), `.tok-className`·`.tok-typeName`·`.tok-labelName`(`--code-type`, 굵게). hex 금지(불변식), 어울림은 사람 확인
  - 각주(2026-10-05): 처음에는 `--muted`·`--link`·`--callout-success`·`--callout-example`·`--ink` 였고, 코드블록과 같은 `--code-*` 로 바꿨다 (F-2122 5.2, F-2124 5장)
- `.user-css-editor`: `--font-mono`, 13px, 테두리 `--rule`, 높이 `clamp(160px, 45dvh, 420px)`, 안에서 스크롤

### 4.2 모양 (개요 5.2 + 5.8)

- `Dialog` `size="xwide"`, `titleId="user-css-edit-title"`, 제목 `CSS 편집`. 설정 대화상자 **위에** 뜬다(D-15 선례, 네이티브 top layer)
- 위에서 아래: `이름` 입력(`maxLength=60`) · `CSS`(라벨 `span#user-css-edit-css-label`) + 편집기 · 상태 줄 `p.user-css-status[aria-live=polite]` · 오류 줄 · `닫기`
- **첫 포커스 = CSS 편집기 `.cm-content`.** `Dialog` 의 초점 이펙트가 자식보다 늦게 돌므로, 뷰는 `useLayoutEffect` 에서 만들고 그 `contentDOM` 을 `initialFocusRef` 로 준다. 뷰는 닫힐 때 `destroy`
- **휴대폰 폭**: 폭은 `xwide` 규칙 그대로 `min(720px, 100vw − 32px)`(360 창 328px). 편집기 높이는 `dvh` 라 가상 키보드가 뜨면 줄어든다(`interactive-widget=resizes-content`). 이름·상태 줄은 위아래 그대로

### 4.3 이름

## 11. 열린 질문

### Q1. D-16 에 자동 완성을 넣을까 — **기본값: 넣지 않는다**

개요 5.9 가 "자동 완성 하지 않는다" 로 승인됐다. 다만 개요 Q1 표는 CM6 를 고를 때 "속성 이름 자동 완성(lang-css 기본)" 을 장점으로 적었다. 번들 차이는 거의 없다(M1: `css()` 와 `cssLanguage` 18B, `@codemirror/autocomplete` 는 위키링크 완성으로 이미 있다).
넣는 쪽을 고르면: 4.1 에 `autocompletion()` + `completionKeymap`, 언어를 `css()` 로. `Escape` 가 먼저 목록을 닫고(`closeCompletion`) `Enter` 가 선택을 받는다 — 목록이 떠 있을 때 `Escape` 두 번이 필요해진다(M3). 개요 5.9 에서 한 줄을 뺀다
