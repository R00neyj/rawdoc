# F-171 표 행·열 추가 때 화면 튐

작성일: 2026-09-15
상태: 사용자 지시(2026-09-15 "스크롤되는 버그 수정해야함"). 제보 "표에 행을 추가하면 가끔 화면 밑으로 자동 스크롤". **F-147 커밋 뒤** 시작 (브라우저 검증을 한 번에 한 에이전트만 돌림, 파일은 겹치지 않음)
근거: F-125 2.3(Enter 이동), F-140 3.5(마지막 행 Enter 로 행 추가)·3.6(+버튼), F-135 3.5(`exitToMain`), F-165(범위 선택 포커스 요소)

## 2. 현재 상태 (원인 미확정)
- 행 추가 두 경로 모두 `addRow` 트랜잭션 → `pendingFocus` → 위젯 다시 그리기 → `startEdit` → `cellView.focus()` 순서다
- F-165 에이전트는 `cellView.focus()` 가 스크롤한다고 보았으나, `@codemirror/view` `EditorView.focus()` 는 `focusPreventScroll` 로 `preventScroll` 을 쓴다 (`node_modules/@codemirror/view/dist/index.js` 8618줄). 원인으로 확정할 수 없다
- 남은 후보 (코드만 보고 추정):
  1. 구조가 바뀌어 표 DOM 을 새로 만들 때 주 에디터가 선택을 DOM 에 다시 쓰거나 높이 변화에 맞춰 스크롤 위치를 옮김
  2. 칸 하위 에디터 `docView.updateSelection()` 이 DOM 선택을 옮기며 브라우저가 스크롤
  3. F-165 범위 선택 포커스 요소 `el?.focus()` (`preventScroll` 없음) — 범위 선택 뒤 삭제 경로에만 해당
- **구현 첫 단계로 e2e 측정으로 원인을 찾아 보고에 적는다** (어느 호출 전후로 스크롤 위치가 바뀌는지)

## 3. 요구사항
- 대상 동작: 마지막 행 Enter 로 행 추가, `+` 행 추가, `+` 열 추가, Enter·Tab·방향키로 다른 칸 편집 시작
- 새로 편집하는 칸이 편집 영역 스크롤 창 안에 이미 다 보이면 스크롤 위치를 바꾸지 않는다 (±1px)
- 새 칸이 창 아래로 벗어나면 그 칸 아래 끝이 창 아래 끝에 닿을 만큼만 스크롤한다 (가운데로 옮기지 않는다). 위로 벗어나면 위 끝에 닿을 만큼만
- 표 가로 스크롤(`.md-table-scroll`, 열이 많을 때)도 같은 규칙 — 새 열 칸이 보이게 필요한 만큼만
- F-165 범위 선택 포커스 요소에 포커스를 줄 때 `preventScroll: true`
- 원문·실행 취소 동작은 바꾸지 않는다
