# F-2085 휴대폰 폭 상단바를 떠 있는 알약으로

작성일: 2026-09-29
상태: 승인 — 받음 (2026-09-29, 사용자가 Q2·Q3 는 추천안을 고르고 나머지 열린 질문은 기본값대로 승인). 사용자가 Obsidian 모바일 캡처(왼쪽 위 둥근 알약 속 사이드바 버튼, 오른쪽 위 버튼 셋을 묶은 알약, 전폭 바 없음, 제목·본문이 바로 보임)를 보고 요청했다(2026-09-29). 아래 "정해진 것" 다섯은 사용자가 정했다. 이 명세가 새로 정하는 것은 본문 위 여백(4장), 겹치는 것들의 층위·위치(5장), 노치·상태바(6장), 알약 바탕(7장), 기존 e2e 영향(10장)이다. 열린 질문 12장은 모두 기본값이 있다
구현 담당: `feature-implementer`. 선행 회귀 수정(⋯ 판이 휴대폰 폭에서 열리지 않던 버그, `2a668f8` `icons.tsx`)은 커밋됨

## 정해진 것 (2026-09-29 사용자, 바꾸지 않는다)

1. 적용은 **창 폭 600px 이하만**. 601px 이상은 지금 그대로
2. 전폭 상단바(바탕·아래 선) 대신 **떠 있는 알약 두 개**: 왼쪽 `[☰ 로고]`, 오른쪽 `[보기 모드 ⋯]`. 접속자 아바타(있을 때만, 1명 + `+N`)는 오른쪽 알약 **앞에 따로**
3. **로고를 되살린다** — 로고는 기존 홈 버튼(`{제품명} 홈으로`, `data-go-home`)이다. 그래서 **⋯ 판의 `홈` 행을 뺀다**. F-2083 이 CSS 로 제품 아이콘을 숨긴 규칙은 되돌린다
4. **늘 떠 있다** — 스크롤해도 숨지 않는다(Obsidian 이 하단 바 자동 숨김으로 반발을 산 사례). 본문은 알약 밑으로 지나간다
5. 작은 명세 후 구현(tweak 아님)

## 2. 범위

### 한다
- ≤600px 에서 상단바의 전폭 바탕·아래 선을 없애고 왼쪽 알약 `[☰ 로고]`, (아바타), 오른쪽 알약 `[보기 모드 ⋯]` 을 본문 위에 띄운다
- 로고(홈 버튼)를 되살리고 ⋯ 판 `홈` 행을 뺀다
- 문서 화면 본문이 알약 밑으로 지나가게 하되, 맨 위·제목 이동·커서 따라가기가 알약에 가리지 않게 한다

### 하지 않는다
- 601px 이상. 그 폭의 상단바·로고·목차 버튼·알림 띠는 한 픽셀도 바꾸지 않는다

- 서식 바 가로 스크롤바 두께·터치 뒤 툴팁 잔상 — 별도 tweak

## 3. 구조와 계약

### 3.1 DOM (≤600px)

```
header.topbar
├─ div.topbar-lead.topbar-pill        ← SidebarHead variant="phone"
│   ├─ span.icon-btn-wrap > button.icon-btn.sidebar-toggle   (사이드바 열기/닫기)
│   └─ span.icon-btn-wrap > button.brand-group[data-go-home] (아이콘만) + IconTooltip
├─ div.topbar-spacer
├─ div.peer-avatars                   ← 있을 때만, 따로 떠 있는 작은 알약
└─ div.topbar-pill.topbar-pill--end
```

```ts

variant: 'topbar' | 'sidebar' | 'phone'
```

- `'phone'`: 루트 클래스 `topbar-lead topbar-pill`. **DOM 순서 ☰ → 로고** — 정해진 것 2 의 `[☰ 로고]` 를 Tab 순서까지 같게 한다(CSS `order` 로 겉만 뒤집으면 포커스 순서가 로고 → ☰ 로 남는다). 로고 버튼은 지금과 같은 `button.brand-group`(`aria-label`·`data-go-home`·`img.brand-icon` 그대로)이되 `span.brand` 글자를 그리지 않는다. 아이콘만 있는 버튼이 되므로 `IconTooltip` 을 단다(design.md 4장 "아이콘만 있는 버튼에는 반드시 툴팁"). 검색·팔레트 버튼은 그리지 않는다(지금도 이 폭에서 CSS 로 숨김 — 사이드바 줄·⋯ 판에 있다)
- `'topbar'`(601~1023px)·`'sidebar'` 는 지금 그대로
- `TopBar` 는 이미 부르는 `usePhoneWidth()` 로 `'phone'`·`'topbar'` 를 고른다. `.topbar` 첫 자식이 `.topbar-lead` 라는 사실은 유지된다(`e2e/topbar.spec.js` `F-151 A4` 가 900px 에서 보는 것 — 휴대폰 폭에서도 같다)
- 오른쪽 묶음 `div.topbar-pill.topbar-pill--end` 은 `TopBar` 의 휴대폰 분기 안에서만 그린다. 문서 화면이 아니면 안에 ⋯ 하나뿐(동그란 알약)


- `moreSheetItems` 순서: 목차 → 댓글 → 공유 → 내보내기 → 명령 팔레트 → 알림 → 계정. `'home'` 은 어느 화면에서도 없다
- 결과: 문서 화면 = 목차¹·댓글²·공유·내보내기·명령 팔레트·알림³·계정 / 홈 = 명령 팔레트·알림³·계정 / 도움말·공유 관리·지도·공유 화면·부팅 중 = **홈과 같다**(명령 팔레트·알림³·계정). 각주 조건은 F-2083 4.2 그대로
- 이유: 로고가 모든 화면에서 늘 보이는 홈 버튼이다(`goHome` 은 이미 홈이면 아무것도 안 한다 — `useDocNavigation.ts`). 판 행은 중복
- `TopBarMoreSheet` 는 `home` 에 딸린 것(라벨·아이콘·`data-go-home` 속성·동작 분기)을 모두 지운다. `MoreItemKey` 에서 빠지므로 `Record<MoreItemKey, …>` 표에 남기면 타입 오류로 드러난다

### 3.3 `src/lib/floatCover.ts` — 알약이 가리는 높이 (계약)

CSS 한 곳(`--float-cover`)이 값을 갖고, JS 는 그것을 읽기만 한다. 편집기(`src/editor/`)도 쓰므로 `src/app/` 이 아니라 `src/lib/` 에 둔다(`src/editor` 는 `src/app` 을 import 하지 않는다 — `grep` 0건).

```css
/* src/styles/app.css 맨 위 */
@property --float-cover { syntax: '<length>'; inherits: true; initial-value: 0px; }
```

```ts
export const FLOAT_COVER_PROP = '--float-cover'
export function parsePx(raw: string): number
export function coverOverlap(input: { cover: number; shellTop: number; targetTop: number }): number
export function floatCoverFor(el: Element): number
```

- `parsePx`: `'60px'` → 60, `'60.5px'` → 60.5, `''`·`'0px'`·숫자가 아닌 것·음수 → 0. 공백은 앞뒤를 잘라 읽는다
- `coverOverlap`: 알약 띠(앱 틀 위 끝부터 `cover` px)가 대상 요소 위 끝을 얼마나 덮는가 = `max(0, cover − (targetTop − shellTop))`. 대상이 앱 틀 맨 위에 붙어 있으면 `cover` 전부, 알약 띠보다 아래서 시작하면 0
- `floatCoverFor(el)`: `el.closest('.app-shell')` 이 없으면 0(공개 보기 등). 있으면 그 앱 틀의 계산된 `--float-cover` 를 `parsePx` 로 읽고, 앱 틀과 `el` 의 `getBoundingClientRect().top` 으로 `coverOverlap` 을 돌려준다. 601px 이상은 `--float-cover` 가 `0px` 라 늘 0
- 앞 둘은 DOM 을 import 하지 않는 순수 함수(단위 테스트 A1), `floatCoverFor` 는 DOM 을 읽고 e2e 로 본다
- **`@property` 등록이 계약이다** — 등록하지 않으면 계산값이 `calc(0px + 60px)` 문자열로 나와 `parsePx` 가 0 을 준다(근거 절 측정)
- iOS 에서 키보드가 페이지를 밀어 `.app-shell` 이 `--vv-top` 만큼 내려가도(F-2084 3.3) `shellTop` 을 빼므로 값이 맞다

## 4. 본문 위 여백 (반드시 결론 1)

**결론: ≤600px 에서 상단바를 흐름에서 빼(`position: absolute`) 본문 영역이 앱 틀 맨 위부터 시작하게 하고, 문서 화면은 문서 위 여백 `--doc-pad-top` 을 `알약 띠 + 16px` 로 늘린다. 스크롤하면 본문이 알약 밑으로 지나간다. 스크롤로 무언가를 맨 위로 보내는 동작은 `floatCoverFor` 만큼 덜 올린다. 문서 화면이 아닌 화면은 알약 띠만큼 비우고 그 아래에서 시작한다.**

### 4.1 값

| 이름 | 값 (≤600px) | 601px 이상 |
| --- | --- | --- |
| 알약 위 여백 | `8px` + `env(safe-area-inset-top, 0px)` (6장) | — |
| 알약 높이 | `44px` | — |
| `--float-cover` (`.app-shell` 에 준다) | `calc(env(safe-area-inset-top, 0px) + 60px)` = 위 여백 8 + 알약 44 + 아래 틈 8 | `0px`(등록 초기값) |
| 문서 화면 `--doc-pad-top` (`.content-area--doc` 에 준다) | `calc(var(--float-cover) + 16px)` = 76px | 48px 그대로 |

- 편집 모드 제목 글자 칸 위 끝: 지금 104px → **80px**(76 + 제목 블록 padding 4). 알약 아래 끝 52px 보다 28px 아래. 한 화면에 24px 더 보인다. 값은 사람 확인 H5, 다른 안은 12장 Q1
- `--doc-pad-top` 을 `.content-area--doc` 에서 덮으므로 편집·원문(`.cm-content`)·보기 모드(`.viewer`)가 같은 값을 받는다. 공유 화면(`.shared-view-body`)은 문서 화면이 아니라 받지 않는다(4.4)
- 스크롤 영역(`.cm-scroller`·`.viewer`)은 앱 틀 맨 위(알약 뒤)부터 시작한다. 스크롤바 위 끝도 알약 뒤에 있다 — 휴대폰 스크롤바는 겹쳐 그려지는 얇은 막대라 받아들인다

### 4.2 편집기 — `EditorView.scrollMargins`

- `createEditor.ts` 가 주 편집기에 `EditorView.scrollMargins` 확장 하나를 더한다: 위 여백 = `floatCoverFor(view.scrollDOM)`, 나머지 방향은 주지 않는다
- 효과(모두 CM6 한 경로 — 근거 절): 커서가 위로 움직여 스크롤될 때 커서 줄이 알약 아래에 온다, `scrollToHeading`(목차·위키링크 제목 이동·팔레트)이 제목을 `알약 띠 + 16px` 에 둔다, 댓글 `reveal` 도 같다, 알약에 가린 위치를 기준으로 한 툴팁(자동완성 등)은 CM6 가 "보이지 않는 곳" 으로 친다
- 601px 이상·공개 보기는 값이 0 이라 지금과 같다
- 표 칸 하위 편집기(`tableWidget.ts` 의 칸 `EditorView`)에는 달지 않는다 — 칸 편집기는 자기 스크롤 영역이 없고 스크롤은 주 편집기가 한다

### 4.3 보기 모드 — 제목 이동 둘과 현재 위치

- `Outline.tsx` `selectHeading`(보기 모드)과 `useEditorSync.ts` 위키링크 제목 이동(보기 모드)은 목표 `scrollTop` 에서 `floatCoverFor(스크롤 영역)` 을 **더 뺀다** — 제목이 `알약 띠 + 16px` 에 온다. 지금 16px 여백 상수(`SELECT_MARGIN`·`HEADING_JUMP_MARGIN`)는 그대로
- `Outline.tsx` 현재 위치 계산(편집·보기 둘 다)은 `scrollTop` 대신 `scrollTop + 알약 높이` 를 기준선으로 쓴다 — 알약 밑에 숨은 제목을 "지금 위치" 로 강조하지 않게. 알약 높이는 **스크롤 이벤트마다 읽지 않는다**(`getComputedStyle` 강제 계산) — 효과가 설치될 때 한 번, 창 `resize` 때 다시 읽는다
- 모드 전환 스크롤 보존(F-295)은 바꾸지 않는다 — 양쪽 기준이 같아 서로 맞다
- 스크롤 영역에 `scroll-padding-top: var(--float-cover)` 를 준다(`.content-area--doc .cm-scroller`, `.content-area--doc .viewer`) — 브라우저가 포커스 이동(Tab 으로 링크·제목 입력칸)으로 스크롤할 때 알약 밑에 두지 않게. `scrollTo(top)` 에는 먹지 않으므로 위 두 줄이 따로 필요하다

### 4.4 문서 화면이 아닌 화면

- 홈(S-2)·도움말(S-7)·공유 관리(S-6)·지도(S-8)·공유 화면(S-4)·부팅 중(S-3)의 `.content-area` 는 ≤600px 에서 `padding-top: var(--float-cover)`. 선택자는 `.app-shell .content-area:not(.content-area--doc)`
- 이유: 도움말·공유 관리·지도·공유 화면은 맨 위에 **자기 머리 줄**(`.help-page-head`·`.shares-page-head`·지도 머리·`.shared-view-notice`)이 고정돼 있어, 밑으로 지나가게 하면 머리 줄 버튼(`닫기` 등)이 알약에 가린다. 홈은 내용이 짧고 가운데 정렬이라 지나갈 것이 없다. 알약 띠 자리는 `.content-area` 바탕(`--panel`)이 보인다
- 다른 안(이 화면들도 지나가게)은 12장 Q5

### 4.5 `content-area--doc`

- `DocumentArea.tsx` 루트 `.content-area` 에 클래스 `content-area--doc` 을 더한다. 601px 이상에서는 이 클래스에 걸린 규칙이 없다
- `:has(> .editor-slot)` 같은 구조 추측 대신 이름을 붙이는 이유: `AppScreens` 부팅 칸도 `data-editor-slot` 을 갖고, 구조가 바뀌면 선택자가 소리 없이 빗나간다

## 5. 겹치는 것들 (반드시 결론 2)

### 5.1 층위 (≤600px, `.app-shell` 쌓임 맥락 안)

| 층위 | 무엇 | 비고 |
| --- | --- | --- |
| 50 | 우클릭 메뉴, 끌어놓기 덮개 | 그대로 — 알약 위 |
| 40 | 사이드바·알림 띠 등 **알약 밖** 아이콘 툴팁 | 그대로 |
| **36** | **`.topbar`(알약·아바타, 그 안의 보기 모드 메뉴·툴팁)** | 새 값. 사이드바(35) 위 |
| 35 / 34 | 겹침 사이드바 / 그 뒤 막 | 그대로 |
| **15** | **알림 띠 `.notice`**(5.2) | 새 값 |
| 0 (`isolation: isolate`) | **`.content-area`** 한 덩어리 — 그 안의 목차 카드 20·`댓글 달기` 20·댓글 판 30·위키링크 미리보기 35·CM6 찾기 패널 300·CM6 툴팁 500 | ≤600px 에서 `.content-area` 에 `isolation: isolate` |

- **`.content-area` 를 가두는 이유**: CM6 찾기 패널(300)·툴팁(500)과 위키링크 미리보기(35)가 `.content-area` 밖 층과 겨루면 알약(36) 위로 올라와 알약을 덮는다. 가두면 "본문 영역 안의 것은 모두 알약 밑" 한 줄 규칙이 된다. 알약보다 위에 떠야 하는 것(대화상자·⋯ 판·우클릭 메뉴·끌어놓기 덮개)은 모두 `.content-area` 밖이거나 최상위 층이다
- 받아들이는 것: 본문 맨 위 가까이에서 뜬 CM6 자동완성·위키링크 미리보기가 알약에 조금 가릴 수 있다 — 4.2 대로 CM6 는 그 영역을 보이지 않는 곳으로 친다
- `isolation` 은 기준 상자를 만들지 않는다 — `.content-area` 안 `position: fixed` 요소 좌표는 그대로다(F-2084 3.3 의 `transform` 금지 이유와 부딪히지 않음)

### 5.2 알림 띠 (`NoticeBar`)

**결론: ≤600px 에서 알림 띠를 흐름에서 빼 알약 바로 아래에 떠 있는 카드로 둔다.**

- 위치: `position: absolute`(기준 상자 `.app-body` — `position: relative`), `top: var(--float-cover)`, 좌우 `8px`. 모서리 `--radius-dialog`, 테두리 1px `--rule`(아래 선만이 아니라 네 변), 그림자 7.2 알약과 같은 값. 바탕·글자색·종류별 색(`notice--error`·`notice--update`)은 그대로
- 층위 15 — 본문 위, 사이드바(35) 아래
- 내용 줄(메시지·동작 버튼·닫기)과 여닫기 전환(`translateY(-4px)`)은 그대로
- 이유: 흐름 안에 두면 알약 띠(60px) 아래에 띠가 끼어 본문이 알림 높이만큼 밀렸다 돌아오고, 문서 화면은 `--doc-pad-top` 의 알약 몫까지 두 번 비게 된다(`--float-cover` 를 알림이 있을 때만 0 으로 바꾸는 조건이 새로 필요). 카드로 띄우면 본문이 움직이지 않는다
- 받아들이는 것: 알림이 떠 있는 동안 그 아래 본문 첫 줄들이 가린다. 정보성은 몇 초 뒤 사라지고, 오류는 `알림 닫기` 로 닫거나 본문을 스크롤해 비켜 읽는다. 목차 카드(5.4)가 같은 높이에서 열리면 알림 카드가 위에 온다(층위 15 > `.content-area` 덩어리). 다른 안은 12장 Q2
- `specs/ia.md` 4.2 "상단바 아래, 편집 영역 위에 1줄" 은 601px 이상 설명으로 남기고 ≤600px 예외 한 줄을 더한다(11장)

### 5.3 겹침 사이드바 — 사이드바가 열리면 왼쪽 알약은?

**결론: 왼쪽 알약은 사이드바 위에 그대로 남고(☰ 이 `사이드바 닫기` 가 된다), 아바타와 오른쪽 알약은 사라진다. 사이드바 내용은 알약 띠 아래에서 시작한다.**

- 이제 `.app-body` 가 앱 틀 맨 위부터 시작하므로 `.sidebar--overlay` 도 맨 위부터 덮는다. ≤600px 에서 `.sidebar--overlay` 에 `padding-top: var(--float-cover)` — 첫 줄(동작 버튼 줄)이 왼쪽 알약 밑에 들어가지 않게
- 왼쪽 알약(층위 36 > 사이드바 35)이 사이드바 위에 떠 있다. ☰ 로 닫고, 로고로 홈에 간다(홈으로 가도 사이드바는 열린 채 — F-232 A7 "사이드바 유지", 601~1023px 과 같다)
- 오른쪽 알약·아바타: 선택자 `.topbar:has(.sidebar-toggle[aria-expanded='true'])` 일 때 `opacity: 0; visibility: hidden`, 전환 `--transition-fast`(design.md 4장 "나타나고 사라지는 것도 전환"). 이유: 사이드바 폭 `--sidebar-w` 기본 300px(200~480)이라 360px 폰에서 오른쪽 알약(약 80px, x 272~352)이 사이드바 위에 겹친다. 사이드바가 열린 동안 문서 동작(보기 모드·⋯)은 쓸 일이 없고, 사이드바 뒤 막(34)이 그 자리 탭을 "닫기" 로 받는다
- 새 prop 없음 — 토글의 `aria-expanded` 가 이미 `sidebarOpen` 이다

### 5.4 목차 카드

- ≤600px `.app-shell .outline-popup` 의 `top` 을 `calc(var(--float-cover) − 8px)` 로. 버튼이 숨어 높이 0 이므로 카드 윗변 = `--float-cover`(60px) — 알약 아래 끝 52px 에서 8px 아래. 오른쪽 16px 그대로
- 카드 최대 높이 계산(`Outline.tsx` `min(60vh, 컨테이너 높이 − 80)`)은 그대로 — 컨테이너가 알약 띠만큼 길어졌으므로 카드 아래 끝은 컨테이너 아래 끝 −20px, 화면 안
- F-2083 사람 확인 "목차 카드가 `.content-area` 위 +20px" 항목은 이 값으로 바뀐다(11장)

### 5.5 댓글 판·`댓글 달기` 버튼·찾기 패널·서식 바

- 댓글 판 `.comment-sheet`(≤600px 아래 판): `max-height: calc(100% − var(--float-cover))` — 키보드가 떠 앱 틀이 줄어도(F-2084) 판 머리(`닫기`)가 알약 밑으로 올라가지 않게. 60dvh 는 iOS 에서 키보드로 줄지 않는다
- `댓글 달기` 버튼: `DocumentArea.tsx` `clampFabY` 의 위 한계를 `8` 에서 `알약 높이 + 8` 로. 알약 높이는 `floatCoverFor(.content-area)` 를 `editorViewportH` 를 재는 때에 같이 읽는다(렌더 중 DOM 읽기 금지). 601px 이상은 0 이라 지금과 같다
- CM6 찾기 패널(`search({ top: true })`, `view.dom` 첫 자식): ≤600px 에서 `.content-area--doc .cm-panels-top` 에 `padding-top: var(--float-cover)` — 패널 바탕이 알약 뒤까지 올라가고 입력칸은 알약 아래에 온다. 패널이 열린 동안 `.cm-scroller` 위 끝이 알약 띠 아래로 내려가므로 `floatCoverFor` 가 0 을 돌려준다(3.3) — 이중으로 비키지 않는다
- 서식 바(F-2084): 편집기 포커스 중에만 앱 틀 맨 아래에 붙는다. 알약과 만나지 않는다. 포커스가 없을 때는 자리가 없다 — 바꿀 것 없음
- ⋯ 판·보기 모드 메뉴·공유·API 토큰 대화상자: ⋯ 판과 대화상자는 최상위 층(근거 절 측정), 보기 모드 메뉴는 알약 안 `position: absolute` 라 `.topbar` 층위 36 을 따른다 — 바꿀 것 없음

### 5.6 iOS 키보드 (F-2084 와의 관계)

- 알약은 `.app-shell`(≤600px `position: fixed; top: var(--vv-top)`) 안의 `position: absolute` 라, iOS 가 키보드로 페이지를 밀어도 앱 틀과 함께 보이는 영역 맨 위에 남는다. 새 코드 없음. 확인은 사람 확인 H6

## 6. 노치·상태바 (반드시 결론 3)

**결론: `viewport-fit=cover` 를 넣지 않는다. 알약 위 여백에 `env(safe-area-inset-top, 0px)` 를 더해 두되, 지금은 모든 경우 0 이다.**

| 환경 | 상태바와 앱의 관계 (meta 에 `viewport-fit=cover` 없음) | `safe-area-inset-top` |
| --- | --- | --- |
| iOS Safari 일반 탭 | 브라우저 UI 가 상태바 아래를 차지하고 페이지는 그 아래에서 시작 | 0 |
| iOS 홈 화면 PWA (`display: standalone`, `apple-mobile-web-app-status-bar-style` 없음 → 기본값) | 상태바가 불투명 띠로 남고 페이지는 그 아래에서 시작 | 0 |
| 안드로이드 Chrome 일반 탭 | 주소창 아래에서 시작 | 0 |
| 안드로이드 설치 PWA (`standalone`, `theme_color`) | 상태바(테마색) 아래에서 시작 | 0 |

- **이 표의 iOS·안드로이드 행은 WebKit·Chrome 의 문서화된 동작이고 실기기로 확인하지 않았다** — 사람 확인 H1 이 네 곳에서 본다. Chrome 154 모바일 에뮬레이션에서 `env(safe-area-inset-top, 0px)` 가 `0px` 로 계산되는 것만 확인했다
- `env()` 를 미리 더해 두는 이유: 나중에 `viewport-fit=cover` 를 넣어도 알약·`--float-cover`·사이드바 위 여백이 따라 내려온다. 지금 비용은 0
- `viewport-fit=cover` 를 넣지 않는 이유: meta 는 모든 폭·모든 화면에 걸린다. 넣으면 iOS 에서 아래 홈 표시줄 영역(상태바·docked 서식 바·⋯ 판 아래)과 가로 모드 좌우 노치까지 이 명세가 다뤄야 하고, 601px 이상 화면도 바뀐다. 알약만을 위한 이득(상태바 밑까지 본문을 까는 것)은 작다. 넣는 안은 12장 Q6
- 참고: `.more-sheet-body` 의 `padding-bottom: env(safe-area-inset-bottom)` 도 같은 이유로 지금은 0 이다 — 이 명세는 바꾸지 않는다

## 7. 알약 모양 (반드시 결론 4 — 값은 초안, 사람 확인 H1·H2)

색 hex 를 쓰지 않는다. 바탕은 `color-mix()` 로 토큰에서 만든다. 그림자는 기존 겹침 그림자와 같은 `rgba(0, 0, 0, …)` 계열(design.md 4장 선례 — 메뉴 `0 8px 24px rgba(0,0,0,.14)`, 댓글 판 `0 -12px 40px rgba(0,0,0,.16)`)이다. 다크 테마에서 `--ink` 로 섞으면 밝은 그림자가 되므로 쓰지 않는다

### 7.1 ≤600px 상단바

| 대상 | 클래스 | 값 |

- 360px 폭 최악 경우 합: 좌우 여백 16 + 왼쪽 알약 80 + 아바타 알약 약 60(1명 + `+N`) + 오른쪽 알약 80 + 간격 3×8 = 260 ≤ 360. 가로 넘침 없음
- 넓은 배치 규칙 `.topbar` 기본값(높이 52·바탕 `--panel`·아래 선)은 그대로 — 위 값은 모두 `@media (max-width: 600px)` 안

### 7.2 바탕 — 가독성

| 속성 | 값 |
| --- | --- |
| 바탕 | `color-mix(in srgb, var(--panel) 85%, transparent)` |
| 흐림 | `backdrop-filter: blur(12px)` (빌드가 `-webkit-` 접두사를 붙인다 — 근거 절) |
| 테두리 | 1px `var(--rule)` |
| 그림자 | `0 2px 12px rgba(0, 0, 0, 0.12)` |
| 투명도 줄이기 | `@media (prefers-reduced-transparency: reduce)` 이면 바탕 `var(--panel)`, 흐림 없음 |

- 이유: 불투명이면 본문이 알약 가장자리에서 뚝 잘려 "밑으로 지나간다" 가 보이지 않고, 투명도만 있으면 글자가 비쳐 아이콘을 읽기 어렵다. 85% + 흐림이면 지나가는 것은 보이되 글자 모양은 뭉개진다. 흐림이 안 되는 브라우저(개발 서버 + iOS 17 이하)에서도 85% 바탕이라 아이콘은 읽힌다
- 알림 카드(5.2)는 이 바탕을 쓰지 않는다 — 글자를 읽어야 하므로 지금 불투명 바탕 그대로, 그림자만 같다
- 성능: 흐림은 알약 셋(합 약 220×44px)에만 걸린다. 저사양 안드로이드에서 스크롤 중 흐림 재계산 비용은 **재지 않았다** — 사람 확인 H2. 끊기면 12장 Q3 의 불투명 안

## 12. 열린 질문 (모두 기본값 있음)

### Q1. 문서 위 여백 — **기본값: 알약 띠 + 16px (제목 글자 칸 80px)**
- 이유: 사용자가 본 Obsidian 캡처처럼 "제목·본문이 바로 보임" 에 가깝다. 지금(104px)보다 24px 더 보인다. 알약 아래 끝과 제목 사이 28px 은 알약 띠 아래 틈(8)보다 넉넉하다
- 다른 쪽(알약 띠 + 48px, 지금 문서 위 여백 그대로 = 제목 112px): 4.1 표의 값 한 줄만 바뀐다. 제목이 지금보다 8px 내려가 넓은 창과 "알약 아래 48px" 로 같은 리듬이 된다. e2e 기대는 "≥ pillBottom" 이라 그대로

### Q2. 알림 띠 — **기본값: 알약 아래 떠 있는 카드 (5.2)**
- 이유: 본문이 움직이지 않고, `--float-cover` 를 알림 유무로 바꾸는 조건이 없다
- 다른 쪽(흐름 안 띠, 알약 아래): `.main-column` 에서 알림이 있으면 `.content-area` 의 `--float-cover` 를 0 으로 덮는 규칙(`:has(> .notice)`)과 알림 `margin-top: var(--float-cover)` 가 필요하다. 알림이 뜨고 질 때 본문이 `알림 높이 + 60px` 만큼 밀렸다 돌아온다. 5.1 층위 표에서 15 행이 빠지고, H4 가 "밀림이 거슬리는가" 로 바뀐다

### Q3. 알약 바탕 — **기본값: 85% 반투명 + 흐림 12px (7.2)**
- 이유: 7.2
- 다른 쪽(불투명 `--panel` + 테두리 + 그림자): 흐림 비용이 없고 모든 브라우저에서 같다. 대신 본문이 알약 가장자리에서 잘려 보인다. 7.2 표의 바탕·흐림 두 줄과 투명도 줄이기 줄이 빠진다. H2 에서 성능 항목이 빠진다

### Q4. 아바타 — **기본값: 작은 알약 하나로 따로 띄움**
- 이유: 정해진 것 2 "따로 둔다". 바탕 없이 두면 24px 원이 본문 글자 위에 그대로 떠 읽기 어렵고, 원 테두리(`--panel` 2px)만으로는 경계가 약하다
- 다른 쪽(바탕 없이 원만): 7.1 아바타 행이 "오른쪽 음수 여백 없앰" 만 남는다. 폭 합이 약 20px 준다

### Q5. 문서 화면이 아닌 화면 — **기본값: 알약 띠만큼 비우고 그 아래에서 시작 (4.4)**
- 이유: 그 화면들은 맨 위 머리 줄이 고정이라 지나가게 해도 얻는 것이 없고 `닫기` 같은 버튼이 가린다
- 다른 쪽(모두 지나가게): 화면마다 머리 줄에 `padding-top: var(--float-cover)` 를 따로 주고(도움말·공유 관리·지도·공유 화면 CSS 4곳), 스크롤 몸통의 위치 계산(도움말 목차 `helpOutline.ts` 이동)에도 `floatCoverFor` 를 넣어야 한다. 소유표에 `src/app/helpOutline.ts`·`src/styles/map.css` 가 는다

### Q6. `viewport-fit=cover` — **기본값: 넣지 않는다 (6장)**
- 이유: 6장
- 다른 쪽(넣는다): `index.html` 이 소유표에 들고, iOS 에서 본문이 상태바 밑까지 깔린다(알약은 `env()` 덕에 따라 내려온다). 대신 아래 홈 표시줄 영역 — `.statusbar`·docked 서식 바(F-2084)·댓글 판·⋯ 판 — 에 `env(safe-area-inset-bottom)` 을 모두 더해야 하고, 가로 모드 좌우 노치와 601px 이상 화면도 같이 봐야 한다. 홈 화면 PWA 는 `apple-mobile-web-app-status-bar-style` 을 `black-translucent` 로 정하는 결정이 따라온다. 사실상 별도 명세 크기다

### Q7. 부팅 스켈레톤 — **기본값: 바꾸지 않는다**
- 이유: 부팅 몇백 ms 동안만 보이는 자리표시다. 휴대폰 폭에서 52px 바 모양 → 알약으로 바뀌는 한 번의 전환을 받아들인다. `index.html` 과 부팅 CSS(F-2015)를 이 명세 소유에 넣지 않는다
- 다른 쪽(스켈레톤도 알약 모양): `index.html` 의 `.boot-skeleton-topbar` 와 그 CSS 에 ≤600px 규칙(알약 자리 두 개, 바 없음)을 더한다. 소유표에 `index.html` 과 스켈레톤 CSS 파일이 는다
