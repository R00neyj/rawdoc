## 2. 요구사항

### 2.1 표시
- 편집 모드에서 표(GFM `Table`)는 **커서·선택 위치와 상관없이 항상 표 위젯**이다. 원문은 원문 모드에서 본다
  - 예외 (F-139 3.1): 주 에디터의 빈 커서가 표 원문 범위 안이면 원문으로 보인다 (표를 치는 도중 입력 손실 방지)
- ~~칸 글자는 원문 텍스트 그대로 표시한다~~ → F-140 3.2 로 대체: 편집 중이 아닌 칸은 인라인 서식 표시
- 표 스타일은 F-124 3.4
- 위젯 높이 규칙은 F-124 3.4 "가로 스크롤 요소 아래 줄 클릭 위치 어긋남" 을 따른다: 최상위 요소 세로 `margin` 금지, `ResizeObserver` → `view.requestMeasure()`. 행·열 추가, 칸 편집 중 줄바꿈으로 높이가 바뀌어도 표 아래 줄 클릭 위치가 맞아야 한다

### 2.2 칸 편집
- 칸을 클릭하면 그 칸에 **하위 CM6 `EditorView` 1개**를 띄워 편집한다. 동시에 1칸만
  - 이유: 한글 조합 입력을 CM6 가 처리하게 하기 위해서다. 위젯 안에 `contenteditable` 을 직접 두면 조합 처리를 새로 만들어야 한다
  - 하위 에디터 확장: 한 줄, 기본 키맵 일부(글자 이동·삭제·선택), 실행 취소 기록 없음, 마크다운 강조 없음
- 칸 원문 범위 = 앞뒤 파이프 사이에서 **앞뒤 공백을 뺀 부분**. 공백 패딩은 건드리지 않는다. 빈 칸은 앞 파이프 뒤 공백 1개 다음 위치(공백이 없으면 파이프 바로 뒤)를 삽입 위치로 쓴다
- 하위 에디터의 변경은 즉시 주 문서에 **그 칸 범위만 바꾸는 트랜잭션**으로 보낸다 (`userEvent: 'input.table'`). 주 문서가 원본이고 하위 에디터는 입력 창구다 (CLAUDE.md 불변조건)
  - 주 문서 트랜잭션으로 위젯이 다시 그려질 때 편집 중인 칸의 DOM(하위 에디터)을 새로 만들지 않는다 (`WidgetType.updateDOM` 으로 다른 칸 글자만 갱신)
- 입력한 `|` 는 원문에 `\|` 로 넣는다 (표 구조 유지). 붙여넣기의 줄바꿈은 공백 1개로 바꾼다
- 한글 조합 중에는 주 문서 트랜잭션을 보내되, 위젯 재계산 보류·따라잡기는 `src/editor/composition.js` 규칙을 따른다

### 2.3 칸 편집 중 키
| 키 | 동작 |
| --- | --- |
| Tab / Shift+Tab | 다음 / 이전 칸 (행 끝이면 다음 행 첫 칸). 마지막 칸의 Tab·첫 칸의 Shift+Tab 은 아무것도 안 함 |
| Enter | 아래 행 같은 열 칸. 마지막 행이면 ~~편집을 끝내고 표 다음 줄 시작으로 주 에디터 커서~~ → F-140 3.5: 글자 있는 행은 행 추가 후 같은 열, 빈 행은 표 다음 줄로 |
| ← / → | 칸 글자 끝(처음)에서 누르면 다음(이전) 칸 |
| ↑ / ↓ | 위 / 아래 행 같은 열 칸. 머리 행에서 ↑ 는 표 앞 줄 끝, 마지막 행에서 ↓ 는 표 다음 줄 시작으로 주 에디터 커서 |
| Esc | 편집 끝, 주 에디터 커서를 표 다음 줄 시작으로 |
| Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y | 주 에디터의 실행 취소 / 다시 실행. 표 구조가 바뀌면 칸 편집을 끝낸다 |
| Ctrl+B / Ctrl+I / Ctrl+K | F-109 와 같은 기호 삽입을 칸 범위 안에서 |

- 조합 중(`composing`)에는 위 이동 키를 가로채지 않는다
- 주 에디터에서 방향키로 표에 들어올 때(F-106 방향키 보조): ↓ 는 머리 행 첫 칸, ↑ 는 마지막 행 첫 칸 편집 시작
- 칸 밖 클릭·포커스 이탈 시 편집을 끝낸다

### 2.4 행·열 추가
- 표 위젯에 마우스를 올리면 **아래 가장자리 가운데** `+`(툴팁 `뒤에 행 추가하기`), **오른쪽 가장자리 가운데** `+`(툴팁 `뒤에 열 추가하기`) 버튼 표시. 키보드 포커스로도 보인다. `<button type="button" aria-label="…">`
  - 위치 기준은 표 테두리다 (F-140 3.1)
- 툴팁은 앱이 그린다: 배경 `--ink`, 글자 `--panel`, 12px, 모서리 6px, 버튼 아래(열 추가는 버튼 위 — F-140 3.1)
- M1 은 표 끝에만 추가한다. 중간 삽입은 원문 모드에서 직접 고친다. ~~행/열 삭제는 원문 모드에서 직접 고친다~~ → 2026-09-14 F-165: 칸 범위 선택 후 Del·Backspace 로 행·열 삭제
- **행 추가 원문**: 마지막 행 줄 끝에 줄바꿈 + 새 행. 칸 수는 머리 행과 같다. 앞·끝 파이프 유무는 머리 행을 따른다. 각 칸은 공백 1개 — 예) 머리 `| a | b |` → 새 행 `|  |  |`. 추가 후 새 행 첫 칸 편집 시작
- **열 추가 원문**: 각 행 줄 끝에 붙인다
  - 끝 파이프가 있는 행: 끝 파이프 뒤에 `  |` — `| a | b |` → `| a | b |  |`
  - 구분 행: `| --- |` 형식이면 끝에 ` --- |`, 끝 파이프가 없으면 ` | ---`
  - 끝 파이프가 없는 행: ` | ` 를 붙인다 — `a | b` → `a | b | `
  - 추가 후 머리 행의 새 칸 편집 시작
- 칸 수가 머리 행보다 적은 행의 빈 채움 칸(F-106)을 편집하면 그 행 끝에 모자란 칸을 위 규칙으로 붙인 뒤 입력한다
- **바뀐 곳만 고친다** (Q19): 다른 행의 공백 정렬을 다시 맞추지 않는다. 행·열 추가는 위 규칙의 삽입만 한다

### 2.5 `tableModel.js`
- `parseTable(text, from) → { rows: [{ line, cells: [{ from, to, text }], leadingPipe, trailingPipe }], delimiterRow, columnCount }`
  - `from`·`to` 는 문서 절대 위치. `\|` 는 칸 구분이 아니다
- `cellEdit(table, row, col, value) → ChangeSpec[]`, `addRow(table, lineBreak) → { changes, focus }`, `addColumn(table) → { changes, focus }`, `escapeCell(value) → string`
