# F-3021 서버 문서 휴지통

작성일: 2026-10-16
상태: 개요. 흐름은 사용자가 확정했다 — [`specs/wireframes/trash-flow.html`](../wireframes/trash-flow.html)(아래 "정해진 것" 1~9). 원격 MCP(F-4008)의 지우기 도구가 4.2 함수를 부른다. `specs/product.md` 198·428행이 휴지통을 범위 밖에 두고 있다 — 9장 갱신 대상

## 정해진 것 (사용자, 바꾸지 않는다)
1 모든 서버 문서 지우기(앱·CLI·MCP)는 휴지통으로, 로그인 없는 로컬 문서는 지금처럼 바로 지움 · 2 30일 뒤 자동 영구 삭제 · 3 휴지통 문서·첨부도 용량에 셈 · 4 공유 중 문서는 초대받은 사람·공개 링크가 곧바로 못 연다("삭제된 문서"), 초대·링크 행은 남겨 복원하면 되살아남, 열린 실시간 방은 닫음 · 5 사이드바 맨 아래 `휴지통` → 목록(복원·영구 삭제·비우기) · 6 지우기 확인 대화상자는 그대로, 문구만 · 7 지운 주체(앱·CLI·연결된 앱 이름) 기록·표시 · 8 복원해야만 열림(미리보기 없음) · 9 폴더 `전부 삭제`는 폴더를 지우고 안 문서는 각각 휴지통, 원래 폴더를 기억, 복원 때 폴더가 없으면 최상위

## 근거 (2026-10-16 작업 트리, 이름으로 찾는다)
- 지우기: `docs.ts` `deleteDocRows`(단건 영구, `/api`·`/v1` 공용), `folders.ts` `deleteFolderContents`(`delete-all` 은 `purge_jobs` + `runPurgeJobs`), `v1.ts` `handleDeleteDocV1`·`handleDeleteFolderV1`. 접근 판정은 대부분 `access.ts` `getDocAccess`(`/api`·`/v1`·`docSocket.ts`·`commentsApi.ts`)
- `worker/*.ts`(테스트 제외)의 `docs` SQL 은 **25파일 79곳**(정규식 `(FROM|JOIN|UPDATE|INTO) docs`·`docs d`). 외래 키 `share_link_docs`·`github_links`·`github_images` → `docs(id)`, `docs.folder_id` 는 외래 키 없음. GC 는 `docs` 행으로 남길 것을 고른다(`attachmentGc.ts` 참조, `commentGc.ts` `NO_DOC`)
- DO: 행이 없으면 `roomGone`(4404 `deleted` + **저장소 비움**), 스냅숏은 5~60초 늦다(`FLUSH_DEBOUNCE_MS`·`SLOW_SNAPSHOT_MS`), 클라이언트는 4404 에 `md-yjs` 를 지운다(`useLiveDoc.ts`). 다른 기기는 목록 받기의 `deleteDocsNotIn` 으로 캐시를 지운다. 클라이언트는 404 를 **상태 코드로만** 가른다(`docsApi.ts`·`cli/src/client.ts`)
- Cron: `0 18 * * *`(매일), `*/10 * * * *`(`runPurgeJobs` 호출 40 + D1 4, 무료 호출당 50 안)

## 1. 표현 — `docs` 열 셋 (별도 표 아님)
```sql
ALTER TABLE docs ADD COLUMN deleted_at INTEGER;  -- ms. NULL = 살아 있음
ALTER TABLE docs ADD COLUMN deleted_by TEXT;     -- TrashActor (4.1)
ALTER TABLE docs ADD COLUMN deleted_path TEXT;   -- 지울 때 폴더 이름 경로 'A/B', 최상위면 NULL
CREATE INDEX docs_trashed ON docs(deleted_at) WHERE deleted_at IS NOT NULL;
```
- 행을 별도 표로 옮기면 79곳은 저절로 빠지지만 ① 위 외래 키 셋 때문에 묶음·GitHub 행을 같이 옮겨야 하고 ② 첨부 GC 가 R2 이미지를, 댓글 GC 가 댓글을 지워 **복원해도 잃는다**. 열 방식에서 필터를 빠뜨리면 휴지통 문서가 **보이는** 것이고, 표 방식에서 빠뜨리면 **지워진다**. 앞쪽이 고치기 쉬워 열을 고른다
- `folder_id` 는 그대로 둔다(복원 자리), 폴더가 지워져도 `deleted_path` 로 경로를 보인다. 파일 번호는 다음 빈 번호(지금 `0027`), 열 이름이 계약. 용량: 보낼 때 `content_bytes`·`doc_count`·첨부를 건드리지 않고(결정 3) 하루 쓰기만 +1(`dayUsageStatement`), 영구 삭제 때 지금 문장으로 줄인다

## 2. 조회 경로 막기 — 누락 지점
**방법**: ① `getDocAccess` 가 휴지통 행을 `null` 로 본다(늘 `deleted_at` 을 같이 읽는다 — 지금 `e2ee_key` 를 덧붙이는 방식) ② 아래 "막음" 곳에 `deleted_at IS NULL` ③ 가드 단위 테스트 `tests/worker/trashFilter.test.ts` 가 `worker/*.ts` 의 79곳 정규식에 걸리는 문자열마다 `deleted_at` 이 있거나 허용 목록(파일·상수/함수 이름·한 줄 이유)에 있어야 통과 — 새 질의가 생기면 여기서 걸린다

## 3. 생애
- **보내기**: `deleted_at`·`deleted_by`·`deleted_path` 한 문장 + 하루 쓰기, 그다음 방 닫기(5장). 초대·링크·묶음·댓글·GitHub 연결 행은 그대로(결정 4). 이미 휴지통이면 `getDocAccess` `null` → 404(멱등). **폴더 `전부 삭제`**: 하위 폴더 행과 폴더의 초대·링크는 지금처럼 지우고 안의 살아 있는 문서는 각각 보내기 — 폴더째 공유는 복원해도 돌아오지 않는다. `move-up` 은 그대로
- **복원**: 휴지통 행만. `folder_id` 의 폴더가 있고 내 것이며 금고 여부가 문서와 같으면 그 자리, 아니면 `NULL`(최상위, F-401 "금고 폴더 안에 일반 문서 없음" 유지). `deleted_*` 를 비우고 하루 쓰기 +1. `updated_at`·`version` 은 그대로
- **영구 삭제**: 한 건은 `deleteDocRows`, 비우기·만료는 지금 `delete-all` 의 대량 문장 한 벌을 id 목록 함수로 뽑아 쓴다(방은 `purge_jobs`). 첨부 R2 는 지금처럼 다음 날 첨부 GC
- **30일 만료**: 10분 Cron 이 `runPurgeJobs` 앞에서 `deleted_at < now − 30일` 문서를 **소유자 한 명·99개까지** 영구 삭제(사용량 문장이 소유자별), 하루 쓰기는 올리지 않는다. D1 문장 수를 재서 `PURGE_CALLS_ON_CRON` 을 호출당 50 안으로 줄인다. 몰리면 몇 시간 늦을 수 있다 — 받아들인다. **쓰기 관문**: 휴지통 라우트는 `isWriteRoute` 그대로(지금 `DELETE /api/docs` 도 막힌 계정은 못 한다)

## 4. 계약
### 4.1 `src/lib/trash.ts` (서버·앱 공용, 순수)
```ts
export const TRASH_RETENTION_DAYS = 30
export type TrashActor = 'app' | 'cli' | `mcp:${string}`   // /api = 'app', /v1 = 'cli'
export function trashActorForMcp(clientName: string): TrashActor  // 제어 문자 제거·trim·40자에서 자름
export type TrashItem = { id: string; title: string; e2ee?: true; deletedAt: number; deletedBy: TrashActor; path: string | null; purgeAt: number }
```
### 4.2 `worker/trash.ts` — `/api`·`/v1`·MCP 가 같이 부른다
```ts
trashDoc(env, ctx, user: AuthUser, docId, opts: { by: TrashActor; allowE2ee: boolean })
  → { ok: true; id; title } | { ok: false; error: 'not_found' | 'forbidden' | 'e2ee_doc' }
trashFolder(env, ctx, user, folderId, opts) // contents=delete-all 의 뜻
  → { ok: true; id; parentId: string | null; docs: number; folders: number } | { ok: false; error: 'not_found' | 'e2ee_folder' }
```
- 판정 순서는 F-2050 3.2·3.4 그대로. `allowE2ee`: 앱 참(금고 문서도 암호문 그대로 휴지통), `/v1`·MCP 거짓. HTTP 응답 모양(`/api` 204, `/v1` `V1DeletedDoc`·`V1DeletedFolder`)은 호출부가 만든다 — **바뀌지 않는다**
**4.3 라우트** (`/api` 만, CLI·MCP 에 복원·비우기 없음): `GET /api/trash` → `TrashItem[]`(`deletedAt` 내림차순, 전부) · `POST /api/trash/:id/restore` → 200 `{ id, folderId }` · `DELETE /api/trash/:id` → 204 · `DELETE /api/trash` → 200 `{ docs }`. 휴지통에 없는 id 는 404
문구 기준(F-2145 가 ia 6장에 옮긴다): 사이드바 `휴지통` · 머리 `30일이 지나면 영구히 지워집니다.` · 행 `{경로 또는 (최상위)} · {지운 때} · {N}일 남음 · {앱에서 지움 | CLI에서 지움 | {이름}에서 지움 | 연결된 앱에서 지움}` · 빈 상태 `휴지통이 비어 있습니다.` · 문서 D-1 `"{제목}" 을(를) 휴지통으로 옮길까요? 30일 뒤 영구히 지워집니다.` · 공개·초대 `삭제된 문서입니다.`

## 5. 실시간 방·기기 동기화
- **방 저장소는 휴지통 동안 남긴다.** 지우면 복원 때 D1 본문으로 새 `Y.Doc` 을 씨앗 하고, 오프라인 기기의 `md-yjs` 옛 기록이 다른 계보로 합쳐져 글이 겹친다. 저장소는 영구 삭제 때 지금 경로(`notifyPurge`·`purge_jobs`)로 지운다
- 새 RPC `closeTrashed()`: 마지막 스냅숏(느린 날 우회) → 연결 4404 `deleted` → 인스턴스 abort, **저장소 유지**. 보내기 뒤 `ctx.waitUntil`. 폴더는 `updated_at` 최근 20개까지(`REVALIDATE_FANOUT_MAX`, F-4002 3.3 선례), 나머지는 방의 다음 D1 확인에서(Q1). `UPDATE_SQL` 은 휴지통 행에도 쓴다(마지막 편집 보존). 읽기 셋은 `deleted_at` 을 같이 읽어 **행 없음 → `roomGone`(지금), 휴지통 → 4404 만, 저장소 유지**
- 이 기기: `store.remove` 경로 그대로(캐시·outbox). 다른 기기: 다음 목록 받기의 `deleteDocsNotIn`, 열려 있으면 4404 → N3. 복원은 목록 다시 받기로 돌아온다. 휴지통 목록은 캐시하지 않는다 — 오프라인이면 안내 문구

## 8. 열린 질문
- **Q1 폴더 휴지통의 21번째 이후 방** — 기본: 다음 D1 확인(편집·접속·60초 점검) 때 닫힘. 편집 없이 열어만 둔 방은 이미 받은 글을 계속 보인다(새 글은 없다). 다른 안: `purge_jobs` 에 `room_close` 종류 — `kind` CHECK 때문에 표를 다시 만드는 마이그레이션과 `runPurgeJobs` 갈래가 F-3023 에 는다
- **Q2 휴지통 금고 문서와 금고 초기화** — 기본: 휴지통 금고 문서도 "금고 문서가 남음"(409 `vault_not_empty`)으로 센다. 키가 사라지면 복원해도 못 열기 때문. F-2145 가 안내에 "휴지통에 든 금고 문서도 먼저 영구 삭제하세요"를 붙인다. 다른 안: 세지 않고 초기화가 휴지통 금고 문서를 함께 영구 삭제 — `e2eeKeys.ts` batch 에 문장이 늘고 D-? 초기화 문구가 바뀐다
