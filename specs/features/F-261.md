# F-261 찾기·바꾸기 (Ctrl+H)

작성일: 2026-09-19
상태: 사용자 요청("ctrl + h 로 문자열 치환기능 필요함"). `specs/product.md` 4.5 를 이 명세와 함께 고쳐 범위를 명확히 한다
근거: `@codemirror/search` — CM6 공식 검색·치환 확장(기존 `@codemirror/commands`·`@codemirror/language` 와 같은 `@codemirror/*` 계열, 새 의존성이지만 라이브러리 자체를 대신할 것이 없다)

사용자 확인 결과(2026-09-19): UI 는 CM6 기본 검색 패널(정규식·대소문자·단어 단위 옵션 포함)에 앱 색 토큰만 입혀 쓴다. 커스텀 UI를 새로 만들지 않는다

**범위 구분** — `specs/product.md` 4.5 의 기존 제외 항목 두 개와 겹치지 않는다:
- "분할 보기(원문 | 미리보기 두 칸)" 제외 항목은 **같은 문서**를 두 칸에 나눠 보여주는 것이고, 이 명세는 무관하다
- "검색"(사이드바 버튼 자리만) 제외 항목은 **여러 문서**를 대상으로 하는 전문 검색이고, 이 명세는 **지금 열려 있는 문서 하나** 안에서 찾고 바꾸는 기능이다(CM6 에디터 자체 기능)

## 2. 요구사항

### 2.1 확장 등록
- `createEditor.ts` 의 확장 목록에 `@codemirror/search` 의 `search({ top: true })`(패널이 상단바 바로 아래, 편집 영역 맨 위에 붙는다) 를 넣는다. 모드(편집·원문)와 무관하게 항상 켠다 — `fenceLinePreview()`·`wikiComplete()` 처럼 `previewCompartment` 밖에 둔다
- 보기 모드(view, CM6 에디터가 없는 화면)에는 이 기능이 없다 — 원래 CM6 를 쓰지 않으므로 손댈 곳이 없다

### 2.2 단축키
- `Mod-f`: CM6 기본 `openSearchPanel` — 찾기 패널을 연다(패널 자체에 치환 입력·옵션이 이미 있다면 그대로, 없다면 찾기만)
- `Mod-h`: 검색 패널을 열되, 치환 입력이 바로 보이고 포커스가 그리로 가게 한다(라이브러리가 찾기·치환을 한 패널로 묶어 제공하면 `openSearchPanel` 과 동일하게 처리해도 된다 — 실제 동작은 설치한 `@codemirror/search` 버전의 패널 구조를 구현 중 확인해 맞춘다). 이미 패널이 열려 있으면 다시 열지 않고 치환 입력으로 포커스만 옮긴다
- `F3`/`Shift-F3`(또는 `Mod-g`/`Shift-Mod-g`, 라이브러리 기본값 그대로): 다음·이전 찾기
- `Escape`: 패널이 열려 있으면 닫는다(라이브러리 기본 동작)
- 브라우저 기본 동작(Chrome 의 방문 기록 열기 등)과 겹치는 단축키는 `keymap` 매치 시 CM6 가 자동으로 `preventDefault` 한다(F-109 기존 `Mod-b`/`Mod-i`/`Mod-k` 와 같은 전제)
- 이 패널은 여러 문서 검색 결과로 문서를 열 때도 열린다. 검색어를 넣고 첫 매치로 옮기는 것은 `src/editor/showSearchMatches.ts`(F-294)이고, 이 명세의 패널 구성·키맵은 그대로다

### 2.3 동작
- 찾기: 대소문자 구분, 정규식, 단어 단위 옵션(라이브러리 기본 제공) 그대로 노출
- 바꾸기: 하나 바꾸기·모두 바꾸기 모두 지원(라이브러리 기본 제공). 바꾸기는 실제 문서 편집이라 `Ctrl+Z` 로 되돌릴 수 있다(CM6 `history()` 가 이미 켜져 있다 — F-103)
- 읽기 전용 문서(F-212 view 권한, `setReadOnly(true)`)에서는 찾기는 되지만 바꾸기 트랜잭션은 CM6 `readOnly` 확장이 막아 실제로 바뀌지 않는다(추가 코드 없이 기존 `readOnlyExtensionsFor` 로 해결됨 — 확인만 한다)
- 목록·인용 안 텍스트, 코드블록 원문 안 텍스트도 검색 대상이다(CM6 문서 전체가 대상, 위젯은 표시만 바꾼다는 불변조건과 무관)

### 2.4 라이브 프리뷰 위젯과의 상호작용 (알려진 제약, 이번 라운드에서 해결하지 않는다)
- 코드블록: 매치로 선택이 생기면 F-106 의 "커서·선택이 겹치면 원문" 규칙이 자연히 적용돼 원문이 열리며 하이라이트가 보인다
- 표(Table): F-125 2.1 규칙상 커서·선택이 겹쳐도 항상 위젯이라, 표 셀 안 텍스트가 매치돼도 화면에 하이라이트가 안 보일 수 있다. 매치 자체(다음 찾기 이동, 바꾸기)는 정상 동작한다 — 시각적으로 안 보일 뿐이다. 이번 명세에서 대응하지 않는다(사람 확인 항목으로만 기록)

### 2.5 스타일 (최소, 사람 확인 대상)
- CM6 검색 패널의 배경·테두리·입력란·버튼·체크박스를 앱 토큰으로 바꾼다. 정확한 여백·크기는 사람이 보고 조정(`CLAUDE.md` "디자인은 TDD 하지 않는다")
