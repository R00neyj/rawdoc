## 1. 범위

### 1.1 문제 — 기호는 이미 넣을 수 있는데 아무 데서도 보이지 않는다

`F-167`·`F-169` 가 우클릭 메뉴·툴바에 **기호 삽입**만 M1 에 넣어 두었다. 2026-09-21 코드로 확인한 현재 상태:

| 어디 | 무엇이 있는가 | 확인한 자리 |
| --- | --- | --- |
| 우클릭 메뉴 | `수식`(`$…$` 감싸기/벗기기), `수식 블럭`(`$$\n…\n$$` 넣기) | `src/app/contextMenuItems.ts` 140·160행 |
| 툴바 | 같은 두 항목 | `src/app/toolbarConfig.ts` 107·135행 |
| 명령 | `toggleMath = toggleWrap('$', { blockOuterGuard: true })`, `insertMathBlock` | `src/editor/formatCommands.ts` 113행, `src/editor/insertCommands.ts` 178행 |
| 서식 지우기 | `LINE_PAIR_MARKERS = ['==', '%%', '$']` 로 `$…$` 짝을 떼어 낸다 | `src/editor/formatCommands.ts` 211행 |

즉 **원문에 `$` 를 넣는 길은 이미 다 있고, 그 결과가 어느 모드에서도 수식으로 보이지 않는다.** 이 명세가 그 표시를 맡는다. `formatCommands.ts`·`insertCommands.ts`·메뉴·툴바는 **손대지 않는다** — 지금 넣는 모양(`$…$`, `$$\n…\n$$`)이 이 명세의 감지 규칙과 그대로 맞는다(3.4)

파서 실측(2026-09-21, `@lezer/markdown` 과 `markdown-it` 을 직접 돌려 확인):

| 입력 | lezer(편집 모드) | markdown-it(보기 모드) |
| --- | --- | --- |
| `a $x^2$ b` | `Paragraph` 하나, 자식 노드 없음 | `inline` 토큰의 `text` 자식 하나 |
| `$$\nx^2\n$$` | `Paragraph` 하나 | `paragraph_open` + `inline("$$\nx^2\n$$")` + `paragraph_close` |
| `이 책은 $5 이고 …` | `Paragraph` 하나 | `<p>이 책은 $5 이고 …</p>` (linkify·typographer 가 `$` 를 건드리지 않는다) |

**둘 다 `$` 를 모른다.** `F-283`(하이라이트 `==`)과 같은 상황이라 같은 구조로 푼다 — 감지 규칙을 DOM 없는 순수 함수 하나로 두고, 편집 모드와 보기 모드가 그 함수를 함께 쓴다(3.5)

### 1.2 한다
- 인라인 `$…$` 과 블록 `$$…$$` **둘 다** 지원한다 (2026-09-21 사용자 결정 — 블록만으로 줄이지 않는다)
- 무엇이 수식이고 무엇이 그냥 `$` 글자인지를 규칙으로 못박고(3장), 그 규칙을 DOM 없는 순수 함수와 단위 테스트 표로 고정한다. **이 명세의 핵심은 3장이다**
- 편집(라이브) 모드에서 수식을 그려 보여 준다. 커서·선택이 닿으면 원문 `$…$` 가 드러난다(4장)
- 보기 모드·공유 화면·공개 보기에서 수식을 그린다(5장)
- `.html` 내보내기·인쇄(PDF)·서식 있는 복사·`.txt` 평문에서 수식을 어떻게 다룰지 정한다(7장)

### 1.3 하지 않는다
- **원문을 바꾸는 일.** `$…$` 는 언제나 원문 그대로 남는다. `.md` 내보내기 바이트는 입력과 같다 (`CLAUDE.md` 불변조건 "decoration 은 문서 내용을 바꾸지 않는다"). 이 제품의 핵심이라 수용 기준 A20 으로 따로 잡는다
- 수식 편집 보조 — 자동완성, 기호 팔레트, 수식 전용 대화상자, 미리보기 창
- `\begin{align}` 같은 **KaTeX 가 지원하지 않는 환경**을 따로 메우는 일. KaTeX 가 그리지 못하면 오류로 보여 준다(6.3)
- 원문(raw) 모드에서 `$` 에 기호 색(`md-mark`) 주기. `F-283` 은 하이라이트에 한해 `highlightMarkStyle()` 을 `previewCompartment` 밖에 뒀지만, 수식은 범위를 늘리지 않는다 — 12장 Q3
- `\ce{}`(mhchem)·`\href` 같은 KaTeX 확장·신뢰 옵션 켜기. `trust` 는 기본값(꺼짐) 그대로 둔다(6.2)
- 목록·인용 안의 `$$` 블록 위젯 (3.3 B3 — 인라인 `$…$` 은 목록·인용 안에서도 동작한다)
- 새 화면·새 버튼·새 설정 항목

## 3. 감지 규칙 — 무엇이 수식이고 무엇이 `$` 글자인가

CommonMark 에 수식은 없다. 베껴 올 기존 구현이 없으므로 이 장이 이 제품의 규칙을 **확정**한다.

바탕으로 삼은 규칙: Pandoc `tex_math_dollars` 확장 — "여는 `$` 오른쪽에 공백이 아닌 글자가 바로 와야 하고, 닫는 `$` 왼쪽에 공백이 아닌 글자가 바로 와야 하며, 닫는 `$` 바로 뒤에 숫자가 오면 안 된다. 그래서 `$20,000 and $30,000` 은 수식으로 읽히지 않는다" (https://pandoc.org/MANUAL.html#extension-tex_math_dollars). `markdown-it-katex` 계열의 `isValidInlineDelim` 도 같은 조건을 쓴다. 이 세 조건을 그대로 채택하고 줄바꿈 금지(R7)를 더한다

### 3.1 인라인 `$…$` 규칙

| # | 규칙 |
| --- | --- |
| R1 | 앞에 역슬래시가 **홀수 개** 붙은 `$` 는 기호가 아니라 글자다(`\$`). 보기 모드에서는 markdown-it 의 `escape` 규칙이 먼저 먹어 이 자리에 오지 않고(실측: `\$5` → `<p>$5</p>`, `text` 토큰 내용은 `$5`), 편집 모드에서는 이 규칙이 직접 센다 |
| R2 | `$` 가 연속 두 개면(`$$`) 인라인 여는 기호가 아니다 — 블록 기호다(3.3) |
| R3 | 여는 `$` **바로 뒤**가 줄 끝이거나 공백(스페이스·탭)이면 열지 않는다 |
| R4 | 닫는 `$` **바로 앞**이 공백(스페이스·탭)이면 닫지 않는다 |
| R5 | 닫는 `$` **바로 뒤**가 숫자(`0`~`9`)면 닫지 않는다 |
| R6 | 안쪽이 비면 짝이 아니다(R2·R3 이 이미 대부분 막는다) |
| R7 | **줄바꿈을 넘지 않는다.** 여는 `$` 와 닫는 `$` 는 같은 줄이어야 한다 |
| R8 | 왼쪽부터 훑는다. 여는 후보마다 같은 줄에서 **가장 가까운** 유효한 닫는 `$` 와 짝짓는다. 못 찾으면 그 `$` 는 글자로 두고 **다음 글자**부터 다시 훑는다. 짝을 찾으면 닫는 `$` **다음 글자**부터 다시 훑는다 (`highlightSyntax.ts` 의 `findHighlights`·`formatCommands.ts` 의 `findMarkerPairs` 와 같은 진행 방식) |
| R9 | 대상이 아닌 자리에서는 아예 끄다 — 3.2 |

R7 을 두는 이유는 `F-283` 3.2.1 과 같다: 편집 모드의 `Decoration.replace` 는 줄바꿈을 덮을 수 없고(CM6 가 "Decorations that replace line breaks may not be specified via plugins" 를 던진다 — `src/editor/preview/inline.ts` 19~27행 `pushHide` 주석), 보기 모드만 줄을 넘는 수식을 인정하면 **두 모드가 서로 다른 글을 보여 준다**

#### 통과 (수식으로 읽는다)

| # | 입력 | 결과 | 왜 |
| --- | --- | --- | --- |
| P1 | `$x$` | 수식 `x` | 최소 형태 |
| P2 | `$E = mc^2$` | 수식 `E = mc^2` | 안쪽 공백은 상관없다 — 보는 곳은 여는 기호 **뒤**·닫는 기호 **앞** 한 글자뿐 |
| P3 | `값은 $x^2$ 이다` | 수식 1개 | 한글 사이 |
| P4 | `$\frac{1}{2}$` | 수식 1개 | 역슬래시 명령. `\f` 는 `$` 앞이 아니므로 R1 과 무관 |
| P5 | `a$b$c` | 수식 `b` | 낱말 가운데도 허용 — 취소선·하이라이트(`F-283` 3.2)와 같은 태도 |
| P6 | `$x$와 $y$` | 수식 2개 | 한 줄에 둘. R8 대로 닫는 기호 뒤부터 다시 훑는다 |
| P7 | `$x$.` | 수식 1개 | 닫는 기호 뒤가 숫자가 아닌 문장부호 |
| P8 | `$100$` | 수식 `100` | 안쪽이 숫자인 것은 상관없다. R5 가 보는 것은 닫는 기호 **뒤** 글자다 |

**알려진 한계(받아들인다)**: `a$b$c` 처럼 공백 없이 붙은 `$` 두 개는 수식으로 읽힌다. Pandoc 도 같다. 사용자가 글자로 두고 싶으면 `\$` 로 쓴다(R1) — 12장 Q1

### 3.2 대상이 아닌 자리 (R9)

| 프론트매터 | 같음 | `renderMarkdown` 이 본문만 markdown-it 에 넘긴다(`findFrontmatter`·`textAfterFrontmatter`) |
| `$$` 블록 안 | 블록 위젯이 그 범위를 통째로 가져가 인라인 훑기가 닿지 않는다 | 블록 코어 규칙이 `inline` 규칙보다 먼저 돌아 토큰을 치운다(5.1) |

`F-137` 이 위키링크를 프론트매터에서 뺀 것과 같은 판정이고, 같은 함수(`isOpaquePosition`)를 그대로 쓴다

### 3.3 블록 `$$…$$` 규칙

| # | 규칙 |
| --- | --- |
| B1 | **문단 하나가 통째로** 수식 블록일 때만 대상이다. 문단 안에 섞인 `$$` 는 대상이 아니다 |
| B2 | 두 형태만 인정한다. (가) 여러 줄: 첫 줄이 `$$` 뿐(뒤 공백 허용), 마지막 줄이 `$$` 뿐(앞뒤 공백 허용), 사이에 한 줄 이상. (나) 한 줄: `$$…$$` 한 줄이고 안쪽이 비지 않음 |
| B3 | **문서 최상위 문단만.** 목록·인용 안은 대상이 아니다 |
| B4 | 안쪽(TeX 본문)이 공백뿐이면 대상이 아니다 |
| B5 | 프론트매터 안은 대상이 아니다(본문 파싱에 들어가지 않는다) |

B3 의 이유는 `F-157` 2.1(이미지 블록)과 같다: 블록 decoration 은 줄 경계에 놓여야 하는데(`blocks.ts` 297~300행), 목록 안 `  $$` 줄을 통째로 치환하면 들여쓰기까지 위젯이 먹어 목록 구조가 깨진다. `blocks.ts` 가 이미 가진 `isInsideListOrQuote` 를 그대로 쓴다

실측(2026-09-21)으로 확인한 파서 모양 — 두 파서 모두 **`$$` 블록을 `Paragraph` 하나로 준다**:

| 입력 | lezer | markdown-it |
| --- | --- | --- |
| `$$\nx^2\n$$\n` | `Paragraph[0,9]` | `paragraph_open` + `inline("$$\nx^2\n$$")` + `paragraph_close` |
| `문단\n\n$$\nx^2\n$$\n\n다음\n` | `Paragraph[0,2]` `Paragraph[4,13]` `Paragraph[15,17]` | 문단 3개, 가운데 `inline` 내용이 `"$$\nx^2\n$$"` |
| `$$x^2$$\n` | `Paragraph[0,7]` | `inline("$$x^2$$")` |
| `- 항목\n\n  $$\n  x\n  $$\n` | `ListItem` 안 `Paragraph[8,19]` | `list_item` 안 `inline("$$\nx\n$$")` |

즉 **양쪽 모두 "문단 글자 → 수식 블록인가" 하나로 판정할 수 있다.** `parseImageBlock`(F-156)이 `blocks.ts` 와 `renderMarkdown.ts` 양쪽에서 쓰이는 것과 똑같은 구조다

`문단\n$$\nx^2\n$$\n`(빈 줄 없이 이어 쓴 것)은 lazy continuation 으로 **한 문단**이 되므로 B1 에 걸려 수식이 아니다. `insertMathBlock`(F-169)은 앞뒤 빈 줄을 맞춰 넣으므로(`computePlacement`) 이 경우에 빠지지 않는다

### 3.4 `F-167`·`F-169` 와의 연결

| 기존 기능 | 넣는 모양 | 이 명세의 판정 |
| --- | --- | --- |

### 3.5 순수 함수 하나로 규칙을 고정한다 (`src/lib/mathSyntax.ts`)

테스트 환경이 `node` 라(jsdom·happy-dom 미설치) **감지 규칙은 DOM 없이 돌아야 한다.** `src/lib/highlightSyntax.ts`·`src/lib/wikiLink.ts`·`src/lib/imageBlock.ts` 와 같은 자리에 순수 모듈로 둔다

```ts
export type MathMatch = { from: number; to: number; innerFrom: number; innerTo: number }

// text[start] 가 여는 $ 라는 가정 아래 3.1 규칙으로 짝을 찾는다.
// 줄바꿈을 만나면 멈춘다(R7). 편집 모드는 줄 글자를, 보기 모드(markdown-it)는
// state.src 와 state.pos 를 그대로 넘긴다 — 규칙이 한 벌만 존재하게 하는 지점이다
export function matchMathAt(text: unknown, start: number): MathMatch | null

// 한 줄 글자에서 R8 순서대로 반복 적용 (편집 모드가 쓴다)
export function findInlineMath(lineText: unknown): MathMatch[]

// 문단 글자 하나 → 블록 수식이면 { tex }, 아니면 null (3.3). parseImageBlock 과 같은 모양
export function parseMathBlock(paragraphText: unknown): { tex: string } | null
```

- `matchMathAt` 하나를 편집 모드와 보기 모드가 **함께** 쓴다. 이렇게 해야 `F-283` 8장 M3 같은 "편집과 보기가 한 글자 어긋남" 이 처음부터 생기지 않는다
- `findInlineMath` 는 `matchMathAt` 을 R8 순서로 부르는 얇은 반복문이다. 규칙은 `matchMathAt` 한 곳에만 적는다
- 인자 타입을 `unknown` 으로 받고 문자열이 아니면 빈 결과를 내는 방어는 `findHighlights`(`highlightSyntax.ts` 8행)와 같게 한다

### 5.1 `renderMarkdown.ts` — 인라인 규칙 + 블록 코어 규칙

**인라인은 코어 규칙이 아니라 인라인 규칙으로 넣는다.** 위키링크식(코어 규칙에서 `text` 자식 훑기)이면 R1(`\$`)을 지킬 수 없다 — 실측으로 확인했듯 markdown-it 의 `escape` 규칙이 먼저 돌아 `\$` 를 `text` 토큰의 `$` 로 바꿔 버려서, 코어 규칙 단계에서는 이스케이프였는지 알 길이 없다. 인라인 규칙이면 `escape`·`backticks` 가 우리 규칙보다 **먼저** 돌아 R1·R9 가 공짜로 맞는다 (`F-283` 3.1 이 같은 이유로 인라인 규칙을 골랐다)

```ts
md.inline.ruler.before('emphasis', 'math_inline', mathInlineRule)
md.core.ruler.before('inline', 'math_block', mathBlockRule)
md.renderer.rules.math_inline = …
md.renderer.rules.math_block = …
```

- `mathInlineRule(state, silent)`: `state.src.charCodeAt(state.pos) !== 0x24` 면 `false`. 맞으면 `matchMathAt(state.src, state.pos)` 를 부른다(3.5 — **편집 모드와 같은 함수**). `null` 이면 `false`. 짝이면 `math_inline` 토큰(`content` = TeX 원문)을 밀고 `state.pos` 를 닫는 기호 뒤로 옮긴다. `silent` 면 토큰을 밀지 않고 위치만 옮긴다(markdown-it 관례)
  - `$`(0x24)가 markdown-it 의 `text` 규칙 종결 문자 목록에 들어 있는 것을 실측으로 확인했다(`markdown-it.mjs` 2596~2623행 `isTerminatorChar` 의 `case 36`). 그래서 `text` 규칙이 `$` 앞에서 멈추고 우리 규칙에 차례가 온다
- `mathBlockRule(state)`: `imageBlockRule`(`renderMarkdown.ts` 164~187행)과 같은 모양 — `paragraph_open`(`level === 0`, B3) + `inline` + `paragraph_close` 세 토큰을 보고 `parseMathBlock(inline.content)` 이 참이면 셋을 `math_block` 토큰 하나로 바꾼다. `before('inline')` 이라 인라인 규칙이 그 문단을 보기 전에 치운다(3.2 마지막 줄)
- renderer 규칙 둘은 `renderMath`(6장) 결과를 그대로 내놓는다. 성공이면 KaTeX HTML, 실패면 `<span class="md-math-error">…원문…</span>`(인라인) / `<div class="md-math-error">…</div>`(블록). 원문을 넣을 때는 `md.utils.escapeHtml` 을 거친다
- `md` 인스턴스는 모듈 안 기존 것 하나를 그대로 쓴다. 새 인스턴스를 만들지 않는다

### 5.2 `Viewer.tsx` — 고치지 않는다

`F-258` 은 Mermaid 가 비동기라 `.md-mermaid[data-mermaid-source]` 를 나중에 채우는 `useEffect` 를 뒀다(`Viewer.tsx` 114~143행). **KaTeX 는 동기라 `renderMarkdown` 이 이미 완성된 HTML 을 내놓는다** — 채울 것이 없다. `Viewer.tsx` 는 부분 Edit 대상이 아니다

그 결과 공유 화면(`F-130`)·공개 보기(`F-210`)·인쇄(`F-279`)도 `Viewer` 를 그대로 쓰므로 **추가 작업 없이 수식이 나온다**

### 6.2 호출 방식

```ts
import katex from 'katex'
import 'katex/dist/katex.min.css'   // 앱 화면용. Vite 가 폰트를 같이 낸다

export type MathResult = { html: string } | { error: string }
export function renderMath(tex: string, options?: { display?: boolean }): MathResult
```

- 옵션은 `{ throwOnError: true, displayMode: display, trust: false, maxSize: 100 }`. 나머지는 KaTeX 기본값
- **`throwOnError: true` 로 부르고 우리가 잡는다.** `false` 로 두면 KaTeX 가 `<span class="katex-error" … style="color:#cc0000">` 을 직접 내놓는데(실측 확인), 이는 `CLAUDE.md` 불변조건 "색 hex 를 코드·CSS·HTML 에 직접 쓰지 않는다" 를 우리 출력 안에서 깬다. 잡아서 우리 클래스(`md-math-error`)로 바꾸면 색은 CSS 토큰이 정한다
- `trust: false`(기본값)는 `\href`·`\includegraphics` 를 막는다 — 실측: `\href{javascript:alert(1)}{x}` 는 링크가 아니라 빨간 오류 글자로 나왔고 `\includegraphics` 도 같았다. 공개 보기(`F-210`)에서 **남의 문서를 내 브라우저로 여는** 경로가 있으므로 이 기본값을 바꾸지 않는다. 외부 주소 요청이 생기지 않아 오프라인 원칙(`F-116`)과도 맞는다
- `maxSize: 100`(단위 em)은 `\rule{9999em}{9999em}` 류가 레이아웃을 무너뜨리는 것을 막는 값싼 방어다. 12장 Q5
- 출력 형식은 KaTeX 기본값(`htmlAndMathml`)을 유지한다 — 8장(접근성)
- **모듈 스코프에서 `katex` 를 정적 import 한다(비동기 로딩을 쓰지 않는다).** 그래야 5.2·7.1 의 "동기라서 공짜" 가 성립한다. 첫 화면 번들이 얼마나 커지는지는 **측정하지 않았다**(12장 M2)

## 7. 내보내기

### 7.1 무엇이 이미 되는가 (코드로 확인)

`buildExportBody`(`toHtmlDoc.ts` 68~74행)는 `renderMarkdown(withoutComments)` 을 부른 뒤 이미지 `data:` URI 와 Mermaid SVG 를 **정규식으로 채워 넣는다**. 수식은 그 단계가 필요 없다 — 5.1 의 renderer 규칙이 이미 최종 KaTeX HTML 을 내놓기 때문이다. 따라서

- `.html` 파일(`F-280`): **본문은 그대로 된다.** `toHtmlDoc.ts` 를 고치지 않는다
- 인쇄·PDF(`F-279`): 화면의 `Viewer` DOM 을 인쇄하므로 그대로 된다
- 서식 있는 복사(`F-280` 5장): `toInlineStyledHtml` 이 정해진 태그에만 `style=` 를 박는다. KaTeX 는 자기 치수를 `style=` 로 이미 달고 있어(실측: 간단한 식 하나에 `style="` 16개) 붙여넣는 앱이 CSS 를 버려도 **가로 배치는 어느 정도 남는다.** 다만 KaTeX 폰트가 없는 곳에서는 모양이 어긋난다 — 사람 확인 항목(14장)
- `.md` 내보내기(`F-112`): 원문 그대로. 이 명세는 원문을 건드리지 않는다

### 7.2 스크립트 없는 `.html` 에 수식이 들어가려면 무엇이 필요한가 (결론)

실측으로 확인한 것:

1. **JS 는 필요 없다.** `katex.renderToString('x^2 + \\frac{1}{2}')` 출력에 `<script` 가 없다(정규식으로 확인). `buildHtmlDocument` 의 마지막 방어 `SCRIPT_TAG_RE`(`toHtmlDoc.ts` 90행)에 걸릴 것도 없다
2. **CSS 는 반드시 필요하다.** `katex.min.css` 23,827 B. 이것이 없으면 위첨자·분수가 전부 평평한 글자열로 무너진다
3. **폰트도 반드시 필요하다.** `katex.min.css` 의 `font-family` 선언에는 **대체 글꼴이 하나도 없다**(실측: `font-family:KaTeX_Main` 처럼 이름 하나뿐, 13종 전부 같다). `@font-face` 를 떼면 브라우저가 문서 기본 글꼴로 그려 글리프 메트릭이 어긋나고 늘어나는 괄호·근호가 깨진다
4. 그런데 `exportHtmlCss.ts` 는 지금 **`stripFontFaceBlocks` 로 `@font-face` 를 떼고 있다**(`toHtmlDoc.ts` 77~79행, `F-280` 4.4) — 단독 파일에서 상대 경로 `url(fonts/…)` 가 깨지기 때문이다. KaTeX CSS 를 그냥 붙이면 같은 이유로 폰트가 깨진다

**결론 — 내보내기 CSS 를 이렇게 만든다** (`exportHtmlCss.ts` 부분 Edit):

```ts
// katex.min.css 의 @font-face 를 떼고, woff2 20개를 data: URI 로 다시 쓴 @font-face 를 붙인다
export const MATH_EXPORT_CSS = stripFontFaceBlocks(katexCssRaw) + KATEX_FONT_FACE_INLINE
```

- 폰트는 Vite 의 `?inline` 로 base64 `data:` URI 를 받는다. Vite 에 그 기능이 있는 것을 소스에서 확인했다(`node_modules/vite/dist/node/chunks/config.js` `shouldInline`: `if (inlineRE.test(id)) return true`) — 파일 종류를 가리지 않으므로 `.woff2` 에 쓸 수 있다
- 넣는 것은 **woff2 20개뿐**(실측 259,792 B → base64 약 346 KB). `.ttf`·`.woff` 는 넣지 않는다. 판정 브라우저가 Chrome 이고(`product.md` Q7) woff2 를 지원한다
- **수식이 없는 문서의 내보내기 결과를 지금과 똑같이 둔다.** `exportDoc.ts` 에서 본문에 KaTeX 출력이 있을 때만(`body.includes('class="katex')`) `MATH_EXPORT_CSS` 를 이어 붙인다. `buildHtmlPayload({ title, body, css })` 는 이미 `css` 를 인자로 받으므로(`exportDoc.ts` 188~200행) 순수 함수 쪽은 고칠 것이 없고 단위 테스트로 판정할 수 있다(A18)
- 첫 화면 번들에는 영향이 없다 — `exportHtmlCss` 는 이미 동적 import 다(`exportDoc.ts` 244행, `F-280` 6.1 "CSS 원문 ~60KB 를 첫 화면 번들에서 뗀다")

### 7.3 앱 화면 쪽 폰트

`mathRender.ts` 가 `katex/dist/katex.min.css` 를 import 하면 Vite 가 폰트 파일을 `dist/assets/` 로 내보내고 `url()` 을 고쳐 쓴다. 서비스 워커 precache 글롭이 `woff2` 를 포함하고(`vite.config.ts` 206행) 파일 하나 상한이 3MB 라(211행) woff2 20개(합 259,792 B)는 그대로 들어간다 — **오프라인에서도 수식이 보인다**(`F-116`). `.ttf`·`.woff` 도 `dist` 에는 나오지만(합 1,076,572 B) precache 대상이 아니고 Chrome 은 woff2 를 먼저 고르므로 요청되지 않는다. 필요하면 나중에 빌드에서 떼는 것을 따로 본다 — 12장 Q6

### 7.4 `.txt` 평문 (`toPlainText.ts`)

| 토큰 | 평문 |
| --- | --- |
| `math_inline` | TeX 원문 그대로, `$` 기호는 뗀다 (`$E = mc^2$` → `E = mc^2`) |
| `math_block` | TeX 원문 줄 그대로, `$$` 줄은 뗀다 |

`F-278` 이 세운 규칙 그대로다 — 강조 기호(`strong_open` 등)는 떼고 안쪽 글자는 남긴다(`toPlainText.ts` 49~58행). Mermaid 를 `[다이어그램]` 으로 바꾼 것(237~239행)과 다르게 가는 이유: 다이어그램 원문은 읽을 수 없는 그림 명세지만 **TeX 는 글자라 `E = mc^2` 는 평문으로도 읽힌다.** 12장 Q7 에 대안(`[수식]`)을 남긴다

구현은 `inlineToText` 의 `switch` 에 `case 'math_inline': out += t.content` 한 줄, `renderBlockSequence` 에 `case 'math_block': blocks.push(t.content)` 한 줄이다

## 8. 접근성

- KaTeX 기본 출력(`htmlAndMathml`)을 그대로 쓴다. `<span class="katex-mathml">` 안에 MathML 이 들어가고 시각용 `<span class="katex-html">` 에는 `aria-hidden="true"` 가 붙는다(실측 확인) — 스크린 리더가 MathML 을 읽는다. **`output: 'html'` 로 줄이지 않는다**(그러면 MathML 이 빠진다. 실측: 2,031 B → 1,756 B, 275 B 아끼자고 접근성을 버리는 거래다)
- MathML 안 `<annotation encoding="application/x-tex">` 에 TeX 원문이 그대로 들어간다 — 내보낸 `.html` 에서도 원문을 되찾을 수 있다
- 오류 표시 `.md-math-error` 는 색만으로 알리지 않는다. `title` 속성에 오류 문구를 넣어 마우스로도 읽히게 한다(인라인. 블록은 문구 자체가 보인다)
- 편집 모드 위젯은 `contenteditable` 바깥 DOM 이라 키보드 초점을 받지 않는다. 방향키로 지나갈 수 있어야 하고 그 판정은 `blocks.ts` 의 기존 보조가 맡는다(4.2)
