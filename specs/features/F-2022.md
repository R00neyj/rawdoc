## 2. 범위

### 한다
- 명령 팔레트 D-7: `Ctrl+P` 와 에디터 우클릭 `명령 팔레트…` 로 연다. 입력칸 + 걸러지는 목록, 두 단계(명령 → 템플릿)
- 명령 등록 구조(3장)와 1차 명령 2개: `템플릿 삽입`, `PDF (A4 인쇄)`

- 기존 명령(서식·단락·삽입·검색·설정 등)을 팔레트에 옮겨 담기 — 3장 구조가 그것을 받을 수 있게만 한다

## 3. 명령 등록 계약 — `src/app/paletteContract.ts`

### 3.1 타입

이 모양 자체가 결정이다(다음 명령을 더하는 사람이 이 계약에 맞춘다)

```ts
// 목록 한 줄 — 명령이든 2단계 항목(템플릿)이든 같은 모양
export type PaletteItem = {
  id: string
  label: string
  detail?: string                 // 오른쪽 흐린 글자 — 템플릿 폴더 경로, '내장'
  keywords?: readonly string[]    // 거르기에만 쓰고 화면에 안 보인다
}

// 명령이 읽는 화면 상태와 App 이 넘기는 동작. 명령을 더하다 필요한 값이 생기면 여기에 필드를 더한다
export type PaletteContext = {
  canInsertTemplate: boolean      // 6.3
  canPrint: boolean               // 6.3
  templates: readonly TemplateEntry[]   // src/lib/templates.ts, 4.1
  insertTemplate: (templateId: string, signal: AbortSignal) => Promise<void>   // 5.7
  printDoc: () => void            // F-279 handlePrintDoc
}

type PaletteCommandBase = PaletteItem & {
  shortcut?: string               // 오른쪽 끝 표시만. 키를 등록하지 않는다
  when: (ctx: PaletteContext) => boolean   // false 면 목록에 아예 없다(흐리게 두지 않는다)
}

// 고르면 팔레트를 닫고 바로 실행
export type PaletteActionCommand = PaletteCommandBase & {
  kind: 'action'
  run: (ctx: PaletteContext) => void
}

// 고르면 2단계 목록으로 들어간다
export type PalettePickCommand = PaletteCommandBase & {
  kind: 'pick'
  stageTitle: string              // 2단계 h2
  placeholder: string             // 2단계 입력칸 자리 표시·aria-label
  emptyText: string               // 걸러서 0개일 때
  hint?: (ctx: PaletteContext) => string | null   // 목록 아래 안내 한 줄
  items: (ctx: PaletteContext) => readonly PaletteItem[]
  pick: (item: PaletteItem, ctx: PaletteContext, signal: AbortSignal) => void | Promise<void>
}

export type PaletteCommand = PaletteActionCommand | PalettePickCommand

export function visibleCommands(commands: readonly PaletteCommand[], ctx: PaletteContext): PaletteCommand[]
export function filterPaletteItems<T extends PaletteItem>(items: readonly T[], query: string): T[]
```

### 3.2 규칙
- **명령 id** 는 `영역.동작` 소문자 점 구분(`template.insert`, `doc.print`). 목록 안에서 겹치지 않는다(U3 이 판정)
- `when` 이 `false` 인 명령은 **목록에 없다.** 흐린 비활성으로 두지 않는다 — 팔레트는 "지금 할 수 있는 것" 목록이다. VS Code 명령 팔레트가 `when` 절로 숨기는 방식과 같다
- `visibleCommands` 는 등록 순서를 지킨다
- 실행 수명:
  - `action` — 팔레트가 **먼저 닫히고** `run` 이 불린다
  - `pick` — `pick` 이 도는 동안 팔레트는 **열린 채**다. 250ms 넘게 걸리면 상태 줄에 `불러오는 중…`(F-288 Q4 와 같은 지연). 이 동안 `Esc`·바깥 클릭으로 닫으면 `signal` 을 abort 한다. `pick` 이 끝났는데 팔레트가 아직 열려 있으면 팔레트가 스스로 닫는다. `pick` 이 문서를 바꿀 때는 **먼저 팔레트를 닫고** 바꾼다(5.7 — 포커스·조합 때문)
- 명령을 하나 더하는 일 = `PALETTE_COMMANDS` 에 한 줄 + (필요하면) `PaletteContext` 에 필드 하나 + `App.tsx` 에서 그 값을 채우는 한 곳. UI(`CommandPalette.tsx`)는 고치지 않는다

### 4.2 템플릿 폴더 — 고정 이름

- **템플릿 폴더 = 화면 트리에서 최상위인 내 폴더 중 이름이 `템플릿` 이거나 `templates`(대소문자 무시)인 것.** 이름은 `normalizeForSearch` 후 앞뒤 공백을 떼고 비교한다. "최상위" 는 `screenParentResolver(folders)` 가 `null` 을 돌려주는 폴더다(끊긴 부모·순환도 화면에서 최상위라 같이 본다, F-2017)
- 그런 폴더가 여럿이면 **전부** 쓴다
- **그 폴더와 모든 하위 폴더(`descendantFolderIds`) 안의 문서**가 템플릿이다(옵시디언 템플릿 폴더와 같게 하위까지)
- `role` 이 `'edit'`·`'view'` 인 문서(공유받은 문서)는 넣지 않는다. 서버 저장소의 폴더 목록은 원래 내 것뿐이다(`worker/folders.ts` 의 `WHERE owner_id = ?`)
- 제목이 비었으면(앞뒤 공백 뗀 뒤) `제목 없는 문서`
- `detail` = 템플릿 폴더 이름부터 문서가 든 폴더까지 `' / '` 로 이은 것(검색 결과 `folderPath` 와 같은 모양). 템플릿 폴더 바로 아래 문서는 폴더 이름 하나
- 순서: **사용자 템플릿 먼저**(제목 `localeCompare(…, 'ko')`, 같으면 `detail`), 그다음 내장(4.4 표 순서). 사용자가 직접 만든 것을 먼저 찾을 가능성이 높아서다
- 템플릿 폴더 안의 문서는 템플릿이면서 **보통 문서**다 — 검색·지도·위키링크·내보내기에서 따로 빼지 않는다(옵시디언도 기본으로 빼지 않는다)

왜 설정이 아니라 고정 이름인가 (13장 Q2): 설정(`localStorage`)은 기기마다 따로라 서버 저장소 사용자가 기기마다 다시 골라야 하고, 폴더 고르기 UI 가 새로 필요하다. 고정 이름은 UI 가 0개이고 모든 기기·볼트 가져오기(F-2019)에서 바로 먹는다. 영어 `templates` 를 함께 받는 이유는 옵시디언 볼트에서 가장 흔한 폴더 이름이라서다(옵시디언 템플릿 폴더 설정의 기본값이 없어 흔한 관례일 뿐이다 — 14.2)

## 5. 넣기

### 5.1 순서 (App, 5.7 에서 다시 적는다)
원문 읽기 → `toEditorText`(LF) → `expandTemplateVariables` → `planTemplateInsert(에디터 본문, 치환된 글)` → `insertTemplate`(자리 계산 + 트랜잭션 1개)

### 5.2 변수 치환 — 1차에 넣는다

옵시디언 기본 템플릿 플러그인의 세 변수를 같은 이름으로 받는다. 볼트를 가져온(F-2019) 사용자의 템플릿이 그대로 먹게 하려는 것이다

| 쓰는 글 | 바뀌는 값 |
| --- | --- |
| `{{date}}` | `formatTemplateDate(now, 'YYYY-MM-DD')` |
| `{{time}}` | `formatTemplateDate(now, 'HH:mm')` |
| `{{date:형식}}`·`{{time:형식}}` | `formatTemplateDate(now, 형식)` |
| `{{title}}` | 지금 문서 제목. 앞뒤 공백을 뗀 뒤 비었으면 `제목 없는 문서` |

- 이름은 소문자 그대로만 받는다. `{{ date }}`(안쪽 공백)·`{{Date}}`·`{{title:x}}`·`{{모르는것}}` 은 **글자 그대로 둔다**
- `형식` 은 `}` 를 뺀 아무 글자. `now` 는 **고른 순간**의 브라우저 지역 시간(`new Date()`)
- 프론트매터 안의 변수도 바꾼다(치환이 프론트매터 분리보다 먼저)

`formatTemplateDate` 토큰 — 왼쪽부터 읽으며 **가장 긴 토큰**을 먼저 맞춘다. 표에 없는 글자는 그대로

| 토큰 | 값 (2026-09-23 09:05:07 수요일 기준) |
| --- | --- |
| `YYYY` · `YY` | `2026` · `26` |
| `MM` · `M` | `09` · `9` |
| `DD` · `D` | `23` · `23` |
| `HH` · `H` | `09` · `9` |
| `mm` · `ss` | `05` · `07` |
| `dddd` · `ddd` | `수요일` · `수` |
| `[글자]` | 대괄호 안을 그대로, 대괄호는 빠진다 (`[오늘] YYYY` → `오늘 2026`) |

- moment 의 나머지 토큰(`Do`·`hh`·`A`·`m` 한 글자 등)은 받지 않는다. `Do` 는 `D` + `o` 로 읽혀 `23o` 가 된다 — U5 가 이 한계를 그대로 못박는다. 필요해지면 토큰을 더한다

### 5.3 본문 자리 — F-169 블록 자리 규칙 + 불투명 블록 뒤로

템플릿은 여러 줄 블록(제목·목록)이 대부분이라 **커서 글자 사이에 끼우지 않고 줄 단위로 넣는다.** 옵시디언은 커서 자리에 그대로 넣지만, 여기서는 줄 가운데 `## 회의` 가 붙어 제목이 되지 않는 일을 막는 쪽을 골랐다(13장 Q5)

- **빈 문서**(`state.doc.length === 0`)면 치환된 템플릿 전체를 앞뒤 빈 줄만 떼고 그대로 넣는다. 프론트매터 합치기(5.4)는 하지 않는다 — 통째로 들어가 프론트매터가 저절로 맨 앞에 선다
- 그 밖: 기준 줄 = 주 선택의 마지막 줄(`insertCommands.ts` 의 `selectionLines` 규칙 — 여러 줄 선택의 끝이 열 0 이면 그 줄은 뺀다)
  - 기준 줄 머리가 **펜스 코드블록·프론트매터·표 안**이면(구문 트리 부모 사슬에 `FencedCode`·`Frontmatter`·`Table`, 확인 (b)) 기준 줄을 **그 블록의 마지막 줄**로 바꾼다. F-169 는 이 경우 아무것도 안 하지만(`false`), 템플릿은 "못 넣습니다" 대신 블록 뒤에 넣는다 — 표 칸 편집 중·코드 안에서 `Ctrl+P` 를 눌러도 결과가 있다
  - 그다음은 F-169 2장 그대로(`computePlacement(state, first, last, false)` + `buildInsert`): 기준 줄이 빈 줄 하나면 그 줄에, 아니면 기준 줄 끝 뒤 새 줄에. 윗줄이 있고 비지 않았으면 앞에 빈 줄 1개, 아랫줄이 있고 비지 않았으면 뒤에 빈 줄 1개
- **선택은 지우지 않는다.** 선택이 있으면 선택의 마지막 줄 뒤에 넣는다(F-169 의 표·수평선과 같다). 옵시디언은 선택을 바꿔 넣지만, 선택한 글을 잃는 쪽보다 남기는 쪽을 골랐다(13장 Q6)
- 본문 다듬기(`planTemplateInsert`): 앞뒤의 **빈 줄**(글자 0개인 줄)을 뗀다. 공백만 있는 줄·마지막 줄 끝 공백(`- [ ]␣`)은 그대로 둔다 — 목록 표지 뒤 공백이 커서 자리다

### 5.4 프론트매터

`planTemplateInsert` 가 정한다. 문서 쪽 = `findFrontmatter(에디터 본문)`, 템플릿 쪽 = `findFrontmatter(치환된 글)`

| 문서 | 템플릿 | 결과 |
| --- | --- | --- |
| 비었음 | 무엇이든 | 5.3 첫 줄 — 통째로 |
| 없음 | 없음 | 본문만 |
| 없음 | 있음 | **문서 맨 앞(0)에** `---⏎` + 템플릿 프론트매터 내용 + `---⏎` 를 넣는다(닫는 줄이 `...` 이었어도 `---`). 사이에 빈 줄을 더하지 않는다. 본문은 5.3 자리에. 같은 자리(0)면 프론트매터가 앞 |
| 있음 | 없음 | 본문만 |
| 있음 | 있음, 둘 다 `parseSimpleProperties` 가 `null` 이 아님 | **문서에 없는 키만** 템플릿의 원래 줄 그대로(키 줄 + 이어지는 들여쓴 `  - 값` 줄) 문서 닫는 줄 바로 앞(`contentTo`)에 더한다. 문서에 이미 있는 키는 문서 값을 둔다. 템플릿의 주석 줄(`#`)·빈 줄은 옮기지 않는다. 더할 키가 없으면 프론트매터 변경 없음 |
| 있음 | 있음, 어느 한쪽이 `null`(중첩·여러 줄 문자열) | 프론트매터는 건드리지 않고 본문만. `frontmatterSkipped: true` → info 알림 `템플릿 속성을 문서 속성에 합치지 못해 본문만 넣었습니다.` |

- 키 비교는 `parseSimpleProperties` 가 돌려준 `key`(앞뒤 공백 뗀 것) 그대로, 대소문자 구분
- 템플릿 프론트매터를 뗀 나머지(`textAfterFrontmatter`)가 본문이다 — 그 뒤 5.3 다듬기
- 옵시디언도 속성을 합친다고 알려져 있으나 충돌 규칙은 확인하지 않았다(14.2). "문서 값 우선" 은 이미 적어 둔 값을 지우지 않는 쪽을 고른 것이다

### 5.5 커서
- 넣은 본문의 **마지막 글자 바로 뒤**(뒤에 붙인 빈 줄 앞). 내장 템플릿은 `- [ ]␣`·`1.␣`·`-␣` 뒤에 선다
- 본문이 비었으면(템플릿이 프론트매터뿐) 커서는 원래 자리(변경에 따라 옮긴 값)
- 커서가 보이게 스크롤한다(`scrollIntoView: true`)
- 치환 뒤 템플릿이 공백·줄바꿈뿐이면 아무것도 넣지 않고 info 알림 `템플릿이 비어 있습니다.`

### 5.6 트랜잭션과 되돌리기 — `src/editor/insertTemplate.ts`

```ts
export function insertTemplate(
  target: { state: EditorState; dispatch: (tr: Transaction) => void },
  templateText: string,           // 치환이 끝난 LF 글
): { inserted: boolean; frontmatterSkipped: boolean }
```

- 프론트매터 변경과 본문 변경을 **트랜잭션 1개**에 담는다. `userEvent: 'input.template'` — 이 값이 계약이다: `input.type`·`delete` 로 시작하지 않아 `nextUndoGroup` 이 **새 묶음을 연다**(확인 (a)). 그래서 `Ctrl+Z` 한 번에 프론트매터·본문이 함께 사라진다. `input.type` 이 아니라 자동완성(`wikiComplete`)도 켜지지 않는다
- `state.readOnly` 면 아무것도 안 하고 `inserted: false`
- `Y.Doc` 원본(F-302)과의 관계: 보통 로컬 편집 트랜잭션이다. `y-codemirror.next` 가 `Y.Text` 로 옮기고 `Y.UndoManager` 가 내 편집으로 기록한다. 원격 게이트(F-303)는 원격 업데이트만 다루므로 이 명세와 닿지 않는다
- **알려진 모양:** 넣은 직후 **500ms 안에** 넣은 글 끝에 이어 치면 그 글자가 템플릿 묶음에 합쳐져 `Ctrl+Z` 한 번에 같이 사라진다(확인 (a), `UNDO_GROUP_DELAY_MS`). 붙여넣기와 같은 규칙이고 CM6 `history()` 도 같다(F-302 4.4). 따로 끊지 않는다

### 5.7 App 의 `insertTemplate(templateId, signal)`
1. `canInsertTemplate`(6.3) 가 거짓이면 info 알림 `읽기 전용이라 템플릿을 넣지 못했습니다.` 뒤 끝
2. 시작할 때의 `currentDocId` 를 기억한다
3. 원문 읽기: 내장은 `body`, 사용자 템플릿은 4.3 표. 실패·`null` → error 알림 `템플릿을 읽지 못했습니다.` 뒤 끝(팔레트는 3.2 수명대로 닫힌다)
4. `signal.aborted` 면 조용히 끝. 지금 `currentDocId` 가 2번 값과 다르거나 `canInsertTemplate` 가 거짓이 됐으면 조용히 끝(사용자가 이미 다른 곳으로 갔다)
5. **팔레트를 닫는다.** 그다음 같은 틱에 `toEditorText` → `expandTemplateVariables({ title: 현재 문서 제목, now: new Date() })` → `insertTemplate(주 에디터 view, …)`
6. 결과에 따라 5.4·5.5 알림
7. **최종 포커스는 주 에디터**(커서 보이게). 주의: `Dialog.tsx` 는 `close` 이벤트(비동기)에서 **연 순간의 요소**로 포커스를 돌린다 — 팔레트를 제목 입력·사이드바에서 열었으면 그 복귀가 에디터 포커스를 덮을 수 있다. 덮이지 않게 하는 방법은 구현이 고른다(A11 이 제목 입력에서 열어 판정한다)

- 넣는 동안 팔레트 입력칸이 포커스를 갖고 있었으므로 **에디터가 한글 조합 중일 수 없다.** 그래서 조합 중 미룸·따라잡기(불변조건)가 필요 없다. 읽기를 팔레트가 열린 채로 하는 이유가 이것이다(3.2)
- 표 칸 하위 에디터에서 열었어도 넣는 곳은 **주 에디터**다. 팔레트가 포커스를 가져가며 칸 편집이 끝나고(F-125 blur 확정), 주 에디터 선택이 표 안이면 5.3 규칙으로 표 뒤에 들어간다

## 6. `Ctrl+P`

### 6.1 어디서 무엇을 하나

`App.tsx` 의 지금 `Ctrl+P` effect(F-279 6.1)를 **이 표로 바꾼다.** 키 조건식은 그대로(`ctrlKey || metaKey`, `shiftKey`·`altKey` 없음, `e.key.toLowerCase() === 'p'`). 위에서부터 먼저 걸리는 것

| 상황 | 동작 | 이유 |
| --- | --- | --- |
| 공개 보기 S-5(`publicRoute`) | 가로채지 않음 → 브라우저 인쇄 | 읽기 화면. F-279 6.2 와 같다. `Ctrl+Shift+F` effect 도 여기서 빠진다 |
| 공유 링크 화면 S-4(`sharedDoc`) | 가로채지 않음 → 브라우저 인쇄 | 같은 이유. F-279 6.2 그대로 |
| 부팅 중(`bootPhase !== 'ready'`) | `preventDefault`, 아무것도 안 함 | 스켈레톤을 인쇄해 봐야 쓸모가 없고, 곧 팔레트 키가 될 키가 잠깐 인쇄 창을 여는 것이 더 놀랍다. 다른 창이 저장소를 막아 부팅이 안 끝나는 화면(F-136)도 같다 |
| 팔레트가 열려 있음 | `preventDefault`, 입력칸 글 전체 선택 | 검색 대화상자 `Ctrl+Shift+F` 와 같은 모양(F-287 3.4) |
| 팔레트 말고 다른 대화상자가 열려 있음(`dialog[open]` 이 팔레트가 아님) | `preventDefault`, 무시 | 대화상자 위에 겹치지 않는다(F-287 3.4 와 같은 판정). 인쇄 창도 안 연다 |
| 그 밖 — 편집 화면 S-1, 홈·빈 상태 S-2, 공유 관리 S-6, 도움말 S-7, 지도 S-8 | `preventDefault`, 팔레트 1단계로 열기 | 팔레트는 앞으로 앱 전체 명령을 받을 자리다. 지금은 쓸 명령이 없는 화면(홈 등)도 있다 — 8.3 빈 상태 문구 |

- **에디터 안에 포커스가 있어도 가로챈다.** Windows·Linux 에서 CM6 는 `Ctrl+P` 를 쓰지 않는다(`Ctrl-p` 는 `emacsStyleKeymap` 이 `mac:` 으로만 넣는다 — `node_modules/@codemirror/commands/dist/index.js` 1698·1770행). 앱 키맵(`shortcutKeymap` `Mod-b/i/k`, `Mod-h`, 찾기 키맵)에도 없다
- macOS 에서 `Ctrl+P`(ctrlKey)는 CM6 `cursorLineUp` 과 겹쳐 커서가 한 줄 올라가며 팔레트도 열린다. F-279 6.1·H155 와 같은 성질이고 같은 조건식을 쓴다. `Cmd+P` 는 겹치지 않는다
- 팔레트를 열 때: 열려 있던 우클릭 메뉴를 닫는다. 좁은 창(1024px 미만)에서 겹친 사이드바가 열려 있으면 닫는다(`openSearch` 의 `closeSidebarIfNarrow` 와 같다)
- 한글 입력 상태에서 `Ctrl+P` 의 `e.key` 가 `'p'` 로 오는지는 확인하지 못했다 — 사람 확인 H5. 지금 `Ctrl+F`·`Ctrl+Shift+F` 가 같은 판정(`e.key`)을 쓰고 H189 가 대기 중이다

### 6.2 인쇄가 가는 길
- 내보내기 메뉴 `PDF (A4 인쇄)` — 그대로(F-279 3장)
- 팔레트 명령 `PDF (A4 인쇄)` — 새로 더한다. `Ctrl+P` → `인쇄` 또는 `pdf` → `Enter` 로 키보드만으로 인쇄할 길이 남는다. 1차 범위를 템플릿 하나로 두라는 요청과의 균형: **새 기능이 아니라 이 명세가 빼앗는 길을 되돌려 놓는 것**이고, 비용은 등록 한 줄 + 기존 `handlePrintDoc` 호출뿐이다. 두 번째 명령이 `action` 종류라 3장 계약의 두 갈래가 1차부터 둘 다 쓰인다는 이점도 있다(13장 Q3)
- 브라우저 메뉴(⋮ → 인쇄)는 F-279 5장대로 화면 그대로 인쇄된다

### 6.3 명령이 보이는 조건 — `PaletteContext` 의 두 값

`canInsertTemplate` 는 아래가 **모두** 참일 때

- `bootPhase === 'ready'`, 공유 링크 화면(S-4)이 아님
- 현재 문서가 있고 그 문서의 에디터가 떠 있음(`openDoc.id === currentDocId`, `editorRef.current` 있음)
- 보기 모드가 `편집`·`원문`(`viewMode` 가 `'live'`·`'raw'`). `보기` 에서는 커서 자리가 화면에 없어 어디에 들어갈지 보이지 않는다
- `isReadOnlyDoc` 거짓 — 보기 권한·403 강등(F-212), 편집 잠금(F-213), 다른 탭 편집권(F-296 6.4), 다른 탭에서 지워짐(F-296 7.3)을 한꺼번에 덮는다
- 지도(S-8)·도움말(S-7)·공유 관리(S-6)가 편집 영역을 덮고 있지 않음(`mapRoute`·`helpOpen`·`sharesOpen` 거짓)

`canPrint` 는 지금 `printDisabledRef` 가 거짓인 조건과 **같다**(`bootPhase === 'ready' && currentDocId !== null && !sharedDoc`). F-279 의 인쇄 가능 범위를 바꾸지 않는다

## 8. 팔레트 UI — `src/app/CommandPalette.tsx` (D-7)

### 8.1 모양
- 공용 `Dialog`(네이티브 `<dialog>` + `showModal`, 뒤 막·흐림·열고 닫는 전환은 기존 규칙 그대로) + `size="wide"`(520px, 좁은 창은 창 폭 − 32px). `Dialog.tsx` 는 고치지 않는다
- **창 위쪽에 고정**한다: 기본값 위 여백 `12vh`. 가운데 정렬(D-6)이면 거를 때마다 목록 높이가 바뀌어 입력칸이 위아래로 움직인다. 위치는 `palette.css` 의 `.dialog:has(> .command-palette)` 로 준다. 값은 사람 확인 H1
- 위에서부터: `h2`(1단계 `명령 팔레트`, 2단계 명령의 `stageTitle`) → 입력칸 줄(돋보기 아이콘 `IconSearch` + 입력칸, D-6 `search-input-row` 와 같은 모양) → 목록 또는 상태 문구 → 안내 줄(있을 때)
- 목록 한 줄 = 왼쪽 `label`, 오른쪽 흐린(`--muted`) `detail` 또는 `shortcut`. 아이콘 없음. 목록 최대 높이 `min(360px, 60vh)`, 넘으면 목록 안에서 스크롤, 선택 줄이 보이게 따라간다(`scrollIntoView({ block: 'nearest' })`)
- 선택 줄 표시·호버 색 전환은 D-6 결과 행과 같은 규칙(`design.md` 4장 선택 상태·전환). 시각값은 e2e 로 고정하지 않는다

### 8.2 두 단계
- **1단계(명령):** `visibleCommands(PALETTE_COMMANDS, ctx)` 를 `filterPaletteItems` 로 거른 목록
  - `action` 을 고르면 → 닫고 `run`
  - `pick` 을 고르면 → **2단계**: 입력칸을 비우고, `h2`·자리 표시를 그 명령 값으로, 목록 = `filterPaletteItems(command.items(ctx), 검색어)`, 첫 줄 선택
- **2단계(항목):** 고르면 `pick(item, ctx, signal)` (3.2 수명)
- 2단계에서 **입력칸이 빈 채 `Backspace`** → 1단계로 돌아간다. 검색어는 비고, 선택은 방금 들어갔던 명령 줄
- 한 목록에 명령과 템플릿을 섞지 않는 이유(13장 Q4): 명령이 늘면 템플릿 수십 개가 명령을 밀어낸다. 옵시디언(`Templates: Insert template` → 템플릿 고르기)·VS Code(명령 → 빠른 고르기)가 같은 두 단계다

### 8.3 상태 문구 (목록 자리, 하나만)

| 상태 | 문구 |
| --- | --- |
| 1단계, 보일 명령이 0개(검색어와 무관) | `지금 쓸 수 있는 명령이 없습니다` |

- 문구 요소는 `role="status"`

### 8.4 키보드·마우스·접근성
- 열리면 입력칸에 포커스, 1단계 첫 줄 선택
- `↑` `↓` — 선택 옮기기, 끝에서 처음으로(`searchResults.ts` 의 `nextResultIndex` 를 그대로 쓴다). 포커스는 입력칸에 남는다
- `Enter` — 선택 줄 실행. **`isComposing` 이 참인 `keydown` 은 무시한다.** 한글을 치다 `Enter` 를 누르면 Chrome 이 조합 중 `keydown`(Enter) 뒤에 조합이 끝난 `keydown` 을 한 번 더 보낸다고 알려져 있어, 막지 않으면 1단계 `Enter` 가 2단계로 넘어간 뒤 두 번째 `Enter` 가 첫 템플릿을 넣어 버린다(14.2 가정 — 사람 확인 H3)
- 검색어가 바뀌면 첫 줄 선택(0개면 선택 없음)
- `Esc`·뒤 막 클릭 — 닫기(`Dialog` 기본). 2단계에서도 한 번에 닫힌다. `pick` 이 도는 중이면 abort(3.2)
- 줄 클릭 — 그 줄 실행. 마우스를 올려도 선택은 옮기지 않는다(D-6 과 같다)
- 입력칸: `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls="command-palette-list"`, `aria-activedescendant`, `aria-label` = 1단계 `명령 이름` / 2단계 명령의 `placeholder`. 자리 표시도 같은 글
- 목록: `role="listbox"`, `id="command-palette-list"`, `aria-label` 1단계 `명령` / 2단계 `템플릿`. 줄: `role="option"`, `id="command-palette-option-{i}"`, `aria-selected`
- 닫으면 검색어·단계를 버린다. 다음에 열면 늘 1단계, 빈 검색어(최근 명령을 기억하지 않는다)

### 14.1 코드를 읽거나 돌려 확인한 것

### 14.2 가정으로 남긴 것
- **옵시디언 템플릿 동작** — 변수 이름(`{{date}}`·`{{time}}`·`{{title}}`, `{{date:형식}}`), 기본 형식(`YYYY-MM-DD`·`HH:mm`), 하위 폴더까지 템플릿으로 치는 것, 속성 합치기는 기억에 기댄 것이다. 이번에 옵시디언을 돌려 보거나 문서를 열어 확인하지 않았다. 틀려도 이 명세의 규칙은 자기 완결적이다(옵시디언과 다른 점만 생긴다)
