# F-259 위키링크 묶음 공유 링크, 묶음 바뀌어도 주소 유지

작성일: 2026-09-18
상태: 사용자 지시(2026-09-18 "위키링크 추가될때마다 링크 초기화되는데 방법 없음?") — 대화에서 "주소는 유지하고 묶음만 갱신" 으로 확인. **사용자 승인**
근거: `F-252`(D-6 대화상자, 묶음 발급) 0장·2.4·3.2. 이 명세가 F-252 의 해당 결정을 대체한다

## 1. 문제

F-252 는 "묶음이 바뀌면 이전 주소를 끊고 새 주소를 발급한다" 로 정했다(F-252 0장, 이유: 조회 시점 동적이면 문서 편집이 곧 의도치 않은 공개가 된다는 우려). 그런데 실제로는 **주소를 이미 배포한 뒤 위키링크를 하나 추가하고 D-6 에서 그 문서를 체크해 다시 `링크 복사` 를 누르는 것만으로도 주소가 바뀐다** — 이미 나눠준 링크가 끊긴다. 사용자에게는 "위키링크 추가할 때마다 링크가 초기화된다"로 느껴진다

## 2. 결정

- **주소(토큰)는 살아있는 링크가 있는 한 유지한다.** 체크한 묶음이 바뀌어도 새 토큰을 만들지 않고 `share_link_docs` 행만 갱신한다
- F-252 가 막으려던 "편집 = 의도치 않은 공개" 문제는 그대로 막는다 — **묶음은 여전히 D-6 에서 사람이 체크박스로 직접 고르고 `링크 복사` 를 눌러야만 바뀐다.** 원문에 `[[D]]` 를 쓰는 것만으로는 아무 것도 안 바뀐다(F-252 와 동일)
- 대신 **주소가 고정되므로, 이미 그 주소를 아는 사람은 나중에 새로 체크한 문서도 보게 된다.** D-6 에 이 사실을 알리는 문구를 새로 넣는다(3장)
- 체크 해제로 문서를 뺄 때도 같다 — 주소는 그대로, 그 문서만 묶음에서 빠진다

## 3. 파일 소유

| 파일 | 변경 |
| --- | --- |
| `worker/links.ts` | `handleCreateDocLink`: 살아있는 링크가 있으면 묶음이 달라도 토큰을 끊고 새로 만들지 않는다. `share_link_docs` 를 그 토큰 기준으로 지우고 다시 넣는다. 새 토큰 발급은 "살아있는 링크가 아예 없을 때"만 |
| `src/app/ShareSetDialog.tsx` | 기존 경고 문구(주소가 새로 발급된다는 내용)를 지우고, 체크한 묶음이 기존 링크와 다를 때 "이미 이 주소를 아는 사람도 방금 선택한 문서를 보게 됩니다" 로 바꾼다. `sameIdSet`/`showWarning` 로직은 그대로 재사용(비교 대상만 유지) |

## 4. 하지 않는다

- 새 토큰 발급 경로(살아있는 링크가 없을 때) 변경 없음
- `GET /pub/docs/:token/set`·`GET /pub/docs/:token/docs/:docId` 등 조회 라우트 변경 없음 — 이미 `share_link_docs` 를 그때그때 읽으므로 갱신만 되면 자동으로 반영된다
- D-6 을 열지 않고 원문 편집만으로 묶음이 바뀌는 동작은 만들지 않는다(F-252 와 동일하게 사람이 체크해야 바뀐다)
