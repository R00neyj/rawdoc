### 2.1 이 커밋이 끝난 시점의 상태

지도를 열고 `지도 설정` 을 누르면 **`필터`·`그룹`·`표시`·`장력` 네 묶음**이 쌓이고 맨 위 `필터` 가 펼쳐져 있다. `그룹` 을 펼치면 `새 그룹` 버튼 하나와 안내 한 줄이 있고, 누르면 행이 하나 생긴다. 조건 칸에 `tag:일기` 를 치면 **그 조건에 맞는 문서 노드가 그 그룹의 색으로 칠해지고**, 색 칩 여덟 개 중 하나를 고르면 그 자리에서 색이 바뀐다. 두 그룹에 다 맞는 문서는 **위 그룹의 색**이다. 끊긴 링크 노드는 늘 `--muted` 다. `목록` 으로 가도 같은 색이 행 앞 점으로 보이고, **거기서도 `그룹` 을 고칠 수 있다.** 지도를 닫았다 다시 열면 그룹이 그대로 남아 있고, `기본값으로` 를 눌러도 그룹은 지워지지 않는다.

### 2.2 F-2007 과의 경계 — 함수 하나와 타입 하나

## 3. `tokens.css` — 팔레트 별칭 여덟 줄

### 3.1 무엇을 어디에 넣나

`:root` 블록 안, 콜아웃 8색 묶음 **바로 아래**에 여덟 줄을 더한다. 값은 전부 `var(--callout-*)` 이고 **hex 는 한 글자도 쓰지 않는다.**

```css
/* 지도 그룹 팔레트 — 위 콜아웃 8색의 별칭이다. 새 색이 아니다 (F-292 6.5, F-2008 3장).
   저장값은 hex 가 아니라 인덱스 1~8 이라 테마를 바꾸면 그룹 색도 따라 바뀐다 */
--map-group-1: var(--callout-note);
--map-group-2: var(--callout-tip);
--map-group-3: var(--callout-success);
--map-group-4: var(--callout-question);
--map-group-5: var(--callout-warning);
--map-group-6: var(--callout-danger);
--map-group-7: var(--callout-example);
--map-group-8: var(--callout-quote);
```

**반드시 기존 `:root` 블록 *안*이어야 한다.** `src/styles/tokens.test.ts` 의 `extractBlock(':root')` 는 `:root\s*\{([^}]*)\}` 를 `s` 플래그로 한 번만 실행해 **파일에서 처음 만나는 `:root` 블록**을 읽는다. 새 `:root { … }` 블록을 따로 만들면 그 안의 토큰이 테스트에서 안 보인다.

- **테마 블록(`:root[data-theme='sepia']`·`[data-theme='dark']`)에는 아무것도 더하지 않는다.** 이유는 3.2
- `data-theme` 이 없는 화이트가 곧 `:root` 값이므로 "그 밖의 테마" 라는 별도 경로가 없다 — 테마는 화이트·세피아·다크 셋뿐이다 (`design.md` 3.4)

### 3.2 테마 3종에서 따라오는지 — 실측했다 (2026-09-22, 설치된 Chrome)

별칭도 그 대상도 **같은 요소(`html`)에 얹히므로**, 다크 블록이 `--callout-tip` 을 덮으면 `--map-group-2` 의 계산값도 함께 바뀐다. `tokens.css` 의 테마 블록 머리 주석이 이미 같은 말을 적어 뒀고(`var()` 로 참조하는 파생 토큰은 다시 적지 않아도 함께 바뀐다), `--callout-note: var(--link)` 가 다크에서 이미 그렇게 동작하고 있다. **말로만 두지 않고 실제로 확인했다** — 위 여덟 줄을 페이지에 주입한 뒤 F-292 3.4 의 프로브 방식(`el.style.color = 'var(--토큰)'` → `getComputedStyle(el).color`)으로 읽었다.

| 토큰 | 화이트 | 세피아 | 다크 |
| --- | --- | --- | --- |
| `--map-group-1` (= `--callout-note` = `--link`) | `rgb(41, 82, 204)` | `rgb(36, 80, 160)` | `rgb(138, 174, 245)` |
| `--map-group-2` (= `--callout-tip`) | `rgb(11, 114, 133)` | `rgb(11, 114, 133)` | `rgb(79, 184, 199)` |
| `--map-group-8` (= `--callout-quote` = `--ink-2`) | `rgb(74, 71, 64)` | `rgb(73, 59, 43)` | `rgb(189, 183, 172)` |

- **세 테마 모두 별칭과 대상이 한 글자도 다르지 않게 나왔다.** 2단계 `var()` 사슬(`--map-group-1` → `--callout-note` → `--link`)도 그대로 풀린다
- **전부 `rgb(…)` 로 나온다.** `src/lib/cssColor.ts` 가 이미 다루는 꼴이라 파서를 손댈 일이 없다. 다크에서 `color(srgb …)` 로 나오는 것은 `color-mix()` 가 든 `--accent` 뿐이고, 팔레트에는 `color-mix()` 가 없다
- 세피아는 콜아웃 6색을 덮지 않으므로 화이트와 같은 값이다. **그것이 지금 콜아웃의 동작이고, 이 명세가 바꾸지 않는다**

### 3.3 불변조건 — 새 hex 0개

CLAUDE.md 불변조건은 "색 hex 는 `brand.config.ts`·`tokens.css` 에만" 이다. 이 명세가 더하는 여덟 줄은 **전부 `var()` 참조**이고, 저장값은 hex 가 아니라 인덱스 `1`~`8` 이다(6장). 임의 색 고르기를 두지 않는 이유가 이것이다 — 색을 고르게 하는 순간 hex 가 `localStorage` 로 새어 나가고 테마를 바꿔도 안 따라온다 (F-292 6.5).

`map.css` 에도 hex 를 쓰지 않는다. 색 칩과 색 점은 `var(--map-group-N)` 만 참조한다 (11장).

## 4. `computeGroupColors` — `mapFilter.ts` 에 덧붙이는 것이 전부다

테스트 환경이 `node` 다. **DOM 도 three 도 import 하지 않는 순수 함수여야 단위 테스트가 된다** — F-2007·F-2010 과 같은 규칙이다.

### 4.1 내보내는 것

```ts
// 팔레트 색 수. src/app/mapPrefs.ts 의 MAP_GROUP_MAX 와 같은 값이어야 한다 (13.1 U12 가 지킨다)
export const MAP_GROUP_PALETTE = 8

// src/app/mapPrefs.ts 의 MapGroup 과 구조가 같다. src/lib 은 src/app 을 가져오지 않는다 (2.2)
export type MapFilterGroup = { q: string; c: number }

// out[i] = 0 이면 그룹 없음, 1~8 이면 그 팔레트 번호. 돌려주는 값은 색이 칠해진 노드 수
export function computeGroupColors(
  groups: readonly MapFilterGroup[],
  ctx: MapFilterContext,
  out: Uint8Array,
): number
```

**더 내보내는 것은 없다.** 상수 1개 + 타입 1개 + 함수 1개다.

### 4.2 판정 규칙 — 노드 하나마다 위에서 아래로

| # | 조건 | 결과 |
| --- | --- | --- |
| 1 | `node.missing` | **0** — 끊긴 링크 노드는 문서가 아니라 맞출 본문도 프로퍼티도 없다 (F-292 6.5 "항상 `--muted`") |
| 2 | `ctx.docById` 에 그 `node.id` 가 없다 | **0** — F-2007 3.2 의 같은 상황과 같은 판단이다 |
| 3 | 위에서부터 첫 번째로 `matchDoc(doc, 그 그룹의 쿼리) !== null` 인 그룹 | **그 그룹의 번호** |
| 4 | 그 밖 | **0** |

- **`out.fill(0)` 을 함수 안에서 한다.** 호출부가 잊으면 직전 그룹 설정의 자취가 색으로 남고 그건 눈으로만 잡힌다 — `fillNodeFocus`(F-2010 3장)가 같은 이유로 같은 규칙을 갖는다
- **쿼리가 비어 있는 그룹은 건너뛴다.** `parseSearchQuery` 결과가 `isEmpty` 면 아무것도 칠하지 않는다 (F-292 6.5 "빈 쿼리인 그룹은 아무것도 칠하지 않는다"). 공백만 친 것도 `isEmpty` 다
- **쿼리 파싱은 이 함수 안에서 한다.** 그룹이 최대 8개이고 전부 짧은 문자열이라 미리 파싱해 넘길 만한 비용이 아니다. 호출부가 파싱 결과를 들고 다니지 않아도 되는 쪽이 계약이 좁다
- **`c` 가 1~`MAP_GROUP_PALETTE` 의 정수가 아니면 `1` 로 본다.** `normalizeMapGroups` 와 같은 규칙이다. 저장을 거치지 않은 값이 들어와도 결과가 정해져야 순수 함수로서 전체 함수가 된다
- 판정은 **노드 수 × 그룹 수**다. 정렬도 재귀도 없다. 비용은 8장

### 4.3 F-2007 이 만든 것을 왜 안 고치나

`MapFilterContext` 는 `nodes`·`docById`·`distances` 셋인데 그룹 판정에 필요한 것은 앞의 둘뿐이다(`distances` 는 `몇 다리` 전용). **필드를 더하지도 빼지도 않는다.** 둘을 한 파일에 둔 것은 `ctx` 를 한 번만 만들려는 것이고(F-2007 2.2), 필드를 각자 늘리기 시작하면 그 이유가 사라진다.

## 5. 색이 겹치는 순서 — 그룹 · 깊이 · 호버 · 필터

### 5.1 노드 바탕색 판정 사슬 (`applyColors()`)

지금 `MapScene.tsx` 의 `applyColors()` 는 **끊긴 링크 → 현재 문서 → 공유받음 → 기본** 순으로 `baseColors` 를 채운다. 그룹은 **세 번째 자리**에 들어간다.

| 순위 | 조건 | 색 |
| --- | --- | --- |
| 1 | 끊긴 링크(`node.missing`) | `--muted` |
| 2 | 현재 문서(`#/map/{id}` 의 그 문서) | `--accent` |
| 3 | **그룹에 맞음** | **`--map-group-{번호}`** |
| 4 | 공유받아 본문을 못 읽음 | `--ink-2` |
| 5 | 그 밖 | `--ink` |

- **1·2 는 그룹을 이긴다.** 끊긴 링크는 F-292 6.5 가 못 박았고, 현재 문서는 F-292 6.1 색 표가 "`--accent` 만" 이라고 적었다. 현재 문서는 화면에 언제나 하나뿐이라 그룹 하나를 잃는 대가가 작다
- **3 이 4 를 이긴다 — F-292 6.1 색 표의 순서를 한 칸 바꾸는 것이다** (16장 Q2). 공유받은 문서는 본문이 빈 문자열이라 본문 낱말로는 절대 안 맞고 제목·폴더로만 맞는데, 그렇게까지 맞은 문서를 사용자가 정한 색이 아니라 `--ink-2` 로 두면 **"내 규칙이 안 먹는다" 로 읽힌다.** 공유받은 문서가 있다는 사실은 꼬리 줄이 이미 따로 말한다(`공유받은 문서 N개는 나가는 링크를 읽지 못했습니다.`)
- `centerIndex` 를 세우는 자리는 그대로 2번이다. 그룹 가지가 그 앞에 끼어들지 않는다

### 5.2 깊이·호버·필터와 겹칠 때 — 계산했다

그룹 색은 **바탕색만 바꾼다.** 그 위에 얹히는 세 장치는 전부 `--panel` 쪽으로 섞는 같은 연산이고, F-2010 `combineMix` 와 F-2007 의 `Math.max` 규칙을 그대로 탄다.

| 장치 | 어디서 | 값 |
| --- | --- | --- |
| 깊이 섞기 | `applyDepth()`, F-2004 | 가장 먼 노드가 `0.65` |
| 호버 흐리기 | `applyDepth()`, F-2010 | `MAP_HOVER_DIM` `0.85` |
| 필터 흐리기 | `applyDepth()`, F-2007 | `MAP_FILTER_DIM` `0.85`, 호버 흐리기와 **쌓지 않고 `Math.max`** |

**F-2008 은 이 세 줄을 한 글자도 안 고친다.** 그룹 색은 `applyColors()` 가 채우는 `baseColors` 에만 들어가고, 섞기는 그 뒤에 그대로 일어난다. 그래서 F-292 결정 9("색상은 그룹 전용, 깊이는 크기·투명도로")가 지켜진다 — 섞는 상대가 배경 하나뿐이라 **그룹 사이의 색상 차이(hue)는 끝까지 유지된다.**

**남는 단계를 F-2010 4.2 와 같은 방법으로 계산했다.** 0~255 sRGB 좌표에서 `--panel` 과의 채널별 최대 거리이고, 섞기가 선형이라 거리는 `(1 − t)` 배로 줄어든다. `둘 다` 는 가장 먼 노드가 흐려지기까지 한 최악값(`combineMix(0.65, 0.85)` = `0.9475`, 남는 비율 `0.0525`)이다.

| 테마 | 팔레트에서 제일 짙은 색 | 제일 옅은 색 | 원색 거리 | 깊이 0.65 | 흐리기만 | **둘 다(최악)** | `--panel` 대비 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 화이트 | 4·5번(`question`·`warning`) | **7번 `example`** | 251 / **186** | 88 / **65** | 38 / **28** | 13.2 / **9.8** | 5.38~6.56:1 |
| 세피아 | 2번 `tip` | 7번 `example` | 240 / 176 | 84 / 62 | 36 / 26 | 12.6 / **9.2** | 4.95~9.86:1 |
| 다크 | 1번 `note` | 8번 `quote` | 216 / 156 | 76 / 55 | 32 / 23 | 11.3 / **8.2** | 5.63~8.17:1 |

**읽는 법.**

1. **화이트 테마에서 가장 옅은 그룹 색(7번 `--callout-example`)은 깊이와 흐리기를 다 받아도 배경과 9.8 단계 남는다.** F-2010 4.2 가 사람 승인을 받은 최악값 범위(6~12)의 **안**이다. 그룹 색을 넣는다고 흐리기 설계가 나빠지지 않는다
2. 세 테마 최악값이 **8.2~13.2** 로 전부 그 범위 안이다. 제일 위험한 것은 다크의 8번(`--ink-2` 별칭)으로 8.2 단계다
3. **쌓으면 안 되는 이유가 여기서도 확인된다.** 흐리기를 둘 쌓으면(`t` = 0.9921) 팔레트 최악값이 **1.4~2.0 단계**로 떨어져 8비트 화면에서 배경과 같은 색이 된다. F-2007 9.2 의 결론과 정확히 같은 수치 관계다
4. 여덟 색 전부 세 테마에서 `--panel` 대비 **4.95:1 이상**이다(최솟값은 세피아 3번 `success` 4.95:1). `design.md` 3.3 의 "전부 `--panel` 대비 4.5:1 이상" 이 별칭에도 그대로 성립한다 — `tokens.test.ts` 가 이미 콜아웃 8색에 대해 이 검사를 돌리고 있고, 13.1 U11 이 별칭 경로로도 한 번 더 본다

### 5.3 그룹 색이 가지 않는 곳

| 대상 | 색 | 왜 |
| --- | --- | --- |
| 간선 | `--rule`~`--ink` 사이 (`선 두께`), 현재 문서·호버 간선은 `--accent` | F-292 6.1 색 표 그대로다. 간선은 양끝이 서로 다른 그룹일 수 있어 색 하나로 정할 수 없다 |
| 이름표 | `--ink-2` | F-292 6.2. 캔버스 위 글자라 대비가 먼저다 |
| 목록 행 글자 | `--ink-2` | 색은 **행 앞 점**으로만 드러낸다 (10장) |
| 배경 | `--panel` | — |

## 6. 저장 — `md.mapGroups` 는 이미 다 만들어져 있다

### 6.1 스키마와 검증 — F-2005 가 넣은 것을 그대로 쓴다

`src/app/mapPrefs.ts` 에 이미 있는 계약이다. **F-2008 은 이 파일을 안 고치고 부르기만 한다.**

```ts
export type MapGroup = { q: string; c: number }   // q = 검색 쿼리, c = 팔레트 인덱스 1~8
export const MAP_GROUP_MAX = 8
export function normalizeMapGroups(raw: unknown): MapGroup[]
export function loadMapGroups(): MapGroup[]
export function saveMapGroups(groups: MapGroup[]): void
```

저장 모양은 `md.mapGroups` 키에 든 **JSON 배열**이고 항목이 `{ "q": "tag:일기", "c": 3 }` 꼴이다 (F-292 6.11 그대로). 검증 규칙은 이미 구현돼 있고 `mapPrefs.test.ts` 가 판정한다 — 확인한 내용을 여기 옮겨 적는다:

| 들어온 값 | 결과 |
| --- | --- |
| 배열이 아니다 (`null`·문자열·객체) | **`[]`** |
| JSON 파싱 실패 | **`[]`** (`loadMapGroups` 의 `try`) |
| 키가 없다 / 빈 문자열 | **`[]`** |
| 항목이 객체가 아니다 | 그 항목만 **버린다** |
| `q` 가 문자열이 아니다 | 그 항목만 **버린다** |
| `c` 가 1~8 정수가 아니다 | `c` 를 **`1`** 로 두고 항목은 남긴다 |
| 9개째부터 | **버린다** (`MAP_GROUP_MAX`) |
| 빈 배열 | 그룹 없음 — `computeGroupColors` 를 아예 부르지 않는다 (8.2) |

### 6.2 언제 저장하나

**입력마다 그 자리에서 저장한다.** `표시`·`장력`·`필터` 와 같다 (F-2005 6.3 이 `JSON.stringify` + `localStorage.setItem` 비용을 0.004 ms 로 쟀다). 조건 글자 한 자, 색 칩 한 번, 추가·삭제 전부 곧바로 `saveMapGroups` 다.

**저장과 칠하기는 다르다.** 저장은 즉시, 칠하기는 조건 글자에 한해 150 ms 뒤다 (8.2).

### 6.3 `기본값으로` 는 그룹을 안 지운다

`MapPanel` 의 `기본값으로` 는 지금 `onChange(defaultMapView())` 만 부른다 — `md.mapGroups` 는 다른 키라 **코드를 고치지 않아도 안 지워진다.** F-292 6.11·결정 Q4 가 키를 둘로 나눈 이유가 정확히 이것이고, F-2005 4.4 가 같은 말을 적어 뒀다.

**그래도 e2e 로 못 박는다** (13.2 A9). 이 성질은 "안 하는 일" 이라 코드를 읽어서는 깨진 것을 못 알아차린다.

## 7. 패널 `그룹` 묶음

### 7.1 묶음 등록 — 단어 둘과 `case` 하나

| # | 어디 | 무엇 |
| --- | --- | --- |
| 1 | `MapPanel.tsx` `SECTION_READY` | `'group'` 한 단어. 이로써 네 묶음이 다 찬다 |
| 2 | `MapPanel.tsx` `SECTION_IN_LIST`(F-2007 이 만든다) | `'group'` 한 단어. 목록 보기에서 `필터`·`그룹` 둘을 그린다 |
| 3 | `MapPanel.tsx` `renderSection` | `case 'group'` 하나 |

- `SECTION_ORDER` 는 이미 `['filter','group','display','force']` 다. **자리가 저절로 `필터` 아래로 잡힌다**
- 펼침 규칙(F-2005 4.2 "그리는 묶음 중 맨 위 하나")대로 **`그룹` 은 접힌 채로 뜬다.** 지도 보기든 목록 보기든 맨 위는 `필터` 다
- **`그룹` 묶음은 그룹이 0개여도 그린다.** F-2005 4.2 의 "내용이 없는 묶음은 그리지 않는다" 는 *아직 구현되지 않은* 묶음을 말한 것이고, 여기서는 `새 그룹` 버튼이 언제나 내용이다. 이 커밋 뒤로 묶음 수는 지도 보기 **4**, 목록 보기 **2** 로 고정된다
- **`표시`·`장력` 을 목록 보기에서 그리지 않는 규칙은 그대로다** (F-2007 11.3) — 3D 장면에만 듣는 값이기 때문이다. 그룹 색은 목록에도 보이므로(10장) 목록에서 그린다

### 7.2 `MapPanel` props 둘

```tsx
export type MapPanelProps = {
  // … F-2005·F-2007 이 정한 것은 그대로 …
  groups: readonly MapGroup[]
  // 색 고르기·추가·삭제 — 곧바로 반영한다
  onGroupsChange: (next: MapGroup[]) => void
  // 조건 글자 — 저장은 곧바로, 칠하기는 150 ms 뒤다 (8.2)
  onGroupQueryChange: (index: number, q: string) => void
  // 한글 입력기 조립 상태를 MapPage 로 올린다 (8.3)
  onGroupComposing: (composing: boolean) => void
}
```

- **`MapPanel` 은 `mapPrefs` 를 직접 읽거나 쓰지 않는다.** 저장소를 아는 것은 `MapPage` 하나다 (F-2005 4.1 의 규칙)
- 콜백을 둘로 나눈 이유는 **미루는 대상이 조건 글자 하나뿐**이기 때문이다. 색 칩을 눌렀는데 150 ms 뒤에 색이 바뀌면 그건 버그로 읽힌다

### 7.3 행 하나의 모양

한 행은 두 줄이다 — 위에 `조건 입력 + 삭제`, 아래에 `색 칩 여덟 개`.

```tsx
<li className="map-group-row">
  <div className="map-group-head">
    <input className="map-group-q" type="text" aria-label={`그룹 ${n} 조건`} placeholder="tag:일기" … />
    <button type="button" className="icon-btn map-group-del" aria-label={`그룹 ${n} 삭제`}><IconDelete size={16} /></button>
  </div>
  <div className="map-group-swatches" role="radiogroup" aria-label={`그룹 ${n} 색`}>…</div>
</li>
```

| 무엇 | 정함 |
| --- | --- |
| `n` | **1부터 세는 행 번호**다. 행을 지우면 아래 행들의 이름이 한 칸씩 당겨진다 — 화면에 보이는 순서와 접근성 이름이 어긋나지 않는 쪽이 낫다 |
| 입력 종류 | `type="text"`(역할 `textbox`). `파일 검색`(F-2007)은 `type="search"`(역할 `searchbox`)라 **선택자가 겹치지 않는다.** 여기서 `search` 를 안 쓰는 것은 Chrome 이 붙이는 지우기 `×` 가 바로 옆 삭제 버튼과 헷갈리기 때문이다 |
| 자리 표시 | `tag:일기` — F-292 6.11 의 저장 예시와 같은 문자열 |
| 문법 | **F-284 그대로.** `parseSearchQuery` → `matchDoc` (F-292 결정 15). 새 문법을 만들지 않는다 |
| 삭제 | 아이콘 버튼 하나. 확인 대화상자를 두지 않는다 — 그룹은 조건 한 줄이라 다시 만드는 값이 싸고, 저장소에 실행 취소 장치가 없다 |
| 행 순서 | **만든 순서 고정.** 순서 바꾸기는 안 넣는다 (16장 Q3) |

### 7.4 색 칩 — 팔레트 8색 라디오

**새 색도 새 토큰도 만들지 않는다.** 칩은 `data-group` 속성으로 `var(--map-group-N)` 여덟 규칙 중 하나를 받는다 (11장).

```tsx
<label className="map-swatch map-dot" data-group={c}>
  <input type="radio" name={`${idBase}-group-${index}-color`} aria-label={`색 ${c}`} checked={…} onChange={…} />
</label>
```

| 무엇 | 정함 | 왜 |
| --- | --- | --- |
| 모양 | 지름 **18px** 원 여덟 개, `gap: 6px` | 8 × 18 + 7 × 6 = **186px**. 패널 폭 280px 에서 좌우 여백 16px 을 뺀 248px 안에 한 줄로 들어간다 |
| 고른 표시 | 칩 둘레에 `--ink` 2px 테두리 (`:has(input:checked)`) | 색으로만 알리지 않는다. `map.css` 가 이미 `:has()` 를 쓰고 있다 |
| 키보드 | **네이티브 라디오 묶음 그대로** — 탭 정지가 한 번이고 방향키로 여덟 색을 옮겨 다닌다 | 직접 짠 세그먼트보다 규칙이 적고 스크린리더에서 `그룹 1 색, 색 3, 8개 중 3번째` 로 읽힌다 |
| 라디오 숨기기 | `opacity: 0` 으로 칩 위에 겹친다. `display: none` 을 쓰지 않는다 | `display: none` 은 접근성 트리와 포커스에서 통째로 사라진다. `opacity: 0` 이면 Playwright 의 `getByRole('radio')`·`check()` 도 그대로 잡는다 |
| 드롭다운·컬러피커 | **안 쓴다** | 여덟 개뿐이라 펼칠 이유가 없고, 컬러피커는 F-292 6.5 가 금지했다 |

### 7.5 `새 그룹` 과 상한

- 묶음 맨 아래 글자 버튼 하나. `기본값으로` 와 같은 모양(`.map-panel-reset` 이 아니라 자기 클래스 `.map-group-add` 를 쓰되 값은 같다)
- 누르면 **조건이 빈 문자열인 행**이 맨 아래에 생긴다. 빈 조건은 아무것도 칠하지 않으므로(4.2) 화면이 바뀌지 않고, 커서는 그 행의 조건 칸으로 옮긴다
- **새 행의 색은 지금 안 쓰이는 가장 작은 번호**다. 없으면 `1`. 여덟 개를 차례로 쓰게 되어 색이 겹치는 일이 드물고, **가장 자주 쓰이게 될 1번이 `--callout-note`(= `--link`) 라 테마 3종에서 가장 또렷하다**
- 그룹이 8개면 버튼을 **`disabled`** 로 두고 아래에 안내 한 줄. 버튼을 숨기지 않는 것은 "왜 못 만드는지" 를 말할 자리가 필요해서다 (F-2007 7.5 의 잠긴 슬라이더와 같은 판단)

### 7.6 문구 (`specs/ia.md` 6장 문구표에 더한다)

| 자리 | 문자열 |
| --- | --- |
| 묶음 제목 | `그룹` (이미 있다) |
| 조건 칸 접근성 이름 | `그룹 {n} 조건` |
| 조건 칸 자리 표시 | `tag:일기` |
| 색 묶음 접근성 이름 | `그룹 {n} 색` |
| 색 칩 접근성 이름 | `색 {c}` |
| 삭제 버튼 접근성 이름 | `그룹 {n} 삭제` |
| 추가 버튼 | `새 그룹` |
| 그룹이 0개일 때 안내 | `조건에 맞는 문서에 색을 칠합니다.` |
| 그룹이 2개 이상일 때 안내 | `위에서부터 먼저 맞는 그룹의 색을 씁니다.` |
| 그룹이 8개일 때 안내 | `그룹은 8개까지 만들 수 있습니다.` |

- 문장형은 `~습니다` 체 (`specs/ia.md` 6장)
- **안내 세 줄은 서로 배타적이다** — 0개면 첫 줄, 1개면 없음, 2~7개면 둘째 줄, 8개면 둘째 줄과 셋째 줄이 함께 뜬다
- `색 1`~`색 8` 을 `정보`·`팁` 같은 콜아웃 이름으로 부르지 않는다. 팔레트가 콜아웃 색의 별칭인 것은 구현 사정이고 **그룹에는 아무 뜻도 없다**

### 7.7 묶음 전체 배치

```
그룹                       ▾
  [ tag:일기            ] [🗑]
  ●●●●●●●●
  [ 회고                ] [🗑]
  ●●●●●●●●
  위에서부터 먼저 맞는 그룹의 색을 씁니다.
  [        새 그룹        ]
```

## 8. 매칭 비용 — 실측하고 150 ms 미루기로 정했다

### 8.1 쟀다 (2026-09-22, 이 PC, Node v24.12.0)

**F-2007 의 GF2(1,000 항목 전수 `matchDoc` 1.22 ms)를 여덟 배 해서 쓰면 안 된다.** 그 값은 `tag:일기 문서` 라 프로퍼티 필터에서 대부분 먼저 탈락해 본문을 안 보는 쿼리였다. 그룹은 낱말 쿼리가 흔하고, `matchDoc` 은 **부를 때마다 본문 전체를 `foldCase` 한다.** 그래서 직접 쟀다 — 실제 `src/lib/docSearch.ts` 를 그대로 import 해 7회 중앙값이다.

| 조건 (문서 수 × 한 문서 크기) | 그룹 8개, 아무것도 안 맞음(최악) | 그룹 8개, 낱말 매칭 | 그룹 8개, `tag:` 필터 | 그룹 1개(대조군) |
| --- | --- | --- | --- | --- |
| 200 × 2 KB | **4.6 ms** | 2.8 ms | 0.23 ms | 0.53 ms |
| 1,000 × 28자 | **1.7 ms** | — | — | — |
| 1,000 × 300자 | **4.2 ms** | — | — | — |
| 500 × 2 KB | **10.0 ms** | — | — | — |
| **1,000 × 2 KB** | **19.5~23.7 ms** | 14.0 ms | 0.53 ms | 2.6 ms |

**비용의 정체를 특정했다.** 같은 조건에서 본문을 **한 번만 접어 두고** 낱말만 보면 1,000 × 2 KB 가 **1.8 ms** 다(본문 접기 자체는 2.3 ms). 즉 19.5 ms 중 90% 이상이 **같은 본문을 여덟 번 다시 접는 값**이다.

- **`docSearch.ts` 를 고쳐 접은 본문을 캐시하는 길은 가지 않는다.** F-284 소유 파일이고, 인덱스에 접은 본문을 더하면 메모리가 두 배가 된다. 그 판단은 F-284·F-286 의 몫이지 이 명세의 몫이 아니다 — 15장 갱신 대상에 한 줄로 남긴다
- **노드 상한이 1,000 이므로(F-2002 10.3) 이 표의 마지막 줄이 설계상 최악값이다.** 다만 문서 하나가 20 KB 면 그 열 배가 되므로 상한이 값을 완전히 묶어 주지는 않는다

### 8.2 그래서 조건 글자만 150 ms 미룬다

| 무엇 | 언제 반영하나 |
| --- | --- |
| 조건 글자 | **마지막 입력에서 150 ms 뒤** |
| 색 칩 · 추가 · 삭제 | **곧바로** |
| 지도 열기 · 문서 목록 바뀜 · 테마 바뀜 | 곧바로 |

- **150 ms 는 새 숫자가 아니다.** `src/app/SearchDialog.tsx` 의 `DEBOUNCE_MS` 와 같은 값이고, 같은 이유(글자마다 전수 매칭)로 이미 쓰이고 있다
- **`파일 검색`(F-2007)에는 디바운스가 없는데 여기만 두는 이유**: 필터는 한 번에 한 번만 매칭하고(1.22 ms), 그룹은 최대 여덟 번 하며 낱말 쿼리에서 본문을 여덟 번 접는다(19.5 ms). **두 자리 수가 갈린다**
- **그룹이 0개면 아무 일도 하지 않는다.** `computeGroupColors` 를 부르지 않고 `MapScene` 에 `null` 을 내려보내 오늘과 똑같은 경로를 탄다 (9.1)
- 미루는 것은 **칠하기뿐**이다. 글자는 언제나 보이고 저장도 곧바로 한다 (6.2)

### 8.3 한글 입력기 — 조립 중에는 안 칠한다

F-2007 8.1 이 CDP 로 확인한 이벤트 순서(`compositionend` 뒤에는 `input` 이 오지 않는다)가 여기에도 그대로 적용된다.

- 조립 중(`compositionstart`~`compositionend`)에는 **타이머를 걸지 않는다**
- **`compositionend` 에서 반드시 한 번 건다.** 안 걸면 마지막 글자가 영영 반영되지 않는다 — CLAUDE.md 불변조건("IME 조립 중 미룬 재계산은 조립이 끝날 때 따라잡아야 한다")
- 조립 상태는 `onGroupComposing` 으로 `MapPage` 가 들고 있다. 입력칸이 여러 개여도 **한 번에 하나만 조립 중**이므로 상태 하나로 족하다
- e2e 는 `e2e/helpers.js` 에 이미 있는 `fakeImeCompose`·`fakeImeCommit` 로 판정한다 (13.2 A12)

## 9. `MapScene.tsx` — 자리별 변경

**F-2007 이 들어간 뒤의 코드 기준이다.** 아래 여섯 자리 밖은 건드리지 않는다.

| # | 어디 | 무엇 |
| --- | --- | --- |
| 1 | `MapSceneProps` | `groups: Uint8Array \| null` 한 줄. `null` = 그룹 없음 |
| 2 | `ThemeColors` | `group: Rgba[]` 한 줄 (팔레트 8개) |
| 3 | `readTheme` | `--map-group-1`~`-8` 을 돌면서 읽는 여덟 번. 읽는 법은 기존 `readToken` 그대로 |
| 4 | `SceneBundle` | `setGroups: (mask: Uint8Array \| null) => void` 한 줄 |
| 5 | `applyColors()` | 색 판정 사슬에 가지 하나 — 5.1 의 3번 자리 |
| 6 | effect **(i)** | `useEffect(() => { sceneRef.current?.setGroups(groups) }, [groups])` |

### 9.1 왜 마스크를 prop 으로 올리나

그룹 매칭에는 **검색 인덱스**가 필요하고 그것은 `store` 를 읽는 비동기 작업이다. `MapScene` 을 three 와 캔버스만 아는 모듈로 두는 것이 F-2002 이후의 구조이고, F-2007 이 `visible` 마스크로 같은 길을 이미 냈다. **`MapPage` 가 `Uint8Array` 하나로 요약해 내려보낸다.**

- 값이 바뀔 때마다 **새 `Uint8Array`** 를 만든다. 내용만 바꾸면 참조가 같아 effect 가 안 뜬다
- 그룹이 하나도 없거나 전부 빈 조건이면 **`null`** 을 내려보낸다. 장면은 오늘과 완전히 같은 경로를 탄다
- 1,000개짜리 `Uint8Array` 는 1 KB 다. 만들고 버리는 비용을 아낄 자리가 아니다

### 9.2 `setGroups(mask)` 가 하는 일 — 그리고 안 하는 일

마스크를 들고 있는 변수만 바꾼 뒤 `applyColors()` 를 다시 부르고 다시 그린다.

- **`layout.*` 도 `fit()` 도 부르지 않는다.** 그룹 색은 배치도 카메라도 건드리지 않는다
- `applyColors()` 는 테마도 다시 읽는다. **토큰이 6개에서 14개로 느는데, 재 보니 프로브 읽기가 0.10 ms → 0.20 ms 다**(설치된 Chrome, 21회 중앙값). 프레임 루프가 아니라 여는 순간·테마 변경·`맞춤`·중심 이동·그룹 변경에서만 도는 경로라 그대로 둔다
- 깊이 섞기는 `applyDepth()` 가 프레임마다 다시 하므로 따로 더럽힘 표시가 필요 없다 (F-2004 6.1 의 구조 그대로)

## 10. `목록` 보기 — 행 앞 색 점

F-292 6.8 은 "필터와 **그룹**을 그대로 반영한다" 고 적었다. 필터는 F-2007 이 행을 빼는 것으로 반영했고, 그룹은 **뺄 것이 없으므로 드러낼 모양을 정해야 한다.**

| 안 | 판단 |
| --- | --- |
| **행 앞에 지름 8px 색 점 — 채택** | 캔버스의 점과 같은 뜻이 그대로 읽힌다. 글자 색·글자 크기를 안 건드려 기존 e2e 가 깨지지 않는다 |
| 행 글자를 그룹 색으로 | 팔레트에 `--muted` 급 대비의 색이 없어 본문 대비는 살지만, **목록이 알록달록해져 읽기 어렵다** |
| 행 왼쪽 세로 막대 | 점과 정보량이 같은데 자리를 더 먹는다 |
| 아무것도 안 함 | **F-292 6.8 을 어긴다.** 그리고 목록 보기에서 `그룹` 묶음을 고칠 수 있는데(7.1) 화면이 안 바뀌면 죽은 조작이 된다 |

- 점은 `<span className="map-list-dot map-dot" data-group={번호} aria-hidden="true" />` 이고 **그룹에 맞은 행에만** 넣는다
- **`aria-hidden` 이다.** 버튼의 접근성 이름에 글자를 더하면 `getByRole('button', { name: 'B', exact: true })` 로 잡는 기존 e2e 셋(`F-2002 A5`·`A6`·`A7`)이 깨진다. 색을 소리로 옮길 값어치보다 그쪽이 크다 — 16장 Q4
- 목록은 `displayGraph` 의 노드를 순서를 바꿔 늘어놓으므로(F-2007 11.3 이 옮긴 뒤 기준) **id → 팔레트 번호 표**를 하나 만들어 쓴다. 인덱스를 들고 다니지 않는다
- **끊긴 링크 묶음의 행에는 점이 없다.** 끊긴 링크는 언제나 그룹 밖이다 (4.2)

## 13. 수용 기준

## 16. 열린 질문 / 사람 결정 필요

**사람이 꼭 골라야 하는 것은 없다. 다섯 다 기본값이 서 있고, 다른 쪽을 골랐을 때 무엇이 달라지는지 적었다.**

### Q1. 조건 글자를 150 ms 미루는 것 — **기본: 미룬다**

8.1 에서 1,000문서 × 2 KB · 그룹 8개 최악이 **19.5~23.7 ms** 로 한 프레임(16.7 ms)을 넘는 것을 쟀다. 값은 `SearchDialog.tsx` 가 이미 쓰는 150 ms 그대로다.

**다른 쪽을 고르면**: `파일 검색` 과 똑같이 글자마다 바로 칠한다. 코드가 서너 줄 줄고 8.3 의 조립 처리가 단순해지지만, **문서가 많은 사용자는 그룹 조건을 칠 때마다 한 프레임씩 흘린다.** 문서 수십 개(4.6 ms)에서는 차이가 눈에 안 보인다 — 실제 사용자 데이터가 그 규모라면 미루지 않는 쪽도 성립한다.

### Q2. 그룹 색이 공유받은 문서의 `--ink-2` 를 이기는 것 — **기본: 이긴다**

F-292 6.1 색 표는 `공유받은 문서(본문을 못 읽은 것) | --ink-2 단색` 이라고만 적었고 그룹과의 순서를 안 정했다. 공유받은 문서는 인덱스에 본문이 빈 문자열이라 **제목·폴더로만 맞을 수 있는데**, 그렇게 맞은 문서를 사용자가 정한 색이 아니라 회색으로 두면 규칙이 안 먹는 것으로 읽힌다.

**다른 쪽을 고르면**: 5.1 표의 3번과 4번을 맞바꾼다. `applyColors()` 의 가지 위치 한 줄 차이이고 e2e 도 안 바뀐다(기본 문서에는 공유받은 것이 없다). 대신 **공유 문서가 섞인 작업 공간에서는 그룹 색이 군데군데 빠진 것처럼 보인다.**

### Q3. 그룹 순서를 바꾸는 길을 안 두는 것 — **기본: 안 둔다**

순서는 우선순위를 뜻하므로(F-292 6.5) 바꾸고 싶을 수 있지만, 행이 최대 여덟 개이고 조건이 한 줄이라 지웠다 다시 만드는 값이 싸다. 드래그 재정렬은 이 저장소에 전례가 없고(사이드바 문서 순서도 드래그가 없다) 터치까지 맞추면 이 명세만 한 덩어리가 는다.

**다른 쪽을 고르면**: 행마다 `▲`·`▼` 버튼 둘을 더한다. 280px 패널의 첫 줄이 `입력 + ▲ + ▼ + 삭제` 로 네 칸이 되어 입력칸이 좁아지므로, 두 버튼을 색 칩 줄 오른쪽 끝으로 내리는 편이 낫다. 문구가 둘(`그룹 {n} 위로`·`그룹 {n} 아래로`), e2e 가 하나(A6 옆에) 는다.

### Q4. 목록 색 점을 `aria-hidden` 으로 두는 것 — **기본: 둔다**

점에 접근성 이름을 주면 그 글자가 **버튼의 접근성 이름에 섞여** `getByRole('button', { name: 'B', exact: true })` 로 잡는 기존 e2e 셋이 깨진다(14.2). 그리고 그룹은 사용자가 스스로 만든 규칙이라, 어떤 문서가 어느 그룹인지는 조건 문자열을 보면 알 수 있다.

**다른 쪽을 고르면**: 점을 `role="img"` + `aria-label="색 {c}"` 로 두고 `F-2002 A5`·`A6`·`A7` 의 이름 단언을 `hasText` 로 바꾼다. 세 테스트가 바뀌고, 스크린리더 사용자가 목록을 훑을 때 제목마다 `색 3` 이 따라 읽혀 **오히려 시끄러워진다.** 더 나은 셋째 길은 그룹별로 목록을 묶는 것이지만 그건 F-292 6.8 의 묶음 구조를 다시 여는 일이다.

### Q5. 팔레트를 콜아웃 8색 그대로 쓰는 것 — **기본: 그대로 쓴다**

F-292 결정 13·6.5 가 정한 것이고 `design.md` 3.3 에 이미 적혀 있다. 다만 **계산으로 약한 자리 둘을 찾았다.**

- **4번·5번(`question`·`warning`)이 서로 가깝다** — sRGB 거리 41(화이트·세피아) / 32(다크)
- **8번(`quote` = `--ink-2`)이 그룹 없는 노드(`--ink`)와 가깝다** — 거리 75 / **53** / 79. 세피아가 가장 위험하다

**그래도 그대로 가는 이유**: 저장소에 이 여덟 말고 "테마 3종에서 대비가 맞춰진 색" 이 더 없다. `--accent` 는 현재 문서, `--muted` 는 끊긴 링크, `--danger` 는 5·6번과 겹친다. **새 hex 를 더하는 것은 불변조건이 막는다.** 그리고 8번은 `새 그룹` 의 기본 색 규칙(7.5)상 여덟 번째로 쓰이므로 실제로 고르는 일이 드물다.

**다른 쪽을 고르면**: (a) **팔레트를 7색으로 줄이고** 8번을 뺀다 — 그러면 `MAP_GROUP_MAX` 도 7이 되어 F-292 6.5("최대 8개")와 `mapPrefs.ts` 를 함께 고쳐야 한다. (b) **8번을 `--accent` 로 바꾼다** — 현재 문서 강조와 부딪힌다. (c) `tokens.css` 에 hex 를 더한다 — **불변조건 위반이라 사람 승인이 먼저다.** 판단은 H-a·H-b 를 보고 한다.

### 기본값으로 정한 것 (승인되면 확정)

1. **팔레트는 `tokens.css` `:root` 안의 `var(--callout-*)` 별칭 여덟 줄이다. 새 hex 0개이고 테마 블록에는 아무것도 안 더한다** — 3장
2. **저장은 `md.mapGroups` 에 `{ q, c }` 배열. 검증은 F-2005 가 만든 `normalizeMapGroups` 를 그대로 쓰고 `mapPrefs.ts` 는 안 고친다** — 6장
3. **`기본값으로` 는 그룹을 안 지운다. 그 성질을 e2e 로 못 박는다** — 6.3
4. **색 판정은 끊긴 링크 → 현재 문서 → 그룹 → 공유받음 → 기본** — 5.1
5. **그룹 색은 바탕색만 바꾸고 깊이·호버·필터 섞기는 한 글자도 안 고친다. 최악 대비를 계산해 F-2010 승인 범위 안인 것을 확인했다** — 5.2
6. **`computeGroupColors` 는 `out.fill(0)` 을 안에서 하고 위에서부터 첫 매치를 쓴다. 쿼리 파싱도 안에서 한다** — 4장
7. **조건 글자만 150 ms 미뤄 칠하고, 조립 중에는 타이머를 안 걸고 `compositionend` 에서 건다** — 8장
8. **색 칩은 네이티브 라디오 여덟 개이고 `opacity: 0` 으로 칩 아래 깔린다. 드롭다운도 컬러피커도 없다** — 7.4
9. **`목록` 보기는 행 앞 8px 색 점으로 그룹을 드러내고, 목록에서도 `그룹` 묶음을 고칠 수 있다** — 10장
10. **묶음은 지도 보기 넷, 목록 보기 둘로 고정된다. 그룹이 0개여도 `그룹` 묶음을 그린다** — 7.1
11. **캔버스 안 색은 e2e 로 보지 않는다. 판정 통로는 목록의 색 점이고 색·구분은 사람 확인이다** — 13장
