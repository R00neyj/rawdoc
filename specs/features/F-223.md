# F-223 자동 업로드 API `/v1`

작성일: 2026-09-15
상태: 사용자 요청(2026-09-15 "API 토큰(자동 업로드) ㄱㄱ"). **F-222 커밋 뒤** 시작(토큰 판정·`index.ts`·`wrangler.jsonc` 겹침)
근거: `specs/product.md` 7장 F-223. 기존 `/api` 핸들러(F-206·F-209·F-210·F-212·F-213·F-221)를 다시 쓴다 — 권한·검사 로직을 복사하지 않는다

## 1. 파일 소유

| 파일 | 변경 |

| `worker/v1.ts`(+test) | 신규. `/v1` 전용 핸들러(몸통 보정·응답 모양), 나머지는 기존 핸들러 재사용 |

## 2. 요구사항

### 2.1 공통
- 인증: F-222 2.3 토큰만. 없거나 틀리면 401 `{"error":"unauthenticated"}`
- 요청·응답 JSON(`application/json; charset=utf-8`), 이미지 올리기 몸통만 바이트
- CORS 헤더를 주지 않는다(브라우저 다른 출처 호출 불가). `OPTIONS` 는 405
- 오류 모양은 `/api` 와 같다: `400 invalid(field)`, `403 forbidden`, `404 not_found`, `409 conflict(doc)`, `413 too_large(limit)`, `423 locked(email, expiresAt)`, `507 quota_exceeded(used, limit)`
- 권한은 F-212 규칙 그대로 — 공유받은 편집 권한 문서도 읽고 고칠 수 있다

### 2.2 라우트

| 메서드·경로 | 동작 |
| --- | --- |
| `GET /v1/docs` | 내 문서 요약 목록 (`/api/docs` 와 같은 모양) |
| `GET /v1/docs/:id` | 문서 1개(원문 포함) |
| `POST /v1/docs` | `{ title, content, folderId? , lineEnding? }` → 201. `lineEnding` 없으면 `content` 에 `\r\n` 이 있으면 `crlf`, 아니면 `lf`. `id`·`createdAt`·`updatedAt`·`pinnedAt` 은 받지 않는다(무시가 아니라 400 `field`) |
| `PUT /v1/docs/:id` | `{ title?, content?, baseVersion }` → `/api` 와 같다. **편집 잠금이 살아 있으면 항상 423**(토큰 요청에는 잠금 세션이 없다 — 브라우저에서 편집 중인 문서를 덮지 않는다) |
| `GET /v1/folders` | 내 폴더 목록 |
| `POST /v1/folders` | `/api/folders` 와 같은 몸통 → 201 |
| `POST /v1/attachments` | 몸통 = 이미지 바이트(`Content-Length` 필수). 서버가 id(16 hex) 를 만들고 형식은 시그니처로 판정(F-209). 5MB·형식·계정 500MB 검사 그대로. 201 `{ id, ext, mime, size, width, height, markdown }` — `markdown` = `buildImageBlock({ id, ext, alt: '이미지', width: min(width, 800) })` |
| `POST /v1/docs/:id/link` | 읽기 전용 링크 발급(있으면 그대로) → `{ token, url }`, `url` = `{요청 origin}/#/p/{token}`. 소유자만(F-210) |

- 서버에는 캔버스가 없어 이미지 축소(F-220)를 하지 않는다. 큰 이미지는 호출하는 쪽이 줄여 보낸다
- 삭제·이동·고정·초대·링크 끊기는 이 명세 범위 밖

### 2.3 원문 보존
- `content` 는 받은 문자열 그대로 저장한다(줄바꿈 변환·앞뒤 공백 정리 없음). `GET` 이 돌려주는 `content` 는 보낸 것과 같다
