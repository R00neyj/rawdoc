## 3. 화면 상태 (계약)

### 3.1 상태 기계

화면 상태는 **순수 함수 하나** `pushSettingsView(input)` 가 정한다(`src/app/pushClient.ts`). 입력:

| 입력 | 값 | 어디서 |
| --- | --- | --- |
| `supported` | 서비스 워커·`PushManager`·`Notification` 셋 다 있음 | `'serviceWorker' in navigator && 'PushManager' in window && 'Notification' in window` |
| `ios` | iOS·iPadOS | 3.3 |
| `standalone` | 설치 앱으로 실행 중 | `navigator.standalone === true` 또는 `matchMedia('(display-mode: standalone)').matches` |
| `permission` | `'default'` \| `'granted'` \| `'denied'` | `Notification.permission` |
| `online` | 온라인 | `useAccountDelete` 와 같은 값 — 계정 `in` 이고 `syncState?.online !== false` 면 참, 계정 `offline` 이면 거짓 |
| `enabled` | 이 기기가 지금 계정으로 켜져 있음 | `md.push === 지금 사용자 id`(계정 `offline` 이면 `storedAccount().id`) |
| `key` | `unknown` \| `ok` \| `unavailable` \| `error` | 3.4 |
| `busy` | `null` \| `'on'` \| `'off'` \| `'test'` | 훅 상태 |

출력: 상태 이름 하나 + 스위치 `checked`·`disabled` + 아래 줄 문구 + `테스트 알림 보내기` 버튼 유무. **위에서부터 먼저 맞는 것**:

| # | 상태 | 조건 | 스위치 | 아래 줄 | 테스트 버튼 |
| --- | --- | --- | --- | --- | --- |
| 1 | `turning-on`(켜는 중) | `busy === 'on'` | 꺼짐, **잠김**(3.2) | `켜는 중…` | 없음 |
| 2 | `turning-off`(끄는 중) | `busy === 'off'` | 켜짐, 잠김 | `끄는 중…` | 보임, 잠김 |
| 3 | `ios-browser`(iOS 설치 필요) | `ios && !standalone` | 꺼짐, `disabled` | `iPhone·iPad에서는 홈 화면에 추가한 앱에서만 푸시를 받을 수 있습니다.` | 없음 |
| 4 | `unsupported`(지원 안 됨) | `!supported` | 꺼짐, `disabled` | `이 브라우저는 푸시 알림을 지원하지 않습니다.` | 없음 |
| 5 | `denied`(거절됨) | `permission === 'denied'` | 꺼짐, `disabled` | `이 사이트의 알림이 브라우저에서 차단되어 있습니다. 브라우저 설정에서 허용한 뒤 다시 켜 주세요.` | 없음 |
| 6 | `offline` | `!online` | `enabled` 그대로, `disabled` | `온라인일 때 바꿀 수 있습니다.` | `enabled` 면 보임, `disabled` |
| 7 | `on`(켜짐) | `enabled` | 켜짐 | 설명(5.2 `ready` 문구) | 보임. `busy === 'test'` 면 잠김 |
| 8 | `unavailable`(서버에 푸시 없음) | `key === 'unavailable'` | 꺼짐, `disabled` | `지금은 푸시 알림을 켤 수 없습니다.` | 없음 |
| 9 | `off`(꺼짐) | 그 밖 | 꺼짐 | 설명 | 없음 |

- 문구는 F-3001 4.2 표·5.2 그대로다. 새 문구는 `켜는 중…`·`끄는 중…` 둘(10장 ia.md 갱신)
- `busy === 'test'` 인 동안 스위치도 잠근다(7행 안에서). 테스트 요청과 끄기가 겹치지 않게
- **`denied` 가 `enabled` 보다 앞이다**: 권한을 거둔 기기는 `md.push` 가 남아 있어도 꺼진 것으로 보인다. 서버 쪽 정리는 다음 부팅(4.4 `revoke`)이 한다
- **`on` 이 `unavailable` 보다 앞이다**: 켜진 기기는 키를 다시 묻지 않으므로(3.4) `unavailable` 을 볼 일이 없고, 끄기(`DELETE`)는 비밀 값이 없어도 된다(F-3003)
- 다른 계정이 켠 기기(`md.push` 가 다른 id)는 `enabled` 가 거짓 → `off`. 켜면 서버가 그 행을 이 계정으로 옮긴다(F-3003 A4)

### 3.2 "잠김" 과 `disabled` 의 차이

- 누른 뒤 생기는 `turning-on`·`turning-off`·테스트 중은 **`aria-disabled="true"` + 누름 무시**다. `disabled` 속성을 쓰지 않는다 — 초점을 가진 버튼에 `disabled` 를 걸면 초점이 `document.body` 로 빠진다. 흐름이 끝나면 초점은 누른 그 요소에 그대로 있다
- 환경 때문에 못 쓰는 3~6·8행은 `disabled` 속성(누르기 전부터 그런 상태라 초점 문제가 없다)
- 잠긴 동안 스위치에 `aria-busy="true"`

### 3.3 iOS 판정 — `isIosLike(userAgent, maxTouchPoints)`

- 참: UA 에 `iPhone`·`iPad`·`iPod` 중 하나가 있음, 또는 UA 에 `Macintosh` 가 있고 `maxTouchPoints > 1`(iPadOS 데스크톱 UA — F-3001 4.2)
- `standalone` 은 훅이 읽어 넣는다. `navigator.standalone` 은 타입에 없으므로 `unknown` 으로 좁혀 `=== true` 만 본다
- iOS 16.4+ 설치 앱에서 실제로 받는지는 **확인하지 않았다**(F-3001 Q2 — 범위 밖, 사람 확인 ⑤ 참고만)

### 3.4 서버 키 상태 — `key`

- `unknown` 으로 시작한다. **계정 탭이 보일 때**(`onShown`) 다음이 모두 참이면 `GET /api/push/key` 를 한 번 부른다: `key` 가 `unknown` 또는 `error`, `enabled` 거짓, 3.1 의 3~6행이 아님(=`off` 후보). 부르는 동안에도 스위치는 누를 수 있다 — 켜기 흐름이 같은 요청을 기다린다(한 번에 하나)
- 결과(`fetchPushKey`): 200 이고 `publicKey` 가 base64url 로 풀려 **65 B·첫 바이트 `0x04`** 면 `ok`(키를 이 페이지 동안 기억) / 503 이면 `unavailable`(이 페이지 동안 기억) / 그 밖(네트워크 오류·다른 상태·모양 틀림)은 `error` — 화면은 `off` 그대로, 다음 `onShown` 이나 켜기 때 다시 부른다
- 기억은 훅 메모리뿐이다(저장하지 않는다). 새로 읽으면 다시 `unknown`
- 켜진 기기는 부르지 않는다 — 요청을 아끼고, `unavailable` 을 보일 이유가 없다(3.1)
- Q1

## 4. 흐름 (계약 — `src/app/pushClient.ts`)

흐름은 브라우저를 직접 만지지 않고 `PushDeps` 로 받는다. 훅(5장)이 실제 브라우저로 채우고, 단위 테스트가 가짜로 채운다.

```ts
export const PUSH_SYNC_INTERVAL_MS = 604_800_000   // 7일 (F-3001 2.5)
export const PUSH_SW_READY_TIMEOUT_MS = 10_000      // serviceWorker.ready 기다림 상한 (m2)

export type PushPermission = 'default' | 'granted' | 'denied'
export type PushKeyState = { kind: 'unknown' } | { kind: 'ok'; publicKey: string } | { kind: 'unavailable' } | { kind: 'error' }

export type PushSubscriptionLike = {
  endpoint: string
  options: { applicationServerKey: ArrayBuffer | null }
  toJSON(): unknown
  unsubscribe(): Promise<boolean>
}
export type PushPlatform = {
  permission(): PushPermission
  requestPermission(): Promise<PushPermission>
  // serviceWorker.ready 를 PUSH_SW_READY_TIMEOUT_MS 까지 기다려 pushManager 를, 넘으면 null
  pushManager(): Promise<{
    getSubscription(): Promise<PushSubscriptionLike | null>
    subscribe(options: { userVisibleOnly: true; applicationServerKey: Uint8Array }): Promise<PushSubscriptionLike>
  } | null>
}
export type PushDeps = {
  platform: PushPlatform
  fetch: typeof fetch
  now: () => number
  getPref: (key: 'md.push' | 'md.pushSyncedAt') => string
  setPref: (key: 'md.push' | 'md.pushSyncedAt', value: string) => void
}

export type TurnOnResult = 'on' | 'permission-refused' | 'unavailable' | 'unsupported-service' | 'failed'
export type PushSyncOutcome = 'skip' | 'fresh' | 'synced' | 'revoked' | 'unavailable' | 'failed'

export function fetchPushKey(fetchFn: typeof fetch): Promise<PushKeyState>
export function turnOnPush(deps: PushDeps, userId: string, key: PushKeyState): Promise<{ result: TurnOnResult; key: PushKeyState }>
export function turnOffPush(deps: PushDeps): Promise<'off' | 'failed'>
export function sendTestPush(deps: PushDeps): Promise<'sent' | 'failed'>
export function syncPushOnBoot(deps: PushDeps, userId: string): Promise<PushSyncOutcome>
```

- 모든 요청은 `credentials: 'same-origin'`, 몸통이 있으면 `Content-Type: application/json`. 몸통 모양은 `src/lib/pushApi.ts` 타입 그대로
- **어느 흐름도 던지지 않는다.** 브라우저 API·`fetch` 가 던지면 그 흐름의 실패 값으로 끝난다
- 서버에 보내는 몸통은 `subscribeBody(subscription.toJSON())` — `endpoint` 문자열과 `keys.p256dh`·`keys.auth` 문자열만 골라 `PushSubscribeBody` 로. 하나라도 없으면 `null` → 그 흐름은 `failed`
- `subscribe` 의 `applicationServerKey` 는 base64url 을 푼 **65 B `Uint8Array`** 로 넘긴다(문자열로 넘기는 것을 모든 브라우저가 받는지 확인하지 않았다)
- 브라우저 구독의 키가 서버 키와 같은지는 `sameServerKey(subscription.options.applicationServerKey, 풀린 키)` — 바이트 비교, `null` 이면 다름

### 4.1 켜기 — `turnOnPush`

스위치를 누른 **사용자 동작 안에서** 부른다. 순서가 결정이다:

1. 권한이 `default` 면 `requestPermission()` — **이 흐름의 첫 `await`** 다(권한 창은 사용자 동작 직후여야 뜬다 — 브라우저 일반 규칙, 확인 안 함). 결과가 `granted` 가 아니면 `permission-refused`. 처음부터 `denied` 여도 `permission-refused`(화면은 3.1 에서 이미 막는다)
2. `key` 가 `ok` 가 아니면 `fetchPushKey` — `unavailable` 이면 `unavailable`, `error` 면 `failed`
3. `pushManager()` 가 `null`(서비스 워커 없음·10초 넘김)이면 `failed`
4. `getSubscription()` — 있고 키가 같으면 그것을 쓴다. 있는데 키가 다르면 `unsubscribe()` 뒤 새로. 없으면 `subscribe({ userVisibleOnly: true, applicationServerKey })`
5. `PUT /api/push/subscription` — 204 면 `md.push = userId`, `md.pushSyncedAt = String(now())` 를 쓰고 `on`. 400 `unsupported_push_service` 면 `unsupported-service`. 503 이면 `unavailable`. 그 밖·네트워크 오류는 `failed`
6. 2~5에서 실패하면 설정 키를 **건드리지 않는다**. 4에서 만든 브라우저 구독은 그대로 둔다(다음 켜기가 다시 쓴다 — 서버에 행이 없으니 보내지 않는다)
- 돌려주는 `key` 는 이 흐름에서 알게 된 최신 키 상태다(훅이 기억한다)

### 4.2 끄기 — `turnOffPush`

1. `pushManager()` → `getSubscription()`. 구독이 있으면 `DELETE /api/push/subscription` `{ endpoint }`
   - 204 가 아니거나 네트워크 오류면 **`failed` — 설정 키 그대로(켜진 채)**. 서버가 계속 보내기 때문이다(F-3001 4.2)
   - 204 면 `unsubscribe()`(결과·예외는 보지 않는다)
2. 구독이 없거나(`pushManager()` 가 `null` 포함) 1이 성공하면 `md.push`·`md.pushSyncedAt` 을 `''` 로 쓰고 `off`
- 구독이 없으면 서버에 알릴 `endpoint` 가 없다. 그 서버 행은 다음 보내기에서 푸시 서비스가 404·410 을 돌려 지워진다(F-3003 `pushResultStatements` `gone`)

### 4.3 테스트 — `sendTestPush`

1. `pushManager()` → `getSubscription()`. 없으면 4.4 의 `subscribe` 절차(키 → 구독 → `PUT`)를 한 번 한다. 그것도 실패하면 `failed`
2. `POST /api/push/test` `{ endpoint }` — 204 면 `sent`
3. **404 면 한 번만 되살린다**: 같은 구독으로 `PUT` → 204 면 `md.pushSyncedAt = now` 를 쓰고 2를 한 번 더. 그 결과가 204 면 `sent`, 아니면 `failed`. 404 의 뜻은 "서버 행이 없거나 옛 세션에 묶여 죽음"(F-3003 Q4) — 7.2 의 구멍이 다른 길로 남아 있어도 테스트 한 번으로 메운다
4. 그 밖(502 `push_failed`·503·네트워크 오류)은 `failed`

### 4.4 부팅 다시 알리기 — `syncPushOnBoot`

판정은 순수 함수 `decidePushSync(input)` 가 한다. 입력: `userId`, `md.push`, `md.pushSyncedAt`, `now`, `supported`, `permission`, `hasSubscription`. 위에서부터:

| # | 조건 | 판정 | 하는 일 |
| --- | --- | --- | --- |
| 1 | `md.push !== userId` | `skip` | 없음(요청 0) |
| 2 | `!supported` | `skip` | 없음 |
| 3 | `permission !== 'granted'` | `revoke` | 구독이 있으면 `DELETE` `{ endpoint }`(결과 무시) + `unsubscribe()`(결과 무시). **결과와 상관없이** `md.push`·`md.pushSyncedAt` 을 `''` 로. 알림 띠 없음(Q4) → `revoked` |
| 4 | 브라우저 구독 없음 | `subscribe` | `fetchPushKey` → 구독 → `PUT` |
| 5 | `md.pushSyncedAt` 이 숫자이고 `0 ≤ now − 그 값 < PUSH_SYNC_INTERVAL_MS` | `fresh` | 없음(요청 0) |
| 6 | 그 밖(7일 지남·빈 값·숫자 아님·미래 시각) | `refresh` | `fetchPushKey` → 키가 구독과 다르면 `unsubscribe` → 새 구독, 같으면 그대로 → `PUT` |

- `hasSubscription` 은 1~3을 통과했을 때만 읽는다(`pushManager()` → `getSubscription()`). `pushManager()` 가 `null` 이면 `failed`, 설정 키 그대로
- 4·6 의 결과: `PUT` 204 → `md.pushSyncedAt = now` 쓰고 `synced`. 키 503 또는 `PUT` 503 → `unavailable`(설정 키 그대로 — 비밀 값이 돌아오면 다음 부팅이 잇는다). `PUT` 400 `unsupported_push_service` → `md.push`·`md.pushSyncedAt` 을 `''` 로 쓰고 `failed`(이 기기는 켤 수 없다). 그 밖 → `failed`, 설정 키 그대로(다음 부팅에 다시)
- 권한이 `default` 인 것도 3 이다 — 사용자가 사이트 권한을 "초기화" 하면 `default` 가 되고 그때 구독은 쓸 수 없다(`userVisibleOnly`)
- 부팅 때는 권한을 묻지 않는다(사용자 결정 4). 4·6 의 `subscribe` 는 이미 `granted` 일 때만 간다
- 기기 하나가 평소 쓰는 요청은 7일에 `GET key` + `PUT` 둘(F-3001 3.1)

- **`onShown`**(계정 탭이 보일 때마다): `md.push`·`Notification.permission`·`standalone` 을 다시 읽어 화면 상태를 새로 만들고, 3.4 조건이면 키를 묻는다. 다른 탭에서 켜고 끈 결과도 이때 반영된다

- **`onTest`**: `busy = 'test'` → `sendTestPush` → P1 또는 P2 → `busy = null`
- **부팅 다시 알리기**: `bootPhase === 'ready'` 이고 계정이 `in` 이 된 **첫 때 한 번**(이 페이지에서). 오프라인으로 부팅해 나중에 `in` 이 되면 그때 한 번. 결과로 알림 띠를 띄우지 않는다
- 흐름의 결과가 돌아왔을 때 컴포넌트가 사라졌으면 상태를 쓰지 않는다

### 5.2 `push-open` 받기 (F-3004 10장이 넘긴 세 조건)

1. **부팅 때부터 듣는다**: 훅이 처음 붙을 때 `navigator.serviceWorker` 의 `message` 수신기를 단다 — `bootPhase`·계정과 무관하게. `navigator.serviceWorker` 가 없으면 달지 않는다
2. 받은 `event.data` 를 순수 함수 `pushOpenTarget(data, bootedPublic)` 에 넘긴다:
   - `data` 가 객체이고 `type === PUSH_OPEN_MESSAGE`(F-3004 `src/pwa/pushSwCore.ts`)이고 `url` 이 문자열이 아니면 `none`
   - `url` 을 **`safePushUrl` 로 한 번 더 거른다**(`src/lib/pushPayload.ts`). 결과의 경로 부분(첫 `#` 앞, `?` 뒤는 무시)이 `/` 가 아니면 `none`
   - 해시 부분(첫 `#` 부터, 없으면 `''`)을 `parseHash` 로 풀어 **`type === 'doc'` 일 때만** 옮긴다. 그 밖(`''`·`#`·`#/`(홈)·공유·지도 등)은 `none` — **`/`·`/#/` 은 해시를 옮기지 않는다**(창을 앞으로 가져오는 것으로 끝). 테스트·저장 공간·폴더 공유 알림(`/#/`)이 보던 문서를 닫지 않게
   - `bootedPublic` 이 참이면 `{ kind: 'reload', url }`, 아니면 `{ kind: 'hash', hash, docId }`
3. `hash` 이면: `bootPhase` 가 아직 `ready` 가 아니면 **마지막 하나만** 기억했다가 `ready` 가 된 뒤 적용한다(부팅이 해시를 읽은 뒤·`hashchange` 수신기를 달기 전 사이에 잃지 않게). 적용은 `useNotificationsGlue` `handleOpenNotification` 과 같다 — 그 `docId` 가 `docsRef` 에 없고 `navigator.onLine` 이면 `resyncFromStore()` 를 기다리고(실패는 삼킨다), `location.hash = hash`. 이동·스레드 열기는 기존 `hashchange` → `decideHashNav` 가 한다
4. `reload` 이면: `history.replaceState(null, '', url)` 뒤 `location.reload()`. 공개 보기로 부팅한 창은 저장소를 열지 않았으므로(`runBoot`) 해시만 바꾸면 빈 앱이 된다. `replaceState` 는 `hashchange` 를 일으키지 않는다(Q2)
- `bootedPublic` = 훅이 처음 붙을 때 `parseHash(location.hash).type` 이 `public`·`publicFolder` 인가 — `runBoot` 과 같은 판정(`isPublicBoot(hash)`)
- `event.source` 로 보낸 이를 거르지 않는다: 같은 출처 페이지 스크립트만 이 이벤트를 흉내 낼 수 있고, 그 스크립트는 이미 `location.hash` 를 바꿀 수 있다. e2e 가 합성 이벤트로 판정한다(m3)
- 해시가 지금 해시와 같으면 `hashchange` 가 없어 아무 일도 없다 — 알림함 항목 누르기와 같은 동작이다

### 7.2 로그아웃·계정 전환·재로그인 (F-3003 10장이 넘긴 구멍)

- **구멍**: 로그아웃하면 서버 세션 행이 지워져 그 기기 구독은 "산 구독" 이 아니다(F-3003 4.2). `md.push` 는 남으므로 같은 계정으로 다시 로그인하면 켜짐으로 보이는데, 4.4 의 `fresh`(7일 안) 때문에 `PUT` 을 하지 않아 **최대 7일 푸시가 오지 않는다**
- **막는 법**: `src/app/account.ts` `logout` 이 2xx 를 받아 `md.account` 를 비우는 바로 그 자리에서 `md.pushSyncedAt` 도 `''` 로 쓴다. 로그아웃은 곧바로 `/?app=1` 로 새로 읽고(근거 절), 다음에 같은 계정으로 로그인해 부팅하면 4.4 가 6(`refresh`)으로 가서 새 세션으로 `PUT` 한다
  - 실패한 로그아웃(`false`)은 아무것도 지우지 않는다(지금 `md.account` 와 같다)
  - `md.push` 는 지우지 않는다 — 같은 계정으로 돌아오면 다시 켜지 않아도 된다
- **계정 전환**(A 가 로그아웃하고 B 가 로그인): `md.push` 가 A 의 id 라 B 에게는 `off`, 4.4 는 `skip`. A 의 서버 행은 A 의 세션이 없어 보내지 않고 매일 정리가 지운다. B 가 켜면 같은 `endpoint` 행이 B 로 옮겨 간다. A 가 다시 로그인하면 `md.push` 가 B 라 A 에게는 `off`
- **세션 만료(30일 안 씀)**: 따로 할 일이 없다. `fresh` 는 "7일 안에 로그인 상태로 부팅했다" 는 뜻이고 그때 세션은 적어도 23일 더 산다(하루마다 연장, F-3001 p12) — 세션이 만료됐다면 `md.pushSyncedAt` 은 이미 7일보다 오래됐다
- **계정 삭제 다시 로그인**(F-2038 `reauth`): 새 세션이 생기고 옛 세션도 만료까지 산다. 7일 안에 다음 `refresh` 가 새 세션으로 옮긴다. 계정을 끝내 지우면 서버가 행을 지운다
- **권한 회수**: 4.4 의 3(`revoke`). 페이지가 열린 동안 거두면 계정 탭이 `denied` 로 보이고(3.1 — `onShown` 이 다시 읽는다) 정리는 다음 부팅
- 다른 길로 남은 구멍은 `테스트 알림 보내기` 의 404 되살리기(4.3 3번)가 메운다

## 12. 사람 확인 (구현 뒤 main 이 `specs/human-checks.md` 에)

F-3003(비밀 값)·F-3004 가 배포된 주소에서:

1. **안드로이드 설치 앱**: 계정 탭 → 스위치 → 권한 창 → 허용 → 켜짐 → `테스트 알림 보내기` → P1, 알림이 몇 초 안에 온다(F-3004 사람 확인 ①과 함께)
2. **알림 누르기**: 앱이 뒤에 열려 있을 때 테스트 알림을 누르면 앱이 앞으로 오고 **보던 문서가 그대로**다(`/#/` 은 옮기지 않음). 실제 멘션 알림(F-3006 뒤)은 그 스레드로 옮긴다
3. **권한 거절**: 권한 창에서 차단 → P3, 스위치 꺼짐, 다시 열면 `denied` 문구
4. **권한 회수**: 켠 뒤 브라우저 사이트 설정에서 알림 차단 → 계정 탭 다시 열면 `denied`, 새로고침 뒤 `md.push` 가 비고 서버에 `DELETE` 가 한 번 갔다(개발자 도구 네트워크)
5. **로그아웃 → 같은 계정 재로그인**: 부팅 때 `PUT` 이 한 번 가고, 곧바로 테스트 알림이 온다
6. **데스크톱 Chrome 탭**: 켜기·테스트·끄기. 끈 뒤 테스트 버튼이 사라진다
7. **스위치 모양·초점**: 켜짐·꺼짐·흐림이 한눈에 구별된다, 세 테마에서 대비, 키보드로 Space 켜고 끄기 뒤 초점이 스위치에 남는다, 화면 읽기 프로그램이 "이 기기에서 푸시 받기, 스위치, 켬/끔" 과 아래 줄을 읽는다
8. **iOS Safari 탭**: `ios-browser` 문구, 스위치 흐림(F-3001 Q2 — 참고만, 범위 밖)
9. **로컬 `npm run dev:worker`**: 계정 탭에서 `unavailable` 문구(F-3003 Q3)

## 13. 열린 질문

### Q1. 서버 키를 언제 묻나 — **기본값: 계정 탭이 보일 때 한 번(꺼진 기기만), 페이지 동안 기억**

- 이유: 비밀 값이 없는 환경(로컬, 키를 뺀 배포)에서 스위치를 누르기 **전에** `지금은 푸시 알림을 켤 수 없습니다.` 를 보이고 권한 창을 헛되이 띄우지 않는다. 받은 키를 켜기 흐름이 다시 써서 누른 뒤의 `await` 가 하나 준다. 비용은 계정 탭을 연 페이지마다 `GET` 하나(D1 인증 읽기뿐, F-3003 5.2)
- 다른 안: 누를 때만 묻는다 — 탭을 여는 것만으로는 요청 0. 대신 로컬에서는 권한을 받은 뒤에야 `unavailable` 을 알게 되고, `requestPermission` 뒤에 `await` 가 하나 더 는다. 3.4 가 빠지고 U1 의 8행 입력이 "켜기 결과" 로 바뀐다

### Q2. 공개 보기로 부팅한 창이 `push-open` 을 받으면 — **기본값: 그 주소로 새로 읽는다**

- 이유: 공개 보기 창은 저장소를 열지 않았다(`runBoot`). 해시만 바꾸면 빈 앱이 된다. 새로 읽으면 보통 부팅으로 그 문서가 열린다. 서비스 워커는 경로 `/` 인 창만 고르므로(F-3004 3.3) `/#/p/…` 창이 뽑힐 수 있다
- 다른 안: 무시한다 — 창만 앞으로 오고 옮기지 않는다. 코드가 한 갈래 준다. 대신 공개 링크만 보던 사람이 멘션 알림을 눌러도 그 문서로 가지 않는다

### Q3. 문구와 배포 시점 — **기본값: F-3001 5.2 최종 문구 그대로, 배포 시점은 main 이 사용자에게 묻는다**

- 설명 `멘션·답글, 내 문서의 새 댓글, 공유 받음, 저장 공간 경고를 이 기기로 보냅니다. …` 와 도움말의 "3분씩 모아" 는 F-3005·F-3006(댓글)·F-3007(공유)·F-3008(저장 공간)이 들어와야 참이다. F-3001 6장은 F-3003+F-3004+F-2110 만으로 `테스트 알림` 을 실제 기기에서 먼저 확인하자고 했다 — 그 사이에 배포하면 켠 사람은 테스트 알림만 받는다
- 기본값의 이유: 문구를 두 번 바꾸지 않는다. 사용자 수가 적고 뒤 명세가 곧 이어진다
- 다른 안 A: F-3006 이 들어올 때까지 `deploy` 브랜치에 올리지 않는다 — 사람 확인 ①은 `npm run build` + preview 가 아니라 배포 주소가 필요하므로(서비스 워커·VAPID) 확인이 늦어진다
- 다른 안 B: 그동안 임시 설명 `지금은 테스트 알림만 보냅니다. 멘션·답글 알림은 곧 추가됩니다.` 를 두고 F-3006 에서 바꾼다 — F-3006 파일 목록에 `pushClient.ts` 가 더해진다

### Q4. 권한을 거둔 기기를 부팅 때 정리할 때 알리나 — **기본값: 조용히 정리**

- 이유: 사용자가 스스로 브라우저에서 막았다. 계정 탭을 열면 `denied` 문구가 이유를 말한다
- 다른 안: info 띠 `브라우저에서 알림을 막아 이 기기의 푸시를 껐습니다.` — 새 문구 하나, 부팅마다가 아니라 정리한 그 한 번

### Q5. 로그아웃 때 서버에 `DELETE` 도 하나 — **기본값: 하지 않는다. `md.pushSyncedAt` 만 비운다**

- 이유: 세션을 지우면 서버가 그 기기로 보내지 않는다(F-3001 2.1 — 클라이언트 요청 없이). 로그아웃 앞에 요청을 하나 더 두면 로그아웃이 느려지고 실패 갈래가 는다(F-2034 순서)
- 다른 안: `logout` 앞에 `DELETE` + `unsubscribe` — 같은 계정으로 돌아와도 다시 켜야 하고(`md.push` 도 지워야 맞다), 공용 컴퓨터에서 브라우저 구독까지 남지 않는다

### Q6. 테스트 404 에 한 번 되살리기 — **기본값: 한다(`PUT` 후 한 번 더)**

- 이유: 404 는 "서버 행이 없거나 옛 세션" 이고 그 기기의 구독은 살아 있다. 사용자가 "테스트가 안 된다" 로 끝나지 않게 한다(F-3003 Q4 가 이 되살리기를 예상했다)
- 다른 안: 곧바로 P2 — U7 의 404 행이 `failed` 가 되고, 7.2 밖의 구멍은 다음 7일 `refresh` 까지 남는다
