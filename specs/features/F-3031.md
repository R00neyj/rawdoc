# F-3031 MCP 쓰기 도구 넷

작성일: 2026-10-16
상태: 승인(2026-10-16, 사용자 "ㄱㄱ" — F-4008 결정·새 의존·영어 문구 일괄 승인). F-4008 3장 표의 `create_document`·`create_folder`·`move_document`·`update_document` 와 4장 쓰기 관문·`/limits` 링크를 만든다. 서버만, 화면 없음
근거 코드(2026-10-16): `worker/writeGate.ts` `runWriteGate`(사용자 → 막힘 403 → 하루 429 → 분 429, 몸통 `RateLimitedBody`), `worker/auth.ts` `getUser`(기억된 사용자 먼저), `worker/v1.ts` `handleCreateDocV1`·`handleCreateFolderV1`·`handleMoveDocFolderV1`(금고 목적지 403 `e2ee_folder`)·`handleUpdateDocV1`(409 `{ error:'conflict', doc }`), `worker/docs.ts` `handleCreateDoc`(없는·남의 `folderId` 는 통과, 금고 폴더 409 `e2ee_folder`), `worker/folders.ts` `handleCreateFolder`(금고 부모 409), `worker/access.ts` `getOwnedFolder`. F-3030 2장 계약(`McpCall`·`innerV1`·`toToolResult`·`toolResult`·`toolError`·`safeTool`·`docUrl`·`VAULT_DOC_MESSAGE`)과 3장 등록 자리(`registerReadTools` 다음 줄)를 그대로 쓴다

## 2. 계약
```ts
// worker/mcpWriteGate.ts
export function gateMcpWrite(call: McpCall): Promise<CallToolResult | null>   // null = 통과
export function limitsUrl(origin: string, scope: 'minute' | 'day', retryAfter: number): string
// → `${origin}/limits?scope=${scope}&retry=${retryAfter}` (F-2147 질의 이름)
```
- `gateMcpWrite`: `rememberUser(call.request, call.caller.user)` 뒤 `runWriteGate(call.request, call.env)` 를 그대로 부른다 — 판정·한도·바인딩 경고가 `/v1` 과 한 곳. origin 은 `new URL(call.request.url).origin`. 429 → `toolError(문구, { error:'rate_limited', scope, limit, retryAfter, limitsUrl })`, 403 → `toolError(문구, { error:'account_blocked' })`, 401(오지 않아야 함)은 `toToolResult` 그대로
- 도구 하나의 순서: SDK 입력 검사 → `gateMcpWrite` → (create_document 만) 폴더 확인 → `innerV1` 로 `/v1` 핸들러 → 결과 변환. 콜백은 모두 F-3030 `safeTool(cb)` 로 감싼다. `/v1` 처럼 관문을 먼저 지나므로 검사에서 떨어진 쓰기도 분 한도를 하나 쓴다. 하루 쓰기 수는 핸들러가 지금처럼 센다
- 입력 스키마(zod)는 **형식만**(string·int·null). 길이·uuid·크기는 핸들러가 판정한다 — 두 곳에 두지 않는다

## 3. 도구 (주석 F-4008 3장 그대로, 이름·title·설명은 계약)
| 도구 · title | 입력 | 부르는 것 | 성공 결과 |
| --- | --- | --- | --- |
| `create_document` · `Create document` | `{ title: string, content: string, folderId?: string }` | `POST /v1/docs` `handleCreateDocV1` | `toolResult({ id, title, version, folderId, updatedAt, url })` |
| `create_folder` · `Create folder` | `{ name: string, parentId?: string }` | `POST /v1/folders` `handleCreateFolderV1` | `toToolResult` 그대로 |
| `move_document` · `Move document` | `{ id: string, folderId: string \| null }` | `PUT /v1/docs/:id/folder` `handleMoveDocFolderV1` | `toToolResult` 그대로 |
| `update_document` · `Update document` | `{ id: string, baseVersion: int, content?: string, title?: string }` | `PUT /v1/docs/:id` `handleUpdateDocV1` | `toolResult({ id, title, version, updatedAt, url })` |
- `url` = `docUrl(call, id)`. 성공 결과에 본문을 되돌리지 않는다(모델이 방금 보낸 글, 토큰 낭비)
- **create_document 폴더 확인**: `folderId` 가 있으면 `getOwnedFolder` 로 내 폴더인지 본다. 없으면 `toolError` `folder_not_found`. 앱의 "없는 폴더 통과"는 오프라인 순서 때문이고 모델에겐 그 이유가 없다 — 통과시키면 잘못된 `folder_id` 를 가진 문서가 생긴다(9장)
- **update_document**: `content`·`title` 이 둘 다 없으면 핸들러를 부르지 않고 `toolError` `missing_change`

설명(description):
- create_document: `Create a new Markdown document. content is the full Markdown text. Omit folderId to create it at the top level (use list_folders for ids). Returns the new id, version and url.`
- create_folder: `Create a folder. Omit parentId for a top-level folder. Returns the new folder.`
- move_document: `Move a document you own into a folder, or to the top level with folderId null. The text is not changed.`
- update_document: `Replace a document's whole text and/or its title. Read it with fetch first and pass its version as baseVersion. If the document changed since, nothing is written and the current document is returned so you can reapply your edit.`

## 4. 오류 문구 (영어, `toolError(문구, data)` → `{ message, ...data }`; 표에 없는 실패 — 404 `Not found, or you do not have access.`·400 `Invalid argument: {field}.` 등 — 는 F-3030 `toToolResult` 그대로)
| 경우 | 문구 | data |
| --- | --- | --- |
| 429 분 | `Write limit reached ({limit} writes per minute). Writes resume in {retryAfter} seconds. Details: {limitsUrl}` | `{ error:'rate_limited', scope, limit, retryAfter, limitsUrl }` |
| 429 하루 | `Daily write limit reached ({limit} writes per UTC day). Writes resume in {retryAfter} seconds. Details: {limitsUrl}` | 같음 |
| 403 `account_blocked` | `This account is blocked from writing. Reading still works.` | `{ error:'account_blocked' }` |
| 409 `conflict` | `The document changed since version {baseVersion} (now {doc.version}). Nothing was written. The current document is in doc; apply your edit to it and retry with baseVersion {doc.version}.` | `{ error:'conflict', baseVersion, doc }` (409 몸통 `doc` 그대로, 본문 포함) |
| 403 `e2ee_doc` | `VAULT_DOC_MESSAGE` | `{ error:'e2ee_doc' }` |
| 403·409 `e2ee_folder` | `Vault (end-to-end encrypted) folders cannot be used through this connection.` | `{ error:'e2ee_folder' }` |
| 403 `forbidden` (move 비소유자·update 보기 권한) | `You do not have permission to change this document.` | `{ error:'forbidden' }` |
| `folder_not_found` | `Folder not found, or you do not have access. Use list_folders to find one.` | `{ error:'folder_not_found' }` |
| `missing_change` | `Provide content, title, or both.` | `{ error:'missing_change' }` |
- 휴지통 문서는 `getDocAccess` 가 `null` 로 보므로(F-3021 2장) update·move 에서 404 not found 문구로 끝난다 — 따로 두지 않는다
