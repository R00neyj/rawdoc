## 3. 요구사항

### 3.1 툴팁을 공유 화면에서 쓸 수 있는가 — 쓸 수 있다 (코드 확인)

| 확인한 것 | 결과 |
| --- | --- |
| `.icon-btn`·`.icon-btn-wrap`·`.icon-tooltip` 선택자 (app.css 1943·1950·1993·2021·2026·2031·2039·2047행) | **`.app-shell` 로 감싸지 않은 전역 선택자다.** `.public-view` 안에서도 그대로 먹는다 |
| `app.css` 안 `.topbar` 로 좁힌 툴팁 규칙 | 314행 `.topbar .icon-btn-wrap:has(> .topbar-search-btn)` 하나뿐이고 검색 버튼 전용이다 |
| `app.css` 로딩 | `src/main.tsx` 10행이 앱 전체에 한 번 import 한다. 경로(`#/p/…`)와 무관하다 |
| 잘릴 위험 | `.public-view`(2626행)·`.public-view-header`(2634행)·`html`·`body`·`#root`(tokens.css 224~249행) 어디에도 `overflow` 가 없다. 툴팁은 `top: calc(100% + 6px)` 로 머리줄 아래에 그려지고 `z-index: 40` 이다. 같은 자리의 `.viewer` 는 `position` 이 없어(정적) 위치 지정 요소인 툴팁 아래에 깔린다 |
| 버튼 기본 모양 | `tokens.css` 257~261행이 `button { background:none; border:0; cursor:pointer }` 를 전역으로 준다 |

**고칠 것은 없다.** `TopBar.tsx`·`ExportMenu.tsx` 와 똑같은 마크업을 쓰면 된다

```jsx
<span className="icon-btn-wrap">
  <button type="button" className="icon-btn public-view-settings" aria-label="설정" onClick={…}>
    <IconSettings size={18} />
  </button>
  <IconTooltip text="설정" />
</span>
```

- **`public-view-settings`·`public-view-export` 클래스 이름은 남긴다.** 모양은 `.icon-btn` 이 주고 이 클래스는 선택자 손잡이로만 쓴다(CSS 규칙 없음). `e2e/homeScreen.spec.js` 125행이 `.public-view-settings` 로 버튼을 찾는다 — 이름을 지우면 그 테스트가 깨진다
- 툴팁 지연은 앱과 같다: 마우스 400ms(app.css 2044행), 키보드 `:focus-visible` 0ms(2052행). **공개 화면이라고 다른 값을 두지 않는다** — 값이 두 군데로 갈라지면 한쪽만 고쳐지는 일이 생긴다

### 3.2 머리줄 버튼 2개

| 자리 | 아이콘 | 크기 | `aria-label` = 툴팁 문구 | 툴팁 정렬 | 비활성 |
| --- | --- | --- | --- | --- | --- |
| 설정 | `IconSettings` (`settings`) | 버튼 32×32, 아이콘 18px | `설정` | `center` | 없음 (항상 누를 수 있다) |
| 내보내기 | `IconDownload` (`download`) | 같음 | `.md 내보내기` | `end` | `disabled={!doc}` — 지금 조건 그대로 |

- 문구는 **지금 화면에 보이는 글자를 그대로 옮긴다.** `설정`·`.md 내보내기` 둘 다 `specs/ia.md` 6장 문구표에 이미 있는 말이고(`앱 설정 → 설정`, `파일 내보내기 → .md 내보내기`), 문자열을 바꾸지 않으면 `getByRole('button', { name: … })` 로 찾던 기존 e2e 3곳이 그대로 통과한다 (6.2)
- 툴팁 정렬을 내보내기만 `end` 로 두는 이유: 머리줄 오른쪽 끝 버튼이라 좁은 창에서 가운데 정렬 툴팁이 창 밖으로 나갈 수 있다. `ExportMenu.tsx` 97행이 같은 이유로 `align="end"` 를 쓴다
- 순서(설정 → 내보내기)·간격(`.public-view-header` 의 `gap: 12px`)은 그대로다. 앱 상단바도 `gap: 12px` 다 (app.css 32행)
- **누르는 동작은 하나도 바뀌지 않는다.** 설정은 `SettingsDialog` 를 열고, 내보내기는 `buildExportPayload` 로 `.md`(이미지가 있으면 zip)를 받는다

### 3.3 아이콘만 남겼을 때 잃는 것 — 명세에 남긴다

공유 화면은 **앱을 한 번도 안 써 본 사람이 링크를 받아 처음 들어오는 곳**이다. 아이콘 전용으로 바꾸면 이것을 잃는다

1. 마우스를 올리기 전에는 두 버튼이 무엇인지 글자로 알 수 없다. 특히 아래 화살표(`download`)만으로 "**마크다운 원문 파일**을 받는다"까지는 읽히지 않는다
2. 터치 기기에는 호버가 없다 — 툴팁이 뜰 기회 자체가 없고, 누르기 전까지 모른다
3. `aria-label` 로 스크린 리더 사용자는 그대로 알 수 있으므로, 잃는 것은 **눈으로 보는 사람** 쪽뿐이다

통일이 사용자 결정이므로 뒤집지 않는다. 대신 완화책을 정한다

| 완화책 | 값 |
| --- | --- |
| 아이콘은 관용 아이콘만 | `settings`(톱니바퀴)·`download`(아래 화살표)·`left_panel_open`/`left_panel_close`. 새 그림을 만들지 않는다 |
| 툴팁 지연 | 앱과 같은 400ms (3.1). 더 짧게 두지 않는다 |
| 툴팁 = `aria-label` | 같은 문자열 하나를 두 곳에 넘긴다. 보이는 말과 접근성 이름이 어긋나지 않게 (F-142 3.2) |
| 좁은 창에서 툴팁이 잘리지 않게 | 오른쪽 끝 버튼은 `align="end"` (3.2). A4 로 판정한다 |
| 되돌리는 방법 | 2.1 C1·C2 두 줄만 되돌리면 원래대로다. 다른 변경과 얽혀 있지 않다 |

### 3.4 좁은 창 폴더 목록 토글

### 3.6 코드블록 머리줄 — 어디서 만드는가

**`Viewer.tsx` 의 `codeCopy` effect 가 DOM 으로 넣는다. `renderMarkdown` 출력(HTML 문자열)은 한 글자도 바꾸지 않는다.**

읽고 확인한 근거 — `renderMarkdown` 출력에 넣으면 두 곳으로 새어 나간다

| 새는 곳 | 근거 |
| --- | --- |
| 내보낸 HTML 파일 (F-280) | `src/viewer/toHtmlDoc.ts` 70행 `buildExportBody` 가 같은 `renderMarkdown(withoutComments)` 를 부른다. 결과는 `buildHtmlDocument`(87~110행)로 단독 `.html` 이 된다 — 누를 수 없는 복사 버튼과 머리줄이 정적 파일에 박힌다 |
| 인쇄·PDF (F-279) | `src/app/printDoc.ts` 30~33행이 `App.tsx` 1482행의 `renderMarkdown(...)` 결과를 `.print-root .markdown-body` 의 `innerHTML` 로 그대로 넣는다 |

DOM 쪽에 넣으면 두 경로 모두 손댈 필요가 없다

- 내보낸 HTML: `buildHtmlDocument` 가 `<body class="public-view"><div class="viewer">` 로만 감싼다(`viewer--code-copy` 가 아니다). 머리줄 요소도 없고, 3.7 CSS 도 선택자가 안 맞아 죽은 규칙으로 남는다. `exportHtmlCss.ts` 31행이 `viewer.css` 를 통째로 넣으므로 문자열 몇 줄이 늘 뿐이다
- 인쇄: `printDoc` 은 `Viewer` 를 거치지 않는다. 지금도 복사 버튼이 없고, 앞으로도 없다

#### 조립 규칙 (`Viewer.tsx` 145~154행 교체)

```
root.querySelectorAll('pre > code') 마다
  pre = code.parentElement                       (없으면 건너뜀 — 지금과 같다)
  pre.parentElement 가 .md-code 면 건너뛴다      (멱등 가드, 아래)
  wrap  = <div class="md-code">
  head  = <div class="md-code-head">
  word  = displayLangFromClass(code.className)   (3.8)
  word 가 빈 문자열이 아니면 head 에 <span class="md-code-lang">{word}</span>
  head 에 createCodeCopyButton(() => code.textContent ?? '')   ← 지금과 같은 호출
  pre 자리에 wrap 을 끼우고, wrap 에 head → pre 순으로 넣는다
```

- **대상은 지금 복사 버튼이 붙는 범위와 똑같다** — `pre > code` 전부. `renderMarkdown` 이 프론트매터를 못 읽었을 때 내는 `<pre class="markdown-frontmatter-raw"><code>`(renderMarkdown.ts 511행)도 포함되고, 언어가 없으므로 머리줄에는 복사 버튼만 놓인다. 여기 복사 버튼은 지금도 붙고 있다 → 동작 불변
- Mermaid 블록은 `<div class="md-mermaid">`(renderMarkdown.ts 324행)라 `pre > code` 가 아니다 → 영향 없음
- **멱등 가드를 반드시 넣는다.** 지금 effect 에는 cleanup 도 중복 방지도 없다(`Viewer.tsx` 146~154행). `src/main.tsx` 37행이 `<StrictMode>` 로 감싸고 있어 개발 모드에서 effect 가 두 번 돌면 버튼이 두 개 붙는다(운영 빌드는 한 번이라 지금까지 드러나지 않았다). 래퍼가 생기면 더 눈에 띄므로 가드로 함께 막는다
- `codeCopy` 가 거짓이면 지금처럼 **아무것도 하지 않는다** → 앱 보기 모드(`App.tsx` 2430행)·S-4 공유 화면(`SharedView.tsx` 38행)은 DOM 도 모양도 그대로다

#### 머리줄 내용

| 경우 | 머리줄 |
| --- | --- |
| ` ```js ` → `<code class="language-js">` | `JavaScript` + 복사 버튼 |
| ` ``` ` (정보 없음) → `<code>` (클래스 없음) | **복사 버튼만.** 머리줄 높이는 그대로 36px — 언어가 없다고 줄이 사라지지 않는다 |
| 표에 없는 언어 (` ```nim `) | 첫 낱말 그대로 `nim` + 복사 버튼 (`displayLang` 규칙, F-248 3.1) |
| 긴 언어 이름·좁은 창 | 머리줄은 한 줄 고정. 이름이 남은 폭보다 길면 `…` 로 자른다(`text-overflow: ellipsis`). 복사 버튼은 언제나 오른쪽 위 제자리 |

**선택자에 `.markdown-body` 를 끼우는 이유(우선순위 계산).** `pre` 의 바탕·여백을 되돌리는 규칙은 아래 둘을 이겨야 한다

| 이기려는 규칙 | 특이도 |
| --- | --- |
| `markdown.css` 81~86행 `:is(.app-shell, .public-view) .markdown-body pre { background-color: var(--md-bg-muted) }` | (0,2,1) |
| `frontmatter.css` `:is(.app-shell, .public-view) .markdown-body pre.markdown-frontmatter-raw { margin-bottom: 1rem }` | (0,3,1) |

`.viewer--code-copy .markdown-body .md-code > pre` 는 (0,3,1) 이라 첫째는 이기지만 둘째와는 **동점**이라 파일 로드 순서에 달린다. `viewer.css` 는 컴포넌트가 import 하는 파일이라 `main.tsx` 가 넣는 `frontmatter.css` 와의 순서를 보장할 수 없다 → `pre.markdown-frontmatter-raw` 선택자를 (0,4,1) 로 한 줄 더 적어 확실히 이긴다. 같은 이유로 `frontmatter.css` 가 `table.markdown-frontmatter` 로 클래스를 더 붙여 놓았다(그 파일 주석)

#### 2026-09-21 에 넣은 임시 규칙 2개는 지운다

```css
/* 지운다 — viewer.css 22~33행 */
.viewer--code-copy pre { position: relative; overflow: visible; }
.viewer--code-copy pre > code { display: block; overflow-x: auto; }
```

- 그 규칙이 필요했던 이유는 **복사 버튼이 `pre` 안에 있었기 때문**이다. `pre` 가 스크롤 컨테이너면 안에 절대 위치로 놓인 버튼이 코드와 함께 밀려 글자를 덮었다
- 머리줄을 붙이면 버튼이 `pre` 밖(`.md-code-head` 안)으로 나가고, 기준 요소도 `.md-code` 로 바뀐다. **`pre` 가 스크롤해도 버튼은 움직이지 않는다** → 규칙이 필요 없다
- 지우면 `pre` 는 `github-markdown-css` 기본값 `overflow: auto` 로 돌아가고 `code` 는 다시 인라인이 된다. 긴 줄은 `pre` 안에서 가로 스크롤된다 — 되돌린 뒤 이 동작을 A8 에서 확인한다

### 3.8 `displayLangFromClass` (`src/lib/codeLang.ts`)

보기용 렌더 결과에는 편집 모드 같은 정보 문자열(`info`)이 없고 `<code class="language-js">` 클래스만 있다. 그 클래스에서 언어 낱말을 꺼내 `displayLang` 에 넘긴다

```ts
// <code class="language-js"> 같은 클래스에서 언어를 읽어 정식 표기로 (F-293 3.8)
// 클래스가 없거나 language- 로 시작하는 것이 없으면 빈 문자열
export function displayLangFromClass(className: string): string
```

규칙: 공백으로 나눈 토큰 중 `language-` 로 시작하는 **첫 번째**를 골라 접두사를 떼고 `displayLang` 에 넣는다. 없으면 `''`

markdown-it 이 실제로 무엇을 붙이는지 직접 돌려 확인했다 (`markdown-it` 기본 `langPrefix`, `options.highlight` 없음 — renderMarkdown.ts 17·311~312행)

| 원문 | 출력 | `displayLangFromClass` |
| --- | --- | --- |
| ` ```js ` | `<pre><code class="language-js">` | `JavaScript` |
| ` ``` ` | `<pre><code>` (클래스 없음) | `''` |
| ` ```c++ title="x" ` | `<pre><code class="language-c++">` — **첫 낱말만**, `+` 는 이스케이프되지 않는다 | `C++` |
| ` ```Python ` | `<pre><code class="language-Python">` — 대소문자 그대로 | `Python` (`displayLang` 이 소문자로 찾는다) |

- DOM 을 쓰지 않는 순수 함수라 `node` 테스트 환경에서 그대로 단위 테스트한다 (CLAUDE.md "테스트 환경은 `node`")
- `displayLang`·`isMermaidInfo` 는 고치지 않는다

## 8. 사람 확인 필요 (테스트로 판정하지 않음)

1. 공유 화면 머리줄이 앱 상단바와 같은 인상인지 — 아이콘 크기·간격·세로 정렬 (화이트·세피아·다크)
2. **아이콘만 남은 두 버튼이 무엇인지 처음 보는 사람이 짐작할 수 있는지** (3.3 에 적은 잃는 것). 특히 아래 화살표가 "마크다운 파일 받기" 로 읽히는지
3. 툴팁 400ms 지연이 공유 화면에서도 답답하지 않은지
4. 보기용 코드블록 머리줄이 편집 모드 머리줄과 같은 무게로 보이는지 — 언어 이름 크기·색, 머리줄 높이, 코드 위 여백
5. 머리줄을 붙인 뒤 긴 코드 줄이 코드블록 안에서만 가로 스크롤되는지, 스크롤해도 복사 버튼이 제자리인지 (3.7 임시 규칙 삭제 확인)
6. 언어가 없는 코드블록의 머리줄이 비어 보이지 않는지 (복사 버튼만 있는 줄)
7. 좁은 창(400px 안팎) 폴더 보기에서 40px 띠 안의 32px 아이콘 버튼이 답답하지 않은지 (K2·Q4)
8. 폴더 목록 현재 문서 행(C5·C6)이 호버 행과 확실히 구분되는지
9. 터치 기기(툴팁 없음)에서 머리줄 버튼 두 개만으로 쓸 만한지
