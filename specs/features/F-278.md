## 4. `.txt` 평문 변환

### 4.1 왜 토큰 순회인가 (개요 결정의 코드 해석)

개요 1.1 은 "보기 모드 변환 결과(HTML)에서 글을 뽑는다 — 원문을 정규식으로 지우지 않는다" 로 정했다. 코드에서 이를 **`renderMarkdown` 과 같은 markdown-it 인스턴스가 만든 토큰 배열을 순회하는 것**으로 구현한다. 렌더된 HTML 문자열을 `DOMParser` 로 다시 파싱하지 않는다. 근거:

1. **단위 테스트가 안 된다.** `vite.config.ts` 의 `test.environment` 가 `'node'` 이고 `jsdom`·`happy-dom` 이 설치돼 있지 않다. `DOMParser` 를 쓰면 4.3~4.4 규칙을 `*.test.ts` 로 판정할 수 없어 `CLAUDE.md` "로직은 TDD" 를 못 지킨다. 테스트 환경 변경·새 의존성은 이 명세 범위 밖이다
2. **HTML 은 정보를 이미 잃었다.** `renderMarkdown` 의 이미지 렌더러는 `![alt](url)` 을 `<a>이미지: alt</a>` 로 바꾸고(210행), 이미지 블록은 `data-attachment` 만 남기며(160행), 체크박스는 `<input>` 으로 바뀐다. 토큰에는 `info`·`markup`·`attrs` 가 남아 있어 `1.` 의 원래 번호, 자동 링크 여부(`markup === 'linkify'`), Mermaid 여부(`isMermaidInfo(token.info)`)를 그대로 읽을 수 있다
3. `md.parse()` 는 core 규칙(작업목록·콜아웃·이미지블록·위키링크·표 `<br>`)을 모두 거친 뒤의 토큰을 준다. 렌더러만 건너뛰는 것이라 **"보기 모드가 본 것과 같은 해석"** 이라는 개요의 뜻은 그대로 지켜진다

원문 정규식을 쓰지 않는다는 결정도 그대로다 — 코드블록 안 `**`·`%%` 가 살아남는지는 A8·A12 로 판정한다. **예외 한 곳**: 하이라이트(4.4)

### 4.2 `renderMarkdown.ts` 에 더할 것

```ts
// 보기 모드와 같은 해석의 토큰 배열. 렌더러만 거치지 않는다 (F-278 4.1)
export function parseMarkdownTokens(body: string, env?: object): Token[]
```

- 모듈 안 `md` 인스턴스를 그대로 쓴다. 새 인스턴스를 만들지 않는다
- 프론트매터는 **호출하는 쪽**이 떼고 본문만 넘긴다(`renderMarkdown` 이 하는 것과 같은 `findFrontmatter`·`textAfterFrontmatter`)
- `env.resolveWikiLink` 를 넘기지 않으면 위키링크가 `wikilink_span_open`/`text`/`wikilink_span_close` 로 나온다 → 평문은 이 경로를 쓴다
- `imageBlockRule` 이 `html_block` 토큰을 만들 때 `token.meta = parsed`(`ParsedImageBlock`) 를 함께 넣는다. 그러지 않으면 평문 쪽이 자기가 만든 `<img alt="…">` 문자열을 다시 정규식으로 뜯어야 한다. 렌더 결과는 바뀌지 않는다(`meta` 는 출력에 쓰이지 않는다)

### 4.3 입력 처리 순서

```
handle.getText(lineEnding)          // 에디터 현재 원문 (F-112 2.2)
 → stripComments(text)              // 주석 제거 (F-214 2.1)
 → findFrontmatter / textAfterFrontmatter   // 프론트매터 제거 (F-133 3.3)
 → parseMarkdownTokens(body)        // 4.2
 → 블록 순회 → 문단 문자열 배열
 → 배열을 '\n\n' 으로 잇는다
 → lineEnding 이 'crlf' 면 '\n' → '\r\n'
 → 끝에 줄바꿈 1개
```

- 인코딩 UTF-8, **BOM 을 붙이지 않는다**(`F-112` 2.2 와 같다)
- 파일명은 `toFileName(title)` 의 `.md` 를 `.txt` 로 바꾼 것(`exportDoc.ts` 가 zip 에 쓰는 방식과 같다)
- MIME `text/plain;charset=utf-8`
- 결과가 빈 문자열이면 줄바꿈 1개만 있는 파일을 내려받는다(빈 문서도 내보내기가 실패하지 않는다)

| 토큰 | 평문 |
| --- | --- |
| `heading_open`…`heading_close` | 인라인 글자만 한 줄. 앞뒤 빈 줄은 블록 잇기(`\n\n`)로 생긴다 |
| `paragraph_open`…`paragraph_close` | 인라인 글자 |
| `bullet_list` | 항목마다 `- ` + 글자 |
| `ordered_list` | 항목마다 `{list_item_open.info}. ` + 글자. `info` 가 비면 1부터 센다 |
| 중첩 목록 | 깊이 1당 공백 2칸 들여쓰기. 항목 안 둘째 문단도 같은 깊이로 맞춘다 |
| 체크박스 | 목록 표시 뒤에 `[ ] ` / `[x] `. `taskListsRule` 이 넣은 `html_inline`(`<input type="checkbox"` 로 시작) 의 `checked` 유무로 판정한다 |
| `blockquote_open`…`blockquote_close` | 안쪽 블록을 먼저 평문으로 만든 뒤 모든 줄 앞에 `> `. 빈 줄은 `>` 만(뒤에 공백을 남기지 않는다). 중첩이면 `> > ` |
| 콜아웃 | 인용과 같다. `calloutRule` 이 이미 제목을 첫 문단으로 떼어 놓았으므로 **제목이 첫 줄**이 된다. `[!note]`·접기 기호는 토큰에 없다. 제목 앞 아이콘 `html_inline`(`<span class="markdown-callout-icon"…`)은 버린다 |
| `table` | `thead`·`tbody` 의 `tr` 마다 한 줄, 칸은 탭(`\t`)으로 잇는다. 구분 줄(`---`)은 출력하지 않는다. 표 전체가 블록 하나 |

| `fence` 중 `isMermaidInfo(token.info)` | `[다이어그램]` |
| `html_block`(이미지 블록) | `token.meta.alt` 가 있으면 `[이미지: {alt}]`, 비면 `[이미지]` |
| `hr` | `---` 한 줄 (개요 표에 없어 기본값으로 정함 — 6장 M2) |

| 토큰 | 평문 |
| --- | --- |

| `code_inline` | `token.content` |

### 4.6 하이라이트 — 개요와 코드가 어긋나는 곳

개요 1.1 은 하이라이트를 "글자만" 으로 적었지만, **`renderMarkdown` 에는 `==…==` 를 해석하는 규칙이 없다.** `markdown-it-mark` 를 쓰지 않아 보기 모드에서도 `==글자==` 가 글자 그대로 보인다(툴바 `하이라이트` 버튼은 `src/editor/formatCommands.ts` 가 `==` 를 넣는다). 토큰만 보면 평문에 `==` 가 남는다

결정(2026-09-20 사용자): **보기 모드 렌더는 F-283 이 따로 더한다.** F-278 은 그보다 먼저 들어가므로 그때까지 **평문 변환에서만 `==` 를 뗀다.** 적용 대상은 `text` 자식 토큰뿐이라 인라인코드(`code_inline`)·코드블록(`fence`·`code_block`)은 애초에 대상에서 빠진다 — 4.1 이 금지한 "원문 전체 정규식" 이 아니다

- F-283 이 들어오면 `renderMarkdown` 토큰에 하이라이트 토큰이 생겨 이 예외가 필요 없어진다. F-283 이 이 `text` 토큰 처리를 걷어내고 토큰 기반으로 바꾼다 — 그 순서를 F-283 명세에 적는다
- 두 명세 모두 `src/viewer/renderMarkdown.ts` 를 건드리므로 **F-278 을 먼저 커밋한 뒤 F-283 을 진행한다**

- 수식(`$…$`)·각주(`[^1]`)도 markdown-it 이 해석하지 않지만 **개요 1.1 표에 없으므로 손대지 않는다.** 보기 모드와 같이 글자 그대로 남는다
