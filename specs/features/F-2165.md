## 2. 계약 (`paneDrag.ts`)
```ts
export type DropSide = 'left' | 'right' | 'up' | 'down'
export type Box = { left: number; top: number; width: number; height: number }
export const EDGE_BAND = 1 / 3
export function pickDropSide(box: Box, x: number, y: number): DropSide | null
export function dropPreview(box: Box, side: DropSide): Box
export function splitPaneAt(s: SplitState, pane: number, side: DropSide, tab: DocTab): SplitState | null
export function dragSplit(s: SplitState, from: number, key: string, to: number, side: DropSide): SplitState | null
export function moveTabToPane(s: SplitState, from: number, key: string, to: number, index: number): SplitState | null
export type Divider = { index: number; axis: 'x' | 'y'; at: number; from: number; to: number } // 모두 칸 영역 비율
export function dividers(layout: SplitLayout, ratios: readonly number[]): Divider[]
export function setRatio(layout: SplitLayout, ratios: readonly number[], index: number, value: number, size: { width: number; height: number }): number[]
```
- **`pickDropSide`**: 상자 밖(경계 포함 안쪽만)·폭이나 높이 0 → `null`. 네 변까지 거리를 폭·높이로 나눈 값 중 가장 작은 것이 `EDGE_BAND` 미만이면 그 변, 같으면 left→right→up→down 순. 가운데(모두 1/3 이상)는 `null` — 흐름 4 가 옮기기를 탭 줄로만 정했다
- **`dropPreview`** = 상자의 그 변 쪽 절반. three→grid 는 새 경계가 기존 짝 경계(F-2162 3장 표 `[x, y]`)를 따라 반이 아닐 수 있다 — 사람 확인 H1
- **`splitPaneAt`**(네 변 모두): `right`·`down` = `splitPane` 그대로. `left`·`up` = 같은 축 `splitPane` 결과에서 **대상 칸과 새 칸의 `panes` 자리를 맞바꾸고 `focus` 를 새 칸 자리로**. F-2162 3장 나누기 표 10행을 손으로 대조해 맞바꾼 결과가 모두 같은 배치의 올바른 자리 순서임을 확인함(예: single left → cols [n,a], cols 0 up → three-right [b,n,a], three-left 0 up → grid [n,b,a,c]) — U3 가 판정. `ratios` 는 그대로(맞바꿔도 경계 자리가 같다). `splitPane` 이 `null` 이면 `null`
- **`dragSplit`(흐름 2 "끈 탭은 원래 칸에서 빠져 새 칸으로")**: `from` 칸에 `key` 가 없거나, `from === to` 이고 그 칸 탭이 하나뿐이면 `null`. 아니면 `splitPaneAt(s, to, side, 그 탭)` 뒤 옛 `s.panes[from]` 객체의 새 자리에 `setPaneTabs(…, closeTabs(그 칸, [key]))` — 비면 그 칸이 닫히고(흐름 5 "끌어내 닫기") 포커스는 `closePane` 규칙대로 새 칸을 따라간다. 판정은 끌기 전 배치 기준(F-2159 3장 "`null` 이면 자리 표시 안 함"), 탭 합은 그대로라 탭 상한·4칸 알림 없음
- **`moveTabToPane`(흐름 4)**: `from === to`·`from` 에 `key` 없음·`to` 범위 밖 → `null`(같은 칸은 기존 `moveTab`). `to` 칸에 같은 문서 탭이 있으면 그 탭을 고정·활성(자리 그대로), 없으면 `{ ...탭, pinned: true }` 를 `index`(0~길이로 자름)에 넣고 활성. `focus = to` 를 먼저 정한 뒤 `from` 칸에 `setPaneTabs(…, closeTabs(…, [key]))` — 비면 칸이 닫히고 포커스는 대상 칸을 따라간다. 옮긴 탭이 고정이 되는 것은 대상 칸에 임시 탭이 둘 생기지 않게(`openTab` 은 첫 임시 탭만 바꾼다)
- **`dividers`**: single `[]`. index 0 은 늘 칸 영역 전체를 가로지른다(`from` 0, `to` 1) — cols·three-left/right·grid 는 `x`, rows·three-top/bottom 은 `y`. index 1: three-left `y` [x~1], three-right `y` [0~x], three-top `x` [y~1], three-bottom `x` [0~y], grid `y` [0~1]. `at` = 그 자리 `ratios` 값(F-2162 2장 "왼쪽·위에서 잰 비율")
- **`setRatio`** = `ratios[index]` 를 `value` 로 바꾼 뒤 `clampRatios(layout, …, size)`. 최소 280×160 은 `clampRatios` 의 축별 하한·상한으로 충분하다(three 의 작은 둘 사이·grid 의 경계도 칸 영역 전체 축으로 잰다)

## 3. 탭 끌기 배선
- **끌기 상태는 창에 하나**(`useTabDrag`: `{ pane, key } | null`). 탭 `dragstart` 가 쓰고(데이터는 지금처럼 `DRAG_TYPE`), `drop` 처리에서 지우고, 놓지 못하고 끝나면(`Esc`·밖에 놓기) 창 `dragend`(캡처)에서 지운다 — 옮긴 탭 요소는 놓은 뒤 문서에서 빠져 `dragend` 를 못 받을 수 있어서. 다른 창에서 끌어온 `DRAG_TYPE` 은 저장소가 `null` 이라 무시. 탭 `pointerdown` 은 F-2163 대로 그 칸을 포커스로 만들어 새 칸 `viewMode` 는 끈 칸 값이다
- **탭 줄**(`DocTabBar`, 1칸의 창 위 탭 줄은 `pane` 0): 끄는 탭이 같은 칸이면 지금 `before`/`after` → `onMove` 그대로. 다른 칸이면 같은 표시로 자리를 고르고 `onMoveIn(from, key, 자리)`. 탭이 아닌 탭 줄 빈 자리(`＋` 포함)에 놓으면 끝 자리
- **칸 영역**: `SplitPanes` 가 칸마다 탭 줄을 뺀 본문 요소(1칸이면 `DocumentArea` 뿌리, 새 감싸개 없음)에 `data-pane-zone="{칸 번호}"` 를 달고 `dragenter`·`dragover`·`dragleave`·`drop` 을 **네이티브 캡처**로 듣는다. 끌기 상태가 있을 때만 `stopPropagation` — CM6 `dropCursor`·`handlers.drop` 과 F-145 창 처리에 닿지 않는다. 상태가 없으면(파일·글 끌기) 손대지 않는다
- 자리 = `pickDropSide(그 요소 사각형, 포인터)` 이고 `dragSplit` 이 `null` 이 아닐 때만 `preventDefault`(놓기 허용)·미리보기. 미리보기는 `document.body` 포털의 `.split-drop-preview[data-side]`(`position: fixed`, `pointer-events: none`, 좌표 `dropPreview`). 영역을 벗어나거나 끌기가 끝나면 지운다. 숨은 칸(F-2163 `hidden`)은 사각형이 0 이라 자리 없음
- 놓기: `useDocTabs.dragSplit(from, key, to, side)`·`onMoveIn` 은 F-2163 5장 닫기·나누기와 같은 길 — 어느 칸에서도 활성이 아니게 되는 문서가 있으면 `beforeLeaveDoc()` 를 기다린 뒤 상태를 바꾸고, `focusEditorRef.current = true`, 포커스 칸 활성이 `currentDocId` 와 다르면 `selectDoc`. 옮긴 탭 편집기는 대상 칸에서 다시 만든다(실행 취소는 칸마다, F-2159 2장). 저장은 `storeSplit`
- 키보드 대안: 나누기는 F-2163 메뉴·팔레트·`Alt+Shift+D`. 칸 사이 탭 옮기기는 키보드 대안이 없다(흐름 7 결정 7 이 끌기만 정함)

## 4. 경계 끌기 (흐름 0)
- `SplitDividers` 는 2칸 이상이 보일 때만 `.split-panes` 안에 `dividers()` 마다 `.split-divider[data-ratio-index][role="separator"][aria-orientation][aria-valuenow][tabindex="0"]`(`aria-label` `칸 경계`, `aria-valuenow` = 백분율 정수, `x` 축 = `vertical`). 위치는 `at`·`from`·`to` 를 % 로
- `pointerdown`(주 버튼) → `setPointerCapture`, `pointermove` 마다 값 = (포인터 − 영역 왼쪽·위) ÷ 영역 폭·높이로 `setRatio(…, 영역 크기)` → `SplitPanes` 임시 비율로 그리기, `pointerup`·`pointercancel` 에 한 번 `useDocTabs.setRatios` → `storeSplit`(끄는 동안 저장소를 매 프레임 쓰지 않으려고). 저장 값 = 그 크기로 자른 값
- 키보드: 포커스된 막대에서 `x` 축 `←`/`→`, `y` 축 `↑`/`↓` 로 0.05 씩, 누를 때마다 저장. `isComposing` 무시
