## 3. 계약

### 3.1 한 목록 — `src/app/contextMenuItems.ts`

```ts
export type EditorCommandGroup = 'link' | 'format' | 'paragraph' | 'insert'
// 이 명령을 비활성으로 만드는 조건 — 'none' 은 늘 활성
export type EditorCommandGate = 'none' | 'clear' | 'paragraph' | 'insert'

export type EditorCommandSpec = {
  id: string                    // 메뉴 항목 id 그대로(5장 표). 팔레트 id 는 'editor.' + id
  group: EditorCommandGroup
  label: string                 // 메뉴 글자 그대로
  shortcut?: string             // 'Ctrl+B' 등 — 표시만
  run: StateCommand
  gate: EditorCommandGate
  keywords: readonly string[]   // 팔레트 거르기용. 메뉴는 쓰지 않는다
}
export const EDITOR_COMMANDS: readonly EditorCommandSpec[]   // 5장 표 순서 = 메뉴 순서

// true = 비활성. 계산 규칙은 지금 buildEditorContextMenu 의 그것 그대로
export type EditorCommandGates = { clear: boolean; paragraph: boolean; insert: boolean }
export function editorCommandGates(state: EditorState, place: EditorMenuPlace): EditorCommandGates
```

- `editorCommandGates` 규칙은 **지금 코드와 같다**: `paragraph` = 칸이거나 `paragraphGroupDisabled(state)`, `insert` = 칸이거나 `insertGroupDisabled(state)`, `clear` = 칸. 옮기기만 하고 규칙을 바꾸지 않는다
- `buildEditorContextMenu` 는 `EDITOR_COMMANDS` 를 묶음별로 나눠 지금과 같은 트리를 만든다: `link` 둘은 맨 위 낱개 항목, `format`·`paragraph`·`insert` 는 각 2차 메뉴(`서식`·`단락`·`삽입`). 2차 메뉴 `단락`·`삽입` 자체의 `disabled` 도 지금처럼 `gates.paragraph`·`gates.insert`. 클립보드·댓글·팔레트 항목은 이 목록 밖에 그대로 둔다
- `setHeading(level)` 은 목록을 만들 때 **한 번** 불러 둔다(지금은 메뉴를 열 때마다 새 함수). 그래야 팔레트 명령과 메뉴 항목의 `run` 이 같은 함수다(U1). `runContextMenuCommand` 의 `cmd === insertTable` 비교는 그대로 맞는다 — `insertTable` 은 원래 모듈 상수다
- **메뉴 id 는 이제 계약이다.** 팔레트 id(`editor.bold`)가 F-2053 최근·고정 목록에 저장되므로(F-2053 3.4 "한 번 배포한 id 는 바꾸지 않는다") 메뉴 id 를 바꾸면 사용자의 고정이 조용히 빠진다. `contextMenuItems.ts` 에 이 뜻의 주석 한 줄

### 3.3 팔레트 명령 — `src/app/paletteEditorCommands.ts`

```ts
export const EDITOR_PALETTE_GROUP_LABEL: Record<EditorCommandGroup, string>   // link·insert → '삽입', format → '서식', paragraph → '단락'
export const EDITOR_PALETTE_COMMANDS: readonly PaletteActionCommand[]
```

`EDITOR_COMMANDS` 한 줄 → 팔레트 명령 한 개. 규칙:

| 필드 | 값 |
| --- | --- |
| `id` | `'editor.' + spec.id` (예: `editor.bold`, `editor.heading2`, `editor.codeblock`) — `PALETTE_ID_RE` 통과(U3) |
| `kind` | `'action'` |
| `label` | `` `${EDITOR_PALETTE_GROUP_LABEL[spec.group]}: ${spec.label}` `` (예: `서식: 볼드체`, `단락: 제목 2`, `삽입: 링크 추가`) — 5.1 |
| `shortcut` | `spec.shortcut` 그대로 (`Ctrl+B`·`Ctrl+I`·`Ctrl+K` 셋만) |
| `keywords` | `spec.keywords` 그대로 |
| `when` | `ctx.editor` 가 있고, `spec.gate === 'none'` 이거나 `ctx.editor.disabled[spec.gate]` 가 거짓 |
| `run` | `ctx.editor?.run(spec.run)` |

- 메뉴는 비활성 항목을 흐리게 두지만 팔레트는 **없앤다**(F-2022 3.2 "`when` 거짓이면 목록에 없다"). 코드 블록 안에서 연 팔레트에는 단락 11개·삽입 6개가 없고, 링크 둘·서식 8개만 남는다
- `paletteCommands.ts` 의 `PALETTE_COMMANDS` 에서 **마지막 원소**로 스프레드한다 — 앱 명령(F-2022·F-2052·F-2054)이 먼저다. 이유: F-2053 빈 입력 `명령` 구역과 같은 단계 안 순서가 "넘겨받은 순서" 라, 뒤에 둬야 기존 e2e 의 "`>` → `Enter` = 첫 명령 `템플릿 삽입`" 이 그대로다(9장)
- `id` 영역 `editor.` 는 이 명세가 쓴다. F-2054 는 `editor.` 로 시작하는 id 를 쓰지 않는다(12장 갱신 대상 — F-2054 에 한 줄)

## 4. 동작

### 4.1 보이는 조건 — 팔레트를 **어디서 열었나**

App 이 팔레트를 열 때 "본문에서 열었나" 를 한 번 정해 두고, 닫힐 때 버린다

| 여는 길 | 판정 | 서식 명령 |
| --- | --- | --- |
| 주 에디터에 포커스가 있을 때 `Ctrl+P` | 여는 순간 `document.activeElement === 주 에디터 view.contentDOM` | 보임 |
| 주 에디터 우클릭 → `명령 팔레트…` (`place: 'editor'`) | 우클릭 갈래가 "본문" 을 명시해 넘긴다 | 보임 |
| 표 칸 하위 에디터에서 `Ctrl+P` | 칸의 `.cm-content` 는 주 `contentDOM` 이 아니다(칸 하위 에디터는 주 `contentDOM` **안에 든 다른 요소**다) | 없음 |
| 표 칸 우클릭 → `명령 팔레트…` (`place: 'cell'`) | 우클릭 갈래가 "본문 아님" 을 명시해 넘긴다 — 이 갈래는 팔레트를 열기 **전에** 주 에디터에 포커스를 주므로(`handleContextMenuSelect`, F-2022 7.3) `activeElement` 로 판정하면 틀린다 | 없음 |
| 제목 입력·사이드바·찾기 패널 입력·댓글 입력·F-2053 팔레트 버튼 | `activeElement` 가 주 `contentDOM` 이 아님 | 없음 |

- 그리고 **`canInsertTemplate` 와 같은 조건**(F-2022 6.3 — 부팅 끝, 공유 링크 화면 아님, 지금 문서의 에디터가 떠 있음, 보기 모드가 `편집`·`원문`, 읽기 전용 아님, 지도·도움말·공유 관리가 덮지 않음)이 참일 때만 `editor` 를 채운다. 보기 모드에서는 포커스가 `contentDOM` 에 있을 수 없어 위 판정으로도 걸러진다
- `disabled` 는 여는 순간 `editorCommandGates(주 view.state, 'editor')` 한 번. 팔레트가 열린 동안 원격 편집으로 줄 모양이 바뀌어도 다시 계산하지 않는다 — 명령 함수가 실행 때 건너뛰는 줄을 스스로 판정해 `false` 를 돌려주므로(F-168·F-169 규칙) 문서가 틀리게 바뀌지는 않는다(4.3-2)
- 구현 모양: `openPalette` 가 선택 인자 하나(본문에서 열었나)를 받고, **인자가 없으면 `activeElement` 로 판정**한다. `Ctrl+P` effect 와 F-2053 버튼은 인자 없이 부르던 그대로 두고, 우클릭 `open-palette` 갈래만 `cm.place === 'editor'` 를 넘긴다

**표 칸에서 숨기는 이유 (사용자 결정 4 의 결론)**
1. **칸 안에 적용할 선택이 남아 있지 않다.** 팔레트 입력칸이 포커스를 가져가면 칸 하위 에디터의 `blur` → 다음 틱 `endEdit` 로 칸 편집이 끝나고 하위 `EditorView` 가 사라진다(`tableWidget.ts` `startEdit` 의 `blur` 처리, F-125). 되살릴 칸 선택이 없다
2. **주 에디터에 적용하면 표를 깨뜨린다.** 칸 우클릭 갈래는 팔레트를 열기 전에 주 에디터 선택을 표 위젯 첫머리(`posAtDOM(표 wrap)`)로 옮긴다(템플릿을 표 뒤에 넣으려고, F-2022 7.1). 거기서 `볼드체` 를 실행하면 빈 선택이라 `****` 가 표 첫 줄 앞에 들어가 `****| a | b |` 가 된다(`toggleStrong` — 빈 선택이면 그 자리에 `****`). 단락·삽입은 표 줄이 건너뛰는 줄이라 어차피 비활성이다(`SKIP_NODE` 에 `Table`)
3. 템플릿과 다른 이유: 템플릿은 **줄 단위로 표 뒤에** 넣는 규칙(F-2022 5.3)이 있어 표를 건드리지 않는다. 서식은 선택 자리에 기호를 끼우는 명령이라 "표 뒤" 라는 자리가 없다
- 칸 안 서식은 칸에서 `Ctrl+B`·`Ctrl+I`·`Ctrl+K`(`cellKeydown`)와 칸 우클릭 메뉴 `서식 ▸` 로 된다 — 잃는 길이 없다

### 4.2 선택 영역을 되살리는 방법 — **따로 저장하지 않는다**

- 주 에디터의 선택은 `EditorState.selection` 에 있고 **포커스를 잃어도 그대로다.** `@codemirror/view` 의 `blur` 처리는 DOM 선택 기록만 지우고(`observer.clearSelectionRange()`) 포커스 효과 트랜잭션만 보낸다 — 선택을 바꾸는 트랜잭션이 없다
- 팔레트가 열린 동안 **원격 갱신**(F-305 실시간 연결)이 들어오면 `y-codemirror.next` 가 `view.dispatch({ changes, annotations })` 로 넣는다 — 선택을 주지 않으므로 CM6 가 기존 선택을 그 변경에 맞춰 옮긴다(`Transaction.newSelection` = `startState.selection.map(changes)`). 선택 앞에 글이 들어오면 선택이 뒤로 밀려 **같은 글자**를 가리킨다. 선택한 글이 원격으로 지워지면 선택은 그 자리의 빈 커서가 된다 — 그때 `볼드체` 는 빈 커서 규칙(`****`)으로 동작한다. 알려진 모양으로 둔다
- 팔레트가 열린 동안에는 에디터가 조합 중일 수 없으므로(4.4) 원격 갱신을 미루는 IME 게이트(F-303)도 걸리지 않고, 위 매핑이 바로 일어난다
- 그래서 "여는 순간 선택을 따로 적어 두었다가 되돌리기" 는 **하지 않는다.** 적어 둔 위치는 원격 갱신에 맞춰 옮겨지지 않아 틀린 자리에 적용되고, 선택의 원본이 둘이 된다(불변조건 "원본은 하나" 의 취지와 같다)
- 원문·편집 모드 차이: 없다. 두 모드 모두 같은 `EditorState` 에 같은 `StateCommand` 를 쓴다. 차이는 편집 모드 `표` 뿐(4.3-4)
- macOS 에서 `Ctrl+P`(`ctrlKey`)는 CM6 `cursorLineUp` 과 겹쳐 커서가 한 줄 올라간 뒤 팔레트가 뜬다(F-2022 6.1). 그 경우 명령은 **올라간 커서**에 적용된다. `Cmd+P` 는 겹치지 않는다 — 사람 확인 H3

### 4.3 실행 — App 의 `editor.run(command)`

`CommandPalette` 의 `action` 수명(F-2022 3.2)대로 팔레트가 먼저 닫히고(`onClose`) 곧바로 `run` 이 불린다. App 은 이 순서로 한다

1. **그만둘 때(조용히, 알림 없음):** 주 에디터 view 가 없음 / 지금 문서가 팔레트를 연 때의 문서와 다름(`currentDocIdRef`) / `readOnlyDocRef` 가 참(열린 동안 다른 탭이 편집권을 가져간 경우 등, F-296) / `isComposing(view)` 참(4.4 — 일어나지 않아야 하는 방어). **읽기 전용 확인을 빼면 안 된다** — CM6 `EditorState.readOnly` 는 사용자 입력만 막고 코드의 `dispatch` 는 막지 않는다(`createEditor.ts` `readOnlyExtensionsFor`)
2. **글 바꾸기는 바로(같은 작업 안).** `command(view)` — 4.2 의 선택에 적용된다. 명령 한 번 = `dispatch` 한 번 = 되돌리기 한 단계(`commands.ts` 머리 주석). `false`(건너뛰는 줄 등)면 글은 그대로
3. **포커스·커서 되돌리기는 다음 화면 갱신 뒤(`requestAnimationFrame`)**: 주 에디터에 `view.focus()` 하고 선택 머리가 보이게 스크롤한다(`refocusContextMenuTarget` 과 같은 두 동작). `view.focus()` 는 상태의 선택을 DOM 에 다시 그린다(`EditorView.focus()` → `docView.updateSelection()`) — 이것이 사용자가 보는 "되살린 선택" 이다
4. **편집 모드에서 `표` 가 성공했으면** 3 대신 `enterTableAtCursor()` — 우클릭(`runContextMenuCommand`, F-170 A6)과 같이 새 표 머리 첫 칸 편집으로 들어간다. 원문 모드면 3 그대로
- **왜 3·4 를 `rAF` 로 미루나:** `Dialog` 는 `close` 이벤트에서 연 순간의 요소(여기서는 주 `contentDOM`)로 `.focus()` 한다. 확인 (a) 에서 `close` 는 다음 화면 갱신 때 오고 `rAF` 보다 늘 먼저였지만, `setTimeout(0)` 은 4/150 번 `close` 보다 먼저 돌았다. 3 은 순서가 바뀌어도 결과가 같다(둘 다 주 에디터). **4 는 다르다** — 칸 편집에 들어간 뒤 `Dialog` 복귀가 주 `contentDOM` 을 포커스하면 칸 하위 에디터가 `blur` 로 끝난다. 그래서 둘 다 `rAF` 로 통일한다
- `rAF` 안에서 다시 확인: 그사이 문서가 바뀌었거나(1 과 같은 값) view 가 없어졌으면 아무것도 안 한다
- `Dialog.tsx` 는 고치지 않는다. 열린 동안 `Esc`·바깥 클릭으로 그냥 닫을 때는 지금 동작 그대로 — `Dialog` 복귀(주 `contentDOM`)와 CM6 의 "포커스 직후 요소 첫머리로 간 DOM 선택을 상태 선택으로 되돌리는" 처리(`DOMObserver.readSelectionRange`)로 선택이 보인다. 우클릭에서 연 경우는 F-2022 7.3 그대로

### 4.4 IME 불변조건과의 관계
- **F-2022 5.7 의 논리가 그대로 맞는다.** 서식 명령은 팔레트 입력칸에서 `Enter`·클릭으로 고를 때만 실행되고, 그 순간 포커스는 입력칸에 있다. 에디터는 조합 중일 수 없다 → 조합 중 재계산 미룸·따라잡기(불변조건)나 원격 갱신 대기열(F-303)과 닿지 않는다. 팔레트 입력칸 자체의 조합 중 `Enter` 는 F-2022 8.4·F-2053 8.4 가 이미 무시한다
- **조합 중 우클릭 → 팔레트 길은 없다.** `createEditor.ts` `editorContextMenuHandler` 와 `tableWidget.ts` `cellContextMenu` 가 조합 중이면 앱 메뉴를 열지 않는다(F-170 2장)
- **조합 중 `Ctrl+P` 길은 있다.** App 의 `Ctrl+P` effect 는 `isComposing` 을 보지 않는다(F-2022 6.1 — 이 명세도 바꾸지 않는다). 팔레트가 뜨며 입력칸이 포커스를 가져가면 브라우저가 조합을 확정하고 CM6 가 `compositionend` 처리 → 미뤄 둔 재계산을 따라잡는다(기존 `composition.ts` 경로). 포커스를 잃은 조합은 끝난 것으로 본다(F-303 5.4). 그래서 명령을 고를 때쯤에는 조합이 끝나 있다. 4.3-1 의 `isComposing` 확인은 이 가정이 깨졌을 때 글을 망가뜨리지 않으려는 방어다. 실제 한글 IME 로는 사람 확인 H1

### 5.1 라벨 모양 — 묶음 접두어 `{묶음}: {메뉴 글자}`
- 팔레트는 평평한 목록이라 `제목 1`·`본문`·`표`·`코드` 가 문맥 없이 보인다. `본문` 은 "본문으로 바꾸기" 인지 알 수 없고, `제목 1` 은 F-2053 문서 구역의 문서 제목과 헷갈린다. 접두어가 그 문맥을 준다(옵시디언 명령 팔레트가 `편집기: …` 처럼 영역 이름을 앞에 붙이는 것과 같은 방식 — 기억에 기댄 것, 14.2)
- **오른쪽 흐린 글(`detail`)로 묶음을 보이는 방법은 못 쓴다** — 명령 줄의 오른쪽은 `shortcut` 자리이고(F-2022 `toRows`, F-2053 8.2), 이것을 바꾸려면 `CommandPalette.tsx` 를 고쳐야 한다(F-2053 3.4 가 막는다)
- 링크 둘은 메뉴에서 맨 위 낱개지만 사용자 결정 1 이 삽입 묶음으로 적었으므로 `삽입:`
- F-2053 거르기와의 관계: 라벨이 `서식:` 으로 시작하므로 `볼드` 를 치면 볼드체는 "라벨 머리 일치(①)" 가 아니라 "라벨 안(②)" 단계다. 같은 검색어에 ① 로 맞는 앱 명령이 있으면 그것이 먼저다 — 칠 말이 앱 명령 이름으로 시작하면 앱 명령이 먼저 나오는 것은 해가 없다. `서식`·`단락`·`삽입` 을 치면 그 묶음이 다 나온다(①). 초성: F-2053 느슨한 비교는 공백을 뗀 글자열(`서식:볼드체`)의 **어느 자리에서든** 맞추므로 `ㅂㄷㅊ` 이 볼드체에, `ㅈㅁ 2` 가 제목 2 에 맞는다(확인 (b)). `:` 은 조각 나누기(공백)에 영향이 없다 — 명령 쪽은 공백으로만 쪼갠다(F-2053 4.1)
- 사람 결정 권장 — 13장 Q1

## 6. 상태·빈 상태·오류
- 보일 서식 명령이 0개인 경우(코드 블록 안 + 링크·서식만 남음은 0개가 아니다) 따로 문구가 없다 — F-2053 5.4 상태 문구가 그대로 덮는다
- 실행 실패(명령이 `false`)는 알림 없이 포커스만 돌린다 — 우클릭 메뉴와 같다(메뉴는 비활성으로 막지만 팔레트는 4.1 스냅샷 뒤 바뀐 경우뿐이다)
- 새 UI 문구 없음 — 라벨 27개(5장)만 새 글이다

## 7. 접근성
- 옵션 접근 이름 = 라벨 + 단축키(F-2022 그대로). 스크린 리더가 `서식: 볼드체 Ctrl+B` 로 읽는다 — 접두어가 그대로 문맥 역할을 한다
- 실행 뒤 포커스는 늘 주 에디터(또는 편집 모드 `표` 면 새 표 첫 칸). 포커스가 사라진 요소나 `body` 로 가지 않는다(4.3)

## 8. 성능
- 명령이 27개 는다. F-2053 확인 (a) 에서 문서 5,000개 거르기가 키 입력당 2.3 ms 이하였고 명령 쪽 거르기는 수십 개라 따로 재지 않았다. 빈 입력 `명령` 구역(F-2053 Q1)에 최대 27 + 앱 명령 수만큼 줄이 그려진다 — 목록 최대 높이 안에서 스크롤(F-2022 8.1). 렌더 비용은 재지 않았다(14.2)
- `editorCommandGates` 는 팔레트를 열 때 한 번. 지금 우클릭 메뉴를 열 때마다 하는 계산과 같다

- **확인 (a) 의 순서가 앱에서도 같다** — 순수 페이지에서 `close()` 를 직접 불러 쟀다. 앱에서는 React 가 `Enter` `keydown`(이산 입력)의 effect 를 같은 작업 안에서 비운다고 보고(React 18 이후 "이산 입력의 effect 는 동기로 비운다") 같은 모양이라 판단했다. React 안에서 재지 않았다. A3 이 앱에서 판정한다

### 14.3 기존 명세·코드와 부딪힌 것
