# F-4011 /mcp 관문과 연결된 앱 API

작성일: 2026-10-16
상태: 승인 2026-10-16(사용자 "ㄱㄱ" — F-4008 결정·흐름 그림·새 의존 승인과 함께). F-4008 6장의 F-4011: `/mcp` 토큰 관문, 보호 자원 메타데이터, `/api/connected-apps` 둘, OpenAI 도메인 확인. 도구·`/mcp` 분기는 F-3030, 화면은 F-2148. 구현 `feature-implementer`, 전부 node 단위(`testD1`), e2e 없음(끊기 e2e 는 F-2148)

## 근거 (2026-10-16 HEAD·`npm pack @better-auth/oauth-provider@1.7.10`, 이름으로 찾는다)
- 플러그인 `validateOpaqueAccessToken`: 저장값 `token` = `defaultHasher` = SHA-256 → base64url(패딩 없음)(`storeTokens: 'hashed'`). `revoked`·`expiresAt` 은 date, `scopes`·`resources` 는 `string[]`. 세션이 지워지면 `sessionId` 는 `set null`(스키마 `onDelete`)
- 플러그인의 자원 쪽 검증(`oauthProviderResourceClient().verifyBearerToken`)은 JWT(`jwksUrl`)나 원격 introspect(기밀 클라이언트 필요)뿐 — 같은 worker 의 불투명 토큰을 보려면 HTTP 로 자기 자신을 불러야 한다. 그래서 `getTokenUser`(`worker/apiTokens.ts`)처럼 D1 을 직접 본다
- better-auth 날짜 열은 ISO 문자열이다(`cleanupExpiredAuth` 가 `toISOString()` 으로 비교). `isAllowedOrigin`(`worker/origin.ts`)은 `SITE_URL` 출처와 로컬 모드의 localhost 를 받는다. `handleRequest` 는 `/api/`·`/pub/`·`/v1/` 밖을 `ASSETS` 로 넘기고 `run_worker_first` 에 `/.well-known/*`·`/mcp` 가 없다
- OpenAI 도메인 확인은 출처 루트 `/.well-known/openai-apps-challenge` 의 평문 토큰([커뮤니티 확인](https://community.openai.com/t/chatgpt-app-submissions-domain-verification-step-does-not-support-subpath-hosted-mcp-servers/1379021): 하위 경로 불가)

## 2. `/mcp` 관문 (계약, F-3030 이 `handleMcp` 맨 앞에서 부른다)
```ts
export type McpCaller = { user: AuthUser; clientId: string; clientName: string }
export function authenticateMcp(request: Request, env: Env, ctx: ExecutionContext): Promise<McpCaller | Response>
```
순서 — 앞에서 걸리면 D1 을 읽지 않는다:
1. `Origin` 머리가 있고 `isAllowedOrigin` 이 거짓 → 403 `{ error: 'forbidden_origin' }`(DNS 재바인딩). Origin 없음(서버 간 호출)은 통과
2. `Authorization: Bearer {토큰}` 이 없으면 401 `{ error: 'unauthenticated' }` + 도전(아래, `error` 없이). 쿠키·`DEV_AUTH_EMAIL` 우회는 보지 않는다(`/v1` 과 같음)
3. 해시로 한 번 SELECT: `oauth_access_tokens` ⋈ `oauth_clients` ⋈ `users` ⟕ `oauth_client_use`(표·열은 F-4009 — 날짜 ISO TEXT, 배열 JSON TEXT, `last_used_at` 은 ms). 조건: `token` 일치, `revoked IS NULL`, `expires_at > {지금 ISO}`, `disabled` 가 참 아님. 없으면 401 + `error="invalid_token"` 도전. `rd_` 토큰도 여기서 없음 → 401(F-4008 A10)
4. `resources` 에 `mcpResource(env)` 가 없으면 401 `invalid_token`. `scopes` 에 `docs` 가 없으면 403 `{ error: 'insufficient_scope' }` + `error="insufficient_scope"` 도전(RFC 6750 3.1). `offline_access` 는 요구하지 않는다
5. **`session_id` 는 보지 않는다.** 로그아웃 때 플러그인 `session.delete` 훅이 그 세션의 접근 토큰을 `revoked` 로 찍어 401 이 나지만, 갱신 토큰은 세션에 묶이지 않아(F-4009) 클라이언트가 갱신으로 이어 간다. 완전히 끊는 것은 `연결 끊기`·계정 삭제·갱신 만료뿐
6. 마지막 사용: 행이 없거나 `last_used_at` 이 10분(`apiTokens.ts` `LAST_USED_UPDATE_INTERVAL_MS` 와 같은 값) 넘게 지났으면 `INSERT … ON CONFLICT(user_id, client_id) DO UPDATE SET last_used_at` 을 `ctx.waitUntil` 로
7. 성공: `user` 는 `getTokenUser` 와 같은 모양(`id`·`email`·`usage`, `sessionId` 없음), `clientName` = F-4010 `clientLabel({ name, redirectUris }).name`. 막힌 계정도 통과 — 막힘은 쓰기 관문이 본다(`/v1` 과 같음). `rememberUser` 는 F-3030 이 안쪽 요청에 한다

도전 머리(값은 이 글자 그대로, 매개변수 순서 고정). `scope` 에 `offline_access` 를 같이 넣는다 — 빠지면 클라이언트가 `docs` 만 요청해 갱신 토큰이 나오지 않고 1시간마다 다시 동의하게 된다(F-4009 확인, F-4008 2장의 `scope="docs"` 를 고침):
```
WWW-Authenticate: Bearer resource_metadata="{origin}/.well-known/oauth-protected-resource/mcp", scope="docs offline_access"
WWW-Authenticate: Bearer error="invalid_token", resource_metadata="…", scope="docs offline_access"
WWW-Authenticate: Bearer error="insufficient_scope", resource_metadata="…", scope="docs offline_access"
```
`{origin}`·자원·발급자는 F-4009 `worker/oauthServer.ts` 의 `mcpResource(env)`(= `new URL('/mcp', BETTER_AUTH_URL).href`)·`oauthIssuer(env)` — 플러그인 설정과 글자가 같아야 해서 정의는 한 곳

## 3. 공개 경로 (`ASSETS` 앞, `GET`·`HEAD` 만, 그 밖 405 `{ error: 'method_not_allowed' }`)
| 경로 | 응답 |
| --- | --- |
| `/.well-known/oauth-protected-resource`, `…/mcp` | 같은 JSON(아래). `Cache-Control: public, max-age=3600`, `Access-Control-Allow-Origin: *`(공개 정보, 브라우저 MCP 검사기용) |
| `/.well-known/openai-apps-challenge` | 비밀이 비지 않았으면 200 `text/plain; charset=utf-8` 몸통 = 값 그대로(앞뒤 공백 자름), `Cache-Control: no-store`. 없으면 404 `{ error: 'not_found' }` |

JSON: `{ resource: mcpResource(env), authorization_servers: [oauthIssuer(env)], scopes_supported: ['docs', 'offline_access'], bearer_methods_supported: ['header'], resource_name: brand.name }`(이름은 `brand.config.ts` 에서)

## 4. 연결된 앱 API (일반 `/api/` 라우트 — 기존 Origin 검사 그대로)
| 메서드·경로 | 성공 | 실패 |
| --- | --- | --- |
| `GET /api/connected-apps` | 200 `[{ id, name, host, createdAt, lastUsedAt }]`, `Cache-Control: no-store` | 401 |
| `DELETE /api/connected-apps/:id` | 204 | 401, 404 `not_found`(그 사용자의 동의 행 없음) |
- 목록: 그 사용자의 `oauth_consents` ⋈ `oauth_clients` ⟕ `oauth_client_use`. `id` = client id, `name`·`host` = `clientLabel({ name, redirectUris })`(둘째 인자 없이), `createdAt` = 동의 만든 시각 ms, `lastUsedAt` = ms 또는 `null`. `createdAt` 내림차순
- 끊기: 한 `batch` 에 `oauth_access_tokens` → `oauth_refresh_tokens` → `oauth_consents` 순(접근 토큰이 갱신 토큰을 참조), 모두 `user_id`·`client_id` 조건. 클라이언트 행과 `oauth_client_use` 행은 남긴다 — F-4009 Cron 은 동의도 사용 기록도 없는 클라이언트만 지우므로, 끊었다 다시 붙는 앱의 client id 가 산다. 쓰기 관문 밖 — 막힌 계정도 끊는다(F-3013 3.4 선례), `dayUsageStatement` 없음
