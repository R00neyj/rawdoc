## 2. 요구사항

### 2.1 D1
```sql
CREATE TABLE doc_locks (
  doc_id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  email TEXT NOT NULL,
  session_id TEXT NOT NULL,
  expires_at INTEGER NOT NULL
);
```

### 2.2 Worker
- 세션 id: 창(탭)마다 클라이언트가 `crypto.randomUUID()` 로 만든다. 같은 사람의 다른 창도 다른 세션이다. 탭 복제로 `sessionStorage` 가 복사되면 두 탭의 세션 id 가 같아진다 — F-297 이 부팅 때 겹침을 감지해 뒤에 뜼 탭에 새 id 를 준다. 클라이언트가 이 id 를 얻는 곳은 `src/storage/lockSession.ts` 의 `getLockSessionId()` 다
| 요청 | 동작 |
| --- | --- |
| `POST /api/docs/:id/lock` `{sessionId}` | edit 이상 권한 필요. 잠금이 없거나 만료됐거나 같은 세션이면 잡고/연장(`expires_at = 지금 + 60초`) → `200 {"expiresAt"}`. 다른 세션이 유효하게 잡고 있으면 `423 {"error":"locked","email","expiresAt"}` |
| `DELETE /api/docs/:id/lock?session={id}` | 같은 세션일 때만 삭제 → 204 (아니면 204, 아무것도 안 함) |
- 잡기는 한 문장 조건부 쓰기: `INSERT ... ON CONFLICT(doc_id) DO UPDATE ... WHERE doc_locks.expires_at < ? OR doc_locks.session_id = ?` 후 변경 행 수로 판정
- `PUT /api/docs/:id` 는 요청 헤더 `X-Lock-Session` 이 유효 잠금 세션과 같거나 **유효 잠금이 없을 때만** 반영. 다른 세션이 유효하게 잡고 있으면 `423` (F-206 버전 검사보다 먼저)
- 이동·고정·삭제·초대는 잠금과 무관

### 2.3 앱 (`useDocLock`)
- **F-305 이후: 경로가 `pending` 또는 `fallback` 일 때만 잡는다**(F-305 4.1·10.1) — 실시간 경로(`realtime`, 첫 동기화 전후 모두)는 Yjs 만 쓰고 이 잠금을 잡지 않는다. `App` 이 `useDocLock` 에 넘기는 `docId` 를 그 조건일 때만 채우고, 그 밖이면 `null`
- **F-306 갱신(2026-09-24)**: `md-yjs` 기록이 있는 문서는 연결에 실패해도 폴백하지 않는다 — 재개 가능한 `realtime` 으로 로컬 기록을 이어 편집하며 재연결을 기다리므로 이 잠금을 잡지 않는다(F-306 6.2). 폴백은 기록이 없어 처음부터 `pending`/`fallback` 인 경로에만 남는다
- 서버 문서(`store.kind === 'server'`)를 열고 역할이 `owner`·`edit` 이고 온라인일 때만
- 열 때 `POST lock` → 성공: 편집 가능, **20초마다 연장**. 423: 읽기 전용(F-212 `readOnly`) + 알림 띠(info) `{이메일} 님이 편집 중입니다. 읽기만 할 수 있습니다.` (자기 다른 창이면 `다른 창에서 편집 중입니다. 읽기만 할 수 있습니다.`)
- 읽기 전용 동안 15초마다 다시 잡기 시도. 잡히면 **서버에서 최신 문서를 받아 에디터를 다시 마운트**(불변조건: 열린 에디터에 밀어 넣지 않음) + 알림 `이제 편집할 수 있습니다.`
- 문서를 떠날 때·`pagehide`: 저장 flush 뒤 `DELETE lock` (`fetch(..., { keepalive: true })`). 못 보내도 60초 뒤 만료
- 연장이 423 을 받으면(잠금을 뺏김 — 네트워크가 60초 넘게 끊겼던 경우) 대기 저장은 F-207 보내기가 423 처리(2.4), 에디터는 위 읽기 전용 흐름
- 오프라인: 잠금 없이 편집 허용 (보낼 목록). 온라인이 되면 잠금부터 시도

### 2.4 저장소
- `PUT` 에 `X-Lock-Session` 헤더
- 423 을 받으면 F-207 2.4 **충돌과 같은 처리**(내 편집은 충돌 사본, 원래 문서는 서버 값). 알림 문구만 `{이메일} 님이 편집 중이라 내 편집을 "{사본 제목}" 으로 저장했습니다.`

### 2.5 비용 메모
- 열린 편집 창 1개당 시간당 약 180번 쓰기(20초 연장). D1 무료 하루 10만 행 쓰기 기준 동시 편집 창 약 23개가 하루 종일 열려 있을 때 한도. 넘으면 연장 간격을 명세로 고친다
