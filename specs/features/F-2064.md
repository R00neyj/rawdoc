## 5. 시그니처 (계약)

```ts
import type { AccountState } from './account'
import type { ShareLinkRow, ShareGrantRow } from './sharesApi'

export type UseSharesPageOptions = {
  sharesOpen: boolean
  account: AccountState
}

export type UseSharesPageResult = {
  sharesLoading: boolean
  sharesLinks: ShareLinkRow[]
  sharesGrants: ShareGrantRow[]
  revokeShareLinkRow: (link: ShareLinkRow) => Promise<void>
  revokeShareGrantRow: (grant: ShareGrantRow) => Promise<void>
  loginFromShares: () => void
}

export function useSharesPage(options: UseSharesPageOptions): UseSharesPageResult
```

- 옵션은 함수 머리에서 **구조 분해**한다(`{ sharesOpen, account }`) — effect 본문 `if (!sharesOpen || account.state !== 'in') return` 과 deps `[sharesOpen, account.state]` 가 글자 그대로 남는다(F-2062 5.2 와 같은 이유)
- `account` 를 `AccountState` 객체 그대로 받는다. `accountState: 'in' | …` 로 좁히면 effect 본문·deps 두 줄이 이동 줄이 아니게 된다. deps 는 `account.state` 만이라 `account` 객체가 매 렌더 바뀌어도 다시 돌지 않는다 — 지금과 같다
- 반환 객체의 키 이름 = 지금 App 변수 이름. App 은 `const { sharesLoading, sharesLinks, sharesGrants, revokeShareLinkRow, revokeShareGrantRow, loginFromShares } = useSharesPage({ sharesOpen, account })` 한 벌로 받고, JSX 6곳은 한 글자도 바뀌지 않는다
- setter(`setSharesLinks` 등)는 반환하지 않는다 — 구역 밖에서 쓰는 곳 0건
- 반환 객체를 `useMemo` 로 감싸지 않는다. 받는 쪽이 JSX prop 뿐이고 지금도 매 렌더 새 함수다
- 파일 머리 한 줄 주석: `// 공유 관리 페이지 S-6 목록·해제 — 들어올 때마다 새로 부른다 (F-243 3.4, F-2064)`. 옮겨 온 절 머리 주석은 effect 위에 그대로 둔다

## 11. 열린 질문

### Q1. `openSharesTarget` 을 옮기나 — **기본값: App 에 남긴다**

- 이유: 본문이 `selectDoc`·`goHome`·`addOpenFolders` 세 개만 부른다. 앞 둘은 F-2059 2.2 가 "D1 판정 전에 옮기지 않는다" 고 한 문서 이동 함수이고, `addOpenFolders` 는 F-2066 이 곧 훅 반환값으로 바꾸는 허브다. 공유 상태(`sharesLinks` 등)는 읽지 않는다. 옮기면 훅이 이동 함수 셋을 옵션으로 받게 돼 공유 관리 훅이 문서 이동 구역에 묶이고, F-2066 이 이 훅 호출까지 고쳐야 한다
- 다른 쪽(옮긴다): App 이 9줄 더 줄고 `SharesPage` prop 함수가 한 파일에 모이지만, 옵션 3개가 늘고 F-2059 7장 D1 을 고칠 때 이 훅도 봐야 한다

### Q2. `loginFromShares` 를 옮기나 — **기본값: 옮긴다**

- 이유: 공유 관리 화면 전용 3줄이고 `loginUrl` import 를 App 에서 뺄 수 있다(App 의 다른 로그인 경로는 `loginUrl` 을 쓰지 않는다 — `grep` 1건). 상태를 읽지 않아 어느 쪽이든 동작은 같다
- 다른 쪽(App 에 남긴다): 반환 키가 하나 줄지만 `loginUrl` import 가 이 함수 하나 때문에 App 에 남는다

### Q3. 특성 테스트 8개가 많은가 — **기본값: C1~C8 전부**

- 이유: 옮기는 코드가 작아도 갈래(로딩·실패·취소·재진입·부팅 재실행·폴더·실패 순서·로그인)가 8개이고, 지금 e2e 는 그중 성공 갈래만 본다. 모두 `fakeServer` 위 1~2초짜리다
- 다른 쪽(C3·C5·C7 셋만 — 옮기며 가장 쉽게 깨지는 `catch`·`cancelled`·성공 뒤 빼기): 묶음이 몇 초 짧아지지만 부팅 재실행(C4)·폴더 갈래(C6)가 바뀌어도 아무것도 안 깨진다
