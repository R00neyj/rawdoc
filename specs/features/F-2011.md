# F-2011 지도 머리 줄 아이콘 버튼화

작성일: 2026-09-22
상태: **사람 승인 — 받음 (2026-09-22).** 갈림길이던 12장 Q1(`Esc` 로 지도를 닫을 것인가)은 **넣지 않는다**로 정해졌다 (5장). 나머지 넷(아이콘 고르기, `.seg` 재사용, 툴팁, `aria-disabled` 표현)은 전부 코드로 확인한 기본값이 그대로 선다.

`specs/design.md` 4장 `아이콘`·`툴팁`·`선택 상태` 세 행이 정한 것을 지도 화면(S-8) 머리 줄에만 적용하지 않고 있다. 사용자 지시 (2026-09-22):

> 우리 design.md 사항으로 버튼들은 아이콘 버튼이 기본값이고 툴팁으로 어떤 버튼인지 안내하는게 전반적인 앱의 디자인 기조임. 근데 지도뷰는 설정만 아이콘이고 맞춤, 닫기, 지도, 목록이 전부 텍스트로 표시되고 있음. 아이콘으로 수정. 지도/목록은 뷰모드 전환처럼 보더 테두리로 같은 카테고리인점 표시

**F-292 9장 로드맵에 없는 새 번호다.** 지도 기능을 더하거나 빼지 않고, 이미 있는 버튼 다섯 개의 **겉모습과 접근성 이름만** 바꾼다. 새 색·새 토큰·새 의존성은 0개다.

근거(실제로 읽은 것, 전부 이 작업 시점의 작업 트리 기준):

### 1.1 `src/styles/app.css` 를 왜 건드리나

`.seg`·`.view-mode-seg`·`.icon-btn`·`.icon-tooltip` 이 전부 `app.css` 에 있다 (2087~2256행). 6.2 에서 **지도 세그먼트를 `.view-mode-seg` 와 같은 값으로 그리기로** 정했고, 값을 `map.css` 에 한 벌 더 적으면 두 곳이 갈라진다 (`CLAUDE.md` "Two copies drift apart" 와 같은 문제). 그래서 **선택자 목록에 `.map-segment` 를 더하는 방식**을 쓴다. 바뀌는 것은 선택자 세 줄과 그 위 주석뿐이고 선언은 그대로다.

## 2. 아이콘 넷 — 실제 파일을 보고 골랐다

`node_modules/@material-symbols/svg-400/outlined/` 에서 후보 파일을 전부 꺼내 path 를 읽고 골랐다. **새로 가져오는 파일은 둘, 이미 있는 것을 그대로 쓰는 것은 둘이다.**

| 버튼 | 아이콘 | 파일 | 상태 |
| --- | --- | --- | --- |
| `지도`(세그먼트) | `IconMap` | `outlined/hub.svg` | **이미 있다** — `icons.tsx` 179행. 사이드바 `지도` 와 같은 그림 |
| `목록`(세그먼트) | **`IconList`(신규)** | `outlined/list.svg` | 파일 있음(확인) |
| `맞춤` | **`IconFit`(신규)** | `outlined/fit_screen.svg` | 파일 있음(확인) |
| `닫기` | `IconClose` | `outlined/close.svg` | **이미 있다** — `icons.tsx` 120행 |
| `지도 설정` | `IconSettings` | `outlined/settings.svg` | **이미 있다** — 그림은 안 바꾼다 (F-2005 5.1) |

### 2.1 `맞춤` 에 `fit_screen` 을 고른 이유

지금 `맞춤` 에 해당하는 아이콘이 저장소에 없다. 후보 넷의 path 를 직접 읽었다.

| 후보 | 실제 그림 (path 를 읽고 적었다) | 판정 |
| --- | --- | --- |
| **`fit_screen`** | 바깥 네 모서리 꺾쇠 + 그 안에 꽉 찬 직사각형 하나 | **고른다.** "틀 안에 내용이 딱 들어간 그림" 이라 `맞춤` 의 뜻(모든 노드가 보이게 카메라를 다시 잡는다, F-2002 6.7)과 그림이 1:1로 맞는다 |
| `zoom_out_map` | 가운데에서 네 모서리로 뻗는 대각선 화살표 넷 | 뺀다. 화살표 언어가 `IconRecenter`(`여기로 이동`)와 겹치고, 뜻이 "확대/펼치기" 로 읽힌다 |
| `center_focus_strong` | 네 모서리 꺾쇠 + 가운데 동그라미 | 뺀다. **`여기로 이동` 과 뜻이 정면으로 겹친다**(가운데로 맞춘다) |
| `crop_free` | 네 모서리 꺾쇠만 | 뺀다. 안이 비어 있어 "무엇을 맞추는지" 가 없다 |

`IconRecenter`(`outlined/recenter.svg`)는 **가운데 점 하나로 모이는 화살표 넷**이다. `fit_screen` 은 화살표가 한 개도 없어 두 그림이 섞이지 않는다.

### 2.2 `목록` 에 `list` 를 고른 이유

| 후보 | 실제 그림 | 판정 |
| --- | --- | --- |
| **`list`** | 왼쪽 점 셋 + 오른쪽 가로줄 셋, 테두리 없음 | **고른다** |
| `view_list` | 테두리 상자 안에 왼쪽 칸 + 오른쪽 줄 | 뺀다. 상자가 `.seg` 바깥 테두리와 겹쳐 네모가 두 겹으로 보인다 |
| `format_list_bulleted` | `list` 와 거의 같은 그림 | 뺀다. 이미 `IconBulletList`(편집기 서식 도구모음 `글머리 목록`)로 쓰고 있다 |

- `list` 는 **점 + 선**, 짝이 되는 `hub` 는 **점 + 점을 잇는 선**이다. 한 세그먼트 안에서 획 밀도가 맞는다
- `format_list_bulleted` 와 한 화면에 같이 나올 일은 없다 — **지도가 열려 있으면 서식 도구모음이 아예 그려지지 않는다** (`App.tsx` 2726~2733행 `showToolbar` 에 `!mapRoute` 가 있다). 그래도 그림이 거의 같은 파일을 두 이름으로 두면 헷갈려서 뺐다

### 2.3 `icons.tsx` 에 더하는 것

## 3. 머리 줄 — 바뀌기 전과 바뀐 뒤

### 3.1 그림

```
전:  [hub] 지도   [ 지도 | 목록 ]                    [맞춤] [⚙] [× 닫기]
후:        지도   [ [hub] | [list] ]                 [fit] [⚙] [×]
                  └ .seg 바깥 테두리 ┘                └ 낱개, 테두리 없음 ┘
```

### 3.2 버튼 다섯

| 버튼 | 전 (보이는 것) | 후 아이콘 | `aria-label` | 툴팁 문구 | 툴팁 정렬 | 테두리 | 묶음 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 제목 | `[hub] 지도` | **아이콘 없음**, 글자 `지도` 만 | — (버튼 아님, `<h1>`) | 없음 | — | 없음 | — |
| 세그먼트 `지도` | 글자 `지도` | `IconMap` 18px | `지도` | `지도` | `center` | **`.seg` 바깥 테두리 안** | `.seg.map-segment` |
| 세그먼트 `목록` | 글자 `목록` | `IconList` 18px | `목록` | `목록` | `center` | **`.seg` 바깥 테두리 안** | `.seg.map-segment` |
| `맞춤` | 글자 `맞춤`, 1px 테두리 | `IconFit` 18px | `맞춤` | `맞춤` | `center` | **없음** | 낱개 |
| `지도 설정` | `IconSettings` (툴팁 없음) | `IconSettings` 18px (그대로) | `지도 설정` (그대로) | **`지도 설정` (새로 붙인다)** | `center` | 없음 (그대로) | 낱개 |
| `닫기` | `[×] 닫기` | `IconClose` **18px** | `닫기` | `닫기` | **`end`** | **없음** | 낱개 |

- **화면에서 글자가 사라지는 것은 `지도`·`목록`·`맞춤`·`닫기` 넷이다.** 문구 자체는 바뀌지 않고 `aria-label` 과 툴팁으로만 남는다. `specs/ia.md` UI 문구표에 새로 더할 낱말은 **0개**다 (9장)
- **제목 `<h1>` 은 글자 `지도` 만 남는다.** 세그먼트 첫 칸이 같은 `hub` 그림이라 한 줄에 같은 아이콘이 두 번 나오기 때문이다 (2026-09-22 사용자 지시)
- **`닫기` 아이콘 크기를 16px → 18px 로 올린다.** `.icon-btn` 을 쓰는 다른 모든 버튼이 18px 이다(`TopBar.tsx` 108행, `MapPage.tsx` 206행). 16px 만 혼자 작으면 32×32 안에서 어긋나 보인다
- **`닫기` 툴팁만 `align="end"`** 다. 머리 줄 맨 오른쪽 버튼이라 가운데 정렬이면 툴팁이 창 밖으로 나간다. `ExportMenu.tsx` 97행·`AccountMenu.tsx` 147행·`NoticeBar.tsx` 45행이 같은 이유로 쓰는 값이다
- `맞춤`·`지도 설정` 은 **`effectiveView === 'graph'` 일 때만 그린다** — 지금 조건 그대로다 (`MapPage.tsx` 191·196행, F-2005 5.1)

### 3.3 `MapPage.tsx` 머리 줄 (바뀐 뒤)

```tsx
<div className="map-page-head">
  <h1 className="map-page-title">지도</h1>

  {/* 배타적인 한 벌이라 상단바 보기 모드와 같은 .seg 묶음을 쓴다 (design.md 4장 선택 상태, F-2011 6.2) */}
  <div className="seg map-segment" role="group" aria-label="지도·목록">
    {/* disabled 가 아니라 aria-disabled — 포커스는 받아야 한다 (F-2002 7.1) */}
    <span className="icon-btn-wrap">
      <button
        type="button"
        className="icon-btn"
        aria-label="지도"
        aria-pressed={effectiveView === 'graph'}
        aria-disabled={unsupported || undefined}
        onClick={showGraph}
      >
        <IconMap size={18} />
      </button>
      <IconTooltip text="지도" />
    </span>
    <span className="icon-btn-wrap">
      <button type="button" className="icon-btn" aria-label="목록" aria-pressed={effectiveView === 'list'} onClick={showList}>
        <IconList size={18} />
      </button>
      <IconTooltip text="목록" />
    </span>
  </div>

  <div className="map-page-actions">
    {effectiveView === 'graph' && (
      <span className="icon-btn-wrap">
        <button type="button" className="icon-btn map-fit-btn" aria-label="맞춤" onClick={() => setFitToken((n) => n + 1)}>
          <IconFit size={18} />
        </button>
        <IconTooltip text="맞춤" />
      </span>
    )}
    {effectiveView === 'graph' && (
      <span className="icon-btn-wrap">
        <button
          type="button"
          className="icon-btn map-settings-btn"
          aria-label="지도 설정"
          aria-expanded={panelOpen}
          aria-controls="map-panel"
          ref={settingsBtnRef}
          onClick={() => setPanelOpen((v) => !v)}
        >
          <IconSettings size={18} />
        </button>
        <IconTooltip text="지도 설정" />
      </span>
    )}
    <span className="icon-btn-wrap">
      <button type="button" className="icon-btn map-page-close" aria-label="닫기" onClick={onClose}>
        <IconClose size={18} />
      </button>
      <IconTooltip text="닫기" align="end" />
    </span>
  </div>
</div>
```

- `import` 줄(5행)에서 **`IconMap` 은 남기고**(세그먼트가 쓴다) `IconFit`·`IconList`·`IconTooltip` 을 더한다
- `.map-fit-btn`·`.map-settings-btn`·`.map-page-close` **클래스 이름은 남긴다.** CSS 는 사라지지만(6.3) 디버그·앞으로의 e2e 가 잡을 손잡이가 필요하고, 이름을 지우면 F-2007 이후가 다시 만들어야 한다
- `settingsBtnRef` 는 **버튼에 그대로** 둔다. `closePanel()` 의 `settingsBtnRef.current?.focus()`(56행)와 `F-2005 A2` 의 `toBeFocused()` 가 그대로 산다

## 4. 툴팁 — 앱이 그리는 것을 그대로 쓴다

`specs/design.md` 4장 `툴팁` 행: "앱이 그린다. 배경 `--ink`, 글자 `--panel`, 12px, 모서리 6px. **아이콘만 있는 버튼에는 반드시 둔다**".

- **새 툴팁 장치를 만들지 않는다.** `icons.tsx` 182~190행의 `IconTooltip` + `app.css` 2103~2213행의 `.icon-btn-wrap` / `.icon-tooltip` 조합을 그대로 쓴다. `TopBar.tsx` 96~111행이 **`.seg` 안에서 이 조합을 쓰는 본보기**다
- **구조는 `버튼의 형제`다.** `<span class="icon-btn-wrap"><button …>svg</button><IconTooltip/></span>`. 툴팁이 버튼 **안**에 있으면 `button.textContent` 가 비지 않아 7장 A1 판정이 흐려지고, `.icon-btn-wrap:hover .icon-tooltip`(2199행)·`:focus-visible ~ .icon-tooltip`(2207행) 선택자도 맞지 않는다
- **세그먼트 버튼에도 툴팁을 단다.** 아이콘만 남으므로 design.md 의 "반드시 둔다"에 그대로 걸린다. `.view-mode-seg` 가 `overflow: visible`(2238행)인 이유가 정확히 이것이고(F-153 2.1 주석), 지도 세그먼트가 같은 규칙을 물려받으므로(6.2) 툴팁이 잘리지 않는다
- **`지도 설정` 버튼에는 지금 툴팁이 없다.** F-2005 5.1 의 코드 블록과 현재 `MapPage.tsx` 196~208행을 읽어 확인했다 — `IconTooltip` 이 없고 `.icon-btn-wrap` 도 없다. **design.md 4장 위반이라 이 명세가 함께 고친다**
- 툴팁이 머리 줄 아래로 펼쳐지는 것은 문제없다 — `.icon-tooltip` 은 `top: calc(100% + 6px)`(2155행)이고 머리 줄은 화면 맨 위 띠다. `.map-page-head` 와 `.map-page-actions` 에 `overflow` 지정이 없는 것도 확인했다 (`map.css` 11~30행)

## 5. `Esc` — 넣지 않는다 (사람 결정, 2026-09-22)

### 5.1 확인 결과: **지금은 `Esc` 로 지도가 닫히지 않는다**

코드를 훑어 확인했다.

| 자리 | `Esc` 로 하는 일 | 지도를 닫나 |
| --- | --- | --- |
| `MapPage.tsx` 60~71행 | `panelOpen` 일 때만 듣고, 설정 **패널만** 닫는다 | 아니다 |
| `App.tsx` 1056~1059행 | `narrow && sidebarOpen` 일 때 겹침 사이드바를 닫는다 | 아니다 |
| `App.tsx` 1408~1412행 | 끌어놓기 표시를 끈다 | 아니다 |
| `Dialog.tsx` 63행 | 네이티브 `<dialog>` 기본 동작 | 아니다 |
| `FolderMenu.tsx` | 노드 메뉴를 닫는다 (F-2003 8.1) | 아니다 |

`closeMap()`(`App.tsx` 2373~2377행)을 부르는 곳은 `MapPage` 의 `onClose` prop(2887행) 하나뿐이고, 그 prop 을 쓰는 곳은 `닫기` 버튼 하나뿐이다. **키보드 전용 사용자가 지도에서 나가는 길은 `Tab` 으로 `닫기` 버튼까지 가서 `Enter`, 또는 브라우저 뒤로 가기(`Alt+←`) 둘뿐이다.**

- 이 명세가 `닫기` 를 아이콘만으로 바꿔도 **그 두 길은 그대로 산다** — 버튼은 여전히 `<button>` 이고 `aria-label="닫기"` 가 접근성 이름을 준다. 즉 **아이콘화 자체는 키보드 길을 끊지 않는다**

### 5.2 그래서 넣지 않는다

`Esc` 로 지도를 닫을지 사람에게 물었고, **넣지 않는다**로 정해졌다 (2026-09-22). 근거는 둘이다.

- **아이콘화 때문에 생기는 문제가 아니다** (5.1). `Esc` 를 넣고 말고는 이 명세와 독립된 취향 문제다
- 넣으면 **승인된 문장 넷을 뒤집는다** — `specs/ia.md` 377행·3.29-9(210행), `specs/features/F-292.md` 5장 표(301행) "지도는 대화상자가 아니라 화면이다", `specs/features/F-2005.md` 6.2. 지도를 대화상자가 아닌 화면으로 본다는 그 결정을 이 명세가 건드릴 이유가 없다

따라서 **`MapPage.tsx` 에 `Esc` 핸들러를 더하지 않는다.** 지금의 `panelOpen` 전용 핸들러(60~71행)는 그대로다.

나중에 넣기로 하면 별도 명세로 다루고 위 네 문장을 함께 고친다. 그때 쓰라고, 이 작업에서 코드로 확인한 것만 남겨 둔다 — **먼저 먹어야 할 것이 넷이다**: 설정 패널(`panelOpen`), 노드 메뉴(`FolderMenu`), `dialog[open]`(`SearchDialog.tsx` 153행이 공용 `<Dialog>` 를 쓰므로 **검색 대화상자도 여기 걸린다**), `.sidebar-backdrop`(`App.tsx` 2836~2839행, `narrow && sidebarOpen` 일 때만 그려진다).

### 5.3 닫은 뒤 포커스

`닫기` 버튼이 `closeMap()` 을 부르면 `mapRoute` 가 지워지고 지도 DOM 이 사라지면서 포커스가 `<body>` 로 떨어진다. **지금과 똑같고 이 명세는 그 동작을 바꾸지 않는다.** 포커스를 편집기로 되돌리는 것은 지금도 없고 새로 넣지도 않는다 (범위 밖).

## 6. CSS

### 6.1 `.icon-btn` 을 그대로 쓸 수 있는지 — 확인했다

`app.css` 2110~2141행의 `.icon-btn` 은 32×32, 테두리 없음, `--ink-2`, `:hover` 에 `--rule-2`, `[aria-pressed='true']` 에 `--ink` 10% 섞기, `[aria-disabled='true']` 에 `--muted` + `cursor: default` 를 모두 갖고 있다. **지도 머리 줄이 필요한 네 가지 상태가 전부 이미 있다.** 지도 전용 값은 필요 없다.

- `.map-page-head` 는 `min-height: var(--topbar-h)` + `padding: 8px 16px` + `align-items: center`(`map.css` 11~22행)라 32px 버튼이 그대로 들어간다
- `[aria-pressed='true']` 바탕이 **`--accent-soft` → `--ink` 10%** 로 바뀐다. 지금 `.map-segment button[aria-pressed='true']`(`map.css` 74~78행)가 `--accent-soft` 를 쓰는데, 이것은 `design.md` 4장 `선택 상태` 행("선택된 버튼·세그먼트는 바탕 `--ink` 10% 섞기")과 어긋나 있었다. **이 명세가 바로잡는 것이고, 새 색을 만드는 것이 아니다**

### 6.2 세그먼트 — `.map-segment` 를 지우고 `.seg` 로 간다

**정한 것: `.seg` 를 그대로 쓴다.** `MapPage` 의 묶음 `className` 은 `"seg map-segment"` 가 되고, `map.css` 의 `.map-segment` 블록(56~83행)은 사라진다. `.map-segment` 는 CSS 를 스스로 갖지 않고 **`app.css` 의 `.view-mode-seg` 규칙에 얹히는 이름**으로만 남는다.

`app.css` 에서 바꾸는 세 줄:

```css
/* 아이콘 전용 세그먼트 — 버튼 사이 2px, 툴팁 때문에 overflow:hidden 끈다 (F-153 2.1) */
/* 바깥 테두리는 .seg 기본값 그대로 — 배타적인 한 벌이라 묶어 보인다 (F-153 2.1, F-2011 6.2) */
.view-mode-seg,
.map-segment {            /* 2236행 */
...
.view-mode-seg button + button,
.map-segment button + button {   /* 2245행 */
...
.view-mode-seg .icon-btn,
.map-segment .icon-btn {         /* 2250행 */
```

왜 이렇게 하는가 — 전부 실제 규칙을 읽고 확인한 것이다.

- `.seg` 기본값(2087~2101행)만으로는 안 된다. `overflow: hidden` 이라 **툴팁이 잘리고**, `button + button` 에 1px 구분선이 있어 아이콘 버튼 사이에 허공 선이 생긴다. `.view-mode-seg` 세 규칙이 정확히 그 둘을 끄고 32×32 를 준다
- 특이도도 맞는다. `.view-mode-seg .icon-btn`(0,2,0)이 `.seg button`(0,1,1)의 `padding: 7px 14px` 를 이긴다 — 상단바 보기 모드가 이미 그렇게 돌고 있다
- **값을 `map.css` 에 베껴 쓰지 않는 이유**: `CLAUDE.md` "Do not duplicate … Two copies drift apart" 와 같은 이유다. 상단바와 지도의 두 세그먼트는 사용자 지시상 **같아 보여야 하는 것**이라 한 벌만 있어야 한다
- 클래스 이름을 `.view-mode-seg` 하나로 합쳐 지도에도 쓰는 방법도 있었지만, `TopBar.tsx` 를 고쳐야 해서 소유 범위가 넓어진다. 선택자 목록에 더하는 쪽이 파일 하나를 덜 건드린다

### 6.3 `map.css` 에서 지우는 것

| 행 | 규칙 | 왜 지우나 |
| --- | --- | --- |
| 30~38행 중 `gap: 6px` 한 줄 | `.map-page-title` | 아이콘이 빠져 자식이 글자 하나뿐이다. `display: inline-flex` 는 남긴다 (`.map-page-title` 을 `hover()` 대상으로 쓰는 `map.spec.js` 541행이 상자를 필요로 한다) |

합쳐서 **40~96행을 통째로 지우고**(뒤따르는 빈 줄 포함) `.map-page-title` 의 `gap` 한 줄을 지운다. `map.css` 98행 이후(`.map-page-body` 아래)는 한 줄도 건드리지 않는다.

### 6.4 새로 만들지 않는 것

- **새 색·새 hex·새 토큰 0개** (`design.md` 3.2 불변조건). `--accent-soft` 를 쓰던 자리가 `--ink` 10% `color-mix()` 로 바뀌는데, 그 `color-mix()` 는 `app.css` 2135행에 이미 있는 것이다
- 새 전환(transition) 0개. `.icon-btn` 의 `var(--transition-colors)` 와 `.icon-tooltip` 의 `--transition-pop` 계열을 그대로 물려받는다

## 7. `aria-disabled` 인 `지도` 버튼 (WebGL2 없음)

글자가 사라져도 **추가 문구를 넣지 않는다.**

- `.icon-btn[aria-disabled='true']`(2127~2131행)가 색을 `--muted` 로 떨어뜨리고 `:hover` 배경을 막는다. 스크린리더는 `aria-disabled` 를 "사용 안 함" 으로 읽는다
- **왜 그것으로 충분한가**: WebGL2 가 없으면 본문 맨 위에 `이 브라우저에서는 3D 지도를 그릴 수 없습니다. 목록으로 보여 드립니다.` 가 이미 떠 있다 (`MapPage.tsx` 229~231행, `.map-notice`). 버튼 바로 아래 한 줄이 이유를 말하고 있으므로 툴팁에 사유를 겹쳐 쓰면 같은 말이 두 번이다
- 그래서 **툴팁 문구는 켜져 있을 때와 같은 `지도`** 다. `specs/ia.md` UI 문구표에 더할 낱말이 없다
- 포커스는 계속 받는다 (`disabled` 가 아니라 `aria-disabled`, F-2002 7.1). 그 결정은 그대로다

## 8. 기존 테스트 회귀 — 저장소 전체를 훑었다

`grep` 으로 `맞춤`·`목록`·`닫기`·`지도`·`map-page-close`·`map-fit-btn`·`map-segment`·`map-page-title` 를 `e2e/`·`src/` 전체에서 찾았다.

### 8.1 **깨지지 않는다** — 이유를 행 단위로 확인한 것

접근성 이름이 `글자 내용` → `aria-label` 로 옮겨갈 뿐이고, 둘 다 `getByRole('button', { name })` 의 이름 계산에 쓰인다. `aria-label` 이 우선이라 **문구가 같으면 매칭도 같다.**

| 파일·행 | 코드 | 왜 산다 |
| --- | --- | --- |
| `map.spec.js` 7 | `page.getByRole('button', { name: '지도' }).first()` | 지도를 **열기 전**이라 후보는 사이드바 버튼뿐. `.first()` 도 그대로 |
| `map.spec.js` 13 | `map.getByRole('button', { name: '목록', exact: true })` | `aria-label="목록"` 이 같은 이름을 준다 |
| `map.spec.js` 51·52·53·54 | `지도`·`목록`·`맞춤`·`닫기` 각 `toHaveCount(1)` | 넷 다 `aria-label` 로 이름이 유지되고 개수도 1 그대로 |
| `map.spec.js` 49 | `지도 설정` `toHaveCount(1)` | 이름·개수 그대로 |
| `map.spec.js` 148 | `지도` 버튼 `aria-disabled` | 속성 그대로 |
| `map.spec.js` 158·186·746·761·784·951·977·1072 | `닫기` 클릭 | `aria-label="닫기"` 로 유지 |
| `map.spec.js` 225 | `.dialog[open]` 안의 `닫기` | 대화상자로 범위가 좁혀져 있어 지도 `닫기` 와 안 부딪힌다 |
| `map.spec.js` 240·393 | `맞춤` 클릭 | 이름 유지 |
| `map.spec.js` 541 | `.map-page-title` `hover()` | `<h1>` 이 남고 글자 `지도` 도 남는다. 아이콘만 빠져 상자가 조금 좁아질 뿐 |
| `map.spec.js` 701~710 (`F-2005 A2`) | 패널 열고 `Escape` → 지도는 남는다 | 5.2 (a) 의 `if (panelOpen) return` 이 지킨다 |

| `topbar.spec.js` 281 | 레일 5번째 버튼 `aria-label='지도'` | 사이드바다. 안 건드린다 |

### 8.2 조심할 것 — 테스트를 새로 쓸 때만 해당

- **`getByText('맞춤')` 류를 쓰면 안 된다.** 툴팁 `<span class="icon-tooltip">맞춤</span>` 이 DOM 에 있고 `opacity: 0` 일 뿐이라 Playwright 는 그것을 **보이는 요소로 친다**. "글자가 사라졌다" 는 `toHaveText('')`(버튼의 `textContent`)로 판정한다 — 툴팁은 버튼의 자식이 아니므로 `''` 가 나온다 (4장)
- `map.spec.js` 475행 `visibleLabels()` 는 `.map-label:not([hidden])` 이라 `.icon-tooltip` 과 안 겹친다
- 지도가 **열린 뒤** `page.getByRole('button', { name: '지도' })`(비-exact)를 새로 쓰면 사이드바 1 + 세그먼트 1 + `지도 설정` 1 = 3개가 잡혀 strict mode 위반이다. 지금 그런 코드는 `openMap()` 하나뿐이고 그것은 열기 전이라 괜찮다

### 8.3 단위 테스트

`src/**/*.test.ts` 에서 머리 줄을 보는 것은 **0건**이다 (`MapPage` 는 DOM 컴포넌트고 테스트 환경이 `node` 라 애초에 렌더하지 않는다). 새 단위 테스트도 만들지 않는다 — 이 명세가 더하는 순수 로직이 없다.
