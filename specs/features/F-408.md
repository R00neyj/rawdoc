| 항목 | 결정 | 어디서 |
| --- | --- | --- |
| 이관 | 로컬 금고 문서는 **암호를 물어 풀고 계정 금고 키로 다시 암호화해** 올린다. 계정 금고가 없으면 같은 암호로 만든다. 건너뛰면 기기에 남고 다음 로그인 때 다시 묻는다. 일반 문서 이관은 그대로 한 번 | F-400 결정 12, 4.4 |

### 2.1 계정 금고가 없을 때와 있을 때 — 흐름과 화면

**공통 앞부분** — E9 `옮기기` → D-14 1단계 `로그인 전 금고 암호` 하나를 받는다

1. 로컬 행 `local` 의 묶음을 `parseKeyBundle` 하고 `openWithPassword` 로 **로컬 MK** 를 푼다(F-403 함수를 곧바로 부른다 — 로그인 페이지의 열쇠고리는 계정 범위라 로컬 묶음을 열 수 없다, c10). 풀린 MK 는 이관 함수의 지역 변수로만 들고 끝나면 놓는다. `upgradedBundle` 이 와도 로컬 행을 고치지 않는다(이관이 로컬을 바꾸지 않는다)
2. **계정 금고 만들기를 먼저 시도한다** — `createAccountBundleSource(userId).create(로컬 묶음 JSON 그대로)`. `PUT /api/e2ee/keys { bundle, baseRev: 0 }` 이 계정 금고가 있으면 409 를 주므로(c1) "있나 보고 만들기" 사이의 경합이 없다
   - `ok` → **그대로 올리기(`adopt`)**
   - `conflict` → **다시 감싸기(`rewrap`)**
   - `error` → D-14 오류 줄(F-404 7.9 쓰기 문구), 아무것도 바뀌지 않았다. 다시 누를 수 있다

**계정 금고가 없을 때 (`adopt`)** — 암호는 한 번만 묻는다

- 올린 묶음이 곧 계정 금고다. **로컬 금고 암호·복구 코드가 그대로 계정 금고의 암호·복구 코드가 된다**(F-400 2.4 끝 문장). 계정 MK = 로컬 MK 라 문서 키·첨부 봉투를 **한 바이트도 바꾸지 않고** 올린다
- 올린 직후 `useE2ee.openWithPassword(같은 암호)` 로 이 탭의 계정 금고를 연다(PBKDF2 한 번 더, 약 83ms — F-404 k12). 실패해도 이관은 계속한다(금고가 잠긴 채 옮겨지고 사이드바에 `잠긴 문서` 로 보인다)
- D-14 1단계 덧붙임 줄이 이 사실을 미리 알린다(5.2 — 계정 금고 상태를 대화상자를 열 때 읽는다)

**계정 금고가 있을 때 (`rewrap`)** — 계정 금고 키가 필요하다. **두 암호를 모두 묻는 것은 아래 둘 다 아닐 때뿐이다**

| 계정 열쇠고리 | 하는 일 | 사용자가 넣는 암호 |
| --- | --- | --- |
| 이 탭에서 이미 열림 | `getMasterKey()` 를 쓴다 | 로컬 하나 |
| 잠김 | ① 방금 받은 로컬 금고 암호로 `useE2ee.openWithPassword` 를 **먼저 한 번** 해 본다(11장 Q2) — 두 금고 암호가 같은 사람은 더 묻지 않는다 | 로컬 하나 |
| 〃 ① 이 `wrong-password` | ② D-14 **2단계** `계정 금고 열기` — F-404 `E2eeUnlockForm`(계정 열쇠고리)으로 계정 금고 암호를 받는다. `암호를 잊었나요?` 는 D-11 복구 1 모드(`openSettingsDialogs.recover()`) | **로컬 + 계정 둘** |

- 계정 MK 를 얻으면: 문서마다 `rewrapDocKey(감싼 키, 로컬 MK, 계정 MK)`(r1), 첨부마다 `rewrapAttachment(봉투, 로컬 MK, 계정 MK)`(r3). 제목·본문 봉투는 **글자까지 그대로**다 — AAD 가 문서 id 이고 id 를 바꾸지 않으므로(F-400 3.2)
- 계정 금고의 암호·복구 코드는 바뀌지 않는다. 키 묶음은 쓰지 않는다
- 2단계에서 `나중에`·Esc 로 닫으면 아무것도 쓰지 않았다(묶음·문서 모두). 다시 E9 를 띄우지 않는다 — 다음 부팅에 다시 묻는다

**화면 요약** (문구 원문은 6장)

```
E9 알림 ── 나중에 ─► 닫힘 (기억 안 함)
   └ 옮기기 ─► D-14 1단계 [로그인 전 금고 암호] ── 나중에 ─► 닫힘
                 └ 옮기기 ─► adopt ──────────────► 실행(4장) ─► E43 진행 ─► E44 끝
                           └ rewrap ─ 열림/같은 암호 ─► 실행
                                   └ 다른 암호 ─► D-14 2단계 [계정 금고 암호] ─► 실행
```

### 2.2 로컬 금고 문서·첨부가 서버에 평문으로 한 번도 닿지 않는 순서

**규칙**: 이관은 로컬 `md-docs` 의 **저장소 층 값**(봉투·감싼 키, `createIdbStore` 그대로 — `withE2ee` 를 거치지 않는다)을 읽어, 키만 바꾼 봉투를 계정 캐시(`md-remote`)와 보낼 목록에 쓴다. 평문은 암호를 풀어 얻은 MK 로 **키를 다시 감싸는 동안에만** 메모리에 있고, 제목·본문 평문은 섞인 평문 첨부(4.3)가 있는 문서에서만 잠깐 만든다

| # | 요청 (나가는 순서) | 싣는 것 | 평문이 없는 이유 |
| --- | --- | --- | --- |
| 1 | `GET /api/e2ee/keys` (D-14 을 열 때 `refreshStatus`, 계정 열쇠고리 열기) | 몸통 없음. 응답이 계정 묶음 | 보내는 것이 없다 |
| 2 | `PUT /api/e2ee/keys` — **`adopt` 에서만, 문서보다 먼저** | `{ bundle: 로컬 행 JSON 그대로, baseRev: 0 }`. 묶음 = PBKDF2 소금·반복 수, `AES-KW(KEK_p, MK)`, 복구 소금, `AES-KW(KEK_r, MK)`, 만든 시각 (F-400 2.3) | 암호·복구 코드·MK 는 들어 있지 않다. 감싼 MK 는 암호나 복구 코드로만 풀린다 — 계정 금고를 새로 만들 때(F-404 D-8)와 같은 값이다 |
| 3 | `POST /api/folders` (금고 폴더, 부모 먼저) | `{ id, name, parentId, e2ee: true }` | 폴더 이름은 평문이다 — **결정 2 가 정한 공개 메타데이터** |
| 4 | `POST /api/docs` (문서마다) | `{ id, title: 봉투, content: 봉투, lineEnding, folderId, createdAt, updatedAt, pinnedAt, e2eeKey: AES-KW(계정 MK, DEK), attachmentRefs: id 목록 }` | 봉투는 로컬 행의 것 그대로(섞인 경우만 같은 DEK 로 다시 암호화한 것). 감싼 키는 계정 MK 로 감쌌다. id 목록·시각·줄바꿈은 결정 2·7 의 메타데이터 |
| 5 | `PUT /api/attachments/{id}.{ext}?e2ee=1&w=&h=` (첨부마다) | 몸통 = 첨부 봉투 `0x01 ‖ AES-KW(계정 MK, 첨부 DEK) ‖ IV ‖ 암호문+태그` | `adopt` 는 로컬 봉투 그대로, `rewrap` 은 머리 40 B 만 바뀐 봉투(r3), 섞인 평문 첨부는 계정 MK 로 새로 암호화한 봉투. 형식·가로세로·크기는 결정 16 의 메타데이터 |

- **2 가 4·5 보다 먼저인 이유**: 키 묶음이 없는 계정에 `e2eeKey` 문서를 보내면 409 `no_vault` 이고, F-405 5.3 은 그 캐시 행과 항목을 **지운다**(E24). 새는 것은 아니지만 옮긴 문서를 잃는다. 2 는 D-14 안에서 곧바로 보내고 성공을 확인한 뒤에야 4·5 를 보낼 목록에 넣는다
- **보내지 않는 것**: 금고 암호·복구 코드·MK·DEK 원값(모두 `extractable: false` — 다시 감싸기도 원값을 꺼내지 않고 WebCrypto 안에서 한다, `rewrapDocKey`·`rewrapAttachment`), 제목·본문·이미지 평문
- **다른 길로 새지 않는 것**:
  - 일반 이관 `importLocal` 은 금고 폴더·문서를 건너뛴다(c6, F-405 5.5)
  - `migrateLocalAttachments` 는 캐시 문서 **본문**에서 참조를 찾는다 — 금고 문서의 본문은 봉투라 금고 첨부·섞인 평문 첨부를 찾지 못한다(c6). 섞인 평문 첨부는 이 명세가 새 id 로 암호화한 것만 올린다(4.3)
  - 계정 캐시(`md-remote`)에도 봉투만 쓴다 — F-400 결정 8 "기기 캐시는 암호문" 그대로
  - 금고 문서는 경로가 `e2ee` 라 소켓·`md-yjs` 를 쓰지 않는다(F-405 2.1). 이관은 `updateDoc` 을 만들지 않는다
- **드러나는 것**(F-400 1.2 표 그대로): 폴더 이름, 문서·첨부 수와 크기, 시각, 고정 여부, 첨부 id 목록·형식·가로세로, 줄바꿈. 그리고 `adopt` 에서는 **로컬 금고 암호가 계정 금고 암호가 되므로 운영자가 그 암호를 오프라인으로 맞춰 볼 수 있는 대상이 된다** — 계정 금고를 만들 때와 같은 위험이고, D-14 1단계 덧붙임 줄이 알린다

### 2.3 도중 실패·새로고침 뒤 이어 가기 — 진행 기록은 **계정 캐시(+보낼 목록)** 와 로컬 행 표시

F-407 처럼 서버 표지를 읽어 다시 계획하지 않는다. **F-208 처럼 계정 캐시에 쓰고 보낼 목록(outbox)에 넣는 것**으로 한다(11장 Q1)

| 무엇 | 어디 | 수명 |
| --- | --- | --- |
| 계정 금고가 생겼나 | 서버 `e2ee_keys` (`adopt` 의 2번 요청) | 영구 |
| 어느 폴더·문서·첨부를 넣었나 | **계정 캐시 행의 id** — `importLocalE2ee` 가 캐시에 같은 id 가 있으면 건너뛴다. 캐시에 쓴 것은 보낼 목록에도 있다(한 함수가 둘을 차례로 쓴다) | 보낼 목록이 비면 서버 행이 그 기록이다. `list()` 는 보낼 목록에 남은 문서를 캐시에서 지우지 않는다(c5) |
| 이 계정으로 이관을 끝냈나 | 로컬 행 `local` 의 `migratedTo` 에 사용자 id (3.1) | 로컬 금고를 초기화하면 행과 함께 사라진다 |

- **왜 F-407 실행기(곧바로 보내기·600ms 간격)를 쓰지 않나**: ① F-407 이 온라인·곧바로를 고집한 이유는 서버가 평문 흔적(DO·링크·초대·평문 첨부)을 치우는 일이 한 요청에 묶여서다(F-400 10장 Q5). 이관에는 치울 평문이 없다 — 올리는 것이 처음부터 봉투다 ② 보낼 목록에 넣으면 키 묶음 뒤로는 오프라인·429·서버 오류가 모두 지금 규칙(F-207·F-2030)으로 이어진다. 캐시에 쓴 순간 탭을 닫아도 다음 부팅에 계속 나간다 ③ F-208 이 일반 문서를 같은 방식으로 옮긴다. 대가는 11장 Q1
- **캐시 쓰기 순서** — 이어 가기가 안전한 순서가 규칙이다: 폴더 전부(부모 먼저) → 문서마다 [그 문서가 쓰는 첨부 → 그 문서]. 문서를 **자기 첨부 뒤에** 쓰므로, 문서가 캐시에 있으면 그 첨부도 이미 있다. 도중에 끊기면 다음 실행은 캐시에 없는 것부터 한다
  - 보낼 목록도 같은 순서로 나간다 — 첨부 `upload` 가 그 문서의 `createDoc` 바로 앞이다. 서버 정리 Cron(F-402, 참조 없고 만든 지 24시간 지난 첨부)과 부딪치려면 두 항목 사이에서 보내기가 24시간 넘게 멈춰야 한다 — 붙여넣기(F-406)도 같은 순서라 받아들인다
- **새로고침·탭 닫기로 끊기면**:
  - `adopt` 의 키 묶음을 올린 뒤 끊김 → 다음 부팅에 E9 가 다시 뜬다(`migratedTo` 없음). 이번에는 2번 요청이 `conflict`(방금 올린 묶음이 있다) → `rewrap`. 계정 묶음 = 로컬 묶음이라 ①(로컬 암호로 계정 열기)이 늘 성공해 **암호는 한 번만** 묻는다. 계정 MK 와 로컬 MK 가 같은 값이라 다시 감싼 키가 원래 값과 같다(r2)
  - 캐시 쓰기 도중 끊김 → 다음 실행이 캐시에 있는 id 를 건너뛰고 나머지를 쓴다. E9 의 개수 `{N}` 도 계정에 없는 것만 센다(4.1)
  - 캐시에 다 쓴 뒤 `migratedTo` 쓰기 전에 끊김 → 다음 E9 판정에서 계정에 없는 문서가 0개 → 묻지 않고 `migratedTo` 만 적는다(4.1)
- **서버가 거절하면**(보낼 목록 단계): 지금 규칙 그대로 — 413 은 캐시에 남고 알림(F-207), 429 는 멈췄다 이어 감(F-2030), 409 `no_vault` 는 F-405 5.3(E24 — 다른 기기에서 그 사이 계정 금고를 초기화한 경우뿐). 이 명세가 새 갈래를 만들지 않는다
- **같은 브라우저 두 탭이 동시에 옮기면**: 둘째 탭의 2번이 `conflict` → `rewrap`(같은 MK 라 같은 감싼 키, r2) → 캐시에 있는 id 는 건너뛴다. 캐시 확인과 쓰기 사이에 겹쳐 같은 `createDoc` 이 두 번 들어가도 서버가 같은 소유자의 같은 id 를 200 으로 받는다(c2)·첨부도 같다(c3). 탭 사이 잠금을 두지 않는다

### 2.4 암호를 모르거나 건너뛰면 — 로컬에 그대로 둔다

- 로컬 금고 문서·폴더·첨부는 **하나도 바꾸지 않는다**(`md-docs` 를 읽기만 한다). 로그아웃하면 지금처럼 로컬 금고가 보이고, 로그인 상태에서는 보이지 않는다(F-400 4.4 끝 줄)
- `나중에`(E9·D-14)·Esc·틀린 암호로 멈춤 = 아무것도 쓰지 않는다. `migratedTo` 를 적지 않으므로 **다음 부팅마다** E9 가 다시 뜬다(F-400 4.4 "기억하지 않는다")
- **암호를 잊었으면**: D-14 는 복구 코드를 받지 않는다(11장 Q3). D-14 1단계 아래 안내 줄 — 로그아웃한 뒤 설정 `금고` 탭 → `금고 열기…` → `암호를 잊었나요?`(F-404 D-11 복구, 로컬 범위)로 새 암호를 정하고 다시 로그인하면 E9 가 그 새 암호로 옮긴다. 복구로 로컬 묶음이 바뀌어도 `migratedTo` 는 옮겨 실린다(3.1)
- 암호와 복구 코드를 모두 잃었으면 로컬 금고 문서는 누구도 열 수 없다(결정 3). E9 는 계속 뜬다 — 멈추려면 로그아웃 상태에서 로컬 `금고 초기화…`(F-404 D-13)로 로컬 금고 문서를 지운다. E9 가 매번 뜨는 것을 막는 별도 "다시 묻지 않기" 는 두지 않는다(11장 Q8)

```ts
export type LocalE2eeKeys = { mode: 'adopt' | 'rewrap'; localKey: CryptoKey; accountKey: CryptoKey }

export type LocalE2eeMigrationPlan = {
  folders: Folder[]        // 계정에 만들 금고 폴더. 부모 먼저. parentId 는 4.2 로 고친 값
  docs: Doc[]              // 옮길 금고 문서 (저장소 층 — 봉투·e2eeKey 그대로). folderId 는 4.2 로 고친 값

}

export function planLocalE2eeMigration(input: {

  account: { docIds: ReadonlySet<string>; folderIds: ReadonlySet<string> }
}): LocalE2eeMigrationPlan

// 금고 첨부 봉투 하나. adopt 면 같은 바이트, rewrap 이면 머리 40 B 만 바뀐다. id·ext·가로세로 그대로
export function rekeyLocalE2eeAttachment(attachment: Attachment, keys: LocalE2eeKeys): Promise<Attachment>

// 섞인 평문 첨부 하나를 새 id 로 계정 키에 암호화한다 — 바이트·확장자 그대로(F-407 Q8). 암호화할 수 없으면 null (4.3)
export function encryptLocalPlainAttachment(attachment: Attachment, keys: LocalE2eeKeys): Promise<Attachment | null>

// 문서 하나. title 봉투는 늘 그대로. links 가 비었으면 content 봉투도 그대로, 있으면 같은 DEK 로 다시 암호화하고 attachmentRefs 를 다시 만든다
export function rekeyLocalE2eeDoc(
  doc: Doc,
  keys: LocalE2eeKeys,
  links: ReadonlyMap<string, { id: string; ext: AttachmentExt }>, // 옛 평문 첨부 id → 새 금고 첨부
): Promise<Doc>
```

- 네 함수가 돌려주는 값은 **저장소 층**이다 — `e2eeKey` 가 있고 `title`·`content` 가 봉투, 첨부는 `e2ee: true` 이고 `blob` 이 봉투(형식 `application/octet-stream`). `withE2ee` 를 거치지 않고 `importLocalE2ee` 로 곧바로 간다

- 던짐: 풀기 실패(`E2eeError` `decrypt-failed`·`bad-envelope`·`unsupported-version`)는 그대로 던진다 — 부르는 쪽(4.4)이 그 문서를 건너뛴다

## 4. 규칙

### 4.1 언제 묻나 — `checkLocalE2eeMigration`

부팅이 끝나고(`bootPhase === 'ready'`) `useE2ee` 가 `null` 이 아니고, 저장소가 `server` 이고, 부팅 때 계정 상태가 `in` 이고 `blocked` 가 거짓일 때 **페이지마다 한 번**. F-208 이관(`migrateLocalIfNeeded`)이 끝난 뒤다(부팅 안에서 먼저 돈다)

판정 (싼 것부터, 번호가 계약이다):

1. `localDbExists()` 가 거짓 → `skip` (로그인만 쓰는 사람의 브라우저에 `md-docs` 를 만들지 않는다 — F-404 k9 와 같은 태도)
2. `readLocalRow()` 가 `null`(로컬 금고 없음) → `skip`
3. 행의 `migratedTo` 에 `userId` 가 있음 → `skip`
4. `readLocal()` → `planLocalE2eeMigration({ local, account: accountIds() })`. `accountIds` 는 부팅이 이미 받은 App 목록 상태의 소유 문서·폴더 id(보낼 목록에 남은 것 포함 — c5)
5. 계획의 `docs` 가 0개 → `markMigrated(행 bundle)` 뒤 `skip` (금고 문서가 없거나 모두 이미 계정에 있다. 빈 금고 폴더만 있으면 옮기지 않는다 — 11장 Q9)
6. 그 밖 → `ask`, `count` = 계획의 `docs` 수

- `ask` 면 App 이 E9 를 띄운다(5.1). IndexedDB 읽기 오류는 `skip` + `console.error` — 부팅을 막지 않는다
- 판정은 **부팅마다** 다시 한다 — `나중에` 를 기억하지 않는다(F-400 4.4). 1~3 이 걸리는 사람(대부분)은 IndexedDB 행 하나만 읽는다

### 4.2 계획 — `planLocalE2eeMigration`

- 대상: 로컬 폴더 중 `e2ee: true`, 로컬 문서 중 `e2eeKey` 가 있는 것
- **계정에 같은 id 가 있으면 건너뛴다** — 문서는 `skippedDocIds` 에, 폴더는 만들지 않고 그 계정 폴더를 그대로 쓴다. 계정 쪽이 일반 문서여도 같다(F-208 2.2 3번 "캐시에 같은 id 가 이미 있으면 건너뛴다" 그대로 — 로그아웃 중에 로컬에서 금고로 옮긴 옛 이관 문서가 여기 걸린다. 로컬 사본은 로컬에 남는다)
- **부모 고치기**: 금고 폴더의 `parentId`·금고 문서의 `folderId` 는 그 폴더가 ① 이 계획의 금고 폴더이거나 ② 계정에 있으면 그대로, 아니면 `null`(맨 위). 이유 c4 — 없는 부모로 폴더를 만들면 서버가 400 을 준다. 로그아웃 뒤 로컬에 새로 만든 일반 폴더는 F-208 이 다시 옮기지 않으므로(`md.localMigrated`) 계정에 없을 수 있다
- 폴더 순서: 부모 먼저(깊이 얕은 것부터, 같은 깊이는 로컬 목록 순서). 문서 순서: 로컬 `list()` 순서(`updatedAt` 내림차순)

### 4.3 섞인 평문 첨부 — 금고 문서가 평문 첨부를 참조할 때

- 로컬 금고 문서의 `attachmentRefs` 에는 금고 첨부(`e2ee: true` 행)뿐 아니라 **평문 첨부**가 있을 수 있다 — 일반 문서의 이미지 줄을 금고 문서에 복사해 넣은 경우(F-402 3.2 의 반대 방향). 로컬에서도 그 이미지는 평문이었다
- 이관은 그 평문을 서버에 올리지 않는다. 대신 F-407 이 금고로 옮길 때 하는 것과 같게 **새 id 로 계정 키에 암호화해** 올리고 계정 쪽 본문의 줄을 바꾼다(11장 Q5):
  - `encryptLocalPlainAttachment`: 평문 바이트 > `E2EE_MAX_PLAIN_ATTACHMENT_BYTES`(5,242,811 B)이거나 가로·세로가 1 이상 정수가 아니면(행 값, 없으면 `inspectImageBytes` 로 한 번 잰다) `null`. 아니면 새 id(16진 소문자 16자) · `encryptAttachment(accountKey, 새 id, 평문)` · 같은 `ext`·`mime`·가로세로
  - `rekeyLocalE2eeDoc` 에 옛 id → 새 첨부 짝을 준다 → `openDocKey(localKey, e2eeKey)` 로 본문을 풀고 `rewriteAttachmentLinks`(F-407)로 줄을 바꾼 뒤 **같은 DEK** 로 다시 암호화, `attachmentRefs` 를 새 본문에서 다시 만든다(`attachmentRefsOf` — F-405). 제목 봉투는 그대로. 바꾼 줄은 id 16자만 다르고 확장자가 같아 본문 바이트 수가 같다 — 크기 상한을 다시 넘지 않는다
  - `null` 이면 그 줄은 바꾸지 않는다(계정에서는 깨진 이미지). 끝 알림에 E47 덧붙임
- **로컬은 바꾸지 않는다** — 로컬 금고 문서는 옛 평문 줄 그대로다
- 한 실행 안에서 같은 평문 첨부를 여러 금고 문서가 쓰면 한 번만 암호화한다(실행 메모리의 짝). 이어 가기로 다음 실행에서 또 만나면 새 id 로 한 번 더 만든다 — 앞 실행에서 캐시에 썼지만 문서가 쓰이기 전에 끊긴 사본은 참조가 없어 서버 정리 Cron 이 지운다

### 4.4 실행 — `runLocalE2eeMigration`

(번호가 계약이다)

1. 계획을 다시 세운다(`readLocal()`·`accountIds()` — D-14 를 연 사이 바뀌었을 수 있다). `total` = 계획의 `docs` 수
2. 폴더 전부를 `importLocalE2ee({ folders })` 한 번
3. 문서마다:
   1. `keyAlive()` 가 거짓이면 멈춤(`locked`). `noteActivity()`
   2. 그 문서의 `attachmentRefs` 마다 `getLocalAttachment(id)`: 없으면 넘어간다(로컬에서도 깨진 이미지) / `e2ee` 행이면 `rekeyLocalE2eeAttachment` → `importLocalE2ee({ attachments: [하나] })` / 평문 행이면 4.3. **한 번에 첨부 하나씩** 읽고 쓴다 — 5MB 이미지 여럿을 메모리에 같이 들지 않는다
   3. `rekeyLocalE2eeDoc` → `importLocalE2ee({ docs: [하나] })`. 풀기가 던지면(로컬에서도 열리지 않는 손상 문서, F-405 4.1) 그 문서는 건너뛰고 세지 않는다 + `console.error('e2ee_migrate_doc_failed', id)`
   4. `onProgress(n, total)`
4. 끝: `markMigrated(bundle)`. 거짓이어도(그 사이 로컬 묶음이 바뀜) `done` — 다음 판정의 5번이 적는다
5. `done`: `count` = 쓴 문서 수, `skippedImages` = 4.3 의 `null` 수

- `importLocalE2ee` 가 캐시에 있는 id 를 건너뛰므로 1~3 을 다시 돌려도 같은 결과다(2.3)
- 로컬 MK·계정 MK 는 `keys` 로만 들어온다. 실행이 끝나면 App 이 `keys` 참조를 놓는다. `rewrap` 에서 계정 열쇠고리가 잠기면(3.1 번) 들고 있는 계정 MK 참조가 살아 있어도 **쓰지 않고 멈춘다** — 잠그기는 "이 탭에서 키를 더 쓰지 않는다" 는 뜻이다(F-404 4.1)

### 4.5 App 흐름

1. 4.1 이 `ask` → E9(5.1). `옮기기` → D-14 1단계를 연다(E9 는 걷는다). D-14 를 열 때 `refreshStatus()` 로 계정 금고 상태를 읽어 덧붙임 줄을 고른다(5.2)
2. D-14 1단계 제출 — 로컬 행을 **새로 읽고**(`readE2eeRow('local')`) 2.1 공통 앞부분 1·2 → `adopt`/`rewrap` 갈래. 오류는 5.2 오류 표
3. 키를 얻으면 D-14 를 닫고 진행 알림 E43(자동 숨김 없음 — F-407 7.3 이 진행 알림에 쓰는 방식 그대로) → `runLocalE2eeMigration` → 결과 알림(6장) → `resyncFromStore()`
4. 실행 중에 같은 탭에서 E9·D-14 를 다시 열 수 없다(E9 를 띄우지 않는다)
5. 실행이 끝나면 `keys` 를 버린다

## 13. 확인한 것과 가정

### 13.1 코드를 읽거나 돌려 확인한 것
- 머리 표 r1~r5, c1~c12
- `crypto.ts` 에 `rewrapDocKey`·`rewrapAttachment` 가 이미 있다(F-403) — 둘 다 원값을 `extractable: true` 로 WebCrypto 안에서 풀어 곧바로 다시 감싸고, 로컬·계정 MK 는 `extractable: false` 여도 된다(`wrapKey`·`unwrapKey` 용도만 쓴다). 그래서 이관 어느 갈래에서도 MK 를 꺼낼 수 있게 풀 필요가 없다 — F-400 2.1 "이관처럼 MK 를 다시 감싸는 순간" 의 예외를 쓰지 않는다
- `openWithPassword` 가 돌려주는 MK 는 `extractable: false`, 용도 `wrapKey`·`unwrapKey`
- `App.tsx` 부팅에서 F-208 이관은 `resolvedStore.kind === 'server' && accountState.state === 'in'` 일 때 `createIdbStore()` 로 로컬을 읽는다(저장소 층 — `withE2ee` 를 거치지 않는다)
- `useE2ee` 의 `requestOpen` 은 `unknown`·`unavailable` 이면 `keyring.load()` 뒤 `none` → D-8, `locked` → D-11. `handleOpened` 는 대화상자를 닫고 대기 중인 `requestOpen` 을 푼다
- `E2eeUnlockForm` 은 `keyring`·`onOpened`·`onForgotPassword`·`autoFocus`·`labelId` 를 받고 제출 때 `keyring.open` 을 부른다 — D-14 2단계가 그대로 쓸 수 있다
- `worker/docs.ts` `handleCreateDoc` 은 `createdAt`·`updatedAt`·`pinnedAt` 을 받아 그대로 쓴다(F-208 2.3) — 이관한 금고 문서의 시각이 유지된다

### 13.2 가정으로 남긴 것
- **r1·r3·r4 는 Node 값이다.** 브라우저의 다시 감싸기 비용은 재지 않았다. IndexedDB 에서 첨부 `Blob` 을 읽고 계정 캐시에 쓰는 시간·메모리도 재지 않았다(10장 3번)
- `src/e2ee/convert.ts`(F-407)는 아직 없다. `attachmentLinksOf`·`rewriteAttachmentLinks` 가 F-407 3.3 계약대로 만들어진다고 보고 썼다
- `idbStore` 의 금고 첨부 행 모양(`e2ee: true`, `blob` 이 봉투)과 서버 저장소의 `upload` 가 캐시 행 `e2ee` 로 `?e2ee=1&w&h` 를 붙이는 것은 F-406 2.3·4.2 계약이다 — F-406 은 아직 구현되지 않았다
- 알림 `info` 의 자동 숨김을 끄는 App 쪽 방법은 F-407 7.3 이 만든다고 보고 "같은 방식" 으로 적었다 — 이름은 F-407 구현을 따른다
- 1,000개 규모 이관에서 보낼 목록이 429 를 몇 번 맞는지는 재지 않았다. F-407 c3 의 모형(분당 120 고정 창)을 따르면 쓰기 1,010번에 몇 차례 쉰다
- `indexedDB.databases()` 가 설치된 Chrome 과 `fake-indexeddb` 에 있다는 것은 기존 테스트(`e2e/cliLogin.spec.js`, `src/storage/yjsStore.test.ts`)가 쓰는 것으로 확인했다. 다른 브라우저(Safari 등)에서 없으면 4.1 1번은 참으로 친다
