# F-2147 쓰기 한도 안내 페이지 /limits

작성일: 2026-10-16
상태: 승인(사용자 "ㄱㄱ", 2026-10-16 — F-4008 개요 결정·흐름 그림과 함께). 개요 F-4008 4장 `/limits` 줄과 6장 표의 자식. 선행 없음, 배포는 F-4009·F-4010 다음·F-4011 앞(F-4008 6장). 구현 담당 `feature-implementer`. `App.tsx` 변경 없음

## 근거 (2026-10-16 HEAD, 이름으로 찾는다)
- 한도 값: `worker/writeGate.ts` `MINUTE_WRITE_LIMIT`(120, `wrangler.jsonc` `WRITE_LIMITER` 와 같은 값)·`MINUTE_RETRY_AFTER`, `worker/usage.ts` `DAILY_WRITE_LIMIT`(5000)·`writesToday`·`secondsUntilUtcMidnight`·`usageOf`. 분당 바인딩은 남은 횟수를 주지 않는다 → 로그인해도 분 상태는 보일 수 없다
- 같은 모양 선례: `worker/loginPage.ts` `renderLoginPage`(스크립트 없는 완결 HTML, `PAGE_TOKENS_CSS`·`SITE_CHROME_CSS`·`renderSiteHeader({ appCta: 'link' })`·`renderSiteFooter`, `Cache-Control: private, no-store`), `worker/index.ts` `handleLoginPage`(GET·HEAD 외 405, `getUser` 가 던져도 페이지는 그림)
- `worker/index.ts` `handleRequest` 의 `/api`·`/pub`·`/v1` 밖 분기에 `/login`·`/welcome` 이 있다. `getUser` 는 `/v1/` 이 아니면 세션 쿠키(개발 우회 포함)를 본다
- CSP: `worker/securityHeaders.ts` `cspKindOf` 가 `/limits` 를 `site` 로 분류 — 인라인 `<style>` 허용, 스크립트 없음. 바꿀 것 없다
- 대기 시간 글: `cli/src/output.ts` `remainingTimeText`("{h}시간 {m}분", 0 자리 뺌, 분 올림). `worker/` 는 `cli/` 를 들여오지 못하므로 같은 규칙을 새로 쓴다. 하루 기준 문구 선례: ia 6장 L6 `한국 시간 오전 9시(UTC 자정)`

## 2. 계약
```ts
export type LimitsScope = 'minute' | 'day'
export function parseLimitsQuery(params: URLSearchParams): { scope: LimitsScope | null; retry: number | null }
export function waitText(seconds: number, scope: LimitsScope): string
export function renderLimitsPage(args: {
  scope: LimitsScope | null
  retry: number | null
  account: { used: number; resetIn: number } | { blocked: true } | null // null = 로그아웃·세션 판정 실패
}): Response
export async function handleLimitsPage(request: Request, env: Env): Promise<Response>
```
- 선택자: `main.limits` 안에 `h1`, `ul.limits-rules`(기준 줄들), `p.limits-wait`(질의 대기), `p.limits-status`(내 상태). 테스트가 이 이름으로 찾는다

## 3. 동작
- **질의**: `scope` 는 `minute`·`day` 만, 아니면 `null`. `retry` 는 `/^\d{1,5}$/` 이고 1~86400 일 때만 수, 아니면 `null`. `scope` 가 `null` 이면 `retry` 도 버린다. 질의 글자는 화면에 그대로 넣지 않는다 — 수와 고정 문구만 들어간다(반사 XSS 없음)
- **`waitText`**: `minute` → `{seconds}초`. `day` → `remainingTimeText` 와 같은 규칙(분 올림·최소 1분, `{h}시간 {m}분`, 0 인 자리는 뺌). 개요의 `약 {retry}초` 를 하루에 그대로 쓰면 `약 43200초` 가 되어 하루만 시간·분으로 바꿨다
- **`handleLimitsPage`**: GET·HEAD 외 405 `method_not_allowed`. `getUser` → 있으면 `usageOf` 로 `blockedAt` 이 있으면 `{ blocked: true }`, 아니면 `{ used: writesToday(usage, now), resetIn: secondsUntilUtcMidnight(now) }`. `getUser`·`usageOf` 가 던지면 `console.error` 뒤 `null` 로 그린다. 쓰기 관문·사용량 줄을 건드리지 않는다(읽기만)
- **응답 머리**: 200, `Content-Type: text/html; charset=utf-8`, `Cache-Control: private, no-store`, `X-Robots-Tag: noindex`. `<meta name="robots" content="noindex">`, `<html lang="ko">`, `<script` 없음
- **화면**(위에서 아래, 각 줄은 있을 때만):

| 자리 | 조건 | 문구 |
| --- | --- | --- |
| `<title>` | — | `{h1} · {brand.name}` (`escapeAttr` 는 로그인 페이지와 같게) |
| `h1` | `scope` 있음 / 없음 | `쓰기 제한에 걸렸습니다` / `쓰기 한도` |
| `ul.limits-rules` 1 | 늘 | `1분에 {MINUTE_WRITE_LIMIT}번, 하루 {DAILY_WRITE_LIMIT}번까지 쓸 수 있습니다 (CLI·MCP·앱 공통)` |
| `ul.limits-rules` 2 | 늘 | `하루 횟수는 한국 시간 오전 9시(UTC 자정)에 0부터 다시 셉니다.` |
| `p.limits-wait` | `scope=minute` + `retry`, 또는 `scope=day` + `retry` + `account` 가 `null` | `약 {waitText(retry, scope)} 뒤 다시 가능` |
| `p.limits-status` | `account` 가 `{used, resetIn}` | `지금 상태: 하루 {used}/{DAILY_WRITE_LIMIT}`, `used >= DAILY_WRITE_LIMIT` 면 뒤에 ` · 약 {waitText(resetIn, 'day')} 뒤 다시 가능` |
| `p.limits-status` | `account` 가 `{blocked}` | `이 계정은 운영자가 쓰기를 막았습니다. 문서 읽기와 내보내기만 할 수 있습니다.` (ia L5 그대로) |

- 로그인 상태의 하루 대기는 서버 값만 쓴다(질의 `day` 대기는 링크가 만들어진 뒤 낡는다). 분 대기는 서버가 모르므로 질의로만 보인다. `used` 는 한도를 넘어도 그대로 보인다(스냅숏이 관문 뒤에 더해질 수 있어 거르지 않는다)
- 로그아웃 상태에 로그인 링크는 두지 않는다 — `/login` 복귀 주소는 `#/…` 해시만 받아(`loginReturn`) 이 페이지로 돌아올 수 없다. 머리의 앱 링크(`appCta: 'link'`)로 충분
- 모양: 로그인 페이지와 같은 머리·바닥·색 변수, 본문 폭·여백은 `LIMITS_CSS` 에서 `LOGIN_CSS` 의 `main` 값을 따른다. 색 hex 없음(`PAGE_TOKENS_CSS` 변수만)

## 4. 사용자 흐름 (`specs/wireframes/remote-mcp-flow.html` 3절)
MCP 쓰기 도구가 429 → `isError` 글의 `{origin}/limits?scope=…&retry=…`(F-3031) → 이 페이지: 기준 두 줄(U3) · 질의 대기(U3) · 로그인이면 내 하루 사용량과 다시 가능 시각(U4) · 막힌 계정(U4). 그림의 `{retry}초 뒤 다시 가능` 이 한 줄에 있던 것은 질의 대기와 내 상태 두 줄로 나눴다(분 대기는 내 상태로 알 수 없어서)
