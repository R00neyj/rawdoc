## 2. 현재 문제 (코드 읽기, 구현에서 실측으로 확정)
- 칸 편집 하위 에디터는 `td`/`th` 안에 붙는다 (`tableWidget.js` `startEdit`). 그런데 `td` 자체에도 keydown 리스너가 있어 `key === ' '` 또는 `Enter` 면 `preventDefault()` 후 `startEdit` 를 다시 부른다 (`buildCell`, 506~510줄). 하위 에디터에서 올라온 스페이스도 여기서 막힌다 → 띄어쓰기 불가
- 같은 칸이면 `startEdit` 가 `cellView.focus()` 를 불러 선택을 다시 놓는다. 한글 조합을 스페이스로 확정하는 순간 이 경로가 겹치면 마지막 글자가 이상하게 붙거나 사라질 수 있다 (추정)
- `cellKeydown` 의 조합 판정은 `view.composing` 만 본다. 조합 시작 직후에는 이 값이 false 다 (`composition.js` 주석). 그 사이 온 Tab·Enter·방향키를 가로채 칸을 옮기면 조합 글자가 확정 전에 편집기와 함께 사라질 수 있다 (추정)
- H6: 영문 키 입력으로 줄 단위로 표를 치는 `F-139 A2` e2e 는 통과한다. 한글 입력에서만 생기는지, 사람 확인 당시 dev 서버(작업 트리)에 섞여 있던 커밋 전 F-146 코드 때문인지 모른다

## 3. 요구사항

### 3.1 칸 안 키가 칸 진입 처리로 새지 않게
- `td`/`th` 의 keydown(Enter·Space 로 편집 시작)은 **이벤트 대상이 칸 요소 자신일 때만**(칸에 키보드 포커스가 있고 편집 중이 아닐 때) 동작한다. 하위 에디터 안에서 올라온 키는 건드리지 않는다
- 칸에 Tab 으로 포커스한 뒤 Enter·Space 로 편집을 시작하는 기존 동작은 그대로

### 3.2 조합 중 키 가로채지 않기
- `cellKeydown` 은 `event.isComposing` 이거나 `event.keyCode === 229` 이거나 하위 에디터가 조합 중(`composing` 또는 `compositionStarted`)이면 아무 키도 가로채지 않는다 (Tab·Enter·방향키·Esc·단축키 전부)
- 조합이 끝난 뒤 칸 이동·편집 종료가 일어나면, 그 전에 조합 결과가 주 문서의 그 칸 범위에 반영돼 있어야 한다 (F-135 3.4 따라잡기 그대로)

### 3.3 표 원문을 줄 단위로 치며 한글 입력 (H6)
- F-146 커밋 뒤 코드에서, 편집 모드 새 줄에 `| 이름 | 값 |⏎| --- | --- |⏎| 가 | 나 |` 를 한글 포함 입력으로 쳐서 원문이 친 그대로 남는지 e2e 로 확인한다
- 재현되면 원인을 찾아 고친다 (F-139 3.2 와 같은 경로 조사). 재현되지 않으면 시도한 입력 방법과 결과를 보고하고 사람 확인으로 남긴다

### 3.4 e2e 에서 한글 조합 흉내
- Playwright 의 CDP 세션(`page.context().newCDPSession(page)`)으로 `Input.imeSetComposition`(조합 중 글자)과 `Input.insertText`(확정)를 보내 조합 입력을 흉내 낸다. 이 방법으로 `compositionstart/update/end` 가 실제로 발생하는지 먼저 확인하고, 발생하지 않으면 해당 기준은 "자동 판정 불가" 로 보고한다
- 흉내 입력은 헬퍼로 만들어 `e2e/table.spec.js` 안에 둔다 (`e2e/helpers.js` 는 이 명세 소유가 아니다)
