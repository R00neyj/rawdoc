# F-254 커서가 기호 위에 있을 때만 목록 기호를 원문으로

작성일: 2026-09-18
상태: 사용자 승인 (2026-09-18 "불릿포인트 / 수정중에도 미리보기 처럼 노출 / 정확히 포커스가 불릿포인트일때만 -로 보임 / 이렇게 해야 포커스된 줄에서 너무 크게 좌우로 움직이는 거 막을 수 있을듯")
근거: `specs/features/F-152.md` 2.3(목록 기호 폭·내어쓰기), `F-236`(중첩 안내선), `F-251`(중첩 들여쓰기 고정 폭), `F-146` 3.2(포커스와 활성 줄)

## 1. 범위

### 문제

지금은 **커서가 목록 줄 어디에 있든** 그 줄 전체가 원문으로 돌아간다(`src/editor/preview/lines.ts` `buildLines` 의 `active.has(line)` 분기). 그래서 `•` 위젯이 `- ` 로, 중첩 들여쓰기 고정 폭 위젯(F-251)이 원래 공백으로 한꺼번에 바뀌고, 본문 글자가 좌우로 크게 튄다. 문장 중간을 고치는 중에도 매 줄 이동마다 흔들린다

### 한다
- 목록 기호는 **커서가 기호 구역 안에 있을 때만** 원문(`- `, `1. `)으로 보인다. 그 밖(본문 쪽)에 있으면 편집 중에도 보기 모드와 같은 `•`·기호 폭을 유지한다
- 중첩 들여쓰기 위젯(F-251)과 안내선(F-236)도 같은 판정을 따른다 — 커서가 본문에 있으면 유지한다
- "기호 구역" = 줄 시작부터 `ListMark` 끝 + 뒤 공백 1칸까지 (숨김 범위와 같은 기준, `hideMarkAndSpace`)
- 기호 구역에 커서를 둘 수 있어야 한다 — `Home`·왼쪽 방향키·기호 위 클릭으로 들어가면 원문으로 바뀐다

### 하지 않는다
- 헤딩(`#`)·인용(`>`)·강조 기호의 활성 줄 규칙 변경 — 이번엔 목록만
- 체크박스(`- [ ]`)의 `TaskMarker` 위젯 규칙 변경 — `ListMark` 는 지금도 숨기고 있고, 그 앞 기호 구역 판정만 같은 규칙을 받는다
- 목록 기호 자체의 모양·폭·색 변경 (F-152·F-251 값 그대로)
- 위젯을 atomic 으로 만들기 — 커서가 기호 안으로 못 들어가면 고칠 수 없다

## 3. 요구사항

### 3.1 판정

한 줄에 대해 "기호 구역에 커서가 있다" 는:

- 주 선택(`state.selection.main`) 뿐 아니라 **모든 range** 를 본다
- `range.from <= 구역끝` 이고 `range.to >= 줄시작` 이면 구역 안으로 본다(빈 커서·선택 범위 모두)
- 구역끝 = `ListMark.to` + 뒤 공백 1칸(있을 때). 즉 `- 하나` 에서 커서가 `하` 앞이면 **구역 안**이다(지금 커서 앞의 공백이 기호의 일부라서, 여기서 원문이 아니면 Backspace 대상이 안 보인다)
- 편집기 포커스가 없으면(F-146 3.2 `hasFocus=false`) 지금처럼 모두 보기 모드

## 7. 구현 중 명세와 달라진 것 (2026-09-18, 메인 승인)

`TaskMarker` 분기의 활성 판정도 앞 `ListMark` 의 기호 구역 판정을 그대로 받는다. 2장 "하지 않는다" 의 "`TaskMarker` 위젯 규칙 변경 안 함" 은 **위젯 구조·`checked` 판정을 두라는 뜻**이고, 활성 판정 기준까지 옛 `active.has(line)` 로 두면 C8(체크박스 줄 본문에 커서 → 위젯 유지)이 성립하지 않는다(줄 전체가 원문으로 남는다). `CheckboxWidget` 자체는 손대지 않았다
