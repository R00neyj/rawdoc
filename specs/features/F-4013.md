# F-4013 금고 보강 묶음 — 방 지우기 재시도·잠금 실패 알림·잠금 뒤 평문·동시 동작·GitHub 첨부·템플릿

상태: 승인 — 사용자 상시 지시("p2까지 수정", 9장 Q1~Q3 기본값대로, 별도 검토 없음). 코드리뷰 발견 6건을 2026-10-19 HEAD 코드로 확인했다(오탐 없음, 단 5번 서버 쪽은 단독으로는 존재 여부만 새고 클라이언트 쪽과 겹칠 때 평문이 나간다). 전부 node 단위, e2e 없음(브라우저만 보이는 동작이 없다). App.tsx 변경 없음

## 근거 (이름으로 찾는다)
- **R1** `worker/e2eeDocs.ts` `purgeBeforeResponse`: 2번 실패하면 `console.error('e2ee_purge_failed')` 뒤 `false` 만. `handleSetDocE2ee` 는 `purged: false` 로 200, 클라이언트는 E40 경고(`appNotices.ts`)뿐 아무도 다시 지우지 않는다. 휴지통 영구 삭제의 방 작업(`trash.ts` `purgeTrashStatements`)은 `e2ee_key IS NULL` 만 넣고, 계정 삭제(`account.ts`)만 전부 넣는다 → 옮기기 전 평문 Yjs 가 DO 저장소에 계정 삭제까지 남는다. `purge_jobs` 는 `docs` 를 참조하지 않아(FK 없음) 문서 행이 지워져도 남는다. DO 는 금고 문서를 없는 문서로 보고 소켓도 막혀(F-401 X15·X16) 저절로 깨어나 지우지 않는다
- **R2** `useE2ee.ts`: E14 는 `lockManual` 만 띄운다. `checkIdle`(15초마다)·`handleOtherTabLock`·`lockForAccountChange`·`page-restore`·`retryDeferredLock`·`load()` 의 `reset` 은 `'aborted'` 를 조용히 버린다 — F-404 4.1 표("`aborted`, 알림 E14")와 다르다. `useDocSaver.flush` 는 저장이 한 번 실패하면 dirty 를 비운 채 `failedRef` 로 계속 `false` → `too-large`·`too-many-refs`(`e2eeStore.ts` `checkPlainContent`)처럼 본문을 줄이기 전엔 안 풀리는 실패면 자동 잠금이 영영 조용히 실패한다
- **R3** `e2eeStore.ts` `create`·`update`·`setDocE2ee`(옮기기): 아래 저장소 `await` 뒤 세대 확인 없이 `plainMemo`·`docKeys` 에 넣고 `decode` 로 열린 평문을 돌려준다. 잠그기 `indexes`(`clearPlainCache`)와 `masterKey = null` 사이에 끝나면 메모 경로라 평문이 그대로 나가고, 그 뒤에도 다음 `currentMasterKey()` 호출까지 메모리에 남는다(`decode`·`decodeSummary`·`getAttachment` 는 이미 세대를 본다)
- **R4** `keyring.ts` `runExclusive`: 진행 중인 동작이 있으면 **그 동작의** Promise 를 `T` 로 속여 돌려준다. 예: `open` 중 `reset()` → 호출자는 `null` 을 받아 `result.ok` 에서 터진다, `createStart` 중 `open()` → 객체를 오류 코드로 읽는다
- **R5** `useGithubFlow.ts` `readAttachment`: `rec.e2ee` 를 거르지 않는다(금고가 열렸으면 `e2eeStore.getAttachment` 가 복호화한 바이트). `githubPush.ts` `uploadableNames`: `owner_id` 조건 없이 `e2ee = 0 AND id IN …`. `attachments` PK 가 `(owner_id, id)` 라 남이 같은 `id.ext` 평문을 가지면 내 금고 첨부가 `missing` 으로 분류되고 클라이언트가 평문으로 GitHub 에 올린다
- **R6** `templates.ts` `listTemplates` 는 `e2ee === 'locked'` 만 뺀다. 열린 금고 문서는 새 문서·달력 문서 템플릿·팔레트 삽입에 쓰여 본문이 일반 문서로 복사된다(`useNewDocTemplate.readTemplateDocText`). 템플릿 폴더는 트리·검색에서 숨으므로 목록에서 아예 빼면 템플릿 관리 창에서도 사라져 그 문서에 닿을 길이 없다

## 2. 동작
### 2.1 방 지우기 재시도 (R1)
- 금고로 **옮기기**에서 `purgeBeforeResponse` 가 `false` 면 응답 전에 `INSERT INTO purge_jobs (kind, target, priority, created_at) VALUES ('room', ?1, ?2, ?2) ON CONFLICT (kind, target) DO NOTHING`(`?2` = `now`). 이 문장이 던지면 `console.error('e2ee_purge_enqueue_failed', docId)` 뒤 응답은 그대로. 응답 `purged: false`·E40 문구는 바꾸지 않는다(Cron 이 지우기 전까지 사실이다). 10분 Cron `runPurgeJobs` 가 기존대로 처리한다
- 금고에서 **빼기**는 작업을 넣지 않는다(이제 평문 문서라 남은 옛 기록은 비밀이 아니고, 늦게 도는 작업이 살아 있는 방을 지우면 편집이 끊긴다). 대신 `setDocE2eeStatements` 의 빼기 갈래 끝에 `DELETE FROM purge_jobs WHERE kind = 'room' AND target = ?1 AND EXISTS (SELECT 1 FROM docs WHERE id = ?1 AND e2ee_key IS NULL)` — 1번 문장이 0행(버전 충돌)이면 금고 그대로라 지우지 않는다. 옮기기 갈래 문장 수(13)는 그대로
- `trash.ts` 의 `e2ee_key IS NULL` 은 **그대로 둔다**: 실패한 문서는 이제 자기 작업 행이 있고 문서 행이 지워져도 남는다. 나머지 금고 문서는 방이 없어 부를 이유가 없다
- 받아들이는 경합: Cron 이 행을 읽은 뒤 빼기가 끝나면 그 방을 한 번 지운다 — DO 가 D1 본문으로 다시 시작하고 그 사이 몇 초 편집만 잃는다
- 배포 뒤 한 번(옛 실패분, 5장): 금고 문서 전부를 우선순위 0 으로 넣는다

### 2.2 잠금 실패 알림 (R2)
- `KeyringDeps` 에 `onLockAborted?: (reason: E2eeLockReason) => void`. `lock()` 결과가 `'aborted'` 면 부른다 — 모든 이유(`manual`·`idle`·`other-tab`·`account`·`page-restore`·`load()` 의 `reset`)와 `retryDeferredLock` 경로를 한 곳에서 덮는다. **열린 한 번에 한 번만**(F-404 4.1 규칙을 열쇠고리로 옮긴다): 부른 뒤 표지를 세우고 상태가 `open` 이 될 때 내린다. `reset()` 안의 잠그기는 부르지 않는다(초기화 대화상자가 이미 실패를 보인다)
- `useE2ee` 는 `onLockAborted` 에서 E14 `저장하지 못한 금고 문서가 있어 금고를 잠그지 못했습니다.`(error) 를 띄운다. 문구·종류는 F-404 7.9 그대로
- 영구 실패를 따로 가르지 않는다(8장 Q1): 키는 버리지 않고 `open` 유지, 자동 잠금은 15초마다 계속 시도. 본문을 줄여 저장이 성공하면 다음 시도에 잠긴다

### 2.3 잠금 뒤 평문 기억 (R3)
`create`·`update`·`setDocE2ee`(옮기기)는 `currentMasterKey()` 직후 `generation` 을 적고, 아래 저장소 `await` 뒤 `generation` 이 같고 `deps.getMasterKey()` 가 같은 MK 일 때만 `docKeys`·`plainMemo` 에 넣는다. 다르면 넣지 않고 `lockedShape` 를 돌려준다(`decode` 를 부르지 않는다 — MK 가 아직 남은 틈에 다시 풀지 않게). 쓰기 자체는 이미 끝났으므로 던지지 않는다

### 2.4 동시 동작 (R4)
`runExclusive(kind, busy, fn)`: `kind` 는 동작 이름(`open`·`createStart`·`createConfirm`·`changePassword`·`recoveryVerify`·`recoveryReset`·`recoveryConfirm`·`reset`). 진행 중인 것이 **같은 kind** 면 그 Promise(같은 타입, 지금의 두 번 누르기 묶음 유지), **다른 kind** 면 `fn` 을 부르지 않고 `busy` 로 끝난다. `busy` = 오류 코드 반환형은 `'failed'`, 결과 객체형은 `{ ok: false, error: 'failed' }`. 타입 단언(`as Promise<T>`)이 남지 않는다

### 2.5 GitHub 첨부 (R5)
- 서버 `uploadableNames(env, ownerId, names)`: `WHERE owner_id = ? AND e2ee = 0 AND id IN …`, `ownerId` = `c.user.id`(= 문서 주인, `openLink`). 공동 편집자가 넣은 그림(F-4012)은 이제 `skipped` 로 가고 푸시는 계속된다(지금은 `missing` → 읽기 실패 → 푸시 전체 실패)
- 클라이언트 `src/app/githubPush.ts` 에 `readPushAttachment(store: Pick<Store, 'getAttachment'>, name: string): Promise<Uint8Array | null>` — 기록이 없거나 `e2ee` 가 참이면 `null`(→ 기존 `그림을 읽지 못해 푸시하지 않았습니다 ({name})`). `useGithubFlow` 의 `readAttachment` 는 이것만 부른다

### 2.6 템플릿 (R6)
- `TemplateEntry` 에 `e2ee?: true` — `listTemplates` 가 `e2ee === 'open'` 문서 항목에 단다(`locked` 는 지금처럼 뺌). 관리 창은 그대로 보인다
- `usableTemplates(entries)` = `e2ee` 없는 항목. `resolveNewDocTemplate` 는 `e2ee` 항목을 `missing` 으로(→ 빈 문서, 알림 없음, 설정 칸은 `찾을 수 없는 템플릿`), `newDocTemplateOptions` 는 `user` 묶음에서 뺀다. `useCommandPalette` 는 팔레트 `templates` 와 `insertTemplate` 찾기 모두 `usableTemplates(templateEntries)` 를 쓴다
- 마지막 벽: `readTemplateDocText` 는 대상이 금고 문서(지금 문서면 `docs` 메타 `e2ee`, 아니면 `store.get` 결과 `e2ee`)면 `null`

코드 배포 뒤 한 번: `npx wrangler d1 execute md-editor-db --remote --command "INSERT INTO purge_jobs (kind, target, priority, created_at) SELECT 'room', id, 0, CAST(strftime('%s','now') AS INTEGER) * 1000 FROM docs WHERE e2ee_key IS NOT NULL ON CONFLICT (kind, target) DO NOTHING"`. 먼저 `SELECT COUNT(*) FROM docs WHERE e2ee_key IS NOT NULL` 로 수를 본다 — Cron 은 10분에 최대 29방(`PURGE_CALLS_ON_CRON`), 하루 약 4,100방이고 계정 삭제 작업(우선순위 = `updated_at`)이 먼저 돈다. 마이그레이션 파일 없음

## 8. 열린 질문
