# F-4003 잠긴 금고의 문서 숨김과 폴더에서 열기·잠그기

작성일: 2026-10-09
상태: 승인(2026-10-09). 사용자가 11장 Q1 을 기본값("그대로 둠")으로 골랐고 Q2·Q3 은 기본값대로 간다 — 별도 검토 없이 "결정이 없으면 바로 구현" 상시 지시로 승인한다. 사용자 요청 셋("잠금 해제 안하고도 안에 파일 몇 개 있는지 추정가능", "폴더 펼치기 자체에 잠금 풀수 있게", "다시 잠그기가 너무 멀리있음 … 우클릭 (...) 메뉴에 추가?")을 한 명세로 묶는다. 보안(`F-4NNN`)이고 노출 지점이 화면 스무 곳 넘게 흩어져 있어 전수 표를 싣는다 — 그래서 300줄 남짓이다
범위: `src/` 화면·알림만. 서버·저장소 형식·새 의존성·새 설정 키 없음. 불변조건 변경 없음

## 정해진 것 (사용자, 바꾸지 않는다)
1. 잠긴 동안 금고 문서의 **존재와 개수**를 화면 어디에서도 추정할 수 없게 한다
2. 잠긴 금고 폴더를 펼치려 하면 기존 D-11 `금고 열기`(`useE2ee` `requestOpen`)를 띄운다. 열리면 그 폴더를 펼치고, 닫으면 접힌 채. 잠긴 동안 금고 폴더는 펼쳐지지 않는다. 사이드바 안 인라인 암호칸은 없다
3. `금고 잠그기` 를 금고 폴더의 `⋯`·우클릭 메뉴에 넣는다. 이 탭에서 금고가 열려 있을 때만. 동작은 기존 잠그기(F-400 2.5 순서·탭 전파)와 같다. 상태바·팔레트·설정의 잠그기는 그대로
4. 폴더 이름은 평문이라 잠겨 있어도 보인다(F-400 결정 2)

## 2. 결론 (프롬프트가 결론을 요구한 것)

### 2.1 숨기는 지점 — App 이 **표시용 목록 하나**를 따로 만든다

- App `docs` 상태는 **거르지 않는다.** `currentDoc`(P1 판정·경로 `e2ee` 판정, F-405 7.5)·`useFolderActions`·`useDocNavigation`·`exportActions`·`wikiResolver`·`useGithubFlow` 는 지금처럼 전체를 본다. 거른 목록이 여기로 새면 해시로 연 잠긴 문서가 `currentDoc` 에서 사라져 P1 대신 빈 화면이 되고 경로가 `realtime` 으로 잘못 판정된다
- 대신 `listedDocs = hideLockedVaultDocs(docs)` 를 한 번 만들고, `ownedDocs` 를 그것에서 거른다. 받는 곳은 **표시만 하는 곳**: Sidebar `docs`, AppScreens `docs`(지도 `docCount`·빈 상태 `hasDocs`), 빈 상태 `recentDocs`
- Sidebar 는 받은 목록을 끌어 옮기기(`dedupeDescendants`)·선택 정리(`prune`)·폴더 메뉴 판정(`allDocs` → `e2eeMenuForFolder`)에도 쓴다. 셋 다 거른 목록이 맞다: 숨은 문서는 고를 수 없고, 선택에서 저절로 빠지고, r8 의 `금고에서 빼기…` 가 잠긴 동안 사라진다(금고 폴더 자신의 `금고에서 빼기…` 는 폴더 `e2ee` 로 정해지므로 남는다)
- **`store` 쓰기 경로에는 거른 목록을 넘기지 않는다.** 폴더 삭제·이동은 저장소가 처리하므로 숨은 문서도 함께 움직인다 — 2.5
- **기준은 문서 상태 하나**: `e2ee === 'locked'` 면 숨긴다(금고 상태와 무관). 상태로 거르면 r6 의 틈(③~⑥)에 `잠긴 문서` 행이 한 번 그려져 개수가 보인다. 결과로 **열린 동안 풀지 못한 손상 문서**(F-405 6.2 `damaged`)도 목록에서 빠진다 — 11장 Q3

계약 (`src/app/vaultVisibility.ts`, `E2eeStatus` 는 type import 만):

### 2.2 해시로 직접 연 잠긴 금고 문서 — **P1 유지**, 자동 고르기에서는 뺀다

- `#/d/{id}` 를 직접 열면 지금처럼 P1. 주소를 가진 사람만 닿고 개수를 드러내지 않는다. 숨기면 즐겨찾기·뒤로 가기가 막다른 길이 된다
- 위키링크는 이미 닿지 않는다(r7 — 잠긴 문서는 해석되지 않고 끊긴 링크)
- **앱이 스스로 고르는 세 곳(r10)은 잠긴 금고 문서를 건너뛴다**(`firstListedDocId`). 시작 화면 `마지막 문서`·없는 해시·지금 문서 삭제 뒤 앱을 연 사람에게 P1 이 뜨면 금고 문서가 있다는 것이 드러나서다. `resolveInitialDoc` 은 해시 판정에는 전체 목록, `fallbackDocId` 에만 건너뛰기를 쓴다 — `md.lastDocId` 가 잠긴 금고 문서여도 해시가 없으면 다음 문서(없으면 홈)

### 2.3 펼침 상태 기억

- **잠글 때 `md.openFolders` 를 고치지 않는다.** 표시층(Sidebar)이 `visibleOpenFolderIds` 로 잠긴 동안만 금고 폴더를 접힌 것으로 그린다. 저장된 펼침으로 부팅하거나 해시 열기가 조상을 펼쳐 넣어도(r3) 같은 규칙으로 접혀 보인다
- 열리면(어느 길로든) 저장된 대로 다시 펼쳐진다 — 사용자가 둔 모양으로 돌아온다. 잠글 때 쓰기를 하나 더 하지 않는다
- 이 접힘은 `aria-expanded`, 펼침 아이콘, `visibleOrder`(Shift 범위 선택), 접힌 폴더의 안 읽음 점(`unreadFolderIds`) 모두에 같은 목록으로 적용한다

### 2.4 상태별 펼치기 (`unlockVaultFolder`, 금고 폴더를 펼치려 할 때만)

1. 상태가 `unknown`·`loading`·`unavailable` 이면 먼저 `load()`
2. `open` 또는 `none` → `expand(id)`(= `addOpenFolders([id])` — 저장된 펼침이 이미 있을 수 있으므로 토글이 아니라 "펼친 상태로")
3. `locked` → `requestOpen()`(D-11). `true` 면 `expand(id)`, `false`(Esc·바깥 클릭) 면 아무것도 안 함
4. 그래도 `unavailable` → `notifyUnavailable()`(E48), 접힌 채. `requestOpen` 을 부르지 않는다

- `none` 에서 펼치는 이유: 열 금고가 없고(r4 의 D-8 을 피한다), 그 안 문서는 어차피 `locked` 라 숨는다. 금고 폴더가 있는데 금고가 없는 상태는 다른 기기 초기화 직후의 낡은 목록뿐이다
- 문은 **금고 폴더**에만 있다. 일반 폴더는 잠긴 문서가 들어 있어도 지금처럼 펼치고, 그 문서는 숨는다
- 범위가 없으면(`e2ee === null`, 메모리 저장소·공개 보기) Sidebar 에 `vault` 를 주지 않고 지금 동작 그대로

### 2.5 잠긴 금고 폴더에 끌어 놓기·새 문서·삭제

| 동작 | 결과 | 바뀜 |
| --- | --- | --- |
| `⋯` `새 문서`·상단 `새 문서`·가져오기 | F-405 2.4 그대로 — D-11, 열리면 만들고 조상을 펼쳐 넣는다 → 문이 열려 있어 펼쳐 보인다 | 없음 |
| 일반 문서·일반 폴더를 끌어 놓음 | E19 그대로. 문구는 대상 폴더 규칙만 말하고 내용을 드러내지 않는다 | 없음 |
| 금고 폴더를 끌어 놓음 | 허용(F-405 4.5) — 접힌 폴더 안으로 들어가 안 보인다. 놓을 때 펼치지 않는다 | 없음 |
| 폴더 `삭제` | `empty = folderLooksEmpty(…)`: 문이 `locked` 인 금고 폴더는 **늘 `false`**(두 갈래 대화상자 — 안의 문서·하위 폴더 유무가 대화상자로 드러나지 않게). 그 밖의 폴더는 잠긴 금고 문서를 빼고 센다 | **바뀜** |

- 빈 것처럼 보이는 일반 폴더를 지우면 `empty` 갈래의 `move-up`(r9)이라 숨은 금고 문서는 **지워지지 않고 부모로 올라간다**. 사람이 고른 적 없는 이동이지만 데이터가 사라지지 않는 쪽이다
- 여러 항목 삭제·이동은 보이는 행만 고를 수 있어 바꿀 것 없음


- `gate === 'locked'` 일 때 금고 폴더 행의 펼치기 단추·이름 단추(일반 클릭)는 `onToggleFolder` 대신 `onUnlockFolder(id)` 를 부른다. Ctrl·Shift 클릭(선택)은 그대로
- **접근 이름은 바꾸지 않는다** — `{이름} 펼치기` 그대로. 누르는 뜻(펼치기)이 같고, 행의 자물쇠(`aria-label="금고"`)와 뜨는 대화상자 제목 `금고 열기` 가 이유를 말한다. 기존 e2e 선택자도 그대로다. 대신 그때만 두 단추에 `aria-haspopup="dialog"` 를 단다
- `displayTitleOf` 의 `잠긴 문서` 갈래·`LOCKED_DOC_TITLE`·`doc-item-btn--locked` 는 받는 목록에 잠긴 문서가 없으므로 지운다(CSS 포함)

### 3.2 `금고 잠그기` 메뉴 항목

- 조건: 금고 폴더 행, `vault.gate === 'open'`, 단독 메뉴(여러 항목 메뉴에는 없음)
- 항목: `{ key: 'e2ee-lock', label: '금고 잠그기', icon: IconLock, onSelect: vault.onLock }`
- 자리: 금고 항목(`금고에서 빼기…`) 바로 뒤, `삭제` 앞. 결과 순서 — `새 문서` · `하위 폴더` · `이름 변경` · `폴더 내보내기` · `옵시디언 볼트로 내보내기` · `금고에서 빼기…`(맨 바깥 금고 폴더만) · `금고 잠그기` · `삭제`
- `onLock` = `e2ee.openSettingsDialogs.lockNow`(상태바와 같은 `lock('manual')`, 실패 알림 포함). 탭 전파·잠그는 순서는 F-404 4장 그대로
- 메뉴가 닫힌 뒤 초점은 다른 항목과 같다(`FolderMenu` `selectItem`). 잠기면 그 폴더는 접히고 행은 남는다

### 3.3 `useVaultGate`

```ts
export function useVaultGate(input: {
  e2ee: UseE2ee | null
  probe: boolean                      // 검색 대화상자 또는 지도가 떠 있다
  requestOpen: () => Promise<boolean> // App requestE2eeOpen
  expandFolder: (id: string) => void  // addOpenFolders([id])
  showNotice: (n: { type: 'error'; message: string }) => void
}): SidebarVault | undefined          // e2ee 가 null 이면 undefined
```

- `probe` 가 참이 되는 렌더에 상태가 `unknown` 이면 `keyring.load()` 를 한 번 부른다 — F-404 3.2 "읽는 때" 에 ⑤ 검색·지도 열 때를 더한다(팔레트 ②와 같은 방식). 4장의 안내 줄이 금고 주인에게 문서 유무와 무관하게 뜨려면 상태를 알아야 해서다
- 내보내기는 `exportActions.ts` 가 같은 일을 직접 한다(시작할 때 `unknown` 이면 `await load()`) — ⑥
