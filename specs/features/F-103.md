## 3. 요구사항

### 3.1 `createEditor(parent, options) → handle`
options: `{ text, viewMode, onDocChange(state), onSelectionChange(state) }`
- `text` 는 저장소 `content` 를 그대로 받는다. `EditorState.lineSeparator` 를 **지정하지 않는다** — CM6 기본값이 `\r\n`·`\r`·`\n` 을 모두 줄 구분으로 읽는다 (`@codemirror/state` d.ts `lineSeparator` 주석, `specs/product.md` Q9)
- 확장
  - `lineNumbers()`, `history()`, `EditorView.lineWrapping`
  - `markdown({ base: markdownLanguage })` — 기본 base 는 GFM 표를 파싱하지 않는다 (spike `index.js` 86~88행)
  - `keymap.of([...defaultKeymap, ...historyKeymap, indentWithTab])`, `indentUnit.of('  ')`, `EditorState.tabSize.of(2)`
  - `highlight.js` 의 `syntaxHighlighting` (F-107)
  - 보기 모드 `Compartment` 두 개: 프리뷰 확장(`preview/index.js` 의 `livePreview()`), 모드별 속성(`EditorView.editorAttributes` 로 `data-view="live|raw"`)
  - F-109 단축키 keymap
  - `composition.js` 확장
- `basicSetup` 을 쓰지 않는다. 자동완성·검색 패널을 넣지 않는다. 괄호·강조 기호 자동 짝은 F-127 이 따로 넣는다 (2026-09-14 변경, 사용자 입력 편의성 요청)
- handle
  - `view`
  - `getText(lineEnding)` → `state.doc.sliceString(0, state.doc.length, lineEnding === 'crlf' ? '\r\n' : '\n')`
  - `focus()`, `setCursorToStart()`
  - `setViewMode(mode)` (F-107), `destroy()` (두 번째 호출은 무시)

### 3.2 조합 종료 따라잡기 (`composition.js`, CLAUDE.md 불변조건)
- `export const forceRecalc = StateEffect.define()`
- `export function isComposing(view)` → `view.composing`
- `export function isForced(update|transaction)` → effect 포함 여부
- 확장: `compositionend` 에서 `setTimeout(0)` 뒤 destroy 여부 확인 후 `view.dispatch({ effects: forceRecalc.of(null) })`
- 이유와 함정은 spike `index.js` 9~19·60~103행 주석, `.workflow/architecture.md` 3장(`compositionstart` 시점 `view.composing` 은 false)을 옮겨 적는다. `imeLog` 는 가져오지 않는다

### 3.3 `Editor.jsx`
- props: `docId`, `text`, `lineEnding`, `viewMode`, `onDocChange`, `onSelectionChange`, `autoFocus`, `ref`
- `autoFocus` 가 true 면 뷰를 만든 직후 `focus()` + `setCursorToStart()`. React StrictMode 가 dev 에서 뷰를 한 번 부수고 다시 만들어도 최종 뷰가 포커스를 받게 하려는 것이다 (2026-09-14 추가, dev 전용 포커스 유실 수정)
- 마운트 시 1회 생성, 언마운트 시 destroy. `App` 은 `key={docId}` 로 문서마다 새로 마운트한다
- `text` prop 이 나중에 바뀌어도 에디터 내용을 바꾸지 않는다 (역방향 동기화 금지 — architecture.md 3장)
- `ref` 로 handle 노출 (React 19 ref prop)
- StrictMode 이중 effect 에서 에디터가 2개 생기지 않는다

### 3.4 App 연결
- 문서를 열면 `store.get(id)` → `<Editor key={id} text={doc.content} …>`. 본문을 React state 에 오래 두지 않는다(열 때 넘기는 용도만)
- 목록 클릭 전환 후 에디터 포커스 + 커서 문서 맨 앞 (ia.md 3.4). 새 문서·최초 실행은 에디터에 포커스를 주지 않는다 (3.1·3.3)
- 제목 입력 Enter → `handle.focus()`
- S-2 에서는 에디터를 마운트하지 않는다

### 3.5 스타일
- `.cm-editor` 높이는 편집 영역 전체, 내부 스크롤. 내용 최대 너비 `--content-max`(줄 번호 포함) 가운데 정렬, 편집면 배경 `--panel`, 바깥 `--paper`
- 글자 크기 15px, 줄 높이 1.75. 줄 번호: `--font-mono` 12px `--muted`
- `data-view="live"`: 본문 `--font-sans`. `data-view="raw"`: 전체 `--font-mono`
- 커서 색 `--accent`, 선택 영역 `--accent-soft`. `.cm-focused` 기본 점선 외곽선은 끄고 편집 영역 바깥 테두리 등으로 포커스를 표시하지 않는다(편집면 자체가 포커스 대상)
- 기존 `EditorView.baseTheme` 에 hex 를 쓰지 않는다. 전부 CSS 변수

### 3.6 키보드 빠져나가기 (ia.md I3)
- CM6 는 Esc 를 누르면 2초 동안 tab-focus 모드를 켠다 (`@codemirror/view` `dist/index.js` `handlers.keydown`: `keyCode == 27` → `tabFocusMode = Date.now() + 2000`). 별도 구현하지 않는다
- 이 동작을 막지 않도록 Esc 를 가져가는 keymap 을 추가하지 않는다
