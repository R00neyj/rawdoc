## 2. 결정

1. **부팅은 저장된 검사 결과를 적용만, 앱은 원문에서 다시 컴파일해 이어받는다**(F-2094 6.2). 부팅 값이 없거나 낡으면 부팅은 아무것도 안 하고 앱이 한 번 늦게 칠한다
2. **이어받기 = 글이 같은 시트는 그대로 둔다.** 부팅이 만든 시트·글을 `window.__userCssBoot` 에 걸고, 앱은 새 컴파일 글과 글자 그대로 같은 시트를 다시 쓰고 다른 칸만 새로 만들어 `document.adoptedStyleSheets` 에 **한 번 대입**한다. 평소엔 DOM 이 전혀 안 바뀐다(다시 계산·`data:` 글꼴 다시 읽기·rev 증가 없음). 우리 시트는 늘 한 목록이고 바꾸는 일은 한 태스크 안 대입 한 번 → 두 번 적용·빈 순간이 없다
3. **공개 보기** = 부팅은 `data-boot-view="off"` 와 **같은 판정**(해시 `#/p/`·`#/p/f/`, 경로 `/p/…`·`/p/f/…` — 개요는 `#/p/` 만 적었다), 앱은 `publicRoute !== null`. 공개 보기에선 컴파일도 안 한다. 서식 있는 복사는 코드 변경 없음(개요 2.4)
4. **슬롯** = 개요 2.3 그대로. 계정 id 는 부팅에서 `storedAccount()` 규칙(`md.account` JSON 의 `id`·`email` 이 둘 다 문자열), 앱에서 `usePushDevice` 의 `userId` 식(`in`→id, `offline`→저장 id, `out`→없음). 앱 초기 상태가 `offline` 이라 부팅 직후 두 답이 같다
5. **안전 모드** = 질의를 `&` 로 나눈 조각 중 첫 `=` 앞이 정확히 `safe` 인 것이 있으면(값·위치 무관, 디코딩 없음 — 부팅이 `URLSearchParams` 를 못 쓰므로). 부팅과 앱이 같은 규칙, 표 테스트로 묶는다
6. **같은 탭 변경은 바로, 다른 탭·서버 변경은 조합이 끝난 뒤**(개요 2.5). 조합 판정은 `useE2ee.ts` 모양 — `window` 캡처 `compositionstart`/`compositionend` 표시 ∧ `document.hasFocus()` ∧ `visibilityState === 'visible'`, 밀린 적용은 `compositionend` 뒤 `setTimeout(0)`·`blur`·`visibilitychange` 에서 푼다
7. **"다섯 전역만"(F-2015 4.3)은 그대로 지킨다.** 새 단계의 호스트 전역은 `document`·`localStorage`·`location` 뿐, 생성자와 이어받기 자리는 `document.defaultView` 로 얻는다. `JSON` 은 ECMAScript 내장(지금도 `Math`·`Number` 를 쓴다). 가짜에 `search`·`defaultView` 가 없으면 조용히 건너뛰므로 기존 `run()` 테스트는 그대로 초록
8. **컴파일러는 정적 import** — 마운트 효과에서 동기로 돌아 공개 보기 전환·계정 바뀜과 순서가 엇갈리지 않는다. 대가 첫 번들 +4KB gzip(M2)

## 3. 부팅 스크립트 — 마지막 단계, 자기 `try`

이 순서, 멈출 때마다 `data-user-css` 를 넣는다. 읽기마다 따로 감싼다(F-2015 4.3).

1. 안전 모드 → `safe`, 끝 (`location.search` 가 문자열 아니면 `''`)
2. 공개 보기 → `off`, 끝
3. `md.userCssBoot` 를 `JSON.parse` — 객체 아님·`v` ≠ `USER_CSS_CHECKER_VERSION` → `off`, 끝
4. 슬롯: 계정 없음 → `local`. 계정 id 있음 → `account.userId === id` 일 때만 `account.sheets`, 아니면 `off`, 끝
5. 목록이 배열 아님·50개 초과·문자열 아닌 원소·길이 0 → `off`, 끝
6. `document.defaultView.CSSStyleSheet` 또는 `document.adoptedStyleSheets` 없음 → `off`, 끝
7. 원소마다 시트 + `replaceSync`. 하나라도 던지면 **하나도 안 붙이고** `off`, 끝
8. 기존 `adoptedStyleSheets` 뒤에 이어 **한 번 대입**, `defaultView.__userCssBoot = { sheets, texts }`, `on`, rev `1`

빈 문자열 원소도 시트 하나(F-2094 6.1 — 길이 = 켠 수). ES2017 이하. 부팅 값이 없으면 비용은 `getItem` 한 번.

## 4. 앱 — 적용·이어받기

**시트 묶음(`createUserCssSheets`)** — 만들 때 `__userCssBoot` 가 모양이 맞고 시트가 모두 문서에 있으면 가진 목록으로 삼는다. 어느 쪽이든 그 속성을 지운다. `apply(items, mode)`: `planUserCssSheets` 로 칸마다 재사용할 시트를 정하고(아래) `null` 칸만 새로 만든다 → 목표 = 문서의 `adoptedStyleSheets` 에서 가진 시트를 뺀 나머지(순서 유지) + 새 목록 → 지금과 칸마다 같은 객체면 대입 안 함, 다르면 한 번 대입하고 rev + 1 → `data-user-css` 는 늘 `mode` 로. `replaceSync` 가 던지면 그 칸은 빈 시트(개수·순서 유지).

**`planUserCssSheets(prev, next)`** — `next` 의 칸마다 `prev` 에서 아직 안 쓴, 글이 같은 가장 앞 칸 번호, 없으면 `null`. `['a','b']→['b','a']` = `[1,0]`, `['a']→['a','a']` = `[0,null]`.

**`refresh()`** — 안전 모드 → `apply(null,'safe')` / 공개 보기 → `apply(null,'off')` / 아니면 `readUserCssSources` → `selectSlot` → 켠 것만 → `{ name, css: compileCached(원문).css }` → `apply(items, 개수>0 ? 'on' : 'off')` → `isBootCurrent` 가 거짓일 때만 `writeUserCssBoot`(평소엔 1MB 가까운 값을 부팅마다 다시 쓰지 않는다) → 캐시를 두 슬롯 원문으로 줄인다.

| 부르는 때 | 방식 |
| --- | --- |
| 마운트, `isPublic`·계정 id 바뀜 | `useLayoutEffect` — 공개 보기 커밋이 칠해지기 전에 뺀다. 상한 이어받기 약 30ms(F-2094 A15), 그동안 화면은 스켈레톤 + 이미 먹은 부팅 시트 |
| `notifyUserCssChanged('self')` | 바로 |
| `notifyUserCssChanged('remote')`, `storage` 이벤트 key `md.userCss`·`md.userCssAccount`·`null` | `createDeferredRun`(조합 중 미룸) |

`md.userCssBoot`·`md.account` 의 `storage` 이벤트는 듣지 않는다(쓴 탭이 이미 맞췄고, 계정은 이 탭의 `useAccountStatus` 가 주인).

## 5. 안전 모드 — `/?safe`

- 부팅·앱 모두 붙이지 않고 `safe`. 저장값을 읽지도 쓰지도 않는다. 이 창에서 F-2096 이 저장하면 저장만 되고 적용은 `refresh()` 에서 막힌다(개요 3.3). `appliedUserCss()` = `[]`
- 알림: 마운트 때 안전 모드이고 공개 보기가 아니면 한 번 `warn` — `사용자 CSS 를 끄고 열었습니다.` + `다시 켜기`(개요 5.8). `warn` 인 까닭: 닫을 때까지 남고 뒤 `info` 에 밀리지 않는다(`pushNotice`) — 앱이 망가져 들어온 사람이 버튼을 놓치지 않게
- 주소에서 지우는 때는 **`다시 켜기` 뿐**: `await beforeReload()` 뒤 `location.replace(urlWithoutSafe(…))`. `safe` 조각과 빈 조각을 빼고 나머지 순서 유지, 남는 것 없으면 질의 없이, 해시 그대로. (`/`,`?app=1&safe`,`#/d/x`) → `/?app=1#/d/x`. 그 밖엔 앱이 안 지운다 — 해시 이동·`window.open(formatHash…)` 새 탭에 `?safe` 가 따라간다(예외: 푸시 `reload` 갈래는 `target.url` 로 바꿔 풀린다 — 받아들인다)
- 설정 탭의 안전 모드 줄(F-2096)은 `data-user-css === 'safe'` 로 판정한다

## 6. 저장

- **읽기:** 슬롯 값이 빈 값·깨진 JSON·`validateUserCssSnippets` 실패면 로컬 `[]`/계정 `null`. 계정 슬롯은 `userId`(빈 문자열 아님)·`snippets` 만 읽는다(`rev`·`pending` 등은 F-2099). 깨진 값을 읽었다고 고쳐 쓰지 않는다
- **`saveLocalSnippets`** (F-2096 이 부른다), 첫 실패에서 멈춤: `checkUserCssLimits` → `count`/`bytes` · 검증 실패 → `invalid`(쓰면 다음 읽기가 목록 전체를 버린다) · `trySetPref('md.userCss', …)` 실패 → `quota`(아무것도 안 바뀜) · `writeUserCssBoot` 실패 → 부팅 값을 `''` 로(낡은 결과를 쓰느니 늦게 칠함) · `notifyUserCssChanged('self')` → `ok`. 원문·부팅 값은 같은 호출 안(개요 4.2)
- **`isBootCurrent`**: 3장 3~5번과 같은 규칙으로 부팅이 적용할 목록을 구해 `texts` 와 칸마다 같으면 참. 부팅 값이 비었거나 깨졌으면 `texts` 가 빈 목록일 때만 참
- **한도:** M1 로 상한 최악도 한도의 40%. `quota` 는 다른 무엇이 같은 출처에 3MB 넘게 쓸 때만 난다 → e2e 로 두지 않고 단위(던지는 가짜)로 본다
- **경계:** F-2096 = 결과 코드 → 문구(`invalid`·`quota` 문구는 F-2096 이 정한다), D-16 의 규칙 수는 자기가 부른 `compileCached` 의 `ruleCount`. F-2097 = `appliedUserCss()`. F-2098 = `data-user-css-rev` 관찰 — 이 명세는 DOM 의 사용자 시트가 실제로 바뀔 때만 올린다. F-2099 = `md.userCssAccount` 쓰기 뒤 같은 호출에서 `writeUserCssBoot(readUserCssSources())` + `notifyUserCssChanged('remote'|'self')`

## 11. 열린 질문

### Q1. 로그인했는데 계정 슬롯이 없을 때 — **기본값: 개요 2.3 그대로, 아무것도 적용 안 함**

계정 슬롯은 F-2099 가 만든다. 그래서 **F-2099 전까지 로그인한 사람에게는 사용자 CSS 가 안 먹는다** — F-2096 이 먼저 나가면 로그인한 사람의 스니펫이 저장만 되고 안 보인다. 기본값의 까닭: 승인된 규칙이고, 한 브라우저를 여럿이 쓸 때 로그아웃 상태 스니펫이 남의 계정 화면에 섞이지 않는다. 틈은 **F-2096·F-2099 를 같은 배포에 싣는 것**으로 막기를 권한다.
다른 쪽(계정 슬롯이 없으면 로컬 슬롯)을 고르면: 부팅 3장 4번·`selectSlot` 에 갈래 하나, B3 표가 바뀌고 개요 2.3 을 고친다. F-2099 뒤에도 병합 전(오프라인 첫 로그인)·다른 계정으로 막 바꾼 동안 로컬 스니펫이 보인다.
