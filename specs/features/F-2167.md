# F-2167 목록·인용 안 첨부 이미지도 그림으로

상태: 승인됨(2026-10-24, Q1 은 사용자가 "그림으로 봄", Q2·Q3 기본값 — 남은 갈림길 없음) — 사용자(2026-10-24) "칸반과 별개로 불릿포인트 에 이미지 들어가면 렌더안됨". 정해진 것: 보기(+인쇄·HTML 내보내기)·편집 둘 다, 그림 한 줄만 있는 줄만, 문장 안·외부 주소는 지금처럼 링크(F-116). 사용자 결정(2026-10-24): 항목 바로 아래 빈 줄 없이 들여쓴 그림 줄도 그림, 할 일 첫 줄은 체크박스 + 링크 그대로, 삭제는 그림 글자만. 열린 질문 없음

## 근거 (HEAD `e6c0eb2f`, 스크래치패드에서 `node` 로 돌려 확인)
- 지금 `- ![a|center|200](attachments/…)` 보기 = 링크 `이미지: a|center|200`, 평문 `- [이미지: a|center|200]`. 콜아웃 본문 첫 줄 그림은 이미 보기에서 그려진다(`calloutRule` 본문 `paragraph_open` 이 level 0)
- markdown-it `Token` 의 `level` 기본값은 0 — `imageBlockRule` 의 `html_block` 이 0 이면 `exportVault.ts` `computeImageBlockEdits` 의 `level !== 0` 거르기를 지나 `- ` 까지 줄째 `![[…]]` 로 바꾼다
- lezer: `- L`·`1. L`·`> L`·`> - L`·`- 항목⏎⏎  L` 은 `Paragraph`(from = 그림 시작). `- 항목⏎  L`·`> 인용⏎> L` 은 한 `Paragraph` 의 둘째 줄(인용이면 그 줄 `QuoteMark` 가 문단 안 자식). `- [ ] 할일⏎  L` 은 `Task` 의 둘째 줄. 게으른 줄(`- 항목⏎L`, `> 인용⏎L`)도 같은 노드 안이다
- 3장 규칙 복제본 출력: tight `<li>시안 비교<div class="md-image…">…</div>\n</li>`, `> 인용⏎> L` → `<p>인용</p>` + div, `> [!note]⏎> L` → 머리 문단 + div. 게으른 줄·최상위 `글⏎L`·항목 글자 시작보다 4칸 이상 깊은 줄은 지금처럼 링크. 인용의 게으른 줄은 종료 규칙이 아예 불리지 않는다

## 2. 범위 — 목록 항목·인용(콜아웃 포함) 안의 줄이 F-2127 2.1·2.2 를 통과하는 그림 한 줄일 때
- 그린다: 항목 첫 줄(`- L`, `1. L`), 항목 아래 들여쓴 줄(`- 시안 비교⏎  L`, 빈 줄 뒤 `- 항목⏎⏎  L`, 할 일 항목 아래 `- [ ] 할일⏎  L`), 인용 줄(`> L`, `> 인용⏎> L`, `> [!note]⏎> L`), 중첩(`> - a⏎>   L`, 2단계 이상 목록)
- 지금처럼 글자·링크: 할 일 첫 줄 `- [ ] L`(체크박스를 내는 `taskListsRule` 이 문단 인라인을 전제), 게으른 줄, 최상위 문단 중간 줄(`글⏎L`, 요청노트 2026-10-21 그대로), 문장 안, 외부 주소, 대응 없는 상대 경로, 들여쓰기 코드(항목 글자 시작보다 4칸 이상)
- 붙여넣기 자리 규칙(목록 안에서 붙여도 최상위 줄)·볼트 가져오기 `standalone`(F-2019 5.1)·볼트 내보내기(level 0 만)는 그대로

## 3. 보기 모드 (`renderMarkdown.ts`)
- `imageLineBlockRule` 을 `{ alt: ['paragraph'] }` 로 등록하고 `state.level !== 0` 조건을 뺀다(4칸 검사는 둔다). 블록 시작으로 불릴 때(`silent` 거짓)는 지금처럼 그 줄만 문단으로 끊는다
- 문단 종료 검사로 불릴 때(`silent` 참)는 **`state.level === 0` 이면 거짓**(최상위 문단 중간 줄은 글자 — 경계), `state.sCount[줄] < state.blkIndent` 면 거짓(목록 게으른 줄). core 에서 inline 을 나누는 방식은 쓰지 않는다 — `map`·tight 숨김·콜아웃 분리가 블록 단계 결과를 그대로 받는다
- 그 결과 콜아웃 머리 바로 아래 그림 줄도 같은 규칙으로 끊겨 지금과 같은 그림이 된다(따로 다루지 않는다)
- `imageBlockRule`: `open.level !== 0` 조건을 뺀다. `html_block.level` = `open.level`(근거 2번). `data-source-line` 은 `open.level === 0` 일 때만 — F-295 그대로, `toHtmlDoc.ts` 정규식도 맞는다
- 모양(`image.css`): 정렬·폭은 `<li>`·`<blockquote>` 글자 영역 기준(`margin-inline` 규칙 그대로). `<li>`·`<blockquote>` 마지막 자식 `.md-image` 아래 여백 0, tight `<li>` 에서 글자 바로 뒤에 오면 위 여백을 문단 간격만큼 — 값은 H1
- 코드 변경 없음(확인함): `Viewer.tsx`·`fillMarkdownAssets.ts`(`printDoc.ts` 가 씀)는 `querySelectorAll('img[data-attachment]')`, `viewFindDom.ts` 는 `.md-image` 선택자, `toPlainText.ts` 는 안쪽 `html_block` 도 `meta` 로 읽는다

## 4. 편집 모드
### 4.1 찾기 — `imagePaths.ts`
```ts
export type NestedImageLine = LeadingImageLine & { imageFrom: number; hideFrom: number; markLine: boolean }
// from·to = 그 줄 전체. hideFrom = 위젯 범위 시작. markLine = 그 줄에 ListMark 가 있음
export function nestedImageLines(state: EditorState, node: SyntaxNode, resolveImagePath: ResolveImagePath | undefined): NestedImageLine[]
```
- 대상 노드: `isInsideListOrQuote` 인 `Paragraph`(모든 줄)와 `Task`(둘째 줄부터). 줄마다 `imageFrom` = 줄 앞 `[ \t>]` 를 건너뛴 첫 글자, `imageFrom ~ 줄 끝` 이 `imageLineAt` 통과
- 둘째 줄부터는 게으른 줄·코드 들여쓰기를 뺀다(3장과 같은 경계): 그 줄 `>` 수 = 조상 `Blockquote` 수, 마지막 `>`(없으면 줄 시작) 뒤 공백 n 이 가장 안쪽 `ListItem` 의 글자 시작 칸 c(그 항목 첫 줄에서 같은 방식으로 잰 `ListMark` 끝 + 1) 에 대해 c ≤ n ≤ c+3, 항목이 없으면 n ≤ 3. 탭이 섞이면 그리지 않는다
- `hideFrom`: `markLine` 이면 `imageFrom`, 아니면 마지막 `>` 와 공백 1칸 뒤(없으면 줄 시작) — 들여쓰기 공백까지 위젯이 덮는다
- `buildBlocks` `Paragraph` 갈래(와 새 `Task` 갈래): `isInsideListOrQuote` 면 `return false` 하던 자리에서 줄마다 `BlockSpan` = 줄 전체(커서가 그 줄이면 원문 — F-2127 4.1 그대로), 장식 = `Decoration.replace({ widget, block: false })` `[hideFrom, 줄 끝)`. `leadingImageLine`(최상위·setext·목차)은 바꾸지 않는다
- 이유: 줄 전체 블록 위젯은 글머리·번호·인용 선·콜아웃 배경·안내선(F-236)을 지운다. 인라인이면 `lines.ts` 줄 장식이 남는다. 조합 중 보류·`compositionend` 따라잡기는 같은 StateField 경로, `stepIntoBlock` 은 논리 줄 차이 1 이라 개입 안 함 — E1 이 판정
### 4.2 모양·들여쓰기 기준선
- wrap = `md-block md-image` + `data-img-form="inline"`, 줄 안 위쪽 맞춤 인라인 상자, 폭 = 줄 글자 영역 100%, 안쪽 `text-indent: 0`(F-166 3장 원인 1)
- `markLine` 줄: 기존 매달린 들여쓰기(`md-list-line`)가 기호 뒤에 위젯을 둔다 — 추가 없음
- 그 밖 줄: 기준선 = 가장 안쪽 항목 첫 줄의 실측 `--md-list-indent` px(`listIndentPreview` 가 이미 잰 값). `lines.ts` 가 그 줄에 클래스 `md-image-indent` 와 같은 px 의 `--md-list-indent` 를 단다(`padding-left` 만, `text-indent` 없음). 항목 없는 인용 줄은 0 → 인용 글자와 같은 선. 결과: 그림 왼쪽 = 항목 글자 시작선
- **구현 때 측정**(`npm run measure`, 1280×800·`--touch --size 390x844`): `- L`·`- 시안 비교⏎  L`·`- a⏎  - b⏎    L`·`> - a⏎>   L` 에서 ① 위젯 왼쪽 − 항목 첫 줄 글자 시작 ≤ 1px ② 그 `.cm-line` 높이 − wrap 높이 ≤ 2px ③ 가로 스크롤 없음. ②가 반올림으로 깨지면 폭 1px 줄이기까지 구현자 재량, 그래도 안 되면 멈추고 보고
### 4.3 조작 (`imageWidget.ts`, `ImageForm` 에 `'inline'`)
- 현재 범위 = 그 줄의 `imageFrom ~ 줄 끝`(`posAtDOM(wrap)` 의 줄에서 다시 찾는다). 정렬·너비 = 그 글자에 `imageLineAlignChange`·`imageLineWidthChange`(기호를 빼야 해석된다). 끌기 최대 폭 = wrap 폭
- 삭제(그림 글자만): `markLine` 이면 `[imageFrom, 줄 끝)` 만 지워 기호를 남긴다. 그 밖 줄은 줄째 + 줄바꿈 1개(`imageBlockDeleteRange`) — 공백만 남은 줄이 빈 줄이 되어 항목을 loose 로 바꾸지 않게. 커서 = 지운 자리, `userEvent: 'delete.image'`. 더블클릭 = 커서를 `imageFrom` 에
- **끌어 옮기기 없음**: `attachImageMove` 를 붙이지 않고 `grab` 커서도 없다 — `imageMoveChanges` 는 줄 통째 + 빈 줄 정리라 기호·들여쓰기·tight/loose 를 깬다
