# F-2133 캐시 없는 부팅이 본문 다운로드를 기다리지 않음

작성일: 2026-10-07
상태: 상시 지시(결정 없음 → 승인)로 승인. 사용자가 부팅 지연 세 갈래(F-3019 placement, F-2133 이 명세, F-2134 `/api/me` 전 캐시 셸)를 모두 하기로 정했다(2026-10-07). 열린 질문 3개 모두 기본값이 있다. 구현은 B(이 명세) → C(F-2134) 순서 — F-2134 는 이 명세의 `listStaged()` 위에 쌓는다

## 사용자가 이미 정한 것 (바꾸지 않는다)

1. 캐시 없는(또는 캐시와 서버가 크게 다른) 로그인 부팅은 요약(`/api/docs`)·폴더·공유 목록만으로 셸을 띄우고 본문은 뒤에서 받는다

## 3. 저장소

### 3.1 계약

```ts
// src/storage/serverStore.ts
export type DocSummary = Omit<Doc, 'content'>
// ServerStore 에 더한다
listStaged(): Promise<{ docs: DocSummary[]; full: Promise<Doc[]> }>
```

- `docs` 는 그 회차의 요약·공유 목록이 온 뒤(본문 받기 전) resolve 한다. `full` 은 **같은 회차**의 `list()` 결과와 같은 값으로 resolve 한다
- 같은 쓰기 세대의 회차가 진행 중이면 합류한다(R2 와 같은 규칙). `listStaged()` 와 `list()` 를 섞어 불러도 회차가 하나면 `/api/docs`·`/api/shared` 는 한 번씩이다
- `full` 이 거부돼도 처리되지 않은 거부가 나지 않게 한다(부르는 쪽이 `full` 을 안 기다려도 된다)
- `Store` 공용 타입은 넓히지 않는다(F-2042 3.6 과 같음). `withTabBroadcast` 는 펼쳐 넘기므로 손대지 않는다

### 3.2 `docs` 를 만드는 규칙

요약이 왔을 때(`deleteDocsNotIn` 과 받을 목록 계산이 끝난 시점):

- 캐시 행(그 시점의 `cache.getDocs`) 중 받을 목록에 **없는** 것 → 캐시 값(본문 뺌, `role: 'owner'`)
- 받을 목록에 있는 id → **요약 값**(`role: 'owner'`). 캐시 행이 있어도 요약이 이긴다(서버가 더 새 버전)
- 공유받은 문서 → 그 회차 `/api/shared` 결과(본문 뺌). 실패면 없음 — `runList` 와 같음
- `updatedAt` 내림차순. 결과 id 집합은 그 회차의 본문 받기가 모두 성공했을 때 `full` 의 id 집합과 같다
- `/api/docs` 가 실패(네트워크·401·그 밖 `ApiError`)하면 캐시 행 전부 + 공유(대개 없음) — 그때 `full` 도 곧바로 같은 문서를 본문째 준다

### 3.3 그 밖의 회차 상태

- `lastListSharedOk`·`lastSharedDocs`·`lastServerListAt` 은 지금처럼 **회차 끝**(`full` 시점)에 정한다 — "마지막으로 끝난 `list()`" 의미를 지킨다
- 요약이 오면 그 id 집합을 "마지막 서버 요약 id" 로 남긴다(3.5 의 `remove` 가 쓴다)

### 3.4 공유 id 판정 앞당김

- `knownSharedIds` 는 `/api/shared` 응답이 **도착하는 즉시** 갱신한다(지금은 회차 끝, R5). 까닭: `docs` 로 셸이 뜬 뒤 본문 받기가 끝나기 전 사용자가 공유받은 문서를 열면 `get()` 이 그 문서를 내 캐시에 넣는다 — 버그 수정 2026-09-26 이 막은 것과 같은 결과

### 3.5 캐시 행 없는 문서 쓰기

`docs` 로 사이드바에 보이지만 본문을 아직 못 받아 캐시 행이 없는 문서가 생긴다. 사이드바 메뉴로 옮기기·고정·삭제를 누를 수 있다

- `moveDoc`·`setPinned`: 행이 없으면 `update` 와 같이 `api.getDoc` 로 받아 캐시에 넣은 뒤 진행한다. 진행 중인 회차가 그 문서를 받고 있으면(`ensureBodyFetch` 모음) 그것을 기다린다. 끝내 행이 없으면 지금처럼 던진다
- `remove`: 행이 없고 그 id 가 "마지막 서버 요약 id" 에 있으면 `removeDoc` 을 보낼 목록에 넣는다. 둘 다 아니면 지금과 같다(아무것도 안 보냄). 까닭: 지금 동작이면 삭제가 서버에 안 가고 다음 목록에서 문서가 되살아난다

### 3.6 `withE2ee`

- 안쪽에 `listStaged` 가 있으면 감싸 내보낸다(`listCached` 를 감싸는 자리와 같은 방식). 없으면 키도 없다
- `docs`: 금고 행(`e2eeKey` 있음)은 **제목만** 푼다 — MK 없으면 `e2ee: 'locked'`·빈 제목, 있으면 평문 제목·`e2ee: 'open'`, 풀기 실패면 잠긴 모양. 본문 봉투가 없으므로 `decode` 를 그대로 쓰지 않는다
- `full`: `list()` 감싸기와 같이 `decode`

## 4. 부팅 (`src/app/bootFlow.ts`)

### 4.1 기다리는 길 (캐시 먼저 셸을 못 쓸 때)

- 서버 저장소면 `listFolders()` 와 `listStaged()` 를 함께 시작해, 폴더와 `docs` 로 `setFolders`·`setDocs` → `finishBootRouting` → ready. `full` 은 기다리지 않는다
- `full` 이 끝나면 그 결과로 `scheduleGc`. 사이드바에 다시 반영하지 않는다(요약이 서버 기준이라 더 정확하다. `full` 은 본문 실패 문서가 빠질 수 있다). `full` 이 거부되면 `console.error('boot_resync_failed', err)` 한 줄, 이 페이지에선 GC 를 안 한다(F-2056 3.5 와 같음)
- `idb`·`memory` 저장소는 지금 그대로(`list()` 가 로컬)

### 4.2 캐시 먼저 길의 뒤 맞추기·`afterImport`

- 뒤 맞추기: `Promise.all([listFolders(), list()])` → `Promise.all([listFolders(), listStaged()])`, `docs` 로 `applyBootMerge`(F-2042 4.3 규칙·순번 그대로), 그 뒤 `full` 로 `scheduleGc`. 서버에만 있는 문서가 본문 받기를 기다리지 않고 ≈ 1왕복 뒤 붙는다
- `afterImport`: `listStaged().docs` 로 `setDocs`·`setFolders`. 이관 직후 부팅이 다시 목록을 읽으므로(같은 세대면 같은 회차에 합류) 본문을 기다릴 까닭이 없다

### 4.3 본문 없는 문서를 연 순간

새 장치 없음(D4). 길마다:

| 열기 경로 | 무엇을 기다리나 |
| --- | --- |
| `realtime` | 방 첫 동기화. 캐시 본문 안 씀 |
| 금고·`pending`·`fallback`(`store.get`) | `get()` — 회차 요약은 셸 전에 이미 왔으므로 기다림 0, 그 id 가 받을 목록이면 풀 밖에서 곧바로 받기(진행 중이면 합류). 받기가 실패해 행이 없으면 `api.getDoc` 한 번 더 |
| `view`(공유 보기) | 방. 3.4 로 캐시에 안 들어간다 |

"열린 문서 우선" 은 이것으로 채운다 — 풀 순서를 바꾸는 장치는 두지 않는다

### 5.2 검색·지도·탭 신호 — 첫 서버 회차 기다림

```ts
// src/app/cachedList.ts — createCachedListSource deps 에 더한다
firstServerList: () => Promise<void> | null
```

- 이 페이지에서 `/api/docs` 를 읽은 회차가 아직 없고(`lastServerListAt() === null`) 온라인이면, App 은 `serverStore.list()`(진행 중 회차 합류)를 기다리는 promise 를, 아니면 `null` 을 준다. 거부는 삼킨다
- `readRound` 는 이 promise 가 있으면 먼저 기다린 뒤 지금 규칙(`hasLiveChanges`·`maybeRefresh`)으로 간다. 기다린 뒤엔 `lastServerListAt` 이 차서 `maybeRefresh` 가 회차를 또 열지 않는다
- `resyncFromCache`(탭 신호)도 같은 promise 를 먼저 기다린 뒤 `listCached()` 를 읽는다
- 오프라인이면 기다리지 않는다. 캐시 먼저 길로 뜬 뒤 첫 회차가 끝나기 전 검색을 열어도 기다린다(12장 Q1)
