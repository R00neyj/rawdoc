**effect E-A·E-B·E-C 가 건너는 것(F-2076 Q6 이 호출을 `dismissNotice` 아래로 정했다 — F-2076 3.2 "effect 덩어리 자리" 규칙의 예외).** `accountBlocked` 를 `useDocSession`(≈436)이 렌더 중 읽으므로 호출은 그보다 위여야 하고, 훅 하나에 effect 가 들어 있으니 effect 도 함께 올라간다. 건너는 App 수준 effect: `useDocSession`·`useLiveNotices`·`useLiveRoomDoc`·`useDocLock` 안 effect, `listRefreshDepsRef` 대입, `useTabSync`·`useE2ee` 안 effect, `e2eeRef` 대입, `useE2eeMigrate` 안 effect, 금고 상태 목록 effect, `useDocComments` 안 effect·`commentsRef` 대입, `useShortcutUsage`, `useNotificationsGlue`, 지워짐 알림 effect, `useSidebarLayout` 안 effect, 새 버전 알림 effect, 그리고 **E-B 와 E-C 사이에 있던 동기화 구독 effect**(≈832, 이제 셋 모두 뒤). 판정:

1. **E-A·E-B 는 마운트 때 한 번 리스너를 붙이는 effect다.** deps `[recheckAccount]` → `[applyAccountFlags]` → `[showNotice, dismissNotice, e2eeRef]` 가 모두 한 번 만들어진 참조라 다시 돌지 않는다. 바뀌는 것은 같은 이벤트에 붙은 다른 리스너와의 **등록 순서**뿐이다(`online`: `useLiveRoomDoc`·`useLiveDoc`·`useNotifications`, `visibilitychange`: `useE2ee` 둘·`useNotifications`·탭 숨김 저장). 두 핸들러의 동기 부분은 `recheckAccount()` → `fetchAccount()` 의 `fetch('/api/me')` 시작뿐이고 상태를 동기로 바꾸지 않는다(`applyAccountFlags` 는 `.then` 안). 그래서 다른 리스너가 보는 값이 순서에 따라 달라지지 않는다. 바뀌는 것은 네트워크 요청이 나가는 순서뿐이다
2. **E-C(`setAccountBlocked`)는 `store`·`accountBlocked` 가 바뀐 커밋에서 돈다.**
   - `store` 가 바뀌는 부팅 커밋: `runBoot` 가 `applyAccountFlags(accountState)` 를 `await openStore` **전에** 부르고, 막혔으면 `setStore` 전에 `setAccountBlocked(true)` 를 직접 부른다(`bootFlow.ts`). 그래서 이 커밋의 E-C 는 이미 같은 값을 다시 넣는 무동작이다
   - `accountBlocked` 가 거짓→참: `blockedStop = true` 만 한다. 같은 커밋의 다른 effect 가 저장소에 쓰더라도 `serverStore` 의 쓰기는 모두 `await cache…` 뒤에 `kickSend()` 를 부르므로, 보내기는 이 커밋의 모든 passive effect 가 끝난 뒤에 시작한다 → 순서와 무관하다
   - 참→거짓: 멈춤 중이었으면 `pendingBlockedDocId` 처리(`onForbidden` → `setForbiddenDocIds` 업데이터, `FORBIDDEN_DOC_MESSAGE` 알림)와 `kickSend()` 를 한다. 순서가 결과를 바꾸려면 **같은 커밋에서 건너는 effect 가 동기로 알림을 띄워야** 한다(`pushNotice` 는 나중 것이 이긴다). `accountBlocked` 를 deps 에 둔 `useLiveNotices` 두 effect 는 세션 순번·방 Doc 표지로 한 번만 띄워 이 커밋에서 새로 띄우지 않고, `account` 를 deps 에 둔 `useE2eeMigrate` 판정 effect 는 알림을 `.then` 안에서 띄운다. 그래서 순서가 드러나는 길을 코드에서 찾지 못했다(가정 절 셋째 항목)
3. 동기화 구독 effect 와 E-C 의 순서가 바뀌는 커밋은 부팅 커밋뿐이고, 그때 E-C 는 위 2 의 무동작이다

## 11. 열린 질문 (모두 기본값 — 기본값대로면 사람이 정할 갈림길 없음)

### Q1. `useAccountStatus` 가 effect 셋을 호출 자리로 끌어올리는 것 — **기본값: F-2076 Q6 대로 `dismissNotice` 바로 아래에서 부르고 effect 도 함께 올린다**

- 이유: F-2076 Q6 이 호출 자리를 정했고(승인), 4.5 판정으로 순서가 결과를 바꾸는 길을 코드에서 찾지 못했다. C1·C2 가 옮긴 effect 의 동작을 옮기기 전·후로 고정한다
- 다른 쪽(effect 셋을 App 제자리에 남기고 훅은 상태·함수만): effect 순서가 한 줄도 안 바뀐다. 대신 F-2076 2.4 9행 경계("계정 effect 셋 → `useAccountStatus`")를 바꾸고, `lastAccountCheckOkRef` 를 반환해야 해 ref 가 경계를 넘는다(F-2059 3.2 "하나라도 App 에 남으면 App" 에 따라 ref 도 App 에 남긴다). A1 이 약 −200 으로 준다

### Q2. 두 파생값을 모두 내리나 — **기본값: `isReadOnlyByRole`·`canInviteCurrentDoc` 둘 다(F-2076 Q6 문구)**

- 이유: 한 덩어리(주석 포함 6줄)라 함께 이동색으로 보이고, 둘 다 effect 가 없다
- 다른 쪽(`isReadOnlyByRole` 만): 이동 줄이 3줄 준다. `canInviteCurrentDoc` 은 `accountBlocked` 를 읽지 않아 내릴 필요가 없다. 결과는 같다

### Q3. `settingsAccount` 를 `useAccountDelete` 에 두나 — **기본값: 둔다**

- 이유: `onDelete` 가 `openAccountDelete` 를 부르고 App 에 남는 다른 참조가 없다. F-2076 2.4 16행의 "4단계 뒤 28줄" 셈도 이것을 옮기는 것을 전제한다
- 다른 쪽(App 에 남김): 훅이 `openAccountDelete` 를 반환하고 App 이 7줄 더 갖는다. 설정 표시 계산이 계정 삭제 훅 밖에 남아 이름과 경계가 더 곧다

### Q4. `<Editor>` 마운트 넘김값 두 콜백의 deps 를 늘리나 — **기본값: 늘린다(4.2)**

- 이유: 더하는 이름(`setFloatingCommentAnchor`, `docsRef`·`currentDocIdRef`)이 렌더마다 같은 참조라 콜백 참조가 바뀌지 않는다. F-2059 3.4 가 막으려는 "마운트 뒤 바뀐 함수가 편집기에 닿지 않는 것" 이 생기지 않는다. 새 `eslint-disable` 도 없다
- 다른 쪽(deps 를 `[]` 로 두고 `react-hooks/exhaustive-deps` 끄기): 3.4 문구대로 deps 가 한 글자도 안 바뀐다. 대신 새 `eslint-disable` 이 두 줄 생긴다 — F-2059 3.7 은 `react-hooks/refs` 예외만 허용하므로 사용자 결정이 필요하다

### Q5. C 항목이 둘로 충분한가 — **기본값: 둘(C1·C2)**

- 이유: 8장 표에서 기존 e2e 가 없는 옮기는 동작 중 만들 수 있는 것이 둘이고, 둘 다 자리가 가장 크게 바뀌는 effect 다. 변이에서 실패함을 확인했다
- 다른 쪽(막힘 풀림 `pendingBlockedDocId` 갈래까지): 남의 문서 쓰기 403 `account_blocked` → 풀림을 흉내내야 해 `fakeServer` 조종이 늘고 e2e 시간이 는다. 코드는 `serverStore.ts` 안이고 App 쪽은 `setAccountBlocked(accountBlocked)` 한 줄이다

### Q6. `serverStore.ts` 의 "App 이 /api/me 로 확인해 setAccountBlocked 를 부른다" 주석을 고치나 — **기본값: 고치지 않는다**

- 이유: F-2059 3.6 은 `App.tsx` 라는 파일 이름 언급만 고치게 했다(F-2078 Q4 와 같은 판단). "App" 은 앱 쪽이라는 뜻으로도 읽힌다
- 다른 쪽(`useAccountStatus` 로 고친다): 이름 검색이 정확해진다. 소유 표에 `src/storage/serverStore.ts` 가 더해진다

### 관찰 (이 조각은 고치지 않는다 — F-2059 7장 성격, 판정은 사용자)
