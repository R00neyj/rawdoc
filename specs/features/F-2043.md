### 2.2 순수 함수 계약 — `src/app/contentWidth.ts`

```ts
export const MIN_CONTENT_WIDTH = 600
export const MAX_CONTENT_WIDTH = 1600
export const CONTENT_WIDTH_STEP = 20
export const DEFAULT_CONTENT_WIDTH = 800
export const CONTENT_WIDTH_VAR = '--content-width'

// 저장값 해석 — 정확한 값(정수·범위 안·20의 배수)만 받고 나머지는 기본값
export function resolveStoredContentWidth(stored: string | null | undefined): number
// 숫자를 범위 안·20 단위로 맞춘다
export function normalizeContentWidth(n: number): number
// 숫자 입력 확정(blur·Enter) — 빈 값·숫자 아님·무한대는 null(되돌림), 나머지는 맞춘 값
export function parseContentWidthInput(raw: string): number | null
// 숫자 입력 치는 중 — 이미 정확한 값일 때만 그 수, 아니면 null(아직 반영하지 않음)
export function exactContentWidthInput(raw: string): number | null
```

규칙

- **맞추기(`normalizeContentWidth`)**: 20 단위 반올림(정확히 가운데면 올림 — `1210` → `1220`) 후 600~1600 으로 자른다. 두 끝이 20의 배수라 자르기와 반올림의 순서는 결과에 영향이 없다
- **해석(`resolveStoredContentWidth`)**: `null`·`undefined`·`''` → 800. `Number(stored)` 가 정수이고 범위 안이고 20의 배수면 그 값, 아니면 800. `'1210'`·`'1700'`·`'abc'`·`'800.5'` 는 800 이다. 맞추지 않고 기본값으로 되돌리는 이유: 앱은 맞춘 값만 쓰므로 이런 저장값은 손으로 고친 것이다(`resolveStoredSidebarWidth` 선례)
- **확정(`parseContentWidthInput`)**: 앞뒤 공백을 떼고 빈 문자열이면 `null`. `Number()` 가 유한하지 않으면 `null`. 그 밖에는 `normalizeContentWidth` — `'1234.5'` → 1240, `'-5'` → 600, `'5000'` → 1600, `'1e3'` → 1000
- **치는 중(`exactContentWidthInput`)**: 확정 규칙으로 얻은 값이 `Number(raw)` 와 **같을 때만** 그 값. `'1200'` → 1200, `'120'`·`'1210'`·`'1700'`·`''` → `null`
  - 이 규칙이면 정확한 값을 한 자씩 칠 때 중간 값이 반영되지 않는다: 600~980 은 세 자리, 1000~1600 은 네 자리이고 네 자리 값의 앞 세 자리(`100`~`160`)는 모두 600 미만이라 정확한 값이 아니다(m5 의 `input` 이 `1`→`12`→`123`→`1234` 로 온다)

## 3. 화면에 반영

### 3.1 변수 둘 — `--content-width`(사용자 값)와 `--content-max`(실제 쓰는 값)

- `tokens.css` `:root` 에 `--content-width: 800px;` 를 두고 `--content-max: var(--content-width);` 로 바꾼다. 기존 규칙 11곳과 `Outline` 은 계속 `--content-max` 를 쓴다
- 사용자 값은 **`<html>` 인라인 스타일의 `--content-width`** 로만 넣는다(`document.documentElement.style.setProperty(CONTENT_WIDTH_VAR, '{N}px')`). 인라인 선언이 `:root` 규칙을 이기고, `:root` 의 `--content-max` 는 같은 요소에서 계산돼 `{N}px` 로 내려간다(m4)
- 왜 `--content-max` 를 직접 덮지 않나: F-505 5.1 이 레일이 열린 동안 `.content-area` 에서 `--content-max` 를 다시 정한다. 그 식이 사용자 값을 써야 하는데 `--content-max` 가 자기 자신을 참조하면 순환이라 값이 사라진다(m4). 사용자 값을 다른 이름으로 두면 F-505 는 `min(var(--content-width), …)` 로 적을 수 있다
- `data-*` 속성 + `:root[data-…]` 블록(글자 크기 방식)을 쓰지 않는 이유: 값이 51개라 블록 51개가 필요하다
- 기본값 800 은 `tokens.css` 와 `DEFAULT_CONTENT_WIDTH` 두 곳에 적힌다. U4 가 `node:fs` 로 `tokens.css` 를 읽어 둘이 같은지 본다(F-2015 U6 가 `index.html` 을 읽는 선례)

### 3.2 언제 넣나 — 첫 페인트부터

| 때 | 누가 | 값 |
| --- | --- | --- |
| 첫 페인트 전 | `BOOT_PAINT_SCRIPT`(F-2015 4.3) | `resolveStoredContentWidth(md.contentWidth)` 와 **같은 결과**를 `{N}px` 로. 저장값이 없어도 `800px` 를 넣는다 |
| 번들 실행, 첫 렌더 전 | `src/main.tsx` | 같은 값을 다시 넣는다(`dataset.fontSize` 줄들과 같은 자리). 머리 스크립트가 실패했을 때의 안전망이다(F-2015 4.3 "`data-theme` 을 다시 넣는 줄은 그대로 둔다" 와 같은 이유) |
| 설정에서 바꿀 때 | `App` 변경 핸들러(4.3) | 새 값 |

- **머리 스크립트에 넣는 이유**: 스켈레톤 `.boot-skeleton-doc` 이 `width: min(100%, var(--content-max))` 다(`boot.css`, F-2015 9.3). 머리 스크립트가 넣지 않으면 저장값 1400 인 사용자는 스켈레톤이 800 폭으로 그려졌다가 인계 뒤 1400 으로 튄다 — F-2015 가 막으려던 깜박임이다
- 머리 스크립트 규칙(F-2015 4.3 "지킬 것")을 그대로 따른다: 전역은 다섯 개(`document`·`localStorage`·`matchMedia`·`location`·`innerWidth`)만, `localStorage` 읽기는 따로 감싸기, 키 문자열과 상수 넷은 `JSON.stringify` 로 끼우기, ES2017 이하. 판정 논리는 스크립트 안에 다시 적고 U6 가 `resolveStoredContentWidth` 와 결과가 같은지 표로 묶는다
- `removeBootSkeleton` 은 `--content-width` 를 **지우지 않는다.** 그 뒤로는 `main.tsx`·App 이 같은 인라인 값을 쓴다(`data-theme` 을 남기는 것과 같은 이유, F-2015 5.3). F-2015 A11(`--boot-sidebar-w` 가 빈 문자열)은 그대로 통과한다
- 공개 보기(`/p/…`, 머리 스크립트 `data-boot-view='off'`)와 CLI 로그인 화면도 `main.tsx` 를 거치므로 이 기기의 값을 따른다. 공개 보기 설정 대화상자에는 `편집기` 탭이 없어 거기서는 바꿀 수 없다(F-290 3.4 — 탭이 하나뿐이면 탭 목록도 없다)

### 3.4 목차 여백 판정 — `Outline`

- 지금은 `(.content-area 폭 − --content-max) / 2 ≥ 56` 일 때 오른쪽 목차, 아니면 목차 버튼이다(`Outline.tsx` 여백 판정 effect, F-229 2.3). 이 계산은 **`.content-area` 크기가 바뀔 때만** 다시 돈다. 설정에서 폭만 바꾸면 영역 크기가 그대로라 판정이 옛 값에 머문다
- 계약: `Outline` 에 선택 prop 을 더한다

```ts
contentWidth?: number   // 주면 이 값으로 여백을 판정하고, 값이 바뀌면 다시 판정한다
```

- 주지 않으면 지금처럼 `<html>` 의 `--content-max` 를 읽는다
- App 의 문서 화면 `Outline` 과 `HelpPage`(새 선택 prop `contentWidth` 를 `Outline` 에 그대로 넘김)에는 App 상태 값을 준다. 도움말 화면에서도 사이드바 `설정` 으로 폭을 바꿀 수 있기 때문이다
- `PublicView` 의 `Outline` 은 주지 않는다 — 그 화면에서는 값이 바뀌지 않는다(3.2 끝)
- 예: 1600×900, 사이드바 펼침 → `.content-area` 1300px. 800 이면 여백 250 → 오른쪽 목차. 1200 이면 여백 50 → 목차 버튼. A9 가 이 전환을 본다

### 3.5 F-505 와의 관계

F-505(pending) 5.1 은 레일이 열린 동안 본문 폭을 `min(800px, 편집기 칸 폭 − COMMENT_CONTENT_SIDE_GAP)` 로 두고, `.content-area` 에서 `--content-max` 를 다시 정하라고 권한다. 이 명세 뒤로는 `800px` 대신 `var(--content-width)` 를 써야 사용자 값이 레일과 함께 살아 있다. `min(var(--content-max), …)` 로 적으면 순환이라 무효다(m4). 10장 갱신 대상에 적는다

## 4. 설정 칸 — `본문 너비`

### 4.1 자리

- 설정 대화상자 **`편집기` 탭**, `줄 번호` 다음·`새 문서 템플릿` 앞. 탭 순서는 `탭바` / `들여쓰기` / `줄 번호` / `본문 너비` / `새 문서 템플릿` 이 된다. `새 문서 템플릿` 을 끝에 두는 F-2037 3.2 는 그대로다
- `SettingsDialog` 선택 prop 둘 — 둘 다 있을 때만 그린다. App 만 준다(공개 보기는 안 준다)

```ts
contentWidth?: number
onChangeContentWidth?: (px: number) => void
```

### 4.2 모양과 이름

```
본문 너비                          ← span#content-width-label (.dialog-field 의 직계 span)
[────────●──────────]  [ 1200 ] px ← div.settings-range: range · number · 단위
```

- 틀은 기존 `.dialog-field` 하나다. 라벨은 `Segment` 와 같이 **직계 `<span id="content-width-label">`**
- **두 입력에 `id` 를 주지 않는다.** 접근 이름은 `aria-labelledby="content-width-label"` 로 둘 다 `본문 너비` 가 된다(역할이 `slider`·`spinbutton` 으로 달라 구분된다). 기존 라벨 세기 선택자 `.dialog-field > span, .dialog-field [id]`(theme·publicView·lineNumbers e2e)가 입력을 라벨로 세지 않게 하려는 것이다 — `NewDocTemplateField` 의 `select` 에 `id` 가 있어 `lineNumbers.spec.js` 가 `:not(select)` 를 붙여야 했던 선례
- 슬라이더: `type="range"`, `min=600`, `max=1600`, `step=20`, `aria-valuetext="{N}px"`, `accent-color: var(--accent)`(`.map-slider input[type='range']` 와 같은 값). 값 글자(`.map-slider-value`)는 두지 않는다 — 숫자 입력이 그 자리다
- 숫자 입력: `type="number"`, `min=600`, `max=1600`, `step=20`, `inputMode="numeric"`. 바탕·테두리·초점은 `.dialog-field input[type='number']` 규칙 그대로 쓰되 그 규칙의 `display: block; width: 100%` 는 이 줄에서 덮는다(그 규칙의 명시도는 `.dialog-field input:is(…)` = 클래스 2·요소 1 이다)
- 단위 `px`: 숫자 입력 오른쪽의 `<span aria-hidden="true">`. 직계가 아니고 `id` 가 없어 라벨로 세지 않는다
- `.settings-range` 는 한 줄 flex, 슬라이더가 남는 폭을 가진다(줄어들 수 있게). 숫자 입력 폭 기본 88px, 간격 8px — **시각 값이라 사람 확인에서 조정한다**(H-2). 400px 창(`편집기` 탭)에서 가로 넘침이 없어야 한다(A10)
- 도움말 문장(`.dialog-note`)은 두지 않는다. 범위는 슬라이더 끝과 숫자 입력의 `min`/`max` 로 드러난다

### 4.3 반영·저장 규칙

- **App 상태**: `resolveStoredContentWidth(getPref('md.contentWidth', ''))` 로 시작하는 숫자 하나
- **변경 핸들러**(`onChangeContentWidth(px)`): 지금 값과 같으면 아무것도 하지 않는다. 다르면 ① 상태를 바꾸고 ② `<html>` 인라인 `--content-width` 를 `{px}px` 로 ③ `md.contentWidth` 에 `String(px)` 를 쓴다. 들어오는 값은 늘 정확한 값이다(아래 두 입력이 맞춘 뒤 부른다)
- **슬라이더**: `input` 이 올 때마다(끄는 중 포함) 핸들러를 부른다. 저장도 그때마다다
  - 근거: 한 번 바꾸는 동기 비용이 최대 4.6ms 이고 두 프레임 안에 끝난다(m1). 값이 51개뿐이라 끝에서 끝까지 끌어도 저장은 최대 50번이고, 같은 값은 핸들러가 거른다. 사이드바 너비는 놓을 때만 저장하지만(F-159 2.5 `handleSidebarWidthCommit`) 거기는 값이 px 단위로 수백 개다. 끄는 중 App 전체를 다시 그리는 것은 `handleSidebarWidthChange` 가 이미 하는 일이다
  - 키보드는 브라우저 기본이다: 방향키 ±20, PageUp/PageDown ±100, Home 600, End 1600(m5)
  - 끌다가 대화상자 밖에서 놓아도 대화상자는 닫히지 않는다(m6)
- **숫자 입력** — 화면에 보이는 글자(초안)를 칸 안 상태로 따로 둔다
  - 칠 때마다(`input`): 초안을 바꾼다. `exactContentWidthInput(초안)` 이 수를 주면 바로 핸들러를 부른다. 이것으로 스핀 버튼·방향키(±20)는 즉시 반영되고, 한 자씩 치는 중간 값은 반영되지 않는다(2.2 끝)
  - **확정 — 칸을 떠날 때(`blur`)와 `Enter`**: `parseContentWidthInput(초안)` 이 `null` 이면 초안을 지금 값으로 되돌린다(저장 안 함). 수를 주면 핸들러를 부르고 초안을 그 수의 문자열로 바꾼다. 예: `1210` → `1220`, `5000` → `1600`, `100` → `600`, `abc`(브라우저가 빈 값으로 줌)·빈 칸 → 되돌림
  - **`Esc`**: 초안을 지금 값으로 되돌린다. 이벤트를 막지 않으므로 대화상자는 평소대로 닫힌다. 되돌린 뒤라 닫히며 `blur` 가 나더라도 아무것도 바뀌지 않는다 — 닫힐 때 `blur` 가 나는지에 기대지 않으려는 규칙이다
  - `닫기` 버튼·바깥 클릭: 누르기 전에 숫자 입력에서 초점이 빠지므로 `blur` 확정이 먼저 돈다
  - 지금 값이 밖(슬라이더)에서 바뀌면 초안도 그 값의 문자열이 된다
- 대화상자를 다시 열면 `편집기` 탭이 아니라 첫 탭으로 열리므로(F-290 3.7) 이 칸은 새로 그려지고 초안은 저장값에서 시작한다

### 4.4 문구 (새 UI 문자열)

| 자리 | 문구 |
| --- | --- |
| 칸 라벨 | `본문 너비` |
| 단위 | `px` |
| 슬라이더 `aria-valuetext` | `{N}px` (예 `1200px`) |

- `너비` 는 `사이드바 너비`(`Sidebar.tsx` 손잡이 `aria-label`, ia.md 7장)와 맞춘 말이다. `폭` 은 쓰지 않는다
- 오류 문구는 없다. 잘못된 값은 조용히 맞추거나 되돌린다(사용자 결정 2)

- Tab 순서: `줄 번호` 선택 버튼 → 슬라이더 → 숫자 입력 → `새 문서 템플릿` 선택칸

## 11. 열린 질문

### Q1. 어느 탭 — **기본: `편집기`**

- 사용자 말은 "편집 탭(글꼴 크기·들여쓰기와 같은 탭)" 인데 지금 `글자 크기` 는 `화면` 탭, `들여쓰기` 는 `편집기` 탭에 있다(ia.md 3.15, `SettingsDialog.tsx` `fieldsForTab`). 이름이 가까운 `편집기` 를 기본으로 했다
- `화면` 을 고르면: `글자 크기` 다음·`시작 화면` 앞에 둔다. 공개 보기 설정 대화상자(탭 없이 `화면` 항목만)에도 이 칸이 나와 공개 보기에서도 폭을 바꿀 수 있다. 회귀가 바뀐다 — `settingsTabs.spec.js` `F-290 A4`(화면 탭 라벨 목록, 48줄 근처)와 공개 보기 탭 없음 테스트(라벨 목록, 174줄 근처), `theme.spec.js` `F-154 A7` 의 `nth(4)` `시작 화면`, `publicView.spec.js` `F-230 A1`·`A4` 라벨 수 4 → 5. 대신 `settingsTabs.spec.js` 52줄·`lineNumbers.spec.js` 는 그대로다. `SettingsDialog` 의 `편집기` 탭은 건드리지 않는다

### Q2. 목록 화면도 따르나 — **기본: 전부 따른다**(사용자 결정 3)

- 3.3 표에서 본문이 아니라 **목록**인 곳: 홈 빈 화면·최근 문서(`.empty-state*`), 공유 관리(`.shares-page`), 지도 목록(`.map-list`). 1600 이면 한 행의 왼쪽(제목)과 오른쪽(날짜·버튼)이 1600px 가까이 벌어진다
- 빼기로 하면: 그 선택자들만 `var(--content-max)` 대신 새 고정 토큰(예 `--list-max: 800px`)을 쓴다. `app.css`·`map.css` 규칙 5곳을 고치고 A7 의 `.empty-state` 단정을 800 으로 바꾼다. H-5 가 판단 자료다

### Q3. HTML 내보내기 파일 — **기본: 늘 800px**

- 내보낸 파일은 다른 사람이 다른 화면에서 여는 것이라 이 기기의 표시 설정을 싣지 않는다. 지금 구조(`EXPORT_CSS` 가 `tokens.css` 원문을 실음)대로 두면 따로 할 일이 없다
- 싣기로 하면: `toHtmlDoc` 에 폭 인자를 더하고 `:root{--content-width:{N}px}` 한 줄을 `EXPORT_CSS` 뒤에 붙인다. `src/viewer/exportHtmlCss.ts`·`toHtmlDoc.ts`·`App.tsx` 내보내기 경로와 `F-280` 테스트가 소유에 든다

### Q4. `기본값으로` 버튼 — **기본: 두지 않는다**

- 슬라이더 눈금에 800 표시도 없다. 되돌리려면 숫자 칸에 `800` 을 친다. 다른 설정 칸에도 되돌리기 버튼이 없다
- 두기로 하면: `.settings-range` 끝에 글자 버튼 `기본값`(800 이면 비활성)을 더하고 A 하나를 더한다

### Q5. 도움말 — **기본: 적지 않는다**

- `helpDoc.ts` 는 `글자 크기`·`들여쓰기`·`줄 번호` 같은 표시 설정을 적지 않는다(ia.md 6.1 R1 "쓰다가 바로 부딪히는 기본값·상한" 에 들지 않는다고 봤다)
- 적기로 하면: `## 화면` 절 끝에 한 문장 — "설정 `편집기` 탭의 `본문 너비`에서 본문이 차지하는 최대 너비를 600~1600px 사이로 바꿀 수 있습니다." R2(600자·4문단) 안이다. 수치 둘이라 R5 에 따라 `helpDoc.test.ts` 에 `MIN_CONTENT_WIDTH`·`MAX_CONTENT_WIDTH` 대조 행을 더한다. `helpDoc.ts`·`helpDoc.test.ts` 가 소유에 든다

### 기본값으로 정한 것 (승인되면 확정)

- 사용자 값은 `--content-width`, 실제 값은 `--content-max`(3.1). `<html>` 인라인 스타일로 넣는다
- 머리 스크립트가 첫 페인트 전에 넣는다(3.2)
- 슬라이더는 끄는 중에도 값마다 반영·저장(4.3)
- 숫자 입력은 정확한 값이면 즉시, 아니면 blur·Enter 에 맞춰 확정, 빈 값·숫자 아님은 되돌림, Esc 는 되돌림(4.3)
- 저장값이 정확하지 않으면 맞추지 않고 800(2.2)
- 라벨 `본문 너비`(4.4), 자리 `줄 번호` 다음(4.1)
- `Outline` 은 선택 prop 으로 다시 판정(3.4)
