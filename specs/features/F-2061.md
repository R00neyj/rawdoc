| 수정의 모양 | 이 조각의 처리 |

## 4. 시그니처 (계약)

### 4.1 `src/app/useContextMenu.ts`

```ts
export type UseContextMenuOptions = {
  editorRef: RefObject<EditorHandle | null>
  commentsRef: RefObject<Pick<UseDocCommentsResult, 'access' | 'canWrite'> | null>
  beginComment: () => void
  openDoc: { readonly id: string } | null
  currentDocId: string | null
  showNotice: (input: NoticeWithAction) => number
  openPaletteFrom: (fromEditor: boolean | undefined) => void
}

export type UseContextMenuResult = {
  contextMenu: ContextMenuState | null
  handleViewContextMenu: (info: ViewContextMenuInfo) => void
  handleContextMenuSelect: (node: MenuItemNode) => Promise<void>
  closeContextMenu: (opts?: { returnFocus?: boolean }) => void
}

export function useContextMenu(options: UseContextMenuOptions): UseContextMenuResult
```

App 호출 (절 헤더 주석 자리, 4.1 인자 순서 그대로):

```ts
const { contextMenu, handleViewContextMenu, handleContextMenuSelect, closeContextMenu } = useContextMenu({
  editorRef, commentsRef, beginComment: comments.beginComment, openDoc, currentDocId, showNotice, openPaletteFrom,
})
```

규칙과 이유:

- **`openDoc` 는 객체 그대로 넘긴다. `openDoc?.id` 로 줄이지 않는다.** 구독 layout effect 의 deps 가 `openDoc` 객체 정체성이라, 같은 id 로 새 `openDoc` 이 들어오면(편집기 다시 마운트 뒤) 다시 구독한다. id 만 넘기면 이 재구독이 사라진다
- **`beginComment` 는 `comments.beginComment` 를 렌더마다 넘긴다.** 지금 `handleContextMenuSelect` 는 그 렌더의 `comments` 를 클로저로 읽는다 — 렌더 중 평가한 속성값을 인자로 넘기는 것과 같은 값이다(F-2059 3.2 "클로저로 읽던 값은 훅 인자로"). `comments` 전체를 넘기지 않는 것은 훅이 쓰는 면을 줄이려는 것이다(10장 Q2)
- **`closeContextMenu` 를 반환해 `openPaletteFrom` 이 쓴다.** 지금 `openPaletteFrom` 의 `setContextMenu(null)` 을 `closeContextMenu()` 로 바꾼다. 인자 없는 `closeContextMenu()` 는 `setContextMenu(null)` 만 하고 포커스를 옮기지 않으므로(`opts?.returnFocus` 가 `undefined`) 동작이 같다. setter 를 반환하지 않는 이유: 훅 밖에서 메뉴 상태를 임의 값으로 쓸 길을 열지 않는다
- `handleEditorContextMenu` 는 반환하지 않는다. 쓰는 곳이 훅 안 구독 effect 뿐이다
- `handleViewContextMenu` 는 지금처럼 `useCallback(…, [])` — `Viewer`·`SharedView` 에 넘기는 값의 정체성이 그대로 안정해야 한다
- `closeContextMenu`·`handleContextMenuSelect` 는 지금처럼 `useCallback` 없는 함수 선언(렌더마다 새 함수). `ContextMenu` 에 넘기는 정체성 모양을 바꾸지 않는다
- `ContextMenuState` 는 `contextMenuActions.ts` 에서 import 한다

### 4.2 `src/app/contextMenuActions.ts`

DOM·`window`·`navigator`·`EditorView` 호출이 없는 판정만 둔다(F-2059 2.1). `EditorState` 는 `@codemirror/state` 라 node 테스트 환경에서 만들 수 있다(`contextMenuItems.test.ts` 선례).

```ts
export type ContextMenuState = {
  x: number
  y: number
  place: 'editor' | 'cell' | 'view'
  view: EditorView | null
  mainView: EditorView | null
  container: HTMLElement | null
  nodes: ContextMenuNode[]
}

export function contextMenuCommentOption(
  comments: Pick<UseDocCommentsResult, 'access' | 'canWrite'> | null | undefined,
  place: 'editor' | 'cell',
): { disabled: boolean } | undefined

export function contextMenuSelectionText(state: EditorState): string

export function replaceSelectionChanges(state: EditorState, insert: string): { from: number; to: number; insert: string }[]

export type ClipboardPastePick =
  | { kind: 'text'; index: number }
  | { kind: 'image'; index: number; type: string; fileName: string }
  | null

export function pickClipboardPaste(itemTypes: readonly (readonly string[])[], place: ContextMenuState['place']): ClipboardPastePick

export function entersTableAfterCommand(input: { isInsertTable: boolean; place: ContextMenuState['place']; dataView: string | undefined }): boolean
```

- `ContextMenuState` 는 필드·순서·앞 주석 한 줄을 바이트 그대로 옮긴다(`export` 만 붙음). 타입만이라 node 에서 문제없다
- `UseDocCommentsResult`·`ContextMenuNode`·`EditorView`·`EditorState` 는 `import type` 으로만 가져온다 — 이 모듈이 React·DOM 코드를 런타임에 끌어오지 않게

각 함수가 대신하는 지금 식 (규칙은 지금 코드 그대로 — 새 판정을 만들지 않는다):

| 함수 | 대신하는 식 (자리) | 규칙 |
| --- | --- | --- |
| `contextMenuCommentOption` | `handleEditorContextMenu` 의 `const comment = commentsRef.current && … : undefined` | 댓글 값이 없거나 `access.kind === 'none'` 이면 `undefined`(항목 없음, F-505 3.5). 아니면 `{ disabled: !canWrite \|\| place === 'cell' }` |
| `contextMenuSelectionText` | 지금 같은 이름 함수(인자 `view` → `view.state`) | 모든 선택 범위의 글자를 `\n` 으로 잇는다 (F-170 4장, CM6 Ctrl+C 와 같음). 부르는 쪽은 `contextMenuSelectionText(cm.view.state)` |
| `replaceSelectionChanges` | `cutContextMenuSelection` 의 `changes: …map(… insert: '')`, `insertTextAtContextMenuSelection` 의 `changes: …map(… insert: text)` | 선택 범위마다 `{ from, to, insert }`, 범위 순서 그대로. `userEvent`(`'delete.cut'`·`'input.paste'`)와 `dispatch` 는 훅에 남는다 |
| `pickClipboardPaste` | `pasteContextMenuClipboard` 의 두 `for` 루프 | ① `types` 에 `'text/plain'` 이 있는 **첫** 항목 → `text`. ② 없고 `place === 'editor'` 이면 `'image/'` 로 시작하는 타입이 있는 **첫** 항목, 그 항목에서 처음 맞는 타입 → `image`, `fileName` = `` `pasted.${type.split('/')[1] ?? 'png'}` `` (지금 식 그대로). ③ 그 밖(`cell`·`view` 의 이미지뿐인 경우 포함) → `null`. 훅은 `index` 로 `items[index].getType(…)` 을 부르고, `null` 이면 아무것도 하지 않고 끝난다(지금과 같음) |
| `entersTableAfterCommand` | `runContextMenuCommand` 의 `cmd === insertTable && cm.place === 'editor' && cm.view.dom.dataset.view === 'live'` | 셋 다 참일 때만 `true`. `cmd === insertTable` 비교와 `dataset.view` 읽기는 훅이 해서 넘긴다 |

- 이 다섯 곳의 식 교체가 3.6 이동 판정에서 빨강·초록으로 나오는 **허용된 추가 분류**다(7장 A5). 다른 식은 바꾸지 않는다
- `selectAllContextMenuTarget`·`refocusContextMenuTarget`·`forwardImagePasteToEditor`·`closeContextMenu`·클립보드 읽기·쓰기는 DOM·`navigator` 를 부르므로 훅에 그대로 둔다. `handleContextMenuSelect` 의 `node.action` 분기 순서도 한 글자도 바꾸지 않는다(분기 자체를 순수 함수로 빼지 않는다 — 10장 Q1)

## 10. 열린 질문 (모두 기본값, 사람 결정 필요 없음)

### Q1. 순수 모듈로 무엇까지 빼나 — **기본값: 4.2 의 식 교체 5개만. `handleContextMenuSelect` 의 `action` 분기는 훅에 그대로**

- 이유: 분기마다 하는 일이 전부 DOM·`navigator`·`EditorView` 호출이라 "어느 갈래로 가나" 만 떼면 `switch` 를 한 번 더 쓰는 셈이다. 식 교체 5곳은 조건이 여러 개 얽힌 판정(댓글 항목, 클립보드 항목 고르기, 표 칸 진입)이라 단위 테스트 값이 있다
- 다른 쪽(분기 계획 `planContextMenuSelect(node, cm)` 도 뺌): 이동 판정의 빨강·초록 줄이 약 30줄 늘고, 분기 순서가 두 곳(계획·실행)에 나뉘어 3.6 판정이 어려워진다
- 반대쪽(순수 함수 0개, 훅만): 이동 판정은 가장 깨끗하지만 F-2059 전제 1("순수 로직을 먼저 모듈로")과 2.3 의 `contextMenuActions.ts` 계약을 어긴다

### Q2. 댓글을 어떻게 넘기나 — **기본값: `commentsRef`(ref 객체) + `beginComment`(렌더마다 값)**

- 이유: 지금 읽는 방식이 두 가지다 — 우클릭 때는 ref(`commentsRef.current`), 항목 실행 때는 클로저(`comments.beginComment()`). F-2059 3.2 는 둘을 바꾸지 말라고 한다. `beginComment` 만 넘기면 훅이 `UseDocCommentsResult` 전체 모양에 묶이지 않는다
- 다른 쪽(`comments` 전체): 호출이 `comments.beginComment()` 그대로라 이동 판정 줄이 한 줄 적지만, 훅이 댓글 훅 결과 전체 타입에 의존한다. 동작은 같다

### Q3. `ContextMenuState` 자리 — **기본값: `contextMenuActions.ts`**

- 이유: 순수 함수가 `ContextMenuState['place']` 를 쓰고, 순수 모듈이 훅 파일(React import)을 타입으로라도 거꾸로 가리키지 않게 한다. App 은 이 타입을 직접 쓰지 않는다
- 다른 쪽(`useContextMenu.ts`): 상태를 가진 파일 옆이라 찾기 쉽지만 순수 모듈 → 훅 파일 방향 import 가 생긴다
