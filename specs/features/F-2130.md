## 2. 결정 요약

1. **열 때 한 번 확인한다**: `푸시…` 를 누르면 대화상자를 `GitHub 확인 중…` 으로 열고 `flushOutbox` → `push-plan`. 충돌·빈 저장소·한도는 커밋 메시지를 적기 전에 보이고, `새 그림 {N}장` 을 보여 줄 수 있다. `push-plan` 은 횟수가 들지 않는다(F-3016 3장)
2. **누르면 처음부터 다시**: `푸시` → `flushOutbox` → 그 순간 본문 스냅숏으로 `push-plan` → `.md` `blobs` → `missing` 그림 `blobs` 한 장씩(입력 순서, 앞 50장) → `push`. 열 때 결과를 다시 쓰지 않는다 — 그사이 그림이 늘거나 남이 푸시했을 수 있다. `push-plan` 은 GitHub GET 3번뿐
3. **`.md` 바이트** = `fromEditorText` 와 같은 `editor.getText(lineEnding)`(r3 와 같은 `lineEnding`) UTF-8 + `link.remoteBom` 이면 앞에 `EF BB BF`. 내보내기와 BOM 하나만 다르다(F-3013 Q2)
4. **크기**: `githubPull.ts` `mergedTooLarge(text, lineEnding)` 이 참이면 요청 0 으로 막는다 — 1MB 넘게 올리면 다음 당기기가 `너무 큽니다` 로 거부된다
5. **푸시는 `liveStatus === 'live'` 일 때만** 연다(F-2129 2장 7과 같은 이유 — 실시간이 끊긴 본문을 올리지 않게). 아니면 대화상자 없이 오류 알림 `온라인일 때 푸시할 수 있습니다`
6. **커밋 메시지**: 기본값 빈 칸(사용자 결정 6). `<textarea>` 3줄, `maxLength={1000}`(서버 `message.length` 와 같은 UTF-16 단위), `trim()` 이 빈 글자면 `푸시` 꺼짐, 보낼 때 `trim()` 한 값. Enter 는 줄바꿈 — 보내기 단축키를 두지 않는다. **초안은 문서별로 메모리에 남는다**: 취소·실패·충돌로 닫혀도 다음 `푸시…` 에 그대로, 푸시 성공(`commitSha` null 포함) 때만 지운다. 새로고침하면 사라진다
7. **재시도**: `blobs` 가 502 또는 네트워크 실패(status 0)면 **같은 몸통을 한 번만** 다시 보낸다(같은 바이트 = 같은 sha, F-3016 4장). `push-plan`·`push` 는 자동으로 다시 보내지 않는다(`push` 502 는 이미 올라갔을 수 있다, F-3016 5.1). 실패하면 대화상자에 `role="alert"` 줄, 메시지는 남고 `푸시` 를 다시 누르면 2부터
8. **새 그림 50장 초과**: 앞 50장만 이번 커밋에 넣고 나머지는 다음 푸시에 맡긴다(Q2). 다음 `push-plan` 이 올라간 50장을 빼고 나머지를 `missing` 으로 준다 — `.md` 가 같아도 `images` 가 있으면 서버가 커밋을 만든다
9. **`skipped` 는 올리지 않고 알리기만**: 대화상자에 한 줄. 푸시를 막지 않는다(`.md` 의 그 참조는 저장소에서 깨진 그림이 된다)
10. **첨부를 못 읽으면 멈춘다**: `getAttachment` 가 null·예외, 또는 만든 몸통이 `GITHUB_BLOB_MAX_BYTES` 를 넘으면 `push` 를 부르지 않는다. 이미 만든 blob 은 GitHub 가 치운다(F-3016 5.1)
11. **진행 중엔 닫히지 않는다**: busy 동안 `취소`·Esc·바깥 클릭 막음(F-2129 `GithubPullDialog` 의 capture click 가로채기와 같은 방법). 본문 스냅숏을 누를 때 떴으므로 그사이 다른 사람 편집은 이번 푸시에 안 든다
12. **IME**: 누르는 순간 본 편집기는 모달 뒤라 조합 중일 수 없다(F-303 5.4). 커밋 메시지 칸 조합은 `푸시` 버튼으로 초점이 옮겨 가며 끝난다 — 따로 막지 않는다

## 3. 순수 계약 — `src/app/githubPush.ts`

```ts
export type PushStep = { kind: 'md' } | { kind: 'image'; index: number; total: number } | { kind: 'commit' }
export type PushDeps = {
  plan(names: string[]): Promise<GithubResult<GithubPushPlan>>
  blob(body: string): Promise<GithubResult<GithubBlobCreated>>
  push(body: GithubPushBody): Promise<GithubResult<GithubPushed>>
  readAttachment(name: string): Promise<Uint8Array | null>   // '{id}.{ext}'
  progress(step: PushStep): void
}
export type PushOutcome =
  | { kind: 'pushed'; sha: string; commitUrl: string | null; left: number }   // commitUrl null = 바뀐 것 없음, left = 다음으로 미룬 그림 수
  | { kind: 'conflict'; gone: boolean }
  | { kind: 'failed'; message: string }
export const PUSH_OFFLINE_MESSAGE = '온라인일 때 푸시할 수 있습니다'
export const PUSH_MAX_REFS = 1000                                                // E2EE_MAX_ATTACHMENT_REFS 와 같은 값
export function pushImageNames(text: string): string[]
export function pushMdBytes(text: string, bom: boolean): Uint8Array             // text = getText(lineEnding) 결과
export function blobBody(bytes: Uint8Array): string
export function readConflict(r: GithubFailure): { gone: boolean } | null
export function pushFailureMessage(r: GithubFailure): string
export function planSummary(plan: GithubPushPlan): { newLine: string; skippedLine: string | null }
export function pushedNotice(o: Extract<PushOutcome, { kind: 'pushed' }>): string
export function runGithubPush(input: { md: Uint8Array; names: string[]; message: string }, deps: PushDeps): Promise<PushOutcome>
```

- `pushImageNames`: r4 의 `REF_RE` 와 같은 꼴로 `'{id}.{ext}'` 를 처음 나온 순서, 중복 없이. `imageBlock.ts` 는 고치지 않는다(id 만 주므로 이름을 따로 모은다)
- `blobBody`: `JSON.stringify({ encoding: 'base64', content })`, base64 는 8KB 끊기 + `btoa`(r5. `exportDoc.ts` 의 함수는 모듈 안이고 그 파일은 fflate·mermaid 를 끌고 와 가져다 쓰지 않는다 — 같은 6줄을 둔다. 선례 `cliSeal.ts`·`shareCodec.ts`)
- `readConflict`: `status === 409 && error === 'github_conflict'` 일 때만. 몸통에 `remoteSha` 키가 있고 값이 `null` 이면 `gone: true`(원격 파일이 지워졌거나 폴더로 바뀜 — 당기기가 404 가 되므로 당기기로 잇지 않는다), 키가 없거나 문자열이면 `gone: false`
- `pushFailureMessage`: `github_empty_repo` → `빈 저장소에는 푸시할 수 없습니다. GitHub에서 파일을 하나 만든 뒤 다시 해 주세요`, `github_forbidden` → `GitHub에서 이 브랜치에 쓸 수 없습니다. 브랜치 보호 규칙과 권한을 확인해 주세요`, 그 밖 `githubErrorMessage`(한도·끊김·꺼짐·`too_large` 포함)
- `planSummary`: `missing` 0 → `새 그림 없음`, 1~50 → `새 그림 {N}장`, 51 이상 → `새 그림 {N}장 — 이번에 50장, 나머지는 다음 푸시에 올라갑니다`. `skipped` 0 → null, 아니면 `올리지 않는 그림 {M}장 (금고 그림이거나 아직 서버에 올라가지 않은 그림)`
- `pushedNotice`: `commitUrl` null → `GitHub 파일과 같습니다`, `left > 0` → `푸시했습니다. 남은 그림 {left}장은 한 번 더 푸시하면 올라갑니다`, 그 밖 `푸시했습니다`
- `runGithubPush` 순서가 결정이다:
  1. `names.length > PUSH_MAX_REFS` → `failed` `그림이 너무 많아 푸시할 수 없습니다 (최대 1,000장)`, 요청 0
  2. `plan(names)` — 실패면 `readConflict` 가 있으면 `conflict`, 아니면 `failed`
  3. `progress({ kind: 'md' })`, `blob(blobBody(md))` (7의 재시도 규칙) → `mdSha`
  4. `missing` 앞 50장을 차례로: `progress({ kind: 'image', index: i + 1, total })`(`total` = 이번에 올릴 수), `readAttachment` → 10의 멈춤 → `blob` (재시도 규칙) → `{ name, sha }`
  5. `progress({ kind: 'commit' })`, `push({ message: message.trim(), mdSha, images })` — 실패면 2와 같은 갈래
  6. `pushed` (`sha`, `commitUrl`, `left = missing.length - 50` 의 0 이상)
- 읽기 실패 문구: `그림을 읽지 못해 푸시하지 않았습니다 ({name})`

## 4. 흐름 — `useGithubPush`

```ts
export type GithubPushView = {
  docId: string
  target: string                    // '{repo} · {branch} · {path}'
  message: string
  plan: GithubPushPlan | null       // null = 확인 중이거나 확인 실패
  checking: boolean
  progress: string | null           // role="status"
  error: string | null              // role="alert"
  conflict: { gone: boolean } | null
  busy: boolean
}
export type GithubPushDialogProps = {
  state: GithubPushView | null
  onMessage(m: string): void
  onPush(): void
  onPull(): void
  onCancel(): void
}
```

옵션은 `useGithubPull` 과 같은 것(`editorRef`·`liveStatus`·`currentDocId`·`lineEnding`·`showNotice`·`watch`·`linkOf`) + `flush: () => Promise<void>`(`store.flushOutbox`, 예외는 삼킨다)·`readAttachment`(`store.getAttachment(id, { ext })` → `blob.arrayBuffer()`)·`onPushed(docId, sha)`·`startPull(docId)`. 모든 API 결과는 `watch` 를 거친다(꺼짐·다시 연결 → 상태 다시 읽기, F-2128)

### 4.1 열기 `openPush(docId)` — 주인 + 연결됨 + 지금 문서일 때만 불린다
1. 이미 열려 있거나 당기기 대화상자가 열려 있으면 무시
2. 2장 5 — 아니면 오류 알림 `PUSH_OFFLINE_MESSAGE`, 끝
3. 상태 `checking: true`, `message` = 그 문서 초안. `flush` → `pushImageNames(editor.getText('lf'))` → `plan`
4. 결과가 올 때 대화상자가 닫혔거나 다른 문서면 버린다. 성공 → `plan`, 충돌 → `conflict`, 그 밖 → `error`(`pushFailureMessage`)

### 4.2 푸시 `onPush()`
1. `trim()` 빈 글자·busy·`conflict` 면 무시. 지금 문서가 `docId` 가 아니면 닫고 오류 알림 `문서가 바뀌어 푸시를 멈췄습니다`. `'live'` 아니면 alert 줄 `PUSH_OFFLINE_MESSAGE`
2. 스냅숏 `text = editor.getText(lineEnding)`. 2장 4 → alert 줄 `GitHub 파일이 너무 큽니다 (최대 1MB)`(`GITHUB_TOO_LARGE_MESSAGE` 그대로)
3. `busy`, `error`·`conflict` 비움. `flush` → `runGithubPush({ md: pushMdBytes(text, link.remoteBom), names: pushImageNames(text), message }, deps)`. `progress` 글자: `md` → `파일 보내는 중…`, `image` → `그림 보내는 중 ({index}/{total})`, `commit` → `GitHub에 기록하는 중…`
4. `pushed` → 닫기, 초안 지움, `onPushed(docId, sha)`(링크 캐시 `remoteSha = sha`·`syncedAt = now`, `remoteBom` 그대로 — F-2129 `onSynced` 와 같은 갱신), 알림 info `pushedNotice` + `commitUrl` 이 있으면 `action: { label: 'GitHub에서 보기', onClick: () => window.open(commitUrl, '_blank', 'noopener') }`
5. `conflict` → busy 풂, `conflict` 를 둠(5장). `failed` → busy 풂, `error`

### 4.3 충돌 → 당기기 → 다시 푸시
- `conflict.gone === false` 면 `당기기…` 버튼. 누르면 푸시 대화상자를 닫고(초안 남김) 곧바로 `startPull(docId)` — F-2129 4.2 그대로(받는 중 대화상자 → 합치기 또는 같음 → `synced`). 횟수 1
- 당기기가 끝나도 푸시 대화상자를 **다시 열지 않는다**(Q1). 사용자는 합친 결과를 본 뒤 `푸시…` 를 다시 누르고, 메시지는 초안으로 남아 있다. `synced` 가 `remote_sha` 를 원격 sha 로 바꿨으므로 다음 `push-plan` 은 통과한다
- `gone === true` 면 버튼 없이 alert 줄만 — 연결을 해제하고 다시 연결하면(`sha: null`) 첫 푸시가 새로 만든다
