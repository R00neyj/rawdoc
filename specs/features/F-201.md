## 2. 요구사항

### 2.1 의존성

| 패키지 | 버전 | 구분 |
| --- | --- | --- |
| `typescript` | `~6.0.3` | devDependencies |
| `typescript-eslint` | `^8.70.0` | devDependencies |

- `typescript` 7.x 는 쓰지 않는다. `typescript-eslint` 8.70 의 peer 범위가 `>=4.8.4 <6.1.0` 이다 (2026-09-15 `npm view`)
- 빌드는 지금처럼 Vite 가 한다. `tsc` 는 타입 검사만 (`noEmit`)

### 2.2 `tsconfig.json`
- `strict: true`, `noEmit: true`, `jsx: "react-jsx"`, `module: "ESNext"`, `moduleResolution: "bundler"`, `target: "ES2022"`, `lib: ["ES2023", "DOM", "DOM.Iterable"]`, `allowImportingTsExtensions: false`, `verbatimModuleSyntax: true`, `skipLibCheck: true`
- **`allowJs: true`, `checkJs: false`** — F-203 까지 JS·TS 가 섞여 있는 동안만. F-203 에서 끈다
- `include`: `src`, `brand.config.ts`, `vite.config.ts`. `e2e/`·`scripts/`·`spike/` 는 넣지 않는다 (2.6)
- 스크립트 `"typecheck": "tsc --noEmit"`

### 2.3 ESLint
- `typescript-eslint` 의 `recommended` 를 `**/*.{ts,tsx}` 에만. 기존 JS 규칙·`react-hooks`·`react-refresh` 는 ts 파일에도 그대로
- `no-unused-vars` 는 ts 파일에서 `@typescript-eslint/no-unused-vars` 로 같은 옵션(`varsIgnorePattern: '^[A-Z_]'`)
- 타입 정보가 필요한 규칙(`recommendedTypeChecked`)은 켜지 않는다

### 2.4 타입
- `specs/architecture.md` 2장 JSDoc `@typedef` 를 `src/types.ts` 의 `type` 으로 옮긴다. `Store` 는 `kind: 'idb' | 'memory'` 와 2장 메서드 전부
- `memoryStore`·`idbStore` 는 `Store` 를 반환 타입으로 명시
- 이전한 파일의 **타입만 적은 JSDoc(`@param {…}`·`@returns {…}`·`@typedef`)은 지운다.** 설명 문장이 필요하면 한 줄 주석으로 (CLAUDE 전역 주석 규칙)
- 명시적 `any` 금지. 외부 값(IndexedDB 레코드, `JSON.parse`, localStorage)은 `unknown` 으로 받고 좁힌다
- `as` 단언은 DOM 요소 조회처럼 좁힐 방법이 없을 때만

### 2.5 동작
- **동작을 바꾸지 않는다.** 로직·문구·저장 형식·IndexedDB 스키마 그대로. 이전 중 버그를 찾으면 고치지 않고 보고한다
- 파일 이름만 바꾸고 import 경로에서 확장자를 뺀다(`bundler` 해석). `src/` 안 기존 import 가 `.js` 확장자를 쓰고 있으면 이 명세 소유 파일을 가리키는 것만 고친다 — 다른 파일의 import 는 Vite 가 `.js` → `.ts` 를 찾지 못하면 그 줄만 고치고 보고한다
- 테스트는 대상 옆 `{이름}.test.ts` 로 이름만 바꾼다. 기대값 그대로

### 2.6 이번에 옮기지 않는 것
- `e2e/`·`scripts/`·`playwright.config.js`·`spike/` 는 JS 로 둔다 (Node 도구, 앱 코드 아님)
- `public/` 정적 파일
