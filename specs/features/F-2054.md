기존 8개(`template.insert` → `doc.print` → `e2ee.lock` → `e2ee.unlock` → `comment.add` → `comment.toggleRail` → `notifications.open` → `shortcuts.open`)는 **자리를 그대로** 두고, 그 뒤에 아래 29개를 이 순서로 붙인다: **만들기 → 이동 → 지금 문서 → 보기**

- 기존 자리를 지키는 이유: F-2053 A3·A4 가 `>` 뒤 `ArrowDown` 한 번 = `PDF (A4 인쇄)`(2번째)를, F-2022 A13 이 보기 모드 첫 옵션 = PDF 를 전제한다. 앞에 끼우면 그 테스트들과 사용자가 익힌 첫 두 줄이 바뀐다
- 만들기를 앞에 두는 이유: 어느 화면에서나 보이고 가장 자주 쓴다. 이동은 화면마다 하나가 빠질 뿐 늘 보인다. 지금 문서 묶음은 문서 화면에서만 보인다. 보기는 설정 성격이라 끝
- 지금 문서 묶음 안에서 `이 문서 삭제` 를 **맨 끝**에 둔다 — 방향키로 훑다가 복사·내보내기 옆에서 잘못 고를 일을 줄인다(골라도 D-1 이 막는다)

## 5. 팔레트 뒤에 여는 것 — 포커스와 순서

### 5.1 규칙
3장 표에서 **늦춤 ✓** 인 명령(`doc.new`·`folder.new`·`search.open`·`nav.settings`·`doc.move`·`share.invite`·`doc.delete`, 그리고 `mode.live`·`mode.raw` 의 에디터 포커스)은 **팔레트 `<dialog>` 의 `close` 이벤트 처리(= `Dialog` 의 포커스 복귀)가 끝난 뒤** 실행한다

- 왜: 확인 (a). 지금처럼 `run` 안에서 같은 틱에 대화상자를 열면, 그 대화상자가 "연 순간의 요소" 로 **팔레트 입력칸**을 기억하고(JSX 에서 D-1·D-2·D-3·D-4·D-6 이 모두 `CommandPalette` 보다 앞에 있어 그 effect 가 먼저 돈다), 닫힐 때 포커스가 `body` 로 떨어진다. 늦추면 새 대화상자가 기억하는 요소가 팔레트를 연 곳(보통 본문 에디터)이 되고, 닫으면 그리로 돌아온다
- 대화상자가 아닌 포커스 대상(새 문서의 제목 입력, 새 폴더의 이름 칸, 모드 전환 뒤 에디터)도 같은 이유로 늦춘다 — 늦추지 않으면 뒤이은 팔레트 `close` 이벤트의 복귀가 그 포커스를 뺏을 수 있다(확인 (a) 셋째 줄)
- 그냥 `setTimeout(0)` 을 `run` 안에서 거는 것으로는 **순서가 보장되지 않는다**(확인 (a): 20회 중 두 가지 순서). 보장되는 자리가 하나 있다 — `Dialog` 의 `close` 처리기는 `onClose()`(= `CommandPalette.handleDialogClose` → App `closePalette`)를 부른 **다음** 같은 처리기 안에서 포커스를 돌린다. 그러니 `closePalette` 가 `close` 이벤트에서 불릴 때 걸어 둔 일을 0ms 타이머에 올리면 복귀 뒤에 돈다. 구현은 이 자리를 쓰거나 같은 보장을 주는 다른 방법을 고른다(`Dialog.tsx`·`CommandPalette.tsx` 는 고치지 않는다)
- 늦춘 일이 도는 시점은 팔레트 `close` 이벤트 직후 한 태스크 뒤라 사람이 느낄 지연이 없다

### 5.2 같은 틱에 부르는 것과 이유
- `doc.import`: 파일 선택 창은 사용자 활성화가 살아 있을 때만 뜬다. 같은 틱이든 늦춤 뒤든 확인 (b) 로 된다. 파일 창은 `<dialog>` 가 아니라 포커스 문제가 없어 **같은 틱**(여유가 가장 크다). 파일을 고른 뒤 뜨는 가져오기 미리보기는 비동기라 팔레트가 이미 닫혀 있다
- `nav.guides`·`doc.openNewTab`: `window.open` 은 팝업 차단을 피하려면 사용자 활성화 안에서 불러야 한다 → 같은 틱
- 내보내기·복사·토글·`nav.home`·`nav.map`·`nav.help`·`nav.shares`·`mode.view`·`doc.togglePin`: 대화상자를 열지 않는다. 포커스는 `Dialog` 기본 복귀(팔레트를 연 요소). 그 요소가 화면 전환으로 사라지면(`홈으로` 뒤 에디터) 포커스는 `body` 다 — 사이드바 로고로 홈에 갈 때 포커스가 로고에 남는 것과 다르지만, 새 화면에서 첫 `Tab` 이 문서 처음부터 시작하므로 그대로 둔다(사람 확인 H1)

### 5.3 삭제 (사용자 결정 2)
- `이 문서 삭제` → (늦춤) → `requestDeleteDoc({ id, title: 표시 제목 })` → **사이드바 ⋯ `삭제` 와 같은 D-1** — 제목 `문서 삭제`, 본문 `"{제목}" 을(를) 삭제할까요? 되돌릴 수 없습니다.`, 기본 포커스 `취소`(ia 3.6). 새 문구 없음
- `취소`·`Esc` → 아무것도 지우지 않고 포커스는 팔레트를 연 요소로(A4)
- `삭제` → 기존 `confirmDelete` 그대로(지운 문서가 지금 문서면 목록 첫 문서, 없으면 홈 — ia 3.6-4)
- 삭제는 **되돌릴 수 없다**(product 8장: 휴지통·버전 기록 없음). 그래서 D-1 을 건너뛰는 갈래(예: `Shift+Enter`)를 두지 않는다

### 5.4 이미 있는 같은 문제 (고치지 않음)
`e2ee.unlock`(`금고 열기`)은 지금 `run` 안에서 같은 틱에 금고 열기 대화상자를 연다 — 확인 (a) 의 첫 경우라 닫은 뒤 포커스가 `body` 로 갈 것으로 보인다(**앱에서 돌려 보지는 않았다**). 이 명세 범위 밖이라 고치지 않고 14장 C2 에 적는다. 5.1 의 늦춤을 App 에 만들면 `e2ee.openUnlock` 에 한 줄로 걸 수 있다

## 6. 그 밖의 구현 단위

### 6.1 `새 폴더` — 사이드바 `commandRef`
사이드바 `새 폴더` 는 폴더를 만든 뒤 **사이드바 안 상태**(`startRename`)로 트리의 이름 칸을 연다. App 의 `handleCreateFolder` 는 폴더만 만든다. 팔레트가 같은 결과를 내려면 사이드바의 그 동작을 불러야 한다

```ts
// src/app/Sidebar.tsx
export type SidebarCommands = { createTopFolder: () => void }
// SidebarProps 에 선택 prop
//   commandRef?: RefObject<SidebarCommands | null>
```

- 사이드바는 커밋마다 `commandRef.current` 를 채운다(App 이 `openPaletteRef.current = openPalette` 를 effect 에서 채우는 것과 같은 방식)
- `createTopFolder` = 레일이면 먼저 펼친 뒤 최상위 폴더를 만들고 이름 칸을 연다 — 지금 `handleRailCreateFolder` 와 `handleCreateFolder(null)` 그대로(중복 생성 막는 `creatingFolderRef` 포함)
- App 쪽(늦춤 뒤): 좁은 창이면 겹친 사이드바를 먼저 연다(`setSidebarOpen(true)` — 닫힌 겹침 사이드바는 `inert` 라 이름 칸이 포커스를 못 받는다), 그다음 `commandRef.current?.createTopFolder()`
- 폴더 자리는 **최상위** — 사이드바 `새 폴더` 버튼과 같다. `새 문서` 처럼 지금 문서의 폴더에 만들지 않는다 — 14장 Q9

### 6.2 공유 복사 — `src/app/shareCopy.ts`
`링크 복사`·`마크다운 복사` 의 본문은 지금 `ShareMenu.tsx` 컴포넌트 안 함수라 App 이 부를 수 없다. 알림 문구와 순서를 **바꾸지 않고** 순수 파일로 옮겨 공유 메뉴와 팔레트가 같이 쓴다

```ts
export type ShareCopyDeps = {
  getShareDoc: () => ShareDoc
  onNotice: (notice: Notice) => void
  writeText: (text: string) => Promise<void>   // 앱은 navigator.clipboard.writeText
  baseUrl: string                              // 앱은 location.origin + location.pathname
}
export async function copyShareLink(deps: ShareCopyDeps): Promise<void>
export async function copyShareMarkdown(deps: ShareCopyDeps): Promise<void>
```

- 옮기는 것: 주석 빼기(`stripComments`) → `encodeShare` → 길이 상한 `MAX_LINK_LENGTH`·경고 `WARN_LINK_LENGTH` → 복사 → 알림 셋(첨부 있음·없음·긴 링크), 실패 알림 `복사하지 못했습니다. 브라우저 권한을 확인하세요.`, 마크다운 복사 `마크다운을 복사했습니다.`. 두 상수도 이 파일로 옮긴다
- `writeText`·`baseUrl` 을 주입하는 이유: 테스트 환경은 `node`(DOM·`location`·`navigator.clipboard` 없음). `encodeShare` 는 이미 node 에서 도는 단위 테스트가 있다(`src/lib/shareCodec.test.ts`)
- 공유 메뉴의 읽기 전용 링크·끊기·사람 초대 코드는 옮기지 않는다

### 6.3 `mode.*` 와 스크롤
`changeViewMode` 를 그대로 부르므로 스크롤 위치 유지(F-295)·같은 모드 무시가 버튼과 같다. 모드 명령은 지금 모드일 때 안 보이므로 같은 모드로 부를 일도 없다

### 6.4 `새 문서`·가져오기가 도움말·공유 관리를 떠나게 (확인 (c))
- `createNewDoc`: 지금 `setSharedDoc(null)`·`setMapRoute(null)` 만 부른다. `selectDoc`·`goHome` 처럼 `setSharesOpen(false)`·`setHelpOpen(false)` 도 부른다
- `runImportFiles`: 지금 `setSharedDoc(null)` 만 부른다. 같은 자리에서 `setSharesOpen(false)`·`setHelpOpen(false)`·`setMapRoute(null)` 도 부른다. 이 함수는 사이드바 `가져오기`·OS 파일 열기(F-119)·`.md` 끌어놓기(F-145)가 같이 쓴다 — 도움말 화면은 끌어놓기 차단 조건(`dropBlockedRef`)에 없어 끌어놓기에서도 같은 모양이 난다(**끌어놓기는 코드만 읽었다**)
- 지도에서 가져오기가 지도를 떠나지 않는 것은 코드로만 읽었다(`runImportFiles` 에 `setMapRoute` 가 없다). 지도에서 `새 문서` 는 이미 떠난다(확인 (c))
- 이 수정은 사이드바 버튼에도 적용된다. 팔레트 없이도 있는 버그라 **별도 버그 수정 커밋으로 먼저** 넣는 쪽도 있다 — 14장 Q4

## 7. 빈 상태와 오류

- 팔레트 1단계에 보일 명령이 0개인 화면이 사실상 없어진다: 부팅이 끝난 앱 화면이면 `새 문서`·`새 폴더`·`.md 가져오기`·`여러 문서 검색`·`설정 열기`·`사용법 열기 (새 탭)`·보기 토글이 늘 보인다. 상태 문구 `지금 쓸 수 있는 명령이 없습니다` 는 코드에 남되(F-2053 5.4 표) 앱에서는 나오지 않는다 — 9장 회귀 셋이 이 문구를 단언하던 것을 바꾼다
- 실패 알림은 모두 **기존 함수의 문구 그대로**다(새 문구 없음): 새 문서 실패 `새 문서를 만들지 못했습니다. 다시 시도하세요.`, 템플릿 읽기 실패, 복사 실패 `복사하지 못했습니다. 브라우저 권한을 확인하세요.`, 링크 과대, 금고 폴더 규칙 E19 등

## 15. 확인한 것과 가정

### 15.1 코드를 읽거나 돌려 확인한 것
- 머리의 확인 (a)~(d)
- `CommandPalette.runAction` 은 `onClose()` 다음 같은 틱에 `cmd.run(context)` 를 부른다. `Dialog` 의 `close` 처리기는 `onClose()` 뒤 `returnFocusRef.current.focus()`. `CommandPalette` 는 `Dialog` 의 `onClose` 로 `handleDialogClose`(→ App `closePalette`)를 넘긴다
- App JSX 에서 D-1(`ConfirmDeleteDialog`)·D-3(`MoveDocDialog`)·D-4(`InviteDialog`)·D-2(`SettingsDialog`)·금고 대화상자·D-6(`SearchDialog`)이 모두 `CommandPalette` 보다 앞에 있다
- 명령 줄 오른쪽 흐린 글은 지금 `shortcut` 만 보인다(`CommandPalette.tsx` 의 `toRows` — 명령은 `detail: it.shortcut`). 명령의 `detail` 필드는 화면에 안 보여 이 명세는 쓰지 않는다
- 앱의 전역 키 가운데 이 명령들과 겹치는 것은 `Ctrl+Shift+F`(검색) 하나다. 모드 전환·사이드바·새 문서에 앱 단축키가 없다(`App.tsx` 의 `keydown` effect 들)
- `공유 관리` 진입은 `AccountMenu.tsx` 에서 `location.hash = '#/shares'`, 로그인일 때만. `사용법` 은 `GUIDES_PATH`(`src/lib/siteChrome`) 새 탭 링크
- 사이드바 `공유받음` 줄에는 ⋯ 메뉴가 없고, 내 문서·고정 줄의 ⋯ 는 잠긴 금고 문서에도 새 탭·고정·이동·삭제를 준다
- `createNewDoc` 은 `newDocFolderId()` 폴더에 `제목 없는 문서` 를 만들고 제목 입력에 포커스(`focusTitleRef`). 사이드바 `새 폴더` 는 `handleCreateFolder(null)` → `startRename` 이고 레일에서는 먼저 펼친다
