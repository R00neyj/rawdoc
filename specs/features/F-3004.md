## 3. `src/pwa/pushSwCore.ts` (계약)

```ts
export const PUSH_ICON_URL = '/icons/icon-192.png'
export const PUSH_BADGE_URL = '/icons/badge-96.png'
export const PUSH_OPEN_MESSAGE = 'push-open'
export const PUSH_SW_MAX_BYTES = 4096

export type PushOpenMessage = { type: 'push-open'; url: string }
export type PushNotificationSpec = {
  title: string
  options: { body: string; tag: string; icon: string; badge: string; lang: 'ko'; data: { url: string } }
}
export type PushWindowCandidate = { url: string; focused: boolean; visibilityState: string }

export function pushNotificationSpec(text: string | null): PushNotificationSpec
export function pushClickUrl(data: unknown): string
export function pickPushWindow<T extends PushWindowCandidate>(windows: readonly T[], origin: string): T | null
```

- 이름은 F-2110(`PushOpenMessage`·`PUSH_OPEN_MESSAGE` 를 import 해 메시지를 거른다)과 이 명세의 글루가 쓰는 계약이다
- **import 는 `../lib/pushPayload` 하나.** `hashRoute.ts`·`pushText.ts`·React 등을 끌어오면 `push-sw.js` 가 커진다(5.2 크기 상한). `Buffer`·`node:`·`window`·`document` 금지 — 서비스 워커와 node 테스트에서 같이 돈다
- `lang: 'ko'` 는 문구가 모두 한국어라서다(읽어 주기 기능이 한국어로 읽게). `dir`·`timestamp`·`requireInteraction`·`silent`·`renotify`·`vibrate`·`actions` 키는 **넣지 않는다**(U1 이 키 목록을 못 박는다)

### 3.1 `pushNotificationSpec(text)`

- 입력은 `PushMessageData.text()` 결과 또는 `null`(본문 없는 푸시)
- `null` 이거나 `JSON.parse` 가 던지거나 `readPushPayload` 가 `null` 이면 `FALLBACK_NOTIFICATION` 으로, 아니면 그 본문으로 만든다. **던지지 않는다**
- `title` = 본문의 `title`, `options` = `{ body, tag, icon: PUSH_ICON_URL, badge: PUSH_BADGE_URL, lang: 'ko', data: { url } }`. `url` 은 `readPushPayload` 가 이미 `safePushUrl` 로 바꿔 끼운 값이다
- 대체 알림의 `tag` 는 `fallback` 이라 대체 알림끼리도 하나로 바뀐다(m4 ④)

### 3.2 `pushClickUrl(data)`

- 누른 알림의 `notification.data` 를 받아 `safePushUrl(data?.url)` — 객체가 아니거나 `url` 이 없거나 틀리면 `'/'`. 알림은 다른 버전의 처리기가 띄웠을 수도 있어 **다시 검사한다**(F-3001 4.4)

### 3.3 `pickPushWindow(windows, origin)` — 어느 창을 쓰나

"앱 창" = `new URL(w.url)` 이 던지지 않고, `origin` 이 인자와 같고, `pathname` 이 정확히 `/` 인 창. 앱은 `/` 에서만 뜬다(`not_found_handling: "404-page"`, 해시 라우팅) — `/welcome`·`/guides/…`·`/help`·`/privacy`·`/login`·`/p/…`·`/sw.js` 같은 같은 출처 페이지는 앱이 아니라 메시지를 받아도 아무것도 하지 않는다. 쿼리(`?app=1`)는 상관없다.

앱 창 가운데 먼저 맞는 것:
1. `focused === true` 인 첫 창
2. `visibilityState === 'visible'` 인 첫 창
3. 목록의 첫 창 — `clients.matchAll` 이 준 순서(m5: 마지막으로 포커스된 창이 앞)를 그대로 믿는다

앱 창이 없으면 `null`(→ 새 창).

- **"그 문서를 이미 연 창" 을 먼저 고르지 않는다**: `Client.url` 이 해시 이동·`pushState` 를 따라오지 않는다(m5). 옛 주소로 고르면 엉뚱한 창을 고른다
- **"설치 앱 창 먼저" 는 서비스 워커가 판정할 수 없다** — `WindowClient` 에 `display-mode` 가 없다(근거 절). 기본값과 다른 안은 Q1. 창이 없을 때 `clients.openWindow` 는 범위(`scope: '/'`) 안 주소라 안드로이드 설치 앱이 있으면 그 앱 창으로 열린다(F-3001 4.4 — 일반 지식, 확인 안 함)
- 창 고르기가 `navigate()` 가 아니라 메시지인 이유: `navigate()` 는 제어받는 창에만 된다(근거 절 타입 설명). 첫 설치 때 열려 있던 창은 제어받지 않는다(`clientsClaim` 없음)

## 4. `src/pwa/pushSw.ts` (글루 — 규칙만)

- 파일 머리에 `/// <reference lib="webworker" />`, 모듈 안에서 `self` 를 `ServiceWorkerGlobalScope` 로 선언한다 — m6 에서 앱 타입 검사와 함께 통과를 확인한 방식. 다른 방식을 쓰면 `npm run typecheck` 통과만 지킨다
- 수신기는 **모듈 맨 위에서 바로** `addEventListener` 로 단다(비동기 뒤에 달지 않는다). m3 처럼 Workbox 의 수신기와 같은 시점에 달린다
- 푸시 본문·주소를 `console` 에 쓰지 않는다(잠금 화면 밖으로 내용이 새지 않게)

**`push`**
1. `event.data` 가 있으면 `text()`, 없거나 던지면 `null`
2. `pushNotificationSpec` 결과로 `self.registration.showNotification(title, options)` 을 `event.waitUntil` 에 넣는다. **보이는 창이 있는지 보지 않는다**(F-3001 Q6) — 모든 푸시가 알림 하나가 된다. `showNotification` 이 거절되면(권한을 거둔 경우) 더 하지 않는다
- 복호에 실패한 푸시는 브라우저가 `push` 이벤트를 부르지 않는다고 알려져 있다(일반 지식, **확인 안 함**) — 그 경우 처리기가 할 수 있는 일은 없다. 처리기가 받는 실패는 "본문 없음·JSON 아님·모양 틀림" 셋이고 모두 대체 알림이 된다(m4 ③④)

**`notificationclick`**
1. `event.notification.close()`
2. `url = pushClickUrl(event.notification.data)`
3. `event.waitUntil` 안에서: `self.clients.matchAll({ type: 'window', includeUncontrolled: true })` → `pickPushWindow(목록, self.location.origin)`
   - 창이 있으면 `focus()` → 돌려받은 창에 `postMessage({ type: 'push-open', url })`. `focus()` 가 거절되면 `self.clients.openWindow(url)` (Q3)
   - 없으면 `self.clients.openWindow(url)`
   - `includeUncontrolled: true` 인 이유: 첫 설치 때 열려 있던 창도 앱 창이다(근거 절 `useAppUpdate`)
- `url` 이 `/` 여도(대체 알림·주소가 틀린 본문) 같은 길이다. 메시지를 받은 앱이 `/` 를 "해시를 옮기지 않음" 으로 다룰지는 F-2110 이 정한다(10장)

## 5. 빌드

### 5.1 `pushSwPlugin()` (`vite.config.ts`)

- `apply: 'build'`. 훅은 **`generateBundle`** — 여기서 `this.emitFile({ type: 'asset', fileName: 'push-sw.js', source })` 한다. `closeBundle` 에서 파일을 쓰지 않는 이유: VitePWA 가 `closeBundle` 에서 precache 목록을 만든다(근거 절). `generateBundle` 에서 내보내면 순서와 무관하게 그보다 먼저 `dist` 에 있다(m2)
- `source` 는 같은 파일 위쪽에서 import 하는 Vite `build()` 를 한 번 더 불러 얻는다: `configFile: false`, `root` 는 저장소 루트, `logLevel: 'warn'`, `build.write: false`, `build.emptyOutDir: false`, `build.lib = { entry: src/pwa/pushSw.ts, formats: ['iife'], name: 'pushSw' }`(m1). 결과 청크는 정확히 하나여야 한다
- 앱 번들의 `rollupOptions.input` 에 넣지 않는다(F-3001 4.1 — 공유 청크가 생기면 `import` 문이 끼어 고전 스크립트가 깨진다). IIFE 형식에서는 Vite 가 동적 `import()` 를 한 청크 안에 인라인한다(`inlineDynamicImports`, 구현 때 확인) — 결과는 여전히 `import` 문 없는 고전 스크립트이고 크기는 4,096 B 상한이 잡는다
- **빌드를 멈추는 조건**: 결과 청크가 하나가 아님, 또는 크기가 `PUSH_SW_MAX_BYTES`(4,096 B) 초과. 오류 문구 `push-sw.js 는 IIFE 청크 하나여야 합니다 ({n}개)` / `push-sw.js 가 {n} B 로 상한 4096 B 를 넘습니다`. 4 KB 는 m1(1,643 B)의 약 2.5배 — 순수 모듈이 `hashRoute.ts`·`pushText.ts`(→ `usageLimits.ts`) 등을 실수로 끌어오면 걸리게
- **`push-sw.js` 가 없으면 서비스 워커 설치 자체가 실패한다**(`importScripts` 가 네트워크 오류를 던지면 `sw.js` 평가가 실패 → 오프라인·새 버전 알림(F-116·F-117)까지 멈춘다). 그래서 이 파일은 빌드마다 반드시 나와야 하고, 없으면 빌드가 실패해야 한다 — 위 두 조건과 E1 이 지킨다
- 다른 빌드(`E2E_DIST`·`npm run measure` 의 `dist-measure`)에도 같은 플러그인이 돈다 — `emitFile` 이라 `outDir` 을 따로 알 필요가 없다. `npm run dev`(서비스 워커 꺼짐)·Vitest 에서는 돌지 않는다

### 5.2 `VitePWA` 설정

- `workbox` 에 `importScripts: ['/push-sw.js']` 한 항목. 그 밖의 `workbox`·`manifest` 값은 한 글자도 바꾸지 않는다
- **`push-sw.js` 는 precache 에 들어간다**(`globPatterns` 의 `**/*.js` 가 잡는다 — `globIgnores` 에 넣지 않는다 — 5.3 의 갱신 규칙이 여기에 기댄다). 크기 1.6 KB 안팎(m1). F-2040 A2 의 precache 합계 10 MiB 상한에 영향 없음

### 5.3 갱신 규칙 — 파일 이름에 해시가 없어도 옛 처리기가 남지 않게

1. `push-sw.js` 바이트가 바뀌면 precache 목록의 그 항목 `revision`(내용 해시)이 바뀐다 → `sw.js` 바이트가 바뀐다(m2) → `/sw.js` 는 `no-cache` 라 브라우저의 갱신 확인(열 때·60분마다, `useAppUpdate`)이 새 서비스 워커를 찾는다 → 대기 → F-117 `새 버전` 띠 → 새로고침하면 새 처리기. **지금 앱 갱신과 같은 길이다**
2. 새 `sw.js` 가 설치될 때 `importScripts('/push-sw.js')` 는 HTTP 캐시를 거칠 수 있다(서비스 워커 등록의 `updateViaCache` 기본값 `imports` — 일반 지식, 확인 안 함). 옛 바이트를 캐시에서 집지 않게 **`public/_headers` 에 `/push-sw.js` → `Cache-Control: no-cache`** 를 둔다. 자리는 `/sw.js` 덩어리 바로 뒤(`/assets/*` 보다 앞 — `tests/src/welcome/gsapBoundary.test.ts` B5 는 `/assets/*` 뒤만 본다)
3. 설치된 뒤에는 브라우저가 `importScripts` 한 스크립트를 서비스 워커 스크립트와 함께 보관한다 — 오프라인에서도 처리기가 돈다
4. `?v=` 쿼리를 붙이지 않는다 — 1·2 로 충분하고, 설정 파일 안에서 해시를 미리 알 방법이 없다

## 9. 사람 확인 (구현 뒤 main 이 `specs/human-checks.md` 에)

F-3003(배포·비밀 값)·F-2110(스위치·`테스트 알림 보내기`·`push-open` 받기)까지 들어간 뒤 배포 주소에서:

1. **안드로이드 설치 앱**: 켜기 → `테스트 알림 보내기` → 알림에 앱 아이콘, 상태 표시줄에 `#` 배지, 제목 `테스트 알림`, 본문이 보인다. "탭하여 이 앱의 URL 복사" 같은 Chrome 기본 알림이 따로 뜨지 않는다(F-3001 사람 확인 ①·⑧)
2. **누르기**: (a) 앱 창이 뒤에 열려 있으면 그 창이 앞으로 오고(F-2110 뒤) 그 주소로 옮긴다 (b) 앱 창이 없으면 새 창(설치 앱이면 앱 창)이 그 주소로 열린다 (c) 앱 창 없이 `/guides` 탭만 열려 있으면 그 탭이 아니라 새 창이 열린다
3. **배지 모양**: 상태 표시줄에서 `#` 가 뭉개지지 않고 다른 앱 배지와 크기가 비슷하다(6.1 의 14% 여백이 맞는지)
4. **갱신**: `push-sw.js` 만 바뀐 배포 뒤 열린 앱에 `새 버전` 띠가 뜨고, 새로고침 뒤 개발자 도구 Application → Service Workers 의 새 워커가 새 `push-sw.js` 를 쓴다
5. **데스크톱 Chrome**: 탭을 모두 닫고 브라우저만 켜 둔 채 테스트 알림 → OS 알림, 누르면 새 창

## 11. 열린 질문

### Q1. 설치 앱 창을 먼저 고르나 — **기본값: 가리지 않는다. 앱 창 가운데 포커스 → 보임 → `matchAll` 순서**

- 서비스 워커가 보는 `WindowClient` 에는 `display-mode` 가 없다(근거 절, TS 6.0.3 `lib.webworker.d.ts`). 설치 앱 창과 브라우저 탭을 서비스 워커 혼자서는 가릴 수 없다
- 기본값의 이유: 안드로이드에서 설치 앱과 Chrome 탭을 둘 다 열어 둔 경우는 드물고, 마지막으로 쓰던 창으로 가는 것이 사용자가 기대하는 곳과 대체로 같다. 창이 없을 때는 `openWindow` 가 설치 앱으로 연다(일반 지식, 확인 안 함)
- 다른 안 A: 앱이 부팅 때 `display-mode: standalone` 여부를 서비스 워커에 메시지로 알리고, 서비스 워커가 창 id 별로 **IndexedDB 나 Cache 에** 적어 둔다(서비스 워커는 쉬면 메모리를 잃는다). 새 저장소 이름·F-2110 메시지 하나·정리 규칙이 는다
- 다른 안 B: 누를 때 각 창에 `MessageChannel` 로 물어보고 250 ms 기다린다. 휴대폰에서 뒤에 있는 페이지는 얼어 있어 답하지 않는다 — 정작 필요한 경우에 못 쓴다

### Q2. 배지를 만드는 스크립트 — **기본값: 새 `scripts/make-badge.mjs`(Playwright + 설치된 Chrome)**

- 개요(F-3001 2.4·6장)는 `scripts/make-icons.py` 에 더하라고 적었다. **이 PC 에 Python 이 없다**(m7) — 구현 담당이 돌릴 수 없고, 돌리지 않은 PNG 를 커밋하게 된다
- 기본값의 이유: `make-og-image.mjs` 가 같은 방식이고(Playwright 로 PNG), 새 의존성이 없으며, 결과가 바이트까지 같다(m8)
- 다른 안 A: `make-icons.py` 에 함수 하나 — 개요 그대로. 사람이 Python + Pillow 12.1.1 이 있는 곳에서 돌려 PNG 를 넘겨줘야 한다
- 다른 안 B: node 만으로 PNG 를 직접 쓴다(`node:zlib` 로 IDAT 압축, 막대를 여러 번 표본 찍어 가장자리 부드럽게). 브라우저가 필요 없지만 스크립트가 약 80줄로 는다

### Q3. `focus()` 가 거절되면 — **기본값: 새 창을 연다**

- 이유: 알림을 눌렀는데 아무 일도 없는 것보다 창이 하나 더 생기는 편이 낫다. 알림 누르기 안에서는 `focus()` 가 허용되므로 드문 경우다
- 다른 안: 아무것도 하지 않는다 — 창이 겹치지 않지만 눌러도 반응이 없는 경우가 남는다

### Q4. `pushsubscriptionchange` — **기본값: 처리하지 않는다**

- 이유: 앱이 부팅 때와 7일마다 구독을 다시 알린다(F-3001 4.3). 서비스 워커에서 다시 구독하려면 서버 공개 키를 받고(`GET /api/push/key`) `PUT` 해야 하는데, 그 요청은 로그인 쿠키·쓰기 관문을 타고 `md.push`(어느 계정이 켰나)를 서비스 워커가 모른다
- 다른 안: 서비스 워커가 `event.newSubscription` 이 있으면 그것을, 없으면 `GET /api/push/key` → `subscribe` → `PUT` 한다. 브라우저가 구독을 바꾼 뒤 앱을 열기 전까지의 푸시를 잃지 않는다. 글루가 두 배 가까이 늘고 e2e 로 판정할 수 없다

### 기본값으로 정한 것 (승인 시 확정)

1. 순수 규칙은 `src/pwa/pushSwCore.ts`, 글루는 `src/pwa/pushSw.ts`, `src/lib/pushPayload.ts` 는 import 만 — 1장·3장
2. 알림 옵션 키 여섯(`body`·`tag`·`icon`·`badge`·`lang`·`data`)만, `renotify` 없음 — 3장
3. 풀기·모양 실패는 모두 `새 알림`(`tag` `fallback`) — 3.1
4. 앱 창 = 같은 출처·경로 `/`, 포커스 → 보임 → 목록 순서, "같은 문서 창" 은 고르지 않음(m5) — 3.3
5. 누르면 `focus()` + `push-open` 메시지, 창이 없거나 `focus()` 가 거절되면 `openWindow` — 4장, Q3
6. `generateBundle` 에서 IIFE 를 `emitFile`, 청크 하나·4,096 B 상한으로 빌드를 멈춤 — 5.1
7. `push-sw.js` 는 precache 에 넣고 `_headers` 로 `no-cache` — 5.2·5.3
8. 배지 96×96 RGBA, 여백 14%, `--paper` 색, `scripts/make-badge.mjs` — 6장, Q2
9. e2e 둘(빌드 산출물, CDP 푸시 → 알림), 누르기는 사람 확인 — 7.2
