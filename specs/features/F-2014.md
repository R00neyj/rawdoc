# F-2014 e2e `openApp()` 의 첫 실행 문서 의존 끊기

작성일: 2026-09-18 (2026-09-23 개정)
상태: **사람 승인 — 받음 (2026-09-23), 병합 뒤 낡은 수치 개정.** 2026-09-18 에 `F-258` 번호로 썼다. 원격에서 F-258 이 Mermaid 로 먼저 쓰여 2026-09-23 병합 때 번호만 F-2014 로 옮겼다(`ec3cc42`). 본문의 행 번호·호출 수·알려진 실패가 2026-09-18 기준이라 낡아, 2026-09-23 에 코드를 다시 읽고 전체 e2e 를 직접 돌려 고쳤다. 사용자가 정한 2장 결정·파일 소유(1장으로 옮김)는 바꾸지 않았다. 개정에서 바뀐 것은 셋이다 — (1) 문서 0개 모사(H2)를 `App.tsx` 임시 수정 대신 **환경 변수 스위치**로 한다(3.3), (2) 홈의 `새 문서` 를 **마우스가 아니라 키보드로** 누른다(3.1 — 실측으로 찾은 회귀), (3) `serverStore.spec.js` 는 "있으면 지우기" 가 아니라 **제목과 무관하게 한 줄을 지운다**(3.2 — 원래 규칙으로는 문서 수가 4개가 된다)
근거: `specs/features/F-150.md`(E2E 도입·헬퍼 3.2), `F-232.md`(시작 화면 기본값 홈), `F-257.md` 7장(첫 실행 안내 문서 없애기 — 이 명세가 끝나야 진행 가능), 사용자 지시(2026-09-18 F-257 7장 처리 방향 "1 — openApp 의존성을 다른 명세로 떼어 먼저 고친다")

모든 행 번호는 **`1441262` 기준 힌트**다. 이름(함수·테스트명·선택자)이 기준이다. 같은 시각 F-2007·F-2015 가 `App.tsx`·`e2e/map.spec.js` 를 고치고 있어 번호는 곧 밀린다.

## 1. 파일 소유

| 파일 | 변경 |
| --- | --- |
| `e2e/helpers.js` | `openApp()` 과 그 바로 위 한 줄 주석만 (3.1, 3.3) |
| `e2e/serverStore.spec.js` | `createLocalDocsThenSignIn()` 의 `사용법` 삭제 단계만 (3.2) |

- `src/**` 는 **한 줄도 바꾸지 않는다.** 바꿔야 할 것 같으면 멈추고 보고한다
- `openAppHome`·`importMarkdown`·`setPrefBeforeLoad` 등 다른 헬퍼의 계약은 바꾸지 않는다
- 다른 spec 파일의 본문은 고치지 않는다. H2 에서 이 두 파일 밖이 깨지는 것(5.1 `F-247 A7`)은 **F-257 7장 몫**으로 넘긴다(7장 갱신 대상)
- `playwright.config.js`·`scripts/**` 도 건드리지 않는다. 3.3 스위치가 그것들 없이 된다

## 2. 결정 (사용자, 바꾸지 않는다)

문서가 없을 때 **홈 화면의 `새 문서` 를 눌러** 에디터로 들어간다. IndexedDB 를 직접 심지 않는다 — 저장소 구현에 묶이지 않고, 실제 사용자 경로와 같다

## 3. 요구사항

### 3.0 지금

`e2e/helpers.js` 의 `openApp()` 은 `md.startScreen='last'` 를 미리 넣고 `/` 를 연 뒤 `.cm-host .cm-editor` 가 보이길 기다린다. 빈 저장소에서 이게 되는 이유는 `src/app/App.tsx` 의 `boot()` 안 첫 실행 분기(785~793행) 때문이다

- 조건: **`list.length === 0 && getPref('md.firstRunDone', '') === ''`** — 저장소에 문서가 0개이고 **동시에** `md.firstRunDone` 설정이 비어 있을 때만
- 하는 일: `GUIDE_DOC_TITLE`(`사용법`, `src/app/guideDoc.ts`)·`GUIDE_DOC_CONTENT_CRLF` 로 문서 하나를 만들고 `md.firstRunDone='1'` 을 쓴다
- 그러면 `md.startScreen='last'` 분기(`shouldAutoOpen`)가 그 문서를 자동으로 연다

**`openApp()` 은 50개 spec 파일에서 560번 불린다**(`1441262`, `grep -rE "\bopenApp\(" e2e --exclude=helpers.js`). 호출 모양은 전부 `await openApp(page)` 하나다(다른 모양 0건). 전체 e2e 는 766개다.

F-257 7장이 이 분기를 없애면 빈 저장소에서 문서가 0개라 홈(`.empty-state`)만 뜨고, `openApp()` 이 에디터를 기다리다 모두 멈춘다.

### 3.1 `openApp()` 새 동작

서명은 그대로 `openApp(page): Promise<void>`. 반환값 없음. 호출부 560곳은 바꾸지 않는다.

순서 규칙:
1. (3.3 스위치가 켜져 있으면 `md.firstRunDone='1'` 을 먼저 넣는다)
2. 지금처럼 `setPrefBeforeLoad(page, 'md.startScreen', 'last')` → `page.goto('/')`
3. **에디터 `.cm-host .cm-editor` 또는 홈 `.empty-state` 중 하나가 보일 때까지** 기다린다. 선택자는 지금 `openApp`·`openAppHome` 이 쓰는 두 문자열 그대로다
4. 홈이 보이면 **`.empty-state` 안의** `새 문서` 버튼(`getByRole('button', { name: '새 문서' })`)에 포커스를 주고 **`Enter` 로 누른다**
5. 에디터가 보일 때까지 기다린다

규칙마다 이유:

- **3 에서 홈이 잠깐 비쳤다가 에디터로 바뀌는 경쟁은 없다.** `App.tsx` 의 `isEmpty` 는 `bootPhase === 'ready' && currentDocId === null` 이고, `boot()` 는 자동 열기 때 `setCurrentDocId` 와 `setBootPhase('ready')` 를 같은 비동기 이어짐 안에서 부른다 — React 19 자동 배치로 한 번에 그려진다. 부팅 중에는 둘 다 안 보인다. 문서가 있는 저장소에서 `.empty-state` 가 먼저 잡혀 문서를 하나 더 만드는 일은 생기지 않는다. F-2015(부팅 스켈레톤)도 둘이 ready 뒤에만 생긴다고 적었다(F-2015 "F-2014 와의 관계")
- **4 에서 `.empty-state` 로 범위를 좁혀야 한다.** 사이드바에도 이름이 `새 문서` 인 버튼이 둘 있다(`src/app/Sidebar.tsx` 의 `RailButton`·`SidebarIconButton`, `label="새 문서"`). 범위 없이 찾으면 Playwright strict 위반이다
- **4 를 마우스 클릭으로 하면 `F-149 A3` 두 테스트가 결정적으로 깨진다 — 실측.** 툴팁은 `:focus-visible` 에서만 뜬다(`src/styles/app.css` `.icon-btn-wrap :is(button, a):focus-visible ~ .icon-tooltip`, 표 `+` 버튼은 `src/editor/preview/preview.css` `.md-table-add:focus-visible::after`). Chrome 은 마지막 입력이 마우스면 뒤이은 스크립트 `focus()` 를 `:focus-visible` 로 치지 않는다. `F-149 A3` 은 `openApp()` 직후 `btn.focus()` 로 툴팁을 기대하므로, openApp 이 마우스로 `새 문서` 를 누르면 툴팁 opacity 가 `0` 으로 남는다. 클릭 판: 단독 3/3 실패. 포커스+`Enter` 판: 단독 3/3 통과(5.2). 문서가 있는 상태(지금)에서는 이 단계를 아예 안 거치므로 영향이 없다
- 4 뒤의 상태는 지금과 **다르다** — 이를 계약으로 적어 둔다. 빈 저장소일 때 openApp 이 끝나면 문서는 `사용법` 대신 **`제목 없는 문서`**(`createNewDoc`, 본문 `''`, `lineEnding: 'crlf'`) 하나이고, 포커스는 제목 입력 `.doc-title` 에 있다(실측: `document.activeElement.className === 'doc-title'`. 지금은 포커스가 `body`). 전체 e2e 에서 이 차이로 깨지는 것은 `F-247 A7` 하나뿐이었다(5.1)

코드 규약:
- 바로 위 한 줄 주석을 새 동작에 맞게 고친다 — "문서가 없으면 홈의 새 문서로 들어간다" 는 뜻이 들어가야 한다. 주석은 한 줄(`helpers.js` 의 다른 헬퍼와 같다)
- 로케이터는 지역 상수로 둘 수 있다. `expect(...).or(...)` 대기는 Playwright `Locator.or` 를 쓴다(`@playwright/test` 설치 버전에 있다 — 스크래치 실행에서 확인)

### 3.2 `serverStore.spec.js` 의 `사용법` 삭제 단계

`createLocalDocsThenSignIn()`(106행~)은 `openApp()` 직후 로컬 문서 수를 3개로 맞추려고 `사용법` 줄을 찾아 지운다(112~117행: 주석 한 줄 + `filter({ hasText: '사용법' }).first()` 를 hover → `.item-menu-btn` → `삭제` 메뉴 → `삭제` 확인). 이 헬퍼를 `F-208 A2`·`F-208 A3` 이 쓴다.

- 2026-09-18 판의 "있으면 지우고 없으면 넘어간다" 는 **틀렸다.** 빈 저장소에서는 openApp 이 `제목 없는 문서` 를 하나 만든다. 건너뛰면 그 빈 문서가 로컬에 남아 이관 대상이 되고(`migrateLocal.ts` 필터는 `사용법` 원문만 거른다) `server.docs.size` 가 3 이 아니라 4 가 된다
- 새 규칙: **openApp 직후 `.tree-row` 가 정확히 1개인지 단정한 뒤, 그 한 줄을 제목과 무관하게 지운다.** 그 뒤 삭제 조작(메뉴·확인 버튼)은 지금과 같다. 주석은 "openApp 이 남긴 문서 하나(사용법이든 새 문서든)를 지워 3개로 맞춘다" 뜻으로 한 줄
- 뒤이은 개수 단정(`server.docs.size` 3, 제목 셋)은 바꾸지 않는다 — 위 규칙이면 두 상태 모두 3 이 나온다(실측, 5.2)

### 3.3 문서 0개 모사 스위치 — `E2E_NO_FIRST_RUN_DOC`

H2 는 "첫 실행 분기가 없어진 세상" 에서 openApp 호출부 전체를 돌려 보는 판정이다. `App.tsx` 를 임시로 고쳐 빌드했다 되돌리는 대신 **테스트 쪽 설정으로 분기를 끈다.** 분기 조건이 `md.firstRunDone` 이 비어 있을 것이므로(3.0), 그 값을 페이지 스크립트보다 먼저 넣으면 빈 저장소가 그대로 0개로 뜬다 — `homeScreen.spec.js`(F-232 A3 등)·`exportWorkspace.spec.js`(F-281 A15)·`docSearch.spec.js` `seedThreeDocs`·`map.spec.js` `openMapWithDocs`·`landing.spec.js`(F-271 A7)가 이미 같은 방법을 쓴다.

계약:

| 항목 | 값 |
| --- | --- |
| 환경 변수 | `E2E_NO_FIRST_RUN_DOC` |
| 켜짐 | 값이 정확히 `'1'` 일 때만. 없거나 다른 값이면 지금과 똑같다 |
| 효과 | `openApp()` 이 맨 먼저 `setPrefBeforeLoad(page, 'md.firstRunDone', '1')` 를 부른다 |
| 범위 | `openApp()` 을 부르는 테스트만. `openAppHome`·직접 `page.goto` 하는 테스트는 그대로다 |

일괄 적용 방식을 이렇게 고른 이유:
- **`openApp()` 안에 두면 "openApp 을 부르는 모든 spec" 과 정확히 같은 범위**가 된다. 소유 파일(`e2e/helpers.js`) 안이라 소유 밖 파일이 diff 에 남지 않는다
- 환경 변수는 Playwright 워커까지 그대로 내려간다 — `scripts/e2e-one.mjs`·`scripts/verify.mjs` 모두 `spawnSync(..., { env: { ...process.env, ... } })` 로 넘긴다. 스크래치에서 워커 안 `process.env.E2E_NO_FIRST_RUN_DOC === '1'` 을 확인했다
- 버린 방법: (a) 헬퍼 모듈 최상위의 전역 `test.beforeEach` — 모듈 캐시 때문에 워커마다 처음 읽힌 spec 파일 하나에만 붙는다. (b) `playwright.config.js` 의 `use.storageState` 나 fixture 로 localStorage 를 심기 — 소유 밖이고, 켜고 끌 때마다 설정 파일을 고쳐야 한다. (c) `App.tsx` 임시 수정 — `src` 를 건드렸다 되돌리는 위험(2026-09-18 판의 방식)
- 이미 `md.firstRunDone` 을 스스로 심는 테스트와 **충돌하지 않는다.** 그 다섯 파일의 해당 테스트는 전부 `openAppHome` 이나 직접 `page.goto` 를 쓰고 `openApp` 을 부르지 않는다(grep 확인). 설령 겹쳐도 같은 값 `'1'` 을 두 번 쓰는 `addInitScript` 라 결과가 같다
- `setPrefBeforeLoad` 의 순서: `md.startScreen` 보다 먼저든 뒤든 서로 다른 키라 상관없다. 3.1 은 "맨 먼저" 로 고정해 읽기 쉽게만 한다

실행 예 (PowerShell): `$env:E2E_NO_FIRST_RUN_DOC='1'; npm run verify:full` 또는 `$env:E2E_NO_FIRST_RUN_DOC='1'; npm run e2e:one -- "F-208"`. 끝나면 `Remove-Item Env:E2E_NO_FIRST_RUN_DOC`.

스위치는 **커밋에 남긴다**(9장 Q1). F-257 7장이 분기를 없앤 뒤에는 효과가 없는 줄이 되므로 F-257 7장 구현이 함께 지운다(7장 갱신 대상).
