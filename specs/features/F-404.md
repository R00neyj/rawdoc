## 3. 키 상태 기계 — `src/e2ee/keyring.ts`

### 3.1 범위(scope) — 한 페이지에 열쇠고리 하나

저장소는 부팅 때 한 번 고른다(F-207 2.6, `openStore`). 열쇠고리도 그 결과로 한 번 정하고 페이지가 사는 동안 바꾸지 않는다

| `store.kind` | 범위 | 키 묶음 |
| --- | --- | --- |
| `'server'` (로그인, 또는 오프라인 부팅에서 저장된 계정) | `{ kind: 'account', userId: (store as ServerStore).userId }` | 서버 `e2ee_keys` + 기기 캐시 행 `account:{userId}` |
| `'idb'` (로그아웃) | `{ kind: 'local' }` | 기기 행 `local` |
| `'memory'` | 없음 — 금고 기능 전체를 그리지 않는다(설정 탭·팔레트·상태바 모두) | — |
| 공개 보기·공유 링크 화면 | 없음 | — |

### 3.2 상태

| 상태 | 뜻 | 들어오는 때 |
| --- | --- | --- |
| `unknown` | 아직 키 묶음을 읽지 않았다 | 처음 |
| `loading` | 읽는 중 | `load()` |
| `unavailable` | 읽지 못했고 기기 캐시도 없다 | 계정 범위에서 요청 실패 + 캐시 행 없음, 또는 IndexedDB 오류 |
| `none` | 금고가 없다 | 읽었더니 없음(서버 404 `no_vault`·로컬 행 없음), 초기화 성공 |
| `locked` | 금고가 있고 이 탭에 키가 없다 | 읽었더니 있음, 잠그기 성공 |
| `open` | 이 탭 메모리에 MK 가 있다 | 열기·만들기·복구 코드로 새 암호 정하기 성공 |

- **읽는 때는 "필요할 때" 뿐이다. 부팅 때 읽지 않는다** — 금고를 안 쓰는 사람에게 부팅마다 요청 하나를 더하지 않고, 터미널 로그인 화면이 `md-docs` 를 만들지 않아야 해서다(k9). 읽는 때: ① 설정 `금고` 탭이 보일 때마다 ② 팔레트를 열 때 상태가 `unknown` 이면 한 번 ③ 열기·만들기·암호 바꾸기·복구·초기화를 시작할 때마다(그 동작의 첫 단계로) ④ F-405 가 잠긴 금고 문서를 보일 때
- ③ 이 "매번 새로 읽기" 인 이유: 다른 탭·기기가 그 사이 금고를 만들었거나 암호를 바꿨으면 옛 묶음으로 열거나 덮어쓰게 된다. 로컬 읽기는 IndexedDB 한 번, 계정은 `GET` 한 번이다
- `open` 에서 `load()` 를 부르면 상태를 바꾸지 않는다(키를 버리지 않는다). 읽은 결과가 `none` 이면(다른 곳에서 초기화) 잠그기 이유 `reset` 으로 잠근 뒤 `none`
- 상태가 바뀔 때마다 `subscribe` 로 받은 함수를 부른다. React 는 상태 이름만 들고, **MK 는 열쇠고리 안(닫힌 변수)에만 둔다** — React 상태·`ref`·전역·IndexedDB·`sessionStorage` 어디에도 두지 않는다. `CryptoKey` 는 IndexedDB 에 구조적 복제로 들어갈 수 있으므로 이 금지를 코드 검토 기준으로 적는다(A3)

### 3.3 계약 — 다른 명세가 부르는 면

```ts
// src/e2ee/keyring.ts
export type E2eeScope = { kind: 'local' } | { kind: 'account'; userId: string }
export type E2eeStatus = 'unknown' | 'loading' | 'unavailable' | 'none' | 'locked' | 'open'
export type E2eeLockReason = 'manual' | 'idle' | 'other-tab' | 'account' | 'reset' | 'page-restore'
export type E2eeLockPhase = 'flush' | 'unmount' | 'indexes' | 'blobs'
export type E2eeLockOutcome = 'locked' | 'deferred' | 'aborted' | 'not-open'

export type Keyring = {
  readonly scope: E2eeScope
  getStatus(): E2eeStatus
  subscribe(listener: () => void): () => void
  getMasterKey(): CryptoKey | null // open 이고 잠그기 ⑥ 전일 때만. F-405~F-408 이 쓴다
  registerLockStep(phase: E2eeLockPhase, step: () => void | Promise<void>): () => void
  registerResetStep(step: () => Promise<void>): () => void // F-405: 금고 문서·폴더 지우기
  lock(reason: E2eeLockReason): Promise<E2eeLockOutcome>
}

// 화면이 문구를 고르는 오류 코드 (7.9 표)
export type E2eeActionError =
  | 'wrong-password' | 'wrong-recovery-code' | 'password-too-short'
  | 'vault-exists' | 'conflict' | 'no-vault' | 'vault-not-empty'
  | 'offline' | 'rate-limited' | 'account-blocked'
  | 'bad-bundle' | 'unsupported-version' | 'failed'

export const E2EE_LOCK_MINUTES = [5, 15, 30, 60, 240] as const
export type E2eeLockMinutes = (typeof E2EE_LOCK_MINUTES)[number]
export const E2EE_DEFAULT_LOCK_MINUTES = 30
export const E2EE_IDLE_CHECK_MS = 15_000
export function parseLockMinutes(raw: string): E2eeLockMinutes     // 목록 밖·빈 값·숫자 아님 → 30
export function isIdleExpired(lastActivityAt: number, now: number, lockMinutes: number): boolean
```

- 열기·만들기·암호 바꾸기·복구·초기화를 부르는 함수의 이름과 모양은 구현 재량이다(부르는 곳이 `useE2ee.ts` 하나뿐). 다만 결과는 성공이거나 위 `E2eeActionError` 하나다 — 화면은 7.9 표로만 문구를 고른다
- **동작은 한 번에 하나다.** 열기·만들기·바꾸기·복구·초기화 중 하나가 진행 중이면 두 번째 요청은 시작하지 않고 곧바로 `'failed'` 가 아니라 **무시**된다(화면은 진행 중에 버튼을 막으므로 도달하지 않아야 한다). 잠그기는 이 규칙 밖이다(4장)
- `isIdleExpired` 는 `now - lastActivityAt >= lockMinutes × 60,000` 이면 참이다. 경계값에서 잠근다
- F-403 오류 코드 → `E2eeActionError`: `wrong-password`·`wrong-recovery-code`·`password-too-short` 는 같은 이름, `bad-recovery-code` → `wrong-recovery-code`(화면 문구가 하나 — F-400 5.1 P1), `bad-bundle` 은 그대로, `unsupported-version` 은 그대로, 그 밖(`bad-envelope`·`decrypt-failed`·`bad-argument`) → `failed`

### 3.4 동작별 규칙

| 동작 | 순서 | 성공 뒤 상태 | 실패 |
| --- | --- | --- | --- |
| 읽기 `load` | 출처 `read()` → 있음이면 `parseKeyBundle` 로 형식만 확인 | `locked`(열려 있으면 그대로) / `none` / `unavailable` | 형식이 틀리면 상태 `locked` 로 두고 열기에서 `bad-bundle` 을 돌려준다(초기화로 빠져나갈 길을 남긴다) |
| 열기 | 새로 읽기 → 없으면 `no-vault`(상태 `none`) → `openWithPassword` → `open`. `upgradedBundle` 이 있으면 **열린 뒤** 출처 `replace(새 묶음, 읽은 값)` 을 한 번 보낸다. 그 쓰기의 실패·충돌은 삼킨다(다음 열기 때 다시) | `open`, 마지막 활동 시각 = 지금 | `wrong-password`·`bad-bundle`·`unsupported-version`·`offline`(계정, 캐시 없음)·`failed` |

| 암호 바꾸기 | 새로 읽기 → `changePassword(읽은 묶음, 지금 암호, 새 암호)` → 출처 `replace(새 묶음, 읽은 값)` | 그대로(`open` 이면 `open`, `locked` 이면 `locked`) — MK 가 같으므로 잠그지 않는다 | `wrong-password`·`password-too-short`·`conflict`·`no-vault`·쓰기 오류 |
| 복구 코드로 새 암호 | 새로 읽기 → `openWithRecoveryCode` 로 코드만 확인(HKDF, 빠르다) → 새 암호 두 칸 → `resetWithRecoveryCode` → **새 복구 코드를 보이고 확인받은 뒤** 출처 `replace(새 묶음, 처음 읽은 값)` → 성공하면 MK 를 들인다 | `open` | `wrong-recovery-code`·`password-too-short`·`conflict`·`no-vault`·쓰기 오류 |

- **MK 는 저장이 성공한 뒤에만 들인다**(만들기·복구). 저장이 실패했는데 열린 채가 되면, 그 MK 로 만든 문서 키가 어디에도 없는 묶음에 매인다
- **복구 코드는 저장 전에 보인다**(만들기·복구 둘 다). 저장 뒤에 보이면, 사용자가 코드를 보기 전에 대화상자를 닫았을 때(Esc·바깥 클릭 — `Dialog.tsx` 는 둘 다 닫는다) 유효한 코드가 사라진다. 저장 전이면 닫아도 아무것도 바뀌지 않는다. 저장이 실패하면 같은 묶음을 다시 보낸다 — 이미 받아 적은 코드가 그대로 유효하다
- 쓰기 충돌은 "읽은 뒤 다른 탭·기기가 먼저 썼다" 는 뜻이다. 판정은 5.3 이 한다

## 4. 잠그기

### 4.1 순서 (F-400 2.5 — 순서 자체가 규칙)

`lock(reason)` 은 아래를 이 순서로 한다

1. 상태가 `open` 이 아니면 `'not-open'`. 이미 잠그는 중이면 그 잠그기의 결과를 같이 돌려준다(한 번만 돈다)
2. **IME 조합 중이면 미룬다** — 이유를 적어 두고 `'deferred'`. 4.2 의 때에 다시 시도한다
3. 단계 `flush` → `unmount` → `indexes` → `blobs` 를 차례로. 같은 단계 안에서는 등록 순서대로, 하나씩 기다린다
4. 키를 버린다(열쇠고리가 MK 참조를 놓는다) → 상태 `locked`
5. 이유가 `manual`·`idle`·`reset` 이면 탭 채널로 `e2ee-lock` 을 보낸다. `other-tab`·`account`·`page-restore` 는 보내지 않는다(받은 신호를 되돌려 보내지 않기 위해서, 그리고 계정·되돌아온 페이지는 이 탭만의 사정이라서)

| 단계 | F-400 2.5 | 누가 등록 | 실패하면 |
| --- | --- | --- | --- |
| `flush` | ② 대기 중인 금고 문서 저장을 **암호화해 캐시에 쓰는 것까지** | F-405 | **잠그기를 멈춘다** — 키를 버리지 않고 상태 `open` 그대로, `'aborted'`, 알림 E14. 편집을 잃지 않는 쪽이다 |
| `unmount` | ③ 금고 문서 편집기를 내리고 P1 을 띄운다 | F-405 | 기록만(`console.error`), 계속 |
| `indexes` | ④ 검색·지도 메모리 색인 비우기 | **이 명세** — App 이 `resetSearchIndexCache`·`resetMapIndexCache` 를 등록한다 | 기록만, 계속 |
| `blobs` | ⑤ 금고 첨부 `blob:` 거두기 | F-406 | 기록만, 계속 |

- ①(조합)은 2번, ⑥(키 버리기)은 4번이다
- `aborted` 뒤: 자동 잠금이면 다음 검사(4.3)에서 다시 시도한다. 알림 E14 는 **한 번 열린 동안 한 번만** 띄운다(15초마다 같은 오류 알림이 뜨지 않게). 잠그기가 성공하면 다시 띄울 수 있다
- 단계 1~3 동안 `getMasterKey()` 는 MK 를 돌려준다 — `flush` 가 암호화에 쓴다. 4번 뒤로는 `null`

### 4.2 IME 조합 판정

- `useE2ee.ts` 가 `window` 에 캡처 단계로 `compositionstart`(조합 표지 켬)·`compositionend`(끔)·`blur`(끔)를 단다. **조합 중** = 표지가 켜져 있고 `document.hasFocus()` 이고 `document.visibilityState === 'visible'` — F-303 5.4 "초점을 잃은 조합은 끝난 것" 과 같은 판정이다(`remoteGate.ts` `compositionAlive` 와 같은 세 조건). 편집기 본문·제목·표 칸·대화상자 입력칸 어디의 조합이든 잡는다
- 미룬 잠그기를 다시 시도하는 때: `compositionend`, `window` `blur`, `visibilitychange`. 다시 시도는 이유를 그대로 쓴다. 미룬 동안 잠그기 요청이 더 오면 이유는 처음 것을 둔다
- 불변조건 "조합 중 보류한 일은 조합이 끝나면 따라잡는다" 를 지키는 장치다 — `compositionend` 이벤트 처리 안에서 바로 잠그지 말고 한 틱 뒤(`setTimeout 0`)에 한다. 편집기가 `compositionend` 에서 하는 `forceRecalc`(F-103)와 조합 글자의 마지막 트랜잭션이 먼저 끝나야 `flush` 가 그 글자를 저장한다

### 4.3 자동 잠금 — 무엇을 재나

- **"쓴다"** = 그 탭 문서의 `keydown`·`pointerdown`·`wheel`(F-400 2.5). `window` 캡처 단계, `passive: true`. `mousemove`·`scroll`·`focus` 는 세지 않는다. 금고가 `open` 일 때만 센다
- **활동 이벤트를 받으면 먼저 검사하고, 그다음 시각을 적는다.** 40분 비운 탭에서 누른 첫 키가 시계를 되돌리면 안 된다 — 그 키는 잠그기를 부르고 그 자체는 활동으로 적힌다(잠긴 뒤라 의미 없다)
- 검사하는 때(각각 `isIdleExpired(마지막 활동, Date.now(), 설정값)` 이 참이면 `lock('idle')`):
  1. 열려 있는 동안 `setInterval` `E2EE_IDLE_CHECK_MS`(15,000ms)마다. 잠그면 멈춘다
  2. `visibilitychange`(보이게 될 때·숨을 때 둘 다)
  3. 활동 이벤트마다(위 규칙)
  4. `pageshow` — `persisted` 가 참(뒤로 가기 캐시에서 되돌아옴)이면 검사 없이 `lock('page-restore')`(11장 Q4)
- 열 때(열기·만들기·복구) 마지막 활동 = 지금
- **타이머 하나로 30분을 재지 않는다**(F-400 2.5). 절전·숨은 탭에서 타이머가 늦거나 멈춰도 다음 검사가 `Date.now()` 와 비교하므로 늦게라도 맞게 잠근다
- 숨은 탭에서 검사가 얼마나 늦어지나: 재지 못했다(11.3 m1). 늦어진 동안에도 **보이게 되는 순간**(2번)과 **첫 입력**(3번)에서 잠그므로, 늦음은 "숨은 탭 메모리에 키가 남는 시간" 만 늘린다
- 설정값을 바꾸면 다음 검사부터 새 값이다. 새 값이 이미 지난 시간보다 짧으면 다음 검사(최대 15초 뒤)에 잠근다
- 설정값은 `getPref('md.e2eeLockMinutes', '30')` 을 `parseLockMinutes` 로 읽는다 — 검사할 때마다 읽는다(다른 탭에서 바꾼 값도 따라간다)

### 4.4 탭 사이 — 잠그기만 전파

```ts
// src/app/tabSync.ts TabMessage 에 더하는 것
| { kind: 'e2ee-lock'; tabId: string }
```

- 보냄: 4.1 5번. `useTabSync` 가 돌려주는 `post` 로 보낸다. 채널이 없거나(부팅 전·`BroadcastChannel` 없음) 닫혔으면 안 보낸다 — 다른 탭은 자기 자동 잠금에 맡긴다
- 받음: `useTabSync` 가 `e2ee-lock` 을 받으면(자기 `tabId` 는 무시) 새 옵션 `onE2eeLock()` 을 부른다. 받은 탭은 `open` 이면 `lock('other-tab')`, 아니면 아무것도 안 한다. **열기 중(유도 계산 중)인 탭은 잠그지 않는다** — 그 탭 사용자가 방금 연 것이 더 새 뜻이다
- `reduceClaim` 은 `e2ee-lock` 에 `null`(편집권 판정과 무관)
- 범위를 싣지 않는다: 같은 브라우저의 탭은 같은 로그인 쿠키를 쓰므로 범위가 같다. 범위가 달라도(한 탭은 로그아웃 뒤 옛 페이지) 잠그는 것은 해가 없다
- **풀기·만들기·암호 바꾸기는 보내지 않는다.** 다른 탭은 필요할 때 새로 읽는다(3.2)

### 4.5 로그아웃·계정 바뀜

- 이 탭에서 로그아웃: `AccountMenu` `handleLogout` 이 `logout()` 성공 뒤 `location.replace` **전에** 새 prop `onLoggedOut()` 을 부르고, App 은 거기서 `e2ee-lock` 을 보낸다. 이 탭은 곧 페이지를 떠나 메모리가 사라진다(잠그기 단계를 기다리지 않는다)
- 다른 이유로 계정이 바뀜: App 의 `applyAccountFlags` 가 받은 결과가 `out` 이거나 `in` 인데 `id` 가 열쇠고리 범위의 `userId` 와 다르면 `lock('account')`. `offline` 은 바뀜으로 보지 않는다. 로컬 범위에는 해당 없다
- 알림 E13 은 `account` 로 실제로 잠갔을 때만


- `DB_VERSION` 5, `upgrade` 에 `if (oldVersion < 5) createObjectStore('e2ee', { keyPath: 'id' })`. `meta` `schema` 가 5 가 된다
- `bundle` 은 **JSON 문자열**이다(F-400 4.1 은 로컬 행을 객체로 적었다 — 11장 Q1 에 함께 적는다). 계정 캐시가 서버가 준 문자열과 `rev` 를 그대로 짝지어 들어야 하고, 두 행을 같은 한 길(`parseKeyBundle`)로 검사하려는 것이다
- 행 함수는 **부를 때마다 연결을 열고 끝나면 닫는다.** `createIdbStore` 와 같은 `upgrade` 를 쓴다(한 함수로 모은다) — 로그인 사용자의 브라우저에 `md-docs` 가 아직 없으면 이 열기가 v1~v5 스토어를 모두 만든다(F-208 이관의 `readLocal` 이 이미 하는 일과 같다). `blocking` 이 오면 곧바로 닫는다. 열기가 5,000ms 안에 끝나지 않으면(다른 창에 막힘) 실패로 친다 → 출처가 `failed`
- **`CryptoKey` 는 이 스토어에 절대 넣지 않는다.** 들어가는 것은 묶음 문자열·`rev`·시각뿐이다
- F-405 는 문서·폴더·첨부 행에 필드만 더하므로 버전을 다시 올리지 않는다. F-408 은 로컬 행에 필드를 더한다(버전 그대로)

### 5.2 서버 — `src/e2ee/keysApi.ts`

F-401 3.1 의 세 라우트를 부른다. `credentials: 'same-origin'`, 쓰기는 `Content-Type: application/json`

```ts
export type KeysGet = { kind: 'found'; bundle: string; rev: number } | { kind: 'none' } | { kind: 'error'; reason: KeysErrorReason }
export type KeysPut = { kind: 'ok'; rev: number } | { kind: 'conflict'; rev: number } | { kind: 'error'; reason: KeysErrorReason }
export type KeysDelete = { kind: 'ok' } | { kind: 'not-empty'; docs: number; folders: number } | { kind: 'error'; reason: KeysErrorReason }
export type KeysErrorReason = 'offline' | 'unauthorized' | 'rate-limited' | 'account-blocked' | 'failed'

export function getKeys(): Promise<KeysGet>
export function putKeys(bundle: string, baseRev: number): Promise<KeysPut>
export function deleteKeys(): Promise<KeysDelete>
```

| 응답 | 분류 |
| --- | --- |
| `fetch` 가 던짐 | `offline` |
| 200 `GET` 몸통 `{ bundle: 문자열, rev: 0 이상 정수 }` | `found` — 모양이 다르면 `failed` |
| 404 `GET` `{ error: 'no_vault' }` | `none` — 몸통이 다른 404(라우트 없음 등)는 `failed` |
| 200 `PUT` `{ rev }` / 204 `DELETE` | `ok` |
| 409 `PUT` `{ error: 'conflict', rev }` | `conflict` |
| 409 `DELETE` `{ error: 'vault_not_empty', docs, folders }` | `not-empty` |
| 401 | `unauthorized` |
| 403 `{ error: 'account_blocked' }` | `account-blocked` |
| 429 | `rate-limited` |
| 그 밖(400·413·5xx·200 인데 JSON 아님) | `failed` |

- 413 `too_large` 는 F-403 묶음이 321~323자(F-403 c11)라 일어나지 않는다 — `failed` 로 둔다

### 5.3 출처 — `src/e2ee/bundleSource.ts`

```ts
export type E2eeBundleRead = { kind: 'found'; bundle: string; rev: number } | { kind: 'none' } | { kind: 'error'; reason: 'offline' | 'failed' }
export type E2eeBundleWrite =
  | { kind: 'ok' }
  | { kind: 'conflict' }
  | { kind: 'not-empty'; docs: number; folders: number } // remove 만
  | { kind: 'error'; reason: 'offline' | 'rate-limited' | 'account-blocked' | 'failed' }

export type E2eeBundleSource = {
  read(): Promise<E2eeBundleRead>
  create(bundle: string): Promise<E2eeBundleWrite>                                   // 없을 때만
  replace(bundle: string, expected: { bundle: string; rev: number }): Promise<E2eeBundleWrite>
  remove(): Promise<E2eeBundleWrite>
}
export function createLocalBundleSource(dbName?: string): E2eeBundleSource
export function createAccountBundleSource(userId: string, dbName?: string): E2eeBundleSource
```

**로컬** (`rev` 는 늘 0)

| 메서드 | 규칙 |
| --- | --- |
| `read` | 행 `local` 이 있으면 `found`, 없으면 `none`, IndexedDB 오류는 `failed` |
| `create` | `writeE2eeRow(…, { absent: true })` — 거짓이면 `conflict`(다른 탭이 먼저 만듦) |
| `replace` | `writeE2eeRow(…, { bundle: expected.bundle })` — 거짓이면 `conflict`(다른 탭이 먼저 바꿈·지움) |
| `remove` | 행을 지우고 `ok`. 로컬에는 `not-empty` 판정이 없다 — 초기화 단계(F-405)가 금고 문서를 먼저 지운다 |

**계정** (캐시 행 `account:{userId}`)

| 메서드 | 규칙 |
| --- | --- |
| `read` | `getKeys()`: `found` → 캐시 행을 덮어쓰고 `found` / `none` → 캐시 행을 지우고 `none` / `error` → 캐시 행이 있으면 그 `bundle`·`rev` 로 `found`, 없으면 `offline`(이유가 `offline` 일 때) 또는 `failed`. **`unauthorized`(세션 만료)도 캐시로 연다** — 키를 아는지는 로그인과 무관하고, 오프라인 편집(F-207)과 같은 태도다 |
| `create` | `putKeys(bundle, 0)`: `ok` → 캐시 행(`rev` = 받은 값) / `conflict` → `conflict` / `error` → 이유 그대로(`unauthorized` → `failed`) |
| `replace` | `putKeys(bundle, expected.rev)`: 같은 분기. 캐시 `rev` 가 낡았으면 서버가 409 → `conflict`, 사용자가 다시 하면 3.4 가 새로 읽는다 |
| `remove` | `deleteKeys()`: `ok` → 캐시 행 지움 / `not-empty` 그대로 / `error` → 이유 |

- **쓰기는 온라인에서만 된다**(계정). 키 묶음 쓰기를 outbox 에 넣지 않는다 — 오프라인에서 만든 금고를 나중에 올리다 다른 기기의 금고와 부딪치면 되돌릴 길이 없다. 오프라인이면 7.9 `offline` 문구
- 키 묶음 쓰기(`PUT`·`DELETE`)는 F-2024 하루·분당 한도에 센다(F-400 3.7). 반복 수 올리기 쓰기는 열 때마다가 아니라 묶음이 낡았을 때만 한 번이다

## 10. 수용 기준

### 10.1 단위 (환경 `node`)

반복 수가 필요한 곳은 F-403 `createKeyBundle(…, { iterations: 1_000 })` 으로 만든 묶음을 쓴다. 그 묶음을 여는 테스트는 F-403 이 반복 수를 올리느라 600,000회를 한 번 더 돈다(k11) — 그런 테스트는 U2 둘뿐으로 둔다

| # | 파일 | 확인 | 기대 |

| U1 | `keyring.test.ts` | 가짜 출처(메모리) + 1,000회 묶음. `load` | 없음 → `none`, 있음 → `locked`, 출처 `error offline` → `unavailable`. `subscribe` 가 상태마다 불린다 |

### 12.1 사람 확인 (specs/human-checks.md 에 더할 것)

1. 실제 한글 IME 로 본문을 조합하는 도중 다른 탭에서 `지금 잠그기` → 조합한 글자가 깨지지 않고, 조합이 끝난 뒤에 잠긴다(4.2)
2. 느린 PC 에서 `열기`·`다음`(만들기) 누른 뒤 걸리는 시간(F-400 m2 가 재지 못한 것)
3. 좁은 창(400px)에서 설정 탭 넷, `자동 잠금` 버튼 다섯, 복구 코드 한 줄이 넘치지 않는지
4. 설정 위에 겹친 D-8 에서 Esc 한 번이 D-8 만 닫는지, 초점이 `금고 만들기…` 로 돌아오는지
5. 비밀번호 관리자가 `금고 암호` 를 사이트 로그인 암호와 섞어 저장·자동 채움 하지 않는지
6. 절전에서 깨어난 뒤 곧바로 잠기는지(설정 `5분`, 10분 절전)
7. `recovery-code.txt` 를 메모장·모바일에서 열어 한글이 깨지지 않는지
8. 설정 `5분` 으로 연 탭을 다른 탭 뒤에 7분 숨겼다가 돌아오면 곧바로 잠겨 있는지(보이는 순간 검사, 4.3 — m1 을 재지 못한 대신)

## 13. 확인한 것과 가정

### 13.1 코드를 읽거나 돌려 확인한 것
- 머리 표 k1~k12
- `App.tsx` 에서 상태바는 `!sharedDoc && !mapRoute && showEditor` 일 때만 그려진다. 팔레트 문맥은 `paletteContext` 객체 한 곳에서 만든다. 탭 채널 `post` 는 `useTabSync` 가 돌려주고 부팅 `boot()` 의 `withTabBroadcast` 가 쓴다
- `Dialog.tsx` 는 Esc(`cancel`)·바깥 클릭 둘 다로 닫고, 닫을 때 연 요소로 초점을 돌린다
- `logout()` 은 `AccountMenu.tsx` `handleLogout` 에서만 부르고 성공하면 `location.replace(AFTER_LOGOUT_URL)`
- `ServerStore.userId` 가 오프라인 부팅에서도 채워진다(`openStore` 가 `md.account` 의 id 로 만든다)
- `resetSearchIndexCache`·`resetMapIndexCache` 가 각 파일에 `export function` 으로 있다

### 13.2 가정으로 남긴 것
- **Chrome 의 숨은 탭 타이머 감속 규칙(5분 넘게 숨은 탭은 1분에 한 번으로 묶는다는 "intensive throttling")** 은 기억에 기댄 것이다 — m1 은 헤드리스에서 탭이 숨지 않아 재지 못했다. 사람 확인 12.1 에 "숨은 탭에서 설정 `5분` 뒤 돌아왔을 때 곧바로 잠겨 있는지" 를 두는 것으로 대신한다
- **절전에서 깨어난 뒤 밀린 `setInterval` 이 곧바로 한 번 돈다**는 것은 재지 않았다. 안 돌아도 첫 입력·`visibilitychange` 에서 잠근다(4.3)
- `page.clock.install()` 이 앱의 `setInterval` 과 `Date.now` 를 함께 당긴다는 것은 Playwright 문서(타입 주석)로만 확인했다 — E8 이 처음 실행해 보는 곳이다
- 겹친 네이티브 `<dialog>`(`showModal` 두 번)의 Esc 가 위 것만 닫는다는 것은 HTML 규격 동작으로 알고 있다 — 12.1-4 로 사람이 본다
- Chrome 외 브라우저의 `pageshow.persisted`·`compositionend` 순서는 확인하지 않았다
