# F-2005 지도 설정 패널 틀과 `표시` 3축

작성일: 2026-09-22
상태: **승인 대기.** 사람이 꼭 골라야 하는 갈림길은 15장 Q1~Q3 셋이고 전부 기본값이 서 있다. **F-292 를 다섯 곳 뒤집거나 구체화한다**: (1) 머리 줄 버튼의 접근성 이름을 `설정` 이 아니라 **`지도 설정`** 으로 한다(5.2 에 e2e 충돌 근거), (2) **아직 내용이 없는 묶음 셋(`필터`·`그룹`·`장력`)은 그리지 않는다**(4.2), (3) `선 두께` 의 "간선 색 진하기" 를 실측 위에서 구체값으로 못 박는다(8장), (4) `노드 크기` 슬라이더가 **6.1 공식이 아니라 F-2004 가 정한 `NODE_SCALE` 에 곱한다**(3.3 — 안 그러면 기본 상태에서 노드가 절반이 된다), (5) `이름표 표시 거리` 정규값을 **그 프레임 노드 거리의 `near`~`far` 로 푼다**(7.3). 다섯 다 14장 갱신 대상에 올렸다

**`depends` 에 `F-2004` 가 없는 이유**: 로드맵(F-292 9장)상 실제 선행은 **F-2004(노드 표현)** 다. 이 명세를 쓰는 시점에 `specs/features/F-2004.md` 파일이 아직 없고, 없는 명세를 가리키는 `depends` 는 `npm run specs -- --check` 가 오류로 잡는다. **F-2004.md 가 커밋된 뒤 `depends` 에 `F-2004` 를 더한다** (메인이 이 명세를 커밋할 때 한 줄).

**이 명세가 후속 셋의 계약을 쥐고 있다.** `F-2006`(`장력` 4축)·`F-2007`(`필터`)·`F-2008`(`그룹` 색)이 전부 여기서 정하는 두 계약 위에 올라간다 — 3장(`mapPrefs.ts` 의 저장 구조와 늘리는 법)과 4장(`MapPanel.tsx` 의 묶음 등록과 공용 슬라이더). 그래서 이 명세는 자기 몫인 `표시` 3축보다 **그 둘을 더 길게 적는다.**

### 2.1 이 커밋이 끝난 시점의 상태

1. 머리 줄 오른쪽에 `맞춤` 과 `닫기` 사이로 **`지도 설정` 아이콘 버튼**이 생긴다. 누르면 오른쪽에서 패널이 밀려 들어온다
2. 패널에는 **`표시` 묶음 하나**가 펼쳐진 채 있고 슬라이더가 셋이다 — `노드 크기`·`이름표 표시 거리`·`선 두께`
3. `노드 크기` 를 끌면 **그 자리에서 노드가 커지고 작아진다.** `선 두께` 를 끌면 간선이 배경색까지 옅어졌다가 본문색까지 진해진다. `이름표 표시 거리` 를 올리면 **호버하지 않아도 가까운 노드부터 이름표가 붙는다**
4. **기본값(`1.00배` · `호버할 때만` · `50%`)에서는 F-2004 가 만든 화면이 한 픽셀도 안 바뀐다** (13장)
5. 값은 `md.mapView` 에 바로 저장되고, 지도를 닫았다 다시 열어도 그대로다. 패널 맨 아래 `기본값으로` 로 한 번에 되돌린다
6. `Esc` 는 패널만 닫는다. 지도는 그대로 있다 (F-292 5장, `ia.md` 5장)
7. 패널은 캔버스 **위에 겹친다** — 열고 닫아도 카메라가 움직이지 않는다 (6.1)

**쓸 만한가 — 판단.** 쓸 만하다. `노드 크기` 하나만으로도 F-2004 가 정한 공식이 내 화면에 맞는지 사람이 직접 맞출 수 있게 된다. 남는 아쉬움은 묶음 셋이 아직 없다는 것뿐이고, 그건 다음 세 커밋이다.

## 3. 계약 1 — `mapPrefs.ts` 와 저장 구조

### 3.1 `prefs.ts` 에서 바뀌는 것

```ts
// PrefMap 에서 'md.mapDepth' 줄을 지우고 두 줄을 더한다
'md.mapView': string
'md.mapGroups': string
```

`ALLOWED_KEYS` 에서도 `'md.mapDepth'` 를 지우고 둘을 더한다. 값 타입이 `string` 인 것은 **JSON 을 한 키에 넣는 전례**(`md.openFolders` 폴더 id 배열, `md.account` 객체 — `architecture.md` 4장 138·162행)를 그대로 따른 것이다.

- **`md.mapDepth` 는 죽은 키다.** `grep -rn "mapDepth" src/ e2e/ worker/ scripts/` 결과가 **`src/app/prefs.ts` 23행·47행 둘뿐**이다 (2026-09-22 확인). F-2002 가 단계 세그먼트를 지우면서 읽는 곳도 쓰는 곳도 사라졌다
- **기존 브라우저 localStorage 에 남은 `md.mapDepth` 항목은 지우지 않는다.** F-292 6.11 이 이미 정한 대로다 — `prefs.ts` 는 허용 키만 읽으므로 아무도 보지 않고, 지우려면 없는 삭제 함수를 새로 만들어야 한다
- `getPref`·`setPref` 는 **동기**다 (`prefs.ts` 61·74행이 `globalThis.localStorage?.getItem/setItem` 을 그대로 부른다). 읽기·쓰기 예외는 그 안에서 삼키고 기본값을 돌려준다 — `mapPrefs` 는 예외 처리를 따로 하지 않고 **JSON 파싱 실패만 자기가 막는다**

### 3.2 `md.mapView` 의 모양 — **묶음 단위 객체**

```json
{
  "display": { "nodeScale": 1, "labelDistance": 0, "edgeStrength": 0.5 },
  "force":   { "center": 0.2236, "repel": 0.6771, "linkStrength": 0.7295, "linkDistance": 0.1915 }
}
```

**평평한 객체가 아니라 묶음 단위로 나눈다.** 이유는 셋이다.

1. **검증이 묶음마다 독립이다.** `force` 가 깨져도 `display` 는 살아남는다. F-292 6.11 이 키를 둘로 나눈 것(`md.mapView`·`md.mapGroups`)과 같은 논리를 한 단계 더 적용한 것이다
2. **`force` 묶음은 이미 F-2001 이 만든 리졸버를 그대로 쓴다.** `src/lib/mapLayout3d.ts` 78행의 `resolveForceNorms(input)` 이 "모르는 키는 버리고 0~1 밖은 자르고 없으면 기본값" 을 이미 한다. F-2005 는 그 함수를 부르기만 한다
3. **묶음을 더하는 것이 한 줄이다.** F-2007 이 `filter` 묶음을 더할 때 `MapView` 타입 한 줄과 `normalizeMapView` 안 한 줄만 는다

**`display` 는 F-2005 가 쓰고, `force` 는 지금 아무도 안 읽는다.** F-2001 이 배치 엔진을 죽은 코드로 한 커밋 두었던 것(F-292 9.1)과 같은 판단이다 — 스키마가 묶음 둘로 실제로 서는 것을 이 커밋에서 확인해 두면, F-2006 은 **`mapPrefs.ts` 를 한 줄도 안 고치고** `view.force` 를 읽어 `layout.setForces()` 에 넘기고 패널에 묶음 하나를 더하기만 하면 된다.

**버전 필드(`v: 1`)를 두지 않는다.** 묶음마다 "모르는 키 버림 + 범위 밖 되돌림 + 없으면 기본값" 이 돌아서 검증이 곧 마이그레이션이다. 버전을 두면 올릴 때마다 변환 함수를 써야 하는데, 이 값들은 전부 **잃어도 기본값으로 돌아가면 그만인 표시 설정**이다.

### 3.3 `표시` 3축 정의 — `MAP_DISPLAY_AXES`

`mapLayout3d.ts` 의 `MAP_FORCE_AXES`(26~31행)와 같은 모양으로 둔다. **숫자는 여기, 화면 문구는 `MapPanel.tsx` 에** — F-2001 이 쓴 분업 그대로다.

```ts
export type MapDisplayAxis = 'nodeScale' | 'labelDistance' | 'edgeStrength'

export type MapDisplayAxisSpec = {
  readonly min: number
  readonly max: number
  readonly step: number
  readonly start: number
}

export const MAP_DISPLAY_AXES: Readonly<Record<MapDisplayAxis, MapDisplayAxisSpec>> = Object.freeze({
  nodeScale: Object.freeze({ min: 0.5, max: 3, step: 0.05, start: 1 }),
  labelDistance: Object.freeze({ min: 0, max: 1, step: 0.01, start: 0 }),
  edgeStrength: Object.freeze({ min: 0, max: 1, step: 0.01, start: 0.5 }),
})
```

| 축 | 범위 | 기본 | 단위 | 무엇이 되나 |
| --- | --- | --- | --- | --- |
| `nodeScale` (`노드 크기`) | 0.5 ~ 3.0 | **1.0** | **지금 화면 대비 배율** | `MapScene.tsx` 의 `NODE_SCALE`(48행, F-2004 가 `2.0` 으로 정한 값)에 **곱한다** (7.2) |
| `labelDistance` (`이름표 표시 거리`) | 0 ~ 1 | **0** | 정규값 | 0 이면 호버할 때만. F-2004 의 `pickLabelNodes` 후보에 더한다 (7.3) |
| `edgeStrength` (`선 두께`) | 0 ~ 1 | **0.5** | 정규값 | 간선 색 진하기 (8장) |

- **범위·기본값은 F-292 6.6 표 그대로다.** `노드 크기` 만 정규값이 아니라 배율인 것도 그 표대로다 — 배율은 그 자체가 사람이 읽을 수 있는 수라 정규화할 이유가 없다 (장력 4축이 정규값인 이유는 "내부 범위를 나중에 바꿔도 저장값이 안 깨지게" 인데, 배율에는 바꿀 내부 범위가 없다)
- **`nodeScale` 은 `nodeRadius()` 의 `scale` 인자가 아니라 그 위의 배율이다.** F-2004 가 `MapScene.tsx` 48행에 `const NODE_SCALE = 2.0` 을 두었고, 주석이 "2.0 인 것은 고립 문서가 F-2003 까지의 고정 반지름 6.0 과 같아지는 값이기 때문이다 — 공식만 넣으면 3.0 이라 점이 작아 보인다(사용자 지시 2026-09-22)" 라고 적고 있다. **슬라이더가 `nodeRadius` 에 값을 그대로 넘기면 기본 상태에서 노드가 절반으로 줄어 그 지시를 뒤집는다.** 그래서 실제로 넘기는 값은 `NODE_SCALE * view.display.nodeScale` 이고, **슬라이더 1.00배 = 지금 화면 그대로**다. 나중에 F-2004 가 `NODE_SCALE` 을 다시 손봐도 사용자가 저장해 둔 `1.2배` 는 여전히 "기본보다 20% 큼" 을 뜻한다
- `step` 은 슬라이더가 멈추는 눈금이다. `노드 크기` 0.05 는 0.5~3.0 을 50칸으로, 나머지 둘의 0.01 은 100칸으로 나눈다

### 3.4 내보내는 것

```ts
export type MapDisplay = Record<MapDisplayAxis, number>
export type MapView = { display: MapDisplay; force: MapForceNorms }
export type MapGroup = { q: string; c: number }

export const MAP_GROUP_MAX = 8

export function defaultMapView(): MapView
export function normalizeMapView(raw: unknown): MapView
export function loadMapView(): MapView
export function saveMapView(view: MapView): void

export function normalizeMapGroups(raw: unknown): MapGroup[]
export function loadMapGroups(): MapGroup[]
export function saveMapGroups(groups: MapGroup[]): void
```

**검증 규칙 — 전부 못 박는다.**

| 무엇 | 어떻게 |
| --- | --- |
| `md.mapView` 가 없다 / 빈 문자열 | `defaultMapView()` |
| JSON 파싱 실패 | `defaultMapView()` |
| 최상위가 객체가 아니다 (배열·문자열·`null`) | `defaultMapView()`. **배열도 객체가 아닌 것으로 본다** (`Array.isArray` 로 거른다) |
| 모르는 최상위 키 (`{"wat": 1}`) | **버린다.** 결과 객체에 남기지 않는다 |
| `display` 가 객체가 아니다 | 그 묶음 전체를 기본값으로 |
| `display` 안 모르는 키 | 버린다 |
| `display` 안 축 값이 유한수가 아니다 (문자열·`null`·`NaN`·`Infinity`) | **그 축만** `start` 로. 나머지 축은 살아남는다 |
| `display` 안 축 값이 범위 밖 | **자른다**(clamp). `nodeScale: 99` → `3`, `-5` → `0.5` |
| `force` | `resolveForceNorms(raw.force)` 에 그대로 넘긴다 (F-2001 이 같은 규칙을 이미 구현했다) |
| `md.mapGroups` 가 배열이 아니다 / 파싱 실패 | `[]` |
| 항목이 객체가 아니거나 `q` 가 문자열이 아니다 | **그 항목을 버린다** |
| 항목의 `c` 가 1~8 정수가 아니다 | **`1` 로 되돌린다.** 항목은 살린다 — 사용자가 쓴 쿼리를 색 하나 때문에 잃게 하지 않는다 |
| 항목이 9개 이상 | **앞에서부터 8개만 남긴다** (F-292 11.2 B6 "그룹 9개째는 버린다") |
| 항목의 모르는 키 | 버린다. 결과는 언제나 `{ q, c }` 둘뿐이다 |

- **`saveMapView` 는 객체 전체를 쓴다.** 기본값이어도 생략하지 않는다 — 저장 크기가 147 B 이고(측정, 6.3) 생략 규칙이 늘면 읽기 쪽이 복잡해진다
- **읽을 때 버린 키는 다음 저장에서 사라진다.** 배포를 되돌려 옛 버전이 도는 동안 새 묶음 값이 지워질 수 있다. 받아들인다 — 표시 설정이라 다시 맞추면 그만이다

### 3.5 축 하나를 더하려면 어디를 고치나 (F-2006·F-2007 에게)

**같은 묶음 안에 축을 하나 더할 때는 두 곳이다.** (1) `mapPrefs.ts` 의 그 묶음 축 표(`MAP_DISPLAY_AXES` 같은 것)에 `{ min, max, step, start }` 한 줄, (2) `MapPanel.tsx` 의 그 묶음 문구 표에 `{ label, format }` 한 줄. 검증도 저장도 슬라이더 렌더도 전부 그 표를 돌면서 하므로 `normalizeMapView`·`MapSlider`·JSX 는 손대지 않는다. **묶음을 통째로 더할 때는 네 곳이다.** (1) `MapView` 타입에 그 묶음 한 줄, (2) `normalizeMapView` 안에 그 묶음 리졸버 호출 한 줄, (3) `MapPanel.tsx` 의 `SECTION_READY` 배열에 그 묶음 id 한 줄, (4) `renderSection()` 의 `switch` 에 `case` 하나. **`SECTION_ORDER`·`SECTION_TITLE` 은 이미 네 묶음이 다 적혀 있어 건드리지 않는다** (4.2).

## 4. 계약 2 — `MapPanel.tsx`

### 4.1 props

```tsx
type MapPanelProps = {
  view: MapView
  // 값이 바뀔 때마다 부른다. MapPage 가 상태를 바꾸고 그 자리에서 저장한다 (6.3)
```

- **`onCommit` 을 따로 두지 않는다.** 이유는 6.3 (저장 비용을 실제로 쟀다)
- **F-2006 이 `onCommit` 을 한 번 더했다가 F-2012 가 다시 뺐다.** 저장 때문이 아니라 **슬라이더에서 손을 뗄 때 카메라를 다시 맞추려고** 네이티브 `change` 리스너를 달았던 것인데(F-2006 6.4), 장력을 바꿀 때 카메라를 안 맞추기로 정해지면서 쓸 데가 없어졌다 (F-2012 3.3, 사람 결정 2026-09-22). **Q2 의 결론(저장은 입력마다)은 처음부터 끝까지 그대로다**
- `MapPanel` 은 `mapPrefs` 를 **직접 읽거나 쓰지 않는다.** 저장소를 아는 것은 `MapPage` 하나다 — 그래야 F-2007 이 필터를 더할 때도 저장 지점이 하나로 남는다

### 4.2 묶음 등록 — 표 셋과 `switch` 하나

```tsx
type SectionId = 'filter' | 'group' | 'display' | 'force'

// 화면에 쌓이는 순서. F-292 6.3 의 네 묶음을 그대로 적어 둔다
const SECTION_ORDER: readonly SectionId[] = ['filter', 'group', 'display', 'force']

const SECTION_TITLE: Record<SectionId, string> = {
  filter: '필터',
  group: '그룹',
  display: '표시',
  force: '장력',
}

// 지금 내용이 있는 묶음. 빈 껍데기를 미리 그리지 않는다 (ia.md 8장, F-2002 15장 Q3)
const SECTION_READY: readonly SectionId[] = ['display']
```

**F-2007 이 실제로 `['filter', 'display', 'force']` 로 바꿨다** (F-2006 이 먼저 `'force'` 를 더했고, F-2007 이 `'filter'` 를 앞에 더했다). 그리고 **보기 모드별 목록**을 새로 뒀다 — `SECTION_IN_LIST = ['filter']`, `sectionsFor(mode)` 가 `mode === 'list'` 면 `SECTION_IN_LIST`, 아니면 `SECTION_READY` 로 거른다 (11.3)

- **그리는 묶음은 `SECTION_ORDER.filter((id) => SECTION_READY.includes(id))` 다.** F-2006 은 `SECTION_READY` 에 `'force'` 한 단어를 더하고 `renderSection` 에 `case 'force'` 하나를 더하면 자리가 `표시` 아래로 자동으로 잡힌다
- **빈 묶음은 아예 그리지 않는다** (제목만 두지도, `준비 중` 문구를 두지도 않는다). 근거: `specs/ia.md` 8장 "빈 공간이나 비활성 UI 로 미리 만들지 않는다", F-2002 15장 Q3(머리 줄 `설정` 버튼을 미리 두지 않은 판단), F-2003 2장(죽은 메뉴 항목을 한 커밋 동안 보이게 두지 않은 판단). **F-292 6.3 표의 네 묶음은 "다 채워졌을 때의 모습" 으로 읽는다**
- **펼침 규칙: 그리는 묶음 중 맨 위 하나만 펼쳐져 있다.** 네 묶음이 다 차면 맨 위가 `필터` 라 F-292 6.3 의 "`필터` 만 펼침" 과 정확히 같아지고, 지금처럼 `표시` 하나뿐이면 그것이 펼쳐진다. 규칙 하나로 두 상태를 다 덮는다
- **펼침 상태는 저장하지 않는다.** 패널을 열 때마다 위 규칙으로 다시 잡는다. 여러 묶음을 동시에 펼칠 수 있다(아코디언이 아니다)
- **패널 열림 상태도 저장하지 않는다.** 지도를 열면 언제나 접혀 있다 (F-292 6.3 "기본 접힘")

### 4.3 공용 슬라이더 `MapSlider` — F-2006 이 그대로 쓴다

**저장소에 `input[type=range]` 를 쓰는 곳이 한 군데도 없다** (`grep -rn 'type="range"' src/` 결과 0건, 2026-09-22). 그래서 여기서 처음 만든다. `MapPanel.tsx` 안에 두고 **내보내지 않는다** — F-2006 도 같은 파일에 묶음을 더하므로 파일 밖으로 낼 이유가 없다.

```tsx
type MapSliderProps = {
  id: string
  label: string
  min: number
  max: number
  step: number
  value: number
  // 화면에 보이는 값 문자열. 0~1 정규값 → 실제 범위 매핑이 들어올 자리다 (F-2006)
  format: (value: number) => string
  onChange: (value: number) => void
}
```

```tsx
<div className="map-slider">
  <label htmlFor={id}>{label}</label>
  <span className="map-slider-value" aria-hidden="true">{text}</span>
  <input
    id={id}
    type="range"
    min={min}
    max={max}
    step={step}
    value={value}
    aria-valuetext={text}
    onChange={(e) => onChange(Number(e.currentTarget.value))}
  />
</div>
```

- **`format` 이 곡선 매핑이 들어올 자리다.** F-2006 은 슬라이더의 `value` 로 **0~1 정규값**을 그대로 넘긴다. **다만 화면 문자열을 실제 단위로 만들지 않기로 했다** — `format={(v) => `${Math.round(v * 100)}%`}` 로 정규값을 그대로 퍼센트로 보여 준다 (F-2006 7.3). `800` 이나 `0.02` 같은 내부 단위는 사용자에게 뜻이 없고, 퍼센트는 슬라이더 위치와 눈이 맞는다. 그래서 **F-2006 은 `normToForceValue`·`toForceValues` 를 안 부른다.** 곡선 자체는 F-2006 이 정한다 (F-292 6.7)
- **값 문자열을 `<label>` 안에 넣지 않는다.** 넣으면 접근성 이름이 `노드 크기 1.00배` 가 되어 `getByRole('slider', { name: '노드 크기', exact: true })` 가 안 맞는다. `<label for>` 은 이름만, 값은 옆의 `aria-hidden` span 과 `aria-valuetext` 로 준다
- **`onChange` 는 React 가 네이티브 `input` 이벤트에 매어 둔 것이다.** 끄는 내내 프레임마다 들어온다. 네이티브 `change` 를 따로 듣지 않는 이유는 6.3

`표시` 묶음의 문구 표 (`MapPanel.tsx` 안):

| 축 | `label` | `format` |
| --- | --- | --- |
| `nodeScale` | `노드 크기` | `${v.toFixed(2)}배` → `1.00배` |
| `labelDistance` | `이름표 표시 거리` | `0` 이면 `호버할 때만`, 아니면 `${Math.round(v * 100)}%` |
| `edgeStrength` | `선 두께` | `${Math.round(v * 100)}%` |

### 4.4 `기본값으로`

패널 맨 아래에 버튼 하나. 누르면 `onChange(defaultMapView())` 로 **`md.mapView` 전체**(`display` + `force`)를 기본값으로 되돌린다. **`md.mapGroups` 는 건드리지 않는다** — F-292 6.11 이 키를 둘로 나눈 이유가 정확히 이것이다("슬라이더 `기본값으로` 가 사용자가 만든 그룹까지 지우면 안 된다").

- **F-2007 이 이 조건을 뒤집었다.** 필터·그룹은 `목록` 에도 반영되므로(F-292 6.8) `지도 설정` 버튼은 이제 두 보기에서 다 그려진다 — `맞춤` 버튼만 `effectiveView === 'graph'` 조건에 남고 `지도 설정` 은 조건 밖으로 나왔다 (코드로 확인, `MapPage.tsx`)
- **`목록` 으로 전환하거나 `unsupported` 가 켜져도 `setPanelOpen(false)` 를 부르지 않는다 — F-2007 이 그 줄을 지웠다.** 패널이 두 보기 모두에서 열려 있어야 하므로 `showList()`·`onUnsupported` 는 더 이상 패널을 닫지 않는다 (코드로 확인)
- 아이콘은 **기존 `IconSettings`** 다 (`icons.tsx` 107행). 사이드바 `설정` 과 같은 그림인 것이 헷갈리는지는 사람 확인 H-f

### 5.2 접근성 이름이 `설정` 이 아니라 `지도 설정` 인 이유 — e2e 충돌을 실제로 확인했다

**`e2e/map.spec.js` 223행(`F-2002 A15 테마 전환`)이 지도를 연 채 `page.getByRole('button', { name: '설정', exact: true }).click()` 으로 앱 설정 대화상자를 연다.** 그 시점에 사이드바 `설정` 버튼(`Sidebar.tsx` 1066·1072행)이 화면에 살아 있다 — `App.tsx` 2800~2845행에서 `<Sidebar>` 가 `.main-column` → `.content-area` 보다 **앞**에 있고 지도는 `.content-area` 를 덮을 뿐이다.

> 머리 줄 버튼 이름을 `설정` 으로 하면 그 `getByRole` 이 **두 개**를 잡아 Playwright strict mode 위반으로 `F-2002 A15` 가 깨진다.

`지도 설정` 으로 하면 `exact: true` 매칭에 걸리지 않아 **A15 를 한 줄도 안 고쳐도 된다.** 저장소 전체에서 `name: '설정'` 을 쓰는 e2e 가 37곳인데(13장), 그중 지도를 연 채로 도는 것은 A15 하나뿐이고 나머지는 영향이 없다. 화면에 글자가 보이지 않는 아이콘 버튼이라 **사용자가 읽는 문구가 아니라 툴팁·스크린리더 이름**이고, 그 자리에서는 `지도 설정` 이 오히려 정확하다.

- `openMap()` 헬퍼(7행)의 `getByRole('button', { name: '지도' }).first()` 는 **비-exact 부분 일치**라 `지도 설정` 도 후보로 잡히지만, 사이드바가 DOM 상 앞이라 `.first()` 가 지금처럼 사이드바 버튼을 고른다. 깨지지 않는다
- `F-2002 A3` 의 `map.getByRole('button', { name: '지도', exact: true })).toHaveCount(1)`(51행)은 `exact` 라 영향이 없다
- `F-2002 A9`(148행)의 `aria-disabled` 검사도 `exact` 라 영향이 없다

## 6. 패널의 자리·`Esc`·저장 시점

### 6.1 캔버스를 줄이지 않고 **위에 겹친다**

`.map-panel` 은 `.map-page-body`(이미 `position: relative`, `map.css` 98~103행) 안에서 `position: absolute; top/right/bottom: 0` 이다. `.map-scene` 은 `inset: 0` 그대로 두고 건드리지 않는다.

**왜 줄이지 않나 — 세 가지가 전부 겹침 쪽이다.**

1. **줄이면 패널이 열리는 180 ms 동안 그래프가 줌 애니메이션을 한다.** 폭이 줄면 `ResizeObserver`(`MapScene.tsx` 481~487행)가 프레임마다 돌고, 사용자가 아직 카메라를 안 건드렸으면(`userMoved === false`) 그 안에서 `fit()` 이 돈다. 패널을 여닫을 때마다 덩어리가 커졌다 작아진다
2. **카메라를 건드린 뒤(`userMoved === true`)에는 더 나쁘다.** `fit()` 대신 `updateClip()` 만 돌아서(483~484행) 보던 화면이 가로로 잘린 채 남고, 패널을 닫으면 다시 넓어진다. 여닫기가 시야를 흔든다
3. 겹치면 `resize()` 자체가 안 돌아 **카메라가 한 톨도 안 움직인다.** 패널을 닫으면 보던 그림 그대로다. 베끼는 대상인 옵시디언 패널도 캔버스 위에 뜬다

- **대가**: 패널 아래 노드는 클릭·호버가 안 된다. 받아들인다 — 패널이 떠 있는 동안은 설정을 만지는 중이고, 닫으면 그대로 돌아온다
- **좁은 창**: `max-width: 560px` 아래에서는 패널이 폭 100% 가 되어 캔버스를 통째로 덮는다. 휴대폰 폭에서 280px 짜리 패널을 띄우면 남는 캔버스가 80px 라 어차피 못 쓴다. 사람 확인 H-c
- **z-index 2** — `.map-notice`(z-index 1, `map.css` 176행) 위다. 안내 줄과 패널이 오른쪽 위에서 겹칠 때 패널이 이긴다

### 6.2 `Esc`

`MapPage` 안 effect 하나. **패널이 열려 있을 때만 리스너를 단다.**

```
if (!panelOpen) return
keydown(e):
  if (e.key !== 'Escape') return
  if (nodeMenu !== null) return                          // 노드 메뉴가 먼저 먹는다
  if (document.querySelector('dialog[open]')) return      // 앱 설정 대화상자가 위에 떠 있다
  e.preventDefault()
  setPanelOpen(false)
  settingsBtnRef.current?.focus()
```

- **`dialog[open]` 검사는 저장소의 기존 처방 그대로다** (`App.tsx` 1106행, `Outline.tsx` 127행, `useEdgeSwipe.ts` 24행). 이게 없으면 `F-2002 A15` 처럼 지도 위에 설정 대화상자가 떠 있을 때 `Esc` 한 번이 둘을 같이 닫는다
- **노드 메뉴 검사가 필요한 이유**: `FolderMenu` 도 `Esc` 를 듣는다(`FolderMenu.tsx` 99~102행). 둘이 같이 닫히면 메뉴만 닫으려던 `Esc` 가 패널까지 닫는다
- **지도 자체는 `Esc` 로 닫히지 않는다** (F-292 5장, `ia.md` 5장 — 이미 그렇게 적혀 있다)
- **여는 순간 포커스를 옮기지 않는다.** 패널은 대화상자가 아니라 화면의 일부라 포커스를 가두지 않는다. `Esc` 나 버튼으로 닫을 때만 `지도 설정` 버튼으로 되돌린다

### 6.3 저장 시점 — **입력마다 바로 쓴다**

`MapPage` 의 `onChange`:

```tsx
function handleViewChange(next: MapView) {
  setView(next)
  saveMapView(next)
}
```

**`prefs.ts` 의 `setPref` 는 동기다**(74행). 그래서 슬라이더를 끄는 동안 프레임마다 `localStorage.setItem` 이 돈다. **비용을 실제로 쟀다** — 설치된 Chrome 에서 3.2 모양의 147 B 짜리 객체를 `JSON.stringify` + `setItem` 하는 데 **첫 호출 0.5 ms, 그 뒤 0.004 ms**(100회·1,000회 평균, 2026-09-22 측정). 120 Hz 로 끌어도 프레임당 0.004 ms 이고 16.7 ms 예산의 **0.024%** 다.

- **그래서 `onCommit` 을 따로 두지 않는다.** 사이드바 너비(`Sidebar.tsx` 573·584행)는 끄는 동안 `onWidthChange`, 놓을 때 `onWidthCommit` 으로 갈라 두었지만, 거기서 갈린 이유는 비용이 아니라 손잡이가 `mousemove` 를 직접 받기 때문이다. 슬라이더는 값이 `step` 눈금에 붙어 들어와 중간값이 쓰레기가 아니다
- **React 는 `onChange` 로 네이티브 `input` 만 준다.** 네이티브 `change` 를 잡으려면 `ref` + `addEventListener` 가 필요한데, 위 측정대로 그렇게 해서 얻는 것이 없다
- **끄는 도중 탭이 죽어도 문제가 없다.** 마지막으로 들어온 값이 그대로 저장돼 있고, 그것은 사용자가 실제로 보고 있던 값이다

## 7. `표시` 3축이 장면에 닿는 길 — `MapScene.tsx`

### 7.1 통로는 prop 하나 + effect 하나

```tsx
// MapSceneProps 에 한 줄
view: MapView
```

- `inputs` ref 에 `view` 를 함께 담는다 — 기존 구조 그대로다
- **effect 가 하나 는다.** F-2002 가 둘, F-2003 이 넷(9.2), F-2004 가 다섯(a~e)으로 늘렸고 여기서 여섯 번째가 붙는다

| | 의존성 | 하는 일 |
| --- | --- | --- |
| (a)~(e) | 기존 (F-2004 까지) | 그대로 |
| **(f)** | `[view]` | `sceneRef.current?.setView(view)` |

`SceneBundle` 에 함수 하나를 더한다.

```ts
setView: (view: MapView) => void
```

`buildScene` 안에서 **직전에 적용한 값을 들고 있다가 바뀐 축만 처리한다.**

```
setView(next):
  if (next.display.nodeScale !== applied.nodeScale) { fillRadii(next.display.nodeScale); posDirty = true }
  if (next.display.edgeStrength !== applied.edgeStrength) applyEdgeColor(next.display.edgeStrength)
  applied = next.display
  requestDraw()
```

- `labelDistance` 는 `setView` 에서 따로 할 일이 없다 — `applied.labelDistance` 만 갱신되고, 다음 프레임의 `applyDepth()` 가 그 값을 읽는다 (7.3). `requestDraw()` 가 그 프레임을 일으킨다
- `requestDraw()` 는 축이 안 바뀌었어도 부른다. 값 하나 다시 그리는 비용이 조건 분기보다 싸다

### 7.2 `노드 크기` — 반지름 배열을 다시 채우고 행렬을 다시 올린다

**F-2004 가 자리를 이미 만들어 두었다** (2026-09-22 작업 트리에서 직접 읽었다). `src/lib/mapNodeStyle.ts` 18행:

```ts
export function nodeRadius(degree: number, missing: boolean, scale = 1): number
```

`MapScene.tsx` 174~181행이 여는 시점에 한 번 `radii` 를 채우고 `maxNodeRadius` 를 구한다. **그 여덟 줄을 함수 하나로 뺀다.**

```
fillRadii(scale):
  for i: radii[i] = nodeRadius(graph.nodes[i].degree, graph.nodes[i].missing, NODE_SCALE * scale)
  maxNodeRadius = radii 의 최댓값 (없으면 0)
```

- **공식은 F-2004 가 정한 대로 따른다.** F-292 6.1 의 `(3 + 2.2 × √(min(degree, 64)))` 과 끊긴 링크 노드의 고정 반지름은 `mapNodeStyle.ts` 5~22행에 있고 **F-2004 소유**다. F-2005 가 하는 일은 **`scale` 인자 하나를 만들어 넘기는 것뿐**이고, 공식도 깊이 섞기(`depthMix`)도 여기서 다시 정하지 않는다
- `NODE_SCALE`(`MapScene.tsx` 48행)은 **그대로 둔다.** 곱하는 자리만 는다 (3.3 의 마지막 글머리)
- `posDirty = true` 만 세우면 다음 프레임에 `uploadPositions()`(271~284행)가 돈다. **`fit()` 을 부르지 않는다** — 슬라이더를 끄는 동안 카메라가 따라 움직이면 손이 화면을 밀어내는 느낌이 된다. 배율 3.0 에서 노드가 틀을 살짝 넘칠 수 있고, 그때 쓰라고 `맞춤` 이 있다 (사람 확인 H-b)
- `maxNodeRadius` 는 `graphRadius()`(204~206행)를 거쳐 절단면에 반영되는데, `updateClip()` 이 프레임마다 돌므로(319~320행) 따로 부를 것이 없다

**비용을 쟀다** (2026-09-22, `three@0.186.0` 을 Node 에서 직접 돌림, 각 200회 평균).

| 노드 수 | `radii` 다시 채우기 | `uploadPositions()`(`Matrix4.compose` + `setMatrixAt`) | 합 |
| --- | --- | --- | --- |
| 200 (지금 사용자 규모) | 0.000 ms | 0.006 ms | **0.006 ms** |
| **1,000 (`NODE_CAP`)** | 0.013 ms | 0.020 ms | **0.033 ms** |
| 2,000 | 0.004 ms | 0.018 ms | 0.022 ms |

> **프레임 예산 16.7 ms 의 0.2% 다.** F-2003 6.3 이 G6 를 위해 회전 중 `uploadPositions()` 를 건너뛰게 만들었지만, **슬라이더를 끄는 동안만 다시 올리는 것은 그 최적화를 되돌리지 않는다** — 끌지 않으면 `posDirty` 가 안 서고, 끄는 동안에도 프레임당 0.033 ms 다. 그래서 디바운스나 rAF 합치기를 넣지 않는다.

### 7.3 `이름표 표시 거리` — F-2004 의 `candidates` 에 더한다

**F-2004 가 자리를 이미 만들어 두었고 주석으로 이름까지 적어 두었다.** `src/lib/mapNodeStyle.ts` 38~44행:

> `pinned` 는 호버한 노드다 — 이웃이 상한을 넘어도 자기 이름표는 반드시 보인다. **F-2005 가 표시 거리 안쪽 노드를 `candidates` 에 더하기만 하면 되도록 둘로 갈랐다**

```ts
export function pickLabelNodes(
  pinned: readonly number[],
  candidates: readonly number[],
  degreeOf: (index: number) => number,
  max = MAP_MAX_LABELS,
): number[]
```

**거리 임계값을 어디서 구하나.** `MapScene.tsx` 247~269행의 `applyDepth()` 가 **프레임마다** 노드별 카메라 거리 `depths[i]` 와 그 프레임의 최소 `near`·최대 `far` 를 이미 구한다 (F-2004 5.1). 그 값을 그대로 쓴다.

```
applyDepth() 끝에서 (labelDistance > 0 일 때만):
  threshold = near + (far - near) * labelDistance
  distanceCandidates = depths[i] <= threshold 인 i 들
  next = pickLabelNodes(hoverIndex >= 0 ? [hoverIndex] : [], 이웃 ∪ distanceCandidates, degreeOf)
  if (next 가 labelIndices 와 원소까지 같지 않으면) { labelIndices = next; setLabelItems(...) }
```

- **`labelDistance === 0` 이면 이 블록을 통째로 건너뛴다.** F-2004 의 지금 동작(호버한 노드와 이웃만)이 한 톨도 안 바뀌고 프레임 비용도 0 이다. **기본값이 0 이라 이 커밋이 기본 상태의 화면을 바꾸지 않는다**
- **정규값을 그 프레임 실제 거리 범위로 푼다.** 절대 world 거리로 풀면 확대·축소할 때마다 뜻이 달라진다. `near`~`far` 정규화는 `depthMix`(`mapNodeStyle.ts` 25~29행)가 깊이 섞기에 쓰는 것과 **같은 축**이라, 슬라이더를 올리면 "덜 흐려진 노드부터 이름이 붙는다" 로 읽힌다
- **바뀔 때만 `setLabelItems` 를 부른다.** 안 그러면 회전하는 내내 `near`·`far` 가 미끄러져 프레임마다 React 가 이름표 DOM 을 다시 그린다. 인덱스 배열 비교는 최대 60개라 공짜다
- 동시 표시 상한 60개(`MAP_MAX_LABELS`)와 `degree` 큰 순 정렬은 `pickLabelNodes` 가 이미 한다. **F-2005 는 후보 목록만 넓힌다**
- 자리 잡기(`placeLabels`)와 이름표 DOM(`MapLabels.tsx`)은 **한 줄도 안 건드린다**

### 7.4 `선 두께` — 간선 재질 색만 바꾼다

```
applyEdgeColor(strength):
  toColor(edgeMaterial.color, edgeColorAt(strength, { panel: theme.panel, rule: theme.rule, ink: theme.ink }))
```

- `applyColors()` 안 **230행** `toColor(edgeMaterial.color, theme.rule)` 한 줄을 위 호출로 바꾼다. 테마가 바뀌어 `applyColors()` 가 다시 돌 때도 현재 `strength` 를 쓴다
- `theme` 세 색은 **이미 읽고 있다** — `readTheme` 이 `panel`·`ink`·`rule`(과 F-2004 가 더한 `ink2`)을 다 준다. **새로 읽는 토큰이 0개다**
- 비용은 `Color.setRGB` 한 번이다. 좌표 업로드도 지오메트리 갱신도 없다

## 8. `선 두께` 가 왜 굵기가 아니라 진하기인가 — 실측

### 8.1 WebGL 은 선 굵기를 1px 로 고정한다 (직접 쟀다)

F-292 6.6 은 "WebGL `lineWidth` 가 대부분 1px 로 무시된다" 고만 적었다. **두 가지로 확인했다.**

1. **`three` 가 자기 소스에 적어 두었다.** `node_modules/three/src/materials/LineBasicMaterial.js` 62~72행:
   > Controls line thickness or lines. Can only be used with SVGRenderer. **WebGL and WebGPU ignore this setting and always render line primitives with a width of one pixel.**
   `WebGLRenderer.js` 1285~1289행은 `state.setLineWidth(material.linewidth * pixelRatio)` 를 실제로 부르긴 한다 — 무시하는 쪽은 드라이버다
2. **이 PC 의 설치된 Chrome 에서 잰 값**(2026-09-22, Playwright `channel: 'chrome'`): `gl.getParameter(gl.ALIASED_LINE_WIDTH_RANGE)` = **`[1, 1]`**, renderer `ANGLE (AMD, AMD Radeon RX 7600 (0x00007480) Direct3D11 vs_5_0 ps_5_0, D3D11)`. **최소도 1, 최대도 1이다** — 2px 짜리 선을 그릴 방법이 아예 없다

> **결론: 굵기는 포기하고 진하기로 간다. F-292 6.6 의 판단이 맞았고, 이제 근거가 실측이다.**

굵은 선을 정말 그리려면 `Line2`/`LineMaterial`(three 의 fat-lines addon)로 갈아타야 하는데, 간선마다 사각형 두 개를 만드는 방식이라 4,000 간선에서 정점 수가 8배가 되고 F-292 3.5 가 정한 "드로우콜 1회" 구조를 버려야 한다. **하지 않는다.**

### 8.2 `src/lib/mapEdgeStyle.ts` — 세 정점 보간

```ts
export type EdgeColorStops = { panel: Rgba; rule: Rgba; ink: Rgba }

// 선 두께 정규값(0~1) → 간선 색. 0.5 가 정확히 --rule 이다
export function edgeColorAt(strength: number, stops: EdgeColorStops): Rgba
```

| `strength` | 결과 |
| --- | --- |
| 0 | `--panel` 과 **같다** — 배경색이라 간선이 안 보인다 |
| 0 ~ 0.5 | `--panel` → `--rule` 선형 보간, 비율 `strength / 0.5` |
| **0.5 (기본)** | `--rule` 과 **정확히 같다** |
| 0.5 ~ 1 | `--rule` → `--ink` 선형 보간, 비율 `(strength − 0.5) / 0.5` |
| 1 | `--ink` 와 **같다** — 노드 기본색과 같은 진하기 |
| 유한수가 아니거나 범위 밖 | `0`~`1` 로 자르고, `NaN`·`Infinity` 면 `0.5` |

- **기본값 0.5 가 `--rule` 이라 이 커밋이 기본 상태의 화면을 한 픽셀도 바꾸지 않는다.** 지금 `MapScene.tsx` 229행이 간선을 `--rule` 로 칠하고 있고, 그것이 정확히 기본값 자리다
- **색 hex 를 쓰지 않는다.** 세 끝점이 전부 `readTheme` 이 프로브로 읽어 온 토큰 값이다 (F-292 3.4). 테마를 바꾸면 세 끝점이 같이 바뀐다
- **`--panel` 을 한쪽 끝으로 쓰는 것이 F-292 3.5 의 "깊이·걸러짐도 `--panel` 과 섞어 표현한다" 와 같은 어법이다.** 알파를 쓰지 않으므로 깊이 정렬 문제가 없다
- `a`(알파)도 함께 보간한다. 세 토큰 모두 테마 3종에서 불투명 hex 라(`tokens.css` 17~23·144~150·157~163행) 실제로는 1 로 고정이지만, 식을 반쪽만 쓰지 않는다
- **순수 함수라 `node` 환경에서 단위 테스트가 된다** (12.1 U14~U18). `src/lib/cssColor.ts`·`src/lib/mapCamera.ts` 와 같은 자리다

> **F-292 2장 파일 표에 없는 새 파일이다.** F-2003 이 `src/lib/mapCamera.ts` 를 같은 이유로 더했던 전례(F-2003 17장 Q7)를 따른다 — 떼지 않으면 이 명세의 유일한 순수 계산이 `MapScene.tsx` 안에 묻혀 단위 테스트가 0개가 된다. 14장 갱신 대상에 올렸다.

## 15. 열린 질문 / 사람 결정 필요

**사람이 꼭 골라야 하는 것은 없다. 셋 다 기본값이 서 있고, 다른 쪽을 골랐을 때 무엇이 달라지는지 적었다.**

### Q1. 머리 줄 버튼 이름을 `지도 설정` 으로 하는 것 — **기본: `지도 설정`**

F-292 6.3 은 `설정` 이라고 적었다. 5.2 의 이유로 뒤집는다 — `설정` 으로 하면 `F-2002 A15`(지도를 연 채 앱 설정 대화상자를 여는 테스트)가 Playwright strict mode 위반으로 깨진다. 아이콘 버튼이라 화면에 글자가 안 보이고, 툴팁·스크린리더에는 `지도 설정` 이 더 정확하다.

**다른 쪽을 고르면**: 이름을 `설정` 으로 두고 `e2e/map.spec.js` 223행을 `page.locator('nav').getByRole('button', { name: '설정', exact: true })` 처럼 사이드바로 좁힌다. **F-2002 의 테스트를 F-2005 가 고치게 되고**, 앞으로 지도를 여는 테스트가 늘 때마다 같은 충돌을 다시 만난다.

### Q2. 값을 입력마다 저장하는 것 — **기본: 입력마다 저장한다**

6.3 의 측정(147 B 객체 저장이 Chrome 에서 0.004 ms). 코드 경로가 하나로 끝나고, React 가 네이티브 `change` 를 안 주므로 놓을 때만 저장하려면 `ref` + `addEventListener` 가 더 필요하다.

**F-2006 이 실제로 그 리스너를 달았다가 F-2012 가 뺐다** (2026-09-22). 달았던 이유는 저장이 아니라 카메라였고(F-2006 6.4), 장력을 바꿀 때 카메라를 안 맞추기로 정해지면서 사라졌다 (F-2012 3.3). **이 Q2 의 결론은 그 사이에도 안 바뀌었다 — 저장은 언제나 입력마다였다.**

**다른 쪽을 고르면**: `MapSlider` 에 `ref` 로 네이티브 `change` 리스너를 달고 `onChange`(미리보기)·`onCommit`(저장)을 갈라 `MapPanel` → `MapPage` 로 둘 다 올린다. 사이드바 너비(`Sidebar.tsx` 573·584행)와 모양이 같아지고, 끄는 도중 탭이 죽으면 그 드래그가 저장되지 않는다. **12.2 A5 는 `fill()` 이 `change` 도 쏘므로 그대로 통과한다.**

### Q3. `이름표 표시 거리` 의 정규값을 **그 프레임 실제 거리 범위**로 푸는 것 — **기본: 그렇게 한다**

`threshold = near + (far − near) × labelDistance` (7.3). `near`·`far` 는 `applyDepth()` 가 프레임마다 구하는 그 프레임 노드 거리의 최소·최대이고, 깊이 섞기(`depthMix`)가 쓰는 것과 같은 축이다. 그래서 슬라이더를 올리면 "덜 흐려진 노드부터 이름이 붙는" 것으로 읽힌다.

**다른 쪽을 고르면**: 절대 world 거리(예: `맞춤` 거리의 몇 배)로 푼다. 확대·축소해도 임계값이 안 흔들려 안정적이지만, 멀리서 전체를 볼 때는 아무 이름표도 안 뜨고 바싹 들어가야만 뜬다 — 슬라이더를 올렸는데 화면이 안 바뀌는 구간이 생긴다. 바꾸려면 7.3 의 `threshold` 한 줄만 고치면 된다.
