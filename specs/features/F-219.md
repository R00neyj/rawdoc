# F-219 서버 안 쓰는 첨부 정리

작성일: 2026-09-15
상태: 사용자 요청(2026-09-15 "이미지 글에서 삭제하면 서버 자동정리 됨?" → 없음 → "ㄱㄱ", 유예 "7일 좀 긴건가?" → 24시간). F-217·F-218 과 파일 겹침 없음
근거: F-156 2.7 로컬 정리 규칙(어떤 문서 원문에도 없고 24시간 지난 첨부)을 서버 D1·R2 에 같게 적용. F-209 2.3 R2 키 `att/{owner_id}/{id}.{ext}`

## 1. 파일 소유

| 파일 | 변경 |
| --- | --- |
| `worker/attachmentGc.ts`(+test) | 신규. `cleanupServerAttachments(env, now)` |
| `worker/index.ts` | `export default` 에 `scheduled` 추가 (부분 Edit) |
| `wrangler.jsonc` | `"triggers": { "crons": ["0 18 * * *"] }` (UTC 18시 = 한국 03시) |

- 새 의존성 없음. 참조 추출은 `src/lib/imageBlock` 의 `extractAttachmentRefs` 그대로(worker 가 이미 import 중)

## 2. 요구사항

### 2.1 판정
- 참조 집합 = **모든 사용자** `docs.content` 에서 뽑은 첨부 id 합집합. 공유 편집자가 올린 첨부(`owner_id` = 편집자)가 소유자 문서에 들어 있을 수 있어 소유자별로 나누지 않는다
- 지울 대상 = `attachments` 행 중 id 가 참조 집합에 없고 `created_at < now − 24시간` 인 것
- 문서는 200행씩 `ORDER BY id` 로 나눠 읽는다(`content` 만 선택)

### 2.2 삭제
- 대상마다 R2 `att/{owner_id}/{id}.{ext}` 삭제 후 D1 행 삭제(`owner_id`·`id` 둘 다 조건). R2 삭제 실패면 그 행은 남긴다(다음 날 다시)
- 한 번에 최대 500개. 넘으면 다음 실행으로 넘긴다
- 실패는 `console.error` 한 줄 남기고 계속한다. 응답·예외를 밖으로 던지지 않는다
- 끝나면 `console.log` 한 줄: 지운 개수·남긴(실패) 개수

### 2.3 범위 밖
- 클라이언트 캐시(IndexedDB `remoteCache`) 정리 — 서버에서 지워져도 캐시 사본은 남아 그 기기에선 보일 수 있다. 원문에 참조가 없어야 지워지므로 화면에 영향 없음
- 사용자별 저장 한도·용량 표시
