# F-2135 공개 보기의 권한 요청 버튼과 대화상자

작성일: 2026-10-12
상태: 승인 2026-10-12(사용자 "추천안대로" — 상시 지시로 승인). 개요 F-4004 2장(버튼 표)의 S-5 화면. F-4005 의 라우트·`src/lib/accessRequest.ts` 를 쓴다. S-4 는 F-2137 이 같은 `AccessRequestControl` 을 글자 버튼으로 쓴다. 구현 담당 `feature-implementer`. `App.tsx` 변경 없음

## 근거 (2026-10-12 HEAD, 이름으로 찾는다)
- `src/app/PublicView.tsx` `DocPane` 머리 줄(`.public-view-header`)에 `설정`·`.md 내보내기` 아이콘 버튼(I14 — 테두리 없는 32×32 + `IconTooltip`). 문서 링크는 `PublicDocView`(묶음 둘째 문서부터 `activeDocId`, 시작 문서는 `isStartDoc`), 폴더 링크는 `PublicFolderView` — 폴더에 문서가 없으면 `DocPane` 을 그리지 않는다
- 공개 보기는 `/api/me` 를 부르지 않는다. 알림 띠는 `usePublicNotice`(info 하나, 4초)
- 대화상자 틀 `src/app/Dialog.tsx`, 아이콘 `IconPersonAdd`·`IconOpenInNew` 가 이미 있다. 앱 진입 주소는 `/?app=1`(`src/app/account.ts` `AFTER_LOGOUT_URL` 와 같은 탈출구, `worker/rootRoute.ts`)
- 대화상자 번호 D-18~D-22 는 쓰였고 D-23 이 비었다

## 2. 계약
```ts
// accessRequestApi.ts — 401·404·네트워크·5xx·모양 틀림은 모두 null(버튼을 그리지 않는다)
export function fetchAccessStatus(token: string, docId: string | null): Promise<AccessRequestStatus | null>
export type AccessRequestError = 'gone' | 'already_member' | 'cooldown' | 'too_many_pending' | 'owner_full' | 'blocked' | 'rate_limited' | 'failed'
export function sendAccessRequest(token: string, docId: string | null, role: AccessRole): Promise<{ ok: true; status: AccessRequestStatus } | { ok: false; error: AccessRequestError; retryAt: number | null }>
export function cancelAccessRequest(token: string, docId: string | null): Promise<boolean>
// accessRequestView.ts
export type AccessControlView = {
  openHref: string | null   // 문서 `/?app=1#/d/{id}`, 폴더 `/?app=1#/`
  request: { mode: 'form'; roles: AccessRole[] } | { mode: 'pending'; role: AccessRole } | { mode: 'rejected'; retryAt: number } | null
}
export function accessControlView(s: AccessRequestStatus | null): AccessControlView
export function accessRequestErrorMessage(e: AccessRequestError, retryAt: number | null): string
// AccessRequestControl.tsx — S-5 는 icon·reload, S-4(F-2137) 는 text·hash
export type AccessRequestControlProps = { token: string; docId: string | null; variant: 'icon' | 'text'; openIn: 'reload' | 'hash'; onNotice: (message: string) => void }
```
- `docId`: 문서 링크는 시작 문서면 `null`, 묶음 문서면 그 id. 폴더 링크는 늘 `null`(F-4004 1장)
- 오류 대응: 404 → `gone`, 403 `account_blocked` → `blocked`, 429 → `rate_limited`, 409 는 `error` 값 그대로, 그 밖 → `failed`

## 3. 동작
- **불러오기**: `AccessRequestControl` 이 그려질 때와 `token`·`docId` 가 바뀔 때, 그리고 `visibilitychange` 로 다시 보일 때 `fetchAccessStatus`. `null` 이면 아무것도 그리지 않는다(로그아웃 방문자는 지금 S-5 그대로)
- **버튼**(F-4004 2장 표 = `accessControlView`): `openHref` 가 있으면 `앱에서 열기`(`IconOpenInNew`) — `openIn="reload"` 면 `location.assign(openHref)`, `"hash"` 면 `location.hash = formatHash(targetId)`(글자는 `원본 문서 열기`). `request` 가 있으면 `권한 요청`(`IconPersonAdd`), 대기면 접근 이름·툴팁(글자 버튼은 글자)이 `권한 요청 보냄`. `variant="icon"` 은 I14 아이콘 버튼 + 툴팁, `"text"` 는 아이콘 + 글자. S-5 순서 `앱에서 열기` · `권한 요청` · `설정` · `.md 내보내기`
- **D-23** (`Dialog`, 제목 `권한 요청`):
  - form — 라디오 `보기`(설명 `공유받은 문서로 내 목록에 둡니다`)·`편집`(`함께 고칠 수 있습니다`), `roles` 에 있는 것만. 처음 선택은 `roles[0]`, 첫 초점 그 라디오. 아래 줄 `소유자에게 내 이름과 이메일이 보입니다.` 버튼 `취소`·`요청 보내기`(보내는 동안 `보내는 중…`, 비활성)
  - pending — `{보기|편집} 권한을 요청했습니다. 소유자가 승인하면 알림이 옵니다.` 버튼 `닫기`·`요청 취소`
  - rejected — `소유자가 요청을 받아들이지 않았습니다. {YYYY-MM-DD}부터 다시 요청할 수 있습니다.` 버튼 `닫기`
- **보낸 뒤**: 성공 → 응답 상태로 바꾸고 닫고 알림 `권한을 요청했습니다.` 실패 → 대화상자 유지, 알림 `accessRequestErrorMessage`. `gone` 은 컨트롤을 숨기고, `already_member`·`cooldown` 은 상태를 다시 부른다
- **취소**: 성공 → 닫고 상태 다시 부름, 알림 `요청을 취소했습니다.` 실패 → `요청을 취소하지 못했습니다. 연결을 확인한 뒤 다시 시도해 주세요.`
- 대화상자를 닫으면 초점은 `권한 요청` 버튼(`Dialog` 기본 복귀)

## 4. 오류 문구 (`accessRequestErrorMessage`)
| 값 | 문구 |
| --- | --- |
| `gone` | `링크가 끊겨 권한을 요청할 수 없습니다.` |
| `already_member` | `이미 이 권한이 있습니다.` |
| `cooldown` | `{YYYY-MM-DD}부터 다시 요청할 수 있습니다.` |
| `too_many_pending` | `기다리는 요청이 너무 많습니다. 보낸 요청이 처리된 뒤 다시 시도해 주세요.` |
| `owner_full` | `소유자가 받은 요청이 많아 지금은 보낼 수 없습니다.` |
| `blocked` | `계정이 제한되어 요청할 수 없습니다.` |
| `rate_limited`·`failed` | `요청을 보내지 못했습니다. 잠시 뒤 다시 시도해 주세요.` |
