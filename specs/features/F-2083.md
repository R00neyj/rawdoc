## 정해진 것 (2026-09-29 grill, 바꾸지 않는다)

1. 적용 폭은 **창 폭 600px 이하만**. 601~1023px 와 1024px 이상은 지금 배치 그대로
2. 상단바에 남는 것: `☰ 사이드바 토글`, `접속자 아바타`(지금처럼 1명 + `+N`, F-307 Q6), `보기 모드 버튼 1개`, `⋯`. 나머지는 모두 ⋯ 안으로
3. ⋯ 안 항목: 홈, 목차, 댓글 N, 공유, 내보내기, 알림, 계정. 검색·명령 팔레트는 이미 이 폭에서 사이드바 버튼 줄에 있다(F-216, F-2053 10.1) — 그대로
4. ⋯ 모양은 **아래서 올라오는 판**. 알림·계정을 누르면 **같은 판 안에서** 그 내용으로 바뀌고 ← 로 돌아온다. 댓글 판(F-505 6장)과 같은 계열 모양
5. ⋯ 의 점: **안 읽은 알림이 있거나, 열린 댓글 스레드가 1개 이상**일 때(지금 상단바 댓글 배지와 같은 값 `comments.openThreadCount`). 사용자가 "알림만" 추천을 거절하고 이쪽을 골랐다
6. 보기 모드: 지금 모드를 보여 주는 버튼 1개, 누르면 편집·원문·보기 3개 메뉴. 순환 버튼이 아니다
7. 목차: 본문 위에 떠 있는 둥근 `목차` 버튼(F-229)을 이 폭에서 없애고 ⋯ 안으로. 누르면 기존 목차 카드를 연다
8. 명세 분할: F-2083(이것) = 상단바·목차, F-2084 = 서식 바

## 2. 범위

### 한다

- 창 폭 ≤600px 에서 상단바를 `☰` · 아바타 · 보기 모드 버튼 1개 · `⋯` 로 줄인다

- 공유·내보내기·알림·계정 메뉴의 항목과 딸린 상태를 트리거에서 떼어 넓은 배치의 팝오버와 판이 같이 쓴다

- 601px 이상 배치. 그 폭의 상단바·목차 버튼·메뉴 팝오버는 한 픽셀도 바꾸지 않는다

- 판을 끌어서 닫기(스와이프 다운) — 9장 Q4
- 도움말 본문(`helpDoc.ts`) 문장 — 8장, `write-guide` 로 따로

## 3. 판정과 순수 함수

### 3.1 600px 판정 — JS, 새 훅 파일 (반드시 결론 1)

**결론: 상단바 배치는 JS 로 가른다. 판정은 새 파일 `src/app/usePhoneWidth.ts` 의 훅이고, `TopBar` 가 직접 부른다.**

```ts
// src/app/usePhoneWidth.ts
export const PHONE_QUERY = '(max-width: 600px)'   // app.css 의 @media (max-width: 600px) 와 글자 그대로 같아야 한다
export function usePhoneWidth(): boolean
```

- 첫 렌더에 `matchMedia(PHONE_QUERY).matches` 를 동기로 읽고(깜빡임 없음), `change` 를 구독한다. `useSidebarLayout` 의 `narrow` 와 같은 모양이다
- **CSS 만으로 안 되는 이유**: CSS 로 숨기면 넓은 배치의 `ShareMenu`·`AccountMenu`(딸린 `ShareSetDialog`·`ApiTokensDialog` 포함)와 판이 한 화면에 둘 다 마운트된다. 판도 `ShareMenu` 와 같은 훅을 쓰므로(5장) 링크 유무 GET·사용량 GET·대화상자가 두 벌 생긴다. 렌더 여부를 갈라야 한다
- **`useSidebarLayout` 에 넣지 않는 이유**: 600px 에서 사이드바는 바뀌지 않는다(CSS 로 버튼 줄만 바뀜). 넣으면 `UseSidebarLayoutResult` → `AppTopBarProps` Pick → App 전달 목록까지 줄이 늘어난다. 쓰는 곳이 `TopBar` 하나라 거기서 부르면 App 배선이 0이다
- CSS 가 그대로 맡는 것: 600px 이하 상단바 블록(검색·팔레트·제품 아이콘 숨김)과 `.app-shell` 안 목차 버튼 숨김(4.6). 같은 미디어 조건 문자열이라 JS 와 CSS 가 1px 도 어긋나지 않는다(브라우저 미디어 쿼리 엔진 하나가 판정)

규칙:

- `moreDotVisible`: `unread > 0` 이거나, `screen === 'doc'` 이고 `commentsOpenCount > 0`. **문서 화면이 아닐 때 댓글 수는 점에 넣지 않는다** — 판에 `댓글` 행이 없는데 점이 뜨면 누를 곳이 없다(도움말·공유 관리 화면에서도 `currentDoc` 이 남아 `comments` prop 은 살아 있다 — `AppTopBar` 조건이 화면을 보지 않기 때문)
- 세 함수는 DOM·React 를 import 하지 않는다(테스트 환경 `node`)

### 4.4 아래 판 — 여닫기·포커스 (반드시 결론 4)

**판은 네이티브 `<dialog>` 를 `showModal()` 로 연다.** 공용 `Dialog.tsx` 는 쓰지 않는다(클래스·가운데 배치가 고정이고, 포커스 복귀 대상이 "열 때의 `activeElement`" 라 탭해도 버튼에 포커스가 가지 않는 브라우저에서는 `body` 로 돌아간다 — 판은 늘 `⋯` 버튼 ref 로 돌린다). 모달을 고른 이유는 9장 Q1

열기:
- `⋯` 누르기 → 판 첫 화면(목록). 포커스는 첫 행
- `notifications.open` 이 참이 되면(팔레트 `알림 열기`) 판을 **알림 하위 화면으로 바로** 연다. 포커스는 NotificationsMenu 와 같은 이유로 두 프레임 뒤에 첫 알림 항목(없으면 ← 버튼)으로 — 팔레트 `dialog` 의 close 포커스 복귀가 뒤에 오기 때문
- 판이 열려 있는 동안 `⋯` 의 `aria-expanded="true"`

닫기 — 아래 어느 것이든 판 전체를 닫는다:

| 무엇으로 | 포커스 |
| --- | --- |
| 머리 `닫기` 버튼 | `⋯` 버튼 |
| 뒤 막(판 바깥) 누르기 — `dialog` 자신이 클릭 대상일 때 | `⋯` 버튼 |
| `Esc` (`dialog` 의 `cancel`). 하위 화면에서도 한 번에 판 전체를 닫는다 — `Esc` 한 번은 한 가지만 | `⋯` 버튼 |
| 행 동작 실행(4.7) | 먼저 `⋯` 버튼, 그다음 동작(동작이 포커스를 옮기면 그쪽 — 댓글 판·대화상자·목차 카드) |
| 주소(해시)가 바뀜 — `hashchange` | 옮기지 않는다 |
| 창이 601px 이상으로 넓어짐 — 판 컴포넌트가 빠진다 | 옮기지 않는다 |

- 알림 하위 화면에서 판이 닫히면 `notifications.onOpenChange(false)` 를 부른다. 넓어져서 빠질 때는 부르지 않는다 — 열림 상태가 넓은 배치의 알림 팝오버로 이어진다
- **뒤로 가기**: 판은 기록(history)에 항목을 넣지 않는다. 안드로이드 Chrome 의 뒤로 가기가 모달 `dialog` 를 닫는지(닫기 요청), 기록을 한 칸 되돌리는지는 브라우저 몫이다. 되돌리면 해시가 바뀌어 위 표대로 판이 닫힌다 — 어느 쪽이든 판이 떠 있는 채 화면이 바뀌지 않는다. 기록 항목을 넣는 안은 9장 Q2
- 판이 열린 동안 화면 가장자리 밀기(F-227)는 `useEdgeSwipe` 의 `dialog[open]` 검사로 이미 무시된다. 목차 카드는 `Outline` 의 `dialog[open]` 감시로 닫힌다
- 행 사이 이동은 Tab 이다. 방향키 순회는 두지 않는다(메뉴 역할이 아니라 대화상자 안 버튼 목록)

하위 화면(공유·내보내기·알림·계정):
- 목록 행을 누르면 판 안 내용이 그 하위 화면으로 바뀐다. 판은 닫히지 않는다
- 머리: `←` 버튼 + 제목(`h2`). 알림은 오른쪽에 `모두 읽음`(지금 규칙 그대로 — `blocked` 면 없음, 안 읽음 0 이면 비활성)
- 들어가면 포커스는 첫 동작 항목, 없으면(알림 0개·오프라인 계정) `←` 버튼
- `←` 를 누르면 목록으로 돌아오고 포커스는 들어갔던 행
- 알림 하위 화면에 들어가는 것 = `notifications.onOpenChange(true)`(→ `refresh('open')`), `←` 로 나오는 것 = `onOpenChange(false)`. 판의 "알림 화면인가" 는 `notifications.open` 을 그대로 따른다

### 4.6 목차 (정해진 것 7)

```ts
// src/app/Outline.tsx
export type OutlineControl = {
  hasHeadings: () => boolean
  openCard: (returnFocusTo: HTMLElement | null) => void
}
// OutlineProps 에 추가
controlRef?: RefObject<OutlineControl | null>
```

- `controlRef` 가 오면 `Outline` 은 마운트된 동안 그 ref 를 채우고, 빠질 때 `null` 로 돌린다. `PublicView` 는 넘기지 않는다 — 지금 그대로
- `hasHeadings()` = 제목 1개 이상. `openCard(el)` = 카드를 열고, 이후 **Esc 로 닫을 때 포커스를 `el` 로** 돌린다(`el` 이 `null` 이면 지금처럼 `buttonRef`). 항목 고르기·바깥 누르기로 닫힐 때는 지금처럼 포커스를 옮기지 않는다(F-229 2.4)
- `openCard` 는 버튼 모드(`!railOpen && !fits`)일 때만 카드를 연다. 선 목차 모드면 아무것도 안 한다(이 폭에서는 늘 버튼 모드 — 근거 절 `Outline.tsx`)
- 판의 `목차` 행 표시 여부는 **판을 여는 순간** `controlRef.current?.hasHeadings()` 로 한 번 읽는다(렌더 중에 ref 를 읽지 않는다 — `react-hooks/refs`). 판이 열린 동안 제목이 생기거나 없어져도 목록은 그대로
- `목차` 행을 누르면: 판을 닫고(`dialog.close()`), `⋯` 버튼으로 포커스, 그다음 `openCard(⋯ 버튼)`. **순서가 결정이다** — 카드를 먼저 열면 `Outline` 의 `dialog[open]` 감시가 막 연 카드를 바로 닫는다
- 카드는 F-229 2.3 그대로(폭·최대 높이·현재 위치 항목으로 스크롤·포커스). 버튼이 없으므로 `.outline-popup` 높이가 0이 되어 카드 윗변은 `.content-area` 위 +20px(12 + 8)에 온다 — 값 확인은 사람 몫
- 떠 있는 버튼 숨김: 600px 이하 CSS 에서 `.app-shell .outline-popup > .outline-btn { display: none }`. `.app-shell` 으로 좁히는 이유는 공개 보기도 `.content-area` 를 쓰기 때문(`PublicView.tsx` `public-view-body content-area`)

### 4.7 행 동작

| 행 | 누르면 |
| --- | --- |
| `홈` | 판 닫기 → `⋯` 포커스 → 홈으로. 행 버튼에 `data-go-home` 을 달아 App 의 위임 클릭(`handleAppShellClick`)을 그대로 쓴다 — 새 prop 없음 |
| `목차` | 4.6 |
| `댓글` | 판 닫기 → `⋯` 포커스 → `comments.onToggle()`. 이 폭은 댓글이 아래 판이라 열린다(`⋯` 를 누를 때 댓글 판은 바깥 누르기로 이미 닫혔다, F-505 6장). 댓글 판이 포커스를 가져간다 |
| `공유`·`내보내기`·`알림`·`계정` | 하위 화면으로 (4.4) |
| 하위 화면 항목 | 판 닫기 → `⋯` 포커스 → 그 항목의 동작. 넓은 배치 메뉴의 `runAndClose` 와 같은 순서 |
| 알림 항목 | 판 닫기 → `onOpenItem(item)`(지금 `handleOpenNotification` — 닫고 읽음, 해시 이동) |
| `모두 읽음` | 판은 열린 채 `onReadAll()` |

- 공유 하위 화면 항목·순서·비활성·금고 안내 문구는 `ShareMenu` 와 **같다**(같은 훅, 5장). `읽기 전용 링크 복사…` 가 여는 `ShareSetDialog`·`사람 초대…` 의 초대 대화상자는 판이 닫힌 뒤 뜨고, 닫히면 포커스가 `⋯` 로 돌아온다(`Dialog.tsx` 가 열 때의 `activeElement` = `⋯` 로 돌림)
- 계정 하위 화면의 머리 줄(이메일·오프라인·사용량)과 항목(`공유 관리`·`API 토큰`·`로그아웃` / `로그인`)은 `AccountMenu` 와 같다. 사용량은 하위 화면에 들어갈 때마다 새로 받는다(지금 "열 때마다" 규칙을 옮긴 것)

## 5. 메뉴 재사용 (반드시 결론 2)

**결론: 각 메뉴 파일에서 "항목·딸린 상태" 를 트리거와 떼어 named export 로 내보내고, 넓은 배치 팝오버와 판이 같은 것을 쓴다. 판 전용 목록을 새로 만들지 않는다.**

이유:
- 공유 항목은 조건이 다섯 겹이다(서버 저장소 여부, 링크 유무 GET, 위키링크 대상 유무, 금고 문서, 초대 권한). 판 전용으로 새로 쓰면 이 조건과 문구가 두 벌이 되고, 한쪽만 고치는 사고가 난다(CLAUDE.md "두 벌은 갈라진다")
- 계정도 사용량 GET·`ApiTokensDialog`·로그아웃 순서(F-2034 4.1)가 있어 같다
- 넓은 배치 DOM 을 판에 그대로 넣는 안(팝오버를 판 안에 띄우기)은 `role="menu"` 방향키·바깥 `mousedown` 닫기·절대 위치가 판과 부딪혀 버린다

계약(이름과 입력·출력이 계약, 내부 ref 전달 모양은 구현자 재량):

```ts
// 공통 — 네 파일이 같이 쓰는 항목 모양. 새 파일을 만들지 않고 ShareMenu.tsx 에서 export 한다
export type MenuAction = {
  key: string
  label: string
  icon: ComponentType<{ size?: number }>
  onSelect: () => void | Promise<void>
  disabled?: boolean
}

// ShareMenu.tsx
export function useShareMenu(props: ShareMenuProps & { active: boolean; onClose: () => void }): {
  items: MenuAction[]
  e2eeNote: boolean          // 참이면 '금고 문서는 공유할 수 없습니다.' 를 목록 끝에
  dialogs: ReactNode         // ShareSetDialog
}

// ExportMenu.tsx
export function exportMenuItems(handlers: Omit<ExportMenuProps, 'disabled'>): MenuAction[]

// NotificationsMenu.tsx
export function NotificationsList(props: {
  state: NotificationsState
  active: boolean            // 참인 동안 60초마다 시각을 다시 그린다
  onOpenItem: (item: NotificationItem) => void
}): ReactNode                // 불러오는 중 / 실패 / 빈 목록 문구 또는 ul.notifications-list

// AccountMenu.tsx
export function useAccountMenu(props: AccountMenuProps & { active: boolean; onClose: () => void }): {
  usage: Usage | null
  items: MenuAction[]
  dialogs: ReactNode         // ApiTokensDialog
}
export function AccountInfoRows(props: { account: AccountState; usage: Usage | null }): ReactNode   // 이메일·오프라인·사용량 li 줄
```

- `active` 는 "열려 있다" 의 뜻이다 — 넓은 배치는 팝오버 `open`, 판은 그 하위 화면이 보이는 동안. 링크 유무 GET·위키링크 판정·사용량 GET·60초 갱신이 `active` 가 참이 될 때 돈다(지금 `open` 에 걸린 것을 그대로 옮긴다)
- `onClose` 는 "닫고 트리거로 포커스" — 넓은 배치는 팝오버를 닫고 자기 트리거로, 판은 판을 닫고 `⋯` 로. 항목 동작 순서(닫기 → 포커스 → 동작)는 지금 `runAndClose` 그대로
- **`dialogs` 는 판 본체가 아니라 `TopBarMoreSheet` 의 늘 마운트된 자리에 그린다.** 판이 닫히며 하위 화면이 빠져도 `ShareSetDialog`·`ApiTokensDialog` 가 살아 있어야 한다(`읽기 전용 링크 복사…`·`API 토큰` 은 판을 닫은 뒤 대화상자를 연다). 그래서 `useShareMenu`·`useAccountMenu` 는 `TopBarMoreSheet` 최상위에서 부르고 `active` 로 하위 화면 표시 여부를 넘긴다
- 넓은 배치의 네 컴포넌트는 이 훅·함수를 불러 지금과 **같은 DOM**(클래스·`role`·`aria-*`·문구·순서)을 그린다. 기존 e2e 가 그대로 통과해야 한다(A8)
- 판 하위 화면은 같은 `items` 를 `ul.more-sheet-list` 의 `<button class="more-sheet-item">` 로 그린다. `role="menuitem"` 을 쓰지 않는다(4.4 — 대화상자 안 버튼 목록). 비활성 항목은 지금처럼 `aria-disabled` + 누르기 무시(공유 금고 규칙 F-409 6.2)

### 7.2 e2e — `e2e/topbarMore.spec.js` (3개, 모두 390×844 `hasTouch`·`isMobile`)

- **`F-2083 E1 휴대폰 폭 상단바와 판`** — 로컬 저장소, 로그인 안 함. `# 제목 1\n\n본문\n\n## 제목 2\n` 문서를 연다

## 10. 열린 질문 (2026-09-29 사용자: 전부 기본값대로)

### Q1. 판을 모달 `<dialog>` 로 할까, 댓글 판처럼 모달 아닌 `div` 로 할까 — **기본값: 모달 `<dialog>`**
- 이유: ⋯ 판은 잠깐 골라 닫는 선택지라 뒤를 막는 편이 맞다. `showModal` 이 뒤 막·`Esc`(`cancel`)·배경 `inert`·최상위 층을 그냥 준다. `useEdgeSwipe` 와 `Outline` 이 이미 `dialog[open]` 을 "무언가 떠 있다" 로 읽어 밀기·목차 카드를 알아서 멈춘다. 안드로이드 Chrome 뒤로 가기가 모달 대화상자를 닫을 가능성이 있다(확인 안 함 — H4)
- 다른 쪽을 고르면: 뒤 막·바깥 누르기·Esc·포커스 가두기를 직접 짜야 하고, 밀기·목차 카드와의 충돌 예외를 따로 더해야 한다. 대신 댓글 판과 한 벌 구조가 되고 뒤 화면이 흐려지지 않는다. 6장 뒤 막 행이 빠진다

### Q2. 판을 열 때 기록(history)에 항목을 넣어 뒤로 가기가 판만 닫게 할까 — **기본값: 넣지 않는다**
- 이유: 앱의 어떤 겹침(사이드바·대화상자·댓글 판)도 기록을 쓰지 않는다. 넣으면 `useHashRouting` 의 해시 처리와 "뒤로 = 이전 문서"(ia.md 3.10)가 판 하나 때문에 갈라진다. 넣지 않아도 뒤로 가기가 판을 떠 있는 채로 두지는 않는다(4.4 `hashchange` 닫기)
- 다른 쪽을 고르면: `pushState` 로 가짜 항목, 닫을 때 `history.back()`, `popstate` 가 판을 닫게 — `useHashRouting.ts` 가 소유표에 들고 ia.md 3.10 표에 한 줄이 는다. 판을 연 채 다른 주소로 가면 가짜 항목이 기록에 남는 문제를 따로 막아야 한다

### Q3. 공유·내보내기도 하위 화면으로 들어갈까, 첫 화면에 펼쳐 둘까 — **기본값: 하위 화면(알림·계정과 같게)**
- 이유: 사용자가 정한 "알림·계정은 같은 판 안에서 바뀐다" 와 한 규칙이 된다. 첫 화면이 7행(최대 336px + 머리 52px)으로 짧게 유지된다. 공유 항목은 최대 5개 + 안내, 내보내기는 5개라 펼치면 첫 화면이 17행을 넘는다
- 다른 쪽을 고르면: 첫 화면에 `공유`·`내보내기` 구역 머리 아래 항목을 바로 보인다. 한 번 덜 누르지만 판이 80dvh 를 넘어 스크롤이 생기고, e2e E1 4번의 흐름이 바뀐다

### Q4. 판을 아래로 끌어 닫기 — **기본값: 넣지 않는다**
- 이유: 끌기 제스처는 목록 스크롤과 부딪히고(F-229 A9 에서 카드 스크롤·화면 밀기 혼동을 이미 사람 확인으로 둠), 뒤 막 탭·`닫기`·뒤로 가기로 충분하다. 넣으면 새 제스처 훅과 사람 확인이 는다
- 다른 쪽을 고르면: 판 머리에 끌기 손잡이(`.more-sheet-grabber`)와 pointer 이벤트 처리 — `useEdgeSwipe` 와 같은 결의 훅 하나가 소유표에 는다

### Q5. `⋯` 버튼 이름 — **기본값: `메뉴`**
- 이유: 앱의 다른 `⋯` 버튼이 모두 `… 메뉴`(`댓글 메뉴`·`답글 메뉴`·`{폴더} 메뉴`)다. `더 보기` 는 ia.md 6장에서 두 곳의 "쓰지 않는 말" 로 올라 있다
- 다른 쪽을 고르면: 6.1 표·e2e E1·E3 의 이름만 바뀐다

### Q6. 목차 행을 판 안 하위 화면(제목 목록)으로 보일까 — **기본값: 아니다, 기존 카드를 연다**
- 이유: 사용자가 "기존 목차 패널을 연다" 로 정했다(정해진 것 7). 카드는 현재 위치 강조·스크롤 따라가기를 이미 한다
- 다른 쪽을 고르면: `Outline` 을 건드리지 않고 판 안에 `headings` 를 그리게 되며(그 경우 `OutlineControl` 이 `getHeadings`·`select` 로 바뀐다), 4.6·E3 2번이 다시 쓰인다
