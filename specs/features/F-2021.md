**직접 재거나 돌린 것** (2026-09-23, 이 PC Windows 11, Node v24.12.0, npm 11.7.0. 스크립트는 스크래치패드에만 있다)
- (a) **npm 이름.** `npm view rawdoc` → **404(등록 안 됨)**. 비슷한 이름 `raw-doc`·`rawdocs`·`raw_doc`·`raw.doc`·`rawdoc.js`·`rawdoc-js`·`rawdoc-cli`·`@rawdoc/cli` 도 전부 404. `@rawdoc` 조직이 비어 있는지는 확인하지 못했다(`npmjs.com` 이 curl 에 403). 이 PC 는 `npm whoami` 가 `ENEEDAUTH` — npm 로그인이 없다
- (b) **빌드 방식.** 저장소의 Vite 7.3.6 으로 `build.ssr` + `ssr.noExternal: true` + ESM + `banner: '#!/usr/bin/env node'` 로 TS 진입점을 묶었다. 결과는 **파일 1개**, `node:*` import 만 바깥에 남고 `brand.config.ts` 는 쓰는 필드(`name`)만 인라인됐다. `node out/rawdoc.js --json` 이 돌았다
- (c) **토큰 봉인 왕복**(5.3). WebCrypto 만으로 RSA-OAEP 2048·SHA-256 키 생성 → SPKI 내보내기 → 공개키로 토큰 암호화 → 개인키로 풀기. 세 번 돌려 **키 생성 21.0~70.3 ms**, 공개키 base64url **392자**, 봉인한 토큰 **342자**, 원문 일치. 암호문 1바이트를 바꾸면 `OperationError` 로 풀기 실패. `extractable: false` 로 만든 키 쌍에서도 공개키 SPKI 는 내보내졌다. 토큰 원문 길이는 **46자**(`rd_` + 43자)
- (d) **주소 길이.** 인증 화면 주소 505자, 콜백 주소 410자(포트 5자리, state 22자 기준)
- (e) **루프백 서버.** `node:http` 를 `127.0.0.1` 포트 0 에 열면 OS 가 **3410** 을 줬다 — Windows 가 1024~49151 사이 포트도 준다. 그래서 포트 검사 범위를 임시 포트 대역으로 좁히지 않는다(5.2). `http://127.0.0.1:{포트}` 요청의 `Host` 는 `127.0.0.1:{포트}`, `http://localhost:{포트}` 요청은 `localhost:{포트}` 로 들어왔다
- (f) **`fetch` 몸통.** Node `fetch` 에 `Uint8Array` 1,234바이트를 넘기면 `Content-Length: 1234` 가 붙고 `Transfer-Encoding` 은 없다 — `POST /v1/attachments` 가 요구하는 `Content-Length` 를 따로 넣지 않아도 된다. 기본 `User-Agent` 는 `node`
- (g) **`node:util` `parseArgs`.** `strict: true` 에서 모르는 옵션은 `ERR_PARSE_ARGS_UNKNOWN_OPTION`, `-` 는 위치 인자로 남는다
- (h) **파일 권한.** Windows 에서 `writeFileSync(..., { mode: 0o600 })`·`chmodSync(0o600)` 뒤에도 `stat` 모드는 `666` 이다. `%APPDATA%`(`C:\Users\yjw05\AppData\Roaming`) ACL 은 `SYSTEM`·`Administrators`·본인 계정만 가진다(`icacls`)
- (i) **셸 리디렉션 바이트.** `process.stdout.write('# 한글\r\nabc')` 를 `>` 로 파일에 받았다. **Windows PowerShell 5.1** → `ff fe 23 00 20 00 3f 00 …` (UTF-16LE + BOM, 한글이 `?` 로 깨지고 끝에 CRLF 가 붙음). **PowerShell 7**·**Git Bash** → `23 20 ed 95 9c ea b8 80 0d 0a 61 62 63`(원문 그대로). 4.6 의 `-o` 옵션 근거
- (j) **`@types/node` 없음.** 루트 타입 검사는 `node:*` 를 `src/vite-env.d.ts` 에 손으로 선언해 통과한다(`--traceResolution` 에서 `'node:fs' was not resolved`, 그래도 오류 0). 선언 없는 파일에서 `node:http` 를 import 하면 `TS2591`
- (k) **선례.** `node_modules/wrangler` 의 `wrangler login` 이 `http://localhost:8976/oauth/callback` 루프백 리디렉션을 쓴다. 브라우저 열기는 번들된 `open` 패키지가 macOS `open`, Linux `xdg-open`, Windows 는 PowerShell `Start` 를 `-EncodedCommand` 로 부른다
- (l) **무시 규칙.** `git check-ignore cli/dist/rawdoc.js` → `.gitignore:11:dist` 로 무시된다. ESLint `isPathIgnored('cli/dist/rawdoc.js')` → **false**(루트 `dist` 만 무시)
- (m) **Node 지원 일정.** `nodejs/Release` `schedule.json`: v20 종료 **2026-04-30**, v22 종료 2027-04-30, v24 종료 2028-04-30. `vitest` 5.0.0 `engines` 는 `^22.12.0 || ^24.0.0 || >=26.0.0`, `wrangler` 4.131.1 은 `>=22.0.0`

## 사용자가 이미 정한 것 (바꾸지 않는다)

1. **원격 MCP 서버 대신 CLI** (2026-09-22 제안, 2026-09-23 명세 작성 지시로 확정)
2. **배포는 npm 이 주 경로** — `npx` 로 설치 0단계. GitHub 릴리즈 바이너리는 만들지 않는다
3. **1차 범위는 CLI 만.** `rawdoc mcp`(로컬 stdio MCP) 서브커맨드는 다음 명세. 다만 얹기 쉬운 구조는 여기서 잡는다(4.7)
4. **TUI 를 만들지 않는다**("CLI 에 TUI까지 갖출 필요는 없어보임"). 전체 화면·대화형 선택·스피너·진행 막대·색이 없다. 사람용 출력과 `--json` 두 가지. **기본은 비대화형** — 어떤 명령도 입력을 기다리며 멈추지 않는다
5. **인증은 브라우저 위임.** `login` → localhost 임시 포트 → 브라우저로 웹의 CLI 인증 화면 → 기존 Access 로그인 → 웹앱이 기존 `POST /api/tokens` 호출 → 토큰을 localhost 로 → 0600 파일. 토큰 직접 넘기기·환경 변수(CI)도 받는다

## 3. 패키지 — 위치·이름·빌드·Node 버전

### 3.1 위치와 이름
- 저장소 안 위치는 **`cli/`**. 루트 `package.json` 은 `private: true` 이고 `workspaces` 가 없다 — workspaces 로 만들지 않는다. CLI 는 런타임 의존성이 0 이라 자기 `node_modules` 가 필요 없고, 빌드는 루트의 `vite` 를 쓴다. 루트와 `cli/` 두 `package.json` 이 같은 `name` 을 가져도 workspaces 가 아니라 충돌하지 않는다(루트는 게시되지 않는다)
- npm 이름은 **`rawdoc`**(스코프 없음). 측정 (a) — 등록돼 있지 않고 닮은 이름도 없다. 이름과 실행 파일 이름이 같아 `npx rawdoc ls` 가 바로 된다
- `cli/package.json` 계약:

```json
{
  "name": "rawdoc",
  "version": "0.1.0",
  "description": "마크다운 편집기 rawdoc의 명령줄 도구(CLI)입니다",
  "type": "module",
  "bin": { "rawdoc": "dist/rawdoc.js" },
  "files": ["dist"],
  "engines": { "node": ">=22" },
  "repository": { "type": "git", "url": "git+https://github.com/R00neyj/rawdoc.git", "directory": "cli" },
  "license": "UNLICENSED",
  "scripts": { "prepublishOnly": "npm --prefix .. run build:cli" }
}
```

- `description` 은 사용자 지시 문구(2026-09-23: "마크다운 편집기 rawdoc의 명령줄 도구(CLI)입니다 ... 이런식으로"). `package.json` 은 `brand.config.ts` 를 import 할 수 없으므로 **가드 테스트가 `name` 과 함께 `description` 안의 제품명도 `brand.config.ts` 값과 같은지 본다**
- `dependencies`·`devDependencies` 는 두지 않는다. `license` 는 `UNLICENSED`(15장 Q1, 사용자 결정 2026-09-23) — 저장소에 `LICENSE` 파일이 없다(확인)

### 3.2 Node 최소 버전 — `>=22`
- v20 은 2026-04-30 에 지원이 끝났다(측정 (m)). 저장소 도구(`vitest`·`wrangler`)도 22 이상을 요구한다
- 쓰는 기능(`fetch`·`AbortSignal.timeout`·`parseArgs`·전역 `crypto.subtle`·`atob`/`btoa`·`node:http`)은 전부 22 에 있다
- 22 미만에서 실행하면 첫 줄에서 `Node.js 22 이상이 필요합니다 (지금 {process.version}).` 를 표준 오류에 쓰고 종료 코드 1

### 3.3 빌드 — TS → 파일 1개
- `cli/vite.config.ts` 로 Vite SSR 빌드(측정 (b)): 진입점 `cli/src/main.ts`, `ssr.noExternal: true`(공유 파일까지 전부 묶음), 출력 `cli/dist/rawdoc.js` 하나, ESM, 첫 줄 `#!/usr/bin/env node`, 대상 `node22`, 압축하지 않음(오류 스택을 읽을 수 있게)
- `package.json`(루트) 스크립트:
  - `"build:cli": "vite build --config cli/vite.config.ts"`
  - `"typecheck:cli": "tsc -p cli --noEmit"`
- 번들에 `node:` 로 시작하지 않는 import 가 남으면 안 된다(13.3 B1)
- `--version` 이 찍는 값은 `cli/package.json` 의 `version` 이다. 빌드 때 그 파일에서 읽어 넣는다

### 3.4 타입 — `@types/node` 를 들이지 않는다 (기본값, 15장 Q6)
- 선례: `src/vite-env.d.ts` 가 `@types/node` 없이 `node:fs`·`node:url`·`node:path` 에서 쓰는 함수만 선언한다(측정 (j))
- CLI 도 같은 방식으로 `cli/src/node-shim.d.ts` 에 쓰는 것만 선언한다: `node:http`(`createServer`·요청·응답의 쓰는 멤버), `node:fs/promises`, `node:os`(`homedir`·`hostname`), `node:path`, `node:child_process`(`spawn`), `node:util`(`parseArgs`), 전역 `process`
- `fetch`·`Response`·`URL`·`TextEncoder`·`CryptoKey`·`crypto.subtle` 타입은 `cli/tsconfig.json` 의 `lib` 에 `DOM` 을 넣어 얻는다(Node 의 해당 전역은 WHATWG 모양이다)
- `cli/tsconfig.json` 이 포함하는 저장소 밖 파일: `../brand.config.ts`, `../src/lib/cliLoginUrl.ts`, `../src/lib/cliSeal.ts`, `../src/lib/decodeMarkdown.ts`, `../src/lib/lineEnding.ts`, `../src/lib/siteMeta.ts`, `../src/lib/folderTree.ts`, `../worker/v1Contract.ts`. **`src/vite-env.d.ts` 는 넣지 않는다** — `node:path` 선언이 두 번 들어가 `sep` 가 겹친다
- 왜 `@types/node` 가 아닌가: 루트·worker `tsconfig.json` 둘 다 `types` 를 지정하지 않아, 설치하면 `node_modules/@types` 전체가 두 프로그램에 자동으로 들어간다. 앱의 `setTimeout` 반환 타입, worker 의 `Request`·`Response` 전역과 겹칠 수 있다. **실제로 깨지는지는 설치하지 않아 확인하지 못했다**(16.2)

## 4. 명령

### 4.1 공통 규칙

**서버 결정 순서**: `--server <주소>` → 환경 변수 `{CLI}_SERVER` → `SITE_URL`(`src/lib/siteMeta.ts`, 지금 `https://rawdoc.app/`). `{CLI}` 는 8장
- 값은 `new URL(값).origin` 으로 줄인다(경로·쿼리 버림). 문자열 비교·저장 키도 이 origin
- `https:` 는 어떤 호스트든, `http:` 는 호스트가 `localhost`·`127.0.0.1`·`[::1]` 일 때만(`npm run dev:worker` 가 `http://localhost:8790`). 그 밖의 `http:` 는 사용법 오류 `http 주소는 localhost 에서만 쓸 수 있습니다: {주소}` — 토큰이 평문으로 나가지 않게

**토큰 결정 순서**: 환경 변수 `{CLI}_TOKEN` → 저장 파일의 그 서버 항목(5.6). 둘 다 없으면 `not_logged_in`(종료 코드 3)
- **토큰을 명령줄 인자 값으로 받지 않는다.** 프로세스 목록·셸 기록에 남는다. 넘기려면 `login --with-token` 에 표준 입력으로(5.5)

**요청**
- 헤더: `Authorization: Bearer {토큰}`, `User-Agent: {cliName}/{version} node/{process.version}`, JSON 몸통이면 `Content-Type: application/json; charset=utf-8`
- 시간 제한 **60초**(요청 하나당, 이미지 올리기 포함). 넘으면 `timeout`
- 다시 시도하지 않는다 — 부르는 쪽(사람·AI 도구)이 종료 코드를 보고 판단한다

**입력을 기다리지 않는다**
- 표준 입력은 **위치 인자 자리에 `-` 를 줬을 때만** 읽는다. 인자가 없다고 표준 입력을 읽지 않는다 — AI 도구가 표준 입력을 열어 둔 채 부르면 영원히 멈추기 때문이다
- `login` 만 사람의 동작(브라우저 승인)을 기다리고, 그것도 5분 제한이 있다(5.1)

**출력 원칙**
- 표준 출력 = 결과 데이터만. 안내·경고·오류는 전부 표준 오류
- 색(ANSI)·스피너·진행 표시 없음. TTY 인지에 따라 출력 모양을 바꾸지 않는다
- `console.log` 를 쓰지 않는다 — `npm run review` 가 `scripts/` 밖의 `console.log` 를 금지 패턴으로 잡는다(`scripts/review-diff.mjs` `checkLines`). 쓰기는 `main` 이 받은 출력 객체로만

### 4.2 명령 표

전역 옵션: `--server <주소>`, `--json`, `-h, --help`, `-v, --version`. 모르는 옵션·인자 개수 오류는 사용법 오류(종료 코드 2)

| 명령 | 인자·옵션 | 부르는 것 | 표준 출력(사람용) |
| --- | --- | --- | --- |
| `login` | `[--force] [--with-token] [--no-browser]` | 5장 + `GET /v1/me` | 없음(안내는 표준 오류) |
| `logout` | — | 없음 | 없음 |
| `whoami` | — | `GET /v1/me` | `{email}\t{origin}` |
| `ls` | `[--folder <폴더id>]` | `GET /v1/docs` | 문서마다 `{id}\t{updatedAt}\t{title}` |
| `get <문서id>` | `[-o, --output <파일>]` | `GET /v1/docs/:id` | `-o` 없으면 `content` 그대로, 있으면 `{id}\t{version}` |
| `new [<파일>\|-]` | `[--title <제목>] [--folder <폴더id>]` | `POST /v1/docs` | `{id}` |
| `put <문서id> [<파일>\|-]` | `[--title <제목>]` + (`--base-version <n>` 또는 `--force`) | (`GET`) + `PUT /v1/docs/:id` | `{id}\t{version}` |
| `folders` | — | `GET /v1/folders` | 폴더마다 `{id}\t{경로}` |
| `mkdir <이름>` | `[--parent <폴더id>]` | `POST /v1/folders` | `{id}` |
| `upload <이미지파일>` | — | `POST /v1/attachments` | 서버가 준 `markdown` 3줄 |
| `link <문서id>` | — | `POST /v1/docs/:id/link` | `{url}` |

명령별 규칙
- `ls --folder` 는 받은 목록을 `folderId` 가 같은 것만 남긴다(서버에 거르기 인자가 없다). 순서는 서버 순서(`updatedAt` 내림차순)
- `get` 은 `content` 를 **바이트 그대로** 쓴다. 끝 줄바꿈을 더하지 않는다. `-o` 는 그 파일을 UTF-8(BOM 없음)로 덮어쓴다
- `new`
  - 원문: `<파일>` 이면 그 파일, `-` 면 표준 입력 끝까지, 둘 다 없으면 빈 문자열 — 이때는 `--title` 필수(없으면 사용법 오류 `원문 파일이나 --title 이 필요합니다.`)
  - 원문 바이트는 **앱의 가져오기와 같은 해독**을 거친다: `decodeMarkdown`(`src/lib/decodeMarkdown.ts`) — BOM 제거, 섞인 줄바꿈은 CRLF 로 통일, UTF-8 이 아니면 `not_utf8`. 몸통의 `lineEnding` 은 그 결과값을 명시해 보낸다
  - 제목: `--title` 이 있으면 그것. 없으면 파일 이름에서 끝 `.md`(대소문자 무시)를 뗀 것, 비면 `제목 없는 문서`. 표준 입력이면 `제목 없는 문서`. 규칙은 `src/app/importFiles.ts` `titleFromFileName` 과 같다(app 파일을 import 하지 않고 같은 규칙을 CLI 쪽에 둔다 — 한 줄짜리)
- `put`
  - 원문: `<파일>`·`-` 는 `new` 와 같은 해독. 원문이 없고 `--title` 만 있으면 제목만 바꾼다. 둘 다 없으면 사용법 오류 `올릴 원문 파일이나 --title 이 필요합니다.`
  - **`--base-version <n>` 과 `--force` 중 정확히 하나가 필요하다**(기본값, 15장 Q4). 둘 다 없으면 사용법 오류 `--base-version 또는 --force 가 필요합니다. {cli} get {id} --json 으로 지금 version 을 확인하세요.` 둘 다 있으면 사용법 오류
  - `--base-version` 은 0 이상의 정수 문자열만
  - `--force` 는 `GET /v1/docs/:id` 로 지금 `version` 을 읽어 그 값으로 `PUT` 한다. 그 사이 바뀌어 409 가 나면 그대로 409(다시 시도하지 않는다)
  - 이유: `baseVersion` 을 자동으로 채우면 AI 도구가 `get` → 고치기 → `put` 하는 사이 브라우저에서 저장된 내용을 조용히 덮는다. 편집 잠금(F-213)은 창을 닫으면 풀리므로 이 경우를 막지 못한다
- `folders` 의 `{경로}` 는 조상 폴더 이름을 `/` 로 이은 것(`folderAncestors`, `src/lib/folderTree.ts`). 경로 오름차순
- `upload` 는 파일 바이트를 그대로 보낸다. 형식·크기 검사는 서버가 한다(클라이언트에서 5MB 를 미리 재지 않는다 — 한도 값의 원본이 `worker/attachments.ts` 하나이게)
- `link` 의 `url` 은 서버가 만든 `{origin}/#/p/{token}` 그대로

**사람용 출력 세부**
- 줄마다 끝에 `\n`. 칸 구분은 탭(`\t`) — 사람이 읽고 `cut`·`awk` 로도 자른다
- `{title}`·`{경로}` 안의 제어 문자(U+0000~U+001F, U+007F)는 공백 하나로 바꾼다. `--json` 은 바꾸지 않는다
- `{updatedAt}` 은 ISO 8601 UTC 초 단위 `2026-09-23T04:05:06Z`. 시간대에 따라 출력이 달라지지 않게
- 목록이 비면 표준 출력은 비우고 표준 오류에 `문서가 없습니다.` / `폴더가 없습니다.`
- `get`(`-o` 없음)만 끝 줄바꿈이 없다

### 4.3 도움말

| `login` | 브라우저로 로그인해 토큰을 저장합니다 |
| `logout` | 이 컴퓨터에 저장한 토큰을 지웁니다 |

- 도움말 끝에 두 줄: `Windows PowerShell 5.1 에서는 > 대신 -o 로 저장하세요. > 는 파일을 UTF-16 으로 바꿉니다.`(측정 (i)), `AI 도구에서 쓸 때는 npx -y {cli} … 또는 {CLI}_TOKEN 환경 변수를 쓰세요.`

### 4.4 `--json` 출력 스키마

`--json` 이면 표준 출력에 JSON 값 **하나**를 한 줄로(`JSON.stringify` + `\n`). 서버 응답을 **그대로 넘긴다** — CLI 가 필드를 더하거나 빼는 곳은 표에 적은 것뿐이다. 타입 이름은 `worker/v1Contract.ts`(7.2)

| 명령 | 표준 출력 |
| --- | --- |
| `login`·`whoami` | `V1Me & { server: string }` |
| `logout` | `{ server: string; removed: boolean }` |
| `ls` | `V1DocSummary[]` (`--folder` 면 거른 뒤) |
| `get` | `V1Doc`. `-o` 와 함께면 `Omit<V1Doc, 'content'>` |
| `new`·`put` | `V1Doc` |
| `folders` | `V1Folder[]` |
| `mkdir` | `V1Folder` |
| `upload` | `V1Attachment` |
| `link` | `V1Link` |

오류는 `--json` 이어도 표준 오류로 간다. `--json` 일 때 표준 오류 모양(한 줄):

```ts
type CliErrorJson = {
  error: string          // 4.5 표의 코드
  status: number | null  // HTTP 상태. 요청 전 오류면 null
  message: string        // 4.5 표의 한국어 문구
  field?: string         // 서버 400 의 field
  limit?: number         // 413·507
  used?: number          // 507
  email?: string         // 423
  expiresAt?: number     // 423
  currentVersion?: number // 409 — 서버 몸통의 doc.version. doc 전체는 싣지 않는다
}
```

- `{cli}` 는 `brand.cliName`, `{CLI}` 는 그 대문자(8장)
- 서버 `error` 코드가 표에 없으면 상태 코드로 줄을 고른다(4xx 는 `bad_response`)
- 이 표가 스크립트와 AI 도구가 기대는 계약이다. 번호를 바꾸는 것은 호환이 깨지는 변경(10.1)

### 4.6 원문 보존
- 문서 원문을 CLI 가 바꾸는 경우는 **파일을 올릴 때 `decodeMarkdown` 이 하는 두 가지(BOM 제거, 섞인 줄바꿈 CRLF 통일)뿐**이고, 그때 표준 오류에 앱과 같은 문구를 쓴다: `"{파일}" 줄바꿈 형식이 섞여 있어 CRLF 로 통일했습니다.` / `"{파일}" 파일 맨 앞의 BOM 을 제거했습니다.`(F-114). 표준 입력이면 `"{파일}"` 자리에 `표준 입력`
- 왜 해독을 거치나: CM6 은 섞인 줄바꿈을 담지 못해 앱에서 한 번 열면 바이트가 바뀐다. 앱의 가져오기와 같은 원문이 서버에 들어가게 해 "앱으로 연 뒤 내보낸 바이트 = CLI 가 올린 바이트" 를 지킨다
- 받기(`get`)는 `content` 를 한 글자도 바꾸지 않는다. `get -o a.md` 로 받은 파일을 `put` 으로 다시 올리면 원문이 같다(13.1 U7)
- Windows PowerShell 5.1 의 `>`·파이프는 바이트를 바꾼다(측정 (i)). CLI 가 막을 수 없으므로 `-o`·파일 인자를 쓰라고 도움말·README 에 적는다

### 4.7 나중에 `rawdoc mcp` 를 얹기 쉬운 구조
- `commands.ts` 의 명령 함수는 **입력 객체를 받아 결과 데이터(와 표준 오류로 보낼 안내 목록)를 돌려주고**, 실패는 `code`·`status`·서버 부가 필드를 가진 오류 객체를 던진다. 출력·종료 코드는 모른다
- `main.ts` 가 유일하게 `process.stdout`·`process.stderr` 에 쓰고 종료 코드를 정한다. `main` 은 인자·환경 변수·출력 객체·`fetch` 를 받는 함수로 두고 단위 테스트가 직접 부른다
- 이유: stdio MCP 서버에서는 표준 출력이 프로토콜 통로라 명령 코드가 한 글자라도 찍으면 깨진다. 다음 명세는 같은 명령 함수를 MCP 도구로 감싸고 결과를 도구 결과 JSON 으로, 오류를 `isError` 로 바꾸기만 하면 된다
- 명령 함수의 입력은 사람용 문자열 인자가 아니라 이미 해석된 값(예: `put` 은 `{ id, content?: string, title?: string, baseVersion?: number, force: boolean }`)이다. 파일 읽기는 `main` 쪽 층에서 끝낸다 — MCP 도구는 파일이 아니라 문자열을 받을 것이기 때문

## 5. 로그인

### 5.1 흐름
1. 이미 그 서버 토큰이 저장돼 있고 `--force` 가 없으면 `GET /v1/me` 로 확인한다. 200 이면 표준 오류 `이미 {email} 계정으로 로그인돼 있습니다 ({origin}). 다시 로그인하려면 --force 를 붙이세요.` 종료 0. 401 이면 그대로 새 로그인으로 간다
2. RSA-OAEP 키 쌍(5.3)과 `state`(무작위 16바이트 base64url, 22자)를 만든다
3. `127.0.0.1` 포트 0 에 HTTP 서버를 연다(5.2)
4. 인증 화면 주소를 만든다(`buildCliLoginUrl`, 6.1) — `{origin}/?app=1#/cli-login/{port}/{state}/{공개키}/{host}`
5. 표준 오류에 `브라우저에서 로그인을 승인하세요. 브라우저가 열리지 않으면 이 주소를 여세요:` 와 다음 줄에 주소. `--no-browser` 가 아니면 브라우저를 연다(5.4). 열기 실패는 치명적이지 않다(주소는 이미 찍혔다)
6. 콜백을 기다린다. **5분**(`login_timeout`). Ctrl+C 면 서버를 닫고 130
7. 봉인을 풀어 얻은 토큰으로 `GET /v1/me`. 200 이면 저장(5.6)하고 표준 오류 `{email} 계정으로 로그인했습니다 ({origin}).` 종료 0. 실패면 저장하지 않고 4.5 의 코드로 끝낸다
8. 환경 변수 `{CLI}_TOKEN` 이 있으면 끝에 한 줄 더: `{CLI}_TOKEN 환경 변수가 설정돼 있어 저장한 토큰 대신 그 값을 씁니다.`

- 원격 셸(SSH·원격 컨테이너)에서는 브라우저가 그 기계의 `127.0.0.1` 에 닿지 않는다. 그 경우는 `--with-token`(5.5)으로 간다 — README 에 적는다

### 5.2 CLI 쪽 로컬 서버 규칙
- **`127.0.0.1` 에만** 연다(모든 인터페이스 아님). 콜백 주소도 `localhost` 가 아니라 `127.0.0.1` — RFC 8252 7.3 의 루프백 권고와 같고, `localhost` 가 IPv6 로 풀리는 환경을 피한다
- 판정은 순수 함수 하나로(단위 테스트 대상). 요청마다:

| 조건 | 응답 | 로그인 |
| --- | --- | --- |
| 메서드가 `GET` 아님 | 405 | 계속 기다림 |
| `Host` 가 정확히 `127.0.0.1:{port}` 아님 | 400 | 계속 기다림 (DNS 리바인딩 방어, 측정 (e)) |
| 경로가 `/callback` 아님 (`/favicon.ico` 등) | 404 | 계속 기다림 |
| `state` 가 다름(길이 같은 상수 시간 비교) | 400, 페이지 `로그인 응답이 맞지 않습니다. 터미널에서 다시 로그인하세요.` | 계속 기다림 |
| `error=denied` | 200, 페이지 `로그인을 취소했습니다. 이 창을 닫아도 됩니다.` | `login_denied` 로 끝 |
| `sealed` 를 풀지 못함 | 400, 위 "맞지 않습니다" 페이지 | 계속 기다림 |
| 성공 | 200, 페이지 `로그인했습니다. 이 창을 닫고 터미널로 돌아가세요.` | 서버를 닫고 7번으로 |

- 응답 헤더: `Content-Type: text/html; charset=utf-8`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`. 페이지는 `<meta charset="utf-8">` + 문장 한 줄. 제품명은 쓰지 않는다
- "계속 기다림" 인 400 이 와도 5분 제한은 처음부터 잰다

### 5.3 토큰 봉인 — RSA-OAEP (기본값, 15장 Q5)
- 토큰은 브라우저가 `http://127.0.0.1:{port}/callback?…` 으로 **최상위 이동**해서 넘긴다. 그런데 이 주소는 브라우저 방문 기록에 남고, Chrome 동기화면 다른 기기로도 간다. 원문 `rd_…` 를 그대로 싣지 않는다
- CLI 가 만든 **일회용 RSA-OAEP 2048 / SHA-256 키 쌍**의 공개키(SPKI, base64url)를 인증 화면 주소에 싣는다. 화면은 발급받은 토큰을 그 공개키로 암호화한 `sealed`(base64url)만 콜백에 싣는다. 개인키는 CLI 프로세스 메모리에만 있고 끝나면 사라진다 — 기록에 남은 `sealed` 는 쓸모가 없다
- 측정 (c): 키 생성 21~70 ms, 공개키 392자, `sealed` 342자, 변조하면 풀기 실패
- `src/lib/cliSeal.ts` 계약(웹·CLI 가 같은 파일을 쓴다. `Buffer` 를 쓰지 않고 `atob`/`btoa` 로 base64url):

```ts
export function generateSealKeyPair(): Promise<{ publicKey: string; privateKey: CryptoKey }>
export function sealToken(publicKey: string, token: string): Promise<string>
export function openSealedToken(privateKey: CryptoKey, sealed: string): Promise<string>
```

- 개인키는 `extractable: false`
- 풀린 값이 `^rd_[A-Za-z0-9_-]{43}$` 가 아니면 "풀지 못함" 으로 본다

### 5.4 브라우저 열기 — `cli/src/openBrowser.ts`
- 순수 함수가 `{ command, args }` 를 정하고, 실행은 `spawn`(`detached`, 표준 입출력 무시, 기다리지 않음)
  - macOS: `open {url}`
  - Windows: `powershell.exe -NoProfile -NonInteractive -EncodedCommand {base64(UTF-16LE("Start '{url}'"))}` — `wrangler` 에 들어 있는 `open` 패키지와 같은 방식(측정 (k)). `cmd /c start` 를 쓰지 않는 이유는 `&`·`%`·`^` 해석
  - 그 밖(Linux 등): `xdg-open {url}`
- 실행 실패(`ENOENT`·0 아닌 종료)는 무시한다. 주소는 5.1-5 에서 이미 찍혔다
- 인증 화면 주소는 **`[A-Za-z0-9._~:/?#=-]` 문자만** 쓴다(6.1). 셸 해석이 끼어들 문자가 없게 만들어 두면 위 세 명령 어느 쪽도 인용 문제를 겪지 않는다
- WSL 에서 `xdg-open` 이 없으면 실패 → 주소를 사람이 연다. WSL 전용 처리는 하지 않는다

### 5.5 토큰 직접 넘기기와 환경 변수
- `login --with-token`: 표준 입력 끝까지 읽어 앞뒤 공백을 뗀 값을 토큰으로. 표준 입력이 TTY 면 기다리지 않고 사용법 오류 `토큰을 파이프로 넘기세요: {cli} login --with-token < token.txt`. 형식이 `^rd_[A-Za-z0-9_-]{43}$` 가 아니면 사용법 오류 `API 토큰 형식이 아닙니다 (rd_ 로 시작하는 46자).` 그다음 `GET /v1/me` 로 확인하고 저장. 브라우저를 열지 않는다
  - 토큰은 웹 계정 메뉴 `API 토큰`(F-222 D-5)에서 만든다
- 환경 변수 `{CLI}_TOKEN`: 저장 파일보다 먼저 쓴다(4.1). CI·AI 도구용. 저장하지 않는다
- 같은 서버에 계정을 둘 이상 쓰는 방법은 환경 변수뿐이다. 저장 파일은 서버 origin 하나당 토큰 하나(15장 Q7 참고)

### 5.6 저장 위치와 파일 모양
- 디렉터리 이름은 **`md-editor`** — 제품명을 넣지 않는다(불변조건 "저장 식별자는 제품명과 무관하게 고정". IndexedDB `md-docs`·localStorage `md.*`·D1 `md-editor-db` 와 같은 계열). 이름이 바뀌어도 저장한 토큰이 사라지지 않게
  - Windows: `%APPDATA%\md-editor\credentials.json` (`APPDATA` 가 없으면 `{homedir}\AppData\Roaming`)
  - 그 밖(macOS 포함): `$XDG_CONFIG_HOME/md-editor/credentials.json` (`XDG_CONFIG_HOME` 이 없거나 비면 `{homedir}/.config`)
- 위치 계산은 `{ platform, env, homedir }` 를 받는 순수 함수(테스트는 세 OS 를 다 돈다)
- 쓰기: 디렉터리 `0o700`, 파일 `0o600`, 같은 디렉터리의 임시 파일에 쓰고 `rename` 으로 바꾼다(쓰다 끊겨도 반쪽 파일이 남지 않게). Windows 는 모드가 적용되지 않는다(측정 (h)) — 사용자 프로필 ACL 에 기댄다
- 모양:

```json
{
  "version": 1,
  "servers": {
    "https://rawdoc.app": { "token": "rd_…", "email": "a@b.com", "savedAt": "2026-09-23T04:05:06.000Z" }
  }
}
```

- 키는 4.1 의 origin(끝 `/` 없음). 모르는 `version`·깨진 JSON 이면 읽을 때 빈 것으로 보고 표준 오류 `저장 파일을 읽지 못해 무시합니다: {경로}` — 다음 `login` 이 새로 쓴다
- "기본 서버" 를 저장하지 않는다. 서버는 늘 4.1 순서로 정한다 — `--server http://localhost:8790` 으로 로그인한 뒤 옵션 없이 부른 명령이 개발 서버로 가는 일이 없게

### 5.7 `logout`·`whoami`
- `logout`: 그 서버 항목을 지운다. 남은 항목이 없으면 파일도 지운다. 표준 오류 `로그아웃했습니다 ({origin}). 토큰은 서버에 남아 있습니다 — 웹의 계정 메뉴 → API 토큰에서 폐기할 수 있습니다.` 항목이 없었으면 `저장된 토큰이 없습니다 ({origin}).` 둘 다 종료 0
- `whoami`: 4.1 순서로 고른 토큰으로 `GET /v1/me`

## 6. 웹 — CLI 로그인 화면 (S-9)

### 6.1 주소
- `{origin}/?app=1#/cli-login/{port}/{state}/{publicKey}/{host}`
- `?app=1` 이 필요한 이유: 이 브라우저가 앱을 처음 여는 것이면 `/` 가 랜딩을 준다(`rootTarget`, `worker/rootRoute.ts`). 해시는 서버에 가지 않으므로 서버는 이 주소를 모른다. `?app=1` 은 F-271 2.3 의 탈출구다
- 정보를 해시에 두는 이유: 해시는 서버·Access 로그에 남지 않는다. 그리고 `run_worker_first`·서비스 워커 `navigateFallbackDenylist`·worker 라우트를 하나도 고치지 않아도 된다
- 조각 검사(하나라도 어기면 "잘못된 주소"):

| 조각 | 규칙 |
| --- | --- |
| `port` | 10진 정수 1024~65535 (측정 (e) — OS 가 3410 을 줬다) |
| `state` | `^[A-Za-z0-9_-]{22}$` |
| `publicKey` | `^[A-Za-z0-9_-]{300,800}$` 이고 `importKey('spki', RSA-OAEP SHA-256)` 성공 |
| `host` | `^[A-Za-z0-9.-]{1,34}$` |

- CLI 쪽 `host` 는 `os.hostname()` 에서 `[A-Za-z0-9.-]` 밖 문자를 `-` 로 바꾸고 34자로 자른 것, 비면 `unknown`
- `src/lib/cliLoginUrl.ts` 계약:

```ts
export const CLI_LOGIN_HASH_PREFIX = '#/cli-login/'
export type CliLoginRequest = { port: number; state: string; publicKey: string; host: string }
export function buildCliLoginUrl(origin: string, req: CliLoginRequest): string
export function parseCliLoginHash(hash: string): CliLoginRequest | null   // publicKey 의 importKey 검사는 하지 않는다(동기 순수 함수)
export function cliCallbackUrl(port: number, result: { state: string; sealed: string } | { state: string; error: 'denied' }): string
export function sanitizeCliHost(raw: string): string
export function cliTokenName(host: string): string   // `CLI · {host}`
```

- **콜백 주소는 오직 `cliCallbackUrl` 로 만든다: `http://127.0.0.1:{port}/callback?state=…&sealed=…`.** 호스트·경로를 주소 조각에서 받지 않는다 — 열린 리디렉션이 없다
- 토큰 이름 `CLI · {host}` 은 최대 6 + 34 = 40자 = F-222 이름 상한과 같다

### 6.2 `src/main.tsx` 분기
- `markAppEntry()` 는 지금처럼 먼저 부른다(쿠키 `md_app` — Access 로그인 뒤 돌아올 주소 `/#/cli-login/…` 에는 `?app=1` 이 없으므로 이 쿠키로 앱을 받는다)
- `location.hash` 가 `CLI_LOGIN_HASH_PREFIX` 로 시작하면 **`App` 을 렌더하지 않고** `./app/CliLoginPage` 를 동적 import 해 렌더한다. `DEV_YSYNC` 분기보다 먼저 본다
- 이유: `App` 을 띄우면 IndexedDB 를 열고 첫 실행이면 `사용법` 문서를 심는다. 이 화면에서 필요한 것은 `/api/me`·`/api/tokens` 뿐이다. 그리고 `App.tsx` 를 건드리지 않아 F-2022 와 겹치지 않는다
- 동적 import 이므로 평소 앱 번들은 거의 늘지 않는다(분기 몇 줄). 실제 증가량은 구현 보고에 적는다(13.3 B5)
- `CliLoginPage` 는 마운트 때 `removeBootSkeleton(document)` 를 부른다(`App` 의 공개 보기 분기와 같은 이유 — F-2015 5.3)
- 서비스 워커 등록·새 버전 알림(`App` 이 한다)은 이 화면에 없다

`ready` 내용(위에서 아래로)
- 제목(h1) `터미널 로그인`
- `{email} 계정으로 이 컴퓨터의 명령줄 도구가 문서를 읽고 고칠 수 있게 합니다.`
- `토큰 이름` / `CLI · {host}`
- 경고 `터미널에서 직접 로그인 명령을 실행한 경우에만 승인하세요.`
- 안내 `승인하면 API 토큰이 하나 만들어집니다. 계정 메뉴 → API 토큰에서 언제든 폐기할 수 있습니다.`
- 버튼 `취소`·`승인`

동작
- `승인` → `createToken(cliTokenName(host))`(`src/storage/apiTokensApi.ts`) → `sealToken` → `location.replace(cliCallbackUrl(port, { state, sealed }))`. 누르는 순간 `issuing` 으로 바꿔 두 번 눌러도 토큰이 하나만 만들어진다
- `취소` → 토큰을 만들지 않고 `location.replace(cliCallbackUrl(port, { state, error: 'denied' }))`
- 오류(`error` 상태 문구, F-222 문구 재사용)

  - `unauthorized`(세션 만료): `out` 상태로 바꾼다
  - 그 밖: `토큰을 만들지 못했습니다. 잠시 뒤 다시 시도하세요.`
- 콜백 이동이 실패하면(CLI 가 이미 끝남) 브라우저의 연결 오류 화면이 뜬다. 토큰은 만들어진 채 남는다 — 이름(`CLI · {host}`)으로 목록에서 알아볼 수 있다. 따로 처리하지 않는다

접근성
- `<main>`, h1 하나, 오류 줄 `role="alert"`, 버튼은 `<button>`, `로그인` 은 `<a>`
- **첫 포커스를 `승인` 에 두지 않는다**(엔터 한 번으로 승인되지 않게). 첫 포커스는 h1(`tabIndex={-1}`)
- 모양(카드 폭·여백·다크)은 사람 확인(13.4 S6). 클래스 이름 계약: `.cli-login`, `.cli-login-card`, `.cli-login-email`, `.cli-login-name`, `.cli-login-warning`, `.cli-login-note`, `.cli-login-error`

### 6.4 보안 규칙 (화면 쪽)
1. 버튼을 눌러야만 토큰을 만든다(자동 승인 없음)
2. 콜백 대상은 `http://127.0.0.1:{port}/callback` 로 고정(6.1). 다른 호스트·경로로 보낼 길이 없다
3. 토큰 원문은 화면에 표시하지 않고 봉인한 값만 내보낸다(5.3)
4. `window.top !== window.self`(다른 페이지의 틀 안)이면 `invalid` — 클릭 가로채기 방어
5. `state` 는 CLI 가 만든 값을 그대로 돌려줄 뿐 화면은 해석하지 않는다. 가짜 콜백을 거르는 것은 CLI 의 몫(5.2)

위협별로
- 악성 사이트가 이 주소를 새 창으로 열어도: 사용자가 누르지 않으면 아무 일 없다. 눌러도 토큰은 사용자 자기 컴퓨터의 `127.0.0.1` 로만 가고, 그 주소에 실린 공개키의 주인만 풀 수 있다
- 로그인 CSRF(공격자 토큰을 피해자 CLI 에 심기): 공격자는 피해자 CLI 의 `state`·공개키를 모른다
- 같은 컴퓨터의 다른 사용자가 자기 CLI 주소로 승인을 유도하는 피싱: 경고 문구와 토큰 이름의 호스트로만 막는다(기기 코드 대조는 두지 않는다 — 루프백 흐름에서는 같은 컴퓨터 공격만 남고, 그 경우 코드도 공격자가 보여 줄 수 있다)

### 6.5 notes 의 "신규 서버 작업은 인증 화면 하나" — 코드로 확인
**맞다. 인증 화면은 서버·worker 변경이 0 이다.** 근거:
- 토큰 발급: `POST /api/tokens` 가 원문을 이 응답에만 싣는다(`handleCreateToken`). 웹 래퍼 `createToken` 이 이미 있다(`src/storage/apiTokensApi.ts`)
- 로그인 복귀: `GET /api/login?return=#/…` 은 `return` 이 `#/` 로 시작하면 `/{return}` 으로 302(`handleLogin`) — `#/cli-login/…` 이 그대로 통과한다
- 첫 방문 랜딩 우회: `?app=1`(`rootTarget`)
- 주소 정보가 해시라 worker 라우트·`run_worker_first`·서비스 워커 예외가 필요 없다
- 토큰 전달이 `fetch` 가 아니라 최상위 이동이라 CORS·`Access-Control-Allow-Private-Network` 가 필요 없다

**이 명세가 서버에 더하는 것은 `GET /v1/me` 하나**이고, 인증 화면이 아니라 `whoami`·`--with-token` 확인·로그인 직후 이메일 확인에 쓴다(7.1). 없애는 안은 15장 Q3

## 7. 서버 — `GET /v1/me` 와 응답 모양 계약

### 7.1 `GET /v1/me`
- `worker/index.ts` `routes` 에 `{ method: 'GET', path: '/v1/me', handler: handleMe }` 한 줄. `handleMe` 는 `getUser` 를 부르고, `getUser` 는 `/v1/` 경로면 Bearer 토큰만 본다(`worker/auth.ts`) — **핸들러 코드는 새로 쓰지 않는다**
- 응답 `200 { id, email }`, 토큰 없음·틀림·폐기 `401 { error: 'unauthenticated' }`
- `last_used_at` 갱신은 `getTokenUser` 의 10분 규칙 그대로. `handleMe` 는 `ctx` 를 넘기지 않아 갱신 쓰기를 응답 전에 기다린다 — 지금 `/api/me` 와 같은 모양이고 10분에 한 번이라 두지 않는다
- F-304 가 같은 파일에 `/ws` 라우트를 더한다. 두 구현을 동시에 돌리지 않는다(메인이 순서를 정한다). 겹치는 곳은 `routes` 배열 한 곳

### 7.2 `worker/v1Contract.ts` — 계약 한 벌
- `/v1` 응답 모양의 **타입과 예시 값**을 둔다. 서버 핸들러는 이 파일을 import 하지 않는다(동작을 바꾸지 않는다). 양쪽 테스트가 이 파일에 대 본다
- 타입 계약(필드는 `rowToDoc`·`rowToDocSummary`·`rowToFolder`·`storeAttachment` 의 `row` + `markdown`·`handleCreateDocLinkV1`·`handleMe` 에서 옮겼다):

```ts
export type V1DocSummary = { id: string; title: string; lineEnding: 'crlf' | 'lf'; folderId: string | null; pinnedAt: number | null; version: number; createdAt: number; updatedAt: number }
export type V1Doc = V1DocSummary & { content: string }
export type V1Folder = { id: string; name: string; parentId: string | null; createdAt: number; updatedAt: number }
export type V1Attachment = { id: string; ext: 'png' | 'jpg' | 'gif' | 'webp'; mime: string; size: number; width: number; height: number; markdown: string }
export type V1Link = { token: string; url: string }
export type V1Me = { id: string; email: string }
export type V1Error = { error: string; field?: string; limit?: number; used?: number; email?: string; expiresAt?: number; doc?: V1Doc }
export const V1_EXAMPLES: { docSummary: V1DocSummary; doc: V1Doc; folder: V1Folder; attachment: V1Attachment; link: V1Link; me: V1Me }
```

- 서버 쪽 고정: `worker/v1.test.ts` 가 실제 핸들러(`makeEnv` 가짜 D1·R2)로 만든 응답의 **키 집합**이 `V1_EXAMPLES` 의 해당 값 키 집합과 같은지 본다(13.1 U15). 필드를 더하거나 빼면 이 테스트가 깨지고, 그때 CLI 쪽도 같이 본다
- CLI 쪽 고정: `client.ts`·`commands.ts` 는 이 타입으로 응답을 받고, 단위 테스트의 가짜 서버는 `V1_EXAMPLES` 로 응답한다
- 값의 의미(예: `version` 의 409 판정)는 F-223 테스트가 이미 붙잡고 있어 여기서 다시 하지 않는다

## 8. 제품명 불변조건의 CLI 적용 — 결론

**적용한다.** `cli/` 도 "이름 문자열을 코드·UI 문구에 직접 쓰지 않는다" 를 따른다. 다만 파일이 import 를 할 수 없는 식별자는 예외로 두고 테스트로 묶는다

- `brand.config.ts` 에 필드 하나: `cliName: 'rawdoc'`(`Brand` 타입에도). 실행 파일·npm 이름으로 쓸 소문자 식별자다. `name.toLowerCase()` 로 만들지 않는 이유 — 표기가 `Raw Doc` 처럼 바뀌면 명령 이름으로 쓸 수 없는 값이 된다
- 도움말·안내 문구의 제품명은 `brand.name`, 명령 이름은 `brand.cliName`, 환경 변수 이름은 `brand.cliName.toUpperCase()` + `_TOKEN`·`_SERVER`(지금 `RAWDOC_TOKEN`·`RAWDOC_SERVER`). 빌드가 번들에 값을 넣는다(측정 (b))
- 예외(파일 형식상 import 불가): `cli/package.json` 의 `name`·`bin` 키, `cli/README.md`. 선례는 루트 `package.json` 의 `"name": "rawdoc"` 과 루트 `README.md`
- **저장 식별자는 제품명과 무관**: 설정 디렉터리 `md-editor`(5.6)
- 기본 서버 주소는 `SITE_URL`(`src/lib/siteMeta.ts`)을 import — 도메인 문자열을 새로 쓰지 않는다
- `npm run review` 의 `제품명` 검사는 `src/`·`index.html`·`public/` 만 본다(`scripts/review-diff.mjs`). 그래서 `cli/src/brandGuard.test.ts` 가 대신한다: 테스트가 아닌 `cli/src/*.ts` 에 `brand.name`·`brand.cliName` 문자열이 없을 것, `cli/package.json` 의 `name` 과 `bin` 의 유일한 키가 `brand.cliName` 일 것
- 환경 변수를 제품명에서 만들면 이름이 바뀔 때 CI 설정도 바꿔야 한다. 명령 이름 자체가 바뀌어 어차피 스크립트를 고쳐야 하므로 받아들인다(15장 Q7)

## 9. M3(F-308) 과의 관계
F-301 7장: `/v1` PUT 은 F-308 에서 DO 경유로 바뀐다. CLI 에 닿는 것만:
- **요청·응답 모양은 그대로다** — `baseVersion` 은 D1 `version` 으로 계속 검사하고 낡으면 409(F-301 7장 4번). `put --base-version`·`--force` 동작이 바뀌지 않는다
- **423 은 F-308 에서 사라진다**(7장 5번). F-305~F-308 사이에는 "활성 DO 연결이 있으면 423" 이 되는데, 그 몸통에 `email`·`expiresAt` 가 있다는 보장이 없다. 그래서 4.5 의 423 문구는 `email` 이 없으면 괄호째 뺀다. 종료 코드 6 은 F-308 뒤에도 남겨 둔다(쓰이지 않을 뿐)
- **읽기가 최대 5초 낡을 수 있다**(F-301 3.5). DO 가 `version` 을 쓸 때마다 올리므로 누가 편집 중이면 `put --base-version` 이 409 를 자주 받는다. 예상된 동작이다
- `POST /v1/docs`·폴더·이미지·링크는 F-301 이 바꾸지 않는다
- F-308 명세를 쓸 때 이 장을 읽고 CLI 문구·종료 코드 표(4.5)를 같이 본다 — 14장 갱신 대상에 적었다

## 15. 열린 질문 / 사람 결정

### Q1. 패키지 라이선스 — **결정됨: `UNLICENSED` (2026-09-23 사용자)**
- 기본값: `"license": "UNLICENSED"`. 저장소에 `LICENSE` 가 없어 지금 상태(권리 유보)를 그대로 옮긴다. 나중에 바꿀 수 있다
- 다른 쪽 `MIT`: 남이 CLI 코드를 가져다 쓰고 고칠 수 있다. `cli/LICENSE` 파일을 더하고(`files` 에 포함), 저장소 전체 라이선스와 어긋나지 않게 루트도 같이 정해야 한다
- 영향: `cli/package.json` 한 줄, npm 페이지 표시

### Q2. npm 계정·게시·이름 선점 — **결정됨: 지금 `0.0.1` 로 이름 선점 (2026-09-23 사용자).** 자리 표시 패키지는 저장소 밖에서 메인이 만들고 사용자가 `npm login` 뒤 직접 게시한다. 구현 판은 `0.1.0`
- 기본값: 사용자가 자기 npm 계정으로 10.3 절차를 밟는다. 첫 게시는 웹 배포 뒤
- `rawdoc` 은 지금 비어 있다(측정 (a)). 구현까지 시간이 길면 그 사이 다른 사람이 가져갈 수 있다. 다른 쪽: 명세 승인 직후 빈 `0.0.1`(도움말만)을 먼저 올려 이름을 잡는다 — 그러면 `0.0.1` 이 로그인 없이 실패하는 판으로 남는다
- 이름을 잃으면: `@{계정}/rawdoc` 스코프 이름. `npx @{계정}/rawdoc` 는 실행 파일 이름이 `rawdoc` 이라 그대로 되지만, 문서·README 의 설치 문구가 바뀐다

### Q3. `GET /v1/me` 를 더하나 — 기본값: **더한다**
- 이유: `whoami`, `--with-token` 확인, 로그인 직후 이메일을 서버에서 받는다. 핸들러를 새로 쓰지 않는 한 줄이다(7.1)
- 다른 쪽(서버 변경 0): 인증 화면이 콜백에 `email` 을 평문으로 실어 저장, `whoami` 는 저장값만 보여 주고 토큰 확인은 `GET /v1/folders` 로. `--with-token` 로그인은 이메일을 모른다. 이 경우 1장에서 `worker/index.ts` 가 빠져 F-304 와 겹치지 않는다

### Q4. `put` 의 기본 충돌 처리 — 기본값: **`--base-version` 또는 `--force` 필수**
- 이유: 4.2 — 자동으로 최신 버전을 채우면 브라우저에서 저장된 내용을 조용히 덮는다
- 다른 쪽(옵션 없이 최신으로 덮기): AI 도구가 한 번에 성공하지만 덮어쓰기 사고를 막을 장치가 없다. `--base-version` 은 선택 옵션이 된다

### Q5. 토큰 전달 방식 — 기본값: **RSA-OAEP 봉인 + 최상위 이동**
- 다른 쪽 ① 원문을 쿼리에: 구현이 짧지만 방문 기록·동기화에 토큰 원문이 남는다
- 다른 쪽 ② 페이지가 `fetch` 로 `127.0.0.1` 에 POST: 기록에 안 남지만 CORS 응답과 `Access-Control-Allow-Private-Network`·Chrome 의 로컬 네트워크 접근 권한 창을 다뤄야 하고 브라우저마다 다르다. 이 권한 동작은 확인하지 못했다(16.2)

### Q6. `@types/node` — **결정됨: 들이지 않고 손으로 선언**(3.4, 2026-09-23 사용자)
- 다른 쪽: `@types/node`(devDependency, `~22`)를 들이고 루트·worker `tsconfig.json` 에 `"types": […]` 를 명시해 새지 않게 한다. 선언 파일을 손으로 관리할 일이 없어진다. **새 의존성이라 사람 결정**이고, 두 tsconfig 가 1장 소유에 더해진다

### Q7. 환경 변수 이름 — 기본값: **`brand.cliName` 대문자 + `_TOKEN`·`_SERVER`**(지금 `RAWDOC_TOKEN`)
- 다른 쪽: 저장 식별자처럼 제품명과 무관한 고정 이름(`MD_EDITOR_TOKEN`). 이름이 바뀌어도 CI 비밀 값을 안 고쳐도 되지만 사용자가 추측하기 어렵다

### Q8. `logout` 이 서버 토큰도 폐기하나 — 기본값: **아니다**(로컬만)
- 다른 쪽: `DELETE /v1/token`(부른 토큰 자신을 폐기)을 서버에 더한다. `getTokenUser` 가 토큰 id 를 돌려주도록 고쳐야 해 worker 소유가 늘고 F-222 2.3 이 바뀐다. `login --force` 를 반복하면 토큰이 쌓여 10개 한도에 닿는 문제가 줄어든다

### Q9. 로컬 폴더 동기화(`push`/`pull`) — 기본값: **이번에 하지 않는다**
- 이유: 파일 ↔ 문서 대응표를 어디에 둘지(원문 프론트매터는 원문 보존을 깨고, 별도 파일은 저장 식별자 규칙이 붙는다)와 충돌 규칙이 따로 명세 한 개 분량이다. `get -o`·`put --base-version` 으로 스크립트가 같은 일을 할 수 있다
- 다른 쪽: 이 명세에 넣으면 4장에 대응표 스키마·충돌 처리·삭제 전파가 더해진다

### Q10. Node 최소 버전 — 기본값: **`>=22`**
- 다른 쪽 `>=20.19`: 쓰는 기능은 20 에도 있다. 그러나 v20 은 지원이 끝났고(측정 (m)) 테스트도 22 이상에서만 돈다

### Q11. CI 에서 게시 — 기본값: **하지 않는다**(사람이 게시)
- 다른 쪽: 태그 푸시 때 GitHub Actions 가 `NPM_TOKEN` 비밀 값으로 게시(provenance 포함). 저장소 비밀 값 관리가 생긴다

### Q12. 인증 화면을 앱 해시 경로로 — 기본값: **그렇다**(`#/cli-login/…`, `main.tsx` 분기)
- 다른 쪽: worker 가 그리는 정적 페이지 `/cli/login`(랜딩처럼). React 를 안 쓰지만 `handleLogin` 의 `return` 규칙(`#/` 만 허용), `run_worker_first`, 서비스 워커 예외, 인라인 스크립트용 WebCrypto 코드 중복이 생긴다

### 기본값으로 정한 것 (승인 범위 안)
- 명령 이름·옵션(4.2), 사람용 출력 형식, 요청 시간 제한 60초, 로그인 대기 5분, 설정 디렉터리 이름 `md-editor`, 토큰 이름 `CLI · {host}`, 버전 규칙(10.1), 인증 화면 문구(6.3)

### 16.2 가정으로 남긴 것
- **Chrome·Edge·Firefox 가 https 페이지에서 `http://127.0.0.1:{port}` 로의 최상위 이동을 막지 않는다.** `wrangler login` 이 같은 모양(루프백 리디렉션)을 쓰는 것은 확인했지만(측정 (k)), 브라우저의 로컬 네트워크 접근 제한이 최상위 이동에 권한 창을 띄우는지는 확인하지 않았다 → S3
- **Windows PowerShell `Start '{url}'` 가 해시 조각을 버리지 않고 기본 브라우저에 넘긴다.** 브라우저 창을 띄우는 일이라 이 세션에서 실행하지 않았다 → S1
- **Access 로그인 뒤 원래 주소(`/api/login?return=…`, 약 500자)로 돌아온다.** F-205 가 짧은 해시로 쓰는 경로라 길이만 다르다 → S2
- **`@types/node` 를 들이면 루트·worker 타입 검사가 깨질 수 있다**(3.4) — 설치하지 않아 확인하지 못했다. 기본값(손 선언)은 이 가정에 기대지 않는다
- **Node 22 에서 번들이 돈다.** 이 PC 는 Node 24 만 있다. 쓰는 API 는 22 문서 기준으로 있다고 보았다 → B2 를 CI(Node 24)에서, 22 는 사람 확인에 넣지 않았다. 필요하면 `ci.yml` 에 22 행렬을 더한다
- **`@rawdoc` npm 조직이 비어 있는지** 모른다(Q2 의 대안에만 영향)
- Windows `%APPDATA%` ACL 이 본인 전용이라는 것은 **이 PC 에서만** 확인했다(측정 (h))
