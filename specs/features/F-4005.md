## 2. 마이그레이션 `0025_access_requests.sql` (계약)
```sql
CREATE TABLE access_requests (
  id TEXT PRIMARY KEY,                    -- UUID. 알림함 행 id 와 같다 (F-3020)
  target_type TEXT NOT NULL CHECK (target_type IN ('doc','folder')),
  target_id TEXT NOT NULL,
  owner_id TEXT NOT NULL REFERENCES users(id),
  token TEXT NOT NULL,                    -- 요청을 만든 링크
  requester_id TEXT NOT NULL REFERENCES users(id),
  requester_email TEXT NOT NULL,          -- 소문자. 승인 때 초대 이메일
  requester_name TEXT NOT NULL,           -- 요청 때 users.name, 100자에서 자름
  role TEXT NOT NULL CHECK (role IN ('view','edit')),
  status TEXT NOT NULL CHECK (status IN ('pending','rejected')),
  created_at INTEGER NOT NULL,
  decided_at INTEGER,
  CHECK ((status = 'pending') = (decided_at IS NULL)),
  UNIQUE (target_type, target_id, requester_id)
);
CREATE INDEX access_requests_owner ON access_requests(owner_id, status, created_at DESC);
CREATE INDEX access_requests_requester ON access_requests(requester_id, status);
CREATE INDEX access_requests_token ON access_requests(token);
```
같은 파일에서 `notifications` 를 0021 과 같은 순서로 다시 만든다. 바뀌는 것은 둘: `kind IN (…,'share','access_request')`, CHECK 의 `CASE WHEN kind = 'share'` → `CASE WHEN kind IN ('share','access_request')`. 14열 그대로 옮기고 색인 셋을 같은 정의로. 원격 D1 에 코드보다 먼저(옛 코드는 새 표에서 그대로 돈다 — 0021 6장과 같은 이유)

## 3. `src/lib/accessRequest.ts` (계약)
```ts
export const ACCESS_REQUEST_PENDING_MAX = 20                  // 요청자 한 명의 대기
export const ACCESS_REQUEST_OWNER_PENDING_MAX = 100           // 소유자 한 명이 받은 대기
export const ACCESS_REQUEST_COOLDOWN_MS = 7 * 24 * 3_600_000  // 거절 뒤 다시 요청까지
export const ACCESS_REQUEST_EXPIRE_MS = 30 * 24 * 3_600_000   // 대기 수명 (F-4006 Cron)
export type AccessRole = 'view' | 'edit'
export type AccessRequestStatus = {
  target: 'doc' | 'folder'
  owner: boolean                      // 링크 주인 본인
  memberRole: AccessRole | null       // 지금 권한. owner 면 null
  targetId: string | null             // owner 이거나 memberRole 이 있을 때만
  request: { state: 'pending' | 'rejected'; role: AccessRole; retryAt: number | null } | null  // retryAt 은 rejected 만
}
export type AccessRequestRow = { id: string; targetType: 'doc' | 'folder'; targetId: string; targetName: string; email: string; name: string; role: AccessRole; createdAt: number }
```

## 4. 라우트
| 메서드·경로 | 성공 | 실패 |
| --- | --- | --- |
| `GET /api/access-requests/link/:token?docId=` | 200 `AccessRequestStatus` | 401, 404 `not_found` |
| `POST /api/access-requests/link/:token` 본문 `{ role, docId? }` | 201 새 대기 / 200 이미 대기(권한만 바뀜) — 본문은 `AccessRequestStatus` | 400 `invalid`+`field`, 404, 409 `owner`·`already_member`·`cooldown`(+`retryAt`)·`too_many_pending`·`owner_full` |
| `DELETE /api/access-requests/link/:token?docId=` | 204 대기 지움 | 404 대기 없음 |

- 쓰기 둘은 F-2026 관문을 그대로 탄다(`isWriteRoute` 수정 없음). batch 에 요청자 `dayUsageStatement`. 본문은 `readJsonLimited(MAX_BODY_BYTES)`
- 응답에 소유자 이메일·이름을 넣지 않는다

## 5. 판정
- **대상 찾기**(셋 공통): `isValidToken` → `findPublicLink`(막힌 소유자는 없는 링크). 폴더 링크 → 그 폴더, `docId` 무시. 문서 링크 → `docId` 가 없거나 시작 문서면 시작 문서, 아니면 `share_link_docs` 에 (토큰, `docId`) 가 있어야 한다. 대상 행이 링크 주인 것이고 금고 아님(`docs.e2ee_key IS NULL`, `folders.e2ee` 가 1 아님). 하나라도 아니면 404
- **지금 권한**: 문서는 `resolveDocAccess`(요청자 `{ id, email }`), 폴더는 `FOLDER_CHAIN_SQL` 사슬의 `grants` 중 높은 것
- **만들기 순서**: 주인 → `owner` / `roleAtLeast(지금, 요청)` → `already_member` / 같은 대상 행이 대기면 `role` 만 고쳐 200 / 거절이고 `decided_at + COOLDOWN > now` → `cooldown`(`retryAt = decided_at + COOLDOWN`) / 거절이고 지났으면 그 행을 지우고 새 id 로 / 요청자 대기 ≥ 20 → `too_many_pending` / 소유자 대기 ≥ 100 → `owner_full` / 넣기. 대기 수는 살아 있는 행만 센다
- **취소**: 요청자의 대기 행을 `accessRequestDeleteStatements` 로. 거절 행은 지우지 않는다(쿨다운 유지)
- `LIVE_REQUEST_SQL`(요청 행 별칭 `r`): 같은 `token` 링크가 `revoked_at IS NULL`·같은 `owner_id` 이고, 대상이 링크 대상이거나 (문서) 그 링크 `share_link_docs` 안 + 대상 행이 같은 소유자에 있고 금고 아님. 막힘은 보지 않는다(풀리면 돌아온다). 상태·대기 수·F-4006 목록·승인·Cron 이 이 조각 하나를 쓴다
- `accessRequestDeleteStatements(db, where, binds)` → 문장 셋: `notifRevBeforeDeleteSql` 로 받는 사람 리비전 → `DELETE FROM notifications WHERE kind = 'access_request' AND id IN (SELECT id FROM access_requests WHERE {where})` → `DELETE FROM access_requests WHERE {where}`. F-4006 이 모든 지우는 자리에서 부른다
