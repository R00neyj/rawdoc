- 저장 대기 중인 입력이 있어도 복사·공유는 현재 에디터 원문을 쓴다 (`editorRef.current.getText(lineEnding)`)

## 3. 공유 링크

### 3.1 형식
- `{location.origin}{location.pathname}#/s/{조각}`
- 조각 = base64url(패딩 없음)( deflate-raw( UTF-8( JSON ) ) )
  - JSON: `{"v":1,"t":제목,"c":본문(LF 로 이은 원문),"e":"crlf"|"lf"}`
  - 압축: `new CompressionStream('deflate-raw')` / 해제 `DecompressionStream('deflate-raw')`
- URL 해시(`#` 뒤)는 브라우저가 서버 요청에 넣지 않는다 (RFC 3986 3.5, fragment). 그래도 링크를 붙여 넣은 메신저·메일에는 내용이 남으므로 알림 문구에 밝힌다

### 3.2 길이
- 링크 전체 길이가 **8,000자 초과**면 복사는 하고 알림을 warn 으로: `링크가 깁니다(약 {N}KB). 일부 메신저에서 잘릴 수 있어 파일로 공유를 권장합니다.` — 8,000 은 보수적으로 잡은 값이고, 메신저별 한도는 확인하지 않았다
- **2,000,000자 초과**면 복사하지 않고 error 알림 `문서가 너무 커서 링크로 공유할 수 없습니다. 파일로 공유하세요.` — Chromium 의 URL 최대 길이 2MB(`url::kMaxURLChars`)에 맞춘 값이다

### 3.3 `shareCodec.js`
- `encodeShare({ title, content, lineEnding }) → Promise<string>` — `content` 는 줄 구분이 `lineEnding` 인 원문. JSON `c` 에는 LF 로 바꿔 넣는다
- `decodeShare(fragment) → Promise<{ title, content, lineEnding }>` — `content` 는 `lineEnding` 으로 되돌린 원문. 형식이 틀리거나 `v !== 1` 이면 reject
- 왕복 후 바이트가 같아야 한다 (한글·이모지·CRLF·빈 문서)

## 4. 공유 링크로 열기 (S-share)

- 해시가 `#/s/{조각}` 이면 저장소에서 문서를 찾지 않고 `decodeShare` 결과를 공유 화면으로 보여준다
- 화면: 사이드바는 그대로(내 문서 목록), 편집 영역 자리에
  - 알림 띠(info, 닫기 없음): `공유받은 문서입니다. 아직 내 문서에 저장되지 않았습니다.` + 버튼 `내 문서로 가져오기` `닫기`
  - 제목(읽기 전용) + F-123 `Viewer` 로 렌더한 본문
  - 상단바 모드 세그먼트·`공유`·`.md 내보내기` 는 비활성
- `내 문서로 가져오기`: `store.create({ title, content, lineEnding, folderId: null })` → 그 문서를 편집 모드로 열고 해시 `#/d/{id}` (히스토리 교체). info 알림 `내 문서로 가져왔습니다.`. 같은 링크를 다시 가져오면 문서가 하나 더 생긴다 (중복 검사 없음)
- `닫기`: 마지막으로 연 문서(`md.lastDocId`) 또는 빈 상태로
- 사이드바에서 다른 문서를 누르면 공유 화면을 떠난다 (가져오지 않음)
- 해석 실패: error 알림 `공유 링크를 읽을 수 없습니다. 주소가 잘렸는지 확인하세요.` 후 일반 첫 화면
- 공유 화면의 위키링크(F-131)는 링크로 만들지 않는다 (받는 사람 저장소와 무관하므로)
- 오프라인에서도 열린다 (서버 요청 없음)
