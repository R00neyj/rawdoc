## 3. 요구사항

### 3.1 대상 판정

| 상태 | 대상 | 코드에서의 판정 |
| --- | --- | --- |
| 로그인하지 않음 | 이 브라우저(IndexedDB)의 문서·폴더·첨부 전부 | `store.kind !== 'server'` |
| 로그인함 | **내가 소유한** 문서·폴더·첨부 | `store.kind === 'server'` |
| 로그인 + 오프라인 | 내보내기 막음 | `store.kind === 'server' && syncState.online === false` |

- **내 소유 문서**: `store.list()` 결과에서 `doc.role` 이 `'owner'` 이거나 **없는**(`undefined`) 것만. 공유받은 문서는 `role` 이 `'edit'`·`'view'` 다 (`src/types.ts`, `serverStore.list()` 가 내 문서에 `role: 'owner'` 를 붙이고 공유받은 것은 `api.getShared()` 로 따로 이어 붙인다). 로컬 저장소(`idb`·`memory`)는 `role` 자체가 없으므로 `undefined` 를 포함해야 전부 나온다
- **폴더**: `store.listFolders()` 는 서버 저장소에서도 내 폴더만 돌려준다(공유받은 폴더는 목록에 없고 문서의 `viaFolder` 로만 온다). 따로 거르지 않는다
- **오프라인**: `store.subscribeSync` 로 받는 `SyncState.online`(`src/app/App.tsx` 의 `syncState`). 버튼을 `disabled` 로 두고 버튼 옆에 안내 `온라인일 때 내보낼 수 있습니다` 를 적는다. 근거는 F-277 2.1 — 서버 첨부는 캐시에 없을 수 있고 `serverStore.getAttachment` 가 오프라인에서 `null` 을 돌려준다
- **폴더 내보내기 범위**: `descendantFolderIds(folders, folderId)`(`src/lib/folderTree.ts`, 자신 포함)에 속한 폴더와 그 폴더들에 속한 문서만
- 시작 전에 저장 대기 중인 입력을 **기다린다** — `await saver.flush()`. 저장소 값을 읽어 내보내므로 지금 열린 문서의 마지막 입력이 빠지면 안 된다 (문서 한 개 내보내기는 에디터 원문을 직접 읽어 기다리지 않는다 — F-112 2.2. 여기는 다르다)

### 3.2 zip 모양과 이름 규칙

```
{날짜}-export.zip              (폴더 단위는 {폴더 이름}.zip)
├─ manifest.json
├─ attachments/{id}.{ext}      ← 맨 위 문서가 쓰는 이미지만
├─ {문서}.md
└─ {폴더}/
    ├─ attachments/{id}.{ext}  ← 이 폴더 문서가 쓰는 이미지만
    ├─ {문서}.md
    └─ {하위 폴더}/…
```

- zip 파일명: 전체는 `{YYYY-MM-DD}-export.zip`(로컬 시간). 폴더 단위는 `{toFolderName(폴더 이름)}.zip`
- 폴더 단위 zip 은 **그 폴더가 곧 zip 루트**다. 그 폴더 자신의 이름은 zip 안 경로에 나타나지 않는다(zip 파일명이 대신한다)
- zip 파일명·폴더명·문서 파일명 어디에도 제품명을 넣지 않는다 (F-277 2.2)
- 문서 파일명 `toFileName(doc.title)`, 폴더 디렉터리 이름 `toFolderName(folder.name)`
  - `toFolderName` 은 `toFileName` 과 같은 규칙(금지 문자·제어 문자 `_`, 앞뒤 공백·끝 `.` 제거, 빈 이름은 `제목 없는 문서`, Windows 예약 이름 뒤 `_`, 100 코드포인트 자르기)에서 **`.md` 만 붙이지 않는다**
  - 폴더 기본 이름이 비면 `제목 없는 문서` 가 되는 것이 어색하지만, 규칙을 하나로 유지한다(빈 폴더 이름은 `createFolder` 가 `새 폴더` 로 채워 실제로는 나오지 않는다)

이름 충돌:

- 같은 디렉터리 안에서 **폴더끼리**, **문서끼리** 각각 본다. 폴더 `가` 와 문서 `가.md` 는 충돌이 아니다
- 비교는 **대소문자를 구분하지 않는다** (Windows·macOS 파일 시스템이 구분하지 않아 푼 뒤 덮어써진다)
- 훑는 순서는 `createdAt` 오름차순, 같으면 `id` 사전순. 먼저 나온 것이 원래 이름을 갖고, 다음부터 `이름 (2).md`, `이름 (3).md` … (폴더는 `이름 (2)`)
- 예약어: 폴더 디렉터리 이름이 `attachments`(대소문자 무시)가 되면 `attachments (2)` 로 민다. 생성하는 `attachments/` 와 섞이지 않게
- 원래 제목·폴더 이름은 `manifest.json` 에 그대로 남는다

`.md` 바이트:

- `doc.content` 를 `fromEditorText(content, doc.lineEnding)`(`src/lib/lineEnding.ts`)로 이은 뒤 UTF-8 로 인코딩한다. BOM 을 붙이지 않는다 — 문서 한 개 `.md` 내보내기와 같은 바이트다 (F-112 2.2)
- 문서가 없는 빈 폴더는 zip 에 디렉터리 항목이 생기지 않는다. `manifest.folders` 에는 남으므로 F-282 가 다시 만들 수 있다

### 3.3 이미지

- 문서 원문에서 `extractAttachmentRefs(content)`(`src/lib/imageBlock.ts`)로 첨부 id 를 모은다. 원문의 `src` 는 `attachments/{id}.{ext}` 라는 **상대 경로**라, 그 문서가 놓인 디렉터리에 `attachments/` 를 같이 넣으면 원문을 고치지 않아도 경로가 맞는다 (원문 보존 불변조건)
- **폴더(= zip 디렉터리)마다** 그 폴더 문서가 쓰는 첨부만 `{폴더 경로}/attachments/{id}.{ext}` 로 넣는다. 같은 이미지가 여러 폴더에 중복해 들어갈 수 있다 (F-277 2.2, 사용자 결정)
- 같은 폴더 안에서 여러 문서가 같은 id 를 쓰면 한 번만 넣는다
- 확장자는 저장소 레코드의 `record.ext` 를 쓴다 (F-158 2.3 과 같다)
- `store.getAttachment(id)` 가 `null` 이면 그 이미지는 빼고 **서로 다른 id 개수**를 센다(폴더마다 중복해 세지 않는다). 0보다 크면 끝난 뒤 `warn` 알림 `이미지 {N}개를 찾을 수 없어 빼고 내보냈습니다.` (F-158 2.3 과 같은 문구)
- 서버 저장소에서는 캐시에 없는 첨부를 `getAttachment` 가 서버에서 받아 온다. 오프라인이면 전부 `null` 이 되므로 3.1 에서 미리 막는다
- 첨부 총량은 계정 300MB 가 상한이다 (F-221 2.1). 로그인하지 않은 IndexedDB 에는 상한이 없다

### 3.4 `manifest.json` (형식 확정)

루트에 `manifest.json` 한 개. UTF-8, BOM 없음, 들여쓰기 2칸

```json
{
  "format": 1,
  "exportedAt": 1789000000000,
  "scope": "all",
  "rootFolderId": null,
  "folders": [
    { "id": "f1", "name": "교안", "parentId": null, "path": "교안" }
  ],
  "docs": [
    {
      "id": "d1",
      "path": "교안/1주차.md",
      "title": "1주차",
      "folderId": "f1",
      "lineEnding": "crlf",
      "createdAt": 1788000000000,
      "updatedAt": 1789000000000,
      "pinnedAt": null
    }
  ]
}
```

최상위:

| 필드 | 타입 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `format` | number | 예 | 형식 판. 지금은 `1`. 모르는 값이면 F-282 가 가져오기를 거부한다 |
| `exportedAt` | number | 예 | 만든 시각, epoch 밀리초 |
| `scope` | `"all"` \| `"folder"` | 예 | 전체 내보내기인지 폴더 내보내기인지 |
| `rootFolderId` | string \| null | 예 | `scope: "folder"` 면 zip 루트가 된 폴더 id, 아니면 `null` |
| `folders` | 배열 | 예 | 아래. 빈 배열 가능 |
| `docs` | 배열 | 예 | 아래. 빈 배열 가능 |

`folders[]`:

| 필드 | 타입 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `id` | string | 예 | 저장소 폴더 id 그대로 |
| `name` | string | 예 | 사용자가 지은 원래 이름(파일 이름 규칙 적용 전) |
| `parentId` | string \| null | 예 | 저장소 값 그대로. `scope: "folder"` 에서는 **이 목록에 없는 id**(= `rootFolderId`)를 가리킬 수 있다 |
| `path` | string | 예 | zip 안 디렉터리 경로. 구분자는 `/`, 앞뒤 `/` 없음 |

`docs[]`:

| 필드 | 타입 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `id` | string | 예 | 저장소 문서 id 그대로 |
| `path` | string | 예 | zip 안 `.md` 경로. **zip 항목 이름과 글자가 같아야 한다** |
| `title` | string | 예 | 원래 제목(파일 이름 규칙 적용 전) |
| `folderId` | string \| null | 예 | 저장소 값 그대로. `folders[].parentId` 와 같은 단서가 적용된다 |
| `lineEnding` | `"crlf"` \| `"lf"` | 예 | `.md` 바이트를 이은 방식 |
| `createdAt` | number | 예 | epoch 밀리초 |
| `updatedAt` | number | 예 | epoch 밀리초. F-282 의 갱신 판정에 쓴다 |
| `pinnedAt` | number \| null | 예 | 고정 시각. 안 고정했으면 `null` |

- **첨부 목록은 두지 않는다.** 원문의 `attachments/{id}.{ext}` 참조가 원본이다 (F-277 2.3)
- `folders` 는 부모가 자식보다 먼저 오도록 정렬한다(F-282 가 순서대로 만들 수 있게). `docs` 는 `path` 사전순
- 미래에 필드를 더해도 `format` 은 그대로 둔다 — **모르는 필드는 무시**가 읽는 쪽 규칙이다. `format` 은 기존 필드의 뜻이 바뀔 때만 올린다

### 3.5 스트리밍 zip (조사 결과)

설치된 `fflate` **0.8.3** 에는 스트리밍 zip API 가 있다: `Zip`(출력 콜백), `ZipPassThrough`(무압축 입력 스트림), `ZipDeflate`/`AsyncZipDeflate`(압축 입력 스트림). `node_modules/fflate/lib/index.d.ts` 1187~1310줄

실제로 돌려 확인한 것(2026-09-20, Node 24, 프로젝트의 `fflate` 0.8.3):

- 항목마다 `new ZipPassThrough(경로)` → `zip.add(f)` → `f.push(바이트, true)` 로 넣고 마지막에 `zip.end()` 하면, **항목을 넣을 때마다 출력 콜백이 곧바로 불린다.** 1MB 항목 3개를 넣자 파일마다 약 1,048,630바이트씩 누적됐고 `end()` 에서 184바이트(중앙 디렉터리)만 더 나왔다
- 한글 경로·`폴더/attachments/{id}.png` 같은 중첩 경로가 그대로 들어가고, `unzipSync` 로 풀면 바이트가 같다. CRLF `.md` 도 그대로다
- 즉 **입력 쪽은 메모리에 한 번에 올리지 않아도 된다.** 문서·첨부를 하나씩 저장소에서 읽어 넣고 바로 버리면 된다

출력 쪽 — 만들어진 zip 바이트를 어디에 모으는가:

- **이 명세의 방식**: 콜백이 주는 조각을 배열에 모았다가 끝에서 `new Blob(chunks, { type: 'application/zip' })` → `URL.createObjectURL` → 임시 `<a download>` 클릭 (기존 내보내기와 같은 흐름). `zipSync` 와 달리 **연속된 큰 `Uint8Array` 를 한 번에 잡지 않고**, 브라우저가 Blob 을 자체적으로 관리(구현에 따라 디스크로 넘길 수 있다)한다. 정확한 한계는 브라우저마다 달라 보장 값을 적지 않는다
- 하지 않는 것: `showSaveFilePicker()` + `FileSystemWritableFileStream` 으로 디스크에 바로 쓰기. 진짜 스트리밍이지만 Chromium 계열에만 있고 저장 대화상자가 떠서 다른 내보내기와 동작이 달라진다. 4장 미결로 올린다
- 크기 한계의 현실적 상한: 로그인 계정은 첨부 300MB(F-221) + 문서(서버 문서 1개 1MB 상한). 로그인하지 않은 IndexedDB 는 상한이 없어 그보다 커질 수 있다 — 사람 확인 항목(5장)

압축 수준: **모든 항목을 `ZipPassThrough`(저장, 압축 안 함)로 넣는다.** 근거 — 용량의 대부분이 이미 압축된 이미지고(F-158 2.3 이 같은 이유로 `level: 0`), `ZipDeflate` 는 동기라 문서가 많으면 화면이 멈춘다. `AsyncZipDeflate` 는 워커를 띄워 오프라인·번들 전제를 건드린다

넣는 순서: `manifest.json` → 루트의 `.md` → 루트 `attachments/` → 폴더별로 같은 순서. 항목 하나를 `push(..., true)` 로 끝낸 뒤 다음 항목을 `add` 한다

### 3.6 화면 — 설정 대화상자 `데이터` 절

- `SettingsDialog` 맨 아래(`닫기` 위)에 `.dialog-field` 한 줄을 더한다. 라벨 `데이터`, 컨트롤은 버튼 `전체 내보내기`
- `onExportAll`(함수)이 주어질 때만 그린다. 공개 보기 화면(`PublicView.tsx`)은 주지 않으므로 절이 나오지 않는다 (F-230·F-232 의 다른 선택 항목과 같은 방식)
- 오프라인(3.1)이면 버튼이 `disabled` 이고, 같은 줄에 안내 `온라인일 때 내보낼 수 있습니다` 를 `--muted` 색 작은 글씨로 둔다
- 내보내는 동안 버튼은 `disabled`. 대화상자는 닫을 수 있고, 닫아도 내보내기는 이어진다
- `가져오기…` 자리는 이번에 만들지 않는다 (F-282)

### 3.7 화면 — 폴더 메뉴 `폴더 내보내기`

- `Sidebar.tsx` 의 폴더 행(`FolderRow`) `ownItems` 에서 `이름 변경` 다음, `삭제` 앞에 넣는다. 아이콘 `IconDownload`(이미 있다), `danger` 아님
- 여러 항목을 고른 상태의 메뉴(`multiMenuItems`)에는 넣지 않는다 — 이번 범위가 아니다
- 우클릭 메뉴도 같은 `items` 를 쓰므로 자동으로 함께 나온다 (F-255 3.2)
- 오프라인이면 항목을 **숨기지 않고** 눌렀을 때 `error` 알림 `온라인일 때 내보낼 수 있습니다` 를 낸다 — 메뉴 항목은 `disabled` 상태를 표현할 구조가 없다(`FolderMenuItem` 에 그 필드가 없고, 이 명세에서 메뉴 구조를 바꾸지 않는다)
- 공유받은 폴더에는 `⋯` 메뉴 자체가 없다 (`SharedDocRow`) — 따로 막을 것이 없다

### 3.8 진행 표시·알림·실패

- 진행: 문서 하나를 zip 에 넣을 때마다 `onProgress({ done, total })` 를 부른다. `total` 은 대상 문서 수. App 은 이 값을 알림 띠 `info` `내보내는 중… {done}/{total}` 로 갱신한다. `info` 는 앞선 `info` 를 대체하므로 띠가 쌓이지 않는다 (`src/app/notice.ts`). 새 진행 UI 를 만들지 않는다
- 끝: 다운로드가 시작된 뒤 `info` `문서 {N}개를 내보냈습니다.` 빠진 이미지가 있으면 그 뒤에 3.3 의 `warn` 을 낸다(`warn` 이 `info` 를 대체한다)
- 대상이 0개(문서도 폴더도 없음): zip 을 만들지 않고 `info` `내보낼 문서가 없습니다.`
- 목록 읽기 실패(`store.list()`·`listFolders()` 가 던짐): 시작하지 않고 `error` `내보내지 못했습니다. 연결을 확인하세요.`
- 첨부 하나 실패: 건너뛰고 계속한다 (3.3 의 개수에 들어간다)
- zip 만들기·다운로드 자체가 실패: 부분 파일을 내려받지 않고 `error` `내보내지 못했습니다.`
- 내보내는 동안 문서를 계속 편집할 수 있다. 시작 시점에 읽은 값으로 내보낸다(도중 변경은 반영하지 않는다)
