# F-4012 첨부↔문서 연결 기록으로 첨부 IDOR 막기

상태: 승인 — 사용자 상시 지시(9장 Q1~Q3 기본값대로, 별도 검토 없음). 코드리뷰 발견 — 공격자 A 가 피해자 V 의 첨부 id 를 알면 자기 문서에 `attachments/{id}.png` 를 쓰고 V 를 edit 초대(동의 불필요, `grants.ts` `applyGrant`)해 `isDocAttachmentOwner` 를 통과시켜 V 의 R2 객체를 `?doc=`·공개 링크·폴더 링크·묶음 링크·MCP `fetch_image` 로 얻는다. 방식은 사용자 결정("첨부↔문서 연결 기록, 초대만으로는 인정 안 함"). 전부 node 단위, e2e 없음(브라우저만 보이는 동작이 없다)

## 근거 (2026-10-19 HEAD, 이름으로 찾는다)
- 판정 네 곳: `findDocAttachment`(`?doc=`·`/pub/docs/:token`·MCP `fetch_image` 가 부름), `handlePublicGetDocSetAttachment`·`handlePublicGetFolderAttachment` 안 같은 반복의 복사본 둘. 후보는 `id`·`ext` 로만 고르고 주인은 `isDocAttachmentOwner` 가 본다 — `github_images` 의 `owner_id` 도 판정에 안 쓰인다
- 올리기 경로가 받는 문서 id: 앱 `uploadAttachment`(`PUT /api/attachments/:idext`)·보낼 목록 `{ type: 'upload' }` 항목 모두 **없음**. `attachImages` 를 부르는 `useImportFlow` 는 `currentDoc` 을 안다. CLI `upload`(`POST /v1/attachments`) 없음. MCP 는 올리기 도구가 없다. GitHub 그림은 `openOwnedLink` 가 문서 주인만 받아 올린 사람 = 문서 주인. 금고·작업공간 가져오기·로그인 이관·충돌 사본은 모두 `INSERT INTO docs … owner_id = user.id` 로 **자기 문서**를 만든다 → 이 넷은 주인 경로라 기록이 필요 없다
- 문서 복제 기능은 없다. 문서 소유자를 바꾸는 `UPDATE` 도 없다(소유자는 영구). `grants` upsert 는 역할만 바꾸고 `created_at` 을 그대로 둔다. 다음 마이그레이션 번호 0029

## 2. 표 (계약)
```sql
CREATE TABLE IF NOT EXISTS attachment_docs (
  owner_id TEXT NOT NULL,       -- 올린 사람 = attachments.owner_id
  attachment_id TEXT NOT NULL,
  doc_owner_id TEXT NOT NULL,   -- 넣은 문서의 소유자. 판정은 이 열로 한다
  doc_id TEXT NOT NULL,         -- 처음 넣은 문서(기록용, 판정에 안 씀)
  created_at INTEGER NOT NULL,
  PRIMARY KEY (owner_id, attachment_id, doc_owner_id)
);
CREATE INDEX IF NOT EXISTS attachment_docs_doc_owner ON attachment_docs(doc_owner_id);
```
- 뜻: "U 가 자기 첨부 X 를 O 의 문서에 직접 넣었다" = U 가 X 를 O 에게 내줬다. 판정을 문서가 아니라 **소유자 단위**로 하는 이유 — O 는 이미 X 를 받아 볼 수 있어 O 의 다른 문서(충돌 사본, O 문서 사이 잘라 붙이기, 공동 편집자가 O 의 문서 사이로 옮긴 문단)에 보여도 O 가 새로 얻는 것이 없다(O 가 내려받아 다시 올리는 것과 같다). 소유자가 영구라 행이 낡지 않는다
- 문서 삭제·휴지통은 행을 지우지 않는다(같은 O 의 다른 문서가 쓸 수 있다). 지우는 때: 그 첨부 행을 지울 때(`handleDeleteAttachment` batch, `attachmentGc` 삭제 직후, 같은 id 재사용으로 옛 연결이 새 그림에 붙지 않게), 계정 삭제(양쪽)

## 3. 동작
### 3.1 서버
- **판정 하나**: `findDocAttachment(env, doc: { id; owner_id; content }, id, ext): Promise<AttachmentRow | null>` — `isDocAttachmentRef` 가 참일 때, `e2ee = 0` 이고 `owner_id = doc.owner_id` 이거나 `attachment_docs` 에 `(그 owner_id, id, doc.owner_id)` 행이 있는 후보를 **한 질의**로, 문서 소유자 것 먼저. 공개 핸들러 둘도 이것만 부른다. MCP 는 이미 이 함수를 불러 코드가 그대로다
- 편집 권한이 나중에 끊겨도 연결은 남는다 — 지금은 초대를 지우면 공동 편집자 그림이 그 문서에서 깨졌는데, 이제는 남는다(올린 사람이 내준 것). 거두려면 올린 사람이 첨부를 지운다(F-402 3.3 `in_use` 판정은 그대로)
- **기록**: `PUT /api/attachments/:idext?doc={id}`·`POST /v1/attachments?doc={id}` 에서 평문(`e2ee` 없음)일 때만. `getDocAccess(doc)` 의 role 이 정확히 `edit`(막힘으로 낮아진 `view` 제외)면 `INSERT … ON CONFLICT DO NOTHING` 을 첨부 `INSERT` 와 **같은 batch** 에(`storeAttachment` 가 선택 인자로 받는다). 이미 있는 행(200 갈래)이면 따로 한 문장. `owner`·권한 없음·없는 문서·금고 → 기록 없이 **올리기는 지금과 같은 응답**(보낼 목록이 초대 취소 때문에 막히지 않게). 문서를 먼저 읽고 본문을 읽는다
### 3.2 앱
- `uploadAttachment(id, ext, blob, e2ee?, docId?)`: `e2ee` 가 없고 `docId` 가 있으면 `?doc={encodeURIComponent(docId)}`. `Store.putAttachment` 입력과 보낼 목록 `upload` 항목에 `docId?: string`(없으면 키를 넣지 않는다), 보낼 때 그대로 넘긴다
- `attachImages` 옵션 `docId?`, `useImportFlow` 가 `currentDoc?.id`. 내 문서여도 보낸다(서버가 무시). 로컬 저장소·`putAttachmentNow`(금고)·가져오기·GitHub 는 바꾸지 않는다
### 3.3 CLI
`rawdoc upload <파일> [--doc <id>]` → `POST /v1/attachments?doc=`. 개요 문구 `'이미지를 올리고 붙일 마크다운을 출력합니다 (공유받은 문서에 넣으면 --doc <그 문서 id>)'`

## 4. 백필 (0029 안, 그리고 배포 14일 뒤 같은 파일 한 번 더)
`(U, X, O)` 한 행을 넣는 조건 — 모두 참일 때: ① `attachments` 행 X(주인 U)가 `e2ee = 0` ② O 의 평문 문서 d(`e2ee_key IS NULL`, 휴지통 포함, `d.owner_id ≠ U`) 본문에 `instr(content, 'attachments/' || X || '.') > 0` ③ `grants` 에 `owner_id = O`, `grantee_email` = U 의 `users.email`, `role = 'edit'`, 대상이 d 이거나 d 의 폴더·상위 폴더(`FOLDER_CHAIN_SQL` 과 같은 사슬)인 행이 있고 그 `created_at ≤ X.created_at` ④ `d.created_at ≤ X.created_at`. `doc_id` = 만족하는 d 중 가장 작은 id, `created_at` = X 의 것
- ③④ 가 이유: 정상 흐름은 "초대받은 뒤, 있던 문서에 올린다". 공격은 X 가 생긴 **뒤에** 초대하므로 이미 저질러진 공격도 이어받지 않는다
- 받아들이는 손실: 초대 전에 올린 자기 그림을 나중에 남의 문서에 붙인 경우는 기록되지 않아 다른 사람에게 깨진다(편집기에서 다시 넣으면 된다). 옛 `view` 초대를 X 뒤에 `edit` 로 올린 경우는 `created_at` 이 옛 값이라 들어간다
- 14일 뒤 재실행 이유: 프롬프트 갱신(`registerType: 'prompt'`)이라 옛 앱 탭이 한동안 `?doc=` 없이 올린다. 같은 규칙으로 그 사이 정상 업로드를 줍는다

## 9. 열린 질문
- **Q1 판정 단위 — 기본: 문서 소유자.** 다른 안 "기록된 문서 id 만": 충돌 사본·O 문서 사이 옮긴 공동 편집자 그림이 깨진다. 고르면 PK 를 `(owner_id, attachment_id, doc_id)` 로, 판정을 `doc_id = doc.id` 로, 백필을 문서마다로 바꾼다
- **Q2 소유자가 다른 문서로 붙여 넣은 내 그림 — 기본: 연결하지 않음**(다시 넣어야 남에게 보인다). 다른 안 "붙여넣기 때 글 속 내 첨부 id 를 그 문서에 연결": V 가 A 의 문서에서 A 가 심은 `attachments/{V 의 id}` 문단을 A 의 다른 문서로 옮기기만 해도 연결돼 이 명세가 막는 유출이 다시 열린다. 고르면 `imageInsert.ts` 붙여넣기 콜백·연결 라우트·보낼 목록 항목이 늘고 `src/editor/**` 가 소유 표에 든다
- **Q3 백필 — 기본: 4장 시각 조건.** 다른 안 "지금 통과하는 조합 전부": 깨지는 그림은 0 이지만 배포 전 이미 저지른 공격도 영구 허용된다
