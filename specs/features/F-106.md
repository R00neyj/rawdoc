## 2. 요구사항

### 2.1 옮겨 오는 것 (spike `blocks.js`)
- `StateField` 로 제공 (CM6 는 블록 decoration 을 ViewPlugin 에서 받지 않는다 — spike 229~232행)
- `Table` → 표 위젯, `FencedCode` → 코드블록 위젯. 범위는 줄 경계로 확장
- 선택이 블록 범위와 겹치면 위젯을 씌우지 않는다 (원문 노출)
- 위젯 `eq()` 는 원문 내용만 비교. 위치를 넣지 않는다
- `atomicRanges` 를 쓰지 않는다
- 조합 중 보류 + `forceRecalc` 따라잡기는 `src/editor/composition.js` 사용. 보류 중 문서가 바뀌면 `value.map(tr.changes)`
- 표 셀 안 인라인 프리뷰 없음, 코드블록 구문 강조 없음
- 계산 함수 `buildBlocks(state)` 를 분리해 DOM 없이 테스트한다

### 2.2 방향키 보조와 `lineWrapping`
- spike 의 판정("`moveVertically` 결과가 논리 줄 번호로 2 이상 떨어지면 바로 옆 줄로 보냄")은 **논리 줄 번호**를 비교하므로 자동 줄바꿈으로 한 줄이 여러 시각 줄이 되어도 같은 줄 안 이동(차이 0)과 옆 줄 이동(차이 1)은 개입하지 않는다
- verify.md 4장 결함 1("lineWrapping 을 켜면 판정이 무너진다")은 lineWrapping 을 켜지 않은 상태에서 적은 추정이다(같은 문단: "현재 켜지 않았다"). 이 명세는 spike 판정을 유지하고 **lineWrapping 을 켠 상태에서 실측**한다 (3장 A3)
- 실측에서 깨지면 `view.moveVertically` 결과 대신 "현재 줄의 마지막(첫) 시각 줄인가"를 `view.coordsAtPos`·`view.lineBlockAt` 으로 판정하는 방식으로 바꾸고, 그 사실을 보고한다
- 선택 영역이 있으면 개입하지 않는다 (Shift+방향키)
- keymap 은 `Prec.highest`

### 2.3 클릭 진입 (verify.md 결함 2 개선)
- 코드블록 클릭: 블록 시작이 아니라 클릭한 줄로 진입한다. 위젯이 `CodeText` 의 줄 시작 오프셋(블록 시작 기준 상대값)을 들고, 클릭한 `<span>` 줄의 상대 오프셋 + `view.posAtDOM(wrap)` 으로 위치를 구한다
- 표 셀 클릭: 그 셀 원문 시작 위치로 진입. 셀마다 블록 시작 기준 상대 오프셋을 `data-offset` 에 둔다
- `mousedown` 에서 `preventDefault` 후 `dispatch({ selection })` + `focus()` (spike 18~35행)

### 2.4 스타일 (`preview.css`, 토큰만)
- 코드블록: `--font-mono` 13px, 배경 `--rule-2`, 테두리 1px `--rule`, 반경 6px, 정보 문자열(언어)은 오른쪽 위 `--muted` 11px
- 표: 테두리 1px `--rule`, 머리행 배경 `--rule-2` 굵게, 셀 패딩 6px 10px, 가로로 넘치면 위젯 안에서 가로 스크롤

### 2.5 성능 기록 (Q6)
- 단위 테스트 안에서 표 50개·코드블록 50개가 섞인 약 5,000줄 문서로 `buildBlocks` 1회 시간을 측정해 출력한다. 통과 기준은 두지 않는다. 보고에 수치를 적는다
