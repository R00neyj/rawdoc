## 1. 범위

### 한다
- `내보내기` 메뉴에 항목 두 개를 **더한다**: `HTML 파일`, `서식 있는 복사`

- 외부 주소 이미지(`![](https://…)`)를 내려받아 넣는 일 — 보기 모드와 같이 링크로 둔다(4.6 표, F-116)

## 3. 메뉴에 더하는 것

### 3.1 왜 문자열인가 (설계 제약)

`vite.config.ts` 의 `test.environment` 가 `'node'` 이고 `jsdom`·`happy-dom` 이 설치돼 있지 않다. `DOMParser`·`document` 를 쓰면 4장 규칙을 `*.test.ts` 로 판정할 수 없어 `CLAUDE.md` "로직은 TDD" 를 못 지킨다. `F-278` 4.1 이 평문 변환기를 토큰 순회로 정한 것과 같은 이유다

따라서 HTML 만들기는 **`renderMarkdown(text)` 가 낸 HTML 문자열을 문자열로 손보는 것**으로 구현한다. 이 문자열 치환이 안전한 근거:

1. `renderMarkdown` 의 markdown-it 은 `html: false` 다 — 사용자 원문의 `<`·`>` 는 전부 이스케이프된다. `<img data-attachment="…">`·`<div class="md-mermaid" …>` 같은 태그는 **앱 코드가 만든 것뿐**이라 사용자 입력이 치환 대상에 섞일 수 없다(A12 로 판정)
2. 그 두 태그의 모양은 `renderMarkdown.ts` 의 `renderImageBlockHtml`·`fence` 규칙이 한 줄로 고정해 두었다
3. Mermaid 원문은 토큰에서 직접 뽑으므로(3.2) HTML 안의 이스케이프된 문자열을 되돌릴 필요가 없다

DOM 이 필요한 일(첨부 blob 읽기, Mermaid 렌더, 클립보드 쓰기)은 전부 `src/app/exportDoc.ts` 쪽에 두고, 결과를 자료로 받아 순수 함수에 넘긴다

### 3.2 `toHtmlDoc.ts` 공개 API

```ts
export type ExportMermaid = { svg: string } | { error: string }

export type ExportResources = {
  // 첨부 id → data: URI. 저장소에 없으면 키가 없다
  images: Record<string, string>
  // 문서에 나온 순서대로의 Mermaid 결과 (collectMermaidSources 와 같은 순서)
  mermaid: ExportMermaid[]
}

export type ExportPalette = { rule: string; rule2: string; ink: string; ink2: string }

// 원문에서 Mermaid 코드블록 본문을 문서 순서대로 뽑는다 — 호출부가 renderMermaid 로 그린다
export function collectMermaidSources(text: string): string[]

// 보기 모드와 같은 본문 HTML 에 이미지 data: URI·Mermaid SVG 를 채운 것
export function buildExportBody(text: string, res: ExportResources): { html: string; missingImages: number }

// 단독 .html 파일 한 개
export function buildHtmlDocument(args: { title: string; body: string; css: string }): string

// 서식 있는 복사용 — 본문 HTML 의 정해진 태그에 style= 를 박는다 (5.2)
export function toInlineStyledHtml(body: string, palette: ExportPalette): string

// tokens.css 문자열의 첫 :root(화이트 테마)에서 값을 읽는다 (vite.config.ts readTokenColor 와 같은 방식)
export function readPalette(tokensCss: string): ExportPalette
```

- `collectMermaidSources` 는 `parseMarkdownTokens(body)`(F-278 4.2) 를 돌려 `fence` 중 `isMermaidInfo(token.info)` 인 것의 `content` 를 모은다. 입력은 `stripComments`·프론트매터 제거를 **먼저 거친 본문**이어야 하고, 그 전처리는 이 함수가 안에서 한다(`toPlainText` 와 같은 순서)
- `buildExportBody` 의 전처리도 같다: `stripComments(text)` → 프론트매터는 떼지 **않고** `renderMarkdown` 에 그대로 넘긴다. 프론트매터 표는 보기 모드에 보이므로 HTML 에도 남긴다(4.6 표)
- `renderMarkdown` 은 `resolveWikiLink` 없이 부른다 → 위키링크가 클릭 불가능한 `<span class="wikilink wikilink--plain">` 이 된다(F-131 4장, 공유 화면과 같다)

## 4. HTML 파일 (F-277 1.3)

### 4.1 입력 처리 순서

```
handle.getText(lineEnding)              // 에디터 현재 원문 (F-112 2.2)
 → extractAttachmentRefs(text)          // 첨부 id 목록 (F-158)
 → store.getAttachment(id) 마다 blob → data: URI      ← DOM/저장소, exportDoc.ts
 → collectMermaidSources(text) 마다 renderMermaid()   ← DOM, exportDoc.ts
 → buildExportBody(text, { images, mermaid })         ← 순수
 → buildHtmlDocument({ title, body, css: EXPORT_CSS })← 순수
 → downloadBlob(new Blob([...]), '{제목}.html')
```

- 파일명은 `toFileName(title)` 의 `.md` 를 `.html` 로 바꾼 것(`buildPlainPayload` 와 같은 방식)
- 인코딩 UTF-8, **BOM 없음**. 줄바꿈은 문서 `lineEnding` 과 상관없이 **항상 `\n`** — `.html` 은 원문 보존 대상이 아니다(`product.md` 6장의 바이트 보존은 `.md` 만)
- MIME `text/html;charset=utf-8`
- `saver?.flush?.()` 를 부르고 기다리지 않는다(`F-112` 2.2)
- 진행 알림은 띄우지 않는다. 성공 알림도 없다(`ia.md` 3.8 — 브라우저 다운로드 표시로 충분)

### 4.2 이미지를 담는 방식 — `data:` URI 인라인

`F-277` 1.3 이 정한 대로 첨부를 `data:` URI 로 **인라인한다.** 다른 선택지를 버린 근거:

| 안 | 버린 이유 |
| --- | --- |
| 별도 zip(`.html` + `attachments/`) | "파일 하나로 인터넷 없이 열림"(1.3)이 깨진다. 폴더째 보내는 건 이미 F-281 이 한다 |
| 이미지를 빼고 자리 표시만 | 받는 사람에게 그림이 안 간다. `.txt`(F-278)와 구별이 없어진다 |
| 외부 주소로 링크 | 첨부는 로그인·토큰이 있어야 읽히는 R2 객체라 남에게 열리지 않는다 |

- `data:{mime};base64,{…}`. MIME 은 첨부 `ext`(`png`·`jpg`·`gif`·`webp`)에서 고정 표로 만든다 — `blob.type` 은 서버에서 받은 blob 에서 비어 있을 수 있다
- base64 는 `btoa` 로 만든다. 인수 개수 한도에 걸리지 않게 8KB 단위로 끊어 잇는다
- 용량: 한 장 5MB 제한(F-209)은 그대로고, base64 는 바이트가 약 1.33배가 된다. 계정 첨부 한도는 300MB(F-221)라 **한 문서만으로도 수십 MB 가 될 수 있다.** 그래도 자르지 않는다 — 조용히 빠진 그림이 더 나쁘다. 대신 결과 크기가 **20MB** 를 넘으면 `warn` 알림을 띄운다(6장 M3):
  `HTML 파일이 약 {N}MB 입니다. 메일 첨부가 어려울 수 있습니다.`
- 저장소에 없는 첨부는 자리 표시로 바꾸고 개수를 센다. 만드는 마크업은 보기 모드 실패 모양(F-157 2.2)과 같은 클래스를 쓴다:
  `<div class="md-image md-image--{align} md-image-missing" role="img" aria-label="{alt}"><span class="md-image-missing-text">이미지를 찾을 수 없습니다</span></div>`
  아이콘 SVG 는 넣지 않는다(파일 크기·의존 최소화). 개수가 1개 이상이면 `warn` 알림:
  `이미지 {N}개를 찾을 수 없어 자리 표시로 넣었습니다.`

치환 대상 정규식은 `renderImageBlockHtml`(`renderMarkdown.ts` 154~161행)이 내는 한 줄 전체다:

```
<div class="md-image md-image--{align}"{ style="width:{n}px"}><img data-attachment="{id}" alt="{alt}"{ width="{n}"}></div>
```

찾으면 `data-attachment="{id}"` 를 `src="{dataUri}"` 로 바꾸고 나머지(정렬 클래스·`style`·`alt`·`width`)는 그대로 둔다

### 4.3 Mermaid

- `collectMermaidSources` 로 얻은 순서대로 `renderMermaid(source)`(`src/lib/mermaidRender.ts`)를 돌리고 결과 배열을 넘긴다
- `<div class="md-mermaid" data-mermaid-source="…"></div>` 를 문서 순서대로 만나는 대로 갈아 끼운다
  - 성공: `<div class="md-mermaid">{svg}</div>` — mermaid 가 내는 SVG 는 안에 `<style>` 을 품은 자립형이라 그대로 들어간다
  - 실패: `<div class="md-mermaid-error">{메시지}</div>` — 보기 모드(`Viewer.tsx` 152~163행)와 같은 모양
- 배열이 모자라면(있을 수 없지만) 그 자리는 `<div class="md-mermaid-error">다이어그램을 그리지 못했습니다</div>`
- **SVG 안에 `<script>` 가 있으면 통째로 뺀다.** 1.3 의 "스크립트를 넣지 않는다" 를 지키기 위한 마지막 방어다(A7 로 판정)

### 4.4 인라인 CSS — `exportHtmlCss.ts`

`?raw` 로 원문을 읽어 이어 붙인다. `?inline` 이 아니라 `?raw` 인 이유: `?inline` 은 CSS 안 `url()` 을 빌드 자산 경로로 바꿔 단독 파일에서 깨진다

| 순서 | 내용 | 근거 |
| --- | --- | --- |
| 1 | `:root{--brand-accent:{brand.accent}}` | `src/brand.ts` 에서 읽는다. 코드에 hex 를 적지 않는다(불변조건). 평소에는 `vite.config.ts` 가 `index.html` 에 넣어 주는 값이라, 단독 파일에서는 여기서 넣어야 한다 |
| 2 | `src/styles/tokens.css?raw` | 색·서체·크기 토큰. 첫 `:root` 가 화이트 테마라 `data-theme` 을 주지 않으면 흰 바탕이다(F-277 1.3) |
| 3 | `github-markdown-css/github-markdown-light.css?raw` | 보기 모드 기준 스타일. 라이트 전용이라 `prefers-color-scheme` 블록이 없다(확인함) |
| 4 | `src/styles/markdown.css?raw` | `.markdown-body` 토큰 덮어쓰기 |
| 5 | `src/styles/callout.css?raw` · `image.css?raw` · `wikilink.css?raw` · `frontmatter.css?raw` | 콜아웃·이미지·위키링크·프론트매터 |
| 6 | `src/viewer/viewer.css?raw` | `.viewer` 배치, `.md-mermaid` |
| 7 | 내보내기 전용 덮어쓰기(아래) | |

가공 두 가지:

- **`@font-face` 블록을 뺀다.** tokens.css 의 D2Coding `@font-face` 만 해당한다(`src/styles/**`·`viewer.css` 를 통틀어 `url()` 은 그 한 줄뿐임을 확인했다). `F-277` 1.3 이 "서체 파일은 넣지 않고 `font-family` 목록만" 으로 정했고, 넣으면 파일이 수 MB 커진다. 받는 사람 PC 에 서체가 없으면 `system-ui`·`serif`·`monospace` 로 떨어진다
- **`@import` 줄을 뺀다.** `viewer.css` 첫 줄의 `codeCopy.css` 하나뿐이고, 내보낸 파일에는 복사 버튼이 없다

내보내기 전용 덮어쓰기(이 문자열이 전부다. 색값을 새로 적지 않는다):


`app.css` 는 넣지 않는다 — 71KB 에 사이드바·상단바 규칙이 섞여 있고, 단독 문서에 쓸 것이 없다

## 5. 서식 있는 복사 (F-277 1.4)

### 5.1 클립보드 API 와 제약

MDN 을 2026-09-20 에 확인한 사실:

- `ClipboardItem` 과 `navigator.clipboard.write()` 는 **보안 컨텍스트(HTTPS) 에서만** 쓸 수 있다. 운영은 `https://rawdoc.app`, 개발·E2E 는 `http://localhost:…` 라 둘 다 보안 컨텍스트다
- **Baseline 2024**(2024-06 부터 최신 브라우저 전반). 그보다 오래된 브라우저에서는 `ClipboardItem` 자체가 없다
- 브라우저가 흔히 지원하는 형식은 **텍스트·HTML·PNG** 라고 적혀 있다. `text/html` + `text/plain` 조합은 이 범위 안이다
- `ClipboardItem` 의 값으로 **`Promise<Blob>` 을 줄 수 있다**(MDN 예제)
- 거부되면 `NotAllowedError` 가 난다
- **사용자 제스처(transient activation) 요구는 MDN 의 `Clipboard.write` 문서에 명시돼 있지 않다.** 크롬이 실제로 얼마나 엄격한지는 이 명세가 확인하지 못했다 → 아래 순서로 방어한다

호출 순서(`ExportMenu` 의 `runAndClose` 가 클릭 핸들러 안에서 동기로 부른다):

1. `ClipboardItem` 이 있으면 **먼저 `Promise<Blob>` 을 담은 `ClipboardItem` 을 만들어 `navigator.clipboard.write()` 를 부른다.** `await` 를 한 번도 하기 전에 불러 제스처 안에 들어가게 한다
2. 1 이 던지거나 거부되면, HTML 을 `await` 로 다 만든 뒤 **진짜 `Blob` 으로 다시** `write()` 를 시도한다(`Promise` 값을 안 받는 브라우저 대비)
3. 2 도 실패하면 `navigator.clipboard.writeText(평문)` 으로 떨어뜨리고 알림 `서식 없이 글만 복사했습니다.`
4. 3 도 실패하면 알림 `복사하지 못했습니다. 브라우저 권한을 확인하세요.`(`App.tsx` 2030행의 기존 문구를 그대로 쓴다)

성공하면 알림 `서식을 포함해 복사했습니다.`(`F-277` 1.4 문구 + 마침표, 6장 M5)

`navigator.clipboard` 자체가 없는 환경에서 호출이 **동기적으로** 던지므로 전체를 `try` 로 감싼다(`codeCopyButton.ts` 28행·`ShareMenu.tsx` 와 같은 처리)

### 5.2 인라인 스타일 범위

`F-277` 1.4 는 "1.3 의 본문, 스타일은 인라인" 으로 정했다. `<style>` 블록은 붙여넣는 앱이 대개 버린다. 그렇다고 CSS 엔진으로 모든 규칙을 계산해 박으려면 새 의존성(juice 류)과 DOM 이 필요하다 — 둘 다 이 명세 범위 밖이다

그래서 **정해진 태그에만 정해진 `style=` 을 박는다.** 4.5 의 본문 HTML 을 입력으로 받는 순수 문자열 함수다(`toInlineStyledHtml`). 나머지 모양은 받는 앱의 기본 태그 스타일에 맡긴다(제목·굵게·기울임·목록·`<mark>` 는 어느 앱이나 자기 기본값이 있다)

| 대상 | 박는 `style` |
| --- | --- |
| `<blockquote>` | `margin:0 0 16px;padding:0 1em;border-left:4px solid {rule};color:{ink2}` |
| `<pre>` | `padding:16px;overflow:auto;background:{rule2};border-radius:6px` |
| `<code>` 중 `<pre>` 안이 아닌 것 | `padding:.2em .4em;background:{rule2};border-radius:6px` |
| `<table>` | `border-collapse:collapse` |
| `<th>` · `<td>` | `border:1px solid {rule};padding:6px 13px` |
| `<img …>` | `max-width:100%` |
| `<div class="markdown-callout …">` | `margin:0 0 16px;padding:8px 12px;border-left:4px solid {rule};color:{ink2}` |
| `<p class="markdown-callout-title">` | `font-weight:600;margin:0 0 4px` |

- 값은 `readPalette(tokensCss)` 가 tokens.css 첫 `:root` 에서 읽은 것이다(`vite.config.ts` 의 `readTokenColor` 와 같은 방식). **코드에 hex 를 적지 않는다**(불변조건, `npm run review` 의 `색hex` 검사)
- 콜아웃 **종류별 색은 재현하지 않는다.** `--callout-*` 는 `var()`·`color-mix()` 라 CSS 엔진 없이 값을 낼 수 없다. 인용과 같은 회색 띠로 간다
- 콜아웃 아이콘 `<span class="markdown-callout-icon" …>{svg}</span>` 은 **뺀다.** 워드·메일 편집기가 인라인 SVG 를 자주 버리고, 버릴 때 깨진 자리를 남긴다
- `class` 속성은 그대로 둔다. 지우는 이득이 없고 지우려면 치환이 늘어난다
- `<pre>` 안 `<code>` 에 인라인코드 스타일이 붙지 않게, `<pre><code` 를 먼저 표시해 두고 남은 `<code` 만 바꾼다(A10)

### 5.3 클립보드에 담는 두 가지

| 형식 | 내용 |
| --- | --- |
| `text/html` | `<meta charset="utf-8">` + `<div>{5.2 결과}</div>` 한 덩어리. `<html>`·`<head>`·`<style>` 을 넣지 않는다 |
| `text/plain` | `toPlainText(text, 'lf')`(F-278) |

- 평문의 줄바꿈은 문서 `lineEnding` 과 상관없이 **`\n`** — CM6 복사(`App.tsx` `contextMenuSelectionText`)와 같다

- Mermaid 는 인라인 SVG 그대로다. 버리는 앱이 있다 — 사람 확인

| A12 (단위) | 사용자 입력이 태그가 되지 않는다 | 코드블록 안에 `<img data-attachment="x" alt="">` 와 `<div class="md-mermaid" data-mermaid-source="y"></div>` 를 그대로 적은 원문 | 둘 다 이스케이프된 글자로 남고 치환되지 않는다(`&lt;img`). `images`·`mermaid` 를 줘도 마찬가지 |
| A13 (단위) | `.html` 파일명·바이트 | `buildHtmlPayload({ title: 'CON', … })` 등 | 파일명이 `toFileName(title)` 의 확장자만 `.html`(예약어·금지문자·100자 규칙 그대로), `bytes` 가 `TextEncoder().encode(html)` 과 같다. 맨 앞 BOM 없음 |
| A14 (단위) | 복사 payload | `buildRichCopyPayload({ text, body, palette })` | `plain` 이 `toPlainText(text, 'lf')` 와 같다(CRLF 없음). `html` 이 `<meta charset="utf-8">` 로 시작하고 `<html`·`<style` 이 없다 |
| A15 (e2e) | 메뉴 항목 | 상단바 `내보내기` 클릭 | 항목이 `.md` · `.txt (평문)` · `HTML 파일` · `서식 있는 복사` 순서로 있다. 첫 항목에 포커스, `Escape` 로 닫히고 트리거로 복귀 |
| A16 (e2e) | `.html` 다운로드 | 제목·목록·표가 있는 문서에서 `HTML 파일` | 파일명이 `{제목}.html`. 내용이 `<!doctype html>` 로 시작하고 `<style>` 과 `<title>{제목}</title>` 이 있으며 **`<script` 가 없다** |
| A17 (e2e) | 이미지 인라인 | PNG 를 붙여넣은 문서에서 `HTML 파일` | 받은 내용에 `src="data:image/png;base64,` 가 있고 `data-attachment` 가 없다 |
| A18 (e2e) | Mermaid | ` ```mermaid\ngraph TD; A-->B;\n``` ` 문서에서 `HTML 파일` | 받은 내용에 `<svg` 가 있고 `data-mermaid-source` 가 없다 |
| A19 (e2e) | 서식 있는 복사 | 권한 부여 후 `서식 있는 복사` → `navigator.clipboard.read()` | `types` 에 `text/html`·`text/plain` 이 모두 있다. html 에 `<h1`·`<strong`·`border-collapse` 가 있고(`toContain`), plain 에 `**`·`#` 가 없다. 알림 `서식을 포함해 복사했습니다.` |
| A20 (e2e) | 복사 대체 경로 | `addInitScript` 로 `window.ClipboardItem` 을 지운 뒤 `서식 있는 복사` | `clipboard.readText()` 가 평문과 같고, 알림 `서식 없이 글만 복사했습니다.` |
| A21 (e2e) | 비활성 회귀 | 문서가 없는 빈 상태 | `내보내기` 버튼이 `disabled`, 새 항목도 열리지 않는다 |

| A23 | 타입·린트·빌드 | `npm run typecheck`, eslint(바꾼 파일), `npm run build` | 통과 |

### 사람 확인 필요 (테스트로 판정하지 않음)

- 내려받은 `.html` 을 인터넷 없는 PC 의 크롬·엣지·사파리에서 열었을 때 보기 모드와 비슷하게 보이는지 (서체는 받는 PC 에 Pretendard·Noto Serif KR·D2Coding 이 없으면 기본 서체로 떨어진다 — 의도한 것)
- 제목이 보기 모드(20px 세리프)와 달리 본문 `#` 제목과 같은 크기로 보이는 것(4.5)이 받아들일 만한지
- `서식 있는 복사` 를 지메일·아웃룩·노션·구글 문서·워드·한글에 붙여넣었을 때: 제목·굵게·목록·표가 살아 있는지, 이미지(`data:` URI)가 들어가는지, Mermaid SVG 가 들어가는지, 콜아웃이 회색 인용으로 보이는 게 괜찮은지
- 크롬 말고 파이어폭스·사파리에서 `서식 있는 복사` 가 동작하는지(5.1 의 1·2단계 중 어디로 가는지). E2E 는 크롬 채널 하나만 돈다
- 이미지가 많은 문서(10MB 이상)에서 `HTML 파일` 을 누른 뒤 창이 멈추지 않는지, 20MB 경고 문구가 적당한지
