## 2. 핵심 결정

### 2.1 본문은 **생성 요청의 `content` 로** 넣는다 (편집기 트랜잭션이 아니다)

`createNewDoc`·`openWikiLinkTarget` 이 지금 `store.create({ title, content: '', lineEnding: 'crlf', folderId })` 를 부르는 자리에서, `content` 에 템플릿 본문(4.3, CRLF)을 넣는다. 그 뒤 흐름(목록 추가·폴더 펼침·제목 포커스·해시)은 그대로다

왜 이쪽인가 — 코드로 확인한 근거:

| 따져 본 것 | 생성 `content` (고른 쪽) | 연 뒤 편집기 트랜잭션 |
| --- | --- | --- |
| 불변조건 "원본은 `Y.Text` 하나" | 새 문서는 `setStore` 가 감싼 `create` 가 `createdHereRef` 에 적어 **`pending` 경로**로 열린다(`decideDocPath` 의 `hasPendingChanges`). 편집기 `Y.Doc` 은 `createYBinding(content)` 로 한 번 씨앗을 받는다. 나중에 실시간으로 열면 `docRoomCore` 가 **저장된 Yjs 행이 0개일 때만** D1 `content` 를 `Y.Text` 에 한 번 넣고, 클라이언트 방 Doc(`useLiveDoc`)은 빈 `Y.Doc` 에서 서버 상태만 받는다 — 두 곳에서 따로 씨앗을 넣는 길이 없어 **두 번 들어가지 않는다.** 가져오기(F-282)·`도움말을 문서로 복사`(`copyHelpToDoc`)가 이미 같은 길을 쓴다 | 같은 결과지만 편집기가 뜬 뒤에야 넣을 수 있다. 실시간 경로면 첫 동기화(`ready`) 뒤, `pending` 이면 `openDoc` 도착 뒤 — 문서 전환·다른 탭·오프라인마다 "언제 떴나" 를 따로 기다려야 하고, 기다리는 동안 사용자가 친 글과 섞일 수 있다 |
| 오프라인 | `serverStore.create` 는 캐시 + outbox `createDoc` 에 `content` 를 그대로 싣는다 → 연결되면 한 번 올라간다. 로컬(`idb`)·메모리도 `create` 한 번 | 편집 → 저장 대기 → `updateDoc` 이 따로 쌓인다 |
| 서버 쓰기 횟수(F-2025 하루 5,000번) | **1번**(`createDoc`) — 지금과 같다 | 2번(`createDoc` + `updateDoc`) |
| 빠지는 경우 | `create` 가 실패하면 문서 자체가 없다(기존 오류 알림) — 템플릿만 빠진 문서가 생기지 않는다 | 문서는 생겼는데 넣기 전에 사용자가 떠나면 빈 문서가 남는다 |
| 한글 조합 | 편집기 밖에서 일어나 조합과 닿지 않는다 | 제목 입력이 포커스를 가져 편집기가 조합 중일 수는 없지만 판정이 하나 더 필요하다 |

**`Ctrl+Z` 로 템플릿은 되돌아가지 않는다.** `yBinding.ts` 의 `bind` 가 씨앗을 넣은 **뒤에** `Y.UndoManager` 를 만들고 `trackedOrigins` 를 빈 집합으로 둬, 씨앗은 되돌리기 기록에 없다(F-302 3.4 "첫 Ctrl+Z 가 본문을 지우지 않게"). 템플릿이 든 새 문서는 "처음부터 그 글이 있던 문서" 이고, 가져온 문서와 같다. 되돌리려면 전체 선택 → 삭제다. 다른 쪽을 고르면 → 12장 Q2

### 2.2 순수 함수 계약 — `src/lib/templates.ts`

```ts
// 설정값 = 'none' 또는 TemplateEntry.id ('builtin:{key}' · 'doc:{docId}')
export const NEW_DOC_TEMPLATE_NONE = 'none'

export type NewDocTemplateResolution =
  | { kind: 'none' }                         // 설정이 'none'
  | { kind: 'missing' }                      // 설정값이 지금 목록에 없다(3.4)
  | { kind: 'found'; entry: TemplateEntry }

// 원문(줄바꿈 무엇이든) → 새 문서 content. 공백·줄바꿈뿐이면 ''
export function newDocContentFromTemplate(
  rawText: string,

  lineEnding: LineEnding,

export type NewDocTemplateOption = { value: string; label: string; group: 'none' | 'builtin' | 'user' | 'missing' }
```

- `templates.ts` 가 `./lineEnding` 을 import 한다(`lib → lib`)
- `resolveNewDocTemplate` 은 `entries` 에서 `id === pref` 를 찾기만 한다. 모르는 모양(`'xyz'`, `''`)도 `missing` 이다. `'none'` 만 `none`
- `newDocContentFromTemplate` 규칙은 4.3

## 3. 설정 — `새 문서 템플릿`

### 3.1 키

### 3.2 자리와 모양

- `편집기` 탭 **맨 끝**(`줄 번호` 아래). 새 문서에 무엇이 들어갈지는 편집 습관이라 `편집기` 에 둔다. `화면` 탭 `시작 화면` 옆도 후보였으나 그 탭은 모양 설정 모음이다
- 공개 보기(S-5)의 설정 대화상자에는 그리지 않는다 — `PublicView.tsx` 는 새 props 를 주지 않으므로 저절로 빠진다(F-290 2a 규칙 그대로. `PublicView.tsx` 는 고치지 않는다)
- 모양: 기존 `.dialog-field` 한 칸. 라벨은 `<span id="new-doc-template-label">새 문서 템플릿</span>`(다른 항목과 같은 `span` — `.dialog-field > span` 스타일을 그대로 받는다), 그 아래 `<select id="new-doc-template-select" class="settings-select" aria-labelledby="new-doc-template-label">`
- 세그먼트(`Segment`)가 아니라 `<select>` 인 이유: 항목 수가 사용자 템플릿 수만큼 늘어난다. 키보드·스크린 리더·좁은 창을 브라우저가 맡는다. 앱에 `<select>` 는 이것이 처음이다(`grep "<select" src` 0건) — 모양은 사람 확인 H1
- `.settings-select`: 폭 100%. 테두리·모서리·배경·포커스 표시는 `.search-input-row` 와 같은 토큰(`--rule`·`--radius-control`·`--paper`, 글자 `--ink`, 포커스 `--accent`, 전환 `--transition-colors`)을 쓴다. 새 토큰 없음. 값은 사람 확인
- 선택하면 **곧바로** `setPref` 하고 상태를 바꾼다(ia 3.15 3번 "누르는 즉시 반영, 저장 버튼 없음")

### 3.3 선택지 — `newDocTemplateOptions`

위에서부터. 사용자가 정한 순서(`없음` / 내장 / 템플릿 폴더)다 — 팔레트(사용자 템플릿 먼저)와 순서가 다른 것은 의도다

| group | value | label | 조건 |
| --- | --- | --- | --- |
| `none` | `none` | `없음` | 늘 |
| `builtin` | `builtin:meeting` 등 | `회의록` · `일일 노트` · `버그 보고` · `주간 회고` (4.4 순서) | 늘 |
| `user` | `doc:{id}` | `{title} ({detail})` — 예 `주간 보고 (템플릿)`, `가 (템플릿 / 회의)` | 사용자 템플릿마다, `listTemplates` 순서 |
| `missing` | 지금 설정값 그대로 | `찾을 수 없는 템플릿` | 설정값이 `missing` 일 때만, 맨 끝 |

- 화면에서는 `builtin` 을 `<optgroup label="내장">`, `user` 를 `<optgroup label="템플릿 폴더">` 로 묶는다. `user` 가 0개면 그 묶음을 그리지 않는다
- `missing` 선택지는 `disabled` 이고 선택된 채로 보인다. 다른 것을 고르면 사라진다
- 사용자 템플릿이 0개면 선택칸 아래 `.dialog-note` 로 `최상위에 '템플릿' 폴더를 만들고 문서를 넣으면 여기에 함께 나옵니다.` (F-2022 안내 문장과 같은 글)
- 목록은 App 의 `templateEntries`(F-2022 4.2 `listTemplates`) 를 그대로 쓴다. 공유받은 문서는 이미 빠져 있다

### 3.4 고른 템플릿이 없어졌을 때

- 템플릿 문서를 지웠거나, `템플릿` 폴더 밖으로 옮겼거나, 폴더 이름을 바꿨거나, 다른 계정이면 → 설정값이 목록에 없다(`missing`)
- **새 문서는 조용히 빈 문서로 만든다.** 알림을 띄우지 않는다
- **설정값은 지우지 않는다.** 목록은 부팅 중·다시 읽는 중에 잠깐 비거나 덜 찬다(`docs`·`folders` 상태). 그때 지우면 멀쩡한 설정을 잃는다. 문서를 다시 템플릿 폴더로 옮기면 그대로 다시 먹는다
- 대신 설정 대화상자가 `찾을 수 없는 템플릿` 을 보여 사용자가 알 수 있다(3.3)
- 다른 쪽(자동으로 `none` 으로 되돌리기)을 고르면 → 12장 Q4

### 4.2 템플릿 원문 읽기

`createNewDoc`·`openWikiLinkTarget` 에서 `beforeLeaveDoc()` 뒤, `store.create` 앞에 한다

1. 설정값은 **그 순간 `getPref('md.newDocTemplate', 'none')`** 로 읽는다(설정 대화상자용 React 상태가 아니라). 다른 탭에서 바꾼 값도 새로 고침 없이 먹는다. 앱은 `storage` 이벤트를 듣지 않는다(`grep "'storage'" src/app` 0건) — 대화상자 표시는 열 때의 상태라 다른 탭 변경이 늦게 보일 수 있다. 다른 설정과 같은 성질이다
2. `resolveNewDocTemplate(설정값, templateEntries)`
   - `none`·`missing` → `content: ''` (지금과 같다), 알림 없음
   - `found` + 내장 → `entry.source.body`
   - `found` + 문서 → **팔레트 `insertTemplate` 과 같은 읽기**: 그 문서가 지금 연 문서이고 편집기가 있으면 `editorRef.current.getText('lf')`(저장 대기 중 편집까지), 아니면 `store.get(docId)` 의 `content`. **이 읽기를 App 안 함수 하나로 뽑아 팔레트와 새 문서가 같이 쓴다**(이름은 구현이 정한다). 팔레트 동작은 바뀌지 않는다
3. 문서 템플릿 읽기는 **3,000ms** 를 넘기면 실패로 본다. `store.get` 은 캐시에 없으면 `fetch` 를 부르는데 `docsApi.ts` 의 `send` 에 시간 제한이 없어, 막힌 연결에서 `새 문서` 버튼이 끝없이 안 먹을 수 있다. 3,000ms 는 재 본 값이 아니라 정한 값이다(12장 Q5). 보통은 캐시에 있다 — `serverStore.list` 가 버전이 바뀐 내 문서 본문을 받아 캐시에 넣어 두기 때문이다
4. 읽기 실패(`null`·예외·시간 초과) → **빈 문서로 만들고** error 알림 `새 문서 템플릿을 읽지 못해 빈 문서로 만들었습니다.` 문서 만들기 자체는 막지 않는다. 3.4(목록에 없음)와 달리 알리는 이유: 설정은 맞는데 이번만 못 읽었다 — 사용자가 모르고 지나가면 "설정이 안 먹는다" 로 보인다
5. 알려진 모양(F-2022 에서 물려받음): 캐시 본문은 마지막 `list` 때 것이다. 다른 기기에서 방금 고친 템플릿이 아직 목록 새로 읽기 전이면 옛 본문이 들어간다. 팔레트와 같은 성질이라 따로 막지 않는다

### 4.3 본문 만들기 — `newDocContentFromTemplate`

원문 → `toEditorText`(LF) → `expandTemplateVariables(…, { title, now, emptyTitle })`(4.4) → 결과가 `trim()` 뒤 비었으면 `''` → 아니면 `planTemplateInsert('', 치환된 글).body` (F-2022 5.3 "빈 문서" 규칙: 앞뒤 빈 줄만 떼고 프론트매터는 통째로 맨 앞) → `fromEditorText(…, lineEnding)`

- `lineEnding` 은 새 문서 기본 `crlf` 다(ia 3.3, product Q9). 저장된 원문은 CRLF 다 — 확인 (a)
- `now` 는 그 `새 문서` 처리가 시작된 순간의 `new Date()`
- 변수 규칙·토큰은 F-2022 5.2 그대로. 이 명세가 더하는 변수는 없다
- 공백뿐인 템플릿을 따로 빈 문서로 두는 이유는 확인 (c)

### 4.4 `새 문서` 버튼의 `{{title}}` — 빈 글자 (사용자 결정 2026-09-25)

- 버튼으로 만들 때 제목은 아직 없다. **`{{title}}` 은 빈 글자로 바뀐다** — `## {{title}}` 은 `## `, `title: {{title}}` 은 `title: ` 가 된다(확인 (a)). 사용자 원문: "그냥 없어도 될듯"
- 저장소에 넘기는 문서 제목은 지금처럼 `제목 없는 문서` 다(`createNewDoc` 그대로). 본문 치환만 빈 글자다
- 위키링크로 만들 때는 링크 제목 그대로(4.1)
- 치환은 만들 때 한 번이다. **나중에 제목을 정해도 본문의 그 자리는 따라 채워지지 않는다**
- **치환 함수 변경 — `expandTemplateVariables` 에 선택 인자 하나를 더한다**

```ts
export function expandTemplateVariables(
  text: string,
  vars: { title: string; now: Date; emptyTitle?: 'fallback' | 'keep-empty' },  // 기본 'fallback'
): string
```

- `'fallback'`(기본): 지금 그대로 — 앞뒤 공백을 뗀 제목이 비었으면 `제목 없는 문서`
- `'keep-empty'`: 앞뒤 공백을 뗀 제목이 비었으면 빈 글자 그대로. 날짜·시각 치환은 같다
- `newDocContentFromTemplate` 는 `vars` 를 그대로 넘긴다(2.2 시그니처의 `vars` 에 같은 `emptyTitle?` 가 붙는다). `createNewDoc` 은 `{ title: '', now, emptyTitle: 'keep-empty' }`, `openWikiLinkTarget` 은 `{ title: 만드는 제목, now }` 로 부른다
- **기존 호출은 바뀌지 않는다.** 팔레트 `insertTemplate`(App)은 `emptyTitle` 을 넘기지 않으므로 빈 제목 문서에 넣어도 지금처럼 `제목 없는 문서` 다. F-2022 5.2 규칙과 그 U6 은 그대로 통과해야 한다(U7·A7b 가 판정)

### 4.5 포커스·커서

- 지금과 같다: 새 문서는 **제목 입력에 포커스 + 전체 선택**(`focusTitleRef`, F-217 2.3). 본문이 이미 `content` 로 들어가 있으므로 제목 포커스와 부딪칠 일이 없다 — 편집기에 트랜잭션을 보내지 않는다
- 제목에서 `Enter` 를 치면 커서는 **본문 맨 앞(0)** 이다(`docTitle.ts` 의 본문 포커스 함수, F-217 규칙 그대로). 템플릿 끝(`- [ ] ` 뒤)으로 옮기지 않는다 — 12장 Q3
- 보기 모드에서 누르면 편집 모드로 바뀌는 것(`changeViewMode('live')`)도 그대로다

### 4.6 그 밖

- 템플릿 문서 자신이 든 폴더(`템플릿`)에서 폴더 메뉴 `새 문서` 를 눌러도 똑같이 넣는다. 그 새 문서도 템플릿 목록에 들어간다(F-2022 4.2 — 폴더 안 문서는 전부 템플릿)
- 고른 템플릿이 **지금 새로 만드는 문서가 들어갈 폴더와 무관**하다(폴더별 규칙 없음 — 사용자 결정 1)
- 새 문서 크기가 저장 한도(F-2025)에 걸리면 지금 `create` 실패와 같은 오류 알림 경로를 탄다. 따로 다루지 않는다

```md
내 틀을 쓰려면 사이드바 **최상위**에 `템플릿` 폴더를 만들고 그 안에 문서를 넣습니다. 영어 이름 `templates` 폴더도 똑같이 알아보고, 하위 폴더의 문서도 함께 나옵니다.

틀 안에 `date`·`time`·`title`을 중괄호 두 쌍으로 감싸 적어 두면, 넣는 순간 오늘 날짜·지금 시각·문서 제목으로 바뀝니다. `date:YYYY.MM.DD`처럼 쌍점 뒤에 형식을 붙일 수도 있습니다. 형식에는 `YYYY`·`MM`·`DD`·`HH`·`mm`·`ss`와 요일 `dddd`를 씁니다.

설정 `편집기` 탭의 `새 문서 템플릿`에서 틀 하나를 고르면, `새 문서` 버튼이나 없는 위키링크를 눌러 만든 문서에 그 틀이 처음부터 들어 있습니다. 제목 자리는 `새 문서` 버튼이면 비워 두고, 위키링크면 링크에 적은 제목으로 채웁니다. 기본값은 `없음`입니다.
```

- **도움말 원문에 `{{` 를 쓰지 않는다.** 도움말은 공개 사이트 `/help` 로도 나가고(F-274), `site/build.ts` 가 도움말에도 `checkContentFile` 을 부르며, `site/guard.ts` 의 `PLACEHOLDER_RE` 가 `{{…}}` 를 보면 빌드를 실패시킨다(코드블록 안도 걸린다). 그래서 `content/guides/command-palette-templates.md` 가 이미 쓴 "중괄호 두 쌍으로 감싸" 표현을 따른다. U6 이 이것을 못박는다
- `## 단축키` 의 `Ctrl+P` 줄은 그대로 둔다

### 6.3 사용법 글 — `content/guides/command-palette-templates.md`

- `## 알아 둘 것` 앞에 새 절:

```md
## 새 문서에 템플릿 자동으로 넣기

설정의 `편집기` 탭에서 `새 문서 템플릿`을 고르면, 그 뒤로 만드는 새 문서에 틀이 처음부터 들어 있습니다. 내장 템플릿 넷과 `템플릿` 폴더의 문서 가운데 하나를 고를 수 있고, 기본값은 `없음`입니다.

사이드바·폴더 메뉴·빈 화면의 `새 문서` 버튼과, 아직 없는 문서를 가리키는 위키링크를 눌러 만든 문서에 들어갑니다. `.md` 가져오기나 `새 문서로 저장`으로 만든 문서에는 넣지 않습니다.

제목 자리는 `새 문서` 버튼이면 비워 두고, 위키링크면 링크에 적은 제목이 됩니다. 넣은 뒤 제목을 정해도 본문의 그 자리는 따라 채워지지 않습니다.

이 설정은 브라우저마다 따로 저장됩니다. 고른 템플릿 문서를 지우거나 `템플릿` 폴더 밖으로 옮기면 새 문서는 빈 문서로 만들어집니다.
```

- `## 알아 둘 것` 첫 줄 `템플릿 폴더는 이름으로만 정해집니다. 따로 고르는 설정은 없습니다` → `템플릿 폴더는 이름으로만 정해집니다. 폴더를 고르는 설정은 없습니다` (새 설정은 폴더가 아니라 템플릿 하나를 고른다 — 원래 문장이 틀리게 읽힌다)
- 프론트매터 `updated` 를 구현 커밋 날짜로. `{{` 를 쓰지 않는다(가드)

## 13. 확인한 것과 가정

### 13.1 코드를 읽거나 돌려 확인한 것
- 머리의 "직접 돌려 확인한 것" (a)~(e)
- `createNewDoc`·`openWikiLinkTarget` 둘 다 `store.create({ content: '', lineEnding: 'crlf' })` 로 만들고 `focusTitleRef.current = true`·`focusEditorRef.current = false` 를 둔다. `새 문서` 버튼 다섯 곳(레일·아이콘·폴더 메뉴 `new-doc`·빈 화면·지도 빈 상태)이 모두 `createNewDoc` 으로 온다
- `setStore` 가 `create` 를 감싸 `createdHereRef` 에 적고, 문서 경로 effect 가 그것을 `hasPendingChanges` 로 넘겨 `decideDocPath` 가 `pending` 을 고른다 — 이 탭에서 막 만든 문서는 실시간 방으로 열리지 않는다
- `useLiveDoc` 의 방 Doc 은 `new Y.Doc()` 로 시작하고 본문을 스스로 넣지 않는다. `docRoomCore` 는 저장된 행이 0개일 때만 D1 `content` 로 `Y.Text` 를 채운다
- `createYBinding` 은 씨앗을 넣은 뒤 `Y.UndoManager` 를 만들고 `trackedOrigins` 가 빈 집합이다 → 씨앗은 되돌리기 대상이 아니다
- `serverStore.create` 는 `content` 를 캐시와 outbox `createDoc` 둘 다에 싣는다. `serverStore.get` 은 캐시 → 서버 → 실패 `null`, `docsApi.send` 는 시간 제한이 없다
- 도움말은 `site/build.ts` 에서 `checkContentFile` 을 지나고, `site/guard.ts` 가 `{{…}}` 를 막는다. 사용법 글이 "중괄호 두 쌍" 으로 쓴 이유가 이것이다
- 설정 대화상자의 라벨은 `.dialog-field > span`, `F-290 A4` 가 그 선택자로 라벨 목록을 센다. 앱에 `<select>` 는 없다. 앱은 `storage` 이벤트를 듣지 않는다
- `findLinkFolder('과제/새 글', …)` = `{ folderId, title: '새 글' }` (`wikiResolve.test.ts` U8)

### 13.2 가정으로 남긴 것
- 3,000ms 는 잰 값이 아니다(Q5)
- `App.tsx` 를 같은 날 다른 작업(폴더 메뉴 새 문서 제목 포커스)이 건드리는지, 어느 줄인지 모른다
- `<select>` 가 세 테마에서 보기 좋은지는 보지 않았다(H1)
- Playwright `toHaveText`·`toContainText` 가 `white-space: pre-line` 의 줄바꿈을 어떻게 비교하는지 돌려 보지 않았다 — 그래서 A14 는 줄마다 `toContainText` 로 적었다
