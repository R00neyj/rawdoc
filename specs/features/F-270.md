# F-270 공개 사이트 — 설계 개요

작성일: 2026-09-20
상태: **사람 승인(2026-09-20 "병렬작업 가능한것들 병렬로 실행, 승인").** 승인 범위는 1~5장 결정과 6장 로드맵. 사용자 요청(2026-09-20 "로그인 하지 않았을때 랜딩 1회 보여주고, 로그인 없이 사용 누르면 로컬스토리지에 상태 저장해서 다음부터는 에디터로", "랜딩 + 메인 홈페이지처럼 체인지로그랑 도움말 각종 법적 사항들(개인정보처리방침 등)", "블로그처럼 사용법 글(제텔카스텐 기법이나 위키링크를 이용한 사용법 등)이라도 올려야 SEO에 걸릴거같아서")
근거: F-239(`/welcome` 랜딩, Worker 가 완결된 HTML 을 돌려주는 이유 §2), `wrangler.jsonc` `assets`(`not_found_handling: single-page-application`, `run_worker_first`), `vite.config.ts` PWA(`navigateFallback: 'index.html'`, `start_url: '/'`), `specs/architecture.md` 4장 localStorage 키

**이 파일은 작은 명세가 아니라 설계 개요다.** 1~5장의 결정과 6장 로드맵만 승인 대상이고, F-271~F-276 은 이 설계가 승인된 뒤 하나씩 상세 명세를 쓴다(F-262 와 같은 방식)

## 1. 주소 구성

| 주소 | 내용 | 응답 |
| --- | --- | --- |
| `/` | 첫 방문·크롤러: 랜딩. 앱을 쓰기로 한 브라우저: 앱(`index.html`) | Worker (2장) |
| `/welcome` | 없앰 | `301` → `/` (이미 퍼진 링크·색인 유지) |
| `/guides` | 사용법 글 목록 | 사이트 (3장) |
| `/guides/{slug}` | 사용법 글 | 사이트 |
| `/changelog` | 체인지로그 | 사이트 |
| `/help` | 도움말 (앱 `#/help` 와 같은 원본) | 사이트 |
| `/privacy` | 개인정보 처리방침 | 사이트 |
| `/terms` | 이용약관 | 사이트 |

- 앱 화면은 지금처럼 `/` + 해시(`#/d/{id}`, `#/help` …)다. 경로(`/help`)와 해시(`#/help`)는 겹치지 않는다
- `/api/*`·`/pub/*`·`/v1/*`·`/p/*` 는 그대로

## 2. 첫 방문 판정

서버는 localStorage 를 읽을 수 없다. 그래서 **원본은 localStorage, 서버가 보는 사본은 쿠키**로 둔다

| 이름 | 위치 | 값 | 비고 |
| --- | --- | --- | --- |
| `md.landingDone` | localStorage | `1` | `architecture.md` 4장 표에 추가. 판정의 원본 |
| `md_app` | 쿠키 | `1` | `Path=/`, `Max-Age` 1년, `SameSite=Lax`, `Secure`. JS 로 쓰므로 `HttpOnly` 아님. 이름에 제품명을 쓰지 않는다(불변조건) |

흐름:

1. `GET /` — Worker 가 `md_app=1` 쿠키를 보면 `env.ASSETS.fetch` 로 `index.html`(앱). 없으면 랜딩 HTML
2. 랜딩 `로그인 없이 사용` — 두 값을 쓰고 `location.replace('/')` → 앱
3. 랜딩 `로그인` — 두 값을 쓰고 앱의 기존 로그인 흐름(`loginUrl`)으로
4. 랜딩 인라인 스크립트가 **먼저** 확인해서 곧바로 앱으로 보낸다 (쿠키만 지워진 경우·기존 사용자 대응):
   - localStorage 에 `md.landingDone`·`md.firstRunDone`(F-111)·`md.account`(F-205) 중 하나라도 있으면 → 쿠키를 다시 쓰고 `location.replace`
   - 주소에 앱 해시(`#/…`)가 붙어 있으면 → 두 값을 쓰고 그대로 앱. 공유받은 앱 주소가 랜딩에 막히지 않게 한다
5. 앱이 켜질 때 두 값이 없으면 쓴다 — 서비스 워커로 들어온 기존 사용자도 다음부터 서버 판정이 맞게

- 서비스 워커가 있는 브라우저(앱을 한 번 연 사람, 설치한 PWA)는 `/` 를 캐시된 `index.html` 로 받으므로 Worker 판정을 거치지 않고 바로 앱이다. 이것이 의도한 동작이다
- 크롤러는 쿠키·localStorage·서비스 워커가 없어 항상 랜딩을 읽는다 — 이 개편의 SEO 목적
- 로그인한 사용자는 로그인 전에 이미 2·3 을 거쳤으므로 랜딩을 다시 보지 않는다
- 랜딩을 다시 보는 방법: 앱 → 사이트 링크(6장 F-276)로 `/guides` 등은 언제든 열 수 있다. 앱 사용자에게 `/` 랜딩을 다시 보여주는 기능은 두지 않는다
- 쿠키는 기능용이고 추적에 쓰지 않는다. 처리방침(F-275)에 적는다

## 3. 사이트 페이지 만드는 방식

- **원본**: 저장소 `content/` — `guides/{slug}.md`(앞에 YAML 프론트매터: 제목·요약·작성일·수정일), `changelog.md`, `legal/privacy.md`, `legal/terms.md`. 도움말은 새로 쓰지 않고 `src/app/helpDoc.ts` 가 만드는 문서를 그대로 쓴다
- **빌드 때 HTML 로 만든다.** `npm run build` 에서 Vite 빌드 뒤 사이트 생성 단계가 `content/` 를 HTML 로 바꿔 `dist/` 에 쓴다. 요청마다 Worker 에서 변환하지 않는다 — 무료 플랜 Worker CPU 시간 상한이 있고, 글은 배포 사이에 바뀌지 않는다
- 변환은 보기 모드(F-123)와 같은 `markdown-it` 설정을 쓴다. 콜아웃·위키링크·Mermaid 처럼 브라우저가 필요한 확장이 Node 에서 도는지는 F-272 에서 확인하고, 안 되는 것은 사이트 글에서 쓰지 않는 것으로 정한다
- **공통 틀**: 랜딩과 같은 토큰·서체(F-239 §0.2), 머리(로고 + `사용법`·`체인지로그`·`도움말` + `앱 열기`), 꼬리(`개인정보 처리방침`·`이용약관`). 랜딩도 같은 머리·꼬리를 쓴다
- 제품명·색은 `brand.config.ts` 에서만 읽는다(불변조건). `content/*.md` 본문의 제품명은 글이라 예외로 두되, 틀(HTML 템플릿)에는 직접 쓰지 않는다
- **없는 주소는 `404`** — 지금 `not_found_handling: single-page-application` 이라 없는 경로도 앱 `index.html` 을 `200` 으로 준다(검색엔진이 빈 페이지를 색인할 수 있음). 사이트 접두사(`/guides*`·`/changelog`·`/help`·`/privacy`·`/terms`)는 `run_worker_first` 에 넣고, Worker 가 빌드 때 만든 목록에 없으면 `404` 페이지를 준다
- **서비스 워커 제외** — `navigateFallbackDenylist` 에 사이트 경로를 전부 넣는다. 안 넣으면 앱을 한 번 연 사람이 `/guides` 를 열 때 서비스 워커가 앱 `index.html` 을 준다(F-239 §0.2 와 같은 문제)
- 색인: 페이지마다 `<link rel="canonical">`, `og:*`, `<html lang="ko">`. `sitemap.xml` 에 사이트 주소 전부와 글 수정일. `robots.txt` 는 `/api/`·`/v1/`·`/pub/`·`/p/` 를 막고 `sitemap.xml` 위치를 적는다. `/p/*` 는 이미 `X-Robots-Tag: noindex`(F-238)

## 4. 내용 규칙

- **없는 기능을 쓰지 않는다** (F-239 §0, F-257 1장과 같음). 사용법 글·도움말·랜딩 모두 배포된 기능만. 실시간 동시 편집·댓글은 "만들고 있습니다" 로만
- 체인지로그: 배포 단위(날짜) 묶음, 사용자 눈높이 문장. F 번호·내부 용어(e2e, 스모크 등)를 쓰지 않는다. 과거분은 git 기록을 배포 날짜로 묶어 한 번 요약한다. 이후 배포마다 메인이 항목을 추가한다 — `CLAUDE.md` "배포" 절차에 넣는 것은 F-273 승인 때 사람이 정한다
- 법적 문서: 실제 수집·저장 항목을 코드에서 확인해 쓴다(로그인 이메일, 문서·이미지, API 토큰 해시, 초대받은 이메일, 쿠키·localStorage, 위탁처 Cloudflare·Google 로그인). 확인하지 못한 항목은 쓰지 않고 보고한다. 지금 계정 삭제 기능이 없다면 그 사실을 그대로 적고 요청 방법(연락처)을 둔다
- 자리표시 `{운영자}`·`{연락처}` 가 남아 있으면 **빌드가 실패**한다 — 채우기 전에 배포되지 않게
- 사용법 글 첫 3편(Claude 초안, 제목은 F-276 에서 확정): 위키링크로 문서 잇기 / 제텔카스텐 방식으로 메모 쌓기(위키링크·폴더·고정 활용) / 기호가 남는 `.md` 를 다른 도구(GitHub·VS Code·Obsidian)로 옮기기

## 5. 하지 않는 것

- 블로그 댓글, 태그, 검색, RSS (필요해지면 따로)
- 앱 안에서 글을 써서 사이트에 발행하는 기능 (글 원본은 저장소 `.md`)
- 다국어
- 분석·추적 스크립트(Google Analytics 등). 넣게 되면 처리방침을 먼저 고친다
- 쿠키 동의 배너 — 추적 쿠키가 없어서. 추적 도구를 넣으면 다시 본다
