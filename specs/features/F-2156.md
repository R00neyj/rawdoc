## 2. 순수 모듈 `localFileOpen.ts`
```ts
export type LocalFileOpenMode = 'import' | 'edit'
export function parseLocalFileOpenMode(raw: string | null | undefined): LocalFileOpenMode // 'edit' 만 edit, 나머지 전부 import
export function localFileOpenSettingVisible(w: { launchQueue?: unknown; showOpenFilePicker?: unknown }): boolean
export type LaunchPlan = { kind: 'import' } | { kind: 'edit'; index: number; notice: string | null }
export function planLaunch(mode: LocalFileOpenMode, names: string[]): LaunchPlan
export function launchOpenFailNotice(result: LocalOpenResult, name: string): string | null // LocalOpenResult 는 F-2155 5장, type import
```
- `localFileOpenSettingVisible`: `launchQueue` 가 참 값이고 **그리고** `showOpenFilePicker` 가 함수일 때만 참(F-2154 5장). 둘 중 하나라도 없으면 거짓 — 안드로이드·Firefox·Safari·비보안 출처
- `planLaunch`: `import` 면 늘 `{ kind: 'import' }`(개수 무관). `edit` 면 `index = names.length - 1`(마지막), `names.length >= 2` 일 때만 `notice` = `` `파일은 한 번에 하나만 고칠 수 있어 "${names[index]}" 만 열었습니다.` ``, 1개면 `null`. 빈 배열은 부르는 쪽이 이미 걸러 정의 안 함
- `launchOpenFailNotice`: `'missing'` 만 `` `"${name}" 을(를) 열지 못했습니다.` ``(F-2155 문구 재사용 — `openLocalFile` 은 `missing` 에 알림을 안 낸다). `'not-utf8'`·`'error'` 는 `openLocalFile` 이 이미 알렸으니 `null`, `'opened'`·`'same'` 도 `null`

## 3. 설정 절 `LocalFileOpenSetting`
- `localFileOpenSettingVisible(window)` 거짓이면 `null`. 참이면 `<section className="data-section" aria-labelledby="data-local-open-title">`: `h3#data-local-open-title.data-section-title` `로컬 파일 기본 열기 방식` → `p.dialog-note.data-row-note` `파일 탐색기에서 .md 파일을 이 앱으로 열 때` → `div.data-row-note[role=radiogroup][aria-labelledby=data-local-open-title]` 안에 `label.panel-item-check` 둘, 각 `input[type=radio][name=local-file-open]`
- 라벨 글자(접근 이름 = 전체): `<strong>가져오기</strong> — 새 문서로 만듭니다. 로그인 중이면 계정에 올립니다.`(`import`) / `<strong>이 파일만 고치기</strong> — 업로드하지 않고 이 파일에 바로 저장합니다.`(`edit`). 순서 고정, 기본 표시 꼬리표 없음
- 첫 값 `parseLocalFileOpenMode(getPref('md.localFileOpen', 'import'))`, 바꾸면 state + `setPref` 즉시(저장 버튼 없음, 다른 설정과 같음). 앱 다시 시작 불필요 — 4장이 열 때마다 읽는다
- `.dialog-field` 를 쓰지 않는다(설정 라벨 세는 선택자, F-290 A4). CSS 추가 없음 — 모양은 H2

## 4. launch 분기 (`openOrImportLaunchedFiles`)
- 빈 목록 걸러낸 직후 `planLaunch(parseLocalFileOpenMode(getPref('md.localFileOpen', 'import')), items.map(i => i.handle.name))`. 매 launch 때 읽으므로 설정 바꾼 뒤 곧바로 적용
- `import` → 아래 기존 코드 그대로(F-119·F-231 재중복, `runImportFiles`). `F-2068 C3` 가 지키는 동작
- `edit` → `items[index].handle` 만 쓰고 나머지 handle·`file` 은 버린다(읽기만 했고 아무 데도 안 쓴다). 순서: ① `notice` 가 있으면 info 알림 ② `result = await localFileRef.current.openLocalFile(handle, { gesture: false })` ③ `launchOpenFailNotice(result, handle.name)` 가 있으면 error 알림. ①을 열기 **앞에** 두는 까닭: 열기가 내는 알림(섞인 줄바꿈·UTF-8 아님·열지 못함)이 info 인 ①을 덮어야 해서(`pushNotice`)
- **어떤 결과든 가져오기로 넘어가지 않는다** — 실패해도 `runImportFiles` 안 부름, 앞 파일로 다시 시도 안 함, F-231 `findDocByFileHandle` 도 안 봄(이미 가져온 파일이어도 설정대로 파일을 연다). 몰래 올리지 않기가 F-2154 요청의 핵심
- 권한: `gesture: false` 라 요청 창 없음 → 이미 허용(Chrome 122+ 영구 허용 등)이면 바로 저장, 아니면 S-11 `저장 권한 필요` + `저장 허용`(F-2155 3장 그대로)
- 끌어놓기·`가져오기 › .md 파일`·`파일 열기…` 는 설정과 무관(F-2154 5장) — 이 분기는 launch 하나에만
