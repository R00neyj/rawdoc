## 3. 계약

개요 1.4 그대로이고, 아래 `// 추가` 표시만 새로 생긴다:

```ts
// src/lib/codeLang.ts — import 0개(순수). cli·site 번들도 이 파일을 묶는다(F-2126)
export type CodeLangId = 'javascript' | 'jsx' | 'typescript' | 'tsx' | 'css' | 'html' | 'xml' | 'json' | 'yaml' | 'python' | 'sql' | 'shell'
export function codeLangId(info: string): CodeLangId | null
export function codeLangIdsInHtml(html: string): CodeLangId[]
export const HIGHLIGHT_LANG_LABELS: readonly string[]

// src/lib/codeParsers.ts — 정적 import 는 `import type` 만
export type CodeGrammar = { parser: Parser; cmLanguage?: Language }
export function loadCodeGrammar(id: CodeLangId): Promise<CodeGrammar | null>
export function loadedCodeGrammar(id: CodeLangId): CodeGrammar | null

// src/lib/codeHighlight.ts — 정적 import 는 `@lezer/highlight`, `./codeLang`, `import type` 만
export const CODE_TOKEN_KINDS = ['keyword', 'string', 'comment', 'number', 'function', 'type', 'property', 'tag'] as const
export type CodeTokenKind = (typeof CODE_TOKEN_KINDS)[number]          // 추가
export type CodeSegment = { text: string; kind: CodeTokenKind | null }  // 추가
export const codeTokenHighlighter: Highlighter
export function highlightCodeLines(code: string, parser: Parser): CodeSegment[][]
export function highlightHtmlCodeBlocks(html: string, parserFor: (id: CodeLangId) => Parser | null): string
export const CODE_HIGHLIGHT_LIMITS = { blockChars: 20_000, totalChars: 100_000 }
```

### 3.1 `codeLang.ts`

- `codeLangId`: `displayLang` 과 같은 자르기(앞뒤 공백 제거 → 첫 단어 → 소문자) 뒤 개요 1.2 표의 별칭과 **정확히** 같을 때만 그 id. 표 조회는 자기 속성만 본다 — `constructor`·`toString`·`__proto__` 는 `null`
- `codeLangIdsInHtml`: `<code` 시작 태그의 `class` 값에서 `language-` 로 시작하는 토큰을 읽어 `codeLangId` 에 넣는다. 문서에 처음 나온 순서, 중복·`null` 없음. `<pre><code>`(언어 없음)·`md-mermaid` div 는 안 잡힌다
- `HIGHLIGHT_LANG_LABELS` = `JavaScript` `TypeScript` `CSS` `HTML` `XML` `JSON` `YAML` `Python` `SQL` `Shell` (개요 5.3 목록과 같은 순서, jsx·tsx 는 따로 적지 않는다). 각 값은 그 언어 별칭 하나를 `displayLang` 에 넣은 결과와 같아야 한다(테스트로 묶는다)
- `displayLang` 별칭 표는 넓히지 않는다 — `mjs`·`htm`·`svg`·`jsonc` 는 칠해지지만 머리줄은 지금처럼 원문 그대로 보인다(F-248 "표에 없으면 그대로")

### 3.2 `codeParsers.ts`

| id | 만드는 법 |
| --- | --- |
| `javascript` | `@lezer/javascript` `parser` |
| `jsx` · `typescript` · `tsx` | 같은 `parser.configure({ dialect })` — `'jsx'` · `'ts'` · `'ts jsx'` |
| `css` | `@lezer/css` `parser` |
| `html` | `@lezer/html` `parser.configure({ wrap: configureNesting([...]) })` — `script` 태그 → javascript 파서, `style` 태그 → css 파서 (N6 에서 `<script>` 안 `const`=keyword, `<style>` 안 `color`=property 확인) |
| `xml` · `json` · `yaml` · `python` | 각 `@lezer/*` `parser` |
| `sql` | `@codemirror/lang-sql` `StandardSQL.language` — `parser` 는 그 `.parser`, `cmLanguage` 는 그 언어 |
| `shell` | `@codemirror/language` `StreamLanguage.define(shell)` (`@codemirror/legacy-modes/mode/shell`) — `parser` 는 그 `.parser`, `cmLanguage` 는 그 언어 |

- **모든 런타임 의존은 `import()` 로만.** 모듈마다 `const { 이름 } = await import('…')` 처럼 받은 자리에서 바로 푼다 — 이름공간을 `Promise.all` 로 넘기거나 변수에 담아 두면 N4 처럼 쓰지 않는 내보내기까지 따라온다. 이 파일의 정적 import 는 `import type` 뿐이다 — 그래야 진입 청크 쪽 코드가 이 파일을 정적으로 불러도 문법이 따라오지 않는다
- **같은 id → 같은 객체.** 성공한 `CodeGrammar` 는 id 마다 하나를 모듈 안에 두고 `loadedCodeGrammar` 가 그것을 낸다. `parser` 객체가 바뀌지 않으므로 3.3 캐시 키와 F-2125 의 `LanguageDescription` 캐시가 이것에 기댄다
- **동시 호출**은 진행 중인 약속 하나를 같이 기다린다(같은 id 로 `import()` 가 한 번만 불린다)
- **실패**: 로더가 거부하면 `null` 로 풀고 그 id 를 실패 목록에 넣는다. 이후 그 탭(모듈 수명)에서는 `import()` 없이 바로 `null`. `loadedCodeGrammar` 도 `null`. 던지지 않는다
- `loadedCodeGrammar` 는 동기, 부르기만 해서는 아무것도 불러오지 않는다

### 3.3 `codeHighlight.ts`

- `codeTokenHighlighter` = `tagHighlighter` 에 개요 1.3 표를 그대로 옮긴 규칙 8개, 클래스는 `code-{종류}`. `all`·`scope` 옵션 없음(scope 는 F-2125 가 감싸서 준다)
- **`highlightCodeLines(code, parser)`**
  - `code` 를 `'\n'` 으로 나눈 줄 수만큼 배열을 낸다(`'\n'` 이 k 개면 k+1 줄). 빈 줄은 `[]`
  - 한 줄의 조각 `text` 를 이으면 그 줄 원문과 같다. 조각은 비어 있지 않고 `'\n'` 을 품지 않는다
  - 구간은 `highlightTree(parser.parse(code), codeTokenHighlighter, …)` 가 낸 범위 그대로, 그 사이 칠하지 않은 글자는 `kind: null` 조각. 클래스 문자열에 공백으로 나뉜 클래스가 여럿이면 첫 번째의 종류(N6 에서 0건)
  - `code.length > blockChars` 면 파싱하지 않고 줄마다 `kind: null` 조각 하나(빈 줄은 `[]`)
  - **캐시**: (parser 객체, code) → 결과. 모듈 안 하나의 `Map` 에 전부 합쳐 **200개**, 넘으면 가장 오래 안 쓴 것부터 버린다(찾으면 가장 최근으로 옮긴다). 상한을 넘은 블록은 캐시에 넣지 않는다. 돌려준 배열은 캐시와 같은 객체이므로 호출자는 고치지 않는다
- **`highlightHtmlCodeBlocks(html, parserFor)`**
  - 대상: `<pre` 시작 태그 바로 뒤에 `<code` 시작 태그가 오고 그 `class` 에 `language-{x}` 토큰이 있는 곳부터 **첫** `</code></pre>` 까지. renderMarkdown 은 `data-source-line` 을 `class` 앞에 둔다(`<code data-source-line="1" class="language-ts">`, N3 사본에서 확인) — 속성 순서에 기대지 않는다
  - `codeLangId(x)` 가 `null` 이거나 `parserFor` 가 `null` 이면 그 블록은 손대지 않는다
  - 안쪽만 바꾼다: `&amp;` `&lt;` `&gt;` `&quot;` 네 개를 **한 번에** 풀고(`&amp;lt;` → `&lt;`, 두 번 풀지 않는다) → `highlightCodeLines` → 조각마다 같은 네 글자로 다시 이스케이프, `kind` 가 있으면 `<span class="code-{kind}">…</span>` 로 감싸고 줄은 `'\n'` 으로 잇는다. 시작·끝 태그와 속성은 바이트 그대로
  - **문서 상한**: 앞에서부터 칠한 블록의 코드 글자 수(푼 뒤 UTF-16 길이)를 더한다. 다음 블록을 더하면 `totalChars` 를 넘을 때 그 블록과 **그 뒤 모든 블록**은 손대지 않는다. `blockChars` 를 넘어 손대지 않은 블록·`null` 블록은 합에 넣지 않는다
  - 칠할 블록이 하나도 없으면 받은 문자열과 같은 값을 낸다

## 4. 청크 경계와 측정

### 4.1 정한 것

- 진입 청크(`dist/index.html` 의 `<script type="module" src>`)에는 엔진·문법이 없다. 시제품에서 rollup 은 엔진·`codeParsers`·`codeLang` 을 `createEditor` 청크에 넣었다 — 이 청크는 이미 첫 로드(N2)이고, 거기 든 몫은 +13.8 KB(gzip +5.0 KB)이며 그중 8.4 KB 가 L2 의 셸(`StreamLanguage`) 값이다. 받아들인다(9장 Q1)
- python·yaml·sql·xml·shell·json 은 각자 따로 청크가 되어 그 언어 블록을 처음 칠할 때만 받는다. 전부 precache 에 든다(`globPatterns` `**/*.js`)
- `manualChunks` 를 두지 않는다

### 4.2 재는 법 (구현자가 보고에 숫자를 적는다)
