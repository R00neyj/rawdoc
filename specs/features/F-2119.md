# F-2119 명령줄 도구 문서 찾기 — ls 폴더 경로·맨 위만, find, info

작성일: 2026-10-03
상태: 승인 대기. 다른 Claude 세션이 CLI 로 실제 문서 24개·폴더 8개를 다룬 뒤 보고한 불편(2026-10-03)에서 나왔다. 선행 개요 없음 — 구현 단위 하나(`cli/` 만, 서버 변경 없음). 9장 열린 질문은 모두 기본값이 있고, 반대쪽이 그럴듯한 것은 Q1 하나다
구현 담당: `feature-implementer`. **F-2118 구현 커밋과 main 의 `ls` `(금고 문서)` tweak 커밋 뒤에** 시작한다(같은 파일)

## 정해진 것 (사용자 결정, 바꾸지 않는다)

1. `ls` 의 폴더 가시성 개선(폴더 경로 열, 맨 위 문서만 보기), 제목으로 찾는 `find <제목>`, 내용 없이 메타만 보는 `info <id>` 를 더한다
2. 서버 변경 없음. 필요해지면 그 부분은 빼고 F-3NNN 후속으로만 적는다 — 결과적으로 필요 없었다(근거 참고)
3. 하지 않는다: 버전 목록·복원(`product.md` 범위 밖), 내용 해시 충돌 방지(`--if-unchanged`, 서버 변경)
4. 제로 런타임 의존성, Node 22+, 모든 명령 `--json`, 종료 코드 표(F-2021 4.5), 기존 `--json` 모양 유지

## 근거 (직접 읽거나 돌려 본 것, 2026-10-03 HEAD `0d9ab10` + 작업 트리)

- **`ls` 기본은 내 문서 전부다** — `worker/docs.ts` `handleListDocs` 가 `WHERE owner_id = ? ORDER BY updated_at DESC`, 폴더 조건 없음. `handleListDocsV1` 은 금고 문서를 `title: ''`·`e2ee: true` 로 바꿀 뿐. 그래서 보고의 "24개가 어느 폴더인지 모름"은 목록은 다 왔으나 폴더 열이 없었다는 뜻이다. `cli/src/commands.ts` `ls` 의 `--folder` 는 `folderId` 가 **같은** 것만 남긴다(하위 폴더 문서는 빠짐)
- **검색·메타 단건 엔드포인트가 없다** — `worker/index.ts` `routes` 의 `/v1` 줄은 `docs`(GET 목록·POST·GET/PUT/DELETE `:id`·`:id/link`·`:id/folder`)·`folders`·`attachments`·`shared`·`me` 뿐. `GET /v1/docs/:id`(`handleGetDocV1`)는 `content` 를 늘 싣고 금고 문서면 403 `e2ee_doc`
- 목록·폴더로 충분하다: `V1DocSummary` 에 `folderId`·`version`·`pinnedAt`·`lineEnding`·`createdAt`·`updatedAt`·`e2ee`, `V1Folder` 에 `parentId`·`name`(금고 폴더도 이름은 평문 — `worker/folders.ts` `rowToFolder`)
- **`folders` 의 경로**는 `cli/src/output.ts` `humanFolderList` 가 `folderAncestors`(`src/lib/folderTree.ts`)로 저장된 부모 사슬을 모아 이름을 `/` 로 잇는다. 이스케이프 없음. 폴더 이름 검사 `worker/validate.ts` `isValidFolderName` 은 길이(1~200)만 봐서 `/` 가 든 이름이 저장될 수 있다
- `GET` 은 쓰기 한도에 세지 않는다 — `worker/writeGate.ts` `isWriteRoute` 가 `GET` 이면 `false`
- **크기 실측**(scratchpad, Node 24, 실제 모양의 요약 JSON): 문서 24개 목록 **5,791 B**(문서당 약 241 B), 문서 수 한도 10,000개(`worker/usage.ts` `DOC_COUNT_QUOTA`)면 **2,435,535 B**. `GET /v1/docs/:id` 는 본문만 최대 1,000,000 B(`E2EE_SERVER_MAX_CONTENT_BYTES`). 10,000개에 NFC 정규화 + `toLowerCase` + `includes` 거르기 **1.74 ms**
- NFD 로 들어온 `회의록` 은 NFC `회의록` 을 `includes` 하지 않고, 양쪽을 `normalize('NFC')` 하면 맞는다(같은 실측)
- 공유받은 문서는 `/v1/docs` 에 없고 `/v1/shared`(`V1SharedDoc`)에만 있다. 그 `folderId` 는 소유자의 폴더라 내 `folders` 로 경로를 못 만든다(`worker/grants.ts` `handleGetShared`)
- 도움말 `## 명령줄 도구` 절은 F-2118 7장 문구 변경 뒤 **600자**로 R2 상한에 닿는다(F-2118 7장 실측) — 이 명세는 그 절을 고치지 않는다

## 2. 명령과 인자 (계약)

### 2.1 명령 표 (F-2021 4.2 에 더하고 바꾸는 줄)

| 명령 | 인자·옵션 | 부르는 것 | 표준 출력(사람용) |
| --- | --- | --- | --- |
| `ls` | `[--folder <폴더id> \| --root \| --shared] [--path]` | `GET /v1/docs` (+ `--path` 면 `GET /v1/folders`) / `--shared` 는 그대로 | 기본 3열 그대로. `--path` 면 `{id}\t{updatedAt}\t{경로}\t{title}` |
| `find <제목>` | `[--folder <폴더id> \| --root] [--path]` | `GET /v1/docs` (+ `--path` 면 `GET /v1/folders`) | `ls` 와 같은 열 |
| `info <문서id>` | — | `GET /v1/docs` + `GET /v1/folders` (동시), 없으면 이어서 `GET /v1/shared` | 5.3 의 `{키}\t{값}` 줄 |

- `--root` 는 `folderId === null` 인 문서만. 이름은 `mv --root`(맨 위로 옮기기)와 같은 뜻으로 맞췄다. 기본이 이미 전부라 `--all` 은 두지 않는다
- `--folder` 의 뜻(그 폴더에 **바로** 든 문서만)은 바꾸지 않는다
- 순서는 늘 서버 순서(`updatedAt` 내림차순). `--path` 는 열만 더하고 순서를 바꾸지 않는다
- 요청은 동시에 보내고(`Promise.all`), 하나라도 실패하면 그 오류로 끝난다(표준 출력 비움, 종료 코드는 F-2021 4.5). 부분 결과를 찍지 않는다 — 스크립트가 반쪽 목록을 전부로 읽지 않게

### 2.2 사용법 오류 (종료 2, 요청 없음, 다음 줄 `{cli} {명령} --help 를 보세요.`)

| 명령 | 조건 | 문구 |
| --- | --- | --- |
| `ls` | `--shared` + `--folder` | `--shared 와 --folder 는 함께 쓸 수 없습니다.` (기존) |
| `ls` | `--shared` + `--root` | `--shared 와 --root 는 함께 쓸 수 없습니다.` |
| `ls` | `--shared` + `--path` | `--shared 와 --path 는 함께 쓸 수 없습니다.` |
| `ls`·`find` | `--root` + `--folder` | `--root 와 --folder 는 함께 쓸 수 없습니다.` |
| `find` | 위치 인자 0개, 또는 앞뒤 공백을 뗀 값이 빈 문자열 | `찾을 제목이 필요합니다.` |
| `find` | 위치 인자 2개 이상 | `제목은 하나만 줄 수 있습니다. 띄어쓰기가 든 제목은 따옴표로 감싸세요.` |
| `info` | 위치 인자가 정확히 1개가 아님 | `문서 id 가 필요합니다.` |

- 판정 순서는 표 위에서 아래. `ls` 의 `--shared`+`--folder` 를 맨 앞에 두어 기존 문구가 그대로 나온다
- `find` 의 여러 낱말을 이어 붙이지 않는 이유: 셸이 공백을 몇 개 먹었는지 CLI 가 모른다. 틀린 제목으로 조용히 0건을 내느니 멈춘다

### 2.3 도움말

- `COMMAND_NAMES`: `ls` 바로 뒤에 `find`, `info` (→ `login`·`logout`·`whoami`·`ls`·`find`·`info`·`get`·…·`link`·`syntax`)
- `COMMAND_DESCRIPTIONS`
  - `ls`: `내 문서 목록 (--path: 폴더 경로 열, --root: 맨 위 문서만, --shared: 공유받은 문서)`
  - `find`: `제목에 그 글자가 든 내 문서를 찾습니다 (대소문자 무시)`
  - `info`: `문서 정보(폴더 경로·판 번호·시각)를 내용 없이 보여 줍니다`
- `COMMAND_DETAILS.ls` (`put` 과 같은 방식, `ls --help` 에만):

## 3. 순수 함수 — `cli/src/docMeta.ts` (계약)

```ts
export function folderPathOf(folders: FolderLike[], folderId: string | null): string[] | null
export function titleMatches(title: string, query: string): boolean
export type DocWithPath<T extends V1DocSummary = V1DocSummary> = T & { folderPath: string[] | null }
export function withFolderPath<T extends V1DocSummary>(docs: T[], folders: FolderLike[]): DocWithPath<T>[]
```

- `folderPathOf`: `folderId === null` → `[]`(맨 위). 목록에 없는 폴더 → `null`. 그 밖은 `folderAncestors` 를 뒤집어 맨 위 → 안쪽 순의 **이름** 배열. 순환은 `folderAncestors` 가 끊는다
- `humanFolderList` 는 이 함수로 경로를 만든다 — `folders` 의 경로와 `ls --path` 의 경로가 같은 함수에서 나와 어긋날 수 없다(A2)
- `titleMatches`: 둘 다 `normalize('NFC')` 한 뒤 `toLowerCase()`, 제목이 질의를 부분 문자열로 품으면 참. 질의는 호출 전에 `trim()` 한다(args 에서). 빈 제목(금고 문서)은 늘 거짓 — `(금고 문서)` 표시 글자로도 찾지 않는다(표시용 글자지 제목이 아니다)
  - `toLocaleLowerCase` 를 쓰지 않는 이유: 실행 기계의 로캘(터키어 `I` 등)에 따라 결과가 달라진다
- `withFolderPath` 는 각 항목 끝에 `folderPath` 를 더한 **새** 객체를 돌려준다. 서버 필드는 그대로

## 4. 명령 함수 — `cli/src/commands.ts`

- `DocScope = { kind: 'all' } | { kind: 'folder'; id: string } | { kind: 'root' }` 를 받는다. `ls(cfg, scope, withPath)`·`find(cfg, query, scope, withPath)`·`info(cfg, id)`. 출력하지 않는다(F-2021 4.7)
- `info` 결과 타입:

```ts
export type DocInfo =
  | DocWithPath<V1DocSummary>
  | (V1SharedDoc & { folderPath: null })
```

- `info` 흐름: 목록·폴더 동시 요청 → 내 목록에 id 가 있으면 그것 → 없으면 `GET /v1/shared` 에서 찾음 → 그래도 없으면 `CliError('not_found', { id })`
- **목록 기반을 고른 이유**(`GET /v1/docs/:id` 후 `content` 버리기 대신): ① 금고 문서도 메타를 보인다(단건은 403) ② 본문(최대 1 MB)을 받지 않는다 ③ `info` 의 한 줄이 `ls --path` 의 그 행과 같은 데이터라 둘이 어긋나지 않는다. 대가: 문서가 아주 많으면 목록이 커진다(10,000개 약 2.4 MB, 근거). 지금 계정 규모(24개 5.8 KB)에서는 단건보다 작다
- 요청 수: 내 문서 2회, 공유받은 문서·없는 id 3회. 모두 `GET`(쓰기 한도와 무관)

## 5. 출력 — `cli/src/output.ts` (계약)

### 5.1 `{경로}` 칸

| 경우 | 사람용 | `--json` `folderPath` |
| --- | --- | --- |
| 맨 위 문서 | `/` | `[]` |
| 폴더 안 | `folders` 와 같은 표기 — 이름을 `/` 로 이음(`수업자료/바이브코딩 수업자료`), 이름마다 `stripControlChars` | 이름 배열(원문 그대로) |
| 목록에 없는 폴더(두 요청 사이 삭제 등) | `?` | `null` |

- 폴더 이름에 `/` 가 들어 있어도 이스케이프하지 않는다 — `folders` 출력을 바꾸지 않기 위해서다. 구분이 필요한 스크립트는 `--json` 의 배열을 쓴다(README 에 한 줄)
- 맨 위를 빈 칸이 아니라 `/` 로 둔 이유: 빈 칸은 탭 두 개가 붙어 사람 눈에 열이 밀려 보인다. `folders` 경로는 `/` 로 시작하지 않으므로 `/` 하나는 맨 위로만 읽힌다(이름이 정확히 `/` 인 폴더만 겹친다 — `--json` 으로 구분)

### 5.2 `ls`·`find`

- `humanDocList(docs, { path })` — `path` 가 없거나 거짓이면 지금 출력과 바이트까지 같다(기존 `output.test.ts` 그대로 통과). 금고 문서 제목 칸은 main 의 tweak 이 넣은 `(금고 문서)` 표시를 그대로 쓴다
- `--json`: `--path` 없으면 `V1DocSummary[]`(지금과 같음), 있으면 `DocWithPath[]`. `find` 도 같다
- 빈 결과: 표준 출력 비움(`--json` 이면 `[]`), 종료 0. 표준 오류는 `ls` 기존 `문서가 없습니다.`, `find` 는 `제목으로 찾은 문서가 없습니다: {질의}`(질의는 `stripControlChars`)

### 5.3 `info` 사람용

키는 `--json` 필드 이름과 같게 둔다 — 사람용과 `--json` 사이를 오가며 헷갈리지 않게(`version` 라벨 tweak `b42c6cf` 와 같은 방향). 줄마다 `{키}\t{값}\n`, 이 순서:

| 키 | 값 |
| --- | --- |
| `id` | id |
| `title` | 제목(`stripControlChars`). 금고 문서는 `(금고 문서)` |
| `folder` | 5.1 의 사람용 경로. 공유받은 문서는 `-` |
| `version` | 정수 |
| `updatedAt` | `isoUtcSeconds` |
| `createdAt` | `isoUtcSeconds` |
| `lineEnding` | `lf` 또는 `crlf` |
| `pinnedAt` | `isoUtcSeconds`, 없으면 `-` |
| `e2ee` | `true` 또는 `false` |
| `role` | 공유받은 문서만 — `편집`/`보기`(기존 `ROLE_LABEL`) |
| `ownerEmail` | 공유받은 문서만 — `stripControlChars` |

- `--json`: `DocInfo` 한 줄. 서버 필드(`viaFolder` 포함)는 그대로, `folderPath` 만 더한다

### 5.4 시각 표기 — 바꾸지 않는다

사람용은 지금처럼 ISO 8601 UTC 초(F-2021 4.2 — 시간대에 따라 출력이 달라지지 않게), `--json` 은 서버 epoch ms(API 계약). 둘이 다르다는 것을 `ls --help`(2.3)·README(7장)에 적어 헷갈림만 없앤다. 현지 시각 열은 넣지 않는다 — 실행 기계 시간대에 따라 같은 명령의 출력이 달라진다

## 7. `cli/README.md`

- 명령 표의 `ls [--folder <id>]` 행을 `ls [--folder <id>\|--root] [--path]` | `내 문서 목록. --path 는 제목 앞에 폴더 경로 열(맨 위 문서는 /), --root 는 폴더에 들지 않은 문서만` 으로 바꾸고, 그 아래 두 행
  - `find <제목> [--folder <id>\|--root] [--path]` | `제목에 그 글자가 든 내 문서(대소문자 무시)`
  - `info <id>` | `문서 정보(제목·폴더 경로·판 번호·시각)를 내용 없이 보여 줍니다`
- 표 아래 `모든 명령은 …` 문장 뒤에: `사람용 출력의 시각은 UTC(예: 2026-10-03T04:05:06Z)이고, --json 의 시각 필드는 1970년부터의 밀리초입니다. 폴더 이름에 / 가 든 경우 경로를 정확히 나누려면 --json 의 folderPath 배열을 쓰세요.`
