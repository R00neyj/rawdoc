# F-4014 worker 접근 제어·악용 방지 보강 묶음

상태: 승인 — 사용자 상시 지시("p2까지 수정", 9장 Q1·Q2 기본값대로, 별도 검토 없음). 코드리뷰 발견 여섯 중 넷을 고친다(①② 두 번째 벽, ④ 등록 관문 IP 단위, ⑥ 한도 경합). ③⑤는 설계대로라 뺀다(2장). 모두 node 단위, e2e 없음(브라우저만 보이는 동작이 없다)

## 근거 (2026-10-19 HEAD `b2854f6` 뒤, 이름으로 찾는다)
- ① 금고 문서를 거르지 않는 공개 질의 다섯: `links.ts` `handlePublicGetDoc`, `publicPage.ts` `renderPublicPage` 문서 갈래, `attachments.ts` `handlePublicGetAttachment`·`handlePublicGetDocSetAttachment`·`handlePublicGetFolderAttachment`. 나머지 공개 질의(`handlePublicGetDocSet`·`…DocSetDoc`·`…FolderDoc`, `githubImages.ts` `publicDoc`)는 이미 `e2ee_key IS NULL`. **지금 도달할 길은 없다** — 금고 옮기기가 같은 batch 에서 링크를 거둔다(`e2eeDocs.ts` `REVOKE_LINKS_SQL`, `WROTE_KEY` 조건). 첨부 셋은 암호문에 `attachments/{id}.` 가 나올 수 없어(`.` 은 base64 밖) 더 멀다. `handlePublicGetDocSet` 의 "두 번째 벽"(F-401 X14)과 같은 이유로 맞춘다
- ② `links.ts` `subtreeIds` 는 링크 폴더가 평문 폴더 목록에 없으면 `[folderId]` 를 돌려줘 `handlePublicGetFolderDoc`·`handlePublicGetFolderAttachment`·`githubImages.ts` `handlePublicFolderGithubImg` 가 그 id 를 트리로 믿는다(`handlePublicGetFolder` 만 404). 역시 지금 도달 길은 없다 — 폴더 지우기 둘(`deleteFolderContents`·`trashFolder`)이 같은 batch 에서 링크를 거두고(`targetShareCleanupStatements`), 금고 켜기가 `REVOKE_FOLDER_LINKS_SQL` 을 같은 batch 에 둔다. `publicPage.ts` 폴더 갈래도 `e2ee` 를 안 본다
- ④ `admitClientRegistration` 은 전역 하루 500(`oauth_register_gate`)뿐 — 비인증 한 곳이 500번 보내면 그날 모든 MCP 커넥터의 새 연결이 429. Rate Limiting 바인딩은 주기가 10·60초만이라 하루 단위를 못 센다 → D1 표. `WRITE_LIMITER`(분당 120)를 IP 키로 같이 쓰는 안(`cspReport.ts` `limited` 선례)은 한 IP 가 4분 남짓에 500을 다 쓴다 — 안 씀. 다음 마이그레이션 번호 0030
- ⑥ `storeAttachment` 와 `handleUploadAttachment` 금고 갈래는 `getUsedBytes` → R2 put → `INSERT` 라 동시 요청이 함께 300MB 를 넘는다(요청마다 최대 `MAX_ATTACHMENT_BYTES`). `handleCreateToken` 도 `COUNT(*)` → `INSERT` 라 10개를 넘는다. 원자적 조건 쓰기 선례: `signup_gate`·`REGISTER_GATE_SQL`, 경합에 진 쪽 하루 +1 은 `handleUpdateFolder` 켜기("하루는 이미 +1 이다")

## 2. 빼는 것 (오탐, 설계대로)
- **③ 폴더 공유 스스로 나가기의 즉시 재검증 없음**: F-4002 3.1 표 "폴더 나가기 — 지연 허용(최대 약 90초). 본인이 버린 권한이라 막을 제3자가 없다" + B7·F-3011 L3(`grantsLeave.test.ts` "알리지 않음", `revalidateFanout.test.ts` "폴더 나가기는 0번")이 정한 동작. 나간 사람의 열린 연결은 나가기 전 권한 그대로라 새로 얻는 것이 없다
- **⑤ edit 연결의 Yjs 직접 댓글 쓰기가 분당 30을 안 거침**: 분당 30은 처음부터 view 명령 한도다(F-500 2.5 "view 명령 속도", 3.2 "edit 이상은 직접 쓰기 + 사후 고치기"). edit 쪽 상한은 `planCommentFixes` 5단계(문서 500·스레드 답글 100)가 이미 건다. 알림은 받는 사람마다 넣을 때 300개로 깎이고(`TRIM_NOTIFICATIONS_SQL`), 지운 댓글의 알림은 같은 batch 에서 지워져 쌓이지 않는다. 연결별 속도를 Yjs 에 걸면 오프라인에서 단 댓글이 다시 붙을 때 한 sync 로 몰려와 30을 넘는 만큼 지워진다(F-500 사용자 결정 1 위반) — 고치지 않는다(5장 Q2)

## 3. 동작
### 3.1 ①② 두 번째 벽
- ① 다섯 질의에 `AND e2ee_key IS NULL`. 금고 문서면 공개 JSON 은 지금 "문서 없음" 응답(`handlePublicGetDoc` 는 `publicMissing` 이 금고를 이미 `not_found` 로), 첨부는 404 `not_found`, `renderPublicPage` 는 `null`(앱이 "링크를 찾을 수 없습니다")
- `renderPublicPage` 폴더 갈래도 `AND e2ee = 0`
- ② `subtreeIds` 가 링크 폴더가 목록에 없으면 **빈 배열**(`descendantFolderIds` 그대로). 그러면 세 폴더 핸들러가 404, `publicMissing` 의 `reachable` 도 거짓이라 `not_found`(휴지통 문서여도 `deleted` 를 알리지 않는다)
### 3.2 ④ 등록 IP 관문
```sql
CREATE TABLE IF NOT EXISTS oauth_register_ip (ip_key TEXT PRIMARY KEY, day TEXT NOT NULL, count INTEGER NOT NULL);
```
- `REGISTER_IP_DAILY_LIMIT = 20`(`oauthServer.ts` export). 키 `registerIpKey(header: string | null): string`(export, 순수): `CF-Connecting-IP` 가 IPv4 면 그대로, IPv6 면 펼친 뒤 앞 네 묶음(/64, 소문자, 각 묶음 앞 0 제거, `:` 로 이음), 없거나 해석 못 하면 `'unknown'`(센다 — 실서비스에서는 Cloudflare 가 늘 붙인다)
- `admitClientRegistration(request, env)`: ① IP 문장 하나 — `INSERT … VALUES (키, 오늘, 1) ON CONFLICT(ip_key) DO UPDATE SET count = CASE WHEN day = 오늘 THEN count + 1 ELSE 1 END, day = 오늘 WHERE day <> 오늘 OR count < 20`. 바뀐 행 0 → 지금과 **같은** 429 몸통·`Retry-After`, 전역 문장은 돌지 않는다(넘친 IP 가 전역 몫을 먹지 않게) ② 통과하면 지금 전역 문장. 둘 다 `run` 한 번씩, batch 아님
- 정리: `cleanupOAuth` batch 에 `DELETE FROM oauth_register_ip WHERE day < ?`(오늘 `utcDay`)
### 3.3 ⑥ 한도 경합
- **사전 검사는 둔다**(뻔한 초과는 R2 에 쓰지 않는다). 그 위에 **넣기 문장 자체가 한도를 다시 본다**: `INSERT … SELECT … WHERE (그 사람 SUM(size)) + 이번 크기 <= ATTACHMENT_QUOTA_BYTES` — 평문(`storeAttachment`)·금고 갈래 둘 다. 지금 바인딩 여덟(금고는 여덟 + 리터럴 1)의 순서를 유지하고 한도 인자는 뒤에 붙인다
- 넣기가 0행이면: 같은 `(owner_id, id)` 행이 지금 있는지 한 번 읽어 **없을 때만** 방금 올린 R2 키를 지운다(같은 id 재전송이 이긴 경우 그 객체를 지우지 않게). 응답은 507 `quota_exceeded`, `used` 는 다시 읽은 값. `quotaPushInBackground` 는 성공 때만. 같은 batch 의 하루 사용량 +1 은 남는다(선례대로)
- 같은 batch 의 F-4012 연결 문장(`attachmentLinkStatement`)은 `… SELECT … WHERE EXISTS (SELECT 1 FROM attachments WHERE owner_id = ? AND id = ?)` 로 — 넣기에 진 업로드가 연결 행을 남기지 않는다. 200 갈래(행이 이미 있음)에서는 참이라 F-4012 동작 그대로
- 토큰: `INSERT INTO api_tokens … SELECT … WHERE (살아 있는 토큰 수) < MAX_TOKENS`, 0행이면 지금과 같은 409 `{ error: 'too_many', limit: 10 }`. 사전 `COUNT` 는 둔다, 바인딩 여섯 순서 유지
