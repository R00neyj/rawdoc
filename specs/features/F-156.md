## 2. 요구사항

### 2.1 원문 형식
넣는 원문은 항상 아래 3줄이다. 줄은 에디터 안에서 `\n`, 저장·내보내기에서 문서 `lineEnding` (Q9)

```
<div align="center">
  <img src="attachments/0f3a9c2e7b1d4a58.png" alt="다이어그램" width="480">
</div>
```

- `align`: `left` / `center` / `right`. 넣을 때 `center`
- `src`: `attachments/{id}.{ext}`. id 는 소문자 16진수 16자(`crypto.getRandomValues` 8바이트), 저장소에 이미 있으면 다시 뽑는다. ext 는 `png` `jpg` `gif` `webp`
- `alt`: 끌어놓은 파일은 파일명(확장자 제외), 붙여넣기는 `이미지`. 줄바꿈은 공백, 100자에서 자름. `&` `"` `<` `>` 는 `&amp;` `&quot;` `&lt;` `&gt;`
- `width`: 정수 px. 넣을 때 `min(이미지 가로, 문서 칸 글자 폭)`. 글자 폭은 넣는 순간 `.cm-content` 안쪽 폭(좌우 padding 제외)을 내림
- `img` 줄 들여쓰기는 공백 2칸 고정 (F-154 들여쓰기 설정과 무관)

**해석 규칙** (`parseImageBlock`, F-157·F-158 도 이것만 쓴다)
- 정확히 3줄(각 줄 끝 공백 무시): `<div align="left|center|right">` / 앞 공백 허용 `<img …>` 또는 `<img … />` / `</div>`
- `img` 속성은 `src`(필수, 위 형식), `alt`(선택), `width`(선택, 숫자 1~4자리)만, 각 1번, 순서 무관, 큰따옴표. 그 밖의 속성·태그·글자가 있으면 이미지 블록이 아니다 (원문 그대로)
- `alt` 는 위 4개 문자 참조만 되돌린다
- `extractAttachmentRefs(content)`: 내용 안 **모든** `attachments/{16hex}.{ext}` 문자열의 id 집합. 블록 해석과 무관하게 넓게 잡는다 (원문을 고치다 형식이 깨져도 첨부를 지우지 않기 위해서다)

### 2.2 받는 형식과 검사
순서대로 검사하고 처음 걸린 알림 하나만 띄운다 (warn). 여러 장 중 일부만 걸리면 나머지는 넣고 알림은 `이미지 {N}장을 넣지 못했습니다. {첫 사유}`

| 검사 | 기준 | 알림 |
| --- | --- | --- |
| 크기 | 5MB(5 × 1024 × 1024 바이트) 초과 | `이미지는 한 장에 5MB 까지 넣을 수 있습니다.` |
| 형식 | 앞부분 바이트(시그니처)가 PNG·JPEG·GIF·WebP. `File.type`·확장자는 믿지 않는다. SVG 는 받지 않는다 | `PNG·JPEG·GIF·WebP 이미지만 넣을 수 있습니다.` |
| 가로·세로 | 헤더에서 읽음(PNG IHDR, GIF 논리 화면, JPEG SOF, WebP VP8·VP8L·VP8X). 읽지 못하면 형식 실패. 한 변 10000px 초과 또는 넓이 4000만 px 초과 | `이미지가 너무 큽니다. 가로·세로 10000px 이하만 넣을 수 있습니다.` |
| 저장 | IndexedDB 쓰기 실패 (용량 초과 포함) | `저장 공간이 부족해 이미지를 넣지 못했습니다.` (error) |

- 디코딩(`createImageBitmap`·`img`)으로 크기를 재지 않는다. 압축 폭탄 이미지를 메모리에 풀지 않기 위해서다
- 원본 바이트를 그대로 저장한다. 변환·축소·EXIF 제거는 M1 에서 하지 않는다 (M2 WebP 변환, `specs/product.md` 7장)

### 2.3 저장소
- IndexedDB `md-docs` 버전 3 에서 `attachments` 스토어 추가 (keyPath `id`). 기존 문서·폴더는 그대로. 막힘 처리는 F-136 3.3 그대로
- 레코드 `{ id, mime, ext, size, width, height, createdAt, blob }`. 문서와 연결 필드 없음 (여러 문서가 같은 id 를 써도 된다)
- 인터페이스는 `specs/architecture.md` 2장. 메모리 저장소도 같은 모양(새로고침하면 사라짐)

### 2.4 붙여넣기
- 편집·원문 모드 에디터에서 `paste` 의 `clipboardData.files` 에 이미지가 있으면 받는다
- **`text/plain` 이 비어 있지 않으면 글자 붙여넣기가 이긴다** (엑셀·워드 복사에 딸려 오는 그림 조각을 넣지 않기 위해서). 이미지는 무시
- 보기 모드·공유 화면·빈 상태에서는 아무것도 하지 않는다

### 2.5 끌어놓기 (F-145 와의 관계)
- 끌기 데이터가 **이미지 파일만**이면 F-145 덮개를 띄우지 않는다. 에디터 위에서는 CM6 `dropCursor` 로 놓을 자리를 보인다
- 편집·원문 모드 에디터 안에 놓으면 놓은 좌표(`posAtCoords`) 위치로 2.6 에 넣는다. 파일 순서대로
- 에디터 밖(사이드바·상단바·보기 모드 화면)에 놓으면 넣지 않고 알림(info) `이미지는 편집 영역에 놓아 넣을 수 있습니다.`
- `.md` 와 이미지가 섞이면 F-145 대로 `.md` 만 가져오고 알림(info) `.md 파일만 가져왔습니다. 이미지는 따로 놓아 주세요.`
- F-145 2.1 받지 않는 때(대화상자·공유 화면·저장소 없음)는 이미지도 받지 않는다. 메모리 저장소는 받는다

### 2.6 넣는 위치
- 기준 위치: 붙여넣기는 선택 끝(`main.to`), 끌어놓기는 놓은 좌표. 선택 글자는 지우지 않는다
- 기준 위치 줄이 **비어 있으면 그 줄**에, 아니면 **그 줄 끝 다음**에 블록을 둔다
- 블록 위 줄이 있고 비어 있지 않으면 빈 줄 하나를 앞에, 블록 아래 줄이 있고 비어 있지 않으면 빈 줄 하나를 뒤에 넣는다 (HTML 블록은 빈 줄에서 끝나므로)
- 여러 장은 빈 줄 하나를 사이에 두고 이어 넣는다. **한 트랜잭션** (Ctrl+Z 한 번에 전부 사라짐), `userEvent: 'input.paste'` 또는 `'input.drop'`
- 커서는 마지막 블록 `</div>` 다음 줄 시작
- 넣지 않는 곳: 펜스 코드블록 원문 안, 표 칸 편집 중, 프론트매터 범위 안. 알림(info) `이 위치에는 이미지를 넣을 수 없습니다.`
- 목록·인용 줄 뒤에 넣으면 그 목록·인용은 블록 앞에서 끝난다 (허용)
- 저장(비동기) 사이에 문서가 바뀌면 기준 위치를 그 변경에 맞춰 옮긴다. 한글 조합 중이면 조합이 끝난 뒤 넣는다
- decoration 이 아니라 사용자 동작으로 원문을 바꾸는 것이다. 넣은 뒤 자동 저장(F-110) 흐름 그대로

### 2.7 안 쓰는 첨부 정리
- 앱 시작 후 문서 목록을 읽고 나서 1회(`requestIdleCallback`, 없으면 `setTimeout` 2초): 모든 문서 `content` 의 `extractAttachmentRefs` 합집합에 없고 `createdAt` 이 24시간 이전인 첨부를 지운다
- 24시간 여유는 붙여넣고 지운 뒤 실행 취소, 저장 전 다른 문서로 잘라 붙이기를 보호하기 위해서다
- 문서 삭제 때는 바로 지우지 않는다. 메모리 저장소는 정리하지 않는다
- 정리 실패는 조용히 넘긴다 (알림 없음)
