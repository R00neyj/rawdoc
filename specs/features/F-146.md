## 3. 요구사항

### 3.1 좌우 여백 클릭
- 편집·원문 모드에서 좌우 여백을 누르면 커서를 옮기지 않고 **편집기 포커스를 없앤다** (포커스는 문서 바디로. 다른 요소로 옮기지 않는다)
- 드래그로 글자를 선택하기 시작하는 동작도 좌우 여백에서는 시작하지 않는다
- 그대로 두는 것: 문서 칸 안의 빈 곳(줄 끝 오른쪽, 위아래 여백 — F-143 3.10)을 누르면 CM6 기본대로 가장 가까운 위치에 커서. 거터 클릭 동작 그대로
- 좌우 여백 위 휠 스크롤은 그대로 된다 (F-143 3.8)

### 3.2 편집기 포커스가 없을 때 표시 — 보기 모드에 가깝게
- 편집 모드에서 편집기 포커스가 없으면 **활성 줄이 없는 것으로 본다**: 커서·선택이 닿은 줄도 기호를 숨긴 프리뷰로 보인다(제목 `#`, 굵게 `**`, 링크 주소, 코드블록·표 원문 펼침, 콜아웃 머리 등 전부)
- 커서·현재 줄 강조·선택 영역 표시를 보이지 않게 한다
- 줄 번호 거터는 그대로 (보기 모드와 "거의" 같음)
- 편집기 포커스가 돌아오면(문서 칸 클릭, Tab, 단축키로 포커스) 지금처럼 커서 줄이 드러난다. 선택(`EditorState.selection`)은 포커스를 잃어도 유지되어, 키보드로 돌아오면 이전 위치에서 이어진다
- 원문 모드는 표시가 같으므로 커서·선택 표시만 숨긴다
- 포커스 판정은 표 칸 편집 중(하위 `EditorView` 에 포커스)·자동완성 목록 조작 중을 **포커스 있음**으로 본다. 표 칸 편집이 포커스 판정 때문에 끝나거나 표가 원문으로 바뀌면 안 된다
- 사이드바·상단바·대화상자로 포커스가 가도 같은 규칙 (포커스 없음 → 프리뷰 표시)
- decoration 만 바꾼다. 문서 내용·선택 상태를 바꾸는 트랜잭션을 만들지 않는다

### 3.3 한글 조합
- 조합 중에 좌우 여백을 누르거나 포커스를 잃으면, 조합 글자가 한 번만 확정되고 보류했던 재계산을 따라잡은 뒤 비포커스 표시로 바뀐다 (`src/editor/composition.js` 규칙)

### 3.4 위키링크 자동완성 목록 여백 (2026-09-14 추가)
- 근거: 사용자 요청 + 스크린샷 "위키링크 바로가기 뜨는게 어색. 좌우 패딩은 너무 크고 위아래 패딩은 없는 수준. 상하좌우 비슷하도록"
- 원인(코드 읽기): `wikilink.css` 의 `.cm-tooltip-autocomplete ul li { padding: 4px 8px }` 가 CM6 기본 테마의 항목 여백(위아래 1px 수준)보다 구체성이 낮아 적용되지 않는다. 왼쪽이 넓어 보이는 것은 CM6 가 항목 앞에 두는 종류 아이콘 자리(`.cm-completionIcon`)로 추정. 실측으로 확정
- 수정: 사이드바 `⋯` 메뉴 목록(`.item-menu-list`)과 같은 모양
  - 목록 안쪽 여백 6px, 항목 여백 7px 9px, 항목 모서리 `--radius-control`, 글자 13px
  - 종류 아이콘 자리를 없앤다(위키링크 자동완성은 종류 구분이 없음)
  - 선택 항목 바탕은 지금처럼 `--accent-soft`
- F-141 3.5 서체 규칙과 같은 방식(클래스 반복)으로 구체성을 확실히 이긴다. `!important` 금지
