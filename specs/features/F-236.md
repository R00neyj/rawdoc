# F-236 중첩 목록 깊이 안내선

작성일: 2026-09-16
상태: 사용자 요청(2026-09-16 메모 "2회 이상 중첩시 폴더 구조처럼 | 라인으로 어디까지 깊이인지 표시해야함", 확인 질문에 "2단계부터(첫 중첩)"로 답함). 사용자 승인 후 구현 완료 — 1~5장은 `f56aa82`, 6장 후속은 `f13b55f` 로 반영(2026-09-20 상태 표기 정정, 구현 자체는 그 이전에 끝나 있었음)
근거: F-226(보기 모드 목록을 편집 모드에 맞춤), F-152 2.3(편집 모드 목록 내어쓰기, 실측 들여쓰기 `--md-list-indent`), 사이드바 폴더 가이드 선(`src/styles/app.css` `.tree-group::before`, `--muted`) — 같은 시각 개념이지만 문서 내용 쪽 토큰(`--md-border-muted`)을 쓴다(사이드바는 앱 셸 토큰, 목록은 문서 토큰 — F-226 근거 F-216 2.3 과 같은 구분)

## 2. 지금 상태

- 보기 모드(`markdown.css`): 중첩 `ul ul`·`ul ol`·`ol ul`·`ol ol` 은 `padding-left` 만 다르고(0.4625em·0.6875em, F-226 A1 실측) 단계 구분선은 없다
- 편집 모드(`preview.css`·`lines.ts`): 목록 줄은 `md-list-line` 클래스 + 줄마다 실측 `--md-list-indent` px 값(`listIndentPreview`, F-152 2.3)만 있고, 몇 단계 중첩인지 정보는 계산하지 않는다
- 중첩이 깊어지면(3단계 이상, 즉 최상위 아래로 목록이 2번 중첩됨) 어느 항목이 어느 조상 아래인지 눈으로 구분하기 어렵다는 사용자 지적

## 3. 요구사항

- 대상 줄: **목록 깊이 2단계 이상**(최상위 목록 = 1단계, 그 안에 중첩된 첫 목록부터 2단계)
- 2단계 이상인 목록 항목의 왼쪽에, 그 항목보다 얕은 각 조상 단계마다 세로 안내선을 하나씩 그린다(1단계 조상 선, 2단계 조상 선, … — 사이드바 폴더 가이드 선과 같은 개념)
- 선 색은 `--md-border-muted`(문서 내용 쪽 약한 경계 토큰), 두께 1px
- 안내선은 표시만 바꾼다 — 원문(마크다운 들여쓰기 공백)은 건드리지 않는다(CLAUDE.md 불변조건, decoration 은 표시만)
- 대상 범위:
  - 보기·공개 보기 모드: `:is(.app-shell, .public-view) .markdown-body` 안 중첩 `ul`/`ol`
  - 편집 모드(라이브 프리뷰만, 원문 모드는 F-124 1장 원칙대로 모양을 바꾸지 않는다): `.cm-host .cm-editor[data-view='live']` 안 목록 줄
- 안내선은 그 조상 목록이 이어지는 세로 범위(첫 항목 위~마지막 항목 아래)만 그린다 — 조상 목록 밖(형제 항목 사이 등)까지 새지 않는다
- 가로 위치: 각 조상 단계 안내선은 그 조상 단계 글머리·번호 기호의 **가로 가운데**에 맞춘다 (2026-09-18 사용자 "선도 불릿포인트 처럼 가운데 정렬" — 처음 구현은 기호 왼쪽이었다). 편집 모드는 조상 줄의 실측 들여쓰기를 따라간다(값이 고정 배수가 아니므로 고정 em 계산으로 못 맞출 수 있다 — 구현 조사 필요, 아래 4장 참고)

## 4. 구현 조사가 필요한 부분

- 편집 모드는 각 줄의 들여쓰기를 고정 단계 폭이 아니라 **그 줄의 실제 앞 공백을 DOM 에서 재서** `--md-list-indent` 로 매단다(F-152 2.3, `listIndentPreview`). 안내선을 조상 단계의 기호 위치에 맞추려면 지금처럼 "이 줄 자신의" 값뿐 아니라 "조상 목록이 시작하는 줄의" 들여쓰기값도 필요하다
  - `listIndentPreview`(`lines.ts` 574번줄 근처)를 확장해 줄마다 조상 단계별 x 값 배열을 같이 재는 방법, 또는 조상 목록의 첫 줄 값을 자식 줄에서 참조하는 방법 등을 구현 때 정한다
  - 보기 모드는 실측이 필요 없다(정적 `padding-left` 체계 그대로, 중첩 `ul`/`ol` 자신에 `position: relative` + `::before` 로 사이드바 `.tree-group::before` 와 같은 방식이면 된다) — 편집 모드보다 먼저 하고, 편집 모드는 그 결과를 기준으로 맞춘다(F-226 과 같은 순서)

## 6. 후속 — 안내선을 기호 가운데로 (2026-09-18)

첫 구현은 3.2 옛 문구대로 조상 기호의 **왼쪽**에 선을 세웠다. 사용자 확인(H108)에서 "선도 불릿포인트 처럼 가운데 정렬" 요청을 받아 위 3.2·A2·A5 를 고쳤다. 이 절만 다시 구현한다.

### 6.1 소유 파일

| 파일 | 변경 |
| --- | --- |
| `src/editor/preview/lines.ts` | 안내선 x 를 조상 기호 가로 가운데로 |
| `src/styles/markdown.css` | 보기 모드 `::before` 의 `left` 를 기호 가운데로 |
| `e2e/listGuide.spec.js` 또는 기존 F-236 e2e 파일 | A2·A5 기대값 갱신 |

### 6.2 편집 모드 (`lines.ts`)
- 지금은 `view.coordsAtPos(markFrom, 1)` 의 `left` 만 쓴다. 기호 글자의 오른쪽 끝도 재서 가운데를 쓴다 — 기호 길이는 `-`(1자), `1.`(2자), `10.`(3자)로 다르므로 **고정값을 쓰지 않고 문서에서 기호 끝 위치를 구한다**
- 선은 1px 이라 `round(가운데) - 0.5` 가 필요한지 실측으로 판단한다. 좌표를 하나라도 못 재면 지금처럼 안내선 없이 들여쓰기만 둔다
- 기존 `background-image`·`background-position` 방식을 그대로 쓴다(decoration 은 표시만 — 불변조건)

### 6.3 보기 모드 (`markdown.css`)
- 지금 `left: -2em` 은 기호가 서는 칸의 왼쪽이다. 기호 글자 가운데로 옮긴다
- 값은 눈대중으로 정하지 않고 `npm run measure` 로 글머리 기호의 좌·우 x 를 재서 맞춘다(둥근 점 `•` 과 `1.` 이 다르면 `ul`·`ol` 을 나눠 잡는다)
- 편집 모드와 보기 모드가 같은 자리에 오는지 A5 기준(±4px)으로 확인한다
