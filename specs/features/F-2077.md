### Q1. `setDocSession` 을 반환하나 — **기본값: 반환한다**

- 이유: 온라인 재시작 effect 본문이 `setDocSession((cur) => …)` 과 `setOpenDoc(null)` 을 부른다. 글자 그대로 옮기려면 setter 가 필요하다. F-2076 Q8 이 이 effect 를 `useLiveNotices` 뒤 `useLiveRoomDoc` 에 두기로 했으므로 세션 상태 setter 가 훅 밖으로 나간다
- 다른 쪽(`useDocSession` 이 `restartOnOnline(seq)` 같은 좁은 콜백을 반환): setter 가 새지 않는다. 대신 effect 본문이 바뀌어 옮기기가 아니게 되고(A5 에 빨강·초록 약 8줄), `useCallback` 하나가 새로 생긴다

### Q2. 절 머리 주석을 어디에 두나 — **기본값: 원래 절 머리는 `useDocSession` 본문 첫 줄로 옮기고, App 에는 새 절 머리 두 줄(5.3)**

- 이유: 원래 머리 `… local·view 는 여기서, 나머지는 아래 effect 가 …` 는 옮겨 가는 코드를 설명한다. App 에 두면 "여기서"·"아래" 가 틀린 말이 된다. F-2070 이 같은 처리를 했다
- 다른 쪽(원래 머리를 App 에 두고 훅에는 파일 머리만): A5 초록이 1줄 준다. 대신 App 주석이 없는 코드를 가리킨다

### Q3. 새 타입을 만드나 — **기본값: `liveEditorOption` 은 기존 `LiveEditorOptions`(`src/editor/createEditor.ts`)를 쓴다**

- 이유: 같은 모양의 타입이 이미 있고, `useContextMenu.ts` 가 같은 모듈에서 타입을 가져온 선례가 있다. 새 이름을 만들면 두 타입이 따로 바뀔 수 있다
- 다른 쪽(`useLiveRoomDoc.ts` 에 새 타입): `src/editor` 의존이 없다. 대신 같은 모양이 두 벌이 된다

### Q4. 블록 c·`handleResumeFailed` 에 특성 테스트를 두나 — **기본값: 두지 않는다**

- 이유: 두 갈래 모두 md-yjs 가 없거나 기록 읽기가 실패해야 닿는다(가정 절). e2e 에서 md-yjs 를 막으면 부팅·다른 흐름도 바뀌어 "지금 동작 고정" 이 아니게 된다. 블록은 글자 그대로라 A5 이동색으로 판정한다
- 다른 쪽(`page.addInitScript` 로 `indexedDB.open('md-yjs')` 를 실패시키는 C3): 블록 c 를 직접 본다. 대신 새 우회가 부팅 쪽(`openYjsStore` 실패 처리)까지 건드려 무엇을 고정하는지 흐려지고, 옮기기 전 초록을 보장할 근거가 없다(실측 못 함)

### Q5. e2e 에 로드맵 밖 두 테스트를 더하나 — **기본값: 더한다(8장 둘째 명령)**

- 이유: `F-2056 A8` 은 `liveChangedAtRef` 를, `F-505 E12 두 창` 은 `updatedAt` effect 의 댓글 거르개를 보는 유일한 e2e 다. 로드맵에서 빼는 것이 아니라 더하는 것이라 개요와 부딪치지 않는다(F-2074 Q5 와 같은 판단)
- 다른 쪽(로드맵 그대로): 두 갈래는 `verify:full`(PC)에서만 본다

### Q6. `commentRail.ts`·`useLiveDoc.ts` 의 "App 의 docPath"·"App 이 … 다시 판정한다" 주석을 고치나 — **기본값: 고치지 않는다**

- 확인한 것: `src/app/commentRail.ts` `docPath: … // App 의 docPath …`·`liveReadOnly: … // App 의 docSession.readOnly …`, `src/app/useLiveDoc.ts` `onResumeFailed` 앞 주석 `… App 이 기록 없음으로 다시 판정한다 …`
- 이유: F-2059 3.6 은 `App.tsx` 라는 파일 이름 언급만 고치게 했다. 값은 여전히 App 스코프 이름이라 뜻이 맞고, 고치면 소유 표 밖 파일이 는다
- 다른 쪽(`useDocSession` 으로 고친다): 이름 검색이 정확해진다. 소유 표에 두 파일이 더해진다

### 관찰 (이 조각은 고치지 않는다 — F-2059 7장 성격, 판정은 사용자)

1. **블록 c 는 e2e 환경에서 효과가 드러나지 않는다.** `everLiveIds` 는 `useEditorSync` 의 `openLoad` 에서 "실시간이었던 폴백은 서버 본문 먼저" 에만 쓰인다. md-yjs 가 있으면 한 번 동기화한 문서는 다음에 재개 세션으로 열려(`hasLocalState`) 첫 동기화 전 폴백으로 가지 않는다. 그래서 이 갈래는 md-yjs 를 못 연 브라우저(메모리 대체)에서만 뜻이 있다. 코드를 읽어 판단한 것이고 실행해 보지 않았다
2. `restartDocSession` 과 온라인 재시작 effect 가 **같은 세션 초기화 객체 리터럴**(`seq + 1, path: null, …, persist: null`)을 두 벌 갖는다. 한쪽에 필드가 늘면 다른 쪽이 빠질 수 있다(F-2059 D5 와 같은 종류). 옮기기만 하므로 그대로 둔다 — D17 후보

기본값으로 정한 것(승인 시 확정): 파일 이름·경계(F-2076 2.3·Q8), 5장 인자·반환 이름 = 지금 App 이름, `createdHereRef`·`liveChangedAtRef` 는 App 에 남기고 호출 위로(2.3), deps 여섯 줄(4.2), Q1~Q6, C1·C2(7.2), e2e 세 명령(8장), 사람 확인 한 줄(7.4).
