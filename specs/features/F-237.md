## 2. 범위

- 대상은 F-211 폴더 공개 보기(`#/p/f/{토큰}[/{문서 id}]`)뿐
- 대상 문서 풀: 그 공개 폴더 및 하위 폴더(F-211 §2.2 와 같은 2단계까지) 안 문서만. `/pub/folders/:token` 응답(`folder.docs`)에 애초에 그 범위 문서만 담겨 오므로 폴더 밖 비공개 문서 제목이 새어나갈 위험은 없다 — 별도 방어 코드 불필요

## 3. `renderMarkdown` 인터페이스 변경

- 기존: `resolveWikiLink: (target) => id | null`, href 는 `renderMarkdown` 내부가 `#/d/${id}` 로 고정 생성(F-131 §4)
- 변경: `resolveWikiLink: (target) => href | null`. 찾으면 href 문자열, 못 찾으면 `null`(→ `wikilink--missing`)
- `App.tsx` 호출부: `resolveWikiTarget(target, docs)?.id` 로 구한 id 를 `` `#/d/${id}` `` 로 감싸 돌려주도록 한 줄만 바뀐다. 최종 렌더 결과(F-131 A3)는 지금과 같아야 한다
- 옵션을 아예 생략하면 지금처럼 `wikilink--plain`(F-130 과 동일) — 이 경로는 그대로 둔다

## 4. 폴더 공개 보기 동작

- `resolveWikiLink(target)`: `resolveWikiTarget(target, folder.docs)` 로 매칭(F-131 §2.1 규칙 — 정확 일치 → 대소문자 무시 → `updatedAt` 내림차순 목록 앞 것)
  - 찾으면 `` `#/p/f/${token}/${id}` ``
  - 못 찾으면 `null`
- 클릭: `Viewer` 의 `onOpenWikiLink` prop 재사용 → 찾은 문서면 `PublicFolderView` 의 기존 `selectDoc(id)` 호출(해시 push, 목록 클릭과 같은 흐름). 좁은 창에서 목록이 닫혀 있어도 동작한다
- 못 찾은 대상: `wikilink--missing` 스타일 그대로, 클릭 무반응 — 익명 읽기 전용 화면이라 F-131 §5 의 "새 문서 만들기" 흐름은 적용하지 않는다(저장소 자체가 없음). `Viewer` 는 `onOpenWikiLink` 가 없거나 대상을 못 찾아도 `preventDefault` 만 하고 끝나므로 별도 처리 불필요
- `DocPane` 은 문서 단독/폴더 공용 컴포넌트라 `resolveWikiLink` 는 prop 으로 받아 옵션 처리한다(문서 단독 쪽은 계속 생략)

## 5. 스타일

- 색·밑줄 등은 F-131 §6 그대로. 새 스타일 없음(hex 직접 쓰지 않음 원칙도 변경 없음)
