# F-2154 로컬 파일 하나 편집 — 설계 개요

작성일: 2026-10-21
상태: 개요, 승인 대기. 사용자 "로그인한 상태에서 로컬문서를 열면 그대로 업로드 되어버리는데"(2026-10-21). 승인 대상은 1~6장 결정과 7장 로드맵. 흐름도 `specs/wireframes/F-2154-flow.html`

## 정해진 것 (사용자, 바꾸지 않는다)
1 파일 하나 열고 같은 파일에 저장까지 — 폴더·볼트·파일 감시 없음 · 2 PWA + File System Access API(Chrome·Edge 데스크톱), 없는 브라우저는 지금처럼 가져오기만 · 3 OS 로 연 파일의 처리는 열 때마다 묻지 않고 **설정** `로컬 파일 기본 열기 방식` 으로 정한다 — ① 가져오기(지금 동작, 로그인 시 업로드, **기본값**) ② 이 파일만 고치기(업로드 안 함) · 4 이 문서는 명세만

## 근거 (2026-10-21 HEAD, 이름으로 찾는다)
- `fileLaunch.ts` `setupFileLaunch` 는 handle 을 `getFile()` 로 읽기만 한다. `useImportFlow.ts` `openOrImportLaunchedFiles` 는 idb 일 때만 F-231 판정, server 저장소(로그인)면 곧장 `runImportFiles` → `store.create` = 업로드
- TS 6.0 `lib.dom.d.ts`: `FileSystemFileHandle.createWritable`·`FileSystemWritableFileStream` 있음, `showOpenFilePicker`·`queryPermission`·`requestPermission`·`getAsFileSystemHandle` 없음 → `fileLaunch.ts` 의 `launchQueue` 처럼 모듈 안 `declare global`(새 의존성 `@types/wicg-file-system-access` 안 씀)
- Chrome 문서(file-system-access, persistent-permissions 글): 쓰기 권한 없으면 `createWritable()` 이 묻는다, 권한 요청은 사용자 동작 안에서만, 쓴 내용은 `close()` 때 디스크에 반영, 허용은 그 출처 탭을 다 닫을 때까지 유지, Chrome 122+ 는 `매번 방문 시 허용` 으로 영구. 저장한 handle 은 `queryPermission` 부터
- `decodeMarkdown`(F-114 2.1) → `{text, lineEnding, mixed, hadBom}`. 섞이지 않은 파일은 `fromEditorText(toEditorText(원문), lineEnding)` 이 원문과 같다
- `Editor` 는 마운트 때 `text` 로 `Y.Doc` 을 새로 심는다(architecture 3장). `docId`·`live`·`wikiContext`·`onImageFiles`·`resolveAttachment` 는 모두 선택 prop
- 전용 화면 선례: `AppScreens.tsx` 가 `sharedDoc` 이면 문서 화면 대신 `SharedView`(S-4). 떠나기는 `leaveScreens`, 해시는 `hashRoute.ts` `parseHash`
- `globalShortcuts.ts` `isExportKey` — Ctrl+S = `.md` 내보내기(F-2117). 팔레트 `.md 가져오기` keywords 에 `파일 열기` 가 들어 있다

## 1. 불변조건 — 바꾸지 않는다
- 열린 로컬 파일의 원본은 **링크 없는 편집기 `Y.Doc` 의 `Y.Text` 하나**(불변조건의 "링크 없음" 경우 그대로). **디스크 파일은 D1 `docs.content`·IndexedDB 본문과 같은 단방향 파생**: `Y.Text` → `getText(lineEnding)` → 바이트 → `createWritable`
- 디스크 → `Y.Doc` 은 여는 때 1회뿐(architecture 3장 "저장소 → 에디터"). 외부 변경을 들일 때도 열린 `Y.Doc` 에 쓰지 않고 편집기를 새 `key` 로 다시 마운트한다(4장). 뜻은 그대로이고 파생 목록에 디스크 파일 한 줄을 더한다(9장)

## 2. 어디에 사나 — 메모리만
- 본문은 편집기 `Y.Doc` 에만. 저장소에 행을 만들지 않는다(idb·memory·server 모두) → 업로드도 로컬 사본도 없다. 쓰기 전 끊기면 잃는 것은 마지막 1,000ms 뿐
- 세션: `LocalFileSession = { key: string; handle: FileSystemFileHandle; name: string; lineEnding: LineEnding; hadBom: boolean; lastModified: number; canWrite: boolean }`, `key` = `'file:' + crypto.randomUUID()`. `useLocalFile` 훅의 React state. `key` 는 `Editor` 의 `key` 이자 나중 문서 탭(`doc-tabs-flow.html`, 미확정)이 탭 식별자로 쓸 값 — 탭 설계는 여기서 안 한다
- 화면 S-11 `로컬 파일`: `SharedView` 와 같은 전용 화면 자리, 해시 `#/file`(기록 추가). handle 은 주소에 못 실으니 새로고침·직접 입력으로 온 `#/file` 은 홈으로 교체. 머리줄 = 파일명 + 꼬리표 `컴퓨터 파일` + `{제품명} 문서로 가져오기` + `닫기`. 메모리 저장소(시크릿 창)에서도 열린다

| 기능 | 로컬 파일에서 |
| --- | --- |
| 사이드바·검색·지도·백링크·위키링크 후보·달력·할 일 | 안 보임 — 모두 `list()` 를 읽는데 행이 없다. 사이드바 선택 표시 없음 |
| 파일 안 `[[링크]]` | `wikiContext`·`onOpenWikiLink` 안 넘김 — 꾸밈만, 눌러도 아무 일 없음(옆 파일 권한 없음) |
| 이미지 | 붙여넣기·끌어놓기 막고 `컴퓨터 파일에는 이미지를 넣을 수 없습니다.` `resolveAttachment`·`resolveImagePath` 안 넘김 → 자리 표시 |
| 댓글·공유·게시·실시간·GitHub·금고·휴지통·템플릿·내보내기 메뉴 | 없음. 금고 잠금과 무관 |
| `md.lastDocId`·시작 화면·`최근 문서` | 안 바꾼다 |
| 보기 모드 | 상단 `편집`·`원문`·`보기` 를 따른다. 칸반 보드로는 열지 않는다 |

## 3. 저장
- **자동 저장**: 입력이 1,000ms 멈추면 쓴다. 이 화면에서 `Ctrl+S`(맥 `Cmd+S`)는 내보내기 대신 즉시 쓰기. 여는 것만으로는 쓰지 않는다
- 바이트: 신규 순수 함수 `encodeMarkdown(text: string, opts: { hadBom: boolean }): Uint8Array`(`decodeMarkdown` 짝) = BOM(있었으면) + UTF-8. 섞이지 않은 파일은 고치지 않고 저장하면 원본과 바이트 동일. 섞인 파일은 열 때 알림 `줄바꿈 형식이 섞여 있어 저장하면 CRLF 로 통일됩니다.` UTF-8 이 아니면 열지 않고 `"{파일명}" 은(는) UTF-8 텍스트 파일이 아니라 열 수 없습니다.`
- 쓰기 한 번: `getFile().lastModified` 확인(4장) → `createWritable()` → `write` → `close()` → `getFile()` 로 `lastModified` 갱신. 진행 중 쓰기가 끝나기 전에 다음을 시작하지 않는다(`useDocSaver` `runSave` 되풀이 규칙)
- 권한: 사용자 동작 안(파일 선택 직후, 최근 파일 클릭, `저장 허용`)에서 `queryPermission({ mode: 'readwrite' })` → `granted` 아니면 `requestPermission`. OS 더블클릭(설정 ②)처럼 동작 밖이라 실패하거나 거절이면 편집은 되고 쓰기만 멈춘다 — 상태바 `저장 권한 필요` + 머리줄 `저장 허용`(누르면 요청 후 곧바로 쓰기)
- 상태바 `.statusbar-save`: `파일에 저장됨` / `입력 중…` / `저장 실패`(N-1 `파일에 저장하지 못했습니다.`) / `저장 권한 필요`
- 떠나기(닫기·문서 열기·뒤로·다른 파일): 대기 쓰기를 먼저 끝낸다(`beforeLeaveDoc` 자리). 못 쓴 변경이 남아 있으면 `beforeunload` 로 브라우저 확인 창

## 4. 외부 변경 충돌
- 판정 시점: 쓰기 직전, 창 `focus`, `visibilitychange` 로 보일 때. 폴링 없음. 순수 함수 `decideExternalChange({ known, current, dirty }): 'none' | 'reload' | 'conflict' | 'missing'` (`current` 는 `lastModified` 또는 `NotFoundError` 면 `null`)
- `reload`(내 변경 없음): 조용히 재마운트 + 알림 `다른 프로그램에서 바뀐 내용을 불러왔습니다.`
- `conflict`: 자동 저장 멈춤, 머리줄 아래 띠 `다른 프로그램이 이 파일을 바꿨습니다.` + `다시 불러오기`(내 변경 버림) / `내 내용으로 덮어쓰기` / `{제품명} 문서로 가져오기`(내 내용으로 새 문서, 파일은 그대로)
- `missing`: 띠 `파일을 찾을 수 없습니다. 옮겨졌거나 지워졌습니다.` + `{제품명} 문서로 가져오기` / `.md 내보내기`
