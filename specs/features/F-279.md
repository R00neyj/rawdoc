목적: 상단바 `내보내기` 메뉴에 `PDF (A4 인쇄)` 를 더해, 보기 모드 모양을 A4 인쇄 CSS 로 그려 브라우저 인쇄 창을 열고 사용자가 `PDF로 저장` 하게 한다. 앱에서 `Ctrl+P` 를 눌러도 같은 인쇄를 쓴다

## 1. 범위

### 한다

- `ExportMenu` 에 세 번째 항목 `PDF (A4 인쇄)` 추가
- 인쇄 전용 영역(`.print-root`)에 **보기 모드 변환 결과**를 그리고, 이미지·Mermaid·서체가 다 준비된 뒤 `window.print()`
- 인쇄 CSS 새 파일 `src/styles/print.css` — `@page { size: A4; margin: 20mm }`, 앱 화면 숨김, 쪽 나눔 규칙
- 인쇄하는 동안 `document.title` 을 문서 제목으로 (PDF 기본 파일명), 테마와 상관없이 흰 바탕. 끝나면(`afterprint`) 되돌린다
- 앱에서 `Ctrl+P`(`Cmd+P`) → 같은 인쇄

### 하지 않는다

- **PDF 생성 라이브러리를 들이지 않는다** (jsPDF·html2pdf·pdf-lib 등). 근거는 4.7 — `F-277` 5장 "버튼 하나로 바로 받는 `.pdf`(라이브러리 방식)" 는 이미 범위 밖으로 정해졌다
- `HTML 파일`·`서식 있는 복사` — F-280
- 공유 화면(F-130)·공개 보기(F-210)의 인쇄. 그 화면에서 `Ctrl+P` 는 브라우저 기본 인쇄 그대로다 (6.2)
- 머리글·바닥글(날짜·주소) 끄기 — 브라우저 인쇄 설정이라 앱이 손대지 못한다 (`F-277` 1.2). 사람 확인 항목
- 쪽 번호·머리글 자리(`@page` 의 margin box) 커스터마이즈. 브라우저가 `@page` 안 `@top-center` 등을 지원하지 않는다
- 인쇄 미리보기 대화상자·인쇄 설정 화면을 앱이 따로 만드는 일
- 보기 모드 렌더 결과(`renderMarkdown` 출력 HTML)를 바꾸는 일. 인쇄는 **같은 HTML** 을 쓴다

## 4. 인쇄 흐름

### 4.1 무엇을 인쇄하나

**현재 문서의 보기 모드 변환 결과 한 가지만 인쇄한다.** 지금 화면이 편집(live)·원문(raw)·보기(view) 중 무엇이든 결과는 같다 (`F-277` 1.2)

- 편집 모드 화면(CodeMirror)은 인쇄하지 않는다. CM6 는 보이는 줄만 그리는 가상 스크롤이라 화면 그대로 인쇄하면 **문서 일부만 나온다**. 이것이 인쇄 전용 영역을 따로 두는 이유다
- 원문(raw) 모드에서 인쇄해도 마크다운 기호가 그대로 찍히지 않는다. 사람 확인 항목에 적는다(사용자가 다르게 기대할 수 있는 지점)
- 본문 맨 위에 문서 제목(`F-217` 2.1 과 같은 `.doc-title-view`)을 그린다 — 첫 쪽 맨 위가 제목이 된다
- 프론트매터는 보기 모드와 같게 표(`markdown-frontmatter`)로 나온다. 주석(`%%…%%`)은 `renderMarkdown` 이 이미 빼므로 인쇄에도 없다

### 4.2 인쇄 전용 영역

`App.tsx` 가 `.app-shell` 의 **마지막 직계 자식**으로 빈 칸을 하나 그려 두고, `printDoc()` 이 그 안을 채운다

```jsx
<div className="viewer print-root" ref={printRootRef} aria-hidden="true" inert />
```

- **`.app-shell` 안에 있어야 한다.** `markdown.css`·`callout.css`·`frontmatter.css`·`wikilink.css` 가 `:is(.app-shell, .public-view) .markdown-body …` 로 범위를 좁혀 놨다(`F-124` 4장). 밖에 두면 마크다운 서식이 통째로 빠진다
- **`viewer` 클래스도 함께 둔다.** 이미지 블록 규칙이 `.viewer .md-image …`(`image.css` 178행 이후)로 좁혀져 있다. `.viewer` 의 배치값(`height: 100%`·`overflow-y: auto`·`padding`·`background`)은 5장이 `.viewer.print-root`(선택자 특이도 0,2,0)로 덮는다
- `aria-hidden` + `inert` — 화면 밖 사본이 스크린 리더에 두 번 읽히거나 링크가 Tab 순서에 끼지 않게 한다
- React 는 이 `div` 를 자식 없이 그리고, `printDoc()` 이 `replaceChildren()` 으로 채웠다 비운다. `Viewer` 가 이미 같은 방식(`dangerouslySetInnerHTML` 로 그린 뒤 DOM 을 직접 채움)을 쓴다

채우는 내용:

```html
<h1 class="doc-title-view">{제목}</h1>        ← textContent 로 넣는다
<div class="markdown-body">{renderMarkdown 결과}</div>
```

```

cleanup()  — 두 번 불러도 안전하다

```

`printDoc.ts` 가 내보내는 것:

```ts
export function printTitle(title: string): string   // 순수 — 비었으면 '제목 없는 문서'

export async function printDoc(args: {
  root: HTMLElement | null
  html: string
  title: string
  resolveAttachment?: (id: string) => Promise<{ blob: Blob; width: number; height: number } | null>
  print?: () => void                                // 테스트가 바꿔 끼운다. 기본 window.print
}): Promise<void>
```

### 4.4 `document.title` 과 되돌리기

- 인쇄 중 `document.title` = `printTitle(문서 제목)`. Chrome 의 `PDF로 저장` 기본 파일명이 이 값이 된다 (`F-277` 1.2)
- 원래 값은 `index.html` 이 빌드 때 주입한 제품명이다. **코드에 제품명 문자열을 쓰지 않고**, 인쇄 전 `document.title` 을 읽어 뒀다 그대로 되돌린다 (CLAUDE.md 불변조건)
- 되돌리기는 `afterprint` 에서만 한다. Chrome 은 인쇄 미리보기를 닫을 때(인쇄하든 취소하든) `afterprint` 를 쏜다. **`window.print()` 가 돌아온 직후에 되돌리지 않는다** — 미리보기가 아직 열려 있는 동안 내용이 사라질 수 있다
- `afterprint` 가 오지 않는 브라우저에서는 되돌리기가 늦어진다(제목·테마가 그대로 남는다). Chrome 기준 프로젝트라 이 경우를 따로 다루지 않는다 (9장 M2)

### 4.5 테마 — 흰 바탕

`F-277` 1.2·6장 기본값: 인쇄는 테마와 상관없이 흰 바탕·검은 글자, 서체 설정은 따른다

- **인쇄 동안 `<html>` 의 `data-theme` 를 지웠다가 되돌린다.** 속성이 없는 상태가 곧 화이트 테마다(`tokens.css` 첫 `:root` 블록, `F-141` 3.1). 색 값을 `print.css` 에 다시 적지 않아도 되고, 하나뿐인 색 정의 위치가 `tokens.css` 로 유지된다 (불변조건)
- `data-heading-font`·`data-body-font`·`data-font-size` 는 건드리지 않는다 → 서체·글자 크기 설정이 인쇄에도 그대로 간다
- 대가: 다크·세피아 테마 사용자는 인쇄 창이 뜨고 닫히는 순간 화면이 잠깐 흰 테마로 보일 수 있다. **사람 확인 항목** (9장 M3 — 눈에 거슬리면 `print.css` 에 토큰을 다시 적는 방식으로 바꾼다)

### 4.6 이미지·Mermaid 기다리기

`src/viewer/fillMarkdownAssets.ts`

```ts
export async function fillAttachmentImages(root: HTMLElement, resolveAttachment?: ResolveAttachment): Promise<string[]>
export async function fillMermaidBlocks(root: HTMLElement): Promise<void>
```

- `fillAttachmentImages` 는 `root.querySelectorAll('img[data-attachment]')` 를 돌며 `Viewer` 와 **같은 함수**(`showImage`·`showPlaceholder`)로 채우고, 만든 blob URL 목록을 돌려준다. 채운 뒤 `await img.decode()`(실패는 무시) 까지 기다린다 — 인쇄 미리보기가 빈 이미지로 찍히지 않게
- 첨부를 못 찾으면 보기 모드와 같은 자리 표시(`이미지를 찾을 수 없습니다`)가 인쇄된다. 별도 알림은 띄우지 않는다 (`.md` zip 내보내기와 달리 빠진 것이 눈에 보인다)
- `fillMermaidBlocks` 는 `.md-mermaid[data-mermaid-source]` 마다 `renderMermaid(source)`(`F-258` 2.2)를 부르고 **전부 끝날 때까지 기다린다**. 실패하면 보기 모드와 같은 `.md-mermaid-error` 글
- `showPlaceholder`·`showImage` 는 지금 `Viewer.tsx` 안 모듈 private 함수다. 이 파일로 **그대로 옮기고** `Viewer.tsx` 는 import 해 쓴다. 자리 표시 모양이 두 곳으로 갈라지지 않게 하는 것이 목적이고, `Viewer` 의 effect 구조(취소 플래그·URL 해제)는 건드리지 않는다. 회귀는 `e2e/image.spec.js` 로 판정한다 (A12)

### 4.7 왜 라이브러리를 쓰지 않는가

`F-277` 1장·5장이 이미 "브라우저 인쇄(A4 인쇄 CSS) → 사용자가 `PDF로 저장`" 으로 정했고, 라이브러리 방식은 5장 "하지 않는 것" 이다. 코드 쪽 근거도 같은 결론이다

| 방식 | 한글 서체 | Mermaid·이미지 | 무게 | 판정 |
| --- | --- | --- | --- | --- |
| 브라우저 인쇄 + 인쇄 CSS | 화면과 같은 서체 그대로 | 화면에 그려진 것 그대로 | 새 의존성 0 | **채택** |
| jsPDF (+html2canvas) | 한글 폰트를 직접 넣어야 하고(수 MB) 글자가 이미지로 굳는다 | 화면 캡처라 글자 선택·검색 불가 | 수백 KB~MB | 안 함 |
| pdf-lib 류 | 마크다운 → PDF 레이아웃을 직접 짜야 한다 | 표·콜아웃·다이어그램 전부 새로 구현 | 큰 구현 비용 | 안 함 |

기술 스택 표(CLAUDE.md)에 없는 의존성은 추가하지 않는다

## 5. 인쇄 CSS (`src/styles/print.css`)

색 hex 를 쓰지 않는다. 배치·숨김·쪽 나눔만 정한다

| 규칙 | 값·이유 |
| --- | --- |

### 6.1 리스너

`App.tsx` 에 `window` `keydown` 리스너를 더한다. `Ctrl+F` 가로채기(`App.tsx` 914행 이후, `F-261` 2.2)와 같은 모양이다

if (!(e.ctrlKey || e.metaKey) || e.shiftKey || e.altKey) return

  - `src/editor/commands.ts` 의 `shortcutKeymap` 은 `Mod-b`·`Mod-i`·`Mod-k` 뿐
  - `createEditor.ts` 가 얹는 것은 `Mod-h`(치환)·`Enter`·`Backspace`·`ArrowUp`·`Tab`

  - `@codemirror/search` 키맵에도 `Ctrl-p` 는 없다

## 8. 자동으로 판정할 수 있는 것 / 없는 것

Playwright 로 **인쇄 결과(PDF) 자체를 볼 수는 없다**

- `page.pdf()` 는 Chromium **headless 전용**이다. 이 프로젝트 `playwright.config.js` 는 설치된 Chrome 채널(`channel: 'chrome'`)을 쓰고, PDF 안 글자를 확인하려면 PDF 파서 의존성도 필요하다 → **쓰지 않는다**
- 실제 `window.print()` 를 부르면 테스트가 멈출 수 있다. e2e 는 `page.addInitScript` 로 `window.print` 를 기록용으로 바꿔 끼운다(`e2e/image.spec.js` 810행의 `URL.createObjectURL` 바꿔치기와 같은 방식, 전역 이름은 `window.printLog`)
- 인쇄 미디어 아래 **구조**(앱 화면이 빠지고 인쇄 영역만 남는지)는 `page.emulateMedia({ media: 'print' })` + 보임/숨김으로 판정한다. 여백·글자 크기·줄 간격 같은 시각값은 고정하지 않는다
- 쪽 나눔이 실제로 어디서 일어나는지, A4 여백이 맞는지, 한글이 깨지지 않는지는 **사람 확인**이다
