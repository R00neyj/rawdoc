## 3. 모양 결정 — 훅이 아니라 매 렌더 부르는 팩토리

F-2059 2.3 은 이 조각을 순수 모듈 `exportActions.ts`(`createExportActions`), 훅 없음으로 정했다. 부작용(내려받기·클립보드·`window.print`·알림)은 다음처럼 넘긴다.

- **`exportActions.ts` 는 React 를 import 하지 않는다**(`import type { RefObject }` 만). DOM·`window` 도 모듈 최상위에서 만지지 않는다. 부작용은 **기존 모듈 함수 호출**(`exportDoc`·`downloadWorkspaceExport`·`printDoc` …)과 **넘겨받은 콜백**(`showNotice`, ref 안 함수) 안에서만 일어난다
- **기존 내보내기 함수는 주입하지 않고 모듈이 직접 import 한다** — App 이 지금 그렇게 부르므로 본문이 바이트 그대로 옮겨진다. 단위 테스트는 `vi.mock` 으로 그 모듈들을 가짜로 바꾼다(`exportWorkspace.test.ts`·`exportVault.test.ts` 의 `vi.mock('./exportDoc', …)` 선례, 11장 Q5)
- **App 은 매 렌더 `createExportActions(…)` 를 부른다. `useMemo`·`useCallback` 으로 감싸지 않는다.** 지금 함수 선언은 렌더마다 새로 만들어지고 그 렌더의 `currentDoc`·`openDoc`·`currentDocId`·`store`·`syncState`·`showNotice`·`resolveWikiHref`·`resolveAttachment` 를 클로저로 읽는다. 매 렌더 팩토리에 같은 값을 넘기면 한 렌더 안 값·함수 정체성 모양이 지금과 같다(F-2059 3.2 "클로저로 읽던 값은 인자로")
- **ref 로 읽던 값은 ref 객체로 넘긴다**(`editorRef`·`docSaverFlushRef`·`printRootRef`·`foldersRef`·`e2eeRef`). 팩토리는 `.current` 를 호출 때(이벤트 때)만 읽는다 — 렌더 중에 읽지 않는다(3.7 `react-hooks/refs`)
- 팩토리 본문 첫 줄에서 `deps` 를 구조 분해해 지금 이름 그대로 쓴다. 그래서 함수 본문은 `x` → `deps.x` 같은 이름 연결조차 없이 그대로다

## 4. 시그니처 (계약)

```ts
// src/app/exportActions.ts
import type { RefObject } from 'react'
import type { E2eeStatus } from '../e2ee/keyring'
import type { EditorHandle } from '../editor/Editor'
import type { Folder, Store, SyncState } from '../types'
import type { ResolveAttachment } from '../viewer/fillMarkdownAssets'
import type { DocMeta, OpenDoc } from './docMeta'
import type { NoticeWithAction } from './NoticeBar'

export type ExportActionsDeps = {
  store: Store
  syncState: SyncState | undefined
  currentDoc: DocMeta | null
  openDoc: OpenDoc | null
  currentDocId: string | null
  editorRef: RefObject<EditorHandle | null>
  docSaverFlushRef: RefObject<() => Promise<boolean>>
  printRootRef: RefObject<HTMLDivElement | null>
  foldersRef: RefObject<readonly Pick<Folder, 'id' | 'e2ee'>[]>
  e2eeRef: RefObject<{ keyring: { getStatus(): E2eeStatus }; requestOpen(): Promise<boolean> } | null>
  showNotice: (input: NoticeWithAction) => number
  resolveWikiHref: (target: string) => string | null
  resolveAttachment: ResolveAttachment
}

export type ExportActions = {
  handleExportDoc: () => void
  handleExportDocAsText: () => void
  handleExportDocAsHtml: () => void
  handleCopyDocAsRichText: () => void
  handlePrintDoc: () => void
  exportOffline: boolean
  handleExportAll: () => Promise<void>
  handleExportFolder: (id: string) => void
  handleExportVault: () => Promise<void>
  handleExportFolderVault: (id: string) => void
}

export function createExportActions(deps: ExportActionsDeps): ExportActions
```

App 호출 (5.6 자리):

```ts
const {
  handleExportDoc, handleExportDocAsText, handleExportDocAsHtml, handleCopyDocAsRichText, handlePrintDoc,
  exportOffline, handleExportAll, handleExportFolder, handleExportVault, handleExportFolderVault,
} = createExportActions({
  store, syncState, currentDoc, openDoc, currentDocId, editorRef, docSaverFlushRef, printRootRef,
  foldersRef, e2eeRef, showNotice, resolveWikiHref, resolveAttachment,
})
```

- 타입 이름: 순수 모듈 인자 타입은 `…Deps` (`LiveDocDeps`·`ShareCopyDeps`·`MigrateLocalDeps` 선례). 훅이 아니므로 `UseXxxOptions` 를 쓰지 않는다
- `foldersRef`·`e2eeRef` 는 쓰는 면만 적은 구조 타입이다. App 의 `useRef(folders)`(`RefObject<Folder[]>`)·`useRef<ReturnType<typeof useE2ee>>(null)` 을 그대로 넘겨 `tsc` 가 통과하는 것을 탐침으로 확인했다. 테스트가 `UseE2ee` 전체를 흉내 내지 않아도 되게 하려는 것이다
- `showNotice` 는 App 의 `(input, options?) => number` 를 그대로 받는다(두 번째 인자는 쓰지 않는다 — F-2061 `UseContextMenuOptions` 와 같은 타입)
- 반환 객체의 필드 순서는 위와 같다(2.1 순서에서 반환하지 않는 두 함수를 뺀 것)
- `ExportActions` 의 `handleExportAll`·`handleExportVault` 는 지금처럼 `async`(설정 대화상자가 `Promise` 를 받는다), `handleExportFolder`·`handleExportFolderVault` 는 지금처럼 동기 함수 안 `void (async () => …)()` 다. 모양을 바꾸지 않는다

## 6. 동작 (바뀌지 않는다 — 지금 동작 요약)

- 한 문서 내보내기 4개(`.md`·`.txt`·HTML·서식 있는 복사)와 인쇄는 `currentDoc` 이 있고 `openDoc.id === currentDocId` 일 때만 돈다. 인쇄만 `editorRef.current` 도 본다
- `.md`·HTML·서식 있는 복사는 `e2eeScopedExportStore(currentDoc.e2ee === 'open')` 를 첨부 저장소로 쓴다 — 지금 문서가 열린 금고 문서가 아니면 `e2ee` 첨부를 `null`(이미지 누락)로 돌린다. `.txt` 는 첨부를 읽지 않는다
- 인쇄는 저장을 기다리지 않고 flush 를 시작만 한 뒤, 편집기 원문(`'lf'`)을 `resolveWikiHref` 로 렌더해 `printDoc` 에 넘긴다
- `exportOffline` = 서버 저장소이면서 `syncState?.online === false`
- 전체·볼트 내보내기(설정 `데이터` 탭)는 flush 를 **기다린 뒤** 내려받고, 진행은 info 알림 `내보내는 중… {done}/{total}`
- 폴더·폴더 볼트 내보내기(사이드바 폴더 `⋯`)는 `exportOffline` 이면 error 알림 `온라인일 때 내보낼 수 있습니다.` 만 띄우고 끝난다. 아니면 금고 폴더 판정(아래) → flush 대기 → 내려받기
- 금고 폴더 판정 `ensureE2eeOpenForFolderExport`: 폴더가 금고 폴더가 아니거나, 금고 훅이 없거나, 이미 `open` 이면 진행. 아니면 `requestOpen()` — 열리면 진행, 닫혔으면 그때 상태가 `unavailable` 일 때만 진행, 그 밖에는 아무것도 하지 않는다

## 11. 열린 질문 (모두 기본값 있음)

### Q1. 팩토리 호출 자리 — **기본값: `resolveAttachment` 바로 아래로 내린다 (5.6)**

- 이유: 호출 인자 `resolveAttachment` 가 옛 구역보다 아래 `useMemo` 다. 내려도 그 사이 렌더 중 참조가 없어 새 TDZ 가 없고(5.1), 팩토리는 훅이 아니라 effect 순서도 바뀌지 않는다(5.2)
- 다른 쪽(옛 자리에 두고 `getResolveAttachment: () => resolveAttachment` 게터를 넘긴다): 개요 3.8 을 글자 그대로 지키지만, `handlePrintDoc` 본문의 `resolveAttachment,` 한 줄이 `resolveAttachment: getResolveAttachment(),` 로 바뀌어 이동 판정에 본문 수정이 한 줄 생기고, 계약 타입에 게터라는 우회가 남는다

### Q2. `exportOffline` 을 팩토리로 옮기나 — **기본값: 옮기고 반환한다**

- 이유: 앞 주석이 F-281 3.1 내보내기 규칙이고, 팩토리 안 폴더 내보내기 두 함수가 읽는다. App 에 두면 인자로 다시 넘겨야 해 같은 값이 두 곳에 걸친다. JSX `exportAllDisabled={exportOffline}` 은 구조 분해 이름이 같아 줄이 그대로다
- 다른 쪽(App 에 두고 인자로): `searchOffline` 과 나란히 남아 두 식이 한눈에 보이지만, 인자 하나가 늘고 `syncState` 대신 `exportOffline` 을 넘기게 된다. 동작은 같다

### Q3. 한 문서 금고 첨부 거르기의 특성 테스트 — **기본값: e2e 대신 단위 U4·U5**

- 이유: 7.2 끝 항목. 거르는 식은 첨부 레코드 하나와 불리언 하나만 보는 순수 판정이고, 금고 문서 준비가 e2e 로 가장 무거운 축이다. F-2059 5.2 표가 F-2068 에 같은 선택(순수 함수 단위 테스트)을 허용했다
- 다른 쪽(`appSplit.spec.js` 에 C2 로 e2e): 브라우저 경로까지 고정되지만 `setupDocs`·`pasteImage` 류 헬퍼 약 60줄을 복사해야 하고 묶음 시간이 는다

### Q4. 죽은 ref `printDocRef`·`printDisabledRef` — **기본값: 이 조각은 그대로 두고, F-2059 7장에 D7 로 올릴지 사용자에게 묻는다**

- 확인한 것: `grep -rn "printDocRef\|printDisabledRef" src` 결과 선언(≈482·485)과 최신값 effect ② 의 대입(≈2678·2680)뿐이다. 주석은 "Ctrl+P 가 매 커밋 최신 handlePrintDoc 을 읽게 한다" 인데 `Ctrl+P` 는 팔레트를 연다(`print.spec.js` F-279 A11) — F-2062 의 `useGlobalShortcuts` 도 이 ref 를 받지 않는다
- 이유: 지우는 것은 동작이 없는 코드 정리지만 전제 3("옮기기만")과 3.6 판정을 흐린다. 개요 7장처럼 목록에 올리고 따로 판정하는 것이 이 분할의 방식이다
- 다른 쪽(이 조각에서 지움): App 이 4줄 더 줄지만 effect ② 가 바뀌어 이동 판정에 "옮기기 아닌 삭제" 가 섞인다

### Q5. 기존 내보내기 함수를 주입하나 — **기본값: 모듈이 직접 import, 테스트는 `vi.mock`**
