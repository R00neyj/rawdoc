# F-242 폴더 삭제 — 내용을 위로 옮길지 함께 지울지 고르기

작성일: 2026-09-18
상태: 사용자 승인 대기 (2026-09-18 사용자 "삭제시 내용 상위로 옮길지/내용도 전부 삭제할건지 버튼으로 선택할 수 있어야함. 현재는 상위로 옮기기만 되고 있음")
근거: `specs/features/F-126.md`(폴더 트리·삭제), `F-111.md` 3.5(삭제 확인 D-1), `F-206.md` 2.4(폴더 API), `F-207.md` 2.3(보낼 목록)

## 1. 범위

### 문제
폴더를 지우면 안의 문서와 하위 폴더가 **무조건 한 단계 위로 올라온다**(`idbStore.removeFolder`, `serverStore.removeFolder`, `worker/folders.ts` `handleDeleteFolder` 가 모두 그렇게 되어 있다). 폴더째로 정리하고 싶을 때는 안의 문서를 하나씩 지워야 한다.

### 한다
- 폴더 삭제 확인 대화상자에서 **두 가지를 버튼으로 고른다**
  - `위로 옮기기` — 지금 동작. 안의 문서·하위 폴더를 한 단계 위로 올리고 폴더만 지운다
  - `전부 삭제` — 폴더 안의 문서와 하위 폴더(그 안의 문서까지 전부)를 함께 지운다
- 저장소 3종(`idb`·`memory`·`server`)과 Worker 가 모두 두 가지를 지원한다
- 폴더가 **비어 있으면**(문서도 하위 폴더도 없으면) 고를 것이 없으므로 버튼을 하나(`삭제`)만 보여준다
- `전부 삭제` 로 지금 열려 있는 문서가 없어지면 홈 화면으로 돌아간다

### 하지 않는다
- 휴지통·되돌리기 — 지금 문서 삭제와 같은 수준(되돌릴 수 없음)
- 삭제될 문서 개수를 대화상자에서 세어 보여주기(문구로 경고만 한다)
- 폴더에 걸린 공유 권한(`grants`)·공개 링크(`links`) 정리 — 지금 문서 삭제도 하지 않는다(별도 명세로)
- 서버 첨부(R2) 즉시 삭제 — 지금처럼 안 쓰는 첨부 정리에 맡긴다 (F-221)
- 다중 선택 삭제

## 3. 요구사항

### 3.1 모드 (`types.ts`, 저장소 공통)
- `FolderDeleteMode = 'move-up' | 'delete-all'`. `removeFolder(id)` 를 인자 하나로 부르면 `'move-up'`(지금 동작) — 기존 호출부·테스트가 그대로 돈다
- `'move-up'`: 지금 그대로. 안의 문서·하위 폴더의 부모를 지우는 폴더의 부모로 바꾸고 폴더를 지운다
- `'delete-all'`: 지우는 폴더와 **모든 하위 폴더**, 그리고 그 폴더들에 들어 있는 **모든 문서**를 지운다
- 하위 폴더 모으기는 `folderTree.descendantFolderIds` 하나로 한다(저장소마다 다시 구현하지 않는다). 순환 참조는 만들 수 없지만 방어적으로 같은 id 를 두 번 따라가지 않는다

### 3.2 로컬 저장소 (`idbStore.ts`, `memoryStore.ts`)
- `delete-all` 은 지금 `move-up` 이 쓰는 것과 같은 트랜잭션(`docs`+`folders` readwrite) 안에서 한 번에 끝낸다
- 지울 대상: `ids = descendantFolderIds(all, id)`, 문서는 `folderId ∈ ids`
- 첨부는 여기서 건드리지 않는다 — 문서를 지우면 안 쓰는 첨부 정리(F-156 2.7)가 다음 기회에 치운다

### 3.3 서버 저장소 (`serverStore.ts`, `remoteCache.ts`, `docsApi.ts`)
- 캐시를 먼저 고치고 즉시 resolve, 보낼 목록에 넣는다 (F-207 2.3 그대로)
- `delete-all` 캐시 정리: 대상 폴더들과 그 안 문서를 캐시에서 지우고, **그 문서·폴더로 대기 중이던 보낼 목록 항목도 지운다**(`removeOutboxForDoc`·`removeOutboxForFolder`, 진행 중인 항목 `inFlightKey` 는 남긴다 — 지금 `removeFolder` 가 하는 방식과 같다)
- outbox 항목: `{ type: 'removeFolder', folderId, mode }`. `mode` 가 없는 옛 항목(이전 버전이 남긴 것)은 `'move-up'` 으로 읽는다
- 보내기: `DELETE /api/folders/:id?contents={mode}`. 404 는 지금처럼 "이미 없음" 으로 보고 캐시·목록에서 지운다
- 서버가 하위 문서를 지우므로 클라이언트가 문서 삭제 요청을 따로 보내지 않는다 — 한 번의 요청으로 끝낸다

### 3.4 Worker (`worker/folders.ts`)
- `DELETE /api/folders/:id` 에 질의 문자열 `contents` 를 받는다. 값은 `move-up`(기본, 없으면 이 값) 또는 `delete-all`. 다른 값이면 `400 {error:'invalid', field:'contents'}`
- `move-up`: 지금 그대로 (문서·하위 폴더 부모 올리고 폴더 삭제)
- `delete-all`:
  1. 내 폴더 전부를 읽어 `descendantFolderIds` 로 지울 폴더 id 를 구한다(`src/lib/folderTree.ts` 를 그대로 import — `worker/folders.ts` 는 이미 `canCreateFolder`·`canMoveFolder` 를 그렇게 쓰고 있다)
  2. `DELETE FROM docs WHERE owner_id = ? AND folder_id IN (…)`, `DELETE FROM folders WHERE owner_id = ? AND id IN (…)` 를 `env.DB.batch` 로 한 번에
  3. id 목록이 길어질 수 있으므로 한 번에 넣는 값이 **100개를 넘으면 나눠서** 보낸다(D1 바인딩 한도 여유)
- 남의 폴더면 지금처럼 `404`

### 3.5 대화상자 (`ConfirmDeleteDialog.tsx`)
- 폴더이고 **안에 무언가 있으면**(문서 또는 하위 폴더) 버튼 3개: `취소` · `위로 옮기기` · `전부 삭제`(`danger`)
  - 문구: `"{이름}" 폴더를 삭제합니다. 안의 문서와 하위 폴더를 어떻게 할까요?`
  - `전부 삭제` 아래 보조 문구: `전부 삭제하면 되돌릴 수 없습니다.` (`--muted`)
- 폴더가 **비어 있으면** 지금처럼 버튼 2개(`취소`·`삭제`), 문구 `"{이름}" 폴더를 삭제할까요?`. 이때 모드는 `'move-up'`(옮길 것이 없어 결과가 같다)
- 문서 삭제는 지금 그대로 (`취소`·`삭제`)
- 처음 포커스는 지금처럼 `취소`
- `onConfirm(target, mode)` 로 모드를 올려 준다
- 폴더가 비었는지는 App 이 알려 준다 — `target` 에 `empty: boolean` 을 담아 넘긴다(대화상자가 문서·폴더 목록을 직접 뒤지지 않는다)

### 3.6 App (`App.tsx`)
- 폴더 우클릭 → 삭제로 `deleteTarget` 을 만들 때 `empty` 를 같이 계산한다: `docs.some(d => d.folderId === id) || folders.some(f => f.parentId === id)` 의 반대
- `confirmDelete(target, mode)`: `store.removeFolder(target.id, mode)` → 지금처럼 `listFolders()`·`list()` 를 다시 받아 반영
- `delete-all` 로 **열려 있던 문서가 사라졌으면** 홈으로 간다 — `currentDocId` 가 새 목록에 없으면 `currentDocId = null`, 해시 `#/`(F-232 3.3 의 홈 이동 경로 재사용)
- 알림은 따로 띄우지 않는다(지금 삭제도 안 띄운다)
