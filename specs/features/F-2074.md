### 5.2 `decideBootRoute` — 첫 화면 판정

```ts
export type BootRouteInput = {
  hash: HashRoute
  docs: { id: string }[]
  lastDocId: string | null
  startScreen: 'home' | 'last'
}

export type BootRoute =
  | { kind: 'share'; fragment: string }
  | { kind: 'shares' }
  | { kind: 'help' }
  | { kind: 'map'; anchorId: string | null }
  | { kind: 'doc'; docId: string; notFound: boolean; threadId: string | null }
  | { kind: 'home' }

export function decideBootRoute(input: BootRouteInput): BootRoute
```

규칙(지금 `finishBootRouting` 의 분기를 위에서 아래로 옮긴 것):

1. `hash.type` 이 `share` 면 `{ kind: 'share', fragment }`, `shares` 면 `shares`, `help` 면 `help`. 이 셋은 `docs`·`lastDocId`·`startScreen` 과 무관하다
2. `map` 이면 `hash.docId` 가 있고 `docs` 에 그 id 가 있을 때만 `anchorId` 가 그 id, 아니면 `null`
3. 그 밖이면, `hash.type === 'doc'` 일 때만 해시 문서 id 와 `threadId`(없으면 `null`)를 쓴다. 해시 문서 id 가 있거나 `startScreen === 'last'` 이면 자동으로 연다. 이때 `resolveInitialDoc({ hashDocId, lastDocId, docs })` 결과의 `docId` 가 있으면 `doc` 을 돌려준다. `threadId` 는 `notFound` 가 거짓이고 해시에 `threadId` 가 있으며 결과 id 가 해시 문서 id 와 같을 때만 그 값이고, 아니면 `null` 이다
4. 자동으로 열지 않거나, 결과 `docId` 가 `null` 이면 `{ kind: 'home' }`. 해시 문서가 목록에 없고 목록이 비었으면 **`notFound` 알림 없이** `home` 이다(지금 코드가 `resolved.docId` 가 있을 때만 알림을 띄운다 — U10)
5. `home`·`none`·`public`·`publicFolder` 해시는 3·4 의 "해시 문서 없음" 과 같다(`public` 계열은 `runBoot` 첫 갈래에서 이미 끝나 여기 오지 않는다)

- React·DOM·`localStorage` 를 읽지 않는다. `getPref` 는 부르는 쪽이 읽어 넘긴다
- 머리 한 줄 주석: `// 부팅 첫 화면 판정 — 해시가 먼저, 문서 해시가 아니면 시작 화면 설정 (F-2074, F-111 2-1, F-232 3.1)`
- 본문이 지금 이름을 읽도록 입력을 구조 분해하며 이름을 바꾼다(`hash` → `parsedHash`, `docs` → `metaList`). 그러면 `const hashDocId = parsedHash.type === 'doc' ? …`, `anchorId` 식, `shouldAutoOpen` 식, 기존 주석 `// 해시가 특정 문서를 안 가리키면 시작 화면 설정을 따른다 — 기본(home)은 자동으로 안 연다 (F-232 3.1)` 이 이동색으로 남는다

**`finishBootRouting` 호출 자리 규칙**(옮긴 뒤 `runBoot` 안):

- 함수 첫 줄에서 `decideBootRoute({ hash: parsedHash, docs: metaList, lastDocId: getPref('md.lastDocId', '') || null, startScreen: getPref('md.startScreen', 'home') })` 를 한 번 부른다. **두 `getPref` 읽기가 `share`·`shares`·`help`·`map` 갈래에서도 일어난다.** 지금은 그 갈래에서 읽지 않는다. `getPref` 는 부작용 없는 읽기라 관찰 가능한 차이가 없다(`prefs.ts` — 허용 키 검사 + `getItem`, 던지면 기본값)
- 그 뒤 부작용은 지금과 **같은 호출을 같은 순서로** 한다
  - `share`: `await openSharedFragment(route.fragment, metaList)` → `setBootPhase('ready')` → `return`
  - `shares`: `setSharesOpen(true)` → `ready` → `return`
  - `help`: `setHelpOpen(true)` → `ready` → `return`
  - `map`: `setCurrentDocId(anchorId)` → `anchorId` 가 있으면 `setPref('md.lastDocId', anchorId)` → `setMapRoute({ centerDocId: anchorId, returnDocId: anchorId })` → `ready` → `return`
  - `doc`: `setCurrentDocId` → `setPref('md.lastDocId', …)` → `replaceHashUrl(docId)` → `notFound` 면 info `문서를 찾을 수 없습니다.`, 아니고 `threadId` 가 있으면 `commentsRef.current?.setPendingTarget({ docId, threadId })` → `metaList` 에서 그 문서를 찾아 `addOpenFolders(ancestorsOfDoc({ folders: folderList, doc: openedDoc }))`
  - `home`: `replaceHashUrl(null)`
  - `doc`·`home` 뒤에 `setBootPhase('ready')`
- 각 갈래 앞 주석(`// 공유 링크(#/s/{조각})는 …`, `// 공유 관리 페이지(#/shares) …`, `// 도움말 페이지(#/help) …`, `// 위키링크 지도(#/map·#/map/{id}) …`, `// 댓글 주소로 들어온 경우 …`)은 부작용 쪽에 그대로 둔다

## 11. 열린 질문 (모두 기본값 — 기본값대로면 사람이 정할 갈림길 없음)

### Q1. `decideBootRoute` 가 어디까지 판정하나 — **기본값: 여섯 갈래 전부(5.2)**

- 이유: 개요 2.3 이 이름을 정했다. 부팅 첫 화면의 우선순위(공유 링크 > 공유 관리 > 도움말 > 지도 > 문서 해시·시작 화면)는 지금 e2e 로만 흩어져 보인다. 여섯 갈래를 한 함수로 떼면 U1~U16 이 한곳에서 고정한다. 부작용 호출과 순서는 그대로다
- 다른 쪽(문서·홈 갈래만, `share`·`shares`·`help`·`map` 의 `if` 는 글자 그대로): 빨강·초록이 약 20줄 준다. 대신 지도 기준 문서 판정과 해시 우선순위가 단위 테스트 밖에 남는다. 5.2 타입에서 앞 네 갈래가 빠진다

### Q2. 러너 effect 본문을 옮기나 — **기본값: `startFlushRunner` 로 옮긴다(5.3)**

- 이유: 개요 5.4 매핑이 러너를 `bootFlow.ts` 로 정했고, 4장이 `isOpenDoc` 을 이 조각에 걸었다. 본문 43줄이 글자 그대로 옮겨지고 App 은 가드·deps 만 남긴다
- 다른 쪽(App 에 둔다): 개요 2.3 괄호에 없는 export 이름이 생기지 않는다. 대신 A1 이 42줄 줄고, 5.4 매핑과 어긋난다. `isOpenDoc` 판정은 어느 쪽이든 글자 그대로다

### Q3. 스켈레톤 인계 layout effect 를 옮기나 — **기본값: App 에 둔다**

- 이유: 판정은 App 상태 세 개의 `||` 한 줄이고, DOM 일은 이미 `bootPaint.ts` `removeBootSkeleton` 에 있다. 순수 함수로 떼면 줄이 늘고(함수 + 호출), 옮기기 아닌 줄이 생긴다. layout ↔ passive 를 바꾸면 안 된다(개요 3.2)
- 다른 쪽(`shouldRemoveBootSkeleton({ bootPhase, publicRoute, dbBlockedMessage })` 을 `bootFlow.ts` 에): 단위 테스트 3줄이 생긴다. `bootSkeleton.spec.js` 가 이미 세 갈래(ready·공개·F-136)를 보므로 새로 보는 것이 없다

### Q4. `runBoot` 단위 테스트 R1~R3 을 두나 — **기본값: 둔다(7.1)**

- 이유: 공개 보기 조기 끝, 메모리 저장소 알림, `listCached()` 실패 뒤 기다리는 길은 e2e 로 닿지 않는다(IndexedDB 를 끄거나 캐시 읽기를 실패시킬 수 없다). 모듈 7개를 `vi.mock` 하는 비용은 F-2065 선례 수준이다
- 다른 쪽(U 만): 테스트가 가볍다. 대신 세 갈래는 A5 이동색 판정만 남는다

### Q5. e2e 묶음에 `comments.spec.js` F-505 E11 을 더하나 — **기본값: 더한다(8장)**

- 이유: 댓글 주소로 부팅하는 유일한 e2e 다(`threadId` → `setPendingTarget`). 로드맵 행에서 빼는 것이 아니라 더하는 것이라 개요와 부딪치지 않는다(F-2068 Q7 과 같은 판단)
- 다른 쪽(로드맵 그대로): `verify:full` 에서만 본다

### Q6. `replaceHashUrl`·`openSharedFragment` 를 deps 로 받나, `bootFlow.ts` 가 직접 import 하나 — **기본값: deps**

- 이유: 둘 다 F-2071 이 옮길 수 있는 이름이다. deps 로 받으면 F-2071 이 어디에 두든 App 에서 이름으로 닿기만 하면 된다. 본문은 `replaceHashUrl(…)` 그대로라 이동색이다(F-2068 이 `pushHashUrl` 을 옵션으로 받은 선례)
- 다른 쪽(F-2071 이 `hashNav.ts` 에서 export 하면 직접 import): deps 가 하나 준다. 대신 F-2071 결과에 이 명세가 묶인다

### Q7. App 주석의 `boot()` 두 줄을 고치나 — **기본값: 고치지 않는다**

### Q8. `depends` 에 F-2073 을 넣나 — **기본값: 지금은 넣지 않는다**

### 관찰 (이 조각은 고치지 않는다 — F-2059 7장 성격, 판정은 사용자)

1. **`applyBootMerge` 는 `setDocs` 업데이터 안에서 부작용을 낸다.** `deletedElsewhereSourceRef` 대입, `setDeletedElsewhereId`, `void restartDocSessionAfterFlush()` 가 업데이터 함수 안에 있다. 같은 일을 하는 `applyResyncResult` 는 리뷰 e 때 `flushSync` 로 업데이터를 곧바로 돌리고 부작용을 업데이터 **밖**으로 뺐다. 업데이터가 두 번 불리면(개발 StrictMode, 동시 렌더 재적용) 세션 재시작 요청이 두 번 갈 수 있다. 코드를 읽어 판단한 것이고 실행해 보지는 않았다. 개요 D2 와 이웃한다
2. **공유 조각 실패 대체 경로는 문서 해시 갈래와 부작용이 다르다.** `openSharedFragment` 의 `catch` 는 `setCurrentDocId`·`replaceHashUrl` 만 부른다. `md.lastDocId` 저장과 조상 폴더 펼침이 없다. 부팅 `doc` 갈래는 둘 다 한다(개요 D1 과 같은 종류)
3. 절 머리 `// ----- 부팅 (S-3 → S-1|S-2), 최초 실행 안내 문서 (ia.md 3.1·3.2, F-111 3.1) -----` 와 본문 주석 `// 로컬 → 계정 이관 (F-208.md 2.1·2.2) — 첫 실행 안내 문서 판단은 이 뒤에 한다` 가 "첫 실행 안내 문서" 를 말한다. 그런데 HEAD `App.tsx` 에 그 문서를 만드는 코드가 없다(`grep "firstRunDone\|안내 문서"` 결과는 이 두 주석뿐이다). 주석이 옛 동작을 가리킨다. 그대로 옮긴다
4. 없는 문서 해시로 부팅했는데 목록이 비어 있으면 `문서를 찾을 수 없습니다.` 없이 홈이 된다(U10). 알림은 `resolved.docId` 가 있을 때만 뜬다. 의도인지는 F-111 판정이다
5. `#/map/{id}` 로 부팅하면 `md.lastDocId` 는 저장하지만 조상 폴더는 펴지 않는다. 문서 해시 갈래는 편다
6. 러너 effect 는 `yjsStoreRef.current` 를 idle 콜백 **안**에서 읽는다. 부팅이 `yjsStoreRef` 를 채우는 것은 `ready` 전이라 늦게 채워질 틈은 없다(순서 확인만, 동작 차이 없음)
7. **경계 — 옆 조각과 대조 필요**: `openSharedFragment`(≈1517, 절 "공유 링크 조각 해석 F-130")는 개요 5.4 표 어느 행에도 이름이 없다. 부팅과 `hashchange` 가 같이 쓰므로 F-2071 이 가져갈 수 있다. 이 조각은 deps 로 받아 어느 쪽이든 맞지만, F-2071 명세가 이 이름을 **훅 안에만** 두고 반환하지 않으면 가정 1 이 깨진다. main 은 F-2071 명세를 쓸 때 대조한다
