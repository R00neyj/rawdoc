# F-3030 원격 MCP 서버 뼈대와 읽기 도구

작성일: 2026-10-16
상태: 승인 2026-10-16(사용자 "ㄱㄱ" — F-4008 개요·새 의존 `@modelcontextprotocol/server` 2.3.1·`zod` 직접 의존·모델이 읽는 글 영어 포함). `POST /mcp` 를 SDK 에 잇고, 읽기 도구 다섯과 쓰기·지우기 명세(F-3031·F-3032)가 쓸 안쪽 요청 도우미를 만든다. 토큰·Origin·401 은 F-4011 `authenticateMcp`. 전부 node 단위, e2e 없음

## 근거 (2026-10-16, 스크래치에 2.3.1 설치·측정)
- `createMcpHandler(factory, { legacy: 'stateless' })`: 2025-06-18 `initialize` 에 `instructions` 가 실려 나가고, GET 은 SDK 가 405, Accept 에 `text/event-stream` 이 없으면 406. 응답은 2025 세대에서 `text/event-stream` 한 이벤트
- `responseMode: 'json'` 은 핸들러를 만들 때마다 콘솔 경고를 찍는다 → 쓰지 않는다(기본 `auto`)
- 요청마다 핸들러+서버+도구 다섯 새로 만들기 `tools/list` 0.56ms, 모듈 하나 공유 0.42ms(node, 300회 평균) → 요청마다 새로(env·사용자를 닫아 넣는다)
- 도구 콜백이 던지면 SDK 가 **예외 메시지를 그대로** `isError` 글로 보낸다 → 2장 `safeTool`. 인자 형식 오류는 SDK 가 `isError` + `Input validation error: …`, 없는 도구는 JSON-RPC `-32602`
- `structuredContent` 에 배열을 주면 SDK 가 `{ result: [...] }` 로 감싼다 → 결과는 늘 객체로 만든다
- 지금 worker 번들 `wrangler deploy --dry-run` 2881 KiB / gzip 576 KiB. `zod` 4.5.4 는 better-auth 를 거쳐 이미 번들에 있다
- `handleListDocsV1` 은 금고 행을 `title: ''`·`e2ee: true` 로 남기고 폴더 거르기가 없다. `handleListFolders` 행에 금고면 `e2ee: true`. `handleSearchV1` 은 내 문서만·금고 제외·200건. `DOC_COUNT_QUOTA` 10,000(`usage.ts`)

## 2. 계약 (`worker/mcpCall.ts`, F-3031·F-3032 가 그대로 쓴다)
```ts
export type McpCall = { request: Request; env: Env; ctx: ExecutionContext; caller: McpCaller }  // McpCaller = F-4011 { user; clientId; clientName }
export const VAULT_DOC_MESSAGE = 'Vault (end-to-end encrypted) documents cannot be opened through this connection.'
export const MCP_LIST_PAGE = 200
export function innerV1(call: McpCall, method: 'GET' | 'POST' | 'PUT' | 'DELETE', path: string, body?: unknown): Request
export function docUrl(call: McpCall, id: string): string            // `${origin}/?app=1#/d/${id}`, origin = call.request.url 의 출처
export function toolResult(data: Record<string, unknown>): CallToolResult   // structuredContent = data, 텍스트 = JSON.stringify(data)
export function toolError(message: string, data?: Record<string, unknown>): CallToolResult  // isError, 둘 다 { message, ...data }
export function toToolResult(res: Response): Promise<CallToolResult>
export function safeTool<A>(cb: (args: A) => Promise<CallToolResult>): (args: A) => Promise<CallToolResult>
```
- `innerV1`: 주소 = 원래 요청 출처 + `path`(`/v1/…`), 헤더는 원래 요청 것을 잇되 `Content-Length` 를 빼고 몸통이 있으면 JSON 직렬화 + `Content-Type: application/json; charset=utf-8`, `rememberUser(inner, call.caller.user)`. 핸들러는 라우터를 거치지 않고 직접 부른다(`handleGetDocV1(innerV1(…), env, ctx, { id })`) — 쓰기 관문은 F-3031 이 앞에서 부른다
- `toToolResult`: 2xx 이고 몸통이 JSON 객체면 `toolResult`. 그 밖은 `toolError(문구, { status, ...몸통 })`, 문구: 404 → `Not found, or you do not have access.` · 403 `e2ee_doc` → `VAULT_DOC_MESSAGE` · 400 `invalid` → `Invalid argument: {field}.` · 나머지 `Request failed ({status} {error}).`
- `safeTool`: 던진 `Response` 는 `toToolResult`, 그 밖은 `console.error` 후 `toolError('Internal error. Try again later.')`. 예외 글은 밖으로 내지 않는다. **모든 도구 콜백을 이것으로 감싼다**

## 3. `/mcp` 처리 (`worker/mcp.ts`)
- 순서: POST 아님 → 405 `{ error: 'method_not_allowed' }` + `Allow: POST`(인증 전) → `authenticateMcp` 가 `Response` 면 그대로 → `createMcpHandler(() => createMcpServer(call), { legacy: 'stateless' }).fetch(request)` → 어디서든 던지면 `console.error` + 500 `{ error: 'internal' }`
- `createMcpServer(call)`: `new McpServer({ name: brand.cliName, title: brand.name, version: '1.0.0' }, { instructions: MCP_INSTRUCTIONS })` → `registerReadTools(server, call)`. 쓰기·지우기는 다음 줄에 `registerWriteTools`(F-3031)·`registerTrashTools`(F-3032)
- `MCP_INSTRUCTIONS`(이름은 `brand.name` 으로 끼운다): `{name} stores Markdown documents exactly as written. Use search or list_documents to find a document, then fetch to read its full text. list_shared shows documents other people shared with you. Vault (end-to-end encrypted) documents are never available through this connection.` F-3031·F-3032 가 자기 문장을 끝에 더한다
- 도구 등록: `server.registerTool(name, { title, description, inputSchema: z.object(…), annotations: { readOnlyHint, destructiveHint, openWorldHint } }, safeTool(cb))`. 주석 셋은 늘 명시 boolean(F-4008 5장)

## 4. 읽기 도구 (모두 주석 `true/false/false`)
| 도구 · 제목 | 입력 (zod) | 부르는 것 | 결과 |
| --- | --- | --- | --- |
| `search` · `Search documents` | `query` 문자열 1–200자 | `GET /v1/search?q=` → `handleSearchV1` | `{ results: [{ id, title, url }] }` |
| `fetch` · `Fetch document` | `id` 문자열 1–64자 | `GET /v1/docs/{id}` → `handleGetDocV1` | `{ id, title, text, url, metadata: { version, folderId, updatedAt } }` |
| `list_documents` · `List documents` | `folderId?` uuid, `offset?` 0 이상 정수 | `handleListDocsV1` | `{ documents: [{ id, title, folderId, version, updatedAt, url }], vaultSkipped, nextOffset? }` |
| `list_folders` · `List folders` | 없음 | `handleListFolders` | `{ folders: [{ id, name, parentId }], vaultSkipped }` |
| `list_shared` · `List shared documents` | `offset?` | `handleListSharedV1` | `{ documents: [{ id, title, role, ownerEmail, sharedFolder, updatedAt, url }], vaultSkipped, nextOffset? }` |
- 설명(description, 영어): search `Find my own documents whose title or text contains the query (case-insensitive for English letters). Returns up to 200 matches, newest first.` · fetch `Read the full Markdown text of a document by id. Works for your documents and documents shared with you. The version is needed to update it.` · list_documents `List your documents, newest first, 200 per page. Pass folderId for the documents directly in that folder, and nextOffset as offset for the next page.` · list_folders `List your folders as a tree (parentId null = top level).` · list_shared `List documents other people shared with you, newest first, 200 per page.`
- `fetch` 의 `text` = `/v1` 응답 `content` 그대로(바이트 보존 — 제품 원칙). 금고 403 → `VAULT_DOC_MESSAGE`
- 목록 셋: 금고 행(`e2ee: true`)은 빼고 범위 안 개수를 `vaultSkipped`. 정렬은 핸들러 그대로, 금고를 뺀 뒤 `offset` 부터 `MCP_LIST_PAGE` 개, 더 있으면 `nextOffset`. `folderId` 는 그 폴더 **바로 아래**만, 내 폴더가 아니면(`getOwnedFolder` 없음) `toolError('Not found, or you do not have access.')`. `sharedFolder` = `viaFolder?.name ?? null`. 폴더 목록은 상한 없음(한 행 ~100바이트, 안 자른다)
- 휴지통 행 거르기는 `/v1` 핸들러 몫(F-3022) — 여기서 따로 하지 않는다. 읽기 도구는 쓰기 관문·쓰기 수를 건드리지 않는다(F-4008 A8 뒤쪽)

## 9. 열린 질문
- Q1 목록 페이지 200·`offset` — 문서 상한 10,000 이라 다 주면 한 번에 2MB 넘게 모델에 들어간다. 다른 안 "다 준다"면 `offset`·`nextOffset` 과 M5 뒷부분이 빠진다
- Q2 `search` 결과를 ChatGPT 표준 세 키로만 — `/v1` 의 맞은 줄(`lines`)도 주면 `fetch` 왕복이 준다. 바꾸면 결과에 `lines` 하나 더하고 M3 만 바뀐다
