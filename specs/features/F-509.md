## 2. 결론 넷 (프롬프트가 결론을 요구한 것)

### 2.1 D-9 문장과 댓글 수를 어디서 얻나

- **문장**: 옮기기(`to-e2ee`)의 D-9 `notes` 맨 끝(N3 뒤)에 한 줄. 서버·로컬, 문서·폴더 모두 같은 규칙
  - 수를 알고 1 이상 → `댓글 {N}개도 함께 지워집니다.` (F-500 5.1 그대로. `{N}` 은 `formatCount` — `1,234`)
  - 수를 알고 0 → 줄 없음
  - 세다 실패 → `댓글이 있다면 함께 지워집니다.` (**신규**, 9장 Q2)
  - 아직 세는 중 → 줄 없음. 결과가 오면 줄이 생긴다 (9장 Q1)
  - 빼기(D-10)에는 없다 — 금고 문서에는 댓글이 없다
- **`N`** = 계획의 `doc` 단계 문서마다 센 수의 합. 문서 하나의 수:
  - **저장된 수** — 서버 저장소는 `GET /api/docs/:id/comments/count` 의 `total`(c5), 로컬 저장소는 F-508 댓글 기록의 항목 수(4.2)
  - **편집기 수** — 그 문서가 이 탭에서 지금 열린 문서이고 F-505 `commentAccess` 가 `read`·`write` 이면 `editorRef.current.comments.map.size`(c12). 아니면 없음
  - 문서 하나의 수 = `max(저장된 수, 편집기 수)`. 이유: 저장된 수는 D1 복사본이라 최대 30초 늦다(c7) — 방금 단 댓글이 빠진다. 편집기 `Y.Map` 이 원본이다(불변조건). 둘 중 큰 쪽을 쓰면 **적게 알리는 일은 없고**, 많게 알리는 것은 방금 지운 댓글이 아직 복사본에 남은 경우뿐이다(9장 Q3)
  - 저장된 수를 세다 실패하면 편집기 수가 있어도 그 문서는 "모름" — 결과 전체가 "모름"(아래 3.1)
- **실패로 치는 것**: 네트워크·401·5xx·그 밖 상태·200 인데 `total` 이 0 이상 정수가 아님. **0 으로 치는 것**: 404 `not_found`(아직 서버에 없는 문서 — `createDoc` 이 outbox 에 남았다. 서버 댓글이 있을 수 없고, 실행기가 어차피 `pending-sync` 로 멈춘다), 409 `e2ee_doc`(이미 금고 — 계획에 들지 않지만 그 사이 다른 곳에서 옮겼을 수 있다)
- **언제 세나**: D-9 를 띄우는 순간 시작하고, 대화상자를 기다리게 하지 않는다 — F-407 7.2 의 `fetchUsage` 와 같은 방식(c10). 동시에 최대 **4개** 요청(`E2EE_COMMENT_COUNT_CONCURRENCY`, 9장 Q5). 첫 실패가 나면 남은 요청을 더 보내지 않는다(결과가 이미 "모름"이다). 대화상자가 닫히면(취소·확인 모두) 진행 중인 요청을 `AbortSignal` 로 끊고 결과를 버린다 — 확인 뒤에는 옮기기 쓰기가 시작되므로 읽기가 연결을 다투지 않게

### 2.2 서버 문서를 금고로 옮길 때 서버 쪽 댓글·알림 — **이미 됐다. 클라이언트는 문장만**

- D1 `doc_comments`·`notifications`·댓글 바이트: 옮기기 batch 안에서 지운다(c1). 엇갈려 도착한 스냅숏은 쓰지 못한다(c3). Cron 이 안전망(c3)
- DO `comments` `Y.Map`: `purgeRoom` 이 본문과 함께 비운다(c2). 실패는 F-407 E40 이 알린다
- 이 기기 `md-yjs` 의 방 기록(댓글 포함): F-407 실행기가 `removeYjsRecord` 로 지운다(c4)
- 편집기에 떠 있던 댓글: F-407 `finishDoc` 이 문서 세션을 새로 열면 금고 경로가 되고 F-505 `commentAccess` 가 `none` 이라 레일·장식이 붙지 않는다(c14). 금고에서 빼면 DO 가 D1 본문에서 새로 심는데 `doc_comments` 행이 없으므로 댓글 없이 시작한다(F-500 3.4·4.7)
- **클라이언트가 할 일**: D-9 문장(2.1) 하나. 서버 삭제 API 를 따로 부르지 않는다
- **남는 것(알려진 한계, 새로 생기지 않음)**: 다른 기기의 `md-yjs` 에 남은 방 기록(댓글 포함)은 그 기기가 문서를 열 때까지 남는다 — F-407 이 본문에 대해 이미 가진 한계(F-407 14장 6번)와 같다. 받는 사람 화면에 60초 안 가져온 알림 항목이 남을 수 있고 누르면 C9(F-507)

### 2.3 로컬 금고로 옮길 때 F-508 기록 지우기 — **`idbStore.setDocE2ee` 의 같은 트랜잭션에서**

- 금고로 옮기는 `setDocE2ee(id, { e2ee: true, … })` 가 `docs` 행을 봉투로 덮어쓰는 **같은 IndexedDB 트랜잭션**에서 그 문서의 댓글 기록을 지운다. 빼기(`e2ee: false`)는 기록을 건드리지 않는다
- F-407 11장은 "실행기 `doc` 단계 8번 뒤에 더한다" 를 제안했다. 그쪽을 쓰지 않는 이유: 기록에는 본문의 **평문 인용**(`quote` 최대 200자, `prefix`·`suffix` 32자씩, F-500 3.3)이 있다. 행을 봉투로 바꾼 뒤 기록 지우기 전에 탭이 닫히면 금고 문서의 평문 조각이 기기에 남고, 금고 문서에는 댓글 UI 가 없으니 다시 지울 길도 없다. 한 트랜잭션이면 "봉투 + 평문 기록" 상태가 생기지 않는다(9장 Q4)
- **금고 행에는 기록을 쓰지 않는다**: F-508 이 만든 기록 쓰기 자리(본문 저장과 같은 트랜잭션)는 같은 트랜잭션에서 읽은 `docs` 행에 `e2eeKey` 가 있으면 기록을 쓰지 않는다. 막는 경우: 옮기는 동안 다른 탭(편집권 탭)이 옛 편집기 상태로 저장을 한 번 더 보내는 경우, 세션을 닫을 때의 마지막 저장. F-508 이 이미 이 조건을 두었으면 이 명세는 테스트(U11)만 더한다
- 로컬 문서 삭제 때 기록 지우기는 F-508 몫이다(F-500 4.5 "문서를 지우면 기록도 지운다")
- 서버 저장소(로그인)에는 해당 없음 — 서버 문서의 기록은 `md-docs` 가 아니라 `md-yjs` 에 있다(c4)

### 2.4 금고 문서에 댓글 UI 가 없음을 e2e 로 — **F-505 E15 가 못 보는 두 길**

- F-505 E15 는 처음부터 금고인 **로컬** 문서만 본다(c14). 이 명세는 **옮기기를 거친** 문서를 본다 — 댓글이 붙어 있던 문서가 같은 탭에서 금고가 되는 전환이 이 명세의 몫이다
  - 서버: 실시간으로 열려 댓글 카드가 보이던 문서를 옮긴 뒤(E3)
  - 로컬: 댓글을 단 로컬 문서를 옮긴 뒤(E4)
- 판정 선택자는 F-505 3.8 의 계약 이름 그대로(5장 표)

## 4. 규칙

### 4.1 App 흐름 — `requestE2eeConvert` 에 더하는 것 (F-407 7.3 5번)

1. 옮기기(`to-e2ee`)면 D-9 를 띄우는 **같은 순간**에 `countE2eeConvertComments` 를 시작한다. `docIds` = 계획의 `doc` 단계 id(순서 그대로), `signal` = 이 대화상자용 `AbortController` 하나
2. `storedCount`: 서버 저장소면 `fetchCommentCount(id, { signal }).total`. 로컬 저장소면 F-508 읽기 함수(4.2)의 항목 수 — 저장소에 그 함수가 없으면 0
3. `liveCount`: `id` 가 지금 문서이고 편집기 핸들이 있고 F-505 `commentAccess` 가 `read`·`write` 이면 `comments.map.size`, 아니면 `null`. **대화상자를 띄울 때 한 번 읽은 값**을 쓴다(그 뒤 새 댓글은 세지 않는다 — 옮기는 동안은 F-407 7.4 가 문서를 읽기 전용으로 만든다)
4. 결과가 오면 — 대화상자가 아직 같은 것일 때만(`fetchUsage` 결과와 같은 판정, c10) — 그때까지 받은 `usage` 와 함께 `buildE2eeConvertDialogText` 로 글을 다시 만든다. `fetchUsage` 결과가 나중에 와도 `comments` 를 잃지 않는다(두 결과를 같은 곳에 모아 두고 어느 쪽이 오든 둘 다 넣어 다시 만든다)
5. 대화상자가 닫히면(`answerE2eeConvertDialog` — 취소·확인) `abort()`. 결과 `null` 은 버린다
6. 빼기(`from-e2ee`)는 세지 않는다

- `옮기기` 단추는 세는 동안에도 누를 수 있다(9장 Q1)
- 멈춘 옮기기를 다시 누르면 새 계획의 남은 문서만 센다 — 앞에서 옮긴 문서의 댓글은 이미 지워졌다
