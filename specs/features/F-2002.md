### 2.3 **회전이 아직 안 된다**가 정확히 무슨 뜻인가 — 중간 상태의 정의

F-292 9.1 이 "회전은 아직 안 되지만 지도는 3D 로 떠 `맞춤` 된 상태로 보이고 노드 클릭·목록·닫기가 전부 동작한다"고만 적었다. **이 명세가 그 문장을 다음처럼 확정한다.**

**카메라는 고정이다. 확대도 이동도 회전도 없다.** 카메라는 그래프 무게중심의 `+Z` 축 위에 놓이고 언제나 중심을 바라본다. 사용자가 카메라를 움직일 수단은 **`맞춤` 버튼 하나뿐**이고, 그 버튼조차 "이미 맞춰진 것을 다시 맞추는" 동작이다. 휠 확대를 임시로 붙이지 않는다 — F-2003 이 `OrbitControls` 로 같은 일을 하므로 손으로 짠 뒤 지우는 낭비가 된다 (15장 Q2).

**머리 줄에 남는 것 / 없는 것**

| | 항목 |
| --- | --- |
| 남는다 | 제목 `지도`(아이콘+글자) · 세그먼트 `지도`·`목록` · `맞춤` · `닫기` |
| 없앤다 | `현재 문서`·`전체` 세그먼트, `몇 다리까지` 라벨과 `1단계`·`2단계`·`3단계` 세그먼트 |
| **아직 안 만든다** | `설정`(아이콘) — F-2005 가 패널과 함께 넣는다. **누르면 아무 일도 안 하는 단추를 미리 두지 않는다** (15장 Q3) |

**사용자가 할 수 있는 일**

1. 사이드바(또는 레일) `지도` 로 연다. 해시는 `#/map/{현재 문서 id}`, 편집 영역은 언마운트되지 않고 `hidden` 으로만 숨는다
2. 3D 로 배치된 문서 덩어리를 본다. 배치가 잡히는 동안 카메라가 자동으로 따라 물러나 **언제나 전체가 화면에 들어온다**
3. 노드를 좌클릭해 그 문서를 연다(지도가 닫힌다). 끊긴 링크 노드면 그 제목으로 새 문서를 만들어 연다 (F-131 5장)
4. 노드를 `Ctrl`(⌘)+좌클릭하면 지도를 닫지 않고 그 노드가 강조되고 해시가 `#/map/{id}` 로 바뀐다
5. `목록` 으로 바꿔 `나가는 링크`·`들어오는 링크`·`끊긴 링크` 묶음과 `연결이 많은 순` 을 보고, 항목을 클릭(또는 `Ctrl`+클릭)한다
6. `맞춤` 으로 카메라를 다시 맞춘다
7. `닫기`·브라우저 뒤로 가기로 나간다
8. 설정에서 테마를 바꾸면 지도 색이 곧바로 따라온다
9. WebGL2 가 없는 브라우저면 `목록` 으로 자동 전환되고 안내 줄이 뜬다

**쓸 만한가 — 판단.** 쓸 만하다. 다만 **이 한 커밋 동안 "3D 처럼 안 보일" 위험이 실제로 있다.** 카메라가 고정이고 F-2004 의 깊이 섞기도 아직 없어서, 원근 하나로만 깊이를 느껴야 한다. 노드가 수십 개인 현재 사용자 데이터에서는 "흩어진 점 그림"으로 보일 공산이 크다. 이것은 **받아들이는 대가**다 — F-292 9.1 이 "쪼개면 중간 커밋에서 화면이 깨진다"고 쪼개지 않기로 했고, 회전(F-2003)과 깊이(F-2004)는 바로 다음 두 커밋이다. 사람 확인 H-b 가 이 점을 묻는다.

## 3. `three@0.186.0` — 설치하지 않고 소스를 읽어 확인한 것

**스크래치패드에 `npm i three@0.186.0` 해서 `node_modules/three/src/**` 를 직접 읽었다. 저장소에는 아직 설치하지 않았다.** 행 번호는 그 소스의 행이다.

### 3.1 번들 — 직접 쟀다. **F-292 3.1 의 198 KB 는 tree-shaking 없는 기준이었다**

F-292 3.1 은 그릴링 세션에서 받은 값(three 184,897 B gzip)을 인용했고 이 저장소에서 잰 값이 아니라고 12장에 밝혀 뒀다. **직접 쟀다.**

측정: 스크래치패드에서 `npm i three@0.186.0 d3-force-3d@3.0.6` 뒤
`esbuild entry.mjs --bundle --minify --format=esm` → `zlib.gzipSync(buf, { level: 9 })`.

| 무엇을 번들했나 | raw | gzip |
| --- | --- | --- |
| `import * as THREE from 'three'` (tree-shaking 없음) | 742,859 B | **190,379 B** |
| **우리가 쓸 것만 이름으로 import** (아래 목록) | 538,168 B | **135,039 B** |
| 위 + `OrbitControls` (F-2003 이 더할 몫) | 560,977 B | 140,486 B |
| **우리 import 집합 + `d3-force-3d`** (= 지도 청크의 의존성 전부) | **564,947 B** | **143,632 B** |

우리 import 집합:
`WebGLRenderer` · `Scene` · `PerspectiveCamera` · `InstancedMesh` · `SphereGeometry` · `MeshBasicMaterial` · `LineSegments` · `LineBasicMaterial` · `BufferGeometry` · `BufferAttribute` · `Color` · `Object3D` · `Vector3` · `Matrix4` · `Raycaster` · `Vector2` · `SRGBColorSpace` · `DynamicDrawUsage`

**결론 셋.**

1. **three 는 이 사용 패턴에서 tree-shaking 이 된다. 55,340 B gzip(29%) 차이다.** F-292 3.1 이 bundlephobia 를 근거로 "사실상 안 된다"고 적은 것은 `import * as THREE` 기준이었다. 14장 갱신 대상.
2. **그래서 구현 규칙으로 못 박는다 — `import * as THREE from 'three'` 를 쓰지 않는다.** 필요한 것만 이름으로 가져온다. 이 한 줄이 55 KB 다.
3. 지도 청크 예상은 **약 575 KB raw / 147 KB gzip**(위 564,947/143,632 + 우리 코드 ~10 KB/~3 KB). G2(198 KB)·G3(3 MiB)에 여유가 크다. 실제 값은 10장에서 빌드로 확인한다.

`@types/three@0.186.0` 은 **런타임 번들에 영향이 없지만 디스크에는 영향이 있다** — 직접 재 보니 `fflate`·`meshoptimizer`·`@tweenjs/tween.js`·`@dimforge/rapier3d-compat`·`@types/webxr`·`@types/stats.js` 까지 **7개 패키지 13 MB** 가 딸려 온다(그중 `@dimforge/rapier3d-compat` 이 7.3 MB). addons 타입을 위한 것이고 `devDependencies` 라 `dist` 에 한 바이트도 안 들어간다. 손으로 선언을 쓰는 대안은 three 의 API 폭이 `d3-force-3d` 와 비교가 안 돼 현실적이지 않다 (15장 Q6).

### 3.2 `WebGLRenderer` 생성 — 기본값과 **던진다는 사실**

`src/renderers/WebGLRenderer.js` 70~85행이 생성자 기본값이다.

| 옵션 | 기본값 | 우리가 |
| --- | --- | --- |
| `canvas` | `createCanvasElement()`(새로 만든다) | **우리가 만든 `<canvas>` 를 넘긴다** — React 가 그린 요소에 `role`·`aria-label` 을 선언적으로 달기 위해서다 (6.2) |
| `antialias` | **`false`** | **`true`** — 구체 외곽선과 1px 선이 계단으로 보인다 |
| `alpha` | **`false`** | `false`(기본). 배경은 `--panel` 로 칠한다 |
| `powerPreference` | `'default'` | `'high-performance'` — 노트북 통합 GPU 에서 외장으로 넘어갈 여지를 준다 |
| `stencil` | `false` | 기본 |
| `depth` | `true` | 기본 |

- **408~425행: `webgl2` 컨텍스트를 못 얻으면 생성자가 `Error` 를 던진다.** `WebGLRenderer` 는 r163 이후 WebGL1 을 지원하지 않는다(102행이 명시적으로 던진다). 그래서 `canvas.getContext('webgl2') === null` 검사와 **생성자 `try`/`catch` 를 둘 다** 둔다 (6.2)
- `renderer.setAnimationLoop(fn)`(1609행) / `setAnimationLoop(null)` 로 루프를 세운다. 직접 `requestAnimationFrame` 을 돌리지 않는다 — three 가 권장하는 방식이고 XR 대응 코드를 우회하지 않는다
- `renderer.setSize(w, h, false)`(671행) — 세 번째 인자 `updateStyle=false` 로 두어 캔버스의 CSS 크기를 건드리지 않는다. CSS 가 `width:100%;height:100%` 로 잡고 그리기 버퍼만 맞춘다
- `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))` — 상한 2. 4K·200% 배율에서 픽셀 수가 네 배로 뛰는 것을 막는다

### 3.3 **색 관리 — 이 명세에서 가장 놓치기 쉬운 지점**

| 확인 | 결과 | 근거 |
| --- | --- | --- |
| `ColorManagement.enabled` | **기본 `true`** | `math/ColorManagement.js` 21행 |
| `ColorManagement.workingColorSpace` | **`LinearSRGBColorSpace`** | 같은 파일 23행 |
| `renderer.outputColorSpace` | **`SRGBColorSpace`** | `WebGLRenderer.js` 312행 |

| `Color.setStyle(style, colorSpace)` | `rgb()`·`rgba()`·`hsl()`·`#hex` 만 본다. **`color(srgb …)` 는 `default:` 로 떨어져 `Unknown color model color` 경고를 내고 색이 안 바뀐다** | `math/Color.js` 286~400행 |

**그래서 규칙 두 개.**

1. **`setRGB(r, g, b, SRGBColorSpace)` 로 네 번째 인자를 반드시 준다.** 빠뜨리면 우리가 넘긴 sRGB 0~1 값이 "이미 선형"으로 취급돼 변환 없이 저장되고, 출력 단계에서 선형→sRGB 변환이 한 번 더 먹어 **화면이 눈에 띄게 밝고 뿌옇게 나온다.** 컴파일도 통과하고 예외도 없어 **눈으로만 잡히는 종류의 실수**다.
2. **`setStyle()` 에 CSS 문자열을 넘기지 않는다.** F-292 3.4 가 "three 의 파서가 `color(srgb …)` 를 받는지 확인 못 했다"며 우회하기로 한 결정은 **여전히 옳고, 이제 코드 근거가 있다** — 위 표 다섯째 줄. 다크 테마의 `--accent` 가 정확히 `color(srgb …)` 로 계산되므로(5.1) `setStyle` 을 쓰면 **다크 테마에서만 노드가 검게** 나온다.

배경(`scene.background`)·재질 색·인스턴스 색 전부 같은 규칙이다.

## 5. `src/lib/cssColor.ts` — 공개 API 전문

### 5.1 받아야 하는 모양 — Chrome 에서 직접 쟀다

설치된 Chrome 을 Playwright 로 띄워 `el.style.color = X` 뒤 `getComputedStyle(el).color` 를 읽었다 (2026-09-21).

| 넣은 값 | 계산값 |
| --- | --- |
| `#3B4890` | `rgb(59, 72, 144)` |
| `#abc` | `rgb(170, 187, 204)` |
| `#3B489080` | `rgba(59, 72, 144, 0.5)` |
| `rgb(59 72 144)` (공백꼴) | `rgb(59, 72, 144)` |
| `rgb(59 72 144 / 30%)` | `rgba(59, 72, 144, 0.3)` |
| `hsl(120, 50%, 50%)` | `rgb(64, 191, 64)` |
| `rebeccapurple` | `rgb(102, 51, 153)` |
| `transparent` | `rgba(0, 0, 0, 0)` |
| **`color-mix(in srgb, #3B4890 55%, white)`** | **`color(srgb 0.577255 0.605294 0.760588)`** |
| **`color-mix(in srgb, #3B4890 30%, transparent)`** | **`color(srgb 0.231373 0.282353 0.564706 / 0.3)`** |
| `color-mix(in oklab, #3B4890 55%, white)` | `oklab(0.686383 0.00314942 -0.0653011)` |
| `color(display-p3 0.5 0.2 0.1)` | `color(display-p3 0.5 0.2 0.1)` |

**읽히는 사실 넷.**

1. **Chrome 은 `hsl()`·색 이름·공백꼴 `rgb()` 를 전부 `rgb()`/`rgba()` 로 정규화한다.** 파서가 hsl 이나 색 이름을 알 필요가 없다
2. **알파가 있으면 `rgba(r, g, b, a)` 로 나온다.** `rgb(r g b / a)` 로는 안 나온다. (그래도 공백꼴을 받아 두면 손해가 없어 받는다)
3. **`color-mix(in srgb, …)` 만 `color(srgb …)` 로 나온다.** `in oklab` 은 `oklab(…)` 이 되고 우리 파서가 거절한다 — **`tokens.css` 의 `color-mix` 9건이 전부 `in srgb` 인 것을 `grep -o "color-mix(in [a-z-]*"` 로 확인했다.** 이 사실은 14장 갱신 대상에 제약으로 올린다
4. `oklch`·`oklab`·`color(display-p3 …)` 는 그대로 흘러나온다 → **`null` 을 돌려주는 것이 맞다**

### 5.2 API 전문

```ts
// CSS 색 문자열 → 0~1 sRGB 넷. three 의 Color.setStyle() 이 color(srgb …) 를 못 받아서
// 우리가 파싱한다 (specs/features/F-292.md 3.4, F-2002 3.3·5장)
// DOM 을 쓰지 않는 순수 모듈이다 — 테스트 환경이 node 라 이 규칙이 곧 테스트 가능성이다

/** 0~1 로 자른 sRGB 넷. 알파가 없던 입력은 1 */
export type Rgba = [number, number, number, number]

/**
 * 받는 모양은 아래뿐이다. 그 밖(oklch·oklab·color(display-p3 …)·빈 문자열·쓰레기)은 null.
 *   #rgb · #rgba · #rrggbb · #rrggbbaa      (대소문자 무시)
 *   rgb(r, g, b) · rgba(r, g, b, a)          (쉼표꼴. r·g·b 는 0~255 또는 %, a 는 0~1 또는 %)
 *   rgb(r g b) · rgb(r g b / a)              (공백꼴)
 *   color(srgb r g b) · color(srgb r g b / a) (r·g·b 는 0~1 실수 또는 %)
 * 앞뒤 공백은 버린다. 범위를 벗어난 성분은 0~1 로 자른다.
 */
export function parseCssColor(input: string): Rgba | null
```

- **내보내는 것은 이 둘뿐이다.** 깊이 섞기·필터 흐리기의 색 보간은 `lib/mapNodeStyle.ts`(F-2004) 몫이라 여기 넣지 않는다 (F-292 2장)
- `null`·`undefined` 가 들어와도 던지지 않고 `null` 을 돌려준다 (`typeof input !== 'string'` 먼저 검사)
- `color(srgb …)` 의 성분은 **0~1 실수**, `rgb(…)` 의 성분은 **0~255**. 같은 함수가 둘을 섞지 않게 분기를 나눈다
- **파싱에 실패했을 때 무엇을 쓰나는 `MapScene` 이 정한다** — 6.3 이 `[0.5, 0.5, 0.5, 1]`(중간 회색)을 쓴다고 적었다. `cssColor.ts` 는 기본값을 모른다

1. **three 객체는 전부 `useRef` 에 담은 하나의 가변 객체(`sceneRef.current`)에 모은다.** React state 에 넣지 않는다 (렌더마다 재생성되면 안 된다)
2. **`useEffect` 는 두 개뿐이다** — (a) 그래프가 바뀔 때 도는 "장면 만들고 버리기" effect, (b) `fitToken` 이 바뀔 때 도는 "다시 맞추고 다시 그리기" effect. **F-2003 에서 넷이 됐다** — (c) `centerId` 전용(그 노드로 카메라 이동), (d) `menuOpen` 전용(조작 잠그기)이 더해졌다 (F-2003 9.2)

### 6.2 props 와 WebGL 판정

```tsx

  centerId: string | null   // #/map/{id} 의 그 문서. 없으면 null

/** WebGL2 를 쓸 수 있나. 한 번 재면 모듈 수준에 캐시한다 */
```

- **`MapPage` 가 `MapScene` 을 그리기 전에 `hasWebGL2()` 로 먼저 판정한다** (F-292 3.6). `false` 면 `MapScene` 을 아예 마운트하지 않는다
- `hasWebGL2()` 는 **DOM 에 붙이지 않는 1×1 `<canvas>`** 로 재고, 얻은 컨텍스트는 곧바로 `getExtension('WEBGL_lose_context')?.loseContext()` 로 놓는다. 컨텍스트 슬롯을 낭비하지 않기 위해서다
- `onUnsupported` 는 **두 번째 그물**이다. `getContext` 는 됐는데 `new WebGLRenderer({ antialias: true, … })` 가 던지는 경우(3.2)를 잡는다. 이때도 같은 목록 보기로 떨어진다
- 캔버스는 JSX 로 그린다 — `role="img"`, `aria-label`, `tabIndex={-1}`:

```tsx

  ref={canvasRef}
  className="map-canvas"
  role="img"
  aria-label={`문서 ${graph.nodes.length}개, 연결 ${graph.edges.length}개의 지도. 같은 내용을 목록으로 보려면 목록 단추를 누르세요.`}
  tabIndex={-1}
```

### 6.3 테마 색을 어떻게 읽나 — F-292 3.4 를 더 단순하게

F-292 3.4 는 "토큰 수만큼 `<span>` 을 두고 **CSS 로** `color: var(--…)` 를 건다"고 적었다. **직접 재 보니 CSS 규칙이 필요 없다.**

Chrome 에서 확인한 것 (2026-09-21):

- `el.style.color = 'var(--ink)'` 로 **인라인 스타일에 `var()` 를 넣어도** `getComputedStyle(el).color` 가 제대로 해석된 값을 준다
- **조상에 `display:none` 이 걸려 있어도 값이 그대로 읽힌다**
- 없는 토큰(`var(--nope)`)은 `rgb(0, 0, 0)`(초기값)이 된다 — **없는 토큰과 진짜 검정을 구분할 수 없다.** 우리가 읽는 토큰은 전부 `tokens.css` 에 있으므로 문제가 되지 않지만, 토큰 이름을 틀리면 조용히 검정이 된다는 사실은 알고 있어야 한다

**그래서 이렇게 한다.**

```
프로브 <span aria-hidden="true" class="map-probe"> 하나를 지도 컨테이너에 붙인다.
읽을 때: 토큰마다  probe.style.color = ''  →  probe.style.color = `var(${token})`
         →  parseCssColor(getComputedStyle(probe).color)
```

| 읽는 토큰 | 쓰는 곳 |
| --- | --- |
| `--panel` | 배경 |
| `--ink` | 보통 노드 |
| `--accent` | 현재 문서 노드 |
| `--muted` | 끊긴 링크 노드 |
| `--rule` | 간선 |

- 요소 하나를 돌려쓰므로 `getComputedStyle` 호출이 **열 때 5번, 테마가 바뀔 때 5번**이다
- **파싱 실패 시 `[0.5, 0.5, 0.5, 1]`(중간 회색).** 어떤 테마에서도 보이는 색이고, 디자인 색이 아니라 "읽기 실패 표시"라는 뜻이다. 실제로는 닿지 않는 경로다(5.1 로 확인)
- 다시 읽는 시점: **지도를 열 때 한 번**, 그리고 `document.documentElement` 의 `data-theme` 변화를 `new MutationObserver(...)` + `observe(root, { attributes: true, attributeFilter: ['data-theme'] })` 로 볼 때
- **`prefers-color-scheme` 을 따로 듣지 않는다.** `App.tsx` 1010~1017행이 `md.theme === 'system'` 일 때도 항상 해석된 값을 `documentElement.dataset.theme` 에 쓰는 것을 확인했다. 위 Observer 하나로 전부 잡힌다
- **`App.tsx` 에 `setTheme` 호출을 더하지 않는다** (F-292 3.4 가 `F-156 A7` 회귀를 이유로 못 박았다)
- 색이 바뀌면 인스턴스 색·간선 재질 색·`scene.background` 를 다시 쓰고 **한 프레임 다시 그린다**(시뮬레이션은 건드리지 않는다)

### 6.4 무엇을 어떤 색·크기로 그리나 — F-2002 판

**F-292 6.1 의 반지름 공식과 깊이 섞기는 `lib/mapNodeStyle.ts`(F-2004) 의 것이다.** 그 파일은 순수 모듈이라 단위 테스트로 판정되는데, 공식을 `MapScene.tsx` 에 먼저 적어 두면 **테스트 없는 사본**이 하나 생기고 F-2004 가 그걸 지우며 옮겨야 한다. 그래서 F-2002 는 공식을 쓰지 않는다 (15장 Q1).

| 대상 | F-2002 | F-2004 가 바꿀 것 |
| --- | --- | --- |
| 노드 반지름 | **전부 `6.0`**, 끊긴 링크만 `3.0` | `(3 + 2.2 × √(min(degree,64))) × 배율` |
| 보통 노드 색 | `--ink` | 그룹 색 (F-2008) |
| 현재 문서(`centerId`) | `--accent` | + 바깥 링 |
| 끊긴 링크 | `--muted` | 그대로 |
| 공유받은 문서 | **`--ink`** (테두리 없음) | `--ink-2` 테두리 |
| 간선 | `--rule` 한 가지 | 현재 문서에 닿는 간선만 다른 색 |
| 깊이 | **없음** | `--panel` 쪽으로 보간 |
| 이름표 | **없음** | `MapLabels.tsx` |

끊긴 링크 노드의 `3.0` 은 F-292 6.1 표가 이미 "degree 와 무관하게 3.0 고정"으로 정한 값이라 그대로 쓴다.

### 6.5 그리기 루프

```
그래프를 받으면
  layout = createMapLayout(displayGraph)     // F-2001. tick 을 한 번도 돌리지 않은 상태
  장면·메시·재질·카메라를 만든다
  reduced = matchMedia('(prefers-reduced-motion: reduce)').matches
  renderer.setAnimationLoop(frame)

frame():
  if (reduced) {
    if (!layout.isSettled()) {
      layout.runTickBudget(8)                 // F-2001 7장
      if (!layout.isSettled()) return         // 다 돌 때까지 그리지 않는다
      onLayoutReady()                         // MapPage 의 `배치를 계산하는 중…` 을 지운다
    }
  } else if (!layout.isSettled()) {
    layout.tick(1)                            // 프레임마다 1 tick — 배치가 잡혀 가는 모습이 보인다
  }

  if (!layout.isSettled()) fitCamera()        // 멈출 때까지 자동으로 맞춘다
  uploadPositions()                           // setMatrixAt 루프 + readEdgePositions
  renderer.render(scene, camera)

  if (layout.isSettled() && !dirty) renderer.setAnimationLoop(null)   // 멈춘다
```

- **`dirty` 를 세우고 루프를 다시 켜는 경우**: 창 크기 변화, 테마 변화, `fitToken` 증가(`맞춤`). `requestDraw()` 하나가 `dirty = true` + 루프가 꺼져 있으면 `setAnimationLoop(frame)` 을 한다
- **보통 동작(reduced-motion 아님)은 프레임마다 1 tick 이다.** 기본 `alphaDecay` 에서 정확히 300 tick 에 멈추므로(F-2001 3.1·8장) 노드 수와 무관하게 **약 5초 동안 배치가 잡혀 간다.** 그것이 "재미"(F-292 결정 1)의 몫이고, 1 프레임에 여러 tick 을 몰면 작은 그래프에서 애니메이션이 아예 안 보인다
- **reduced-motion 이면 `배치를 계산하는 중…` 이 뜨고, 다 돌면 사라지면서 첫 프레임이 그려진다** (F-292 4.2). 이 문구의 등장·소멸이 **10장 G5 의 유일한 DOM 관측 통로**다
- `onLayoutReady` 는 `MapScene` → `MapPage` 콜백이 아니라 **`MapPage` 가 넘긴 `onLayoutReady?: () => void` prop** 이다. `MapPage` 가 `배치를 계산하는 중…` 을 자기 본문에 그린다 (7.4)

### 6.7 카메라 `맞춤`

`PerspectiveCamera` 기본값은 `(fov 50, aspect 1, near 0.1, far 2000)` 이다(`PerspectiveCamera.js` 33행). **`far` 2000 을 그대로 두면 안 된다** — F-2001 8장 실측에서 2,000 노드의 평균 원점 거리가 2,338 이라 덩어리가 통째로 잘린다.

```
const { center, radius } = layout.bounds()      // F-2001 5.3
const r = Math.max(radius, 1)
const vFov = camera.fov * Math.PI / 180
const hFov = 2 * Math.atan(Math.tan(vFov / 2) * camera.aspect)
const dist = (r * 1.15) / Math.sin(Math.min(vFov, hFov) / 2)   // 1.15 = 여백
camera.position.set(center[0], center[1], center[2] + dist)
camera.lookAt(center[0], center[1], center[2])
camera.near = Math.max(dist * 0.01, 0.1)
camera.far = dist + r * 4
camera.updateProjectionMatrix()
```

- `Math.min(vFov, hFov)` 로 **좁은 쪽 시야**에 맞춘다. 창이 세로로 길면 가로가 좁고, 그 반대도 있다
- `near` 를 `dist` 에 비례시켜 잡는 것은 깊이 버퍼 정밀도 때문이다. `near` 가 너무 작으면 멀리 있는 구체들이 서로 파고든다
- 배치가 멈출 때까지 **프레임마다** 이 계산을 한다(6.5). 계산은 `bounds()` 한 번 + 산수 몇 줄이라 비용이 없다
- **F-2003 에게**: `OrbitControls` 가 붙으면 **사용자가 카메라를 한 번이라도 건드린 뒤에는 자동 맞춤을 멈춰야 한다.** 그 판정은 F-2003 이 더한다
- **F-2003 이 고친 것**: 위 `r` 에는 **최대 노드 반지름을 더해야 한다** (`Math.max(radius + maxNodeRadius, 1)`). 노드가 하나뿐이면 `bounds.radius` 가 0 이라 카메라 거리가 2.72 가 되는데 노드 반지름이 6.0 이라 **카메라가 구체 안으로 들어가 첫 실행 화면에 아무것도 안 보인다** (F-2003 7.2)

```
  나가는 링크 (N) / 들어오는 링크 (N) / 끊긴 링크 (N)
```

## 9. `scripts/measure.mjs` — 옵션 둘

### 9.1 `--docs {문서 수}:{문서당 링크 수}`

10장 G4·G5 를 재려면 문서 N개가 든 저장소가 필요하다. `importMarkdown` 은 한 건씩 `input[type=file]` 에 넣고 문서가 열릴 때까지 기다리므로 2,000건에 쓸 수 없다.

**IndexedDB 에 직접 넣는다.**

```
opts.docs = { count, links }   // "--docs 2000:1" → { count: 2000, links: 1 }

await openApp(page)                       // 첫 실행 — DB(md-docs, v4)가 만들어지고 `사용법` 1건이 생긴다
await page.evaluate(seedDocs, opts.docs)  // docs 스토어에 count 건을 put
await page.reload()
await page.locator('.sidebar').waitFor()
```

`seedDocs` 가 넣는 레코드 (`src/types.ts` 5~20행의 `Doc` 모양 그대로):

```js
{ id: `m${i}`, title: `문서 ${i}`, content, lineEnding: 'lf',
  createdAt: base + i, updatedAt: base + i, folderId: null, pinnedAt: null }
```

- **그래프 모양은 F-2001 8장의 벤치마크와 같게 만든다** — 앞쪽 `round(count × 0.95)` 건만 링크를 갖고 나머지 5%는 고립 문서다. 링크 상대는 **선호적 연결**(허브가 생기게): 씨앗 1 의 선형 합동 난수 `r` 로 `target = 1 + floor(r² × (i - 1))`. **`Math.random` 을 쓰지 않는다** — 재현되지 않는 측정은 게이트 판정에 못 쓴다
- 본문은 `문서 {i}\n\n[[문서 {t1}]] [[문서 {t2}]] …\n` (링크 `links` 개)
- `--docs` 를 주면 `--doc`(본문 픽스처)과 `importMarkdown` 은 건너뛴다. 둘을 같이 주면 오류
- JSON 출력에 `docs: { count, links }` 를 함께 찍는다

### 9.2 `--reduced-motion`

`page.emulateMedia({ reducedMotion: 'reduce' })` 를 `page.goto` 전에 건다. `e2e/transition.spec.js:269` 가 쓰는 것과 같은 방법이다.

**왜 필요한가**: 10장 G5 가 잴 수 있는 유일한 통로가 reduced-motion 경로의 `배치를 계산하는 중…` 이기 때문이다(10.2). F-292 7장은 `--docs` 만 언급했지만, 그 문장은 "문서를 하나만 넣을 수 있다"는 제약을 푸는 이야기였고 이 플래그는 별개의 작은 추가다. 14장 갱신 대상에 올린다.

### 10.2 G4·G5 (성능) — **무엇을 재는지 먼저 정한다**

**G5(`배치가 멈출 때까지 3,000 ms`)를 보통 동작에서 재면 뜻이 없다.** 6.5 대로 보통 동작은 **프레임마다 1 tick** 이고 기본 `alphaDecay` 에서 정확히 300 tick 에 멈추므로(F-2001 3.1), **노드가 20개든 2,000개든 60 fps 에서 약 5초**다. 그건 성능이 아니라 애니메이션 길이다.

**그래서 G5 는 reduced-motion 경로에서 잰다** — 프레임당 8 ms 예산으로 300 tick 을 다 도는 데 걸리는 **순수 계산 시간**이고, 이것이 F-2001 8장이 "Node 에서 2,000 노드 300 tick = 4,138 ms" 로 비교한 그 값이다. 14장 갱신 대상에 F-292 7장 G5 행을 이렇게 고치라고 적는다.

| # | 무엇을 | 목표 | 재는 법 |
| --- | --- | --- | --- |
| **G4** | 사이드바 `지도` 클릭 → 캔버스가 DOM 에 생기기까지 | **100 ms** | 아래 (a) |
| **G5** | reduced-motion 에서 `배치를 계산하는 중…` 이 뜬 뒤 사라질 때까지 (문서 2,000) | **3,000 ms** | 아래 (b) |

(a)
```

```

(b)

- G6(회전 fps)·G7(시뮬레이션 중 fps)은 **F-2003·F-2006 몫이다.** F-2002 는 재지 않는다

### 10.3 **G5 를 못 맞췄을 때 — 이 순서대로 한다**

F-2001 8장 Node 실측이 이미 4,138 ms 다. **넘을 공산이 크다는 것을 전제로 쓴다.**

1. **먼저 잰다.** 10.2 (b). 3,000 ms 이하면 `NODE_CAP = 2000` 으로 확정하고 끝
2. **넘으면 `NODE_CAP` 을 1000 으로 내리고 다시 잰다.** 문서는 `--docs 2000:1` 그대로 두고 상한만 내린다(상한이 실제로 동작하는지도 같이 보게 된다). F-2001 8장에서 1,000 노드 300 tick 이 Node 1,809 ms 였으므로 통과할 공산이 크다
   - 통과하면 **`NODE_CAP = 1000` 으로 확정한다.** F-292 12장 Q5 가 "그 판단은 사람 승인 없이 F-2002 가 게이트 결과로 내린다"고 이미 정했다
   - 꼬리 줄 문구의 숫자가 `2,000` → `1,000` 으로 따라 바뀐다. 문구는 `NODE_CAP` 에서 만들므로 코드는 한 군데만 바뀐다. **`specs/features/F-292.md` 4.3·6.12 의 `2,000` 을 고쳐야 한다는 사실을 14장 갱신 대상에 미리 올려 둔다**
3. **1,000 에서도 넘으면 거기서 멈추고 보고한다.** 이유:
   - F-292 7장 "넘으면 순서대로"의 **(2) `alphaDecay` 를 키워 tick 수를 줄임**은 **이 명세의 파일 소유를 벗어난다.** `src/types/d3-force-3d.d.ts` 의 `Simulation` 인터페이스에 `alphaDecay` 가 **선언되어 있지 않고**(직접 확인했다) `src/lib/mapLayout3d.ts` 도 그것을 내보내지 않는다. 둘 다 **F-2001 소유**다
   - **(3) 화면 밖 간선을 안 그리기**·**(4) 구체 분할 수 낮추기**는 **프레임 비용(G6)을 줄일 뿐 tick 총량(G5)을 한 톨도 줄이지 않는다**
   - **(5) 웹 워커**는 F-292 7장이 "명세를 먼저 고친다"고 정했다
   - 즉 **2단계 아래로는 F-2002 안에서 할 수 있는 것이 없다.** 상한을 500 으로 더 내리는 것은 Q5 승인 범위 밖이라 사람 결정이다
4. **G4 를 못 맞추면**(100 ms 초과) 원인을 먼저 가른다 — 청크 내려받기 시간인지(`performance.getEntriesByType('resource')` 로 지도 청크의 `duration` 을 본다) 첫 장면 만들기 시간인지. **청크 시간이면 게이트를 고치는 쪽이 맞다**(첫 클릭은 네트워크를 타고 두 번째부터는 캐시다). 장면 만들기 시간이면 구체 분할 수부터 낮춘다. 어느 쪽이든 **수치와 판단 근거를 보고에 적는다**
