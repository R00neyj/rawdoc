### 2.1 이 커밋이 끝난 시점의 상태

1. 배경을 **우클릭으로 끌면 회전**하고, **좌클릭으로 끌면 이동**하며, **휠로 확대·축소**한다
2. 노드를 좌클릭하면 그 문서가 열린다 (F-2002 그대로). `Ctrl`(⌘)+좌클릭이면 지도를 닫지 않고 **그 노드로 카메라가 이동**하고 해시가 `#/map/{id}` 가 된다
3. 노드를 우클릭하면 `열기`·`새 탭에서 열기`·`여기로 이동` 세 항목 메뉴가 뜬다. 배경 우클릭은 회전이고 브라우저 기본 메뉴는 어디서도 안 뜬다
4. 터치는 한 손가락 회전, 두 손가락 확대·이동, 노드 위 길게 누르기(500 ms)로 같은 메뉴
5. `맞춤` 은 회전·이동·확대를 전부 되돌려 그래프 전체를 다시 화면에 넣는다
6. 배치가 도는 동안 카메라가 자동으로 따라가다가, **사용자가 카메라를 한 번 움직이면 그때부터 자동 맞춤을 멈춘다**
7. 손을 떼면 관성이 남아 서서히 멈추고, 멈추면 그리기 루프도 멈춘다

**쓸 만한가 — 판단.** 쓸 만하다. 이 커밋으로 F-292 결정 1(재미·인상)의 핵심인 "마우스로 돌리면 덩어리가 회전한다"가 처음 성립한다. 남는 아쉬움은 노드 크기·깊이·이름표가 아직 없다는 것(F-2004)뿐이다.

### 3.1 어디서 import 하나 — `three/addons/controls/OrbitControls.js`

- `node_modules/three/package.json` 의 `exports` 에 `"./addons/*": "./examples/jsm/*"` 와 `"./examples/jsm/*": "./examples/jsm/*"` **둘 다** 있다. 어느 쪽으로 써도 같은 파일이다
- **`three/addons/controls/OrbitControls.js` 를 쓴다.** three 가 공식 문서에서 쓰는 경로이고 짧다
- **타입이 붙는지 직접 확인했다.** 스크래치패드에 `tsconfig`(이 저장소와 같은 `moduleResolution: "bundler"`, `strict: true`, `verbatimModuleSyntax: true`)를 두고 `tsc` 를 돌려 **오류 0개**였다. `@types/three@0.186.0` 의 `exports` 가 같은 모양이라 `examples/jsm/controls/OrbitControls.d.ts` 로 해결된다. 확인한 것: `new OrbitControls(camera, canvas)`, `mouseButtons`·`touches` 대입, `update(): boolean`, `target`, `addEventListener('start'|'change'|'end', …)`, `cursorStyle`, `dispose()`

### 3.3 `connect()` 가 실제로 하는 일 (495~510행)

생성자에 `domElement` 를 주면 곧바로 `connect()` 가 돈다(459행). 그 안에서:

| 줄 | 무엇 |
| --- | --- |
| 499 | `domElement` 에 `pointerdown` |
| 500 | `domElement` 에 `pointercancel` |
| 502 | `domElement` 에 `contextmenu` |
| 503 | `domElement` 에 `wheel`(`{ passive: false }`) — 그래서 지도 위 휠이 페이지를 스크롤하지 않는다 |

### 3.4 `update()` (697행) — 반환값과 이벤트

- `update()` 는 **카메라가 실제로 움직였으면 `true`, 아니면 `false`** 를 돌려준다(924·928행). 판정식은 "카메라 이동 거리² > `_EPS`(1e-6) 또는 회전각² > `_EPS` 또는 target 이동 거리² > `_EPS` 또는 zoom 변화"(910~923행)
- **움직였을 때만 `change` 이벤트를 쏜다**(918행). `start` 는 조작이 시작될 때만(1738행 마우스, 1782행 휠, 1876행 터치), `end` 는 끝날 때만(1621·1786행)
- **감쇠는 `update()` 를 계속 불러야 잦아든다.** 켜져 있으면 쌓인 회전량의 `dampingFactor` 만큼만 적용하고 나머지를 `(1 - dampingFactor)` 로 줄인다(715~722행, 799~806행). 꺼져 있으면 한 번에 전부 적용하고 **누적값을 0으로 비운다**(808~812행) — 7.2 가 이 성질을 쓴다
- **OrbitControls 는 자기 이벤트 처리 안에서도 `update()` 를 부른다** (`_handleMouseMoveRotate` 1110행, `_handleMouseWheel`, `_handleTouchMove*` 등이 끝에 `this.update()`). 그래서 **우리 루프가 멈춰 있어도 조작이 들어오면 카메라는 움직인다** — 6.2 가 이것 때문에 `change` 를 구독한다

## 4. 마우스 — 노드 우클릭과 배경 우클릭을 가르기

### 4.1 등록 순서가 전부다 (F-292 5장 설계의 확인)

캔버스에는 자식 요소가 없어 이벤트가 항상 target 단계에서 끝난다. **그 단계에서는 capture 플래그가 순서를 바꾸지 못하고 등록 순서가 곧 실행 순서다.** 그래서:

> **`buildScene()` 안에서 `new OrbitControls(...)` 보다 먼저 우리 캔버스 리스너를 전부 단다.**

지금 `MapScene.tsx` 290~291행이 `pointerdown`·`pointerup` 을 달고 **그 뒤** 293행부터 `ResizeObserver` 를 만든다. `OrbitControls` 생성은 **그 리스너 등록 줄들보다 아래**에 둔다.

등록 순서 (전부 `canvas` 에, 옵션 없음 — `touchend` 만 5.3 참고):

1. `pointerdown` (기존 + 확장)
2. `pointermove` (신규 — 길게 누르기 판정 전용)
3. `pointerup` (기존 + 확장)
4. `pointercancel` (신규)
5. `touchend` (신규 — 5.3)
6. `contextmenu` (신규)
7. `new OrbitControls(camera, canvas)` ← **여기**

### 4.2 브라우저가 실제로 무엇을 어떤 순서로 주는지 — 설치된 Chrome 에서 쟀다

2026-09-21, Playwright(`channel: 'chrome'`, Windows)로 캔버스에 리스너를 달고 **진짜 마우스 입력**을 넣어 기록했다.

| 조작 | 관찰된 순서 |
| --- | --- |
| 우클릭 한 번 | `pointerdown(button 2, buttons 2)` → `mousedown` → `pointerup` → `mouseup` → `auxclick` → **`contextmenu`(buttons 0, 맨 마지막)** |
| 좌버튼을 누른 채 우클릭 | `pointerdown(button 0)` → `mousedown(0)` → **`mousedown(2)`** → `mouseup(2)` → `auxclick` → **`contextmenu`(buttons 1)** → `pointerup(0)`. **두 번째 버튼에는 `pointerdown` 이 아예 오지 않는다** |

같은 방법으로 `OrbitControls` 를 실제로 태워 본 결과(우리 설정 그대로):

| 확인 | 결과 |
| --- | --- |
| 우클릭 드래그 | 회전한다. 카메라 `[0,0,100]` → `[-100,0,0.72]`, target 까지 거리 100 유지. **캔버스 높이 400 에서 100 px 를 끌어 정확히 90°**(공식 `2π·dx/clientHeight`, 1116~1122행과 일치) |
| 좌클릭 드래그 | target 이 움직인다(이동). **끈 픽셀당 world 0.2331 = `2·tan(fov/2)·거리/clientHeight` 와 정확히 일치** → **target 평면에 있는 노드는 끈 만큼 화면에서 그대로 따라온다** |
| 휠 | `deltaY -100` 에 거리 100 → 95, `deltaY +300` 에 95 → 110.8 (= 95 × 0.95⁻³). `_getZoomScale` 과 일치 |
| `controls.enabled = false` 에서 우클릭 드래그 | **카메라가 한 톨도 안 움직인다**(`change` 0건, `start` 0건). 그동안에도 **우리 `pointerdown`·`contextmenu` 리스너는 그대로 불린다** |
| 합성 `PointerEvent` 로 몰기 | **안 된다.** `onPointerDown` 이 1559행 `setPointerCapture(event.pointerId)` 에서 `NotFoundError` 를 던진다(별도 실험으로 예외 이름까지 확인). **e2e·측정에서 회전을 합성 이벤트로 흉내 낼 수 없고 Playwright 의 진짜 입력을 써야 한다** (14.2·11장) |
| 감쇠 꼬리 | 손을 뗀 뒤 **약 110 프레임** 동안 `update()` 가 `true` 를 돌려준다(`dampingFactor` 0.08). 60 fps 면 약 1.8초 |

### 4.3 그래서 이렇게 가른다

**메뉴는 `contextmenu` 에서 연다. `pointerdown` 에서 열지 않는다.** 이유: `FolderMenu` 는 열리자마자 `document` 의 `mousedown` 으로 바깥 누르기를 듣는다(`FolderMenu.tsx` 68~75행). `pointerdown` 에서 열면 **같은 클릭의 `mousedown` 이 곧바로 그 메뉴를 닫는다.** 4.2 표대로 Windows Chrome 은 `contextmenu` 가 `mousedown` 보다 **뒤**에 오므로 이 자멸이 없다.

```
pointerdown(e):
  downAt = { x: e.clientX, y: e.clientY }            // 버튼과 무관하게 기록한다 (지금은 button 0 일 때만 기록한다)
  menuWasOpen = inputs.current.menuOpen              // 4.5
  (터치면 5장의 길게 누르기 준비)

contextmenu(e):
  e.preventDefault()                                  // 조건 없이 언제나
  if (e.buttons & 1) return                           // 다른 버튼을 누른 채면 메뉴를 열지 않는다
  if (downAt 와의 거리 > 4 px) return                 // 드래그였다 — 회전이지 메뉴가 아니다
  if (e.pointerType 이 없고 터치 길게 누르기가 이미 열었으면) return   // 5.2
  hit = 레이캐스트(e.clientX, e.clientY)
  if (!hit || hit.missing) return                     // 배경·끊긴 링크면 아무 일도 없다 (8.5)
  inputs.current.onNodeMenu(hit.id, e.clientX, e.clientY)
```

- **`e.buttons & 1` 로 거른다.** `e.buttons === 0` 으로 거르면 Windows 에서만 맞다 — macOS·Linux Chrome 은 `contextmenu` 가 버튼을 누르는 순간 와서 `buttons` 가 2 다. `& 1`(왼쪽 버튼이 눌려 있나)은 두 쪽 모두에서 맞다
- **4 px 는 F-2002 6.8 의 `CLICK_SLOP` 과 같은 상수를 쓴다**
- **`controls.enabled = false` 를 `pointerdown` 에서 미리 걸지 않는다.** F-292 5장은 그렇게 적었지만, 그러면 **노드 위에서 시작한 우클릭 드래그가 회전도 메뉴도 아닌 죽은 제스처**가 된다. 지금 설계는 노드 위에서 시작해도 회전이 정상으로 되고, 4 px 안에서 끝난 우클릭만 메뉴가 된다. 그 4 px 동안 일어난 회전은 감쇠까지 곱해 **0.2° 미만**이라 눈에 보이지 않는다 (4.2 의 환산: 400 px = 360°)
- **플랫폼 차이를 적어 둔다.** `contextmenu` 가 누르는 순간 오는 브라우저(macOS Chrome 등)에서는 노드 위 메뉴가 **누르는 순간** 열리고, 그 자리에서 시작한 우클릭 드래그 회전은 안 된다. Windows 에서 실측한 순서가 이 저장소의 e2e 기준이다

### 4.4 `controls.enabled` 를 언제 `false` 로 두고 언제 되돌리나

**메뉴가 떠 있는 동안만 `false` 다.** `MapPage` 가 가진 메뉴 상태를 `menuOpen` prop 으로 받아 effect 하나가 `controls.enabled = !menuOpen` 을 맞춘다(9.2 의 effect (d)).

되돌아오는 경로를 전부 셌다 — `FolderMenu` 가 닫히는 길은 셋뿐이고 **전부 `onOpenChange(false)` 로 모인다**:

| 닫히는 길 | 코드 |
| --- | --- |
| 항목 선택 | `selectItem()` → `setOpen(false)` (`FolderMenu.tsx` 150~153행) |
| `Esc` | `closeAndReturnFocus()` → `setOpen(false)` (99~102행) |
| 메뉴 바깥 `mousedown` | 65~75행 |

- **창 크기 변경·창 blur 로는 닫히지 않는다.** 사이드바 우클릭 메뉴(F-255)도 같고, 메뉴가 떠 있는 동안만 잠기므로 갇히지 않는다. 따로 리스너를 달지 않는다
- `목록` 보기로 전환하거나 지도를 닫으면 `MapPage` 가 메뉴 상태를 `null` 로 비운다 (10.2)

### 4.5 메뉴가 떠 있을 때의 첫 좌클릭

바깥을 누르면 `mousedown` 에 메뉴가 닫히고, 이어서 우리 `pointerup` 이 레이캐스트를 돌려 **문서까지 열어 버린다.** 그래서:

> `pointerdown` 에서 기록한 `menuWasOpen` 이 `true` 면 그 `pointerup` 은 레이캐스트를 건너뛴다.

즉 **메뉴가 떠 있을 때의 첫 클릭은 메뉴를 닫기만 한다.** 같은 이유로 그 클릭은 이동도 하지 않는다(그 시점에 `controls.enabled` 가 아직 `false` 다).

## 5. 터치 — 길게 누르기

### 5.1 `OrbitControls` 의 터치를 실제로 태워 봤다

CDP `Input.dispatchTouchEvent`(진짜 터치 입력 경로)로 설치된 Chrome 에서 쟀다.

| 확인 | 결과 |
| --- | --- |
| 한 손가락 드래그 | 회전한다 (`touches.ONE = TOUCH.ROTATE` 기본값). 터치의 `pointerdown` 은 **`button === 0`** 이라 F-2002 의 좌클릭 레이캐스트가 터치 탭에도 그대로 먹는다 |
| 두 손가락 벌리기 | 확대된다 (거리 100 → 38.5). `touches.TWO = TOUCH.DOLLY_PAN` 기본값 |
| **`enableRotate = false` 를 첫 손가락 `pointerdown` 에서 걸면** | **한 손가락 회전이 완전히 막힌다**(카메라 그대로). `onTouchStart` 1806~1812행이 `enableRotate === false` 에서 `state` 를 세우기 전에 빠져나간다 |
| **그 상태에서 손가락을 하나 더 얹으면** | **두 손가락 확대가 그대로 된다**(거리 100 → 23.8). `case 2:` 의 `DOLLY_PAN` 가지는 `enableRotate` 를 보지 않는다(1838~1848행) |
| 900 ms 길게 누르기 | `contextmenu` 가 **오지 않는다.** `pointerdown`·`touchstart` 뿐이다 |
| 손가락을 뗄 때 | **`pointerup` → `touchend` → `mousedown` → `mouseup` → `click` (호환 마우스 이벤트가 온다)** |
| `touchend` 에서 `preventDefault()` | **호환 마우스 이벤트가 전부 사라진다** (`pointerup`·`touchend` 만 남는다) |
| `pointerup` 에서 `preventDefault()` | 아무 효과가 없다 |

### 5.2 그래서 길게 누르기는 이렇게 한다

```
pointerdown(e):
  if (e.pointerType !== 'touch') return
  activeTouches += 1
  if (activeTouches > 1) { endLongPress(); return }          // 두 손가락은 확대·이동이다
  hit = 레이캐스트(e.clientX, e.clientY)
  if (!hit || hit.missing) return                            // 배경이면 그냥 회전하게 둔다
  controls.enableRotate = false                              // 5.1 이 확인한 처방
  longPress = { id: e.pointerId, x, y, nodeId: hit.id, timer: setTimeout(fire, 500) }

pointermove(e):  longPress 가 있고 같은 pointerId 이며 이동 거리 > 10 px 이면 endLongPress()
pointerup / pointercancel(e): activeTouches -= 1 (0 아래로 안 내려간다), endLongPress()

fire():                                    // 500 ms 가 지났다
  longPressOpened = true                   // touchend 에서 preventDefault 할 표시 (5.3)
  endLongPress({ keepFlag: true })
  inputs.current.onNodeMenu(nodeId, x, y)

endLongPress(): 타이머를 지우고 longPress = null, controls.enableRotate = true
```

- **500 ms · 10 px** 은 F-292 5장이 정한 값 그대로다
- **노드 위에서 시작한 한 손가락 드래그는 그 제스처 동안 회전하지 않는다.** 10 px 를 넘겨 `enableRotate` 를 되돌려도 `OrbitControls` 의 `state` 가 이미 `NONE` 이라 회전이 시작되지 않는다. 받아들인다 — 되살리려면 `_rotateStart` 같은 내부 값을 만져야 하고, F-2004 가 그 제스처를 **노드 끌기**로 가져갈 자리이기도 하다 (17장 Q3)
- **배경 위 한 손가락 회전과 두 손가락 확대·이동은 아무 영향을 받지 않는다** (5.1 표의 마지막에서 두 번째 줄이 그것을 재 준다)
- 길게 누르는 동안 시각 피드백(원이 차오르는 표시 등)은 **넣지 않는다.** 사람 확인 H-f 가 그래도 되는지 묻는다

### 5.3 손가락을 떼도 메뉴가 남게 하는 한 줄

5.1 실측대로 손가락을 떼면 **호환 `mousedown` 이 오고**, 그것이 `FolderMenu` 의 바깥 누르기 리스너에 잡혀 **방금 연 메뉴를 곧바로 닫는다.** 그래서:

> 캔버스에 `touchend` 리스너를 하나 달고, **길게 누르기로 메뉴를 연 그 제스처의 `touchend` 에서만** `e.preventDefault()` 한다. 그 뒤 `longPressOpened = false`.

- 실측에서 `{ passive: false }` 를 주지 않아도 `preventDefault()` 가 먹었다(`touchend` 는 Chrome 의 기본 passive 대상이 아니다). 그래도 **의도를 남기려고 `{ passive: false }` 를 명시해 단다**
- 이 한 줄은 **길게 누르기로 메뉴를 연 경우에만** 돈다. 보통 탭·드래그는 호환 이벤트를 그대로 받는다

## 6. 그리기 루프 — 관성이 잦아들 때까지

### 6.1 지금 루프 (F-2002 `MapScene.tsx` 229~260행)

```
frame(): 배치 tick → (안 멈췄으면) fit() → dirty=false → uploadPositions() → render()
         → if (layout.isSettled() && !dirty) setAnimationLoop(null)
```

`dirty` 를 세우는 것은 창 크기 변화·테마 변화·`fitToken` 증가뿐이다. 카메라가 들어오면 이 판정으로는 **감쇠가 남아 있는데 루프가 멈춘다.**

### 6.2 바꾸는 판정 — `update()` 의 반환값이 아니라 `change` 이벤트를 쓴다

**결론부터: `controls.update()` 의 반환값을 직접 읽지 않고 `change` 이벤트를 구독한다.** 이유는 3.4 마지막 글머리다 — `OrbitControls` 는 자기 `pointermove`·`wheel` 처리 안에서도 `update()` 를 부르므로, **우리 루프가 이미 멈춘 상태에서 카메라가 움직이는 경우가 실제로 있다.** 반환값만 보면 그 프레임을 놓쳐 화면이 안 따라간다.

```
controls.addEventListener('change', requestDraw)   // requestDraw() 는 dirty=true + 루프가 꺼져 있으면 켠다

frame():
  dirty = false                                    // ← 맨 앞에서 내린다
  if (reduced) { … 기존 예산 tick … } else if (!layout.isSettled()) { layout.tick(1); posDirty = true }
  if (!layout.isSettled()) { if (!userMoved) fit(); else updateClip() }   // 7.3
  controls.update()                                // 움직였으면 change 가 dirty 를 다시 세운다
  if (posDirty) { uploadPositions(); posDirty = false }
  renderer.render(scene, camera)
  if (layout.isSettled() && !dirty) { renderer.setAnimationLoop(null); running = false }
```

**정확한 정지 판정식은 `layout.isSettled() && !dirty` 그대로이고, 달라지는 것은 `dirty` 를 세우는 주체에 `controls` 의 `change` 가 더해진다는 것뿐이다.** 이 식이 옳은 이유:

- `dirty = false` 를 **`controls.update()` 보다 먼저** 내린다. 감쇠가 남아 있으면 `update()` 가 카메라를 움직이고 → `change` → `dirty = true` → 다음 프레임도 돈다
- 관성이 `_EPS` 아래로 떨어지면 `update()` 가 아무것도 하지 않고 `change` 도 안 쏜다 → `dirty` 가 `false` 로 남아 **그 프레임에 멈춘다.** F-292 12장 Q3 이 말한 "`update()` 가 `false` 를 돌려줄 때까지 rAF 를 유지"와 같은 시점이고, 구현만 이벤트 쪽이 새지 않는다
- 드래그 중 손가락이 멈춰 있으면 `change` 가 없어 루프도 멈춘다 — 그릴 것이 없으니 맞다. 다시 움직이면 `OrbitControls` 내부 `update()` → `change` → `requestDraw()` 가 루프를 되살린다
- **실측(4.2): 손을 뗀 뒤 약 110 프레임 동안 `change` 가 이어지고 그 뒤 끊긴다**

### 6.3 좌표 업로드를 건너뛴다 — G6 를 위한 유일한 최적화

지금은 프레임마다 `uploadPositions()` 가 노드 수만큼 `Matrix4.compose` + `setMatrixAt` 를 돈다. **배치가 멈춘 뒤에는 좌표가 바뀌지 않으므로 회전 중에 이 일을 다시 할 이유가 없다.**

- `posDirty` 플래그를 두고 **tick 을 돌린 프레임과 장면을 막 만든 첫 프레임에만** `uploadPositions()` 한다
- 노드 1,000개 기준 프레임당 `compose` 1,000회 + `Float32Array` 쓰기 16,000개가 사라진다. **G6(회전 중 fps)에 직접 듣는다**
- **F-2009 에게**: 노드를 끌면 좌표가 바뀌므로 끄는 동안 `posDirty = true` 를 세워야 한다. 2장 경계표에 적었다 (F-2004 는 `posDirty` 규칙을 그대로 뒀다)

## 7. 카메라

### 7.1 `맞춤` 이 `OrbitControls.target` 까지 맞추는 정확한 순서

`OrbitControls` 가 붙으면 `camera.lookAt()` 은 **다음 `update()` 에서 `target` 기준으로 덮어써진다.** `update()` 는 맨 앞에서 `position - target` 으로 구면좌표를 다시 세우고(699~707행), 맨 뒤에서 `position = target + offset` + `lookAt(target)` 을 한다(795~797행). 그래서 `lookAt` 을 부를 필요가 없고, **순서는 `target` → `position` → `update()`** 다.

감쇠가 켜져 있으면 **남은 관성이 새 위치 위에 얹힌다.** 그래서 먼저 비운다 — `enableDamping = false` 로 한 번 `update()` 하면 누적값을 전부 적용하고 **0으로 비운다**(808~812행).

```
fit():
  const { center, radius } = layout.bounds()                 // F-2001 5.3
  const r = Math.max(radius + maxNodeRadius, 1)              // 7.2
  const dist = fitDistance(r, camera.fov, camera.aspect)     // 7.5
  selfDriven = true
  controls.enableDamping = false
  controls.update()                                          // 남은 관성을 비운다
  controls.target.set(center[0], center[1], center[2])
  camera.position.set(center[0], center[1], center[2] + dist)
  const { min, max } = zoomLimits(dist)
  controls.minDistance = min
  controls.maxDistance = max
  applyClip(dist, r)                                         // near·far + updateProjectionMatrix
  controls.update()                                          // target 기준으로 카메라를 다시 맞춘다
  controls.enableDamping = true
  selfDriven = false
  userMoved = false                                          // 7.3
```

- **감쇠가 켜진 채로도 `맞춤` 은 그 프레임에 즉시 반영된다.** 위 순서가 `position` 을 직접 쓰고 누적값이 비어 있기 때문이다. `controls.update()` 를 한 번 더 부를 필요는 없다
- `selfDriven` 은 이 동안 오는 `change` 를 "사용자 조작"으로 세지 않기 위한 표시다 (7.3)

**F-2012 가 뒤집었다** — `맞춤` 을 눌렀을 때 위 순서로 즉시 자세를 쓰던 것이 **240 ms 전환**으로 바뀌었다(F-2012 5.4). `fit()` 자체는 지우지 않았다 — 첫 열림·자동 맞춤·`ResizeObserver` 는 그대로 이 함수를 즉시 호출로 쓴다 (F-2012 5.4·10장).

### 7.2 `fit()` 이 노드 반지름을 더해야 하는 이유 (F-2002 6.7 의 작은 오류)

지금 `fit()` 은 `r = Math.max(bounds.radius, 1)` 이다. **노드가 하나뿐이면 `bounds.radius` 가 0 이라 `r = 1`, 카메라 거리가 2.72 가 되는데 노드 반지름이 6.0 이라 카메라가 구체 안으로 들어간다.** `MeshBasicMaterial` 은 앞면만 그리므로 **첫 실행(`사용법` 문서 하나)에서 화면에 아무것도 안 보인다.**

> `r = Math.max(bounds.radius + maxNodeRadius, 1)`. `maxNodeRadius` 는 `radii` 배열의 최댓값(없으면 0)이다.

- F-2002 가 `radii` 를 배열로 잡아 둔 덕에(6.6) 최댓값을 여는 시점에 한 번 구해 두면 된다. **F-2004 가 반지름 공식을 갈아끼워도 같은 배열의 최댓값이라 따라온다**
- 부수 효과로 **노드 하나짜리 그래프에서 노드가 화면 높이의 78.8% 를 차지하게 된다** — 이 값은 시야각과 여백 배수 1.15 만으로 정해지고 반지름과 무관하다(`cos(fov/2)/1.15 = 0.788`). 14.2 의 좌표 기준이 여기서 나온다

### 7.3 "사용자가 카메라를 건드렸다" 의 판정

**`start` 가 아니라 `change` 로 판정한다. 단, 우리가 일으킨 `change` 는 빼고 센다.**

```
let userMoved = false
let selfDriven = false
controls.addEventListener('change', () => { if (!selfDriven) userMoved = true; requestDraw() })
```

왜 `start` 가 아닌가 — `start` 는 **카메라가 움직이지 않아도** 뜬다(1738행, 버튼을 누르는 순간). 노드를 우클릭해 메뉴만 열어도, `Ctrl`+좌클릭으로 재중심만 해도 `start` 가 떠서 **배치가 도는 5초 동안 자동 맞춤이 꺼져 그래프가 틀을 벗어난다.** `change` 는 4.2 실측대로 실제 이동이 있을 때만 온다.

왜 `selfDriven` 이 필요한가 — `fit()`·`lookAtNode()` 안의 `controls.update()` 도 `change` 를 쏜다. 그 사이만 표시를 세워 빼고 센다.

**플래그가 풀리는 시점은 `맞춤`(`fitToken` 증가 → `fit()` 끝에서 `userMoved = false`) 하나뿐이다.** 그래프가 다시 만들어지면 장면 자체가 새로 만들어져 자동으로 `false` 다. `여기로 이동`·`Ctrl`+클릭은 **오히려 `userMoved = true` 로 세운다**(7.4).

**F-2012 가 옮겼다** — `userMoved` 가 `false` 로 풀리는 시점이 `맞춤` 을 누르는 순간에서 **그 240 ms 전환이 끝나는 순간**으로 옮겨졌고, 전환이 도중에 취소되면 안 풀린다 (F-2012 7.3). 그리고 `selfDriven` 외에 **`start` 이벤트로 사용자 조작을 가려 전환을 취소하는 경로**가 새로 생겼다 (F-2012 7.2).

자동 맞춤이 꺼진 뒤에도 **절단면은 프레임마다 다시 잡는다** — 배치가 계속 퍼지는 동안 `camera.far` 를 그대로 두면 덩어리 뒤쪽이 잘린다.

```
updateClip():                                  // fit() 을 건너뛰는 프레임에서 부른다
  const { center, radius } = layout.bounds()
  const r = Math.max(radius + maxNodeRadius, 1)
  const d = camera.position.distanceTo(center)
  applyClip(d, r)
```

### 7.4 `여기로 이동` — 각도와 거리를 유지한 채 target 만 옮긴다

F-292 5장은 `여기로 이동`(과 `Ctrl`+좌클릭)을 "카메라를 그 노드로 옮기고 강조"라고 적었는데, F-2002 는 카메라를 옮길 수단이 없어 **전체 맞춤 + 색 강조**로만 구현돼 있다. `OrbitControls` 가 붙으면 제대로 할 수 있다.

```
lookAtNode(id):
  const i = graph.nodes.findIndex((n) => n.id === id);  if (i < 0) return
  const pos = layout.readPositions(posBuf)              // 최신 좌표 (같은 배열을 돌려준다)
  selfDriven = true
  controls.enableDamping = false
  controls.update()                                     // 남은 관성 비우기
  offset.copy(camera.position).sub(controls.target)     // 보던 방향·거리를 그대로 들고 간다
  controls.target.set(pos[i*3], pos[i*3+1], pos[i*3+2])
  camera.position.copy(controls.target).add(offset)
  controls.update()
  controls.enableDamping = true
  selfDriven = false
  userMoved = true                                      // 사용자가 카메라를 지정했으므로 자동 맞춤을 멈춘다
```

- **각도를 유지하는 이유**: 돌려 놓은 시점을 메뉴 한 번에 정면으로 되돌리면 방금 만든 공간감이 날아간다. 되돌리고 싶으면 `맞춤` 이 있다
- `offset` 은 장면마다 하나 만들어 돌려쓰는 `Vector3` 다 (F-2002 6.6 의 규칙)
- 절단면은 다음 프레임의 `updateClip()` 이 잡는다
- **이미 중심인 문서를 다시 골라도 카메라가 움직여야 한다** (2026-09-22 사용자 신고·승인). `여기로 이동` 은 해시만 바꾸므로(`App.tsx` 의 `recenterMap`) 같은 문서를 다시 고르면 `centerDocId` 가 그대로고, 9.2 의 효과 (c) 가 직전 값과 같다며 통째로 빠져나갔다. 회전·이동으로 노드를 화면 밖으로 밀어낸 다음 그 노드를 다시 고르는 것이 **가장 흔한 쓰임인데 그때만 안 들었다**. `centerToken` 을 하나 더 두고 `여기로 이동` 을 고를 때마다 올린다 — `MapPage` 가 들고 있고 `MapScene` 은 받아서 효과 (c) 의 방아쇠로만 쓴다. 값 자체에는 뜻이 없다

**F-2012 가 뒤집었다** — `여기로 이동` 도 위치를 즉시 옮기지 않고 **240 ms 전환**을 탄다(`'look'` 모드, F-2012 5.4). `userMoved = true` 는 전환이 끝날 때가 아니라 **전환을 시작할 때** 세운다 (F-2012 7.3) — 지금 이 함수가 마지막 줄에서 하던 것과 같은 자리다.

### 7.5 `src/lib/mapCamera.ts` — 순수 계산만 떼어낸다

테스트 환경이 `node` 라 three·DOM 이 붙은 코드는 단위 테스트가 안 된다. **카메라 수식만 순수 함수로 떼면 이 명세에서 유일하게 TDD 가 되는 부분이 생긴다.**

```ts
// 지도 카메라 거리·절단면·확대 한계 (specs/features/F-2003.md 7장)
// three 를 import 하지 않는 순수 모듈이다 — 테스트 환경이 node 라 이 규칙이 곧 테스트 가능성이다

/** 반지름 radius 인 구가 다 들어오는 카메라 거리. 좁은 쪽 시야에 맞춘다 */
export function fitDistance(radius: number, fovDeg: number, aspect: number, margin?: number): number

/** 카메라가 그래프 중심에서 distance 만큼 떨어져 있을 때의 near·far */
export function clipPlanes(distance: number, radius: number): { near: number; far: number }

/** `맞춤` 거리 기준 확대·축소 한계 */
export function zoomLimits(fitDist: number): { min: number; max: number }
```

| 함수 | 정의 | 왜 이 값인가 |
| --- | --- | --- |
| `fitDistance` | `r = max(radius, 1)`; `vFov = fovDeg·π/180`; `hFov = 2·atan(tan(vFov/2)·max(aspect, 1e-6))`; `return r·margin / sin(min(vFov, hFov)/2)`. `margin` 기본 `1.15` | F-2002 6.7 의 식을 그대로 옮긴 것이다. 좁은 쪽 시야에 맞춰야 세로로 긴 창에서 가로가 잘리지 않는다 |
| `clipPlanes` | `near = max(distance·0.01, 0.1)`, `far = distance + max(radius, 1)·4` | `near` 를 거리에 비례시키는 것은 깊이 버퍼 정밀도 때문(F-2002 6.7). `far` 를 **현재 거리** 기준으로 잡아야 축소(거리 증가)해도 덩어리가 안 잘린다 |
| `zoomLimits` | `min = max(fitDist·0.05, 0.1)`, `max = fitDist·4` | 0.05배까지 들어가면 덩어리 안을 돌아볼 수 있고, 4배까지 나가면 전체가 화면의 1/4 로 보인다. `maxDistance` 가 없으면 `far` 밖으로 나가 그림이 통째로 사라진다 |
| `parseCubicBezier` | CSS `cubic-bezier(x1,y1,x2,y2)` 문자열 → 제어점 넷, 모양이 아니면 `null` | **F-2012 가 더했다** (9.1·9.2). 240 ms 전환의 곡선을 실행 시점에 토큰에서 읽어 푼다 |
| `easeAt` | 진행도 `t(0~1)` → 곡선 위의 값, `curve` 가 `null` 이면 선형 | **F-2012 가 더했다** (9.1·9.2) |
| `tweenPose` | 두 자세 사이 `e(0~1)` 지점의 `target`·`position` 을 출력 배열에 쓴다. 방향은 구면, 거리는 등비, `target` 은 선형 | **F-2012 가 더했다** (9.1·9.3). `맞춤`·`여기로 이동` 전환이 매 프레임 부른다 |

- **F-2012 가 뒤집었다 — 내보내는 것은 이 셋이 아니라 여섯이다.** `parseCubicBezier`·`easeAt`·`tweenPose` 가 늘었다 (F-2012 9장). three 타입을 쓰지 않는 것은 그대로다 — 카메라 객체에 값을 넣는 일은 `MapScene` 이 한다
- 단위 테스트는 14.1 U1~U6

### 8.4 `map.css` 에 새 규칙이 필요 없는 이유

- **커서**: ~~`controls.cursorStyle = 'grab'`~~ — **F-2004 에서 이 줄을 지웠다** (사용자 지시 2026-09-22). 아래는 그때의 근거로 남긴다. 그 setter 가 인라인 스타일로 넣고 드래그 중 `grabbing` 으로 바꾼다. CSS 로 하면 `disconnect()` 가 남기는 인라인 `cursor: auto`(535~537행)에 덮인다 — StrictMode 의 두 번째 마운트에서 실제로 벌어진다
- **대신 노드 위에서만 `pointer` 를 쓴다** (2026-09-22 사용자 신고·승인). 캔버스는 요소 하나라 CSS 선택자로는 노드 위와 배경을 가를 수 없다 — 어디에 있는지는 레이캐스트만 안다. `setHover()` 가 호버가 **바뀌는 순간에만** `canvas.style.cursor` 를 쓴다(맞았으면 `'pointer'`, 아니면 빈 문자열로 지워 기본값으로). `OrbitControls` 는 `_cursorStyle` 이 `'grab'` 일 때만 커서를 건드리므로(1584·1625행) 우리가 쓰는 값과 부딪히지 않고, 드래그 중에도 `pointer` 가 유지된다
- **메뉴 자리**: `FolderMenu` 의 바깥 `<div class="item-menu">` 는 `position: relative; flex: none`(`app.css` 798~801행)이고 트리거는 `display: none`(885~887행), 목록은 `position: fixed`(857~866행)다. `.map-page-body` 안에 두어도 **높이 0 짜리 빈 블록**이다
- **잘리지 않는다**: `.map-page-body` 가 `overflow: hidden` 이지만 `position: fixed` 는 조상에 `transform`·`filter`·`contain` 이 있을 때만 잘린다. `.map-page`·`.map-page-body`·`.content-area`(947~954행) 어디에도 없다 (`transform` 을 쓰는 `.sidebar--overlay` 는 형제다)

### 8.5 끊긴 링크 노드에서는 메뉴를 열지 않는다

끊긴 링크 노드의 `id` 는 `missing:{정규화한 제목}` 이다(`wikiGraph.ts` 158행) — 문서 id 가 아니다. 그래서 `새 탭에서 열기`(`formatHash` 가 깨진 주소를 만든다)도 `여기로 이동`(해시가 문서 id 여야 한다)도 성립하지 않고, 남는 `열기` 는 실제로는 **새 문서를 만드는** 동작이라 이름이 거짓말이 된다.

> **F-2003 에서는 끊긴 링크 노드 우클릭이 아무 메뉴도 열지 않는다**(배경과 같게 회전한다). F-2004 가 그 가드를 빼고 `이 제목으로 새 문서`(F-131 5장) 하나짜리 메뉴로 열게 했다 (F-2004 8.1).

좌클릭은 지금처럼 그대로 동작한다 — 그 제목으로 새 문서를 만들어 연다.

### 9.2 `useEffect` 는 넷이다

F-2002 6.1 은 "`useEffect` 는 두 개뿐"이라고 정했다. **넷으로 늘린다.** 늘어난 둘은 각각 방아쇠가 하나뿐이라 서로 섞이지 않는다.

## 11. `scripts/measure.mjs` — `--action` 두 종류 추가

G6 는 **회전하는 동안의 프레임 간격**이다. 4.2 실측대로 합성 이벤트로는 `OrbitControls` 가 안 움직이므로 **Playwright 의 진짜 마우스**가 필요하고, 지금 `--action` 에는 드래그가 없다. `--eval` 은 액션이 전부 끝난 뒤에 한 번 도는 것이라 수집기를 미리 심을 수도 없다. 그래서 둘을 더한다.

```js
case 'eval':
  await page.evaluate(rest)
  break

// drag:{선택자}:{버튼}:{dx}:{dy}:{단계}  — 선택자에 ':' 가 들어갈 수 있어 뒤에서부터 넷을 떼어 읽는다
case 'drag': {
  const parts = rest.split(':')
  const steps = Number(parts.pop())
  const dy = Number(parts.pop())
  const dx = Number(parts.pop())
  const button = parts.pop()
  const selector = parts.join(':')
  const box = await page.locator(selector).boundingBox()
  if (!box) throw new Error(`drag 대상이 없다: ${selector}`)
  const cx = box.x + box.width / 2
  const cy = box.y + box.height / 2
  await page.mouse.move(cx, cy)
  await page.mouse.down({ button })
  for (let i = 1; i <= steps; i++) {
    await page.mouse.move(cx + (dx * i) / steps, cy + (dy * i) / steps)
    await page.waitForTimeout(16)   // 프레임마다 한 걸음 — fps 를 재려면 시간에 퍼져야 한다
  }
  await page.mouse.up({ button })
  break
}
```

- 둘 다 이 명세 전용이 아니라 일반 도구다. `--dry-run` 은 액션을 파싱하지 않으므로 건드릴 것이 없다
- 잘못된 버튼 이름은 Playwright 가 스스로 던진다 — 따로 검사하지 않는다

## 12. 게이트

### 12.1 G6 — 회전 중 fps

**F-292 7장 G6 의 "노드 2,000" 은 1,000 으로 읽는다** (F-2002 10.3 이 `NODE_CAP` 을 1,000 으로 확정했다).

| # | 무엇을 | 목표 |
| --- | --- | --- |
| **G6** | 노드 1,000·시뮬레이션 정지 상태에서 **우클릭 드래그로 회전하는 동안의 프레임 간격** | **평균 55 fps 이상, 최악 프레임 33 ms 이하** |

재는 법 (Git Bash. PowerShell 은 따옴표가 깨지니 `--%` 뒤에 붙이거나 Git Bash 에서 돌린다). **3회 돌려 중앙값**을 적는다.

```
npm run measure -- --docs 1000:1 --reduced-motion \
  --action "eval:document.querySelector('[aria-label=\"지도\"]').click()" \
  --action "wait:9000" \
  --action "eval:window.__f=[];window.__p=performance.now();window.__t=()=>{const n=performance.now();window.__f.push(n-window.__p);window.__p=n;window.__r=requestAnimationFrame(window.__t)};window.__r=requestAnimationFrame(window.__t)" \
  --action "drag:.map-canvas:right:600:0:60" \
  --eval "(()=>{cancelAnimationFrame(window.__r);const f=window.__f.slice(2);const avg=f.reduce((a,b)=>a+b,0)/f.length;return{settled:document.querySelectorAll('.map-page .map-status').length===0,frames:f.length,avgFps:Math.round(1000/avg),worstMs:Math.round(Math.max(...f))}})()"
```

- **`--reduced-motion` 으로 재는 이유**: 보통 동작은 배치가 멈출 때까지 프레임마다 1 tick 이라 5초 넘게 걸리고, 그동안 재면 "회전 중"이 아니라 "배치 중"을 재게 된다. reduced-motion 은 예산 tick 으로 한 번에 끝낸 뒤 루프가 멈추므로 **시뮬레이션 정지 상태**라는 G6 의 전제가 정확히 성립한다. 회전은 reduced-motion 과 무관하게 그대로 동작한다 (F-292 결정 13)
- 결과의 `settled` 가 `false` 면 **그 측정은 버린다** (`배치를 계산하는 중…` 이 아직 떠 있다는 뜻)
- 앞 두 프레임은 버린다(`slice(2)`) — 수집기를 심은 프레임과 드래그 시작 프레임이 섞인다
- `--docs 1000:1` 은 문서 1,000개에 문서당 링크 1개다. 상한이 1,000 이라 전부 뜬다
- 프레임 간격은 rAF 기준이라 **아무도 안 그리는 프레임도 60 fps 로 세어진다.** 드래그가 도는 동안에만 수집하므로 그 구간은 전 프레임이 그려진다(6.2 의 `change` → `requestDraw`)

**못 맞추면 이 순서대로 한다** (F-292 7장 "넘으면 순서대로" 중 **G6 에 실제로 듣는 것만**. (1) 노드 상한·(2) `alphaDecay` 는 tick 총량을 줄이는 것이라 회전 fps 와 무관하다):

1. **좌표 업로드 건너뛰기**(6.3)가 실제로 먹고 있는지 먼저 확인한다 — 이게 안 먹으면 프레임마다 1,000회 `compose` 를 돈다
2. 구체 분할 수를 `8 × 6` → `6 × 4` 로 낮춘다 (F-292 7장 (4)). 인스턴스당 96 → 36 삼각형
3. `setPixelRatio` 상한을 2 → 1.5 로 낮춘다
4. 그래도 못 맞추면 **멈추고 보고한다.** 남은 길인 "화면 밖 간선 안 그리기"(F-292 7장 (3))는 `LineSegments` 를 쪼개는 큰 작업이라 명세를 먼저 고친다

**참고로 함께 적는다**: F-2002 가 미해결로 남긴 G4(첫 열기 412 ms)·G5(reduced-motion 배치 5,521 ms)는 **이 명세가 건드리지 않는다**(F-292 12장 Q5 아래, 사람 결정 대기). 다만 위 측정에서 그 숫자가 같이 보이면 참고로 적어 둔다.

## 17. 열린 질문 / 사람 결정 필요

**사람이 꼭 골라야 하는 것은 없다. 아래는 전부 기본값이 서 있고, 다른 쪽을 골랐을 때 무엇이 달라지는지 적었다.**

### Q1. `맞춤` 이 자동 맞춤을 다시 켜는가 — **기본: 켠다**

배치가 도는 동안 돌려 본 뒤 `맞춤` 을 누르면, 그 순간부터 다시 프레임마다 전체가 들어오게 따라간다. `맞춤` 의 뜻이 "전체가 보이게 해 달라"이므로 배치가 커지는 동안에도 유지하는 것이 그 말에 맞다. 사용자가 다시 마우스를 대면 `change` 가 즉시 플래그를 세워 따라가기를 멈추므로 갇히지 않는다.
**다른 쪽을 고르면**: `맞춤` 은 그 순간 한 번만 맞추고 자동 맞춤은 영영 꺼진 채로 둔다. 7.1 의 `userMoved = false` 한 줄을 빼면 된다. 배치가 도는 중에 `맞춤` 을 누르면 곧 다시 틀을 벗어난다.

**F-2012 가 시점만 옮겼다** — 결론(`맞춤` 은 자동 맞춤을 다시 켠다)은 그대로다. `userMoved = false` 로 풀리는 시점이 **240 ms 전환이 끝나는 순간**으로 늦춰졌을 뿐이다 (F-2012 7.3).

### Q2. 끊긴 링크 노드에서 우클릭 메뉴를 여는가 — **기본: 열지 않는다**

8.5 의 이유(항목 셋 중 둘이 성립하지 않고 남은 하나는 이름이 거짓말이 된다). F-2004 가 `이 제목으로 새 문서` 와 함께 연다.
**다른 쪽을 고르면**: `열기` 대신 `이 제목으로 새 문서` 한 항목짜리 메뉴를 F-2003 에서 넣는다. F-2004 범위가 줄지만, 항목 이름이 F-131 흐름과 묶여 있어 그 명세를 미리 읽어야 한다.

### Q3. 노드 위에서 시작한 한 손가락 드래그가 회전하지 않는 것 — **기본: 받아들인다**

5.2 의 이유. 되살리려면 `OrbitControls` 의 `_rotateStart` 같은 내부 값을 만져야 하고, 안 만지고 되살리면 **10 px 만큼의 회전이 한 번에 튄다.**
**다른 쪽을 고르면**: 길게 누르기를 `pointerdown` 이 아니라 `pointerup` 에서(누른 시간이 500 ms 이상이었나로) 판정한다. 그러면 회전이 살지만 **메뉴가 손가락을 뗄 때 뜬다** — 길게 누르기의 통념과 어긋난다.

### Q4. 노드 메뉴를 `FolderMenu` 로 그리는 것 (F-292 5장은 `ContextMenu` 라고 적었다) — **기본: `FolderMenu`**

8.1 의 비교표. 공유 파일을 한 줄도 안 고치는 쪽이다.
**다른 쪽을 고르면**: `contextMenuItems.ts` 의 `MenuActionKind` 에 지도용 값 셋을 더하고 `App.tsx` 의 `handleContextMenuSelect` 와 섞이지 않게 `MapPage` 가 자기 `onSelect` 를 갖는다. 파일 소유가 F-170 쪽으로 번진다.

### Q5. `dampingFactor` 0.08 — **기본: 유지**

F-292 12장 Q3 이 정한 값이고 "돌려 봐야 아는 것"이라 사람 확인(H-c)으로 넘겼다. 실측으로 **꼬리가 약 110 프레임**이다.
**다른 쪽을 고르면**: 0.12~0.15 로 올리면 손가락을 더 바싹 따라오고 꼬리가 짧아진다(0.15 면 약 55 프레임). 숫자 하나만 바꾼다.

### Q6. `rotateSpeed`·`zoomSpeed` 기본값 1.0 — **기본: 유지**

실측 값(높이 1/4 드래그 = 90°, 휠 한 칸 = 5%)을 적어 두고 사람 확인(H-d·H-e)에 맡긴다.
**다른 쪽을 고르면**: `rotateSpeed` 0.6~0.8 이 흔한 선택이다. 숫자 하나.

### Q7. `src/lib/mapCamera.ts` 를 새로 만드는 것 (F-292 2장 표에 없는 파일) — **기본: 만든다**

7.5 의 이유 — 이 명세에서 유일하게 순수하게 떼어낼 수 있는 계산이고, 떼지 않으면 **단위 테스트가 0개**가 된다. `clipPlanes` 는 "축소하면 그림이 사라진다"는 실제 버그를 막는 자리다.
**다른 쪽을 고르면**: 수식을 `MapScene.tsx` 안에 두고 단위 테스트 없이 e2e·눈으로만 판정한다. 파일 둘이 줄지만 14.1 이 통째로 사라진다.

### Q8. `여기로 이동`·`Ctrl`+클릭이 전체 맞춤이 아니라 그 노드로 target 만 옮기는 것 — **기본: 그렇게 한다**

7.4 의 이유. F-292 5장 표의 문장(`카메라를 그 노드로 옮기고 강조`)을 이제야 글자대로 구현하는 것이다.
**다른 쪽을 고르면**: F-2002 처럼 색 강조 + 전체 맞춤만 한다. `lookAtNode` 와 effect (c)가 통째로 빠지고, A5 는 해시만 보므로 그대로 통과한다.
