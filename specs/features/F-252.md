## 2. A — Worker

### 2.1 `migrations/0008_share_link_docs.sql`

```sql
CREATE TABLE share_link_docs (
  token TEXT NOT NULL REFERENCES share_links(token),
  doc_id TEXT NOT NULL REFERENCES docs(id),
  PRIMARY KEY (token, doc_id)
);
CREATE INDEX share_link_docs_token ON share_link_docs(token);
```

- `share_links` 는 바꾸지 않는다. 묶음도 `target_type='doc'`, `target_id` = **시작 문서**다. 이 표에는 시작 문서를 빼고 **함께 공유하기로 한 문서만** 담는다
- 행이 하나도 없는 링크 = 지금까지의 단일 문서 링크. 기존 링크는 마이그레이션 없이 그대로 동작한다

### 2.2 `worker/shareSet.ts` — 재귀 수집 (순수)

```ts
type SetNode = { id: string; title: string; depth: number; parentId: string | null }
collectWikiSet(rootId, loadDoc, allDocs, opts): { nodes: SetNode[]; truncated: boolean }
```

- `loadDoc(id) => { id, title, content } | null`, `allDocs => { id, title }[]` (같은 소유자 문서 전부)
- 너비 우선. 한 문서의 원문에서 `findWikiLinks` 로 대상을 뽑고, `resolveWikiTarget(target, allDocs)` 로 문서를 찾는다 (F-131 2.1 — 정확 일치 → 대소문자 무시)
- 이미 담은 문서(시작 문서 포함)는 다시 담지 않는다. 순환(`A→B→A`)은 여기서 끊긴다
- 못 찾은 대상은 버린다(목록에 없는 제목은 보여주지 않는다)
- 상한: `maxDepth = 5`, `maxNodes = 50`. 상한에 걸려 더 못 담으면 `truncated: true`
- 시작 문서는 `nodes` 에 넣지 않는다 (`depth` 는 1부터)
- **D1 을 모른다.** `loadDoc`·`allDocs` 를 주입받아 단위 테스트한다

### 2.3 묶음 미리보기 `GET /api/docs/:id/share-set`

- 로그인. 문서 소유가 아니면 `404` (F-206 2.2)
- 응답 `200 { "nodes": [{ "id", "title", "depth", "parentId" }], "truncated": bool }`
- 수집에 쓰는 원문은 `stripComments` 를 거친 값이다 — 주석 안에 적어 둔 위키링크가 공유 대상을 늘리면 안 된다 (F-214 2.2 와 같은 취급)
- 목록 순서는 너비 우선 방문 순서 그대로. 화면이 이 순서로 그린다

### 2.4 묶음 발급 `POST /api/docs/:id/link`

- 기존 동작 유지 + **본문 `{ "docIds": string[] }` (선택)**
- 본문이 없거나 `docIds` 가 빈 배열이면 지금과 똑같다(단일 문서 링크)
- `docIds` 가 있으면
  - 각 id 는 **같은 소유자 문서**여야 한다. 하나라도 아니면 `400 {"error":"bad_request"}` — 발급하지 않는다
  - 시작 문서 id 가 섞여 있으면 무시한다(중복 저장 안 함)
  - **살아있는 링크가 있고 묶음이 지금과 다르면 먼저 끊고 새로 발급한다**(토큰이 바뀐다). 묶음이 같으면 기존 토큰을 그대로 돌려준다
  - `share_link_docs` 에 행을 넣는다
- `DELETE /api/docs/:id/link` 는 그대로. 끊긴 링크의 `share_link_docs` 행은 지우지 않는다(조회가 `revoked_at` 으로 막힌다)
- `GET /api/docs/:id/link` 응답에 `docIds` 추가 → `200 { "token", "docIds": [] }`. 링크가 없으면 지금처럼 `404 {"error":"no_link"}`

### 2.5 공개 조회 (로그인 없음)

| 요청 | 동작 |
| --- | --- |
| `GET /pub/docs/:token` | 그대로 — 시작 문서 본문 |
| `GET /pub/docs/:token/set` | `200 { "docs": [{ "id", "title" }] }` — 시작 문서가 맨 앞, 그 뒤 `share_link_docs` 문서. 삭제된 문서는 빠진다 |
| `GET /pub/docs/:token/docs/:docId` | 묶음 안 문서 본문. `docId` 가 묶음 밖이면 `404` |

- 응답 모양·헤더(`X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`)·`stripComments`·`no-store` 는 F-210 2.3 그대로
- `target_type !== 'doc'` 이면 `404`
- **`/pub` 아래는 읽기만 한다** (F-210 2.3). 쓰기 라우트를 늘리지 않는다

### 2.6 묶음 문서 이미지

- `GET /pub/docs/:token/docs/:docId/attachments/:idext` 추가. 검사 순서는 `handlePublicGetFolderAttachment`(F-216) 와 같다: 토큰 형식 → 살아있는 `doc` 링크 → `docId` 가 묶음 안 → 그 문서 원문에 그 첨부 참조가 있는지 → 소유 검사 → R2
- 기존 `/pub/docs/:token/attachments/:idext` 는 시작 문서 전용으로 그대로 둔다

## 3. B — 공유 대화상자 D-6

### 3.1 여는 조건 (`ShareMenu`)

- 항목 이름: 링크로 이어질 문서가 하나라도 있으면 `읽기 전용 링크 복사…`, 없으면 지금처럼 `읽기 전용 링크 복사`
- 판정은 메뉴를 열 때 **로컬에서** 한다: `getShareDoc().content` 에 `findWikiLinks` → `resolveWikiTarget(대상, wikiDocs)` 가 하나라도 맞으면 있음. `wikiDocs` 는 `App` 이 넘기는 `{ id, title }[]`
- 있으면 D-6 을 연다. 없으면 **지금 동작 그대로**(바로 발급·복사, F-210 2.6)
- D-6 을 열기 전에도 `onBeforeLinkAction()` 으로 저장 대기 입력을 flush 한다 — 서버가 읽는 원문이 최신이어야 한다

### 3.2 D-6 모양

- `Dialog` 재사용. 제목 `함께 공유할 문서`
- 첫 줄 안내: `이 문서의 위키링크가 가리키는 문서입니다. 선택한 문서만 링크로 함께 열립니다.`
- 여는 즉시 `GET /api/docs/:id/share-set` 호출. 그동안 본문 자리에 `찾는 중…`. 실패하면 `문서를 불러오지 못했습니다. 연결을 확인하세요.` + `다시 시도`
- 목록: 한 행 = 체크박스 + 문서 제목. `depth` 만큼 들여쓴다(단계당 16px). 제목이 비면 `제목 없는 문서`
- **기본 전체 해제.** 단, 이미 살아있는 링크가 있으면 그 링크에 담긴 문서(`GET /api/docs/:id/link` 의 `docIds`)를 체크한 상태로 연다
- 부모 규칙: 부모 행 체크가 풀리면 그 아래 자식 행은 **자동 해제·비활성**(도달할 수 없는 문서를 실수로 내보내지 않는다). 부모를 다시 체크하면 자식은 활성(해제 상태)
- `truncated` 면 목록 아래 흐린 글자 `링크가 많아 일부만 보여줍니다.`
- 이미 링크가 있고 체크 묶음이 그 링크와 다르면 버튼 위에 경고 한 줄: `주소가 새로 발급되어 이전 주소는 열리지 않습니다.`
- 버튼: `링크 복사`(기본 포커스) / `취소`. Esc·바깥 클릭은 취소
- 체크가 0개여도 `링크 복사` 는 눌린다 — 시작 문서만 공유된다

### 3.3 `링크 복사` 동작

1. 체크된 id 로 `POST /api/docs/{시작문서}/link` (본문 `{ docIds }`)
2. 주소 `${location.origin}/p/${token}` 을 클립보드로
3. 대화상자를 닫고 알림
   - 함께 공유한 문서가 있으면 `읽기 전용 링크를 복사했습니다. 문서 {N+1}개가 함께 열립니다.`
   - 없으면 기존 문구 그대로 `읽기 전용 링크를 복사했습니다. 링크를 아는 사람은 로그인 없이 볼 수 있습니다.`
4. 발급 실패 `링크를 만들지 못했습니다. 연결을 확인하세요.` / 복사 실패 `복사하지 못했습니다. 브라우저 권한을 확인하세요.` (F-210 2.6 문구 그대로)

## 4. C — 공개 보기 위키링크 이동

### 4.1 `renderMarkdown` 인터페이스

- 기존: `resolveWikiLink: (target) => id | null`, href 는 내부가 `#/d/${id}` 로 고정 생성 (F-131 4장)
- 변경: `resolveWikiLink: (target) => href | null`. 찾으면 href 문자열, 못 찾으면 `null` → `wikilink--missing`
- 옵션을 생략하면 지금처럼 `wikilink--plain` — 이 경로는 그대로
- `App.tsx` 는 `resolveWikiTarget(target, docs)?.id` 를 `` `#/d/${id}` `` 로 감싸 돌려준다. 최종 렌더 결과는 지금과 같아야 한다(F-131 A3~A8 회귀 없음)

### 4.2 해시 경로

- `#/p/{토큰}/{문서id}` 추가. `HASH_PUBLIC_PATTERN` 을 `` /^#\/p\/([^/]+)(?:\/(.+))?$/ `` 로 바꾸고 `{ type: 'public'; token; docId? }`
- 토큰은 base64url 43자라 `/` 를 담지 않으므로 `#/p/f/…`(폴더) 와 겹치지 않는다. 폴더 패턴을 먼저 검사하는 순서는 그대로
- `formatPublicHash(token, docId?)` 추가 — `#/p/{토큰}` 또는 `#/p/{토큰}/{문서id}`
- `parsePathRoute` 는 바꾸지 않는다. 경로형 `/p/:token`(F-238) 은 시작 문서만 연다. 그 뒤 이동은 F-211 과 같은 방식으로 해시를 push 한다

### 4.3 `publicDoc.ts`

- `fetchPublicSet(token): { docs: { id, title }[] }` — `/pub/docs/{토큰}/set`
- `fetchPublicSetDoc(token, docId): PublicDoc` — `/pub/docs/{토큰}/docs/{문서id}`
- 오류 분류는 기존 `PublicDocError` 그대로

### 4.4 `PublicDocView`

- 처음에 `fetchPublicSet` 을 같이 호출한다. 실패해도 시작 문서 표시는 막지 않는다(묶음을 못 받으면 위키링크는 `--plain`)
- 묶음 문서가 **2개 이상일 때만** `resolveWikiLink` 를 준다: `resolveWikiTarget(target, set.docs)` → 찾으면 `formatPublicHash(token, id)`, 못 찾으면 `null`
- 클릭(`onOpenWikiLink`): 찾은 문서면 `history.pushState` 로 해시를 바꾸고 그 문서를 연다. 못 찾으면 아무 일도 없다
- 뒤로·앞으로 가기: `hashchange` 로 `#/p/{토큰}/(.+)` 을 읽어 문서를 바꾼다 (F-211 `PublicFolderView` 와 같은 방식)
- 문서 본문은 시작 문서면 `fetchPublicDoc`, 아니면 `fetchPublicSetDoc`
- `resolveAttachment` 경로도 같은 규칙: 시작 문서면 `/pub/docs/{토큰}/attachments/…`, 아니면 `/pub/docs/{토큰}/docs/{문서id}/attachments/…`
- 묶음 문서가 1개면 지금과 완전히 같다 — 위키링크는 `--plain`, 화면·요청 추가 없음
- **문서 목록 UI 는 이번 범위가 아니다.** 옆 목록을 그리지 않는다. 돌아가기는 브라우저 뒤로 가기

### 4.5 `PublicFolderView` (F-237 승계)

- `resolveWikiLink(target)`: `resolveWikiTarget(target, folder.docs)` → 찾으면 `formatPublicFolderHash(token, id)`, 못 찾으면 `null`
- 클릭은 기존 `selectDoc(id)` 를 재사용한다(목록 클릭과 같은 흐름). 좁은 창에서 목록이 닫혀 있어도 동작한다
- 대상 풀은 `/pub/folders/:token` 응답(`folder.docs`)뿐이라 폴더 밖 제목이 새어나가지 않는다 — 별도 방어 코드 없음

### 4.6 `DocPane`

- `resolveWikiLink?`·`onOpenWikiLink?` 를 prop 으로 받아 `renderMarkdown`·`Viewer` 에 넘긴다. 주지 않으면 지금과 같다(`--plain`)

### 4.7 못 찾은 대상

- `wikilink--missing` 스타일 그대로, 클릭 무반응. 익명 읽기 전용 화면이라 F-131 5장 "새 문서 만들기" 는 적용하지 않는다
- 새 스타일은 만들지 않는다 (F-131 6장 그대로)

## 5. 범위 밖

- 공개 화면 문서 목록·차례 UI (4.4)
- 발급 뒤 묶음을 고치는 관리 화면 — 재발급으로 대신한다 (0장)
- `#/s/{조각}` 해시 공유(F-130) — 대상 문서가 전달되지 않아 계속 `--plain`
- 초대 기반 공유(F-212 `SharedView`)
- 폴더 링크를 이 대화상자로 흡수하는 일 (F-211 은 그대로)
