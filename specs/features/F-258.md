# F-258 Mermaid 다이어그램

## 2. 요구사항

### 2.1 감지
- ` ```mermaid ` 펜스 코드블록(정보 문자열 첫 단어가 대소문자 무관 `mermaid`)만 대상. `isMermaidInfo(info)` 는 `displayLang` 과 같은 방식으로 첫 단어만 본다(뒤에 다른 글자가 있어도 첫 단어가 `mermaid`면 대상 — 기존 언어 표기 관례와 동일)
- 목록·인용 안 코드블록도 F-106 과 동일하게 대상(이미지처럼 "문서 최상위" 제한 없음)

### 2.2 렌더링 공용 로직 (`src/lib/mermaidRender.ts`)
- `mermaid.initialize({ startOnLoad: false })` 를 모듈 로드 시 1회만 호출(편집·보기 모드가 같은 모듈을 import 하므로 중복 호출 방지는 모듈 스코프 플래그로)
- `renderMermaid(source: string): Promise<{ svg: string } | { error: string }>` — `mermaid.render(고유id, source)` 를 호출해 성공하면 `{ svg }`, 예외(문법 오류 등)를 던지면 `{ error: message }`(message 는 `Error.message`, 없으면 고정 문구 `Mermaid 다이어그램을 그릴 수 없습니다`)
- 고유 id 는 호출마다 다른 값(순번 카운터 등, DOM 에러 방지용 — mermaid 내부 요구사항)
- DOM 을 直접 다루지 않는다(순수에 가까운 async 함수) — `mermaid` 라이브러리 자체가 내부적으로 임시 DOM 을 쓰는 것은 이 함수의 책임 밖

### 2.3 편집 모드 위젯 (`mermaidWidget.ts`, F-106 2.1·2.3 패턴)
- `blocks.ts` 의 `codeWidget` 자리에서 `isMermaidInfo(info)` 면 `MermaidWidget` 을, 아니면 기존 `CodeWidget` 을 만든다 — **겹치면 원문 규칙(F-106 2.1)·클릭 진입(`enterOnClick`)·`observeHeight`·조합 중 재계산 보류는 그대로 상속**(TARGET·buildBlocks 쪽 로직 변경 없음, `codeWidget` 함수 안에서만 분기)
- `eq()` 비교 키는 원문 소스 문자열(코드 본문)만 — 위치·정보문자열은 비교에 넣지 않는다(마크다운 소스가 같으면 다시 렌더링하지 않는다)
- `toDOM`: `div.md-block.md-mermaid` 뼈대를 즉시 만들고(로딩 중 표시 없음, 최소 구현), `renderMermaid(source)` 를 비동기로 불러 완료되면(위젯 DOM 이 아직 연결돼 있으면) 결과에 따라:
  - 성공: `innerHTML` 을 svg 로 교체
  - 실패: F-157 이미지 자리 표시와 같은 모양(아이콘 대신 텍스트만도 가능, 최소 구현)으로 오류 문구 표시, 원문은 그대로 두고 클릭하면(F-106 2.3) 원문 진입해 고칠 수 있다
- 소스 텍스트별 캐시(`WeakMap<EditorView, Map<source, Promise<Result>>>`, `imageWidget.ts` 의 `cacheByView`/`loadAttachment` 와 같은 구조) — 같은 소스를 여러 번 렌더링하지 않는다. `blocks.ts` 의 tracker `destroy()` 에서 `destroyMermaidCache(view)` 도 부른다(캐시만 비움, blob URL 이 없어 URL 해제는 불필요)
- `ignoreEvent()` true(다른 위젯과 동일), `ArrowUp/Down`·클릭 진입은 F-106 코드블록과 동일 취급(블록 시작으로 진입, 줄 단위 오프셋 불필요 — 다이어그램은 하나의 시각 단위)

### 2.4 보기 모드 (`renderMarkdown.ts` + `Viewer.tsx`)
- `renderMarkdown.ts`: `md.renderer.rules.fence` 를 오버라이드(기존 규칙 없으면 markdown-it 기본 fence 렌더러를 기억해 그대로 위임 — `link_open`·`image` 오버라이드와 같은 패턴). 정보 문자열이 `isMermaidInfo` 면 `<div class="md-mermaid" data-mermaid-source="{escapeHtml(본문)}"></div>` 를 내보내고, 아니면 기본 렌더러 결과 그대로
- `Viewer.tsx`: 그린 뒤(`useEffect`, 이미지 로드 `useEffect` 와 같은 자리) `.md-mermaid[data-mermaid-source]` 마다 `renderMermaid(그 값)` 을 호출해 성공하면 `innerHTML` 을 svg 로, 실패하면 오류 문구로 채운다(편집 모드와 같은 문구). 언마운트·재렌더 시 취소 플래그로 경쟁 갱신 방지(이미지 로드 `cancelled` 패턴과 동일)
- 공유·공개 보기(F-210)도 `Viewer` 를 그대로 쓰므로 별도 처리 없이 동작

### 2.5 스타일 (최소, 사람 확인 대상)
- `.md-mermaid`: 다이어그램 svg 는 `max-width: 100%; height: auto`, 가운데 정렬
- 오류 표시: `--muted` 톤 문구 + 여백, 이미지 자리 표시(F-157 2.2)와 톤만 맞추면 됨(똑같은 아이콘까지는 필요 없음)
- 정확한 여백·색 값은 이번 라운드에서 사람이 보고 조정(디자인은 TDD 하지 않는다, CLAUDE.md)
