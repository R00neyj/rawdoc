# F-258 e2e `openApp()` 의 첫 실행 문서 의존 끊기

작성일: 2026-09-18
상태: 사용자 지시(2026-09-18 F-257 7장 처리 방향 "1 — openApp 의존성을 다른 명세로 떼어 먼저 고친다")
근거: `specs/features/F-150.md`(E2E 도입·헬퍼), `F-232.md`(시작 화면 기본값 홈), `F-257.md` 7장(첫 실행 안내 문서 없애기 — 이 명세가 끝나야 진행 가능)

## 1. 범위

### 지금
`e2e/helpers.js:13` 의 `openApp()` 은 빈 저장소에서 앱을 열고 곧바로 `.cm-host .cm-editor` 가 보이길 기다린다

```js
export async function openApp(page) {
  await setPrefBeforeLoad(page, 'md.startScreen', 'last')
  await page.goto('/')
  await expect(page.locator('.cm-host .cm-editor')).toBeVisible()
}
```

이게 되는 이유는 `App.tsx` 649~657행이 **첫 실행에 `사용법` 문서를 하나 만들기 때문**이다. 문서가 하나 생기고 `md.startScreen='last'` 가 그걸 자동으로 연다. `openApp()` 은 35개 spec 에서 418번 불린다

그래서 F-257 7장(첫 실행 생성 분기 제거)을 적용하면 문서가 0개가 되어 홈 화면만 뜨고, F-257 과 무관한 기존 e2e 가 대량으로 깨진다 (F-244 A4·F-232 A2 등에서 실측 확인)

### 한다
- `openApp()` 이 **첫 실행 자동 생성 문서에 기대지 않고** 에디터가 열린 상태를 보장하게 한다
- 문서가 이미 있든(지금) 없든(F-257 7장 뒤) **둘 다에서 똑같이 동작**하게 한다

### 하지 않는다
- `src/**` 는 건드리지 않는다. 첫 실행 생성 분기 제거는 F-257 7장이 한다
- `openApp()` 밖의 헬퍼(`openAppHome`·`importMarkdown`·`setPrefBeforeLoad`)의 계약은 바꾸지 않는다
- 각 spec 파일의 본문은 고치지 않는다 (예외는 3.2)

## 2. 결정

문서가 없을 때 **홈 화면의 `새 문서` 를 눌러** 에디터로 들어간다. IndexedDB 를 직접 심지 않는다 — 저장소 구현에 묶이지 않고, 실제 사용자 경로와 같다

## 3. 요구사항

### 3.1 `openApp()`

```js
export async function openApp(page) {
  await setPrefBeforeLoad(page, 'md.startScreen', 'last')
  await page.goto('/')
  // 문서가 하나도 없으면 홈 화면이 뜬다 — 새 문서를 만들어 에디터로 들어간다
  const editor = page.locator('.cm-host .cm-editor')
  const home = page.locator('.empty-state')
  await expect(editor.or(home)).toBeVisible()
  if (await home.isVisible()) await home.getByRole('button', { name: '새 문서' }).click()
  await expect(editor).toBeVisible()
}
```

- 실제 구현은 위 모양을 따르되 셀렉터·대기는 지금 코드 규약에 맞춘다
- 반환값은 지금처럼 없다. 호출부는 바꾸지 않는다

### 3.2 `serverStore.spec.js` 의 `사용법` 문서 삭제 단계

`e2e/serverStore.spec.js:112~113` 은 로컬 문서 수를 맞추려고 첫 실행 `사용법` 문서를 찾아 지운다. F-257 7장 뒤에는 그 행이 없어 실패한다

- 그 행이 **있으면 지우고 없으면 넘어가게** 한다 (`count() > 0` 확인 후 삭제)
- 개수 단정은 그 뒤 실제 문서 수로 맞춘다
