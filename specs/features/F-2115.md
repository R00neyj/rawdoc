# F-2115 공유받음 줄에서 공유 나가기

작성일: 2026-10-01
상태: 승인 대기. 열린 질문은 Q1 하나(기본값 있음). 형제 명세 F-3011(서버 나가기 API, `depends` 에 넣음)·F-3012(share 알림 행)·F-2116(알림함 share 행·목록 갱신, `Sidebar.tsx` 겹침). **이 명세는 F-3011 이 정한 API 를 부르기만 한다** — 경로·메서드·응답은 F-3011 소관이고, 여기서는 클라이언트 함수 모양과 상태 코드 해석만 정한다. **배포 순서: F-3011 워커가 먼저 나간다.**

## 정해진 것 (사용자 결정, 바꾸지 않는다)

1. 진입점은 사이드바 `공유받음` 묶음 줄의 `⋯` 메뉴(와 같은 메뉴를 여는 우클릭·길게 누르기) 하나. 열린 문서 상단·`#/shares`·명령 팔레트·단축키에는 없다
2. 메뉴 항목은 `공유에서 나가기` 하나. 끌어 옮기기는 계속 없다(F-212 2.4 를 이 항목만큼 번복)
3. 메뉴는 (a) 직접 받은 문서 줄 (b) 공유받음 폴더 이름 줄에만. 폴더 경유 문서 줄에는 없다
4. 확인 대화상자 [취소] [나가기]. 소유자에게 알림 없음. 실패하면 오류 알림, 목록 유지
5. 새 의존성 없음

## 근거 (직접 읽은 것, HEAD `a1b973e`)

- **직접+폴더 둘 다 받은 문서는 클라이언트가 가릴 수 없다.** `worker/grants.ts` `handleGetShared`: 초대 폴더 사슬에 걸리면 `viaFolder` 를 채우고(가장 가까운 초대 폴더) `role = higherRole(폴더 역할, 문서 초대 역할)`. 문서 초대가 있었는지는 응답에 없다(`SharedItem`·`v1Contract.ts` `viaFolder` 주석). → 이런 문서는 폴더 묶음 아래 보이고 문서 줄 메뉴가 없다. 판정 규칙은 2.1, 다른 길은 Q1
- 중첩 초대(폴더 A 와 그 하위 B 둘 다 받음)면 B 안 문서의 `viaFolder` 는 B. 그래서 "A 에서 나감" 으로 사라지는 줄은 `viaFolder.id === A` 인 줄뿐이고, B 줄은 남는다
- `serverStore.ts` `fetchDocIntoCache`·`get`: `knownSharedIds` 에 있는 문서는 `md-remote` 에 넣지 않는다. 옛 버그로 들어간 행은 `list()` 의 `deleteDocsNotIn(keepIds)`(keepIds = 내 `/api/docs` 요약 + 대기·로컬 전용)이 지운다 → **`md-remote` 는 따로 지울 것 없음**
- `serverStore.ts` `lastSharedList()` 는 마지막 `list()` 결과를 들고 있고, 로그인 상태의 탭 신호(`resyncFromCache`)·검색·지도(`createCachedListSource`)가 이것을 캐시 목록에 덧붙인다(`combineCachedList`). **그대로 두면 나간 문서가 다음 탭 신호에 되살아난다** → 2.4 `forgetSharedDocs`
- 다른 탭: `docs-changed` 를 받은 서버 탭은 `resyncFromCache` → 자기 탭의 낡은 `lastSharedList` 를 쓰고, 서버 목록은 TTL(`LIST_FRESH_TTL_MS` 600,000ms) 밖에서만 다시 읽는다. **`docs-changed` 로는 다른 탭에서 안 사라진다** → 2.5 새 메시지
- `md-yjs`: `useDocSession` 은 edit 실시간 세션에만 `persist` 를 넘긴다(`readOnly ? null : persist`). `yjsFlush.ts` `flushUnsyncedDocs` 는 `unsyncedLocal` 행을 부팅 때마다 올리려 하고, 결과가 `forbidden` 이면 행을 지우지 않는다(`gone` 만 `removeDoc`) → 나간 문서의 남은 행은 영영 재시도된다. `attachment.detach()` 는 듣기만 멈춘다. 이미 만든 IDB 쓰기 트랜잭션은 뒤에 만든 `removeDoc` 트랜잭션보다 먼저 끝난다(같은 저장소 readwrite 는 만든 순서)
- outbox: edit 문서 대기 편집이 나간 뒤 나가면 `updateDoc` 이 403 → `이 문서를 편집할 권한이 없어졌습니다.` 오류가 뜬다(`serverStore.ts` forbidden 갈래). `ServerStore.flushOutbox()` 가 "진행 중 회차를 기다리고 한 회차 더" 를 준다
- 열린 문서가 목록에서 먼저 빠지면 `currentDoc` 이 null → `isReadOnlyByRole`(`currentDoc?.role === 'view'`)이 거짓이 되어 view 문서가 잠깐 편집 가능해진다 → 홈 이동이 목록 제거보다 먼저(2.3)
- `useDocNavigation.ts` `goHome` = `beforeLeaveDoc` → `leaveScreens` → `setCurrentDocId(null)` → `replaceHashUrl(null)`. `md.lastDocId` 가 목록에 없으면 `resolveInitialDoc` 가 다른 문서로 넘어가므로 지울 필요 없다
- 사이드바 우클릭은 `.tree-row` 의 `onContextMenu` → `handleRowContextMenu` 가 **선택을 그 줄로 바꾸고** `contextMenu` 를 연다. 터치 길게 누르기도 같은 `contextmenu` 이벤트다(고정됨·트리 줄 선례). 선택은 F-255 일괄 이동·삭제의 대상이다
- `FolderMenuItem.disabled` = 모양만 비활성, 눌러도 `onSelect` 를 부른다 — 금고 항목의 오프라인 선례(`e2eeConvertItems`, `useE2eeConvert.ts` `e2eeConvertOnline = syncState?.online ?? true`)
- 대화상자 번호: ia.md 1장 표 D-1~D-7·D-15, F-2092 가 D-16 을 쓴다 → **D-17**

## 2. 동작

### 2.1 메뉴가 붙는 줄

| 줄 | 메뉴 | 대상 |
| --- | --- | --- |
| 문서 줄, `viaFolder` 없음 | 있음 | `{ type: 'doc', id }` |
| 문서 줄, `viaFolder` 있음(직접+폴더 둘 다 받은 문서 포함) | 없음 — 우클릭도 브라우저 기본 | — |
| 폴더 이름 줄 | 있음 | `{ type: 'folder', id: viaFolder.id }` |

- 메뉴 항목: `공유에서 나가기`, 아이콘 `IconGroupRemove`, `danger`. 다른 항목은 없다
- 오프라인(`syncState.online === false`)이면 `disabled` 로 보이고, 누르면 info 알림 `온라인일 때 공유에서 나갈 수 있습니다.` — 대화상자를 열지 않는다
- 우클릭·길게 누르기는 **선택을 바꾸지 않고** 그 줄 메뉴만 연다(`contextMenu` 열쇠 `shared:{id}`·`shared-folder:{id}`, `RowPlace` 는 그대로). 남의 문서가 F-255 일괄 작업 선택에 섞이지 않게
- 폴더 이름 줄은 `div.tree-row.shared-folder-row` 안에 지금의 `span.shared-doc-folder-name` + `FolderMenu`. 펼침·접기는 없다(F-2116 이 넣으면 그 위에 얹는다)
- 문서 줄 `⋯` 은 소유자 이메일 앞부분(`.shared-doc-owner`) 오른쪽 끝. 배치·잘림 값은 명세에 두지 않고 H1

### 2.2 D-17 `공유에서 나가기`

- 메뉴 항목을 누르면 `closeSidebarIfNarrow()` 후 연다(D-1 요청과 같다). 기본 포커스 `취소`, `Esc` = 취소
- `나가기` 를 누르면 두 버튼 비활성, `나가기` 글자가 `나가는 중…`. 보내는 동안 `Esc` 는 막는다(`Dialog` `onCancel` 에서 `preventDefault`). 결과가 오면 닫는다
- 문구는 3장. 폴더의 `{N}` = 지금 목록에서 `viaFolder.id` 가 그 폴더인 공유 문서 수

### 2.3 나가기 순서 (`runLeaveShare`)

1. `affected` = `sharedIdsLeftBy(docs, target)`, `openAffected` = 열린 문서가 `affected` 에 있음
2. `openAffected` 면 `beforeLeaveDoc()`. 그다음 언제나 `flushOutbox()` — 대기 편집을 권한이 있을 때 올려 나간 뒤 403 오류가 뜨지 않게
3. `leaveShare(target.type, target.id)`. 실패 → error 알림 `공유에서 나가지 못했습니다. 연결을 확인한 뒤 다시 시도해 주세요.`, 대화상자 닫기, 그 밖은 아무것도 안 한다(목록·화면 그대로)
4. 성공(404 포함, 2.6) → 대화상자를 닫고 다음 순서로:
   1. `openAffected` 면 `goHome()` 을 기다린다 — **목록 제거보다 먼저**(근거: view 역할이 잠깐 풀린다)
   2. `forgetSharedDocs(affected)` 후 `setDocs` 로 `removeSharedIds`
   3. `affected` 를 `md-yjs` 지울 목록에 넣는다(2.4)
   4. `post({ kind: 'shared-left', tabId, docIds: affected })`
   5. info 알림 `공유에서 나갔습니다.`
   6. `resyncFromStore('tab')` 를 기다리지 않고 부른다 — 다른 초대(직접 초대·바깥 폴더 초대)로 아직 볼 수 있는 문서가 되돌아온다. 제거가 먼저 반영돼 `mergeBootList` 의 `removedIds` 에 들지 않으므로 "다른 곳에서 지워짐" 알림은 나지 않는다
- 낙관 제거는 하지 않는다 — 실패 때 되돌릴 일이 없고, 대화상자가 `나가는 중…` 으로 기다림을 보여 준다
- 직접+폴더 둘 다 받은 문서를 연 채 폴더에서 나가면: `viaFolder` 가 그 폴더라 홈으로 가고 줄이 빠졌다가 6번 다시 읽기 뒤 직접 줄로 돌아온다(그때 메뉴가 생긴다). 드물어 받아들인다

### 2.4 로컬 정리

| 대상 | 처리 |
| --- | --- |
| `docs` 상태 | 2.3 4-2 |
| `md-remote` | 없음(근거) |
| `lastSharedList` | `forgetSharedDocs(ids)` 가 그 id 를 뺀다. `knownSharedIds` 는 **남긴다** — 빼면 다음 `get()` 이 남의 문서를 내 캐시에 넣는다 |
| `md-yjs` | 훅의 effect 가 지울 목록 중 **지금 열린 문서가 아닌 id** 만 `yjsStoreRef` 의 `removeDoc` 으로 지운다. 열린 문서는 홈 이동이 커밋돼 `useLiveDoc` 정리(`detach`)가 돈 뒤에야 지운다 — 같은 커밋의 정리 함수가 effect 본문보다 먼저 돈다 |

| 위키링크·팔레트 문서 | `docs` 상태에서 만들므로 2.3 4-2 로 빠진다 |
| `md.lastDocId` | 그대로(근거) |
| 알림함 행 | 그대로 — F-2116 소관. 누르면 기존 403 경로 |

### 2.5 다른 탭

- 새 메시지 `{ kind: 'shared-left'; tabId; docIds }`. `useTabSync` 가 자기 tabId 가 아니면 디바운스 없이 `onSharedLeft(docIds)` 를 부른다
- 받는 탭: 2.3 4번에서 `post`·성공 알림을 뺀 것과 같다 — 열린 문서가 `docIds` 안이면 `goHome()` 후 info 알림 `다른 탭에서 이 문서의 공유에서 나갔습니다.`(그 경우에만), `forgetSharedDocs`·`removeSharedIds`, `md-yjs` 지울 목록, `resyncFromStore('tab')`
- `docs-changed` 를 쓰지 않는 이유: 근거 다섯째 줄. 받는 탭이 서버를 다시 읽는 것은 이 메시지 한 번뿐이다
- `BroadcastChannel` 이 없으면 아무것도 안 한다(F-296 5.4 와 같다)

- `sharedIdsLeftBy`: 공유 문서(`isSharedDoc`)만 본다. `doc` → 그 id 하나(`viaFolder` 없을 때만), `folder` → `viaFolder.id === target.id` 인 것 전부. 내 문서는 같은 id 여도 절대 넣지 않는다
- `leaveShare`: 2xx·**404 는 resolve**(이미 없는 초대 — 소유자가 먼저 철회했거나 다른 탭이 먼저 나감). 그 밖은 기존 `classifyStatus`·`rateLimitedError`·`accountBlockedError` 분류 후 `ApiError`. F-3011 은 "내 행이 없음"을 404 `not_found` 로 정했다(3.2 2번) — 소유자 철회·다른 탭 먼저 나감·폴더 경유 문서에 문서 경로 호출이 모두 여기 든다. 앞의 둘은 성공으로 보고, 마지막은 메뉴가 viaFolder 문서에 붙지 않아 생기지 않는다
- 포커스(넓은 창, 사이드바가 열려 있을 때만): 취소 → 그 줄의 `⋯` 버튼(`aria-label="{이름} 메뉴"`). 성공 → `공유받음` 머리 버튼(`.shared-group-toggle`), 묶음이 사라졌으면 사이드바 `새 문서` 버튼. 실패 → 그 줄의 `⋯` 버튼. 좁은 창은 사이드바가 닫혀 있어 `Dialog` 기본 복귀에 맡긴다
