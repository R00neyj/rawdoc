## 2. 요구사항

### 2.1 D1
```sql
CREATE TABLE attachments (
  owner_id TEXT NOT NULL REFERENCES users(id),
  id TEXT NOT NULL,
  ext TEXT NOT NULL CHECK (ext IN ('png','jpg','gif','webp')),
  mime TEXT NOT NULL,
  size INTEGER NOT NULL,
  width INTEGER NOT NULL,
  height INTEGER NOT NULL,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (owner_id, id)
);
```
- R2 키 `att/{owner_id}/{id}.{ext}`. 버킷은 공개 접근을 켜지 않는다 (서명 URL 도 쓰지 않는다)

### 2.2 서버 판정 (`imageSniff.ts`)
- 앞부분 바이트로 형식: PNG `89 50 4E 47 0D 0A 1A 0A`, JPEG `FF D8 FF`, GIF `GIF87a`/`GIF89a`, WebP `RIFF????WEBP`. 그 밖(SVG 포함) 거부
- 가로세로: PNG IHDR, GIF 논리 화면, JPEG SOFn 마커, WebP `VP8 `/`VP8L`/`VP8X`
- 거부 조건: 판정 실패, 크기 5,242,880바이트 초과, 가로·세로 0, **픽셀 수 40,000,000 초과**(압축 폭탄)

### 2.3 올리기 (로그인)
- `PUT /api/attachments/:id.:ext`, 본문 = 이미지 바이트 그대로
  - `id` 는 소문자 16진수 16자(F-156), `ext` 는 4종
  - `Content-Length` 가 없거나 5MB 초과면 본문을 읽기 전에 413
  - 2.2 판정 형식이 `ext` 와 다르면 `400 {"error":"type_mismatch"}`, 판정 실패는 `400 {"error":"unsupported"}`
  - 통과: R2 `put`(`httpMetadata.contentType` = 판정 mime) → D1 기록 → `201 {id, ext, mime, size, width, height}`
  - 같은 `(owner, id)` 가 이미 있으면 올리지 않고 `200` 기존 값 (재시도 안전)
- 클라이언트가 보낸 `Content-Type` 은 쓰지 않는다

### 2.4 내보내기
- `GET /api/attachments/:id.:ext` (로그인, 소유자) → R2 본문
- `GET /pub/docs/:token/attachments/:id.:ext` (로그인 없음) → 토큰이 유효하고(F-210 2.3), 링크 문서 원문의 첨부 참조(`src/lib/imageBlock` `extractAttachmentRefs`)에 이 id 가 있고, 첨부 소유자 = 문서 소유자일 때만. 아니면 404
- 응답 헤더: `Content-Type` = D1 에 기록한 판정 mime, `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: same-origin`(다른 사이트 `<img>` 로 못 끌어 쓰게), `Content-Disposition: inline`
  - `/api`: `Cache-Control: private, max-age=31536000, immutable` (id 가 같으면 내용이 같다)
  - `/pub`: `Cache-Control: private, max-age=300` (링크를 끊으면 5분 안에 막힌다)

### 2.5 클라이언트 (`serverStore`)
- `putAttachment({ blob, mime, ext, width, height })`
  1. `ext !== 'gif'` 면 `toWebp(blob)`: `createImageBitmap` → `OffscreenCanvas` → `convertToBlob({ type: 'image/webp', quality: 0.9 })`. **변환 결과가 원본보다 크면 원본을 쓴다.** 변환 실패도 원본
  2. 캐시에 blob 저장(`uploaded: false`) → 보낼 목록 `upload` → `{ id, ext }` 즉시 반환 (반환 `ext` 가 `webp` 일 수 있다 — 원문 `src` 는 반환값으로 만들어진다, F-156)
- 보내기 `upload`: 2.3 PUT. 201·200 → `uploaded: true`. 400·413 → 목록에서 빼고 error 알림 `이미지를 서버에 올리지 못했습니다.` 네트워크 실패는 F-207 규칙
- `getAttachment(id)`: 캐시 → 없으면 원문에서 찾은 `ext` 로 `GET /api/attachments` → 캐시(`uploaded: true`)
- **옮겨 온 로컬 첨부**: 부팅 때 캐시 문서 원문이 참조하는 첨부 중 서버 캐시에 없고 로컬 `md-docs` 에 있는 것은 **변환 없이** 캐시로 복사 + `upload` (원문 `src` 가 바뀌면 안 되므로). 이미 올린 것은 서버가 200
- `listAttachments`·`removeAttachment` 는 캐시만 (서버 삭제·GC 는 이번 범위 밖)

### 2.6 공개 보기 (F-210 S-5)
- `Viewer` 에 `resolveAttachment(id)`: 원문에서 `ext` 를 찾아 `/pub/docs/{토큰}/attachments/{id}.{ext}` → `blob` → `createImageBitmap` 으로 `width`·`height` → `{ blob, width, height }`. 실패는 자리 표시(F-157 문구)
- `.md 내보내기`: 이미지가 있으면 F-158 zip (`buildExportPayload` 에 위 방식으로 읽는 `getAttachment` 를 가진 객체를 넘긴다)
