## 2. 전체 그림

- **알림함**: 로그인하면 상단바 `계정` 왼쪽에 `알림` 버튼이 생긴다. `useNotifications` 가 부팅 뒤 한 번, 그 뒤 60초마다(탭이 보일 때), 탭이 다시 보일 때, 다시 온라인이 될 때, 알림함을 열 때 `GET /api/notifications?limit=30` 을 부른다. 버튼 배지는 안 읽은 수. 팝오버는 새것부터 30개
- **읽음**: 항목을 누르면 그 항목만, `모두 읽음` 은 전부 — 화면을 먼저 바꾸고 `POST /api/notifications/read` 를 보낸다. 실패하면 되돌린다
- **이동**: 항목을 누르면 팝오버를 닫고 `#/d/{docId}/c/{threadId}` 로 간다. 그 뒤는 F-505 7.6(문서 열기 → 댓글 준비 → 스레드 활성·`reveal` → 주소 `#/d/{docId}`). 목록에 없는 문서면 가기 전에 목록을 한 번 다시 읽는다(r5)
- **멘션**: 서버 문서의 새 댓글 입력칸·답글칸에서 `@` 를 치면 입력칸 바로 아래에 후보 목록이 열린다. 후보는 `GET /api/docs/:id/people` 에서 나를 뺀 사람. 고르면 `@{이메일} ` 이 들어가고, 보낼 때 `finalizeMentions(본문, 고른 것)` 이 `mentions` 가 된다. 알림 행은 서버가 만든다(F-500 3.5)

```ts
  pending: readonly PendingRead[],
): NotificationsResponse
export function dropSettledReads(pending: readonly PendingRead[], fetchStartedAt: number): PendingRead[]
```

- 요청은 `fetch(path, { credentials: 'same-origin' })` — `sharesApi.ts` 와 같은 모양. `fetchNotifications` 결과 가르기: 연결 실패 `network`, 401 `unauthorized`, 5xx `server`, 그 밖 2xx 아님·JSON 파싱 실패·`readNotificationsResponse` 가 `null` 이면 `invalid`(r4 — 가짜 서버가 없는 e2e 는 200 HTML 이 온다)
- `readNotificationsResponse`: 키가 `items`(배열)·`unread`(0 이상 정수)이고 항목마다 `NotificationItem` 열한 필드의 타입이 맞고 `kind` 가 `mention`·`reply` 중 하나일 때만 값을 돌려준다. 하나라도 틀리면 `null` — 부분만 쓰지 않는다
- `readDocPeopleResponse`: `people` 이 배열이고 항목마다 `email` 문자열·`role` 이 `owner`·`edit`·`view` 일 때만
- `fetchDocPeople` 는 200 + 모양이 맞을 때만 `ok: true`. 401·404·409 `e2ee_doc`·5xx·연결 실패·모양 틀림은 모두 `ok: false`(화면은 이유를 가리지 않는다 — 5.2)
- `markNotificationsRead` 는 몸통 `{ ids }` 또는 `{ all: true }` 를 JSON 으로 `POST /api/notifications/read`. `ids` 는 1~50개(`NOTIFICATIONS_READ_IDS_MAX`)여야 하고, `markRead` 는 1개, F-510 `markDocRead` 는 그 문서의 안 읽은 id 전부(최대 50)를 보낸다
- `notificationText`: `mention` → `{actorEmail}님이 "{제목}" 댓글에서 멘션했습니다.`, `reply` → `{actorEmail}님이 "{제목}"의 댓글에 답글을 달았습니다.`(F-500 5.1). `{제목}` = `docTitle` 이 빈 문자열(공백만 포함)이면 `제목 없는 문서`, 아니면 앞뒤 공백을 뺀 제목이 `NOTIFICATION_TITLE_MAX`(40) 코드 포인트를 넘으면 39자 + `…`. 이유: `doc_title` 은 500자까지 온다(F-502 6장)
- `notificationExcerptLine`: 줄바꿈(`\r\n`·`\r`·`\n`)을 공백 하나로, 앞뒤 공백을 뺀다. 말줄임은 CSS 가 한다(F-502 6장 "한 줄로 보이는 것은 화면 몫")
- `shouldFetchNotifications` 판정 — 위에서부터 처음 맞는 줄:
  1. `stopped`(401 을 받음, 4.2) 또는 `inFlight` 또는 `!online` → 거짓
  2. `reason === 'enable'` → 참
  3. `reason === 'interval'` → `visible` 이고 `lastStartedAt` 이 `null` 이거나 `now − lastStartedAt ≥ NOTIFICATIONS_POLL_MS`
  4. 그 밖(`visible`·`online`·`open`) → `lastStartedAt` 이 `null` 이거나 `now − lastStartedAt ≥ NOTIFICATIONS_MIN_GAP_MS`
- `applyPendingReads`(먼저 칠한 읽음을 서버 값 위에 얹는다): `ids` 대기의 항목은 `readAt` 을 그 대기의 `at` 으로 본다. `all` 대기는 `createdAt ≤ at` 인 항목을 모두 읽음으로 본다. `unread` = `all` 대기가 있으면 "그 뒤에 만들어진(`createdAt > at`) 안 읽은 항목 수(목록 안)", 없으면 `max(0, 서버 unread − 서버가 안 읽음이라 한 항목 중 ids 대기에 든 수)`
- `dropSettledReads`: 요청이 끝난(`settledAt !== null`) 대기 중 `settledAt ≤ fetchStartedAt` 인 것을 뺀다 — **요청이 끝난 뒤에 시작한 가져오기**가 돌아왔을 때만 뺀다. 이유: 요청 전에 출발한 GET 이 늦게 돌아와 옛 안 읽음을 다시 칠하는 깜빡임을 막는다(판정 U8)

### 3.2 `src/app/mentionCandidates.ts`

```ts
export const MENTION_CANDIDATES_MAX = 8          // F-500 4.9
export const MENTION_QUERY_MAX = 254             // COMMENT_EMAIL_MAX 와 같은 값
export const MENTION_PEOPLE_TTL_MS = 300_000

export type MentionPerson = { email: string; role: 'owner' | 'edit' | 'view' }
export type MentionToken = { start: number; end: number; query: string }

export function mentionTokenAt(text: string, caret: number): MentionToken | null
export function filterMentionCandidates(people: readonly MentionPerson[], query: string, selfEmail: string): MentionPerson[]
export function applyMentionPick(text: string, token: MentionToken, email: string): { text: string; caret: number }
export function mentionLimitReached(body: string, picked: readonly string[]): boolean

export type PeopleCache = {
  get(docId: string): Promise<readonly MentionPerson[] | null>   // null = 불러오지 못함
  peek(docId: string): readonly MentionPerson[] | undefined       // 캐시에 있는 것만, 요청 없음
}
export function createPeopleCache(deps: {
  load: (docId: string) => Promise<readonly MentionPerson[] | null>
  now: () => number
  online: () => boolean

```

- `mentionTokenAt` (r1): 캐럿에서 왼쪽으로 `[A-Za-z0-9._%+\-@]` 글자를 걷는다. 멈춘 자리의 글자가 `@` 이고 캐럿보다 앞이면 토큰이다 — `start` = 그 `@` 자리, `query` = `@` 다음부터 캐럿까지. 캐럿 오른쪽으로도 같은 글자가 이어지면 `end` 는 그 끝(고를 때 함께 바꾼다), 아니면 `end = caret`. `query` 가 `MENTION_QUERY_MAX` 를 넘으면 `null`. 이 규칙은 `parseMentions` 의 "앞 글자가 이메일 글자면 멘션이 아니다"(`MENTION_BEFORE_BAD`)와 같은 판정이라 `a@b`·`.@b`·`x@` 에서는 목록이 열리지 않는다
- `filterMentionCandidates`: `selfEmail` 과 소문자로 같은 사람을 뺀다. `query` 를 소문자로 바꿔 이메일(소문자)에 **부분 일치**하는 사람만 남긴다. 이메일이 `query` 로 **시작하는** 사람을 앞에, 나머지를 뒤에 — 각 묶음 안은 API 순서(소유자 먼저, 나머지 이메일 사전순, F-503 6.2) 그대로. 최대 `MENTION_CANDIDATES_MAX`. 빈 `query` 는 모두 일치
- `applyMentionPick`: `[start, end)` 를 `@{email}` 로 바꾼다. 바꾼 뒤 바로 다음 글자가 공백류(`\s`)가 아니면 공백 하나를 넣는다. 캐럿은 그 공백 뒤(이미 공백이 있었으면 그 공백 뒤). 이메일은 API 가 준 글자 그대로 넣는다 — `parseMentions`·`finalizeMentions` 가 소문자로 맞춘다(r1)
- `mentionLimitReached(body, picked)` = `finalizeMentions(body, picked).length >= MENTIONS_PER_COMMENT_MAX`
- `createPeopleCache`: 문서 id 마다 성공한 결과를 `MENTION_PEOPLE_TTL_MS`(5분) 동안 둔다. 같은 문서의 요청이 진행 중이면 그 Promise 를 같이 쓴다(한 번만 보낸다). 실패(`null`)는 캐시하지 않는다 — 다음 `get` 이 다시 보낸다. `online()` 이 거짓이면 요청하지 않고 캐시 값(만료 전) 또는 `null`. 이유: 초대가 바뀌는 일은 드물고, 요청 하나가 D1 질의 최대 9번(F-503 6.2)이다

### 3.3 `src/app/useNotifications.ts` — 훅

```ts
import type { NotificationItem } from '../lib/docComments'

export type NotificationsState = {
  status: 'idle' | 'loading' | 'ready' | 'failed'   // idle = 꺼짐, loading = 첫 응답 전, failed = 한 번도 못 받음
  items: readonly NotificationItem[]                // 대기 읽음을 얹은 값 (3.1 applyPendingReads)
  unread: number | null                             // null = 아직 모름 → 배지 없음
}
export function useNotifications(input: { enabled: boolean; blocked: boolean }): NotificationsState & {
  refresh: (reason: 'open') => void
  markRead: (id: string) => void
  markAllRead: () => void
}
```

- `enabled` 가 거짓이면 상태 `{ status: 'idle', items: [], unread: null }`, 타이머·듣기 없음. 참이 되면 `enable` 로 한 번 가져온다
- 가져오기 까닭과 판정은 3.1 `shouldFetchNotifications`. `interval` 은 `setTimeout` 을 **가져오기를 시작할 때마다** `NOTIFICATIONS_POLL_MS` 뒤로 다시 건다 — "마지막 가져오기로부터 60초". `visibilitychange`(보임), `online` 이벤트, `refresh('open')` 이 나머지 까닭이다. `visible` = `document.visibilityState === 'visible'`, `online` = `navigator.onLine`
- 응답: 성공이면 `dropSettledReads(대기, 이 가져오기의 시작 시각)` 뒤 `applyPendingReads` 로 상태를 바꾼다. 실패면 상태를 두고(한 번도 못 받았으면 `failed`), `unauthorized` 면 `stopped` 를 켠다 — 이 훅이 다시 `enabled` 로 켜질 때(계정 상태가 바뀔 때) 풀린다
- `markRead(id)`: 그 항목이 이미 읽음이거나 `blocked` 면 아무것도 하지 않는다. 아니면 `ids` 대기를 더하고 곧바로 화면에 얹은 뒤 `markNotificationsRead({ ids: [id] })`. 성공이면 `settledAt = Date.now()`, 실패면 그 대기를 빼고 마지막 서버 값으로 되돌린다
- `markAllRead()`: `unread` 가 0 이거나 `null` 이거나 `blocked` 면 아무것도 하지 않는다. 아니면 `all` 대기로 같은 방식
- 읽음 요청 실패에 알림 띠를 띄우지 않는다 — 다음 가져오기에서 서버 값으로 돌아오는 것이 전부다(F-500 4.8)

## 4. 알림함 (반드시 결론 1)

### 4.1 보이는 조건·버튼

- **보이는 조건(모두)**: 부팅이 끝남(`bootPhase === 'ready'`) · 저장소가 `server` · 계정 상태가 `in`. 로그아웃·로컬 저장소·계정 상태 `offline`(부팅 때 `/api/me` 를 못 읽음)이면 버튼이 없다. 계정 상태가 `offline` → `in` 으로 바뀌면(지금 `online` 이벤트의 `recheckAccount`) 버튼이 생기고 곧바로 가져온다
- 모든 화면(문서·홈·공유 관리·도움말·지도·공유 링크 화면)에서 같다 — 상단바가 모든 화면에 있다. 알림은 계정 단위라 문서와 무관하다
- 버튼: 아이콘 `IconNotifications`, 툴팁 `알림`, `aria-label` = `알림, 안 읽음 {N}개`(N = `unread`, 모르면 0). 배지 글자 = `commentBadgeText(unread)`(1~99, 100 이상 `99+`, 0 → 없음 — F-500 4.8 과 4.3 이 같은 규칙이라 F-505 함수를 다시 쓴다). `unread === null`(첫 응답 전·한 번도 못 받음)이면 배지 없음
- 좁은 창에서도 상단바에 그대로 둔다(메뉴로 접지 않는다) — H4

### 4.2 가져오기와 갱신 주기

| 까닭 | 언제 | 조건 (3.1) |
| --- | --- | --- |
| `enable` | 4.1 조건이 참이 된 순간(부팅 뒤 한 번, 계정이 `in` 이 될 때) | 온라인·진행 중 아님 |
| `interval` | 마지막 가져오기 시작으로부터 60초 | 탭이 보임. 안 보이면 건너뛰고 다음 `visible` 을 기다린다 |
| `visible` | `visibilitychange` 로 보이게 됨 | 마지막 시작으로부터 5초 이상 |
| `online` | `online` 이벤트 | 같음 |
| `open` | 알림함을 열 때 | 같음 — 5초 안에 가져왔으면 그 값을 보인다 |

- **폴링이다.** 실시간 밀어주기는 없다(F-500 8장). 최악 지연은 F-500 3.5 대로 서버 쪽 최대 60초 + 이 주기 60초

- 탭이 여럿이면 탭마다 가져온다. 한 탭에서 읽은 것은 다른 탭의 다음 가져오기에 반영된다(Q4)
- 비용은 9장

### 4.3 팝오버

- 폭 360px, 좁은 창(`narrow`)은 화면 폭. 최대 높이·그림자·안 읽음 점 모양은 design.md(12장 H3). 항목이 넘치면 팝오버 안에서 스크롤
- 머리: 제목 `알림` + 버튼 `모두 읽음`(안 읽은 것이 없으면 비활성, 막힌 계정은 없음)
- 몸통 — 위에서부터 처음 맞는 것: `status === 'loading'` → `불러오는 중…` / `status === 'failed'` → `알림을 불러오지 못했습니다.` / 항목 0개 → `새 알림이 없습니다.` / 그 밖 → 항목 목록(`items` 순서 그대로 — 서버가 새것부터 준다)
- 항목 한 줄씩 세 부분: `notificationText(item)` / `notificationExcerptLine(item.excerpt)`(한 줄, 넘치면 CSS 말줄임) / `formatCommentTime(item.createdAt, now)`. 안 읽은 항목은 `data-unread="true"` 와 점 표시, 그리고 버튼 안 눈에 안 보이는 글자 `안 읽음`(읽기 이름에 들어간다)
- `now` 는 팝오버가 열린 동안 60초마다 다시 읽는다(F-505 레일과 같은 주기)
- 30개를 넘는 알림은 보이지 않는다(더 보기 없음 — F-500 3.9 `limit=30`). `unread` 는 서버의 전체 수라 목록 안 점 수보다 클 수 있다. `모두 읽음` 은 보이지 않는 것까지 읽음으로 한다
- **포커스**: 열면 첫 항목, 항목이 없으면 팝오버(`tabindex="-1"`). `↑`·`↓` 는 항목 사이를 돌고(끝에서 처음으로), `Home`·`End` 는 처음·끝. `Enter`·`Space` 는 버튼 기본 동작. `Esc` 는 닫고 `알림` 버튼으로. `Tab` 은 막지 않는다(`AccountMenu` 와 같게 — 팝오버 밖으로 나가도 열린 채)
- 여는 길: `알림` 버튼, 팔레트 `알림 열기`

### 4.4 읽음 처리 시점

- **알림함을 열기만 해서는 읽음이 되지 않는다.** 읽음이 되는 것은 셋이다: 그 항목을 누름(F-500 4.8 "그 항목만"), `모두 읽음`, 문서를 열 때 그 문서의 것(F-510 4.2)
- 둘 다 먼저 화면을 바꾸고(점·배지) 요청을 보낸다. 실패하면 대기를 빼서 서버 값으로 돌아간다(3.3). 요청 전·중에 출발한 가져오기가 옛 값을 다시 칠하지 않는다(3.1 `dropSettledReads`)
- 이미 읽은 항목을 누르면 읽음 요청 없이 이동만 한다
- **막힌 계정**(`account.blocked`): 읽음 요청을 보내지 않는다 — `POST /api/notifications/read` 가 쓰기 관문에서 403 `account_blocked` 로 막히기 때문이다(F-503 8.3). `모두 읽음` 이 없고, 항목을 누르면 이동만 한다. 안 읽음 표시는 그대로 남는다
- 쓰기 한도: 읽음 요청 하나 = 하루 쓰기 5,000·분당 120 중 1(F-500 3.8). 항목 하나마다 한 번이라 한도에 가까워질 일은 없다고 본다(9장)

### 4.5 항목 → 문서·스레드로 이동 (반드시 결론 3)

항목을 누르면 App 의 `onOpenItem(item)` 이 이 순서로:

1. 알림함을 닫는다
2. `markRead(item.id)`(4.4 — 이미 읽음·막힌 계정이면 건너뜀)
3. `item.docId` 가 사이드바 목록(`docsRef.current`)에 없고 온라인이면 `resyncFromStore()` 를 한 번 기다린다(r5 — 부팅 뒤에 초대받은 문서). 실패는 무시하고 다음으로
4. `location.hash = formatCommentHash(item.docId, item.threadId)` — 주소 바꾸기라 뒤로 가기 기록이 하나 는다(위키링크를 누른 것과 같다). 그 뒤는 **F-505 7.6 그대로**: 같은 문서면 대상만 잡고, 다른 문서면 연다. 댓글이 준비되면 스레드 활성·`reveal`, 주소는 `#/d/{docId}` 로 바뀐다(`replaceState`)

## 5. 멘션 입력 (반드시 결론 2)

### 5.1 어디서 되나

- `MentionSource` 가 있는 때(모두): 4.1 의 조건(부팅 끝·`server`·계정 `in`) · 열린 문서가 있음 · `commentAccess(…)` 가 `write`(직접이든 F-506 의 명령이든 — edit·소유자·연결된 view). App 이 `{ docId: currentDocId, selfEmail: account.email, people: 캐시 }` 를 만들어 `MentionSourceContext` 로 준다
- 없을 때: 로컬 문서, 금고, 댓글을 달 수 없는 경로. 입력칸은 평범한 `textarea`
- 되는 입력칸: **새 댓글 입력 카드와 답글칸 둘 다**(F-500 3.1 `comment-reply` 도 `mentions` 를 가진다)
- 자리 표시: 새 댓글 입력 카드 — 소스가 있으면 `댓글을 입력하세요. @로 사람을 멘션할 수 있습니다.`, 없으면 `댓글을 입력하세요.`(F-500 5.1). 답글칸은 늘 `답글을 입력하세요.`
- 카드 본문의 `@이메일` 은 평문 그대로 보인다(F-500 1.2 — 댓글 본문 렌더링 없음). 강조하지 않는다

### 5.2 후보 불러오기

- **처음 `@` 토큰이 생길 때** `people.get(docId)` 을 부른다(Q1). 같은 문서는 5분 캐시, 진행 중 요청 공유(3.2). 문서를 바꾸면 다른 캐시 칸이다
- 불러오는 동안 목록에 `불러오는 중…` 한 줄. 끝나면 거른 후보로 바꾼다
- **실패**(오프라인·401·404·409·5xx·모양 틀림): 목록을 닫고 그 토큰에서는 다시 열지 않는다 — 후보 없이 평문 `@`(F-500 4.9). 다음 새 토큰(`@` 를 새로 침)에서 다시 부른다
- 요청 수 판정: 한 문서에서 5분 안에 `@` 를 몇 번 쳐도 `GET /people` 은 1번(E16)

### 5.3 토큰과 후보 목록

- 입력칸 값이나 캐럿이 바뀔 때마다(`input`·`select`, 조합 중은 5.6) `mentionTokenAt(값, 캐럿)` 으로 토큰을 찾는다. 토큰이 없으면 목록을 닫는다. 선택이 범위(시작 ≠ 끝)면 토큰이 없는 것으로 본다
- 토큰이 있으면 목록을 연다 — 내용은 위에서부터 처음 맞는 것:
  1. `mentionLimitReached(값, picked)` → `멘션은 한 댓글에 10명까지 할 수 있습니다.`(옵션 없음)
  2. 불러오는 중 → `불러오는 중…`
  3. 나를 뺀 사람이 0명 → `이 문서에 접근할 수 있는 다른 사람이 없습니다.`
  4. `filterMentionCandidates` 결과 0개 → `맞는 사람이 없습니다.`(F-500 5.1)
  5. 그 밖 → 후보(최대 8), 첫 후보가 강조(`aria-selected="true"`)
- 목록 자리: 입력칸 **바로 아래, 카드 안**(떠 있는 팝업이 아니다). 이유: 레일 카드 영역은 `overflow: hidden` 이고 카드는 `transform` 으로 움직인다(F-505 5.2·5.3) — 떠 있는 목록은 잘리거나 따로 놀고, 카드 안에 두면 F-505 의 카드 높이 다시 재기가 그대로 다른 카드를 비킨다. 판(좁은 창)에서도 같다
- 후보 한 줄: 이메일만(역할은 보이지 않는다 — F-500 5.1 에 역할 문구가 없다)
- 입력칸 접근성: `aria-autocomplete="list"`, `aria-controls` = 목록 id, `aria-expanded` = 목록 열림, `aria-activedescendant` = 강조한 후보 id. 목록이 닫히면 앞의 셋을 뺀다(`aria-expanded="false"`)

### 5.4 고르기와 `mentions` 확정

- 고르기: 강조한 후보에서 `Enter`·`Tab`, 또는 후보 누르기(후보의 `mousedown` 은 기본 동작을 막아 입력칸 포커스를 지킨다). `applyMentionPick` 으로 값·캐럿을 바꾸고, 그 이메일을 `picked` 에 더하고, 목록을 닫는다
- 보낼 때: `mentions = finalizeMentions(본문, picked)` — **고른 이메일 중 본문에 `@이메일` 이 남은 것만**, 앞에서부터 최대 10개(F-500 4.9). 손으로 친 `@이메일` 은 고르지 않았으므로 멘션이 아니다(알림 없음). 고른 뒤 그 글자를 지우면 빠진다
- 서버는 받은 `mentions` 를 다시 걸러 접근 집합 밖을 조용히 뺀다(F-500 3.6). 화면은 그 결과를 알리지 않는다
- 오프라인에서 고른 멘션은 edit 이상이면 `Y.Map` 에 그대로 들어가고, 다시 붙어 DO 스냅숏이 돌 때 알림이 생긴다(F-500 3.5). view 는 연결돼 있을 때만 보낸다(F-506)

### 5.5 키보드 — 목록이 먼저

목록이 열려 있을 때 입력칸의 키(조합 중이 아닐 때):

| 키 | 옵션이 있을 때 | 옵션 없음(문구 줄만) |
| --- | --- | --- |
| `↓` / `↑` | 다음·이전 후보로 강조(끝에서 처음으로), `preventDefault` | 입력칸 기본 동작 |
| `Enter` / `Tab` | 강조한 후보 고르기, `preventDefault` | 입력칸 기본(줄바꿈 / 포커스 이동) |
| `Esc` | 목록 닫기, `preventDefault` + `stopPropagation` — **입력 카드 취소(F-505 7.1 7번)로 가지 않는다** | 같음 |
| `Ctrl+Enter` | 목록을 닫고 부모 처리기로(보내기) | 같음 |
| 그 밖 | 부모 처리기로 | 같음 |

- `Esc` 로 닫은 목록은 **같은 토큰**(같은 `start`)에서는 다시 열리지 않는다. 캐럿이 토큰을 벗어났다 돌아오거나 새 `@` 를 치면 다시 열린다. 목록이 닫힌 상태의 `Esc` 는 F-505 대로(입력 카드는 취소, 답글칸은 비우고 카드로)
- 입력칸에서 포커스가 나가면 목록을 닫는다
- F-505 의 `onKeyDown`(Ctrl+Enter·Esc)은 목록이 먹지 않은 키만 받는다(3.5)

### 5.6 IME 조합 중

- 조합 중(`compositionstart` ~ `compositionend`, 또는 `e.nativeEvent.isComposing`)에는 **목록이 키를 먹지 않고 토큰도 다시 찾지 않는다** — 조합 확정 `Enter` 가 후보 고르기로 오인되지 않게. 목록은 조합 전 모양 그대로 둔다
- `compositionend` 에서 한 번 토큰을 다시 찾는다(미룬 재계산을 조합 끝에 따라잡는다 — CLAUDE.md 불변조건과 같은 규칙). 한글은 토큰 글자가 아니므로 `@` 뒤에 한글을 확정하면 토큰이 끝나 목록이 닫힌다
- 이 입력칸은 `textarea` 라 편집기 조합·원격 갱신 게이트(F-500 4.2)와 무관하다. 실제 한글 IME 판정은 H5

### 5.7 한도

- 댓글 하나(입력 카드 하나·답글 하나)에서 `mentionLimitReached` 가 참이면 목록은 5.3 의 1번 문구만 보이고 고를 수 없다. `@` 를 더 쳐도 글자로 남는다
- 서버·F-501 검사도 10개를 넘는 `mentions` 를 거절한다(`too_many_mentions`) — `finalizeMentions` 가 10개에서 자르므로 정직한 화면은 걸리지 않는다(r1)

## 14. 열린 질문 — 모두 기본값 있음

### Q1. 멘션 후보를 언제 불러오나 — **기본값: 그 문서에서 처음 `@` 를 칠 때, 5분 캐시**

- F-500 4.9 는 "문서를 열 때 한 번" 이다. 요청 하나가 D1 질의 최대 9번(F-503 6.2)인데 댓글을 달지 않고 여닫는 문서가 대부분이라, 여는 때마다 부르면 쓰지 않을 요청이 대부분이다
- 대가: 처음 `@` 뒤 한 번 `불러오는 중…` 이 보인다(보통 요청 하나 시간)
- **다른 안(문서를 열 때)을 고르면**: 5.2 첫 불릿과 3.2 캐시 규칙이 "문서가 열리고 멘션 소스가 생길 때 `get`" 으로 바뀌고 E16 이 "문서 열기 1번" 이 된다. 코드 차이는 부르는 자리 하나다

### Q2. 파일 목록이 개요와 다름 — **기본값: 1장 표대로**

- 더한 것: `mentionCandidates.ts`(+test) — 토큰·거르기·고르기를 node 에서 판정하려고(F-278 과 같은 이유). `useNotifications.ts` — 폴링은 알림함이 닫혀 있어도 돌아야 하고, 팝오버 컴포넌트와 떼야 팔레트가 열 수 있다. `MentionField.tsx` — 개요 행에는 `CommentComposer.tsx` 만 있지만 답글도 `mentions` 를 가진다(F-500 3.1 `comment-reply`) — 두 입력칸이 같은 컴포넌트를 쓴다. `CommentThread.tsx` — 답글칸 자리. `useDocComments.ts`·`CommentRail.tsx` — `mentions` 를 쓰기 수단까지 나르는 한 곳(F-505 3.2 가 "F-505 는 늘 `mentions: []`" 라 했다). `icons.tsx`·`paletteContract.ts`·`paletteCommands.ts`(+test) — 개요 5.2 의 `notifications.open`(개요 7장이 `paletteCommands.test.ts` 를 "F-505·F-507" 로 이미 적었다). `helpDoc.ts`(+test) — F-505 10장이 "멘션·알림 문장은 F-507 이 더한다" 고 넘겼다. `app.css`
- 다른 안: 답글칸 멘션을 빼면 `CommentThread.tsx`·`MentionField.tsx` 가 빠지고 입력 카드에만 목록을 둔다 — 답글로 사람을 부를 수 없게 된다

### Q3. 막힌 계정의 읽음 처리 — **기본값: 요청하지 않고, `모두 읽음` 을 숨긴다**

- 서버가 403 `account_blocked` 로 막으므로(F-503 8.3) 보내 봐야 되돌아온다. 보내지 않으면 쓸모없는 요청과 깜빡임이 없다
- 다른 안: 이 페이지 동안만 화면에서 읽음으로 두기(서버에 없는 상태를 들고 있음) — 다음 새로고침에서 다시 안 읽음이 된다. 상태가 하나 더 는다

### Q4. 탭 여럿의 폴링 — **기본값: 탭마다 따로(보이는 탭만)**

- 보이지 않는 탭은 `interval` 을 건너뛰므로 보통 탭 하나만 가져온다
- 다른 안: `BroadcastChannel` 로 한 탭만 가져오고 나머지에 나누기 — 지도자 뽑기 규칙이 새로 든다. `tabSync`(F-296)의 편집권 채널과 섞이지 않게 새 채널이 필요하다. 9장 H7 결과가 크면 그때 다시 본다

### Q5. 항목 문구 안 제목 자르기 40자 — **기본값: 40 코드 포인트, 넘으면 39 + `…`**

- 다른 안: 자르지 않고 CSS 줄 수 제한만 — U5 의 자르기 줄이 빠진다
