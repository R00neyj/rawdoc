# F-2112 설정에서 기본 뷰

작성일: 2026-10-01
상태: 승인(2026-10-01) — 열린 질문이 없어 "갈림길 없으면 바로 구현" 상시 지시(2026-09-21)로 승인함. 사용자 원문 "설정에서 기본 뷰 설정할 수 있도록"(2026-10-01). 아래 "정해진 것" 은 사용자가 이미 정했고, 남은 갈림길이 없어 열린 질문 없음
구현 담당: `feature-implementer`

## 정해진 것 (바꾸지 않는다)

1. `설정 > 화면` 탭 `시작 화면` 바로 아래에 Segment `기본 뷰` — `기억`(기본) · `편집` · `원문` · `보기`
2. `기억` = 지금 동작(마지막에 쓴 모드로 열림). 나머지 셋은 **부팅(새로고침·재실행) 때만** 그 모드로 시작한다. 문서를 옮기거나 열 때는 쓰던 모드를 유지한다
3. 새 키 `md.defaultView`, 기기(브라우저 프로필)별 한 키. 폰/PC 분리 없음. `md.viewMode` 는 지금처럼 `changeViewMode` 가 "마지막 모드" 로 계속 기록한다 — 고정 모드일 때도
4. 설정을 바꿔도 지금 화면의 모드는 바꾸지 않는다(F-232 3.4 `시작 화면` 과 같은 규칙)
5. `보기` 에서 `새 문서` 를 누르면 편집으로 바꾸는 규칙(F-123 3.3, `useDocNavigation.ts` 의 `if (viewMode === 'view') changeViewMode('live')`)은 그대로
6. 공개 보기(`PublicView`)에는 항목을 주지 않는다 — `시작 화면` 과 같은 옵셔널 prop 처리
7. 새 의존성·새 화면·새 명령·새 단축키 없음. 팔레트(F-2054)에 노출하지 않는다 — F-2054 의 모드 토글 셋은 `changeViewMode` 를 그대로 쓰므로 `md.viewMode` 기록 규칙에 자동으로 맞는다

## 근거 (직접 읽은 것, HEAD `d38babb`)

- 부팅 초기값은 `App.tsx` 의 `useState(() => getPref('md.viewMode', 'live'))` 한 곳(166행 부근). **저장값을 검사하지 않는다** — 모르는 문자열이 그대로 `viewMode` 가 된다. 이 명세에서 같이 막는다(2.1)
- `md.viewMode` 를 쓰는 곳은 `changeViewMode`(`setPref('md.viewMode', v)`) 하나. 읽는 곳은 위 초기값과 `e2e/viewFind.spec.js` 뿐(`grep md.viewMode src e2e tests`)
- `bootPaint.ts`(`BOOT_PAINT_SCRIPT`)는 `md.viewMode` 를 읽지 않는다 — 읽는 키는 `md.theme`·`md.sidebar`·`md.sidebarWidth`·`md.startScreen`·`md.contentWidth`·`md.userCssBoot`·`md.account`. 부팅 골격은 모드와 무관하므로 **`bootPaint.ts` 변경 없음**
- **탭 간 동기화(F-296) 대상 아님.** `tabSync.ts` 의 `TabMessage` 는 `docs-changed`·`claim-*`·`e2ee-lock` 뿐이고, `storage` 이벤트를 듣는 곳은 사용자 CSS(`useUserCss.ts`·`UserCssTab.tsx`) 둘뿐이다. `md.viewMode`·`md.startScreen` 등 다른 설정과 같이, 다른 탭에는 다음 부팅부터 적용된다. 열려 있는 다른 탭의 설정 대화상자는 새로고침 전까지 옛 값을 보인다 — 모든 설정 키가 같다
- 보기 모드의 화면 문구는 `ViewModeMenu.tsx` `VIEW_MODES` 의 `label` 앞부분(`편집`·`원문`·`보기`)과 같다
- 다른 진행 중 명세(F-2092 사용자 CSS, F-3001 푸시)는 `SettingsDialog.tsx` 의 `css`·`account` 탭과 `settingsTabs.ts` 를 건드린다. 이 명세는 `screen` 탭의 Segment 하나와 props 두 개만 더해 겹치는 블록이 없다. `settingsTabs.ts` 는 고치지 않는다(`screen` 탭은 이미 항상 보인다)

## 2. 동작

### 2.1 `src/app/defaultView.ts` (계약)

```ts
import type { ViewMode } from './ViewModeMenu'
export type DefaultView = 'remember' | ViewMode
export const DEFAULT_VIEW_OPTIONS: readonly { value: DefaultView; label: string }[]
  // [{ remember, '기억' }, { live, '편집' }, { raw, '원문' }, { view, '보기' }] — 이 순서
export function resolveDefaultView(stored: string): DefaultView
export function resolveInitialViewMode(defaultView: string, lastViewMode: string): ViewMode
export function readInitialViewMode(): ViewMode
```

- `resolveDefaultView`: 네 값 중 하나면 그대로, 아니면(빈 문자열·모르는 문자열·대소문자 다름) `'remember'`
- `resolveInitialViewMode`: `resolveDefaultView(defaultView)` 가 `'remember'` 가 아니면 그 값. `'remember'` 면 `lastViewMode` 가 `live`·`raw`·`view` 중 하나일 때 그 값, 아니면 `'live'`
- `readInitialViewMode`: `getPref('md.defaultView', 'remember')` 와 `getPref('md.viewMode', 'live')` 를 읽어 위 함수에 넘긴다. App.tsx 초기값은 `useState(readInitialViewMode)` 형태가 된다
- 이유: 판정을 순수 함수로 떼어 노드 환경 단위 테스트로만 덮는다. 저장값 검증을 여기 한 곳에 둔다

### 2.2 `useAppearancePrefs.ts`

- 상태 `defaultViewPref`(초기값 `resolveDefaultView(getPref('md.defaultView', 'remember'))`)와 `changeDefaultView(value: string)` — `startScreenPref`·`changeStartScreen` 과 같은 모양. `changeDefaultView` 는 상태와 `setPref('md.defaultView', v)` 만 바꾼다. **`viewMode`·`md.viewMode`·`editorRef` 를 건드리지 않는다**(정해진 것 4)
- `UseAppearancePrefsResult` 에 `defaultViewPref: DefaultView`, `changeDefaultView: (value: string) => void`

### 2.3 `SettingsDialog.tsx`

- props: `defaultView?: string`, `onChangeDefaultView?: (value: string) => void` — 둘 다 있을 때만 그린다(`시작 화면` 과 같은 조건식). `PublicView` 의 `SettingsDialog` 호출은 손대지 않으므로 거기서는 안 보인다
- 자리: `시작 화면` Segment 바로 뒤, `위키링크 미리보기` 앞
- `<Segment labelId="default-view-label" label="기본 뷰" options={DEFAULT_VIEW_OPTIONS} …>` — 접근성은 기존 `Segment` 그대로(`radiogroup` 의 `aria-labelledby`, 각 버튼 `role="radio"`·`aria-checked`). 새 aria 문구 없음

| 상황 | 결과 |
| --- | --- |
| 키 없음(기존 사용자 전부) | `기억` 이 선택돼 보이고 동작은 지금과 같다 |
| `편집`/`원문`/`보기` 로 부팅 | 그 모드로 시작. `md.viewMode` 는 바꾸지 않는다(사용자가 모드를 바꿀 때만 기록) |
| 고정 모드로 부팅한 뒤 상단바·팔레트로 모드 변경 | 지금처럼 바뀌고 `md.viewMode` 에 기록. 다음 부팅은 다시 고정 모드 |
| `기억` 으로 되돌림 | 다음 부팅에 `md.viewMode`(마지막으로 사용자가 고른 모드)로 시작 |
| 저장값이 모르는 문자열 | `기억` 으로 다룬다. Segment 도 `기억` 에 체크. 저장값을 고쳐 쓰지는 않는다 |
| 홈(`시작 화면 = 홈`)으로 부팅 | 모드 상태만 정해지고, 문서를 열면 그 모드로 열린다 |
| 오프라인·금고 잠김·공유 문서 | 지금 `md.viewMode = view` 로 부팅할 때와 같은 경로. 새 분기 없음 |

## 5. E1 시나리오

`openApp` 은 `.cm-host .cm-editor` 가 보일 때까지 기다리므로 **보기로 시작하는 상태를 `openApp` 이나 `setPrefBeforeLoad` 로 세우지 않는다.** `setPrefBeforeLoad` 는 `addInitScript` 라 새로고침마다 다시 심겨 테스트 중 바꾼 값을 덮는다(F-160 2.7 의 `--mode view` 실패와 같은 원인). 대신 편집으로 연 뒤 설정 UI 로 바꾸고 `page.reload()` 한다(선례 `e2e/viewFind.spec.js` 의 `localStorage.setItem('md.viewMode','view')` → `reload` → `.viewer .markdown-body` 대기).

1. `openApp(page)` → `importMarkdown(page, { content: '본문 한 줄\n' })` (`openApp` 이 심은 `md.startScreen='last'` 가 새로고침 뒤에도 이 문서를 연다)
2. `설정` → 화면 탭 → `radiogroup` `기본 뷰` 의 `보기` 클릭. 즉시 확인: `localStorage['md.defaultView'] === 'view'`, `.content-area--doc` 의 `data-view-mode` 는 여전히 `live`. `닫기`
3. `setViewMode(page, 'raw')` → `md.viewMode === 'raw'`
4. `page.reload()` → `.viewer .markdown-body` 가 `본문 한 줄` 을 담을 때까지 대기. `data-view-mode="view"`, `.editor-slot` 숨김, `md.viewMode` 는 여전히 `raw`
5. `설정` → `기본 뷰` 의 `보기` 가 `aria-checked="true"` → `기억` 클릭 → `닫기`. `data-view-mode` 는 여전히 `view`
6. `page.reload()` → `.cm-host .cm-editor` 보임, `data-view-mode="raw"`

e2e 는 이 하나뿐이다. 판정 함수는 U1~U2 단위로만 덮는다.

  `| \`md.defaultView\` | \`remember\` \| \`live\` \| \`raw\` \| \`view\` (화면 문구는 \`기억\` \`편집\` \`원문\` \`보기\`) | \`remember\` | F-2112 |`
  그리고 `md.viewMode` 행의 명세 칸 끝에 `, F-2112(부팅 초기값은 \`md.defaultView\` 가 \`remember\` 일 때만)` 를 덧붙인다
- `specs/ia.md` 3.15 2번 표 `화면` 행: `` `시작 화면`(`홈` / `마지막 문서`), `` 뒤에 `` `기본 뷰`(`기억` / `편집` / `원문` / `보기`, 기본 `기억`. 앱을 열 때만 적용), `` 삽입
- `specs/ia.md` 3.15 항목 이력: `위키링크 미리보기 F-2044` 뒤에 `, 기본 뷰 F-2112`
- `specs/ia.md` 2장 화면 표 상단바 `보기 모드 토글` 행 설명의 "전체 문서 공통 설정" 뒤에 `(앱을 열 때의 모드는 설정 \`기본 뷰\`, F-2112)` 덧붙임

## 9. 열린 질문

없음. 사용자가 정한 것 외의 세부(모르는 저장값은 `기억`, 모르는 `md.viewMode` 는 `편집`, 옵션 위치 `시작 화면` 바로 뒤)는 반대로 갈 이유가 없어 본문에서 정했다.
