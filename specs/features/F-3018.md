## 사용자가 이미 정한 것 (바꾸지 않는다)

- 지금은 무제한. "월 N회(비우면 무제한)"·"기능 끄기" 를 **배포 없이** 바꾼다("쓰기제한 부분은 언제든지 한도 막을수있게 해야함")
- 처음엔 꺼진 채 배포, 하위 명세가 다 나간 뒤 `--on --yes` 로 켠다(F-3013 2장·7장 5번)
- 횟수가 드는 것은 가져오기·당기기·푸시 각 1회(F-3013 Q5). 이 도구는 세는 방식을 바꾸지 않고 보기만 한다

## 2. 명령과 인자

```
node scripts/admin-github.mjs [--on | --off] [--limit N | --unlimited] [--top N] [--yes] [--local [--persist-to 경로]]
```

| 인자 | 뜻 | 규칙 |
| --- | --- | --- |
| (바꾸는 인자 없음) | 보기 — 설정·이번 달 요약·상위 사용자 | `--yes` 를 주면 2(`admin-usage` 와 같음) |
| `--on` / `--off` | `enabled` 를 1 / 0 으로 | 둘 다 주면 2 |
| `--limit N` | `monthly_limit = N` | 정수 **1~1,000,000**. 0·음수·소수·글자는 2. 0 을 받지 않는 이유: 모든 사용을 막는 것은 `--off` 가 맡고, 0 이면 화면 문구 `이번 달 GitHub 사용 0회를 모두 썼습니다` 가 된다 |
| `--unlimited` | `monthly_limit = NULL` | `--limit` 과 함께면 2 |
| `--top N` | 상위 사용자 수 | F-2029 와 같은 1~1,000, 기본 20. **보기에서만** — 바꾸는 인자와 함께면 2 |
| `--yes`·`--local`·`--persist-to`·`--help` | F-2029 6.1·6.2 그대로 | |

- 바꾸는 인자(`--on`·`--off`·`--limit`·`--unlimited`)는 `github` 명령에서만 받는다. 다른 명령이 받으면 지금처럼 `알 수 없는 인자: {인자}` 2
- 켜기와 한도를 한 번에 바꿀 수 있다(`--on --limit 30`) — 한 UPDATE 문장(4장)이라 둘이 따로 반영되는 틈이 없다
- 인자 오류 문구: `--limit 값이 이상합니다: {입력}`, `--on 과 --off 를 함께 쓸 수 없습니다`, `--limit 과 --unlimited 를 함께 쓸 수 없습니다`, `--top 은 보기에서만 씁니다`, `github 보기는 --yes 를 받지 않습니다`
- 사용법 줄: `사용: node scripts/admin-github.mjs [--on|--off] [--limit N|--unlimited] [--top N] [--yes] [--local [--persist-to 경로]]`

## 3. 바꾼 값이 반영되는 때 (결론)

- **Worker: 다음 요청부터.** 설정 행은 요청마다 D1 에서 읽고 캐시가 없다(c1). `worker/` 는 D1 Sessions API(`withSession`)를 쓰지 않아 모든 질의가 주 DB 로 가므로 커밋된 값을 다음 요청이 본다. 끄면 그다음 `file`·`pull`·`push` 등이 503 `github_disabled`, 한도를 낮추면 그다음 횟수 드는 요청이 429 `github_quota`
- **앱 화면: 그 사람의 앱이 `GET /api/github/status` 를 다시 읽을 때.** 언제 다시 읽는지는 F-2128 이 정한다. 그 전에 버튼을 눌러도 서버가 위처럼 거절하므로 막는 효과는 즉시다
- **켜도 꺼진 것으로 보이는 경우**: 비밀 값이 없으면 `status.enabled` 가 false(c2). 이 도구는 Worker 비밀 값을 볼 수 없으므로 `--on` 성공 출력에 이를 한 줄 적는다(5장 N3)
- **F-3017 에 넘기는 조건**: 프록시(F-3013 3.8)는 대응 없는 그림을 GitHub 에서 받기 **전에, Cache API 를 보기 전에** `enabled` 를 확인한다. 그래야 `--off` 뒤 캐시된 GitHub 그림이 새로 나가지 않는다. 이미 브라우저가 받은 사본(`Cache-Control: private, max-age=300`)은 최대 300초 남는다 — 받아들인다

## 4. SQL (계약)

모두 문장 하나, `;` 없음(F-2029 3장). 숫자는 `intLiteral`, 달은 `^\d{4}-\d{2}$` 를 통과한 것만 `'…'` 로. `{m}` = `utcMonth(now)` — `githubMonth` 와 같은 값(UTC `YYYY-MM`). `scripts/` 는 JS 라 `src/lib/githubContract.ts` 를 가져오지 않고 복제한다(F-2029 `utcDay` 와 같은 이유)

| 이름 | 문장 |
| --- | --- |
| `githubSummary(now)` | `SELECT enabled, monthly_limit, updated_at, (SELECT COUNT(*) FROM github_accounts) AS accounts, (SELECT COUNT(*) FROM github_links) AS links, (SELECT COALESCE(SUM(count), 0) FROM github_usage WHERE month = {m}) AS month_total, (SELECT COUNT(*) FROM github_usage WHERE month = {m}) AS month_users FROM github_settings WHERE id = 1` |
| `githubTop(now, top)` | `SELECT users.email, github_usage.count, github_accounts.login FROM github_usage JOIN users ON users.id = github_usage.user_id LEFT JOIN github_accounts ON github_accounts.user_id = github_usage.user_id WHERE github_usage.month = {m} ORDER BY github_usage.count DESC, users.email LIMIT {top}` |
| `githubSet(change, now)` | `UPDATE github_settings SET {바꿀 칸들}, updated_at = {now} WHERE id = 1 AND ({조건}) RETURNING enabled, monthly_limit, updated_at` |

- `githubSet` 의 `change` = `{ enabled?: 0 | 1, limit?: number | null }`. **준 칸만** `SET` 에 넣고(`enabled = 1`, `monthly_limit = 30`, `monthly_limit = NULL`), 조건은 준 칸마다 `{칸} IS NOT {값}` 을 `OR` 로 잇는다. 예: `--on --unlimited` → `SET enabled = 1, monthly_limit = NULL, updated_at = … WHERE id = 1 AND (enabled IS NOT 1 OR monthly_limit IS NOT NULL)`
- 준 칸만 쓰는 이유: `--on` 만 줬는데 읽은 한도를 같이 써 넣으면, 읽기와 쓰기 사이 다른 운영자가 바꾼 한도를 되돌린다
- `IS NOT` 조건은 F-2029 5.2 와 같은 역할 — 이미 그 값이면 바꾸지 않고 `updated_at` 도 그대로 둔다. 결과 `[]` 는 흐름이 "그 사이 바뀜" 으로 읽는다(5장)
- 행 비용: `githubSummary` 는 `github_accounts`·`github_links` 를 세고 `github_usage` 를 두 번 훑는다. `githubTop` 은 `github_usage` 한 번 + 행마다 색인 두 번(c4). 운영자가 손으로 돌리는 도구라 따로 줄이지 않는다
- 이메일은 결과에서만 나오고 SQL 에 들어가지 않는다 — 이 명세에는 사용자 입력 문자열이 SQL 에 들어가는 자리가 없다

## 5. 흐름과 출력

공통 규칙(첫 줄 대상 DB, 읽기 먼저, `--yes` 없으면 SQL 과 M3 를 보이고 0, 대화형 질문 없음, 종료 코드 0·1·2)은 F-2029 6.1·7장 그대로. 종료 코드 3(계정 없음)은 이 명령에 없다

**보기** (`node scripts/admin-github.mjs`) — 호출 둘: `githubSummary` → `githubTop`

```
대상: 원격 D1 md-editor-db
GitHub 기능: 꺼짐 · 월 한도: 무제한 · 마지막 변경: -
이번 달(UTC 2026-10): 14회 · 2명 · 연결 계정 1 · 연결 문서 0
이번 달 많이 쓴 순 20명
이메일  이번 달  GitHub
b@example.com  9  -
a@example.com  5  alice
```

- 설정 줄 문구(계약): `GitHub 기능: {켜짐|꺼짐} · 월 한도: {무제한|{N}회} · 마지막 변경: {시각|-}`. `updated_at` 0(씨앗 행)은 `-`, 그 밖은 F-2029 의 `isoMinute`
- 요약 줄(계약): `이번 달(UTC {YYYY-MM}): {month_total}회 · {month_users}명 · 연결 계정 {accounts} · 연결 문서 {links}`
- 표 머리글 `이메일`·`이번 달`·`GitHub` 는 계약, 폭은 구현 재량(F-2029 8.2 와 같음). `GitHub` 칸은 연결 계정의 `login`, 연결을 끊었으면 `-`
- 이번 달 행이 없으면 머리글 아래 `이번 달 사용 기록이 없습니다.`
- **이메일·GitHub 로그인을 가리지 않는다** — F-2029 8.3 그대로(출력은 돌린 운영자의 터미널에만, 그 사람은 D1 을 이미 본다, 가리면 `admin-block` 으로 이어 갈 수 없다). 로그인은 GitHub 쪽 남용 신고·확인에 쓴다
- `githubSummary` 가 `[]`(설정 행 없음)이면 `설정 행이 없습니다. migrations/0023_github.sql 이 적용됐는지 확인하세요.` 종료 1. 표는 읽지 않는다

**바꾸기** (`--on`·`--off`·`--limit`·`--unlimited` 중 하나 이상) — `githubSummary` 를 읽어 설정 줄을 보인 뒤

| # | 경우 | 출력 | 코드 |
| --- | --- | --- | --- |
| N1 | 준 칸이 모두 이미 그 값 | `이미 그 설정입니다.` — 쓰기 SQL 을 만들지 않는다 | 0 |
| N2 | `--yes` 없음 | `바꿀 것: {칸별 "전 → 후" 를 · 로}` (예 `꺼짐 → 켜짐 · 무제한 → 월 30회`), `SQL: {githubSet}`, M3 | 0 |
| N3 | `--yes`, 결과 한 행 | `바꿨습니다: GitHub 기능 {켜짐\|꺼짐} · 월 한도 {무제한\|{N}회} ({시각})` 다음 줄 `Worker 는 다음 요청부터 이 값을 씁니다. 앱 화면은 GitHub 상태를 다시 읽을 때 바뀝니다.` 켜짐이 된 경우 한 줄 더 `GITHUB_APP_CLIENT_ID·GITHUB_APP_SLUG·GITHUB_APP_CLIENT_SECRET·GITHUB_TOKEN_KEY 가 없으면 켜도 앱에는 꺼진 것으로 보입니다 (F-3014 3장).` | 0 |
| N4 | `--yes`, 결과 `[]` | M13 `그 사이 상태가 바뀌었습니다. 다시 실행해 지금 상태를 보세요.` | 1 |
| N5 | 설정 행 없음 | 보기와 같은 문구 | 1 |

- 한도를 낮춰 이번 달 이미 넘긴 사람이 있어도 막지 않고 그대로 바꾼다 — 그 사람은 다음 횟수 드는 요청부터 429. 누가 넘겼는지는 보기 표로 본다

**`admin-usage` 한 줄** — 기존 `사용자 … 주의 {n}` 줄 바로 뒤, `githubSummary` 호출 하나를 더해:
`GitHub: {켜짐|꺼짐} · 월 한도 {무제한|{N}회} · 이번 달 {month_total}회 · {month_users}명`

- 이 호출이 실패하거나 `[]` 면 그 자리에 `GitHub: 읽지 못했습니다 ({D1 오류 글 또는 "설정 행 없음"})` 를 적고 **나머지는 계속, 종료 코드는 바꾸지 않는다.** 이유: 원격에 `0023` 이 적용되기 전에도 `admin-usage`(F-2029 차단 운영의 기본 도구)가 돌아야 한다. `admin-github` 쪽은 GitHub 전용이라 실패를 1 로 낸다
- `admin-usage` 호출 수: 2 → 3 (wrangler 한 번에 약 1.1초, F-2029 측정 c)

## 9. 열린 질문

### Q1. `admin-usage` 의 GitHub 줄이 실패할 때 — **기본값: 그 줄만 `읽지 못했습니다` 로, 종료 코드 그대로**
- 이유: 원격 `0023` 적용 전이나 GitHub 표 문제로 차단 운영 도구 전체가 멈추면 안 된다
- 다른 안(실패를 1 로): 문제를 놓치지 않지만 `0023` 전에는 `admin-usage` 가 늘 1 로 끝난다. G9 의 기대가 1 로, 5장 마지막 문단이 바뀐다

### 기본값으로 정한 것 (승인 시 확정)
1. `--limit` 은 1~1,000,000, 0 은 받지 않는다(모두 막기는 `--off`) — 2장
2. 한 번에 켜기·한도를 같이 바꾼다, 준 칸만 쓴다 — 4장
3. 설정 캐시 없음 → 다음 요청부터 반영. 화면은 status 다시 읽을 때 — 3장
4. 이메일·GitHub 로그인 가리지 않음 — 5장, F-2029 8.3
5. 보기에 `--top` (기본 20), 바꾸기와 함께면 2 — 2장

### 가정으로 남긴 것 (확인하지 않았다)
- 원격 D1 에 `0023` 이 이미 적용됐는지 — 조회하지 않았다. 적용 전이면 `admin-github` 는 1, `admin-usage` 는 Q1 대로 한 줄만 실패
- 원격 D1 이 `UPDATE … RETURNING`·`LEFT JOIN`·`IS NOT` 을 로컬·`node:sqlite` 와 같게 받는다(F-2029 가정과 같음)
- `withSession` 없는 D1 질의는 읽기 복제본이 아니라 주 DB 로 간다 — Cloudflare 문서 기억에 기댄 것이고 이번에 문서를 다시 받지 않았다. 코드에 `withSession` 이 없다는 것만 `grep` 으로 봤다
