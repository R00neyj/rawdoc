# F-3032 MCP 지우기 도구 둘 (휴지통으로)

작성일: 2026-10-16
상태: 승인 2026-10-16(사용자 "ㄱㄱ" — F-4008·F-3021 개요와 흐름 그림 `specs/wireframes/remote-mcp-flow.html`·`trash-flow.html` 을 함께 승인). F-4008 6장의 마지막 도구 단위: `delete_document`·`delete_folder` 가 F-3023 `trashDoc`·`trashFolder` 를 부른다. 배포는 휴지통(F-3023·F-2145) 배포 뒤, F-3031 뒤. 구현 담당 `feature-implementer`. 전부 node 단위, e2e 없음(OAuth 연결은 브라우저 e2e 로 재현하지 않는다 — F-4008 A5 는 사람)

## 근거 (2026-10-16, 이름으로 찾는다)
- `worker/v1.ts` `handleDeleteDocV1`·`handleDeleteFolderV1` 의 판정이 F-3023 에서 `trashDoc`·`trashFolder` 안으로 들어간다. 확인(Spec3023): 관문은 안에서 부르지 않고, 성공하면 자기 batch 에 `dayUsageStatement` +1. `allowE2ee: false` 면 문서 `not_found → e2ee_doc → forbidden`(F-2050 3.2), 폴더는 없음·남의 것 `not_found`, `folderSubtreeHasE2ee` 참이면 `e2ee_folder` 이고 아무것도 바꾸지 않는다. 이미 휴지통인 문서는 `getDocAccess` `null` → `not_found`(멱등)
- 그래서 이 도구는 `/v1` 안쪽 요청(`innerV1`)을 거치지 않고 두 함수를 직접 부른다 — `/v1` 응답 모양(`V1DeletedDoc`)에는 휴지통 보존 정보가 없고, `by` 를 `'cli'` 가 아닌 앱 이름으로 남겨야 한다(F-3021 결정 7)
- F-3030 계약(Spec3030): `worker/mcp.ts` `createMcpServer(call)` 이 도구 등록 함수를 차례로 부른다. `McpCall = { request, env, ctx, caller: { user, clientId, clientName } }`(`worker/mcpCall.ts`), 결과 `toolResult(data)`·`toolError(message, data?)`, 금고 문구 `VAULT_DOC_MESSAGE`. F-3031 계약(Spec3031): `worker/mcpWriteGate.ts` `gateMcpWrite(call: McpCall): Promise<CallToolResult | null>`, 도구 순서는 SDK 입력 검사 → 관문 → 본체. 오류 문구 상수는 공유하지 않는다 — 3장 문장은 이 파일의 지역 문자열

## 2. 도구 (계약 — 모델이 읽는 글은 영어, F-4008 Q2)
| 이름 | `title` | 입력(zod) | 주석 readOnly/destructive/openWorld |
| --- | --- | --- | --- |
| `delete_document` | `Move document to trash` | `{ id: z.string() }` | `false`/`true`/`false` |
| `delete_folder` | `Delete folder` | `{ id: z.string() }` | `false`/`true`/`false` |

`description`(글자 그대로 계약):
- `delete_document`: `Moves one of your documents to the trash. It disappears from lists, search and shared links at once, and is permanently deleted after 30 days unless the user restores it from the trash in the app. Only the owner can do this. Vault (end-to-end encrypted) documents cannot be deleted through this connection.`
- `delete_folder`: `Deletes one of your folders together with its subfolders and moves every document inside to the trash. Documents can be restored from the trash in the app for 30 days; a restored document goes back to the top level if its folder no longer exists. Shares and links on the folder are removed and do not come back. Fails without changing anything if any vault (end-to-end encrypted) item is inside.`
- `30` 은 `src/lib/trash.ts` `TRASH_RETENTION_DAYS` 로 문자열을 만든다(숫자를 두 곳에 쓰지 않는다). `id` 설명: `Document id from search, fetch or list_documents.` / `Folder id from list_folders.`
- 폴더 `contents` 는 받지 않는다 — 늘 F-3021 3장 `delete-all` 뜻(F-4008 3장 `{id}`). 안의 것을 위로 올리는 `move-up` 은 모델에게 주지 않는다: 폴더 행만 사라지고 문서는 남아 "지웠다"는 결과와 어긋난다

## 3. 처리 순서 (두 도구 같음)
1. `gateMcpWrite(call)` — 결과가 있으면 그대로 돌려준다(429 `/limits` 링크·403 `account_blocked`, F-3031). 읽기 도구와 달리 관문을 지난다(F-4008 A8). 분당 바인딩은 실패할 지우기도 한 번 센다 — `/v1` 과 같다
2. `trashDoc` / `trashFolder(call.env, call.ctx, call.caller.user, id, { by: trashActorForMcp(call.caller.clientName), allowE2ee: false })`
3. 결과 → 도구 결과:

| 결과 | 도구 결과 |
| --- | --- |
| 문서 `ok` | `toolResult({ id, title, trashed: true, retentionDays: TRASH_RETENTION_DAYS })` |
| 폴더 `ok` | `toolResult({ id, parentId, trashedDocuments: docs, deletedFolders: folders, retentionDays: TRASH_RETENTION_DAYS })` |
| `not_found` | `toolError('No document with id {id}.' / 'No folder with id {id}.', { error: 'not_found' })` |
| `forbidden` | `toolError('Only the owner can move this document to the trash.', { error: 'forbidden' })` |
| `e2ee_doc` | `toolError(VAULT_DOC_MESSAGE, { error: 'e2ee_doc' })` |
| `e2ee_folder` | `toolError('Folders that contain vault (end-to-end encrypted) items cannot be deleted through this connection.', { error: 'e2ee_folder' })` |

- `clientName` 은 F-4011 이 토큰에서 꺼낸 DCR `client_name` 그대로. 빈 값이면 `trashActorForMcp` 결과 `mcp:` 를 F-2145 가 `연결된 앱에서 지움` 으로 보인다 — 이 명세가 따로 채우지 않는다
- 방 닫기: `trashDoc`·`trashFolder` 가 `call.ctx.waitUntil` 로 `closeTrashed` 를 건다(F-3021 5장). 폴더의 21번째 이후 방은 다음 D1 확인 때 닫힌다(F-3021 Q1, 사용자 승인) — 이 도구가 더 하지 않는다
- 두 콜백은 F-3030 `safeTool(cb)` 로 감싼다 — 예외(D1 실패 등)는 그쪽이 `Internal error. Try again later.` 로 바꾼다. `toolError` 결과는 `{ message, ...data }` 라 표의 `error` 는 코드로 남는다
- `MCP_INSTRUCTIONS` 끝에 더할 문장(계약): `Deleting moves documents to the trash, where the user can restore them in the app for 30 days; deleting a folder also removes its subfolders and folder shares. Ask the user before deleting.` — 30 은 `TRASH_RETENTION_DAYS`
