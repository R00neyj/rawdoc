## 2. 결정 요약

1. **합치기 편집기**: 문서 = 지금 본문(LF), `original` = 원격 본문(LF) — F-3013 4.3 그대로. `diffConfig` 는 Q1(줄 단위 `override`)
2. **적용 트랜잭션은 덩어리별 changes 하나**. 전체 교체는 쓰지 않는다 — Yjs 에서 지우고 다시 넣기가 되어 바뀌지 않은 곳의 댓글 앵커(`Y.RelativePosition`)·남의 커서가 모두 떨어진다. changes = `mergeChanges(연 때 본문, 결과)`(3.1) 를 `view.dispatch({ changes, userEvent: 'input.github' })` 한 번
3. **`Ctrl+Z` 한 번**: r4 — `input.github` 는 앞 묶음과 합쳐지지 않고, 트랜잭션 하나 = Yjs transact 하나 = 되돌리기 항목 하나. 뒤 경계: 적용하면 대화상자가 닫혀 초점이 상단바 `GitHub` 버튼으로 간다(`Dialog` 기본) — 편집기에 다시 쓰려면 눌러야 해 선택이 움직이므로 다음 타자는 새 묶음이다
4. **IME**: 주인 편집기는 모달 뒤라 초점이 없어 조합 중일 수 없다(F-303 5.4 "초점 잃은 조합 = 끝남"). 적용을 누를 때 본 편집기나 합치기 편집기가 `view.composing` 이면 아무것도 하지 않는다(버튼으로 초점이 옮겨 가며 조합이 끝나므로 다시 누르면 된다). 다른 사람에게는 원격 갱신이라 기존 게이트 보류 그대로
5. **열기~적용 사이 본문이 바뀌면**: 적용 때 본 편집기 `getText('lf')` 가 연 때 본문과 글자 하나라도 다르면 적용하지 않고, 지금 본문으로 합치기 편집기를 새로 만든다(원격은 다시 받지 않음, 횟수 안 듦, 고른 것은 사라진다) + 대화상자 안 `role="status"` 줄 `그사이 본문이 바뀌어 다시 비교합니다`. 1.18MB 문자열 비교 0.1ms(측정). 다시 만든 결과 원격과 같아지면 4.3 "같음" 길로
6. **게이트에 보류된 원격 갱신**은 편집기 글자에 아직 안 보이므로 5의 비교에 안 잡힌다 — 적용 직후 들어오는 편집과 같게 Yjs 가 합친다. 평소 타자와 같은 경우라 따로 막지 않는다
7. **적용은 `liveStatus === 'live'` 일 때만**(r5). 시작할 때 아니면 대화상자 없이 오류 알림, 적용할 때 아니면 대화상자 안 `role="alert"` 줄. 둘 다 `온라인일 때 당길 수 있습니다`
8. **줄바꿈**: 비교는 LF. 원격이 줄바꿈을 하나라도 가졌고(r6) `섞임`이거나 문서 `lineEnding`(`currentDoc.lineEnding ?? 'crlf'` — 내보내기 `getText` 와 같은 기본, App `getText` 배선) 과 다르면 안내 줄. 문서 `lineEnding` 은 바꾸지 않는다
9. **대화상자 먼저 연다**(Q2): `당기기…` 를 누르면 곧바로 D-20 을 `GitHub에서 받는 중…` 으로 열고, 같은 때 `pull` 요청과 지연 조각 `import()` 를 함께 시작한다

## 3. 순수 계약

### 3.1 `githubMerge.ts` (지연 조각에만 든다)

```ts
export const MERGE_DIFF_CONFIG: DiffConfig            // { override: mergeLineDiff }
export function mergeLineDiff(a: string, b: string): readonly Change[]
export function mergeChanges(base: string, result: string): { from: number; to: number; insert: string }[]
export const MERGE_COLLAPSE = { margin: 3, minSize: 4 }
```

- `mergeLineDiff` 규칙(r2): 같으면 빈 배열. 줄(`\n` 기준)마다 처음 본 순서로 UTF-16 글자 하나를 주고 그 두 글자열을 `diff(…, { timeout: 500 })` 로 비교, 줄 경계를 글자 위치로 되돌린다. 바뀐 묶음이 양쪽 다 1,000자 이하면 그 안을 `diff`(설정 없음)로 다시 쪼갠다. 서로 다른 줄이 65,535개를 넘으면 공통 앞·뒤를 뗀 가운데 하나를 `Change` 하나로. 반환은 라이브러리 `Change` 인스턴스여야 한다(`toChunks` 가 `change.offset` 을 부른다 — 평범한 객체는 던짐, 측정 중 확인)
- `mergeChanges` 는 `mergeLineDiff(base, result)` 를 `{ from: fromA, to: toA, insert: result.slice(fromB, toB) }` 로. 원본 위치 기준이라 CM `changes` 배열에 그대로 넣는다

### 3.2 `githubPull.ts` (본 번들)

```ts
export type PulledText = { text: string; hadBom: boolean; lineEnding: LineEnding; mixed: boolean; hasBreak: boolean } // text 는 LF
export function readPulled(content: string): PulledText | { error: 'not-utf8' | 'unreadable' }
export function lineEndingNote(remote: PulledText, doc: LineEnding): string | null
export function sameNotice(note: string | null): string
export function pullFailureMessage(r: GithubFailure, link: { remoteSha: string | null }): string
export function mergedTooLarge(result: string, doc: LineEnding): boolean
export const PULL_OFFLINE_MESSAGE = '온라인일 때 당길 수 있습니다'
```

- `readPulled`: `decodeGithubContent`(throw → `unreadable`) → `decodeMarkdown`(`not-utf8`) → `toEditorText`. `hasBreak` = 원 글자에 `\r` 또는 `\n` 이 있음
- `lineEndingNote`: `hasBreak` 거짓 → null. 원격 이름 = `mixed` 면 `섞임`, 아니면 `LF`·`CRLF`. `mixed` 가 아니고 문서와 같으면 null. 아니면 `줄바꿈이 다릅니다 (GitHub {원격}, 이 문서 {문서}). 푸시하면 이 문서 형식으로 올라갑니다`
- `sameNotice(null)` = `GitHub 파일과 같습니다`. 아니면 `GitHub 파일과 같습니다. 줄바꿈만 다릅니다 (GitHub {원격}, 이 문서 {문서}). 푸시하면 이 문서 형식으로 올라갑니다`
- `pullFailureMessage`: 404 `github_not_found` 이고 `remoteSha === null` → `GitHub에 아직 파일이 없습니다. 첫 푸시가 만듭니다`. 그 밖 `githubErrorMessage`
- `mergedTooLarge`: `fromEditorText(result, doc)` 의 UTF-8 바이트 > `MAX_CONTENT_BYTES`

## 4. 흐름 — `useGithubPull`

### 4.1 상태
`GithubPullState = null | { docId; phase: 'loading' } | { docId; phase: 'compare'; key: number; base: string; remote: PulledText; sha: string; note: string | null; status: string | null; error: string | null; busy: boolean }` — 대화상자 하나만, 열려 있으면 `startPull` 은 무시

### 4.2 시작 `startPull(docId)` — 주인 + 연결됨 + 그 문서가 지금 문서일 때만 부른다
1. `liveStatus !== 'live'` 또는 편집기 없음 → 오류 알림 `PULL_OFFLINE_MESSAGE`, 끝(요청 0)
2. 상태 `loading` (D-20 열림), `postDocGithubPull(docId)` (횟수 1)
3. 실패 → 닫고 오류 알림 `pullFailureMessage`. `watch` 를 거쳐 `github_disabled`·`github_reconnect` 면 상태 다시 읽기(F-2128 2장 ⑥)
4. `readPulled` 오류 → 닫고 `not-utf8` 은 `GitHub 파일이 UTF-8 텍스트가 아니라 당길 수 없습니다`, `unreadable` 은 `githubErrorMessage({ status: 0 })` 문구
5. 그 사이 지금 문서가 바뀌었으면 닫고 끝(알림 없음)
6. `base = 편집기 getText('lf')`. `base === remote.text` → 4.3 "같음". 아니면 `compare`

### 4.3 같음
대화상자를 닫고 `postDocGithubSynced(docId, { sha, bom: remote.hadBom })` → 204 면 알림 `sameNotice(note)` + 링크 캐시의 `remoteSha`·`remoteBom`·`syncedAt = Date.now()` 를 바꿔 상단바 상태 줄이 곧바로 맞는다. 실패면 오류 알림 `githubErrorMessage`

### 4.4 적용 `onApply({ result, changes })` — 대화상자가 합치기 편집기 본문(LF)과 `mergeChanges(base, result)` 를 넘긴다
순서가 결정이다:
1. 지금 문서가 `docId` 가 아니면 닫고 오류 알림 `문서가 바뀌어 당기기를 멈췄습니다`
2. 2장 7(`'live'` 아님 → alert 줄, 대화상자 유지) → 2장 4(조합 중이면 아무것도 안 함)
3. `mergedTooLarge` → alert 줄 `합친 결과가 너무 큽니다 (최대 1MB)`
4. 2장 5 — 다르면 `base` 를 새로, `key` +1, `status` 줄, 끝
5. `busy` (버튼·Esc·바깥 클릭 막음). `changes` 가 비어 있지 않으면 한 번 dispatch. 그 뒤 편집기 `getText('lf') !== result` 면(읽기 전용이 버렸다, r5) synced 없이 닫고 오류 알림 `적용하지 못했습니다. 잠시 뒤에 다시 해 주세요`
6. `postDocGithubSynced` → 204: 닫고 알림 — 바뀐 것이 있었으면 `GitHub에서 당겨 합쳤습니다`, 없었으면(모두 내 것) `지금 내용을 그대로 두었습니다`. 캐시 갱신은 4.3 과 같다. 실패: 닫고 오류 알림 `합친 내용은 넣었지만 동기화 기록을 남기지 못했습니다. 다시 당겨 주세요`(본문은 이미 들어갔고, 푸시는 F-3015 대로 409 로 막힌다)
- F-2131 이 6의 204 뒤(그리고 4.3 204 뒤)에 그림 받아 넣기를 더한다

`취소`·Esc·바깥 클릭(busy 아닐 때) → 닫기만. synced 없음, 본문 그대로

### 4.5 이미 있는 파일에 연결한 뒤 (F-3013 4.2, F-2128 4.3 "F-2129 가 줄 당기기 열기")
`linkDoc` 이 `existed` 로 성공하면 기존 알림 뒤 `requestPull(docId)`: 그 문서가 지금 문서이고 `'live'` 면 곧바로 `startPull`. 아니면 그 문서를 열고(`selectDoc`) 15초 안에 "지금 문서 = docId 이고 `'live'` 이고 편집기 있음" 이 되는 첫 렌더에서 한 번 시작한다. 그 전에 다른 문서로 가거나 15초가 지나면 버린다(기존 알림 `당기기로 내용을 맞춰 주세요` 가 남아 있다)

- `모두 내 것` = 남은 덩어리 전부 `내 것 유지`, `모두 GitHub 것` = 남은 덩어리 전부 `GitHub 것으로`. 이미 고른 덩어리는 다시 건드리지 않는다(라이브러리 버튼과 같은 뜻 — 되돌리려면 합치기 편집기에서 `Ctrl+Z`)
- 초점: 열 때 `loading` 이면 `취소`, `compare` 가 되면 합치기 편집기 본문. 닫으면 연 자리로(`Dialog` 기본)
- 열 때 원격 1MB 쪽에서 덩어리 계산이 최대 약 0.6초(r2) 동기로 돈다 — 그동안 `GitHub에서 받는 중…` 이 남아 있게, 편집기는 그 문구를 그린 다음 프레임에 만든다

## 6. 팔레트 문구 (조사 바로잡기)

## 12. 열린 질문

### Q1. 덩어리 계산 — **기본값: 줄 단위 `override`(3.1)**
- 이유: r1 — 승인된 `{ timeout: 1000 }` 은 1MB 문서에서 27~30초 동안 화면을 멈춘다(시간 상한이 실제로 묶지 못함). 줄 단위는 같은 입력 62~90ms, 최악(모두 다름) 0.52초. 바뀐 줄 묶음 안은 다시 글자 단위로 쪼개 표시·적용이 줄 전체를 덮지 않는다
- 다른 안 ①: F-3013 원안 `{ timeout: 1000 }` — `githubMerge.ts` 가 거의 빈다. 큰 문서에서 수십 초 멈춤을 받아들이거나 따로 크기 상한(예: 200KB 넘으면 당기기 거부)을 둬야 한다. ②: 라이브러리 기본 `{ scanLimit: 500 }` — 빠르지만 m2 대로 바뀐 범위가 약 16,000자를 넘으면 덩어리 하나라 고르기가 무의미
### Q2. 받는 동안 — **기본값: D-20 을 먼저 `GitHub에서 받는 중…` 으로 연다**
- 이유: 1MB 파일 왕복과 지연 조각 받기가 1~2초 걸릴 수 있다. 메뉴를 누른 뒤 아무것도 안 보이면 다시 누르게 된다. 같음이면 그 대화상자가 잠깐 보였다 닫힌다
- 다른 안: F-3013 원안대로 받는 동안 대화상자 없음 — "같음" 때 깜박임이 없지만 받는 동안 알릴 자리가 없다(알림 줄을 쓰면 끝날 때 지워야 한다)
