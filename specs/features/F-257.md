# F-257 도움말을 읽히는 안내 문서로

작성일: 2026-09-18
상태: 사용자 지시(2026-09-18 "그냥 방법만 나열된게 아니라 기존에 있던 사용법 문서처럼 … 더 친절하게 안내 및 앱에 대한 도움말도 있어야함"). 사용자 승인 후 1~6장 구현 완료 — `ac7ea3b` 로 반영. 7장(첫 실행 안내 문서 합치기)은 미구현으로 남음(2026-09-20 상태 표기 정정)
근거: `specs/features/F-244.md`(도움말 전용 페이지 `#/help`), `F-249.md`(오른쪽 목차), `F-235.md`(문법 목록 원본), `F-111.md` 3.7(`guideDoc.ts` 사용법 문서 — 사용자가 "이 문서처럼" 이라고 가리킨 글)

## 1. 범위

### 지금
`src/app/helpDoc.ts` 는 `GROUPS` 배열(제목·강조·목록·인용·링크·위키링크·표·코드블록·이미지·콜아웃·구분선·프론트매터)을 기계적으로 펼쳐 문서를 만든다. 한 항목 = `### 이름` + 원문 코드펜스 + 렌더 결과 + 캡션 한 줄이고, 그 사이를 잇는 설명이 없다. 제목도 `마크다운 문법` 이라 **앱 사용법은 어디에도 없다**

사용자가 `guideDoc.ts`(첫 실행 안내 `사용법`)를 가리키며 "그 문서처럼" 이라고 했다 — 짧은 산문 + 표 + 실제로 렌더된 예시가 섞인 읽히는 글이다

### 한다
- 도움말을 **앱 사용법 + 마크다운 문법** 두 축으로 다시 쓴다. 제목을 `도움말` 로 바꾼다
- `guideDoc.ts` 의 말투를 따른다: 존댓말, 짧은 문장, 기능 이름은 화면에 보이는 그대로(`` `.md 내보내기` `` 처럼 인라인코드)
- 문법 절은 지금 예시(원문 + 결과)를 살리되, 절마다 무엇에 쓰는지 한두 줄을 앞에 둔다
- 2장의 절 구성을 그대로 따른다

### 하지 않는다
- `#/help` 라우트·목차(F-244·F-249) 구조 변경
- `guideDoc.ts`(첫 실행 안내) 수정 — 역할이 다르다(F-235 "온보딩용으로 역할 분리")
- **없는 기능을 적기.** 각 항목은 코드나 명세로 확인한 것만 쓴다. 확인이 안 되면 그 줄을 빼고 보고에 적는다
- 사용자가 준 예시 글에 섞여 있던 콜아웃(`> [!warning] 파일을 그대로 장기기억으로…`)과 주석 문장 — 그건 사용자가 동작을 확인하려고 넣은 것이지 도움말 내용이 아니다. **콜아웃·주석 문법을 설명하는 예시는 넣되, 그 문장은 쓰지 않는다**
- 스크린샷·이미지 추가

- `## 마크다운 문법` 은 문서 뒤쪽에 둔다 — 앱 사용법을 먼저 읽게 한다
- 자주 쓰는 문법은 `guideDoc.ts` 처럼 **표**로 먼저 요약하고, 그 아래 `###` 상세를 둔다

## 3. 구현

- `GROUPS` → 마크다운을 만드는 지금 함수(`fence`·`renderItem`·`renderGroup`)는 **그대로 쓴다**. 문법 절 안에서만 쓰이게 위치를 옮긴다
- 앱 사용법 절은 템플릿 리터럴로 직접 쓴다(기계 생성 아님)
- `HELP_DOC_TITLE` 을 `도움말` 로. 이 상수를 쓰는 곳(`#/help` 화면 제목·사이드바 항목)이 같이 바뀌는지 확인한다
- 본문에 백틱·파이프가 많다 — 표 안 인라인코드가 깨지지 않는지 렌더 결과로 확인한다

## 7. 첫 실행 안내 문서 합치기 (2026-09-18 사용자 결정)

사용자 질문 "guideDoc 과 helpDoc 둘이 합치면 되는거 아님?" → **합친다.** 선택: "없애고 도움말로"

### 7.1 한다
- **첫 실행 때 `사용법` 문서를 만들지 않는다** — `App.tsx` 의 `boot()` 안 `list.length === 0 && getPref('md.firstRunDone', '') === ''` 분기(F-2014 3.0, `1441262` 기준 785~793행)를 없앤다
- 홈 화면(`EmptyState`)에 도움말로 가는 줄을 둔다: `새 문서`·`가져오기` 버튼 아래 `처음이신가요? 도움말 보기`. 누르면 `#/help` — **`ac7ea3b` 에서 이미 들어갔다**
- 안내 본문은 `helpDoc.ts` 한 곳에만 둔다

### 7.2 `guideDoc.ts` 는 지우지 않는다

`migrateLocal.ts` 29행이 **이미 만들어진 안내 문서를 계정으로 옮기지 않으려고** 제목·본문을 그대로 비교한다:

```ts
const docs = local.docs.filter((d) => !(d.title === GUIDE_DOC_TITLE && d.content === GUIDE_DOC_CONTENT_CRLF))
```

기존 사용자 기기에는 그 문서가 남아 있으므로 상수를 지우면 그 문서가 계정에 쌓인다. 따라서

- `GUIDE_DOC_TITLE`·`GUIDE_DOC_CONTENT`·`GUIDE_DOC_CONTENT_CRLF` 를 **값 그대로** 남긴다. 한 글자도 바꾸지 않는다 — 바꾸면 비교가 어긋나 필터가 깨진다
- 파일 맨 위 주석만 바꾼다: 새로 만들지 않고 `migrateLocal` 비교용으로 남은 과거 본문이라고 적는다
- `App.tsx` 의 `guideDoc` import 는 없앤다. `migrateLocal.ts`·`migrateLocal.test.ts` 의 import 는 그대로 둔다
