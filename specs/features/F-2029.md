## 2. 범위

### 한다

- 개요 4.3 의 다섯 스크립트. 원격 D1 이 기본, `--local` 이면 로컬 D1
- 이메일을 SQL 에 넣는 안전한 방법(5.1), 쓰기 전 확인 절차(`--yes`, 6장), 종료 코드(7장)
- 순수 부분과 실행 부분을 나눠 `node` 환경 단위 테스트로 판정(9장)

### 하지 않는다

- 관리자 화면·API, 자동 차단, 차단·주의 **사유 저장**(개요 5.3) — 사유는 SQL 에도 로그에도 넣지 않는다
- 차단의 **효과**(쓰기 403, 공개 404, `/ws` 4403, `/api/me` `blocked`·`warned`) — F-2028. **F-2028 이 배포되기 전에는 `admin-block`·`admin-warn` 이 열 값만 바꾸고 아무것도 막지 않는다.** 스크립트는 효과를 확인하지 않는다
- 실시간 방(DO)에 알리기 — 이미 열린 연결은 F-2028 의 재검증(최대 60초, 개요 4.2)이 맡는다. 스크립트는 D1 만 고친다
- 전체 계정 목록·막힌 계정 목록 출력 — `admin-usage` 는 막힌·주의 계정 **수**만 보인다(11장 Q4)
- 실행 기록 파일·로그 파일 — 출력은 터미널에만 간다(8.3)
- 원격 적용 자동화(CI·Cron·훅에서 부르기)

## 3. 공용 도우미 `scripts/lib/admin.mjs` — 계약

이름을 바꾸면 9장 테스트와 5장 표가 어긋난다

```js
// 명령 이름
export const COMMANDS = ['usage', 'block', 'unblock', 'warn', 'recount']
export const DB_NAME = 'md-editor-db'          // wrangler.jsonc d1_databases[0].database_name

// 실행기 — d1.mjs 가 실제 것을, 테스트가 가짜를 넘긴다
// sql 은 문장 하나(';' 없음). 돌려주는 것은 그 문장의 results 배열. 실패면 AdminError('db') 를 던진다
// type Exec = (sql: string) => Promise<Array<Record<string, unknown>>>

export class AdminError extends Error {        // kind: 'usage' | 'db' | 'not_found' | 'changed'
  constructor(kind, message) {}
}

export function parseAdminArgs(command, argv)  // → { local, persistTo, yes, email, all, top, clear, help } 또는 AdminError('usage')
export function normalizeEmail(raw)            // → 소문자·앞뒤 공백 뺀 문자열 또는 AdminError('usage')
export function sqlText(value)                 // → "CAST(X'<utf-8 16진 소문자>' AS TEXT)"
export function utcDay(now)                    // 'YYYY-MM-DD' — worker/usage.ts utcDay 와 같은 값
export function utcDayStartMs(now)             // 그날 UTC 0시의 ms

export const SQL = {                           // 5장 표의 문장을 만드는 함수들 — 문자열만 돌려주고 실행하지 않는다
  usageTop(now, top), usageSummary(now),
  findUser(email),
  block(email, now), unblock(email),
  warn(email, now), clearWarn(email),
  recountPreview(target), recount(target),     // target: { all: true } | { email }
}

export function parseWranglerJson(stdout)      // → 첫 문장의 results. 실패 모양이면 AdminError('db', text)
export async function runAdmin(command, argv, { exec, now, print })   // → 종료 코드(7장). exec 는 인자 해석 뒤 만들어진다 (아래)
```

- `runAdmin` 의 세 번째 인자: `exec` 는 **해석한 옵션을 받아 실행기를 돌려주는 함수**(`(opts) => Exec`)다 — `--local`·`--persist-to` 에 따라 실행기가 달라지므로. `now` 는 `() => number`, `print` 는 `(line: string) => void`. 진입점 파일은 `d1.mjs` 의 실제 실행기, `Date.now`, `console.log` 를 넘긴다. 테스트는 받은 SQL 을 적는 가짜와 고정 시계를 넘긴다
- 모든 SQL 은 **문장 하나**이고 `;` 를 담지 않는다. wrangler `--command` 는 `;` 로 문장을 나누므로(측정 a 의 도움말 "multiple queries separated by ';'") 한 호출 = 한 문장으로 둔다. 원격에서 여러 문장 한 호출이 원자적인지·결과 배열이 로컬과 같은지는 확인하지 않았다 — 그래서 기대지 않는다
- `utcDay` 를 `worker/usage.ts` 에서 가져오지 않는 이유: `scripts/` 는 JS 이고 `worker/` 는 TS 다. 두 줄짜리라 복제하고, 테스트 S4 가 F-2025 U1 과 같은 값을 본다

## 4. wrangler 부르기 — `scripts/lib/d1.mjs`

```js
export function makeD1Exec({ local, persistTo })   // → Exec (3장)
```

**방식: `wrangler d1 execute` 를 자식 프로세스로, 셸 없이.** 규칙:

- 실행 파일: `process.execPath`(지금 node), 첫 인자는 저장소 뿌리의 `node_modules/wrangler/bin/wrangler.js` 절대 경로. 저장소 뿌리는 `import.meta.url` 에서 구한다(`scripts/lib/` 의 두 단계 위). `require.resolve` 는 쓰지 않는다 — 패키지 `exports` 가 막는다(측정 b)
- 인자: `d1 execute md-editor-db` + (`--remote` 또는 `--local` [`--persist-to <경로>`]) + `--json --command <sql>`. `--yes`(wrangler 의 것)는 넘기지 않는다 — `--command` 경로에서 wrangler 가 묻는 것을 보지 못했고, 묻는다면 멈추는 쪽이 낫다
- `cwd` 는 저장소 뿌리 — wrangler 가 `wrangler.jsonc` 와 뿌리 `.env`(`CLOUDFLARE_API_TOKEN`, 있는 PC 만)를 거기서 읽는다. `.env` 가 없는 PC 는 wrangler 브라우저 로그인 캐시로 돈다(CLAUDE.md "Deployment"). 스크립트는 인증을 따로 다루지 않는다
- `shell: false`. stdin 은 `ignore`, stdout·stderr 는 문자열로 받는다. 제한 시간 120초
- 결과: 종료 코드 0 이고 stdout 이 JSON 배열이면 `parseWranglerJson` 이 첫 원소의 `results` 를 돌려준다. 그 밖(종료 코드 ≠ 0, JSON 이 아님, `{ error: { text } }` 모양, 배열 첫 원소의 `success` 가 `true` 가 아님)은 `AdminError('db')` — 메시지는 `error.text` 가 있으면 그것, 없으면 stdout·stderr 끝 2,000자
- JSON 해석은 stdout 을 앞뒤 공백을 뺀 뒤 통째로 `JSON.parse` 한다(측정 e — 실패 출력 앞에 빈 줄). stdout 앞부분에 다른 글이 섞이면 실패로 보고 원문 끝을 보여 준다 — 섞인 글을 건너뛰는 추측은 하지 않는다. **원격 `--json` 출력에 다른 글이 섞이는지는 확인하지 않았다** — 10장 ①이 첫 원격 실행(읽기만 하는 `admin-usage`)에서 본다

**셸을 쓰지 않는 이유.** 기존 `scripts/e2e-one.mjs`·`verify.mjs` 는 `npx … { shell: true }` 로 부른다. 그 인자들은 경로·검색어라 그래도 되지만, SQL 은 `'`·`"`·`<`·`>`·`(`·`)` 를 담는다. Windows `cmd.exe` 에서 `>` 는 리디렉션이고 `"` 짝이 어긋나면 인자가 쪼개진다. 셸 없이 부르면 인자가 그대로 간다(측정 c)

**다른 길 비교** (기본값: wrangler 자식 프로세스)

| 방식 | 값 넣기 | 인증 | 판단 |
| --- | --- | --- | --- |
| **`wrangler d1 execute --json --command` (채택)** | 바인딩 없음 → 16진 리터럴(5.1) | wrangler 그대로(`.env` 토큰 또는 브라우저 로그인 캐시) | 개요 4.3 이 정한 것. 로컬·원격이 같은 명령 |
| `wrangler d1 execute --file <임시 .sql>` | 같음(바인딩 없음) | 같음 | 원격 `--file` 은 가져오기(import) 경로라 출력·확인 질문이 다를 수 있다 — 돌려 보지 않았다. 임시 파일도 생긴다. 쓰지 않는다 |
| Cloudflare REST `POST /accounts/{id}/d1/database/{id}/query` `{ sql, params }` | **바인딩 된다** | API 토큰이 있어야 한다. 이 PC 는 `.env` 가 없다. wrangler 로그인 캐시의 OAuth 토큰을 꺼내 쓰는 것은 문서화되지 않은 길 | 쓰지 않는다. 토큰이 있는 PC 에서만 돌고, `--local` 과 경로가 갈린다 |
| `getPlatformProxy`(wrangler API) | 바인딩 된다 | 로컬 전용 — 원격 D1 에 붙지 않는다 | 원격 도구가 못 된다 |

## 5. SQL — 문장 모양 (계약)

### 5.1 이메일을 SQL 에 넣는 방법 — 16진 문자열 리터럴

- wrangler 는 바인딩을 받지 않는다(측정 a). 그래서 이메일은 **UTF-8 바이트의 16진 리터럴** `CAST(X'…' AS TEXT)` 로 넣는다(`sqlText`). SQL 에 들어가는 글자는 `0-9a-f` 뿐이라 따옴표·`;`·주석 기호가 끼어들 자리가 없다 — 입력이 무엇이든 주입이 되지 않는다. `UNIQUE(email)` 색인도 그대로 탄다(측정 h)
- 그 **앞에** 형식 검사(`normalizeEmail`)를 둔다. 목적은 오타 잡기다 — 주입 막기는 16진이 맡는다
  1. 앞뒤 공백을 빼고 소문자로 바꾼다. 저장된 이메일은 소문자다 — better-auth 가 만들 때 `toLowerCase`(`internal-adapter.mjs`), 개발 우회도 `toLowerCase`(`worker/auth.ts` `findOrCreateDevUser`)
  2. 통과 조건: 길이 3~254, 제어 문자(U+0000~U+001F, U+007F) 없음, `worker/grants.ts` `EMAIL_RE` 와 같은 모양(`@` 하나 앞뒤로 공백·`@` 아닌 글자, 뒤쪽에 `.` 하나 이상). 초대가 받는 이메일과 같은 범위다 — `o'b@x.com` 처럼 따옴표가 든 주소도 받는다(16진이라 안전)
  3. 어기면 `AdminError('usage')`, 문구 `이메일 형식이 아닙니다: {원래 입력}`
- 숫자(시각 ms, `--top`)는 JS 에서 `Number.isSafeInteger` 를 통과한 정수만 글자로 넣는다. 날짜 문자열(`utcDay`)은 `YYYY-MM-DD` 정규식을 통과한 것만 `'…'` 로 넣는다 — 둘 다 사용자 입력이 아니라 시계에서 나온 값이다
- **개요와 다른 점**: F-2024 4.3·F-2025 7.3 은 "엄격한 형식 검사를 통과한 것만 `'{이메일}'` 로" 였다. 이 명세는 따옴표 리터럴 대신 16진 리터럴을 쓴다 — 형식 검사가 놓친 글자가 있어도 안전하고, 검사를 엄격하게 해서 실제 있는 주소(따옴표·`+`)를 못 고르는 일이 없다. 12장 갱신 대상

### 5.2 문장 표

`{e}` 는 `sqlText(email)`, `{now}` 는 `now()` 의 ms 정수, `{day}` 는 `'YYYY-MM-DD'`, `{day0}` 은 그날 UTC 0시 ms, `{top}` 은 정수. **시각 열(`blocked_at`·`warned_at`)은 epoch ms 로 쓴다** — `users.created_at`(INTEGER ms, `authServer.ts` `create.before`)·문서 시각과 같은 단위다. F-2025 는 열 타입(INTEGER)만 정했고 단위는 이 명세가 정한다(12장 — F-2028 이 같은 단위를 읽는다. F-2030 은 참·거짓만 본다)

| 이름 | 문장 |
| --- | --- |
| `findUser` | `SELECT id, email, created_at, write_day, write_count, content_bytes, doc_count, blocked_at, warned_at FROM users WHERE email = {e}` |
| `block` | `UPDATE users SET blocked_at = {now} WHERE email = {e} AND blocked_at IS NULL RETURNING id, email, blocked_at` |
| `unblock` | `UPDATE users SET blocked_at = NULL WHERE email = {e} AND blocked_at IS NOT NULL RETURNING id, email` |
| `warn` | `UPDATE users SET warned_at = {now} WHERE email = {e} AND warned_at IS NULL RETURNING id, email, warned_at` |
| `clearWarn` | `UPDATE users SET warned_at = NULL WHERE email = {e} AND warned_at IS NOT NULL RETURNING id, email` |
| `usageTop` | `SELECT email, created_at, CASE WHEN write_day = {day} THEN write_count ELSE 0 END AS today, content_bytes, doc_count, blocked_at, warned_at FROM users ORDER BY today DESC, content_bytes DESC, email LIMIT {top}` |
| `usageSummary` | `SELECT (SELECT CASE WHEN day = {day} THEN count ELSE 0 END FROM signup_gate WHERE id = 1) AS gate_today, (SELECT COUNT(*) FROM users WHERE created_at >= {day0}) AS created_today, (SELECT COUNT(*) FROM users) AS users, (SELECT COALESCE(SUM(content_bytes), 0) FROM users) AS bytes, (SELECT COALESCE(SUM(doc_count), 0) FROM users) AS docs, (SELECT COUNT(*) FROM users WHERE blocked_at IS NOT NULL) AS blocked, (SELECT COUNT(*) FROM users WHERE warned_at IS NOT NULL) AS warned` |
| `recountPreview` | `SELECT id, email, content_bytes, doc_count, (SELECT COALESCE(SUM(length(CAST(docs.content AS BLOB))), 0) FROM docs WHERE docs.owner_id = users.id) AS real_bytes, (SELECT COUNT(*) FROM docs WHERE docs.owner_id = users.id) AS real_docs FROM users` + (한 사람이면) ` WHERE users.email = {e}` |
| `recount` | `UPDATE users SET (content_bytes, doc_count) = (S) WHERE (content_bytes, doc_count) IS NOT (S)` + (한 사람이면) ` AND users.email = {e}` + ` RETURNING id, email, content_bytes, doc_count` — `S` = `SELECT COALESCE(SUM(length(CAST(docs.content AS BLOB))), 0), COUNT(*) FROM docs WHERE docs.owner_id = users.id` |

- `block`·`unblock`·`warn`·`clearWarn` 는 **이미 그 상태면 바꾸지 않는다**(`IS NULL`·`IS NOT NULL` 조건). 두 번 막아도 처음 막은 시각이 남는다 — privacy.md 가 "이용 제한이나 주의를 받은 시각" 을 기록한다고 적었고, 덮으면 처음 시각을 잃는다. 결과가 `[]` 이면 흐름(6장)이 `findUser` 결과로 "없음" 과 "이미" 를 가른다
- `recount` 의 `S` 는 F-2025 3장 마지막 문장·7.3 과 같은 행 값 모양이다. 거기에 `WHERE … IS NOT (S)` 를 더해 **어긋난 사용자만** 쓰고 돌려준다 — F-2025 3.1 4번의 "출력의 바뀐 사용자 수" 를 `RETURNING` 으로 안다(로컬 `meta` 에 `changes` 가 없다, 측정 d)
- `usageSummary` 의 오늘 가입 수 두 값: `gate_today`(관문을 지난 수 — `signup_gate.day` 가 오늘이 아니면 0, 씨앗 행 `day = ''` 도 0)와 `created_today`(오늘 UTC 0시 이후 `created_at` 인 `users` 수). 둘이 다르면 헛된 자리(개요 4.1)이거나 F-2028 전이라 관문이 아직 없는 것이다
- `users` 의 `created_at` 에는 색인이 없어 `created_today` 는 `users` 를 한 번 훑는다. 사용자 수만큼 읽기다(5.3)

### 5.3 행 비용 — 로컬 D1 실측 (측정 i)

사용자 3·문서 2,000. `getPlatformProxy` 의 `meta.rows_read`·`rows_written`. **원격 D1 의 행 계산이 같다는 것은 확인하지 않았다**(F-2024 2.4 끝과 같은 한계)

| 문장 | 읽기 | 쓰기 | 결과 |
| --- | --- | --- | --- |
| `recountPreview` (전부) | 4,005 | 0 | 사용자마다 저장값과 실제값 |
| **`recount` (전부, `IS NOT`) — 채택** | 4,011 | **2** | 어긋난 두 명만 고치고 돌려줌 |
| (비교) `recount` 조건 없이 — F-2025 3장 모양 그대로 | 2,013 | 3 | 모든 사용자를 쓴다. 누가 바뀌었는지 모른다 |
| (참고) 한 사람, `IS NOT` 없는 모양 (문서 1,500) | 1,503 | 1 | `IS NOT` 을 더하면 그 사람 문서 수만큼 읽기가 더 는다고 본다 — 이 모양은 재지 않았다 |
| `usageTop` (5.2 글자 그대로) | 6 | 0 | 사용자 수 × 2 |
| `usageSummary` (5.2 글자 그대로) | 19 | 0 | 사용자 수 × 6 + 1 |

- **`IS NOT` 을 고른 이유**: 쓰기 행이 사용자 수 → 어긋난 사용자 수로 준다. 대가는 읽기가 문서 수의 약 2배(부분 질의를 `WHERE` 에서 한 번, `SET` 에서 한 번 더). D1 무료 한도는 하루 쓰기 10만 행·읽기 500만 행이라 이 개요가 지키려는 것은 쓰기 쪽이다(F-2024 1.1). 문서 10만 개일 때 읽기 약 20만 행 = 하루 읽기의 4%
- `--yes` 없는 `admin-recount` 도 `recountPreview` 로 문서 수만큼 읽는다 — 미리보기도 공짜가 아니다. 출력 첫 줄에 적는다(8.2)
- 원격 문서·사용자 수는 조회하지 않았다

## 6. 흐름 — 확인 절차와 스크립트별 동작

### 6.1 공통 규칙

1. 인자를 해석한다. 틀리면 사용법(8.1)을 보이고 종료 코드 2. `--help`·`-h` 면 사용법을 보이고 0
2. 첫 줄에 **대상 DB** 를 적는다: 원격이면 `대상: 원격 D1 md-editor-db`, 로컬이면 `대상: 로컬 D1 md-editor-db` (+ `--persist-to` 가 있으면 ` ({경로})`)
3. **읽기부터 한다.** 쓰는 스크립트도 먼저 `findUser`(recount 는 `recountPreview`)로 지금 상태를 보여 준다
4. `--yes` 가 **없으면** 여기서 멈춘다: `--yes` 로 실행하면 돌릴 SQL 을 그대로 한 줄 출력하고, `실행하지 않았습니다. 위 SQL 을 실행하려면 --yes 를 붙이세요.` 를 적고 종료 코드 0
5. `--yes` 가 **있으면** 쓰기 문장 **하나**를 돌리고, `RETURNING` 결과로 무엇이 바뀌었는지 적는다
6. 대화형으로 묻지 않는다(`readline` 없음) — 확인은 `--yes` 하나다. 이유: 에이전트·비대화형 터미널에서 멈추지 않고, 무엇을 할지가 명령줄에 남는다(개요 4.3)

- **`--yes` 없는 실행은 원격에 쓰는 문장을 하나도 보내지 않는다** — 테스트 S11 이 "`--yes` 없으면 실행기가 받은 SQL 이 전부 `SELECT` 로 시작" 으로 판정한다
- 읽기와 쓰기 사이에 다른 요청이 끼어들 수 있다. 쓰기 문장은 자기 조건(`IS NULL` 등)으로 다시 판단하므로 틀린 행을 고치지 않는다. 읽을 때는 "고칠 수 있음" 이었는데 쓰기 결과가 `[]` 이면 `AdminError('changed')` — `그 사이 상태가 바뀌었습니다. 다시 실행해 지금 상태를 보세요.`, 종료 코드 1

- `admin-recount` 의 `--yes` 결과가 미리보기 수와 다를 수 있다(그 사이 쓰기). 다른 것은 오류가 아니다 — 쓰기 시점의 `IS NOT` 이 기준이다(6.3)

### 6.3 `admin-recount` 와 동시 쓰기 — F-2025 7.2 와 맞추기

- **한 문장이라 원자적이다.** `recount` 는 `UPDATE` 하나다. 같은 사용자의 쓰기 batch(문서 쓰기 + 사용량 줄, F-2025 6장)는 그 전이나 뒤에 통째로 돈다 — 전이면 다시 센 값에 이미 들어 있고, 뒤면 다시 센 값에 증감이 더해진다. 어느 쪽이든 결과가 맞다. 전제: D1 이 한 DB 의 문장·batch 를 하나씩 차례로 실행한다(Cloudflare D1 문서의 설명 — **이 명세에서 원격으로 확인하지 않았다**. 로컬은 측정 g 로 한 `--command` 의 원자성만 봤다)
- 그래서 `admin-recount` 가 **스스로 새 어긋남을 만들지는 않는다.** 남는 어긋남은 F-2025 7.2 의 것 그대로이고, 이 스크립트는 그 시점까지 쌓인 것을 지운다:

| F-2025 7.2 의 어긋남 | 다시 세면 |
| --- | --- |
| 마이그레이션 ~ 배포 사이 옛 Worker 의 쓰기 | 배포가 라이브된 **뒤** 돌리면 사라진다(F-2025 3.1 4번). 라이브 전에 돌리면 그 뒤의 옛 Worker 쓰기가 다시 어긋나게 한다 — 그래서 4번이 3번 뒤다. 라이브 직후 몇 분은 옛 Worker 가 끝내는 요청이 남을 수 있다 — 어긋남이 보이면 한 번 더 돌린다(같은 결과면 `다시 셀 것이 없습니다.`) |
| DO 스냅숏(F-2027 전, 그리고 `base` 에서 거꾸로 계산하는 오차) | 돌린 시점에 맞춰진다. 그 뒤 스냅숏이 다시 어긋나게 할 수 있다 — F-2027 이 붙기 전에는 실시간 편집이 누계를 안 바꾸므로 주기적으로 필요할 수 있다. 주기는 정하지 않는다(사람이 `admin-usage` 로 보고 판단) |
| 만들기 413 과 동시 요청(한도를 몇 개 넘김) | 누계는 원래 맞다(넘친 것은 한도 판정이지 누계가 아니다). 다시 세도 그대로 |
| 음수 누계(F-2025 3장 — CHECK 를 두지 않음) | 실제값으로 돌아온다 |

- 미리보기(`recountPreview`)와 쓰기(`recount`)는 **다른 호출**이다. 그 사이의 쓰기 때문에 미리보기 값은 낡을 수 있지만, 쓰기가 다시 계산하므로 결과는 쓰기 시점 기준으로 맞다

| M9 | 이미 막힘 / 안 막힘 | `이미 막혀 있습니다 ({시각}).` / `막혀 있지 않습니다.` |
| M10 | 이미 주의 / 주의 없음 | `이미 주의를 받은 계정입니다 ({시각}).` / `주의 기록이 없습니다.` |
| M11 | recount 끝 | `다시 셌습니다: {n}명` + 사람마다 한 줄 `{email}  {MB}  {doc_count}개` |
| M12 | recount 할 것 없음 | `다시 셀 것이 없습니다.` |
| M13 | 그 사이 바뀜 | `그 사이 상태가 바뀌었습니다. 다시 실행해 지금 상태를 보세요.` |
| M14 | 이메일 형식 | `이메일 형식이 아닙니다: {입력}` |
| M15 | 알 수 없는 인자 | `알 수 없는 인자: {인자}` |
| M16 | DB 실패 | `D1 실행 실패: {wrangler error.text 또는 출력 끝}` |
| M17 | block·warn 끝의 둘째 줄 | `앱 화면에는 그 사람이 다음에 /api/me 를 읽을 때 뜹니다(열린 탭은 최대 10분, F-2030 5.1).` |

- `{시각}` 은 UTC ISO 분 단위 `2026-09-24T10:00Z`. 한국 시간으로 바꾸지 않는다 — 날짜 경계가 UTC 라서(F-2024 2.3) 같은 기준으로 본다
- MB 는 `bytes / 1,048,576` 소수 한 자리 + `MB`(`AccountMenu.tsx` `formatUsage` 와 같은 MiB 기준)
- 사용법 문구(`--help`·인자 오류 때)는 6.2 표의 "인자" 열을 `사용: node scripts/admin-{이름}.mjs {인자}` 로. 한 줄 설명을 곁들인다 — 글자는 구현 재량

### 8.2 `admin-usage` 모양

```
대상: 원격 D1 md-editor-db
오늘(UTC 2026-09-24) 가입: 관문 3 · 실제 3
사용자 41명 · 문서 1,203개 · 본문 합계 12.4MB · 막힘 0 · 주의 1
```

- 열 순서·머리글 글자(`이메일`·`오늘 쓰기`·`본문`·`문서`·`가입일`·`막힘`·`주의`)는 계약. 폭 맞추기(공백 수)는 구현 재량 — 테스트는 열 값만 본다
- `막힘`·`주의` 는 시각이 없으면 `-`
- 가입일은 `created_at` 의 UTC 날짜
- 하루 한도(5,000)·가입 상한(20)·총량 한도는 **적지 않는다** — 그 상수는 `worker/usage.ts`·F-2028 에 있고, 여기 베끼면 두 벌이 된다. 숫자만 보인다
- `admin-recount` 미리보기 첫 줄: `미리보기는 문서를 한 번 훑습니다(문서 수만큼 읽기).` 그 뒤 어긋난 사용자만 `{email}  저장 {MB}/{n}개 → 실제 {MB}/{n}개`

### 8.3 이메일 가리기 — 가리지 않는다

- 출력은 **스크립트를 돌린 사람의 터미널에만** 간다. 파일·로그·네트워크로 보내지 않는다(2장). 그 사람은 운영자이고 D1 의 이메일을 이미 볼 수 있다(wrangler 로그인이 있어야 스크립트가 돈다)
- 가리면 쓸모가 없어진다 — `admin-usage` 에서 본 주소를 그대로 `admin-block` 에 넘겨야 한다
- privacy.md 의 수집·이용 목적("로그인한 사람을 알아보고…", "이용 제한이나 주의를 받은 시각")과 어긋나지 않는다고 본다 — 문장 해석이라 12장에 확인만 적는다
- 주의: 에이전트가 이 스크립트를 돌리면 출력(이메일)이 에이전트 대화 기록에 남는다. **원격 실행은 사람이 한다**(사용자 결정) — 에이전트가 판정에 쓰는 것은 `--local` 뿐이다(9.2)

## 11. 열린 질문

### Q1. 스크립트 테스트를 `npm test`(CI)에 넣을까 — **기본값: 넣지 않는다. `node:test` 로 따로 돌린다**

- 이유: 이 명세는 `scripts/` 만 소유한다(F-2026·F-2027 과 병렬). `vite.config.ts` `test.include` 는 `src/**`·`worker/**`·`site/**`·`cli/**` 뿐이라 `scripts/` 테스트를 넣으려면 그 파일을 고쳐야 한다. 지금 `scripts/` 에는 테스트가 하나도 없다
- 대가: CI(`ci.yml` 은 `npm test`)가 이 테스트를 돌리지 않는다. 누가 `scripts/lib/admin.mjs` 를 고쳐도 CI 는 모른다 — 고치는 사람이 A1 을 돌려야 한다
- 다른 안(`vite.config.ts` `test.include` 에 `'scripts/**/*.test.mjs'` 한 줄 + 테스트를 vitest API 로): CI 가 돈다. 바뀌는 것 — 소유 표에 `vite.config.ts`, 테스트가 `node:test` 대신 `vitest` 의 `describe`/`it`/`expect`(`node:test` 파일을 vitest 가 그대로 돌리지는 않는다), A1 이 `npm test`, A6 이 사라진다. `vite.config.ts` 는 F-2026·F-2027 소유 표에 없어 병렬로도 부딪치지 않는다 — **main 의 "scripts/ 만" 지시 때문에 기본값을 좁게 뒀다. 이쪽이 더 낫다고 보면 바꿔도 된다**

### Q2. 막기·주의를 다시 하면 시각을 덮을까 — **기본값: 덮지 않는다(5.2)**

- 이유: 처음 시각이 기록으로 남는다. F-2030 은 참·거짓만 보므로 화면 동작은 같다
- 다른 안(늘 `now` 로 덮기): 조건 `AND blocked_at IS NULL` 이 빠지고 M9·M10 "이미" 가 사라진다. "마지막으로 주의를 준 때" 를 알 수 있지만 처음 때를 잃는다

### Q3. 이메일 대신 사용자 id 로도 고를까 — **기본값: 이메일만**

- 이유: 개요 4.3 이 이메일로 정했고, 운영자가 보는 것은 `admin-usage` 의 이메일이다. 16진 리터럴이라 어떤 주소든 고를 수 있다(5.1)
- 다른 안(`--id <uuid>`): 저장소에 대문자 이메일이 남은 옛 행이 있을 때 쓸 길이 된다. 원격에 그런 행이 있는지는 조회하지 않았다 — F-205 이후 모든 경로가 소문자로 넣는다(근거 줄)

### Q4. `admin-usage` 가 막힌·주의 계정 목록을 보일까 — **기본값: 수만 보인다**

- 다른 안(`--flagged` 로 목록): 풀어 줄 사람을 잊었을 때 찾을 수 있다. 문장 하나(`WHERE blocked_at IS NOT NULL OR warned_at IS NOT NULL`)와 S9 한 줄이 는다

### 기본값으로 정한 것 (승인 시 확정)

1. wrangler 를 셸 없이 자식 프로세스로, `node_modules/wrangler/bin/wrangler.js` 경로 직접 — 4장
2. 이메일은 16진 리터럴 `CAST(X'…' AS TEXT)`, 형식 검사는 `grants.ts` `EMAIL_RE` 수준 — 5.1
3. 한 호출 = 한 문장, 바뀐 행은 `RETURNING` 으로 안다(`meta` 에 기대지 않음) — 3장·5.2
4. `recount` 는 `WHERE … IS NOT (S)` 로 어긋난 사람만 쓴다 — 5.2·5.3
5. `blocked_at`·`warned_at` 은 epoch ms — 5.2
6. 확인은 `--yes` 하나, 대화형 질문 없음, `--yes` 없이도 읽기는 한다 — 6.1
7. 종료 코드 0·1·2·3 — 7장
8. 이메일을 가리지 않는다, 출력은 터미널에만 — 8.3
9. `package.json` 에 npm 스크립트를 더하지 않는다 — 1장

### 가정으로 남긴 것 (확인하지 않았다)

- 원격 `wrangler d1 execute --remote --json --command` 의 stdout 이 로컬과 같은 JSON 배열 하나이고 앞뒤에 다른 글이 없다 — 10장 ①
- 원격 D1 이 `CAST(X'…' AS TEXT)`·행 값 `IS NOT`·`UPDATE … RETURNING` 을 로컬(workerd)·`node:sqlite` 3.50.4 와 같게 받는다
- 원격 D1 이 한 DB 의 문장을 차례로 실행해 `recount` 한 문장이 동시 쓰기 batch 와 섞이지 않는다(6.3)
- 원격 D1 의 행 계산이 5.3 로컬 값과 같다
- `--command` 경로에서 wrangler 가 확인 질문을 하지 않는다(로컬에서는 하지 않았다)

## 13. 기존 명세·코드와 부딪치는 것

- **F-2024 4.3·F-2025 7.3 의 이메일 넣는 방법** — 두 곳 다 "엄격한 형식 검사 뒤 따옴표 리터럴" 이다. 이 명세는 16진 리터럴로 바꿨다(5.1). 막으려던 것(주입)은 더 확실히 막고, 검사를 엄격하게 했을 때 생기는 "실제 주소를 못 고름" 을 없앤다. 12장
- **F-2025 7.3 의 "다시 세는 SQL" 모양** — 거기는 조건 없는 `UPDATE`(모든 사용자를 씀)이다. 이 명세는 `IS NOT` 조건을 더해 어긋난 사람만 쓴다(5.3 — 쓰기 3 → 2, 읽기 약 2배). 누계 계산식(`S`)은 같다
- **`blocked_at`·`warned_at` 의 단위** — F-2024·F-2025 는 INTEGER 만 적었다. ms 로 정한 것은 이 명세다. F-2028(아직 명세 없음)이 초로 읽으면 어긋난다 — F-2028 은 NULL 여부만 보면 되므로 실제로 부딪칠 곳은 없다고 본다
- **기존 `scripts/` 의 자식 프로세스 관례** — `e2e-one.mjs`·`verify.mjs`·`lib/server.mjs` 는 `npx … { shell: true }` 다. 이 명세만 셸 없이 부른다(4장 이유). 기존 파일은 고치지 않는다
- **`scripts/` 테스트가 CI 밖** — 11장 Q1
