# F-172 나타나고 사라지는 요소 전환

작성일: 2026-09-15
상태: 사용자 지시(2026-09-15 H38 확인 "디스플레이 토글 → 트랜지션, 오퍼시티, 비지빌리티를 이용하면 트랜지션 넣을 수 있잖아"). 지금 도는 병렬 작업과 파일이 겹치지 않아 자리가 나면 바로 시작
근거: F-149(색 전환 토큰 `--transition-fast`), `specs/design.md` 4장 전환 행, MDN `@starting-style`·`transition-behavior: allow-discrete`(Chrome 117+)

- 새 의존성 없음

## 2. 요구사항

### 2.1 공통
- 시간·곡선: `--transition-fast` (180ms, `--ease-spring`). 움직임 줄이기 설정이면 토큰이 0ms 라 즉시 (지금 규칙 그대로)
- 숨김은 `opacity: 0` + `visibility: hidden` (+ 필요하면 `transform`). 닫힐 때 `visibility` 는 전환 시간 뒤에 바뀌게 한다 (`transition: visibility 0s linear 180ms` 방식 또는 `allow-discrete`)
- 닫힌 요소는 포커스·클릭·스크린리더에 걸리지 않는다: DOM 에서 빠지거나(`usePresence` 끝) `inert`
- 여는 조작·닫는 조작의 키보드 동작(F-126·F-130 포커스 이동, Esc)은 바꾸지 않는다. 닫기 전환 중 다시 열면 바로 열린 상태로 돌아간다

### 2.2 대상

| 요소 | 열 때 | 닫을 때 |
| --- | --- | --- |
| 공유 메뉴, 폴더·문서 `⋯` 메뉴 | 투명 → 불투명, 위로 4px → 제자리 | 반대 |
| 대화상자(`Dialog.jsx` 쓰는 모든 창)와 뒤 막(`::backdrop`) | 창: 투명 → 불투명, 크기 0.98 → 1. 막: 투명 → 불투명 | 반대 (`display`·`overlay` 를 `allow-discrete` 로) |
| 알림 띠 | 투명 → 불투명, 위로 4px → 제자리 | 반대 |
| 좁은 창 겹침 사이드바 | 왼쪽 밖(`translateX(-100%)`) → 제자리 | 반대 |
| 사이드바 트리 폴더 펼침 하위 목록 | 투명 → 불투명 (`@starting-style`, 높이는 움직이지 않음) | 즉시 (목록 줄이 밀리는 움직임을 만들지 않는다) |
| 위키링크 자동완성 목록(CM6 툴팁) | 투명 → 불투명 (`@starting-style`) | 즉시 (CM6 가 DOM 을 바로 뗀다) |

- 제외: 편집·보기 모드 전환(`editor-slot`·`content-area` `hidden` — 편집기 크기 측정이 깨짐), 표 칸 범위 강조(design.md 100ms 규칙), 상단바 접힘(F-151 에 이미 있음), 툴팁(F-149 에 이미 있음)
