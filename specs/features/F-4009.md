# F-4009 OAuth 인가 서버 (better-auth oauth-provider)

작성일: 2026-10-16
상태: 승인 2026-10-16(사용자 "ㄱㄱ" — F-4008 결정·새 의존 better-auth 1.7.10 정확 고정·`@better-auth/oauth-provider` 1.7.10 포함). F-4008 6장 첫 자식. 화면 없음(동의·오류 페이지와 로그인 이어가기는 F-4010, `/mcp` 관문·보호 자원 메타데이터는 F-4011). 전부 node 단위(`testD1` + 실제 better-auth), e2e 없음. 구현 담당 `complex-implementer`(처음 돌리는 외부 플러그인·D1 표 매핑)

## 근거 (2026-10-16, npm 1.7.10 tarball 을 풀어 읽음, 이름으로 찾는다)
- 플러그인 `schema`: `oauthClient`·`oauthResource`·`oauthClientResource`·`oauthRefreshToken`·`oauthAccessToken`·`oauthConsent`·`oauthClientAssertion`. 토큰 저장 `storeTokens: 'hashed'` = base64url(SHA-256) 패딩 없음(`defaultHasher`). `disableJwtPlugin: true` 면 `storeClientSecret` 은 `'encrypted'` 만 된다(`hashed` 는 init 에서 던짐) — 비밀 키는 `BETTER_AUTH_SECRET`
- `handleRefreshTokenGrant` 는 세션을 보지 않는다. 갱신 토큰은 scope 에 `offline_access` 가 있을 때만 나온다. 플러그인 `session.delete` 훅이 better-auth 로그아웃 때 그 세션에서 나온 접근 토큰을 `revoked` 로 찍고 `offline_access` 갱신 토큰은 남긴다
- `enforcePerClientResources` 기본 `true`, `resources` 는 init 때 `oauthResource` 에 insertOnly 로 심는다(isolate 당 SELECT 1). 메타데이터 `authServerMetadata` 는 `introspection_endpoint`·`code_challenge_methods_supported: ['S256']`·`authorization_response_iss_parameter_supported: true` 를 늘 싣는다
- `@better-auth/kysely-adapter` sqlite: 배열·json = JSON 문자열, 날짜 = ISO 문자열(0009 와 같음), boolean = 0/1. `testD1` 의 node:sqlite 는 `foreign_keys = 1`(D1 과 같음)
- `worker/index.ts` `handleRequest` 의 `/api/auth/` 갈래는 POST 본문을 버리고 넘긴다(로그아웃용) → OAuth POST 에 그대로 쓰면 깨진다. `cleanupExpiredAuth` 는 `authServer.test.ts` 516 이 batch 길이 2 를 고정
- 번들 측정(스크래치 esbuild, min/gzip): better-auth 만 808KB/215KB → 플러그인 더해 1345KB/327KB(+537KB/+112KB)

## 2. 표 (`0028_oauth.sql`)
- 이름은 `auth_sessions` 처럼 복수 snake_case: `oauth_clients`·`oauth_resources`·`oauth_client_resources`·`oauth_refresh_tokens`·`oauth_access_tokens`·`oauth_consents`·`oauth_client_assertions`. 열은 플러그인 필드의 snake_case(`clientId`→`client_id`, `redirectUris`→`redirect_uris`, `refreshId`→`refresh_id` …), `id TEXT PRIMARY KEY` 와 플러그인이 `unique`·`index` 로 적은 것은 그대로 UNIQUE·INDEX. 매핑은 `authOptions` `user`·`session` 처럼 `schema.{모델}.modelName`·`fields`
- 외래 키: `user_id → users(id) ON DELETE CASCADE`(접근·갱신·동의. `oauth_clients.user_id` 만 `SET NULL`), `client_id → oauth_clients(client_id) ON DELETE CASCADE`, `session_id → auth_sessions(id) ON DELETE SET NULL`(`cleanupExpiredAuth` 가 막히지 않게), `refresh_id → oauth_refresh_tokens(id) ON DELETE CASCADE`. 그래서 `worker/account.ts` `deleteAccountStatements` 는 고치지 않는다 — `DELETE FROM users` 가 다 지운다
- 우리 표 둘:
```sql
CREATE TABLE oauth_client_use (user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE, client_id TEXT NOT NULL REFERENCES oauth_clients(client_id) ON DELETE CASCADE, last_used_at INTEGER NOT NULL, PRIMARY KEY (user_id, client_id));  -- ms, 쓰는 쪽 F-4011
CREATE TABLE oauth_register_gate (id INTEGER PRIMARY KEY CHECK (id = 1), day TEXT NOT NULL, count INTEGER NOT NULL);  -- signup_gate 와 같은 모양
INSERT INTO oauth_register_gate (id, day, count) VALUES (1, '', 0);
```

## 3. 동작
- **계약(`worker/oauthServer.ts`)**: `oauthIssuer(env)` = `new URL('/api/auth', BETTER_AUTH_URL).href`(끝 `/` 없음, 플러그인 issuer 와 글자까지 같다) · `mcpResource(env)` = `new URL('/mcp', BETTER_AUTH_URL).href` · `OAUTH_SCOPES = ['docs', 'offline_access']` · `REGISTER_DAILY_LIMIT = 500` · `oauthProviderOptions(env)` · `handleAuthServerMetadata(request, env)` · `admitClientRegistration(env)` · `cleanupOAuth(env, now)`
- **옵션**: `disableJwtPlugin: true`, `scopes: OAUTH_SCOPES`(openid 없음 → OIDC 아님), `grantTypes: ['authorization_code', 'refresh_token']`(client_credentials 빼기 — 공개 등록 클라이언트가 사용자 없는 토큰을 받지 못하게), `allowDynamicClientRegistration`·`allowUnauthenticatedClientRegistration: true`, `clientRegistrationDefaultApplicationType: 'infer'`(Claude Code 루프백), `resources: [mcpResource(env)]`, `cachedResources: new Set([mcpResource(env)])`, `enforcePerClientResources: false`(자원이 하나라 행만 는다), `accessTokenExpiresIn: 3600`, `refreshTokenExpiresIn: 2592000`, `refreshTokenReuseInterval: 30`, `storeTokens: 'hashed'`, 접두사 없음, `loginPage: '/login'`, `consentPage: '/oauth/consent'`. `authOptions` 의 `rateLimit: false`·`onAPIError.errorURL: '/login'` 은 그대로(플러그인 엔드포인트별 제한은 돌지 않고, 등록은 아래 관문이 막는다)
- **열리는 경로** `AUTH_ROUTES` 에 넷: `GET /api/auth/oauth2/authorize`, `POST /api/auth/oauth2/token`·`register`·`revoke`. `consent` 는 열지 않는다 — F-4010 의 `POST /api/oauth/consent` 가 안쪽 `Request` 로 핸들러를 부른다(F-4008 1장의 "다섯"에서 하나 줄임). `introspect`·`userinfo`·`client/*`·`admin/*` 는 404 그대로
- **Origin**: `token`·`register`·`revoke` POST 셋만 `isAllowedOrigin` 검사를 건너뛴다(서버 간 호출, 쿠키 없음). 이 셋은 본문을 그대로 넘기고, 로그아웃만 지금처럼 본문을 버린다
- **등록 관문**: `POST …/oauth2/register` 는 better-auth 에 넘기기 전에 `signup_gate` 와 같은 한 문장 조건부 UPDATE(`oauth_register_gate`, 상한 500, UTC 날)를 돈다. 바뀐 행 0 → 429 `{"error":"temporarily_unavailable","error_description":"registration limit reached"}` + `Retry-After: {다음 UTC 자정까지 초}`. 유효하지 않은 등록 요청도 센다(남용 시도를 세는 것)
- **AS 메타데이터**: `GET /.well-known/oauth-authorization-server/api/auth` 와 같은 내용을 루트 `/.well-known/oauth-authorization-server` 에도(경로 끼우기 전 클라이언트용). `auth.api.getOAuthServerConfig` 결과에서 `introspection_endpoint*` 넷을 빼고 플러그인 `metadataResponse` 로 낸다. 그 밖의 `/.well-known/*` 는 이 명세에선 404(보호 자원·도메인 확인은 F-4011)
- **로그아웃**: 위 근거대로 둔다 — 로그아웃 뒤 그 세션의 접근 토큰은 무효, 앱은 갱신 토큰으로 이어 간다(세션에 묶지 않는다)
- **정리** `cleanupOAuth(env, now)` 를 매일 Cron(`cleanupExpiredAuth` 옆, 따로 `runQuietly`)에 한 batch: 만료 접근 토큰, 만료 갱신 토큰, 만료 `oauth_client_assertions`, 그리고 `created_at` 이 24시간 넘었고 `oauth_consents`·`oauth_client_use` 에 행이 없는 `oauth_clients`. 쓰던 앱은 `연결 끊기` 뒤에도 `oauth_client_use` 가 남아 client id 가 살아 있다(F-4011 이 그 행을 지우지 않는다)
