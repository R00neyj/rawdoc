# F-2114 휴대폰 폭 설정 전체화면 1뎁스·2뎁스

작성일: 2026-10-01
상태: 승인(2026-10-01) — 열린 질문 Q1(앞으로 가기가 설정을 다시 여는가)은 기본값(연다)이 사용자가 정한 "history = 기본 네비 제스처" 원칙과 같은 결이라 기본값대로 가고, "갈림길 없으면 바로 구현" 상시 지시(2026-09-21)로 승인함. 사용자 원문(2026-10-01): "모바일 설정창 전체화면으로, 팝업으로 표현하기 좀 좁음 / 단 이렇게 수정하려면 수정 항목을 1뎁스 2뎁스로 페이지 분할해야함", 뒤로 가기는 "히스토리로 해야 기본 네비 제스처 그대로 쓸 수 있잖아"
구현 담당: `feature-implementer`

## 정해진 것 (사용자 결정, 바꾸지 않는다)

1. 정체는 지금의 모달 `<dialog>`(`Dialog.tsx`, `showModal()`)를 ≤600px(`PHONE_QUERY`)에서 100dvh 전체화면으로 쓰는 것. 해시 라우트(`#/settings`)·`hashRoute`·`hashNav`·`leaveScreens`·`useHashRouting` 은 손대지 않는다
2. 1뎁스 = 보일 탭(`visibleSettingsTabs` 결과) 행 목록, 2뎁스 = 그 탭의 지금 패널 내용 그대로. 3뎁스 없음. ≥601px 탭 UI·내용 변경 없음
3. 보일 탭이 1개(공개 보기 `PublicView`)면 지금 대화상자 그대로 — 전체화면도 기록도 없음
4. 뒤로 가기는 history. 열 때 1개, 2뎁스 들어갈 때 1개를 쌓는다. 쓰기는 모두 `historyEntries.ts` 를 거친다(F-2086 3.2)
5. 중첩 대화상자(금고 D-8·D-11·D-12·D-13, D-15, 스니펫 삭제, D-16)는 지금처럼 위에 뜨는 모달 그대로

## 근거 (직접 읽거나 돌린 것, HEAD `6aa406a`)

- **같은 주소 항목 사이 이동은 `hashchange` 를 안 일으킨다.** 스크래치 스크립트(Chrome 154, Playwright `channel: 'chrome'`)로 같은 URL `pushState` 2번 → `history.go(-2)`: `popstate` 1회, `hashchange` 0회. 그래서 설정 항목은 URL 을 그대로 두고 `state` 만 쓰면 `useHashRouting` 의 `handleHashChange`(해시 이벤트만 듣는다)·`decideHashNav`·`TopBarMoreSheet` 의 `hashchange` 닫기가 **아예 불리지 않는다** — 무시 분기를 더할 필요 없음
- `historyEntries.ts` `settle` 은 `readNavIdx` 가 숫자면 표식을 고쳐 쓰지 않는다 → `state` 에 `navIdx` 외 키가 있어도 하단 알약 번호(`navIdx`) 계산은 그대로. `readNavIdx`(`phoneNavRules.ts`)는 `navIdx` 만 읽는다
- **모달 `<dialog>` 의 닫기 요청(`cancel`)** — 같은 스크립트로 측정: 여는 클릭 뒤 행 버튼 클릭 → `Escape` 1·2번째 `cancel.cancelable=true`(막으면 열린 채), 3번째 `false` 로 닫힘. 클릭(사용자 활성화) 하나당 막을 수 있는 `cancel` 하나. 중첩 모달이 떠 있으면 `Escape` 는 중첩만 닫고(`n-cancel`→`n-close`) 바깥은 `cancel` 을 못 받는다(`cancel` 은 버블하지 않음)
- `go(-2)` 직후 같은 작업 안에서 `pushState` 하면 이동 목표가 호출 시점 기준이라 새 항목이 앞쪽에 버려지고 해시가 원래로 돌아간다(측정). 설정을 닫는 코드 경로 중 닫은 직후 같은 작업에서 기록을 쓰는 곳은 없다 — `useImportFlow.ts` `requestImportZip`·`requestImportFolder` 는 `closeSettings()` 뒤 파일 선택창을 열고, 기록 쓰기는 파일을 고른 뒤다
- `Dialog.tsx` 바깥 클릭 판정은 `event.target === dialog` — 전체화면에서는 대화상자 자신의 빈 곳을 누르면 닫힌다. 전체화면은 바깥이 없으므로 이 판정을 끈다(2.6)
- `Dialog.tsx` 열기 이펙트 의존성은 `[open, initialFocusRef]` — 열린 채 `initialFocusRef` **객체**가 바뀌면 다시 돌아 `returnFocusRef` 가 대화상자 안 요소로 덮인다. 그래서 폭·뎁스가 바뀌어도 ref 객체는 하나로 둔다(2.5)
- 공짜로 되는 것: `useEdgeSwipe.ts` `hasOpenDialog()`·`useOutlineSwipe.ts`·`Outline.tsx`(`dialog[open]` 3곳)·`useGlobalShortcuts.ts` 가 `dialog[open]` 을 보고 멈춘다. `PhoneNav` 는 모달 아래라 inert. `useSidebarLayout.ts` Esc 판정은 `settingsOpen` 으로 이미 빠진다
- `SettingsDialog` 는 `<dialog>` 가 닫혀도 마운트돼 자식을 그린다(F-290 3.7). 그래서 폰 목록 행에 `.more-sheet-item` 을 재사용하면 `e2e/topbarMore.spec.js` 등의 클래스 선택자와 겹친다 → 새 클래스 이름(2.2)
- `UserCssEditDialog`(D-16)는 `UserCssTab` 안에 그려지고 언마운트 정리가 `flush` 없이 타이머만 지운다 — 기록 이동으로 2뎁스를 내리면 미저장 입력(최대 `SAVE_DELAY_MS`)이 사라질 수 있다 → 2.4 "중첩이 떠 있으면 기록 이동을 되돌린다". `AccountDeleteDialog` 는 삭제 중 `cancel` 을 막는다 — `.close()` 로 강제로 닫지 않는 이유
- `index.html` viewport `interactive-widget=resizes-content` → 가상 키보드가 뜨면 `dvh` 가 줄어 2뎁스 본문 스크롤 안에서 입력칸이 보인다(실기기 확인은 H2)
- 폰 폭 설정 e2e 없음: 설정을 여는 e2e 는 전부 900px 이상(`grep setViewportSize|viewport` — `appSplit`·`comments`·`defaultView`·`paletteApp`·`publicView`, 기본 1600×900)
- `NARROW_QUERY`(459px)는 ≥601px 에서 대화상자 폭이 520px 이라 도달 불가. 단 `app.css` `@media (max-width: 459px) { .data-grid … }`(`.data-grid .data-row-note` 바로 아래)는 **폰 2뎁스 `데이터` 에서 계속 걸리므로 지우지 않는다**

## 2. 동작

### 2.1 페이지 모드

`pagesMode = settingsPagesMode(usePhoneWidth(), tabs.length)` — 폰 폭이고 탭이 2개 이상일 때만 참. 거짓이면 지금과 글자 하나 다르지 않은 출력(탭 목록 `aria-orientation` 은 늘 `vertical`).

- 페이지 모드에서는 `.dialog-actions`(`소개 보기`·`닫기` 줄)를 그리지 않는다

### 2.3 기록 규칙

항목의 `state` = `{ navIdx, settings: SettingsPage }`(`'list'` 또는 탭 id). URL 은 쓰는 순간의 `pathname + search + hash` 그대로. 기록 쓰기는 `onOpen` 을 받은 `SettingsDialog`(앱)만 한다.

| 일 | 처리 |
| --- | --- |
| 열림(`open` false→true), 페이지 모드, 지금 항목에 표식 없음 | `pushAppEntry(url, { settings: 'list' })`. 1뎁스 |
| 1뎁스 행 누름 | `pushAppEntry(url, { settings: id })`. 2뎁스 |
| `뒤로` 버튼 | `history.back()` |
| `닫기` 버튼 | `history.go(-k)`, k = 지금 항목 표식의 깊이(`list` 1, 탭 2). 표식 없으면 `onClose()` 바로 |
| 그 밖의 닫힘(Esc·닫기 요청으로 `close`, `useImportFlow` 의 `closeSettings`, 언마운트) — `open` true→false 인데 지금 항목에 표식 있음 | `history.go(-k)` 한 번 |
| `popstate` | `decideSettingsPop`(2.7) 결과대로 — `open`: `onOpen()` 하고 그 페이지로 / `show`: 그 페이지로 / `close`: `onClose()`(되감지 않음) / `restore`: `history.go(delta)` |
| 새로고침 | 표식 있는 항목에서 다시 떠도 설정을 열지 않는다(부팅은 `popstate` 가 아니다). 그 뒤 뒤로·앞으로로 표식 항목에 닿으면 위 `popstate` 줄대로 열린다 |
| 주소창 해시 수정 | 새 항목은 표식이 없어 `close` |

- 앞으로 가기로 표식 항목에 닿으면 설정이 다시 열린다(Q1 기본값) — 닫은 뒤 하단 알약 `앞으로 가기` 가 켜지는데, 누르면 아무 일도 없는 빈 칸이 되지 않게
- 기록으로 열릴 때는 그 항목의 페이지가 F-290 3.7 "열 때 첫 탭" 조정보다 이긴다. 그 밖의 열기(사이드바·팔레트)는 늘 1뎁스 + `화면` 이 활성 탭(탭 기억 안 함 유지)
- 되감기 순서: `popstate` 로 닫힐 때는 `onClose()` → `Dialog` 가 `dialog.close()` → `close` → 포커스 복귀. 이때 지금 항목은 이미 표식이 없어 되감기가 다시 일어나지 않는다. 우리가 부른 `go(-k)` 가 늦게 낳는 `popstate` 는 닫힌 상태 + 표식 없는 항목이라 `none`
- 시작·되감기는 `open` 변화로만 일으킨다(이펙트 정리 함수에서 되감지 않는다 — StrictMode 이중 실행)

### 2.4 닫기 요청(`cancel`) — `Escape`, 안드로이드 뒤로

모달 `<dialog>` 는 닫기 요청을 기록 이동보다 먼저 가로챌 수 있다(HTML close watcher, 안드로이드 Chrome 동작은 H1 에서 확인). 그래서 기록 경로와 같은 결과가 나오게 맞춘다:

- 설정 `<dialog>` 의 `cancel`(대상이 설정 자신일 때만)에서, 페이지 모드 + 2뎁스 + `e.cancelable` 이면 `preventDefault()` 하고 `history.back()` → 1뎁스
- 그 밖은 막지 않는다 → `close` → 2.3 "그 밖의 닫힘" 으로 되감기
- 결과: 2뎁스에서 `Escape`(또는 안드로이드 뒤로) 한 번이면 1뎁스, 또 한 번이면 닫힘. 2뎁스 숫자 칸(`본문 너비`)의 `Escape` 도 같다(대화상자 전체가 아니라 한 단계)

### 2.5 중첩 대화상자·폭 전환·포커스

- **중첩이 떠 있을 때**(설정 `<dialog>` 말고 `dialog[open]` 이 하나라도 있을 때) 오는 `popstate` 는 `restore` — 설정이 마지막으로 보인 항목 번호로 `history.go(delta)` 되돌리고 페이지·중첩은 그대로 둔다. 되돌림으로 오는 `popstate` 는 번호가 같아 `show`(같은 페이지, 변화 없음). 안드로이드 뒤로·`Escape` 는 2.4 대로 맨 위 중첩만 닫는다(측정). 중첩을 코드로 `.close()` 하지 않는다 — D-15 의 삭제 중 막기와 D-16 의 닫을 때 저장을 건너뛰지 않게
- **폰 → 데스크톱(열린 채)**: 쌓은 항목은 그대로, 탭 UI 가 `activeTab`(2뎁스였으면 그 탭, 1뎁스면 마지막 활성 탭)을 보인다. 닫을 때 표식이 남아 있으면 2.3 대로 되감는다
- **데스크톱 → 폰(열린 채)**: 지금 항목에 표식이 없으면 `'list'` 를 push 하고 1뎁스. 있으면 그 표식의 페이지
- 포커스: 열 때 1뎁스 첫 행(`화면`), 2뎁스로 가면 `뒤로`, 1뎁스로 돌아오면(버튼·`popstate`·`Escape`) 떠났던 탭의 행(⋯ 판 `returnKey` 선례), 폭 전환 뒤 데스크톱이면 활성 탭 버튼. `Dialog` 의 `initialFocusRef` 는 지금 `activeTabButtonRef` **객체 하나**를 계속 넘기고, 가리키는 요소만 바뀐다. 닫힌 뒤 포커스 복귀는 ia.md 3.15 7번 그대로(`Dialog` `returnFocusRef`)
- 부수 효과: `e2ee.onShown()`·`push.onShown()` 의 "탭이 보일 때" 조건을 **보이는 탭**으로 바꾼다 — 페이지 모드면 2뎁스일 때 그 탭, 아니면 `resolvedActiveTab`. `UserCssTab` 의 `requestUserCssPull()` 은 2뎁스 `사용자 CSS` 에서만 마운트되므로 저절로 같은 시점

### 2.6 CSS (`app.css`)

- `.dialog--full`: 너비 100vw·높이 100dvh·`max-height: none`·`margin: 0`·`padding: 0`·테두리·모서리 0, `[open]` 일 때 세로 flex. 머리줄은 위 `env(safe-area-inset-top)`, 본문은 아래 `env(safe-area-inset-bottom)` 만큼 띄운다(상단바 `.topbar` 폰 규칙 선례)
- `.dialog--full .settings-panel`: 높이 고정(`min(392px, 60vh)`) 해제 — `flex: 1; min-height: 0; overflow-y: auto`. 데스크톱 `.settings-panel` 은 그대로
- `.settings-page-head`·`.settings-page-list`·`.settings-row` 는 `.more-sheet-head`·`.more-sheet-list`·`.more-sheet-item` 과 같은 값(선택자 목록에 더하는 방식 권장). `.settings-row` 를 ≤600px 글자 확대 목록(16px)과 `(pointer: coarse)` 터치 높이 목록에 더한다
- **지운다**: `@media (max-width: 459px) { .settings-body … .settings-tabs … }` 블록 하나, ≤600px 글자 확대 목록의 `.settings-tabs button` 한 줄(폰에서 탭 목록이 더는 안 그려진다). **남긴다**: `.data-grid` 의 459px 규칙(근거 참고)
- `Dialog.tsx`: `size === 'full'` 이면 클래스 `dialog dialog--full`, 바깥 클릭 리스너를 달지 않는다. `onCancel?: (e: Event) => void` 는 `cancel` 리스너로 단다

- `readSettingsPage`: `settings` 가 `'list'` 면 `'list'`, 탭 id 이고 `tabs` 에 있으면 그 id, 탭 id 인데 지금 안 보이는 탭(예: 로그아웃 뒤 `account`)이면 `'list'`, 그 밖(없음·모르는 값·`state` 가 객체 아님)은 `null`
- `decideSettingsPop` 판정 순서: 닫힘 → `page` 있으면 `open`, 없으면 `none` / 열림 + `nestedOpen` + 두 번호가 숫자이고 다름 → `restore`(`delta = shownIdx - nextIdx`) / 열림 + `page` 없음 → `close` / 그 밖 → `show`. `shownIdx` 는 설정이 마지막으로 보인 항목 번호이고 `restore` 때는 바꾸지 않는다(되돌림 `popstate` 가 다시 `restore` 를 낳는 고리 방지)
- `extra` 를 안 주면 지금과 같은 `{ navIdx }` — 기존 호출 무변경

### Q1. 설정을 닫은 뒤 앞으로 가기가 설정을 다시 여는가 — **기본값: 연다**

- 이유: 닫으면 쌓은 항목은 앞쪽에 남고 하단 알약 `앞으로 가기` 가 켜진다. 열지 않으면 그 버튼이 한두 번 아무 일도 안 하는 빈 칸이 된다. 도움말·지도도 앞으로 가기로 다시 열린다(같은 "기록 = 화면" 규칙). 대가는 `state` 표식(`historyEntries.ts` `extra`)과 `onOpen` 배선(AppDialogs·App 한 이름)
