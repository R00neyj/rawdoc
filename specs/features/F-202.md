# F-202 TypeScript 이전 — `editor/`·`viewer/`

작성일: 2026-09-15
상태: 사용자 승인(2026-09-15 "ㄱㄱ"). **F-201 커밋 뒤** 시작. F-203 과 파일이 겹치지 않아 병렬 가능
근거: `specs/product.md` Q27, `specs/features/F-201.md` 2.2~2.6 규칙을 그대로 따른다

## 1. 파일 소유

| 파일 | 변경 |
| --- | --- |
| `src/editor/**` | `.js` → `.ts`, `Editor.jsx` → `Editor.tsx` (+test) |
| `src/viewer/**` | `.js` → `.ts`, `Viewer.jsx` → `Viewer.tsx` (+test) |

## 2. 요구사항

- F-201 2.4·2.5 규칙 (타입 JSDoc 제거, `any` 금지, 동작 불변, 테스트 이름만 변경)
- CM6 타입은 패키지 타입을 그대로 쓴다 (`EditorState`, `Transaction`, `DecorationSet`, `WidgetType` 등). JSDoc `import('@codemirror/…')` 는 `import type` 으로
- `WidgetType` 하위 클래스의 `eq`·`toDOM`·`ignoreEvent` 는 부모 시그니처와 맞춘다
- `markdown-it` 는 패키지 내장 타입(`dist/markdown-it.d.cts`)을 쓴다. `@types/markdown-it` 를 설치하지 않는다
- `?raw` SVG import 는 F-201 `vite-env.d.ts` 로 해결된다. 안 되면 보고
- 불변조건 유지: decoration 은 문서 내용을 바꾸지 않는다, 원본은 `EditorState` 하나, 조합 종료 시 밀린 재계산을 따라잡는다. **타입을 맞추려고 `view.composing` 검사·보류 로직의 순서를 바꾸지 않는다**
- `editor/` 는 React 를 import 하지 않는다(`Editor.tsx` 제외), `viewer/` 는 `editor/` 를 import 하지 않는다 (`specs/architecture.md` 1장)
