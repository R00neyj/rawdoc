# F-150 E2E 자동 테스트 도입 (Playwright)

작성일: 2026-09-14
상태: 사용자 승인(2026-09-14 "플레이라이트든 퍼펫티어든 자동 테스트 + 자동 테스트 불가능한 요소는 사람에게 요청 리스트업"). **F-144 커밋 직후, F-149 보다 먼저** 시작
근거: 명세마다 서브에이전트가 claude-in-chrome 으로 수동 확인하는 데 25~45분이 걸리고, 창 크기 변경 불가·백그라운드 탭 정지·탭 간섭으로 "확인 못 함"이 쌓였다. 반복되는 회귀 확인을 코드로 옮긴다. 판정 브라우저는 데스크톱 Chrome (`specs/product.md` Q7)

## 1. 선택
- **Playwright** (`@playwright/test` `^1.63.0`, devDependencies, Apache-2.0). Puppeteer 는 테스트 실행기·자동 대기·병렬 실행이 없어 따로 붙여야 하므로 고르지 않았다
- 브라우저는 **설치된 Chrome**(`channel: 'chrome'`)을 쓴다. 판정 기준(Q7)과 같고 브라우저 내려받기가 없다. Chrome 을 못 찾으면 멈추고 보고한다

## 2. 파일 소유

| 파일 | 변경 |
| --- | --- |
| `package.json`, `package-lock.json` | `@playwright/test` 설치, `test:e2e` 스크립트 |
| `playwright.config.js` | 신규 |
| `e2e/helpers.js` | 신규. 공용 조작 |
| `e2e/*.spec.js` | 신규. 3장 테스트 |
| `.gitignore` | `test-results/`, `playwright-report/` |
| `eslint.config.js` | `e2e/`·`playwright.config.js` 를 node 환경으로 (부분 Edit) |

- **앱 코드(`src/`)는 고치지 않는다.** 테스트를 위해 앱에 전용 훅·전역 변수를 넣지 않는다. 필요해 보이면 멈추고 보고
- `vitest` 설정이 `e2e/` 를 줍지 않는지 확인한다 (`npm test` 는 지금처럼 단위 테스트만)

## 3. 요구사항

### 3.1 설정
- `testDir: 'e2e'`, 프로젝트는 Chrome 하나, 기본 창 1600×900, 병렬 실행
- `webServer`: `npm run build` 후 `vite preview --port 4317 --strictPort` (5173 은 사용자가 쓴다). 테스트가 끝나면 서버도 끝난다
- 서비스 워커는 막는다(`serviceWorkers: 'block'`) — 캐시가 빌드 사이 결과를 흐리지 않게
- 실패 시 스크린샷·trace 남김. 결과 폴더는 git 에서 뺀다
- `npm run test:e2e` 한 번으로 빌드부터 끝까지. 전체 소요 **3분 이하** 목표, 실제 시간을 보고

### 3.2 `e2e/helpers.js`
- 각 테스트는 새 브라우저 컨텍스트(저장소 비어 있음)에서 시작한다
- 문서 넣기: 숨은 가져오기 입력에 `setInputFiles` 로 원하는 원문의 `.md` 를 넣어 새 문서를 만든다 (키 입력은 자동 짝·IME 규칙에 걸리므로 긴 원문은 이 방법)
- 원문 읽기: 저장이 끝난 뒤(상태바 저장됨) IndexedDB 에서 현재 문서(`#/d/{id}`)의 `content` 를 읽는다. 화면 DOM 으로 원문을 모으지 않는다(CM6 는 보이는 줄만 그린다)
- 모드 전환, 설정값 넣기(localStorage), 창 크기 바꾸기
- 한글 조합 흉내: CDP `Input.imeSetComposition`·`Input.insertText` 로 조합 이벤트를 만든다 (실제 IME 판정은 여전히 사람 몫)
- 고정 대기(`waitForTimeout`)는 명세가 시간을 요구하는 곳(툴팁 지연 등)만. 나머지는 자동 대기·`expect.poll`

### 3.3 옮길 수용 기준 (첫 묶음)
이미 구현된 명세의 브라우저 수용 기준을 테스트로 옮긴다. 기대값·허용 오차는 각 명세 그대로

| 파일 | 대상 |
| --- | --- |
| `e2e/table.spec.js` | F-140 A2·A3(좁은 표·편집 영역 폭에 맞는 표·20열 표, 툴팁 포커스 상태)·A4·A6·A11·A13·A14, F-124 A2d(위젯 아래 줄 클릭 위치), F-139 A2(표를 줄 단위로 입력), F-138 A2(역슬래시)·A5(조합 중 스크롤) |
| `e2e/layout.spec.js` | F-143 A3(레일)·A5(900px 좁은 창)·A6(검색 버튼 무동작)·A7(행 전체 호버)·A8(여백)·A14(편집 영역 한 가지 바탕·스크롤바 오른쪽 끝)·A16(아이콘 크기·가이드 선)·A17(위 48px·아래 50dvh, Ctrl+End) |
| `e2e/topbar.spec.js` | F-142 A1·A2(1280·1024px 툴팁)·A3·A5·A12(공유 메뉴), F-143 A10(메뉴 항목 아이콘) |

| `e2e/outline.spec.js` | F-144 A2~A8 |

- 테스트 이름에 명세 번호와 수용 기준 번호를 넣는다 (예: `F-140 A2 열 추가 버튼이 표 오른쪽 테두리에 붙는다`)
- **앱 버그로 실패하는 테스트**는 고치지 않는다(앱 코드 금지). `test.fail()` 로 표시하고 한 줄 주석에 원인 추정을 적고 보고한다. 테스트 코드 문제로 실패하면 고친다

### 3.4 자동화할 수 없는 항목
- 실제 한글 IME, OS 창(탐색기 연결·끌어놓기·시스템 공유 창), 색감·느낌 판단은 테스트로 만들지 않는다. 옮기다가 추가로 자동화가 안 되는 기준을 찾으면 보고한다 — 메인이 `specs/human-checks.md` 에 올린다
