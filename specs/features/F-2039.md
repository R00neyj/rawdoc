### R3 "자세히" 링크의 모양

그 기능을 다룬 사용법 글이 있으면 **도움말 절의 마지막 문단을 정확히 이 한 줄**로 둔다.

```
사용법 글: [{그 글 프론트매터 title}](/guides/{slug})
```

- 판정 정규식(U2): `^사용법 글: \[[^\]\n]+\]\(/guides/[a-z0-9]([a-z0-9-]*[a-z0-9])?\)$` — slug 부분은 `site/pages.ts` 의 글 주소 규칙과 같다
- 절 하나에 이 줄은 **최대 한 개.** 같은 글을 두 절이 가리켜도 된다
- 링크 글자는 그 글의 `title` 과 **글자 하나까지 같다**(U4)
- 머리말 `사용법 글` 은 사이트 머리 링크 `사용법`(`SITE_NAV`, F-276)과 `specs/ia.md` 6장 "사이트 사용법 글 | 사용법" 행에 맞춘 것이다. `자세히`·`가이드` 는 쓰지 않는다(ia.md 6장 쓰지 않는 말 `튜토리얼, 가이드`)
- **주소는 상대 주소**(`/guides/…`)다. ① 앱과 사이트가 같은 출처라 앱 `#/help` 와 사이트 `/help` 양쪽에서 맞게 열린다 ② 절대 주소는 제품명 검사에 걸린다(m9)
- **새 탭으로 열린다 — 따로 할 일이 없다.** `renderMarkdown` 이 모든 본문 링크에 `target="_blank" rel="noopener noreferrer"` 를 붙인다(m8). 앱 탭은 도움말 화면 그대로 남는다. 사이트 `/help` 에서도 새 탭이다 — F-272 11장 M3·F-276 Q1 이 사이트 전체에 대해 그대로 두기로 한 동작이다
- **오프라인에서는** 링크를 그대로 둔다. 누르면 새 탭에 브라우저의 연결 오류 화면이 뜬다 — 사이트 글은 precache 하지 않기 때문이다(R1). 그래서 **도움말 절은 링크 없이도 그 기능을 쓸 수 있을 만큼**(어디서 켜고, 기본값이 무엇이고, 무엇에 막히나) 적는다. 링크를 숨기거나 비활성으로 두지 않는 이유: 앱에는 온라인 여부로 본문 링크를 바꾸는 장치가 없고, 이 한 줄을 위해 도움말 렌더 경로(`HelpPage.tsx` 의 모듈 스코프 `HELP_HTML`)를 상태에 묶을 값어치가 없다(12장 Q9)
- 설치한 PWA 창에서는 새 탭이 브라우저로 열린다 — F-276 H5 와 같은 사람 확인(11장 H3)
- `내 문서로 복사`(F-244)로 도움말을 복사하면 이 줄도 사용자 문서에 들어간다. 앱 안에서는 그대로 열리고, `.md` 로 내보내 다른 도구에서 열면 상대 주소라 이어지지 않는다 — 받아들인다

### R4 서로 문장을 옮기지 않는다

- 사용법 글은 이어진 도움말 절의 문장을 그대로 쓰지 않고, 도움말 절도 글의 문장을 그대로 쓰지 않는다
- 판정(U5): `사용법 글:` 줄로 이어진 (절, 글) 쌍마다, 한쪽에서 `.`·`?`·`!` 뒤 공백·줄바꿈으로 자른 문장 가운데 **20자(코드 포인트) 이상**인 것이 다른 쪽 본문에 그대로 들어 있으면 실패. 목록 기호(`- `, `1. `)·표 칸 구분자(`| `)는 앞에서 떼고 비교한다
- 화면 글자를 인라인 코드로 인용하는 것(`` `금고 만들기…` ``)은 옮기기가 아니다 — 20자보다 짧아 판정에 걸리지 않는다
- 근거: 두 벌이 같은 문장을 가지면 한쪽만 고쳐지고 다른 쪽이 낡는다(`CLAUDE.md` "Two copies drift apart" 와 같은 이유). m5 로 초안이 통과한다

### R5 수치는 코드 상수 한 곳에서

- **원천은 코드 상수 하나다.** 문서 쪽에는 "한 번만 둔다" 대신 **적은 곳마다 상수와 대조하는 단위 테스트**를 둔다
- 도움말 절에는 쓰다가 바로 부딪히는 수치만 둔다 — **절마다 3개 이하**(예: 금고 절의 `기본 30분`·`약 750KB`). 사용법 글에는 관련 수치를 이유와 함께 둔다
- 사용법 글을 더하는 명세는 그 글의 수치 대조 행을 `site/helpGuides.test.ts` 에, 도움말 절에 수치를 더하는 명세는 대조 행을 `src/app/helpDoc.test.ts` 에 더한다
- 근거: 도움말은 오프라인에서 열리는 유일한 안내라 수치를 빼면 오프라인 사용자가 잃는다. 사용법 글은 사용자 결정 1 이 "한도" 를 가져가게 했다. F-2031 도 CLI 한도 수치를 README 에서 빼고 사용법 글(`cli.md`)에 두었다(F-2031 250행). 두 곳에 같은 수치가 있어도 둘 다 상수와 묶이면 어긋나지 않는다 — 12장 Q3

### R6 사실의 원천과 말

- 글의 사실 원천은 `done` 명세지만 **명세 문장을 옮기지 않는다.** 모든 사실은 현재 코드로 확인하고, 명세와 코드가 다르면 코드를 따르고 그 차이를 그 글 명세의 "갱신 대상" 에 적는다
- 글을 쓰는 명세는 **사실 표**(글의 문장 → 원천 명세 절 → 코드 이름)를 둔다. 이 명세 5장이 첫 예다
- 내부 용어는 쓰지 않는다. 알고리즘처럼 사용자가 검색해 볼 만한 표준 이름은 괄호로 풀어 한 번 쓴다(예: `PBKDF2-SHA256(암호에서 열쇠를 만드는 표준 계산)`)
- `specs/ia.md` 6장의 **쓰지 않는 말**을 쓰지 않는다. 제품명 대신 "이 앱" 으로 쓴다(`cli.md` 의 명령 이름은 예외)
- "완벽히 안전" 류 과장을 쓰지 않는다. 지키지 못하는 것이 있으면 적는다
- 판정(U6): 모든 `content/guides/*.md` 에 아래 낱말이 없다 — 쓰지 않는 말 `비밀번호`·`마스터 암호`·`복구 키`·`백업 코드`·`보관함`·`비밀 폴더`·`잠금 폴더`·`가이드`·`튜토리얼`, 내부 용어 `DEK`·`KEK`·`AES-KW`·`Y.Text`·`Y.Doc`·`Durable Object`·`md-yjs`·`md-docs`·`md-remote`·`e2ee`·`키 묶음`·`봉투`·`outbox`·`IndexedDB`, 과장 `완벽`·`100% 안전`
  - 쓰지 않는 말 가운데 `비밀번호`·`마스터 암호`(→ `금고 암호`), `복구 키`·`백업 코드`(→ `복구 코드`), `보관함`·`비밀 폴더`·`잠금 폴더`(→ `금고`)는 F-400 5.1 이 정한 것이다. **아직 `specs/ia.md` 6장 표에 없다**(13장 C3)
  - `절대` 는 넣지 않는다 — `절대 경로` 같은 정상 쓰임이 걸린다

### R7 글의 형식과 분량

- 프론트매터 `title`·`summary`·`date`·`updated`(F-276 6~8장 형식), 본문 첫 줄 `# {title}` 한 번
- `date`·`updated` 는 그 글을 넣는 **구현 커밋 날짜**(YYYY-MM-DD)다. `/guides` 목록은 `date` 내림차순이다(F-276 3.5)
- 본문(프론트매터 뺀)은 **6,000자 이하, `##` 10개 이하.** 넘으면 글을 둘로 나눈다. 판정 U6
- 근거: m2·m3 — 지금 글은 1,402~2,304자, 금고 글 초안이 5,594자·10절로 가장 길다. 금고 글은 위협 범위·잃었을 때·옮기기·이관을 한 글에 담아야 해서 길다(12장 Q8)

### R8 글 사이 링크

- 사용법 글에서 다른 사용법 글로 링크해도 된다(`/guides/{slug}` 상대 주소). 필수는 아니다
- 근거: `wiki-map.md` 가 이미 `[위키링크로 문서 잇기](/guides/wiki-links)` 로 잇는다. F-276 4.7 의 "두지 않는다" 와 어긋나 있다 — 1.1 에서 F-276 을 고친다

### R9 새 글은 명세로

- 사용법 글 한 편 = 명세 한 개. 그 명세가 R2~R7 의 적용(도움말 링크 줄, 수치 대조 행, 사실 표)을 함께 가진다
- 근거: 사용자 지시(2026-09-26, 다음 글은 각자 명세). `cli.md`·`command-palette-templates.md`·`wiki-map.md` 는 명세 없이 한 커밋(`7194dc4`)으로 들어왔다 — 그래서 사실 표가 없고 R8 과 어긋난 채 남았다(13장 C2)

````markdown
# 금고로 문서 암호화하기

로그인해서 쓰는 문서는 서버에 쓴 그대로 저장됩니다. 운영자가 서버를 열어 보면 읽을 수 있는 구조입니다. 금고는 이것을 막습니다. 금고에 넣은 문서는 서버로 가기 전에 이 브라우저 안에서 암호화되고, 푸는 열쇠는 금고 암호나 복구 코드를 넣은 브라우저에만 생깁니다.

모든 문서를 넣을 필요는 없습니다. 금고 문서는 공유와 실시간 함께 편집을 쓰지 못하고, 잠겨 있는 동안 검색에서도 빠집니다. 남에게 보이면 안 되는 문서만 골라 넣습니다.

## 서버가 읽지 못하는 것과 볼 수 있는 것

암호화되는 것은 **문서 제목, 본문, 문서에 넣은 이미지의 내용**입니다. 이 기기의 브라우저 저장소에 남는 사본도 암호화한 채 둡니다.

아래는 암호화하지 않습니다. 서버가 목록을 정렬하고, 쓰지 않는 이미지를 정리하고, 저장 공간을 세는 데 씁니다.

| 서버가 볼 수 있는 것 | 알아 둘 것 |
| --- | --- |
| 폴더 이름과 폴더 구조 | 금고 폴더의 이름도 보입니다. 숨길 내용은 폴더 이름에 적지 않습니다 |
| 어느 문서가 금고 문서인지, 어느 폴더에 있는지 | |
| 문서 수, 문서와 이미지의 크기 | 암호화한 뒤의 크기지만 원래 길이를 대강 짐작할 수 있습니다 |
| 만든 시각, 고친 시각, 저장한 횟수 | |
| 상단 고정 여부, 줄바꿈 형식(CRLF·LF) | |
| 이미지 형식(PNG·JPEG·GIF·WebP)과 가로세로 | |
| 문서가 쓰는 이미지의 식별자 목록 | 이미지 내용이 아니라 이름표입니다 |

## 금고가 막지 못하는 것

- **열려 있는 탭.** 금고를 연 탭에서는 문서가 풀린 채 화면에 있습니다. 자리를 비울 때는 잠급니다
- **서버가 내려 주는 앱 코드가 바뀌는 경우.** 웹 앱은 화면을 그리는 코드를 매번 서버에서 받습니다. 누군가 서버를 장악해 암호를 빼돌리는 코드를 내려보내면 금고로 막을 수 없습니다. 브라우저에서 도는 종단간 암호화(보내는 쪽에서 암호화해 받는 쪽에서만 푸는 방식)에 공통인 한계입니다
- **이 사이트 안에 끼어든 남의 스크립트.** 금고가 열린 동안에는 그 스크립트도 문서를 풀어 볼 수 있습니다. 열쇠 값 자체를 꺼내 가지는 못합니다
- **짧거나 흔한 금고 암호.** 서버에는 금고 암호로 잠근 열쇠가 있습니다. 그 값을 가진 사람은 암호를 하나씩 넣어 보며 맞춰 볼 수 있고, 틀린 시도는 기록되지 않아 횟수로 막을 수도 없습니다. 그래서 금고 암호는 10자 이상이어야 합니다. 남이 짐작하기 어려운 긴 문장을 씁니다
- **지우기와 옛 판으로 되돌리기.** 서버가 금고 문서를 지우거나 예전에 저장한 암호문으로 바꿔 놓는 것은 막지 못합니다. 누가 암호문을 고쳐 넣으면 풀 때 실패하므로 알아챌 수 있습니다
- **옮기기 전 내용의 백업.** 서버에 이미 있던 문서를 금고로 옮기면, 옮기기 전 내용이 서버의 장애 복구용 자동 백업에 최대 30일 남았다가 사라집니다

## 금고 만들기

설정의 `금고` 탭에서 `금고 만들기…`를 누릅니다. 금고가 없는데 문서 메뉴에서 `금고로 옮기기…`를 고르면, 옮기기 확인 뒤에 같은 창이 뜹니다.

1. `금고 암호`와 `암호 확인`에 같은 암호를 넣습니다. 10자 이상이면 되고, 글자 종류 규칙은 없습니다
2. `복구 코드`가 딱 한 번 나옵니다. 숫자와 영문 대문자 32자를 4자씩 8묶음으로 나눈 모양입니다. `복사`하거나 `파일로 저장`(recovery-code.txt)해 둡니다
3. `복구 코드를 안전한 곳에 보관했습니다`에 표시해야 `금고 만들기` 버튼이 눌립니다

복구 코드는 금고 암호를 잊었을 때 쓰는 두 번째 열쇠입니다. 이 코드만 있어도 금고가 열리니 남에게 보이지 않는 곳에 둡니다.

로그인한 상태에서 만든 금고는 계정에 딸립니다. 같은 계정으로 로그인한 다른 기기에서도 같은 금고 암호로 엽니다.

## 문서를 금고에 넣고 빼기

문서나 폴더의 `⋯` 메뉴에서 `금고로 옮기기…`를 고릅니다.

- 폴더를 고르면 하위 폴더와 그 안의 문서까지 옮기고, 그 폴더는 금고 폴더가 됩니다. 빈 폴더를 옮기면 빈 금고 폴더가 생깁니다
- 금고 폴더 안에서 새로 만든 문서와 하위 폴더는 처음부터 금고입니다. 거기에 문서를 만들거나 가져올 때 금고가 잠겨 있으면 먼저 열어 달라고 묻습니다
- 일반 문서를 금고 폴더로 끌어 넣을 수는 없습니다. 금고 문서는 일반 폴더로 옮겨도 암호화된 채로 남습니다
- 금고 문서는 약 750KB까지입니다. 암호화하면 크기가 늘어서 일반 문서보다 상한이 낮습니다. 이미지는 문서 하나에 1,000개까지입니다
- 로그인한 상태라면 인터넷에 연결되어 있어야 옮길 수 있습니다
- 옮기면 그 문서의 공유 링크와 초대가 끊깁니다. 다른 기기에서 그 문서를 열어 둔 채 아직 저장되지 않은 편집은 사라질 수 있습니다
- 이미지는 암호화해 다시 올리고 원래 이미지는 지웁니다. 다른 일반 문서가 같은 이미지를 쓰고 있으면 원래 이미지는 남깁니다

문서가 많은 폴더는 화면 위 알림에 `금고로 옮기는 중… 3/20`처럼 진행이 보입니다. `멈추기`를 누르거나 연결이 끊겨 멈췄다면, 다시 눌렀을 때 남은 것부터 이어서 옮깁니다.

`금고에서 빼기…`는 거꾸로 복호화해 일반 문서로 되돌립니다. 그 뒤로는 서버가 내용을 읽을 수 있습니다. 금고 폴더 안의 문서는 하나만 뺄 수 없고, 가장 바깥 금고 폴더째 뺍니다.

## 열기와 잠그기

금고를 여는 단위는 탭입니다. 잠긴 금고 문서는 사이드바에 `잠긴 문서`로 보이고, 누르면 편집 영역에 `금고 암호` 입력칸이 뜹니다. `열기`를 누르면 그 탭의 금고 문서가 모두 풀립니다. 명령 팔레트(`Ctrl+P`)의 `금고 열기`·`금고 잠그기`, 설정 `금고` 탭의 `금고 열기…`·`지금 잠그기`로도 열고 잠급니다.

금고는 이럴 때 잠깁니다.

- 탭을 닫거나 새로고침했을 때, 다른 페이지에 갔다가 뒤로 가기로 돌아왔을 때
- 그 탭에서 정해 둔 시간 동안 키 입력·클릭(터치 포함)·휠 굴림이 없을 때. 설정 `자동 잠금`에서 `5분`·`15분`·`30분`·`1시간`·`4시간` 가운데 고르고, 처음 값은 30분입니다. 잠그지 않는 선택지는 없고, 이 설정은 기기마다 따로 저장됩니다
- 같은 브라우저의 다른 탭에서 잠갔을 때. 잠그기는 모든 탭에 퍼지지만 열기는 퍼지지 않아서, 새로 연 탭은 잠긴 채 시작합니다
- 로그아웃하거나 다른 계정으로 바뀌었을 때

## 암호를 잊었을 때

잠긴 문서 화면이나 `금고 열기` 창에서 `암호를 잊었나요?`를 누르고 복구 코드를 넣습니다. 대소문자와 `-`·공백은 가리지 않습니다. 이어서 새 금고 암호를 정하면 복구 코드도 새로 만들어 한 번 보여 주고, 앞서 쓰던 복구 코드는 그때부터 듣지 않습니다.

금고 암호와 복구 코드를 둘 다 잃었다면 금고 문서를 되찾을 길이 없습니다. 열쇠를 서버에 두지 않으므로 운영자에게 요청해도 풀 수 없습니다. 남은 방법은 설정 `금고` 탭의 `금고 초기화…`입니다. 입력칸에 `초기화`를 그대로 적으면 금고 문서와 금고 폴더를 모두 지우고 금고를 없앱니다. 그다음 새 금고를 만들 수 있습니다.

암호를 알고 있을 때는 `암호 바꾸기…`에서 지금 암호와 새 암호를 넣습니다. 복구 코드는 바뀌지 않습니다. 문서를 잠근 열쇠 자체도 그대로라서, 새어 나간 옛 암호와 그 암호로 잠근 열쇠의 사본을 이미 가진 사람은 암호를 바꿔도 막지 못합니다.

## 로그인하지 않고 쓰는 금고

로그인하지 않은 상태에서도 금고를 만들 수 있습니다. 이 금고는 이 브라우저에만 있고, 금고 암호와 복구 코드도 계정 금고와 따로입니다.

그 브라우저에서 로그인하면 화면 위에 로그인 전 금고 문서가 있다는 알림이 `옮기기`·`나중에` 버튼과 함께 뜹니다. `옮기기`를 누르고 로그인 전 금고의 암호를 넣으면 계정 금고로 옮깁니다.

- 계정에 아직 금고가 없으면 로그인 전 금고가 그대로 계정 금고가 됩니다. 금고 암호와 복구 코드도 그대로 씁니다
- 계정에 금고가 있으면 문서를 그 금고에 넣습니다. 계정 금고의 암호와 복구 코드는 바뀌지 않습니다. 넣은 암호로 계정 금고가 열리지 않으면 계정 금고 암호를 한 번 더 묻습니다
- `나중에`를 누르면 기억하지 않고, 다음에 앱을 열 때 다시 묻습니다
- 옮긴 뒤에도 이 브라우저의 로그인 전 금고 문서는 지우지 않습니다. 로그아웃하면 다시 보입니다

## 암호화 방식

- 금고 암호는 PBKDF2-SHA256(암호에서 열쇠를 만드는 표준 계산)을 600,000번 되풀이해 열쇠로 바꿉니다. 되풀이가 많을수록 암호를 하나씩 맞춰 보는 데 오래 걸립니다
- 문서와 이미지는 AES-GCM 256비트(널리 쓰는 표준 암호 방식)로 암호화합니다. 문서와 이미지마다 열쇠를 따로 만들고, 그 열쇠들을 다시 금고 열쇠로 잠급니다
- 복구 코드는 무작위로 뽑은 160비트 값입니다
- 금고 암호와 복구 코드는 서버로 보내지 않습니다. 서버에 가는 것은 둘 중 하나가 있어야 풀리게 잠근 금고 열쇠뿐입니다
- 암호화는 브라우저에 들어 있는 기능(Web Crypto)으로 합니다

## 정리

- 금고 암호와 복구 코드를 둘 다 잃으면 누구도 되찾을 수 없습니다. 복구 코드는 만들 때 한 번만 보입니다
````

```
설정 `금고` 탭에서 `금고 만들기…`를 누르고 `금고 암호`를 정합니다. 그때 한 번만 보이는 `복구 코드`를 복사하거나 파일로 저장해 두세요. 금고 암호를 잊으면 `암호를 잊었나요?`를 눌러 복구 코드로 새 암호를 정합니다. 금고 암호와 복구 코드를 모두 잃으면 누구도 금고 문서를 되살릴 수 없습니다.
```

- 더한 문장 하나: 지금 절은 복구 코드를 **어디에 넣는지** 말하지 않는다. 오프라인에서 사용법 글을 못 여는 사람도 복구 경로를 찾게 한다(R3 오프라인). `암호를 잊었나요?` 는 `E2eeUnlockForm` 의 실제 버튼 글자다

### 6.2 절 끝에 더하는 문단

넷째 문단(`문서나 폴더의 … 약 750KB까지 저장할 수 있습니다.`) 뒤에 빈 줄 하나, 그리고:

```
사용법 글: [금고로 문서 암호화하기](/guides/encryption)
```

### 6.3 바꾸지 않는 것과 이유

- 첫 문단 `폴더 이름과 문서 수·크기·수정 시각은 암호화하지 않습니다.` 는 드러나는 것의 **일부**만 적었지만 틀린 말은 아니다. 전체 목록은 글의 표에 있다 — 도움말은 짧은 참조라 그대로 둔다(R1·R2)
- 수치 `기본 30분`·`약 750KB` 는 둘로 R5 의 "절마다 3개 이하" 안이다. U8 이 상수와 대조한다
- 결과: `사용법 글:` 줄 뺀 본문 494자·4문단(m8) — R2 안이다
