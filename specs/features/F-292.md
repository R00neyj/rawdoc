## 1. 1판(2D·SVG)에서 무엇을 왜 바꿨는가

1판은 2026-09-21 에 `24fadd2` 로 구현돼 `main` 에서 동작하고 있다. 아래는 그날 오후 사용자가 목표를 바꾸면서 무엇이 뒤집혔는지다.

### 1.1 뒤집힌 전제 하나 — "배치를 애니메이션하지 않는다"

1판 7.1 이 SVG 를 고른 근거는 딱 하나였다.

> 배치를 애니메이션하지 않기 때문에 SVG 의 약점인 "매 프레임 DOM 갱신"이 아예 없다. 좌표를 한 번 계산해 한 번 그리고, 그 뒤로는 `<g>` 의 `transform` 만 바뀐다 — 1판 7.1

**개정판은 그 전제를 세 군데에서 깬다.**

| 무엇이 | 왜 매 프레임 갱신이 되나 |
| --- | --- |
| 우클릭 회전 (결정 5) | 카메라가 움직이면 노드 2,000개의 화면 좌표가 전부 바뀐다 |
| 장력 슬라이더 (결정 3) | 슬라이더를 끄는 동안 시뮬레이션이 다시 돌고 노드가 실시간으로 움직인다 |
| 노드 끌기 재가열 (결정 12) | 위와 같다 |

노드 2,000 + 간선 4,000 이면 SVG 요소가 6,000개 이상이고, 그 `cx`·`cy`·`x1`~`y2` 속성을 매 프레임 다시 쓰는 것은 브라우저 레이아웃·페인트를 매번 다시 태우는 일이다. **그래서 SVG 를 고른 근거가 사라졌고, WebGL 로 간다.** 1판 7.1 의 비교표(호버 판정·툴팁·테마 전환이 SVG 에서 공짜라는 것)는 여전히 맞는 말이고, 그 편의를 포기하는 대가를 3.4~3.6 과 6.10 에서 따로 갚는다.

### 1.2 그 밖에 바뀐 것

| 1판 | 개정판 | 이유 |
| --- | --- | --- |
| 2D 평면, `현재 문서 중심`/`전체` 세그먼트 + `1~3단계` | **3D 전체 지도 하나.** 모드 전환 없음. `몇 다리` 는 필터 항목으로 내려간다 (6.4) | 결정 2. 3D 전체 보기가 기본이 되면 "부분만 잘라 보기"는 **거르기**의 문제이지 **모드**의 문제가 아니다. 필터는 자리를 유지하며 흐리므로(결정 14) 무엇이 걸러졌는지 보이고, 1판 모드 전환은 배치를 통째로 다시 돌려 그걸 못 보였다 |
| 노드 상한 500 | **2000** (결정 11) | 1판 상한 500 은 직접 구현한 O(n²) 반발력(1,000개 539ms, 2,000개 5,123ms)과 SVG 요소 수가 정한 값이다. d3-force-3d 는 옥트리 근사라 2,000개에서도 tick 당 한 자릿수 ms 다 (4.1 실측) |
| 고립 문서는 `degree` 0 이라 상한에서 먼저 잘림 | **전부 띄운다** (결정 10) | 현재 사용자 데이터는 문서 수십 개에 링크 5개다. 고립 문서를 빼면 점 6개짜리 3D 가 된다 |
| 이름표를 노드 60개 이하일 때 전부 표시 | **평소 숨김 + 호버하면 그 노드와 이웃까지** (결정 7) | 3D 는 이름표가 겹쳐 읽을 수 없다 |
| 노드 색 = `--accent` 고정, 끊긴 링크만 다름 | **색은 그룹 전용.** 깊이는 크기·투명도로 (결정 9) | fog 를 쓰면 멀리 있는 그룹 색이 씻겨 "색으로 묶음을 구분한다"와 정면충돌한다 |
| 설정 키 `md.mapDepth` 하나 | `md.mapView`·`md.mapGroups` 둘 (6.11) | 슬라이더 7개·토글 여럿·그룹 목록이 생겼다 |
| 검색 인덱스(F-286)와 지도 인덱스를 **따로 둔다** (1판 Q7) | **지도가 `searchIndex.ts` 를 그대로 쓴다** (6.4·6.5) | 결정 15 가 그룹 조건에 본문 검색어를 허용한다. 본문을 찾으려면 F-286 인덱스가 필요하다. 1판 Q7 은 뒤집힌다 |
| 배치는 `lib/graphLayout.ts` 직접 구현(Fruchterman-Reingold) | **`d3-force-3d`** (결정 4) | 3D·실시간·재가열을 직접 짜려다 실패한 기록이 4.4 에 있다 |

## 3. 그리는 방법 — `three` + `d3-force-3d`

### 3.1 왜 래퍼(`3d-force-graph`)를 쓰지 않는가 — 번들 실측

2026-09-21 실측 (min+gzip):

| 안 | 추가 전송량 | 판단 |
| --- | --- | --- |
| `3d-force-graph` | **344 KB** | 안 쓴다 |
| **`three` + `d3-force-3d` (채택)** | **198 KB** (three 184,897 B + d3-force-3d 9,063 B + OrbitControls 4,438 B) | **채택** (결정 4) |
| Canvas 2D + `d3-force-3d` 만 | 9 KB | 3D 원근·회전을 직접 짜야 한다. 안 쓴다 |

- **146 KB 차이의 원인을 실측으로 특정했다.** `three-render-objects@1.42.0` 이 최상단에서 `import { WebGPURenderer } from 'three/webgpu'` 를 **정적으로** 한다. `three.webgpu.js` 단독이 199,237 B gzip 이다. 게다가 `three` 를 `peerDependencies` 가 아니라 일반 `dependencies` 로 두어 버전을 우리가 고정할 수 없다
- **three 는 이 사용 패턴에서 tree-shaking 이 사실상 안 된다.** bundlephobia 의 webpack+terser 빌드(343,898 B)가 벤더 UMD(345,186 B)와 0.4% 차이였다. 위 198 KB 는 tree-shaking 없는 기준이다
- **실제 빌드 후 수치는 아직 재지 못했다.** 7장에 게이트로 둔다

### 3.2 의존성과 정확한 버전 — 소명세가 딴 걸 깔지 않게

### 3.3 번들 — 지도 청크를 지연 로드한다

현재 실측 (2026-09-21):

| 항목 | 값 |
| --- | --- |
| 초기 로드 합계 | 2,331,423 B raw / **690,570 B gzip (674 KiB)** |
| `index-*.js` | 626,811 / 208,339 |
| `createEditor-*.js` | 1,599,114 / 463,703 |
| PWA precache | **104개 엔트리 / 12,957,322 B (12.36 MiB)** (.js 66개 6.64 MiB) |

- **mermaid 가 초기 로드에 들어간 전례를 반복하지 않는다.** `src/lib/mermaidRender.ts:2` 가 `import mermaid from 'mermaid'` 정적 import 이고 `src/editor/preview/mermaidWidget.ts:4` 가 그걸 정적으로 끌어와 `createEditor` 청크(gzip 463 KB)에 흡수됐다. 지금 `App.tsx:100` 이 `MapPage` 를 **정적 import** 하므로, 그대로 두면 three 198 KB 가 `index` 청크에 그대로 붙는다

- **목표: 초기 로드 gzip 이 690,570 B 에서 늘지 않는다.** 지도 청크는 +198 KB gzip 이내 — 7장 G1·G2

- `maximumFileSizeToCacheInBytes` 는 3 MiB 다. three 청크는 gzip 198 KB 이고 raw 도 그 아래로 보이지만 **실제 빌드에서 확인한다** (7장 G3). 넘으면 그 파일만 precache 에서 조용히 빠져 오프라인에서 지도가 안 열린다

### 3.4 테마 색을 three 가 어떻게 읽는가 — 실측으로 정했다

불변조건상 색 hex 를 코드에 쓸 수 없다. 그런데 `new THREE.Color('var(--accent)')` 같은 것은 없으므로 **CSS 에서 색을 읽어 숫자로 바꿔야 한다.** 2026-09-21 Playwright(설치된 Chrome, headless·headful 둘 다 같은 결과)로 직접 쟀다.

| 읽는 법 | 화이트 테마 | 다크 테마 |
| --- | --- | --- |
| `getComputedStyle(root).getPropertyValue('--accent')` | `#3B4890` | **`color-mix(in srgb, #3B4890 55%, white)`** ← 색이 아니라 토큰 문자열 |
| 프로브 요소의 `getComputedStyle(el).color` (`color: var(--accent)`) | `rgb(59, 72, 144)` | **`color(srgb 0.577255 0.605294 0.760588)`** |
| `color-mix(in srgb, var(--ink) 30%, transparent)` 을 건 프로브 | `color(srgb 0.109804 0.105882 0.0941176 / 0.3)` | `color(srgb 0.909804 0.894118 0.862745 / 0.3)` |

**결론 세 가지.**

1. **커스텀 속성을 직접 읽으면 안 된다.** `tokens.css` 175행의 다크 `--accent` 는 `color-mix()` 이고, 커스텀 속성의 계산값은 `var()` 만 치환될 뿐 `color-mix()` 는 그대로 남는다. 다크 테마에서 그대로 파싱하면 실패한다
2. **프로브 요소의 `color` 를 읽는다.** 지도 컨테이너 안에 0px 크기의 `<span aria-hidden="true">` 를 토큰 수만큼 두고 CSS 로 `color: var(--…)` 를 건 뒤 `getComputedStyle(el).color` 를 읽는다. 읽는 토큰은 `--ink`(노드 기본), `--accent`(현재 문서 강조), `--muted`(끊긴 링크), `--rule`(간선), `--panel`(바탕·깊이 섞기 대상), `--map-group-1`~`-8`(그룹 색)
3. **파싱은 우리가 한다.** `src/lib/cssColor.ts` 의 `parseCssColor(input): [r,g,b,a] | null` 이 `#rgb`·`#rrggbb`·`rgb()`·`rgba()`·`color(srgb r g b)`·`color(srgb r g b / a)` 를 받아 0~1 실수 넷으로 돌려준다. `THREE.Color.setStyle()` 에 문자열을 넘기지 않고 `setRGB(r, g, b)` 로 준다 — three 의 CSS 파서가 `color(srgb …)` 를 받는지 **코드로 확인하지 못했고**(three 미설치), 확인할 필요가 없게 만드는 쪽을 고른다. 파서가 순수 함수라 **DOM 없는 `node` 테스트 환경에서 단위 테스트가 된다**

**언제 다시 읽는가.**

- 지도를 열 때 한 번
- `document.documentElement` 의 `data-theme` 속성 변화를 `MutationObserver({ attributes: true, attributeFilter: ['data-theme'] })` 로 보고 다시 읽는다
- **`prefers-color-scheme` 변화를 따로 듣지 않는다.** `App.tsx` 1008~1019행이 `md.theme === 'system'` 일 때도 `document.documentElement.dataset.theme` 를 항상 해석된 값(`white`|`sepia`|`dark`)으로 쓰는 것을 확인했다. 위 Observer 하나로 전부 잡힌다
- **`App.tsx` 에 `setTheme` 호출을 더하지 않는다.** F-260 이 mermaid 위젯을 위해 `editorRef.current?.setTheme(resolved)` 를 마운트 시점에 부르게 했다가 `F-156 A7` 회귀를 냈다(CLAUDE.md "배포" 2026-09-21 항목). 같은 함정을 만들지 않으려고 지도는 자기 안에서 스스로 감지한다

### 3.5 노드·간선·이름표를 무엇으로 그리는가

| 대상 | 방법 | 이유 |
| --- | --- | --- |
| 노드 | `THREE.InstancedMesh` 하나 (저해상도 `SphereGeometry`, 인스턴스마다 위치·크기·색) | 드로우콜 1회. 2,000개를 개별 `Mesh` 로 두면 드로우콜 2,000회다 |
| 간선 | `THREE.LineSegments` 하나 (`BufferGeometry` 의 정점 배열을 tick 마다 갱신) | 드로우콜 1회. 굵기는 WebGL `lineWidth` 가 대부분 1px 로 무시되므로 **투명도로 표현한다** (6.6) |
| 이름표 | **캔버스 위에 겹친 DOM 레이어** (`MapLabels.tsx`). 프레임마다 `camera.project()` 로 화면 좌표를 구해 `transform: translate()` | (1) 한글 글꼴·자간·테마 색이 CSS 로 그대로 먹는다 (2) SDF 폰트 아틀라스를 만들 필요가 없다 (3) 동시에 보이는 이름표가 호버 이웃 수로 제한돼(보통 10개 미만, 상한 60개) DOM 개수가 문제되지 않는다 |
| 호버·클릭 판정 | `THREE.Raycaster` + `InstancedMesh` 의 `instanceId` | DOM 이 없으니 직접 쏜다. 1판 7.1 이 "브라우저가 해 준다"고 적었던 몫을 여기서 갚는다 |

- **깊이(멀고 가까움)는 진짜 알파가 아니라 바탕색 섞기로 준다.** 인스턴스 색을 `--panel` 쪽으로 보간한다. 반투명 렌더링은 깊이 정렬을 요구해 2,000개에서 비싸고 결과도 불안정하다. 불투명한 바탕 위에서는 눈에 같아 보인다. **결정 14 의 "투명도 15%" 도 같은 방식으로 구현한다** — `--panel` 과 85% 섞은 색
- fog 는 쓰지 않는다 (결정 9)
- 배경색은 `--panel` (1판 7.2 와 같게, F-143 3.8)

### 3.6 WebGL 을 못 쓰는 브라우저

- `canvas.getContext('webgl2')` 가 `null` 이면 캔버스를 만들지 않고 **`목록` 보기로 자동 전환**한다. 머리 줄의 `지도` 세그먼트 버튼은 `aria-disabled="true"` 가 되고, 본문 위에 한 줄 안내: `이 브라우저에서는 3D 지도를 그릴 수 없습니다. 목록으로 보여 드립니다.`
- WebGL2 가능 여부는 **이 PC 의 설치된 Chrome 에서 headless·headful 둘 다 확인했다** — `webgl2: true`, renderer `ANGLE (AMD, AMD Radeon RX 7600 … Direct3D11)`. Playwright e2e 도 같은 채널을 쓰므로(`playwright.config.js` `channel: 'chrome'`) 캔버스가 실제로 그려진다. 다만 다른 기기(노트북)나 GPU 차단 환경에서는 다를 수 있어 **e2e 의 판정을 캔버스 픽셀에 걸지 않는다** (11장)

## 4. 배치 — `d3-force-3d`

### 4.1 시뮬레이션 수명 (결정 12) — 실측 근거

`d3-force`(2D, 같은 알고리즘·같은 Barnes-Hut 근사)를 이 PC(Node v24.12.0)에서 직접 쟀다. 간선 ≈ 노드 × 0.95, 문서 5%는 고립 노드로 뒀다. `forceLink(120, 0.05)` + `forceManyBody(-800)` + `forceCenter`. 각 3회 중앙값.

| 노드 수 | 간선 수 | tick 당 | 기본 `alphaDecay` 에서 멈출 때까지 | 총 시간 |
| --- | --- | --- | --- | --- |
| 200 | 190 | 0.46 ms | 300 tick | 0.14 s |
| 500 | 475 | 1.25 ms | 300 tick | 0.37 s |
| 1,000 | 950 | 2.73 ms | 300 tick | 0.82 s |
| **2,000** | **1,900** | **5.87 ms** | **300 tick** | **1.76 s** |
| 4,000 | 3,800 | 13.21 ms | 300 tick | 3.96 s |

- **`alpha` 가 `alphaMin`(0.001) 아래로 내려가면 tick 을 멈추고 rAF 루프도 멈춘다.** 기본값(`alphaDecay` 0.0228)에서 정확히 300 tick 이다
- **재가열**: 장력 슬라이더 조작, 노드 끌기, 문서 목록 변경 → `alpha(0.3).restart()`
- **회전·확대·이름표 호버는 시뮬레이션을 건드리지 않는다.** 카메라가 움직이는 동안만 다시 그린다 (결정 12)
- **`OrbitControls.enableDamping` 을 켠다.** 기본값은 `false` 다(`OrbitControls.js:209`). 켜는 쪽으로 정했다 (2026-09-21 사람 결정, 12장 Q3) — 목적이 재미(결정 1)라 관성 없는 회전은 뻣뻣하다. 대신 "안정되면 멈춘다"(결정 12)를 지키려고, 드래그를 놓은 뒤에는 `controls.update()` 가 `false` 를 돌려줄 때까지만 rAF 를 이어 가고 그 뒤 멈춘다. 시뮬레이션 tick 과는 별개다. `dampingFactor` 는 `0.08` 로 시작하고 눈으로 조정한다 (B22)
- **3D 는 이 값보다 느리다.** d3-force-3d 는 사원트리 대신 옥트리를 쓰고 좌표가 하나 늘어난다. 대략 1.5배로 보지만 **재지 않았다**(미설치). 7장 G5·G7 에서 실제로 잰다

### 4.2 `prefers-reduced-motion` (결정 13)

- 배치가 움직이는 모습을 보여 주지 않고 **최종 위치로 바로 보인다**
- 하지만 300 tick 을 한 프레임에 돌리면 2,000 노드에서 화면이 1.76초(3D 면 더) 멈춘다. **그래서 `requestAnimationFrame` 마다 8 ms 예산 안에서 tick 을 돌리고, 다 돌 때까지 캔버스를 그리지 않는다.** 그동안 본문에 `배치를 계산하는 중…`
- 노드 200개(현재 사용자 데이터 규모)면 0.14초라 한두 프레임에 끝난다
- **회전·확대는 그대로 둔다.** 사용자가 직접 일으키는 조작이라 "움직임을 줄인다"의 대상이 아니다 (결정 13)

### 4.3 노드 상한 2000 (결정 11)

- 넘으면 `truncateGraphByDegree(graph, updatedAtById, 2000)` 으로 **`degree` 큰 순, 같으면 `updatedAt` 최신순**으로 자른다. 1판 5.4 의 함수와 규칙을 그대로 쓴다. 값만 500 → 2000
- 꼬리 줄 안내: `문서가 많아 연결이 많은 2,000개만 보입니다.`
- **링크를 뽑는 대상 문서 수에는 상한이 없다** (1판 5.4 와 같다). 1판 5.1(a) 실측에서 5,000개 22M자에 약 1초였고, `mapIndex.ts` 가 바뀐 문서만 다시 만든다

### 4.4 왜 직접 짜지 않는가

1판은 힘 계산을 직접 짰고, 오늘 그 위에 중심 인력 `(중심까지 거리) × gravity × (1 + √연결수)` 를 넣어 gravity 를 0~0.04 로 바꿔 가며 쟀다. **허브의 중심 거리가 305 → 305 로 전혀 움직이지 않았다**(틀 610). 하드 클램프가 인력을 덮어쓰고 있었다. 이 실험은 되돌렸다.

1판 4장이 이미 "어떤 수십 줄이냐가 결과를 가른다"고 적었다(속도 누적 방식은 600회까지 수렴하지 않았고 FR 방식은 30회에 안정됐다). 거기에 3차원·실시간 파라미터 조절·재가열·노드 고정(끌기)이 더 붙는다. **직접 구현을 고집할 이유가 없다.** 결정 4 를 그대로 따른다.

`OrbitControls` 는 캔버스 **자기 자신**에 리스너를 단다. 캔버스에는 자식 요소가 없어 이벤트는 항상 target 단계에서 끝나고, **그 단계에서는 capture 플래그가 순서에 영향을 주지 않는다 — 등록 순서가 순서다.** 그래서:

1. 캔버스를 만든 뒤 **`new OrbitControls(...)` 보다 먼저** 우리 `pointerdown`·`contextmenu` 리스너를 단다
2. `pointerdown` 에서 `button === 2` 면 레이캐스트한다. 노드에 맞으면 `controls.enabled = false` 로 두고 우리 메뉴를 연다. `pointerup`·메뉴 닫힘에서 `true` 로 되돌린다. 그러면 `OrbitControls` 의 `onPointerDown` 이 1552행에서 곧바로 빠져나가 회전이 시작되지 않는다
3. `controls.enabled` 가 `false` 인 동안에는 `OrbitControls` 의 `contextmenu` 처리도 빠져나간다(1938행). 그래서 **우리 `contextmenu` 리스너가 조건 없이 `preventDefault()` 한다**
4. `stopPropagation()` 에 기대지 않는다 — 같은 요소의 다른 리스너를 막지 못한다

터치 길게 누르기(결정 6)는 `pointerdown` 후 **500 ms** 동안 이동 거리가 10 px 이내면 노드 메뉴를 연다. 그 순간 `controls.enabled = false` 로 두어 회전이 시작되지 않게 한다.

## 6. 화면

### 6.1 노드 크기·깊이·색

**크기 (결정 8).** 1판 공식 `4 + min(degree,16) × 0.5`(4~12px, 최대/최소 3배)는 차이가 안 보였다. 새 공식:

```
반지름(월드 단위) = (3 + 2.2 × √(min(degree, 64))) × 노드_크기_배율
```

| degree | 0 | 1 | 2 | 4 | 9 | 16 | 36 | 64 이상 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 반지름 | 3.0 | 5.2 | 6.1 | 7.4 | 9.6 | 11.8 | 16.2 | 20.6 |

- **최대/최소 비 6.9배** (1판 3배). 면적으로는 47배
- **왜 √인가**: `degree` 는 소수의 허브에 몰린다. 선형이면 허브 하나가 화면을 덮고, 로그면 0 과 1 의 차이가 안 보인다. 점의 **면적**이 값에 비례하게 두는 것이 점 크기 인코딩의 통례다. 현재 사용자 데이터(대부분 degree 0, 몇 개가 1~2)에서도 3.0 대 5.2 로 1.7배라 눈에 띈다
- **64 에서 자르는 이유**: 그 위는 이미 화면에서 가장 큰 점이고, 더 키우면 주변 노드를 가린다
- **3D 원근과 곱해진다.** 멀리 있는 허브가 가까운 고립 문서와 같은 크기로 보일 수 있다. 이것은 3D 를 고른 대가이고, 정확한 연결 수는 노드 호버 툴팁과 `목록` 보기가 준다 (결정 20 이 있는 이유)
- 이 수치는 **시각값이라 e2e 로 고정하지 않는다.** 공식 자체는 `mapNodeStyle.ts` 의 순수 함수라 단위 테스트한다

**깊이 (결정 9).** 카메라와의 거리를 현재 그래프 경계구의 [가장 가까움, 가장 멂] 으로 정규화해, 인스턴스 색을 `--panel` 쪽으로 선형 보간한다. 가장 가까운 노드는 원색, 가장 먼 노드는 `--panel` 과 65% 섞인 색(= 체감 불투명도 35%). fog 를 쓰지 않는 이유는 결정 9 그대로 — 그룹 색이 멀리서 씻기면 색으로 묶음을 구분하는 기능이 죽는다. 여기서도 옅어지기는 하지만 **섞는 상대가 배경색 하나라 그룹 사이 색상 차이(hue)는 유지된다.**

**색.**

| 대상 | 색 |
| --- | --- |
| 그룹에 맞은 문서 | 그 그룹 색 (`--map-group-1`~`-8`, 6.5) |
| 어느 그룹에도 안 맞은 문서 | `--ink` |

### 6.5 `그룹` (결정 15)

- 행마다 **쿼리 입력 + 색 칩 + 삭제**. 아래에 `새 그룹` 버튼
- **위에서부터 먼저 맞는 그룹의 색**을 쓴다. 어디에도 안 맞으면 `--ink`
- **최대 8개** (팔레트 색 수와 같다)
- 매칭은 6.4 와 같은 `parseSearchQuery` + `matchDoc` + `searchIndex`. 빈 쿼리인 그룹은 아무것도 칠하지 않는다
- 끊긴 링크 노드는 문서가 아니므로 그룹 대상이 아니다. 항상 `--muted`

**색 팔레트 — 새 hex 를 쓰지 않는다.** `tokens.css` 에 별칭 여덟 줄만 더한다.

```css
--map-group-1: var(--callout-note);
--map-group-2: var(--callout-tip);
/* … */
--map-group-8: var(--callout-quote);
```

콜아웃 8색은 이미 테마 3종에서 `--panel` 대비 4.5:1 이상으로 맞춰져 있다(`design.md` 3.3, `tokens.css` 48~56·166~173행). **저장값은 hex 가 아니라 팔레트 인덱스 `1`~`8`** 이다 — 테마를 바꾸면 그룹 색도 따라 바뀐다. 임의 색 고르기(color picker)는 두지 않는다. 불변조건("색 hex 는 `brand.config.ts`·`tokens.css` 에만")을 지키는 유일한 방법이다.

### 6.6 `표시` (결정 16 — 셋만)

| `이름표 표시 거리` | 0 ~ 1 (정규값) | 0 | 0 이면 호버할 때만 (6.2) |
| `선 두께` | 0 ~ 1 (정규값) | 0.5 | WebGL `lineWidth` 가 대부분 1px 로 무시되므로 **간선 색의 진하기**로 표현한다 |

**화살표(방향 표시)는 넣지 않는다** (결정 16). 방향은 `목록` 보기의 `나가는 링크`·`들어오는 링크` 묶음으로 본다 (1판 Q6 과 같은 결론).

### 6.7 `장력` (결정 3)

슬라이더는 전부 **0~1 정규값**이고 내부에서 아래 범위로 선형 매핑한다. 그래야 나중에 내부 범위를 조정해도 저장값이 깨지지 않는다.

| 화면 이름 | d3-force-3d 힘 | 출발 범위 | 출발 기본값 |
| --- | --- | --- | --- |
| `중심 장력` | `forceCenter(0,0,0).strength(s)` | 0 ~ 1 | 0.05 |
| `반발력` | `forceManyBody().strength(-s)` | 50 ~ 3,000 | 800 |
| `링크 장력` | `forceLink().strength(s)` | 0.001 ~ 0.1 | 0.02 |
| `링크 거리` | `forceLink().distance(d)` | 30 ~ 500 | 120 |

- 출발점은 참고 구현 `github.com/khuongduy354/obsidian-visualizer-vscode` (MIT, `dev/graph-customization-settings.md`) 의 범위·기본값이다: repulsionForce 100–3000(기본 800), linkDistance 30–500(120), linkStrength 0.001–0.1(0.005), centerForce 0–0.1(0.01). 4.1 벤치마크도 -800 / 120 / 0.05 로 돌렸다
- **이름은 옵시디언 패널의 말을 그대로 쓴다** (사용자가 보여준 스크린샷: 중심 장력 / 반발력 / 링크 장력 / 링크 거리)
- **최종 범위·기본값은 F-2006 이 확정한다.** 사람이 실제로 움직여 봐야 정해지는 값이다
- 슬라이더를 끄는 동안 `alpha(0.3).restart()` 로 재가열한다 (결정 12)

### 6.8 `목록` 보기 (결정 20)

1판 7.4 를 유지·확장한다. **필터와 그룹을 그대로 반영한다** — 걸러진 문서는 목록에도 없다.

| 자리 | 내용 |

| 현재 문서가 있으면 위쪽 | `나가는 링크 ({N})` · `들어오는 링크 ({N})` · `끊긴 링크 ({N})` |
| 그 아래 | `연결이 많은 순` — 제목 · 연결 수 |

- 1판은 `현재 문서` 모드일 때만 묶음을, `전체` 모드일 때만 순위를 보였다. 모드가 없어졌으므로 **둘 다 보인다**

### 6.9 라우팅과 진입 — 바뀌지 않는다

| 해시 | 1판 | 개정판 |
| --- | --- | --- |
| `#/map` | 전체 보기 | 강조 없는 전체 지도 |
| `#/map/{docId}` | 그 문서 중심 **부분 그래프** | **전체 지도 + 그 문서 강조 + 카메라 맞춤** |

- `hashRoute.ts`·`App.tsx` 의 배선은 그대로다. `currentDocId` 를 유지한 채 편집 영역에 `hidden` 을 주는 방식(1판 6.1, F-138 3.2 회귀 방지)도 그대로다. **B14 회귀 테스트를 반드시 남긴다** (10장)
- 모드 전환 세그먼트가 사라졌으므로 `#/map` ↔ `#/map/{id}` 를 오가는 것은 **노드 Ctrl+클릭·노드 메뉴 `여기로 이동`** 뿐이고 여전히 `replaceState` 다
- 사이드바 펼침 아이콘 줄과 접힌 레일의 `지도` 버튼(`hub.svg`)은 그대로다. `e2e/topbar.spec.js:281` 이 레일 5번째 버튼이 `지도` 인 것을 검사하고 있고 **이 검사는 깨지지 않아야 한다**

### 6.10 접근성 — 무엇을 포기하고 무엇으로 갚나

1판 7.3 을 3D 맥락에 맞게 다시 쓴 것이다.

- **캔버스 안 노드는 포커스 대상이 아니다.** 노드가 2,000개면 Tab 순회가 2,000번이 되고, 애초에 WebGL 안에는 포커스를 받을 것이 없다
- 캔버스는 `role="img"` + `aria-label="문서 {N}개, 연결 {M}개의 지도. 같은 내용을 목록으로 보려면 목록 단추를 누르세요."` + `tabindex="-1"` + `outline: none` (마우스 끌기로만 포커스가 들어오므로 테두리를 보일 이유가 없다)
- **대안은 `목록` 보기다** (결정 20). aria-label 이 그 사실을 말한다. 필터·그룹이 목록에도 적용되므로(6.8) 대안이 같은 데이터를 준다
- 이름표 DOM 레이어는 `aria-hidden="true"` 다 — 캔버스 위 장식이고, 같은 제목이 목록에 이미 있다
- 머리 줄·패널의 모든 조작 요소(세그먼트·슬라이더·토글·입력·`맞춤`·`설정`·`닫기`)는 키보드로 닿고 `:focus-visible` 표시를 갖는다. `specs/product.md` 6장 접근성 항목("모든 버튼·토글·목록 항목은 키보드로 조작 가능, 포커스 표시")과 충돌하지 않는다 — 캔버스는 버튼도 토글도 목록 항목도 아니다
- 확대·회전을 키보드로 하지 않는다. `맞춤` 만 있으면 전체를 볼 수 있다

### 6.11 설정 저장 — 키 두 개

`src/app/prefs.ts` 의 허용 키 목록을 읽고 정했다. 값은 전부 문자열이어야 하고, JSON 을 한 키에 넣는 전례가 `md.openFolders`(폴더 id 배열)·`md.account`(객체) 로 이미 있다 (`architecture.md` 4장 137·160행).

| 키 | 값 | 기본 | 무엇이 들어가나 |
| --- | --- | --- | --- |
| `md.mapView` | JSON 객체 | `{}` | 장력 4축 + 표시 3축 + 필터 상태(파일 검색어·폴더 id 배열·고립·끊긴 링크·몇 다리) |
| `md.mapGroups` | JSON 배열 | `[]` | `[{ q: "tag:일기", c: 3 }, …]` — 쿼리 문자열과 팔레트 인덱스(1~8). 최대 8개 |
| ~~`md.mapDepth`~~ | — | — | **삭제한다.** 단계 세그먼트가 사라지고 깊이가 `md.mapView` 안으로 들어간다 |

- **왜 둘로 나누나**: 그룹은 사용자가 만든 **목록**이고 나머지는 기본값이 있는 **스칼라**다. 슬라이더 `기본값으로` 가 사용자가 만든 그룹까지 지우면 안 된다. 또 그룹 JSON 이 깨져도 슬라이더 값은 살아남는다
- `mapPrefs.ts` 가 읽을 때 **모르는 키는 버리고 범위를 벗어난 값은 기본값으로 되돌린다.** 파싱 실패도 기본값. 이 검증은 순수 함수라 단위 테스트한다
- `md.mapDepth` 를 허용 키에서 지우면 기존 브라우저의 localStorage 에 그 항목이 남는다. **그대로 둔다** — `prefs.ts` 는 허용 키만 읽으므로 아무도 보지 않고, 지우려면 `prefs.ts` 에 없는 삭제 함수를 새로 만들어야 해서 얻는 것보다 손이 많이 간다
- 설정은 **계정과 무관하게 이 브라우저에 남는다.** 서버에 올리지 않는다

## 7. 성능·번들 게이트

**아래는 아직 재지 않은 값이고, 구현할 때 판정한다.** 잰 값(4.1 의 d3-force 2D, 3.1·3.3 의 번들 실측)과 구분해 읽는다.

| # | 무엇을 | 목표 | 어느 소명세가 |
| --- | --- | --- | --- |
| G1 | **초기 로드 gzip** | **690,570 B 에서 늘지 않는다** | F-2002 |
| G2 | 지도 청크 gzip | +198 KB 이내 | F-2002 |
| G3 | 지도 청크 raw 크기 | 3 MiB 미만 (`maximumFileSizeToCacheInBytes`). 넘으면 precache 에서 조용히 빠져 오프라인 지도가 죽는다 | F-2002 |
| G4 | 지도 화면 틀이 보이기까지 | 100 ms | F-2002 |
| G5 | **배치가 멈출 때까지** (노드 2,000) | **3,000 ms** | F-2002 |
| G6 | **회전 중 fps** (노드 2,000, 시뮬레이션 정지 상태) | **평균 55 fps 이상, 최악 프레임 33 ms 이하** | F-2003 |
| G7 | 시뮬레이션이 도는 동안 fps (노드 2,000) | 평균 30 fps 이상 | F-2006 |

**재는 법.** G1~G3 은 `npm run build` 결과 파일 크기다. G4~G7 은 `scripts/measure.mjs` 가 이미 갖고 있는 `--eval`(페이지 안에서 임의 식 실행)·`--action` 으로 잰다(1~60행 확인). 다만 문서를 하나만 넣을 수 있으므로 **F-2002 가 `--docs {문서 수}:{문서당 링크 수}` 옵션을 더한다.** fps 는 `requestAnimationFrame` 60프레임의 간격을 모아 평균·최댓값을 낸다. 임시 스크립트를 따로 짜지 않는다 (`CLAUDE.md` "구현 서브에이전트 규칙").

**G4·G5 의 100 ms / 3,000 ms 는 이 프로젝트에서 실측해 정한 값이 아니다.** 응답 시간에 대한 널리 쓰이는 통념(0.1초 = 즉각 반응, 1초 = 생각의 흐름이 안 끊기는 한계. Miller 1968 / Nielsen 1993 의 구분으로 알려져 있다)에 기대었고, 1판 5.4 와 F-284 5.1 이 쓴 것과 같은 기준이다. **1판은 "그래프가 그려지기까지 1,000 ms" 였는데 3,000 ms 로 늘렸다** — 1판은 계산이 끝나야 처음 그림이 나왔지만 개정판은 첫 프레임이 곧바로 뜨고 그 위에서 자리가 잡혀 가므로, 기준을 "보이기까지"가 아니라 "멈출 때까지"로 바꿨다. G6 의 55 fps 도 통념(60 fps 목표에서 몇 프레임 흘리는 것은 눈에 띄지 않는다)이다.

**넘으면 순서대로**: (1) 노드 상한 2,000 → 1,000 (2) `alphaDecay` 를 키워 tick 수를 줄임 (3) 화면 밖 간선을 그리지 않음 (4) 노드 구체 분할 수를 낮춤 (5) 웹 워커로 시뮬레이션 이전. (5) 까지 안 되면 설계를 재검토한다. **(1)~(4) 는 게이트 결과만으로 소명세가 판단하고, (5) 는 명세를 먼저 고친다.**

## 12. 열린 질문 — 전부 답을 받았다 (2026-09-21)

### Q1. `1~3단계`(몇 다리) 를 필터 항목으로 살릴 것인가 — **답: 살린다** (2026-09-21)

| 없앤다 | 결정 17 을 글자 그대로 따른다. 옵시디언 전역 그래프에도 깊이 조절이 없다(로컬 그래프는 별도 뷰다) | 특정 문서 주변만 보는 길이 사라진다. 노드 메뉴 `이어진 문서만 보기` 도 같이 사라진다 |

**다른 쪽을 고르면**: 6.4 표의 마지막 행과 5장 노드 메뉴의 `이어진 문서만 보기` 를 뺀다. `distancesFrom` 은 여전히 필요하다(호버 시 이웃 이름표가 거리 1 을 쓴다). F-2007 범위가 조금 줄고 B20 이 없어진다.

### Q2. 노드 끌기를 허용할 것인가 — **답: 허용한다** (2026-09-21, 기본값대로)

1판은 "노드는 못 옮긴다"였다. 결정 12 가 "노드 끌기에 재가열"이라 못 박았으므로 뒤집는다. **다른 쪽을 고르면**: 끌기를 막고 재가열은 슬라이더에서만 일어난다. F-2004 에서 끌기 몫이 빠지고 레이캐스트가 클릭·호버에만 쓰인다. 다만 결정 12 의 문장과 어긋나므로 바꾸려면 결정 12 도 함께 고쳐야 한다.

### Q3. 회전에 관성(damping)을 줄 것인가 — **답: 준다** (2026-09-21)

`OrbitControls.enableDamping` 기본값이 `false` 인 것을 확인했다(209행). 끄면 손 떼는 순간 정지해서 rAF 루프가 시뮬레이션과 같이 멈추지만, 목적이 **재미**(결정 1)인데 관성 없는 회전은 뻣뻣하다. **사람이 켜는 쪽을 골랐다.**

그래서 `enableDamping = true`, `dampingFactor` 는 `0.08` 로 시작한다. `controls.update()` 가 `false` 를 돌려줄 때까지(움직임이 `EPS` 아래로 떨어질 때까지) rAF 를 유지하고 그 뒤 멈춘다 — "안정되면 멈춘다"(결정 12)는 이 판정으로 지킨다. 시뮬레이션 tick 과는 여전히 별개다. F-2003 이 그 판정 코드를 갖는다. **0.08 이라는 값 자체는 돌려 봐야 아는 것이라 B22 사람 확인으로 넘긴다.**

### Q4. 설정 키를 둘로 나눌 것인가 — **답: 둘 (`md.mapView`·`md.mapGroups`)** (2026-09-21)

하나로 합치면 키가 하나로 줄지만, 슬라이더 `기본값으로` 가 사용자가 만든 그룹 목록까지 지울 위험이 생기고 한쪽 JSON 이 깨지면 다 날아간다. **다른 쪽을 고르면**: `md.mapView` 하나에 `groups` 배열을 넣고 `mapPrefs.ts` 가 초기화 범위를 키 단위가 아니라 필드 단위로 판단하게 한다.

### Q5. 노드 상한 2,000 을 유지할 것인가 — **답: 2,000 유지** (2026-09-21)

4.1 실측(d3-force 2D)에서 2,000 노드 tick 이 5.87 ms 다. 3D 는 더 느리고 **아직 재지 않았다.** G5·G7 게이트에서 넘으면 1,000 으로 낮춘다 — 그 판단은 7장 "넘으면 순서대로"에 따라 사람 승인 없이 F-2002 가 게이트 결과로 내린다.

1. **`three@0.186.0`(정확 고정) + `d3-force-3d@^3.0.6` + `@types/three@0.186.0` + 로컬 `src/types/d3-force-3d.d.ts`.** 그 밖의 패키지는 설치하지 않는다 — 3.2

17. **e2e 판정 통로는 `목록` 보기와 꼬리 줄 숫자다. 테스트 전용 API 를 제품 코드에 넣지 않는다** — 11장
