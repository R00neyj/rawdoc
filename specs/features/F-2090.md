# F-2090 사이드바 하단 한 줄 — 계정·설치·도움말 메뉴·설정

작성일: 2026-09-29
상태: **승인 대기.** 사용자 보고(2026-09-29) — 작은 모니터에서 넓은 사이드바 아래 `앱 설치`·`도움말`·`사용법`·`설정` 네 행이 목록 자리를 먹는다. 같은 날 grill 로 아래 "정해진 것" 열 가지를 사용자가 정했다(Obsidian 아래 볼트 줄 방식). 이 명세가 새로 정하는 것: `?` 메뉴 컴포넌트와 키보드(4.2), 계정 팝오버가 위로·옆으로 열리는 자리와 폭(4.3), 휴대폰 계정 탭의 결과(4.5), 계정 이름 자르기(4.1), 배선과 App.tsx 증가량(1장), 겹침 사이드바 안 `Esc` 한 번 규칙(4.6), 비게 된 ⋯ 버튼(4.7). 열린 질문 9장은 모두 기본값이 있다
구현 담당: `feature-implementer`. 동시에 진행 중인 명세 없음. 방금 들어간 tweak(`fb9a3ec`, `.phone-nav .icon-btn` 44px)과 같은 `src/styles/app.css` 를 만지지만 규칙이 겹치지 않는다(`.phone-nav` 규칙은 건드리지 않는다)
되돌리는 것: tweak 2026-09-29 "휴대폰 폭 사이드바 — 도움말·사용법·설정은 ⋯ 판"(`app.css` ≤600px 블록의 `.sidebar-bottom > :not(.sidebar-install-row) { display: none }`, `topBarMore.ts` `moreSheetItems` 의 `settings`·`help`·`guides`)을 이 명세가 되돌린다

## 정해진 것 (2026-09-29 사용자 grill, 바꾸지 않는다)

1. 데스크톱 넓은 사이드바 하단은 **한 줄**: 왼쪽 계정, 오른쪽 아이콘 버튼들
2. `도움말`·`사용법` 은 `?` 아이콘 **하나**로 묶고, 누르면 작은 메뉴(새 메뉴)
3. `?` 메뉴 항목: `도움말`(기존 도움말 화면) · `사용법` ↗(`GUIDES_PATH`) · `새 소식` ↗(사이트 `/changelog`). 단축키·의견 보내기는 넣지 않는다
4. `앱 설치` 는 설치 가능할 때만(`canInstall`) 같은 줄 아이콘 하나
5. 계정(`AccountMenu`)을 상단바에서 **사이드바 하단 왼쪽으로 옮긴다**. 상단바에서는 빠진다
6. 로그인 안 한 상태면 그 자리에 `로그인` 버튼
7. 알림(`NotificationsMenu`)은 상단바에 그대로
8. 접힌 레일(`sidebar-rail-bottom`)은 기존 아이콘(설치·도움말·사용법·설정) **그대로**, 맨 아래에 계정 아이콘 하나만 추가. 펼침(`?` 메뉴)과 레일(아이콘 둘)의 모양이 다른 것은 사용자가 받아들였다
9. 휴대폰(≤600px)도 통일: 사이드바 맨 아래, 기존 동작 줄(검색·새 문서·새 폴더·가져오기·모두 접기·지도 6칸) **밑에** 계정·⤓·?·⚙ 줄
10. 휴대폰 상단바 `⋯` 판(F-2083)에서 계정·설정·도움말·사용법 행 제거 → 목차·댓글·공유·내보내기·알림만 남는다

## 4. 동작

### 4.1 하단 줄 — 계정 자리 (펼침·겹침·휴대폰 공통)

| 계정 상태 | 왼쪽 자리 | 누르면 |
| --- | --- | --- |
| `in` | `👤 a@b.com` | 계정 메뉴(4.3) |
| `offline` + 저장된 이메일 | `👤 a@b.com` | 계정 메뉴 — 머리 줄에 `오프라인`, 동작 항목 없음(지금 그대로) |
| `offline` + 저장된 이메일 없음(부팅 직후 포함) | `👤 계정` | 계정 메뉴 — `오프라인` 줄만 |
| `out` | `→ 로그인` | 곧바로 로그인 이동. 메뉴 없음(정해진 것 6) |

- **이메일 자르기**: 한 줄, 끝을 `…` 로 자른다(`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`, 트리거 `min-width: 0` 으로 줄어들 수 있게). 이메일 전체는 메뉴를 열면 첫 줄(`.account-menu-email`, 줄바꿈 허용)에 보인다. 트리거 `title` 은 달지 않는다 — 앱 툴팁은 `IconTooltip` 한 가지다. 자르는 위치는 9장 Q3
- 폭 계산(6장 초안 값): 사이드바 최소 200px 에서 줄 안쪽 폭 184px(왼쪽 안쪽 여백 10 + 오른쪽 6 제외), 오른쪽 아이콘 셋(설치 포함) 32×3 + 간격 4×3 = 108px → 계정 버튼 76px, 아이콘 18 + 간격 6 을 빼면 이메일 약 46px(13px 글자 약 6자). 기본 300px 에서는 이메일 약 146px(약 20자). 휴대폰 390px(사이드바 85% = 331px)은 아이콘 44px 라 이메일 약 125px

### 4.2 `?` 메뉴 — 틀·방향·키보드 (반드시 결론)

**결론: `ExportMenu.tsx` 틀을 그대로 따르는 새 파일 `src/app/HelpMenu.tsx`.** 항목이 고정이고 딸린 상태(GET·대화상자)가 없어 `ExportMenu` 와 같은 모양이다. `ShareMenu`(딸린 GET·대화상자)·`NotificationsMenu`(열림 상태 주인이 App)는 맞지 않는다

- 여닫기: 트리거 클릭·`Enter`·`Space` 로 여닫는다(`aria-expanded`). 바깥 `mousedown` 은 닫기만 하고 포커스를 옮기지 않는다
- 여는 방향: **위로**. 목록 아래 끝 = 하단 줄 위 끝 − 4px, 오른쪽 끝 = 하단 줄 오른쪽 끝(6장). 아래로 열면 창 밖으로 나가고 `.sidebar-inner` 의 `overflow: hidden` 에 잘린다
- 포커스: 열면 첫 항목(`도움말`). `↓`·`↑` 는 세 항목을 순환(끝에서 처음으로). `Esc` 는 `preventDefault` 하고 닫은 뒤 트리거로 포커스 — 겹침 사이드바는 닫히지 않는다(4.6). `Tab` 은 가로채지 않는다(`ExportMenu` 와 같게 — 목록은 바깥 누르기 전까지 열려 있다)
- 고르기:
  - `도움말` → 닫기 → 트리거 포커스 → `onOpenHelp()`(= `useDocNavigation` `openHelp`: `#/help` 로, 겹침 사이드바는 거기서 닫힌다)
  - `사용법`·`새 소식` → 링크 기본 동작(새 탭)을 막지 않고, 같은 클릭에서 목록을 닫고 트리거로 포커스. 사이드바는 그대로 둔다(지금 `사용법` 링크와 같다)
- 레일에는 `?` 메뉴가 없다(정해진 것 8)

### 4.3 계정 팝오버 — 자리와 폭 (반드시 결론)

| 어디서 여나 | 목록 자리 | 폭 |
| --- | --- | --- |
| 펼친 사이드바 하단 줄(1024px 이상) | **위로.** 아래 끝 = 하단 줄 위 끝 − 4px, 왼쪽 끝 = 하단 줄 왼쪽 끝 | `min(100%, 280px)` — 100% 는 하단 줄 폭. 최소 폭 규칙(`min-width: 200px`)은 이 변형에서 없앤다(사이드바 200px 에서 줄 폭이 184px) |
| 겹침 사이드바 하단 줄(601~1023, ≤600) | 위와 같다 — 겹침 사이드바 안(`z-index` 35 층위 맥락 안)에서 목록이 사이드바 위에 뜬다 | 위와 같다. 휴대폰 390px 에서 약 315px 줄 → 280px |
| 레일 계정 아이콘(1024px 이상 접힘) | **오른쪽으로.** 왼쪽 끝 = 레일 버튼 오른쪽 끝 + 8px, 아래 끝 = 레일 버튼 아래 끝 | 240px 고정, 최대 `calc(100vw - 64px)` |

- 목록 모양(바탕·테두리·모서리·그림자·항목 모양)은 지금 `.account-menu-list` 그대로. 전환은 방향만 뒤집는다 — 줄에서 열 때 닫힘 `translateY(4px) scale(0.9)`·`transform-origin: bottom left`, 레일에서 열 때 닫힘 `translateX(-4px) scale(0.9)`·`transform-origin: bottom left`. 움직임 줄이기는 기존 규칙 그대로
- 줄 변형은 목록을 **하단 줄 기준**으로 놓는다(`.sidebar-bottom` 이 위치 기준, `.account-menu--row` 는 위치 기준이 아니다). `?` 메뉴도 같은 기준이라 두 목록이 줄 양 끝에 맞는다. 트리거 기준으로 놓지 않는 이유: 계정 버튼 폭이 사이드바 폭에 따라 76~460px 로 바뀌고, `?` 는 줄 오른쪽 끝 근처라 트리거 기준 오른쪽 맞춤이면 사이드바 200px 에서 목록 왼쪽이 `.sidebar-inner` 밖으로 나가 잘린다(9장 Q8)
- 레일은 `.sidebar--collapsed .sidebar-inner { overflow: visible }` 라 목록이 본문 쪽으로 나가도 잘리지 않는다. 층위 30(지금 값) — 본문 쪽 떠 있는 것(목차·댓글 달기 20)보다 위
- 열면 포커스 = 첫 동작 항목(지금 그대로). 동작 항목이 없으면(`offline`) 포커스는 트리거에 남는다(지금 그대로). `↑↓`·`Esc`·바깥 `mousedown` 은 지금 그대로. `Esc` 는 4.6

### 4.4 계정 항목 뒤 — 사이드바 닫기와 대화상자

- 항목 동작 순서: 목록 닫기 → 트리거 포커스 → 동작(지금 `closeThen`) → `afterSelect?.()`. App 은 `afterSelect` 에 `closeSidebarIfNarrow` 를 준다
  - `공유 관리` → `#/shares` 로 간 뒤 겹침 사이드바가 닫힌다. 안 닫으면 휴대폰에서 85% 사이드바가 공유 관리 화면을 가린 채 남는다(`useHashRouting` shares 갈래는 사이드바를 닫지 않는다 — 근거 절)
  - `API 토큰` → 대화상자를 연 뒤 사이드바가 닫힌다(ia.md 3.11 3번 "대화상자 표시 시 사이드바는 닫힌다")
  - `로그인`·`로그아웃` → 페이지가 바뀐다. `afterSelect` 가 불려도 해가 없다
  - 1024px 이상(겹침 아님)에서 `closeSidebarIfNarrow` 는 `setSidebarOpen(false)` 만 하고 펼침·레일(`collapsed`)은 건드리지 않는다
- **`ApiTokensDialog` 를 `document.body` 포털로 그리는 이유**: 겹침 사이드바가 닫히면 `Sidebar.tsx` 가 `nav` 에 `inert` 를 단다. `inert` 는 그 아래 모든 자손에 걸리고 모달 `<dialog>` 의 최상위 층도 DOM 트리를 벗어나지 않는다 — 사이드바 안에 그린 대화상자는 사이드바가 닫히는 순간 누를 수 없게 된다(HTML 명세 기준, 브라우저로 재 보지 않음 — E1 3번이 판정한다). 포털이면 바깥 누르기 판정(`sidebarRef.contains`)에서도 사이드바 밖이라 대화상자 안을 누를 때 사이드바가 먼저 닫혀도 대화상자는 멀쩡하다
- 대화상자를 닫으면 포커스는 `Dialog.tsx` 규칙대로 열 때의 `activeElement`(계정 트리거)로 돌아간다. 겹침 사이드바가 이미 닫혀 트리거가 `inert` 면 `body` 로 간다 — 지금 `설정`(사이드바 버튼 → 사이드바 닫힘 → D-2)과 같다

### 4.5 휴대폰(≤600px) 사이드바 (반드시 결론)

- 줄 순서: 목록 → 동작 줄(6칸, `order: 1`) → **하단 줄(`order: 2`) 계정 · ⤓ · ? · ⚙**
- **계정을 누르면: 같은 `AccountMenu` 팝오버가 하단 줄 위로 열린다(4.3).** ⋯ 판의 계정 하위 화면은 없어진다
  - 이유: 넓은 창·겹침·휴대폰이 한 컴포넌트·한 DOM 이 되고 e2e 선택자(`menuitem`)가 폭마다 같다. ⋯ 판 계정 보기(`AccountInfoRows` + `useAccountMenu` 를 판 행으로 그린 것)를 다시 쓰려면 사이드바 안에서 아래 판(`<dialog>`)을 새로 띄워야 하고, 판 여닫기·포커스 규칙(F-2083 4.4)을 한 벌 더 옮겨야 한다. 팝오버는 줄 폭 약 315px·높이 최대 5행이라 390×844 에 들어간다
  - 손가락: `(pointer: coarse)` 에서 `.account-menu-list button`·`.help-menu-list :is(button, a)` 최소 높이 44px(지금 빠져 있던 것을 더한다)
- `?` 도 같은 팝오버가 위로. `도움말` 을 고르면 `openHelp` 가 사이드바를 닫는다
- 하단 줄 아이콘 버튼은 44×44, 음수 여백 없음(동작 줄 `.sidebar-actions .icon-btn` 과 같은 방식 — 기본 터치 규칙 `margin: -6px` 를 이 줄에서 0 으로)
- 사이드바가 열린 동안 하단 알약(F-2086)은 이미 숨는다 — 겹치지 않는다

### 4.6 겹침 사이드바 안 `Esc` — 한 번은 한 가지 (반드시 결론)

- `useSidebarLayout` 의 겹침 사이드바 `Esc` 닫기는 **`e.defaultPrevented` 가 참이면 아무것도 안 한다**
- 계정·`?` 메뉴의 `Esc` 처리는 지금처럼 `preventDefault` 한다. React 가 `#root` 에서 먼저 처리하므로 `document` 듣개가 돌 때는 이미 `defaultPrevented` 다(근거 절)
- 결과: 겹침 사이드바 안에서 메뉴가 열린 채 `Esc` → 메뉴만 닫히고 포커스는 트리거, 사이드바는 열린 채. 한 번 더 `Esc` → 사이드바가 닫힌다. 같은 이유로 항목 `⋯` 메뉴(`FolderMenu`)도 이제 메뉴만 닫힌다(지금은 사이드바까지 닫힌다 — 코드 읽기)
- 모든 메뉴에 `stopPropagation` 을 다는 안은 9장 Q6

### 4.7 ⋯ 판 (휴대폰)

- `moreSheetItems` 결과: `doc` → 목차(제목 있을 때)·댓글(접근 있을 때)·공유·내보내기·알림(켜졌을 때). `home`·`other` → 알림(켜졌을 때)만
- **`moreButtonVisible` 이 거짓이면 ⋯ 버튼을 그리지 않는다.** `home`·`other` 에서 알림이 꺼져 있으면(로그인 안 함·로컬 저장소) 판에 행이 하나도 없다 — 빈 판을 여는 버튼을 두지 않는다. `doc` 은 공유·내보내기가 늘 있어 늘 보인다
- 점(`moreDotVisible`)은 그대로 — 버튼이 없을 때는 점 조건도 늘 거짓이다(알림 꺼짐이고 `doc` 아님)
- 팔레트 `알림 열기` 로 판을 알림 하위 화면으로 여는 길(F-2083 4.4)은 알림이 켜졌을 때만 있으므로 그때는 버튼도 있다

## 9. 열린 질문 (모두 기본값 있음)

### Q1. `?` 버튼 이름 — **기본값: `도움말 메뉴`**
- 이유: 항목 `도움말` 과 트리거가 같은 이름이면 화면 읽기 프로그램이 "도움말 버튼 → 도움말 메뉴 항목" 을 구별하지 못하고, e2e 의 `getByRole('button', { name: '도움말' })` 가 트리거와 레일 버튼을 같이 잡는다. 앱의 다른 묶음 버튼이 `… 메뉴`(`댓글 메뉴`·`{폴더} 메뉴`·⋯ `메뉴`) 꼴이다
- 다른 쪽을 고르면: `도움말`(항목과 같음) — 5.1 표·E2·10장 `openHelpFromSidebar` 의 이름만 바뀐다. `도움말·사용법` — 같은 곳 이름만 바뀐다

### Q2. 휴대폰 계정 탭 — **기본값: 같은 팝오버를 위로(4.5)**
- 이유: 4.5
- 다른 쪽(⋯ 판에서 쓰던 계정 보기를 아래 판으로): 사이드바 하단 계정이 모달 `<dialog>` 아래 판을 연다. `SidebarFooter` 가 폭(`usePhoneWidth`)으로 갈라 판 컴포넌트를 그리고, F-2083 4.4 의 판 여닫기·포커스 규칙을 옮겨 새 판 컴포넌트(또는 `TopBarMoreSheet` 의 계정 하위 화면을 떼어 낸 것)가 소유표에 는다. E3 2~4번이 판 기준으로 바뀌고, 4.6 의 `Esc` 규칙 대신 판 `cancel` 이 맡는다

### Q3. 이메일 자르기 — **기본값: 이메일 전체, 끝을 `…`**
- 이유: CSS 한 줄로 되고, 지금 사이드바 글자(`.sidebar-btn-label`) 규칙과 같다. 앞부분(아이디)이 먼저 보여 알아보기 쉽다
- 다른 쪽을 고르면: (a) `@` 앞만 보인다 — `accountTrigger` 의 `text` 규칙과 U2 가 바뀐다. 같은 아이디의 다른 도메인 계정(개인·회사)을 구별 못 한다. (b) 가운데 말줄임(`abcd…@b.com`) — CSS 로 안 되어 글자 수로 자르는 순수 함수가 는다. 폭이 사이드바 너비에 따라 바뀌어 글자 수 기준이 폭과 안 맞는다

### Q4. 행이 없는 ⋯ 버튼 — **기본값: 그리지 않는다(4.7)**
- 이유: 빈 판을 여는 버튼은 누를 이유가 없다. 로그인 안 한 휴대폰 홈·도움말·지도 화면에서 상단바가 `☰`(+ 제품 아이콘)만 남는다
- 다른 쪽(늘 둔다): 빈 판에 안내 문구가 필요해진다(새 문구·ia.md 행). `moreButtonVisible` 과 U3 의 해당 행, `topbarMore.spec.js` `F-2083 E1` 홈 단계 기대가 바뀐다

### Q5. 레일에서 로그인 안 한 상태 — **기본값: `로그인` 아이콘(누르면 곧바로 이동)**
- 이유: 정해진 것 6(펼침은 `로그인` 버튼)과 한 규칙. 로그인 안 한 계정 메뉴에는 항목이 `로그인` 하나뿐이라 메뉴를 거칠 이유가 없다
- 다른 쪽(계정 아이콘 + 메뉴 안 `로그인`): 레일만 지금 모양이 된다. 3.4 표 레일 `login` 칸이 `menu` 와 같아지고 `accountTrigger` 결과를 레일에서 다르게 읽는 갈래가 는다

### Q6. 겹침 사이드바 `Esc` 한 가지 — **기본값: `useSidebarLayout` 이 `defaultPrevented` 를 본다(4.6)**
- 이유: 한 곳 한 줄로 계정·`?`·항목 `⋯` 메뉴가 모두 맞는다. 메뉴 쪽은 이미 `preventDefault` 한다
- 다른 쪽(각 메뉴가 `stopPropagation`): `useSidebarLayout` 은 그대로, `AccountMenu`·`HelpMenu`(그리고 원하면 `FolderMenu`)의 `Esc` 에 한 줄씩. `document` 에 붙은 다른 전역 키 듣개(단축키 등)도 그 `Esc` 를 못 보게 된다

### Q7. `ApiTokensDialog` 자리 — **기본값: `document.body` 포털(4.4)**
- 이유: 4.4. 겹침 사이드바를 닫아도 대화상자가 살아 있다
- 다른 쪽(사이드바 안에 두고 `API 토큰` 뒤에는 사이드바를 닫지 않는다): `afterSelect` 를 `공유 관리` 에만 부른다. 대화상자 `Esc` 가 사이드바 `Esc` 닫기와 겹쳐(대화상자 `Esc` 는 React 가 `preventDefault` 하지 않는다) 두 개가 같이 닫힌다 — 그 예외를 `useSidebarLayout` 조건에 따로 더해야 한다

### Q8. 팝오버 기준점 — **기본값: 하단 줄 기준(4.3)**
- 이유: 4.3. 사이드바 200px 에서도 잘리지 않고 두 목록이 줄 양 끝에 맞는다
- 다른 쪽(트리거 기준): 계정 목록은 계정 버튼 왼쪽 끝(거의 같은 자리), `?` 목록은 `?` 오른쪽 끝에 붙는다 — 사이드바 200~240px 에서 `?` 목록 왼쪽이 `.sidebar-inner` 밖으로 나가 잘린다. 막으려면 `?` 목록 폭을 `calc(사이드바 폭 − …)` 로 따로 계산해야 한다

### Q9. `새 소식` 아이콘 — **기본값: `campaign`(확성기)**
- 이유: Material Symbols 에 `new_releases` 가 이 패키지에 없다(목록 확인). `update`·`history` 는 되돌리기·기록과 헷갈린다
- 다른 쪽을 고르면: `icons.tsx` 의 import 한 줄만 바뀐다
