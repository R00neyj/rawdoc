# F-2142 칸반 카드 끌어 옮기기와 휴대폰 보드

작성일: 2026-10-14
상태: 승인 대기. 개요 F-2138 4장. 마우스·터치 끌기, 키보드 옮기기, 휴대폰 폭(≤600px) 모양. 의존성 없이 포인터 이벤트 한 길. 구현 담당 `feature-implementer`. `App.tsx` 변경 없음

## 근거 (2026-10-14 HEAD, 이름으로 찾는다)
- 사이드바 트리 끌기(`Sidebar.tsx` `onDragStart`)는 HTML5 끌어놓기라 휴대폰 길게 누르기·자동 스크롤 선례가 아니다. 보드는 마우스·터치·펜을 포인터 이벤트 한 길로 짜 휴대폰 갈래를 따로 두지 않는다(`kanban-list.html` 의 `draggable` 은 동작 참고용). 터치에서 HTML5 끌기가 도는지는 재 보지 않았다
- `src/app/useEdgeSwipe.ts`(사이드바)·`useOutlineSwipe.ts`(오른쪽 패널)가 `shell` 의 `touchend` 에서 밀기를 판정한다. 보드가 맨 왼쪽(`scrollLeft` 0)이면 `hasScrollableLeftAncestor` 가 거짓이라, 카드를 오른쪽으로 56px 넘게 끌면 `classifySwipe` 가 `open` 을 낸다 — 끄는 동안은 판정을 건너뛰어야 한다
- `src/app/edgeSwipe.ts` `DRAG_AXIS_SLOP_PX = 8`
- 같은 칸 안 놓을 자리 보정은 프로토타입 `drop` 처리(`drag.card < idx` 면 하나 뺌)와 같다 — F-2139 `to.index` 가 "뺀 뒤 자리" 라 그 보정을 이 명세의 순수 함수가 맡는다

## 2. 계약
```ts
export const KANBAN_PICKUP_MOUSE_PX = 4      // 마우스는 이만큼 움직이면 집는다
export const KANBAN_LONG_PRESS_MS = 400      // 터치·펜은 이만큼 누르고 있으면 집는다
export const KANBAN_EDGE_PX = 48             // 가장자리 자동 스크롤 띠
export type PickupInput = { pointerType: 'mouse' | 'touch' | 'pen'; dx: number; dy: number; elapsedMs: number }
export function pickupState(p: PickupInput): 'wait' | 'pick' | 'cancel' // 터치가 400ms 전에 8px 넘게 움직이면 cancel(스크롤로 넘김)
export function dropSlot(cardMids: readonly number[], y: number): number  // 끄는 카드를 뺀 목록의 세로 가운데들 → 0..길이
export function moveTarget(from: { lane: number; card: number }, lane: number, slotWithDragged: number): { lane: number; index: number } // 같은 칸이면 뒤 자리 하나 뺌
export function edgeScroll(pos: number, start: number, end: number): number // 띠 안이면 -12~12 px/프레임, 가장자리에 가까울수록 크게, 밖이면 0
```

## 3. 끌기
- 카드 `pointerdown`(체크 칸·입력칸·`카드 추가` 위는 제외, 읽기 전용이면 없음) → `pickupState` 로 집기. 집으면 `setPointerCapture`, 원래 카드 자리는 `.kanban-card--dragging`(흐리게), 손가락·커서를 따라가는 복제 `.kanban-drag-ghost`(`position: fixed`), 놓을 자리 `.kanban-drop-marker`. `.kanban-board` 에 `data-dragging`
- 놓을 칸 = 포인터 x 가 든 `.kanban-lane`, 자리 = `dropSlot`. 칸 밖이면 표지가 사라지고 놓아도 아무 일 없음
- 끄는 동안 `.kanban-lanes` 가로·그 칸 목록 세로를 `edgeScroll` 로 rAF 마다 민다
- `pointerup` → `moveTarget` → F-2139 `moveCardChanges` → `applyKanban(…, 'kanban.move')` 한 번. 제자리면 쓰지 않는다. `Esc`·`pointercancel` 은 취소
- 집은 카드 위치는 F-2141 자리 추적과 같이 `onChanges` 로 옮기고, 끄는 사이 그 카드가 지워지면 끌기를 조용히 끝낸다
- 터치: 집기 전에는 브라우저 스크롤 그대로(`touch-action: pan-x pan-y`), 집은 뒤에는 `touchmove` 기본 동작을 막는다. 카드에서 길게 눌러 뜨는 `contextmenu` 는 막는다
- 옮긴 뒤 포커스는 옮긴 카드. 화면 낭독기용 `aria-live="polite"` 줄 `.kanban-live`: `{카드 글자} — {칸 이름} {n}번째`

## 4. 키보드와 휴대폰 폭
- 카드 포커스에서 `Alt+↑`·`Alt+↓` 같은 칸 한 칸 위·아래, `Alt+←`·`Alt+→` 옆 칸의 같은 자리(길이보다 크면 끝). 맨 끝에서는 아무 일 없음. `↑`·`↓` 는 같은 칸 카드 사이, `←`·`→` 는 옆 칸 같은 자리 카드로 포커스만 옮긴다
- **휴대폰 폭(≤600px)**: 칸은 화면 폭의 85%(최대 320px), `.kanban-lanes` 는 `scroll-snap-type: x mandatory` 로 칸 하나씩 멈추고 다음 칸 끝이 보인다. 칸 목록은 그 칸 안에서 세로로 스크롤한다. 집는 건 길게 누르기뿐, 놓을 자리가 화면 가장자리면 `edgeScroll` 로 옆 칸으로 넘어간다. `칸 추가` 는 마지막 칸 다음 좁은 자리에
- 휴대폰 폭에서 보드가 보이는 동안 서식 바·`댓글` 은 F-2140 그대로 없다
