*브라우저가 하는 일 (공격 표면)*
- (M1) **규칙 종류 이름.** `Object.prototype.toString.call(rule)` 의 `[object X]` 의 X 가 `rule.constructor.name` 과 23종 모두 같다: `CSSStyleRule` `CSSNestedDeclarations` `CSSMediaRule` `CSSSupportsRule` `CSSContainerRule` `CSSLayerBlockRule` `CSSLayerStatementRule` `CSSKeyframesRule` `CSSKeyframeRule` `CSSFontFaceRule` `CSSPageRule` `CSSMarginRule` `CSSStartingStyleRule` `CSSScopeRule` `CSSViewTransitionRule` `CSSPropertyRule` `CSSCounterStyleRule` `CSSFontFeatureValuesRule` `CSSFontPaletteValuesRule` `CSSPositionTryRule` `CSSFunctionRule` `CSSFunctionDeclarations` (+ `CSSNamespaceRule`)
- (M2) **`replaceSync` 결과.** `@import`·`@charset` 는 사라진다. `@namespace` 는 남고 `sheet.deleteRule` 이 `InvalidStateError` 를 던진다. `@property` 는 `initial-value: url(http://…)`, `@function` 은 `result: url(http://…)` 를 그대로 남긴다. 중첩 규칙 뒤 선언은 `CSSNestedDeclarations`, `@page` 안 `@top-left` 은 `CSSMarginRule`. 일반 속성은 `\75 rl(…)`·`URL(…)` → `url("…")`, `-webkit-image-set`·`image-set("…")` → `image-set(url("…"))` 로 정규화되지만 **사용자 정의 속성과 `var()`·`env()`·`if()` 가 든 일반 속성은 원문 그대로 남는다**
- (M3) **실제 요청.** 원문을 그대로 넣었을 때 요청이 **나갔다**: `--v: \75 rl(…)`+`var(--v)`, `--w: url(…)`+`var(--w)`, **`--s: "http://…"`+`image-set(var(--s) 1x)`**, **`var(--nope, \75 rl(…))`·`var(--nope, image-set("…" 1x))`**, **`if(media(…): url(…); else: none)`**, **`env(nope, url(…))`**, `@property` 초깃값, `@function`, `@font-face` 외부 `src`. **나가지 않았다**: `url(var(--s))`, `src(var(--s))`, `image-set(attr(data-u) 1x)`, `inherit(--x, url(…))`, `@counter-style symbols`
- (M4) **단축 속성 + `var()`.** `background: var(--nope, url(http://…))` 는 개별 속성 목록(`style[i]`) 값이 모두 `""` 라 보이지 않고, 그대로 두면 요청이 나갔다
- (M5) **CSSOM 직렬화 손실.** `margin: var(--m); margin-top: 0` → `cssText` 가 `margin-right: ; margin-bottom: ; margin-left: ; margin-top: 0px;` 가 되어 다시 파싱하면 `margin` 이 사라진다(`border`·`background`·`transition`·`padding` 도 같음). 그 시트 객체를 그대로 쓰면 `cssText` 에 안 보이는 값이 적용돼 `background: var(--nope, url(…)); background-color: red` 에서 요청이 나갔다. — **토크나이저 방식을 고른 까닭**(사용자 결정)
- (M12) **대체는 토큰 단위다.** `--a: u` + `var(--a)rl(http://…)`, `--a: ur` + `var(--a)l("…")`, `--a: url` + `var(--a)("…")`, `--a: image-set` + `var(--a)("…" 1x)`, `--a: url(` 류 — 모두 **요청 0건**, 계산 값 `none`. 변수 경계를 넘어 함수 이름을 이어 붙일 수 없다 → 판정은 선언 하나의 토큰만 보면 된다
- (M13) **URL 파서 앞 공백.** `url(" data:image/gif;base64,…")` 는 앞 공백이 잘려 `data:` 로 적용됐다 → 인자 판정은 URL 파서처럼 앞쪽 C0·공백을 자른 뒤 본다(4.4)
- (M10) **`data:` SVG 안의 외부 참조.** `filter`·`background-image`·`mask-image`·`clip-path` 의 `url("data:image/svg+xml,…")` 안 `<feImage href="http://…">`·`<image href>`·`<style>@import`·`fill:url(http://…)`·`<use href="http://…">` — **요청 0건**

- (M14) **적대 조각(7.3 표, 31줄)** — 원문 적용 시 **20건** 요청, 필터 결과 적용 시 **0건**. 결과를 다시 필터하면 뺄 것 0건(고정점). **`.y { margin: var(--m, 7px); margin-top: 0; background: var(--nope2, url(…)); background-color: red }` 가 `margin-left: 7px`·`background-color: red` 로 적용** — 초판 방식에서 `0px` 이던 것이 남는다. 앱 CSS 9개(`app.css`·`markdown.css`·`preview.css`·`github-markdown-light.css`·`tokens.css`·`print.css`·`callout.css`·`map.css`·`palette.css`)에서 뺀 것은 `app.css` `@property`·`preview.css` `@import`·`tokens.css` `@font-face`(상대 경로 `url`) 셋뿐이고, 나머지 규칙은 원문과 결과를 각각 `replaceSync` 한 `cssText` 가 **모두 같다**(다른 것 5개는 `var()` 값 안의 줄 끝이 CRLF → LF 로 바뀐 것뿐 — 전처리, 4.1). 9개 모두 고정점

## 2. 핵심 결정

1. **판정과 출력은 원문 텍스트 위에서 한다 — 뺄 선언·규칙의 범위만 잘라 내고 나머지 글자는 그대로 둔다.** 브라우저가 다시 쓴 텍스트를 쓰지 않으므로 M5 의 손실이 없다(M14 `.y` 가 `7px`). 주석·공백·서식도 남는다. 원문과 달라지는 것은 전처리(줄 끝 CRLF·CR·FF → LF, NUL → U+FFFD)와 잘라 낸 범위, 끝 닫기(4.6)뿐이다
2. **안전은 구조 해석이 아니라 토큰 전수 검사에 기댄다.** 모든 토큰을 본다 — 선언 값이든 규칙 머리든 어디에 있든, 외부 주소를 부를 수 있는 토큰(4.4 표 금지 토큰)이 남아 있으면 그것을 품은 가장 작은 단위를 잘라 낸다. 블록 파서가 브라우저와 규칙 경계를 다르게 읽어도 **더 넓게 자를 뿐 덜 자르지 않는다.** 토큰화는 명세가 정한 좁은 알고리즘이라 브라우저와 맞추기 쉽고, 구조(중첩·선언/규칙 구분)는 틀려도 안전에 닿지 않게 둔다
3. **이름은 이스케이프를 푼 뒤 ASCII 대소문자 무시로 비교한다** — 함수 이름(`\75 rl(` = `url(`), at-규칙 이름(`@\69mport` = `@import`), 속성 이름. 토크나이저가 명세대로 풀기 때문에 `url(` 은 URL 토큰 또는 `url` 함수 토큰 둘 중 하나로만 나타난다
4. **정규화되지 않는 값에는 원문 `\` 금지를 남긴다** — 사용자 정의 속성(개요 결정 그대로)과 대체 함수가 든 일반 속성. 이 값은 브라우저도 원문 그대로 직렬화해 보조 검증이 보지 못하는 유일한 곳이고(M16), 토크나이저의 이스케이프 풀기에 결함이 있어도 여기서는 새지 않게 하는 두 번째 그물이다. 대가: `--q: "\201C"` 같은 값이 빠진다(개요가 이미 받아들인 것)
5. **보조 검증: 결과를 브라우저에 파싱시켜 브라우저가 다시 쓴 텍스트를 같은 필터로 한 번 더 본다.** 무엇이든 걸리면 결과 전체를 버린다(실패 시 닫힘). 브라우저는 철자를 정규화해 돌려주므로(M2) 우리 토크나이저가 특이한 철자를 놓친 경우를 잡는다(M16). 규칙 종류가 허용 밖이어도 버린다. 비용은 상한에서 필터 7.0ms → 합 25.8ms(M15)
6. **출력은 "닫힌 텍스트"다** — 끝에서 열린 주석·문자열·URL·괄호·블록을 닫고, 블록 없이 끝난 규칙 머리를 잘라 낸다(4.6). HTML 내보내기(F-2097)가 스니펫을 한 `<style>` 에 이을 때 앞 스니펫의 열린 주석이 뒤 스니펫의 문자열을 먹어 검사 안 된 텍스트를 살려 내는 길을 막는다
7. **`filterUserCss` 는 node 에서 도는 순수 함수다.** 판정·잘라 내기·닫기는 모두 단위 테스트로 본다. 브라우저에서만 참인 것(실제 요청, 정규화)은 e2e 하나와 보조 검증이 맡는다

- CSS Syntax 3 "Tokenization" 알고리즘 그대로다. 명세와 다른 점은 둘뿐: **주석을 `comment` 토큰으로 낸다**(명세는 버린다 — 잘라 낼 범위와 끝 닫기에 필요), 숫자 토큰의 수치 값은 내지 않는다(쓰지 않는다)
- `function`·`at-keyword` 의 `value` 는 이스케이프를 푼 이름 그대로(대소문자 보존). 비교하는 쪽이 ASCII 소문자로 바꾼다
- `openAtEnd`: 텍스트 끝에 닫히지 않은 주석·문자열(어느 따옴표)·URL 토큰이 있었는지. 명세상 이 경우도 토큰은 나온다(파싱 오류일 뿐)
- **토큰 끝 = 다음 토큰 시작**, 첫 토큰 시작 = 0, 마지막 토큰 끝 = 텍스트 길이. 토큰을 이으면 전처리한 텍스트가 그대로 나온다(7.1 에서 불변식으로 본다)

## 4. 필터 절차 (`filterUserCss`)

### 4.1 한눈에

1. `preprocessCss` — CSS Syntax 3 "Preprocessing the input stream": CRLF·CR·FF → LF, NUL·서러게이트 코드 포인트 → U+FFFD. **이후 모든 오프셋과 출력은 전처리한 텍스트 기준**
2. `tokenizeCss`
3. 블록 파서(4.2)로 규칙·선언의 범위를 정한다 — 파싱에서는 `comment` 토큰을 건너뛴다
4. 판정(4.3·4.4)으로 잘라 낼 범위를 모은다
5. 텍스트에서 그 범위를 지우고(4.5) 끝을 닫는다(4.6)

### 4.2 블록 파서 — 무엇이 규칙이고 무엇이 선언인가

CSS Syntax 3 "Parsing" 의 "consume a stylesheet's contents"·"consume an at-rule"·"consume a qualified rule"·"consume a block's contents"·"consume a declaration" 을 따른다. 요점:

- **최상위**는 규칙만: `whitespace`·`cdo`·`cdc` 는 건너뛰고, `at-keyword` 면 at-규칙, 아니면 한정 규칙(머리 … `{` 블록 `}`)
- **모든 `{}` 블록의 안**은 "블록 내용"으로 읽는다 — 선언과 중첩 규칙이 섞일 수 있다. `whitespace`·`semicolon` 건너뜀, `at-keyword` 면 중첩 at-규칙, `ident` 로 시작하면 선언을 시도하고 선언이 아니면 되돌아가 중첩 한정 규칙으로 읽는다
- **선언**: 이름(ident) · 공백 · `colon` · 값(블록 안 깊이 0 의 `semicolon` 또는 `}` 앞까지, 괄호·함수·블록은 짝을 맞춰 한 덩이). 이름이 `--` 로 시작하지 않는데 값의 깊이 0 에 `{}` 블록과 그 밖의 공백 아닌 토큰이 함께 있으면 선언이 아니다(`a:hover { … }` 가 중첩 규칙이 되는 명세 규칙)
- **중첩된 한정 규칙**은 깊이 0 의 `semicolon` 이나 `}` 을 만나면 블록 없이 끝난 잘못된 규칙이다(브라우저가 버린다). **중첩 at-규칙**은 깊이 0 의 `}` 에서 그 `}` 를 먹지 않고 끝난다
- `@keyframes`·`@media` 처럼 규칙만 담는 블록도 같은 "블록 내용" 으로 읽는다 — `from {…}`·`0% {…}`·`.a {…}` 는 선언 모양이 아니라 규칙으로 읽힌다. 브라우저와 어긋나는 모양이 있어도 2장 결정 2 에 따라 판정은 더 넓게 자를 뿐이다
- 블록 없이 텍스트 끝에 닿은 규칙 머리는 **불완전 규칙**이다(4.6)

### 4.3 at-규칙 이름 — 허용 목록 (`USER_CSS_ALLOWED_AT_RULES`)

| 이름 (이스케이프 푼 뒤 소문자) | 비고 |
| --- | --- |
| `media` `supports` `container` `layer` `scope` `starting-style` | 규칙 묶음 |
| `keyframes` `-webkit-keyframes` | 뒤는 Chrome 이 같은 `CSSKeyframesRule` 로 읽는다 |
| `font-face` | 4.4 의 글꼴 문맥 |
| `page` | |
| `top-left-corner` `top-left` `top-center` `top-right` `top-right-corner` `bottom-left-corner` `bottom-left` `bottom-center` `bottom-right` `bottom-right-corner` `left-top` `left-middle` `left-bottom` `right-top` `right-middle` `right-bottom` | `@page` 안 여백 상자 16개. 자리와 무관하게 허용한다 — 엉뚱한 자리면 브라우저가 버리고, 안에 든 토큰은 어차피 전수 검사된다 |
| `charset` | 브라우저가 무시한다. 빼면 "외부 파일" 알림 숫자에 들어가 헷갈리므로 둔다 |

- **그 밖의 at-규칙은 규칙째 잘라 낸다** — `import` 는 이유 `import`, 나머지(`namespace`·`property`·`counter-style`·`font-feature-values`·`font-palette-values`·`view-transition`·`position-try`·`function`, 모르는 이름 전부)는 `rule-kind`. 개요 3.1 목록 + 실측으로 요청을 확인한 `@function`(M3)
- `@\69mport` 는 이름을 풀면 `import` 다 → 잘린다(개요 초판이 "세지 못한다" 로 남긴 것이 해결됨)

### 4.4 판정 — 금지 토큰과 문맥

**URL 인자**: URL 토큰은 그 `value`, `url` 함수는 괄호 안 첫 공백 아닌 토큰이 `string` 이면 그 `value`(아니면 인자 없음 = 허용 안 됨). 인자에서 탭·LF·CR 을 모두 지우고 앞쪽 U+0000~U+0020 을 자른 뒤(URL 파서와 같게, M13) ASCII 소문자로 보아 `data:` 로 시작하면 **data 인자**, `#` 으로 시작하면 **조각 인자**.

**금지 토큰 — 어디에 있든**(선언 값·규칙 머리·아무 데나):

| 토큰 | 조건 |
| --- | --- |
| `bad-url` | 늘 |
| `function` | 이름(소문자)이 `src`·`image`·`image-set` 이거나 `-image-set` 으로 끝남(`-webkit-image-set`) |
| URL 토큰·`url` 함수 | 아래 "허용되는 URL" 이 아닌 모든 것 |

**허용되는 URL** — 셋 모두 참일 때만:
1. **일반 선언**의 값 안이다 — 이름이 `--` 로 시작하지 않고, 같은 값에 **대체 함수**(`var`·`env`·`attr`·`if`·`inherit`, 또는 `--` 로 시작하는 이름의 함수)가 없다
2. 인자가 data 인자이거나, 조각 인자이면서 `@font-face` 블록의 선언이 아니다
3. 규칙 머리(선택자·at-규칙 머리) 안이 아니다

**원문 `\` 금지** (2장 결정 4): 사용자 정의 속성의 값, 또는 대체 함수가 든 일반 선언의 값 — 그 값 범위의 전처리 텍스트에서 `comment` 토큰 밖에 `\` 가 하나라도 있으면 금지.

**이유 코드** — 걸린 선언의 이유는 이 순서로 첫 번째: 이름이 `--` 로 시작 → `custom-property`, 값에 대체 함수 → `substitution`, 그 밖 → `url`. `@font-face` 블록 안 선언이 걸리면 선언 대신 **`@font-face` 규칙째** 자르고 이유 `font-src`(서술자 하나만 빼면 `src` 없는 글꼴이 남아 뜻이 없다). 규칙 머리에서 걸리면 규칙째, 이유 `url`.

- 허용 결과 예: `url(data:image/gif;base64,…)`, `filter: url(#x)`, `--ok: 12px`, `padding: var(--ok)`, `background-image: --f()`, `--s: "http://…"`(값만으로는 부르지 않는다 — 쓰는 쪽 `image-set(var(--s))` 이 금지 함수로 걸린다, M3), `content: "url(http://x)"`(문자열 안), `content: "\201C"`(일반 선언의 문자열 안 `\` 는 괜찮다)
- 알고도 막는 것(안내 글 F-2100): 사용자 정의 속성의 `url("data:…")`·`"\201C"`, 대체 함수가 든 값의 `url("data:…")`(`background: var(--x, url("data:…"))`), `image-set()` 전부(data 인자여도), `@supports (background: url(…))` 처럼 머리에 URL 이 든 규칙
- **`attr()` 는 대체 함수로 친다** — `attr(x type(<url>))` 는 Chrome 154 가 버렸지만(M3) 대체 함수 문맥에 넣으면 그 값의 URL 이 모두 막혀 더 엄격해질 뿐이다

| --- | --- |
| 선언 | 이름 토큰 시작부터, 선언이 `semicolon` 으로 끝났으면 그 `;` 끝까지, 아니면(`}`·텍스트 끝) 값의 마지막 공백 아닌 토큰 끝까지 |
| 규칙 | 첫 토큰(`@이름` 또는 머리 첫 토큰) 시작부터 블록을 닫는 `}` 끝까지, 블록 없는 at-규칙은 `;` 끝까지, 부모의 `}` 에서 끝난 중첩 규칙은 그 앞 마지막 공백 아닌 토큰 끝까지 |

- 앞뒤 공백·주석은 남긴다. 지운 자리에 아무것도 넣지 않는다 — 범위의 앞은 늘 `{`·`;`·`}`·공백·주석·텍스트 시작 뒤이고 뒤는 공백·`}`·다음 항목 시작이라 토큰이 새로 붙지 않는다. 그래도 붙는 경우가 있으면 고정점 검사(7.2)와 보조 검증(4.7)이 잡는다
- **바깥 단위만 적는다.** 규칙째 자르는 규칙 안에서 걸린 선언·중첩 규칙은 `removed` 에 따로 넣지 않는다(프로토타입은 `@property` 안 `initial-value` 를 두 번 셌다 — 그렇게 하지 않는다)
- **`removed` 순서**: 잘라 낸 범위의 시작 오프셋 순서(= 문서 순서)
- **고정점**: `filterUserCss(filterUserCss(x).css).removed` 는 늘 빈 배열이고 `css` 는 같다

### 4.6 끝 닫기 — 닫힌 텍스트 (2장 결정 6)

1. 블록 없이 텍스트 끝에 닿은 **불완전 규칙**(최상위든 중첩이든)을 잘라 낸다 — 브라우저도 버리는 것이라 `removed` 에 넣지 않는다. 단 그 머리에 금지 토큰이 있거나 금지 at-규칙이면 4.3·4.4 대로 `removed` 에 넣는다
2. 잘라 낸 텍스트를 다시 토큰화해 `openAtEnd` 가 `comment` 면 `*/`, 따옴표면 그 따옴표, `url` 이면 `)` 를 붙인다
3. 그 뒤 아직 열린 `(`·함수·`[`·`{` 를 안쪽부터 `)`·`]`·`}` 로 닫는다
- 결과 판정(7.2): 어떤 출력 `out` 에도 `out + "\n.probe{color:red}"` 를 파싱하면 `.probe` 가 최상위 한정 규칙 하나로 따로 나온다
- F-2097 이 스니펫을 이을 때는 사이에 줄바꿈을 둔다(`\` 로 끝난 텍스트가 다음 글자와 이스케이프를 이루지 않게, 12장)

### 4.7 보조 검증 (`compileUserCss`, 2장 결정 5)

1. `filterUserCss(source)` → `{ css, removed }`. `css` 가 빈 문자열(또는 공백·주석뿐)이면 여기서 `{ css, ruleCount: 0, removed }`
2. `createSheet()` 에 `css` 를 `replaceSync`
3. 시트를 중첩까지 걸어 모든 규칙의 종류가 허용 목록(아래 표)에 있는지
4. 최상위 규칙의 `cssText` 를 `\n` 으로 이은 **브라우저 직렬화**를 `filterUserCss` 에 다시 넣어 `removed` 가 빈 배열인지
5. 3·4 둘 다 통과면 `{ css, ruleCount: 최상위 규칙 수, removed }`. 아니면 `{ css: '', ruleCount: 0, removed: [...removed, unstable] }`

| `USER_CSS_ALLOWED_RULE_KINDS` (CSSOM 이름, 이 순서) |
| --- |
| `CSSStyleRule` `CSSNestedDeclarations` `CSSMediaRule` `CSSSupportsRule` `CSSContainerRule` `CSSLayerBlockRule` `CSSLayerStatementRule` `CSSKeyframesRule` `CSSKeyframeRule` `CSSFontFaceRule` `CSSPageRule` `CSSMarginRule` `CSSStartingStyleRule` `CSSScopeRule` |

- **잡는 것:** 우리 토크나이저가 특이한 철자(이스케이프·대소문자·주석 끼움)를 놓쳤는데 브라우저가 그것을 `url("…")` 따위 표준 철자로 다시 써 준 경우(M16 전체 조각), 우리가 모르는 방식으로 브라우저가 허용 밖 규칙을 만든 경우
- **못 잡는 것:** 정규화되지 않는 값(사용자 정의 속성·대체 함수 값) 안의 철자 — 브라우저도 원문 그대로 돌려준다(M16 두 번째). 그 자리는 원문 `\` 금지(4.4)와 토크나이저 단위 테스트(7.1)가 맡는다. `cssText` 에 빈 값으로 보이는 숨은 값(M5)도 못 보지만, 그 값은 우리 필터가 원문에서 이미 판정한 선언이다
- 브라우저 직렬화가 손실되는 것(M5)은 여기서 문제가 아니다 — 판정만 하고 출력에 쓰지 않는다
- 적용하는 쪽은 1단계 `css`(원문 보존본)를 쓴다. 브라우저 직렬화는 판정에만 쓴다

## 5. 상한·스니펫 검증 (개요 3.4·3.5)

### 5.1 `checkSnippetName(name)` — 이 순서로 첫 문제

| 순서 | 문제 | 조건 |
| --- | --- | --- |
| 1 | `empty` | 길이 0 |
| 2 | `too-long` | `name.length > 60` (UTF-16 — D-16 `maxlength` 와 같은 단위. F-2099 의 `{이름} (이 브라우저)` 줄이기도 이 단위) |
| 3 | `untrimmed` | `name !== name.trim()` (공백만인 이름도 여기) |
| 4 | `control` | U+0000~U+001F·U+007F~U+009F 중 하나 |

- F-2096 은 저장 전에 앞뒤 공백을 자르고 제어 문자를 지운 뒤 판정한다 — 화면에 나올 수 있는 것은 `empty`(`이름을 입력하세요.`)뿐이다

### 5.2 `checkUserCssLimits(snippets)`

- 개수 > 50 → `'count'`(`스니펫은 50개까지 만들 수 있습니다.`), 아니면 `css` 의 UTF-8 합 > 262,144 → `'bytes'`(`CSS 는 모두 합쳐 256KB 까지 저장할 수 있습니다.`), 아니면 `null`. 켜짐 무관. 정확히 50개·262,144 바이트는 통과

### 5.3 `validateUserCssSnippets(value)` — 서버(F-3010)와 로컬 저장값 읽기(F-2095)가 함께 쓴다

이 순서로 첫 실패:

1. 배열이 아니다 → `{ error: 'invalid', field: 'snippets' }`
2. 길이 > 50 → `invalid`, `snippets`
3. 원소를 앞에서부터, 원소 안은 `id` → `name` → `css` → `enabled` → `updatedAt`:
   - 원소가 객체가 아니다(`null`·배열 포함) → `snippets[{i}]`
   - `id` 가 `/^[0-9a-f]{16}$/` 가 아니다 → `snippets[{i}].id`
   - `name` 이 문자열이 아니거나 `checkSnippetName` 이 문제를 낸다 → `snippets[{i}].name`
   - `css` 가 문자열이 아니다 → `snippets[{i}].css`
   - `enabled` 가 불리언이 아니다 → `snippets[{i}].enabled`
   - `updatedAt` 이 0 이상 안전 정수가 아니다 → `snippets[{i}].updatedAt`
4. 같은 `id` 가 두 번 → 두 번째 원소의 `snippets[{i}].id`
5. `css` UTF-8 합 > 262,144 → `{ ok: false, error: 'too_large' }`
6. 통과 → `{ ok: true, snippets }` — 원소마다 **다섯 키만 담은 새 객체**(모르는 키를 버린다)

- `{i}` 는 0부터, 예 `snippets[3].name`. F-3010 400 응답의 `field` 값이다(개요 4.3). 413 의 `limit` 은 `USER_CSS_MAX_TOTAL_BYTES`. 본문 상한 `USER_CSS_MAX_BODY_BYTES` 는 F-3010 이 본문을 읽을 때 본다

- **끝 닫기(4.6)**: `.a { color: red`, `.a { b: c(`, `.a { content: "x`, `/* x`, `.a { background-image: url(data:,x`, `.a`(불완전 규칙), `.a { .b` 각각 — 결과에 `"\n.probe{color:red}"` 를 붙여 이 모듈의 파서로 읽으면 `.probe` 가 최상위 규칙 하나로 나온다. 불완전 규칙만인 `.a` 는 `css` 가 `''`, `removed` 빈 배열
- **고정점**: 위 모든 입력에서 `filterUserCss(결과.css)` 가 `removed` 빈 배열·같은 `css`
- **끝남**: 임의 입력 모음(빈 문자열, `}}}`, `{{{`, `;;;`, `@`, `\`, `url(`, 10만 개 `(`)에서 던지지 않고 끝난다. 10만 개 `(` 는 재귀가 아닌 방식으로 처리해 스택이 넘치지 않는다

- **대체 함수 값의 원문 `\` 금지(2장 결정 4)** — 보조 검증의 사각(M16)을 막는 두 번째 그물. 풀면 `var(--x, "\201C")` 같은 값이 살지만 토크나이저 이스케이프 결함이 곧 요청으로 이어진다. 사용자 정의 속성 쪽은 개요가 이미 정한 것이라 그대로다
- **규칙 머리 안 URL 은 data: 여도 규칙째(4.4 허용 조건 3)** — 머리의 URL 은 불러오지 않지만(조건 비교) 허용하면 "어느 머리 문법이 URL 을 부르는가" 를 따로 따져야 한다. 쓰임이 드물어 넓게 자른다
- **`@charset` 허용(4.3)** — 브라우저가 무시하는 것을 "외부 파일" 알림 숫자에 넣지 않으려는 것

## 14. 확인한 것과 가정

### 14.1 코드를 읽거나 돌려 확인한 것

- 머리의 M1~M5·M10~M16(돌림), R1~R3(읽음)
- 프로토타입(스크래치패드 `tok.js`)은 CSS Syntax 3 토큰화를 옮기고 블록 파서·4.4 판정을 단순하게 붙인 것이다. 4.5 "바깥 단위만"·4.6 끝 닫기의 불완전 규칙 처리·원문 `\` 금지는 프로토타입에 **없었다** — 이 명세에서 더한 규칙이다. M14·M15 의 수치는 그 전 상태의 것

### 14.2 가정으로 남긴 것

- **토큰화가 Chrome 과 같다**는 것은 7.1 표와 M14(앱 CSS 9개가 보존·고정점), M16(엇나간 철자를 보조 검증이 잡음)로만 뒷받침된다. CSS Syntax 3 전체 적합성 모음(외부 테스트 모음)은 돌리지 않았다 — 새 의존성·외부 파일을 들이지 않으려는 것
- 4.2 블록 파서가 브라우저와 규칙 경계를 다르게 읽는 입력이 있을 수 있다. 2장 결정 2 로 안전에는 닿지 않는다고 보았지만, 경계가 어긋나면 **안전한 선언까지 함께 잘릴** 수 있다(보존 약속이 깨지는 쪽). 앱 CSS 9개에서는 없었다
- 여기 비용(M15)은 프로토타입 값이다. 실제 구현은 A15 로 재고 예산 50ms 를 둔다. 휴대폰은 재지 않았다
- Chrome 154 한 버전에서만 쟀다. HTML 내보내기를 여는 다른 브라우저는 우리 결과(원문 보존본)를 받는다 — 금지 토큰이 없다는 것은 토큰화 수준 사실이라 표준 토크나이저를 따르는 브라우저라면 같다고 보았다. 재지 않았다
- 4.4 대체 함수 목록은 지금 Chrome 이 아는 것이다. 새 대체 함수가 생겨도 그 값의 URL·금지 함수는 "어디에 있든" 규칙으로 걸리지만(data 인자 허용만 달라짐), 목록 밖이면 원문 `\` 금지가 걸리지 않는다 — 그때 검사기 버전을 올린다
- e2e 안 `vite build()` 는 표본(TS 두 파일)에서 143ms 였다. 실제 네 모듈을 묶는 시간은 구현 보고에서 확인한다
