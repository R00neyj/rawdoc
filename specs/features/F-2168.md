# F-2168 한중일 글자 옆 강조 기호 (CJK 친화 규칙)

상태: 승인됨(2026-10-24, 사용자가 대화에서 도입·새 의존성 `markdown-it-cjk-friendly` 결정 — 이 명세가 의존성 승인 근거) — GitHub 이슈 #5 두 번째 버그. `과변조 **"문구"**를` 처럼 닫는 `**` 안쪽이 문장부호·바깥이 한글이면 CommonMark 플랭킹 규칙(기호 양옆 글자로 여닫기를 정하는 규칙)상 편집·보기 모두 굵게가 안 된다. 원문 바이트·`.md` 내보내기는 그대로, 파싱만 바뀐다. 열린 질문 없음

## 근거 (HEAD 기준, 스크래치패드에서 `node` 로 돌려 확인)
- tats-u/markdown-cjk-friendly 저장소 `packages/` 9개 중 lezer·CodeMirror 용 없음(markdown-it·remark·micromark·marked·mdast 만). 규칙 원문: 저장소 `specification.md` 6.2
- `markdown-it-cjk-friendly` 3.0.0 = `md.inline.State` 를 `scanDelims` 만 바꾼 하위 클래스로 갈아 끼운다. markdown-it 15.0.2 의 `*`·`_`(emphasis)·`~~`(strikethrough)와 이 저장소 `==` 규칙(`highlightTokenize`)이 모두 `state.scanDelims` 를 부르므로 함께 바뀐다
- `@lezer/markdown` 1.7.2 `DefaultInline.Emphasis`·GFM `Strikethrough` 는 플랭킹을 자체 계산하고, 구분자 형식 `EmphasisAsterisk`·`EmphasisUnderscore` 는 비공개 객체이며 `resolveMarkers` 가 객체 동일성으로 짝짓는다(그래서 새 형식으로 다시 만들면 `***` 쪼개기·3의 배수 규칙이 사라진다). `configure` 의 `parseInline` 은 같은 이름이면 그 자리 함수만 바꾼다
- 3장 방식 시제품(원래 파서 호출 → 붙은 구분자를 떼고 같은 `type` 으로 판정만 바꿔 다시 `addDelimiter`) 결과가 플러그인 붙인 markdown-it 과 18개 입력에서 모두 일치. 둘 다 강조로 바뀜: `과변조 **"문구"**를`·`**이 괄호(parenthesis)**가 있는`·`*"기울"*임`·`~~"취소"~~를`·`***"굵기울"***는`·`첫 줄⏎과변조 **"문구"**를`·`[과변조 **"문구"**를](https://a.b)`·`> 인용 **"문구"**를`·`**강조。**この`·`😀**"a"**를`. 지금과 같음: `**"WHAT not HOW"**`·`**문구**를`·`「**강조**」했다`·`foo*bar*baz`·`**foo**bar`(강조), `a **"b"**c`·`한_글_한`·`snake_case_word`(강조 아님 — 영문은 CommonMark 그대로)
- 번들: 플러그인+`get-east-asian-width` 1.7.0 만 esbuild 압축 5.6KB, gzip 2.5KB(markdown-it 은 이미 의존성)

## 2. 규칙과 적용 범위
- 규칙 = `markdown-it-cjk-friendly` 의 `scanDelims` 그대로(대상 문자 = 동아시아 폭 W·F·H 중 그림 문자 아닌 것 + 한글 문자, 변형 선택자 처리 포함). 편집기도 **같은 함수를 호출**해 판정한다 — 규칙을 옮겨 적지 않으므로 두 모드가 어긋날 수 없다
- 적용 기호: `*`·`**`·`***`·`~~`(패키지 기본). `_` 는 패키지에서도 사실상 CommonMark 그대로(단어 안 `_` 불가)
- 붙이는 곳: 편집기 `createEditor.ts`, 표 칸 `cellInline.ts`, 보기 `renderMarkdown.ts` 의 `md`. 보기 `md` 를 쓰는 곳은 자동 반영 — 보기·공개·공유·위키 미리보기·칸반 카드(`renderMarkdownInline`)·인쇄·HTML 내보내기·서식 있는 복사(`toHtmlDoc.ts`)·평문 내보내기(`toPlainText.ts`)·제목 찾기(`headingTarget.ts`)·공개 사이트(`site/render.ts`)
- 붙이지 않는 곳(이유): `outline.ts`·`viewOutlineHandle.ts` — 제목 노드만 보고 글자는 정규식 `stripInlineMarkup`. `BoardInput.tsx` — 트리로 강조를 그리지 않는다(카드 표시는 `renderMarkdownInline`). `lib/comments.ts` 의 `md` — 코드 토큰 경계만 본다. `cli/`·`worker/` — 마크다운 파서 없음(grep 확인)
- 편집 쪽 `==` 는 `highlightSyntax.ts` `findHighlights`(공백만 검사)라 이미 `과변조 =="문구"==를` 을 칠한다. 보기 쪽이 이번에 따라와 맞춰진다 — 편집 쪽 코드 변경 없음
- 서식 지우기(`formatCommands.ts`)·기호 숨김(`inline.ts`)은 편집기 트리를 읽으므로 자동 반영

## 3. 편집기 — `src/editor/cjkEmphasis.ts`
```ts
export const cjkEmphasis: MarkdownConfig // parseInline: [{ name: 'Emphasis', … }, { name: 'Strikethrough', … }]
```
- 경로: 기존 인라인 파서를 **같은 이름으로 감싸 교체**(delimiter resolve 단계는 손대지 않는다). 원래 함수는 모듈 적재 때 `markdownLanguage.parser` 의 `inlineParsers[inlineNames.indexOf(이름)]` 에서 꺼낸다
- 감싼 함수: 원래 함수 호출 → `-1` 이면 그대로 반환. 아니면 방금 붙은 구분자(`cx.parts` 마지막)를 떼고 `cx.addDelimiter(그 type, from, to, can_open, can_close)` 로 다시 붙인다. 판정 = 플러그인 붙인 markdown-it 의 `new md.inline.State(cx.text, md, {}, [])` 에 `scanDelims(from - cx.offset, 기호가 '_' 가 아님)`. `State` 는 같은 `cx.text` 동안 하나만 만들어 재사용
- `scanDelims` 의 `length` 가 `to - from` 과 다르면 원래 판정을 그대로 둔다(안전장치)
- `inlineParsers`·`inlineNames`·`parts` 는 `.d.ts` 에 없는 `@internal` 필드 — `frontmatter.ts` 처럼 이 파일 안 로컬 타입으로 보강. lezer 갱신으로 깨지면 U1 이 잡는다
- `createEditor.ts`: `extensions: [frontmatterExtension(), cjkEmphasis]`. `cellInline.ts`: 모듈 `parser` = `(markdownLanguage.parser as MarkdownParser).configure([cjkEmphasis])`

## 4. 보기 — `renderMarkdown.ts`
- `new MarkdownIt(...)` 바로 다음 `md.use(cjkFriendly)`. 다른 규칙 등록 순서와 무관(파서 상태 클래스만 바뀐다)

## 6. 기존 테스트 영향
- grep(`플랭킹`·문장부호 뒤 `**`+한글·`~~`+한글)로 찾은 기존 사례는 모두 공백·한글 사이 강조라 결과가 같다 — 깨질 것으로 보이는 테스트 없음. `renderMarkdown.test.ts` `A4 플랭킹 — …` 두 개(`== 글자==`·`==글자 ==`)는 공백 판정이라 그대로 통과해야 함
