## 2. 게이트별 origin (결론 1)

- 실측: 지금 게이트 둘을 한 공유 Doc 에 붙이고 A 에 ` A` 를 치면 공유 `hello A`, B `hello`(F-2159 2장 재현). 사본에서 아래처럼 바꾸면 B 도 받는다
- `createRemoteGate` 가 부를 때마다 `RELAY_FROM_EDITOR` 객체를 새로 만들고, 모듈 안 `WeakSet<object>` 에 넣는다. `isEditorRelay(origin)` = 객체이고 그 집합에 있음. 상수·집합은 내보내지 않는다(F-306 7.1). 게이트 `destroy` 는 집합에서 빼지 않는다 — 버린 게이트의 늦은 업데이트도 내 편집이고, WeakSet 이라 쌓이지 않는다
- `onSharedUpdate` 첫 분기는 **자기** origin 만 건너뛴다. 다른 게이트의 중계는 원격과 같이 보류·적용 규칙을 탄다(조합 중이면 보류, F-301 2.1 그대로). `RELAY_FROM_SHARED`·`REMOTE` 는 편집기 Doc·포트 쪽이라 모듈 상수 그대로
- 따라오는 것: `createMergeTracker` 의 `isLocalOrigin`, `useLiveRoomDoc` `handleTransaction` 이 어느 칸의 편집이든 내 편집으로 본다. 코드 변경 없음

## 3. 창 안 원본 모음 (결론 2)

```ts
export type SourcePane = { editorDoc: Y.Doc; followSource(source: Y.Doc): void }
export type PaneSources = {
  prepare(docId: string): Y.Doc | null // 칸 편집기를 만들기 직전. null = 그 칸 편집기 Doc 이 원본
  add(docId: string, pane: SourcePane): void // 만든 직후
  remove(docId: string, pane: SourcePane): void // 편집기 destroy 직전
  source(docId: string): Y.Doc | null
}
export function createPaneSources(): PaneSources // 창에 하나 — 주인은 F-2163
```

- **링크 없는 문서(F-2159 2장 b)만 쓴다.** 링크 있는 문서는 방 Doc 이 원본이라 이 모음을 거치지 않는다
- `prepare`: 그 문서 칸이 0 → `null`. 1 이상인데 원본이 없으면 **동기로** 새 `Y.Doc` 을 만들고 그 칸 `editorDoc` 의 `encodeStateAsUpdate` 를 적용(씨앗 origin 은 모듈 상수)한 뒤 그 칸 `followSource(원본)`. 있으면 그것을 돌려준다. 사이에 await 가 없어 씨앗과 게이트 사이로 편집이 새지 않는다
- `remove` 로 칸이 0 이 되면 원본 `destroy`·항목 삭제. 1칸만 남아도 원본은 남고 그 칸은 복제본으로 머문다(F-2159 "모든 칸에서 빠질 때 버린다"). 같은 `pane` 두 번 `add`·없는 `remove` 는 아무 일 없음
- 같은 칸 편집기를 다시 만들 때(문서 다시 읽기 등)는 **새것 `prepare`→생성→`add` 뒤 옛것 `remove`** — 반대면 마지막 칸일 때 원본이 먼저 사라져 저장 안 된 편집을 잃는다
- 실측(사본): 첫 칸에서 `1` 을 친 뒤 원본을 씨앗 삼아 두 칸 → B 가 `hello1`·댓글 맵 1건으로 시작, B 의 `B` → A `Bhello1`, A 조합 중 B 의 `X` → A 그대로, 조합 끝 비우기 뒤 A `XBhello12`, A 실행 취소 두 번 → `XBhello`(A 의 `2`·원본 생기기 **전** `1` 이 둘 다 되돌아가고 B 편집은 남음)

## 4. 편집기 handle

- 옵션 `paneSource?: Y.Doc` — 주면 `createYBindingFromState(encodeStateAsUpdate(paneSource))` 로 만들고 `connectRemote({ …, sharedDoc: paneSource })`. `text` 는 쓰지 않는다. `live` 와 같이 주지 않는다(같이 오면 `live` 만 쓴다). 제목·커서는 비실시간과 같다
- handle `editorDoc: Y.Doc`(= `binding.ydoc`), `followSource(source)`: 게이트가 없을 때만 `connectRemote({ view, editorDoc, docId, sharedDoc: source })` 를 달고 `destroy` 에서 같이 뗀다. 이미 게이트가 있으면(`live`·이미 따름·e2e `__yProviderFactory`) 아무 일 없음. 편집기·UndoManager 는 그대로(실행 취소 기록 유지). `docId` 없는 편집기(랜딩 데모)는 `connectRemote` 가 `null` 이라 모음에 넣지 않는다

## 5. 저장은 원본에서 (결론 3)

- `sourceText(source: Y.Doc, lineEnding: LineEnding): string` — 원본 `Y_TEXT_NAME` 문자열의 `\n` 을 `lineEnding` 구분자로 잇는다. handle `getText` 와 같은 바이트(편집기 Y.Text 는 늘 `\n` — `toEditorText`·ySync)
- 원본이 있는 문서의 저장은 **포커스 칸 `getText` 대신 `sourceText`**, 댓글 기록은 `buildLocalCommentRecords({ map: 원본 comments 맵, ytext: 원본 Y.Text, text: sourceText(…,'lf'), ranges: new Map() })`(범위는 앵커에서 푼다). 조합 중 보류된 칸이 뒤처져도 저장은 원본을 따른다. 읽는 자리는 F-2160 문서 묶음의 `host.getText(docId, lineEnding)` — 바꾸는 것은 F-2163(7장)

## 6. awareness — 마지막 포커스 칸만 (결론 4)

```ts
export type CursorSeat = { owns(): boolean; claim(): boolean; leave(): void }
export function takeCursorSeat(awareness: Awareness, onHandedOver: () => void): CursorSeat
```
- awareness 하나에 자리 여럿. 첫 자리가 주인. `claim()` 은 그 자리를 주인으로 하고 주인이 바뀌었으면 `true`. 주인이 `leave` 하면 남은 자리 중 마지막으로 `claim` 한(없으면 마지막에 들어온) 자리가 주인이 되고 그 `onHandedOver` 가 돈다
- `RemoteCursorsView`: `attach` 에서 자리를 잡고 `detach` 에서 놓는다. 포커스를 얻으면 `claim()`, `true` 이고 접속자가 있으면 `resend({ focused: true })`. **주인 아닌 칸은 `offer`·`resend` 를 부르지 않는다.** `onHandedOver` → `resend({ focused })`(포커스 없으면 마지막 보낸 값, 없으면 null — F-307 그대로)
- 상대 커서 그리기·얼리기는 칸마다 그대로(모든 칸에 그린다). 칸 하나면 자리 하나라 지금과 같다(F-307 A6 기대값 그대로)

## 7. 배선 경계 (결론 5) — F-2163 에 넘기는 조건

F-2160 이 `panes` 길이 1 로 고정하므로 이 명세로 생기는 화면 동작은 없다. F-2163 이 같은 문서를 두 칸에 띄울 때: ① 창에 `createPaneSources()` 하나 ② 링크 없는 문서 칸 편집기 생성 전 `prepare`, 결과가 있으면 `paneSource` 로, 뒤 `add`/destroy 전 `remove`(3장 순서) ③ 문서 묶음 `getText`·`getComments` 가 원본이 있으면 5장대로 ④ 저장 예약은 어느 칸의 `local` 변경이든 그 문서 saver 하나로 ⑤ 로컬 댓글 되살리기(`restoreLocalComments`)는 원본이 없는 첫 칸에서만 ⑥ 문서의 경로가 바뀌면(링크가 생김 등) 그 문서 칸을 모두 `remove` 하고 다시 만든다 ⑦ 사람 확인 F-2159 H3 를 `human-checks.md` 에
