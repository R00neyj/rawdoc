## 3. 요구사항

### 3.1 `idbStore.js`
- DB 이름 `md-docs`, 버전 1. object store `docs`(keyPath `id`), `meta`(스키마 버전 `{ key: 'schema', version: 1 }` 기록). 이름에 제품명을 쓰지 않는다
- architecture.md 2장 인터페이스 그대로. `kind: 'idb'`
- `update` 는 한 트랜잭션 안에서 읽고 쓴다

### 3.2 `openStore.js`
- `openStore() → Promise<store>`: `indexedDB` 가 없거나 열기 실패면 `memoryStore` 를 돌려준다
- 메모리 저장소로 시작하면 N-1 `error`: `이 브라우저에서 저장소를 쓸 수 없습니다. 새로고침하면 문서가 사라집니다.`

### 3.3 `lineEnding.js`
- `detectLineEnding(text) → { lineEnding, mixed }`: `\r\n`, 단독 `\n`, 단독 `\r` 개수로 판정. 줄바꿈 없음 → `crlf`·false. `\r\n` 만 → `crlf`. `\n` 만 → `lf`. 그 외(섞임, 단독 `\r` 포함) → `crlf`·true
- `toEditorText(text)`: `\r\n`·`\r` → `\n`
- `fromEditorText(text, lineEnding)`: `\n` → 해당 줄바꿈
- 테스트: 판정 5갈래, 섞이지 않은 CRLF·LF 원문의 `fromEditorText(toEditorText(x), detect(x).lineEnding) === x`

### 3.4 자동 저장 `useDocSaver`
- 에디터 문서 변경 → 상태 `입력 중…` → 마지막 변경 후 **700ms** 동안 입력이 없으면 `store.update(id, { content: handle.getText(doc.lineEnding) })` → `저장됨`
- 실패: `저장 실패`(상태바 `--danger`) + N-1 `error` `저장하지 못했습니다. 중요한 내용은 .md 내보내기로 백업하십시오.` 다음 변경 때 다시 시도
- `flush()`: 대기 타이머를 취소하고 변경분이 있으면 즉시 저장, 저장 끝날 때까지 await
  - F-111 의 `beforeLeaveDoc` 에 연결 (전환·삭제·해시 변경)
  - `visibilitychange` 가 `hidden` 이 될 때, `pagehide` 때 호출 (결과를 기다릴 수 없어 최선 시도)
- 저장 중 또 입력되면 그 저장이 끝난 뒤 다시 저장 예약. 늦게 끝난 옛 저장이 새 내용을 덮지 않는다
- 저장이 끝나면 목록 state 의 해당 문서 `updatedAt` 갱신 → 목록 맨 위로 (I6)
- 메모리 저장소면 상태 문구 `메모리 모드 — 새로고침하면 사라집니다` 고정
- 데이터 손실 구간 (product.md 6장): 마지막 입력 후 700ms 안에 탭을 강제로 닫으면 그 입력이 빠질 수 있다. `visibilitychange` 저장이 대부분 막지만 보장은 없다. 그동안 상태바는 `입력 중…` 이다

### 3.5 상태바 문구 (ia.md 4.1)
`저장됨` / `입력 중…` / `저장 실패` / `메모리 모드 — 새로고침하면 사라집니다`
