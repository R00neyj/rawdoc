# F-2149 안드로이드 앱 (Capacitor) — 설계 개요

작성일: 2026-10-21
상태: 개요, 승인 전. 사용자 "캐패시터만 남았네"(2026-10-21). 승인 대상은 1~5장 결정과 6장 로드맵. 빌드·화면 일이 대부분이라 `F-2NNN`, 세션·로그인 자식은 `F-4NNN`. `product.md` 8장이 범위 밖에 둔 기능이라 옮긴다(8장 갱신 대상). iOS 는 계속 범위 밖

## 정해진 것 (사용자, 바꾸지 않는다)
1 안드로이드를 범위 안으로 · 2 웹 빌드를 APK 에 넣는다(`server.url` 원격 로드 아님) · 3 APK 직접 배포(본인 기기 사이드로드), Play 스토어 아님 · 4 개요 먼저, 안드로이드 IME 검증(B-005·B-006)이 첫 자식

## 근거 (2026-10-21 HEAD·npm·Capacitor `main` 소스, 이름으로 찾는다)
- 앱은 서버를 같은 출처로 가정한다: 상대 주소 `fetch('/api…'|'/pub…')` 가 20개 파일(`src/storage/docsApi.ts`·`attachmentsApi.ts`, `src/app/account.ts`·`publicDoc.ts`·`notificationsApi.ts` 등), 실시간 주소는 `useLiveDoc.ts`·`bootFlow.ts` 가 `location.host` 로, 공유·초대 링크는 `location.origin`(`ShareMenu.tsx`·`SharesPage.tsx` 등). 첨부는 `fetch` → blob 이고, 서버를 `<img src>` 로 직접 부르는 곳은 `githubImages.ts` `githubProxySrc` 뿐(응답 머리 `Cross-Origin-Resource-Policy: same-origin`)
- 서버: `/api` 사용자 판정은 better-auth 쿠키(`worker/auth.ts` `getUser` → `auth.api.getSession({ headers })`). 비GET `/api` 와 `/ws` 는 `worker/origin.ts` `isAllowedOrigin` 이 `SITE_URL` 출처만 받고 Origin 없음은 403. CORS 머리 없음. `rd_` 토큰(`worker/apiTokens.ts` `getTokenUser`)은 `/v1` 에만 통한다
- better-auth 1.7.10 `dist/plugins` 에 `bearer`(Authorization 을 세션 쿠키로 바꿔 끼움, HMAC 서명 검사, `requireSignature`, 응답 머리 `set-auth-token`)·`one-time-token`(`consumeVerificationValue` 로 한 번만, `storeToken: 'hashed'`, 기본 3분)이 들어 있다 — 새 의존성 아님
- Capacitor 8.5.3 안드로이드: 번들 모드면 앱 호스트로 가는 요청은 전부 로컬 자산으로 답한다(`WebViewLocalServer.isMainUrl`) — 호스트를 `rawdoc.app` 으로 바꾸면 `/api` 가 `index.html` 을 받는다. `Bridge` 는 서드파티 쿠키를 켜지 않는다. CapacitorHttp 는 `fetch` 만 네이티브로 돌리고 쿠키를 WebView 저장소와 나눈다 — WebSocket 은 그대로이고 Origin 을 싣지 않는다. 시스템 바는 core 내장 `SystemBars`(`insetsHandling`). 요구: Node 22+, Android Studio Otter, minSdk 24·target 36. 이 PC 에 Android SDK·JDK 없음(`ANDROID_HOME`·`JAVA_HOME` 빔), `index.html` 에 `viewport-fit=cover` 없음, 저장소는 공개

## 1. 앱 모양과 빌드
- **출처는 Capacitor 기본 `https://localhost`**(`androidScheme: 'https'`). `isMainUrl` 때문에 `rawdoc.app` 흉내는 안 된다
- **빌드 모드 하나 더**: `npm run build:android` = `vite build --mode android`, 출력 `build-android/`(gitignore, `npm run clean` 의 `dist-*` 와 안 겹치게). android 모드는 PWA 플러그인 `disable`, 사이트 페이지·랜딩 생성 생략. 웹 `npm run build` 산출물은 바뀌지 않는다
- 배치: 루트 `capacitor.config.ts`(webDir `build-android`, `appName`·`appId` 는 `brand.config.ts` 에서 — `appId` 는 `siteUrl` 호스트를 뒤집은 값), 루트 `android/`(`cap add android` 산출물, 커밋. `android/app/build/`·서명 파일은 gitignore)
- **플랫폼 분기는 `src/platform/platform.ts` 한 파일**만 `import.meta.env.MODE === 'android'` 를 읽는다. 내보내기: `isAndroidApp`, `apiUrl(path)`, `apiFetch(path, init)`, `siteOrigin()`, `liveSocketBase()`, 앱 전용 훅 진입점. `@capacitor/*` import 는 `src/platform/android/` 아래만 — `tests/src/platform/capacitorBoundary.test.ts` 가 막는다(`gsapBoundary` 방식). 웹 모드 `apiUrl` 은 경로를 그대로 돌려줘 기존 테스트가 안 바뀐다
- 뒤로 키(`@capacitor/app` `backButton`): 열린 층 닫기(기존 Escape 규칙) → 해시 기록 뒤로 → 없으면 앱 종료. 앱에서 숨김: `앱 설치`, `이 기기에서 푸시 받기`(4장), OS 파일 열기. 로그아웃 상태의 로컬 문서는 앱 출처 IndexedDB 에 따로 쌓인다 — 같은 폰 Chrome·PWA 와 나누지 않는다

## 2. 출처와 API
| 안 | 방식 | 막히는 곳 |
| --- | --- | --- |
| A 쿠키 + 자격 CORS | 세션 쿠키 `SameSite=None`, 서드파티 쿠키 켬, `Allow-Credentials` | better-auth 쿠키 속성은 전역이라 웹 사용자 쿠키까지 `None` — CSRF 면이 넓어진다 |
| B CapacitorHttp + CapacitorCookies | `fetch` 를 네이티브로 | WebSocket 은 따로 인증, Origin 없음 → 관문 수정, `AbortSignal`·`redirect: 'manual'`·304·5MB 첨부가 다리(bridge)를 지난다 |
| **C 세션 토큰(추천)** | 앱은 쿠키를 안 쓴다. `bearer` 로 `Authorization: Bearer {서명된 세션 토큰}`, 자격 없는 CORS | 실시간 연결에 짧은 표(ticket) 하나 |
- **C 로 한다.** 웹 쿠키·CSRF 경계가 그대로이고, 토큰이 세션 행이라 만료·로그아웃·계정 삭제가 지금 규칙을 탄다. `rd_` 토큰은 재사용하지 않는다 — 사용자가 이름 붙여 만드는 `/v1` 전용 장기 토큰이라 `/api`·`/ws` 를 열면 F-222 경계가 깨진다. CapacitorHttp·CapacitorCookies 는 끈 채(기본값) 둔다
- 앱 요청: `apiFetch` = `SITE_URL` + 경로, `Authorization` 붙임, `credentials: 'omit'`. 토큰은 localStorage `md.nativeSession`. 키스토어 보관은 안 한다 — 요청마다 JS 가 읽어야 해 XSS 앞에서 같다
- Worker: `bearer({ requireSignature: true })`. `/api`·`/pub`·`/v1` 응답과 preflight 에 `Access-Control-Allow-Origin: https://localhost`(자격 없음, `Allow-Headers: Authorization, Content-Type, If-None-Match`, `Expose-Headers: ETag, set-auth-token`). `isAllowedOrigin` 은 `https://localhost` 를 **Bearer 가 붙은 요청에만** 받는다. better-auth `trustedOrigins` 에도 같은 출처. 다른 기기의 `https://localhost` 페이지는 토큰이 없어 얻는 것이 없다
- 실시간: WebSocket 은 머리를 못 붙인다 → `POST /api/live-ticket {docId}` 가 60초짜리 HMAC 표(사용자·문서·만료, 키는 `BETTER_AUTH_SECRET` 파생)를 주고 앱은 `wss://{SITE_URL 호스트}/ws/doc/:id?ticket=` 로 연다. `docSocket.ts` 는 Origin 이 `https://localhost` 면 표만 본다. 세션 토큰을 주소에 싣지 않는다 — 주소는 로그에 남는다
- GitHub 그림(`githubProxySrc`)은 앱에서 `apiFetch` → blob 주소로(첨부와 같은 길). 공유·초대 링크·API 토큰 예시는 `siteOrigin()`(앱이면 `SITE_URL`). CSP: 번들 앱엔 Worker 응답 머리가 없다 — F-4001 이 report-only 라 1차는 CSP 없이, enforce 로 바꾸는 명세가 앱용 `<meta>` 를 같이 정한다

## 3. 로그인 (F-4016)
Google 은 임베디드 WebView OAuth 를 막는다 → **Custom Tabs(`@capacitor/browser`) + 확인된 App Links** 로 돌아온다
1. 앱: `state`(32바이트 난수)를 sessionStorage 에 두고 `{SITE_URL}/login?app=android&state=…` 를 연다. `/login` 화면은 그대로, 로그인 뒤 갈 곳만 `/app-auth/done?state=…`
2. Worker `/app-auth/done`(Custom Tab 쿠키 세션으로 판정): **앱 전용 세션을 새로 만들고** 그 세션의 일회용 토큰(`one-time-token`, 해시, 3분, 한 번)을 실어 `{SITE_URL}/app-auth/return?ott=…&state=…` 로 보낸다. 브라우저 세션·쿠키는 건드리지 않는다 — 같은 폰 Chrome 에서 웹을 쓰던 사람이 로그아웃되지 않게
3. `/app-auth/return` 은 App Links(`autoVerify`, 이 경로 하나)로 앱이 받는다. `/.well-known/assetlinks.json` 은 Worker 가 `appId` + `vars` `ANDROID_CERT_SHA256` 으로 만든다(지금은 `/.well-known/` 그 밖이 404). Chrome 이 사용자 동작 없는 앱 전환을 막을 때를 위해 `done` 화면에 버튼 `앱으로 돌아가기`. 앱 없는 브라우저가 `return` 을 열면 `이 주소는 안드로이드 앱에서 열립니다.`
4. 앱(`appUrlOpen`): `state` 가 같을 때만 `POST /api/auth/one-time-token/verify` → `set-auth-token` 을 `md.nativeSession` 에 넣고 부팅을 다시 탄다(F-207 판정 그대로)
- 로그아웃 = `POST /api/auth/sign-out`(Bearer) 뒤 토큰 지움. 계정 삭제 재인증(`/login?reauth=1`)은 1~4 를 다시 탄다(새 세션이 최근 로그인 10분을 채운다). 1차에서 앱이 막는 것: GitHub 파일 연결 시작(F-3014 쿠키 OAuth) — 버튼 자리에 `GitHub 연결은 웹에서 해 주세요.` 연결된 뒤 당기기·푸시는 `/api` 라 앱에서도 된다

## 4. 서비스 워커·업데이트·푸시
- **SW 없음**: android 모드는 PWA 플러그인 `disable` → `vite-plugin-pwa` 1.3.0 은 그래도 `virtual:pwa-register/*` 를 no-op 판으로 풀어(`dist/index.js` load 분기) `useAppUpdate.ts` 가 그대로 빌드되고 등록은 하지 않는다. `push-sw.js` 도 안 낸다. 자산이 늘 로컬이라 오프라인에서도 열린다
- **업데이트 띠**: 켤 때와 60분마다(F-117 주기) `{SITE_URL}/android/latest.json`(`{ versionCode, versionName, url }`, `public/_headers` 로 `Access-Control-Allow-Origin: *`)을 읽어 설치된 `versionCode`(`@capacitor/app` `getInfo().build`)보다 크면 같은 띠 `새 버전이 있습니다.` + 버튼 `내려받기`(APK 주소를 시스템 브라우저로). 자동 설치 없음. 판정은 순수 함수

| 푸시 안 | 내용 | 비용 |
| --- | --- | --- |
| **A 1차 범위 밖(추천)** | 앱은 앱 안 알림함만. 푸시가 필요하면 같은 폰 Chrome PWA 를 함께 둔다 | 없음 |
| B FCM | `@capacitor/push-notifications` 8.1.3 + Firebase 프로젝트·`google-services.json` + Worker FCM HTTP v1 발송(서비스 계정 JWT RS256, WebCrypto) + `push_subscriptions` 종류 열(D1 마이그레이션) | 새 의존성·외부 계정·발송 경로 두 벌 |
- A 이유: 본인 기기 1대라 웹 푸시로 대신되고, B 는 F-3001 발송 경로를 두 벌로 만든다. B 를 고르면 F-3034 를 살리고 F-3001 6장에 FCM 행을 더한다. `notes.md` 2026-10-03 아이콘 없는 알림은 Chrome PWA 쪽 일이라 이 개요와 무관

## 5. 의존성과 배포 (사람 결정 필요 — 새 의존성)
| 패키지 | 버전(npm, 2026-10-21) | 쓰는 곳 | 판단 |
| --- | --- | --- | --- |
| `@capacitor/core` · `@capacitor/android` · `@capacitor/cli`(dev) | 8.5.3 셋 다 | 런타임(`SystemBars` 내장)·네이티브 프로젝트·`cap sync` | 필요 |
| `@capacitor/app` · `@capacitor/browser` | 8.1.2 · 8.0.5 | `appUrlOpen`·`backButton`·`getInfo` · Custom Tabs 로그인 | 필요(browser 는 F-4016 부터) |
| `@capacitor/push-notifications` | 8.1.3 | FCM | 보류(4장 A) |
| `@capacitor/status-bar` · `@capacitor-community/safe-area` | 8.0.4 · 8.0.1 | 시스템 바 | 안 씀 — core `SystemBars` 가 대신 |
- 서명 키: `.jks` 하나, 저장소 밖 `%USERPROFILE%\.android-keys\`. gradle 이 루트 `.env`(이미 gitignore) `ANDROID_KEYSTORE_PATH`·`ANDROID_KEYSTORE_PASSWORD`·`ANDROID_KEY_ALIAS`·`ANDROID_KEY_PASSWORD` 를 읽는다. **키를 잃으면 업데이트가 안 깔려 지우고 다시 깔아야 하고, 앱 출처의 로컬 문서가 사라진다** → 만든 날 비밀번호 관리자 + 외장 매체에 백업(`human-checks.md` 행)
- 버전: `android/version.properties` — `versionCode` 정수, 릴리스마다 +1, 되돌리지 않음 / `versionName` `YYYY.MM.DD`, 같은 날 두 번째부터 `.2`. 파이프라인 `npm run android:release`(`scripts/android-release.mjs`): 버전 올림 → `build:android` → `npx cap sync android` → `android/gradlew assembleRelease` → `app-release-{versionCode}.apk` 와 SHA-256 출력
- 올리는 곳: GitHub Releases 태그 `android-{versionCode}`(`gh release create`, 공개 저장소라 로그인 없이 받는다). 그다음 `public/android/latest.json` 을 고쳐 웹 배포. 서버 API 를 깨는 배포는 같은 날 APK 도 올린다 — 번들이 서버보다 늦다. 의존성 버전은 exact 고정. 대안 TWA 는 원격 로드라 결정 2 와 어긋나고, RN 재작성은 `.workflow/architecture.md` 4장에서 이미 버렸다
