# F-234 제목 크기 축소, 폴더 경로 표시

작성일: 2026-09-16
상태: 사용자 승인(2026-09-16 "이대로 승인·구현"). 사용자 요청(2026-09-16) "현재 제목이 상단에 크게 노출되는데 20px 정도로 크기 조정", "폴더 밖에 있을경우 제목만 노출", "폴더 안에 있을경우 {{폴더명}} / {{제목}} 으로 노출". 사용자 선택: 경로 범위 "전체 경로"(다단계면 `A / B`), 폴더명 "클릭 가능하게"
근거: F-217(제목 위젯·크기·포커스 규칙), F-126(사이드바 폴더 펼침·`ancestorsOfDoc`), `src/lib/folderTree.ts`(~~폴더는 최대 2단계~~ 깊이 제한 없음 — 경로는 접지 않고 줄바꿈으로 전부 보인다 (2026-09-23, F-2017) — `canMoveFolder`)

## 1. 범위

### 한다
- 제목 글자 크기를 지금 배율(`calc(var(--md-font-size) * 2)`, 기본 32px)에서 고정 20px 로 줄인다. 편집·원문·보기 모드(`.doc-title`·`.doc-title-view`) 공통
- 문서가 폴더 안에 있으면(`doc.folderId !== null`) 제목 위(F-217 "제목" 작은 표시가 있던 자리)에 폴더 경로를 보여준다: 최상위 폴더부터 문서가 든 폴더까지 `A / B` 형태(~~폴더는 최대 2단계라 `/` 는 많아야 1개~~ 깊이 제한 없음 — 경로는 접지 않고 줄바꿈으로 전부 보인다, 2026-09-23, F-2017)
  - 편집·원문 모드: `.doc-title-label` 자리를 폴더 경로로 바꾼다(폴더 밖이면 지금처럼 "제목")
  - 보기 모드: 지금은 아무 표시가 없던 자리(`h1.doc-title-view` 바로 위)에 폴더 안일 때만 새로 넣는다
- 폴더 이름을 누르면 사이드바에서 그 폴더 행을 찾아 스크롤해 보여주고 잠깐 강조한다. 폴더는 문서를 열 때 이미 펼쳐져 있다(`ancestorsOfDoc`, F-126.md 5.1) — 이 기능은 펼치지 않고 스크롤·강조만 한다
- 사이드바가 접혀 있거나(레일) 좁은 창이라 숨겨져 있으면, 폴더 이름 클릭이 사이드바를 펼친 뒤 스크롤·강조한다

### 하지 않는다
- 공개 공유 화면(F-230 `PublicView`)·초대받은 화면(`SharedView`) — 이 화면들은 폴더 목록이 없다. `viaFolder`(F-212, 공유 폴더로 보이는 문서 표시)와는 다른 기능이라 건드리지 않는다
- 폴더 경로 글자 크기·배치를 더 다듬는 것(예: 구분자 모양) — 기본 `.doc-title-label` 모양 그대로 재사용
- 제목 글자 크기를 설정 가능하게 만들지 않는다(F-154 본문 글자 크기 3단계와는 별개, 제목은 고정값)

## 3. 요구사항

### 3.1 제목 크기
- `.doc-title`·`.doc-title-view` 의 `font-size: calc(var(--md-font-size) * 2)` → `20px` (고정, 글자 크기 설정과 무관)
- 그 외(줄 높이 1.25, 굵기 700, `--font-display`)는 그대로

### 3.2 폴더 경로 계산
- `ancestorsOfDoc({ folders, doc })`(`src/lib/folderTree.ts`, 이미 있음)로 최상위→하위 폴더 id 배열을 얻고, 각 id 를 `folders` 에서 이름으로 매핑해 `{ id, name }[]` 를 만든다
- 문서가 폴더 밖이면(`doc.folderId === null`, 또는 매핑 실패) 빈 배열 — 편집·원문 모드는 "제목" 표시로 되돌아가고, 보기 모드는 아무것도 안 보인다

### 3.3 편집·원문 모드 표시
- `.doc-title-label` 자리에: 경로가 있으면 폴더 이름마다 `<button class="doc-title-crumb">`, 사이에 `<span class="doc-title-crumb-sep">/</span>` (앞뒤 공백 포함, "A / B")
- 경로가 없으면 지금처럼 정적 텍스트 "제목" (`aria-hidden`, 버튼 아님)
- `TitleWidget.updateDOM` 은 `eq()` 가 `breadcrumb` 배열도 비교해 값이 바뀌면 `toDOM` 을 다시 부르게 한다(폴더 이동으로 경로가 바뀔 때만 재생성 — 흔치 않은 경우라 F-217 2.2 의 "포커스 유지" 예외로 둔다. 제목 textarea 자체는 다시 만들지 않도록 기존 노드를 재사용해도 되지만, 구현 단순성을 위해 경로가 바뀌면 위젯 전체를 새로 그려도 된다 — 어차피 텍스트 입력 중엔 경로가 바뀌지 않는다)

### 3.4 보기 모드 표시
- 경로가 있을 때만 `h1.doc-title-view` 바로 위에 같은 모양(`doc-title-label`·`doc-title-crumb`) 렌더. 경로가 없으면 지금처럼 아무것도 없음(레이아웃 안 밀림, F-217.md 4장 여백 그대로)

### 3.5 폴더로 이동
- `onNavigateFolder(folderId)`: 사이드바에서 `[data-folder-id="${folderId}"] .tree-row`(F-153 참고 모양)를 찾아 `scrollIntoView({ block: 'nearest' })`, 짧게(600ms 안팎) 강조 클래스를 붙였다 뗀다(`InviteDialog.tsx` 강조 패턴, 접근성상 `prefers-reduced-motion` 이면 즉시 사라짐)
- 사이드바가 레일(접힘, F-143)이거나 좁은 창에서 숨겨져 있으면 먼저 펼친다(`toggleSidebarCollapsed`·좁은 창 열기, 기존 함수 재사용) — 그다음 스크롤·강조
- 대상 폴더 행이 없으면(사이드바 자체가 없는 상태 등) 아무 것도 하지 않는다(에러 없음)

### 3.6 접근성
- 폴더 이름 버튼은 `aria-label="{{폴더명}} 폴더로 이동"`, Tab 으로 닿고 Enter/Space 로 동작
- 강조는 `aria-live` 가 아니라 시각 효과만(스크린리더에 별도 알림 없음 — 포커스는 폴더 이름 버튼에 남아 있어 다음 Tab 이 자연스럽다)
