# F-260 Mermaid 다크모드 지원

작성일: 2026-09-18
상태: 사람 승인 — 받음 (2026-09-21). 사용자 요청("머메이드 다크모드 지원해야함"). F-258(Mermaid 다이어그램)에서 놓친 부분 — 지금은 앱 테마(화이트·세피아·다크, `specs/design.md` 3.4)와 무관하게 항상 mermaid 기본(밝은) 테마로만 그려진다
근거: F-258 구현(`src/lib/mermaidRender.ts`·`mermaidWidget.ts`·`Viewer.tsx`), F-103 `createEditor.ts` 의 `previewCompartment`/`setViewMode` 재구성 패턴(테마별로 같은 패턴 재사용)

사용자 확인 결과(2026-09-18):
- 설정 대화상자에서 테마를 바꾸면 이미 화면에 그려진 다이어그램도 **즉시 다시 그린다**(편집 모드 위젯 + 보기 모드 둘 다)
- **세피아는 화이트와 동일하게** mermaid 기본(밝은) 테마로 그린다. mermaid 쪽 테마 전환은 다크일 때만 일어난다

## 2. 요구사항

### 2.1 테마 매핑 (`mermaidRender.ts`)
- 앱 테마 3종(`white`\|`sepia`\|`dark`) → mermaid 테마 2종: `white`·`sepia` → mermaid 기본(`'default'`, 생략과 동일), `dark` → `'dark'`
- `renderMermaid(source: string, appTheme: string): Promise<MermaidResult>` — `appTheme` 이 모르는 값이면 `'default'` 로 본다(안전한 폴백, `resolveTheme` 의 "모르는 값은 system" 과 같은 방어적 패턴)
- 마지막으로 `mermaid.initialize` 에 넘긴 mermaid 테마를 모듈 스코프에 기억해 두고, 매핑 결과가 그것과 같으면 재호출하지 않는다(F-258 "1회만 호출" 취지를 "테마가 바뀌지 않는 한 1회만" 으로 바꾼다). 다르면 `mermaid.initialize({ startOnLoad: false, theme })` 로 다시 부른다
- `renderMermaid` 안에서 `ensureTheme` 호출과 `mermaid.render` 호출 사이는 동기 구간이라(첫 `await` 전) 두 렌더 요청이 초기화를 서로 덮어써 섞이는 일은 없다(JS 싱글스레드) — 다만 테마 전환 과도기(2.3의 재렌더 트리거 전)에 옛 테마로 시작된 렌더가 뒤늦게 끝나는 경우는 있을 수 있다. 이번 라운드에서는 대비하지 않는다(사람 확인, 2.5)

### 2.2 편집 모드 위젯 (`mermaidWidget.ts`, `blocks.ts`)
- `MermaidWidget` 생성자에 `theme` 인자 추가. `eq()` 비교 키에 `theme` 도 넣는다(소스가 같아도 테마가 다르면 다른 위젯 — 새 DOM 을 만들어 다시 그리게 하기 위해서다)
- 캐시(`cacheByView`) 키를 소스 문자열에서 `` `${theme}:${source}` `` 로 바꾼다
- `codeWidget(state, node, blockFrom, theme)` 이 `MermaidWidget` 생성 시 `theme` 을 넘긴다. `buildBlocks(state, hasFocus, resolveAttachment, theme)` 로 인자를 관통시킨다(기본값은 없음 — 호출부가 항상 넘긴다. 테스트는 명시적으로 넘긴다)
- `blockPreview({ resolveAttachment, theme })` 가 `buildBlocks` 에 `theme` 을 넘긴다

### 2.3 테마 전환 시 즉시 재렌더 (`createEditor.ts`)
- `previewExtensionFor(mode, theme, callbacks)` 로 `theme` 인자를 추가해 `livePreview({ ..., theme })` 에 관통시킨다
- `createEditor` 내부에 현재 테마를 담는 변수(예: `let currentTheme = initialTheme`)를 두고, 새 핸들 메서드 `setTheme(theme: string)` 을 추가한다: `currentTheme` 을 갱신하고 `setViewMode` 와 같은 방식으로 `previewCompartment.reconfigure(previewExtensionFor(viewMode, currentTheme, callbacks))` 를 `dispatch`(스크롤 위치는 안 바뀌므로 `scrollSnapshot` 불필요)
- `setViewMode` 도 `previewExtensionFor` 호출에 `currentTheme` 을 넘기도록 고친다(모드 전환 때 테마를 잃지 않는다)
- `previewCompartment` 를 다시 구성하면 그 안의 `StateField`(`blocks.ts` 의 `field`) 가 `create` 부터 다시 돌아 `buildBlocks` 를 호출한다 — 이때 모든 `MermaidWidget` 이 새 `theme` 으로 만들어지므로 `eq()` 가 거짓이 되어 `toDOM` 이 다시 불린다(2.2). 별도의 `forceRecalc` 트랜잭션은 필요 없다
- `createEditor` 의 초기 `theme` 인자(`initialTheme`)는 호출부(`App.tsx`)가 최초 마운트 시 넘긴다

### 2.4 보기 모드 (`Viewer.tsx`, `App.tsx`, `PublicView.tsx`)
- `Viewer` 에 `theme?: string` prop 추가(생략 시 `'white'` 로 본다 — 지금 기본과 동일). mermaid 렌더링 `useEffect` 의 의존성 배열에 `theme` 을 추가하고, `renderMermaid(source, theme)` 로 호출한다(테마가 바뀌면 `html` 은 그대로라도 effect 가 다시 돌아 다이어그램을 다시 그린다)
- `App.tsx`: `resolvedTheme` state(`'white'`\|`'sepia'`\|`'dark'`, 초기값은 마운트 시점 `resolveTheme(themePref, prefersDark)`) 를 추가한다. 갱신 지점 둘:
  - 시스템 설정 따라가기 `useEffect`(846~856행 근처)의 `apply()` 안에서 `document.documentElement.dataset.theme` 을 쓰는 자리에 `setResolvedTheme(...)` 도 같이 부르고, `editorRef.current?.setTheme(...)` 도 부른다
  - `changeTheme(value)` 함수 안에서 같은 자리에 `setResolvedTheme(...)` ·`editorRef.current?.setTheme(...)` 를 추가한다
  - `Viewer` 를 그리는 자리(보기 모드 전환 화면)에 `theme={resolvedTheme}` 을 넘긴다
- `PublicView.tsx`: `usePublicSettings`(또는 해당 훅) 가 이미 `theme` pref 와 시스템 설정 감지를 갖고 있다 — 같은 자리에서 적용된 테마(`resolveTheme(theme, prefersDark)`)를 계산해 `Viewer` 의 `theme` prop 으로 넘긴다(공유·공개 보기는 CM6 에디터가 없으므로 `setTheme` 핸들 호출은 필요 없다)

### 2.5 스타일 — 이번 라운드에 다루지 않음
- mermaid `'dark'` 테마 기본 팔레트를 그대로 쓴다. 앱의 `--panel`/`--paper`/`--accent` 토큰에 맞춰 `themeVariables` 로 세부 조정하는 것은 범위 밖(추가 명세 필요하면 나중에)
- 다크 테마에서 다이어그램이 배경과 잘 어울리는지, 오류 문구 톤이 여전히 맞는지는 사람이 보고 판단(`specs/human-checks.md`)
