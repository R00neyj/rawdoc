## 2. 범위

### 한다
- 1단계(명령 단계)를 **구역 목록**으로 바꾼다: 빈 입력은 `고정`·`최근`·`최근 문서`(+ 14장 Q1 `명령`), 입력이 있으면 `문서`·`명령`, `>` 로 시작하면 명령만
- 문서를 제목 + 폴더 경로로 찾아 연다. `Ctrl+Enter`·`Ctrl`+클릭은 새 탭
- `'{제목}' 새 문서 만들기` 줄 — 고르면 그 제목으로 만들어 연다
- 초성·받침 느슨한 비교 — 명령 라벨·키워드, 템플릿 이름(2단계), 문서 제목·경로 모두
- 최근 쓴 명령 기억, 명령 고정(`Alt+P`·핀 아이콘)
- 사이드바 머리 줄·레일·좁은 창 상단바·휴대폰 폭 사이드바 버튼 줄에 `명령 팔레트` 버튼

- 설정 화면의 고정·최근 관리 UI, 최근 명령 지우기 버튼
- 휴대폰 제스처(당기기·밀기) 진입, 앱 전역 새 단축키

- `all`: `e2ee === 'locked'` 인 문서를 **뺀** 전부(사용자 결정 12. 앱 층에서 잠긴 문서의 제목은 빈 문자열이다 — `src/types.ts`). 열린 금고 문서(`'open'`)는 넣는다. 공유받은 문서(`role` 이 `edit`·`view`)도 넣는다 — 사이드바 `공유받음` 에 제목이 보이고 검색 대화상자도 제목으로 찾는다(F-287). 입력 순서를 지킨다

- `folderPath`: `folderPathMap(folders)`(`src/app/searchIndex.ts`) 로 만든 표에서 `folderId` 를 찾는다. `null`·없는 폴더·공유받은 문서는 `''`
- `recent`: **홈 화면 `최근 문서` 와 같은 출처** — App 이 `EmptyState` 에 넘기는 `ownedDocs`(공유받은 문서 뺀 것) 순서에서, **지금 연 문서(`currentDocId`)와 잠긴 문서를 빼고** 앞 `PALETTE_RECENT_DOC_LIMIT`(5)개. 홈 화면은 지금 연 문서가 없어 같은 5개가 되고, 편집 화면에서는 지금 문서를 빼야 고를 값이 있다. 홈 화면이 잠긴 문서를 `잠긴 문서` 로 보여 주는 것과 달리 팔레트는 뺀다 — 결정 12, 그리고 잠긴 문서를 골라 봐야 잠금 화면(F-409 P1)이 뜰 뿐이다
- 최근 문서의 순서는 **수정 최근순**(`updatedAt`)이다. "최근 연 순서" 는 앱이 기록하지 않는다(`md.lastDocId` 하나뿐) — 14장 Q5

### 4.3 조각 매칭 — `src/lib/hangulMatch.ts`

```ts
export type MatchText = { plain: string; compact: readonly string[] }   // 정규화한 글 / 공백을 모두 뗀 글자 배열
export type MatchTerm = { plain: string; chars: readonly string[]; loose: boolean; last: boolean }
export type TermHit = { start: boolean; loose: boolean }   // start = 대상 글 머리에서 맞았나, loose = 4.3 느슨한 비교로만 맞았나
export function prepareMatchText(text: string): MatchText
export function splitMatchTerms(query: string, options?: { slash?: boolean }): MatchTerm[]
export function matchTerm(term: MatchTerm, text: MatchText): TermHit | null
```

조각 하나가 대상 글 하나(라벨, 키워드 하나, 문서 제목, 폴더 경로 …)에 맞는지 이 순서로 본다

1. **일반 비교.** 조각이 정규화한 글의 부분 문자열이면 맞다(`loose: false`). 머리에서 시작하면 `start: true`. F-2022 3.4 와 같은 뜻이다
2. **느슨한 비교** — 1 이 안 맞고, 조각에 **초성 자모**가 있거나 **마지막 조각의 마지막 글자가 받침 없는 음절**일 때만 한다. 대상 글에서 **공백을 모두 뗀 글자열**(`compact`)의 어느 자리부터 조각 글자 수만큼 한 글자씩 비교해 모두 맞으면 맞다(`loose: true`). 자리 0 이면 `start: true`. 글자 하나의 비교:
   - **같은 글자**면 맞다
   - 조각 글자가 **초성 자모**(U+3131~U+314E 가운데 첫소리로 쓰이는 19개: `ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ`)면, 대상 글자가 한글 음절(U+AC00~U+D7A3)이고 그 첫소리가 같을 때 맞다. 첫소리 = `(code − 0xAC00) / 588` 의 몫
   - **된소리는 따로 본다.** `ㄱ` 은 `꼭` 에 안 맞고 `ㄲ` 만 맞다(확인 (b)). 한글 입력기에서 `ㄲ` 은 `Shift` 로 따로 치는 글자라, 섞으면 `ㄱ` 한 글자에 걸리는 결과가 쓸데없이 는다
   - **마지막 조각의 마지막 글자**가 받침 없는 음절(`(code − 0xAC00) % 28 === 0`)이면, 대상 글자가 첫소리·가운뎃소리가 같은 음절(받침은 무엇이든)일 때도 맞다. 한글을 치는 도중 `템플` 이 `템프` 를 지나가는 순간 목록이 비는 것(F-2022 H4)을 막으려는 것이다(확인 (b) `템프`↔`템플릿`)
3. 조각의 **겹자음**은 느슨한 비교 전에 두 초성으로 푼다: `ㄳ→ㄱㅅ`, `ㄵ→ㄴㅈ`, `ㄶ→ㄴㅎ`, `ㄺ→ㄹㄱ`, `ㄻ→ㄹㅁ`, `ㄼ→ㄹㅂ`, `ㄽ→ㄹㅅ`, `ㄾ→ㄹㅌ`, `ㄿ→ㄹㅍ`, `ㅀ→ㄹㅎ`, `ㅄ→ㅂㅅ`. 두벌식 입력기에서 초성만 이어 치면 `ㄱ`+`ㅅ` 이 `ㄳ` 한 글자로 합쳐지는 경우가 있어서다(Windows·macOS 기본 입력기의 동작으로 알고 있으나 이 PC 에서 재지 않았다 — 15.2, 사람 확인 H4). 일반 비교(1)는 풀기 전 글자로 한다 — 제목에 `ㄳ` 이 글자 그대로 있으면 1 에서 맞는다
4. 모음 자모(`ㅏ` 등)·옛한글·첫가끝 조합형 자모(U+1100~)는 초성으로 치지 않는다 — 같은 글자일 때만 맞는다. 검색어는 NFC 로 정규화되므로 입력기에서 온 음절은 완성형이다(확인 (c))

**여러 조각(AND):** 모든 조각이 대상 글들 중 어느 하나에 맞아야 남는다. 한 조각이 두 필드에 걸쳐 맞지는 않는다(필드마다 따로 비교한다. F-2022 의 "공백으로 이은 글" 도 조각에 공백이 없어 결과가 같다)

**왜 공백을 떼나:** 사용자 결정 6 의 예 `ㅅㅁㅅ` → `새 문서` 는 공백을 건너뛰어야 맞는다. 일반 비교(1)는 공백을 그대로 두므로 `새문서` 처럼 붙여 친 일반 글자 조각은, 마지막 조각의 마지막 글자가 받침 없는 음절일 때만 느슨한 비교로 맞는다 — 알려진 모양으로 둔다(해가 없다: 결과가 늘 뿐이다)

**비용:** 느슨한 비교는 조각 길이 × 대상 길이. 확인 (a) 에서 5,000개·최악 2.3 ms 다

### 4.4 문서 거르기 — `filterPaletteDocs`
- 대상 글 = `title`, `folderPath` 둘(4.1 공백·`/` 쪼개기)
- 순서 — 위에서부터 먼저 정한다
  1. 단계: ① 제목이 **첫 조각으로 시작**(`matchTerm` 의 `start`) ② 모든 조각이 **제목 안에** ③ 그 밖(한 조각이라도 폴더 경로에서만 맞음)
  2. 같은 단계 안: 느슨한 비교를 **하나도 쓰지 않은** 문서 먼저. `가`(마지막 조각)를 쳤을 때 `가계부` 가 `강아지` 보다 앞선다
  3. 그다음 입력 순서(수정 최근순, 안정 정렬)
- 앞 `limit`(`PALETTE_DOC_LIMIT` = 6, 사용자 결정 2)개만. 더 있어도 "더 보기" 는 없다 — 더 치면 좁혀진다
- 텍스트가 비면 빈 배열(빈 입력의 문서는 `recent` 가 맡는다)

### 4.5 명령 거르기 — `filterPaletteItems` (F-2022 3.4 를 넓힌다)
- 대상 글 = `label`, `detail`, `keywords` 각각(4.1 공백 쪼개기)
- 순서: ① `label` 이 첫 조각으로 시작 ② 모든 조각이 `label` 안에 ③ 그 밖(키워드·detail 에서만 맞은 조각이 있음). 같은 단계 안은 느슨한 비교 안 쓴 것 먼저, 그다음 **넘겨받은 순서**(안정)
- F-2022 는 ①·나머지 두 무리였다. ②를 떼어 앞에 두는 것은 "라벨에 다 있는 명령" 이 "키워드로만 걸린 명령" 보다 앞서게 하려는 것이다. F-2022 U1 의 기대값 7개는 이 규칙에서도 그대로 나온다(`'템플'` → a(①), c(②))
- **넘겨받은 순서**가 1단계에서는 `고정 → 최근 → 등록 순서`(5.2)다. 그래서 칠 때도 같은 단계 안에서는 최근 쓴 명령이 앞선다. 치는 글이 가장 강한 신호라 최근 사용이 머리 일치를 이기지는 못하게 한 것이다(14장 표 Q3)

## 5. 1단계 구역 — `buildPaletteSections`

### 5.1 빈 입력(`mode: 'all'`, 텍스트 빔)

| 순서 | 구역 key | 머리글 | 줄 |
| --- | --- | --- | --- |
| 1 | `pinned` | `고정` | `pinnedIds` 순서대로, 보이는(`commands` 에 있는) 명령만 |
| 2 | `recent` | `최근` | `recentIds` 순서대로, 보이고 **고정 안 된** 명령만, 앞 `PALETTE_RECENT_COMMAND_LIMIT`(5)개 |
| 3 | `recentDocs` | `최근 문서` | `recentDocs` 그대로(4.2, 최대 5) |
| 4 | `commands` | `명령` | 위 1·2 에 안 나온 보이는 명령, 등록 순서 — **14장 Q1** |

- 명령 하나는 한 구역에만 나온다(고정 > 최근 > 명령)

### 5.2 입력 있음

| 모드 | 구역(순서) |

### 5.3 `parsePaletteQuery`
- 입력 글의 **앞 공백을 뗀 첫 글자가 `>`**(U+003E)이면 `mode: 'commands'`, `text` = 그 `>` 뒤 전부. 아니면 `mode: 'all'`, `text` = 입력 그대로

## 6. `새 문서 만들기` 줄

### 6.1 뜨는 조건 — `planPaletteCreate` (`src/app/paletteDocs.ts`)

```ts
export function planPaletteCreate(text: string, env: {
  resolver: WikiResolver               // App 의 wikiResolver (docs 전부 + folders)
  sourceFolderId: string | null        // App 의 currentFolderId
  fallbackFolderId: string | null      // App 의 newDocFolderId()
  folderPathOf: (folderId: string | null) => string   // folderPathMap 조회, null·없는 폴더는 ''
}): PaletteCreatePlan | null
```

위에서부터, 하나라도 걸리면 `null`(줄 없음)

1. 앞뒤 공백을 뗀 `t` 가 빔
2. `t` 가 **한글 자모와 공백으로만** 되어 있음(U+3131~U+3163). `ㅅㅁㅅ` 는 찾으려는 글이지 제목이 아니다. 그리고 한글을 치는 도중 첫 글자(`ㅎ`)마다 만들기 줄이 깜빡이지 않게 한다
3. **이미 있는 문서** — `resolver.resolve(t, sourceFolderId)` 가 문서를 돌려줌. 위키링크 `[[t]]` 가 풀리는 문서가 있으면 만들지 않는다: 대소문자 무시·`.md` 떼기·경로 형태를 위키링크와 같은 규칙으로 판정하게 되고(F-2018), 사용자 결정 3 의 "제목이 정확히 같은 문서가 없으면" 을 한 함수로 옮긴 것이다. 부분만 맞는 문서가 있어도(`회의` 를 쳤는데 `회의록` 이 있음) 줄은 뜬다 — 그렇지 않으면 `회의` 라는 문서를 팔레트로 만들 길이 없다
4. 제목·폴더: `resolver.findLinkFolder(t, sourceFolderId)` 가 값을 주면 그 `folderId`·`title`(`업무/주간 보고` → 폴더 `업무`, 제목 `주간 보고`). 없으면 제목 = `t`(`/` 가 든 글자 그대로), 폴더 = `fallbackFolderId`. **없는 위키링크를 눌러 만들 때(`openWikiLinkTarget`)와 같은 규칙**이다 — 사이드바 `새 문서` 의 "지금 문서의 폴더" 규칙(`newDocFolderId`, F-138 3.4)도 여기서 그대로 쓰인다
5. 제목이 `E2EE_MAX_PLAIN_TITLE_CHARS`(500, `src/lib/e2eeLimits.ts` — 서버 `MAX_TITLE_CHARS` 와 같은 값)자(`String.length`)를 넘음. 서버가 거부할 제목을 줄로 보이지 않는다
6. 그 밖 → `{ title, folderId, folderPath: folderPathOf(folderId) }`

- `>` 모드·빈 입력·2단계에서는 `CommandPalette` 가 `planCreate` 를 부르지 않는다(3.1)
- 줄을 숨기는 화면 조건은 두지 않는다. 사이드바 `새 문서` 가 막히지 않는 곳이면 팔레트 만들기도 막지 않는다 — 공유 링크 화면 S-4(버튼으로 연 경우, 10.3)·보기 권한 문서를 보는 중·읽기 전용 문서 위에서도 **내** 새 문서는 만들 수 있다. 팔레트 자체가 안 열리는 곳(공개 보기 S-5, 부팅 중)은 F-2022 6.1 그대로

### 6.2 대상 폴더가 금고 폴더일 때
- `ensureE2eeOpenForFolder(folderId)` 를 먼저 부른다(사이드바 `새 문서`·위키링크 만들기와 같다, F-405 7.6). 잠겨 있으면 금고 열기 창이 뜨고, 닫으면 아무것도 만들지 않는다

### 6.3 만들기 — App 의 `create(plan)`
- 팔레트를 **먼저 닫는다.** 그다음 `openWikiLinkTarget` 의 만들기 갈래와 같은 순서: 보기 모드면 편집으로 → `beforeLeaveDoc` → 공유 링크 화면·공유 관리·도움말·지도를 떠난다(`selectDoc` 이 떠나는 네 화면과 같다) → `buildNewDocContent({ title })`(새 문서 템플릿의 `{{title}}` = 만드는 제목, F-2037 4.1 위키링크와 같다) → `store.create({ title, content, lineEnding: 'crlf', folderId })` → 목록·펼친 폴더·`md.lastDocId`·해시 갱신 → 좁은 창이면 사이드바 닫기
- 실패 알림은 기존 문구 그대로(`새 문서를 만들지 못했습니다. 다시 시도하세요.`, 템플릿 읽기 실패 `새 문서 템플릿을 읽지 못해 빈 문서로 만들었습니다.`)
- **포커스는 본문 에디터**다(제목 입력이 아니다). 사이드바 `새 문서`·위키링크 만들기는 제목 입력에 포커스하지만(ia 3.3), 여기서는 사용자가 방금 제목을 쳤다 — 옵시디언 퀵 스위처도 만든 노트의 본문으로 간다. `Dialog` 의 닫힘 포커스 복귀를 이기는 방법은 `openDocFromSearch` 와 같다(다음 틱에 에디터 포커스) — 14장 표 Q8
- 구현이 `openWikiLinkTarget` 의 만들기 갈래와 한 함수로 합쳐도 되고 따로 둬도 된다. 합친다면 위키링크 쪽 동작(제목 포커스, 떠나는 화면)이 바뀌지 않아야 한다 — 위키링크 e2e(`F-2018`)가 판정한다

## 7. 최근·고정 기억 — `src/app/paletteMemory.ts`

### 7.1 최근 쓴 명령
- 1단계에서 명령을 고르면 그 id 를 **맨 앞**에 넣고, 같은 id 가 뒤에 있으면 뺀다. 길이 상한 `PALETTE_RECENT_STORE_LIMIT` = **10**
- 화면에는 5.1 규칙으로 최대 `PALETTE_RECENT_COMMAND_LIMIT` = **5**개. 저장을 10개로 두는 이유: 지금 화면에서 안 보이는 명령(`when` 거짓 — 홈 화면의 `템플릿 삽입` 등)이 앞을 차지해도 보일 5개를 채울 여유
- 저장 시점은 고른 즉시(명령 실행 전). 실행이 실패해도 기록은 남는다

### 7.2 고정
- 1단계의 명령 줄에서 `Alt+P` 또는 핀 버튼 → 고정돼 있으면 빼고, 아니면 **맨 뒤**에 더한다(고정한 순서, 사이드바 `고정됨` 과 같은 규칙 — ia 3.21)
- 개수 상한은 두지 않는다 — 등록된 명령 수가 상한이다
- 문서·만들기 줄에서는 `Alt+P` 가 아무것도 하지 않는다(알림도 없다)

### 7.3 localStorage 키 (제품 이름을 넣지 않는다 — 불변조건)

| 키 | 값 | 기본 | 명세 |
| --- | --- | --- | --- |
| `md.paletteRecent` | 명령 id JSON 배열, 최근 쓴 것부터, 최대 10 | 없음(`[]` 로 읽는다) | F-2053 |
| `md.palettePinned` | 명령 id JSON 배열, 고정한 순서 | 없음(`[]` 로 읽는다) | F-2053 |

- 접근은 `prefs.ts` 의 `getPref`·`setPref` 만(architecture 4장). 두 키를 `PrefMap` 에 `string` 으로, `ALLOWED_KEYS` 에 더한다
- 기기(브라우저 프로필)마다 따로다. 계정으로 옮겨 다니지 않는다(사용자 결정 5·8). 로그아웃해도 지우지 않는다(`md.viewMode` 등 다른 화면 설정과 같다)

### 7.4 읽기와 정리

```ts
export function parseCommandIds(raw: string, known: ReadonlySet<string>): string[]
export function pushRecentCommand(ids: readonly string[], id: string): string[]
export function togglePinnedCommand(ids: readonly string[], id: string): string[]
export const PALETTE_RECENT_STORE_LIMIT = 10
export const PALETTE_RECENT_COMMAND_LIMIT = 5
```

- `parseCommandIds`: JSON 이 아니거나, 배열이 아니면 `[]`. 문자열이 아닌 원소·빈 문자열·**`known` 에 없는 id**(= 지금 `PALETTE_COMMANDS` 에 없는 명령 — 지워졌거나 이름이 바뀐 것)·두 번째 이후 중복은 뺀다. 순서는 지킨다. `known` 은 **등록된 전부**의 id 다(지금 `when` 이 거짓인 명령은 지우지 않는다)
- 정리한 결과는 **읽을 때 쓰지 않는다.** 다음에 최근·고정이 바뀌어 쓸 때 정리된 목록이 저장된다. 읽기가 부작용 없이 끝나야 여러 탭이 동시에 열어도 서로 덮지 않는다
- `CommandPalette` 가 **열릴 때마다** 두 키를 다시 읽는다(다른 탭에서 바꾼 것이 다음 열기에 보인다). 열린 동안 바꾼 것은 즉시 쓴다. `storage` 이벤트는 듣지 않는다
- 읽기·쓰기 예외(시크릿 창·차단)는 `prefs.ts` 가 삼킨다 — 그때 최근·고정은 이번 세션에만 산다

## 8. UI — `src/app/CommandPalette.tsx`

### 8.1 구조
- 1단계 목록은 `ul role="listbox"`(`id="command-palette-list"`, 그대로) 안에 **구역마다** `li role="none"` 하나: 머리글 `div.command-palette-section`(`id="command-palette-section-{key}"`, `role="presentation"`) + `ul.command-palette-group role="group" aria-labelledby="command-palette-section-{key}"` 안의 옵션들. `create` 구역은 머리글 없이 `ul role="group" aria-label="새 문서"` 하나
- 옵션 `id` 는 F-2022 그대로 `command-palette-option-{i}` — `i` 는 **구역을 넘어 이어지는** 0부터의 번호. `aria-activedescendant` 도 그 번호
- 2단계(템플릿)는 F-2022 그대로 — 구역 없음, 머리글 없음, 목록 `aria-label` 은 `템플릿`
- 머리글은 옵션이 아니다 — `getByRole('option')` 개수에 안 잡히고 선택되지 않는다

### 8.2 줄 모양
- 명령 줄: 왼쪽 `label`, 오른쪽 흐린 `shortcut`(F-2022 그대로. 새 단축키는 없다, 사용자 결정 11), 그 오른쪽 핀 버튼(8.3)
- 문서 줄: 왼쪽 제목, 오른쪽 흐린 5.4 글. 아이콘 없음
- 만들기 줄: 왼쪽 `'{제목}' 새 문서 만들기`, 오른쪽 흐린 폴더(`최상위`)
- 긴 제목은 한 줄 말줄임(지금 `.command-palette-item-label` 규칙 그대로)

### 8.3 핀 버튼·`Alt+P`
- 명령 줄에만 `button.command-palette-pin`. 아이콘: 고정 안 됨 `IconPin`, 고정됨 `IconUnpin`(사이드바 `상단 고정`·`고정 해제` 와 같은 한 벌, `src/app/icons.tsx` 의 `keep`·`keep_off`). 툴팁은 5.4(앱 툴팁 `IconTooltip` 이 아니라 `title` 속성 — 목록 줄 안이라 툴팁 층이 목록 스크롤에 잘린다. 사람 확인 H1)
- **보이는 때:** 고정된 명령 줄은 늘, 나머지는 줄에 마우스가 올라갔을 때와 선택된 줄(`--on`)일 때만
- 버튼은 `tabIndex={-1}`, **`aria-hidden="true"`** — 포커스는 늘 입력칸에 있고(F-2022 8.4), 키보드는 `Alt+P` 가 대신한다. 숨기는 다른 이유: 옵션의 접근성 이름에 버튼 이름이 섞이면 `getByRole('option', { name: '금고 잠그기', exact: true })`(`e2e/e2eeSearchExport.spec.js` `lockVaultViaPalette`)가 깨진다
- 누르면: `mousedown` 에서 기본 동작을 막아 입력칸 포커스를 지키고, `click` 은 줄 실행으로 번지지 않게 막고 고정을 토글한다
- `Alt+P`: 입력칸 `keydown` 에서 `altKey` 참, `ctrlKey`·`metaKey`·`shiftKey` 거짓, **`e.code === 'KeyP'`**, `isComposing` 거짓일 때. `e.key` 가 아니라 `e.code` 로 보는 이유: macOS `Option+P` 는 `e.key` 가 `π` 이고 한글 입력 상태에서는 다른 글자가 올 수 있다. 기본 동작을 막는다(`π` 가 입력칸에 안 들어가게)
- 토글 뒤 **선택은 같은 명령을 따라간다**(빈 입력이면 그 명령이 `고정` 구역으로 옮겨 가도 그 줄이 선택된 채). 지금 `pendingSelectId` 로 같은 일을 한다(`Backspace` 로 1단계에 돌아올 때)
- 왜 `Alt+P` 인가: 팔레트 입력칸은 글자 입력칸이라 글쇠 하나(`p`)·`Shift` 조합은 못 쓴다. `Ctrl+D`(옵시디언 북마크 연상)는 브라우저 북마크 키, `Ctrl+Shift+P` 는 파이어폭스 사생활 창 키다. `Alt+P` 는 앱 안 다른 쓰임이 없다(`grep -rn altKey src` — 표 칸 `Alt+Enter`·댓글 `Ctrl+Alt+M` 뿐). Windows Chrome 에서 `Alt` 단독은 메뉴를 부르지만 `Alt+P` 조합은 크롬 메뉴 가속키가 아니다(15.2 가정 — H5)

### 8.4 키보드 (F-2022 8.4 에 더하는 것)

### 8.5 문서 열기 — App 의 `open(id, target)`
- `'here'`: `openDocFromSearch(id, null)` 과 같은 순서 — 팔레트를 닫고 → `selectDoc(id)`(사이드바 선택과 같은 함수. 공유 링크 화면·공유 관리·도움말·지도를 떠난다) → 편집·원문 모드면 다음 틱에 주 에디터 포커스. 보기 모드면 에디터로 옮기지 않는다(F-287 4.6 과 같다). 지금 연 문서를 고르면 `selectDoc` 이 전환 없이 끝난다(읽음 처리만)

### 10.2 모양·문구
- 아이콘: Material Symbols Outlined 400 `terminal`(`@material-symbols/svg-400/outlined/terminal.svg`, 있음 확인). `icons.tsx` 에 `export const IconCommandPalette = makeIcon(terminalSvg)`. 옵시디언 리본의 명령 팔레트 아이콘이 터미널 모양이다(기억에 기댄 것 — 15.2). 다른 후보는 14장 Q2

- 상수: `SidebarHead.tsx` 에 `export const PALETTE_LABEL = '명령 팔레트'`(지금 `SEARCH_LABEL` 옆). `Sidebar.tsx` 레일·버튼 줄이 이 상수를 쓴다

### 10.3 누르면
- `bootPhase !== 'ready'` 면 아무것도 안 한다(`openSearch` 와 같은 이유 — 부팅 중 저장소는 임시 `memoryStore`)
- 그 밖에는 `openPalette()` 그대로(우클릭 메뉴 닫기, 좁은 창 겹침 사이드바 닫기, 금고 상태 읽기). 휴대폰 폭에서 겹친 사이드바의 버튼을 누르면 사이드바가 닫히고 팔레트가 뜬다
- **공유 링크 화면 S-4 에서도 연다.** `Ctrl+P` 는 S-4 에서 브라우저 인쇄로 남기지만(F-2022 6.1) 버튼에는 인쇄와 겹칠 일이 없다. 명령은 `when` 이 걸러(`canPrint` 거짓 등) 문서 열기·만들기만 남는다. 검색 버튼도 S-4 에서 열린다(`openSearch` 는 S-4 를 보지 않는다)
- 팔레트가 이미 열려 있을 때는 버튼이 뒤 막에 가려 누를 수 없다
