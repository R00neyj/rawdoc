### 4.2 최신값 effect 와 ref (3.2)

- **deps — 이 조각에서 유일하게 모양이 바뀌는 코드 줄.** 테마 effect `[themePref]` → `[themePref, editorRef]`. 근거는 머리의 ESLint 실측. `editorRef` 는 App 의 `useRef` 결과라 정체성이 바뀌지 않으므로 effect 가 다시 도는 때(구독·해제)는 지금과 같다. F-2061 5.2·F-2062 4장과 같은 처리. `eslint-disable` 로 막지 않는다(3.7)

### 4.5 공개 보기 조기 반환 (3.5)

훅 호출(≈2311)은 조기 반환(≈4988)보다 위 — 공개 보기 렌더에서도 매번 불린다. 훅 인자는 `editorRef` 하나(조기 반환 위). 훅 안 테마 effect 는 지금처럼 공개 보기 렌더에서도 돌며 `themePref` 와 `editorRef.current`(공개 보기엔 편집기가 없어 `null`)만 읽는다. `publicView.spec.js` 를 묶음에 둔다(8장)

### 4.6 훅 호출 자리 (3.8)

- **테마 effect 가 있던 자리**에서 부른다 — "OS 에서 .md 파일로 열기 연동" effect 바로 아래, "좁은 창 감지" effect 바로 위. 호출 위 한 줄 주석 `// ----- 설정값·시스템 테마 (F-2063) -----`. 원래 절 머리 주석(`테마: 시스템 설정을 즉시 따라간다`)은 훅 안 effect 위로 간다
- 이 조각의 덩어리는 세 곳(상태 ≈330·≈379, effect ≈2311, 함수 ≈4821)에 흩어져 있다. 실행 순서가 있는 것은 effect 하나뿐이라 그 자리를 고른다 — 다른 App effect 와의 상대 순서가 바이트 단위로 같다. 상태 선언은 위치가 아니라 호출 순서만 의미가 있고, 함수 선언은 끌어올려진다
- 다른 자리를 고르지 않는 이유: 상태 선언 자리(≈330)는 `editorRef`(≈434) 선언보다 위라 훅 인자가 TDZ 에 걸리고, 테마 effect 가 App effect 들 중 훨씬 앞으로 옮겨 간다. 함수 자리(≈4821)는 테마 effect 가 편집기 반영 layout effect·자동 저장 등 여러 effect 뒤로 밀리고, 4.1 의 렌더 중 참조(`wikiContext` 등)가 훅 호출보다 위가 되어 TDZ 로 죽는다

App 호출(4.6 자리):

```ts
const {
  themePref, resolvedTheme, headingFont, bodyFont, fontSizePref, lineNumbersPref, indentPref, startScreenPref,
  toolbarPref, wikiPreviewPref, newDocTemplatePref, e2eeLockMinutesPref, contentWidthPref,
```

규칙과 이유:

- **반환 이름 = 지금 App 변수 이름.** 읽는 쪽(4.1 표) 줄이 한 글자도 바뀌지 않아 이동 판정이 깨끗하다. 묶음 객체(`prefs.theme` 등)로 바꾸지 않는다(11장 Q1)
- **세터는 반환하지 않는다.** `setThemePref` 등 13개는 ④ 함수 안에서만 불린다(`grep`). 훅 밖에서 저장 없이 상태만 바꾸는 길을 열지 않는다
- **결과 타입은 지금 `useState` 추론 그대로다.** `getPref` 가 리터럴 키에 `PrefMap[K]` 를 돌려줘 유니온이 된다. `wikiPreviewPref` 만 `string` — 지금 초기화식 `… === 'off' ? 'off' : 'on'` 이 `useState` 에서 `string` 으로 넓어진다(탐침에서 `'on' | 'off'` 로 적으면 TS2322). 좁히려면 초기화식에 타입 인자를 붙여야 해 옮기기가 아니게 된다(11장 Q3). 구현자는 결과 타입을 이 표 그대로 적는다. 타입이 안 맞으면 코드가 아니라 이 표가 틀린 것이므로 멈추고 보고한다
- 훅은 옵션을 매개변수 자리에서 구조 분해(`{ editorRef }`)해 옮긴 본문이 지금 이름 그대로 `editorRef` 를 읽게 한다(F-2062 4장과 같은 이유 — 이동 색 유지)
- 훅 안 순서: 상태 17개(2.1 순서) → 테마 effect → 함수 12개(2.1 순서) → `return`
- 파일 머리 한 줄 주석: `// 설정 대화상자·팔레트가 바꾸는 화면·편집기·자동 잠금 설정값과 시스템 테마 따라가기 (F-2063)`. 옮겨 온 주석은 그대로
- import: `useEffect`·`useState`·`type RefObject`(react), `type EditorHandle`(`../editor/Editor`), `getPref`·`setPref`(`./prefs`), `resolveTheme`(`./theme`), `resolveStoredContentWidth`·`CONTENT_WIDTH_VAR`(`./contentWidth`), `NEW_DOC_TEMPLATE_NONE`(`../lib/templates`)

## 11. 열린 질문 (모두 기본값, 사람 결정 필요 없음)

### Q1. 반환 모양 — **기본값: 평평한 이름 25개(지금 App 변수 이름 그대로)**

- 이유: 읽는 쪽 46줄(탐침 `grep` — 팔레트 context 8줄, `<SettingsDialog>` prop 24개, layout effect·`wikiContext` 본문과 deps, JSX)이 한 글자도 안 바뀌어 3.6 이동 판정에서 빨강·초록이 0 이다. 구조 분해 한 벌(6줄)로 끝난다
- 다른 쪽(`prefs.theme`·`prefs.change.theme` 같은 묶음 객체): App 줄 수는 몇 줄 더 줄지만 읽는 쪽 46줄이 이름 연결로 바뀌어 이동 판정이 흐려지고, F-2072 가 받을 인자 모양도 달라진다

### Q2. e2e 묶음에 `paletteApp`·`mermaid` 를 더하나 — **기본값: 더한다 (8장)**

- 이유: 팔레트에서 `changeTheme`·`changeLineNumbers` 를 부르는 경로(F-2054 A8·A9)와 `changeTheme` 의 편집기 `setTheme` → mermaid 재렌더(F-260 A2·A3)는 로드맵 묶음 8개가 보지 않는다. 테스트가 이미 있으니 묶음에만 넣으면 된다(F-2062 도 `paletteApp` 을 묶음에 넣었다). `mermaid.spec.js` 는 3개, `paletteApp.spec.js` 는 12개 안팎
- 다른 쪽(로드맵 행 그대로 8개): 실행이 조금 짧지만 팔레트 연결을 잘못 이어도 `typecheck` 말고는 잡는 것이 없다. `verify:full`(배포 전)까지 드러나지 않는다

### Q3. `wikiPreviewPref` 타입 — **기본값: 지금 추론 그대로 `string`**

- 이유: 지금 `useState` 가 `'off' | 'on'` 을 `string` 으로 넓힌다(탐침 TS2322). 좁히려면 초기화식에 타입 인자를 더해야 해 옮기기 밖 변경이다. 읽는 쪽은 모두 `=== 'on'` 비교라 차이가 없다
- 다른 쪽(`useState<'on' | 'off'>` 로 좁힘): 결과 타입이 깔끔해지지만 이동 판정 분류에 없는 코드 변경이 한 줄 생긴다. 하려면 분할이 끝난 뒤 따로

### Q4. 옮기면 틀려지는 주석 — **기본값: 그대로 둔다**

- `changeLineNumbers`·`changeIndent` 앞 주석의 "실제 반영은 아래 useLayoutEffect 가 한다" 는 옮긴 뒤 "아래" 가 아니라 App 쪽이다. F-2059 3.6 은 옮긴 코드의 주석을 그대로 가져가라고 하고 예외는 3줄 이상 덩어리뿐이다
- 다른 쪽("App 의 useLayoutEffect" 로 고침): 주석이 정확해지지만 이동 판정 분류 밖 줄이 2줄 생긴다. F-2072 가 그 layout effect 를 옮길 때 함께 고치는 편이 한 번으로 끝난다

기본값으로 정한 것(승인 시 확정): 훅 호출 자리 = 테마 effect 자리(4.6), 반환 이름 = App 변수 이름, 세터 비반환, 결과 타입 표(5장), 테마 effect deps 에 `editorRef` 추가, 특성 테스트 C1~C5, 묶음 11파일.
