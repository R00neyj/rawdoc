## 2. 범위

### 2.1 한다

- 사이드바·상단바 검색 버튼을 **누를 수 있게** 바꾼다 (3.3)
- `Ctrl+Shift+F`(macOS `Cmd+Shift+F`)로 연다 (3.4)
- 검색 대화상자 `SearchDialog.tsx` — 검색창 + 결과 목록 + 키보드 조작 (4장·5장)
- 대화상자를 열 때 `saver.flush()` → `buildSearchIndex()` 순서로 부른다 (4.2)
- 입력 디바운스 150ms → `parseSearchQuery` → `searchDocs` → 결과 행 (4.3·4.4)
- 결과를 눌러 문서 열기 (4.6)
- 상태 문구 3개만 — `검색어를 입력하세요` / `찾는 문서가 없습니다` / `문서를 읽지 못했습니다` (6장)
- 도움말 문장 수정 (3.6)

### 2.2 하지 않는다

- 쿼리 파싱·매칭·발췌 규칙 — **F-285 가 끝냈다.** 이 명세는 부르기만 한다
- 인덱스 자료구조·재사용·캐시 버리기 — **F-286 이 끝냈다**
- 안내 문구 전부와 꼬리 줄 — **F-288** (2.3)
- 최근 검색어 저장, 저장한 검색, 검색 결과 URL — F-284 5.4. **새 localStorage 키를 만들지 않는다**
- 결과에서 문서를 연 뒤 F-261 패널에 검색어를 넣기 — F-284 8장 Q3 기본값(넣지 않는다)
- 가상 스크롤, 웹 워커, 저장하는 역색인 — F-284 5.4
- 사이드바가 `memo` 가 아니라 생기는 다시 그리기 비용 고치기 (7.1 M3). **이 명세 밖이다**

### 3.4 단축키 `Ctrl+Shift+F`

`App.tsx` 의 `Ctrl+F`(946~961행)·`Ctrl+P`(963~974행) 바로 아래에 같은 모양의 `useEffect` 를 하나 더 둔다

```
useEffect(() => {
  if (publicRoute) return                      // 공개 보기(S-5)에는 저장소가 없다
  function handleKeyDown(e: KeyboardEvent) {
    if (!(e.ctrlKey || e.metaKey) || !e.shiftKey || e.altKey) return
    if (e.key.toLowerCase() !== 'f') return
    const open = document.querySelector('dialog[open]')
    if (open && !open.querySelector('.search-dialog')) return       // 다른 대화상자 위에 겹치지 않는다 (판정 근거는 4.1)
    e.preventDefault()
    if (open) { selectSearchQueryRef.current(); return }            // 이미 열려 있으면 검색어 전체 선택
    openSearchRef.current()
  }
  window.addEventListener('keydown', handleKeyDown)
  return () => window.removeEventListener('keydown', handleKeyDown)
}, [publicRoute])
```

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| `e.key.toLowerCase() !== 'f'` | `e.code` 가 아니라 `e.key` 를 쓴다 | 같은 파일 953·967행의 두 핸들러와 같은 방식. **Shift 를 누르면 `e.key` 는 대문자 `'F'` 로 온다 — 실제 Chrome 에서 확인했다**(7.2). `toLowerCase()` 가 그래서 필요하다 |
| `!e.shiftKey` 면 return | 넣는다 | 안 넣으면 `Ctrl+F` 와 둘 다 걸린다. 반대쪽(952행)도 이미 `e.shiftKey` 면 곧바로 return 한다 |
| `publicRoute` 면 등록하지 않는다 | 넣는다 | `App` 은 2441행에서 `PublicView` 로 조기 반환하지만 **훅은 그 전에 전부 돈다.** 공개 보기에서 남의 페이지에 내 문서 검색창이 뜨면 안 된다 |
| 다른 대화상자가 열려 있으면 무시 | `document.querySelector('dialog[open]')` 한 줄로 판정 | 상태 이름을 나열하면(`settingsOpen || deleteTarget || …`) 대화상자가 늘 때마다 빠뜨린다. DOM 질의 한 번은 keydown 당 비용이 없다 |
| 이미 열려 있을 때 | **검색어 입력을 `select()`** 한다 | 다시 열지 않는다. VS Code·Notion 과 같은 관례이고, 이어서 바로 새 검색어를 칠 수 있다 |
| 부팅 중 | `bootPhase !== 'ready'` 면 `openSearch()` 가 아무것도 하지 않는다 | 부팅 중 `store` 는 임시 `memoryStore` 라 인덱스가 빈다 (`App.tsx` 196~197행) |
| ref 로 최신 함수 부르기 | `openSearchRef`·`selectSearchQueryRef` | 295행 `printDocRef` 와 같은 방식. effect 의존성을 `[publicRoute]` 하나로 유지한다 |

- **macOS**: `e.metaKey` 를 같이 본다(`Cmd+Shift+F`). 실기에서 재지 않았다 — 11장 사람 확인
- 겹치는 바인딩이 없는 것은 7.3 에서 소스로 다시 확인했다

### 4.2 여는 순서 — `setState` → `flush` → 인덱스

### 4.4 결과 만들기 — `searchResults.ts` (순수 함수)

**테스트 환경이 `node` 라 DOM 이 없다**(`vite.config.ts` 227행). 그래서 `SearchDialog.tsx` 는 JSX 만 맡고, 판정할 만한 계산은 전부 이 파일로 뺀다. 선례: `src/app/settingsTabs.ts`(F-290)

```ts
import type { ParsedQuery, SnippetPart, SearchOutcome } from '../lib/docSearch'
import type { SearchIndexEntry } from './searchIndex'

export type SearchResultRow = {
  id: string
  titleParts: SnippetPart[]   // 제목 강조 조각
  untitled: boolean           // 제목이 비어 대체 문구를 쓴 행
  folderPath: string          // '상위 / 하위' 또는 ''
  date: string                // 'YYYY-MM-DD'
  snippet: SnippetPart[]      // 발췌 조각. 본문이 없으면 []
  shared: boolean
}

/** ts → 'YYYY-MM-DD' (EmptyState.tsx 21~27행과 같은 모양) */
export function formatSearchDate(ts: number): string

/** ↑↓ 로 갈 다음 선택 자리. 순환한다. 그 밖의 키는 current 그대로 */
export function nextResultIndex(current: number, count: number, key: string): number

/** hits 순서 그대로 화면에 그릴 행을 만든다 */
export function buildResultRows(
  entries: readonly SearchIndexEntry[],
  outcome: SearchOutcome,
  query: ParsedQuery,
): SearchResultRow[]
```

`buildResultRows` 규칙:

| 항목 | 규칙 |
| --- | --- |
| 이어 붙이기 | `entries` 로 `Map<id, entry>` 를 **한 번** 만들고 `outcome.hits` 순서대로 찾는다. `Map` 에 없는 id 는 건너뛴다(있을 수 없지만 방어) |
| 제목 | `entry.title` 이 비었거나 공백뿐이면 `titleParts = [{ text: '제목 없는 문서', hit: false }]`, `untitled = true`. **대체 문구에는 강조를 넣지 않는다** — 문서에 없는 글자를 맞았다고 보이면 거짓말이다 |
| 제목 강조 | 그 밖에는 `highlightParts(entry.title, query)` |
| 발췌 | `buildSnippet(entry.body, query)`. 공유받은 문서는 `body === ''` 라 `[]` 가 나온다(F-285 8.3) |
| 폴더 경로·날짜·공유 | `entry.folderPath`, `formatSearchDate(entry.updatedAt)`, `entry.shared` 그대로 |
| 정렬 | **하지 않는다.** `searchDocs` 가 이미 정렬해 줬다 (F-285 7.3) |
| 상한 | **적용하지 않는다.** `searchDocs` 가 `RESULT_LIMIT=200` 으로 이미 잘랐다 |

`nextResultIndex` 규칙:

| 입력 | 결과 |
| --- | --- |
| `count === 0` | 언제나 `-1` |
| `ArrowDown`, `current === -1` | `0` |
| `ArrowDown` | `(current + 1) % count` — 마지막에서 첫 번째로 **순환** |
| `ArrowUp`, `current === -1` | `count - 1` |
| `ArrowUp` | `(current - 1 + count) % count` |
| 그 밖의 키(`Home`·`End`·`←`·`→` 포함) | `current` 그대로. **호출한 쪽이 `preventDefault` 를 하지 않는다** — 입력 캐럿 이동이 그대로 살아야 한다 |

- `formatSearchDate` 는 `EmptyState.tsx`·`ApiTokensDialog.tsx` 에 이은 **세 번째 같은 6줄**이다. 공용 유틸로 빼지 않는다 — 두 파일 다 이 명세 소유가 아니고, F-241 3.2 가 "쓰는 곳이 둘뿐이라 빼지 않는다"로 정한 것을 셋이 됐다고 이번 커밋에서 뒤집으면 관계없는 파일 둘이 diff 에 섞인다. 13장 Q7 에 별도 정리 명세를 제안한다

### 4.5 키보드 (대화상자 안)

| 키 | 동작 | 구현 |
| --- | --- | --- |
| `↑` `↓` | 선택을 옮긴다. **포커스는 검색창에 그대로**, `aria-activedescendant` 만 바뀐다 | `onKeyDown` 에서 `ArrowUp`/`ArrowDown` 일 때만 `e.preventDefault()` 후 `setSelected(nextResultIndex(...))` |
| 선택 행 보이기 | 선택이 바뀌면 그 행을 `scrollIntoView({ block: 'nearest' })` | `useEffect([selected])`. `block:'nearest'` 라 이미 보이면 스크롤하지 않는다 |
| `Enter` | 선택한 결과를 연다. 결과가 0개면 아무 일도 없다 | `e.preventDefault()` 후 `onOpenDoc(rows[selected].id)` |
| `Esc` | 닫는다 | `Dialog` 의 `<dialog>` 기본 `cancel` — **추가 코드 없음** |
| `Home` `End` `←` `→` | 입력 캐럿 이동 그대로 | `nextResultIndex` 가 `current` 를 그대로 돌려주고 `preventDefault` 도 하지 않는다 |
| `Tab` | 기본 순서. 포커스 받는 요소는 검색창 하나뿐이라 사실상 제자리 | `role="option"` 은 tabbable 이 아니다 |
| `Ctrl+Shift+F` (열려 있을 때) | 검색어 전체 선택 | 3.4 |
| 마우스·터치 | 행을 누르면 연다 | `<li onClick>` |

async function openDocFromSearch(id: string) {
  setSearchOpen(false)

| 물음 | 답 | 근거 |
| --- | --- | --- |
| 지금 열린 문서를 그대로 두나 | **아니다. 그 문서로 이동한다** | F-284 4.3 "대화상자를 닫고 `#/d/{id}` 로 이동(기존 문서 전환 흐름 그대로)" |
| 대화상자는 | **닫힌다** | 같은 줄 |
| 이미 열려 있는 문서를 고르면 | `selectDoc` 이 1332행에서 곧바로 return 한다. 대화상자만 닫힌다 | |
| 본문 매치 위치로 커서를 옮기나 | **옮기지 않는다** | F-284 8장 Q3 기본값. 그리고 **옮길 수가 없다** — 발췌·`bodyHit` 은 **NFC 로 정규화한 문자열 기준**이고 원문 좌표로 되돌리는 표를 만들지 않기로 했다(F-284 4.2, 5.4). NFD 로 저장된 문서에서는 글자 수가 절반 가까이 달라 그대로 쓰면 엉뚱한 자리로 간다. F-286 이 프론트매터를 떼고 넣으므로 그만큼도 어긋난다 |
| 포커스는 어디로 | **편집·원문 모드면 새로 연 문서의 에디터 안.** 보기 모드는 정하지 않는다(`Dialog` 기본 복귀) | 아래 |

**포커스 — 왜 한 줄이 더 필요한가.** `Dialog.tsx` 40~46행은 `close` 이벤트에서 "열기 직전에 포커스가 있던 요소" 로 되돌린다. 여기엔 두 경우가 있다

- 열 때 포커스가 **사이드바 검색 버튼**이었다 → 그 버튼은 그대로 있으므로 포커스가 버튼으로 돌아간다. 새 문서를 열었는데 포커스는 사이드바에 있다
- 열 때 포커스가 **에디터(`Ctrl+Shift+F`)** 였다 → 문서가 바뀌면서 그 DOM 이 사라진다. 떨어져 나간 요소에 `focus()` 는 아무 일도 안 하므로 포커스가 어디에도 없게 될 수 있다

둘 다 좋지 않다. **결정: 문서 전환이 끝난 뒤 에디터에 한 번 더 포커스를 준다** — `setTimeout(() => editorRef.current?.focus(), 0)`(`EditorHandle` 에 `focus()` 가 있다, `src/editor/Editor.tsx` 15·90행). `Dialog` 의 복귀가 `close` 이벤트 태스크에서 오므로 그보다 뒤에 오게 태스크로 미룬다

- **이 타이밍은 추론이고 실측하지 않았다.** 그래서 수용 기준(A8)은 구현 방식이 아니라 **결과**를 고정한다 — "대화상자가 닫히고 `#/d/{id}` 로 갔으며, 편집·원문 모드라면 포커스가 `.cm-editor` 안에 있다". 구현이 다른 방법으로 같은 결과를 내도 통과다

### 7.1 게이트 (a) — "검색창이 보이기까지"

IndexedDB `md-docs` 의 `docs` 스토어에 합성 문서(본문 2.78천자, 프론트매터 5줄)를 직접 넣고 새로고침 → 페이지 **안에서** `performance.now()` 로 잰다. `사이드바 설정 버튼 .click()` 직후부터 `document.querySelector('dialog.dialog[open]')` 이 잡히는 첫 `requestAnimationFrame` 까지. 4회 연속

- **구현이 끝나면 같은 방법으로 검색 대화상자를 다시 잰다** (A17). 판정은 두 가지: (1) 문서 1,000개에서 100ms 이내, (2) **같은 조건 설정 대화상자보다 30ms 넘게 느리지 않을 것** — 넘으면 인덱스 만들기가 첫 페인트 앞을 막고 있다는 뜻이다

### 7.2 `Ctrl+Shift+F` 를 브라우저가 가로채는가 (F-284 8장 Q5)

실제 Chrome(channel `chrome`) **헤드리스·헤드풀 양쪽**에서 빈 페이지에 `window` `keydown` 리스너를 달고 Playwright 로 눌러 봤다

| 조합 | 페이지가 받은 이벤트 |
| --- | --- |
| `Control+Shift+F` | `{key:'Control'}` → `{key:'Shift', ctrl:true}` → **`{key:'F', ctrl:true, shift:true}`** |
| `Control+Shift+P` | 같은 모양으로 `{key:'P', ctrl:true, shift:true}` |
| `Control+F` | `{key:'f', ctrl:true}` |

- **`Ctrl+Shift+F` 는 페이지까지 온다.** 헤드풀에서도 같다
- **`e.key` 가 대문자 `'F'` 다.** 3.4 의 `toLowerCase()` 가 그래서 필요하다
- **재지 못한 것**: 사용자의 실제 크롬 프로필(확장 프로그램이 이 조합을 채 갈 수 있다), 파이어폭스·사파리, macOS, 한글 IME 가 켜진 상태 → 11장 사람 확인
- Playwright 는 CDP 로 키를 넣으므로 OS 단축키는 애초에 끼어들지 않는다. **"브라우저 UI 가 가로채지 않는다" 까지만 확인한 것이고 OS 단축키는 확인하지 못했다**
