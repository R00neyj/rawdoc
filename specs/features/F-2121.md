# F-2121 공개 사이트 JSON-LD 구조화 데이터

작성일: 2026-10-03
상태: **승인 (2026-10-03). 사용자: Q2 Organization 유지, F-272 5.3·12장 A2 문구와 테스트 3곳 갱신 승인.** 사용자 결정 8개(아래)를 받아 쓴 작은 명세. Q1·Q3 은 기본값대로 간다
범위 확인: `specs/product.md` 8장(범위 밖)에 구조화 데이터·SEO 가 없다. 공개 사이트 목적은 F-270 1장 66행("크롤러는 … 항상 랜딩을 읽는다 — 이 개편의 SEO 목적")

## 정해진 것 (사용자 결정, 바꾸지 않는다)

1. 범위: 랜딩(`/`·`/welcome`, `worker/welcomePage.ts`)과 `site/render.ts` 가 만드는 글 페이지 전부. 공유 문서(`/p/{token}`)·앱 본체(`index.html`)·`404.html` 은 제외
2. 가이드 글은 `TechArticle` — `title→headline`, `summary→description`, `date→datePublished`, `updated→dateModified`. 없으면 그 필드 생략
3. 랜딩은 `WebSite` + `WebApplication`. `offers`(가격) 없음 — **가격이 확정되면 `WebApplication.offers` 를 더하는 후속 일로 남긴다**
4. `BreadcrumbList` 없음 — 화면에 breadcrumb UI 가 없다. **그 UI 가 생기는 명세에서 함께 더한다**
5. `src/lib/structuredData.ts` 순수 함수를 `site/render.ts`·`worker/welcomePage.ts` 가 부른다. 파일 입출력 없음, `site/` import 없음
6. 비가이드 글(체인지로그·개인정보·약관·도움말·사용법 목록)은 `WebPage`
7. 제품명은 `brand.config.ts`, 주소는 `src/lib/siteMeta.ts` `SITE_URL`
8. 단위 테스트만, e2e 없음. `<` 이스케이프와 그 테스트 포함

## 근거 (직접 읽거나 받은 것, 2026-10-03 HEAD `968b69e`)

- **Google 문서**(Search Central, `curl` 로 받아 읽음, 각 페이지 "Last updated"):
  - Software app(2026-09-08): 리치 결과 **필수**는 `name`·`offers.price`·평점(`aggregateRating` 또는 `review`) 중 하나. `applicationCategory` 는 권장이고 "supported app type" 이어야 한다 — 목록 22개: `GameApplication` `SocialNetworkingApplication` `TravelApplication` `ShoppingApplication` `SportsApplication` `LifestyleApplication` `BusinessApplication` `DesignApplication` `DeveloperApplication` `DriverApplication` `EducationalApplication` `HealthApplication` `FinanceApplication` `SecurityApplication` `BrowserApplication` `CommunicationApplication` `DesktopEnhancementApplication` `EntertainmentApplication` `MultimediaApplication` `HomeApplication` `UtilitiesApplication` `ReferenceApplication`. "Productivity" 는 없다. `WebApplication` 하위형은 지원한다고 적혀 있다
  - Article(2026-09-08): 필수 속성 없음. "Article objects must be based on one of … `Article`, `NewsArticle`, `BlogPosting`". 권장 `author`(Person 또는 Organization, 조직이면 `url` 에 조직 홈), `headline`, `image`, `datePublished`·`dateModified`(ISO 8601, 시간대 권장). 발행자는 `publisher` 에 둔다
  - Organization(2026-09-08, `…/logo` 주소도 이 문서로 간다): `logo` 는 **최소 112x112px**, 크롤 가능, "Google Images 가 지원하는 형식"
  - Google Images(2026-03-02): 지원 형식 BMP·GIF·JPEG·PNG·WebP·**SVG**·AVIF
  - Site names(2025-12-10): `WebSite` 구조화 데이터는 **도메인 루트 홈페이지**에 있어야 한다. 예시 필수 필드는 `name`·`url`
- 현재 코드: 코드 전체에 `ld+json` 없음(메인 측정). `site/render.ts` `renderSitePage` head 끝이 `og:locale` → `<style>`, canonical 은 `new URL(input.url, SITE_URL).href`. `worker/welcomePage.ts` head 는 canonical·`og:url` 이 두 경로 모두 `siteUrl`(= `SITE_URL`), 설명은 모듈 상수 `subheadText`
- 가이드 판정: `site/pages.ts` `contentUrl` 이 가이드만 `/guides/{slug}` 로, 사용법 목록은 `/guides` 로 낸다. 프론트매터에는 종류 필드가 없다
- `content/guides/*.md` 17편 전부 `date` 가 있고 `date`·`updated` 가 모두 `YYYY-MM-DD` 형식, `summary` 에 `<` 없음. `privacy.md`·`terms.md` 는 `date`·`updated` 없음, `helpPage.ts`·`guidesIndex.ts` 가상 글도 없음
- 아이콘: `public/icons/icon-512.png`(512x512, `vite.config.ts` manifest 가 이미 쓴다), `icon.svg`(`viewBox 0 0 512 512`). `robots.txt`(`site/build.ts` `renderRobots`)는 `/icons/` 를 막지 않는다
- 이스케이프 실측(스크래치 `esc.mjs`, Node 24.12): `JSON.stringify(v).replace(/</g, '\\u003c')` 결과에 `<` 0개, `JSON.parse` 왕복 일치, 한글·`&`·`>` 는 그대로. **함정**: 소스에 역슬래시 하나(`'<'`)로 쓰면 그 문자열이 `<` 자체라 아무것도 안 바뀐다 — 인수 기준 A6 이 이것을 잡는다
- 크기 실측(같은 스크래치, 4장 모양): 랜딩 블록 762 B, 가이드 블록 898 B(요약 200자 기준)

## 2. 계약 (`src/lib/structuredData.ts`)

```ts
export type SitePageLd = {
  url: string          // renderSitePage 의 input.url 과 같은 사이트 경로 ('/guides/account')
  title: string
  summary: string      // parseSitePageMeta 결과 그대로 (없으면 이미 SITE_DESCRIPTION)
  date?: string
  updated?: string
}

export function sitePageGraph(page: SitePageLd): Record<string, unknown>
export function landingGraph(input: { description: string }): Record<string, unknown>
export function jsonLdScript(graph: Record<string, unknown>): string
// → '<script type="application/ld+json">{…}</script>'
```

- 빌더(객체)와 직렬화(문자열)를 나눈다 — 테스트가 객체 모양을 정규식 없이 판정하고, 이스케이프는 `jsonLdScript` 하나에서만 한다
- 호출: `site/render.ts` 는 `jsonLdScript(sitePageGraph({ url: input.url, ...meta }))`. `worker/welcomePage.ts` 는 `jsonLdScript(landingGraph({ description: subheadText }))` 를 모듈 상수로 한 번 만든다
- 의존: `brand.config`(`name`·`ogImage`), `siteMeta`(`SITE_URL`) 만. DOM·`site/`·`worker/` import 없음

## 3. 직렬화와 삽입 위치

- 문서 하나에 `<script type="application/ld+json">` **하나**, 안은 `{"@context":"https://schema.org","@graph":[…]}`. 여러 태그로 나누지 않는 이유: 노드끼리 `@id` 로 이어지고(4장), 테스트가 블록 하나만 파싱하면 된다
- `JSON.stringify` 한 줄(들여쓰기 없음) 뒤 `<` 를 모두 6글자 `<` 로 바꾼다. `</script>`·`<!--` 탈출을 둘 다 막는다. `>`·`&`·한글은 그대로 둔다 — 페이지가 `<meta charset="UTF-8">` 이고 JSON 안에서 의미가 없다
- 삽입 위치는 두 곳 모두 `<meta property="og:locale" content="ko_KR" />` 바로 다음 줄, 첫 `<style>` 앞
- HTML 속성 이스케이프(`escapeHtml`)는 거치지 않는다 — 스크립트 데이터 블록은 엔티티를 풀지 않는다

## 4. 그래프 모양

공통 상수: `ORG_ID = SITE_URL + '#organization'`, `inLanguage: 'ko'`(`<html lang="ko">` 와 같은 값). 날짜는 `/^\d{4}-\d{2}-\d{2}$/` 에 맞을 때만 그대로 넣고 아니면 필드를 생략한다 — 시간대를 붙이지 않는다(실제 시각이 없는데 지어내지 않는다. Google 은 "권장"이고 없으면 Googlebot 시간대로 본다)

**Organization 노드** — 모든 그래프의 첫 노드: `@type: 'Organization'`, `@id: ORG_ID`, `name: brand.name`, `url: SITE_URL`, `logo: SITE_URL 기준 '/icons/icon-512.png' 절대 주소`

- 로고는 PNG 512 로 정한다. SVG 도 Google Images 지원 형식이지만 "최소 112x112px" 를 픽셀 크기가 없는 SVG 가 만족하는지 문서에 없다 — 확인 못 함. 512x512 PNG 는 두 조건을 의심 없이 만족한다. `brand.ogImage`(2400x1260, 제품명 글자가 든 공유 카드)는 로고가 아니라 쓰지 않는다
- `brand.config.ts` 에 로고 필드를 새로 만들지 않는다 — 제품명·색이 아닌 정적 경로이고 manifest(`vite.config.ts`)도 같은 경로를 직접 쓴다. 상수 `LOGO_PATH` 하나로 둔다

**랜딩** `landingGraph` → `[Organization, WebSite, WebApplication]`

| 노드 | 필드 |
| --- | --- |
| `WebSite` | `@id: SITE_URL + '#website'`, `url: SITE_URL`, `name: brand.name`, `inLanguage`, `publisher: { '@id': ORG_ID }` |
| `WebApplication` | `@id: SITE_URL + '#app'`, `name: brand.name`, `url: SITE_URL`, `description: input.description`, `applicationCategory: 'BusinessApplication'`, `operatingSystem: 'Web'`, `inLanguage`, `publisher: { '@id': ORG_ID }`. **`offers` 없음**(결정 3) |

- **두 경로**: `/` 와 `/welcome` 은 **같은 블록**을 낸다. `url`·`@id` 모두 `SITE_URL` 기준 — 두 경로의 canonical 이 이미 `SITE_URL` 이고, Google 은 `WebSite` 를 도메인 루트 홈에서 읽는다. 그래서 `landingGraph` 는 경로 인자를 받지 않는다
- `applicationCategory`: Google 목록에 생산성 분류가 없어, Google 문서가 예시로 드는 `BusinessApplication` 을 쓴다(문서 작성·협업 도구). `UtilitiesApplication`·`DeveloperApplication` 은 각각 시스템 도구·개발 도구로 읽혀 덜 맞는다
- `description`: 랜딩 `<meta name="description">` 과 같은 `subheadText` 재사용 — 화면·메타·구조화 데이터 설명이 어긋나지 않게

**글 페이지** `sitePageGraph` → `[Organization, 본문 노드]`. `canonical = new URL(page.url, SITE_URL).href`(render.ts 와 같은 식)

- 판정: `page.url` 이 `/^\/guides\/[^/]+$/` 이면 `TechArticle`, 아니면 `WebPage`. `/guides`(목록)는 `WebPage`. 근거는 `contentUrl` 이 주소 매핑의 유일한 원본이고 프론트매터에 종류가 없기 때문

| 필드 | `TechArticle` | `WebPage` |
| --- | --- | --- |
| `@id` | `canonical + '#article'` | `canonical + '#webpage'` |
| 제목 | `headline: title` | `name: title` |
| `description` | `summary` | `summary` |
| `url` | `canonical` | `canonical` |
| `mainEntityOfPage` | `canonical` | 없음 |
| `image` | `brand.ogImage` 절대 주소(`og:image` 와 같다) | 없음 |
| `datePublished`·`dateModified` | `date`·`updated`, 4장 머리 규칙 | 같은 규칙 |
| `inLanguage` | `'ko'` | `'ko'` |
| `author` | `{ '@id': ORG_ID }` | 없음 |
| `publisher` | `{ '@id': ORG_ID }` | `{ '@id': ORG_ID }` |

- 작성자 개인 이름은 코드·글 어디에도 없어 쓰지 않는다. `author` 를 조직으로 두는 것은 Google Article 문서의 조직 작성자 예시(`@type: Organization` + 조직 홈 `url`)를 따른 것 — Q2
- 글 페이지에는 `WebSite` 노드를 넣지 않는다. 다른 페이지의 `@id` 를 가리키는 참조는 Google 이 페이지 밖에서 풀어 준다는 근거를 찾지 못해, 페이지 안에 정의된 `@id`(Organization)만 참조한다

## 10. 열린 질문

**Q1 `offers` 없는 `WebApplication`** — 기본값: 그대로 둔다(결정 3). Google Software app 리치 결과는 `offers.price` 와 평점이 필수라 이 노드는 리치 결과 대상이 아니고, 리치 결과 테스트에 누락 경고가 뜰 수 있다. 남기는 이유는 검색엔진이 사이트를 "웹 앱" 으로 이해하게 하는 것. 다른 쪽(노드 제외)을 고르면 랜딩은 `Organization`·`WebSite` 둘만 내고 A1·A2 가 그에 맞게 줄며, 가격 확정 때 노드를 통째로 새로 넣는다. 무료(`price: 0`)로 넣는 안은 결정 3 과 어긋나 기본에서 뺐다

**Q2 작성자·발행자를 조직(`brand.name`)으로** — 기본값: 그렇게 한다. Google Article 문서가 조직 작성자를 허용하고, 로고를 실을 자리가 Organization 뿐이다. 다른 쪽(생략)을 고르면 Organization 노드·`author`·`publisher`·`LOGO_PATH` 가 모두 빠지고 A2 의 logo 단언·A3 의 author/publisher 단언이 없어진다. 운영 주체가 개인이라 "Organization" 이 사실과 다르다고 보면 이쪽

**Q3 `TechArticle` 을 Google 이 인식하는가** — 기본값: `TechArticle`(결정 2). Google 문서는 `Article`·`NewsArticle`·`BlogPosting` 셋만 이름으로 적는다. `TechArticle` 은 schema.org 에서 `Article` 의 하위형이지만 Google 이 하위형을 받아 주는지는 **확인 못 함**. H2 에서 감지되지 않으면 `@type` 값만 `Article` 로 바꾸는 한 줄 tweak 로 처리한다(A3 의 기대값 하나 변경)
