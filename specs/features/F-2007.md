### 2.1 이 커밋이 끝난 시점의 상태

지도를 열고 `지도 설정` 을 누르면 **`필터`·`표시`·`장력` 세 묶음**이 쌓이고 맨 위 `필터` 가 펼쳐져 있다. 검색어를 치거나 폴더를 고르거나 켬끔을 끄면 **맞지 않는 노드가 자리에 남은 채 배경으로 가라앉고**, 눌러도 열리지 않고, 이름표도 뜨지 않으며, 닿는 간선도 같이 옅어진다. 꼬리 줄에 `12개 중 5개 보임` 이 붙는다. `목록` 으로 가도 같은 조건이 걸린 목록이 보이고, **거기서도 패널을 열어 필터를 바꿀 수 있다.** 지도를 닫았다 다시 열면 `파일 검색` 만 비어 있고 나머지 넷은 그대로다.

### 2.2 F-2008(`그룹`)과의 경계 — 함수 단위로 갈랐다

**`mapFilter.ts` 는 F-292 2장 파일표에서 `F-2007`·`F-2008` 공동 소유다.** 두 번 열지 않게 경계를 함수로 못 박는다.

| 무엇 | F-2007(이 명세)이 만든다 | F-2008 이 더한다 |
| --- | --- | --- |
| 값 검증 | `MapFilter`·`MAP_FILTER_DEFAULT`·`normalizeMapFilter` | (없음 — 그룹 검증은 `mapPrefs.ts` 의 `normalizeMapGroups` 가 이미 한다) |
| 공용 타입 | `MapFilterDoc`·`MapFilterFolder`·`MapFilterNode`·`MapFilterContext` | **그대로 재사용한다.** 새 타입을 만들지 않는다 |
| 폴더 | `expandFolders(selected, folders)` | 재사용 |
| 보임 판정 | `computeVisibleNodes(filter, query, allowedFolders, ctx, out)` | — |
| 색 판정 | — | `computeGroupColors(groups, ctx, out)` — 같은 `ctx` 를 받아 `Uint8Array` 에 팔레트 인덱스를 채운다 |
| 상수 | `MAP_FILTER_DIM`·`MAP_HOPS_MAX`·`MAP_FILTER_ROOT` | — |

**`ctx` 를 두 함수가 공유하는 것이 이 경계의 전부다.** `MapPage` 가 `ctx` 를 한 번 만들어 둘에 넘긴다. F-2008 은 이 파일에 **함수 하나와 테스트만 덧붙이고**, 위 여섯 줄을 고치지 않는다.

## 3. `src/lib/mapFilter.ts` — 내보내는 것이 전부다

테스트 환경이 `node` 다(`vite.config.ts` 227행 `environment: 'node'`). **DOM 도 three 도 import 하지 않는 순수 모듈이어야 단위 테스트가 된다** — `mapNodeStyle.ts`(F-2004)·`mapEdgeStyle.ts`(F-2005)·`mapFocus.ts`(F-2010)와 같은 규칙이다.

### 3.1 API

```ts
// 지도 필터 — 무엇을 보이게 두고 무엇을 배경으로 가라앉히나 (specs/features/F-2007.md 3장)
// DOM 도 three 도 import 하지 않는 순수 모듈이다. src/lib 안에서만 가져온다
import { matchDoc, type ParsedQuery, type SearchDocInput } from './docSearch'

// 걸러진 것을 --panel 쪽으로 섞는 비율. F-292 결정 14 가 정한 값이고 F-2010 의 MAP_HOVER_DIM 과 같다 (9장)
export const MAP_FILTER_DIM = 0.85

// `현재 문서에서 몇 다리` 의 최댓값. 0 은 `없음` 이다 (7.5)
export const MAP_HOPS_MAX = 3

// 폴더 밖 문서를 가리키는 자리표. 실제 폴더 id 는 절대 빈 문자열이 아니다 (3.3)
export const MAP_FILTER_ROOT = ''

export type MapFilter = {
  folders: string[]   // 고른 폴더 id. 빈 배열 = 전체
  isolated: boolean   // 고립 문서 보임
  broken: boolean     // 끊긴 링크 보임
  hops: number        // 0~3 정수. 0 = 없음
}

export const MAP_FILTER_DEFAULT: Readonly<MapFilter>
export function normalizeMapFilter(raw: unknown): MapFilter

// src/types 의 Folder 와 구조가 같다. src/lib 은 src/app·src/types 를 가져오지 않는다 (docSearch.ts 와 같은 규칙)
export type MapFilterFolder = { id: string; parentId: string | null }
export type MapFilterDoc = SearchDocInput & { folderId: string | null }
export type MapFilterNode = { id: string; missing: boolean; degree: number }

export type MapFilterContext = {
  nodes: readonly MapFilterNode[]
  docById: ReadonlyMap<string, MapFilterDoc>   // 끊긴 링크 노드는 여기 없다
  distances: Int32Array | null                 // 중심이 없으면 null (4장)
}

// 고른 폴더와 그 하위 폴더 전부. 고른 것이 없으면 null(= 전체)
export function expandFolders(
  selected: readonly string[],
  folders: readonly MapFilterFolder[],
): ReadonlySet<string> | null

export function isFilterActive(filter: MapFilter, query: ParsedQuery): boolean

// out[i] = 1 이면 보임. 돌려주는 값은 보이는 노드 수
export function computeVisibleNodes(
  filter: MapFilter,
  query: ParsedQuery,
  allowedFolders: ReadonlySet<string> | null,
  ctx: MapFilterContext,
  out: Uint8Array,
): number
```

- **내보내는 것은 위가 전부다.** 상수 3개 + 값 1개 + 함수 4개 + 타입 6개
- `isFilterActive` 는 `filter.folders.length > 0 || !filter.isolated || !filter.broken || filter.hops > 0 || !query.isEmpty` 다. 꼬리 줄을 그릴지(11.2), `visible` 을 `null` 로 내려보낼지(12.1)를 이 한 함수가 정한다

### 3.2 판정 규칙 — 노드 하나마다 위에서 아래로

| # | 조건 | 결과 |
| --- | --- | --- |
| 1 | `node.missing` 이고 `!filter.broken` | **안 보임** |
| 2 | `node.missing` 이고 검색어나 폴더가 걸려 있다 | **안 보임** — 끊긴 링크 노드는 문서가 아니라 본문·프로퍼티·폴더 어느 것도 없다. 맞출 것이 없으면 못 맞은 것이다 (19장 Q2) |
| 3 | `!filter.isolated` 이고 `node.degree === 0` | **안 보임** |
| 4 | `allowedFolders !== null` 이고 그 문서의 `folderId ?? MAP_FILTER_ROOT` 가 그 집합에 없다 | **안 보임** |
| 5 | `!query.isEmpty` 이고 `matchDoc(doc, query) === null` | **안 보임** |
| 6 | `filter.hops > 0` 이고 `ctx.distances !== null` 이고 (`d < 0` 또는 `d > filter.hops`) | **안 보임** |
| 7 | 그 밖 | **보임** |

- **끊긴 링크 노드는 3번에 걸리지 않는다.** `buildWikiGraphFromEntries`(`wikiGraph.ts`)가 끊긴 링크 노드를 **간선과 함께** 만들므로 `degree >= 1` 이 보장된다 — 코드로 확인했다(`nodes.push({ … missing: true, degree: 0 })` 뒤에 반드시 `edges.push` 가 따라오고, 마지막 루프가 간선 양끝의 `degree` 를 올린다)
- **끊긴 링크 노드도 6번은 받는다.** 중심에서 두 다리 떨어진 끊긴 링크는 `1단계` 에서 사라진다. F-292 6.4 는 "이웃은 방향을 가리지 않는다" 고만 했지 끊긴 링크를 빼라고 하지 않았고, 화면상 그쪽이 자연스럽다
- **`docById` 에 없는 문서 노드는 안 보임**으로 친다. 지도 인덱스와 검색 인덱스가 한 순간 어긋났다는 뜻이고, 5.2 가 그 어긋남을 구조적으로 없앴으므로 실제로는 일어나지 않는다. **조용히 빠지는 것보다 수가 줄어 꼬리 줄에 드러나는 쪽이 낫다**
- 판정은 **노드 수 × 상수**다. 정렬도 재귀도 없다

### 3.3 `expandFolders` — 부모를 고르면 하위도 들어온다

`parentId` 로 자식 목록(`Map<string, string[]>`)을 한 번 만들고, 고른 id 마다 너비 우선으로 자손을 담는다. 순환 참조가 있어도 방문 집합으로 한 번씩만 본다.

- `selected` 가 비어 있으면 **`null`**(= 전체). `MapPage` 는 그 값을 그대로 `computeVisibleNodes` 에 넘긴다
- `MAP_FILTER_ROOT`(빈 문자열)는 폴더가 아니므로 자손을 찾지 않고 그대로 담는다. **폴더 밖 문서를 고르는 자리표**다
- `selected` 에 있지만 `folders` 에 없는 id(지워진 폴더)는 **그대로 담는다.** 담아도 맞는 문서가 없어 화면에 영향이 없고, 빼면 "지운 폴더를 고른 채 저장해 둔 사용자" 의 값이 조용히 바뀐다

## 4. `distancesFrom` — `subgraphAround` 를 대신한다

## 5. 데이터 — 인덱스 둘을 한 번의 읽기로 채운다

### 5.1 지금 무슨 일이 일어나나

- `buildMapIndex`(`mapIndex.ts` 43행)가 `store.list()` 를 부른다
- `buildSearchIndex`(`searchIndex.ts` 119행)가 `Promise.all([store.list(), store.listFolders()])` 를 부른다
- 지도에 검색 인덱스를 붙이면 **한 번 열 때 `store.list()` 가 두 번**이다. 로컬(IndexedDB)에서는 낭비이고, **`serverStore.list()`(496행)는 `api.listDocs()` 로 네트워크를 타므로 왕복이 하나 더 는다**

### 5.2 처방 — 선택 인자 둘

```ts
export async function buildMapIndex(args: { store: MapSource; scope: string; docs?: Doc[] }): Promise<MapIndexResult>
export async function buildSearchIndex(args: { store: SearchSource; scope: string; docs?: Doc[]; folders?: Folder[] }): Promise<SearchIndex>
```

- 주지 않으면 **지금과 글자 하나 다르지 않게** 동작한다. 기존 호출부(검색 대화상자)는 한 줄도 안 고친다
- `MapPage` 의 적재 effect 가 `const [docs, folders] = await Promise.all([store.list(), store.listFolders()])` 를 한 번 하고 둘 다에 넘긴다 → **지도 한 번 열기에 `list()` 1회 + `listFolders()` 1회**
- 캐시 무효화 규칙(`scope !== cachedScope || store !== cachedStore`)은 그대로다. `docs` 를 준 호출도 `changeKey(doc)` 로 항목별 재사용을 그대로 받는다
- 검색 대화상자(F-287)와 **같은 모듈 캐시를 공유한다.** 먼저 연 쪽이 값을 치르고 뒤에 연 쪽은 거의 공짜다 (15장 GF3)

### 5.3 얼마나 아끼나 — 직접 쟀다 (2026-09-22, 이 PC, 설치된 Chrome)

`scripts/measure.mjs --docs 1000:2` 로 씨를 뿌린 뒤 `--eval` 로 `store.list()` 를 5회씩 돌린 중앙값이다.

| 문서 | 한 문서 크기 | `store.list()` 중앙값 |
| --- | --- | --- |
| 1,000개 | 작음(합계 28,007자) | **6.8 ms** (5.5~22.4) |
| 1,000개 | 약 2 KB 씩(합계 2,031,008자) | **27.8 ms** (25.5~30.4) |

**로컬 저장소에서 아끼는 값은 문서 1,000개·2 KB 기준 약 28 ms 다.** 첫 열림 예산(F-292 G4)에 비하면 작지만, **`serverStore` 에서는 HTTP 왕복 하나**라 크기가 다르다. 그리고 `docs?` 가 없으면 두 인덱스가 서로 **다른 시점의 문서 목록**을 볼 수 있어, 방금 만든 문서가 지도에는 있고 검색 인덱스에는 없는 창이 열린다 — 3.2 의 "`docById` 에 없는 문서 노드" 가 실제로 생긴다. **성능보다 이 일관성이 `docs?` 를 넣는 주된 이유다.**

### 5.4 범위 문자열 — 우연히 같은 것에 기대지 않는다

`App.tsx` 2720·2722행이 `searchScope(kind, accountId)` 와 `mapIndexScope(kind, accountId)` 를 각각 만든다. **두 함수는 지금 같은 문자열(`${kind}:${accountId ?? 'local'}`)을 만들지만 서로 다른 파일의 서로 다른 함수다.** `MapPage` 가 `scope` 하나를 두 인덱스에 돌려 쓰면 한쪽 규칙이 바뀌는 날 조용히 캐시가 섞인다.

→ **`MapPage` 에 `searchScope: string` prop 을 하나 더 받는다.** `App.tsx` 2879행 블록에 `searchScope={searchDialogScope}` 한 줄이다. 그 한 줄이 `App.tsx` 를 소유 표에 올리는 이유의 전부다.

### 5.5 `MapSource` 를 넓힌다

`mapIndex.ts` 6행 `export type MapSource = Pick<Store, 'list'>` → **`Pick<Store, 'list' | 'listFolders'>`**. `MapPage` 가 폴더 목록을 스스로 읽어야 폴더 항목(7.2)을 그릴 수 있다. `MapPage` 의 `store` prop 타입도 같이 넓어지고, `App.tsx` 는 진짜 `Store` 를 넘기고 있으므로 호출부는 안 바뀐다.

지시는 "`파일 검색` 입력은 지도를 열 때마다 비운다" 다. **지키는 방법이 두 가지인데 약한 쪽을 고르지 않는다.**

## 7. 패널 `필터` 묶음 — 다섯 항목

순서는 F-292 6.4 표 그대로다. 묶음 전체는 `SECTION_ORDER` 상 맨 위라 **펼쳐진 채로 뜬다**(F-2005 4.2 규칙).

`MapPanel` 의 props 가 넷 는다.

```tsx
export type MapFolderRow = { id: string; label: string }
export type MapPanelProps = {
  view: MapView
  mode: 'graph' | 'list'              // 11.3 — 목록 보기에서는 `필터` 만 그린다
  query: string                        // 6.2 — 저장하지 않는 값이라 따로 온다
  folderRows: readonly MapFolderRow[]  // 7.2
  hopsDisabled: boolean                // 7.5 — 중심 문서가 없다
  onChange: (next: MapView) => void
  onQueryChange: (next: string) => void
  onCommit: () => void
  onClose: () => void
}
```

### 7.1 `파일 검색`

```tsx
<div className="map-filter-field">
  <label htmlFor={`${idBase}-q`}>파일 검색</label>
  <input
    id={`${idBase}-q`}
    className="map-filter-search"
    type="search"
    value={query}
    placeholder="tag:일기 회고"
    onChange={…}            // 8.2
    onCompositionStart={…}
    onCompositionEnd={…}
  />
</div>
```

- 역할은 `searchbox` 다. e2e 는 `getByRole('searchbox', { name: '파일 검색' })` 로 잡는다
- 문법은 **F-284 의 것 그대로**다. `parseSearchQuery` → `matchDoc` (F-292 결정 12). 자리 표시 문자열 `tag:일기 회고` 는 F-292 6.4 표의 예시를 그대로 쓴다
- **결과 수를 이 자리에 적지 않는다.** 숫자는 꼬리 줄 한 곳에만 있다 (11.2)
- 디바운스를 두지 않는다 — 1,000개 항목 `matchDoc` 전수가 **1.22 ms** 다 (15장 GF2)

### 7.2 `폴더` — 여러 개를 고르는 목록

**수십 개여도 패널이 안 무너지는 모양이 필요하다.** `<select multiple>` 은 OS 마다 모양이 다르고 Ctrl+클릭을 요구해 쓰기 어렵다. **스크롤되는 체크박스 목록**으로 간다.

```tsx
<div className="map-filter-field" role="group" aria-labelledby={`${idBase}-folders-label`}>
  <span id={`${idBase}-folders-label`} className="map-filter-label">폴더</span>
  <ul className="map-filter-folder-list">
    {folderRows.map((row) => (
      <li key={row.id}>
        <label className="map-check" title={row.label}>
          <input type="checkbox" checked={…} onChange={…} />
          <span>{row.label}</span>
        </label>
      </li>
    ))}
  </ul>
  {hasChildSelected && <p className="map-filter-hint">하위 폴더도 함께 보입니다.</p>}
</div>
```

| 무엇 | 정함 |
| --- | --- |
| 행 순서 | 맨 위가 **`폴더 없음`**(id = `MAP_FILTER_ROOT`), 그 아래로 `folderPath` 를 `localeCompare('ko')` 오름차순. 경로 문자열이라 부모가 자식 바로 위에 온다 |
| 행 문구 | `searchIndex.ts` 의 `folderPathMap(folders)`(59행)이 만드는 `상위 / 하위` 그대로. 한 줄로 자르고(`text-overflow: ellipsis`) `title` 로 전체를 준다 |
| 높이 | `max-height: 180px; overflow-y: auto` — 한 줄 약 24px 기준 7행. 그 아래 켬끔 둘과 슬라이더가 접힘 없이 보인다 |
| 부모를 고르면 | **하위 폴더도 들어온다** (3.3). 고른 것 중에 자식이 있는 폴더가 하나라도 있으면 그때만 `하위 폴더도 함께 보입니다.` 한 줄을 띄운다 |
| 아무것도 안 고르면 | **전체**다. `모두` 같은 체크박스를 따로 두지 않는다 — 체크가 하나도 없는 것이 곧 `전체` 이고, 그게 기본값이다 |
| 폴더가 없으면 | **항목을 통째로 안 그린다.** 행이 `폴더 없음` 하나뿐이면 고를 것이 없다. `ia.md` 8장 "빈 공간이나 비활성 UI 로 미리 만들지 않는다" 와 F-2005 4.2 의 판단을 그대로 따른다 |
| 많을 때 | 목록이 스크롤될 뿐 별도 검색칸을 두지 않는다. **폴더 이름으로 좁히고 싶으면 `파일 검색` 에 `folder:` 를 쓸 수 있다**(F-284 문법). 항목을 둘로 늘리지 않는다 |

### 7.3 `고립 문서` · 7.4 `끊긴 링크`

체크박스 둘. 라벨은 그 두 문자열 그대로이고 **기본값은 둘 다 켬(보임)** 이다 (F-292 6.4, 결정 10).

```tsx
<label className="map-check"><input type="checkbox" checked={view.filter.isolated} … /><span>고립 문서</span></label>
<label className="map-check"><input type="checkbox" checked={view.filter.broken} … /><span>끊긴 링크</span></label>
```

- 역할은 `checkbox`. `getByRole('checkbox', { name: '고립 문서' })` 로 잡는다
- 세그먼트(`켬`/`끔` 라디오 둘)가 아니라 체크박스인 이유는 19장 Q3

### 7.5 `현재 문서에서 몇 다리` — 슬라이더 (사용자 지시 2026-09-22)

F-292 6.4 표는 `없음`/`1`/`2`/`3` 세그먼트로 적었다. **사용자가 2026-09-22 에 "넣는데 슬라이더 형태로" 라고 정했다.** `표시`·`장력` 과 같은 `MapSlider` 를 그대로 쓴다.

| 속성 | 값 | 까닭 |
| --- | --- | --- |
| `label` | `현재 문서에서 몇 다리` | F-292 6.4 표의 항목 이름 그대로 |
| `min`·`max`·`step` | `0`·`3`·**`1`** | 값이 네 개뿐인 정수다. `장력` 의 `step="any"`(무리수 기본값이 눈금에 스냅되는 것을 막으려는 것, F-2006 7.3)와 이유가 정반대다. `1` 이면 방향키 한 번이 정확히 한 칸이고 브라우저가 눈금에 붙여 준다 |
| `axis` | `hops` | 측정·선택자용 고리 (F-2006 7.4) |
| `format` | 아래 표 | 값 문자열이 곧 설명이다 |
| `disabled` | `centerIndex < 0` 일 때 | `#/map` 으로 들어오면 기준점이 없다 |

`format(v)`:

| v | 문자열 |
| --- | --- |
| 0 | `없음 — 전부 보임` |
| 1 | `1단계 — 이 문서와 바로 이어진 문서까지` |
| 2 | `2단계 — 그 이웃이 이어진 문서까지` |
| 3 | `3단계 — 거기서 한 칸 더` |
| (`disabled` 일 때) | `현재 문서가 없습니다` |

- **`1단계 — 이 문서와 바로 이어진 문서까지` 는 1판 문자열 그대로다** (F-292 6.4 가 `7e8ee91` 의 것을 옮기라고 했다). 2·3단계 문장은 같은 말투로 새로 썼다
- `1다리` 가 아니라 `1단계` 인 것은 `specs/ia.md` 6장 문구표(416행)가 `1단계 / 2단계 / 3단계` 를 승인된 말로 못 박고 있기 때문이다. **라벨만 `몇 다리`, 값은 `단계`** 로 가고, 그 어긋남을 `ia.md` 에 한 줄로 적는다 (18장)
- 이 문자열은 `MapSlider` 규칙대로 `<label>` 밖의 `aria-hidden` span 과 **`aria-valuetext`** 양쪽에 들어간다. 그래서 스크린리더는 `현재 문서에서 몇 다리, 1단계 — 이 문서와 바로 이어진 문서까지` 로 읽는다 (F-2005 4.3 — 값 문자열을 `<label>` 안에 넣지 않는 이유도 거기 있다)
- **`MapSlider` 에 `disabled?: boolean` 한 줄을 더한다.** `disabled` 인 `input[type=range]` 도 접근성 트리에 `slider` 로 남으므로 e2e 가 그대로 잡는다

## 8. 한글 입력기 — `compositionend` 전에는 다시 거르지 않는다

### 8.1 실제 이벤트 순서를 확인했다 (2026-09-22, CDP)

`Input.imeSetComposition` 으로 `ㅎ → 하 → 한` 을 조립하고 `Input.insertText` 로 확정해 이벤트를 찍었다.

```
compositionstart
compositionupdate + input(isComposing=true)   × 조립 단계마다
compositionend
```

- **`compositionend` 뒤에는 `input` 이 오지 않는다.** 그러므로 "조립 중이면 건너뛴다" 만 두면 마지막 글자가 영영 반영되지 않는다. **`compositionend` 에서 반드시 한 번 스스로 거른다** — CLAUDE.md 불변조건("IME 조립 중 미룬 재계산은 조립이 끝날 때 따라잡아야 한다") 그대로다
- `page.keyboard.pressSequentially('한글')` 은 `composition*` 없이 `input(isComposing=false)` 만 낸다. **보통 타이핑으로는 이 규칙을 시험할 수 없다**
- `e2e/helpers.js` 104~112행에 **`fakeImeCompose(page, text)` 와 `fakeImeCommit(cdp, text)` 가 이미 있다**(F-150·F-161·F-245 전례). 그래서 이 규칙은 **e2e 로 판정 가능하다** (16.2 A9)

### 8.2 처방 — 보이는 값과 거르는 값을 나눈다

```tsx
const composingRef = useRef(false)
const [query, setQuery] = useState('')                // 입력칸에 보이는 글자
const [appliedQuery, setAppliedQuery] = useState('')  // 거르기에 쓰는 글자

onChange={(e) => {
  setQuery(e.currentTarget.value)
  if (!composingRef.current) setAppliedQuery(e.currentTarget.value)
}}
onCompositionStart={() => { composingRef.current = true }}
onCompositionEnd={(e) => {
  composingRef.current = false
  setAppliedQuery(e.currentTarget.value)   // 8.1 — 여기서 안 읽으면 마지막 글자가 빠진다
}}
```

- **글자는 언제나 보인다.** 미루는 것은 거르기뿐이다. 제어 입력이라 `value` 를 안 갱신하면 글자가 안 찍힌다
- 디바운스는 없다. 15장에서 1,000개 전수 `matchDoc` 이 **1.22 ms**, 200개는 0.22 ms 다 — 한 프레임(16.7 ms)의 1/13 이다
- `parseSearchQuery(appliedQuery)` 는 `useMemo` 로 한 번만 돈다
- `기본값으로`(6.2)는 `setQuery('')` 와 `setAppliedQuery('')` 를 함께 한다

## 9. 흐리기 — F-2010 의 장치에 값 하나를 얹는다

### 9.1 겹치기 — 쌓지 않고 **큰 값 하나**를 고른다

F-2010 2.2 가 이미 계약을 적어 뒀다: "F-2007 은 상수 이름 하나(`MAP_FILTER_DIM`)를 더하고 `dimT` 자리에 자기 값을 넣으면 된다 … **둘 중 큰 값을 고른다**". **이 명세는 그 계약을 수치로 확인하고 확정한다.**

```
const filteredOut = visibleMask !== null && visibleMask[i] === 0
const focused     = focusActive && nodeFocus[i] === 1 && !filteredOut    // ← 9.3
const depthT      = (focused || i === centerIndex) ? 0 : depthMix(depths[i], near, far)
const hoverDimT   = (focusActive && !focused) ? MAP_HOVER_DIM : 0
const dimT        = Math.max(hoverDimT, filteredOut ? MAP_FILTER_DIM : 0)   // ← 9.1
const t           = combineMix(depthT, dimT)
```

### 9.2 왜 쌓으면 안 되나 — F-2010 4.2 의 계산을 그대로 이어서 했다

F-2010 4.2 의 표는 0~255 sRGB 좌표에서 `--panel` 과의 채널별 최대 거리이고, 섞기가 선형이라 **거리는 `(1 − t)` 배로 줄어든다**. 그 관계로 F-2010 의 표가 그대로 재현된다(원색 227 × 0.35 = 79, × 0.15 = 34, × 0.35 × 0.15 = 12 — 표의 값과 정확히 맞는다). 같은 방법으로 "쌓는 안" 을 계산하면:

| 노드 | 원색 | 깊이만 0.65 | 흐리기 하나 0.85 | 흐리기 **둘을 쌓음**(t=0.9775) | 깊이 + 쌓은 흐리기(t=0.9921) |
| --- | --- | --- | --- | --- | --- |
| 화이트 `--ink`(보통) | 227 | 79 | 34 | **5.1** | **1.8** |
| 화이트 `--muted`(끊긴 링크) | 121 | 42 | 18 | **2.7** | **1.0** |
| 다크 `--muted` | 107 | 37 | 16 | **2.4** | **0.8** |
| 화이트 `--rule`(기본 간선) | 32 | — | 5 | **0.7** | **0.7** |

**8비트 화면에서 1 미만은 반올림하면 배경과 같은 색이다.** 즉 "걸러졌고 호버 밖인 먼 노드" 가 **말 그대로 사라진다.** 그것은 F-292 결정 14 의 첫 문장("걸러진 노드는 **자리를 유지한다**")을 깬다. `Math.max` 를 쓰면 최악값이 F-2010 4.2 표의 `둘 다` 열(6~12)에 머문다 — **이미 사람이 승인한 그 최악값**이다.

- **뜻으로도 맞다.** 흐리기는 "지금 보는 대상이 아니다" 는 한 가지 뜻이고, 두 이유로 대상이 아니라고 해서 더 아닌 것은 아니다
- 둘이 동시에 서는 경우는 **"걸러진 노드가 호버한 노드의 이웃"** 하나뿐이다. 걸러진 노드 자체는 호버될 수 없다(10장)

### 9.3 걸러진 노드는 초점 면제에서도 뺀다

`fillNodeFocus()`(F-2010 3장)는 호버한 노드와 그 **이웃 전부**에 1 을 세운다. 그 이웃 중에 걸러진 노드가 있으면 `focused === true` 라 **깊이 섞기가 면제되어**(F-2010 5장) 다른 걸러진 노드보다 오히려 밝아진다.

→ 9.1 의 `focused` 한 줄에서 막는다. **`mapFocus.ts` 는 안 고친다** (F-2010 소유).

간선도 같다 — **양끝 중 하나라도 걸러졌으면 그 간선은 걸러진 간선**이다 (F-292 6.4 "닿는 간선도 같은 비율로 흐림").

```
// writeEdgeColors() 안, F-2010 이 edgeClass 로 dim 을 정한 바로 다음 줄
const edgeFiltered = visibleMask !== null && (visibleMask[from] === 0 || visibleMask[to] === 0)
dim = Math.max(dim, edgeFiltered ? MAP_FILTER_DIM : 0)
```

## 10. 걸러진 노드를 클릭·호버에서 빼기 — `InstancedMesh` 하나로 어떻게

노드는 `InstancedMesh` 하나다(F-292 결정 4). 인스턴스를 빼려면 행렬을 다시 올리거나 메시를 나눠야 할 것 같지만, **`three` 소스를 읽어 보니 아무것도 안 해도 된다.**

- `InstancedMesh.raycast()`(`node_modules/three/src/objects/InstancedMesh.js` 279행)는 **모든 인스턴스를 검사해 맞은 것을 전부 배열에 담는다.** 걸러진 것을 빼도 광선 검사 횟수는 그대로다 — **아낄 비용이 애초에 없다**
- `Raycaster.intersectObject()`(`node_modules/three/src/core/Raycaster.js` 202행)가 마지막에 `intersects.sort(ascSort)` 로 **거리 오름차순 정렬**을 보장한다

→ `hitAt()`(`MapScene.tsx` 563~565행)은 `hits[0]` 대신 **앞에서부터 처음 만나는 "보이는" 인스턴스**를 고른다.

```ts
const hits = raycaster.intersectObject(nodeMesh, false)
let instanceId: number | undefined
for (const hit of hits) {
  const id = hit.instanceId
  if (id === undefined) continue
  if (visibleMask !== null && visibleMask[id] === 0) continue   // ← F-2007 이 더하는 줄
  instanceId = id
  break
}
if (instanceId === undefined) return null
```

- **비용은 `hits` 배열 훑기 한 번**이고 길이는 광선이 실제로 맞힌 노드 수(보통 0~3)다. 프레임 루프도 아니다 — `pointermove`·`click` 에서만 부른다
- 걸러진 노드 **뒤**에 보이는 노드가 있으면 그게 잡힌다. "걸러진 것은 없는 셈" 이라는 뜻과 정확히 같다
- `visibleMask` 가 `null`(= 필터 없음)이면 첫 바퀴에서 `hits[0]` 이 그대로 잡혀 **오늘과 한 줄도 다르지 않다**
- 마스크가 바뀌어 호버 중인 노드가 걸러지면 `setVisible()` 이 `setHover(null)` 을 부른다 (12.2)

## 11. 꼬리 줄 · 목록 보기 · 패널 자리

### 11.1 무엇이 "전체" 인가

꼬리 줄의 `{전체}` 는 **`displayGraph.nodes.length`**(상한 1,000 으로 잘린 뒤의 수)다. 그 화면에 실제로 떠 있는 점의 수와 같아야 `12개 중 5개 보임` 이 읽히기 때문이다. 상한에 걸렸다는 사실은 **이미 옆 span 이 따로 말한다**(`문서가 많아 연결이 많은 1,000개만 보입니다.`).

### 11.2 꼬리 줄 — 기존 span 을 고치지 않고 하나 더 붙인다

```tsx
<div className="map-page-foot">
  {displayGraph && (<span>노드 {displayGraph.nodes.length}개 · 간선 {displayGraph.edges.length}개</span>)}
  {filterActive && displayGraph && (
    <span className="map-foot-filter">
      {displayGraph.nodes.length.toLocaleString('ko-KR')}개 중 {visibleCount.toLocaleString('ko-KR')}개 보임
    </span>
  )}
  {truncated && …}
  {sharedCount > 0 && …}
</div>
```

- 자리는 **`노드 N개 · 간선 M개` 바로 다음**, 상한 안내 앞이다
- **필터가 걸려 있을 때만** 그린다 (F-292 6.12 표의 조건 그대로). `isFilterActive` 가 그 판정이고, 검색어가 공백뿐이면 `ParsedQuery.isEmpty` 라 걸리지 않는다
- `toLocaleString('ko-KR')` 로 천 단위 쉼표. F-292 6.4 의 예 `1,000개 중 137개 보임` 과 맞는다
- **기존 span 의 문자열을 한 글자도 안 고친다** → `F-2002 A14`(`노드 3개 · 간선 1개`)가 그대로 통과한다 (17.3)
- **이것이 F-2007 의 주 e2e 판정 통로다** (F-292 결정 17: "e2e 판정 통로는 `목록` 보기와 꼬리 줄 숫자다")
- 보이는 수가 0 이어도 별도 빈 상태 문구를 두지 않는다 — `12개 중 0개 보임` 이 그 말이고, 캔버스에는 흐려진 점들이 그대로 있다. 사람 확인 H-e 로 넘긴다 (19장 Q4)

### 11.3 `목록` 보기 — 필터를 반영하고, **패널도 거기서 열린다**

F-292 6.8: "필터와 그룹을 그대로 반영한다 — 걸러진 문서는 목록에도 없다."
F-2005 5.1: "**F-2007 이 이 조건을 뒤집어야 한다.** 필터·그룹은 `목록` 에도 반영되므로 그때는 두 보기에서 다 보여야 한다."

| 무엇 | 지금 | F-2007 뒤 |
| --- | --- | --- |
| `centerIndex`(`MapPage.tsx` 87~90행) | `graph`(자르기 전) 기준 | **`displayGraph` 기준.** 장면과 목록이 같은 인덱스를 본다 |
| `directLinks`(101~119행) | `graph.edges` 순회 | `displayGraph.edges` 순회 + **보이는 노드만** |

### 12.1 왜 마스크를 prop 으로 올리나

- 1,000개짜리 `Uint8Array` 는 1 KB 다. 만들고 버리는 비용을 아낄 자리가 아니다

### 17.1 가장 큰 것: `필터` 가 맨 위로 들어오면 `표시` 가 접힌다

F-2005 4.2 의 규칙은 **"그리는 묶음 중 맨 위 하나만 펼쳐져 있다"** 다. `필터` 가 생기면 `표시` 는 **접힌다.**

그리고 접힌 묶음 본문은 `hidden` 이다. **`hidden` 안의 컨트롤은 Playwright 의 role 질의에 안 잡힌다 — 실제로 돌려 확인했다**(`hidden` 안 slider 개수 **0**, `fill()` 은 `TimeoutError`). 즉 `표시` 슬라이더를 쓰는 모든 테스트가 깨진다.

**처방은 헬퍼 하나다.** `openForce`(896행) 옆에 두고, 아래 표의 자리에서 `openPanel` 을 `openDisplay` 로 바꾼다.

```js
// `필터` 가 생기면서 `표시` 는 접힌 채로 뜬다 — 슬라이더를 잡으려면 먼저 펼쳐야 한다 (F-2007 17.1)
async function openDisplay(map) {
  const p = await openPanel(map)
  await p.getByRole('button', { name: '표시', exact: true }).click()
  return p
}
```

## 19. 열린 질문 / 사람 결정 필요

**사람이 꼭 골라야 하는 것은 없다. 넷 다 기본값이 서 있고, 다른 쪽을 골랐을 때 무엇이 달라지는지 적었다.**

### Q1. `목록` 보기에서도 패널을 여는 것 — **기본: 연다**

F-2005 5.1 이 "F-2007 이 이 조건을 뒤집어야 한다" 고 미리 적었고, F-292 6.8 이 목록에도 필터가 걸린다고 정했다. **WebGL 을 못 쓰는 브라우저에서는 목록이 유일한 화면**이라 거기서 필터를 못 바꾸면 그 사용자에게 필터가 아예 없는 것이 된다.

**다른 쪽을 고르면**: 지금처럼 지도 보기에서만 버튼을 그리고 `showList()`·`onUnsupported` 의 `setPanelOpen(false)` 를 남긴다. `F-2005 A9`·`A10` 을 안 고쳐도 되고 `map.css` 의 `:has()` 규칙 하나가 없어진다. 대신 목록 사용자는 **지도 보기로 갔다가 필터를 걸고 다시 목록으로 오는 수밖에 없고**, WebGL 없는 사용자는 그 길마저 없다.

### Q2. 검색어·폴더가 걸렸을 때 **끊긴 링크 노드를 숨기는 것** — **기본: 숨긴다**

끊긴 링크 노드는 제목만 있고 본문·프로퍼티·폴더가 없다(`wikiGraph.ts` 가 `{ id: 'missing:…', title, missing: true, degree }` 로만 만든다 — 코드 확인). `matchDoc` 에 넣을 `body`·`properties` 자체가 없으므로 **"맞출 수 없는 것" 을 "맞았다" 고 할 수 없다.**

**다른 쪽을 고르면**: (a) 제목만으로 `matchDoc` 을 돌린다 — `tag:` 같은 프로퍼티 필터가 걸리면 어차피 전부 탈락하므로 반쪽이다. (b) **보이는 이웃이 하나라도 있으면 따라 보이게 한다** — "이 문서가 가리키는 없는 문서" 라는 맥락이 살아 더 나을 수 있다. 바꾸려면 3.2 표의 2번 줄을 "이웃 중 보이는 것이 있나" 검사로 바꾸고 `computeVisibleNodes` 가 **2패스**가 된다(문서 노드를 먼저 정하고 그다음 끊긴 링크). U7 이 바뀐다.

### Q3. `고립 문서`·`끊긴 링크` 를 체크박스로 하는 것 — **기본: 체크박스**

F-292 6.4 는 `켬·끔` 이라고만 적었다. 체크박스는 한 줄에 들어가고 클릭 한 번이며, 접근성 역할(`checkbox`)이 "켜고 끈다" 는 뜻과 정확히 맞는다.

**다른 쪽을 고르면**: 앱 설정 대화상자처럼 `켬`/`끔` 라디오 두 칸짜리 세그먼트(`.seg`)를 쓴다. 저장소에 이미 있는 모양이라 눈에 익지만, 280px 패널에서 항목 하나가 한 줄을 통째로 먹어 둘이면 두 줄이다. e2e 선택자가 `getByRole('radio', { name: '켬' })` 로 바뀌어 **A2·A4·A5 가 달라진다.**

### Q4. 보이는 노드가 0개일 때 안내 문구를 두지 않는 것 — **기본: 두지 않는다**

꼬리 줄이 `12개 중 0개 보임` 이라고 말하고, 캔버스에는 흐려진 점 12개가 그대로 남아 "걸러졌을 뿐 문서는 있다" 가 눈에 보인다. 새 문구를 두면 F-292 6.12 표에 행이 하나 늘고, 그 문구가 어느 보기에서 어디에 뜨는지(`목록` 은 빈 묶음 넷이 된다) 또 정해야 한다.

**다른 쪽을 고르면**: `.map-notice` 자리에 `조건에 맞는 문서가 없습니다.` 한 줄을 띄운다(기존 안내 줄과 같은 자리·같은 규칙). `map.css` 229행의 `:has(.map-notice) .map-list` 여백 규칙이 그대로 먹으므로 CSS 는 0줄이다. **사람 확인 H-e 의 답에 따라 나중에 붙여도 비용이 작아** 기본값을 "없음" 으로 둔다.

### 기본값으로 정한 것 (승인되면 확정)

1. **`파일 검색` 은 `MapView` 에 필드를 두지 않는다.** 저장이 구조적으로 불가능하게 한다 — 6.2

3. **`몇 다리` 는 `min=0 max=3 step=1` 슬라이더이고 값 문자열이 곧 설명이다. 중심이 없으면 잠긴다** — 7.5
4. **폴더는 스크롤되는 체크박스 목록. 부모를 고르면 하위도 들어오고, 아무것도 안 고르면 전체다. 폴더가 없으면 항목을 안 그린다** — 7.2
5. **흐리기는 쌓지 않고 `Math.max`. 걸러진 노드는 초점 면제에서도 뺀다** — 9장
6. **레이캐스트는 `InstancedMesh` 를 그대로 두고 거리순 정렬된 `hits` 에서 첫 보이는 것을 고른다. 추가 비용 0** — 10장
7. **`distancesFrom` 은 부를 때마다 CSR 을 새로 만든다. 캐시하지 않는다**(0.113 ms 실측) — 4장
8. **`subgraphAround` 는 지우고 `induceSubgraph` 는 남긴다** — 4.1
9. **`docs?`·`folders?` 를 더해 지도 한 번 열기에 `list()` 1회. 성능보다 두 인덱스의 시점 일치가 주된 이유다** — 5.3
10. **`MapPage` 가 `searchScope` prop 을 따로 받고 `MapSource` 가 `listFolders` 까지 넓어진다** — 5.4·5.5
11. **한글 입력기는 디바운스 없이 `compositionend` 에서 한 번 따라잡는다** — 8장
12. **꼬리 줄은 기존 span 을 안 고치고 옆에 하나 붙인다. 필터가 걸렸을 때만 보인다** — 11.2
13. **`목록` 의 `centerIndex`·`directLinks`·`allRanked` 를 `displayGraph` 기준으로 옮긴다** — 11.3
14. **걸러진 노드의 시각 판정은 e2e 로 고정하지 않고 사람 확인(H-a)으로 넘긴다.** e2e 는 꼬리 줄 숫자와 목록·클릭 동작만 본다 — 16.2
