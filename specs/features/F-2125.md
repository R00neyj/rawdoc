상태: 승인(2026-10-05, Q1 목차 방식은 기본값 — 상시 지시로 승인 처리). 개요 F-2122 3장을 편집기에 붙이는 구현 단위. 열린 질문 1개(8장), 기본값 있음. 개요에 없던 회귀 하나(목차가 긴 코드 문서에서 제목을 잃음, 4장)를 실측으로 찾아 `outline.ts` 를 소유에 더했다

정해진 것 (사용자, 바꾸지 않는다): 언어 범위 L2(개요 9장 Q1) / 칠한 코드블록 안 `Ctrl+/` 는 그 언어 주석(Q2) / 중첩 파싱 + 들여쓰기 보정 + 마크다운 강조 scope + 줄 단위 서체, 조합 중 보류를 새로 두지 않음(개요 3장·3.5)

## 근거 — 직접 돌려 본 것 (HEAD `b119001`, node 24, 저장소 `node_modules` 그대로)

F-2123 이 아직 없어 문법은 저장소에 있는 `@lezer/javascript`(ts 방언)·`css`·`html`(+`configureNesting` 로 `<script>`→js, `<style>`→css)로 흉내 냈다. `codeTokenHighlighter` 는 개요 1.3 표 그대로 `tagHighlighter` 로 만들었다. 스크립트는 스크래치패드에서 esbuild 로 `src/editor/{highlight,listEnter,frontmatter,outline}.ts`·`preview/blocks.ts` 를 그대로 묶어 돌렸다. 브라우저 실측은 없다

- **R1 scope 는 "우리 언어" 만으로는 모자란다.** `html` 블록 안 `<script>` 는 `@lezer/html` 이 *날* `@lezer/javascript` 파서를 중첩하므로 그 트리 맨 위(`Script`)에 `languageDataProp` 이 없다. `@lezer/highlight` `highlightRange` 는 중첩 트리에 들어갈 때마다 맨 위 노드로 `scope` 를 다시 거른다(dist `index.js` 385·402행). "우리 언어 자료일 때만" 이면 그 html 블록 코드 span 이 14 → 8 개로 줄고 `<script>` 안이 빈다. "자료가 **없거나** 우리 언어 자료" 면 14 그대로, 그러면서 마크다운 본문의 `<script>`·`<style>`·`style=`·`onclick=`·`<?xml ?>`·`<!-- -->` 에서 `code-*` 는 **0개**(본문 HTML 은 `@codemirror/lang-html` 의 언어 자료 붙은 파서라 걸러진다)
- **R2 같은 클래스.** 위 규칙으로 문서 트리(중첩)를 칠한 결과와, 블록 코드만 따로 `parser.parse` → `highlightTree` 한 결과가 TS·HTML(중첩)·인용 안·목록 안 네 블록 모두 글자 단위로 같았다
- **R3 마크다운 쪽 불변.** 중첩 없이 `markdownHighlightStyle` 범위 없음 vs `{ scope: markdownLanguage }`: span 64개 완전히 같음. 중첩 + scope 에서도 펜스 밖 span 은 같음. 펜스 안에서 `md-code` 는 언어 붙은 블록의 `CodeText` 에서만 빠지고, 인용 안 펜스 표시 줄(`> ```ts`)의 `md-quote-text` 는 남는다
- **R4 `buildBlocks` 불변.** overlay mount 는 `firstChild`·`getChildren` 으로도 안 들어간다 — 중첩 유무로 만든 위젯 `key` 5개가 같다
- **R5 `Enter`.** `insertNewlineContinueList` → 안 되면 `insertNewlineAndIndent`(지금 키맵 순서)로 10가지를 돌렸다: 맨 위 8칸 줄, 여는 펜스 줄 끝, `{` 줄 끝, `{|}` 사이, `f(|)` 사이, 목록 안, 인용 안, 인용+목록 안, 탭 들여쓰기, 언어 없는 블록. 보정 없이는 6가지가 지금과 달랐고, 3.2 의 `indentService` 를 넣으면 **10가지 모두 지금과 같다**. 단, 서비스가 `cx.lineAt(pos)` 를 읽으면 `{|}` 가 달라진다(가운데 가상 줄이 빈 줄이라 0칸) — **문서의 실제 줄** `state.doc.lineAt(pos)` 를 읽어야 지금(`insertNewlineAndIndent` 의 "들여쓰기 못 정하면 그 줄 공백 복사")과 같다. `deleteMarkupBackward` 결과도 같다
- **R6 `Ctrl+/`**(`defaultKeymap` `toggleComment`, `commands` dist 1814행): ts `// let a = 1`, html `<!-- <p>x</p> -->`, 주석 자료 없는 언어는 `false`·문서 그대로, 언어 없는 블록·본문은 지금처럼 `<!-- -->`. 셸·SQL 의 `cmLanguage` 는 자체 자료가 있다 — `@codemirror/legacy-modes/mode/shell.js` `commentTokens: {line: "#"}`, `@codemirror/lang-sql` `{ line: "--", block: /* */ }`(unpkg 최신판을 읽음, 저장소에는 아직 없음)
- **R7 지연 로드 실패.** `LanguageDescription.load()` 는 거부되면 `loading` 을 비워 다음 호출에 `loadFunc` 를 다시 부른다(`@codemirror/language` dist 736행). `checkAsyncSchedule` 은 거부를 `logException` 만 하고 다시 파싱을 걸지 않는다(628~637행)
- **R8 목차 회귀.** `extractHeadings`(`outline.ts`)는 트리가 문서 끝에 못 미치면 `ensureSyntaxTree(…, 100ms)` 를 부르고, 시간이 넘으면 덜 된 트리로 제목을 모은다. 중첩이 붙으면 이 100ms 가 코드 파싱에 쓰인다:

  | 문서 | 중첩 없음 | 중첩 | 마크다운만 새로 파싱(중앙값 7회) |
  | --- | --- | --- | --- |
  | `##` + TS 20줄 블록 × 300 (282KB) | 제목 300 / 21.8ms | **제목 4** / 100.5ms | 3.8ms, 제목 300 |
  | 같은 × 30 (28KB) | 30 / 0.5ms | 30 / 21.8ms | 0.2ms |
  | `#` + TS 5,000줄 한 블록 + `#` (173KB) | 2 / 0.8ms | **1** / 101.0ms | 0.5ms |

  편집기는 목차를 **문서가 바뀔 때만** 다시 낸다(`createEditor.ts` `updateListener` → `notifyHeadings`, 150ms 디바운스). 배경 파싱은 뷰포트 + 100,000자까지만 간다(`Work.MaxParseAhead`, dist 612행). 그래서 코드 많은 긴 문서를 열면 목차가 앞 몇 개만 보이고 그대로 남는다. `PublicView.tsx`·`helpOutline.ts` 는 자기 `markdown()` 을 써서 중첩이 없다 — 영향 없음

## 2. `src/editor/codeLanguages.ts`

```ts
export function codeLanguageFor(info: string): LanguageDescription | null
export const codeHighlighter: Highlighter          // codeTokenHighlighter + 2.2 scope
export function codeEditorExtension(): Extension   // [syntaxHighlighting(codeHighlighter), indentService(2.3)]
export const CODE_COMMENT_TOKENS: Partial<Record<CodeLangId, CommentTokens>>   // 2.4
```

### 2.1 `codeLanguageFor`

- `codeLangId(info)`(F-2123, 첫 단어·소문자)로 id 를 얻는다. `null` 이면 `null` — `md`·`mermaid`·빈 정보·표에 없는 말은 지금 모습 그대로
- id 마다 `LanguageDescription` **하나**를 모듈 `Map` 에 두고 같은 객체를 돌려준다(`lang-markdown` `getCodeParser` 가 `found.support` 로 불러옴 여부를 본다)
- `load()`: `loadCodeGrammar(id)` → `cmLanguage` 가 있으면 그것, 없으면 `LRLanguage.define({ name: id, parser, languageData: { commentTokens: CODE_COMMENT_TOKENS[id] } })`(주석 자료가 없으면 `languageData` 를 비운다) → `new LanguageSupport(lang)`. 만든 `lang.data` 를 2.2 판정용 집합에 넣는다
- `loadCodeGrammar` 가 `null` 이면 id 를 실패 집합에 넣고 거부한다. **그 뒤로 `codeLanguageFor` 는 그 id 에 `null`** — R7 대로 그냥 두면 파싱마다 `loadFunc` 를 다시 불러 콘솔에 예외가 쌓인다. 탭이 닫힐 때까지 유지(개요 1.4)
- 실패 직후 그 블록은 다음 파싱(다음 편집)까지 건너뛴 영역으로 남아 색이 없다. 서체는 줄 단위라 모양은 같다

### 2.2 scope

`codeHighlighter.scope(type)` 은 `type.prop(languageDataProp)` 가 **`undefined` 이거나 2.1 집합에 있으면** 참(R1). 마크다운 문서 맨 위·본문 HTML(`lang-html`)·그 안의 js/css 는 각자 언어 자료가 있어 거짓이다. 이 판정이 R2 의 "같은 클래스" 를 만든다 — 바꾸려면 R1 두 사례를 다시 돌린다

### 2.3 들여쓰기

`indentService`: `syntaxTree(state).resolveInner(pos, -1)` 의 부모 사슬에 `FencedCode` 가 있으면 **`state.doc.lineAt(pos)` 줄의 앞 공백 칸 수**(탭은 `tabSize` 로 센다, `countColumn`), 없으면 **`undefined`**. `null` 을 내면 `getIndentation` 이 거기서 멈춰(`@codemirror/language` dist 854~863행) `lang-markdown` 의 `headerIndent` 서비스가 가려진다. 언어 없는 블록에도 같은 값을 낸다(R5 — 지금과 같다)

### 2.4 주석

| id | `commentTokens` |
| --- | --- |
| `javascript` `jsx` `typescript` `tsx` | `{ line: '//', block: { open: '/*', close: '*/' } }` |
| `css` | `{ block: { open: '/*', close: '*/' } }` |
| `html` `xml` | `{ block: { open: '<!--', close: '-->' } }` |
| `python` `yaml` | `{ line: '#' }` |
| `json` | 없음 — `Ctrl+/` 가 아무것도 안 한다 |
| `sql` `shell` | 표에 두지 않는다 — `cmLanguage` 자체 자료(R6) |

- html 블록의 `<script>` 안은 중첩 js 트리에 자료가 없어 html 의 `<!-- -->` 가 쓰인다. 받아들인다
- 단축키 판·ia.md 키보드 표는 바꾸지 않는다(개요 3.2)

## 3. 접힌 위젯 (`blocks.ts` `CodeWidget`)

```ts
export function paintCodeLines(lines: CodeLine[], info: string): { text: string; kind: CodeTokenKind | null }[][] | null
```

- `codeLangId(info)` → `loadedCodeGrammar(id)` 가 있고 `codeBlockText(lines).length <= CODE_HIGHLIGHT_LIMITS.blockChars` 이면 `highlightCodeLines(codeBlockText(lines), grammar.parser)`, 아니면 `null`(단색, 지금 모습). 결과 줄 수는 `lines.length` 와 같고 각 줄 조각 `text` 를 이으면 그 줄 `text` 다
- 생성자에서 `painted = paintCodeLines(…) !== null` 이 될 수 있는지만(문법 불러옴 + 상한 안) 보고 비교 `key` 에 넣는다. 실제 칠하기는 `toDOM` 에서 — 블록 필드는 고칠 때마다 문서 전체를 돈다(F-106 2.5)
- `toDOM`: `.md-codeblock-line` span·`data-offset`·사이 `\n` 글자 노드는 그대로. 줄 span 안을 `kind` 가 있으면 `<span class="code-{kind}">`, 없으면 글자 노드로 채운다. 복사 글자(`codeBlockText`)·클릭 위치(`closest('[data-offset]')`)는 안 바뀐다
- 다시 그리는 길: 문법이 늦게 오면 CM6 가 다시 파싱 → 블록 필드가 `treeChanged` 로 다시 만들어짐(F-134 3.8) → `painted` 가 달라 `eq` 거짓 → 새 `toDOM`. 조합 중이면 필드가 갱신을 건너뛰고 `compositionend` 의 `forceRecalc` 가 무조건 다시 만든다 — 새 보류가 없으니 따라잡기 불변식도 그대로
- 상한(20,000자)을 넘는 블록은 접힌 위젯이 단색이고 펼친 줄은 칠해진다(편집기 줄은 CM6 가 나눠 파싱해 상한이 없다, 개요 1.4). 받아들인다
- mermaid 는 `MermaidWidget` 그대로

## 4. 목차 회귀 (`outline.ts`)

`extractHeadings` 규칙을 바꾼다: **`syntaxTree(state).length` 가 문서 길이와 같으면 그 트리, 아니면 `ensureSyntaxTree` 를 부르지 않고 `outline.ts` 가 가진 마크다운 전용 파서**(`markdownLanguage.parser.configure([frontmatterExtension()])` — 편집기 `markdown()` 과 같은 기반·확장, 코드 중첩 없음)로 문서 전체를 새로 파싱한 트리를 쓴다

- 이유: 제목은 바깥 마크다운 구조만 보면 된다. R8 에서 이 파싱이 282KB 3.8ms 로, 지금 `ensureSyntaxTree` 100ms 상한보다 싸고 결과가 늘 온전하다. 중첩이 없던 지금 문서에도 결과는 같다(같은 파서·같은 확장)
- `ENSURE_TREE_TIMEOUT_MS` 와 `ensureSyntaxTree` import 는 쓰지 않게 되면 지운다
- `formatCommands.ts` `clearFormatting` 의 `ensureSyntaxTree(100ms)` 는 그대로 둔다 — 선택 둘레만 보고, 선택은 늘 파싱된 뷰포트 안이다. 코드 많은 긴 문서에서 첫 호출이 최대 100ms 걸릴 수 있다(지금도 같은 상한)

## 5. 성능·IME (개요 3.5 에 더하는 것만)

- 배경 파싱 조각이 늘어난 만큼 `treeChanged` 갱신이 늘어 `buildBlocks` 가 더 돈다(282KB 코드 문서 첫 파싱 약 280ms — `Work.Slice` 100ms·`MinSlice` 25ms 로 나누면 3~12번, 계산값이고 브라우저에서 세지 않았다). 매 입력 비용은 아니다. 개요 10.2 "블록 300개 문서" 사람 확인에 묶는다
- 원격 Yjs 갱신 보류(`remoteGate`)·조합 판정(`composition.ts`)은 손대지 않는다. 문법 불러옴이 조합 중에 끝나도 트리만 바뀌는 트랜잭션이라 문서를 쓰지 않는다
- 인용 안 칠한 코드블록의 펼친 줄은 `md-quote-text`(`--ink-2`)를 잃어 칠하지 않은 글자가 `--ink` 가 된다(R3). 받아들인다 — 사람 확인
