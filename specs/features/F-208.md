## 2. 요구사항

### 2.1 언제
- 부팅 때 저장소가 `server` 이고, 온라인(`account.state === 'in'`)이고, `md.localMigrated` 가 비어 있고, 로컬 `md-docs` 에 문서가 1개 이상일 때 1회
- **계정당 한 번**: 끝나면 `md.localMigrated` = 그 사용자 id. 같은 계정으로 다시 로그인하면 건너뛰고, **다른 계정으로 로그인하면 다시 옮긴다** (2026-09-26 사용자 확인 — 구현과 `migrateLocal.test.ts` "다른 계정으로 로그인하면 다시 옮긴다" 에 글을 맞춤. 처음 글은 "브라우저당 한 번")
- 로컬에 문서가 0개면 옮길 것 없이 `md.localMigrated` 만 기록
- F-207 2.6 첫 실행 안내 문서는 이관 판단이 끝난 뒤에 정한다

### 2.2 흐름
1. `md-docs` 를 읽기 전용으로 열어 폴더·문서 전체를 읽는다 (`openStore` 가 아닌 `createIdbStore` 직접)
   - **손대지 않은 첫 실행 안내 문서(제목 `사용법`, 내용이 `GUIDE_DOC_CONTENT_CRLF` 와 같음)는 빼고 옮긴다.** 기기마다 새 id 로 만들어져 로그인할 때마다 계정에 쌓였다 (2026-09-15 사용자 보고). 고친 안내 문서는 옮긴다. 빼고 나서 옮길 문서가 0개면 빈 로컬과 같게 기록만 한다
2. info 알림(닫기 없음) `로컬 문서 {N}개를 계정으로 옮기는 중…`
3. `serverStore.importLocal` 로 **id 를 그대로** 캐시에 쓰고 보낼 목록에 넣는다 — 폴더(부모 먼저) → 문서(`title`·`content`·`lineEnding`·`folderId`·`createdAt`·`updatedAt`·`pinnedAt`)
   - id 를 유지해 위키링크·`md.lastDocId`·해시 주소가 그대로 맞는다
   - 캐시에 같은 id 가 이미 있으면(서버에 이미 있음) 건너뛴다
4. 보낼 목록에 다 넣으면(= 캐시에 기록되면) `md.localMigrated` 기록 → 사이드바 목록 새로고침 → info 알림 `로컬 문서 {N}개를 계정에 넣었습니다. 서버로 보내는 중입니다.` (보내기 진행은 F-207 상태바)
5. 캐시 쓰기 자체가 실패하면 기록하지 않고 error 알림 `로컬 문서를 옮기지 못했습니다. 다시 시도하려면 새로고침하세요.`
- 원문은 바이트 그대로 (6장 원문 보존)
- 로컬 `md-docs` 는 지우지 않는다. 로그아웃하면 옮기기 전 로컬 문서가 그대로 보인다
- 첨부(이미지)는 로컬 `md-docs` 에 그대로 두고 F-207 처럼 쓴다. 서버로 올리기는 F-209
- 1MB 넘는 문서는 F-207 413 처리(알림, 캐시에 남음)
- 서버가 `id_taken`(409, 남의 문서 id)을 주면 새 id 로 다시 만들고 원문 속 링크는 고치지 않는다 (보고 대상, 거의 없음)
  - 2026-09-15 구현 보류: 지금은 F-207 공통 처리(보낼 목록에서 버리고 오류 알림). 무작위 id 라 충돌 가능성이 낮아 실제 보고가 오면 다룬다

### 2.3 Worker
- `POST /api/docs` 에 선택 필드 `createdAt`·`updatedAt`(정수 ms, 0 초과, 지금+1일 이하), `pinnedAt`(정수 또는 null). 없으면 지금처럼 서버 시각
- 형식이 틀리면 400 `invalid`
