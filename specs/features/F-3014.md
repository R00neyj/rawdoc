## 4. GitHub fetch 도우미 — `githubClient.ts`

```ts
export type GithubFailure = { code: GithubErrorCode; status: number; retryAfter?: number }
export function githubFetch(env: Env, config: GithubConfig, userId: string, path: string, init?: RequestInit): Promise<Response | GithubFailure>
export function isGithubFailure(v: Response | GithubFailure): v is GithubFailure
export function githubFailureResponse(f: GithubFailure): Response // { error: code, retryAfter? } + Retry-After 머리
```

- `path` 는 `https://api.github.com` 뒤. 머리: `Authorization: Bearer {access}`, `Accept: application/vnd.github+json`, `User-Agent: {brand.name}`(`brand.config.ts` import — `worker/loginPage.ts` 선례). 성공(2xx)·304 는 `Response` 그대로 돌려준다
- **행 없음** → 409 `github_reconnect` (따로 `not_connected` 코드를 두지 않는다 — 화면은 둘 다 `GitHub 연결` 버튼)
- **갱신** (F-3013 3.3 규칙을 순서로 고정):
  1. 행을 읽는다(`token_rev` = r). `refresh_expires_at <= now` → 409 `github_reconnect`
  2. `access_expires_at - now >= 300_000` 이면 저장된 access 를 푼다. 풀기 실패 → 3번의 "다시 연결" 처리
  3. 아니면 `POST https://github.com/login/oauth/access_token` (`Accept: application/json`, 몸통 `client_id`·`client_secret`·`grant_type=refresh_token`·`refresh_token`). 몸통에 `access_token` 이 있으면 새 두 토큰을 봉해 `UPDATE … SET …, token_rev = r + 1 WHERE user_id = ? AND token_rev = r`. 바뀐 행이 0 이면(남이 먼저 씀) 행을 다시 읽어 그 access 를 쓰고 내 새 토큰은 버린다
  4. 몸통 `error` 가 `bad_refresh_token` 이면 행을 다시 읽어 `token_rev > r` 이면 그 access 로 진행, 같으면 `UPDATE … SET refresh_expires_at = 0 WHERE user_id = ? AND token_rev = r` 후 409 `github_reconnect`
  5. 다른 `error`·네트워크 실패·5xx → 502 `github_unavailable`, 행은 그대로(`console.error('github_refresh_failed', error 코드만)`)
- 만료 시각: `now + expires_in * 1000`, `now + refresh_token_expires_in * 1000`
- **API 응답 대응** (한 요청에 재시도는 최대 한 번):
  - 401 → 3번 갱신을 강제로 한 번 하고 다시 보낸다. 또 401 → `refresh_expires_at = 0`(조건부) + 409 `github_reconnect`
  - 429, 또는 403 이면서 `retry-after` 가 있거나 `x-ratelimit-remaining: 0` → 503 `github_rate_limited`, `retryAfter` = `retry-after` 초, 없으면 `x-ratelimit-reset - now` 초(1 이상), 둘 다 없으면 60
  - 그 밖 403 → 403 `github_forbidden`, 404 → 404 `github_not_found`, 5xx·`fetch` 예외 → 502 `github_unavailable`
  - 그 밖 4xx(409·422 등)는 `Response` 그대로 — 호출자(F-3015·F-3016)가 판정한다

## 5. 라우트 — `githubAuth.ts`

F-3013 3.3·3.4 의 다섯을 아래로 바로잡아 고정한다.

**돌아오기 주소 (F-3013 3.3 의 "해시에" 를 바꿈, r5)**: `/?app=1&github=connected{hash}` 또는 `/?app=1&github_error={code}{hash}`. `{hash}` = `loginReturn(return).hash`(빈 글자면 홈). F-2128 은 `location.search` 의 두 이름을 읽고 `history.replaceState` 로 지운다. 오류 코드: `denied`·`state`·`github_taken`·`exchange_failed`·`disabled` (F-3013 3.3 그대로)

**쿠키 `gh_oauth`**: 값 = base64url(JSON `{ s: state, v: verifier, r: return 해시, u: userId }`). 속성 `HttpOnly; SameSite=Lax; Path=/api/github/; Max-Age=600`, `Secure` 는 `isLocalAuthMode(env)` 가 아닐 때만. 지울 때 같은 속성 + `Max-Age=0`. 서명하지 않는다 — 우리 출처만 이 쿠키를 쓸 수 있고, 값만으로는 GitHub `code` 없이 아무것도 못 한다. `state`·`verifier` 는 각 32바이트 난수 base64url, `code_challenge` = base64url(SHA-256(verifier))

| 라우트 | 규칙 |
| --- | --- |
| `GET /api/github/status` | 비로그인 401 `unauthenticated`. 200 `GithubStatus`(6장). `connected` = 행 있음, `reconnect` = 행이 있고 `refresh_expires_at <= now`, `login` 은 행이 있을 때만. 꺼져 있어도 실제 값을 준다. `Cache-Control: no-store` |
| `GET /api/github/connect?return=` | 브라우저 이동이라 JSON 을 내지 않는다. 비로그인 → 302 `loginReturn(return).failureUrl`. 꺼짐 → 302 `github_error=disabled`. 아니면 쿠키를 심고 302 `https://github.com/login/oauth/authorize?client_id&redirect_uri&state&code_challenge&code_challenge_method=S256` |
| `GET /api/github/callback?code&state` | 아래 순서. 어느 단계든 실패하면 쿠키를 지우고 해당 `github_error` 로 302. ① 쿠키 없음·깨짐·`state` 불일치·비로그인·세션 사용자 ≠ `u` → `state` ② `error` 질의가 있으면 → `denied` ③ 꺼짐 → `disabled` ④ 토큰 교환(`Accept: application/json`, `client_id`·`client_secret`·`code`·`code_verifier`·`redirect_uri`): 몸통에 `access_token`·`refresh_token`·`expires_in`·`refresh_token_expires_in` 중 하나라도 없으면 `exchange_failed`(만료 꺼진 앱 설정도 여기 — `console.error('github_token_no_expiry')`) ⑤ `GET /user` 로 `id`·`login`, 실패면 `exchange_failed` ⑥ `github_id` 를 다른 `user_id` 가 쓰면 `github_taken` — **grant 를 폐기하지 않는다**(g7 은 그 GitHub 사용자의 앱 토큰을 전부 지워 다른 계정의 연결을 끊는다). 저장 중 UNIQUE 실패도 `github_taken` ⑦ UPSERT(`ON CONFLICT (user_id)`): 새 행 `token_rev = 1`, 있던 행(다른 GitHub 계정으로 바꾼 경우 포함)은 모든 칸을 덮고 `token_rev + 1` ⑧ `GET /user/installations?per_page=1` 의 `total_count` 가 0 이면 쿠키를 **남긴 채** 302 `https://github.com/apps/{slug}/installations/new`, 그 밖(1 이상·호출 실패)은 쿠키를 지우고 302 `github=connected` |
| `GET /api/github/setup` | DB 를 건드리지 않는다 — 로그인·꺼짐 검사 없음. 쿠키가 있으면 그 `r`, 없으면 빈 해시로 302 `github=connected`, 쿠키를 지운다. 질의(`installation_id`·`setup_action`·`state`)는 읽지 않는다 — 설치 화면이 `state` 를 돌려주는지 확인하지 않았고, 사이드바 `저장소 추가…`(F-3013 4.2)처럼 쿠키 없이 오는 길도 같은 결과면 된다 |
| `DELETE /api/github/account` | 비로그인 401. 쓰기 관문 밖(`isWriteRoute` false), Origin 검사는 그대로. 꺼져 있어도 된다. 행이 있고 설정이 있으면 `githubFetch` 와 같은 갱신 규칙으로 access 를 얻어 `DELETE https://api.github.com/applications/{client_id}/grant`(Basic `client_id:client_secret`, 몸통 `{"access_token": …}`) — 어떤 실패도 무시하고 진행. 행 삭제 → 204. 행이 없어도 204. `github_links` 는 남긴다(F-3013 3.3) |

## 12. 열린 질문

### Q1. 운영 Client ID·slug 가 구현 때 없으면 — **기본값: `vars` 에 `""` 로 커밋**
- 이유: `loadGithubConfig` 가 null → 꺼짐이라 배포·테스트가 막히지 않는다. 앱 등록(사람 일)과 구현을 떼어 둔다
- 다른 안: 운영 앱을 먼저 등록하고 값을 받은 뒤 구현 — U12 가 정확한 값을 박을 수 있지만 사람 일이 구현을 막는다

### Q2. Rawdoc 계정 삭제 때 GitHub grant 폐기 — **기본값: 하지 않는다**
- 이유: 토큰의 유일한 사본이 같은 batch 에서 지워져 남은 grant 로는 아무도 쓸 수 없다. 계정 삭제(F-2038)에 외부 호출·실패 경로를 더하지 않는다
- 다른 안: batch 전에 `DELETE /api/github/account` 와 같은 폐기를 시도(실패 무시) — GitHub 설정 화면의 "Authorized GitHub Apps" 에서도 사라지지만 삭제가 외부 호출 1~2번만큼 느려지고 W8·`account.test` 에 가짜 `fetch` 가 필요하다
