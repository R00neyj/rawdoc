```ts
export type FocusInfo = {
  tag: string               // Element.tagName (대문자)
  type: string | null       // getAttribute('type')
  editable: boolean         // isContentEditable
  readOnly: boolean         // input·textarea 의 readOnly, 그 밖 false
  inToolbarRow: boolean     // closest('.editor-toolbar-row') 가 있다
  inModal: boolean          // closest('dialog[open]') 가 있다
}
export function focusHidesPhoneNav(focus: FocusInfo | null): boolean

export type NavPos = { idx: number; max: number }
export function readNavIdx(state: unknown): number | null
export function parseNavMax(raw: string | null): number | null
export function navAtStart(stateIdx: number | null, storedMax: number | null): NavPos
export function navOnPush(pos: NavPos): NavPos
export function navOnSettle(pos: NavPos, stateIdx: number | null): { pos: NavPos; stamp: number | null }
export function navButtons(pos: NavPos): { canBack: boolean; canForward: boolean }
```

규칙:
- `phoneNavFindDisabled` — 참(흐림)인 경우를 **이 순서로 한 줄씩**: `screen !== 'doc'` / `vaultLocked` / `viewMode === 'view'`. 나머지는 거짓. **F-2087 은 세 번째 줄(`viewMode === 'view'`) 하나를 지우고 U1 의 보기 모드 행 기대를 뒤집는다** — 다른 줄·시그니처는 건드리지 않는다
  - 읽기 전용 문서(`isReadOnlyDoc`)는 흐리지 않는다 — CM6 찾기 패널은 읽기 전용에서 바꾸기 줄만 빼고 동작한다(`createEditor.ts` `openSearchPanelWithReplace` 주석)
- `focusHidesPhoneNav` — `null` → 거짓. `inModal` → 거짓(모달이 알약을 이미 덮는다. 숨기면 대화상자가 닫힐 때 포커스를 돌려줄 알약 버튼이 DOM 에서 사라진다 — `Dialog.tsx` 는 열 때의 `activeElement` 로 돌려준다). 그 밖에 `inToolbarRow` → 참. `editable` → 참. `readOnly` → 거짓. `tag === 'TEXTAREA'` → 참. `tag === 'INPUT'` 이고 `type` 이 `null`·`''`·`text`·`search`·`email`·`url`·`tel`·`password`·`number`(대소문자 무시) → 참. 나머지 거짓
  - 결과: 주 편집기 본문(편집 가능한 `contentDOM`), 표 칸 편집기, 제목 `textarea.doc-title`, CM6 찾기·바꾸기 입력칸, 댓글 입력, 사이드바 이름 바꾸기 입력 → 숨김. 읽기 전용 편집기(`contenteditable="false"`)·버튼·체크박스 → 보임
- `readNavIdx` — `state` 가 `null` 아닌 객체이고 자기 속성 `navIdx` 가 0 이상 안전 정수면 그 값, 아니면 `null`
- `parseNavMax` — `raw` 가 0 이상 정수의 십진 문자열이면 그 수, 아니면 `null`
- `navAtStart` — `stateIdx === null` → `{ idx: 0, max: 0 }`(새 앱 실행). 아니면 `{ idx: stateIdx, max: max(stateIdx, storedMax ?? stateIdx) }`(새로고침·다른 문서에서 돌아옴)
- `navOnPush` — `{ idx: idx + 1, max: idx + 1 }`(앞쪽 항목은 브라우저가 잘라 낸다)
- `navOnSettle` — 지금 항목 `state` 를 읽은 뒤: `stateIdx !== null` → `{ pos: { idx: stateIdx, max: max(pos.max, stateIdx) }, stamp: null }`. `null` → 앱이 모르는 새 항목(`location.hash =`·`location.assign`·주소창 수정)이다 → `idx' = pos.idx + 1`, `{ pos: { idx: idx', max: idx' }, stamp: idx' }`
- `navButtons` — `canBack = idx > 0`, `canForward = idx < max`

### 3.2 `src/app/historyEntries.ts` — 방문 기록 쓰기와 추적

```ts
export const NAV_MAX_KEY = 'md.navMax'          // sessionStorage. 제품명 없음
export function pushAppEntry(url: string): void
export function replaceAppEntry(url: string): void
export function startHistoryTracking(): () => void
export function subscribeHistoryNav(onChange: () => void): () => void
export function getHistoryNavSnapshot(): NavPos  // 값이 안 바뀌면 같은 객체(useSyncExternalStore)
```

- **`history.state` 모양 = `{ navIdx: number }`.** 앱이 만드는 모든 항목(`pushAppEntry`)과 고치는 항목(`replaceAppEntry`)에 이 표식을 쓴다
- 모듈 안 위치 `pos: NavPos` 는 **첫 호출 때 한 번** `navAtStart(readNavIdx(history.state), parseNavMax(sessionStorage 값))` 으로 만든다. 첫 호출이 무엇이든(부팅 `replaceHashUrl`, 추적 시작, push) 이 초기화가 먼저다
- `replaceAppEntry(url)`: 초기화 뒤, 초기화가 이번 호출에서 일어난 것이 아니면 `navOnSettle` 로 지금 항목을 정리한 다음(표식 없는 새 항목이면 번호가 한 칸 오른다), `history.replaceState({ navIdx: pos.idx }, '', url)` 을 **정확히 한 번** 부른다
- `pushAppEntry(url)`: 초기화 때 지금 항목에 표식이 없었으면 먼저 `replaceState({ navIdx: pos.idx }, '')` 로 표식만 남긴다(뒤로 돌아왔을 때 "모르는 새 항목" 으로 잘못 세지 않게). 그다음 `navOnPush` → `history.pushState({ navIdx: pos.idx }, '', url)` 한 번
- `startHistoryTracking()`: 초기화(표식 없으면 `replaceState` 로 0 을 남긴다) 뒤 `window` 의 `popstate`·`hashchange` 둘 다 듣는다. 둘 다 같은 처리 — `navOnSettle(pos, readNavIdx(history.state))`, `stamp` 가 있으면 `history.replaceState({ navIdx: stamp }, '')`(URL 인자를 주지 않아 주소는 그대로). 같은 이동에 두 이벤트가 다 와도 두 번째는 표식이 있어 번호가 바뀌지 않는다 — **어느 이벤트가 오는지·순서에 기대지 않는다.** 여러 번 불려도 듣개는 하나(참조 수), 돌려준 함수로 뗀다
- 위치가 바뀔 때마다 `sessionStorage[NAV_MAX_KEY] = String(pos.max)` 를 쓰고 구독자에게 알린다. `sessionStorage` 는 `globalThis.sessionStorage?.` 로 접근하고 쓰기 실패(사생활 모드 등)는 삼킨다 — 선례 `src/storage/lockSession.ts`
- **node 단위 테스트에서 던지지 않는다**: `history.state` 가 `undefined`(기존 테스트의 가짜 `history`)여도, `sessionStorage` 가 없어도 동작한다. `useHashRouting.test.ts` 의 `replaceState` 호출 횟수(1회·0회) 기대가 그대로 맞아야 한다 — 그래서 `replaceAppEntry` 는 초기화 표식을 따로 쓰지 않고 한 번의 `replaceState` 에 담는다
- `sessionStorage` 를 쓰는 이유: 새로고침·다른 문서(로그인 페이지 등)에서 돌아오면 모듈 상태가 사라진다. 각 항목의 `history.state` 는 살아남지만 "앞쪽에 몇 칸 남았나" 는 지금 항목에서 알 수 없다. 탭마다 따로 살고 새로고침에 살아남는 저장소가 `sessionStorage` 다(`md.lockSession` 과 같은 성질 — `specs/architecture.md` 4.1)

### 4.2 규칙

- 번호 0 = 이 탭에서 앱이 처음 뜬 항목(부팅 때 표식이 없던 항목). 앱 안에서 쌓인 항목마다 1씩. 뒤로는 `idx > 0` 일 때만 켜진다 → **앱 첫 항목에서는 뒤로가 흐려 누를 수 없다.** 앱 밖(검색 결과·랜딩·로그인 제공자)으로 나가는 뒤로는 브라우저 뒤로 버튼·제스처의 몫으로 남는다
- 앞으로는 `idx < max` 일 때 켜진다. 앱 안에서 새 항목을 쌓으면(`pushAppEntry`, 표식 없는 새 항목) `max = idx` — 브라우저가 앞쪽을 잘라 낸 것과 같다
- 교체(`replaceAppEntry`)는 번호를 바꾸지 않는다. `goHome`·`closeMap`·삭제 뒤 이동 등 ia.md 3.10 "교체" 행은 그대로 교체
- 새로고침: 그 항목의 `navIdx` 와 `sessionStorage` 의 `max` 로 되살린다 → 새로고침 뒤에도 뒤로·앞으로 흐림이 맞다
- 알림 열기·팔레트 `공유 관리`·계정 `공유 관리`·주소창 수정처럼 앱이 `state` 없이 만든 항목은 `popstate`·`hashchange` 에서 "새 항목" 으로 보고 번호를 매긴다(3.2)
- 받아들이는 어긋남(흐림이 실제보다 보수적인 경우뿐 — 앱 밖으로 나가는 쪽으로는 틀리지 않는다):
  - 앱 → (같은 탭) 다른 사이트 → 주소창에 앱 주소를 다시 쳐 들어온 두 번째 실행은 번호 0 부터 다시 센다. 거기서 브라우저 뒤로로 첫 실행 항목에 돌아가면 `max` 가 두 번째 실행 값이라 앞으로가 흐릴 수 있다
  - 이 명세 배포 전부터 탭에 남아 있던 표식 없는 항목으로 브라우저 뒤로 돌아가면 "새 항목" 으로 세어 번호가 한 칸 어긋날 수 있다(배포 직후 한 번)
- 탭 복제는 `history`·`sessionStorage` 를 함께 복사하므로 맞다. `새 탭에서 열기`(F-296, `noopener`)는 새 기록·새 `sessionStorage` 라 번호 0 부터

## 6. 휴대폰 폭 본문 자동 포커스 (결론 — 숨김 규칙에서 따라 나옴)

**결론: ≤600px 에서는 문서를 열 때 본문(`contentDOM`)에 자동 포커스하지 않는다. 새 문서의 제목 자동 포커스(`autoFocus === 'title'`)는 그대로.**

- 이유: 지금은 문서를 바꿀 때마다(`selectDoc`, `useHashRouting` 문서 갈래 = 뒤로·앞으로, 가져오기 등) `focusEditorRef` → `Editor` 가 마운트 때 `handle.focus()` 한다. 그대로 두면 **알약 `뒤로 가기` 를 누르는 순간 새 문서 본문이 포커스를 받아 알약이 사라지고**(5.1 첫 줄), 서식 바가 키보드 없이 맨 아래에 뜬다. 두 번 연달아 뒤로 갈 수 없다
- 방법: `DocumentArea` 가 `usePhoneWidth()` 를 불러, 휴대폰 폭이면 `Editor` 의 `autoFocus` 에 `true` 대신 `false` 를 넘긴다. `'title'` 은 그대로 넘긴다. 요청 플래그 소비(`App.tsx` 의 `focusEditorRef.current = false`)는 그대로라 폭을 넓혀도 밀린 요청이 뒤늦게 적용되지 않는다
- 영향: F-2084 서식 바가 문서를 연 직후 자동으로 뜨지 않고, 본문을 탭해야 뜬다. 커서 위치 규칙(문서 맨 앞)은 포커스가 없을 뿐 같다
- 이 명세가 바꾸지 않는 명시적 포커스(열린 질문 Q6): `openDocFromSearch` 의 `setTimeout(() => editorRef.current?.focus(), 0)`(검색 대화상자에서 문서 열기), `createDocFromPalette` 의 편집기 포커스(팔레트 `'…' 새 문서 만들기`), 템플릿·서식 명령 뒤 본문 포커스(F-2055). 이 경로로 열면 알약이 숨은 채로 시작한다 — 사용자가 방금 입력하려던 흐름이라 그대로 둔다

## 12. 열린 질문 (모두 기본값 있음)

### Q1. 뒤로·앞으로 흐림 판정 — **기본값: B, 앱이 `history.state` 에 번호를 매긴다 (4장)**
- 이유: 4.1 표. 첫 앱 항목에서 뒤로가 앱 밖으로 나가는 것을 막는 유일한 안이고, iOS 26.1 이하까지 한 경로다
- 다른 쪽을 고르면:
  - **A(Navigation API)**: `historyEntries.ts` 가 없어지고 `useHashRouting.ts`·`useDocNavigation.ts` 가 소유표에서 빠진다. `phoneNav.ts` 의 `NavPos` 계열 함수 대신 `'navigation' in window` 감지와 `currententrychange` 구독. iOS 26.1 이하에서 두 버튼을 늘 켤지 늘 끌지 정해야 하고, `/welcome` 에서 들어온 첫 항목에서 뒤로가 랜딩으로 나간다(H6 기대가 뒤집힌다). E1 5번(Playwright 첫 항목 앞의 `about:blank`)이 A 에서 어떻게 나올지는 재 보지 않았다
  - **C(둘 다)**: 소유표는 B 그대로 + 감지 분기. e2e 는 A 경로만 본다

### Q2. 숨기는 포커스 — **기본값: 텍스트 입력 전부(3.1 `focusHidesPhoneNav`)**
- 이유: 사용자가 말한 이유가 "아래 겹침" 이고, 제목·찾기 입력칸·댓글 입력도 키보드를 올려 알약이 키보드 바로 위, 입력 중인 줄 근처에 뜨게 된다. 편집기만 보면 5.2 3~4번에서 알약이 찾기 입력 중 키보드 위에 떠 있다
- 다른 쪽(편집기 포커스만 = F-2084 `editorFocused`): `focusHidesPhoneNav`·`FocusInfo` 대신 `AppTopBar` 의 `editorFocused` 를 `PhoneNav` 에 넘긴다(prop 하나). 5.2 표 3·4번의 알약 칸이 "보임" 으로 바뀌고 E2 2·3번 기대가 바뀐다

### Q3. 키보드만 내리고 포커스가 남은 상태(안드로이드 뒤로 키) — **기본값: 알약은 숨은 채**
- 이유: 서식 바가 그 자리에 남아 있어(F-2084 Q5) 알약을 띄우면 둘이 겹친다. 키보드 유무를 가를 믿을 만한 값이 없다(F-2084 Q5 — `interactive-widget=resizes-content` 에서 `innerHeight` 가 같이 준다)
- 다른 쪽(키보드가 내려가면 알약): F-2084 Q5 를 먼저 "키보드 없으면 서식 바 숨김" 으로 바꾸는 별도 명세가 필요하다(실기기 측정으로 판정 기준을 정해야 함). 그 뒤 이 명세 5.1 첫 줄이 "텍스트 입력 포커스 **그리고** 키보드 있음" 이 된다

### Q4. 문서 아닌 화면의 아래 — **기본값: 가림 띠만큼 비운다 (7.2)**
- 이유: F-2085 4.4 가 위쪽을 같은 방식으로 정했다. 지도 노드 수 줄·설정 패널 아래 끝·도움말 마지막 줄이 알약에 가리지 않는다
- 다른 쪽(밑으로 지나가게): 화면마다 스크롤 몸통에 `padding-bottom: var(--phone-nav-cover)` 를 따로 준다(도움말·공유 관리·공유 화면·홈·지도 목록·지도 설정 패널 — `src/styles/map.css` 가 소유표에 는다). 지도 캔버스가 화면 끝까지 깔리고 `.map-page-foot` 은 알약에 가리지 않게 따로 올려야 한다

### Q5. 문서 화면에서 상태바와의 관계 — **기본값: 알약을 상태바 위로 올린다 (7.1)**
- 이유: 상태바는 저장 상태를 보여 준다(F-2084 Q3 에서 두기로 함). 가운데 알약이 상태바 글자를 가리지 않는다
- 다른 쪽: (a) 알약이 상태바를 덮는다 — 올림 규칙이 빠지고 `:has(.statusbar)` 도 빠진다. 360px 에서 `줄·열·글자 수` 가 가린다 (b) ≤600px 에서 상태바를 숨긴다 — F-2084 Q3 를 뒤집는 결정이라 사용자 확인 필요. 저장 상태를 볼 곳이 없어진다

### Q6. 검색·팔레트에서 문서를 열 때의 명시적 본문 포커스 — **기본값: 그대로 둔다 (6장)**
- 이유: 두 경로 모두 사용자가 방금 입력하던 흐름이다(검색어로 찾은 문서의 찾기 패널, 팔레트에서 제목을 친 새 문서). 자동 포커스(`autoFocus`)만 막으면 뒤로·앞으로·사이드바가 모두 해결된다
- 다른 쪽(휴대폰 폭이면 이것도 막는다): `useDocNavigation.ts` 의 `openDocFromSearch`·`createDocFromPalette` 에 폭 조건. 검색 대화상자가 닫힌 뒤 포커스는 `Dialog` 복귀 규칙대로 사이드바 검색 버튼(닫힌 사이드바 안) → `body` 로 간다. 사람 확인 H8 에 두 경로가 는다

### Q7. 흐림 대신 숨김 — **기본값: 흐림(`disabled`)**
- 이유: 사용자가 찾기에 "흐리게" 를 골랐다(정해진 것 6·7). 뒤로·앞으로도 같게 두면 알약 폭이 화면마다 바뀌지 않는다
- 다른 쪽(없는 버튼은 숨김): 알약 폭이 화면·기록 위치마다 달라지고, E1 의 `disabled` 기대가 개수 0 으로 바뀐다
