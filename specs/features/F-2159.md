## 2. 불변조건과 같은 문서 두 칸 (결론 1)

- **원본은 문서마다 하나, 편집기 `Y.Doc` 은 칸마다 하나.** (a) 링크 있는 문서: 원본은 지금처럼 `useLiveDoc` 방 Doc 하나(연결도 하나), 그 문서를 띄운 칸마다 편집기 `Y.Doc` 복제본 + 자기 IME 게이트(`connectRemote` `sharedDoc` 경로 그대로). (b) 링크 없는 문서(로컬·`file:`·폴백 세션): 한 칸에만 있으면 지금처럼 편집기 `Y.Doc` 이 원본. **두 칸 이상에 뜨는 순간 창 안 원본 `Y.Doc`(네트워크·영속 없음)을 첫 칸 편집기 Doc 상태로 씨앗 삼아 만들고, 모든 칸 편집기 Doc 을 그 뒤 복제본으로 돌린다.** 첫 칸 편집기는 다시 만들지 않는다(실행 취소 기록 유지). 원본은 그 문서가 모든 칸에서 빠질 때 버린다
- 두 편집기가 원본 하나를 같이 쓰는(b 를 게이트 없이) 안은 기각 — 한 칸이 조합 중일 때 다른 칸 편집이 그 뷰에 바로 꽂혀 "조합 중 원격 적용 금지" 를 깬다
- **IME**: 다른 칸에서 온 변경은 원격으로 본다. 칸 A 가 조합 중이면 A 게이트만 보류하고 `compositionend` 에서 `forceRecalc` 와 함께 비운다(F-301 2.1 그대로). 칸 B 의 입력·원격 업데이트는 A 와 무관하게 곧바로 원본·B 에 닿는다. A 가 조합으로 쓴 글자는 지금처럼 곧바로 원본으로 나간다
- **실측으로 찾은 막힘(2026-10-22, 스크래치 vitest, 실제 `createRemoteGate`)**: 게이트 두 개를 한 공유 Doc 에 붙이고 A 에서 ` A` 를 넣으면 공유 Doc 은 `hello A`, **B 는 `hello` 그대로**. `RELAY_FROM_EDITOR` 가 모듈 상수라 B 가 A 의 중계를 제 것으로 보고 건너뛴다(`onSharedUpdate` 첫 분기). → 게이트마다 origin 객체를 따로 만들고 `isEditorRelay` 는 어느 게이트의 중계든 알아본다(같은 모양의 다른 객체는 여전히 `false` — F-306 U15)
- 저장: 링크 없는 문서의 저장(`useDocSaver`)·F-296 탭 편집권은 **문서마다 하나**. 원본 `Y.Doc` 이 있으면 저장은 원본 `Y.Text` 에서 읽는다(조합 중 보류된 칸의 `EditorState` 는 뒤처질 수 있다). 실행 취소는 칸마다 자기 편집만
- awareness(내 커서)는 방마다 하나라 그 문서를 띄운 칸 중 **마지막으로 포커스를 받은 칸**의 선택만 싣는다. 상대 커서는 모든 칸에 그린다
- **불변조건 문구 변경 — 사용자 승인(2026-10-22)** (8장 갱신 대상 첫 줄)

## 3. 칸 상태 모델·저장 형식 (결론 2)

```ts
type SplitLayout = 'single' | 'cols' | 'rows' | 'grid' | 'three-left' | 'three-right' | 'three-top' | 'three-bottom' // three-* = 큰 칸 자리
type PaneTabs = DocTabsState & { viewMode: 'live' | 'raw' | 'view' }
type SplitState = { layout: SplitLayout; ratios: number[]; focus: number; panes: PaneTabs[] } // panes 순서 = 칸 자리 순서
// md.docTabs[범위] = { tabs, active, split?: SplitState } — tabs·active 는 늘 panes[focus] 의 거울
```
- 칸 자리: `cols` 왼·오, `rows` 위·아래, `grid` 왼위·오위·왼아래·오아래, `three-*` 큰 칸 먼저 그다음 나머지 둘(위→아래 또는 왼→오). `ratios` 길이 — single 0, cols·rows 1, three 2(큰 칸 대 둘, 둘 사이), grid 2(가로·세로 경계 하나씩). 값은 0.2~0.8, 칸은 최소 280×160px
- **이전 형식 읽기**: `split` 이 없거나 깨졌으면 `{ layout: 'single', panes: [기존 tabs·active] }`. `tabs`·`active` 를 거울로 남기므로 분할이 꺼진 곳(브라우저 휴대폰 폭)과 이전 앱 버전은 지금 코드 그대로 포커스 칸만 읽고, 쓸 때는 `panes[focus]` 만 바꾸고 나머지 `split` 은 보존한다
- 전이는 순수 함수(DOM 없음): 나누기는 **결과가 다섯 배치(거울 포함) 안일 때만** — single→cols·rows, cols 의 한 칸을 위아래로→three, three 의 큰 칸을 직각으로→grid. 그 밖은 `null`(메뉴·팔레트 항목 숨김, 끌기 자리 표시 안 함), 4칸이면 알림. `Alt+Shift+D` = 포커스 칸을 오른쪽 → 안 되면 아래 → 안 되면 큰 칸 나누기(1→cols→three-left→grid 와 같다). 닫기: grid 에서 하나 닫으면 **같은 열 칸이 세로로 늘어** three-left/right, three 의 큰 칸을 닫으면 남은 둘이 rows/cols, 둘 중 하나를 닫으면 cols/rows. 포커스는 늘어난 칸 또는 남은 짝
- `MAX_TABS` 20 은 **창 전체 합**(칸마다 20 아님), 알림 문구 그대로. 칸 안 문서당 탭 하나, 칸끼리 같은 문서 허용(나누기로만)

## 5. 키·자원 (결론 4·5)

- **`Ctrl+Shift+W` 는 둔다.** Chromium `IsReservedCommandOrKey` 첫 줄 "In Apps mode, no keys are reserved" — `TYPE_APP`(설치 앱 창)이면 `false` 를 돌려 페이지가 먼저 받고 `preventDefault` 하면 `IDC_CLOSE_WINDOW` 가 안 돈다(https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/ui/browser_command_controller.cc , 2026-10-22 main). `useDocTabs` 의 `Ctrl+W` 가 같은 근거로 이미 돈다. 칸이 2개 이상일 때만 가로채고 1칸이면 지금처럼 창이 닫힌다. Playwright 는 설치 앱 창이 아니라 판정 못 함 → 사람 확인 H1
- 칸 포커스는 **`Ctrl+1`~`Ctrl+4`**(칸 번호: 왼쪽 위 → 오른쪽 아래 읽는 순서, VS Code `Ctrl+1/2/3` 방식). 없는 번호면 아무 일 없음, 편집기로 넘기지 않음. 앱 안 사용처 없음(`src` 검색 0건). `Ctrl+Alt+↑↓` 는 다중 커서(small 2026-10-22)에 내준다. `Ctrl+K` 이어 누르기는 `Ctrl+K` 링크(`commands.ts:109`)와 겹쳐 기각. `Alt+Shift+D` 는 `e.code === 'KeyD'` 로 판정(한글 입력 중 `e.key` 가 `ㅇ`, `isAddCommentKey` 선례). 셋 다 대화상자 안·`isComposing` 이면 무시
- **Durable Object 영향**: 연결 수 = 칸 활성 탭 중 링크 있는 **서로 다른** 문서 수(같은 문서는 방 Doc·연결 하나), 최대 4. 같은 문서를 브라우저 탭 4개에 여는 지금(F-296)과 같은 규모다. `YProvider` 가 awareness 주기 타이머를 꺼(F-304 R5·11.3 7번) 멈춘 칸은 메시지를 안 보내고 hibernation 중 Duration 이 안 쌓인다(F-301 9.3). 늘어나는 것은 연결 수립 1건씩(Requests)뿐. 감시는 F-301 O1~O3 그대로, 새 관측 없음
