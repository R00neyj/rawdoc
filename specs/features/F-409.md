## 2. 결론 넷 (프롬프트가 결론을 요구한 것)

### 2.1 잠긴 금고 문서가 어디에 어떻게 나오나 — 그리고 열고 잠글 때의 순서

| 자리 | 잠겨 있을 때 | 열려 있을 때 | 누가 |
| --- | --- | --- | --- |
| 사이드바 | `잠긴 문서` + 자물쇠, `updatedAt` 자리 그대로 | 복호화한 제목 + 자물쇠 | F-405 6.1 |
| 빈 상태 `최근 문서` | `잠긴 문서`, `updatedAt` 자리 그대로 | 복호화한 제목 | **이 명세** 4.3 |
| 검색(D-6) | **색인에 없다.** 검색어가 있으면 안내 `금고가 잠겨 있어 금고 문서 {N}개는 찾지 않았습니다` | 일반 문서와 같이 제목·본문·속성으로 찾는다 | **이 명세** 3.1·3.4 |
| 지도(노드·간선·목록 보기·필터·그룹) | **노드가 없다.** 발에 `금고가 잠겨 있어 금고 문서 {N}개는 지도에 넣지 않았습니다.` 일반 문서의 `[[잠긴 문서 제목]]` 은 끊긴 링크 노드로 보인다 | 일반 노드 | **이 명세** 3.2·3.6 |
| 백링크(지도 `들어오는` 링크, c5) | 잠긴 문서가 노드가 아니므로 나오지 않는다 | 나온다 | 3.2 에 따라 저절로 |
| 위키링크 해석(편집기·보기 모드·인쇄) | 끊긴 링크(`.md-wikilink--missing`·`.wikilink--missing`) | 이어진 링크 | 코드 변경 없음(c4). U12·E5 로 고정 |
| `[[` 자동완성 | 후보에 없다 | 후보에 있다(12장 Q1 — 사람 결정 권장) | 코드 변경 없음(c4) |
| 목록 정렬 | 문서 `updatedAt`·폴더 이름은 평문이라 **순서가 바뀌지 않는다**(c6) | 같음 | 변경 없음 |
| 공개 보기의 위키링크 | 늘 끊긴다(서버 해석기는 봉투 제목을 본다 — F-400 4.5) | 같음 | 변경 없음 |

**열 때 색인에 들어가는 시점**

1. 금고가 열리면 F-405 7.4 가 `resyncFromStore()` 로 `docs` 상태를 복호화한 제목으로 바꾼다 → 사이드바·빈 상태·위키링크 해석기·자동완성이 **그 렌더에서** 바뀐다
2. 검색 색인은 **다음에 만들 때** 들어간다 — 검색 대화상자를 열 때마다 만든다(F-286). 열기 순간 대화상자가 떠 있으면 곧바로 다시 만든다(3.5)
3. 지도는 지도 화면이 떠 있으면 곧바로 다시 읽고(3.6), 아니면 다음에 지도를 열 때 들어간다
4. 두 캐시 모두 잠글 때 비워졌으므로 금고 문서 항목은 새로 만들고 나머지는 재사용한다(c11: 200개 새로, 800개 재사용)

**잠글 때 빠지는 순서** — F-400 2.5·F-404 4.1 의 단계에 이 명세가 끼우는 것:

| 순서 | 단계 | 일어나는 일 | 누가 |
| --- | --- | --- | --- |
| ① | (조합 중이면 미룸) | — | F-404 |

### 2.4 성능 — 문서 1,000개 중 금고 200개, 열기 직후

- 그래서 **미리 데워 두기·증분 갱신 같은 추가 장치를 두지 않는다.** 브라우저 값은 재지 않았다 — 14장 사람 확인 4

## 3. 검색·지도 색인

### 3.1 `searchIndex.ts` (계약)

```ts
export type SearchIndex = {
  // … 지금 필드 그대로
  lockedCount: number // e2ee === 'locked' 이라 항목을 만들지 않은 문서 수 (SearchDialog 안내 줄)
}
```

- `buildSearchIndex` 는 `doc.e2ee === 'locked'` 인 문서를 **항목으로 만들지 않고** `lockedCount` 만 센다. `entries`·`sharedCount`·`frontmatterUnreadableCount` 어디에도 들지 않는다
- 잠긴 문서의 id 는 "이번 `list()` 에 있던 id" 에 **넣지 않는다** — 그래서 끝의 지우기 단계가 그 문서의 캐시 항목(열려 있던 때 만든 평문)을 지운다. 잠근 뒤 한 번이라도 색인을 만들면 캐시에서 평문이 스스로 빠진다
- `e2ee === 'open'` 문서는 일반 문서와 똑같이 다룬다(변경 판정 키도 지금 `changeKey` 그대로). 금고 문서라는 표시를 항목에 싣지 않는다 — 결과 행 모양(`SearchResultRow`)을 바꾸지 않는다
- `e2ee` 가 없는 문서는 지금과 바이트까지 같은 항목이 된다

### 3.3 캐시와 잠그기의 경합 — 세대 표지와 두 번째 비우기

규칙(c2 의 구멍을 막는다):

- 두 모듈에 각각 **세대 번호** 하나를 둔다. `reset*Cache()` 가 올린다
- `build*Index` 는 시작할 때 세대를 기억하고, 목록을 기다린 뒤(인자로 받았어도 지금처럼 `await` 한 뒤) 세대가 바뀌었으면 **캐시를 읽지도 쓰지도 지우지도 않고** 이번 목록으로 만든 결과만 돌려준다. 돌려받은 쪽은 금고 상태가 바뀌어 이미 취소돼 있다(3.5·3.6)
- `useE2ee` 는 상태가 `open` 에서 다른 값으로 바뀐 **뒤 한 번** 두 `reset*Cache()` 를 다시 부른다. 이유: ④(`indexes`)와 ⑥(키 버림) 사이에 시작한 색인 만들기는 ④ 뒤의 세대를 기억하고, MK 가 아직 있어 `list()` 가 평문을 준다(F-405 c7) — 세대 표지로는 못 막는다. `MapPage` 처럼 목록을 먼저 읽고 `build*` 에 넘기는 호출도 같은 구멍이 있다
- 이 둘은 잠그기 단계를 늘리지 않는다 — F-404 의 단계 틀(`registerLockStep`)을 바꾸지 않는다

- 옵시디언 볼트 계획의 위키링크 해석기는 지금처럼 `docs` 전부로 만든다. 잠긴 문서는 제목이 `''` 라 해석기가 넣지 않으므로(c4), 내보낸 문서 안의 `[[잠긴 문서 제목]]` 은 **해석되지 않은 링크**로 남는다(지금 없는 대상과 같은 처리, 경로를 붙이지 않는다)
- 첨부: 열린 금고 문서의 첨부는 지금처럼 `store.getAttachment` 로 받는다. 복호화는 F-406 이 `withE2ee` 에서 한다 — 이 명세는 모른다. 내보내는 도중에 잠기면 그 뒤 첨부는 받지 못해 지금의 "이미지 누락" 으로 센다(목록은 시작할 때 이미 읽었으므로 본문은 평문으로 끝까지 들어간다 — 사용자가 누른 내보내기라서 멈추지 않는다)

### 5.2 알림 — `downloadWorkspaceExport`·`downloadVaultExport`

알림 띠가 한 칸이라(c8) 끝에 보내는 `warn` 을 **하나로** 합친다. 순서 규칙:

| 조건 | 보내는 알림 (지금 것에 더하거나 바꾸는 것만) |
| --- | --- |
| 고른 뒤 내보낼 문서 0개, `lockedCount > 0` | `warn` E32 하나. 지금의 `내보낼 문서가 없습니다.` 대신 |
| 고른 뒤 0개, `lockedCount === 0` | 지금 그대로 `info` `내보낼 문서가 없습니다.` |
| 내보냄, `lockedCount > 0`, 이미지 누락 0 | 지금의 성공 `info` 뒤에 `warn` S3 |
| 내보냄, `lockedCount > 0`, 이미지 누락 `K > 0` | 지금의 성공 `info` 뒤에 `warn` E31 **하나**(S3 와 이미지 문구를 이은 것). 지금의 이미지 `warn` 을 따로 보내지 않는다 |
| 내보냄, `lockedCount === 0` | 지금 그대로 |

- 진행 알림 `내보내는 중… {done}/{total}` 의 `total` 은 뺀 뒤의 수다(지금 계산 그대로)
- 성공 `info`(`문서 {N}개를 내보냈습니다.` / `옵시디언 볼트로 내보냈습니다.…`)는 뒤의 `warn` 이 덮는다 — 지금 이미지 누락과 같은 동작이다

### 5.3 금고 폴더를 고른 폴더 내보내기 — App (7.3)

- `handleExportFolder`·`handleExportFolderVault` 는 지금의 오프라인 판정 뒤, 고른 폴더가 금고 폴더(`folders` 의 `e2ee`)이고 금고가 열려 있지 않으면 `e2ee.requestOpen()` 을 기다린다
  - `true` → 지금처럼 내보낸다(이제 금고 문서가 평문으로 들어간다)
  - `false` 이고 그 뒤 상태가 `unavailable`(금고 정보를 못 읽음 — `requestOpen` 이 대화상자 없이 끝남) → 열기 없이 그대로 내보낸다. 5.2 규칙대로 잠긴 문서가 빠지고 알림이 뜬다
  - 그 밖의 `false`(사용자가 D-11 을 닫음) → 아무것도 하지 않는다, 알림 없음(F-405 2.4 3번과 같은 태도)
- 전체 내보내기·설정의 옵시디언 내보내기는 묻지 않는다(Q7)

## 11. 성능 측정 (c11 자세히)

- 조건: 문서 1,000개, 그중 5번째마다 금고 문서(200개). 본문은 프론트매터(`tags` 배열·속성 하나) + 제목 + 위키링크 5개(없는 대상 하나 포함) + 한·영 문단을 목표 바이트까지. MK 는 `generateKey`(AES-KW). 복호화는 문서마다 `openDocKey` + `decryptDocField` 두 번, 순차 `await`(F-405 c6 과 같은 방식). 색인은 `buildSearchIndex`·`buildMapIndex` 를 `docs` 인자로 동시에(MapPage 와 같은 호출)

| 본문 | 캐시 없이 1,000개 | 잠근 뒤 첫 색인(800개 새로) | 잠긴 채 다음 색인(800 재사용) | 열기: 복호화 200 | 열기: 색인 재구성(200 새로·800 재사용) | 열기 합 |
| --- | --- | --- | --- | --- | --- | --- |
| 5,000 B | 25.4ms | 20.6ms | 2.2ms | 53.6ms | **4.9ms** | 60.2ms |
| 20,000 B | 79.8ms | 58.1ms | 2.0ms | 85.5ms | **16.9ms** | 102.4ms |

- 읽는 법: 잠글 때 캐시를 통째로 비우는 비용은 **잠근 뒤 첫 색인 한 번**(일반 문서 800개 다시 만들기, 20.6ms / 58.1ms)이다. 캐시를 통째로가 아니라 금고 문서만 지우면 이 값이 재사용 쪽(약 2ms)으로 내려가지만, F-404 가 이미 통째 비우기로 정했고(F-400 2.5 ④) 첫 한 번뿐이라 바꾸지 않는다 — 12장 Q5
- 복호화는 F-405 의 비용이고, 열린 동안 기억(F-405 4.4)이 있어 검색·지도·사이드바가 한 번만 치른다
- 모두 Node 값이다. 브라우저 WebCrypto 는 F-400 m6(Chrome, 1,000개 키 풀기 + 제목 8.1ms)으로 보아 더 빠를 것으로 **짐작만** 한다

### 15.2 가정으로 남긴 것
- **F-405 가 명세대로 구현된다는 가정** — `Doc.e2ee`·`DocMeta.e2ee`(`stripContent` 가 옮김)·`Folder.e2ee`·`unmount` 단계의 `lockDocMetas`·7.4 의 열림 뒤 `resyncFromStore`·잠긴 문서에 `setOpenDoc` 안 함. 지금 HEAD 에는 없다. 이 명세의 c4·c9 결론(코드 변경 없이 끊긴 링크, 잠긴 문서의 공유 버튼 비활성)은 그 가정 위에 있다
- **F-405 가 `withE2ee` 를 `withTabBroadcast` 안쪽에 감싸 `store` 참조가 부팅 뒤 바뀌지 않는다는 가정** — `buildSearchIndex` 의 "저장소가 바뀌면 통째로 버린다" 가 잠금·열기 때 불필요하게 돌지 않는다는 판단이 여기에 기댄다
- c11 은 Node 값이다. 브라우저 값은 재지 않았다
- E2 의 `page.clock` 전제는 F-404 E8 이 돈다는 것에 기댄다 — 이 명세가 따로 확인하지 않았다
- 가짜 서버에서 `GET /api/docs/{id}/link` 요청이 없음을 보는 E9 는 가짜 서버가 그 경로를 기록한다는 가정이다. 기록하지 않으면 `page.on('request')` 로 본다(구현 재량)
- 폴더 내보내기에서 `requestOpen` 이 `false` 를 돌려준 뒤 상태로 "사용자가 닫음" 과 "금고 정보를 못 읽음" 을 가른다는 규칙(5.3)은 `useE2ee.ts` `requestOpen` 의 지금 분기(읽기 뒤 `unavailable` 이면 대화상자 없이 `false`)를 읽고 정했다. F-405 가 이 함수를 바꾸면 다시 본다
