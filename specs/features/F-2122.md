## 1. 엔진과 언어

### 1.1 하나의 엔진 — lezer 문법 + `@lezer/highlight`

편집기(CM6)와 뷰어·내보내기가 **같은 문법 파서와 같은 "태그 → 클래스" 표**를 쓴다. 그래서 같은 코드가 어느 화면에서든 같은 클래스를 받는다.

| 후보 | 추가 크기 | 편집기와 같은 색 | 라이선스·유지 | 판단 |
| --- | --- | --- | --- | --- |
| **lezer 문법 + `@lezer/highlight`** | 바탕 0(이미 번들, M1). 언어당 1~16KB gzip (M2) | 같다 — CM6 중첩 파싱과 같은 파서·태그 | MIT. `@lezer/highlight` 2026-09-28, `@lezer/python` 2026-05-28 배포 | **채택** |
| highlight.js | core 8.6 + 언어 / common 54KB | 다르다 — 편집기는 따로 CM6 로 칠해야 해 엔진이 둘 | BSD-3, 2026-08 | 안 씀 |
| Prism | core 7.5 + 언어 | 다르다(같은 이유) | MIT, 2026-09 | 안 씀 |
| Shiki | 언어 하나에 약 70KB | 다르다. 편집기 줄에 못 씀, 비동기 | MIT, 2026-10 | 안 씀 |

- 엔진 모듈(`src/lib/codeHighlight.ts`)은 `@lezer/highlight`·`@lezer/common` 만 쓴다. CM6 를 import 하지 않는다 — 뷰어 경로가 CM6 런타임(M3 79KB gzip)을 끌어오지 않게
- 메인 청크(`index-*.js`)에 넣지 않는다. 엔진과 문법은 **필요할 때 동적 import** 한다. `index` 에는 정보 문자열 → 언어 id 표(1.2)만 들어간다
  - 정정(F-2123 4.1·N2): "메인 청크 밖" 은 **진입 `index` 청크 밖**이라는 뜻이다. 엔진은 첫 로드되는(`modulepreload`) `createEditor` 청크에 든다. F-2125 구현 뒤 `codeHighlight`·`codeParsers` 도 `createEditor` 청크로 합쳐졌다(precache +1.09 KiB, 첫 로드 gzip +1,900 B — `f76bb82`). 문법 6개(python·yaml·sql·xml·shell·json)만 따로 지연 청크

### 1.4 계약 모양

```ts
// src/lib/codeLang.ts (추가 — 동기, 메인 청크)
export type CodeLangId = 'javascript' | 'jsx' | 'typescript' | 'tsx' | 'css' | 'html' | 'xml' | 'json' | 'yaml' | 'python' | 'sql' | 'shell'
export function codeLangId(info: string): CodeLangId | null
export function codeLangIdsInHtml(html: string): CodeLangId[]   // class="language-…" 에서, 중복 없이
export const HIGHLIGHT_LANG_LABELS: readonly string[]         // 캡션용 정식 표기, 1.2 표 순서

// src/lib/codeHighlight.ts (신규 — 순수, 동적 import 대상)
export const CODE_TOKEN_KINDS = ['keyword', 'string', 'comment', 'number', 'function', 'type', 'property', 'tag'] as const
export const codeTokenHighlighter: Highlighter                // 1.3 표, scope 없음
export function highlightCodeLines(code: string, parser: Parser): { text: string; kind: CodeTokenKind | null }[][]
export function highlightHtmlCodeBlocks(html: string, parserFor: (id: CodeLangId) => Parser | null): string
export const CODE_HIGHLIGHT_LIMITS = { blockChars: 20_000, totalChars: 100_000 }

// src/lib/codeParsers.ts (신규 — 언어별 동적 import)
export function loadCodeGrammar(id: CodeLangId): Promise<CodeGrammar | null>
export function loadedCodeGrammar(id: CodeLangId): CodeGrammar | null
export type CodeGrammar = { parser: Parser; cmLanguage?: Language }  // cmLanguage 는 셸·SQL 만
```

- **상한:** 코드 한 블록이 20,000자(UTF-16)를 넘으면 그 블록은 칠하지 않는다. 한 번의 `highlightHtmlCodeBlocks` 에서 문서 순서로 칠한 코드가 합쳐 100,000자에 이르면 나머지 블록은 칠하지 않는다. 근거: M7 의 약 1ms/KB — 블록 하나 20ms, 문서 하나 100ms 안. 편집기 줄(3장)은 CM6 가 증분·분할 파싱하므로 상한이 없다
- **캐시:** `(id, 코드)` → 결과를 모듈 안 `Map` 에 200개까지, 넘으면 가장 오래된 것부터 버린다. 같은 문서를 다시 그릴 때(원격 변경·문서 목록 갱신) 바뀐 블록만 다시 파싱한다
- `highlightHtmlCodeBlocks` 는 `<pre…><code class="language-{x}…">…</code>` 의 **안쪽만** 바꾼다. markdown-it `escapeHtml` 이 바꾸는 네 글자(`&` `<` `>` `"`)를 풀고, 칠하고, 같은 네 글자로 다시 이스케이프한다. `<code>` 요소와 속성은 그대로 — `displayLangFromClass`·`toInlineStyledHtml`·`e2e/exportHtml.spec.js` 가 기대는 `<pre><code class="language-` 가 남는다
- **불러오기 실패**(오프라인에 precache 없음 등): `loadCodeGrammar` 는 `null` 을 내고, 그 id 는 **그 탭이 닫힐 때까지 다시 시도하지 않는다**. 편집기에서는 `LanguageDescription.load()` 가 거부되고(CM6 가 `logException` 으로 콘솔에 남긴다 — `@codemirror/language` `checkAsyncSchedule`), 다음 파싱부터 `codeLanguages` 가 그 id 에 `null` 을 내 언어 없는 블록이 된다. 원문은 어떤 경우에도 바뀌지 않는다

## 3. 편집·원문 모드

### 3.1 CM6 중첩 파싱

- `createEditor.ts` 의 `markdown({ … })` 에 `codeLanguages: (info) => LanguageDescription | null` 을 준다(함수 꼴 — `matchLanguageName` 의 느슨한 맞춤 대신 1.2 표로). id 마다 `LanguageDescription` 하나를 캐시하고 `load()` 는 `loadCodeGrammar` → `cmLanguage` 가 있으면 그것, 없으면 `LRLanguage.define({ parser, languageData })`
- 색은 `syntaxHighlighting(codeTokenHighlighter + scope)`. scope 는 "트리 맨 위 노드의 `languageDataProp` 이 **없거나** 1.2 언어 자료일 때" — html 블록 안 `<script>`·`<style>` 은 언어 자료 없는 날 파서라 "우리 언어만" 이면 칠해지지 않는다(F-2125 R1, 2026-10-05 정정). 마크다운 본문과 본문 속 HTML 태그(`lang-markdown` `htmlTagLanguage`)는 칠하지 않는다(M5 확인)
- `highlight.ts` 의 `markdownHighlightStyle` 에 `{ scope: markdownLanguage }` 를 준다(M5 — 코드 안 누수 막기, 마크다운 쪽 결과 불변)
- 확장은 새 파일 `src/editor/codeLanguages.ts` 가 묶어 내고 `createEditor.ts` 는 한 줄 + `markdown()` 옵션 한 개만 바꾼다

### 3.4 접힌 코드블록 위젯 (`blocks.ts` `CodeWidget`)

- `toDOM` 에서 `loadedCodeGrammar` 의 파서로 `highlightCodeLines` 를 불러 `.md-codeblock-line` 안에 `<span class="code-{종류}">` 를 넣는다. 줄 span·`data-offset`·복사 글자(`codeBlockText`)는 그대로 — 클릭 위치는 `closest('[data-offset]')` 라 안쪽 span 을 눌러도 같다
- 비교 키에 "그 언어 파서가 불러와졌는가" 를 넣는다. 언어가 늦게 오면 CM6 가 다시 파싱 → 블록 필드가 `treeChanged` 로 다시 만들어지고(F-134 3.8) → 키가 달라져 다시 그린다
- 칠하기는 생성자가 아니라 `toDOM` 에서 한다 — 블록 필드는 고칠 때마다 문서 전체를 돈다(F-106 2.5). 1.4 상한·캐시를 그대로 쓴다
- 위젯과 펼친 줄은 같은 파서 설정·같은 1.3 표라 같은 클래스를 받는다(10장 A6)

### 3.5 성능·IME

- 매 입력 비용은 M7 의 증분 파싱 — 코드 많은 문서에서 0.4 → 4.7ms. 1,800줄 Python 한 블록 안에서 고치면 30ms 라 CM6 가 동기 20ms 뒤 나머지를 쉬는 시간에 넘기고, 그동안 그 블록 아래쪽 색이 한 박자 늦게 바뀐다. 받아들인다
- **조합 중 보류를 새로 만들지 않는다.** 색은 라이브러리 `syntaxHighlighting` 이 칠한다 — 지금 마크다운 강조(제목·굵게)와 같은 길이고, M1 부터 한글 조합 중에도 돌았다. 우리 쪽 보류 재계산이 늘지 않으니 "조합 끝에 따라잡기" 불변식에 걸릴 것이 없다. 위젯은 이미 조합 중 보류하는 블록 필드 안이다. 실제 한글 IME 는 사람 확인
- 인라인 코드(`InlineCode`)는 중첩 대상이 아니다. 표 칸 하위 편집기에는 마크다운 언어가 없다

### 10.3 체인지로그 후보 (`content/changelog.md`)
