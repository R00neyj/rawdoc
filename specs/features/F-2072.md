# F-2072 App.tsx 분할 3 — 편집기 연동을 useEditorSync 로

작성일: 2026-09-28
상태: **승인 대기.** 11장 열린 질문 Q1~Q8 은 모두 기본값이 있다. 기본값대로 가면 사람이 정할 갈림길은 없다. 설계 개요 `specs/features/F-2059.md`(2026-09-28 승인) 6장 로드맵 F-2072 행을 구현하는 조각이다. 단계 3, "편집기 연동 → `useEditorSync.ts`", 줄 감소 약 240(추정), 선행 F-2071, e2e 묶음 `editor`·`viewScroll`·`lineNumbers`·`outline`·`wikiPreview`·`wikiResolve`·`docSearch`·`yjsUndo`·`liveDoc`·`publicView` + 4장 `--repeat 3` + `verify:full`. 개요 1~5장 결정과 9장 기본값을 그대로 물려받는다. 옮기기만 하고 동작은 바꾸지 않는다(전제 3). 순수 모듈은 없다(개요 2.3 표 F-2072 행 "—")
선행: **F-2071 구현 커밋 뒤에 띄운다**(개요 5.5 — 조각은 순서대로만). 구현 담당은 `feature-implementer`(개요 전제 8). main 은 프롬프트에 "F-2059 5.1 예외" 한 줄을 넣는다 — 8장 e2e 묶음, `--repeat 3`, `verify:full` 이 이 명세의 수용 기준이다. 뒤 조각 F-2073(금고 옮기기)과의 경계는 2.4 에 있다

### 앞 조각에 대한 가정 (구현자가 7.2 에서 먼저 확인한다)

이 명세는 HEAD `82fb3b8`(`git show HEAD:src/app/App.tsx`, 4,260줄)을 읽고 썼다. 그 뒤에 F-2069(알림함)·F-2070(실시간 알림 띠)·F-2071(해시 라우팅)이 먼저 커밋된다. - 세 조각이 옮기는 이름(개요 5.4 구역: 알림함·멘션·점 / 실시간 알림 띠 N1~N10·오프라인 보기 / 해시 라우팅·공개 보기 경로)은 App 에서 빠진다. 줄 번호는 모두 그만큼 당겨진다. 이 명세의 줄 번호는 `82fb3b8` 기준 힌트일 뿐이고, 이름으로 찾는다

### 3.1 effect 실행 순서 — 옮기기 전·후

한 커밋 안에서 layout effect 는 모두 passive effect 보다 먼저, 같은 종류 안에서는 호출 순서대로 돈다. 훅 안 effect 는 훅을 부른 자리에서 돈다(개요 3.2).

| 순서 | 지금(App, `82fb3b8`) | 옮긴 뒤 |
| --- | --- | --- |
| layout | … 부팅 스켈레톤 인계(≈1950) → `useAppearancePrefs` 안 → **줄 번호 → 테마 → 들여쓰기 → 읽기 전용 → 제목 → 제목 읽기 전용 → 폴더 경로 → 스크롤 복원** → `useContextMenu` 구독(≈3629) … | 같다. 굵은 8개가 훅 안에서 같은 순서로, 같은 상대 자리(`useAppearancePrefs`·`useGlobalShortcuts` 뒤, `useContextMenu` 앞)에서 돈다 |
| passive | … `useGlobalShortcuts` 6개 → **① 본문 1회 읽기** → ② stats 타이머 정리 → **③ 보기 HTML → ④ 검색어 넘기기 → ⑤ 제목 이동 → ⑥ 위키 문맥 갱신 → ⑦ view 권한 알림** → ⑧ 포커스 플래그 정리 → 최신값 ②·③ … | … `useGlobalShortcuts` 6개 → **① → ③ → ④ → ⑤ → ⑥ → ⑦**(훅 안) → ② → ⑧ → 최신값 ②·③ … |

- **움직이는 것은 ② 하나다.** ② 가 ③~⑦ 뒤로 간다. 동작이 같은 이유(코드 읽기)
  1. React 는 한 커밋의 passive effect 를 "바뀐 effect 의 정리 함수 전부 → 설정 함수 전부" 두 단계로 돈다. 정리 함수가 있는 것은 ① (`cancelled = true`)과 ② (`clearTimeout`)뿐이고, 둘의 상대 순서(① → ②)는 그대로다
  2. ② 의 설정 함수는 정리 함수를 돌려줄 뿐 아무 일도 하지 않는다. ③~⑦ 은 `statsTimerRef`·`stats` 를 읽지 않는다(`grep -nw`)
- ⑧ 은 원래도 ⑦ 뒤였고 옮긴 뒤에도 ⑦ 뒤다
- layout effect 를 passive 로(또는 반대로) 바꾸지 않는다(개요 3.2 마지막 항목)

## 11. 열린 질문 (모두 기본값 — 기본값대로)

### Q1. Ⓓ 첨부 해석(`attachmentResolverFor`·`resolveAttachment`)을 이 조각이 가져가나 — **기본값: 가져간다**

- 이유: F-2065 2.2 와 F-2068 2.2 가 둘 다 이 두 이름을 "편집기 연동 구역(F-2072)" 으로 넘겼다. `resolveAttachment` 는 `<Editor>` 마운트 넘김값(개요 3.4)이고 `<Viewer>` 도 받는다. `useCallback`·`useMemo` 뿐이라 자리를 옮겨도 effect 순서와 무관하다. F-2065 가 남긴 제약(`createExportActions` 가 훅 호출보다 아래)은 호출 자리 ≈2125 < ≈3007 로 맞는다
- 다른 쪽(App 에 둔다): 개요 5.4 행 이름("본문 1회 읽기·위키 문맥·보기 HTML·layout effect")을 글자 그대로 따른다. App 감소가 17줄 적어지고(−208), 반환이 5개가 된다. F-2065 제약은 생기지 않는다(그래도 `resolveWikiHref` 때문에 같은 제약이 남는다). 두 이름은 단계 4 까지 App 에 남는다

### Q2. stats 타이머 정리 effect 를 App 에 두나 — **기본값: App 에 둔다 (2.2)**

- 이유: `statsTimerRef` 의 대입은 `handleDocChange`(App) 안이다 — 개요 3.2 의 옮기는 조건에 맞지 않는다. 옮기면 정리 함수가 훅 인자 `statsTimerRef.current` 를 읽는데 같은 파일에 대입이 없어 `exhaustive-deps` 가 `will likely have changed by the time this effect cleanup function runs` 를 낸다(규칙 원문 확인). 없애려면 본문을 바꿔야(값을 변수에 복사) 해서 "옮기기만" 을 어긴다. 남겨도 3.1 표대로 순서 차이를 관찰할 수 없다
- 다른 쪽(옮긴다): passive 순서가 한 곳도 안 움직인다. 대신 정리 함수 본문이 바뀌거나 새 `eslint-disable` 이 생긴다 — 둘 다 개요 3.6·3.7 위반

### Q3. 훅 호출 자리 — **기본값: Ⓐ 자리(≈2125) (4.5)**

- 이유: 훅 안 effect 13개가 모두 제자리에서 돈다. 위 한계(`useAppearancePrefs` 반환 ≈2100)와 아래 한계(`createExportActions` ≈3007) 안이다
- 다른 쪽(Ⓒ 자리 ≈2188): stats effect 는 제자리에 남지만 ① 이 ② 뒤로 가고, Ⓑ·Ⓒ 사이 팔레트 `useMemo` 를 넘는다. 움직이는 effect 가 ① 하나로 수는 같지만, ① 은 불변식 경로라 옮기지 않는 쪽이 판정이 쉽다
- 다른 쪽(Ⓓ 자리 ≈2990): 아래 한계 바로 위라 가능하지만, effect 13개가 `useDocSaver`·최신값 ②·③·`useImportFlow`·탭 숨김 저장·금고 옮기기 등 수십 개 effect 를 건너 뒤로 간다

### Q4. `changeViewMode` 를 옮기나 — **기본값: App 에 둔다 (2.2)**

- 이유: 개요 5.4 행에 없다. `setViewMode`(App 상태, 팔레트·상단바·댓글·JSX 가 읽는다)·`setPref('md.viewMode')`·`scrollAnchorRef` 대입을 하는 전환 함수다. 옮기면 `setViewMode` 와 `viewerHtml` 계열 setter 가 모두 이 훅을 거치게 되고, `useDocComments` 인자 화살표·팔레트·JSX 가 반환값을 읽게 된다
- 다른 쪽(옮긴다): 보기 HTML 을 만드는 두 곳(③ effect·`changeViewMode`)이 한 파일에 모인다. `scrollAnchorRef` 도 선언·대입·읽기가 한 조각에 들어와 훅 안으로 갈 수 있다. 대신 `viewMode` 상태까지 옮길지가 새로 갈리고, 반환이 늘며, 함수 선언을 반환값으로 바꾸는 것이라 위쪽 참조의 TDZ 를 다시 따져야 한다

### Q5. view 권한 알림 effect(`notifiedViewDocRef`)를 옮기나 — **기본값: 옮긴다**

- 이유: Ⓒ 절 안(스크롤 복원 바로 아래)에 있고 선언·대입·읽기가 모두 그 안이다. App 에 남기면 Ⓒ 가 둘로 갈라져 훅 호출 뒤 App 쪽에 effect 가 하나 더 남는다. 순서는 어느 쪽이든 같다(⑦ 은 ⑥ 뒤, ⑧ 앞)
- 다른 쪽(App 에 둔다): 이 훅이 알림(F-212)을 몰라도 된다. App 감소가 8줄 적어진다(−217)

### Q6. e2e 묶음에 7개 파일과 `F-409 E5` 를 더하나 — **기본값: 더한다 (8장)**

- 이유: 로드맵 행 10개로는 layout effect 중 테마(`mermaid`)·들여쓰기(`theme`)·읽기 전용과 view 권한 알림(`invite`)·제목과 폴더 경로(`docTitle`), 금고 다시 읽기(`e2eeDocs`), 첨부 해석(`image`·`print`), 문맥 갱신(F-409 E5)을 아무것도 보지 않는다. 빼는 것이 아니라 더하는 것이라 개요와 부딪치지 않는다(F-2066 Q2·F-2068 Q7 과 같은 판단). A7 `verify:full` 이 어차피 전부 돌지만, 묶음이 먼저 잡으면 실패 원인을 좁히기 쉽다
- 다른 쪽(로드맵 행 그대로): 묶음이 짧다. 위 경로는 `verify:full` 에서만 본다

### Q7. 연속 3줄 주석 한 덩어리 — **기본값: 설명 두 줄을 한 줄로 합친다 (5.5)**

- 이유: 새 파일에 추가된 줄로 들어가면 `review` 가 막는다. 개요 3.6 이 "그 자리에서 줄인다" 를 허용한 유일한 주석 변경이다. 절 머리는 다른 절들과 모양을 맞추려고 남긴다
- 다른 쪽(절 머리 줄을 지운다): 설명 두 줄은 그대로 이동색으로 남는다. 대신 "보기 모드 변환" 절 이름이 사라져 옛 명세 F-123 3.3 을 가리키는 표지가 없어진다

### Q8. `--repeat 3` 대상 — **기본값: 개요 4장 행 글자 그대로 6개 파일**

- 이유: 개요가 이 조각의 불변식 검증으로 정한 목록이다. `liveDoc`(실시간 `null`·폴백·4403·4404)·`offlineDoc`(오프라인 보기)·`liveResume`·`sessionRestartFlush`·`remoteGate`·`docLock` 이 본문 1회 읽기 갈래와 `docSaver.blocked` 를 모두 지난다. 검색어가 파일 이름에 맞는 것은 Playwright 원문으로 확인했다
- 다른 쪽(`e2eeDocs.spec.js` 를 더한다): 금고 다시 읽기 갈래(`openLoadE2eeKey`·잠긴 금고 가드)도 세 번 돈다. 이 갈래는 단일 `Y.Text` 불변식이 아니라 금고 표시 쪽이라 기본값에서 뺐다 — 묶음에서 1회는 돈다

### 관찰 (이 조각은 고치지 않는다 — F-2059 7장 성격, 판정은 사용자)

1. **경계 — 옆 조각과 대조 필요:** Ⓓ 첨부 해석은 개요 5.4 행 이름에 없고 F-2065·F-2068 명세만 이 조각으로 넘겼다(Q1). "문서 전환 후 포커스 요청 플래그 정리" 절(F-103)과 `handleDocChange`·`handleSelectionChange`(상태바·떠 있는 댓글 버튼)는 편집기와 닿지만 5.4 어느 행에도 없어 App 에 남긴다 — 단계 4 결정 때 자리를 정한다. F-2070 관찰 5 가 이 조각과 대조하라고 넘긴 `liveEditorOption`(편집기 `live` 넘김값)과 `liveRoomDoc` 사이드바 `updatedAt` effect 도 가져가지 않는다 — 둘 다 방 세션(`liveSession`·`liveRoomDoc`)에서 나오는 값이라 개요 3.3 블록 d 와 같은 세션 핵(단계 4) 쪽이다
2. 개요 전제 6 은 "옮긴 코드의 주석 문제는 없다" 고 보았지만, "보기 모드 변환" 절 머리 + 설명 두 줄이 연속 3줄이다(5.5). App 안에서는 추가된 줄이 아니라 `review` 에 안 걸렸고, 옮기면 걸린다. 같은 모양(절 머리 + 설명 2줄)이 App 에 남는 "문서 전환 후 포커스 요청 플래그 정리" 절에도 있다 — 그 절을 옮기는 조각이 같은 처리를 해야 한다
3. App 에 남는 `changeViewMode` 안 주석 `passive effect(1050행대)에 맡기면 …` 의 줄 번호는 이미 맞지 않는다(그 effect 는 `82fb3b8` 에서 ≈2246, 이 조각 뒤에는 `useEditorSync.ts`). 줄 번호 인용이라 낡았다 — 이 조각은 `changeViewMode` 를 옮기지 않으므로 그대로 둔다
4. 보기 HTML 을 만드는 곳이 두 곳이다 — ③ effect(문서를 열 때·편집기가 바뀔 때)와 `changeViewMode`(보기로 갈 때 즉시, F-295 5.2a). 이 조각 뒤에는 두 파일로 갈린다. 식(`renderMarkdown(editorRef.current.getText('lf'), { resolveWikiLink: resolveWikiHref, sourceLines: true })` + `setViewerDocId(currentDocId)`)이 글자 그대로 같다 — 합치지 않는다(전제 3, D3·D6 과 같은 성격)
