## 2. 요구사항

### 2.1 D1
```sql
CREATE TABLE grants (
  target_type TEXT NOT NULL CHECK (target_type IN ('doc','folder')),
  target_id TEXT NOT NULL,
  owner_id TEXT NOT NULL REFERENCES users(id),
  grantee_email TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('view','edit')),
  created_at INTEGER NOT NULL,
  PRIMARY KEY (target_type, target_id, grantee_email)
);
CREATE INDEX grants_grantee ON grants(grantee_email);
```
- 이메일은 소문자. 초대받은 사람이 아직 로그인한 적 없어도 된다 (로그인하면 이메일로 맞춘다)

### 2.2 권한 판정 (`access.ts`)
- 문서 역할 = 소유자면 `owner` / 아니면 문서 grant 와 문서의 폴더·상위 폴더 grant 중 **가장 높은 것**(`edit` > `view`) / 없으면 없음(404)
- 할 수 있는 것
| 동작 | owner | edit | view |
| --- | --- | --- | --- |
| 조회, 첨부 조회 | O | O | O |
| 제목·원문 수정 (`PUT /api/docs/:id`), 첨부 올리기 | O | O | X (403 `forbidden`) |
| 이동·고정·삭제·링크·초대 관리 | O | X | X |
- 권한이 전혀 없으면 지금처럼 404. 권한은 있으나 동작이 막히면 403
- 문서 소유자 또는 보는 사람이 막힌 계정이면 `owner`·`edit` 가 `view` 로 낮아진다 (F-2028 4.2)
- 편집자가 올린 첨부는 올린 사람 소유. 문서 조회 권한이 있고 원문이 참조하면 읽을 수 있다 (F-209 2.4 규칙을 "첨부 소유자가 문서 소유자이거나 그 문서의 edit 권한자" 로 넓힌다)
- 로그인 첨부 조회는 `GET /api/attachments/:idext?doc={문서 id}`. 내 첨부는 `doc` 없이, 남의 첨부는 `doc` 의 조회 권한 + 원문 참조로 판정 (2026-09-15 Worker 구현에서 정함, 앱은 공유받은 문서 이미지에 `doc` 를 붙인다)
- 첨부 올리기는 문서를 지정하지 않아 역할을 보지 않는다. 올린 사람 공간에만 저장되고, 보기 권한자는 원문을 바꿀 수 없어 참조되지 않는다 (앱이 `view` 문서에서 올리기를 막는다)
- 링크 관리(`/api/docs/:id/link`·폴더 링크)는 소유자가 아니면 404 로 둔다 (위 403 규칙의 예외, 2026-09-15)
- 폴더에 준 권한은 그 안의 문서에 **조회 시점 기준**으로 적용 (옮기면 바로 바뀜)
- 공유받은 문서의 고정(pin)은 이번 범위 밖

### 2.3 초대 라우트 (owner 만)
| 요청 | 동작 |
| --- | --- |
| `GET /api/docs/:id/grants`, `GET /api/folders/:id/grants` | `[{email, role, createdAt}]` |
| `PUT /api/docs/:id/grants/:email` `{role}` (폴더도 같음) | 추가·역할 변경 → 200. 자기 이메일이면 400 |
| `DELETE /api/docs/:id/grants/:email` (폴더도 같음) | 204 |
| `GET /api/shared` | 나에게 권한이 있는 문서 메타 `[{...Doc 메타, role, ownerEmail, viaFolder?:{id,name}}]` (원문 제외). 폴더 초대는 모든 자손 폴더를 덮는다, `viaFolder` 는 가장 가까운 초대 폴더 (2026-09-23, F-2017 4.4) |

### 2.4 앱: 공유받음
- `serverStore.list()` 는 내 문서 + `/api/shared` 문서를 합쳐 캐시(F-207 방식, `role` 포함)
- 사이드바 `고정됨` 아래, 내 폴더·문서 위에 `공유받음` 묶음(IconGroup, 접기 가능, 공유받은 게 없으면 숨김). 폴더로 받은 것은 폴더 이름 아래, 문서로 받은 것은 바로. 행 오른쪽 흐린 글자로 소유자 이메일 앞부분
- 공유받은 문서는 끌어 옮기기·`⋯` 이동·삭제·고정·링크·초대 항목이 없다
- `view` 문서: 에디터 `readOnly`, 편집 모드에서도 입력 불가, 상단바 제목 입력 비활성, 알림 띠(info) `보기 권한만 있는 문서입니다.` 이미지 붙여넣기·끌어놓기 받지 않음
- `edit` 문서: 보통 편집. 저장은 F-207 흐름 그대로 (서버가 403 을 주면 error 알림 `이 문서를 편집할 권한이 없어졌습니다.` 후 읽기 전용으로). 403 `account_blocked` 는 다른 갈래 — F-2030 4.4

### 2.5 대화상자 D-4 `사람 초대`
- 공유 메뉴(문서) / 폴더 `⋯` 메뉴에서 owner 일 때 `사람 초대…` (IconPersonAdd)
- 내용: 이메일 입력 + 역할 선택(`보기` / `편집`, 기본 보기) + `초대` 버튼 → 아래에 현재 초대 목록(이메일, 역할 선택, `삭제`)
- 이메일 형식 오류: 입력 아래 `이메일 주소를 확인하세요.`
- 성공 알림: `{이메일} 님에게 {보기|편집} 권한을 줬습니다. 앱 주소를 직접 알려 주세요.` (메일은 보내지 않는다)
- 대화상자 여닫기·포커스는 기존 D-1~D-3 과 같다
