# F-2089 휴대폰 폭 목차 오른쪽 패널 — 오른쪽 가장자리 밀기

작성일: 2026-09-29
상태: 승인 (2026-09-29, Q1 사용자 선택 '어디서든 왼쪽 밀기', 나머지 기본값). 사용자 보고(2026-09-29, 휴대폰) "목차보기가 너무 안쪽으로 들어가서 보기 불편함. 목차는 이전처럼 표시하거나 (원형버튼) 우측 스와이프시 사이드바로 표시." → 같은 날 AskUserQuestion 으로 **오른쪽 스와이프 → 오른쪽 사이드바 목차** 를 골랐다(둥근 버튼 되살리기는 고르지 않음). 아래 "정해진 것" 1~4 는 요청 때, 5 는 승인 때 사용자가 정했다. 이 명세가 새로 정하는 것은 밀기 판정과 왼쪽 사이드바 밀기와의 분리(4장), OS 가장자리 제스처 대응(4.3), 패널이 열리는 화면(3.1), 여닫기·포커스(5장), 층위·알약 숨김(6장), 휴대폰 폭 목차 카드 경로 제거(7장)다. 12장 결정은 승인 때 모두 정해졌다(Q1 은 사용자가 기본값 "오른쪽 끝 80px" 대신 "어디서든 왼쪽 밀기" 를 골랐다)
구현 담당: `feature-implementer`. 선행 조건 "F-2087(보기 모드 찾기) 커밋 뒤" 는 **해소됨** — F-2087 이 `1bf37c5` 로 커밋됐다. 이 명세도 `src/app/DocumentArea.tsx` 를 고치지만(prop 한 줄, 1장) F-2087 이 넣은 `ViewFindCard` 줄·prop 과 겹치지 않는다. F-2087 이 고친 `PhoneNav.tsx`·`phoneNav.ts`·`AppTopBar.tsx`·`App.tsx` 는 이 명세가 건드리지 않는다

범위 메모: `specs/product.md` 4.5 "M1 에서 하지 않는 것" 의 "모바일 레이아웃" 문장은 F-2083 8장이 이미 갱신 대상으로 올렸다. 이 명세도 M2 이고 사용자가 이 날 직접 요청했다 — 따로 막지 않는다(11장)

## 정해진 것 (2026-09-29 사용자, 바꾸지 않는다)

1. 창 폭 **600px 이하만**. 601px 이상의 목차(F-229 둥근 버튼·팝업 카드, 넓은 창 선 목차 F-144)는 그대로
2. 화면 **오른쪽 끝에서 왼쪽으로 밀면** 오른쪽에서 목차 패널이 나온다(Obsidian 모바일 오른쪽 패널처럼). 화면 높이를 다 쓰는 겹침 패널 — 왼쪽 겹침 사이드바(F-227, `.sidebar--overlay`)와 짝
3. 상단바 ⋯ 판의 `목차` 행(F-2083 결정 7)도 이 패널을 연다. 휴대폰 폭에서는 본문 위 팝업 카드를 더는 쓰지 않는다
4. 둥근 목차 버튼은 되살리지 않는다
5. (승인 때, Q1) 여는 밀기는 **화면 어디서 시작하든** 왼쪽으로 밀면 된다 — 왼쪽 사이드바(F-227 "화면 어디서든")와 대칭, Obsidian 방식. 2번의 "오른쪽 끝에서" 는 이 결정으로 "어디서든" 이 된다. 제목의 "오른쪽 가장자리 밀기" 는 처음 요청 표현이라 그대로 둔다

## 2. 범위

### 한다
- ≤600px 앱 문서 화면에서 어디서든 왼쪽으로 밀면 오른쪽 겹침 목차 패널이 열린다(정해진 것 5)

- 넓은 창(601~1023px, 역시 `narrow`)의 왼쪽 밀기로 목차 열기 — 그 폭은 F-229 버튼이 있다

```ts
  startedInScrollableRight: boolean  // 시작 지점 조상 중 오른쪽으로 더 스크롤되는 요소가 있음
}

export function classifyOutlineSwipe(input: OutlineSwipeInput): 'open' | 'close' | null
```

규칙(거리·방향 비율은 `classifySwipe` 와 같은 상수 `SWIPE_THRESHOLD_PX`·`SWIPE_DIRECTION_RATIO` 를 쓴다):
- **패널이 열려 있으면**: 패널·뒤 막 밖에서 시작했으면 `null`. 오른쪽으로 56px 이상이고 가로 ≥ 1.5×세로면 `'close'`. 그 밖은 `null`
- **닫혀 있으면**: 시작 위치와 무관(정해진 것 5 — `classifySwipe` 열기의 거울). `startedInScrollableRight` 면 `null`. 왼쪽으로 56px 이상이고 방향 비율을 넘으면 `'open'`. 그 밖은 `null`
- DOM·React import 없음

### 3.3 `src/app/Outline.tsx`

```ts
// OutlineProps 에 추가
phonePanel?: boolean   // 참이면 여백 모드에서 .outline-popup 대신 오른쪽 패널(F-2089). DocumentArea 만 넘긴다
```

- `OutlineControl` 모양은 그대로(`TopBarMoreSheet` 를 고치지 않으려고). `openCard(el)` 의 뜻이 넓어진다: `phonePanel` 이면 **패널을 열고** Esc·`목차 닫기` 로 닫힐 때 포커스를 `el` 로 돌린다. 아니면 지금처럼 버튼 모드 카드

- 패널 열림은 `Outline` 안 상태 하나. 카드 열림 상태(`cardOpen`)와 따로 둔다
- 현재 위치 계산·`selectHeading` 은 카드와 같은 것을 쓴다(패널에서 고르면 카드 대신 패널을 닫는다)
- 밀기 훅(`useOutlineSwipe`)은 `if (!visible) return null` **앞에서** 부르고, 켜짐 조건은 `phonePanel && 제목 1개 이상`

### 3.4 `src/app/OutlinePanel.tsx` — DOM

`.app-body` 의 자식으로 포털한다. 찾는 방법: `Outline` 의 `containerRef`(`.content-area`) 에서 `closest('.app-body')` — 마운트 뒤 effect 에서 한 번 찾아 상태로 둔다(렌더 중 DOM 읽기 금지). 못 찾으면 패널을 그리지 않는다.

```html
<div class="outline-panel-backdrop"></div>          <!-- 열림 동안만. 투명, 누르면 닫기 -->
<nav class="outline-panel" aria-label="목차" data-state="open|closed" inert(closed 동안)>
  <div class="outline-panel-head">
    <h2 class="outline-panel-title">목차</h2>
    <button type="button" class="icon-btn outline-panel-close" aria-label="목차 닫기"><IconClose/></button>
  </div>
  <ol class="outline-panel-list">
    <li data-level="1|2|3"><button type="button" class="outline-item" aria-current="location"?>제목 글자</button></li>
  </ol>
</nav>
```

- `data-state` 는 `usePresence`(F-172) — 닫힐 때 전환 시간만큼 `closed` 로 남았다가 빠진다. `closed` 동안 `inert`
- 항목 모양은 `.outline-item` 을 그대로(한 줄 말줄임, `aria-current` 강조), 들여쓰기는 `.outline-popup-card` 와 같은 값(`data-level` 2 → 20px, 3 → 32px)
- 이름: `nav` 의 `aria-label` 과 머리 제목이 모두 `목차`. 닫기 버튼 `목차 닫기`(8장 문구)

## 4. 밀기 판정 (반드시 결론 1·2)

### 4.1 두 밀기가 섞이지 않는 규칙

| 상태(`touchstart` 때) | 오른쪽으로 밀기 | 왼쪽으로 밀기 |
| --- | --- | --- |
| 둘 다 닫힘 | 사이드바 열기(어디서든, F-227 그대로) | **목차 열기(어디서든)** — 정해진 것 5 |
| 왼쪽 사이드바 열림 | 없음(F-227) | 사이드바·뒤 막에서 시작하면 사이드바 닫기(F-227). **목차는 열지 않는다** — 사이드바(85%)와 뒤 막이 화면 전체를 덮으므로 이 상태의 왼쪽 밀기는 모두 "사이드바 닫기" 다 |
| 목차 패널 열림 | 패널·뒤 막에서 시작하면 **목차 닫기**. **사이드바는 열지 않는다** | 없음 |

- 방향이 반대라 "둘 다 닫힘" 에서는 저절로 갈린다(`classifySwipe` 는 닫힌 사이드바에서 왼쪽 밀기를 `null`, `classifyOutlineSwipe` 는 닫힌 패널에서 오른쪽 밀기를 `null`). 두 쪽 모두 "어디서든" 이라 완전한 거울이다
- 부딪히는 두 칸은 **`touchstart` 시점의 DOM 으로** 가른다. `touchend` 때 읽으면 먼저 돈 쪽 리스너가 상태를 바꾼 뒤(실제 터치 이벤트는 리스너 사이에 마이크로태스크가 돌아 React 가 반영할 수 있다) 다른 쪽이 바뀐 상태를 읽을 수 있다
  - `useEdgeSwipe`: `touchstart` 에 `.outline-panel[data-state='open']` 이 있으면 이 터치를 기록하지 않는다(`dialog[open]` 과 같은 자리)
  - `useOutlineSwipe`: `touchstart` 에 `.sidebar-backdrop` 이 있으면(= 좁은 창 겹침 사이드바 열림) 기록하지 않는다
- 패널이 열려 있으면 알약이 숨고(6.2) 나머지 화면은 뒤 막이 덮으므로, 열린 동안 모든 터치는 패널이나 뒤 막에서 시작한다

### 4.2 `useOutlineSwipe` 무시 조건 (`useEdgeSwipe` 와 같은 틀)

시작 영역 제한이 없으므로 본문 위 왼쪽 가로 밀기는 아래 예외가 아니면 모두 목차를 연다. 예외는 `useEdgeSwipe` 열기 예외의 거울이다.

- 손가락 1개가 아니면, 한글 조합 중이면(`compositionstart`~`compositionend`), `dialog[open]` 이 있으면(⋯ 판·팔레트·검색 등), `touchcancel` 이 오면
- 시작 지점이 `.comment-sheet`(댓글 아래 판) 안이면 — 판 안 스크롤·입력과 섞지 않는다
- 편집기 안에서 비어 있지 않은 선택을 끄는 중이면(선택 손잡이 끌기 포함, `isDraggingTextSelection` 과 같은 판정)
- 시작 지점 조상 중 **오른쪽으로 더 스크롤될 수 있는 요소**가 있으면(`scrollWidth > clientWidth` 이고 오른쪽 남은 거리가 1px 초과) — 넓은 표(`.md-table-scroll`)·코드 블록·가로로 넘치는 이미지, 휴대폰 서식 바 줄(`.editor-toolbar-row`, F-2084 가로 스크롤)의 가로 스크롤에 양보(F-227 왼쪽 판정 `hasScrollableLeftAncestor` 의 거울). 이미 오른쪽 끝까지 스크롤된 요소 위에서 왼쪽으로 밀면 목차가 열린다 — 사이드바 쪽(왼쪽 끝까지 간 표 위 오른쪽 밀기 → 사이드바)과 같다. 본문 스크롤러는 가로로 스크롤되지 않는다(근거 절 실측)
- 이벤트는 `passive`, `preventDefault` 하지 않는다 — 세로 스크롤·표 가로 스크롤을 막지 않는다. 세로 스크롤은 방향 비율(1.5)로 걸러진다
- 지도·공유 화면·홈 등은 3.1 로 훅 자체가 꺼져 있다

### 4.3 OS·브라우저 가장자리 제스처 (반드시 결론 3)

- **안드로이드 제스처 내비**: 양쪽 가장자리 안쪽 밀기가 시스템 뒤로 가기다. AOSP 기본 30dp, 민감도 설정에 따라 18~40dp(근거 절). 그 띠 안에서 시작하면 시스템이 가로채고 페이지에는 `touchcancel` 이 온다 — 웹은 빠질 방법이 없다
- **iOS Safari 일반 탭**: 오른쪽 가장자리 밀기가 앞으로 가기(앞 항목이 있을 때). 폭 미확인
- **대응: 시작 영역을 두지 않는다(어디서든, 정해진 것 5) — 그래서 가장자리 띠를 피해 화면 안쪽에서 밀면 된다.** 앱이 할 일은 OS 가 가져간 터치를 판정하지 않는 것 하나다
  - 가장자리 끝에서 시작하면 OS 제스처가 먼저다 — 앱이 막지 않는다. `touchcancel` 로 기록이 버려지므로 뒤로(앞으로) 가기와 패널 열기가 **둘 다 일어나지는 않는다**(`useEdgeSwipe` 의 `touchcancel` 처리와 같다)
  - OS 가 가로채지 않은 채 `touchend` 까지 온 터치만 판정한다. 사이드바 쪽 왼쪽 가장자리도 지금 같은 조건이다(F-227 A7 사람 확인)
  - 오른쪽 위 알약(390 에서 x 300~382, y 8~52) 위에서 시작한 왼쪽 밀기도 패널을 연다. 누르기는 밀기가 아니라 영향 없음
- 사람 확인 H3 에서 실기기로 본다

## 5. 여닫기·포커스 (반드시 결론 4·5)

### 5.1 열기

| 무엇으로 | 포커스 |
| --- | --- |
| 왼쪽 밀기(4장, 어디서든) | 현재 위치 항목(`aria-current="location"`)으로 |
| ⋯ 판 `목차` 행(`openCard(⋯ 버튼)`) | 같음 |

- 열면 현재 위치 항목이 패널 목록 세로 가운데 오도록 **목록만** 스크롤한 뒤 그 항목에 포커스한다. 포커스가 옮겨가면서 본문·입력칸 포커스가 풀려 커서가 패널 뒤에서 깜박이지 않고 가상 키보드가 내려간다 — 왼쪽 사이드바 blur effect(`useSidebarLayout`, 2026-09-29 버그 수정 `a6881ed`)와 같은 목적을, 포커스를 패널로 옮기는 방법으로 이룬다
- 이미 열려 있으면 아무것도 안 한다

### 5.2 닫기

| 무엇으로 | 포커스 |
| --- | --- |
| 항목 누르기 → 그 제목으로 이동(`selectHeading`, 카드와 같다) 후 닫기 | 옮기지 않는다(F-229 2.4 와 같다 — 본문에 포커스를 주면 휴대폰 키보드가 올라온다) |
| `목차 닫기` 버튼 | 연 곳이 ⋯ 판이면 `⋯` 버튼, 밀기로 열었으면 옮기지 않는다 |
| `Esc` — 패널이 열린 동안 `document` `keydown`. `dialog[open]` 이 있으면 무시(그 대화상자가 받는다) | `목차 닫기` 와 같다 |
| 뒤 막 누르기(`click`) | 옮기지 않는다 |
| 패널·뒤 막에서 시작한 오른쪽 밀기(4.1) | 옮기지 않는다 |
| `dialog[open]` 이나 `.sidebar-backdrop` 이 생김(카드의 `MutationObserver` 규칙 재사용) | 옮기지 않는다 |
| 문서가 바뀜(`docId` 변경 — 안드로이드 뒤로 가기 등) | 옮기지 않는다 |
| `phonePanel` 이 거짓이 됨(601px 이상으로 넓어짐, 지도·공유 화면으로 감) | 옮기지 않는다. 다시 좁혀도 닫힌 채 |
| 제목이 0개가 됨(원격 편집 등) | `Outline` 이 `null` — 패널이 곧바로 빠진다 |

- "옮기지 않는다" 인데 포커스가 패널 안에 있었으면 패널이 빠지며 `body` 로 간다. 휴대폰에서 의도한 결과다(키보드가 다시 올라오지 않음)
- 뒤로 가기: 패널은 기록(history)에 항목을 넣지 않는다(F-2083 4.4 ⋯ 판과 같은 판단). 안드로이드 뒤로 가기는 문서를 옮기고, 위 표의 `docId` 줄로 패널이 닫힌다

### 5.3 패널이 열린 동안

- 패널 목록은 세로 스크롤. 현재 위치 강조(`aria-current`)는 본문 스크롤을 따라 계속 갱신된다(지금 스크롤 구독 그대로 — 패널이 본문을 가려도 계산은 돈다)
- 뒤 막은 투명(`.sidebar-backdrop` 과 같음). 본문은 `inert` 로 만들지 않는다 — 겹침 사이드바와 같은 수준
- 키보드: Tab 은 머리 `목차 닫기` → 항목들 순. 패널 밖으로 Tab 이 나가면 닫지 않는다(사이드바와 같다). 방향키 순회 없음

### 6.2 자리와 알약 숨김

- 패널: `.app-body` 안 `position: absolute`, 위·오른쪽·아래 0 — `.app-body` 가 앱 틀 전체(390×844 실측)라 상태바까지 덮는다. 폭 85%(≤600px 겹침 사이드바와 같은 값). 바탕 `--paper`, 왼쪽 1px `--rule`, 그림자는 `.sidebar--overlay` 의 좌우 반전(`-8px 0 30px`). 여닫기는 `translateX(100%)` ↔ 0 + 투명도, `--transition-move`/`--transition-fast`, `@starting-style` — 겹침 사이드바 규칙의 거울. 움직임 줄이기는 `usePresence` 가 0ms 로
- 뒤 막: `.app-body` 전체, 투명, 층위 34
- 머리 줄: 위 여백 `calc(env(safe-area-inset-top, 0px) + 8px)`, 높이 44px — 숨은 알약 줄과 같은 높이에 온다. 오른쪽에 `목차 닫기`(터치 44×44)
- **패널이 열린 동안 상단 알약 둘·아바타·하단 알약을 모두 숨긴다**: `.app-shell:has(.outline-panel[data-state='open'])` 아래의 `.topbar-pill`(`.phone-nav` 도 이 클래스를 가져 함께 걸린다)·`.topbar .peer-avatars` 에 `opacity: 0; visibility: hidden`, 전환 `--transition-fast`(F-2085 5.3·F-2086 5.1 과 같은 방식)
  - 이유: 85% 패널은 390 에서 x 58.5 부터라 왼쪽 알약(x 8~90)과 31.5px 겹치고, 오른쪽 알약(x 300~382)은 통째로 패널 머리 위에 뜬다(근거 절 실측). 하단 알약(x 118~272)도 패널 위에 뜬다. 패널이 열린 동안 알약의 동작(사이드바·홈·보기 모드·⋯·뒤로·찾기·팔레트)은 쓸 일이 없고, 그 자리 탭은 뒤 막·패널이 받는다
  - 사이드바 열림 때와 다른 점: 사이드바는 ☰ 가 닫기 버튼이라 왼쪽 알약을 남겼다. 목차 패널은 알약 안에 여닫기 버튼이 없어 머리 줄에 `목차 닫기` 를 둔다
  - F-2086 5.1 숨김 표에 한 줄 더하는 것과 같다(11장)
- 패널 안 목록 아래 여백 `env(safe-area-inset-bottom, 0px)` — 마지막 항목이 홈 표시줄에 가리지 않게

## 7. 휴대폰 폭 목차 카드 경로 제거 (반드시 결론 7)

- 앱 화면 ≤600px 에서 `.outline-popup`(버튼·카드)이 DOM 에 없다(3.3). 따라서 다음 CSS 두 규칙은 걸릴 대상이 없어진다 — **삭제**:
  - `.app-shell .outline-popup > .outline-btn { display: none }`(F-2083 4.6, "휴대폰 폭 — 상단바는 떠 있는 알약" 블록)

### Q1. 시작 영역 — **결정: 어디서든 왼쪽 밀기 (사용자 선택, 정해진 것 5)**
- 명세 초안 기본값은 "오른쪽 끝 80px" 였다(안드로이드 뒤로 가기 띠 최대 40dp 안쪽에 40px 를 남기려고). 사용자가 왼쪽 사이드바와 대칭인 Obsidian 방식을 골랐다
- 결과: `OUTLINE_EDGE_PX`·`viewportWidth` 입력이 없다(3.2). OS 가장자리 제스처는 앱이 가로채인 터치를 판정하지 않는 것으로만 대응한다(4.3). 본문 위 왼쪽 밀기가 모두 목차를 여는 만큼 가로 스크롤·선택 예외(4.2)가 중요해진다 — H5 에서 본다

### Q2. 항목을 누르면 닫을까 — **결정: 닫는다 (기본값, 5.2)**
- 이유: 패널이 본문 85% 를 가려 이동한 자리를 볼 수 없다. F-229 카드도 닫았다
- 다른 쪽(열어 둔다): 5.2 첫 줄이 "패널 유지", E1 4번 기대가 "패널 열린 채·본문 스크롤만 확인" 으로 바뀐다. 이동 결과를 보려면 사용자가 매번 닫아야 한다

### Q3. 알약 처리 — **결정: 모두 숨기고 패널 머리에 `목차 닫기` (기본값, 6.2)**
- 이유: 실측상 왼쪽·오른쪽·하단 알약 모두 패널과 겹친다. 머리 줄이 알약 줄 자리에 와 화면 위가 비지 않는다
- 다른 쪽(사이드바처럼 알약을 남기고 패널에 `padding-top: var(--float-cover)`): 왼쪽 알약이 패널 왼쪽 끝과 31.5px 겹치는 문제를 따로 풀어야 하고(패널 폭 줄이기 등), 닫기 버튼 자리가 알약 아래로 내려간다. 8장 `목차 닫기` 는 남긴다(밀기 없이 닫을 방법이 필요)

### Q4. 제목 없는 문서에서 밀었을 때 — **결정: 아무 일 없음 (기본값, 3.1)**
- 이유: ⋯ 판 `목차` 행도 제목이 없으면 빠진다(F-2083 4.6), ia.md 3.23 "빈 상태에는 없다"

- 이유: 왼쪽 겹침 사이드바(tweak 2026-09-29)와 짝. 긴 제목이 말줄임 없이 더 보인다
