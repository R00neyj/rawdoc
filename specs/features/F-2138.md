# F-2138 칸반 보드 보기

작성일: 2026-10-14
상태: 개요, 승인 대기. 마크다운 원문을 그대로 둔 채 `##` 칸·`-` 카드를 보드로 보고 고치고 옮긴다. 화면·클라이언트 일이라 `F-2NNN`. 구현 단위는 7장 자식 다섯. 새 의존성 없음. 열린 질문 Q1~Q5 는 사용자가 정했다(2026-10-14, 8장)

## 정해진 것 (사용자 2026-10-14, 바꾸지 않는다)
1. 사용자 흐름 [`specs/wireframes/kanban-create-flow.html`](../wireframes/kanban-create-flow.html), 보드 동작 [`specs/wireframes/kanban-list.html`](../wireframes/kanban-list.html)(끌어 옮기기. 프로토타입의 `원문 + 보드` 는 8장 Q2 로 뺐다)
2. 원문 형식: `## 제목` = 칸, 그 아래 최상위 `- 항목`(`- [ ]`·`- [x]`) = 카드, 들여쓴 하위 줄 = 카드 설명. 카드를 옮기면 그 줄 묶음만 자리를 옮기고 나머지 바이트는 그대로. 표 방식은 기각
3. 보드로 보는 문서 = 프론트매터 `kanban: true`. 다시 열어도 보드
4. 진입점: 폴더 `⋯`·우클릭 메뉴 `새 칸반 보드`, 팔레트 `새 칸반 보드`·`보드로 보기`, 내장 템플릿 `칸반`. 사이드바 `새 문서` 버튼은 그대로(8장 Q3)
5. 새 보드 원문: `kanban: true` 프론트매터 + `# 제목 없는 보드` + `## 할 일`·`## 진행 중`·`## 완료`

## 근거 (2026-10-14 HEAD, 이름으로 찾는다)
- 보기 모드 `viewMode`(`live`·`raw`·`view`)는 앱 전체 하나이고 `md.viewMode` 로 기억한다(`App.tsx` `changeViewMode`). 문서마다 다른 "보드" 를 넣을 자리가 아니다
- `DocumentArea.tsx` 는 `보기` 에서 `.editor-slot` 을 `hidden` 으로만 숨긴다 — 편집기·`Y.Doc`·원격 게이트·실행 취소가 산 채로 다른 화면을 띄우는 선례
- `remoteGate.ts` `connectRemote` 가 조합 판정에 표 칸·프론트매터 하위 편집기를 더한다 — 편집기 밖 입력칸도 같은 자리에 끼울 수 있다
- 실측: 줄 단위 읽기 968KB·카드 2만 개 4.4ms(F-2139 근거) — 변경마다 다시 읽는다

## 1. 결정 — 보드를 어디에 그리나
- **별도 React 화면 `KanbanBoard`** 를 `DocumentArea` 의 편집기 자리에 그린다. 편집기는 숨긴 채 마운트로 둔다. 네 번째 보기 모드가 아니다(문서별이고 기억하지 않는다). CM6 위젯도 아니다 — 문서 전체를 덮는 블록 위젯 안 입력칸은 표 칸 하위 편집기만큼의 보류·따라잡기 장치가 새로 들고, 가로 스크롤이 `lineWrapping` 과 겹친다
- **불변식**: 보드는 원문 사본을 갖지 않는다 — `view.state.doc` 를 읽고(F-2139 칸·카드 위치 배열만 둔다) 쓰기는 `view.dispatch` 한 길(F-2141 `applyKanban`) → `y-codemirror` → 편집기 `Y.Text`(실시간이면 게이트 → 방 Doc). 그리기는 원문을 바꾸지 않는다. 읽기 전용 문서는 쓰지 않는다. 보드 입력칸 조합 중에는 원격 업데이트를 묶어 두고 `compositionend` 에 푼다(`boardComposition.ts`, F-2141). 보드는 문서 변경마다 다시 읽어 따라잡기가 따로 없다
- 변경 하나 = 트랜잭션 하나 = 되돌리기 한 단계(`userEvent` `kanban.*` 는 `nextUndoGroup` 이 잇지 않는다)

## 2. 원문 규칙 (계약은 F-2139)
- `kanban: true`: 프론트매터 안 맨 앞 칸 `kanban: true` 줄(대소문자 무시). 중첩 프론트매터라도 그 줄만 본다
- 칸 = `##` 제목부터 다음 `#`·`##` 제목 앞까지. 카드 = 칸 안 맨 앞 `-`·`*`·`+` 목록 줄 + 들여쓴 하위 줄. 펜스 코드 안은 아무것도 아니다
- **규칙에서 벗어난 원문**: 칸 안 문단·번호 목록·`###`·인용·표·들여쓰지 않은 펜스 → 카드가 아니고 그 칸 아래 `카드가 아닌 줄 {N}개` 버튼(누르면 원문, 그 줄로). 첫 `##` 앞과 `#` 제목 뒤 내용(`# 제목 없는 보드` 포함)은 보드에 안 나온다. 칸 0개면 빈 보드 안내
- 고치기는 그 줄 범위만 바꾼다. CRLF 는 편집기가 LF 로 들고 저장 때 되돌려(`lineEnding.ts`) 함수는 LF 만 본다. 빈 칸·마지막 카드·문서 끝 줄바꿈 없음은 F-2139 4장

## 3. 보기 (문서별, 기억하지 않음)
- `보드`·`원문` 둘. 칸반 문서를 열면 늘 `보드`, 아니면 `원문`(= 지금 문서 화면과 같다). 원문에서 `kanban: true` 를 지우면 `원문`, 치는 중에 생기면 바뀌지 않고 세그먼트만 나타난다
- 상단바: 넓은 창은 보기 모드 세그먼트 왼쪽에 보드 세그먼트, 휴대폰은 보기 모드 메뉴 맨 위 `보드`. 보드에서 `편집`·`원문`·`보기` 를 고르면 문서 화면 + 그 모드
- 보드에서는 서식 바·댓글·목차·위키링크 미리보기가 없다. 공유 화면·공개 보기·인쇄·내보내기는 지금처럼 마크다운이다

## 4. 휴대폰 폭(≤600px)
칸 하나가 화면 폭 85%(최대 320px), 가로 스냅 스크롤로 한 칸씩, 다음 칸 끝이 보인다. 카드는 400ms 길게 눌러 집고 화면 가장자리로 끌면 옆 칸으로 넘어간다. 끄는 동안 사이드바·오른쪽 패널 밀기는 꺼진다. 키보드 대안 `Alt+방향키`(F-2142)

## 8. 확정한 결정 (사용자 2026-10-14)
- **Q1** 템플릿 `칸반` 은 다른 템플릿처럼 지금 문서 커서 자리에 넣고(`kanban: true` 는 프론트매터 합치기로 붙는다) 보드로 바꾼다
- **Q2** `원문 + 보드` 나란히 보기는 하지 않는다. 보기는 `보드`·`원문` 둘. `specs/product.md` Q3 와 부딪칠 일이 없다
- **Q3** 사이드바 `새 문서` 버튼은 그대로. 옵시디언 폴더 우클릭 메뉴처럼 폴더 `⋯`·우클릭 메뉴 `새 문서`·`하위 폴더` 바로 아래에 `새 칸반 보드`. 사이드바 빈 자리 우클릭 메뉴는 지금 없어(`Sidebar.tsx` 에 `.sidebar-scroll`·`tree-root-drop` 의 `onContextMenu` 없음) 새로 만들지 않고, 최상위는 팔레트 `새 칸반 보드` 가 맡는다
- **Q4** 기본 원문의 `# 제목 없는 보드` 는 정해진 대로 둔다. 문서 제목(메타)도 `제목 없는 보드` 이고 둘은 따로 논다. 보드는 `#` 줄을 그리지 않아 화면엔 제목 하나
- **Q5** `보드로 보기` 는 `##` 칸이 하나라도 있으면 된다(빈 칸 보드도 정상 보드). 흐름 그림 마름모 "`##` 아래 목록이 있나" 보다 넓다
