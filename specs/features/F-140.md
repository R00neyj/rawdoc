## 2. 현재 문제 (코드 읽기, 실측으로 확정할 것)
- `.md-table-widget` 은 편집 영역 전체 폭 블록이고 `table` 은 `width: max-content` 라 표가 좁으면 오른쪽이 빈다. 버튼은 표가 아니라 이 블록 기준으로 놓여(`right: -10px`, `left: 50%`) 열 추가 버튼이 표 끝에서 멀리 떨어진다
- 열 추가 버튼의 `right: -10px` 와 툴팁(`left: calc(100% + 6px)`, 투명이어도 자리를 차지함)이 편집 영역 밖으로 튀어나가 문서 스크롤 영역에 가로 스크롤이 생긴다
- 칸은 `textContent = cell.text` 로 원문을 그대로 넣는다 (F-125 2.1 옛 규칙)

## 3. 요구사항

### 3.1 행·열 추가 버튼 위치 (F-125 2.4 수정)
- 버튼 위치의 기준은 **표(`table`) 테두리**다
  - 열 추가: 표 오른쪽 테두리의 세로 가운데. 버튼 가운데가 테두리 위에 온다
  - 행 추가: 표 아래 테두리의 가로 가운데
  - 표가 편집 영역보다 넓어 가로 스크롤 중이면: 열 추가는 **보이는 스크롤 영역**의 오른쪽 끝, 행 추가는 보이는 스크롤 영역의 가로 가운데. 가로 스크롤해도 버튼이 화면에서 사라지지 않는다
- 툴팁: 행 추가는 버튼 아래(지금과 같음), **열 추가는 버튼 위**(가운데 정렬). 문구·색·크기는 F-125 2.4 그대로
  - 가운데 정렬로 편집 영역 밖으로 나가게 되면 툴팁 오른쪽 끝을 버튼 오른쪽 끝에 맞춘다. 툴팁 여유를 위해 버튼을 테두리·스크롤 영역 끝에서 안쪽으로 옮기지 않는다 (2026-09-14 구현 검토)
- 버튼·툴팁은 보이든 숨었든 **문서 스크롤 영역(`.cm-scroller`)에 가로 스크롤을 만들지 않는다**. 필요하면 위젯 안쪽에 버튼 자리 여백을 둔다
- 위젯 높이 규칙은 그대로: 최상위 요소 세로 `margin` 금지, `ResizeObserver` → `requestMeasure` (F-124 3.4)
- 호버·키보드 포커스로 보이는 규칙, 클릭 동작, 원문 규칙은 그대로

### 3.2 칸 인라인 표시 (F-125 2.1 수정)
- **편집 중이 아닌 칸**은 인라인 서식을 적용해 보여준다. 기호는 숨긴다(표시만. 원문은 바뀌지 않는다). 편집 중인 칸은 지금처럼 하위 에디터에 원문
- 대상과 표시

| 원문 | 표시 | 클래스 (편집 모드 인라인 프리뷰와 같음) |
| --- | --- | --- |
| `**a**` `__a__` | a 굵게 | `md-strong` |
| `*a*` `_a_` | a 기울임 | `md-em` |
| `~~a~~` | a 취소선 | `md-strike` |
| `` `a` `` | a 인라인코드. 안쪽 서식 기호는 글자 그대로 | `md-code` |
| `[글자](주소)` | 글자. `title` 에 주소 | `md-link` |
| 맨 URL, `<https://…>` | 주소 글자 | `md-link` |
| `[[대상]]` `[[대상\|별칭]]` | 대상 또는 별칭 (있음/없음 구분 없음) | `md-wikilink` |
| `\*` `\|` 등 역슬래시 이스케이프 | 뒤 글자만 | — |

- 서식은 겹칠 수 있다 (`**a *b***` → 굵게 안 기울임)
- 위 표에 없는 것은 **원문 글자 그대로**: 이미지 `![a](b)`, HTML 태그, 닫히지 않은 기호(`**a`), 칸 맨 앞 블록 기호(`# a`, `- a`, `> a`, `1. a`)
- 칸 안 링크·위키링크를 누르면 **열지 않고** 칸 편집을 시작한다 (지금 칸 클릭과 같음)
- 보안: 칸 DOM 은 `createElement`·`textContent` 로만 만든다. 칸 글자를 `innerHTML` 로 넣지 않는다
- 칸이 다시 그려지는 모든 경로에 적용한다: 처음 그리기(`buildCell`), 구조가 같을 때 글자만 갱신(`updateDOM` patch), 편집 끝(`endEdit`). patch 경로의 "바뀌었는지" 비교는 표시 글자가 아니라 **칸 원문**으로 한다
- `cellInline.js`: `parseCellInline(text) → [{ text, marks: ('strong'|'em'|'strike'|'code'|'link'|'wikilink')[], title? }]`
  - 해석은 주 에디터와 같은 파서 규칙(`markdownLanguage`, GFM)의 인라인 해석을 쓴다. `@lezer/markdown` `MarkdownParser.parseInline` 이 설치 버전에 있으면 그것을 쓴다. 위키링크는 `src/lib/wikiLink.js` 규칙을 쓰고 인라인코드 안에서는 찾지 않는다
  - 설치 버전으로 위 방식이 안 되면 대안을 만들지 말고 멈추고 보고한다
- 칸 안 서식 CSS 가 편집 모드 본문과 다르게 보이면(선택자가 `.cm-line` 한정 등) `preview.css` 에 표 칸 한정 규칙을 더한다. 색은 기존 토큰만 쓴다 (hex 금지)
- 보기 모드는 바꾸지 않는다

### 3.3 편집 중인 칸 강조와 입력 지점 (2026-09-14 추가)

- 2026-09-14 F-164: 단일 칸 편집 강조는 보이지 않게 한다 (사용자 요청 "표 포커스로 들어간 파란색 굳이?"). 강조 요소는 F-165 칸 범위 선택 표시에 다시 쓴다. 아래 여백·입력 지점 규칙은 그대로
- 근거: 사용자 확인 "표 내부 수정 시 하이라이트 패딩값 너무 큰거같음. 값 조금 줄이고, 트랜지션 .1s 정도로 부드럽게 움직여야겠음. 입력지점이 확 움직여서 어지러울수 있을거같음"
- 현재(코드 읽기): `preview.css` 가 편집 중인 칸 여백 `6px 13px` 을 `.cm-content` 와 `.cm-line` **둘 다**에 줘서 실제 여백이 두 배다. 편집을 시작하면 칸이 커지고 글자·입력 지점이 옮겨간다. 편집 칸에 보이는 강조(현재 줄 바탕 등 무엇인지 실측으로 확인)도 그만큼 크다
- 수정
  - 편집 시작·끝에서 칸 글자 위치와 칸 크기가 바뀌지 않는다. 하위 에디터 안 여백 합계 = 칸 기본 여백(`6px 13px`)
  - 편집 중인 칸 강조는 **칸 테두리 안쪽**에만 그린다. 강조 사각형이 칸 경계를 넘거나 글자 주변에 따로 여백을 두지 않는다. 색은 기존 토큰(`--accent-soft`, `--accent-ring` 등)
  - 강조는 표 위젯 안 **요소 하나**가 편집 중인 칸 위치로 옮겨 다니게 한다. 다른 칸으로 옮길 때(Tab·Enter·방향키·클릭) 위치·크기가 `100ms` 전환으로 부드럽게 움직인다. 칸 안 글자가 늘어 칸 크기가 바뀌어도 따라간다
  - 강조 요소는 마우스 입력을 막지 않고(`pointer-events: none`), 표 가로 스크롤을 따라 움직이고, 위젯 높이 규칙(F-124 3.4)을 깨지 않는다
  - 편집이 끝나면 강조를 숨긴다. `prefers-reduced-motion` 이면 전환 없음(`--transition-fast` 처럼 0)
  - 하위 에디터 안의 현재 줄 바탕 등 앱 전역 CM6 규칙이 칸 안에 겹쳐 그려지면 칸 안에서는 끈다

### 3.4 빈 칸 높이 (2026-09-14 추가)
- 근거: 사용자 요청 "표에 min-height로 내용없어도 한줄높이 보장"
- 모든 칸이 비어 있는 행(예: 행 추가 직후 `|  |  |`)도 글자 한 줄이 든 행과 높이가 같다. 편집 중인 빈 칸도 같다
- `td`·`th` 는 `min-height` 가 먹지 않으므로 방법은 구현에서 정한다 (예: 칸 `height` 를 한 줄 높이 + 위아래 여백으로 주기 — 표 칸의 `height` 는 최소 높이로 동작). 칸 여백·글자 위치(3.3)는 바꾸지 않는다
- 편집 모드 표 위젯에만 적용한다. 보기 모드는 바꾸지 않는다

### 3.5 마지막 행에서 Enter 로 행 추가 (F-125 2.3 수정, 2026-09-14 추가)
- 근거: 사용자 요청 "표에서 엔터키로 밑에줄 표 확장가능하게"
- 칸 편집 중 **마지막 행**에서 Enter
  - 그 행에 글자가 있는 칸이 하나라도 있으면: 표 끝에 행을 추가하고(원문 규칙은 F-125 2.4 행 추가와 같음) 새 행의 **같은 열** 칸 편집을 시작한다
  - 그 행의 칸이 모두 비어 있으면: 행을 추가하지 않고 지금처럼 편집을 끝내고 표 다음 줄 시작으로 주 에디터 커서 (빈 행은 지우지 않는다)
- 마지막 행이 아니면 지금처럼 아래 행 같은 열 칸
- 표에서 빠져나가기는 그대로: Esc, 마지막 행에서 ↓
- 한글 조합 중 Enter 는 가로채지 않는다 (F-125 2.3 그대로). 행 추가는 실행 취소 한 번에 되돌아간다
