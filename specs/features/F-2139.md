# F-2139 칸반 원문 읽기와 변경 함수

작성일: 2026-10-14
상태: 승인 대기. 개요 F-2138 2장 원문 규칙의 순수 함수 계약. 화면 없음, 단위 테스트만. 구현 담당 `feature-implementer`. `App.tsx` 변경 없음

## 근거 (2026-10-14 HEAD, 이름으로 찾는다)
- 편집기 원문은 늘 LF 다 — `createYBinding` 이 `toEditorText` 로 씨앗을 심고 CM6 가 `\r\n` 을 `\n` 으로 읽는다. CRLF 는 저장 때 `fromEditorText` 가 되돌린다(`src/lib/lineEnding.ts`). 그래서 이 함수들은 LF 만 받고 위치는 CM6 위치와 같다
- `src/lib/frontmatter.ts` `findFrontmatter` 가 맨 앞 `---` 범위를 준다. `parseSimpleProperties` 는 중첩이 있으면 `null` 이라 `kanban` 판정에 쓰지 않는다
- 실측(Bun, 줄 단위 한 번 훑기 시제품): 카드 200개·9KB 0.09ms, 2,000개·95KB 0.51ms, 20,000개·968KB 4.4ms — 변경마다 다시 읽어도 된다

## 2. 계약
```ts
export const KANBAN_NEW_DOC_TEXT = '---\nkanban: true\n---\n# 제목 없는 보드\n\n## 할 일\n\n## 진행 중\n\n## 완료' // 끝 줄바꿈 없음
export const NEW_LANE_TITLE = '새 칸'
export type KanbanCard = {
  from: number; to: number            // 카드 줄 시작 ~ 묶음 마지막 줄 끝(줄바꿈 앞)
  textFrom: number; textTo: number     // 표지·체크 뒤 ~ 줄 끝
  text: string
  done: boolean | null                 // `[ ]` false, `[x]`·`[X]` true, 체크 없음 null
  checkAt: number | null               // 체크 칸 안 글자 위치
  detail: string[]                     // 하위 줄, 공통 들여쓰기만 뗀 원문
}
export type KanbanLane = { title: string; headingFrom: number; titleFrom: number; titleTo: number; to: number; cards: KanbanCard[]; strayLines: number[] }
export type KanbanChange = { from: number; to?: number; insert?: string } // CM6 ChangeSpec 모양, 바뀌기 전 좌표, 겹치지 않음
export function isKanbanDoc(text: string): boolean
export function parseKanban(text: string): KanbanLane[]
export function kanbanFlagChange(text: string): KanbanChange
export function moveCardChanges(text: string, from: { lane: number; card: number }, to: { lane: number; index: number }): KanbanChange[] | null
export function addCardChange(text: string, lane: number, cardText: string): KanbanChange | null
export function addLaneChange(text: string, title: string): KanbanChange
export function renameLaneChange(text: string, lane: number, title: string): KanbanChange | null
export function editCardChange(text: string, cardFrom: number, cardText: string): KanbanChange | null
export function toggleCardChange(text: string, cardFrom: number): KanbanChange | null
```
- `strayLines`: 칸 안 규칙 밖 줄의 1부터 세는 줄 번호. `lane.to` 는 다음 `#`·`##` 제목 줄 시작 또는 문서 끝
- `to.index` 는 **옮길 카드를 뺀 뒤** 대상 칸 목록에서의 자리(0~길이). 같은 칸 같은 자리면 `null`

## 3. 읽기 규칙 (위에서부터 먼저 걸리는 것)
1. `isKanbanDoc`: `findFrontmatter` 가 있고 그 안에 `/^kanban:[ \t]*true[ \t]*$/i` 줄이 있다. 프론트매터 밖 줄은 보지 않는다
2. 프론트매터 범위는 건너뛴다
3. 펜스: 앞 공백 0~3칸 뒤 백틱 3개 이상 또는 물결 3개 이상으로 연다(`markdown-it` 펜스와 같다). 같은 글자·같거나 긴 길이·뒤에 공백뿐인 줄로 닫는다. 펜스 안 줄은 제목도 카드도 아니다. 들여쓰지 않은 펜스는 지금 카드를 끝내고 그 줄들은 규칙 밖, 열린 카드 아래 들여쓴 펜스는 닫힐 때까지 그 카드 하위 줄
4. `##` 뒤 공백 또는 줄 끝 = 새 칸. 이름은 앞뒤 공백과 닫는 `#` 열을 뗀 글자(`titleFrom`~`titleTo`), 빈 이름 허용
5. `#` 한 개 제목 = 지금 칸을 끝낸다. 다음 `##` 까지는 어느 칸에도 속하지 않는다(보드에 안 나옴). 첫 `##` 앞도 같다
6. 칸 안 `/^[-*+]([ \t]+|$)/` = 카드. 바로 뒤 `[ ]`·`[x]`·`[X]` + 공백이면 체크 카드
7. 카드 뒤 공백·탭으로 시작하는 줄 = 하위 줄. 빈 줄은 뒤에 하위 줄이 이어질 때만 묶음에 든다(묶음 끝 빈 줄은 안 든다)
8. 칸 안 그 밖의 비지 않은 줄(문단·`1.` 목록·`###` 제목·인용·HTML·표) = 규칙 밖. 지금 카드를 끝내고 `strayLines` 에 넣는다

## 4. 변경 규칙 — 손대는 바이트는 아래뿐이다
- **묶음**: 카드 줄부터 `to` 까지 + 그 줄바꿈. 문서 끝 카드라 줄바꿈이 없으면 앞 줄바꿈을 함께 지우고, 넣을 때 끝에 `\n` 을 붙인다
- **넣을 자리 p**: `index` 가 길이보다 작으면 그 카드 `from`, 아니면 마지막 카드 `to` 다음 줄 시작. 빈 칸이면 제목 다음 줄 시작, 그 줄이 칸 안 빈 줄이면 그다음 줄 시작
- p 가 문서 끝이고 문서가 줄바꿈 없이 끝나면 `\n` + 묶음(끝 `\n` 뺌)을 넣는다. 그 마지막 줄이 빈 칸의 제목이면 `\n\n` 을 앞에 둔다
- `moveCardChanges`: 지우기 하나 + 넣기 하나. 다른 줄 바이트·순서는 그대로
- `addCardChange`: p(index = 길이)에 `- {글자}\n`. 앞뒤 공백을 떼고 비면 `null`
- `addLaneChange`: 문서 끝에. 앞 내용과 빈 줄 하나로 떼고(`\n` 0~2개) `## {이름}`. 문서가 줄바꿈으로 끝났으면 뒤에도 하나 붙여 끝 모양을 지킨다
- `renameLaneChange`: `titleFrom`~`titleTo` 만 바꾼다. 비거나 같으면 `null`
- `editCardChange`: `textFrom`~`textTo` 만. 비거나 같으면 `null`. `cardFrom` 에 카드가 없으면 `null`
- `toggleCardChange`: `checkAt` 한 글자를 ` `↔`x`. 체크 카드가 아니면 `null`
- `kanbanFlagChange`: 프론트매터가 없으면 맨 앞에 `---\nkanban: true\n---\n`. 있으면 `kanban:` 줄 값만 `true` 로, 그 줄이 없으면 닫는 줄 앞에 `kanban: true\n`

| U1 | `isKanbanDoc` 참: `kanban: true`·`kanban: True`·뒤 공백·중첩 키가 섞인 프론트매터 안 그 줄 / 거짓: `kanban: false`·`kanban: "true"`·들여쓴 `  kanban: true`·본문에만 있음·닫는 줄 없는 프론트매터 | 단위 |
| U2 | `kanban-list.html` 의 `initial` 원문 → 칸 3, 카드 2·1·2, 첫 카드 `detail` `['- 제목 + 목록 방식']`, 완료 칸 `done` 참 둘 | 단위 |
| U3 | 펜스 안 `## x`·`- y` 는 칸·카드가 아니다. 카드 아래 들여쓴 펜스는 하위 줄, 칸 안 들여쓰지 않은 펜스는 `strayLines`. 물결(`~~~`) 펜스는 백틱 세 개 줄로 닫히지 않는다 | 단위 |
| U4 | 문단·`1.`·`###`·`>` 줄이 `strayLines` 에 줄 번호로, `#` 제목 뒤 `- z` 는 어느 칸에도 없다 | 단위 |
| U5 | `moveCardChanges` 를 `ChangeSet.of(…).apply` 한 결과가 기대 문자열과 같다: 같은 칸 위·아래, 다른 칸 가운데·끝, 빈 칸(빈 줄 있음·없음), 문서 끝 줄바꿈 없는 카드에서·로, 하위 줄 있는 카드. 매번 옮긴 묶음을 뺀 나머지 줄 배열이 전과 같다 | 단위 |
| U6 | CRLF: `fromEditorText(apply(toEditorText(c)), 'crlf')` 가 기대 CRLF 바이트와 같고 `\r` 이 홀로 남지 않는다 | 단위 |
| U7 | `addCardChange`·`addLaneChange`·`renameLaneChange`·`editCardChange`·`toggleCardChange` 4장 결과, 빈 글자·같은 값·없는 자리 → `null`. 닫는 `#` 있는 제목 이름 바꾸기는 닫는 열을 남긴다 | 단위 |
| U8 | `kanbanFlagChange`: 프론트매터 없음·키 없음·`kanban: false`·중첩 프론트매터 네 경우 결과 뒤 `isKanbanDoc` 참, 다른 줄 그대로 | 단위 |
| U9 | `parseKanban(KANBAN_NEW_DOC_TEXT)` → 이름 `할 일`·`진행 중`·`완료`, 카드 0. 여기에 `addCardChange(…, 2, 'a')` → 끝이 `## 완료\n\n- a` | 단위 |
