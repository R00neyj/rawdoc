# F-251 중첩 목록 들여쓰기를 단계마다 고정 폭으로

작성일: 2026-09-18
상태: 사용자 승인 (2026-09-18 "두번째 뎁스가 너무 얕아보임 / 탭크기가 옵시디언이랑 달라서 그런가?" → 선택지 제시 후 "단계마다 고정 폭" 선택)
근거: `specs/features/F-152.md` 2.3(`--md-list-indent` 실측), `F-166.md`(목록 기호 위치·내어쓰기), `F-236.md`(깊이 안내선), `F-154.md` 2.3(`md.indent` 2/4칸), CLAUDE.md 불변조건(decoration 은 표시만 바꾼다)

## 1. 범위

### 문제
중첩 목록의 단계 차이가 눈에 잘 안 띈다. 2026-09-18 실측(`npm run measure`, 편집 모드 1600x900, 기본 설정):

| 항목 | 값 |
| --- | --- |
| 본문 서체 | Pretendard Variable (**가변폭**) |
| 글자 폭(숫자) | 9.01px |
| 공백 폭 | **3.70px** |
| 글머리 기호 x — 1·2·3단계 | 0px / 15px / 30px |

들여쓰기 설정(`md.indent`)은 기본 4칸이고 옵시디언 기본값과 같다. 문제는 칸 수가 아니라 **가변폭 서체에서 공백 하나가 3.7px** 이라 4칸이 15px 밖에 안 되는 것이다. 옵시디언은 원문 공백 수와 무관하게 단계마다 고정 폭(약 2em)을 쓰기 때문에 깊이가 확실히 보인다.

또한 지금은 `2칸` 으로 쓴 문서와 `4칸` 으로 쓴 문서의 깊이가 화면에서 다르게 보인다. 같은 2단계인데 들여쓰기가 7px 과 15px 로 갈린다.

### 한다
- 중첩 단계마다 **고정 폭**으로 들여쓰기를 표시한다. 기본 `2em`(≈32px)
- **원문은 건드리지 않는다.** 공백 2칸으로 썼든 4칸으로 썼든 화면 깊이는 같다 — decoration 으로 표시만 바꾼다(CLAUDE.md 불변조건). `.md` 내보내기·IndexedDB 원문은 그대로다
- 깊이 안내선(F-236)이 새 기호 위치를 따라간다
- 화면 줄바꿈된 둘째 줄의 내어쓰기(F-166)도 새 기호 위치를 기준으로 맞는다
- 보기 모드·공개 링크도 같은 폭으로 보인다
- `Tab`/`Shift+Tab` 이 넣는 **원문 공백 수는 `md.indent` 설정 그대로**다(2칸/4칸). 표시 폭만 고정이다

### 하지 않는다
- 들여쓰기 설정(`md.indent`) 자체의 의미 변경 — 원문에 몇 칸을 쓸지는 그대로 사용자 선택이다
- 표시 폭을 설정 항목으로 노출 — 값은 `2em` 고정으로 두고, 필요하면 나중에 별도 명세
- 원문 모드(`raw`) 변경 — 원문 모드는 지금처럼 실제 글자 그대로 보여준다(F-124 1장, 모양을 바꾸지 않는다)
- 목록이 아닌 줄(들여쓴 코드블록, 인용 안 문단 등)의 들여쓰기 표시 변경
- 서체를 고정폭으로 바꾸기

## 3. 요구사항

### 3.1 단계 판정
- 줄의 중첩 단계는 원문 공백 수가 아니라 **마크다운 구문 트리의 목록 깊이**로 센다(`syntaxTree` 의 `BulletList`/`OrderedList` 조상 수). 공백 2칸·4칸 문서가 같은 깊이로 나와야 한다
- 1단계는 들여쓰기 0, N단계는 `(N-1) × 2em`

### 3.2 편집 모드 (`lines.ts`)
- 지금은 `coordsAtPos` 로 실제 앞 공백 폭을 재서 `--md-list-indent` 에 넣는다. 단계 기반 고정 폭으로 바꾼다
- 기호·내용이 그 위치에서 시작하도록 원문 앞 공백을 화면에서 접거나 늘린다 — **원문 글자를 지우거나 넣지 않는다.** decoration(예: 앞 공백 구간에 폭을 주는 `Decoration.mark`/`replace` + widget)으로 표시만 바꾼다
- 화면 줄바꿈 둘째 줄 내어쓰기(F-166)는 계속 내용 시작 x 에 맞는다
- F-236 안내선은 조상 단계의 **기호 가운데**(F-236 6장)를 따라간다 — 고정 폭이라 좌표 계산이 단순해진다
- 조합 중 재계산 보류·따라잡기 규칙(F-104 2.3)은 그대로다

### 3.3 보기 모드 (`markdown.css`)
- 중첩 `ul`/`ol` 의 `padding-left` 를 지금의 흉내값(0.4625em·0.6875em)에서 `2em` 으로 바꾼다
- F-236 안내선 `left` 도 새 폭에 맞춘다
- 편집 모드와 ±4px 안에서 같아야 한다(F-152 A5 기준)

### 3.4 값
- 고정 폭은 CSS 토큰 하나로 둔다(예: `--md-list-step: 2em`). 코드·CSS 여러 곳에 숫자를 흩어 쓰지 않는다
