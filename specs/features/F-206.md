## 2. 요구사항

### 2.1 D1 스키마
```sql
CREATE TABLE folders (
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,
  parent_id TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE TABLE docs (
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL REFERENCES users(id),
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  line_ending TEXT NOT NULL CHECK (line_ending IN ('crlf','lf')),
  folder_id TEXT,
  pinned_at INTEGER,
  version INTEGER NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX docs_owner_updated ON docs(owner_id, updated_at DESC);
CREATE INDEX folders_owner ON folders(owner_id);
```

### 2.2 규칙
- 모든 라우트 `requireUser`. **다른 사람 소유는 404** (존재 여부를 알리지 않는다)
- 응답 JSON 필드는 앱 `Doc`·`Folder` 모양(camelCase) + 문서 `version`
- `id` 는 클라이언트가 보낼 수 있다(오프라인 생성·F-208 이관). UUID 형식만. 생략하면 서버가 만든다
- **원문 보존**: `content` 는 받은 문자열 그대로 저장·반환. 줄바꿈·공백·BOM 을 손대지 않는다. SQL 은 전부 바인딩 파라미터
- **문서 크기 상한 (Q6)**: `content` UTF-8 1,000,000바이트 이하. 넘으면 `413 {"error":"too_large","limit":1000000}`. 요청 본문 전체는 1,100,000바이트 이하 (넘으면 읽기 전에 413)
- `title` 500자 이하, 폴더 `name` 200자 이하. 형식 오류는 `400 {"error":"invalid","field":"..."}`

### 2.3 문서
| 요청 | 동작 |
| --- | --- |
| `GET /api/docs` | 내 문서 목록, `content` 제외, `updatedAt` 내림차순 |
| `GET /api/docs/:id` | 문서 전체 |
| `POST /api/docs` `{id?, title, content, lineEnding, folderId?}` | `201` 새 문서, `version: 1`. 같은 `id` 가 이미 **내 문서**면 만들지 않고 `200` 기존 문서 (재시도 안전). 남의 문서 id 면 `409 {"error":"id_taken"}` |
| `PUT /api/docs/:id` `{title?, content?, baseVersion}` | `baseVersion === version` 이면 반영, `version + 1`, `updatedAt` 갱신 → `200`. 다르면 바꾸지 않고 `409 {"error":"conflict","doc":{서버 문서 전체}}` |
| `PUT /api/docs/:id/folder` `{folderId}` | 폴더 이동. `version`·`updatedAt` 유지 (M1 `moveDoc` 과 같음). 없는 폴더면 400 |
| `PUT /api/docs/:id/pin` `{pinned}` | `pinnedAt` 지금 / null. `version`·`updatedAt` 유지 |
| `DELETE /api/docs/:id` | `204` (영구 삭제, M1 과 같음) |

- 조건부 갱신은 한 문장으로: `UPDATE docs SET ... WHERE id=? AND owner_id=? AND version=?` 후 변경 행 수로 판정

### 2.4 폴더
| 요청 | 동작 |
| --- | --- |
| `GET /api/folders` | 내 폴더 전부 |
| `POST /api/folders` `{id?, name, parentId?}` | `201`. 깊이 2단계 초과면 400 (`canCreateFolder`) |
| `PUT /api/folders/:id` `{name?, parentId?}` | 이름·이동. 이동은 `canMoveFolder` |
| `DELETE /api/folders/:id` | 안의 문서 `folder_id`·하위 폴더 `parent_id` 를 지운 폴더의 `parent_id` 로 바꾸고 삭제 (M1 `removeFolder` 와 같음). `env.DB.batch` 로 한 번에 |
