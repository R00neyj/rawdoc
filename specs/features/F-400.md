## 1. 범위 — 무엇을 지키고 무엇은 지키지 못하나

### 1.1 하는 것

- 사용자가 고른 문서·폴더를 **브라우저 안에서** 암호화해 저장한다. 서버(D1·R2·DO)·기기 캐시(IndexedDB)·운영자 스크립트(`scripts/admin-*.mjs`)가 보는 것은 암호문뿐이다
- 로그인한 계정의 금고(키 묶음이 서버에 있음)와 로그아웃 상태의 로컬 금고(키 묶음이 이 브라우저에만 있음) 두 벌. 화면·암호 규칙은 같다(결정 11)
- 기존 문서·폴더를 금고로 옮기기와 금고에서 빼기(결정 14), 로그인 때 로컬 금고 이관(결정 12)
- 잠김·열림 상태에 따른 사이드바·검색·지도·내보내기 동작(결정 13)

### 1.2 지키는 것과 지키지 못하는 것 (위협 모델)

### 1.3 이번 범위에서 빼는 것

- **실시간 암호 협업, 금고 문서 공유·초대**(결정 5·6 의 2차). 1차 구조는 2차가 문서 단위로 키를 넘길 수 있게 문서마다 키를 둔다(2.2) — 그 이상은 2차 개요가 정한다. 노트의 선행 조사("partyserver `Server` 로 암호문 로그 + 클라이언트 스냅샷 교체")는 2차 몫이다
- **금고 키 교체.** 암호 바꾸기는 금고 키(MK)를 다시 감쌀 뿐 바꾸지 않는다(2.3). 옛 키 묶음 + 옛 암호를 가진 사람은 여전히 연다 — 키를 새로 만들고 모든 문서 키를 다시 감싸는 기능은 하지 않는다
- **CLI 표시 변경.** `/v1` 이 금고 문서를 어떻게 돌려주는지만 정하고(3.6), CLI(npm `rawdoc`) 새 판은 내지 않는다. 옛 CLI 는 금고 문서를 빈 제목으로 보이고, 읽기·쓰기는 `forbidden` 종료 코드 4 로 끝난다
- 금고 문서의 공개 보기·`.md` 해시 공유(F-130)·인쇄 외 내보내기 형식 추가
- Argon2id 등 새 의존성 (10장 Q1)
- 계정 삭제 화면(지금도 없다 — privacy.md 5절)

## 2. 키 — 암호·복구 코드·금고 키·문서 키

### 2.1 키 구조

```
금고 암호 ──PBKDF2-SHA256 (600,000회, 소금 16 B)──► KEK_p ─┐
                                                           ├─ AES-KW 로 감싼 금고 키(MK) 두 벌 = 키 묶음(서버·기기)
복구 코드 ──HKDF-SHA256 (소금 16 B, info "e2ee-recovery-v1")► KEK_r ─┘
금고 키 MK (AES-KW 256, 무작위) ──AES-KW──► 문서 키 DEK (AES-GCM 256, 문서·첨부마다 하나)
문서 키 DEK ──AES-GCM──► 제목·본문 봉투 / 첨부 봉투 (3.2)
```

- **금고 키(MK)는 계정(또는 로컬 금고)마다 하나.** 암호 바꾸기·복구는 MK 를 새 KEK 로 다시 감쌀 뿐이다 — 문서는 건드리지 않는다
- **문서 키(DEK)는 문서마다, 첨부마다 하나.** MK 로 감싸 문서 행·첨부 봉투에 붙인다. 이유 셋:
  1. 로컬 금고 → 계정 금고 이관(결정 12)이 본문을 다시 암호화하지 않고 **DEK 만 다시 감싸면** 된다(문서당 40 B)
  2. 2차 공유가 문서 하나의 DEK 만 넘기면 된다 — MK 를 넘기지 않는다
  3. 비용이 작다 — 문서 1,000개의 DEK 풀기 + 제목 복호화 8.1ms (m6)
- 비교한 다른 안: MK 가 모든 문서를 직접 암호화. 열 한 개(`e2ee_key`)와 풀기 한 단계가 줄지만 이관 때 본문 전체를 다시 암호화해야 하고 2차 공유에서 MK 를 나눠야 한다 — 쓰지 않는다
- **키 값은 메모리 밖으로 나가지 않는다.** 풀린 MK·DEK 는 `extractable: false` 로 가져온다. 예외는 암호 바꾸기·복구·이관처럼 MK 를 다시 감싸는 순간뿐이고, 그때만 `extractable: true` 로 한 번 풀어 감싼 뒤 버린다
- 틀린 암호·복구 코드는 AES-KW 풀기가 `OperationError` 로 던지는 것으로 안다(m7). 검증용 해시를 따로 두지 않는다 — 두면 그 값으로 서버가 암호를 오프라인에서 맞춰 볼 수 있는 표적이 하나 더 생긴다(없어도 감싼 MK 로 똑같이 맞춰 볼 수 있으므로 늘어나는 위험은 없지만, 쓸 데도 없다)

### 2.2 암호에서 키 유도 — PBKDF2 600,000회

| 안 | 이 PC 에서 한 번 푸는 데 | 드는 것 | 판단 |
| --- | --- | --- | --- |
| **PBKDF2-SHA256 600,000회** | 82.9ms (m1) | WebCrypto, 의존성 0 | **채택** — 결정 3 의 "WebCrypto PBKDF2 후보" |
| PBKDF2 1,000,000회 | 136.3ms | 같음 | 느린 PC 값을 재지 못해(m2) 올리지 않는다. 묶음에 반복 수를 적으므로 나중에 올릴 수 있다 |
| Argon2id (메모리 하드 — GPU 로 한꺼번에 맞춰 보기를 어렵게 만드는 방식) | 재지 않음 | `hash-wasm` 11.3KB gzip (노트 조사) — 새 의존성 | 10장 Q1 — 안 쓴다(2026-09-25 사용자) |

- 600,000 은 OWASP 비밀번호 저장 권고(PBKDF2-HMAC-SHA256)의 값으로 알고 있다 — **이 개요를 쓰며 원문을 다시 열어 보지 않았다.** 숫자는 m1 의 시간(0.1초 안쪽)으로 정했고 OWASP 는 참고다
- 반복 수는 키 묶음(2.3)의 `kdf.iterations` 에 적는다. 상수 `E2EE_PBKDF2_ITERATIONS` 가 묶음 값보다 크면, **열기에 성공한 직후** 새 반복 수로 MK 를 다시 감싸 저장한다(계정 금고는 `PUT /api/e2ee/keys`, 로컬은 IndexedDB). 사용자는 아무것도 하지 않는다
- 암호는 **NFC 로 정규화한 UTF-8** 로 넣는다. 한글이 조합형(NFD)으로 붙여 넣어지면 같은 글자가 다른 바이트가 되어 열리지 않는다
- **암호 최소 10자**, 글자 종류 규칙 없음(10장 Q3). 서버가 감싼 MK 를 가지므로 약한 암호는 운영자가 오프라인으로 맞춰 볼 수 있다 — 그래서 최소 길이를 둔다. 틀린 횟수 제한은 둘 수 없다(풀기가 브라우저에서 일어나 서버가 시도를 모른다)

### 2.3 키 묶음 — 계약

서버 `e2ee_keys.bundle`(3.1)·기기 IndexedDB(4.1)에 같은 JSON 을 둔다. 서버는 크기(`E2EE_BUNDLE_MAX_BYTES = 4_096`)만 보고 내용을 해석하지 않는다

```ts
type E2eeKeyBundle = {
  v: 1
  kdf: { name: 'PBKDF2'; hash: 'SHA-256'; iterations: number; salt: string } // salt: base64 16 B
  wrappedByPassword: string                  // base64 — AES-KW(KEK_p, MK), 40 B
  recovery: { salt: string; wrapped: string } // base64 — HKDF 소금 16 B, AES-KW(KEK_r, MK) 40 B
  createdAt: number
}
```

- base64 는 표준 알파벳(`+/`, 패딩 `=`)이다. 봉투(3.2)도 같다
- 계정 금고 묶음은 `rev`(서버가 매기는 정수)와 함께 오간다 — 두 기기가 동시에 암호를 바꾸면 늦은 쪽이 409 를 받는다(3.1)

### 2.4 복구 코드

- **무작위 20 B(160비트)** 를 Crockford base32(숫자·대문자, `I L O U` 없음)로 적은 32자, 4자씩 8묶음을 `-` 로 잇는다. 예 모양: `7K2M-9QXA-…`(8묶음)
- 입력은 대소문자 무시, `-`·공백 무시, `O`→`0`, `I`·`L`→`1` 로 읽는다
- 160비트 무작위라 늘여 뽑기(PBKDF2)가 필요 없다 — HKDF 한 번으로 KEK_r 을 만든다
- **처음 만들 때 한 번만** 보여 준다(결정 3). 화면에서 `복사`·`파일로 저장`(`recovery-code.txt`, 제품명 없음) 을 주고, `복구 코드를 안전한 곳에 보관했습니다` 를 체크해야 금고가 만들어진다
- 복구 코드로 암호를 다시 정하면 **복구 코드도 새로 만들어 한 번 보여 준다**(10장 Q4) — 쓴 코드는 어딘가에 입력·복사된 적이 있어서다
- 로컬 금고와 계정 금고는 복구 코드가 다를 수 있다. 이관(4.4)에서 계정 금고를 로컬 묶음으로 새로 만들면 로컬 복구 코드가 그대로 계정 금고의 코드가 된다

### 2.5 열림·잠김과 자동 잠금 (결정 9)

- 키는 **그 탭의 메모리에만** 있다. 탭을 닫거나 새로고침하면 잠긴다
- **안 쓴 시간**이 설정값을 넘으면 잠근다. "쓴다" = 그 탭 문서에서 `keydown`·`pointerdown`·`wheel`. 타이머 한 개가 아니라 마지막 활동 시각과 지금 시각을 비교한다 — 절전에서 깨어난 탭도 곧바로 잠긴다(`visibilitychange` 에서도 검사)
- 설정 키(계약, localStorage — 기기마다):

| 키 | 값 | 기본 | 명세 |
| --- | --- | --- | --- |
| `md.e2eeLockMinutes` | `5` \| `15` \| `30` \| `60` \| `240` | `30` | F-404 |
| `md.e2eeBackupNotice` | `1` (4.3 백업 안내를 이 기기에서 이미 보았다) | 없음 | F-407 |

  - "잠그지 않음" 선택지는 두지 않는다
- **잠그는 순서** — 바뀌면 편집이 사라지므로 순서 자체가 규칙이다: ① IME 조합 중이면 조합이 끝날 때까지 미룬다(불변조건 "조합 중 보류한 일은 조합이 끝나면 따라잡는다" 와 같은 태도) ② 대기 중인 금고 문서 저장을 **암호화해 캐시에 쓰는 것까지** 끝낸다 ③ 열린 금고 문서의 편집기를 내리고 잠금 해제 패널을 띄운다 ④ 검색·지도 메모리 색인을 비운다(`resetSearchIndexCache`·`resetMapIndexCache`) ⑤ 금고 첨부 `blob:` 주소를 거둔다 ⑥ 키를 버린다
- **잠그기는 모든 탭에 퍼지고, 풀기는 탭마다 한다**(10장 Q2, 2026-09-25 사용자). 한 탭의 `금고 잠그기`·자동 잠금은 기존 탭 채널(`TAB_CHANNEL_NAME`)로 다른 탭에 알린다. 다른 탭에 키를 넘기는 것은 기술적으로 되지만(m8) 하지 않는다 — 결정 9 그대로
- 로그아웃(`account.ts` `logout()`)·계정 바뀜은 잠금과 같다

## 3. 서버 — 저장 형태·크기·첨부·차단

### 3.1 D1 — `docs` 에 열을 더한다 (별도 표를 만들지 않는다)

| 안 | 공유·공개·`/v1`·DO·정리 경로에서 빠뜨리면 | 되는 것 | 드는 것 | 판단 |
| --- | --- | --- | --- | --- |
| **`docs` 에 열 추가 (채택)** | 암호문이 **새지만 평문은 새지 않는다** — 비밀은 거르기가 아니라 암호가 지킨다. 거르기는 정확성(깨진 제목을 안 보이기)과 결정 6 을 위한 것이다 | 만들기·PUT·버전 409·삭제·폴더 삭제·고정·목록·사용량 누계(F-2025)·outbox 가 **그대로** 돈다 | 3.6 표의 자리마다 거르기 한 줄 | 채택 |
| 금고 전용 표 `e2ee_docs` | 애초에 안 보인다 | — | 만들기·PUT·삭제·폴더 삭제(`handleDeleteFolder` 의 batch)·누계 줄(`usage.ts` `docUsageStatements`·`deleteDocUsageStatement`·`deleteFoldersUsageStatement`)·목록을 **한 벌 더** 짜야 한다. 옮기기는 두 표 사이 이동 | 안 씀 |

마이그레이션(계약 — 이름을 바꾸면 F-401~F-409 가 어긋난다). **번호는 F-401 을 쓸 때 `migrations/` 의 다음 빈 번호**다 — 지금은 `0010_usage.sql` 이 마지막이라 `0011` 이 될 것으로 보지만, F-309(잠금 표 삭제)가 먼저 오면 한 칸 밀린다

```sql
ALTER TABLE docs ADD COLUMN e2ee_key TEXT;        -- 금고 문서의 DEK 를 MK 로 감싼 것(base64). NULL 이면 일반 문서
ALTER TABLE docs ADD COLUMN attachment_refs TEXT; -- 금고 문서만. 본문이 쓰는 첨부 id(16진 16자) JSON 배열, 평문 (결정 7)
ALTER TABLE folders ADD COLUMN e2ee INTEGER NOT NULL DEFAULT 0;      -- 금고 폴더
ALTER TABLE attachments ADD COLUMN e2ee INTEGER NOT NULL DEFAULT 0;  -- 암호 첨부
CREATE TABLE e2ee_keys (                           -- 계정 금고 키 묶음, 계정마다 한 줄
  user_id TEXT PRIMARY KEY REFERENCES users(id),
  bundle TEXT NOT NULL,                            -- E2eeKeyBundle JSON (2.3). 서버는 크기만 본다
  rev INTEGER NOT NULL,                            -- 바꿀 때마다 +1. 조건부 UPDATE
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

- 표·열 이름에 제품명이 없다(불변조건). **코드 식별자에 `vault` 를 쓰지 않는다** — `src/app/exportVault.ts`·`importVault.ts`(F-2019·F-2020)가 이미 "옵시디언 볼트" 를 뜻한다. 코드는 `e2ee`, 화면은 `금고`
- `docs.content`·`docs.title` 은 금고 문서에서 **봉투의 base64 문자열**이다(3.2). 열 모양은 그대로 `TEXT`
- `line_ending`·`folder_id`·`pinned_at`·`version`·`created_at`·`updated_at` 은 평문 그대로(결정 2)

### 3.2 봉투 — 계약

| 무엇 | 바이트 | 저장 |
| --- | --- | --- |
| 제목·본문 봉투 | `0x01` ‖ IV 12 B ‖ AES-GCM 암호문 + 태그 16 B | base64 문자열로 `docs.title`·`docs.content` |
| 추가 인증 데이터(AAD — 암호문과 함께 검사되는 평문 꼬리표) | 제목 `"{docId}:title"`, 본문 `"{docId}:content"` (UTF-8) | 없음 — 복호화할 때 다시 만든다 |
| 감싼 문서 키 | `0x01` ‖ AES-KW(MK, DEK) 40 B | base64 56자로 `docs.e2ee_key` |
| 첨부 봉투 | `0x01` ‖ AES-KW(MK, 첨부 DEK) 40 B ‖ IV 12 B ‖ 암호문 + 태그 16 B, AAD `"att:{attachmentId}"` | **바이너리 그대로** R2 `att/{owner}/{id}.{ext}` |

- AAD 에 문서 id 를 넣는 이유: 서버가 한 문서의 제목 암호문을 본문 자리에 넣거나 다른 문서의 행과 바꿔치기하면 복호화가 실패한다. 그래서 **충돌 사본·옮기기처럼 id 가 바뀌는 곳은 다시 암호화**한다(3.4)
- 본문 평문은 **저장되는 문자열**(`fromEditorText` 로 `lineEnding` 을 이은 것)이다. 복호화한 값은 지금의 `Doc.content` 와 같은 모양이다 — 원문 바이트 보존(6장)이 그대로다
- 첨부 봉투에 감싼 키를 함께 넣는 이유: 첨부는 여러 금고 문서가 같이 쓸 수 있어 문서 행에 매이지 않는다. D1 에 열을 늘리지 않고 R2 객체 하나로 끝난다
- 압축하지 않는다. 압축 뒤 암호화는 길이로 내용을 짐작하게 만드는 공격 갈래가 있고, 결정 15 가 이미 평문 약 750KB 로 정했다
- base64 는 브라우저 기본 `toBase64` 가 있으면 그것(0.2ms), 없으면 `btoa` 묶음(17.9ms, 4배 감속 87.4ms — m5). Node 테스트는 뒤쪽 길을 탄다

### 3.3 크기 — 암호문 1,000,000 B 안에서 (결정 15)

base64 길이 = `4 × ⌈봉투 바이트 / 3⌉`, 봉투 = 평문 + 29 B(버전 1 + IV 12 + 태그 16)

| 항목 | 서버 상한 (검사하는 값) | 평문으로 환산 | 상수 (계약) |
| --- | --- | --- | --- |
| 본문 | `MAX_CONTENT_BYTES` 1,000,000 — **지금 검사 그대로**(`isContentTooLarge`, base64 는 ASCII 라 바이트 = 글자 수) | **749,971 B** 이하 (`4 × ⌈(749,971+29)/3⌉ = 1,000,000`). 측정 m4: 749,010 B → 998,720자 | `E2EE_MAX_PLAIN_CONTENT_BYTES = 749_971` |
| 제목 | 금고 문서만 **2,040자**, base64 글자만(`[A-Za-z0-9+/=]`) | 지금 제목 상한 500자(UTF-16 단위)는 UTF-8 최대 1,500 B → 봉투 1,529 B → base64 2,040자 | `E2EE_MAX_TITLE_CHARS = 2_040` |
| 첨부 id 목록 | 1,000개, 각 16진 16자 | — | `E2EE_MAX_ATTACHMENT_REFS = 1_000` |
| 요청 몸통 | `MAX_BODY_BYTES` 1,100,000 **그대로** | 본문 1,000,000 + 제목 2,040 + id 목록 약 19,000 + 나머지 < 1,100,000 | — |
| 첨부 | `MAX_ATTACHMENT_BYTES` 5,242,880 — 암호 봉투 크기로 | 5,242,811 B (봉투 머리 69 B) | `E2EE_ATTACHMENT_OVERHEAD = 69` |

- 클라이언트는 **암호화 전에** 평문 바이트로 판정한다 — 옮기기 전(결정 15 "옮기기 전에 막는다")과 저장할 때 모두. 금고 문서가 편집으로 749,971 B 를 넘으면 캐시·서버 어느 쪽에도 쓰지 않고 알림(5.1 E7). 편집기 안의 내용은 그대로다
- 금고 문서의 평문 상한(약 750KB)은 일반 문서(1MB)보다 작다 — F-206 2.2 에 예외로 적는다(9장)

### 3.4 저장 경로 — DO·Yjs 를 쓰지 않고 `/api` PUT + 버전 (결정 5·10)

- 금고 문서는 **실시간 방(DO)에 들어가지 않는다.** 저장은 지금의 `POST /api/docs`·`PUT /api/docs/:id`(`baseVersion` → 409) 경로를 탄다 — 문서 전체 봉투를 올린다(결정 5)
- 편집기는 로컬 `Y.Doc`(네트워크 없음)이고 원본은 그 `Y.Text` 다 — 불변조건 "링크가 없으면 편집기 `Y.Doc` 이 원본" 에 들어맞는다. 암호문(D1·캐시)은 거기서 한 방향으로 만든 값이다. 원격 업데이트가 없으므로 IME 게이트가 할 일이 없다
- **옛 탭이 암호문을 평문으로 덮지 못하게** 금고 문서 쓰기는 몸통에 `e2ee: true` 가 있어야 한다. 없으면 409 `{ error: 'e2ee_doc' }`. 금고 기능을 모르는 옛 앱이 금고 문서를 열면 base64 를 본문으로 보여 주고, 고쳐서 PUT 하면 봉투가 깨진다 — 이 표지가 그것을 막는다. 거꾸로 일반 문서에 `e2ee: true` 를 보내면 409 `{ error: 'not_e2ee' }`
- 문서 경로 판정(`docPath.ts` `decideDocPath`)에 새 갈래 `e2ee` 를 **`view`·`pending` 판정보다 앞**에 둔다. 소켓을 열지 않고, 편집 잠금(F-213 `useDocLock`)을 잡지 않고, 자동 저장(`useDocSaver`)만 돈다
- **서버로 보내는 간격은 문서마다 최소 10초** (`E2EE_SERVER_SAVE_INTERVAL_MS = 10_000`, 10장 Q6). 기기 캐시(암호문)는 지금처럼 입력이 700ms 멈추면 쓴다. 같은 문서의 대기 `updateDoc` 은 지금도 합쳐진다(`serverStore.ts` `enqueueUpdateDoc`). 근거 — 금고 문서의 PUT 은 F-2024 의 분당 120·하루 5,000 에 그대로 잡힌다(3.7). 700ms 마다 보내면 쉬엄쉬엄 치는 4시간에 5,000 을 넘을 수 있다(3초에 한 번 멈추면 시간당 1,200). 10초면 문서 하나가 시간당 최대 360, 8시간 2,880
- **충돌 사본**(결정 10): 409 를 받으면 지금 `handleConflict` 처럼 `{제목} (충돌 사본)` 을 새 문서로 만든다. 다만 금고 사본은 **새 DEK 로 다시 암호화**한다(AAD 에 문서 id 가 있고 제목에 꼬리를 붙여야 하므로). **잠겨 있으면** 그 문서의 outbox 항목을 풀릴 때까지 멈추고, 풀린 뒤 사본을 만든다 — 캐시·outbox 에는 이미 암호문만 있어 키 없이는 사본 제목을 만들 수 없다
- 같은 브라우저 여러 탭은 지금의 편집권 클레임(`tabSync.ts` `claim-*`)을 그대로 쓴다 — 한 탭만 편집, 나머지는 읽기
- 로그아웃 로컬 금고는 서버가 없으므로 충돌도 없다. 저장은 `idbStore` 에 암호문으로

### 3.6 금고를 빼는 자리 — 공유·초대·공개·`/v1`·실시간 (결정 6)

**중심 규칙: `access.ts` `resolveDocAccess` 가 금고 문서(`e2ee_key IS NOT NULL`)에 대해 소유자가 아니면 `null` 을 돌려준다.** 초대(문서·폴더 grant)로 오는 모든 `/api` 문서·첨부 접근이 이 한 곳을 지나므로 404 가 된다. 그 밖의 자리는 하나씩 막는다:

| 자리 | 금고 문서·폴더에서 | 응답 |
| --- | --- | --- |
| `POST /api/docs/:id/link`, `POST /v1/docs/:id/link` | 만들지 않는다 | 409 `{ error: 'e2ee_doc' }` |
| `POST /api/folders/:id/link` | 금고 폴더면 만들지 않는다 | 409 `{ error: 'e2ee_folder' }` |
| `PUT /api/docs/:id/grants/:email`, `PUT /api/folders/:id/grants/:email` | 같음 | 409 `e2ee_doc` / `e2ee_folder` |
| 공개 폴더 보기(`handlePublicGetFolder`·`handlePublicGetFolderDoc`) | 일반 폴더 안의 금고 문서·금고 하위 폴더는 **목록에서 빠지고** 열면 404 | 없는 것과 같게 |
| 묶음 링크(`handleGetDocShareSet` 미리보기, `handleCreateDocLink` 의 `docIds`, `handlePublicGetDocSet`·`…SetDoc`) | 금고 문서는 묶음에 넣지 않는다 | 빠짐 / 404 |
| 공유받은 목록(`grants.ts` `handleGetShared`) | 금고 문서·금고 폴더 빠짐 | — |
| `/ws/doc/:id` (`docSocket.ts` `resolveDocSocket`) | 소유자여도 연결하지 않는다 | 닫기 `4403` |
| `GET /v1/docs` | 목록에 **남긴다**, `title: ''`·`e2ee: true`, 감싼 키는 주지 않는다 (10장 Q8) | 200 |
| `GET /v1/docs/:id`, `PUT /v1/docs/:id` | 읽기·쓰기 안 됨 | 403 `{ error: 'e2ee_doc' }` |
| `POST /v1/docs`, `POST /v1/folders` — 금고 폴더 안으로 | 평문을 금고 폴더에 넣지 않는다 | 409 `e2ee_folder` |
| `GET /v1/folders` | 목록에 남긴다, `e2ee: true` | 200 |
| `publicPage.ts` OG 발췌 | 문서 링크만 읽고 금고 문서에는 링크가 생기지 않으므로 바꿀 것 없음. 옮기기 전 있던 링크는 옮길 때 끊는다(4.3) | — |

- 거르기는 **SQL 의 `WHERE` 끝(또는 `ORDER BY` 앞)에 `AND e2ee_key IS NULL` 을 붙이는 방식**을 기본으로 한다 — 가짜 D1 이 SQL 앞부분으로 가르는 테스트(7장)가 덜 깨진다
- **금고 폴더 규칙(서버가 지킨다)**: 금고 폴더 안의 문서는 모두 금고 문서, 하위 폴더는 모두 금고 폴더다. 평문 문서를 금고 폴더로 만들기·옮기기, 금고 폴더 아래 일반 폴더 만들기·옮기기는 409 `e2ee_folder`. 폴더에 `e2ee = 1` 을 켜는 요청은 **바로 아래** 문서가 모두 금고 문서이고 바로 아래 폴더가 모두 금고 폴더일 때만 된다(옮기기가 아래부터 바꾼다 — 4.3). 끄기는 늘 된다
- 금고 문서는 **일반 폴더에도 있을 수 있다**(문서 하나만 금고로 옮긴 경우, 결정 1). 금고 폴더를 일반 폴더 아래로 옮겨도 금고 폴더로 남는다. 금고에서 빼기(4.3)만 평문으로 되돌린다
- 서버는 봉투가 진짜 암호문인지 확인할 수 없다. 위 규칙은 **표지(`e2ee_key`·`e2ee`)** 를 지킨다 — CLI·옛 탭이 금고 폴더에 평문을 넣는 실수를 막는 것이 목적이다

### 4.2 저장소 위에 한 겹 — 앱이 보는 `Doc`

- 암호화·복호화는 `openStore` 가 고른 저장소(`idb`·`server`) **위에 한 겹**(`withE2ee`)에서 한다. 아래 저장소는 봉투만 알고, 앱은 열려 있으면 평문을 본다. `src/` 새 디렉터리 `src/e2ee/` 에 순수 암호 함수(F-403)·키 상태(F-404)·이 한 겹(F-405)을 둔다
- 앱이 보는 `Doc` 에 필드 하나(계약 — F-405·F-409 가 같이 쓴다):

```ts
// src/types.ts Doc 에 더한다. 없으면 일반 문서
e2ee?: 'locked' | 'open'
```

  - `locked`: `title` 과 `content` 는 빈 문자열. 사이드바는 `잠긴 문서` 로 보인다
  - `open`: 복호화한 제목·본문
- 금고 폴더는 `Folder` 에 `e2ee?: true`. 폴더 이름은 평문이라 잠겨 있어도 보인다(결정 2)
- 잠긴 금고 문서를 열면(`#/d/{id}`) 편집 영역에 잠금 해제 패널(5.1 P1)이 뜬다. 잠긴 금고 폴더 안에 `새 문서`·가져오기를 하면 먼저 연다

### 4.3 금고로 옮기기 · 금고에서 빼기 (결정 14)

- **온라인에서만**(10장 Q5). 서버가 평문 흔적(DO 저장소·공유 링크·초대·평문 첨부)을 치우는 일이 한 요청에 묶여 있어서다. 오프라인이면 메뉴가 비활성, 문구 E5. 로그아웃 로컬 금고에서는 온라인 조건이 없다
- **문서 하나 옮기기** 순서: ① 평문 바이트 > 749,971 이면 막는다(E6) ② 금고가 없으면 금고 만들기(D-8), 잠겨 있으면 열기 ③ 본문이 참조하는 평문 첨부를 하나씩 받아 새 id 로 암호화해 올리고, 본문의 `attachments/{옛 id}.{ext}` 를 새 id 로 바꾼다 ④ 새 DEK 로 제목·본문 봉투를 만들어 `PUT /api/docs/:id/e2ee` ⑤ 성공하면 옛 평문 첨부를 `DELETE`(409 `in_use` 면 남긴다 — 다른 일반 문서가 쓰는 중) ⑥ 기기의 `md-yjs` 기록·평문 캐시 첨부를 지운다
- **폴더 옮기기**: 가장 깊은 하위 폴더의 문서부터 문서마다 위 순서, 폴더 안이 다 금고가 되면 그 폴더에 `e2ee` 를 켠다(3.6 규칙). 중간에 실패하면 거기서 멈추고 알린다 — 옮긴 문서는 금고 문서로 남고(어디에 있어도 된다), 폴더는 일반 폴더로 남는다. 다시 누르면 남은 것부터 이어 간다. 진행은 알림 E8
- **금고에서 빼기**: 복호화 → 평문 첨부로 다시 올리기 → `PUT /api/docs/:id/e2ee` 에 `e2eeKey: null` → 암호 첨부 `DELETE`. 폴더는 `e2ee` 를 먼저 끄고 문서를 하나씩 뺀다
- 옮기기는 그 문서의 **공유 링크·묶음·초대를 끊는다**(서버, 3.8). 확인 대화상자(D-9)에 적는다
- **백업 안내**(결정 14 "한 번"): 이 기기에서 처음 옮길 때만 D-9 에 문단 하나를 더 보이고 `md.e2eeBackupNotice = 1`. 숫자는 **30일** — D1 Time Travel 이 무료 7일·유료 30일(m9), DO 저장소 되돌리기가 30일(m10)이라 요금제와 무관하게 맞는 상한이다. 실시간으로 편집했던 문서는 DO 의 Yjs 이력에도 평문이 있었고 `purgeRoom` 이 지워도 PITR 에 남는다. R2 는 문서에 백업 기능이 없어(m11) 문구에 넣지 않는다
- 다른 기기·다른 사람이 그 문서를 실시간으로 열어 두었다면 `purgeRoom` 이 연결을 닫는다. 그쪽의 끊긴 동안 편집은 저장되지 않는다(`e2ee: true` 가 없는 PUT 은 409) — D-9 에 적는다

### 4.4 로그인 이관 (결정 12, F-208 확장)

- F-208 은 지금처럼 **일반 문서를 한 번** 옮긴다(`md.localMigrated`). 로컬 금고 문서·폴더는 그 이관에서 **빼고**, 따로 묻는다
- 로컬 `md-docs` 에 금고 문서가 1개 이상이면 로그인 뒤 알림 E9(버튼 `옮기기`·`나중에`). `나중에` 는 기억하지 않는다 — 다음 로그인(다음 부팅에서 계정 상태가 `in` 이 될 때)에 다시 묻는다
- `옮기기` → 로컬 금고 암호로 로컬 MK 를 푼다 →
  - **계정 금고가 없으면**: 로컬 키 묶음을 **그대로** 계정 금고로 올린다(`PUT /api/e2ee/keys`, `baseRev` 0). 암호·복구 코드가 같게 된다(결정 12 "같은 암호로 만든다"). DEK 는 다시 감쌀 필요가 없다
  - **계정 금고가 있으면**: 계정 금고도 열어야 한다(이미 열려 있으면 묻지 않는다). 문서마다 DEK 를 로컬 MK 로 풀어 계정 MK 로 **다시 감싼다**, 첨부 봉투는 머리의 감싼 키만 바꿔 다시 올린다. 본문 암호문은 그대로다(2.1 이유 1)
- id 는 그대로(F-208 2.2 3번과 같다). 옮긴 로컬 금고 문서는 **로컬에서 지우지 않는다**(F-208 "로컬 `md-docs` 는 지우지 않는다" 그대로) — 대신 옮겼다는 표시를 로컬 키 묶음 행에 남겨 다시 묻지 않는다
- 로그아웃 상태에서는 로컬 금고가 보이고, 로그인 상태에서는 계정 금고가 보인다 — 지금 일반 문서와 같은 규칙

### 4.5 검색·지도·내보내기 (결정 13)

- 검색(`searchIndex.ts`)·지도(`mapIndex.ts`)는 `e2ee: 'locked'` 문서를 **넣지 않는다**. 열면 다음 색인 만들기 때 들어간다. 잠글 때 두 메모리 캐시를 비운다(2.5 ④)
- 검색 대화상자는 잠긴 금고 문서가 있으면 결과 목록 아래 한 줄 `금고가 잠겨 있어 금고 문서 {N}개는 찾지 않았습니다.`
- 위키링크: 일반 문서의 `[[금고 문서 제목]]` 은 열려 있을 때만 이어지고, 잠겨 있으면 끊긴 링크로 보인다. 공개 보기에서는 늘 끊긴다(서버 해석기는 암호문 제목을 본다)
- **내보내기**: `.md` 한 개 내보내기·인쇄는 열린 금고 문서에서 평문으로 된다(사용자가 고른 것). 전체 내보내기(F-281)·옵시디언 내보내기(F-2020)는 **열려 있으면 평문으로 넣고, 잠겨 있으면 빼고** 끝에 알린다 `금고가 잠겨 있어 금고 문서 {N}개는 빼고 내보냈습니다.` (10장 Q7)
- 공유 메뉴: 금고 문서에서는 `공유 링크`·`사람 초대…`·F-130 해시 공유 항목을 비활성으로 두고 설명 `금고 문서는 공유할 수 없습니다.`

### 4.6 금고 초기화

- 암호와 복구 코드를 모두 잃었을 때 새로 시작하는 길. 설정 `금고` 탭의 `금고 초기화…` → 입력 확인(`초기화` 를 그대로 입력) → 금고 문서·폴더를 전부 지우고(지금의 삭제 요청들) → `DELETE /api/e2ee/keys`
- 잠긴 채로 할 수 있다 — 지우기에는 키가 필요 없다

### 5.2 F-309 와의 관계 (결정 10)

F-309 는 일반 문서에서 편집 잠금과 폴백 경로를 걷는다(F-301 11장, F-306 Q1 "`pending`·`fallback` 세션의 outbox `updateDoc{content}`·본문 충돌 사본은 F-309 가 지운다"). 금고는 그 가운데 일부를 계속 쓴다

| F-309 가 걷을 것 | 금고가 쓰나 | F-309 에 요구하는 것 |
| --- | --- | --- |
| `doc_locks` 표·`worker/locks.ts`·`src/app/useDocLock.ts`·`X-Lock-Session`·423 | **안 쓴다** — 금고 문서는 잠금을 잡지 않는다(3.4) | 그대로 지운다 |
| `PUT /api/docs/:id` 의 `baseVersion` 비교와 409 `conflict` | **쓴다** | 지우지 않고 **금고 문서 전용**으로 좁힐 수 있다(일반 문서는 DO 경로) |
| outbox `updateDoc{content}` | **쓴다** | 금고 문서의 `updateDoc` 은 남긴다 |
| `serverStore.ts` `handleConflict`(충돌 사본) | **쓴다** — 금고 사본은 다시 암호화(3.4) | 남긴다 |
| `decideDocPath` 의 `pending`·`fallback` | 안 쓴다 — 금고는 `e2ee` 갈래 | 지워도 된다 |

- **F-309 가 먼저 오면**: F-309 명세가 위 표의 "쓴다" 셋을 지우지 않고 남겨야 한다 — 이때 그 셋은 잠시 쓰는 곳이 없다(금고 하위 명세가 붙을 때까지). F-309 명세를 쓸 때 이 절을 읽게 9장에 적는다
- **금고가 먼저 오면**: F-405 는 셋을 금고 경로에서 부르고, F-309 는 일반 문서 쪽 호출만 걷는다
- 어느 순서든 **409 충돌 사본은 금고 문서에서만** 남는다 — 결정 10

## 10. 열린 질문 — 전부 닫힘 (2026-09-25)

### Q1. 키 유도 — **답(2026-09-25 사용자): PBKDF2-SHA256 600,000회, 의존성 없음. Argon2id 안 씀**
