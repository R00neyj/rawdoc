## 2. 범위

### 한다

- 설정 `데이터` 탭과 폴더 `⋯`·우클릭 메뉴에서 옵시디언 볼트 zip 내려받기
- 문서·폴더 이름을 옵시디언이 링크로 가리킬 수 있는 이름으로
- 이미지 블록을 옵시디언 임베드로, 첨부를 루트 `attachments/` 한 곳에
- 볼트에서 끊기거나 다른 문서로 갈 위키링크에 경로(또는 바뀐 이름)를 붙이기

### 하지 않는다

- 문서 하나 내보내기 메뉴(상단바)에 넣기 — 문서 하나는 볼트가 아니다(개요 5.1)
- `.obsidian/` 설정, `manifest.json`, 빈 폴더 디렉터리 항목
- 프론트매터(`title` 등) 고치기·더하기, 제목을 본문에 넣기
- 옵시디언 전용 문법 만들기(태그·별칭 프론트매터·블록 참조)
- 되가져오기(F-2019), 공유받은 문서 내보내기(F-281 과 같음)
- 내보내는 동안 버튼 비활성 상태 — F-281 코드에도 없다(`handleExportAll` 확인). 이 명세도 더하지 않는다

## 3. 이름과 경로

### 3.1 옵시디언 이름 — `src/lib/filename.ts`

```ts
// src/lib/filename.ts (F-2020)
export function toObsidianFileName(title: string): string   // '.md' 로 끝난다
export function toObsidianFolderName(name: string): string
```

- 규칙: `toFileName`·`toFolderName` 과 **같은 단계**(`sanitizeName`)에서 금지 문자 목록에 `#` `^` `[` `]` 를 더한 것. 즉 네 글자는 `\ / : * ? " < > |`·제어 문자와 **같은 자리에서** `_` 로 바뀌고, 그 뒤 앞뒤 공백·끝 마침표 정리·빈 이름·Windows 예약 이름·100 코드포인트 자르기가 그대로 이어진다
- 네 글자가 없는 이름에서는 `toObsidianFileName(t) === toFileName(t)`, `toObsidianFolderName(n) === toFolderName(n)` 이다
- 이유(개요 Q7): 옵시디언 링크에서 `#` 은 헤딩, `^` 는 블록 참조, `[` `]` 는 링크 괄호다. 이 앱도 `#` 뒤를 헤딩으로 보므로(F-2018 3.1) 그런 제목은 원래 위키링크로 가리킬 수 없다
- NFC 정규화는 하지 않는다 — 제목 글자 그대로. F-2019 가 되가져올 때 이름을 NFC 로 바꿔 비교한다(개요 4.3)

### 3.2 경로 계획 꺼내기 — `src/app/exportWorkspace.ts`

지금 `buildFolderPaths`·`buildDocPaths`·대상 고르기는 `planWorkspaceExport` 안에만 있다. 이름 함수를 인자로 받는 모양으로 꺼낸다

```ts
// src/app/exportWorkspace.ts (F-2020) — F-281 3.1·3.2 규칙 그대로, 이름 함수만 인자
export type ExportNaming = {
  fileName(title: string): string    // '.md' 로 끝나야 한다 — 충돌 번호가 '.md' 앞에 붙는다
  folderName(name: string): string
}
export function selectExportScope(docs: Doc[], folders: Folder[], scope: ExportScope):
  { docs: Doc[]; folders: Folder[]; rootFolderId: string | null }
export function planExportPaths(docs: Doc[], folders: Folder[], rootFolderId: string | null, naming: ExportNaming):
  { folderPaths: Map<string, string>; orderedFolders: Folder[]; docPaths: Map<string, string> }
```

- `selectExportScope`: F-281 3.1 — 문서는 `role` 이 `'owner'` 이거나 없는 것, 범위가 폴더면 `descendantFolderIds` 안 폴더(루트 폴더 자신은 빼고)와 그 문서. 지금 `planWorkspaceExport` 앞부분 그대로
- `planExportPaths`: F-281 3.2 — 같은 디렉터리 안 폴더끼리·문서끼리 `createdAt` → `id` 순으로 훑어 대소문자 무시 충돌에 ` (n)`, 모든 디렉터리에서 폴더 이름 `attachments` 예약. 경로는 `/` 구분, 문서는 `.md` 포함. 지금 `buildFolderPaths`·`buildDocPaths` 그대로
- **충돌은 이름 함수를 거친 뒤의 이름으로 본다.** 옵시디언 이름에서는 `a#`·`a^` 두 문서가 `a_.md`·`a_ (2).md` 가 된다
- `planWorkspaceExport` 는 이 둘을 `{ fileName: toFileName, folderName: toFolderName }` 으로 부른다. **결과(경로·`manifest`·`directories` 순서)가 한 글자도 바뀌지 않는다** — 판정은 `exportWorkspace.test.ts` 무수정 통과(11.1 U9)

- 문서가 없는 폴더는 디렉터리 항목이 생기지 않는다. `manifest` 가 없으므로 빈 폴더는 볼트에 남지 않는다 — 옵시디언으로 가는 볼트에 빈 폴더가 필요하지 않고, F-2019 도 문서 없는 폴더를 만들지 않는다(개요 4.3 표 마지막 행)

## 5. 본문 변환 — `toVaultMarkdown`

입력은 저장소 `doc.content`(에디터 글자, 줄바꿈 LF). 이미지 블록 바꾸기(5.3)와 링크 고쳐 쓰기(5.4)를 **원문 기준 위치로 한 번에** 적용한다. 두 편집이 겹치면(블록 `alt` 안의 `[[…]]`) 블록이 이기고 그 링크는 세지 않는다

### 5.1 찾는 방식을 둘로 나눈 이유

- **이미지 블록은 보기 모드와 같은 판정**(markdown-it). 편집기(`blocks.ts`, lezer `HTMLBlock`)와 보기 모드(`renderMarkdown.ts` `imageBlockRule`, 문단)는 드문 경우에 판정이 다르다 — 글 바로 아래 붙은 블록은 편집기에선 그림, 보기에선 원문이다(CommonMark HTML 블록은 문단을 끊지만 이 앱 markdown-it 은 `html: false` 라 문단으로 본다). `.txt` 내보내기(F-278)가 보기 모드 토큰을 쓰는 선례를 따른다
- **markdown-it 파싱은 첨부 참조가 있는 문서에만** 한다 — `extractAttachmentRefs(content)` 가 비었으면 바꿀 블록이 없다. 전부 파싱하면 5,000개에 1.2~2.5초다(머리 (b))
- **위키링크는 줄 단위 훑기**(지도와 같은 판정, 5.2). 76~97 ms(머리 (b))

### 5.2 링크 찾기 공유 — `src/lib/wikiGraph.ts` `scanWikiLinks`

- 훑기 규칙은 지금 `extractWikiTargets` 그대로다: 프론트매터 건너뜀, 펜스(`matchFence`) 안 건너뜀, 인라인 코드는 `maskInlineCode` 로 가린 줄에서 찾음. **다른 점 하나** — 지금은 표 줄을 건너뛰지만 `scanWikiLinks` 는 표 줄의 링크도 `inTable: true` 로 돌려준다(표 판정은 지금 `TABLE_DELIMITER_RE` 근사 그대로)
- 위치: 줄 시작 위치 + 줄 안 위치. 줄 나눔은 지금처럼 `\r\n`·`\r`·`\n` 을 인정하고 그 길이를 그대로 센다. 프론트매터가 있으면 `fm.to` 를 더한다

- 지도와 같은 판정을 쓰는 이유: 볼트 내보내기에서 고친 링크와 지도에 그려진 간선이 같은 링크 집합이어야 설명이 된다. 보기 모드(markdown-it)와는 들여쓴 코드블록(공백 4칸)에서 다르다 — 들여쓴 코드 안 `[[…]]` 도 고친다. 13장 Q5

### 5.4 위키링크 고쳐 쓰기

**볼트 모형** — 옵시디언이 링크를 어떻게 푸는지 이 앱이 가정하는 규칙(가정 G1·G2·G-e·G-f, 14.2)

- 볼트 문서 경로 = zip 경로에서 `.md` 를 뗀 것을 `/` 로 나눈 조각들. 비교는 조각마다 `toLowerCase()`(F-2018 4.5 와 같은 접기)
- 링크 대상 문자열 `t` 는 맨 앞 `/` 들을 떼고 `/` 로 나눠 조각마다 앞뒤 공백을 뗀다. 빈 조각이 있으면 어떤 문서도 가리키지 않는다
- **`t` 가 볼트에서 문서 D 를 가리킨다** = ① `t` 의 조각이 D 경로 조각 **전체**와 같다, 또는 ② D 경로의 끝 조각들과 같은 볼트 문서가 **D 하나뿐**이다
- ①이 없으면 머리 (d) 의 문서(`색인.md` 옆에 `위키/색인.md`)는 어떤 링크로도 가리킬 수 없다. ①은 "볼트 루트부터 적은 전체 경로는 그 파일로 풀린다" 는 가정(G-e)이다 — 개요 5.3 에 없던 규칙이다. 13장 Q6

**링크마다** (`scanWikiLinks` 결과, 원본 S = 지금 변환하는 문서)

1. `target === ''`(`[[#헤딩]]`) → 그대로
2. D = `resolver.resolve(target, S.folderId)`. `null` 이거나 D 가 **내보내는 문서가 아닌**(`exportedIds` 에 없음) → 그대로. 폴더 내보내기에서 폴더 밖 문서로 풀리는 링크, 공유받은 문서로 풀리는 링크가 여기다
3. `target` 이 볼트에서 D 를 가리킨다 → 그대로
4. 아니면 D 경로의 끝 조각 1개, 2개, … 순으로 **처음으로 볼트에서 D 를 가리키는 형태**를 새 대상으로 한다(전체 경로는 ①로 언제나 가리킨다). 조각 글자는 zip 경로 그대로(접지 않은 것)
5. 원문 편집: `targetFrom` 부터 **원문 조각 안 첫 `#` 앞까지**(없으면 `targetTo` 까지)를 새 대상으로 바꾼다. `#` 부터 뒤(헤딩·블록 참조)는 글자 그대로 둔다
6. 별칭: 링크에 별칭이 **없고 표 줄이 아니면** `]]` 바로 앞에 `|{보이던 글자}` 를 넣는다. 보이던 글자 = `targetFrom`~`targetTo` 원문 조각의 앞뒤 공백을 뗀 것(F-2018 3.2 보이는 글자 규칙). 별칭이 있던 링크는 별칭을 그대로 둔다
7. 고친 링크 하나를 센다

| 원문 (원본 문서 자리) | 볼트 | 결과 |
| --- | --- | --- |
| `[[왜?]]` (최상위) | `왜_.md` | `[[왜_\|왜?]]` |
| `[[회의록]]` (`교안/목차`) — `교안/회의록`·`과제/회의록` 둘 | 같은 이름 둘 | `[[교안/회의록\|회의록]]` |
| `[[회의록#결정\|결정 보기]]` (`교안/목차`) | 같음 | `[[교안/회의록#결정\|결정 보기]]` |
| `[[교안/회의록]]` | `교안/회의록` 은 하나뿐 | 그대로 |
| `[[색인]]` (최상위) — `색인`·`위키/색인` 둘, 앱은 최상위 `색인` 으로 푼다 | ①로 `색인` 은 최상위 `색인` | 그대로 |
| `[[색인]]` (`위키/a`) — 앱은 `위키/색인` 으로 푼다 | `색인` 은 ①로 최상위 문서를 가리킨다 | `[[위키/색인\|색인]]` |
| `\| [[왜?]] \| 1 \|` (표 줄) | `왜_.md` | `\| [[왜_]] \| 1 \|` — 별칭을 넣으면 `\|` 가 칸을 나눈다 |
| `` `[[왜?]]` ``, 펜스 안, 프론트매터 안 | — | 그대로 |
| `[[#결정]]`, `[[없는 문서]]`, `![[그림.png]]` | — | 그대로 |

- **해석은 앱과 같은 풀에서 한다.** 해석기는 `store.list()` 의 문서 전부(공유받은 문서 포함, `updatedAt` 내림차순 — 같으면 입력 순서)와 `store.listFolders()` 폴더 전부로 만든다. 그래서 D 는 "앱 편집기에서 누르면 가는 문서" 와 같다. 그 D 가 볼트에 없으면 고치지 않는다(2). 개요 5.3 의 "후보 = 내보내는 범위 안 문서만" 을 이렇게 읽었다 — 13장 Q3
- 해석기 API(`createWikiResolver`·`resolve`)는 F-2018 명세(`94fee58`) 이름이다. F-2018 커밋에서 이름이 바뀌면 그 이름을 쓴다. `shortestWikiTarget` 은 쓰지 않는다 — 기준이 "앱에서 원본 기준으로 풀림" 이지 "볼트 안에서 하나" 가 아니다(F-2018 4.1 과 같은 판단)
- 표 줄에서 별칭을 넣지 않는 대가: 옵시디언 표에서 `왜_`·`교안/회의록` 처럼 경로가 보인다. `\|` 로 이스케이프하면 옵시디언은 받는다고 알려져 있지만(확인하지 않음), 이 앱 표 칸이 위키링크 안 `\|` 를 되가져온 뒤 어떻게 푸는지 확인하지 않았다. 13장 Q5

## 8. 왕복 (F-2019 와 함께 볼 것)

- **이미지**: `![[{id}.{ext}|{width}]]` 를 F-2019 가 같은 id 로 다시 쓰고 기존 블록의 `align`·`alt` 를 이어받는다(개요 4.4, F-2019 6.2·7.5·U12). 원래 블록이 `buildImageBlock` 이 만든 모양(들여쓰기 2칸, `src`·`alt`·`width` 순서)이면 **바이트까지 같아져** `skip` 된다. 손으로 고친 블록(속성 순서가 다르거나 첫 줄 앞 공백)은 한 번 `update` 된다
- **경로만 붙인 링크**(`[[회의록]]` → `[[교안/회의록|회의록]]`, 폴더·문서 이름이 앱 이름과 같은 경우): F-2019 가 되가져올 때 별칭이 새 대상의 앱 형태와 같으면 별칭을 접어 `[[회의록]]` 로 되돌린다(F-2019 7.8 5단계) → 원래 바이트, `skip`. 별칭이 대상과 다른 링크(`[[회의록#결정|결정 보기]]` → `[[교안/회의록#결정|결정 보기]]`)만 앱에서도 경로식 해석(F-2018 4.3 의 2)으로 같은 문서로 풀려 그대로 남고, 처음 한 번 `update` 된다. 다음 내보내기부터 3단계에서 그대로 → 수렴(개요 5.4, F-2019 U19 가 판정)
- **이름이 바뀐 링크**(`[[왜_|왜?]]`, `[[회의록 (2)|회의록]]`, `attachments (2)/…`, 100자 자름 등 — 볼트 이름 ≠ 앱 제목·폴더 이름): F-2019 는 기존 문서의 제목을 바꾸지 않으므로(개요 4.3) 그대로 두면 앱 안에서 끊긴다. **F-2019 7.8 이 받았다** — 볼트에서 풀리는 문서의 앱 형태(`shortestWikiTarget`)로 되돌리고 F-2020 이 붙인 별칭을 접어 `[[왜?]]` 가 된다. 앱에서 그 문서를 가리킬 글자가 없는 경우(같은 폴더 같은 제목, F-2018 4.8)만 끊긴 채 남는다. 13장 Q2
- **`-vault` 붙은 이름**: 폴더 zip `교안-vault.zip` 을 풀면(탐색기 "압축 풀기" 기본) 폴더 이름이 `교안-vault` 이고, zip 을 그대로 넣어도 볼트 이름이 zip 파일명(`교안-vault`)이다(개요 4.1). **F-2019 4.4 가 볼트 이름 끝 소문자 `-vault` 를 떼어** `넣을 폴더` 기본값이 원래 폴더 `교안` 을 찾는다. 13장 Q7
