작성일: 2026-09-26
상태: **초안 — 사람 승인 전.** 사용자 요청(2026-09-26) 원문은 아래 "요청" 절. 사용자가 이미 정한 다섯 가지(설정으로 켜고 끔·기본 켬, 지연 뒤 뜸·터치 제외, 약 400×400 토큰 하나, 미리보기 안 전체 조작·보기 모드 렌더, 중첩 없음)는 바꾸지 않는다. **사람이 정할 갈림길은 12장 Q1(공유받은 문서)·Q2(길이 상한)** 이고 둘 다 기본값이 있다. 크기감·지연감은 사람 확인(11장 H1·H2)

단위 판단: 작은 명세 하나. 새 파일 셋(순수 함수 모듈, 미리보기 컴포넌트, CSS)과 기존 파일 몇 곳의 배선이다. 구현은 `feature-implementer` 로 충분하다 — 포인터 판정·위치 계산·타이머를 순수 모듈로 떼어 두었고(3장), 무거운 렌더 비용은 이 명세가 미리 쟀다(7장)

## 3. 순수 모듈 `src/app/wikiPreview.ts` (계약)

### 3.1 상수와 본문 자르기

```ts
export const WIKI_PREVIEW_OPEN_DELAY_MS = 500
export const WIKI_PREVIEW_CLOSE_GRACE_MS = 300
export const WIKI_PREVIEW_CHAR_LIMIT = 20_000
export const WIKI_PREVIEW_GAP = 4       // 링크와 미리보기 사이 px
export const WIKI_PREVIEW_MARGIN = 8    // 창 가장자리 여백 px

export type PreviewSlice = { text: string; truncated: boolean }
export function slicePreviewText(text: string, limit?: number): PreviewSlice
```

`slicePreviewText` 규칙:
- 입력은 먼저 줄바꿈을 LF 로 맞춘다(`src/lib/lineEnding.ts` `toEditorText` 와 같은 결과). 보기 모드도 `getText('lf')` 를 렌더한다
- 길이(UTF-16 코드 유닛, `String.length`)가 `limit`(기본 `WIKI_PREVIEW_CHAR_LIMIT`) 이하면 전체, `truncated: false`
- 넘으면 `limit` 이하에서 **마지막 빈 줄(`\n\n`)** 앞에서 자른다. 그 자리가 `limit / 2` 보다 앞이면 마지막 `\n` 앞, 그것도 `limit / 2` 보다 앞이면 `limit` 에서 자른다. 자른 자리가 서로게이트 쌍 가운데면 한 칸 앞으로. `truncated: true`
- 닫히지 않은 코드 펜스가 잘려도 그대로 둔다 — markdown-it 은 닫히지 않은 펜스를 끝까지 코드로 그린다. 모양이 조금 어긋나도 원문은 바뀌지 않는다

```ts
  size: { width: number; height: number },
  viewport: { width: number; height: number },
): PreviewPlacement
```

규칙 — `ContextMenu.tsx` 의 "넘치면 뒤집는다"(c13)를 함수로 옮긴 것이다. 그 파일은 고치지 않는다:
- `width = min(size.width, viewport.width − 2·MARGIN)`
- 아래 자리 `below = viewport.height − MARGIN − (anchor.bottom + GAP)`, 위 자리 `above = anchor.top − GAP − MARGIN`
- `below ≥ size.height` 면 아래. 아니고 `above ≥ size.height` 면 위. 둘 다 모자라면 더 넓은 쪽(같으면 아래)이고 `maxHeight` 는 그 자리 값. 그 밖에는 `maxHeight = size.height`
- 아래면 `top = anchor.bottom + GAP`. 위면 `bottom = viewport.height − (anchor.top − GAP)` — **위쪽은 `bottom` 기준**이다. 짧은 문서라 실제 높이가 `maxHeight` 보다 작아도 링크와의 간격이 4px 로 유지된다
- `left = clamp(anchor.left, MARGIN, viewport.width − MARGIN − width)`
- **판정에 쓰는 높이는 실제 높이가 아니라 최대 높이(`size.height`)다.** 이미지·다이어그램이 나중에 채워져 높이가 늘어도 창 밖으로 나가지 않는다
- `anchor` 는 포인터가 올라간 링크 요소의 `getClientRects()` 가운데 **포인터 y 를 담은 사각형**이다(줄바꿈으로 두 줄에 걸친 링크). 못 찾으면 `getBoundingClientRect()`
- `size` 는 스크립트에 숫자로 다시 쓰지 않는다 — 미리보기 요소의 계산된 스타일(`width`·`max-height`, 둘 다 `--wiki-preview-size` 에서 온다)을 읽는다. 크기를 바꿀 때 CSS 토큰 한 곳만 고친다(사용자 결정 3)

### 3.3 대상 판정

```ts
export type PreviewEligibility = 'ok' | 'missing' | 'self' | 'shared' | 'locked'
export function previewEligibility(
  target: { id: string; role?: 'owner' | 'edit' | 'view'; e2ee?: 'locked' | 'open' } | null,
  currentDocId: string | null,
): PreviewEligibility
```

- `null` → `missing`, `target.id === currentDocId` → `self`, `role` 이 `edit`·`view` → `shared`, `e2ee === 'locked'` → `locked`, 나머지 `ok`. 이 순서로 본다
- 호출하는 쪽(App)은 링크 대상 문자열을 `wikiResolver.resolve(target, currentFolderId)` 로 풀어 얻은 문서 메타를 넘긴다. 대상 `''`(`[[#제목]]`)은 지금 문서다
- `missing`·`self` → 창을 열지 않는다. `shared`·`locked` → 창은 열되 본문 대신 안내 문구(6장). 대상 판정은 열 때마다 새로 한다
- `locked` 는 보통 해석기 단계에서 이미 `missing` 이 된다(c9). 해석은 됐는데 `store.get` 결과가 잠긴 모양인 경쟁(열자마자 잠김)만 여기에 걸린다

### 3.4 호버 타이머

```ts
export type HoverIntent = {
  pointerOnLink(key: string | null): void   // 좌표가 바뀐 포인터 이동마다. null = 판정 대상 링크 위가 아님
  pointerInPreview(inside: boolean): void
  dismiss(): void                           // 즉시 닫기(Esc·스크롤·입력·바깥 누르기 등, 4.3)
  dispose(): void                           // 타이머 전부 해제
}
export function createHoverIntent(handlers: { open(key: string): void; close(): void }): HoverIntent
```

`key` 는 링크 하나를 가리키는 문자열로 호출하는 쪽이 만든다(대상 문서 id + `\u0000` + 제목, 제목 없으면 빈 글자). 규칙:

| 상황 | 결과 |
| --- | --- |
| 닫힌 상태에서 링크 `k` 위로 들어옴 | `OPEN_DELAY_MS` 뒤 `open(k)`. 그 전에 벗어나면 취소 |
| 열기 대기 중 다른 링크 `k2` 로 옮김 | 대기를 `k2` 로 새로 시작 |
| 열린 상태에서 링크·미리보기 **둘 다** 벗어남 | `CLOSE_GRACE_MS` 뒤 `close()`. 그 안에 링크 `k` 나 미리보기로 돌아오면 취소 |
| 열린 상태에서 다른 링크 `k2` 위로 | 유예 없이 `k2` 대기를 시작하고, `OPEN_DELAY_MS` 뒤 `open(k2)`(창을 바꿔 연다). 그 사이 열린 창은 유예 규칙대로 닫힐 수 있다 |
| `dismiss()` | 대기·유예 취소, 열려 있으면 `close()`. 그 뒤 **포인터가 그 링크를 한 번 벗어날 때까지 같은 `key` 로는 다시 열지 않는다**(Esc 로 닫았는데 포인터가 그대로라 곧바로 다시 뜨는 일을 막는다) |

- 경계값은 단위 테스트로 못박는다(10.1 U4): 들어온 뒤 499ms 에 안 열림, 500ms 에 열림, 둘 다 벗어난 뒤 299ms 에 열려 있음, 300ms 에 닫힘
- 지연 값의 근거: 앱 툴팁 지연 400ms(c12)보다 한 단계 길게. 미리보기는 400px 네모로 본문을 덮으므로 포인터가 링크를 지나가기만 할 때는 뜨지 않아야 한다. 사용자가 준 400~500 범위의 윗값이다. 값의 느낌은 사람 확인 H2
- 유예 300ms 의 근거: 링크에서 4px 떨어진 미리보기로 옮기는 동안 닫히지 않을 만큼. 값의 느낌은 H2

## 4. 동작

### 4.1 켜짐 조건

아래가 모두 참일 때만 판정한다. 하나라도 거짓이면 대기 중인 열기를 취소하고, 열려 있으면 닫는다
- 설정 `md.wikiPreview` 가 `on`
- 편집 화면(S-1)에 문서가 열려 있고 모드가 `편집` 또는 `보기`. 공유 문서 화면·지도·도움말·공유 관리가 떠 있지 않다(App 의 `sharedDoc`·`mapRoute`·`helpOpen`·`sharesOpen`)
- 편집기가 조합 중이 아니다(4.4)

### 4.2 여는 규칙

1. **좌표가 실제로 바뀐 `pointermove`** 만 호버 판정에 쓴다. 조건: `pointerType === 'mouse'`, 누른 버튼 없음(`buttons === 0`). 직전 좌표와 같으면 무시한다
   - 이유: 스크롤·원격 편집으로 글자가 포인터 밑으로 옮겨 와도 창이 뜨지 않게. 문서를 연 직후 포인터가 제자리에 있을 때도 같다
   - `pointerType` 이 `touch`·`pen` 이면 판정하지 않는다 — 사용자 결정 2의 "호버 없는 포인터". 터치 노트북에서 마우스를 쓰면 마우스 이벤트만 판정에 들어간다(H5)
   - 드래그 선택 중(버튼 누름)에는 판정하지 않는다
2. 포인터 아래 요소에서 링크를 찾는다
   - 편집 모드: `.md-wikilink` 이고 `.md-wikilink--missing` 이 아닌 가장 가까운 조상. `view.posAtDOM(요소)` → `findWikiLinkAt(view.state, pos)` 로 `target`·`heading` 을 얻는다. null 이면(표 칸 등) 링크 아님
   - 보기 모드: `a.wikilink` 이고 `wikilink--missing` 이 아닌 가장 가까운 조상. `data-wikilink`·`data-wikilink-heading`
3. 얻은 `target` 을 `wikiResolver.resolve(target, currentFolderId)` 로 풀고 `previewEligibility` 로 판정한다. `missing`·`self` 면 `pointerOnLink(null)`
4. 판정이 `ok` 이면 **포인터가 링크에 들어온 그 순간 본문 읽기를 시작한다**(5.1). 열기 지연 동안 읽기가 끝나면 창이 곧바로 내용과 함께 뜬다. 지연 전에 벗어나면 결과를 버린다(취소할 수 없는 읽기는 끝나도 쓰지 않는다)
5. 지연이 끝나면 3.2 로 위치를 정해 창을 연다. **포커스를 옮기지 않는다** — 편집기의 커서·선택·포커스가 그대로다
6. 한 번에 창은 하나다. 다른 링크로 열면 앞 창을 바꾼다
7. 미리보기 안 요소는 판정 범위 밖이다(2장 끝). 미리보기 안 위키링크 위로 포인터를 옮겨도 새 창이 뜨지 않고, 지금 창이 그대로다

### 4.3 닫히는 조건

| 조건 | 동작 |
| --- | --- |
| 포인터가 링크와 미리보기를 둘 다 벗어나 300ms | 닫는다(3.4). 포인터가 창 밖으로 나가 `pointerleave` 만 오고 `pointermove` 가 없는 경우도 "벗어남" 으로 친다 |
| `Esc`(어디에 포커스가 있든, 창이 열려 있을 때) | 닫는다. 이 키는 창을 닫는 데만 쓰고 전파를 막는다 — 편집기 찾기 패널·겹친 사이드바가 같은 `Esc` 로 함께 닫히지 않는다. 캡처 단계에서 받는다. 창이 닫혀 있으면 아무것도 하지 않는다. 포커스가 미리보기 안에 있었으면 4.6 대로 돌려준다 |
| 미리보기 **밖**에서 `pointerdown` | 닫는다. 그 누르기 자체(원래 링크를 눌러 문서 열기 포함)는 막지 않는다. 열기 대기 중이면 취소 |
| 미리보기 **밖**에 포커스가 있는 상태의 `keydown`(단 `Shift`·`Control`·`Alt`·`Meta` 단독 키는 제외) | 닫는다. 열기 대기 중이면 취소. 치는 동안 창이 뜨거나 남지 않는다 |
| 편집기 `compositionstart` | 닫는다·취소(4.4) |
| 스크롤 — 미리보기 **안쪽이 아닌** 모든 스크롤(편집기 `.cm-scroller`, 보기 화면 `.viewer`, 창) | 닫는다. 기준 링크가 움직였기 때문이다. 문서 캡처 단계에서 받고 `event.target` 이 미리보기 안이면 무시 |
| 창 크기 바뀜(`resize`), 창 포커스 잃음(`blur`) | 닫는다 |
| 미리보기 안 링크를 누름 | 5.3 |
| 4.1 조건이 깨짐 — 설정 끔, 문서 바뀜, 모드 바뀜, 지도·도움말·공유 화면이 뜸 | 닫는다 |
| 연 뒤 대상 판정이 `ok` 가 아니게 됨 — 대상 문서가 지워졌거나 금고가 잠겨 해석기가 더는 그 문서를 풀지 못함 | 닫는다. **금고 잠그기 때 평문이 화면에 남지 않게 하는 규칙이다**(F-405 `unmount` 가 `docs` 를 잠긴 모양으로 바꾸는 그 렌더에서 해석기가 바뀐다, c9) |

- 협업 중 다른 사람이 위쪽을 고쳐 편집기가 스크롤 위치를 보정하면(스크롤 이벤트) 창이 닫힌다. 받아들인다 — 기준 링크가 실제로 움직였다

### 4.4 IME·편집과 부딪치지 않게

- 편집기 `view.composing` 이 참이면 판정하지 않는다(4.1). `compositionstart` 에 대기·창을 모두 닫는다
- **이 기능은 조합 중에 미루는 재계산이 없다.** 창을 여는 것은 포인터 이동이 계기이고, 조합이 끝났다고 따라잡아 열지 않는다 — 조합 뒤 포인터를 다시 움직이면 평소대로 판정한다. 따라서 "미룬 재계산은 조합 끝에 따라잡는다" 불변조건이 걸릴 자리가 없다. 유일하게 decoration 을 바꾸는 4.5 의 `title` 생략은 `setWikiContext` 경로를 타므로 기존 규칙(조합 중 보류, `forceRecalc` 로 따라잡기, F-2018 5.3)을 그대로 따른다
- 창이 열려 있어도 편집기 포커스·커서는 그대로다(4.2-5). 키를 치면 창이 닫히고(4.3) 그 키는 평소대로 편집기에 들어간다 — 첫 글자를 먹지 않는다
- 창은 문서 내용을 바꾸지 않는다. 대상 문서의 `Y.Doc`·실시간 연결을 열지 않는다(5.1)

### 4.5 편집 모드 `title` 툴팁 정리

- 켜져 있으면 브라우저 기본 `title` 툴팁(보이는 글자)이 미리보기 위에 겹쳐 뜬다. 그래서 `WikiContext` 에 `hoverPreview?: boolean` 을 더하고, **참이면 있는 문서 링크의 mark 에서 `title` 속성을 뺀다.** 끊긴 링크의 `title="새 문서 만들기: {대상}"` 은 그대로 둔다(미리보기가 안 뜨는 자리의 유일한 안내다)
- 없거나 거짓이면 지금과 같다 — 기존 단위 테스트(`wikiLinks.test.ts` 의 `title` 기대값)가 그대로 통과한다
- App 은 `wikiContext` `useMemo` 에 `hoverPreview: wikiPreviewPref === 'on'` 을 넣고 의존값에 더한다. 설정을 바꾸면 기존 `setWikiContext` 효과가 편집기에 새 문맥을 넣는다
- 보기 모드 링크에는 원래 `title` 이 없다(c5) — 바꿀 것 없음

### 4.6 포커스와 키보드

- 창은 열릴 때 포커스를 가져가지 않는다(4.2-5). **키보드로 창을 여는 길은 없다** — 편집 모드 링크는 포커스 대상이 아니고, 보기 모드 링크에 Tab 포커스가 가도 열지 않는다. 키보드 사용자는 `Enter` 로 그 문서를 연다. 미리보기는 문서를 열어 볼 수 있는 내용을 먼저 보여 주는 보조 수단이다(12장 Q5)
- 창 안을 누르면(글자 선택, 스크롤 막대 등) 포커스가 창 안 `Viewer`(`tabIndex=0`)로 간다. 그때부터 방향키·PageUp/Down 이 창 안을 스크롤하고, Tab 이 창 안 링크 사이를 옮긴다. 창 안에서 친 키는 창을 닫지 않는다(`Esc` 만 닫는다)
- 포커스가 창 안에 들어올 때(`focusin`) 직전 포커스 요소(`relatedTarget`)를 기억한다. `Esc` 로 닫으면 그 요소가 아직 문서에 있을 때 거기로 돌려준다. 없으면 편집 모드는 편집기(`editorRef.current.focus()`), 보기 모드는 보기 화면 요소에 포커스를 준다
- 포커스가 창 밖 요소로 나가고(`focusout` 의 `relatedTarget` 이 창 밖) 포인터도 창 위에 없으면 닫는다
- 접근성 이름: 창 루트에 `role="dialog"`, `aria-label="{제목} 미리보기"`(제목이 비면 `제목 없는 문서 미리보기`). `aria-modal` 은 두지 않는다 — 비모달이다
- 스크린 리더에 창이 뜬 것을 알리지 않는다(포커스가 안 옮겨 가므로). 받아들인다 — 키보드로 열 수 없는 마우스 보조 기능이다

## 5. 내용

### 5.1 본문을 어디서 읽나 — 한쪽 방향 읽기

- `store.get(대상 id)` 한 번. App 의 `store`(금고 층을 거친 것)를 쓴다 — 로컬은 IndexedDB, 로그인은 원격 캐시(없으면 서버에서 받아 캐시, c7). 열린 금고 문서는 복호화된 평문이 온다
- **열린 `Y.Doc` 을 읽지 않고, 대상 문서의 `Y.Doc`·실시간 연결을 만들지 않는다.** IndexedDB·원격 캐시·D1 본문은 `Y.Text` 에서 한쪽으로 파생된 값이고(CLAUDE.md 불변조건), 이 기능은 그것을 **화면에 그리기만** 하고 어디에도 되써 넣지 않는다
- 그래서 다른 기기·다른 사람이 방금 고친 내용이 아직 캐시에 없으면 미리보기는 그 전 저장본이다. 열어 보면 최신이 보인다. 창을 연 뒤 대상이 바뀌어도 창 내용은 연 순간의 것이다(다시 읽지 않는다)
- 지금 문서는 판정에서 빠지므로(`self`) 편집 중인 본문과 저장본이 어긋나 보일 일이 없다
- 공유받은 문서(`role` `edit`·`view`)는 **읽지 않는다**(`shared` 안내, 6장). 목록이 본문을 비워 두고(c8) `get` 으로 읽으면 네트워크 요청 + 원격 캐시에 들어가 오프라인 부팅 때 내 문서처럼 보일 수 있기 때문이다(c8, 추론). 12장 Q1

### 5.2 무엇을 그리나

- `slicePreviewText(본문)` 결과를 `renderMarkdown(text, { resolveWikiLink, sourceLines: true })` 로 바꿔 `Viewer` 에 넘긴다. 보기 모드와 같은 렌더러·같은 컴포넌트다 — 프론트매터 표, 콜아웃, 작업 목록(비활성 체크박스), 코드, 수식(KaTeX), 이미지, mermaid 가 보기 모드와 같게 나온다. 수정할 수 없다(보기 모드가 원래 읽기 전용)
- `Viewer` 에 주는 값: `html`, `theme`(앱 테마), `title`(대상 문서 제목 — 본문 위 `h1.doc-title-view`), `onOpenWikiLink`(5.3), `resolveAttachment`(5.5). `breadcrumb`·`onContextMenu`·`codeCopy` 는 주지 않는다 — 우클릭은 브라우저 기본 메뉴다
- `resolveWikiLink`(창 안 링크 모양): 대상 `''` 이면 `#/d/{미리보기 문서 id}`, 아니면 `wikiResolver.resolve(target, 미리보기 문서의 folderId)` 가 풀면 `#/d/{id}`, 못 풀면 null(끊긴 링크 모양). **해석 기준 폴더가 지금 문서가 아니라 미리보기 문서의 폴더**다 — 그 문서를 열었을 때 보이는 링크와 같은 결과가 나와야 한다(F-2018 같은 폴더 우선)
- 잘렸으면(`truncated`) 본문 아래에 안내 줄과 `문서 열기` 버튼(6장). 버튼은 미리보기 문서를 연다(5.3 과 같은 흐름) — 창 안에서 끝까지 보려면 문서를 연다
- `[[문서#제목]]` 링크의 미리보기는 렌더 뒤 그 제목이 창 맨 위에 오도록 창 안을 스크롤한다 — `findHeadingLine(자른 본문, 제목)`(`src/viewer/headingTarget.ts`)으로 줄을 찾고 `findViewerHeadingElByLine`(`src/app/outlinePosition.ts`)으로 요소를 찾는다. 못 찾거나(없는 제목, 잘린 뒤쪽) 제목이 없으면 맨 위. 알림은 띄우지 않는다
- 창 안의 이미지·mermaid 는 보기 모드처럼 그린 뒤에 채워진다. 창 높이는 최대 높이 안에서 늘어난다(3.2 는 최대 높이로 이미 판정했다)

### 5.3 창 안에서 누르기

| 누른 것 | 동작 |
| --- | --- |
| 이어진 위키링크 | 그 문서를 연다 + 창을 닫는다. 해석 기준은 **미리보기 문서**(5.2) |
| 끊긴 위키링크 | 그 제목으로 새 문서를 만들어 연다 + 닫는다. 새 문서 폴더는 `findLinkFolder(target, 미리보기 문서 폴더)` 가 찾은 곳, 없으면 **미리보기 문서와 같은 폴더**(F-131 5장 "링크를 쓴 문서와 같은 폴더" 규칙을 미리보기 문서에 적용) |
| `[[#제목]]` | 미리보기 문서를 열고 그 제목으로 이동 + 닫는다 |
| 바깥 링크·이미지 링크(`<a target="_blank">`) | 브라우저 기본 동작(새 탭, F-123) 그대로. 창은 **그 클릭 처리가 끝난 다음 작업에서** 닫는다 — 기본 동작이 끝나기 전에 요소를 떼지 않게 |
| `문서 열기`(잘림 안내) | 미리보기 문서를 연다 + 닫는다 |
| 글자·빈 곳·체크박스(비활성) | 아무것도 안 한다. 창이 남는다. 글자 선택·복사가 된다 |

- 여는 흐름은 App 의 `openWikiLinkTarget` 하나를 쓴다. 이 함수에 **선택 인자 `source?: { docId: string; folderId: string | null }`** 를 더한다. 주면 해석·`findLinkFolder`·새 문서 폴더의 기준이 `currentFolderId` 대신 `source.folderId` 이고, 대상 `''` 은 `source.docId` 를 뜻한다(그 문서를 열고 제목 이동). 안 주면 지금과 같다 — 기존 호출부(편집기·보기 모드·지도)는 바꾸지 않는다
- 계약: `openWikiLinkTarget(target: string, heading?: string | null, source?: { docId: string; folderId: string | null }): Promise<void>`. `WikiLinkPreview` 에는 `(target, heading) => …` 로 `source` 를 묶어 `Viewer.onOpenWikiLink` 에 넘긴다 — `Viewer` 의 prop 모양은 그대로다
- 그 밖의 여는 규칙(저장 대기 입력 flush, 해시 push, 보기 모드 유지, 금고 폴더면 금고 열림 확인)은 `openWikiLinkTarget`·`selectDoc` 이 이미 하는 그대로다

### 5.4 상태별 표시

| 상태 | 창 안 |
| --- | --- |
| 읽는 중(열기 지연이 끝났는데 `store.get` 이 아직) | 제목 줄 없이 `불러오는 중…` 한 줄 |
| 읽음, 본문 있음 | 5.2 |
| 읽음, 본문이 공백뿐 | 제목 `h1` + `빈 문서입니다.` |
| `store.get` 이 null·예외 | `문서를 불러오지 못했습니다.` |
| 판정 `shared` | 제목 + `공유받은 문서는 열어야 볼 수 있습니다.` (읽기를 시작하지 않는다) |
| 판정 `locked`(읽은 결과가 잠긴 모양) | `금고가 잠겨 있어 볼 수 없습니다.` |
| 끊긴 링크·지금 문서 | 창을 열지 않는다(2장) |

- 안내 문구는 모두 `.wiki-preview-note` 한 줄이다. 알림 띠(N-1)를 쓰지 않는다

### 5.5 이미지와 금고 첨부

- 창 안 이미지는 App 의 첨부 해석과 같은 규칙을 **미리보기 문서 기준으로** 적용한다: 금고 첨부는 미리보기 문서가 금고 문서(`e2ee` 있음)일 때만 돌려주고, 아니면 누락 자리 표시(F-406 3.1, F-409 5.4). 지금 `resolveAttachment` 는 "지금 문서" 에 묶여 있으므로(c11) App 은 그 규칙을 문서의 금고 여부를 받는 모양으로 빼서 두 곳이 같이 쓴다. 규칙 자체는 바꾸지 않는다

## 7. 비용 측정 (2026-09-26, 이 PC)

**방법.** 스크래치 패드에서 `src/viewer/renderMarkdown.ts` 를 esbuild 로 묶어(아이콘 `?raw` 는 글자로 읽는 플러그인) Node 24.12 에서 돌렸다. 합성 문서: 절마다 `##` 제목, 한국어 문단(굵게·기울임·인라인 코드·위키링크 2개·바깥 링크), 목록 3줄(작업 목록 포함), 표 3행(칸 안 위키링크), `js` 코드 펜스, 콜아웃, 긴 한국어 문단 — 한 절 약 1.1KB. "수식" 변형은 절마다 인라인 수식 1개 + 블록 수식 1개를 더했다. 렌더는 7회 중앙값. DOM 삽입은 같은 HTML 을 Playwright + Chrome(`channel: 'chrome'`)에서 400×400 `overflow:auto` 상자 안 `.markdown-body` 에 `innerHTML` 로 넣고 `offsetHeight` 로 배치를 강제한 시간, 5회 중앙값(`github-markdown-light.css`·`katex.min.css` 적용). mermaid 는 `src/lib/mermaidRender.ts` 를 브라우저용으로 묶어 같은 Chrome 에서 작은 순서도(노드 4, 간선 3)를 잰 값

| 문서 | 글자 수 | `renderMarkdown` | DOM 넣기 + 배치 | 합 |
| --- | --- | --- | --- | --- |
| 20KB | 11,567 | 4.1 ms | 11.0 ms | 약 15 ms |
| 100KB | 56,572 | 12.2 ms | 52.9 ms | 약 65 ms |
| 100KB + 수식 | 60,082 | 21.2 ms | 108.3 ms | 약 130 ms |
| **1MB** | 570,314 | **168.7 ms** | **557.4 ms** | **약 730 ms** |
| **1MB + 수식** | 604,832 | **318.8 ms** | **965.0 ms** | **약 1.3 s** |
| 1MB 를 **20,000자에서 자름** | 19,971 | 4.9 ms | 21.6 ms | 약 27 ms |
| 1MB + 수식, 20,000자에서 자름 | 19,955 | 8.5 ms | 29.6 ms | 약 38 ms |
| (참고) 10,000자 / 40,000자, 수식 | 9,980 / 39,973 | 5.4 / 17.3 ms | 15.7 / 62.6 ms | 약 21 / 80 ms |

| mermaid 순서도 | 첫 그림(초기화 포함) | 두 번째부터(10개 중앙값 / 최대) |
| --- | --- | --- |
| 한 개 | 136.4 ms | 31.2 ms / 33.6 ms |

결론:
- **전체를 그리면 1MB 문서에서 호버 한 번에 주 스레드가 0.7~1.3초 멈춘다.** 마우스가 링크를 지나갈 때마다 생길 수 있는 비용으로 받아들일 수 없다
- **20,000자에서 자르면 수식이 빽빽해도 40ms 안쪽**이다. 400×400 창은 본문 20줄 남짓을 보여 주므로 20,000자는 스크롤로 여러 화면 분량이다. 그래서 상한을 `WIKI_PREVIEW_CHAR_LIMIT = 20_000` 으로 두고 잘림 안내 + `문서 열기` 를 둔다(12장 Q2)
- 수식은 `renderMarkdown` 안에서 동기로 그려지므로(`src/lib/mathRender.ts` `renderMath`) 상한이 그대로 수식 비용 상한이다
- mermaid 는 `Viewer` 가 그린 뒤 비동기로 채운다. 첫 그림 136ms 는 보기 모드에서 이미 한 번 그렸으면 다시 들지 않는다(모듈 수준 `ensureTheme`). 20,000자 안에 다이어그램이 여럿이면 하나에 약 31ms 씩 더 든다 — 창이 뜬 뒤 채워지므로 뜨는 시점을 늦추지 않는다. 미리보기에서도 그린다(12장 Q4)
- 이미지는 `Viewer` 가 첨부를 읽어 채운다(보기 모드와 같다). 이 값은 재지 않았다
- 이 수치는 **이 PC(데스크톱) 한 대의 값**이고, 느린 기기의 값은 모른다. `store.get` 읽기 시간도 재지 않았다(14장)

## 8. 설정

### 8.1 키

| 키 | 값 | 기본 | 명세 |
| --- | --- | --- | --- |
| `md.wikiPreview` | `on` \| `off` | `on` | F-2044 |

- 기기별 localStorage. 계정·서버에 올리지 않는다. 제품명 없음. `prefs.ts` `PrefMap`·`ALLOWED_KEYS` 에 더한다
- 모르는 값이면 기본값(`on`)으로 읽는다 — `getPref('md.wikiPreview', 'on')` 이 `off` 가 아닌 모든 값을 `on` 으로 다룬다
- 부팅 첫 페인트 스크립트(`BOOT_PAINT_SCRIPT`)는 이 키를 읽지 않는다 — 첫 페인트 모양과 무관하다

### 8.2 자리와 모양

- 설정 대화상자(D-2) **`화면` 탭 맨 끝**(`시작 화면` 다음). 라벨 `위키링크 미리보기`, 세그먼트 `표시` / `숨김`, `labelId` 는 `wiki-preview-label`
  - `화면` 탭인 이유: 편집·보기 두 모드 모두에서 동작하고 문서를 읽는 모양에 관한 것이다. `편집기` 탭은 편집 명령(탭바·들여쓰기·줄 번호·새 문서 템플릿)만 있다(12장 Q3)

- 누르는 즉시 반영하고 저장한다(ia.md 3.15-3). 끄면 열린 창이 닫힌다(4.1)
- `SettingsDialogProps` 에 `wikiPreview?: string`·`onChangeWikiPreview?: (value: string) => void`. 둘 다 있을 때만 그린다

- 여백·제목 크기·그림자의 구체 값은 사람 확인(H3). e2e 에 박지 않는다

## 14. 가정으로 남긴 것 (코드로 확인하지 않은 것)

- `store.get` 한 건의 읽기 시간(IndexedDB·원격 캐시)은 재지 않았다. "열기 지연 500ms 안에 대개 끝난다" 는 가정이다 — 넘으면 `불러오는 중…` 이 잠깐 보인다(5.4)
- c8 의 "공유 문서를 `get` 하면 오프라인 부팅 때 내 문서처럼 보인다" 는 `serverStore.ts` 를 읽고 한 추론이다. 실행해 보지 않았다
- 7장 수치는 이 PC 한 대(데스크톱, Chrome)의 값이다
- Chrome 이 스크롤 뒤 보내는 합성 `pointermove` 가 좌표를 바꾸지 않는다는 점(4.2-1 이 기대는 성질)은 확인하지 않았다. 좌표가 같으면 무시하는 규칙이라, 좌표가 바뀌는 합성 이벤트가 오더라도 결과는 "그 자리 링크에서 500ms 뒤 열림" 이고 스크롤 자체가 창을 닫는다(4.3)
