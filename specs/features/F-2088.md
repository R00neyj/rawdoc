## 2. 범위

### 한다
- 팔레트 명령 `오늘 날짜 넣기`(`2026-09-29` 모양)와 `지금 시각 넣기`(`14:05` 모양)
- 본문(주 에디터)의 선택 자리에 넣는다. 선택이 있으면 바꾼다. 되돌리기 한 번으로 취소된다
- 팔레트를 어디서 열었든(본문·제목 입력·사이드바 버튼·휴대폰 버튼) 편집할 수 있는 문서가 떠 있으면 보인다. 표 칸에서 연 경우만 뺀다(4.1)

### 하지 않는다
- 설정의 형식 칸(사용자 결정 4). 형식을 바꾸고 싶으면 틀 변수 `{{date:형식}}` 이 이미 있다(F-2022 5.2)
- 새 단축키(사용자가 요청하지 않음 — 11장 Q4)
- 날짜와 시각을 한 번에 넣는 셋째 명령(사용자 결정 1 "2개" — 11장 Q7)
- 우클릭 메뉴·상단 탭바·휴대폰 서식 바에 같은 항목 넣기. 우클릭 `삽입 ▸` 에 넣으려면 `EDITOR_COMMANDS` 에 들어가야 하고, 그러면 F-2055 의 "본문에서 연 팔레트에만" 규칙을 따라 휴대폰에서 사라진다(사용자 결정 3 과 부딪힘)
- 명령 줄에 넣을 값 미리 보여 주기(`2026-09-29` 를 오른쪽에) — 11장 Q3
- 넣은 글 앞뒤에 빈칸 붙이기 — 원문을 사용자가 친 그대로 두는 제품 원칙상 넣는 글은 정확히 형식 결과뿐이다(11장 Q5)

## 3. 계약

### 3.1 형식 상수 — `src/lib/templates.ts`

```ts
export const TEMPLATE_DATE_FORMAT = 'YYYY-MM-DD'
export const TEMPLATE_TIME_FORMAT = 'HH:mm'
```

- `expandTemplateVariables` 의 `{{date}}`·`{{time}}` 기본 형식이 이 두 상수를 쓴다(지금은 함수 안 문자열). 팔레트 명령도 같은 상수를 쓴다 — **틀의 `{{date}}` 와 팔레트 `오늘 날짜 넣기` 가 어긋날 수 없게** 원본을 하나로 둔다(U2 가 판정)
- `formatTemplateDate` 는 고치지 않는다. 토큰 `HH`·`mm` 은 0을 채운 24시간제(`pad2(getHours())`)다

### 3.2 넣기 명령 — `src/editor/insertDateTime.ts`

```ts
export const DATETIME_USER_EVENT = 'input.datetime'
export function insertTextAtSelection(text: string): StateCommand
```

규칙:
- `state.readOnly` 면 아무것도 하지 않고 `false`(F-2022 5.6 `insertTemplate` 과 같다)
- 선택 범위 **하나하나를** `text` 로 바꾼다(빈 커서면 그 자리에 끼운다). 각 범위의 커서는 넣은 글 **바로 뒤**의 빈 커서가 된다. 메인 선택은 메인 범위의 것이다
- 트랜잭션 **1개**, `userEvent: DATETIME_USER_EVENT`, `scrollIntoView: true`. 이 `userEvent` 값이 계약이다 — `input.type`·`delete` 로 시작하지 않아 `nextUndoGroup` 이 **새 묶음을 연다**(`JOINABLE_USER_EVENT`, `undoGroup.ts`). 그래서 직전에 친 글과 합쳐지지 않고 `Ctrl+Z` 한 번에 넣은 날짜만 사라진다. `userEvent` 를 **빼면 안 된다** — `nextUndoGroup` 은 `userEvent` 가 없는 트랜잭션도 합칠 수 있다고 본다(`!userEvent ||`)
- 알려진 모양(템플릿·붙여넣기와 같다, F-2022 5.6): 넣은 직후 500ms(`UNDO_GROUP_DELAY_MS`) 안에 넣은 글 끝에 이어 치면 그 글자는 날짜 묶음에 합쳐진다. 따로 끊지 않는다
- 여러 범위: 이 앱의 `src/editor` 에는 `allowMultipleSelections`·`rectangularSelection` 설정이 없다(`grep` 0건). 규칙은 범위가 여럿이어도 정의되게 적었고 U4 가 여러 범위로 판정한다
- 표 원문 범위 안이나 경계에 빈 커서가 있어도 막지 않는다. 편집 모드에서 포커스가 있고 빈 커서가 표 원문 범위 안(처음·끝 포함)이면 표가 원문으로 보인다(`blocks.ts` `showsWidget`, F-139 3.1). 그러니 넣은 날짜가 곧바로 보이고, 그 자리에 글자를 치는 것과 결과가 같다

### 3.3 팔레트 명령 — `src/app/paletteDateTimeCommands.ts`

```ts
export type DateTimeKind = 'date' | 'time'
export function dateTimeText(kind: DateTimeKind, now: Date): string
export const PALETTE_DATETIME_COMMANDS: readonly PaletteActionCommand[]
```

- `dateTimeText` = `formatTemplateDate(now, kind === 'date' ? TEMPLATE_DATE_FORMAT : TEMPLATE_TIME_FORMAT)`
- 명령 2개(5장 표). `kind: 'action'`, `shortcut` 없음, `when` = `Boolean(ctx.dateTime)`, `run` = 실행 순간의 `new Date()` 로 `dateTimeText` 를 만들어 `ctx.dateTime?.insert(글)`
- **시각은 실행 순간 값이다.** 팔레트를 연 순간이 아니라 고른 순간. 팔레트를 연 채 자정을 넘기면 넘긴 뒤의 날짜가 들어간다
- **"오늘" 은 기기의 로컬 시간대다.** `formatTemplateDate` 가 `getFullYear()`·`getMonth()`·`getDate()`·`getHours()` 등 로컬 getter 만 쓴다(코드 확인). 계정·서버 시간대는 보지 않는다
- 등록 자리: `PALETTE_COMMANDS` 에서 **`template.insert` 바로 뒤**(`doc.print` 앞). 이유: 빈 입력 `명령` 구역은 등록 순서라(F-2053 5장) 같은 "본문에 넣기" 묶음인 템플릿 옆에 모인다. 첫 원소는 그대로 `template.insert` 라 "`>` → `Enter` = 템플릿 삽입" e2e 가 그대로다(8장)
- id 영역 `insert.` 는 이 명세가 새로 쓴다. `editor.`(F-2055, 우클릭 메뉴 파생)와 섞지 않는다 — 이 두 명령은 `EDITOR_COMMANDS` 에 없다. 한 번 배포한 id 는 최근·고정 목록(`md.paletteRecent`·`md.palettePinned`)에 저장되므로 바꾸지 않는다(F-2053 3.4)

### 3.4 `PaletteContext.dateTime` — `src/app/paletteContract.ts`

```ts
// 오늘 날짜·지금 시각 넣기 — 선택 필드. 없으면 두 명령이 안 보인다 (F-2088)
dateTime?: { insert: (text: string) => void }
```

- F-2053 3.4 모양 그대로 선택 필드. 기존 단위 테스트의 `ctx()` 도우미들은 이 필드를 안 넘기므로 두 명령이 `when` 거짓 — 기존 개수 단언이 그대로다(8장)
- `editor?`(F-2055)를 쓰지 않는 이유: `editor` 는 본문에서 연 팔레트에만 채워진다(F-2055 4.1). 휴대폰은 팔레트를 버튼으로만 열어(F-2053 결정 10) `editor` 가 늘 비어 있다 — 사용자 결정 3 과 부딪힌다

## 4. 동작

### 4.1 보이는 조건 — `useCommandPalette.ts` 가 **여는 순간** 한 번 정한다

`openPaletteFrom` 이 이미 `editorCommandGates` 를 여는 순간 한 번 계산하는 것(F-2055 4.1)과 같은 자리에서, 아래가 모두 참이면 "날짜 넣기 가능" 과 **그 순간의 `currentDocId`** 를 기억한다. 닫혀 다시 열 때 새로 정한다

1. `canInsertTemplate` 가 참 — F-2022 6.3 조건 그대로(부팅 끝, 공유 링크 화면 아님, 지금 문서의 에디터가 떠 있음, 보기 모드가 `편집`·`원문`, `isReadOnlyDoc` 거짓, 지도·도움말·공유 관리가 덮지 않음). `isReadOnlyDoc` 는 보기 권한 공유(`isReadOnlyByRole`), 잠긴 금고 문서(`isLockedReadOnly`), 다른 탭이 편집권을 가진 복제 탭(`claimReadOnly`), 다른 곳에서 지워짐, 실시간 끊김, 오프라인 보기, 금고 전환 중을 모두 품는다(`App.tsx` 정의)
2. 주 에디터 view 가 있다
3. **표 칸에서 연 것이 아니다.** 둘 중 하나면 표 칸이다
   - 우클릭 갈래가 `fromEditor === false` 를 넘겼다 — `useContextMenu.ts` 는 `cm.place === 'editor'` 를 넘기므로 `false` 는 표 칸 메뉴뿐이다
   - 인자 없이 열렸고 여는 순간 `document.activeElement` 가 `.md-table-widget` 안에 있다(칸 하위 에디터에서 `Ctrl+P`)

| 여는 길 | 날짜·시각 명령 |
| --- | --- |
| 본문 `Ctrl+P`·본문 우클릭 `명령 팔레트…` | 보임 |
| 제목 입력·사이드바·검색 패널 등에서 `Ctrl+P`, 사이드바·상단바 `명령 팔레트` 버튼 | 보임 — 본문의 마지막 선택 자리에 넣는다 |
| 휴대폰 폭(≤600px) 팔레트 버튼(지금은 사이드바 머리·더보기 시트, F-2086 이 옮길 수 있다) | 보임 — 같은 규칙. 폭을 보는 조건이 없다 |
| 표 칸 `Ctrl+P`·표 칸 우클릭 `명령 팔레트…` | 없음 |
| 보기 모드·읽기 전용 문서·공유 링크 화면·홈·도움말·지도·공유 관리 | 없음(1번) |

**표 칸에서 숨기는 이유** — F-2055 4.1 과 같은 사정이다. ① 팔레트 입력칸이 포커스를 가져가면 칸 하위 에디터가 `blur` 로 끝나 칸 안에 넣을 자리가 사라진다 ② 칸 우클릭 갈래는 팔레트를 열기 전에 주 에디터 선택을 표 첫머리로 옮긴다(`posAtDOM(표 wrap)`). 거기 넣으면 사용자가 고른 칸이 아니라 표 앞 줄 머리에 날짜가 붙는다. 칸 안에 날짜를 넣는 방법은 11장 Q6

**선택이 없는 문서:** 문서를 열고 본문을 한 번도 누르지 않았으면 주 에디터 선택은 `EditorState` 의 첫 값(문서 맨 앞)이다. 그 자리에 넣는다 — 템플릿 삽입(F-2022)이 같은 조건에서 같은 자리를 쓴다

### 4.2 선택 자리 — 따로 저장하지 않는다
F-2055 4.2 를 그대로 따른다. 주 에디터 선택은 포커스를 잃어도 `EditorState.selection` 에 남고, 팔레트가 열린 동안 원격 갱신이 오면 CM6 가 선택을 변경에 맞춰 옮긴다. 여는 순간 위치를 따로 적어 두지 않는다(적어 둔 위치는 원격 갱신에 맞춰 옮겨지지 않는다)

### 4.3 실행 — 훅의 `dateTime.insert(text)`

`CommandPalette.runAction` 이 `onClose()` 뒤 곧바로 `run` 을 부른다(코드 확인). 훅은 이 순서로 한다

1. **그만둘 때(조용히, 알림 없음):** 주 에디터 view 가 없음 / 지금 문서(`currentDocIdRef`)가 4.1 에서 기억한 문서와 다름 / `readOnlyDocRef` 가 참 / `isComposing(view)` 가 참. 읽기 전용 확인을 빼면 안 된다 — CM6 `EditorState.readOnly` 는 사용자 입력만 막고 코드의 `dispatch` 는 막지 않는다(F-2055 4.3-1 이 `readOnlyExtensionsFor` 로 확인)
2. **글 넣기는 바로(같은 작업 안):** `insertTextAtSelection(text)` 를 주 view 로 실행. 로컬 트랜잭션이라 `y-codemirror.next` 가 `Y.Text` 로 옮긴다 — 원본은 여전히 `Y.Text` 하나다(불변조건)
3. **포커스·커서 되돌리기는 팔레트가 실제로 닫힌 뒤:** `runAfterPaletteClose` 로 쟁여 두고(F-2054 5.1 — `Dialog` 의 `close` 이벤트가 연 곳으로 포커스를 돌린 **다음** 0ms 타이머로 돈다), 그 안에서 문서가 그대로면 주 view `focus()` + 메인 선택 머리로 `scrollIntoView`. `runPaletteEditorCommand`(F-2055)의 표가 아닌 갈래와 같은 두 동작이다. 제목 입력에서 열었으면 `Dialog` 가 제목으로 돌려준 포커스를 이 단계가 본문으로 옮긴다
- 넣은 뒤 커서는 넣은 글 바로 뒤(3.2). 선택이 있었으면 선택은 사라지고 날짜 뒤 빈 커서다

### 4.4 IME 불변조건과의 관계
- F-2055 4.4 와 같다. 명령은 팔레트 입력칸에서 `Enter`·클릭으로 고를 때만 실행되고, 그 순간 포커스는 입력칸이라 에디터는 조합 중일 수 없다. 조합 중 미룬 재계산·원격 갱신 대기열(F-303)과 닿지 않는다
- 조합 중 본문에서 `Ctrl+P` 를 누르면 입력칸이 포커스를 가져가며 조합이 끝나고(포커스를 잃은 조합은 끝난 것, F-303 5.4) CM6 `compositionend` 경로가 미룬 재계산을 따라잡는다. 4.3-1 의 `isComposing` 확인은 그 가정이 깨졌을 때 글을 망가뜨리지 않으려는 방어다. 실제 한글 IME 는 사람 확인 H2

- 라벨은 사용자가 쓴 말 그대로다. F-2055 의 `{묶음}: …` 접두어는 우클릭 메뉴에서 옮겨 와 문맥을 잃는 이름(`본문`·`표`)을 위한 것이고, 이 두 이름은 혼자 읽힌다. 다른 모양은 11장 Q1

- `삽입` 을 keywords 에 넣어 `>삽입` 에 F-2055 삽입 명령과 함께 나온다(확인 (a) — 첫 결과는 그대로 `삽입: 링크 추가`)
- **keywords 에 넣지 않은 말:** `넣기`(라벨에 이미 있다), `템플릿`·`틀`(`template.insert` 와 섞인다), `문서`(F-2053 문서 찾기와 겹친다), `댓글`·`알림`·`금고`·`인쇄`·`pdf`(기존 e2e 가 0개·1개를 단언 — F-2055 5장과 같은 이유), `date:`·`YYYY` 같은 형식 글자

## 6. 상태·오류·접근성
- 새 UI 문구는 라벨 2개뿐이다. 알림 없음 — 4.3-1 에서 그만두는 경우는 팔레트가 연 동안 문서·권한이 바뀐 드문 경우라 우클릭·F-2055 명령과 같이 조용히 둔다
- 보일 명령이 없을 때의 문구는 F-2053 5.4 상태 문구(`맞는 명령이 없습니다`)가 그대로 덮는다
- 옵션 접근 이름 = 라벨(F-2022 그대로). 실행 뒤 포커스는 주 에디터로 간다 — 사라진 요소나 `body` 에 남지 않는다

**Q1. 라벨 모양 — 기본값: `오늘 날짜 넣기` / `지금 시각 넣기`**

## 12. 확인한 것과 가정

### 12.1 코드를 읽거나 돌려 확인한 것
- 머리의 확인 (a)·(b)·(c)
- `formatTemplateDate` 는 로컬 getter(`getFullYear`·`getMonth`·`getDate`·`getHours`·`getMinutes`)만 쓰고 `HH`·`mm` 은 `pad2` 로 두 자리다. `expandTemplateVariables` 의 기본 형식은 `'YYYY-MM-DD'`·`'HH:mm'` 문자열이다(`src/lib/templates.ts`)
- `canInsertTemplate` 에는 폭 조건이 없다. `openPaletteFrom` 은 `fromEditor ?? (activeElement === mainView.contentDOM)` 로 본문 여부를 정하고 `editor` 필드를 그 값으로만 채운다 — 그래서 휴대폰 버튼으로 연 팔레트에는 F-2055 명령이 없고, 이 명세가 `editor?` 를 쓰면 휴대폰에서 사라진다(`useCommandPalette.ts`)
- 우클릭 갈래는 `openPaletteFromRef.current(cm.place === 'editor')` 한 곳뿐이다(`useContextMenu.ts`, `grep openPaletteFromRef`)
- `isReadOnlyDoc` = `isReadOnlyByRole || isLockedReadOnly || claimReadOnly || isDeletedElsewhere || liveStopped || isOfflineView || isConvertingDoc || (isRealtime && docSession.readOnly)` (`App.tsx`)
- `nextUndoGroup` 은 `userEvent` 가 없거나 `input.type`·`delete` 로 시작하면 합칠 수 있다고 본다. `insertTemplate` 은 `'input.template'` 으로 새 묶음을 연다(`undoGroup.ts`·`insertTemplate.ts`)
- 편집 모드 표는 포커스 + 빈 커서가 표 원문 범위 안(처음·끝 포함)이면 원문으로 보인다(`blocks.ts` `showsWidget`·`emptyCursorInside`) — 3.2 에서 표 자리를 막지 않는 근거
- `closePalette` 는 한 판에 두 번 불리고 두 번째(`Dialog` 의 실제 `close`)에서 쟁여 둔 일을 `setTimeout(fn, 0)` 으로 돌린다(`usePaletteOpen.ts`). `CommandPalette.runAction` 은 `onClose()` 뒤 `cmd.run(context)`
- `shortcutCatalog.test.ts` U9 는 `shortcut` 이 있는 팔레트 명령만 대응표와 맞춘다
- `src/editor` 에 `allowMultipleSelections`·`rectangularSelection`·`crosshairCursor` 가 없다(`grep` 0건)
- 표 위젯 바깥 요소의 클래스 `md-table-widget`(`tableWidget.ts` `wrap.className`)

### 12.2 가정으로 남긴 것
- **CM6 의 여러 선택 기본값.** `allowMultipleSelections` 를 켜지 않으면 선택이 한 범위로 줄어든다고 보고 "실제로는 범위 하나" 라 적었다. 이 작업 트리에 `node_modules` 가 없어 `@codemirror/state` 소스로 확인하지 못했다. 3.2 규칙은 범위가 여럿이어도 정의되게 적어 결과가 이 가정에 기대지 않는다
- **`EditorState.replaceSelection` 류로 구현하면 커서가 넣은 글 뒤로 간다** — 같은 이유로 소스 확인을 못 했다. 3.2 는 결과(커서 = 넣은 글 끝)만 계약으로 두고 U4 가 판정한다
- **휴대폰에서 포커스 복귀 뒤 가상 키보드가 뜨는지** — 돌려 보지 않았다(H1)
- 칸 하위 에디터에서 `Ctrl+P` 가 창까지 올라가 팔레트가 열리는지 — F-2055 14.1 처럼 코드로만 읽었다(H4)
- 확인 (a) 는 `@codemirror/*` 를 빈 대역으로 바꿔 묶은 번들에서 돌렸다. 라벨 getter 가 있는 명령(`comment.toggleRail` 등)은 모듈 변수 기본값의 라벨로 걸렀다 — 기존 e2e 검색어는 그 라벨들과 무관한 말이라 결론에 영향이 없다고 본다
