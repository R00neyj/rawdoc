## 1. 범위

### 한다

- 설정 대화상자(D-2) 안을 **왼쪽 탭 목록 + 오른쪽 패널**로 바꾼다. ARIA `tablist`/`tab`/`tabpanel`, 자동 활성화 (3.3)
- 지금 있는 설정 9개를 탭 3개(`화면`·`편집기`·`데이터`)로 나눠 담는다 (3.1)
- 보일 항목이 없는 탭은 그리지 않는다. 보일 탭이 1개뿐이면 탭 목록 자체를 그리지 않는다 (3.4) — 공개 보기 화면이 지금 모습 그대로 남는다
- `전체 내보내기`(F-282 뒤에는 `가져오기…` 도)를 `닫기` 와 같은 대화상자 기본 버튼 모양으로 (3.6)
- `전체 내보내기` 옆 안내 문구의 인라인 `style` 을 CSS 로 옮긴다 (3.6)
- 좁은 창에서 탭 목록을 가로 한 줄로 눕힌다 (3.5)
- 기존 e2e 회귀 수정 5개 파일 (7장)

### 하지 않는다

- **설정 항목을 늘리거나 줄이지 않는다.** 이번 명세는 있는 것을 다시 묶는 일이다. 각 설정의 값·기본값·반영 동작은 그대로다
- 탭 UI 라이브러리·새 의존성 (`@radix-ui/react-tabs` 등). 직접 만든다
- 선택한 탭 기억 (3.7 — 기억하지 않는다). 새 `localStorage` 키를 만들지 않는다
- `src/app/EditorToolbar.tsx` 의 탭 구현을 공통 컴포넌트로 뽑는 일. 모양·동작이 달라(가로 `.seg` 안 세그먼트 vs 세로 목록) 합치면 둘 다 나빠진다
- `src/app/Dialog.tsx` 의 포커스·Esc·바깥 클릭 구조 변경. `initialFocusRef` 가 가리키는 **대상만** 바꾼다 (3.3)
- 설정 검색, 탭 안 소제목, 설정별 설명 문구
- `.dialog-actions` 의 `닫기` 자리·정렬 변경

## 3. 요구사항

### 3.1 탭 구성

| 탭 | id | 들어가는 설정 (위에서 아래 순서) | 지금 어디에 있나 |
| --- | --- | --- | --- |
| `화면` | `screen` | 테마 / 제목 서체 / 본문 서체 / 글자 크기 / 시작 화면 | 1·2·3·4·6번째 |
| `편집기` | `editor` | 탭바 / 들여쓰기 / 줄 번호 | 5·7·8번째 |
| `데이터` | `data` | 전체 내보내기 (F-282 뒤 `가져오기…`) | 9번째 |

- 탭 목록 순서는 사용자가 고른 그림 그대로 `화면` → `편집기` → `데이터`
- 탭 안 항목 순서는 **지금 세로 1열 순서를 그대로 쓴다.** 기존 e2e 의 순서 단언과 사용자가 익숙한 순서를 함께 지킨다
- `시작 화면`을 `화면` 에 두는 근거:
  1. 사용자가 고른 그림의 분류는 3개고, 4번째 탭을 만들면 사용자가 고르지 않은 안(4그룹)으로 되돌아간다
  2. `시작 화면`(`홈` / `마지막 문서`, F-232 3.4)은 **앱을 열었을 때 어느 화면이 뜨는가**를 정한다. 편집기 동작(탭바·들여쓰기·줄 번호)과는 무관하고 데이터도 아니다
  3. 사용자가 본 그림의 4항목(테마·제목 서체·본문 서체·글자 크기)은 맨 위에 그 순서 그대로 남고, `시작 화면` 만 그 아래에 붙는다
  4. 부수 효과로 `e2e/homeScreen.spec.js` `F-232 A5` 가 고치지 않아도 통과한다(기본 탭에 있으므로)
- `데이터` 탭에서는 `데이터` 라벨 `<span>`(지금의 `#data-export-label`)을 **지운다.** 탭 이름이 그 역할을 하고, 같은 말이 대화상자 안에 두 번 보이면 안 된다. 이 `id` 를 참조하는 곳은 없다(코드 전체 확인)
- 탭 이름에 `편집` 을 쓰지 않고 `편집기` 로 하는 이유: `편집` 은 보기 모드 이름으로 이미 잡혀 있다 (`specs/ia.md` 6장 문구표)

### 3.2 순수 함수 (`src/app/settingsTabs.ts`)

테스트 환경이 `node` 라 컴포넌트 테스트를 쓸 수 없다. 판정할 수 있는 로직만 순수 함수로 뗀다

```ts
export type SettingsTabId = 'screen' | 'editor' | 'data'

// 각 탭에 그릴 항목이 하나라도 있는지
export type SettingsTabAvailability = { screen: boolean; editor: boolean; data: boolean }

// 보일 탭을 화면 → 편집기 → 데이터 순서로 돌려준다
export function visibleSettingsTabs(has: SettingsTabAvailability): SettingsTabId[]

// 방향키·Home·End 로 갈 다음 탭 자리. 범위를 벗어나면 순환한다.
// 그 밖의 키는 current 를 그대로 돌려준다(호출한 쪽이 preventDefault 를 하지 않는다)
export function nextTabIndex(current: number, count: number, key: string): number
```

`nextTabIndex` 규칙:

| key | 결과 |
| --- | --- |
| `ArrowDown`, `ArrowRight` | `(current + 1) % count` |
| `ArrowUp`, `ArrowLeft` | `(current - 1 + count) % count` |
| `Home` | `0` |
| `End` | `count - 1` |
| 그 밖 | `current` |

- 네 방향을 모두 받는 이유는 3.5(좁은 창에서 가로로 눕는다)
- `count` 가 `0` 이면 `0` 을 돌려준다(방어. 실제로는 탭이 0개면 대화상자에 패널만 그린다)

`SettingsDialog` 가 `has` 를 만드는 규칙 — 지금 props 조건 그대로다

| 탭 | 조건 |
| --- | --- |
| `screen` | 항상 `true` (테마·서체·글자 크기는 모든 화면에 있다) |
| `editor` | `toolbar` 항목이 있거나 편집기 설정(`indent`+`lineNumbers`)이 있을 때. 지금의 `toolbar !== undefined && onChangeToolbar !== undefined` 와 `showEditorSettings` 를 `OR` 로 묶는다 |
| `data` | `onExportAll` 이 있을 때 |

### 3.3 접근성 — 탭 패턴

**자동 활성화(automatic activation)를 쓴다.** 방향키로 옮기면 그 자리에서 바로 전환된다. Enter·Space 를 따로 누르지 않는다

근거:

- WAI-ARIA Authoring Practices 의 Tabs Pattern 은 **패널 내용을 보여 주는 데 시간이 걸리지 않으면 자동 활성화를 권한다.** 여기 패널은 세그먼트 몇 개뿐이라 비용이 없다(가져오는 데이터도, 그리는 비용도 없다)
- 앱 안에 이미 자동 활성화 선례가 있다 — 편집기 탭바(`src/app/EditorToolbar.tsx` 83~91행, F-233 A8)가 `ArrowLeft`·`ArrowRight` 로 바로 전환한다. 같은 앱에서 탭 두 벌이 서로 다르게 움직이면 안 된다
- 수동 활성화는 선택하지 않은 탭을 훑어볼 수 있게 하는 것이 목적인데, 설정처럼 항목이 적고 즉시 반영되는 화면에서는 이득이 없고 키 입력만 늘어난다

| 항목 | 값 |
| --- | --- |
| 목록 | `<div role="tablist" aria-label="설정 분류" aria-orientation={세로면 "vertical", 가로면 "horizontal"}>` |
| 탭 | `<button type="button" role="tab" id={`settings-tab-${id}`} aria-selected={활성} aria-controls={`settings-panel-${id}`} tabIndex={활성 ? 0 : -1}>` |
| 패널 | `<div role="tabpanel" id={`settings-panel-${활성 id}`} aria-labelledby={`settings-tab-${활성 id}`}>` |

- **로빙 tabindex** — 활성 탭만 `tabIndex=0`, 나머지는 `-1`. 목록 전체가 Tab 한 번에 지나간다
- **패널에는 `tabIndex` 를 주지 않는다.** 패널 안에 늘 포커스 받을 수 있는 버튼이 있다(APG: 포커스 가능한 자식이 있는 tabpanel 은 tabindex 를 갖지 않는다)
- **활성 탭의 패널만 DOM 에 그린다.** 숨긴 패널을 남겨 두면 안 보이는 세그먼트 버튼이 Tab 순서·접근성 트리에 남는다 (`EditorToolbar` 와 같은 방식)
- 방향키 처리는 `tablist` 의 `onKeyDown` 한 곳에서 한다. `nextTabIndex` 가 `current` 와 다른 값을 주면 `preventDefault()` → 그 탭을 활성으로 바꾸고 → 그 탭 버튼에 `focus()`
- `Enter`·`Space` 는 브라우저 기본 버튼 클릭이라 따로 다루지 않는다(이미 활성인 탭을 다시 누르는 것이라 아무 일도 없다)
- `Tab` 키: 활성 탭 버튼 → **패널 안 첫 조작 요소** → … → `닫기`. `Shift+Tab` 은 반대. 대화상자가 `<dialog showModal()>` 이라 밖으로 나가지 않는다
- 탭을 바꿔도 **포커스는 그 탭 버튼에 남는다.** 패널로 옮기지 않는다 (APG 자동 활성화 그대로)

**`Dialog` 의 `initialFocusRef` 와 맞물리는 방식**

- `Dialog.tsx` 는 고치지 않는다. `initialFocusRef` 가 가리키는 대상만 바꾼다
- 탭 목록을 그릴 때(탭 2개 이상): `initialFocusRef` = **활성 탭 버튼**(= `화면`). 대화상자의 첫 조작 요소가 탭 목록이고, 여기서 시작해야 탭이 있다는 것을 키보드·스크린 리더 사용자가 안다. 세그먼트 버튼부터 시작하면 왼쪽 목록을 건너뛴 자리가 된다
- 탭 목록이 없을 때(3.4, 공개 보기): **지금 그대로** `테마` 의 현재 선택 버튼
- 닫기(`닫기`·Esc·바깥 클릭)와 연 요소로의 포커스 복귀는 `Dialog` 가 하던 그대로다 (`specs/ia.md` 3.15 7번)

### 3.4 빈 탭 — 그리지 않는다

| 경우 | 동작 |
| --- | --- |
| 그 탭에 그릴 항목이 하나도 없다 | **그 탭을 그리지 않는다.** 비활성(`disabled`) 탭으로 남기지 않는다 |
| 보일 탭이 1개뿐이다 | **탭 목록 자체를 그리지 않는다.** 그 탭의 항목만 지금처럼 세로로 그린다 |
| 보일 탭이 0개다 | 있을 수 없다 — `화면` 은 항상 있다 (3.2) |

근거:

- 누를 수 없는 탭이 목록에 남으면 "여기에 뭔가 있는데 내가 못 쓴다" 로 읽힌다. `specs/ia.md` 8장 "빈 공간이나 비활성 UI 로 미리 만들지 않는다" 와 같은 방침이다
- 탭이 1개인 `tablist` 는 ARIA 상 의미가 없다(고를 것이 없다)
- **공개 보기 화면(`PublicView`, F-230)이 이 두 번째 규칙에 걸린다.** 거기는 `화면` 탭 4항목(테마·제목 서체·본문 서체·글자 크기)만 있고 `시작 화면`(F-232 3.4)·`탭바`(F-233 3.5)·편집기 설정(F-230 2.2)·`데이터`(F-281 3.6)를 주지 않는다 → 탭 목록 없이 **지금과 똑같은 모습**으로 남는다. `e2e/publicView.spec.js` `F-230 A1`·`A4`, `e2e/homeScreen.spec.js` `F-232 A10`, `e2e/editorToolbar.spec.js` `F-233 A7` 이 고치지 않아도 통과한다

### 3.5 좁은 창

| 창 너비 | 탭 목록 |
| --- | --- |
| 460px 이상 | **왼쪽 세로 목록** (기본) |
| 460px 미만 | **위 가로 한 줄** — 탭 3개가 가로로 늘어서고 그 아래가 패널 |

- 기준을 460px 로 잡은 근거: 대화상자 폭은 `min(W, 100vw - 32px)`(F-224 2.2)라 창이 좁아지면 대화상자도 같이 좁아진다. 460px 아래에서는 대화상자가 428px 이하가 되어 왼쪽 목록 + `테마` 세그먼트(선택지 4개)가 한 줄에 들어가지 않는다. F-224 A4 의 판정 창(400×800)이 이 안에 든다
- 눕히는 것은 **CSS(`@media`)만으로** 한다. 3.4 의 규칙·항목·순서는 그대로다
- `aria-orientation` 은 실제 배치와 맞춘다 — `SettingsDialog` 안에서 같은 미디어 쿼리(`(max-width: 459px)`)를 `matchMedia` 로 읽어 `vertical` / `horizontal` 을 넣는다. `src/app/PublicView.tsx`·`App.tsx` 의 `useNarrow` 와 같은 모양이고 상태 하나뿐이다
- 방향키는 **배치와 상관없이 네 방향 모두** 같게 동작한다 (3.2). 세로일 때 `ArrowLeft`/`ArrowRight` 도 받는 것은 APG 가 허용하는 선택 사항이고, 배치가 바뀌는 화면에서 사용자가 막히지 않게 하는 쪽이 낫다
- 접는 방식(아코디언)·드롭다운으로 바꾸는 방식은 쓰지 않는다. 탭이 3개뿐이라 가로 한 줄에 들어간다

### 3.6 `데이터` 탭 버튼 정리

**지금**

```jsx
<div className="dialog-field">
  <span id="data-export-label">데이터</span>
  <div>
    <button type="button" onClick={onExportAll} disabled={exportAllDisabled}>전체 내보내기</button>
    {exportAllDisabled && <span style={{ marginLeft: 8, fontSize: 12.5, color: 'var(--muted)' }}>온라인일 때 내보낼 수 있습니다</span>}
  </div>
</div>
```

`전체 내보내기` 는 클래스가 없어 `.dialog-actions button` 규칙에 걸리지 않고 **브라우저 기본 버튼**으로 나온다. 안내 문구는 인라인 `style` 로 박혀 있다

**바꾼 뒤**

```jsx
<div className="dialog-btn-row">
  <button type="button" className="dialog-btn" onClick={onExportAll} disabled={exportAllDisabled}>전체 내보내기</button>
  {/* F-282 뒤: <button type="button" className="dialog-btn" onClick={onImport}>가져오기…</button> */}
  {exportAllDisabled && <span className="dialog-note">온라인일 때 내보낼 수 있습니다</span>}
</div>
```

- 버튼 모양은 **값을 다시 적지 않고** `.dialog-actions button` 규칙에 `.dialog-btn` 을 더해 받는다 (3.8). `닫기` 와 바이트 단위로 같은 모양이 보장된다
- 안내 문구는 이미 같은 값(`12.5px` / `var(--muted)`)을 가진 `.dialog-note` 를 그대로 쓴다. 행 안에 들어가므로 여백·정렬만 `.dialog-btn-row .dialog-note` 한 줄로 덮는다
- `데이터` 라벨 `<span>` 은 지운다 (3.1)
- 문구 `온라인일 때 내보낼 수 있습니다` 는 F-281 그대로. 바꾸지 않는다

### 3.7 선택한 탭을 기억하나 — 기억하지 않는다

**대화상자를 닫았다 열면 항상 첫 탭(`화면`)이다.**

- 설정은 자주 여는 화면이 아니다. 늘 같은 자리에서 시작하는 편이 "내가 어디를 마지막에 봤더라" 보다 예측 가능하다
- 기억하려면 `localStorage` 키를 새로 만들고 `src/app/prefs.ts` 의 허용 목록·`src/app/prefs.test.ts`·`specs/architecture.md` 4장을 함께 늘려야 하는데, 얻는 것이 적다
- 3.3 의 초기 포커스(활성 탭 버튼)도 조건 분기 없이 늘 같은 버튼이 된다
- `SettingsDialog` 는 `<dialog>` 가 닫혀 있어도 마운트된 채로 남으므로, **`open` 이 `true` 로 바뀔 때 활성 탭을 첫 탭으로 되돌린다** (그러지 않으면 마지막에 본 탭이 남는다)
- 나중에 기억하기로 바꾼다면 키 이름은 `md.settingsTab` 이다 — `md.` 접두사 고정, 제품명을 쓰지 않는다 (CLAUDE.md 불변조건, `specs/architecture.md` 4장). 이번에는 만들지 않는다. Q2

**새 클래스 5개만** 만든다. 색 hex 를 쓰지 않는다 — 선택 표시는 기존 세그먼트 규칙을 그대로 받는다

### 3.9 대화상자 폭

**`Dialog` 에 `size="wide"` 를 준다 (520px).** Q1

- 지금 D-2 는 기본 폭 420px 이다. 안쪽 여백(18px×2)·테두리를 빼면 내용 폭이 382px 이고, `테마` 세그먼트(`시스템`·`화이트`·`세피아`·`다크`)가 그 폭 안에서 겨우 한 줄이다
- 왼쪽 목록(84px) + 간격(14px)을 빼면 패널이 **284px** 로 줄어 세그먼트가 줄바꿈될 위험이 있다
- `size="wide"`(520px)면 패널이 **384px** 로 지금 내용 폭과 거의 같다 → **어느 세그먼트도 지금과 다르게 보이지 않는다**
- 520px 은 이미 쓰는 값이다(D-4 사람 초대·D-5 API 토큰, F-224 2.2). 새 폭을 만들지 않는다
- 좁은 창에서는 `min(520px, 100vw - 32px)` 라 F-224 A4 의 400×800 판정값 **368px 이 그대로다**
- 대가: `specs/features/F-224.md` 2.2 와 `specs/design.md` 4장이 D-2 를 420px 쪽에 적어 뒀다 → 2장 "갱신 대상" 과 `e2e/dialogLayout.spec.js` `F-224 A2` 수정이 따라온다. **승인 항목 Q1**

## 4. 구조 (`SettingsDialog.tsx`)

```jsx
<Dialog open size="wide" titleId="settings-title" initialFocusRef={탭이 있으면 활성탭 ref, 없으면 checkedRef}>
  <h2 id="settings-title">설정</h2>

  {tabs.length > 1 ? (
    <div className="settings-body">
      <div className="settings-tabs" role="tablist" aria-label="설정 분류"
           aria-orientation={narrow ? 'horizontal' : 'vertical'} onKeyDown={handleTabKeyDown}>
        {tabs.map(…)}          ← role="tab", 로빙 tabindex (3.3)
      </div>
      <div className="settings-panel" role="tabpanel"
           id={`settings-panel-${activeTab}`} aria-labelledby={`settings-tab-${activeTab}`}>
        {활성 탭의 Segment 들}   ← 3.1 순서 그대로
      </div>
    </div>
  ) : (
    <>{그 탭의 Segment 들}</>   ← 3.4: 탭 목록 없음. 지금 모습 그대로
  )}

  <div className="dialog-actions"><button onClick={onClose}>닫기</button></div>
</Dialog>
```

- `Segment` 컴포넌트와 각 옵션 상수(`THEME_OPTIONS`~`TOOLBAR_OPTIONS`)는 **그대로 둔다.** 기존 e2e 가 `#theme-label` → 부모(`.dialog-field`) → `[role="radio"]` 경로로 찾으므로 `.dialog-field` + `<span id>` 구조가 유지돼야 한다
- props 와 그 선택 규칙(`toolbar`·`startScreen`·`indent`·`lineNumbers`·`onExportAll` 이 없으면 안 그린다)은 그대로다. `App.tsx`·`PublicView.tsx` 는 **고치지 않는다**
- 활성 탭 상태는 `useState<SettingsTabId>(tabs[0])`. `open` 이 `true` 가 될 때 `tabs[0]` 으로 되돌린다 (3.7)
- 보일 탭이 줄어 활성 탭이 사라지는 경우는 없다(props 가 화면 안에서 바뀌지 않는다). 방어로 `tabs.includes(activeTab)` 이 아니면 `tabs[0]` 을 쓴다
