광고 자리 — 확인된 사실 (명세 쓸 때 출발점)
- `/p/{token}` 공개 문서 뷰는 별도 페이지가 아니라 **앱 index.html 그 자체**(`worker/publicPage.ts` — og 메타만 치환, 본문은 클라이언트 PublicView). 응답에 `X-Robots-Tag: noindex` 라 검색 유입도 없다 → 광고 면에서 뺐다
- `site/render.ts` 가 만드는 `/guides/{slug}`(17개)·`/guides`·`/help`·`/changelog`·`/privacy`·`/terms` 는 자기 `<head>` 를 가진 정적 페이지 — 앱 번들·사용자 본문과 분리되고 색인도 된다. AdSense 심사의 "충분한 콘텐츠"도 이쪽
- **CSP 가 어디에도 없다**(`worker/`·`site/`·`index.html`). 광고 로더는 페이지 컨텍스트에서 돌고, 편집 화면 DOM·IndexedDB 에는 사용자 본문이 있다 → 편집 화면에 실제 광고를 켜려면 격리(별도 오리진 iframe 등)와 CSP 가 먼저. 불변식 "사용자 CSS 는 주인을 떠나지 않는다"(F-2092)와 같은 결의 문제
- 편집 화면 오른쪽은 이미 목차(`OutlinePanel.tsx`)·댓글 레일(`CommentRailPanel.tsx`)이 쓴다. 편집 화면에서 "본문 아래"가 어디인지(스크롤 끝? 하단 고정 띠?)는 아직 안 정함

열린 질문
1. 편집 화면 광고 자리의 정확한 위치와 격리 방식 (위 CSP 항목)
2. `admin-usage` 는 첨부(R2) 합계를 안 보여준다 — 결정 2 의 R2 신호를 보려면 `attachments.size` 합계 한 줄이 필요 (`users` 에는 `content_bytes`·`doc_count` 만 있음)
3. 처리방침·약관의 운영자 표기: 지금은 `운영자`(2026-09-24 사용자: "일단 운영자로 표시, 나중에 구독요금제 준비할때 바꾸자"). AdSense 를 켜면 처리방침에 광고·쿠키 조항이 필요하다
