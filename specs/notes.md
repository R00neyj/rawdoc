## 2026-09-23 — 금고(E2EE) 폴더·문서

**상태: grill 3차까지 결정 완료(2026-09-24). 명세 없음. M3(F-305~F-309) 뒤에 M4 설계 개요 F-400 으로 쓴다**

사용자 질문 "db에 평문 그대로 다 실리는데 암호화 가능?" 에서 출발. Cloudflare 가 D1·R2·DO 를 이미 저장 시 AES-256 으로 암호화한다는 것([D1](https://developers.cloudflare.com/d1/reference/data-security/)·[R2](https://developers.cloudflare.com/r2/reference/data-security/)·[DO](https://developers.cloudflare.com/durable-objects/reference/data-security/))을 확인한 뒤, 사용자가 **종단간 암호화(서버·운영자도 못 읽음)** 를 골랐다

### 정한 것 (2026-09-23 사용자, 전부 추천안)

| # | 결정 |
| --- | --- |
| 1 | **선택형.** 사용자가 켠 금고 폴더·문서만 E2EE. 일반 문서는 지금 경로(F-301·F-304, DO 가 평문 `Y.Doc` 병합·스냅샷) 그대로 |
| 2 | 암호화 대상: **본문 + 제목 + 첨부 이미지.** 폴더 이름·문서 수·크기·수정 시각은 평문(서버 목록·정렬 유지) |
| 3 | 키: **로그인과 별개인 금고 암호 + 복구 코드.** 암호에서 키 유도(WebCrypto PBKDF2 후보), 복구 코드는 한 번만 보여 준다. 키를 잃으면 복구 불가 |
| 4 | 순서: **F-304 를 그대로 재개하고, 금고는 M3 뒤** 새 설계 개요로. 금고는 일반 경로를 건드리지 않고 옆에 붙인다 |
| 5 | 1차 금고 문서는 **혼자 편집**(실시간 암호 협업은 2차). 저장은 문서 전체를 암호화해 올린다 |
| 6 | 1차 금고는 **나만.** 초대·공유 링크·`/v1`·CLI 에서 빠진다(목록에는 금고 표시만) |
| 7 | 첨부 정리(F-219, `attachmentGc.ts:110-124` 가 본문을 스캔): 금고 문서는 **저장할 때 클라이언트가 쓰는 첨부 id 목록을 평문으로 함께 올리고**, 정리 작업은 그 목록을 본다 |
| 8 | 기기 캐시(IndexedDB): **암호문으로 저장**, 열 때 복호화 |
| 9 | 자동 잠금: 키는 메모리에만. **탭을 닫거나 새로고침하면 잠기고, 30분 안 쓰면 잠긴다**(시간은 설정에서) |
| 10 | 두 기기 동시 수정: **버전 충돌 → 충돌 사본**(F-207 방식을 금고 문서에만 남긴다. F-306·F-309 가 일반 문서에서 걷어내도 금고 경로는 유지) |
| 11 | 로그아웃 로컬 문서에도 **금고를 둔다**(같은 PC 의 다른 사람을 막는 잠금). 로컬 금고도 암호 + 복구 코드, 계정 금고와 같은 화면 (2026-09-24) |
| 12 | 로그인 이관(F-208): 로컬 금고 문서는 **암호를 물어 풀고 계정 금고 키로 다시 암호화해** 올린다. 계정 금고가 없으면 같은 암호로 만든다. 건너뛰면 기기에 남고 다음 로그인 때 다시 묻는다(일반 문서 이관은 그대로 한 번) |
| 13 | 검색·지도: **잠겨 있으면 빠지고, 풀면 복호화해 넣는다.** 다시 잠그면 메모리 색인에서도 지운다 |
| 14 | 기존 문서를 금고로 **옮길 수 있다.** 암호화해 덮어쓰고 평문 첨부는 암호 첨부로 바꾼 뒤 지운다. "D1 Time Travel 백업에 며칠간 평문이 남을 수 있음" 안내를 한 번 보인다. 금고에서 빼면 복호화해 평문으로 저장 |
| 15 | 크기 상한: **암호문 기준 1,000,000 B**(서버 검사 그대로). 금고 문서는 평문 약 750KB 까지 — 넘는 문서는 금고로 옮기기 전에 막는다 |
| 16 | 첨부 이미지 형식·크기: **클라이언트가 암호화 전에 판정**해 평문 메타로 올린다. 서버는 5MB 상한만 검사 |
| 17 | 마일스톤: **M4 신설**, 설계 개요 F-400, 하위 F-401~ |

### 조사해 둔 것 (2026-09-24, 다시 조사하지 말 것)

- 서버가 평문을 읽는 곳: `publicPage.ts:72-84`(OG 발췌), `links.ts`(공개 보기·묶음 위키링크 표·`stripComments`), `attachmentGc.ts:110-124`, `attachments.ts:173·212·254·296`(본문에 첨부 id 가 있는지로 남의 첨부 접근 허가), `imageSniff.ts`, `v1.ts:238·276-287`, `validate.ts:180-194`(크기). 검색·지도는 클라이언트 캐시에서 계산(`searchIndex.ts:78`, `mapIndex.ts:65`)
- WebCrypto 만으로 최소 구성 가능(AES-GCM, PBKDF2, RSA-OAEP/ECDH). Argon2id 는 `hash-wasm` 11.3KB gzip 이 필요
- 선행 사례: Proton Docs(클라이언트 squash), secsync, Excalidraw(`#key` 조각), Standard Notes(Argon2id), Skiff(공유 해제 때 키 교체 안 함). 암호 협업(2차)은 `YServer` 를 못 쓰고 `partyserver` 기반 `Server` 로 암호문 로그 + 클라이언트 스냅샷 교체


## 2026-09-24 — 과금 (열린 질문)

상태: 생각만 있음. 결정 없음. 사용자: "과금 구조는 어케할지 아직 생각 안해봤는데 토스API 정도로 생각만 하고 있었어"

배경
- 사용자 50명 전후에서 먼저 막히는 것은 서버 비용이 아니라 Cloudflare Access 좌석(무료 50 으로 알려짐, 확인 못 함). 서버는 Workers Paid 월 $5 로 수백 명까지 버틸 것으로 추정(실측 없음 — F-304 H394 가 첫 실측)
- 남용 방지 F-2024(M3 뒤)가 계정당 문서 100MB·문서 10,000개 한도를 정함 — 유료 요금제의 경계 후보

열린 질문
1. 대상: 국내 위주인가, 해외 포함인가 → 결제 수단(토스페이먼츠 vs MoR — Paddle·Lemon Squeezy) 이 거의 여기서 갈림
2. 무엇에 과금하나: 저장 용량(100MB 초과) / 실시간 협업(M3) / 금고(M4) / 팀 좌석
3. 요금 단위: 개인 월정액 / 팀 좌석당
4. 법적 준비: 사업자등록, 통신판매업 신고, 약관·개인정보처리방침(`content/legal/`) 결제 조항, 전자상거래법 환불 규정
5. 로그인 교체(Access → 앱 자체 OAuth·메일 링크)가 과금보다 먼저 와야 하는가

토스페이먼츠 조사 (2026-09-24, 서브에이전트. 확인 강도 표시)
- 확실(공식 docs): 테스트 키는 사업자등록 없이 회원가입만으로 발급 (docs.tosspayments.com/blog/how-to-test-toss-payments)
- 확실: 자동결제(빌링)는 일반 결제와 **별도 리스크 검토·추가 계약**, 정기 구독형만 허용. **국내 발급 카드만** — 해외카드 자동결제 불가 (guides/v2/billing)
- 확실: 토스는 결제일 스케줄러를 주지 않는다 — 우리가 Cron 으로 빌링키 승인 API 를 부른다. 재시도·카드 만료·해지(다음 결제일에 안 부르기)도 직접 (guides/v2/billing/integration-api)
- 확실: API 인증은 시크릿 키 Basic. 웹훅은 10초 안에 200, 실패 시 최대 7회 재전송(약 3일 19시간). 서명(HMAC-SHA256)은 지급대행 이벤트 위주로 문서화 — 결제 이벤트 서명 여부는 확인 못 함 (guides/v2/webhook)
- 약함(2차 출처): 가입비 22만 원·연 관리비 11만 원, 카드사 심사 최대 14일, 정산 D+2. 수수료율(%) 확인 못 함
- 대안: Lemon Squeezy 는 한국(ROK) 판매자 지급 지원 명시(docs.lemonsqueezy.com/help/getting-started/supported-countries). Paddle 한국 지원은 확인 못 함. 포트원은 PG 묶음 연동, 페이플은 해외카드 정기청구 지원 설명(약함)
- 함의: 해외 사용자 구독까지 원하면 토스 자동결제만으로는 안 된다(국내 카드 전용) → 열린 질문 1 이 먼저
