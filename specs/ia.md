# Rawdoc(가칭) IA — M1

작성일: 2026-09-13
상태: **초안 — 사람 승인 전.** I1~I8 결정됨 (2026-09-13~14). 미결 없음
제품명은 미정이다. 화면에서 제품명이 들어가는 자리는 `{제품명}` 으로 적는다 (`specs/design.md` 3.2)
범위: `specs/product.md` 의 M1 (로컬 단일 사용자 에디터). M2 이후는 8장에 자리만 적는다

> IA(Information Architecture, 정보 구조): 화면에 무엇이 어디 있고, 사용자가 어떤 순서로 이동하며, 각 상태에서 무엇이 보이는지를 정한 문서
> 기능의 존재 여부는 `specs/product.md` 가 정한다. 이 문서는 그 기능을 **어디에, 어떤 흐름으로** 둘지만 정한다

## 1. 화면 목록

M1 은 페이지 이동이 없는 단일 화면 앱이다

| ID | 화면 / 레이어 | 언제 보이나 |
| --- | --- | --- |
| S-1 | 편집 화면 | 문서가 1개 이상 있을 때 기본 화면 |
| S-2 | 빈 상태 | 문서를 전부 삭제해 0개일 때 |
| S-3 | 부팅 중 | 저장소에서 문서를 읽는 동안 |
| D-1 | 삭제 확인 대화상자 | 문서 삭제를 누를 때 |
| D-2 | 설정 대화상자 | 사이드바 `설정` 을 누를 때 (I8) |
| D-3 | 폴더로 이동 대화상자 | 문서 `⋯` 메뉴 `폴더로 이동…` (F-126) |
| S-4 | 공유받은 문서 | 해시가 `#/s/{조각}` 인 링크로 들어왔을 때 (F-130, 3.19) |
| N-1 | 알림 띠 | 가져오기 결과, 저장 실패, 저장소 사용 불가, 새 버전, 복사·공유 결과 |

- 페이지 이동은 없지만 **현재 문서를 해시 URL `#/d/{id}` 로 나타낸다** (I1). 규칙은 3.10
- 브라우저 기본 대화상자(`alert`·`confirm`)는 쓰지 않는다. D-1 은 앱 안에서 그린다

### 배치 원칙

- **현재 문서에 대한 동작은 상단바, 문서 집합에 대한 동작은 사이드바**에 둔다
- 삭제·이동·고정은 예외로 목록 항목의 `⋯` 메뉴에 둔다. 현재 문서가 아닌 문서도 열지 않고 다룰 수 있게 하기 위해서다
- 앱 전체에 걸린 것(설정, 앱 설치)은 사이드바 맨 아래에 둔다. 단 자주 바꾸는 보기 모드는 상단바에 둔다

## 3. 사용자 흐름

### 3.1 최초 실행

1. S-3 부팅 중 표시
2. 저장소에 문서가 0개이고 **최초 실행 기록이 없으면** 안내 문서 1개 생성
3. 안내 문서를 열고 S-1 표시. 에디터에 포커스를 주지 않는다

안내 문서를 삭제한 뒤 새로고침해도 다시 생기지 않는다 — 최초 실행 기록으로 구분한다

### 3.2 재방문

1. S-3
2. 열 문서를 아래 순서로 정한다
   1. URL 해시의 문서 ID — 그 문서가 있으면 연다
   2. 해시가 없으면 마지막으로 연 문서 ID
   3. 둘 다 없거나 해당 문서가 지워졌으면 목록 첫 번째(최근 수정) 문서
3. 해시에 적힌 문서가 없었으면 N-1 에 `문서를 찾을 수 없습니다.` 표시
4. 문서가 0개면 S-2

### 3.3 새 문서

1. `새 문서` 클릭
2. 제목 `제목 없는 문서`, 내용 빈 문자열, 줄바꿈 형식 CRLF 로 생성하고 즉시 저장 (`specs/product.md` Q9)
3. 새 문서를 열고, **상단바 제목 입력에 포커스 + 제목 전체 선택**
4. Enter 를 누르면 포커스가 에디터로 이동

### 3.4 문서 전환

1. 목록 항목 클릭
2. 현재 문서에 저장 대기 중인 입력이 있으면 **먼저 저장을 끝낸다**
3. 선택한 문서를 연다. 에디터에 포커스, 커서는 문서 맨 앞
4. 실행 취소 기록은 문서를 전환하면 사라진다 (M1)

### 3.5 제목 변경

1. 상단바 제목 입력에서 수정
2. 입력하는 동안 사이드바 항목 제목도 함께 바뀐다
3. 비운 채 포커스를 잃으면 `제목 없는 문서` 로 되돌린다

### 3.6 삭제

1. 목록 항목의 `×` 클릭
2. D-1 표시: `"{제목}" 을(를) 삭제할까요? 되돌릴 수 없습니다.` / `삭제` `취소`. 기본 포커스는 `취소`
3. `삭제` 시 저장소에서 제거
4. 지운 문서가 현재 문서였으면 목록 첫 번째 문서를 연다. 남은 문서가 없으면 S-2
5. Esc 는 `취소` 와 같다

### 3.7 가져오기

1. `가져오기` 클릭 → 파일 선택 창 (`.md` 만 선택 가능)
2. 새 문서 생성: 제목 = 파일명(확장자 제외), 내용 = 파일 원문
3. 새 문서를 열고 N-1 로 결과 표시: `"{파일명}" 을(를) 가져왔습니다.`
4. 파일의 줄바꿈 형식(CRLF 또는 LF)을 문서에 기억한다. 한 형식만 쓴 파일은 그대로 두고 알리지 않는다. CRLF·LF·`\r` 단독이 섞여 있었으면 CRLF 로 통일하고 같은 알림에 `줄바꿈 형식이 섞여 있어 CRLF 로 통일했습니다.` 를 덧붙인다 (`specs/product.md` Q9)
5. 실패(읽기 오류, UTF-8 아님) 시 문서를 만들지 않고 N-1 에 오류 표시
6. 파일 맨 앞에 UTF-8 BOM 이 있으면 떼어 내고 같은 알림에 `파일 맨 앞의 BOM 을 제거했습니다.` 를 덧붙인다 (`specs/features/F-114.md`)

### 3.8 내보내기

1. `.md 내보내기` 클릭
2. 현재 문서를 `{제목}.md` 로 다운로드. 저장 대기 중인 입력도 포함한다
3. 성공 알림은 띄우지 않는다 (브라우저 다운로드 표시로 충분)

### 3.9 보기 모드 전환

1. 상단바 토글 클릭
2. 편집 영역만 다시 그린다. 커서 위치·스크롤 위치·실행 취소 기록 유지
3. 선택한 모드는 저장해 두고 다음 실행에도 쓴다. 기본값 `편집`
4. `보기` 는 원문을 HTML 로 바꿔 읽기만 한다. 제목 입력도 읽기 전용. 편집으로 돌아오면 커서·실행 취소 기록이 그대로다 (F-123)

### 3.10 URL 과 뒤로 가기

| 동작 | URL | 브라우저 기록 |
| --- | --- | --- |
| 문서 전환 (목록 클릭) | `#/d/{새 id}` | 추가 — 뒤로 가기로 이전 문서 |
| 새 문서, 가져오기 | `#/d/{새 id}` | 추가 |
| 최초 실행·재방문에서 문서 결정 (3.1·3.2) | `#/d/{id}` | 교체 |
| 삭제 후 다른 문서로 이동 | `#/d/{id}` | 교체 |
| 문서 0개 (S-2) | `#/` | 교체 |
| 뒤로·앞으로 가기, 주소창 직접 수정 | 해시가 바뀜 | 해시의 문서를 연다. 저장 대기 입력은 먼저 저장 (3.4 와 같음) |

- 바뀐 해시의 문서가 없으면(삭제된 문서로 뒤로 가기 등) 3.2 의 2-3번 규칙으로 대신 열고 N-1 을 표시한다. 기록은 교체
- 해시 형식이 `#/d/{id}` 가 아니면 없는 ID 로 취급한다
- 마지막으로 연 문서 ID 도 계속 기록한다. 해시 없이 들어온 경우에 쓴다
- 경로가 1종류뿐이므로 라우터 라이브러리를 추가하지 않는다

### 3.11 좁은 창의 사이드바 (1024px 미만)

1. 사이드바를 숨기고 상단바 왼쪽에 사이드바 열기 아이콘을 표시한다 (2026-09-14 `☰` 에서 교체, F-143)
2. 열기 아이콘을 누르면 사이드바가 편집 영역 위에 겹쳐 열린다(펼친 모양, 레일 아님). 편집 영역 너비는 변하지 않는다. 사이드바 머리 줄 닫기 아이콘으로도 닫는다
3. 문서 선택, 새 문서, 가져오기, 대화상자(D-1·D-2) 표시 시 사이드바는 닫힌다
4. 사이드바 바깥 클릭 또는 Esc 로 닫힌다
5. 창을 1024px 이상으로 넓히면 `☰` 가 사라지고 사이드바가 원래 자리에 표시된다

### 3.24 `.md` 파일 끌어놓아 열기 (F-145)

1. 탐색기에서 `.md` 파일을 앱 창 위로 끌어오면 창 전체에 `여기에 놓아 .md 파일 가져오기` 덮개
2. 놓으면 3.7 가져오기 2~5단계. 여러 개면 파일마다 새 문서, 마지막 파일을 연다
3. 편집 영역에 놓아도 본문에 글자를 넣지 않고 새 문서로 가져온다
4. 대화상자·공유 화면에서는 받지 않는다

### 3.23 오른쪽 목차 (F-144)

1. 문서에 `#`~`###` 제목이 있고 메인 열 오른쪽 여백이 충분하면(56px 이상) 오른쪽에 제목마다 짧은 선이 세로로 보인다 (노션 방식)
2. 마우스를 올리거나 Tab 으로 들어오면 제목 목록 카드로 펼쳐진다. 현재 읽는 위치 제목이 강조된다
3. 항목을 누르면 그 제목 위치로 스크롤한다. 커서는 옮기지 않는다
4. 편집·원문·보기 모드 공통. 빈 상태·공유 화면에는 없다

### 3.22 사이드바 접기 (F-143, 1024px 이상)

1. 사이드바 머리 줄 왼쪽 접기 아이콘 → 폭 48px 아이콘 레일로 접힌다
2. 레일: 위에 펴기·새 문서·새 폴더·가져오기·검색, 아래에 앱 설치(조건부)·설정. 아이콘만, 툴팁으로 이름. 고정됨·트리는 숨김
3. 레일의 `새 폴더` 는 사이드바를 펼친 뒤 이름 입력을 시작한다
4. 접힘 상태는 저장해 다음 실행에도 쓴다. 좁은 창(3.11)에서는 쓰지 않는다

### 3.12 앱 설치 (F-115)

1. 사이드바 아래쪽 `앱 설치` 클릭
2. 브라우저 설치 확인 창이 뜬다 (브라우저가 그리는 창이며 앱이 문구를 바꿀 수 없다)
3. 설치하면 버튼이 사라진다. 취소하면 버튼이 남는다

### 3.13 새 버전 적용 (F-117)

1. 새 버전이 준비되면 N-1: `새 버전이 있습니다.` + `새로고침` 버튼
2. 사용자가 `새로고침` 을 누르면 저장 대기 입력을 먼저 저장하고 새 버전으로 다시 연다. 현재 문서·보기 모드는 유지 (3.10 URL 규칙)
3. 누르지 않으면 알림을 유지한다. 다음 실행 때 새 버전이 적용된다

### 3.14 OS 에서 `.md` 파일로 열기 (F-119)

1. 설치된 앱에서, OS 파일 탐색기의 `.md` 파일 `연결 프로그램` 으로 이 앱(`{제품명}`) 선택
2. 앱 창이 열리고 3.7 가져오기의 2~5단계를 그대로 탄다
3. 여러 파일을 한 번에 열면 파일마다 새 문서를 만들고 마지막 파일을 연다
4. 원본 파일에 다시 저장하지 않는다. 앱 안의 문서는 파일과 연결되지 않은 사본이다

### 3.15 설정과 제목 서체 전환 (F-121)

1. 사이드바 맨 아래 `설정` 클릭 → D-2 설정 대화상자
2. M1 의 설정 항목은 순서대로 `테마`(`시스템` / `화이트` / `세피아` / `다크`, 기본 `시스템`), `제목 서체`(`세리프` / `산세리프`), `본문 서체`(`세리프` / `산세리프`, 기본 `산세리프`. 버튼 순서는 제목 서체와 같게) 세그먼트다 (2026-09-14 테마·본문 서체 추가, F-141)
3. 누르는 즉시 반영한다. 저장 버튼은 없다. 대화상자 뒤 화면에서 바뀐 모습이 보인다
4. 세리프를 쓰던 자리만 바뀐다: 라이브 프리뷰 `#` `##` 제목, 빈 상태 문구, 상단바 제품명 (`specs/design.md` 2.1). 본문·UI·원문 모드는 원래 산세리프·고정폭이라 그대로다
5. 커서 위치·실행 취소 기록 유지. 제목 줄 높이가 달라지므로 스크롤 위치는 몇 px 달라질 수 있다
6. 선택은 저장해 두고 다음 실행에도 쓴다. 기본값 `세리프`
7. `닫기` 버튼, Esc, 대화상자 바깥 클릭으로 닫는다. 닫으면 포커스를 `설정` 버튼으로 되돌린다

보기 모드(편집 / 원문 / 보기)는 자주 바꾸므로 설정에 넣지 않고 상단바에 둔다

## 4. 상태

### 4.1 저장 상태 (상태바 E)

| 상태 | 문구 | 조건 |
| --- | --- | --- |
| 저장됨 | `저장됨` | 마지막 입력까지 저장 완료 |
| 입력 중 | `입력 중…` | 입력 후 자동 저장 대기 |
| 저장 실패 | `저장 실패` (강조색) | 저장소 쓰기 오류. N-1 도 함께 표시 |
| 저장 안 됨 | `메모리 모드 — 새로고침하면 사라집니다` | 저장소 자체를 쓸 수 없음 (시크릿 창 등) |

### 4.2 알림 띠 (N-1)

- 상단바 아래, 편집 영역 위에 1줄로 표시
- 정보성(가져오기 성공, 문서를 찾을 수 없음)은 몇 초 뒤 자동으로 사라진다. 오류는 사용자가 닫기 버튼 `×` 를 누를 때까지 남는다
- Esc 로 닫지 않는다. 에디터 안의 Esc 동작(I3)과 겹치지 않게 하기 위해서다
- 동시에 1개만. 새 알림이 이전 알림을 대체한다. 단 오류와 `새 버전` 알림은 정보성 알림에 대체되지 않는다

### 4.3 빈 상태 (S-2)

- 상단바: 제목 입력·보기 모드 토글·내보내기 비활성
- 사이드바: `새 문서`, `가져오기`, `설정` 활성. 목록 자리에 비어 있음 표시 없음
- 편집 영역 자리: `문서가 없습니다.` + `새 문서` 버튼 + `가져오기` 버튼
- 상태바 숨김

### 4.4 부팅 중 (S-3)

- 레이아웃 뼈대만 그리고 목록·편집 영역은 비워 둔다
- 보통 순간적으로 지나가므로 로딩 표시는 두지 않는다

## 5. 키보드와 포커스

| 키 | 동작 | 범위 |
| --- | --- | --- |
| Ctrl+B / Ctrl+I / Ctrl+K | 굵게 / 기울임 / 링크 삽입 | 에디터 포커스 시 |
| Tab | 들여쓰기 (2칸) | 에디터 포커스 시 |
| Enter | 에디터로 포커스 이동 | 제목 입력 포커스 시 |
| Esc | 대화상자 닫기, 없으면 겹쳐 열린 사이드바 닫기 | D-1·D-2 또는 3.11 사이드바가 열려 있을 때 |
| Esc 다음 Tab / Shift+Tab | 에디터 밖 다음 / 이전 요소로 포커스 이동 | 에디터 포커스 시 (I3) |

- Tab 을 에디터가 들여쓰기로 가져가므로 Esc 다음 Tab 으로 빠져나간다 (I3). CM6 가 이 동작을 기본 제공하는지는 F-103 에서 확인하고, 없으면 직접 구현한다
- 포커스 순서: 상단바 → 사이드바 → 편집 영역 → 상태바(포커스 대상 없음)
- 모든 버튼에 `:focus-visible` 표시 (`docs/prototype.html` 기준)
- 툴바가 없으므로 표·코드블록·체크박스 등은 마크다운을 직접 입력한다. M1 단축키는 위 표의 3개뿐이다
