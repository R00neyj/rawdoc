- 페이지 이동은 없지만 **현재 문서를 해시 URL `#/d/{id}` 로 나타낸다** (I1). 규칙은 3.10

- **공개 사이트 페이지는 앱 밖이다** — `/`(랜딩, F-271)·`/changelog`·`/help`·`/privacy`·`/terms`·`/guides`(사용법 목록)·`/guides/*`(글)·`404`. 서버가 내려 주는 정적 HTML 이고 저장소·React 를 쓰지 않는다 (F-270·F-272). 위 표의 S·D·N 은 **앱 안**의 화면·레이어이고, 앱이 여전히 단일 화면이라는 문장은 그대로다
  - 글 페이지(`/guides`·`/guides/*`·`/help`·`/changelog`·`/privacy`·`/terms`)에는 왼쪽 문서 목록·오른쪽 이 페이지 목차가 있고, 좁은 창(1055px 이하)은 제목 아래 접는 `목차` 하나로 바뀐다. 랜딩·404 에는 없다 (F-2036)
- 브라우저 기본 대화상자(`alert`·`confirm`)는 쓰지 않는다. D-1 은 앱 안에서 그린다

### 배치 원칙

- **현재 문서에 대한 동작은 상단바, 문서 집합에 대한 동작은 사이드바**에 둔다
- 삭제·이동·고정은 예외로 목록 항목의 `⋯` 메뉴에 둔다. 현재 문서가 아닌 문서도 열지 않고 다룰 수 있게 하기 위해서다
- 앱 전체에 걸린 것(설정, 앱 설치)은 사이드바 맨 아래에 둔다. 단 자주 바꾸는 보기 모드는 상단바에 둔다

## 3. 사용자 흐름

### 3.1 최초 실행

1. S-3 부팅 중 표시
2. 저장소에 문서가 0개이고 **최초 실행 기록이 없으면** 안내 문서 1개 생성
3. 안내 문서를 열고 S-1 표시. 에디터에 포커스를 주지 않는다

안내 문서를 삭제한 뒤 새로고침해도 다시 생기지 않는다 — 최초 실행 기록으로 구분한다

### 3.2 재방문

1. S-3
2. 열 문서를 아래 순서로 정한다
   1. URL 해시의 문서 ID — 그 문서가 있으면 연다
   2. 해시가 없으면 마지막으로 연 문서 ID
   3. 둘 다 없거나 해당 문서가 지워졌으면 목록 첫 번째(최근 수정) 문서
3. 해시에 적힌 문서가 없었으면 N-1 에 `문서를 찾을 수 없습니다.` 표시
4. 문서가 0개면 S-2

### 3.3 새 문서

1. `새 문서` 클릭
2. 제목 `제목 없는 문서`, 내용 빈 문자열, 줄바꿈 형식 CRLF 로 생성하고 즉시 저장 (`specs/product.md` Q9)
3. 새 문서를 열고, **본문 맨 위 제목 입력에 포커스 + 제목 전체 선택** (F-217)
4. Enter 를 누르면 포커스가 에디터로 이동

### 3.4 문서 전환

1. 목록 항목 클릭
2. 현재 문서에 저장 대기 중인 입력이 있으면 **먼저 저장을 끝낸다**
3. 선택한 문서를 연다. 에디터에 포커스, 커서는 문서 맨 앞
4. 실행 취소 기록은 문서를 전환하면 사라진다 (M1)

**M3 부터, 실시간으로 붙는 서버 문서는 다르다(F-305 5.1~5.2)**: 편집기가 곧바로 뜨지 않는다. 상태바만 `불러오는 중…` 으로 보이고, **첫 동기화가 끝난 뒤에야** 편집기가 마운트되고 3번의 포커스·커서 규칙이 적용된다. 그 전에 다른 문서로 옮기면 그 연결은 버려진다. 연결에 아예 실패하면 곧바로 지금(M1)의 흐름(저장소 값으로 편집기)으로 내려간다

**M3 갱신(F-306, 2026-09-24) — 오프라인에서 서버 문서를 열 때**: 이 브라우저에 그 문서를 실시간으로 연 기록이 있으면(`md-yjs`) 편집기가 그 기록으로 곧바로 뜨고 편집할 수 있다(연결 끊김 상태로 시작). 기록이 없으면 편집할 수 없다 — 캐시 본문을 읽기 전용으로 보여 주고 알림 띠로 "오프라인에서는 읽기만 할 수 있고 연결되면 편집할 수 있다" 는 것을 알린다(N7). 온라인이 되면 그 문서 열기를 다시 시작한다

### 3.5 제목 변경

1. 본문 맨 위 제목 입력에서 수정 (F-217)
2. 입력하는 동안 사이드바 항목 제목도 함께 바뀐다
3. 비운 채 포커스를 잃으면 `제목 없는 문서` 로 되돌린다

### 3.6 삭제

1. 목록 항목의 `×` 클릭
2. D-1 표시: `"{제목}" 을(를) 삭제할까요? 되돌릴 수 없습니다.` / `삭제` `취소`. 기본 포커스는 `취소`
3. `삭제` 시 저장소에서 제거
4. 지운 문서가 현재 문서였으면 목록 첫 번째 문서를 연다. 남은 문서가 없으면 S-2
5. Esc 는 `취소` 와 같다

### 3.7 가져오기

1. `가져오기` 클릭 → 파일 선택 창 (`.md` 만 선택 가능)
2. 새 문서 생성: 제목 = 파일명(확장자 제외), 내용 = 파일 원문
3. 새 문서를 열고 N-1 로 결과 표시: `"{파일명}" 을(를) 가져왔습니다.`
4. 파일의 줄바꿈 형식(CRLF 또는 LF)을 문서에 기억한다. 한 형식만 쓴 파일은 그대로 두고 알리지 않는다. CRLF·LF·`\r` 단독이 섞여 있었으면 CRLF 로 통일하고 같은 알림에 `줄바꿈 형식이 섞여 있어 CRLF 로 통일했습니다.` 를 덧붙인다 (`specs/product.md` Q9)
5. 실패(읽기 오류, UTF-8 아님) 시 문서를 만들지 않고 N-1 에 오류 표시
6. 파일 맨 앞에 UTF-8 BOM 이 있으면 떼어 내고 같은 알림에 `파일 맨 앞의 BOM 을 제거했습니다.` 를 덧붙인다 (`specs/features/F-114.md`)

### 3.8 내보내기

1. `.md 내보내기` 클릭
2. 현재 문서를 `{제목}.md` 로 다운로드. 저장 대기 중인 입력도 포함한다. 문서에 첨부 이미지가 있으면 `{제목}.md` + `attachments/` 를 담은 `{제목}.zip` (F-158)
3. 성공 알림은 띄우지 않는다 (브라우저 다운로드 표시로 충분)
4. `옵시디언 볼트로 내보내기` — 설정 `데이터` 탭, 폴더 `⋯`·우클릭 메뉴 두 자리(F-2020). `{YYYY-MM-DD}-vault.zip`(폴더는 `{폴더 이름}-vault.zip`)로 옵시디언이 바로 여는 모양의 zip 을 받는다

### 3.9 보기 모드 전환

1. 상단바 토글 클릭
2. 편집 영역만 다시 그린다. 커서 위치·스크롤 위치·실행 취소 기록 유지
3. 선택한 모드는 저장해 두고 다음 실행에도 쓴다. 기본값 `편집`
4. `보기` 는 원문을 HTML 로 바꿔 읽기만 한다. 본문 맨 위 제목도 글자로만 보인다(F-217). 편집으로 돌아오면 커서·실행 취소 기록이 그대로다 (F-123)
5. 편집 ↔ 원문은 같은 편집기를 다시 구성할 뿐이라 스크롤 위치가 그대로다. 편집·원문 ↔ 보기는 떠나는 화면의 **화면 맨 위에 보이는 원문 줄**을 기억했다가, 들어가는 화면에서 그 줄이 다시 맨 위에 오도록 맞춘다 (F-295)
6. 문서를 바꾸면 기억한 값을 버리고 맨 위부터 본다. 보기 화면의 이미지·다이어그램이 전환 뒤에 그려져 높이가 늘어나는 것까지는 따라가지 않는다 (F-295)

### 3.10 URL 과 뒤로 가기

| 동작 | URL | 브라우저 기록 |
| --- | --- | --- |
| 문서 전환 (목록 클릭) | `#/d/{새 id}` | 추가 — 뒤로 가기로 이전 문서 |
| 새 문서, 가져오기 | `#/d/{새 id}` | 추가 |
| 최초 실행·재방문에서 문서 결정 (3.1·3.2) | `#/d/{id}` | 교체 |
| 삭제 후 다른 문서로 이동 | `#/d/{id}` | 교체 |
| 문서 0개 (S-2) | `#/` | 교체 |
| 뒤로·앞으로 가기, 주소창 직접 수정 | 해시가 바뀜 | 해시의 문서를 연다. 저장 대기 입력은 먼저 저장 (3.4 와 같음) |

- 바뀐 해시의 문서가 없으면(삭제된 문서로 뒤로 가기 등) 3.2 의 2-3번 규칙으로 대신 열고 N-1 을 표시한다. 기록은 교체
- 해시 형식이 `#/d/{id}` 가 아니면 없는 ID 로 취급한다
- 마지막으로 연 문서 ID 도 계속 기록한다. 해시 없이 들어온 경우에 쓴다
- 경로가 1종류뿐이므로 라우터 라이브러리를 추가하지 않는다
- **사이드바·홈 화면의 문서 항목은 `#/d/{id}` 링크다.** 가운데클릭·우클릭 메뉴 `새 탭에서 열기` 로 새 탭에 연다. 일반 클릭·Ctrl+클릭·Shift+클릭은 지금 동작 그대로다 (F-296)

### 3.11 좁은 창의 사이드바 (1024px 미만)

1. 사이드바를 숨긴다. 상단바 제품명 옆 토글이 `사이드바 열기` 가 된다 (2026-09-14 F-151)
2. 토글을 누르면 사이드바가 편집 영역 위에 겹쳐 열린다(펼친 모양, 레일 아님). 편집 영역 너비는 변하지 않는다. 같은 토글(`사이드바 닫기`)로 닫는다
3. 문서 선택, 새 문서, 가져오기, 대화상자(D-1·D-2) 표시 시 사이드바는 닫힌다
4. 사이드바 바깥 클릭 또는 Esc 로 닫힌다
5. 창을 1024px 이상으로 넓히면 사이드바가 원래 자리에 표시되고 토글은 접기·펴기로 돌아간다

### 3.28 여러 문서 검색 (F-287)

1. 사이드바·상단바 `검색` 버튼 또는 `Ctrl+Shift+F` 로 검색 대화상자(D-6)를 연다. 이미 열려 있으면 단축키가 검색어를 전체 선택한다
2. 열리는 순간 저장 안 된 편집을 먼저 흘려보내고(`saver.flush()`) 인덱스를 만든다. 공개 보기(S-5)에서는 열리지 않는다
3. 검색어를 입력하면 150ms 뒤 결과가 바뀐다. 결과는 제목·폴더 경로·수정 날짜·본문 발췌로 보여 준다
4. 필터를 쓰면 검색창 아래에 해석 줄(`필터 tag=일기 · 검색어 "회고"`)이 뜨고, 그 아래에 오프라인·속성을 못 읽은 문서·공유받은 문서 안내가 붙는다. 결과 아래 꼬리 줄에 결과 수가 보인다 (F-288)
5. `↑` `↓` 로 결과 선택을 옮긴다(순환). 포커스는 검색창에 남는다
6. `Enter` 또는 클릭으로 그 문서를 연다. 대화상자가 닫히고 포커스는 에디터로 간다. **본문에 검색어가 있으면 그 문서의 찾기 패널(F-261)이 그 검색어와 함께 열리고 첫 매치가 선택된다. 필터만 친 검색·제목만 맞은 문서·보기 모드에서는 열리지 않는다 (F-294)**
7. `Esc` 또는 바깥 클릭으로 닫는다. 닫으면 검색어를 비운다 — 최근 검색어를 저장하지 않는다

### 3.29 위키링크 지도 (F-292)

1. 사이드바 `지도` 버튼으로 연다. 해시가 `#/map`(전체) 또는 `#/map/{id}`(그 문서 중심)이 되고, 열고 있던 문서는 닫히지 않는다 — 지도는 그 위를 덮는다 (S-8)
2. 저장 안 된 편집을 먼저 흘려보낸 뒤 문서 목록에서 위키링크를 읽어 그래프를 만든다. 만드는 동안 `연결을 읽는 중…`, 배치를 계산하는 동안 `배치를 계산하는 중…`
3. 3D 그래프가 뜬다. **왼쪽 끌기로 이동, 오른쪽 끌기로 회전, 휠로 확대**, `맞춤` 으로 전체가 보이게 되돌린다. **카메라는 240 ms 에 걸쳐 부드럽게 움직인다(움직임 줄이기 설정이면 즉시)** (F-2012). 터치는 한 손가락이 회전, 두 손가락이 확대·이동이다. **노드 위에서 왼쪽으로 끌면 그 노드가 따라오고, 놓으면 힘이 다시 잡는다. 터치는 노드 위 한 손가락 끌기가 그것이다** (F-2009)
4. 노드에 마우스를 올리면 그 문서와 직접 이어진 문서까지 이름표가 뜬다. 평소에는 이름표가 없다 (F-2004)
5. 노드를 클릭하면 지도를 닫고 그 문서를 연다. **노드 위에서 우클릭(터치는 길게 누르기)하면 회전이 아니라 메뉴가 열린다** — 문서 노드에서는 항목이 `열기`·`새 탭에서 열기`·`여기로 이동`·`이어진 문서만 보기` 넷이다 (F-2003, F-2007). **문서 노드에서는 이어진 문서만 보기 로 그 문서를 중심으로 1단계 필터를 켠다 (F-2007).** 끊긴 링크 노드에서는 항목이 `이 제목으로 새 문서` 하나다 (F-2004)
6. 끊긴 링크 노드를 클릭하면 그 제목으로 새 문서를 현재 문서와 같은 폴더에 만들고 연다 (F-131 5장 규칙 그대로)
7. 머리 줄 `지도 설정` 으로 오른쪽 패널을 연다. **`필터`·`그룹`·`표시`·`장력` 네 묶음이고 `필터` 만 펼쳐진다** — 그리는 묶음 중 맨 위가 펼쳐진다 (F-2005, F-2007, F-2008). **목록 보기에서는 `필터`·`그룹` 둘만 보이고, 그룹 색은 행 앞 점으로 나타난다** (F-2007, F-2008). 걸러진 문서는 자리에 남은 채 흐려지고 클릭되지 않는다. `몇 다리까지`(1~3단계)는 그 `필터` 안에 있다. **`장력` 을 바꾸는 동안에는 카메라가 움직이지 않는다 — 덩어리만 오므라들고 벌어진다** (F-2012)
8. `목록` 보기로 전환하면 같은 내용을 제목·연결 수 목록으로 본다. WebGL 을 못 쓰는 브라우저에서는 자동으로 이쪽이 된다
9. 닫기 버튼이나 뒤로 가기로 나온다. `Esc` 는 설정 패널이 열려 있으면 패널만 닫고, 지도 자체는 닫지 않는다

머리 줄 `맞춤`·`목록`·`닫기`는 아이콘 버튼 + 툴팁이다. 문구는 안 바뀐다 (2026-09-22 F-2011)

### 3.27 사이드바 너비 조절 (F-159, 1024px 이상)

1. 사이드바 오른쪽 테두리에 마우스를 올리면 선이 진해지고 커서가 좌우 화살표
2. 끌면 너비가 따라온다 (200~480px, 편집 영역이 너무 좁아지지 않게 창 폭에 따라 더 줄어듦). 놓으면 저장
3. 더블클릭하면 기본 너비 300px (2026-09-21 사용자 요청으로 224px 에서 넓힘)
4. 레일·좁은 창에서는 없다

### 3.26 이미지 넣기 (F-156~F-158)

1. 편집·원문 모드에서 이미지를 붙여넣거나 편집 영역에 끌어다 놓으면 커서 줄(놓은 줄) 아래에 이미지 블록이 생긴다. 원문은 `<div align="center">` + `<img src="attachments/…" alt width>` 3줄
2. PNG·JPEG·GIF·WebP, 한 장 20MB 까지. 긴 변 2000px 넘으면 줄이고 WebP 로 저장(GIF 제외, F-220), 결과는 5MB 까지. 로그인 계정은 이미지 합계 300MB 까지(F-221). 넘거나 다른 형식이면 N-1 알림
3. 편집 모드에서는 둥근 모서리 이미지로 보인다. 마우스를 올리면 오른쪽 위 정렬 버튼(왼쪽·가운데·오른쪽), 오른쪽 가장자리·오른쪽 아래 모서리 손잡이로 크기 조절(오른쪽 정렬이면 왼쪽). 바뀌는 것은 원문의 `align`·`width` 값뿐
4. 방향키로 들어가거나 더블클릭하면 원문 3줄이 드러난다
5. 보기 모드도 같은 모양. 공유 링크에는 이미지가 담기지 않아 자리 표시로 보인다
6. 내보내기는 3.8

### 3.25 문서 바깥 클릭 (F-146)

1. 편집 영역에서 문서 칸(최대 800px) 좌우 바깥 여백을 누르면 커서를 옮기지 않고 에디터 포커스를 잃는다
2. 에디터 포커스가 없으면 편집 모드도 커서 줄 기호를 드러내지 않아 보기 모드에 가깝게 보인다. 커서·선택 표시 숨김, 줄 번호는 유지
3. 문서 칸 안을 누르거나 Tab 으로 돌아오면 다시 편집 표시

### 3.24 `.md` 파일 끌어놓아 열기 (F-145)

1. 탐색기에서 `.md` 파일을 앱 창 위로 끌어오면 창 전체에 `여기에 놓아 .md 파일 가져오기` 덮개
2. 놓으면 3.7 가져오기 2~5단계. 여러 개면 파일마다 새 문서, 마지막 파일을 연다
3. 편집 영역에 놓아도 본문에 글자를 넣지 않고 새 문서로 가져온다
4. 대화상자·공유 화면에서는 받지 않는다

### 3.23 오른쪽 목차 (F-144)

1. 문서에 `#`~`###` 제목이 있고 메인 열 오른쪽 여백이 충분하면(56px 이상) 오른쪽에 제목마다 짧은 선이 세로로 보인다 (노션 방식)
2. 마우스를 올리거나 Tab 으로 들어오면 제목 목록 카드로 펼쳐진다. 현재 읽는 위치 제목이 강조된다
3. 항목을 누르면 그 제목 위치로 스크롤한다. 커서는 옮기지 않는다
4. 편집·원문·보기 모드 공통. 빈 상태·공유 화면에는 없다
5. 오른쪽 여백이 56px 미만(휴대폰·좁은 창)이면 선 대신 오른쪽 위에 `목차` 버튼이 뜬다. 누르면 아래로 같은 목록 카드가 열리고, 항목을 누르거나 밖을 누르거나 Esc 로 닫힌다 (F-229)

### 3.22 사이드바 접기 (F-143, 1024px 이상)

1. 상단바 제품명 옆 접기 아이콘 → 폭 48px 아이콘 레일로 접힌다. 토글·검색 묶음은 제품명 바로 옆으로 붙는다 (2026-09-14 F-151)
2. 레일: 위에 검색·새 문서·새 폴더·가져오기·지도(F-292), 아래에 `도움말`·`사용법`·앱 설치(조건부)·설정. 아이콘만, 툴팁으로 이름. 고정됨·트리는 숨김
3. 레일의 `새 폴더` 는 사이드바를 펼친 뒤 이름 입력을 시작한다
4. 접힘 상태는 저장해 다음 실행에도 쓴다. 좁은 창(3.11)에서는 쓰지 않는다

### 3.12 앱 설치 (F-115)

1. 사이드바 아래쪽 `앱 설치` 클릭
2. 브라우저 설치 확인 창이 뜬다 (브라우저가 그리는 창이며 앱이 문구를 바꿀 수 없다)
3. 설치하면 버튼이 사라진다. 취소하면 버튼이 남는다

### 3.13 새 버전 적용 (F-117)

1. 새 버전이 준비되면 N-1: `새 버전이 있습니다.` + `새로고침` 버튼
2. 사용자가 `새로고침` 을 누르면 저장 대기 입력을 먼저 저장하고 새 버전으로 다시 연다. 현재 문서·보기 모드는 유지 (3.10 URL 규칙)
3. 누르지 않으면 알림을 유지한다. 다음 실행 때 새 버전이 적용된다

### 3.14 OS 에서 `.md` 파일로 열기 (F-119)

1. 설치된 앱에서, OS 파일 탐색기의 `.md` 파일 `연결 프로그램` 으로 이 앱(`{제품명}`) 선택
2. 앱 창이 열리고 3.7 가져오기의 2~5단계를 그대로 탄다
3. 여러 파일을 한 번에 열면 파일마다 새 문서를 만들고 마지막 파일을 연다
4. 원본 파일에 다시 저장하지 않는다. 앱 안의 문서는 파일과 연결되지 않은 사본이다

### 3.30 명령 팔레트와 템플릿 (F-2022)

1. `Ctrl+P`(맥 `Cmd+P`) 또는 편집기 우클릭 `명령 팔레트…`(D-7)로 연다. 편집 화면 S-1·홈과 빈 상태 S-2·공유 관리 S-6·도움말 S-7·지도 S-8 에서 팔레트 1단계가 열린다. 공유 링크 화면 S-4·공개 보기 S-5 에서는 가로채지 않고 브라우저 인쇄로 간다. 부팅 중이거나 팔레트 아닌 다른 대화상자가 열려 있으면 무시한다. 팔레트가 이미 열려 있으면 입력칸 글을 전체 선택한다
2. 1단계는 명령 목록(`템플릿 삽입`·`PDF (A4 인쇄)`)이고 입력한 글로 걸러진다. `템플릿 삽입` 을 고르면 2단계로 들어가 내장 템플릿 4개 + 최상위 `템플릿`(또는 `templates`) 폴더 안 문서 목록이 뜬다. `PDF (A4 인쇄)` 를 고르면 팔레트가 닫히고 바로 인쇄한다
3. 템플릿을 고르면 팔레트가 먼저 닫히고, 변수(`{{date}}`·`{{time}}`·`{{title}}`)를 치환한 뒤 커서가 있던 자리에 줄 단위로 넣는다(F-169 자리 규칙). 코드블록·표·프론트매터 안이면 그 블록 뒤에 넣는다. 문서에 이미 프론트매터가 있으면 템플릿 프론트매터에서 없는 키만 더한다. 넣은 뒤 포커스는 본문 에디터, 커서는 넣은 글 끝
4. `Ctrl+Z` 한 번으로 넣은 프론트매터·본문이 함께 사라진다
5. `Esc`·바깥 클릭으로 닫는다. 2단계에서 입력칸이 빈 채 `Backspace` 를 누르면 1단계로 돌아간다. 닫으면 검색어·단계를 버리고 다음에 열 때 늘 1단계다

### 3.31 터미널 로그인 흐름 (S-9, F-2021, 주소·문구 F-2023)

명령줄 도구 `login` 이 브라우저를 열면 해시가 `#/cli-login/{port}/{host}/{publicKey}`(옛 CLI 는 `{port}/{state}/{publicKey}/{host}`) 인 주소로 온다. 상태에 따라 카드 하나가 바뀐다(세부 문구는 6장)

1. `불러오는 중…` → 계정 로그인 상태를 확인한다
2. 다른 페이지의 `iframe` 안이면 `잘못된 로그인 주소입니다.`(버튼 없음). 해시가 잘못됐거나 잘렸으면 `로그인 주소가 잘렸거나 올바르지 않습니다…`(옛 CLI 로 알아볼 수 있는 잘림이면 업데이트 명령 한 줄 추가). 이 브라우저가 X25519 를 못 쓰면 그 안내(업데이트 또는 `--with-token`)
3. 로그아웃 상태면 `로그인` 링크(누르면 로그인 화면(`/login`)에서 Google·GitHub 로그인 후 같은 해시로 복귀)
4. 로그인 상태면 이메일·토큰 이름(`CLI · {host}`)을 보여주고 `취소`·`승인`
5. `승인` → 토큰을 만들어 봉인한 뒤 CLI 로 돌아간다(`터미널로 돌아가는 중…`). `취소` → 토큰을 만들지 않고 돌아간다
6. 이 화면은 저장소(IndexedDB)를 열지 않고 사이드바·편집기를 띄우지 않는다

### 3.32 위키링크 미리보기 (F-2044)

1. 편집 모드 본문의 `.md-wikilink`(있는 문서), 보기 모드 본문의 `a.wikilink`(있는 문서) 위에 마우스를 올려 두면 0.5초 뒤 그 문서의 미리보기 창이 뜬다. 원문 모드, 끊긴 링크, 지금 문서를 가리키는 링크, 표 칸 안 링크에는 뜨지 않는다. 터치·펜 등 호버 없는 포인터도 판정하지 않는다
2. **미리보기 창 안의 위키링크는 호버해도 새 창을 띄우지 않는다(중첩 없음)** — 누르면 그 문서를 열고 창은 닫힌다
3. 창은 아래 가운데 하나로 닫힌다

   | 조건 | 비고 |
   | --- | --- |
   | 포인터가 링크와 창을 둘 다 벗어나 0.3초 | |
   | `Esc` | 5장 참고 — 겹쳐 열린 사이드바·대화상자보다 먼저 이 창을 닫는다 |
   | 창 밖 클릭, 창 밖에 포커스가 있는 상태의 키 입력 | 원래 링크를 눌러 문서를 여는 동작 자체는 막지 않는다 |
   | 편집기 스크롤, 창 크기 바뀜, 창 포커스 잃음 | |
   | 설정을 끄거나 문서·모드가 바뀌거나 지도·도움말·공유 화면이 뜸 | |
   | 열린 뒤 대상 문서가 지워졌거나 금고가 잠겨 더는 볼 수 없게 됨 | |

4. 창 안을 누르면 아래대로 움직인다

   | 누른 것 | 동작 |
   | --- | --- |
   | 이어진 위키링크 | 그 문서를 열고 창을 닫는다 |
   | 끊긴 위키링크 | 그 제목으로 새 문서를 만들어 열고 창을 닫는다 |
   | 바깥 링크 | 새 탭으로 열고(F-123) 창을 닫는다 |
   | 잘림 안내의 `문서 열기` | 미리보기 문서를 열고 창을 닫는다 |
   | 글자·빈 곳 | 아무 것도 하지 않는다. 글자 선택·스크롤은 된다 |

5. 창 안 내용은 보기 모드와 같은 렌더러로 그리고 수정할 수 없다. 문서가 길면 앞부분만 보여 주고 잘림 안내를 둔다. 공유받은 문서는 본문을 읽지 않고 안내 문구만, 잠긴 금고 문서는 잠김 안내만 보여 준다
6. 설정 `화면` 탭의 `위키링크 미리보기`(3.15)로 끄고 켠다. 기본은 `표시`이고, 끄면 열려 있던 창도 닫힌다

### 3.33 계정 삭제 (D-15, F-2038)

1. 설정 `계정` 탭 `계정 삭제…` → D-15 가 설정 위에 열린다(설정은 닫지 않는다). 열자마자 서버에 미리 보기를 묻는다
2. 세션을 만든 지 10분 안이면 `confirm` — 지울 것의 요약·공유 경고·안내를 보이고, 입력칸에 `삭제` 를 넣어야 `계정 삭제` 가 켜진다
3. 10분이 지났으면 `reauth` — `다시 로그인…` 을 누르면 저장 대기 입력을 먼저 저장하고, 이 탭의 sessionStorage `md.accountDelete` 에 돌아올 표지를 남긴 뒤 `/login?return={지금 해시}&reauth=1` 로 간다. 이 주소의 로그인 화면은 세션이 있어도 곧바로 돌려보내지 않고 안내 줄 한 줄을 더 보인다
4. Google·GitHub 로 다시 로그인하고 돌아오면 보던 문서 주소 그대로 앱이 열리고, 표지가 같은 계정·10분 안이면 D-15 가 설정 없이 저절로 열린다. 다른 계정으로 돌아왔으면 열지 않고 N-1 경고를 보인다
5. `계정 삭제` → 서버가 곧바로 지운다. 끝나면 이 브라우저의 그 계정 서버 사본(`md-remote`·`md-yjs`·계정 금고 키 묶음 캐시)을 지우고, 로그인 없이 만든 문서와 로컬 금고는 남긴 채 `/?app=1` 로 새로 읽은 뒤 N-1 `계정을 삭제했습니다.`
6. 다른 기기는 다음에 서버에 요청할 때 로그아웃 상태가 된다. 같은 브라우저의 다른 탭에는 알리지 않는다(금고 잠금만 전한다)
7. 막힌 계정도 똑같이 열고 지울 수 있다

| 상태 | 언제 | 보이는 것 |
| --- | --- | --- |
| `loading` | 열자마자 미리 보기를 묻는 중 | `불러오는 중…` + `취소` |
| `load-error` | 미리 보기가 네트워크 오류·서버 오류 | 불러오기 실패 문구 + `다시 시도` + `취소` |
| `reauth` | 미리 보기가 10분이 지났다고 하거나, 삭제 요청이 다시 로그인이 필요하다고 거절(또는 401) | reauth 문구 + `다시 로그인…` + `취소` |
| `confirm` | 미리 보기가 10분 안 | 요약 + 입력칸 + `취소`·`계정 삭제` |
| `deleting` | 삭제 요청을 보냄 | 입력칸·`취소` 비활성, 버튼 `삭제하는 중…`. Esc·바깥 클릭으로 닫히지 않는다 |
| `confirm` + 오류 줄 | 삭제가 네트워크 오류·서버 오류 | 입력은 그대로, 오류 줄, 버튼 다시 활성 |

- 미리 보기가 401 이면 로그아웃된 것으로 보고 대화상자를 닫은 뒤 계정 상태를 다시 읽는다
- 열 때 초점은 `취소`, `confirm` 이 되면 입력칸. 닫으면 `계정 삭제…` 버튼으로, 저절로 열린 경우는 `document.body` 로 되돌린다
- 문구 전문은 6장, 조건·순서는 `specs/features/F-2038.md` 4.3·6장·7장

### 4.2 알림 띠 (N-1)

- 상단바 아래, 편집 영역 위에 1줄로 표시
- 정보성(가져오기 성공, 문서를 찾을 수 없음)은 몇 초 뒤 자동으로 사라진다. 오류는 사용자가 닫기 버튼 `×` 를 누를 때까지 남는다
- Esc 로 닫지 않는다. 에디터 안의 Esc 동작(I3)과 겹치지 않게 하기 위해서다
- 다른 탭에서 지워진 문서의 알림은 오류(`error`)이고 `새 문서로 저장` 버튼을 함께 둔다 (F-296 7.3)
- 남의 막힌 문서(소유자 계정이 막힘)에 쓴 편집은 지우지 않고 오류 알림 `이 문서를 편집할 권한이 없어졌습니다.` — 그 문서는 이 페이지 동안 읽기 전용 (F-2030 4.4)
- 계정 메뉴 `로그아웃` 이 실패하면(연결 오류·서버 오류) 오류 알림 `로그아웃하지 못했습니다. 연결을 확인한 뒤 다시 시도해 주세요.` 버튼 없음, 주소·열린 문서는 그대로 (F-2034 3.1)
- 동시에 1개만. 새 알림이 이전 알림을 대체한다. 단 오류와 `새 버전` 알림은 정보성 알림에 대체되지 않는다

### 4.5 검색 대화상자(D-6)의 상태 (F-288)

결과 자리에는 아래 다섯 가지 중 **하나만** 뜬다. 위에서부터 먼저 걸리는 것을 쓴다

- 위키링크 미리보기 창이 떠 있을 때 `Esc` 는 그 창만 닫는다 — 대화상자·겹쳐 열린 사이드바를 닫는 아래 `Esc` 행보다 먼저 먹는다 (F-2044)
- Tab 을 에디터가 들여쓰기로 가져가므로 Esc 다음 Tab 으로 빠져나간다 (I3). CM6 가 이 동작을 기본 제공하는지는 F-103 에서 확인하고, 없으면 직접 구현한다
- 포커스 순서: 사이드바(머리 줄 토글·검색부터) → 상단바 → 편집 영역 → 상태바(포커스 대상 없음). 좁은 창은 상단바 → 사이드바 → 편집 영역 (2026-09-14 F-159)
- 모든 버튼에 `:focus-visible` 표시 (`docs/prototype.html` 기준)
- 검색 결과로 연 문서에서는 찾기 패널이 검색어와 함께 열려 있어 `F3`·`Ctrl+G` 로 다음 매치, `Esc` 로 패널 닫기가 바로 된다 (F-261 키맵, F-294)
- 지도(S-8)에는 단축키가 없고 `Esc` 로도 닫히지 않는다. 닫기 버튼·노드 클릭·뒤로 가기로만 나온다. **설정 패널이 열려 있으면 `Esc` 가 패널만 닫는다** (F-292 개정판 6.3). 다만 **노드 메뉴나 앱 설정 대화상자가 위에 떠 있으면 지도 패널은 `Esc` 를 먹지 않는다** (F-2005 6.2). 캔버스 안 노드는 포커스 대상이 아니고 `목록` 보기가 그 대안이다 (같은 명세 6.10)
- 노드 우클릭 메뉴는 열린 뒤에는 방향키·`Esc` 로 다룰 수 있지만, 캔버스가 포커스를 받지 않아 **키보드만으로 여는 길은 없다.** `목록` 보기가 그 대안이다 (F-2003 8.1). 노드 끌기도 키보드로는 할 수 없다 (F-2009)
- 툴바가 없으므로 표·코드블록·체크박스 등은 마크다운을 직접 입력한다. 나머지 단축키는 위 표 그대로다. 우클릭 메뉴(F-170)·명령 팔레트(F-2022)로 서식·단락·삽입·템플릿·인쇄 명령에 접근할 수 있다

### 6.1 도움말과 사용법 글 (F-2039)

도움말(`src/app/helpDoc.ts`)과 공개 사이트 사용법 글(`content/guides/*.md`)의 분담 규칙이다. 이 규칙의 원본 자리이고, 각 규칙의 근거는 `specs/features/F-2039.md` 2장에 있다. 안의 `m*`(실측)·`U*`(수용 기준)·`H*`·`Q*`·`C*` 와 장 번호는 F-2039 의 것이다

#### R1 역할

| | 도움말 | 사용법 글 |
| --- | --- | --- |
| 원본 | `src/app/helpDoc.ts` 하나 — 앱 `#/help`(S-7)와 사이트 `/help`(F-274)가 같은 원본 | `content/guides/{slug}.md` 한 편 = 주소 `/guides/{slug}` 하나 |
| 어디서 열리나 | 앱 번들 안 — 오프라인에서도 열린다 | 공개 사이트만. 서비스 워커 precache 에서 빠져(`vite.config.ts` `navigateFallbackDenylist` 의 `/^\/guides(\/|\?|$)/`, `e2e/site.spec.js` precache 검사) **온라인 전용** |
| 무엇을 적나 | 기능별로 **어디에 있고(화면 이름·메뉴 경로) 무엇을 하나.** 쓰다가 바로 부딪히는 기본값·상한 | 목적별로 **순서·시나리오, 한도와 그 이유, 되는 것과 안 되는 것, 위험과 한계** |
| 말투 | 존댓말, 짧은 문장, 화면 글자는 인라인 코드(F-257 1장) | 같다 |

- 첫 실행 안내 문서(`src/app/guideDoc.ts`, F-111)는 이 규칙 밖이다 — 사용자 저장소에 들어가는 온보딩 문서다(F-235 "역할 분리")

#### R2 도움말 절의 분량

- 앱 사용법 `##` 절(`## 이 앱은` ~ `## 단축키`) 하나는 **`사용법 글:` 줄을 뺀 본문이 600자(코드 포인트) 이하, 4문단 이하**다. 문단은 빈 줄로 나뉜 덩어리이고, 목록 하나는 한 문단으로 센다
- 넘으면 넘치는 설명을 사용법 글로 옮긴다. 도움말 절에는 "어디·무엇" 과 쓰다가 막히는 수치만 남긴다
- `## 마크다운 문법` 절(문법 예시 모음)은 이 규칙 밖이다

#### R3 "자세히" 링크의 모양

그 기능을 다룬 사용법 글이 있으면 **도움말 절의 마지막 문단을 정확히 이 한 줄**로 둔다.

```
사용법 글: [{그 글 프론트매터 title}](/guides/{slug})
```

- 판정 정규식(U2): `^사용법 글: \[[^\]\n]+\]\(/guides/[a-z0-9]([a-z0-9-]*[a-z0-9])?\)$` — slug 부분은 `site/pages.ts` 의 글 주소 규칙과 같다
- 절 하나에 이 줄은 **최대 한 개.** 같은 글을 두 절이 가리켜도 된다
- 링크 글자는 그 글의 `title` 과 **글자 하나까지 같다**(U4)
- 머리말 `사용법 글` 은 사이트 머리 링크 `사용법`(`SITE_NAV`, F-276)과 `specs/ia.md` 6장 "사이트 사용법 글 | 사용법" 행에 맞춘 것이다. `자세히`·`가이드` 는 쓰지 않는다(ia.md 6장 쓰지 않는 말 `튜토리얼, 가이드`)
- **주소는 상대 주소**(`/guides/…`)다. ① 앱과 사이트가 같은 출처라 앱 `#/help` 와 사이트 `/help` 양쪽에서 맞게 열린다 ② 절대 주소는 제품명 검사에 걸린다(m9)
- **새 탭으로 열린다 — 따로 할 일이 없다.** `renderMarkdown` 이 모든 본문 링크에 `target="_blank" rel="noopener noreferrer"` 를 붙인다(m8). 앱 탭은 도움말 화면 그대로 남는다. 사이트 `/help` 에서도 새 탭이다 — F-272 11장 M3·F-276 Q1 이 사이트 전체에 대해 그대로 두기로 한 동작이다
- **오프라인에서는** 링크를 그대로 둔다. 누르면 새 탭에 브라우저의 연결 오류 화면이 뜬다 — 사이트 글은 precache 하지 않기 때문이다(R1). 그래서 **도움말 절은 링크 없이도 그 기능을 쓸 수 있을 만큼**(어디서 켜고, 기본값이 무엇이고, 무엇에 막히나) 적는다. 링크를 숨기거나 비활성으로 두지 않는 이유: 앱에는 온라인 여부로 본문 링크를 바꾸는 장치가 없고, 이 한 줄을 위해 도움말 렌더 경로(`HelpPage.tsx` 의 모듈 스코프 `HELP_HTML`)를 상태에 묶을 값어치가 없다(12장 Q9)
- 설치한 PWA 창에서는 새 탭이 브라우저로 열린다 — F-276 H5 와 같은 사람 확인(11장 H3)
- `내 문서로 복사`(F-244)로 도움말을 복사하면 이 줄도 사용자 문서에 들어간다. 앱 안에서는 그대로 열리고, `.md` 로 내보내 다른 도구에서 열면 상대 주소라 이어지지 않는다 — 받아들인다

#### R4 서로 문장을 옮기지 않는다

- 사용법 글은 이어진 도움말 절의 문장을 그대로 쓰지 않고, 도움말 절도 글의 문장을 그대로 쓰지 않는다
- 판정(U5): `사용법 글:` 줄로 이어진 (절, 글) 쌍마다, 한쪽에서 `.`·`?`·`!` 뒤 공백·줄바꿈으로 자른 문장 가운데 **20자(코드 포인트) 이상**인 것이 다른 쪽 본문에 그대로 들어 있으면 실패. 목록 기호(`- `, `1. `)·표 칸 구분자(`| `)는 앞에서 떼고 비교한다
- 화면 글자를 인라인 코드로 인용하는 것(`` `금고 만들기…` ``)은 옮기기가 아니다 — 20자보다 짧아 판정에 걸리지 않는다

#### R5 수치는 코드 상수 한 곳에서

- **원천은 코드 상수 하나다.** 문서 쪽에는 "한 번만 둔다" 대신 **적은 곳마다 상수와 대조하는 단위 테스트**를 둔다
- 도움말 절에는 쓰다가 바로 부딪히는 수치만 둔다 — **절마다 3개 이하**(예: 금고 절의 `기본 30분`·`약 750KB`). 사용법 글에는 관련 수치를 이유와 함께 둔다
- 사용법 글을 더하는 명세는 그 글의 수치 대조 행을 `site/helpGuides.test.ts` 에, 도움말 절에 수치를 더하는 명세는 대조 행을 `src/app/helpDoc.test.ts` 에 더한다

#### R6 사실의 원천과 말

- 글의 사실 원천은 `done` 명세지만 **명세 문장을 옮기지 않는다.** 모든 사실은 현재 코드로 확인하고, 명세와 코드가 다르면 코드를 따르고 그 차이를 그 글 명세의 "갱신 대상" 에 적는다
- 글을 쓰는 명세는 **사실 표**(글의 문장 → 원천 명세 절 → 코드 이름)를 둔다. F-2039 5장이 첫 예다
- 내부 용어는 쓰지 않는다. 알고리즘처럼 사용자가 검색해 볼 만한 표준 이름은 괄호로 풀어 한 번 쓴다(예: `PBKDF2-SHA256(암호에서 열쇠를 만드는 표준 계산)`)
- `specs/ia.md` 6장의 **쓰지 않는 말**을 쓰지 않는다. 제품명 대신 "이 앱" 으로 쓴다(`cli.md` 의 명령 이름은 예외)
- "완벽히 안전" 류 과장을 쓰지 않는다. 지키지 못하는 것이 있으면 적는다
- 판정(U6): 모든 `content/guides/*.md` 에 아래 낱말이 없다 — 쓰지 않는 말 `비밀번호`·`마스터 암호`·`복구 키`·`백업 코드`·`보관함`·`비밀 폴더`·`잠금 폴더`·`가이드`·`튜토리얼`, 내부 용어 `DEK`·`KEK`·`AES-KW`·`Y.Text`·`Y.Doc`·`Durable Object`·`md-yjs`·`md-docs`·`md-remote`·`e2ee`·`키 묶음`·`봉투`·`outbox`·`IndexedDB`, 과장 `완벽`·`100% 안전`
  - 쓰지 않는 말 가운데 `비밀번호`·`마스터 암호`(→ `금고 암호`), `복구 키`·`백업 코드`(→ `복구 코드`), `보관함`·`비밀 폴더`·`잠금 폴더`(→ `금고`)는 F-400 5.1 이 정한 것이다. **아직 `specs/ia.md` 6장 표에 없다**(13장 C3)
  - `절대` 는 넣지 않는다 — `절대 경로` 같은 정상 쓰임이 걸린다

#### R7 글의 형식과 분량

- 프론트매터 `title`·`summary`·`date`·`updated`(F-276 6~8장 형식), 본문 첫 줄 `# {title}` 한 번
- `date`·`updated` 는 그 글을 넣는 **구현 커밋 날짜**(YYYY-MM-DD)다. `/guides` 목록은 `date` 내림차순이다(F-276 3.5)
- 본문(프론트매터 뺀)은 **6,000자 이하, `##` 10개 이하.** 넘으면 글을 둘로 나눈다. 판정 U6

#### R8 글 사이 링크

- 사용법 글에서 다른 사용법 글로 링크해도 된다(`/guides/{slug}` 상대 주소). 필수는 아니다

#### R9 새 글은 명세로

- 사용법 글 한 편 = 명세 한 개. 그 명세가 R2~R7 의 적용(도움말 링크 줄, 수치 대조 행, 사실 표)을 함께 가진다
