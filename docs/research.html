# 원문 보존형 마크다운 협업 도구
경쟁 지형과 시장 검증

가격은 모두 USD, 별도 표기 없으면 연간 결제 기준 · 환산은 1,400원/USD 가정

요약

  • "마크다운 원문을 변환하지 않고 남긴다"는 컨셉은 신규가 아님. HackMD가 상용으로, HedgeDoc(구 CodiMD)이 오픈소스로 2016년부터 같은 방식을 제공 중임
  • 줄 단위 인라인 댓글도 HackMD 전 요금제에 이미 포함돼 있어 단독 차별점이 되기 어려움
  • 실제로 비어 있는 지점은 한국어임. HackMD 공식 사이트는 영어·중국어·일본어만 지원하고, 트래픽의 절반 이상이 대만에서 발생함
  • 가격 하한선이 이미 매우 낮음. HackMD 무료 3인, 유료 $5/석. 프리미엄 가격 책정은 어려움
  • 시장 규모 추정치는 리서치사별로 15배 이상 벌어져 있어 TAM 근거로 쓰기 부적절함

## 1. 카테고리 정의

Rawdoc이 속한 칸은 "문서 협업 도구" 전체가 아니라, 그 안의 좁은 교집합임. 두 축으로 자르면 위치가 분명해짐.

원문 보존 · 협업 O HackMD, HedgeDoc — 그리고 Rawdoc이 노리는 자리

이미 선점돼 있음. 빈 칸이 아님
원문 변환 · 협업 X Typora, Bear 등 로컬 WYSIWYG 계열
원문 보존 · 협업 X Obsidian(소스 모드), StackEdit, VS Code

파일은 .md 그대로지만 동시 편집은 없음

확인된 전제 오류

프로토타입의 시드 문서와 툴바 문구는 "원문이 남는 것"을 핵심 주장으로 내세우고 있음. 이 주장 자체는 Notion 대비로는 사실임 — Notion 공식 도움말은 ## 뒤에 스페이스를 치면 H2로 변환된다고 명시함. 다만 이건 Notion과의 차이이지 시장의 빈틈은 아님. 같은 방식의 서비스가 이미 상용·오픈소스 양쪽에 있음

### HackMD를 자세히 봐야 하는 이유

기능·가격·포지셔닝이 Rawdoc과 사실상 겹침. 공식 가격 페이지에서 확인된 내용:

  • 무료 요금제에 실시간 협업과 인라인/페이지 댓글이 모두 포함됨. 유료로 잠기는 건 전문 검색, PDF 내보내기, 버전 무제한, 이미지 20MB, API 20,000회 같은 부가 기능임
  • 무료 제한은 팀원 3명, 초대 3명, 최근 10개 버전, 휴지통 3일, 이미지 1MB, GitHub 푸시 월 20회, API 월 400회
  • Prime은 연간 결제 시 좌석당 $5, 3석 기준 월 $15부터. 페이지에 "37.5% 절약"으로 표기돼 있어 월간 결제는 좌석당 $8로 추정됨
  • "1,000,000+ people"은 자사 홍보 문구이며 검증된 수치가 아님

틈이 보이는 지점

HackMD 공식 사이트의 언어 선택은 English / 中文 / 日本語 세 개뿐임 — 한국어가 없음. Ahrefs의 2025년 6월 트래픽 추정치도 hackmd.io 방문의 57.5%가 대만에서 발생한다고 봄 (검색 트래픽 기반 추정이라 실제 사용자 분포와는 다를 수 있음). 카테고리 자체가 아시아권에서도 지역 편중이 큰 상태이고, 한국어 UI를 갖춘 원문 보존형 협업 에디터는 확인되지 않음

## 3. 시장 규모 — 인용 주의

"지식 관리 소프트웨어(Knowledge Management Software)" 시장 추정치를 여러 리서치사에서 확인했는데, 같은 해 같은 시장에 대한 값이 심하게 엇갈림.

이 숫자들을 쓰지 말아야 하는 이유

최저 $2.6B와 최고 $38.98B의 차이가 15배임. 시장 정의(문서관리·챗봇·검색·엔터프라이즈 검색을 어디까지 넣느냐)가 제각각이고, 대부분 유료 보고서의 미리보기 문구라 산출 근거를 확인할 수 없음. 투자 자료나 사업계획서에 단일 수치로 인용하면 검증 시 문제가 됨. 쓸 거라면 "리서치사별 $2.6B–$39B로 편차가 큼"이라고 범위와 함께 적는 편이 안전함

더 방어 가능한 접근은 상향식 추정임. 예: HackMD Prime $5/석 × 국내 개발팀 규모로 SOM을 직접 계산하는 방식. 다만 국내 개발자 수·팀 수 통계는 이번 조사에서 검증하지 못했음

## 4. 현재 프로토타입과 경쟁사 사이의 실제 격차

첨부된 rawdoc.html 코드를 기준으로 확인한 내용임.

### 아직 없는 것

  • 실시간 동기화 — 상단 "3명 접속 중"과 아바타는 USERS 배열에서 그린 고정 UI임. 서버·CRDT·OT 어느 것도 붙어 있지 않음. 시드 문서의 할 일 목록에도 미완으로 적혀 있음
  • 저장소 — window.storage 단일 키에 전체 상태를 넣고, 없으면 메모리로 떨어짐. 새로고침 시 초기화된다고 상태바에 직접 표시됨
  • 렌더링 범위 — 정규식 기반 자체 파서라 중첩 목록, 각주, 수식, 다이어그램이 없음. HackMD는 수식·Mermaid·PlantUML·발표 모드까지 지원함
  • 댓글 앵커 — 줄 번호(line 인덱스)로 고정돼 있어, 위쪽에 줄을 추가하면 댓글이 엉뚱한 줄을 가리키게 됨. 시드 문서의 "문장 단위 댓글 앵커 고도화"가 이 문제임
  • 내보내기 — 현재 문서 1개만 .md로 저장됨. 워크스페이스 단위 내보내기, Git 연동 없음

### 이미 괜찮은 것

  • 기호를 죽이지 않고 색으로만 강조하는 오버레이 방식은 의도대로 동작함. HackMD의 분할 뷰와 같은 접근이면서 시각적으로는 더 정돈돼 있음
  • 툴바가 "서식 적용"이 아니라 "문법 삽입"으로 설계된 점은 컨셉과 일관됨
  • 줄 번호 거터에 댓글 표시를 찍는 처리는 코드 리뷰 도구의 관습을 따라 학습 비용이 낮음

## 5. 판단

포지셔닝

"Notion 대신 원문이 남는 도구"로 홍보하면 HackMD와 정면으로 부딪힘. 같은 기능을 무료 3인·유료 $5/석으로 이미 제공하는 상대라 가격으로 이기기 어렵고, 기능 수로도 밀림

차별화가 가능한 축은 세 개로 좁혀짐:
(1) 한국어 — UI, 문서, 지원, 결제. HackMD·HedgeDoc 모두 비어 있음
(2) 데이터 위치 — 국내 리전 또는 자체 호스팅. 공공·금융 대응 시 필수 조건이 되는 경우가 있음
(3) 댓글 앵커 정확도 — 줄 번호가 아니라 텍스트 내용에 붙는 앵커. 현재 프로토타입의 미완 항목이지만, 제대로 만들면 실사용 차이가 큰 부분임

### 가격 설계

  • 좌석당 $5(약 7,000원) 안팎이 이 카테고리의 사실상 상한선임. Notion Plus $10과 비교해서 저렴하다고 말하는 건 의미가 없고, HackMD $5와 비교당하게 됨
  • Outline식 인원 구간 정액제($10/월 1–10인)는 소규모 팀에 심리적 장벽이 낮음. 좌석당 과금 대신 검토해볼 만함
  • 무료 구간에 실시간 협업을 넣지 않으면 HackMD 무료(3인 협업 포함)에 밀림

과금 레버 정리

  • 좌석 수 — 주 수익원
  • 이미지 장당 크기 — 전환 트리거. HackMD가 무료 1MB / 유료 20MB로 거는 방식임. 총량 한도는 3년이 지나도 안 걸리지만 장당 1MB는 첫날 걸림
  • 워크스페이스 총량 — 무료 플랜에만. 수익 목적이 아니라 남용 차단용
  • 버전 히스토리 보관 기간 — HackMD 무료는 최근 10개, 휴지통 3일

내보내기는 유료로 막으면 안 됨

"원문이 남아서 잠기지 않는다"가 제품의 핵심 주장인데 .md 내보내기를 과금하면 자기모순이 됨. HackMD도 이 선을 지켜서 .md는 무료고 렌더링된 PDF만 Prime 전용임. 같은 구분을 쓰는 게 맞음

용량 과금에 대한 정정

텍스트만으로는 한도를 못 채우지만 이미지는 다름. 다만 계산해보면 유료 사용자는 이미지를 아무리 넣어도 적자가 안 남 — R2 GB당 월 약 21원 기준, 좌석 5,000원이 스토리지로 전부 소진되는 지점이 약 250GB임. 무압축 3MB 사진으로도 8만 장 수준임

진짜 위험은 매출이 0원인 무료 계정임. R2는 이그레스가 무제한 무료라 방치하면 외부 사이트의 이미지 CDN으로 소비될 수 있음. 핫링크 차단(서명 URL 또는 Referer 제한)이 없으면 크기 상한을 걸어도 우회됨

### 다음에 확인해야 할 것

  • 국내 개발팀·기술문서 작성 인구 규모 (상향식 SOM 계산용, 이번 조사에서 미검증)
  • HackMD의 실제 국내 사용 여부 — 자사 홍보 문구 외에 검증 가능한 데이터 없음
  • Confluence 가격 (엔터프라이즈 앵커로 필요, 이번 조사에서 공식 확인 안 함)
  • 국내 경쟁 후보(콜라비, 플로우 등)의 마크다운 처리 방식 — 미조사

## 6. 기술 구성 (확정)

백엔드는 Cloudflare 단일 스택으로 확정함. 프론트는 React 유지에 에디터 코어만 교체함.

계층선택이유
정적 + APIWorkers (static assets)Pages가 아님. 2024년 9월부터 Workers가 정적 자산을 직접 서빙하고, Cloudflare가 신규 프로젝트에 Workers를 권장함. 정적 자산 요청은 무료·무제한
실시간 동기화Durable Object + y-partyserver문서당 DO 1개. Cloudflare가 직접 유지보수하는 라이브러리라 서버 코드가 사실상 한 줄
메타 DBD1SQLite라 MariaDB에서 쓰던 SQL이 거의 그대로 통함
이미지·스냅샷R2이그레스 무료
에디터CodeMirror 6현재 textarea+오버레이로는 라이브 프리뷰가 원리적으로 불가능함
인증미정Cloudflare에 소비자용 로그인 제품이 없음. Worker에서 OAuth+JWT 직접 구현하거나 이 부분만 외부 사용

### 왜 Yjs를 SaaS로 사지 않는가

검토 결과 Yjs 동기화를 외부 SaaS로 빼는 게 전체에서 가장 비싼 선택이었음.

  • Liveblocks — Pro $25/월(연간)에 협업 분당 $0.002가 별도로 붙음. 사용자가 하루 2시간 × 월 20일 쓰면 1인당 월 $4.8. 좌석당 5,000원을 받으면 원가가 판매가를 넘김
  • Tiptap Cloud — Start $49/월, 무료 티어는 2025년 6월 폐지 (2차 출처 기준)
  • Cloudflare DO — SQLite 백엔드 DO는 Workers Free 플랜에서 사용 가능하고, Free 플랜은 스토리지 과금 대상이 아님. 유료로 올라가도 계정당 최소 $5/월에 포함됨

비용이 튀는 지점 3개

  • Hibernation 실패 — accept()를 호출하면 WebSocket이 연결된 전 시간이 duration으로 과금됨. Hibernation API를 쓰지 않으면 사용자가 탭을 열어둔 시간 전체가 요금이 됨. y-partyserver도 2.1.0에서 hibernation 지원을 고치는 릴리스가 있었을 만큼 까다로운 부분임
  • 반올림 — 초과분은 다음 청구 단위로 올림됨. 공식 문서 예시가 "50만 GB-s는 100만으로 올려 청구". 조금만 넘겨도 $12.50이 통째로 붙어서 요금이 계단식으로 점프함
  • R2 Class A(쓰기) $4.50/100만 — 이미지 업로드는 양이 적지만 Yjs 스냅샷을 초 단위로 R2에 쓰면 여기가 늘어남

배포 직후 대시보드에서 DO duration(GB-s) 지표만 며칠 지켜보면 됨. 이 숫자가 예상대로면 나머지는 무료 티어 안에서 돌아감

## 8. 프론트엔드와 배포

### 에디터 코어 교체가 최우선

옵시디언식 라이브 프리뷰(커서가 있는 줄만 원문, 나머지는 렌더링)는 현재 textarea + 오버레이 구조로 만들 수 없음. textarea는 내부 텍스트를 부분적으로 다르게 그릴 수 없기 때문임

CodeMirror 6로 교체하면 세 가지가 한꺼번에 해결됨:

  • Decoration으로 라이브 프리뷰 구현
  • y-codemirror.next로 Yjs 연동
  • 줄 번호 기반이던 댓글 앵커를 CM6 위치 매핑 + Yjs RelativePosition으로 대체

1차에서는 인라인 요소(굵게·기울임·링크·인라인코드)만 라이브 프리뷰하고, 표·코드블록은 원문 그대로 두는 게 안전함. 블록을 위젯으로 치환하면 커서 진입·이탈 처리가 까다로워짐

### 플랫폼

  • 웹·PC — PWA로 커버됨. Tauri/Electron 같은 데스크톱 래퍼는 로컬 파일시스템 직접 접근이 필요해질 때만
  • Android — Capacitor 또는 TWA로 기존 React 코드를 감쌈. Play 등록비는 1회 $25로 연간 갱신이 없지만, 개인 계정은 테스터 12명 비공개 테스트를 거쳐야 프로덕션 출시가 가능함 (2–4주 일정 확보 필요)
  • Flutter / React Native 신규 개발은 권하지 않음 — 이 제품의 핵심인 에디터가 하필 이식이 가장 어려운 부분이라 텍스트 렌더링·캐럿·선택 영역을 전부 0부터 다시 만들어야 함

### 배포

Vercel·Netlify를 쓰면 프론트와 백엔드가 갈라져서 CORS와 배포 순서를 따로 관리해야 함. Workers로 통일하면 wrangler deploy 한 번에 프론트·API·동기화 서버가 같이 나감. GitHub Actions는 CI 담당으로 그대로 쓰되 배포는 그 안에서 wrangler deploy를 호출하면 됨

  • 시작: npm create cloudflare@latest -- rawdoc --framework=react
  • compatibility_date는 프로젝트 생성일로 고정할 것
  • Pages와 달리 Workers는 node_modules·.git을 자동 제외하지 않음 → .assetsignore 필요

착수 전 반드시 검증할 것

Capacitor WebView에서 CodeMirror 6 + 한글 IME가 정상 동작하는지를 가장 먼저 확인해야 함. CM6 decoration으로 기호를 감췄다 보였다 하는 동작과 한글 조합 중 상태가 겹치면 커서가 튀거나 글자가 중복 입력되기 쉬움

나중에 발견하면 아키텍처를 되돌려야 하는 종류임. 로그인도 DB도 없이 에디터 화면 하나만 띄운 앱을 실기기에 올려보는 게 가장 싼 검증임. 안드로이드 WebView의 Blob 다운로드 동작도 같이 확인하면 됨
